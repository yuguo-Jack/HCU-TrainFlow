# [ROCm][Perf] Qwen3.8-Flash-Next specialized decode at 1-128 rows on MI355X (--monokernel)

[Upstream PR](https://github.com/vllm-project/vllm/pull/65188) · state: open · merged: False

## Original PR description

## Overview

With `--monokernel`, every pure decode step of 1 to 128 requests of `amd/Qwen3.8-Flash-Next-Quark-MXFP4` at TP2 on MI355X runs on persistent FlyDSL kernels, one launch per GDN decoder layer and three around the QSA attention, as RFC #60904 proposes. Prefill and mixed steps run vLLM's forward. This now also covers the 1 to 16 requests of #63032 and is faster there in the same harness (below), so one kernel family serves the whole range. Proof of concept.

## Claims

- Median ITL against #63032 at 1–16 concurrent (same engine base, same GPUs, same harness): **−11 to −24% at 1K inputs**, −10 to −22% at 32K; at 128K, parity at 1 concurrent and −8% at 4.
- Against stock vLLM with TP2-tuned AITER (same flags, `--max-model-len 262144`, 1K inputs): −32 to −42% at 1–16 concurrent (an earlier run on the same engine base), **−18 to −30% at 24–128** (#63032's stock fallback).
- Accuracy at parity: GSM8K stock 0.958 / 0.959, `--monokernel` 0.964 / 0.964 at 128 concurrent and 0.961 / 0.962 at 4 (strict / flexible, stderr 0.005). Long-context retrieval through the decode-time QSA select: every needle recalled at 8K–32K in both arms (single code and all eight codes, 4 and 32 concurrent).
- Stock path: the AMD QSA indexer scoring kernel scores only each row's visible columns. On main its grid grows with `--max-model-len`: at 128 decode rows and 262144 it takes ~375 µs a QSA layer whatever the context, against 28 / 39 / 155 µs at 128 / 8K / 64K context here.
- No new environment variables, and no host syncs in the specialized decode steps (`VLLM_GPU_SYNC_CHECK=error`, 1 to 128 concurrent).

## Validation

MI355X, TP2, AITER main with TP2-tuned GEMM/MoE configs, FlyDSL 0.4.1 (the stage tests also pass on 0.4.0). The serving numbers are on this PR's engine base with the kernels of each PR exported onto it, so only the specialized-decode code differs between the arms. This PR's serving numbers are at its head `b974d398ce`; GSM8K, the retrieval check and the host-sync check ran at `c2550fce02`, before the last five commits, which move work between CTAs and issue weight loads earlier without changing the arithmetic.

## Details

Each launch runs one decoder layer as a sequence of bulk-synchronous phases over the whole batch, inside vLLM's step: vLLM schedules, samples and owns the weights and caches, which the kernels read and update in place.

| layer | launches | phases |
|---|---|---|
| GDN ×36 | `gdn` | attn HC mix, GDN in_proj (MXFP4) + in_proj_ba + conv update, gated delta rule + gated RMSNorm, out_proj (MXFP4) + TP exchange + HC combine, MLP HC mix, router, routing + MXFP4 activation quant, experts, MoE combine + TP exchange + HC combine |
| QSA ×12 | `qsa_front`, `qsa_score`, `qsa_attn`, `qsa_back` | attn HC mix → x, qkv_proj + index_qk_proj; the fused prepare (queries, gate, K/V and indexer cache writes), indexer scores and the top-k select; sparse attention; gated o_proj + TP exchange + HC combine, then the MLP half |

- 256 CTAs × 256 threads co-resident; bulk-synchronous phases; a striped grid barrier (64 counters, wave-0 ballot poll).
- Batch-tiled MFMA GEMMs (`v_mfma_f32_16x16x32_bf16`): bf16 weights or MXFP4 weights decoded in registers from either AITER layout (Triton row-major, ASM shuffled), split-K partials summed in order by a later phase or folded by the last arriving unit.
- Up to 16 rows, a GEMM unit stages its whole K slice once, the next phase's first weights are issued between a grid barrier's arrival and its wait, and a mix, and the GDN projection through the attention combine, each run as one phase whose CTAs hand data over as tagged (value, tag) pairs instead of grid barriers.
- Expert-major fused W4A4 MoE on AITER's `AITER_MXFP4_MXFP4` weights in place (gate-up, SiLU, MXFP4 requant with AITER's scale rule, down), the fused shared expert as expert 512. The schedule adapts to the step's expert distribution: one expert's units run on one XCD (one L2), and a last round at most half full runs as intermediate halves. Up to 12 rows a small-batch path spreads each expert over the grid instead: whole router logits per CTA, gate/up pieces of 32 intermediate rows, and 160 CTAs owning the down projection's output rows and pushing the exchange lines.
- Gated delta rule: one CTA per (row, key head) (one value head a unit up to 16 rows), the next head's state loads in flight, a halving 16-row reduction, non-temporal state traffic.
- QSA (`wide/indexer.py`, `wide/select.py`, `wide/attention.py`), on vLLM's paged caches in place. The scores load the row's page table into LDS and run four 16-column tiles a wave a round on the matrix unit; a radix select (three levels of an LDS histogram) picks the decode top-k's set in the same launch, and a row whose visible blocks fit the budget takes all of them unscored. The attention expands its share of the selected blocks into an LDS table of cache byte offsets, stages 16 tokens a wave (`S^T = K Q^T`, wave-private online softmax, `O^T += V^T P^T`), and merges the waves through LDS and the splits in the row's last CTA (spread over the splits at small widths). FP8 or Octave K/V, FP8 indexer keys and MTP top-k reuse keep vLLM's QSA.
- TP exchange: one-shot lines (8 tokens × 64 columns, the last line of a column group partial when the rows are not a multiple of 8) pushed to every rank's uncached mailbox, one flag per line at a fixed offset; readers sum the ranks' copies in rank order and apply the HC combine. With `VLLM_ROCM_QUICK_REDUCE_QUANTIZATION=INT4` the lines carry QuickReduce's INT4 codec (16-column groups, bf16 group scales; 320 B lines), otherwise exact bf16. Each partial is quantized once (one-shot); on dumped real decode partials that is 22.0 dB SQNR against 18.7 dB for QuickReduce's two-shot, which quantizes twice.

60 layer launches a step plus two QSA kernels on each QSA layer. Four layer builds a capture size in 1–128 compile at startup, one after another (36 for the capture sizes above, ~2 min with an empty FlyDSL cache; 76 for the default list up to 128, ~5.5 min); the QSA kernels compile on first use during graph capture. For profiling, `runtime.layers.TRACE = True` (set in the worker, e.g. from a `--worker-extension-cls` module) builds every launch with per-phase clock stamps.

**Stock QSA scoring.** `_qsa_mqa_paged_kernel` launched one program per 32 columns of the page table's capacity for every query row, so its cost followed `--max-model-len`, not the context, in decode steps and prefill chunks alike. It now launches a fixed grid of at most 4096 programs (CUDA graph safe), and each row's programs stride over its visible column tiles only. Visible scores are bitwise identical; the columns past them, which the decode top-k never reads, are left unwritten, as on the NVIDIA kernel. `test_qsa_mqa_paged_scores_visible_columns` covers it.

**Scope and limitations**

- Follows RFC #60904: `--monokernel`, default-deny refusals (config, model, caches; every reason listed; the TP ranks agree), one `plan()` per step, MRV2 only, model-owned code under `vllm/models/qwen4_exp/amd/specialized_decode/`. Bounded in-kernel waits (grid barriers, exchange flags and tagged hand-offs) with health words; the TP ranks raise together (`FailStop`) rather than hang.
- Speculative decoding is refused, as in #63032. FP8 or Octave K/V, FP8 indexer keys and MTP top-k reuse keep vLLM's QSA inside the specialized step.
- The select runs one CTA per row: at 128K context and one row it is no faster than vLLM's decode top-k, hence the parity with #63032 there.
- vLLM's embedding, PLE, LM head, logits all-gather and sampling stay stock.
- Size: ~9.1K lines of Python, all under the model's `specialized_decode/` except the QSA scoring kernel, the `--monokernel` docstring and the Buildkite step. The kernels are specific to this model, hardware and TP degree; the stage tests pin their numerics.
- Overlap with #63032: both add `specialized_decode/hooks.py` and `runtime/` (`hooks.py` and `runtime/routing.py` are identical). With this PR serving 1–16 rows as well, only one of the two needs to land.
