# [Rust][Benchmark] Map --output-len to the sharegpt and hf datasets

[Upstream PR](https://github.com/vllm-project/vllm/pull/64946) · state: closed · merged: True

## Original PR description

## Purpose

Fixes #64939.

`--output-len` is silently ignored for `--dataset-name sharegpt` and `hf` in the Rust `vllm-bench`: each request's output length comes from the dataset's reference answer instead. Python `vllm bench serve` maps the flag onto both datasets, and Rust already does so for random, custom and prefix_repetition.

This PR:

- Maps `--output-len` onto `sharegpt_output_len` and `hf_output_len`. It takes precedence over the dataset-specific flags, matching Python and the other Rust datasets. Runs that don't pass `--output-len` are unchanged.
- Extends the existing hf check so `--output-len 0` is rejected for `--dataset-name hf`, as `--hf-output-len 0` already is. `--output-len 0` on other datasets isn't affected by this check.
- Updates the `--output-len` help text to say what it maps to.

`--multi-turn` reads the same two config fields, so ShareGPT multi-turn runs now honor `--output-len` as well.

SPEED-Bench is left alone: `--output-len` isn't mapped to `--speed-bench-output-len` in Python either. The question about its README examples is in the issue.

## Not a duplicate

I found no open issue or PR covering this. #62477 changes how output tokens are counted, not the requested length.

## Test Plan

New tests in `config::tests`:
- `test_output_len_maps_to_sharegpt_and_hf`: no flag gives `None`, each flag works alone, and `--output-len` wins when both are set. It fails without the mapping change.
- `test_hf_rejects_zero_output_len`: `--output-len 0` and `--hf-output-len 0` are both rejected.

```bash
cargo test -p vllm-bench
cargo clippy -p vllm-bench --all-targets --locked -- -D warnings
cargo fmt --all -- --check
```

End-to-end against a mock OpenAI-compatible server that logs each request's `max_completion_tokens`, 20 prompts, `--backend openai-chat`.

## Test Result

- `cargo test -p vllm-bench`: all pass (217 unit tests and 3 CLI parity tests). Clippy and fmt are clean.

| Dataset and flags | Before | After |
|---|---|---|
| sharegpt `--output-len 32` | 8 to 600 (3080 tokens) | 32 on all (640 tokens) |
| hf (`openai/gsm8k`) `--output-len 32` | 47 to 199 (2394 tokens) | 32 on all (640 tokens) |
| sharegpt `--multi-turn --output-len 32` | 8 to 600 | 32 on all |
| sharegpt, no flag | 8 to 600 | 8 to 600 (unchanged) |
| sharegpt `--output-len 32 --sharegpt-output-len 16` | not run | 32 on all |
| random `--output-len 32` | not run | 32 on all |

The Python client with sharegpt `--output-len 32` sends 32 on all requests (640 tokens), matching the new behavior.
