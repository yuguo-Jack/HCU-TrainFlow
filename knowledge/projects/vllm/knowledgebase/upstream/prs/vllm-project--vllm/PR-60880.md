# Fix/multibackend preferred block size

[Upstream PR](https://github.com/vllm-project/vllm/pull/60880) · state: open · merged: False

## Original PR description



## Overview

Fixes #60871 by making mixed-attention-backend KV-cache block-size selection respect backend-specific preferred block sizes when those sizes are supported by every backend in the model.

Currently, `_preferred_block_size_for_backends()` returns the default block size (`16`) as soon as all backends support it. In multi-backend configurations, this skips `get_preferred_block_size()` entirely, even when one of the backends explicitly prefers a larger block size.

## Claims

- Mixed-backend models now consider each backend's preferred block size before falling back to the default.
- A preferred size is used only when every participating backend supports it.
- If no preferred size is common across all backends, the existing fallback logic is preserved.
- Single-backend behavior is unchanged.
- Added regression tests for common, incompatible, and mixed backend preferences.
