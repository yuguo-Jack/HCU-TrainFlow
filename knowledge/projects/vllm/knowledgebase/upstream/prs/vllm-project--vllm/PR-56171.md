# [Quantization] Support FlashInfer 4/6 for online NVFP4 MoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/56171) · state: open · merged: False

## Original PR description

Keep native vLLM weight quantization as the default for online
`nvfp4_per_token` MoE. **Only `FLASHINFER_NVFP4_4OVER6=1` switches MoE weight
quantization to FlashInfer.** With the variable unset or `0`, weights retain
`scaled_fp4_quant` and the original 448-based scaling arithmetic.

For opt-in 4/6, FlashInfer packs the weights using the selected 256/448 bound,
and the existing TRTLLM per-token A1 path uses the matching base scale.
FlashInfer's TRTLLM A2 quantizer already honors that bound. The default
per-token activation quantizer remains the existing FlashInfer TRTLLM path.

`FLASHINFER_NVFP4_4OVER6` is **process-global in FlashInfer**, not scoped to
online MoE weight quantization. It also changes FlashInfer TRTLLM/CUTLASS MoE
activation quantization, so enabling it affects **pre-quantized NVFP4 models**
in that process too; their stored checkpoint weights are not re-quantized by
this online weight path. Set the recipe consistently before model loading
and CUDA graph capture. With 4/6 enabled, FlashInfer defaults to the 448
normalization bound; `FLASHINFER_NVFP4_4OVER6_E4M3_USE_256=1` is an optional
override.

Ray forwards only the five variables in FlashInfer's `NVFP4_QUANT_ENV_VARS`
through `DEFAULT_EXTRA_ENV_VARS`. The names are listed explicitly so Ray's
platform-independent environment module does not import FlashInfer. Other
`FLASHINFER_*` variables, including cache paths and `FLASHINFER_CUDA_ARCH_LIST`,
are not forwarded by default, preserving worker-specific settings. The TODO
tracks migration to config-based 4/6 settings after
https://github.com/flashinfer-ai/flashinfer/pull/5152 merges.

The native-default run is from `edaf91dd0`, with identical NVFP4 quantization code to
the current head. The later main refresh was not reevaluated. The two 4/6 runs are
retained from the preceding standalone commit: this update leaves their
quantization paths unchanged, and the `edaf91dd0` regressions verify both
bounds bit-for-bit. The earlier FlashInfer-weight standard run is not used
as the native-default baseline.

All three runs use Qwen/Qwen3-30B-A3B-Instruct-2507
(revision `0d7cf23991f47feeb3a57ecb4c9cee8ea4a17bfe`), TP4, and
`moe_backend="auto"`. Runtime inspection verifies TRTLLM per-token experts
and the recipe's normalization bound on every rank.

Full GSM8K: 1,319 questions, 5-shot raw completions, greedy decoding, maximum
512 output tokens, seed 42, eager mode, BF16 non-MoE weights, context/batched
tokens 8192, maximum sequences 64, and GPU memory utilization 0.8. All three
runs disable FP4 quantization fast math. The 4/6 cases use MSE with fast error
scoring; these are explicit evaluation settings, not FlashInfer
defaults (448, MAE, and fast error scoring disabled). These are single accuracy runs on shared nodes, not throughput
comparisons or statistical-significance claims.

```bash
# Standard: 4OVER6=0. For 4/6, set 1 and select the bound below.
export FLASHINFER_NVFP4_4OVER6=1
# Bound 448 (default): 0 or unset; use 1 only for the 256 comparison.
export FLASHINFER_NVFP4_4OVER6_E4M3_USE_256=0
export FLASHINFER_NVFP4_4OVER6_ERR_MODE=MSE
export FLASHINFER_NVFP4_4OVER6_ERR_USE_FAST_MATH=1
export FLASHINFER_DISABLE_FP4_QUANT_FAST_MATH=1
```

```python
from vllm import LLM
from tests.evals.gsm8k.gsm8k_eval import evaluate_gsm8k_offline
llm = LLM(
    model="Qwen/Qwen3-30B-A3B-Instruct-2507",
    revision="0d7cf23991f47feeb3a57ecb4c9cee8ea4a17bfe",
    dtype="bfloat16", tensor_parallel_size=4,
    quantization="nvfp4_per_token", moe_backend="auto",
    max_model_len=8192, max_num_seqs=64, max_num_batched_tokens=8192,
    gpu_memory_utilization=0.8, enforce_eager=True, seed=42,
    trust_remote_code=True,
)
print(evaluate_gsm8k_offline(
    llm, num_questions=1319, num_shots=5, max_tokens=512, temperature=0.0,
))
```
