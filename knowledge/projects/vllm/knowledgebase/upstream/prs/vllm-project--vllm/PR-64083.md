# [Bugfix] Preserve explicit MTP method regardless of draft model path

[Upstream PR](https://github.com/vllm-project/vllm/pull/64083) · state: open · merged: False

## Original PR description

## Summary

Fix a speculative decoding configuration bug where an explicitly selected `mtp` method is overwritten based on keywords in the draft model's path.

In `SpeculativeConfig.__post_init__`, a checkpoint directory containing `DFlash2` is classified as `dflash` even with `--speculative-config '{"method":"mtp","num_speculative_tokens":3}'`. This incorrectly initializes the EAGLE/DFlash config and can fail with `AttributeError: 'Qwen3_5Config' object has no attribute 'vocab_size'`.

## Fix

- Preserve an explicitly selected `mtp` during automatic name-based speculative method detection, consistent with the existing `eagle`, `eagle3`, `dflash`, and `dspark` exceptions.
- Add parametrized regression coverage for checkpoint directory names containing `dflash2`, `eagle3`, and `dspark`.

## Reproduction

On vLLM v0.32.0, run a Qwen3.5-family model with an MTP head using a local model directory whose basename contains `DFlash2`:

```bash
vllm serve /models/qwen-mtp-DFlash2 \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3}'
```

**Before:** `mtp` is overwritten by `dflash`; EAGLEConfig accesses a nonexistent top-level `vocab_size`.

**After:** The explicitly chosen `mtp` method is retained. Renaming the local checkpoint directory to exclude `DFlash2` was confirmed to work on the affected deployment prior to this fix.

## Validation

- Reproduced on a real vLLM 0.32.0 deployment; renaming the checkpoint directory resolved startup.
- Added focused regression tests (CI pending; not run locally in this environment).

Adding `"mtp"` here fixes the name match, but it also skips the MTP branch below for anyone who sets the method explicitly. That branch is where the DeepSeek V4.1 check lives, the one that raises and says to use `dspark`, plus the `num_speculative_tokens > 1` warning. Before this, an explicit `"mtp"` fell through to it, and the comment in `hf_config_override` still says `method="mtp"` on V4.1 "is rejected below". It also means `"mtp"` on a model that isn't an MTP type now passes here instead of hitting the `NotImplementedError`.

Could you keep the name checks from overriding mtp but still run that branch? Skipping the eagle/dflash/dspark name checks when `self.method == "mtp"` would do it. A test with a `deepseek_v41` target and `method="mtp"` would pin it.
