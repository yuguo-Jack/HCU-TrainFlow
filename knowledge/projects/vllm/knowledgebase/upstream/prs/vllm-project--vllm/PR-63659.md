# [Bugfix] Clamp client-supplied remote_prefill_cached_tokens to the prompt length

[Upstream PR](https://github.com/vllm-project/vllm/pull/63659) · state: open · merged: False

## Original PR description



## Overview

Clamp the client-supplied `kv_transfer_params.remote_prefill_cached_tokens` override to `[0, prompt_len]` before it becomes `num_cached_tokens`. Fixes #58728.

This is the clamp @ptimizeroracle proposed in #58730, which robertgshaw2-redhat acked on the issue. That PR was closed by its author on 2026-10-23 for lack of review. I reproduced the bug independently on current main and am resubmitting the same approach with an end-to-end reproduction. Credit for the fix goes to @ptimizeroracle.

## Claims

- A client can no longer set `usage.prompt_tokens_details.cached_tokens` to an arbitrary or negative value through `kv_transfer_params`.
- `vllm:request_prefill_kv_computed_tokens` no longer goes negative for such requests.

## Validation

Reproducer on CPU through the real request path: JSON body, `CompletionRequest.to_sampling_params`, `OutputProcessor`, `IterationStats`. The prompt has 17 tokens and no local cache hits.

| Client sends | cached_tokens before | kv_computed before | cached_tokens after | kv_computed after |
|---|---|---|---|---|
| 9999 | 9999 | -9982 | 17 | 0 |
| -5 | -5 | 17 | 0 | 17 |
| 3 | 3 | 14 | 3 | 14 |

New test, on the base commit and with the fix:

```
$ pytest -q tests/v1/engine/test_output_processor.py -k remote_prefill   # base
FAILED tests/v1/engine/test_output_processor.py::test_remote_prefill_cached_tokens_clamped_to_prompt_len[9999-8]
FAILED tests/v1/engine/test_output_processor.py::test_remote_prefill_cached_tokens_clamped_to_prompt_len[-5-0]
2 failed, 4 passed, 58 deselected
$ pytest -q tests/v1/engine/test_output_processor.py -k remote_prefill   # this PR
6 passed, 58 deselected
```

`ruff check`, `ruff format --check` (0.14.0, the pre-commit pin) and `tools/pre_commit/mypy.py 3.11 vllm/v1/engine/output_processor.py` pass. The test runs in the `engine.yaml` step (`pytest -v -s v1/engine`).

I could not run a `RemoteOpenAIServer` test here, because this machine's driver cannot run current main's CUDA 13 kernels. The reproducer above covers the same path below the engine core.

## Details

`kv_transfer_params` is an ordinary request field on the completions, chat, responses and messages endpoints, and `to_sampling_params` forwards it with or without a KV connector. `OutputProcessor` copied `remote_prefill_cached_tokens` into `num_cached_tokens` with no bounds check. The clamp matches the bounds of the local count in `PrefillStats`. The Rust frontend change in #58885 reads the same field and may want the same bound.
