# [CI][Bugfix][HiSparse] Give the staged-prefill test a runtime with cache ops

[Upstream PR](https://github.com/vllm-project/vllm/pull/64191) · state: closed · merged: False

## Original PR description

- `test_sparse_mla_backends.py`: `test_hisparse_staged_prefill_cache_backs_min_attention_rows` builds a bare `HiSparseRuntime` with `cache_ops` from the platform backend instead of passing `self=None`

#61659 added this test calling `HiSparseRuntime.gather_prefill_cache(None, host_cache, plan)`, written against the version where the method called `torch.ops._C_cache_ops` directly. #62592 had already moved that call behind `self.cache_ops` from the HiSparse platform backend, so on main the test fails with `AttributeError: 'NoneType' object has no attribute 'cache_ops'` in (B200) V1 Attention Shard 4/6 and (H100) V1 Attention Shard 1/5 (e.g. https://buildkite.com/vllm/ci/builds/97806), and on every PR that runs those shards. The test now sets up the runtime the same way `HiSparseRuntime` does for itself; the assertions are unchanged. I checked the old and new calls against main's runtime code with the CUDA op stubbed: the old call raises the same error, the new one passes the test's assertions.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
