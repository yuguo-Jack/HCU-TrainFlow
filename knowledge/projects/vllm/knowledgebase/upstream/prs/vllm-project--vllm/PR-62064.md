# [Model] MuseSpark: Ampere (sm80) + AutoRound/GPTQ INT4 experts

[Upstream PR](https://github.com/vllm-project/vllm/pull/62064) · state: open · merged: False

## Original PR description



## Overview

Lets MuseSpark Open (816B-A42B) serve on **Ampere (sm80)** with the AutoRound INT4 checkpoint `intel-ai/Muse-Spark-Open-816B-A42B-INT4`, using route-major Marlin WNA16 experts. Stacked on #61879 (`muse-spark-support` @ `6cc692b`). Before this, the NVIDIA path in #61879 required Hopper (route-major) or Blackwell (FlashInfer TRT-LLM) and accepted only NVFP4/BF16 checkpoints.

Commit 1 is the same fix as PR A: https://github.com/vllm-project/vllm/pull/62068, which targets `main`. It is included here because INT4 output is garbage without it. Drop it on rebase once PR A lands.

## Claims

- MuseSpark INT4 (AutoRound/INC, `auto_round:auto_gptq` packing) loads and serves on 8x A100-80G at TP8:
  - 47.6 tok/s at 1 stream;
  - 628 tok/s aggregate at 32 concurrent;
  - 865,400 KV tokens at 32k context.
- MoE block output matches an fp32 reference: cos-sim 0.99999 for BF16 experts (layers 0, 1) and INT4 experts (layer 5).
- Quality on sm80:
  - arithmetic 10/10;
  - perplexity 1.21;
  - needle retrieval pass at 17,847 tokens;
  - images 4/4;
  - audio WER 0.06 / 0.10 / 0.00 on 3 LibriSpeech clips (with an audio-aware system prompt).
- The RoPE cos/sin cache is sized by `max_model_len` instead of the 1M-token config, which frees about 11.5 GiB per GPU at TP8.
- Route-major experts (Triton BF16, Marlin NVFP4/WNA16) run on any non-Blackwell CUDA GPU. Blackwell still uses FlashInfer TRT-LLM.
- `MuseSpark1xForCausalLM` accepts `INCConfig` and `AutoGPTQConfig`:
  - symmetric int4/int8 only;
  - act-order and asymmetric checkpoints are rejected with `NotImplementedError`.

## Details

**Commits:**

1. **`[Bugfix][MoE] Keep per-expert gate/up halves separate under stacked mappers`** (same as PR A: https://github.com/vllm-project/vllm/pull/62068)
   - `LlamaModel.hf_to_vllm_mapper` stacks per-expert `gate_proj` / `up_proj` into `gate_up_proj` and sets `shard_id`.
   - `RoutedExperts.load_weights` then chunks each half as a fused tensor, so `up` overwrites `gate`.
   - The fix restores the name from `shard_id` for per-expert names only.
   - This is the root cause of the garbage output (see the numerics table).
2. **`[Model] MuseSpark: size the RoPE cache by max_model_len`** (`model.py`, +3/−4)
   - The cache was sized by `max(config.max_position_embeddings (1M), max_model_len)`: a 1M-entry fp32 cos/sin cache per RoPE layer, about 11.5 GiB per GPU at TP8.
   - The first load OOMed during Marlin repacking at 78.15 GiB allocated per GPU.
   - The rotary embedding is unscaled `RotaryEmbedding`, so positions never exceed `max_model_len`.
   - This commit could equally be a review suggestion on #61879.
3. **`[Model] MuseSpark: route-major experts on pre-Blackwell CUDA (Ampere/Ada)`** (`muse_moe_runner.py`, +15/−4)
   - Replaces `is_device_capability_family(90)` with `_use_route_major_on_this_gpu()` (CUDA and not ≥ sm100) in `MuseSparkUnquantizedFusedMoE` and `MuseSparkModelOptNvFp4FusedMoE`.
   - Nothing in the route-major path is Hopper-specific.
   - BF16 experts (layers 0 and 61 of the INT4/NVFP4 checkpoints) now run on `TritonExperts`.
   - NVFP4 can use Marlin W4A16 on sm75+, matching vLLM's generic ModelOpt NVFP4 Marlin fallback.
4. **`[Model] MuseSpark: GPTQ-format INT4/INT8 experts (AutoRound/INC, GPTQ) on Marlin`** (+210/−4, including a 53-line test)
   - `MuseSparkWNA16FusedMoE(AutoGPTQMoEMethod)`: route-major Marlin experts. The MuseSpark post-expert-norm finalize is attached in `process_weights_after_loading`. Requires SwiGLU.
   - `_inc_experts_bits` resolves per-expert bit widths from AutoRound `extra_config`. The checkpoint lists its BF16 experts (layers 0 and 61) individually, and those layers fall back to `MuseSparkUnquantizedFusedMoE`.
   - Symmetric int4/int8 only. Act-order and asymmetric checkpoints raise `NotImplementedError`.
   - `MuseSparkRoutedExperts.load_weights` sends per-expert HF tensors (`<E>.<proj>.<param>`) through the per-expert mapping in `RoutedExperts`. The consolidated NVFP4/BF16 path is kept for stacked tensors.
   - `MuseSpark1xForCausalLM.supported_quantization_configs` gains `INCConfig` and `AutoGPTQConfig`.
   - New test: `tests/kernels/moe/test_muse_spark_wna16_config.py`.

**Why INT4 on Ampere:** NVFP4 activations and the TRT-LLM MoE kernels are unavailable on A100/A800. The INT4 W4A16 checkpoint (466 GB) fits on 8x80 GB with room for the KV cache. The NVFP4 checkpoint (533.0 GB) does not.

**Limitations:**
- **Custom all-reduce is unavailable on this topology.** vLLM refuses custom all-reduce on more than two PCIe-only GPUs, and here NVLink only joins pairs. That applies at TP8 and at TP4, so PyNCCL is used. TP4×PP2 gives more KV (1.05M tokens) but about 45% lower throughput.
- **Audio needs a system prompt.** With no system prompt, 2 of 3 clips got "I don't have the ability to listen" even though the audio tokens reach the model. This is model behaviour, not a vLLM bug, and belongs in the model recipe.
- **Private DeepGEMM pin.** #61879 pins a private `Inferact/DeepGEMM` fork that could not be fetched (tarball 404 / clone hangs). For this build it was stubbed by pointing `DEEPGEMM_SRC_DIR` at an empty directory. The sm80 path ran end to end without it, but the pin itself has to be fixed in #61879.
- **NVFP4 on sm80 is unlocked by commit 3 but not run end to end.** The checkpoint needs about 73 GiB per GPU for weights alone at TP8, which leaves no KV room at util 0.92.
- **Fused paths not available on Ampere.** The FlashInfer TP-MoE finalize and the CuTe-DSL finalize are unavailable, so the native/Triton finalize is used. FP32 router input is off (`HAS_ROUTER_OUTPUT=False`).
- **Not tested:**
  - non-INC GPTQ MuseSpark checkpoints (shared code path, but no checkpoint available);
  - INT8;
  - Ada (sm89);
  - video input.
- **Docs.** #61879 has no supported-models or recipe entry for MuseSpark yet. Once it does, add: INT4 (AutoRound/GPTQ) on sm80+ via Marlin, and NVFP4 on sm75+ via Marlin W4A16 (memory permitting).
