# [CI] Pin pydantic in the mypy pre-commit hook

[Upstream PR](https://github.com/vllm-project/vllm/pull/60894) · state: closed · merged: True

## Original PR description



## Overview

Pin `pydantic` in the mypy pre-commit hook. Unpinned, a fresh hook environment installs pydantic 2.14.0 (released Oct 8) and the hook fails on code that has not changed. First seen on #60721, which edits `.pre-commit-config.yaml` and so invalidated the cached hook environment in CI.

Not a duplicate: no open PR addresses the mypy hook's pydantic version or these `TypeAdapter` errors.

## Claims

- With pydantic 2.14.0 the mypy hook reports 6 `arg-type` errors in `vllm/entrypoints/` (`generate/base/protocol.py:214`, `openai/responses/serving.py:1398`, `launchers/run_batch.py:188,190,197,567`), all `TypeAdapter(A | B)` on a union alias.
- With pydantic 2.13.5 (the version in `requirements/docs.txt`) the hook passes.
- Any PR that changes `.pre-commit-config.yaml`, and `main` itself once the cached hook environment is rebuilt, hits this until pydantic is pinned.

## Validation

Each run used a fresh hook environment and a fresh mypy cache, on current `main`:

```bash
PRE_COMMIT_HOME=$(mktemp -d) MYPY_CACHE_DIR=$(mktemp -d) pre-commit run mypy --all-files
```

| Hook environment | Result |
|---|---|
| unpinned (installs pydantic 2.14.0) | Failed, `Found 6 errors in 3 files (checked 2240 source files)` |
| same environment, pydantic downgraded to 2.13.5 | Passed |
| same environment, back to 2.14.0 | Failed, same 6 errors |
| this PR (fresh environment, installs pydantic 2.13.5) | Passed |

## Details

pydantic 2.14.0 changed `TypeAdapter.__init__` to take `type: TypeForm[T]`. mypy 1.20.2 then rejects a union passed there (`expected "type[Never]"`). The call sites are valid at runtime, so this pins the checker's input rather than adding casts or ignores to them.

- The errors only appear in the full-tree scan; running mypy on the three files alone passes even with 2.14.0, so a call-site fix could not be verified file by file.
- Enabling mypy's experimental `TypeForm` feature (`enable_incomplete_feature = ["TypeForm"]`) does not help; the same 6 errors remain.
- The pin can be lifted when the hook's mypy handles `TypeForm`.
