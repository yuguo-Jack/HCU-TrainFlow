# [Test] Support hybrid GDN models in test_process_checkpoint

[Upstream PR](https://github.com/vllm-project/vllm/pull/65113) · state: open · merged: False

## Original PR description

## Purpose

`test_process_checkpoint` cannot run against hybrid GDN (mamba-family) models:
they reject `VLLM_BATCH_INVARIANT=1` at startup
(`VLLM batch_invariant mode is not supported for GDN_ATTN`), and their batched
greedy generation is not run-to-run reproducible, so the test's batched
output comparison is unusable for that model family. The CUDA process
checkpoint feature therefore has no token-exact regression coverage for GDN
models (the test docstring previously just excluded them).

This PR makes the test handle hybrid models:

- When `ModelConfig.is_hybrid` is true for the selected model, the test no
  longer sets `VLLM_BATCH_INVARIANT=1` and compares outputs per request
  (batch-size-1 generation, which is deterministic for this model family).
- Non-hybrid models keep the exact previous behavior (batched generation with
  batch invariance).

Closes #65112

## Test plan

Opt-in GPU test (requires `VLLM_TEST_CUDA_PROCESS_CHECKPOINT=1` and a
checkpoint-capable driver), not run in default CI.

Verified on 4×H20 96 GB, driver 580.126.09, torch 2.14.0+cu130, NCCL 2.30.7:

```bash
VLLM_TEST_CUDA_PROCESS_CHECKPOINT=1 VLLM_TEST_MODEL=Qwen/Qwen3.8-27B \
  VLLM_TEST_SLEEP_CYCLES=2 \
  pytest tests/basic_correctness/memory/sleep_mode/test_process_checkpoint.py -q
```

- Hybrid GDN (`Qwen/Qwen3.8-27B`): `[1-p2p]`, `[2-p2p]`, `[4-p2p]` all PASS —
  per-request outputs verbatim stable across cycles, graph handles identical,
  zero new captures. (shm cells not exercised for the GDN model.)
- Non-hybrid (`Qwen/Qwen3-0.6B`), full file (TP1/2/4 p2p + TP2/4 shm, 5/5):
  PASS via the unchanged batched batch-invariant path.

Additional scale data with the same protocol (5 cycles): TP2 and TP4 on the
27B hybrid GDN model all pass with graph identity preserved and zero
recaptures.

## Details

The per-request path loops `llm.generate([prompt], ...)` over the two fixed
prompts. Everything else in the test (graph identity assertions, replay/capture
counters, sleep/wake order rotation) is unchanged.

Note on the gate: `ModelConfig.is_hybrid` covers all hybrid model families
(not only GDN — e.g. lfm2, olmo_hybrid). Those families keep working in
per-request mode (the comparison stays token-exact, just slower), so the
wider gate is a safe simplification; happy to narrow it to mamba-family
backends explicitly if preferred.
