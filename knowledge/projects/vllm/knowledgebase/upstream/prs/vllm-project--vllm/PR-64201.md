# [Bugfix][Multimodal] Validate video/jpeg frames_indices against the frames sent

[Upstream PR](https://github.com/vllm-project/vllm/pull/64201) · state: open · merged: False

## Original PR description



## Overview

A `video/jpeg` frame sequence that has more frames than the `num_frames` limit (default 32) is rejected when the request also sends `frames_indices` for those frames. `load_base64` truncates the frames to the limit and then compares the original `frames_indices` with the truncated count. This PR checks `frames_indices` against the frames actually sent and truncates them together with the frames.

Fixes #64202

## Claims

- 40 pre-extracted JPEG frames with 40 `frames_indices` (the [documented](https://docs.vllm.ai/en/latest/features/multimodal_inputs/#pre-extracted-frame-sequences-with-media_io_kwargs) `media_io_kwargs` usage) now return 200. On main they return 400 `frames_indices length (40) must match number of frames sent (32)`.
- The `num_frames` limit from #38636 is unchanged: only the first `num_frames` frames are decoded, and the first `num_frames` indices are kept with them. `total_num_frames`, `fps` and `duration` pass through unchanged.
- A `frames_indices` list whose length differs from the number of frames sent is still rejected, and the error now reports the real count.

## Validation

The new test `test_load_base64_jpeg_truncates_frames_indices_with_frames` fails on main and passes with this PR:

```text
# main
E   ValueError: frames_indices length (6) must match number of frames sent (4)
# this PR
tests/multimodal/media/test_video.py: 41 passed
```

End to end on main `274a5e19a`, 1x H200: `Qwen/Qwen3-VL-2B-Instruct` served with `--trust-request-mm-kwargs`. The request is a chat completion with a `data:video/jpeg;base64,...` video, `media_io_kwargs.video = {fps: 30, frames_indices: [0, 10, ...], total_num_frames, duration}`, and the default `num_frames=32`.

| Frames sent | main | this PR |
|---:|---|---|
| 32 | 200 (209 prompt tokens) | 200 (209 prompt tokens) |
| 40 | 400 `frames_indices length (40) must match number of frames sent (32)` | 200 (209 prompt tokens) |
| 64 | 400 | 200 (209 prompt tokens) |

The same 209 prompt tokens show that the extra frames are still dropped by the limit.

```sh
pytest tests/multimodal/media/test_video.py
```

The test is marked `cpu_test` and runs in the CPU multimodal step (`pytest -m 'cpu_test' multimodal`).

## Details

`frames_indices` were added for pre-extracted frames in #40133, after the frame limit from #38636. The check compared them with `frames.shape[0]`, which is already truncated to `num_frames`. The number of frames sent comes from `data.count(",") + 1`, so the check does not split or decode the frames past the limit.

Behavior change: a request with more frames than the limit whose `frames_indices` covered only the first `num_frames` frames used to pass. It is now rejected, since `frames_indices` must describe every frame sent, as the docs and the error message say.
