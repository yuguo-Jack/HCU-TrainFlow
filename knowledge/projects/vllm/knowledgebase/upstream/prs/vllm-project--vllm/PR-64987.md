# [Misc] Skip other ranks' weights before weights transforms

[Upstream PR](https://github.com/vllm-project/vllm/pull/64987) · state: open · merged: False

## Original PR description

## Overview

Follow-up to #64869.

`WeightsMapper` runs `weights_transforms` on the raw checkpoint stream, before `AutoWeightsLoader` skips the layers on other PP stages and the MoE `weight_loader` skips the experts on other EP ranks. When a rank reads the full checkpoint, it runs the transforms on weights it later skips. That's cheap for a rename, but not for a transform that decodes tensors, like the CSF scale transform in #64312.

This adds `RankLocalTransform`, a wrapper that marks a transform as safe to run on only the weights its rank loads. When every transform in the mapper has it, `load_weights` maps each raw name first and drops the weight before the transforms if it falls in a `PPMissingLayer` or `StageMissingLayer`, or names an expert that its MoE layer leaves to another EP rank.

Now that #64312 is on main, this also wraps its CSF scale transform.

## Claims

- Wrapping is opt-in. It's only safe when dropping one layer's or one expert's inputs leaves every other output unchanged, and each output's mapped name stays in the same layer and expert as its inputs. A transform that takes a max over a layer's experts breaks the first; one that merges experts breaks the second. A transform must not turn a non-input-scale weight into an input scale, since some MoE methods need every expert's input scales.
- Once per `load_weights` call, each `MoERunner` gets a filter built from the expert map, quant method and global input scale rule that `weight_loader` uses, so it only drops expert weights `weight_loader` would skip. It keeps everything under EPLB, where checkpoint names carry logical IDs but `weight_loader` takes physical ones. The EP filter stays off for `gpt_oss_mxfp4`, whose weight loader handles all experts in one tensor.
- A name only counts as an expert weight when a `MoERunner`'s path is directly followed by `.<expert id>.`. Fused expert tensors, IDs past the routed experts, names under other modules and names the mapper drops all reach the transforms.
- Plain transforms see the same stream as before, so they can still move a weight into another layer.
- The CSF transform meets the conditions: it decodes each scale matrix from that matrix's own streams and keeps its name minus the stream suffix.

## Validation

```text
pytest tests/models/test_utils.py       # 14 passed on CPU; the 4 GPU-only tests were deselected
pre-commit run --files <changed files>  # passed
```

The new EP test puts three MoE layers with real `ExpertMapManager`s on EP rank 1 of 2 next to a `PPMissingLayer` (one plain, one with a global input scale, one under EPLB) and checks the exact names a wrapped transform sees.

I also ran the CSF transform from #64312 (`c474f56`, unchanged on main) through `AutoWeightsLoader` on the real expert streams of Qwen3.8-Flash-Next-FP4-Local (48 MoE layers, 512 experts, 73,728 scale matrices). The stand-in model has real `RoutedExperts` and `ExpertMapManager`s at the model's MoE paths and uses its top-level weights mapper. CPU, one process, 8 threads, so not a distributed run. Rows other than the first use `RankLocalTransform`:

| Rank | Matrices decoded | Decode |
|---|---|---|
| Any, plain transform | 73,728 | 14.71 s |
| EP2 rank 0 | 36,864 | 7.45 s |
| EP4 rank 0 | 18,432 | 3.71 s |
| PP2 rank 1 | 36,864 | 7.35 s |
| PP2 rank 1 + EP2 rank 1 | 18,432 | 3.72 s |

On every wrapped rank, each tensor the MoE layers receive (block scales, global scales, input scales, and the packed weights of two layers) is byte-identical to what the plain transform gives that rank after the existing PP and EP skips. The same holds with a global input scale, where every EP rank keeps all input scales, and under EPLB, where nothing is dropped.

I also checked GLM-5.3-Flash-FP4-Local, which stores its scales as `csf_32x2_v1` (42 MoE layers, 288 experts, 36,288 scale matrices). This was a single-process CPU test that used the model's actual top-level mapper and reproduced its two nested `AutoWeightsLoader` calls. This model doesn't support PP, so I checked EP only.

Across 10 configurations covering EP2, EP4, EP8, global input scales and EPLB, the filter kept the expected names and bytes for 72 sampled scale matrices from the checkpoint. The accompanying `input_scale` and `weight_scale_2` tensors used synthetic values with the checkpoint's names and shapes.

I also checked all 295,041 checkpoint names. The filter dropped exactly the expected non-local expert weights and kept all names from the vision tower, shared experts, dense layers and MTP layer. On EP4, the name check left streams for 9,072 of the 36,288 scale matrices per rank.

## Details

Whisper is the only other in-tree user of `weights_transforms`. It has no PP support or MoE layers, so I didn't wrap it.
