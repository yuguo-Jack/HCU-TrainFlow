# [Bugfix][Kernel] MXFP4 cutlass MoE: fix experts quant out-of-bounds read for expert counts not divisible by 4 or 16

[Upstream PR](https://github.com/vllm-project/vllm/pull/61336) · state: open · merged: False

## Original PR description



## Overview

Fixes #60914. This ports the #40351 NVFP4 fix to the MXFP4 experts-quant kernels. Their vectorized expert lookup read past `expert_offsets[num_experts]` when the expert count was not a multiple of 16 (low-latency path) or 4 (shared-memory path). On SM100, this made `CutlassExpertsMxfp4` (compressed-tensors W4A4 MXFP4 MoE) hit illegal memory accesses or produce garbage output.

## Claims

- `mxfp4_experts_quant` and `silu_and_mul_mxfp4_experts_quant` no longer read past the offset arrays, for any expert count.
- An MXFP4 W4A4 MoE checkpoint whose expert count is not a multiple of 16 now serves on GB200 in CUDA-graph and eager mode at TP1 and TP4. On main, TP4 hit an illegal memory access in warmup after graph capture, TP1 segfaulted in `cudaGraphLaunch`, and earlier builds collapsed to a single repeated token.
- No change for expert counts that are multiples of 16; they take the same kernels as before.

## Validation

On this PR, I also compared `run_cutlass_moe_mxfp4` at the same shapes, over m ∈ {1, 8, 64, 512}, against two references. Both are computed in PyTorch from the same random weights:

- **W4A4 emulation:** the dequantized MXFP4 weights, with MXFP4 quantize-dequantize applied to both GEMM inputs (the hidden states, and the SiLU-and-mul output). This uses the same E8M0 scale rule as `compute_reference_e8m0_scale` in `tests/kernels/moe/test_mxfp4_moe.py`.
- **bf16:** the original unquantized weights and activations.

The metric is `calc_diff` from the same test file: `1 − 2·Σxy / Σ(x² + y²)`, where 0 means identical outputs.

| comparison | `calc_diff` |
|---|---|
| CUTLASS vs W4A4 emulation | 0.0046–0.0071 |
| CUTLASS vs bf16 | 0.034–0.041 |
| W4A4 emulation vs bf16 | 0.037–0.040 |

CUTLASS tracks the emulation about 7× more closely than either tracks bf16, and its error against bf16 matches the emulation's. So the kernel adds no error beyond MXFP4 W4A4 quantization itself.

# SPDX-License-Identifier: Apache-2.0
"""Repro for vllm#60914: CUTLASS MXFP4 MoE (SM100) with an expert count that is
not a multiple of 16. Random weights; requires a vLLM build with SM100 kernels.

--quant-check  The MXFP4 activation quantizers must never read past
               expert_offsets[E] / blockscale_offsets[E]. Each is run twice on the
               same input, with the memory after those arrays clean vs. poisoned;
               the outputs must be identical.
--moe-check    run_cutlass_moe_mxfp4 over decode and prefill batch sizes vs. a bf16
               PyTorch reference. Run it under compute-sanitizer so out-of-bounds
               accesses are reported per tensor:
                 PYTORCH_NO_CUDA_MEMORY_CACHING=1 compute-sanitizer --tool memcheck \
                   python repro_mxfp4_moe_oob.py --moe-check --ms 1 8 64
--emu-check    run_cutlass_moe_mxfp4 vs. a W4A4 emulation (dequantized weights,
               MXFP4 quantize-dequantize of both GEMM inputs) and vs. bf16. The
               metric is calc_diff from tests/kernels/moe/test_mxfp4_moe.py.
"""

import argparse
import sys

import torch

from vllm import _custom_ops as ops
from vllm.model_executor.layers.fused_moe.activation import MoEActivation
from vllm.model_executor.layers.fused_moe.experts.cutlass_moe import (
    run_cutlass_moe_mxfp4,
    swizzle_mxfp4_scales,
)
from vllm.model_executor.layers.quantization.utils.mxfp4_utils import mxfp4_quantize

E, TOPK, K = 20, 4, 1024  # overridden by --experts/--topk/--hidden
POISON_PAD = 16
N_FUSED = 512


def calc_diff(x, y):
    x, y = x.double(), y.double()
    return (1 - 2 * (x * y).sum() / (x * x + y * y).sum()).item()


def route(m, device, gen):
    logits = torch.randn((m, E), device=device, generator=gen)
    w, ids = torch.topk(torch.softmax(logits, dim=-1), TOPK, dim=-1)
    return (w / w.sum(-1, keepdim=True)).float(), ids.to(torch.int32)


def offsets_for(topk_ids, n):
    dev = topk_ids.device
    eo = torch.empty(E + 1, dtype=torch.int32, device=dev)
    bo = torch.empty(E + 1, dtype=torch.int32, device=dev)
    p1 = torch.empty((E, 3), dtype=torch.int32, device=dev)
    p2 = torch.empty((E, 3), dtype=torch.int32, device=dev)
    am = torch.empty(topk_ids.numel(), dtype=torch.int32, device=dev)
    cm = torch.empty(topk_ids.numel(), dtype=torch.int32, device=dev)
    ops.get_cutlass_moe_mm_data(topk_ids, eo, p1, p2, am, cm, E, n, K, bo)
    return eo, bo


def padded_view(src, poison):
    """src[:E+1] backed by a buffer whose tail is either clean or poisoned."""
    buf = torch.empty(E + 1 + POISON_PAD, dtype=torch.int32, device=src.device)
    buf[: E + 1] = src
    if poison:
        # A lookup that reads expert_offsets[E+1:] sees expert E+1 owning every
        # row, and its scale block starts at row 0 (expert 0's block).
        buf[E + 1 :] = 0
        buf[E + 2 :: 2] = 2**31 - 1
    else:
        buf[E + 1 :] = src[E]
    return buf[: E + 1]


def quant_check(device):
    gen = torch.Generator(device=device).manual_seed(0)
    bad = 0
    for m in (1, 4, 8, 32, 128, 1024):
        _, ids = route(m, device, gen)
        for fused, width in ((False, K), (True, 2 * N_FUSED)):
            eo, bo = offsets_for(ids, width // 2 if fused else width)
            x = torch.randn(
                (m * TOPK, width), device=device, dtype=torch.bfloat16, generator=gen
            )
            raw = (
                torch.ops._C.silu_and_mul_mxfp4_experts_quant
                if fused
                else torch.ops._C.mxfp4_experts_quant
            )
            k_out = width // 2 if fused else width
            sf_cols = (k_out // 32 + 3) // 4
            outs = []
            for poison in (False, True):
                eo_p, bo_p = padded_view(eo, poison), padded_view(bo, poison)
                # Zeroed outputs, so the never-written scale padding compares equal.
                q = torch.zeros(
                    (m * TOPK, k_out // 2), dtype=torch.uint8, device=device
                )
                s = torch.zeros((int(bo[E]), sf_cols), dtype=torch.int32, device=device)
                raw(q, s, x, eo_p, bo_p, E)
                torch.accelerator.synchronize()
                outs.append((q, s))
            same = torch.equal(outs[0][0], outs[1][0]) and torch.equal(
                outs[0][1], outs[1][1]
            )
            print(
                f"quant-check m={m:5d} fused_silu={fused!s:5}: "
                f"{'OK' if same else 'MISMATCH (reads past expert_offsets[E])'}"
            )
            bad += not same
    return bad


def make_weights(n, device, gen):
    w1 = (
        torch.randn((E, 2 * n, K), device=device, dtype=torch.bfloat16, generator=gen)
        / 8
    )
    w2 = torch.randn((E, K, n), device=device, dtype=torch.bfloat16, generator=gen) / 8
    q1, s1 = mxfp4_quantize(w1)
    q2, s2 = mxfp4_quantize(w2)
    raw_s1, raw_s2 = s1, s2
    s1 = torch.stack(
        [
            swizzle_mxfp4_scales(s1[i], 2 * n, K).reshape(2 * n, K // 32)
            for i in range(E)
        ]
    )
    s2 = torch.stack(
        [swizzle_mxfp4_scales(s2[i], K, n).reshape(K, n // 32) for i in range(E)]
    )
    return w1, w2, q1.contiguous(), s1, q2.contiguous(), s2, raw_s1, raw_s2


def ref_moe(x, w1, w2, topk_w, topk_ids):
    out = torch.zeros_like(x, dtype=torch.float32)
    for e in topk_ids.unique().tolist():
        tok, slot = (topk_ids == e).nonzero(as_tuple=True)
        h = x[tok].float() @ w1[e].float().t()
        g, u = h.chunk(2, dim=-1)
        y = (torch.nn.functional.silu(g) * u) @ w2[e].float().t()
        out.index_add_(0, tok, y * topk_w[tok, slot, None])
    return out.to(x.dtype)


E2M1 = [0.0, 0.5, 1.0, 1.5, 2.0, 3.0, 4.0, 6.0]


def dequant_mxfp4(q, scale):
    """Packed E2M1 (low nibble first) x E8M0 scales over 32-element groups."""
    lut = torch.tensor(E2M1 + [-v for v in E2M1], device=q.device)
    vals = torch.stack([lut[(q & 0xF).long()], lut[(q >> 4).long()]], dim=-1)
    vals = vals.flatten(-2)
    sc = torch.exp2(scale.float() - 127).repeat_interleave(32, dim=-1)
    return vals * sc


def qdq_mxfp4(x):
    """Fake MXFP4 quant with the CUTLASS quantizer's E8M0 rule (see
    compute_reference_e8m0_scale in tests/kernels/moe/test_mxfp4_moe.py)."""
    xf = x.float().unflatten(-1, (-1, 32))
    amax = xf.abs().amax(-1, keepdim=True)
    bits = amax.view(torch.int32)
    exp = (((bits + (1 << 21)) & 0x7F800000) >> 23) - 2
    exp = exp.clamp(0, 254)
    sc = torch.exp2(exp.float() - 127)
    mag = (xf.abs() / sc).clamp(max=6.0)
    grid = torch.tensor(E2M1, device=x.device)
    mid = (grid[1:] + grid[:-1]) / 2
    idx = torch.bucketize(mag, mid)
    return (grid[idx] * sc * xf.sign()).flatten(-2)


def emu_moe(x, w1d, w2d, topk_w, topk_ids):
    out = torch.zeros_like(x, dtype=torch.float32)
    xq = qdq_mxfp4(x)
    for e in topk_ids.unique().tolist():
        tok, slot = (topk_ids == e).nonzero(as_tuple=True)
        h = (xq[tok] @ w1d[e].t()).to(x.dtype).float()
        g, u = h.chunk(2, dim=-1)
        a = qdq_mxfp4((torch.nn.functional.silu(g) * u).to(x.dtype))
        y = (a @ w2d[e].t()).to(x.dtype).float()
        out.index_add_(0, tok, y * topk_w[tok, slot, None])
    return out.to(x.dtype)


def emu_check(n, ms, device):
    """CUTLASS must track a W4A4 emulation far more closely than either tracks
    bf16; otherwise the kernel adds error beyond MXFP4 quantization."""
    gen = torch.Generator(device=device).manual_seed(2)
    w1, w2, q1, s1, q2, s2, r1, r2 = make_weights(n, device, gen)
    w1d, w2d = dequant_mxfp4(q1, r1), dequant_mxfp4(q2, r2)
    bad = 0
    for m in ms:
        x = torch.randn((m, K), device=device, dtype=torch.bfloat16, generator=gen)
        topk_w, ids = route(m, device, gen)
        out = torch.empty_like(x)
        ws13 = torch.empty((m * TOPK, max(2 * n, K)), device=device, dtype=x.dtype)
        ws2 = torch.empty((m * TOPK, n), device=device, dtype=x.dtype)
        run_cutlass_moe_mxfp4(
            out,
            x.clone(),
            q1,
            s1,
            q2,
            s2,
            topk_w,
            ids,
            MoEActivation.SILU,
            ws13,
            ws2,
            m,
            n,
            K,
            E,
            device,
        )
        torch.accelerator.synchronize()
        emu = emu_moe(x, w1d, w2d, topk_w, ids)
        ref = ref_moe(x, w1, w2, topk_w, ids)
        d_ce, d_cr, d_er = calc_diff(out, emu), calc_diff(out, ref), calc_diff(emu, ref)
        ok = d_ce < 0.2 * d_er
        print(
            f"emu-check n={n} m={m:5d}: cutlass~emu={d_ce:.5f} "
            f"cutlass~bf16={d_cr:.4f} emu~bf16={d_er:.4f} {'OK' if ok else 'BAD'}"
        )
        bad += not ok
    return bad


def moe_check(n, ms, device):
    gen = torch.Generator(device=device).manual_seed(1)
    w1, w2, q1, s1, q2, s2, _, _ = make_weights(n, device, gen)
    bad = 0
    for m in ms:
        x = torch.randn((m, K), device=device, dtype=torch.bfloat16, generator=gen)
        topk_w, ids = route(m, device, gen)
        out = torch.empty_like(x)
        ws13 = torch.empty((m * TOPK, max(2 * n, K)), device=device, dtype=x.dtype)
        ws2 = torch.empty((m * TOPK, n), device=device, dtype=x.dtype)
        run_cutlass_moe_mxfp4(
            out,
            x.clone(),
            q1,
            s1,
            q2,
            s2,
            topk_w,
            ids,
            MoEActivation.SILU,
            ws13,
            ws2,
            m,
            n,
            K,
            E,
            device,
        )
        torch.accelerator.synchronize()
        d = calc_diff(out, ref_moe(x, w1, w2, topk_w, ids))
        ok = torch.isfinite(out).all().item() and d < 0.05
        print(f"moe-check n={n} m={m:5d}: calc_diff={d:.4f} {'OK' if ok else 'BAD'}")
        bad += not ok
    return bad


def main():
    global E, TOPK, K, N_FUSED
    p = argparse.ArgumentParser()
    p.add_argument("--quant-check", action="store_true")
    p.add_argument("--moe-check", action="store_true")
    p.add_argument("--emu-check", action="store_true")
    p.add_argument("--experts", type=int, default=E)
    p.add_argument("--topk", type=int, default=TOPK)
    p.add_argument("--hidden", type=int, default=K)
    p.add_argument(
        "--n", type=int, nargs="+", default=[512, 256], help="intermediate sizes"
    )
    p.add_argument(
        "--ms",
        type=int,
        nargs="+",
        default=[1, 2, 3, 4, 8, 16, 32, 64, 128, 256, 512, 1024, 2048, 4096],
    )
    a = p.parse_args()
    E, TOPK, K, N_FUSED = a.experts, a.topk, a.hidden, a.n[0]
    device = torch.device("cuda")
    torch.set_grad_enabled(False)
    bad = 0
    if a.quant_check:
        bad += quant_check(device)
    if a.moe_check:
        for n in a.n:
            bad += moe_check(n, a.ms, device)
    if a.emu_check:
        for n in a.n:
            bad += emu_check(n, [1, 8, 64, 512], device)
    print(f"RESULT: {'FAIL' if bad else 'PASS'} ({bad} bad cases)")
    sys.exit(1 if bad else 0)


if __name__ == "__main__":
    main()

## Details

**Root cause.** The MXFP4 experts-quant kernel (#37463) was adapted from the NVFP4 one four days before #40351 fixed this there. The fix never reached the MXFP4 copy.
- **Low-latency kernel** (no `blockRepeat`, i.e. small `m_topk`; which covers decode and the CUDA-graph capture sizes): it loads offsets 16 at a time, `[chunk, chunk + 16]`, with no bound. For example, with E=20 the last chunk starts at 16 and reads `expert_offsets[21..32]` from a 21-entry array. If a stale value there brackets a row, the row gets a bogus `expert_idx`. `output_scale_offset_by_experts[expert_idx]` (also out of bounds) then sends the E8M0 scale writes outside the scale buffer (illegal address), or into another expert's block (wrong scales, garbage output).
- **Shared-memory kernel** (large `m_topk`): it copies offsets into shared memory 4 at a time, which reads and writes past the end when E % 4 != 0.

Existing MXFP4 tests only use power-of-two expert counts up to 32, which never take the broken branches.

**Fix.** These are the same dispatch guards as #40351: take the vectorized lookups only for full 16- or 4-expert chunks, and otherwise use the scalar `SMALL_NUM_EXPERTS` specialization. The scalar low-latency lookup does a linear scan over E offsets, as NVFP4 already does for these expert counts. I have not microbenchmarked it.

@shivankur-code I pushed an update with extra tests.

- **`test_mxfp4_experts_quant_shared_offsets_path`**, E ∈ {20, 21, 22, 23}, both quantizers.
  - It sizes `m_topk` from the device so that work items > SMs × max threads per SM. Since
    `block * grid` never exceeds that, this guarantees `blockRepeat > 1` on any GPU.
  - Experts are uneven, with one empty. Every row's FP4 bytes and E8M0 scales must match a
    single-expert call on the same rows: both are per row, so only scale placement depends on the
    expert lookup.
- **E=21 added to the poisoned-tail test**, for the low-latency side.

On GB200 the experts-quant tests pass (20 passed).

As you said, outputs can't show the old shared-memory over-read, so I also ran both quantizers
under `compute-sanitizer --tool memcheck`. The two offset arrays were in their own exact-size
`cudaMalloc` allocations (E+1 int32s), with one process per case, since the first error kills the
context. Both kernels, E ∈ {20, 21, 22, 23, 24, 40, 41, 48}:

| kernel | pre-fix (v0.31.0) | this PR |
|---|---|---|
| low-latency (`blockRepeat == 1`, 16-wide lookup) | out-of-bounds reads for every E % 16 ≠ 0 (20–24, 40, 41); E=48 clean | 0 errors |
| shared-memory (`blockRepeat > 1`, 4-wide copy) | out-of-bounds reads for E = 21, 22, 41 (E % 4 = 1, 2); clean for E % 4 = 0 **and for E % 4 = 3** | 0 errors |

The E % 4 = 3 result makes sense. The last 4-wide chunk then covers `offsets[E-3..E]`, and
`offsets[E]` is valid. So the old copy over-read only for E % 4 ∈ {1, 2}, by 2 and 1 entries. The
guard (`n_experts % 4 == 0`) also sends E % 4 = 3 to the scalar path. That's safe, just slightly
more conservative than needed. I kept it simple rather than special-casing E % 4 = 3, but I'm happy
to relax it if you'd prefer.
