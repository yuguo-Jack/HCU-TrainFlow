# [Bugfix][Frontend] Keep completion derender stream logprob offsets aligned with tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/62163) · state: open · merged: False

## Original PR description



## Overview

Keep streaming completion derender logprob offsets aligned with reported token strings, matching batch derender and the coupled completion fix in #60668.

## Claims

- A special token filtered from response text no longer shifts subsequent streaming `logprobs.text_offset` backwards relative to batch output.
- Missing/empty logprob metadata retains the existing emitted-text fallback; response text and token IDs are unchanged.

## Validation

Before the fix, the final regression/neighbor selection returned **2 failed, 14 passed**; with the fix, **16 passed**. The two failures are the skip-special-token cases at chunk sizes 1 and 2. With `ignore_eos=true`, `hello`, `</s>`, ` world` produced streaming offsets `[0,5,5]` versus batch `[0,5,9]`; the fix gives `[0,5,9]` in both modes.

Before publication, copied the complete tracked source at `b05ede56168b5718c425c1493914e5e79f6b8181` (including merged #62114) into an isolated Linux CPU validation directory, applied this patch, and ran both the offset selections and #62114's generated-ID regression together: **22 passed, 147 deselected in 5.94s**, exit 0.

## Details

Within a chunk, logprob conversion advances offsets using the reported token strings. Across chunks, derender instead advanced the carried offset by `len(new_text)`. These differ when decoding filters special tokens, so the next chunk restarted too early. Carry the end of the last reported logprob token when available, preserving the prior fallback otherwise.

The existing ordinary-text offset test now encodes without an automatic BOS, making its text-length assumption explicit; the new parametrized test separately covers filtered/preserved special tokens and both chunk sizes.

Fresh open/all-state searches for `60668 in:body`, `derender offset`, `derender text_offset` and `logprob_text_offset` found no competing fix. Related #59510 handles stops and retains the old offset update; #60918 affects coupled packed logprobs, and #60542 changes generate logprob representation rather than this derender state update. #62114 is already merged and preserves token IDs; this PR is based on that merge and fixes a separate metadata field.
