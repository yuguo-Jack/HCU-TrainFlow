# Fix gpt-oss required tool choice constraints

[Upstream PR](https://github.com/vllm-project/vllm/pull/45547) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #44216.

For gpt-oss/Harmony chat completions, function tools were rendered into the Harmony prompt, but the Harmony render path did not run the tool parser request adjustment that attaches guided decoding constraints. This meant `tool_choice=required` could be ignored by generation. The GPT-OSS tool parser now declares the Harmony structural-tag backend, and Harmony rendering applies request adjustment so required/named tool choices can constrain output to Harmony tool-call syntax.

## Test Plan

- Add regression coverage that `tool_choice=required` on a GPT-OSS Harmony chat request installs a Harmony structural tag during render.
- Cover the GPT-OSS tool parser in the structural-tag parser declaration test.
- Run local whitespace and syntax checks.
