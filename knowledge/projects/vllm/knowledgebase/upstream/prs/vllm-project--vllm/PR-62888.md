# [CPU] Warm up MRV2 Triton kernels at startup

[Upstream PR](https://github.com/vllm-project/vllm/pull/62888) · state: closed · merged: True

## Original PR description

## Purpose

On x86 CPU the V2 model runner compiles its scheduler-driven Triton kernels (`input_batch`, `block_table`, the sampler, KV-block zeroing, ...) on first use, so the first requests after server start pay the compile in TTFT. With `triton-cpu` (installed by `requirements/cpu.txt` on `x86_64` since #58140) the first plain request waits ~11-20 s, and the first request using penalties or structured output waits 70-80 s.

Two changes:

- **Run `warmup_kernels` on CPU.** The GPU worker calls it from `compile_or_warm_up_model`, but `CPUWorker` overrides that method and never did. `profile_run` alone builds its tensors directly, so it never reaches these kernels.
- **Use `BLOCK_SIZE = 1024` on CPU for `_penalties_kernel` and `_apply_grammar_bitmask_kernel`.** 

## Test Plan

- End to end: Qwen3.5-9B, BF16, `--kv-cache-dtype fp8_e4m3`,  `--max-model-len 2048`, v0.32.0 CPU wheel with and without each change, cold Triton cache, AMD EPYC Turin (32 cores). Rounds of 2 concurrent streaming requests (512 input / 32 output tokens); rounds 2-4 each enable one sampler feature for the first time.
- Cold compile and steady-state runtime of the two bitmask kernels per block size (Qwen3.5 vocab, 248320), with OpenMP threads bound as in the CPU worker.

## Test Result

TTFT of the first request in each round (s), and engine init:

| build | engine init | plain | penalties | structured output | temperature / top-p / top-k | plain, steady | compiles in requests |
|---|---|---|---|---|---|---|---|
| v0.32.0 | 84 s | 20.2 | 81.0 | 73.7 | 11.0 | 1.7 | 32 |
| + `warmup_kernels` only | 317 s | 4.3 | 1.7 | 2.5 | 1.7 | 1.7 | 2 |
| + this PR | 100 s | 3.9 | 1.7 | 2.5 | 1.7 | 1.7 | 2 |

Bitmask kernels, cold compile per kernel and runtime at 64 tokens:

| BLOCK_SIZE | `_penalties_kernel` compile | `_apply_grammar_bitmask_kernel` compile | LLVM IR | penalties runtime | bitmask runtime |
|---|---|---|---|---|---|
| 1024 | 1.7 s | 1.4 s | 0.8 MB | 403 µs | 102 µs |
| 2048 | 2.4 s | 2.1 s | 3.0 MB | 400 µs | 99 µs |
| 8192 | 71.0 s | 70.5 s | 47.9 MB | 764 µs | 151 µs |
