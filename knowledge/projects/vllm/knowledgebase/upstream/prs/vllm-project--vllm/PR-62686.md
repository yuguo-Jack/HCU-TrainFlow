## Original PR description

# [CI][AMD] Shard the MI300 V1 Spec Decode step

## The failure

`:amd: (MI300) V1 Spec Decode` timed out in AMD CI nightly [15028](https://buildkite.com/vllm/amd-ci/builds/15028) after 50m57s against a 50 minute limit. Nothing failed: the job was killed with 467 of 494 tests done, in the middle of `test_speculators_eagle3.py::test_eagle3_speculators_model[llama3-eagle3-speculator]`.

## The problem

The step runs the whole suite in one job and has been growing for weeks:

| build | date | selected | duration |
|---|---|---|---|
| 14162 | 7 Oct | 377 | 27:30 |
| 14707 | 15 Oct | 378 | 31:45 |
| 14810 | 16 Oct | 386 | 33:28 |
| 14934 | 19 Oct | 494 | 38:43 |
| 15028 | 20 Oct | 494 | killed at 50:57 |

14934 and 15028 ran an identical set of 494 tests, so the last 12 minutes did not come from new tests. Weight loading did: 686 s over 39 loads in 14934 against 1513 s over 37 loads in 15028, which is half of the job's wall time. Cold reads sustain only 16-19 MB/s per stream on these agents, and because `_prefetch_checkpoint` reads each file with one sequential loop, a 4-shard checkpoint can only use 4 of the 8 prefetch threads. The two jobs also ran on different nodes, `gpu90e3` and `gpu8e72`, with different amounts of pre-existing page cache.

Two things rule out the suite itself. The same command on `:amd: (MI355 DPX) V1 Spec Decode` finishes in 23.9, 24.0 and 24.3 minutes in the same three builds. And compute is not growing: torch.compile accounts for 80 s of the 51 minutes, and AITER does no JIT compilation at all, it imports the prebuilt `module_aiter_core.so`.

## The change

Shard the step across two jobs with the `--shard-id` / `--num-shards` pattern already used by the other 30 sharded MI300 and MI355 steps in this file. The upstream mirror for this step in `.buildkite/test_areas/spec_decode.yaml` sets `automatic_shard: true`, which upstream CI resolves to two shards; `test-amd.yaml` has no equivalent key, which is why this one step kept absorbing the growth.

Two is what the same step already runs as upstream, where the shards finish in 23.2 and 18.1 minutes in `vllm/ci` 95866, and 16.0 and 15.3 minutes in 96000. Each shard still pays the cold checkpoint reads for the models it touches, so this is not a clean halving; upstream 96100 shows one shard at 38.7 minutes on a slow node, which is the same storage effect described above.
