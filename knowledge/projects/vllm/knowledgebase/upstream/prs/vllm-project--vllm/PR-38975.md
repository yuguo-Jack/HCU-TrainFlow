# [KV] Sync `_prob_scale_float` and `q_scale`

[Upstream PR](https://github.com/vllm-project/vllm/pull/38975) · state: closed · merged: False

## Original PR description

This PR addresses 2 issues for KV-cache quantization. See comment below for repro.

#### Issue 01: `_prob_scale_float` sync error

After loading checkpoint, `_prob_scale_float` (cache after CUDA graph) is not updated, although `_prob_scale` (tensor) is updated. Add update logic for correct sync

#### Issue 02: Broken `q_scale` fallback

Inside `use_static_kv_scales` block, `q_scale = 1.0` is always executed with override, ignoring fallback. Fix for correct fallback handler

The check `layer.kv_cache_dtype == "fp8"` is too restrictive. In vLLM, the KV cache data type can be specified as `fp8`, `fp8_e4m3`, or `fp8_e5m2`. Using a strict equality check here will cause this warning to be skipped for users explicitly setting `fp8_e4m3`, even though they are using the same FP8 attention path that requires these scaling factors. It is better to use a more inclusive check like `startswith("fp8")` or `is_quantized_kv_cache` (though the latter also includes int8).

```suggestion
        if layer.kv_cache_dtype.startswith("fp8") and (q_scale == 1.0 or prob_scale == 1.0):
```

File: `vllm/model_executor/layers/quantization/kv_cache.py` · line 147

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The `_from_checkpoint` helper function calls `param.item()` without verifying that the parameter is a scalar. While `q_scale` and `prob_scale` are initialized as scalars in `create_weights`, a checkpoint could potentially contain non-scalar values (e.g., per-channel scales), which would cause `param.item()` to raise a `ValueError`. It is safer to check `param.numel() == 1` before calling `.item()`, maintaining the validation logic that was previously present for these scales.

```suggestion
        def _from_checkpoint(param: torch.nn.Parameter) -> float | None:
            """Return the FNUZ-adjusted float scale, or None if absent."""
            if param.numel() != 1:
                raise ValueError("Only support per-tensor scaling factor")
            val = param.item()
            if val > 0.0:
                return val * (2 if current_platform.is_fp8_fnuz() else 1)
            return None
```
