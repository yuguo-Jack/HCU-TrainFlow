# [Bugfix][KV Offload] Preserve SWA null-page offsets after store retry

[Upstream PR](https://github.com/vllm-project/vllm/pull/65279) · state: closed · merged: True

## Original PR description

## Overview

When a CPU offload store is retried after capacity exhaustion, SWA can release a GPU block and reallocate it for another logical position. The offloading scheduler marks the old position as `NULL_BLOCK_ID` but removes it from the source spec, so later pages shift into the wrong positions in the destination CPU chunk and can be loaded back as incorrect KV data.

## Claims

- Preserve the logical page layout of every full SWA chunk in the GPU-to-CPU store spec, including null blocks as placeholders for unreachable pages.
- Prevent store retries from corrupting the mapping between GPU source pages and CPU chunk offsets.
- Add a scheduler regression test with a mocked store failure and SWA block reuse.

Without the fix, the generated store spec contains only 8 source pages and skips the internal null page. With the fix, it contains all 9 logical pages with `group_sizes=[9]` and `block_indices=[0]`.

A separate validation with the real `CPUOffloadingManager`, scheduler, offloading handler, and CUDA transfers reproduced the data error before the fix: loading logical pages 7 and 8 returned `[9, -99]` instead of `[8, 9]`. After the fix, the stored chunk was `[0, 8, 9]` and loading logical pages 7 and 8 returned `[8, 9]`.

No model-level evaluation was performed. The V1 KV Connectors GPU CI job is currently disabled, so the regression test was run manually.

## Details

`prepare_store()` can return `None` when all CPU chunks are held by in-flight loads and no chunk is free or evictable. During the retry window, SWA may release a GPU block and reallocate it for another position. The offloading scheduler then marks the old logical position as `NULL_BLOCK_ID`. `_build_store_jobs()` previously dropped that null block when building `GPULoadStoreSpec.block_ids`. The remaining pages were then packed without their original logical offset, although the destination CPU chunk still reserved a slot for every page in the full chunk.

The fix keeps null blocks as placeholders for unreachable pages in the source spec so source and destination chunk offsets remain aligned. Null blocks are excluded from the fence set because block 0 is the permanently reserved GPU null block and is not a live allocation.

Unlike #62932, which bounds secondary-tier loads by CPU capacity, this fixes GPU-to-CPU store page alignment after a retry.

The change is limited to source-spec construction in `OffloadingConnectorScheduler` and one focused regression test. It does not change admission, eviction, retry, or partial-tail behavior.
