# [XPU] Support register KV offload mmap region as pinned host memory on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/51956) · state: closed · merged: True

## Original PR description

## Summary

Extends the CPU KV-cache offloading path's mmap host registration to Intel XPU, and factors the CUDA/ROCm `cudaHostRegister`/`cudaHostUnregister` calls out into a small platform-dispatching helper module.

## Test Plan


Server:
```bash
VLLM_LOGGING_LEVEL=DEBUG vllm serve Qwen/Qwen2.5-0.5B-Instruct \
  --max-model-len 2048 \
  --enforce-eager \
  --gpu-memory-utilization 0.3 \
  --enable-prefix-caching \
  --kv-transfer-config '{
    "kv_connector": "OffloadingConnector",
    "kv_role": "kv_both",
    "kv_buffer_device": "xpu",
    "kv_connector_extra_config": {"block_size": 64, "cpu_bytes_to_use": 67108864}
  }' > xpu_host_offload.log 2>&1
```

Client: 40 distinct long (~1400-token) prompts to force repeated host offload/eviction (`test.sh`), followed by a re-send of the first prompt to trigger a reload (`test2.sh`):
```bash
for i in $(seq 1 40); do
  python3 -c "
import requests, random, string
random.seed($i)
filler = ' '.join(''.join(random.choices(string.ascii_lowercase, k=6)) for _ in range(400))
r = requests.post('http://localhost:8000/v1/completions', json={
    'model': 'Qwen/Qwen2.5-0.5B-Instruct',
    'prompt': f'request-$i {filler} Summarize in one word:',
    'max_tokens': 8, 'temperature': 0})
print($i, r.json()['choices'][0]['text'])
"
done
```

## Test Result

Ran on 1x Intel XPU GPU with this PR's code  

- Host pinned-memory registration path exercised successfully:
  ```
  DEBUG [v1/kv_offload/cpu/gpu_worker.py:234] Host-registered mmap region rank=0 0.07 GB in 1 chunk(s)
  ```
- All 41 requests (40 distinct prompts + 1 repeat) completed with `200 OK`; zero `ERROR`/`Traceback` lines in the server log over the full run.
- KV offload metrics confirm the offloading pipeline was continuously active against the XPU-pinned host region, e.g.:
  ```
  vllm:kv_offload_store_bytes=314572800, vllm:kv_offload_store_size_count=19, ...
  vllm:kv_offload_lookup_sync_delay_seconds_count=19, ...
  ```
- No crashes, hangs, or XPU errors observed across the full 40+1 request run.
