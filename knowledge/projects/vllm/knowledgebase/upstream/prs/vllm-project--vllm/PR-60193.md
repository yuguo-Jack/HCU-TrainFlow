# [ROCm][Kimi-K3] Apply MLA RoPE with the cached AITER kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/60193) · state: open · merged: False

## Original PR description

## Purpose

Kimi-K3 AMD MLA was compiling the cos/sin table into a pointwise kernel on every layer. `apply_kimi_k3_rope` reads the table already stored on the module and calls the cached AITER rotary op. `VLLM_ROCM_USE_AITER_TRITON_ROPE` stays off. AITER off keeps the module's own forward. Shared RoPE classes are not modified.

On the Kimi-K3 MI355X decode trace the old pointwise kernel ran 24 times a step at about 4.1 µs. This patch has not been re-timed.

## Test Plan

```bash
pytest tests/models/kimi_k3/test_amd_mla_direct_return.py::test_kimi_k3_rope_uses_cached_aiter_op
```

The test checks that the cached op matches the module's native RoPE, that the op is called once when AITER is on, that the compiled graph does not rebuild the table, and that AITER off does not call the op.

## Test Result

not run. This host does not have PyTorch, so the ROCm test was not executed.
