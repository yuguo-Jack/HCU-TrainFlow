# [Security] Do not retain Phi-4 MM audio attention matrices

[Upstream PR](https://github.com/vllm-project/vllm/pull/60614) · state: closed · merged: True

## Original PR description

## Summary

Phi-4 multimodal audio conformer attention (eager path) stored the full attention probability matrix on each encoder layer module. For a legal max-length audio clip this pinned multi-GiB tensors across the 24-layer stack and after the request completed, causing CUDA OOM and EngineCore death. The fix stops retaining those tensors and defaults the encoder to PyTorch scaled-dot-product attention so the dense probability matrix is not materialized in the common serving path.

## Changes
- `phi4mm_utils.py`: remove `self.attn` retention; default `use_pt_scaled_dot_product_attention` to `True`.
- `phi4mm_audio.py`: match the SDPA default on `ConformerEncoder` / `ConformerEncoderLayer`.
- `tests/model_executor/test_phi4mm_attention.py`: assert eager path does not retain matrices and the default uses SDPA.

## Codepath coverage
- All Phi-4 MM audio entry points reach a single sink (`MultiHeadedAttention.forward`); that sink no longer stores attention probabilities, and the serving default avoids materializing them.

## Duplicate-work check
Searched open/merged PRs for `phi4mm_utils`, `phi4mm_audio`, `MultiHeadedAttention`, and `use_pt_scaled_dot_product_attention`. Closest open PR (#47225) only changes streaming-mask device placement and does not touch attention retention. No existing PR closes this sink.

## Tests
- `test_eager_attention_does_not_retain_probability_matrix` — eager forward leaves no retained `attn` tensor on the module.
- `test_multiheaded_attention_defaults_to_scaled_dot_product` — SDPA is the default.
- Command: `.venv/bin/python -m pytest tests/model_executor/test_phi4mm_attention.py -v` — 2 passed.
