# [KVConnector][MoRIIO] Infer control interface and clarify network setup

[Upstream PR](https://github.com/vllm-project/vllm/pull/46504) · state: open · merged: False

## Original PR description


## Summary

This PR improves MoRIIO control-plane setup on multi-NIC hosts and expands the usage guide for common RDMA deployments.

When `host_ip` is not provided, MoRIIO now derives it from the kernel-selected source IP for the route to `proxy_ip`. If `MORI_SOCKET_IFNAME` is unset, vLLM maps that selected source IP back to its local interface and sets `MORI_SOCKET_IFNAME` before MoRI initializes.

Explicit user configuration remains authoritative:

```text
host_ip = configured host_ip if set
        = non-loopback route source IP for proxy_ip if available
        = get_ip() fallback otherwise

if MORI_SOCKET_IFNAME is unset:
    MORI_SOCKET_IFNAME = interface owning host_ip

# vLLM does not change:
# - existing MORI_SOCKET_IFNAME
# - MORI_RDMA_DEVICES
# - MORI_IB_GID_INDEX
```

## Why

Before this change:

- unset `host_ip` used `get_ip()`
- unset `MORI_SOCKET_IFNAME` let MoRI pick the first non-loopback UP/RUNNING IPv4 interface from `getifaddrs()`

On multi-NIC hosts, those fallbacks can disagree or select an interface that cannot reach the MoRI proxy/router.

## Scope

- Infer `host_ip` from the route to `proxy_ip` when `host_ip` is omitted.
- Require `proxy_ip` when `host_ip` is omitted.
- Avoid auto-selecting loopback/unspecified addresses as advertised `host_ip`.
- Set `MORI_SOCKET_IFNAME` only when it is unset.
- Use only Python stdlib socket/ioctl APIs; no dependency on `ip`, `rdma`, `ibv_devinfo`, `netifaces`, or `psutil`.
- Do not infer RDMA device or GID policy.

## Docs

The MoRIIO usage guide now documents:

- when to use real `proxy_ip` values vs local-only `127.0.0.1`
- when `host_ip` can be omitted and how it is inferred
- how `MORI_SOCKET_IFNAME`, `MORI_RDMA_DEVICES`, and `MORI_IB_GID_INDEX` are handled
- `proxy_ping_port`, `http_port`, `handshake_port`, and `notify_port` requirements
- Docker flags needed for RDMA inside ROCm vLLM containers
- host-network MiniMax M3 RDMA examples for 1P1D and 2P1D setups
