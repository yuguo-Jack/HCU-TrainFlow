# [Refactor][Worker] Expose platform executor and PP orchestration hooks

[Upstream PR](https://github.com/vllm-project/vllm/pull/65565) · state: open · merged: False

## Original PR description

## Overview
Expose narrow Worker hooks required by vllm-project/vllm-ascend#18920 to inherit common orchestration without importing the CUDA elastic EP chain or copying the PP loop.

## Claims
- Profiler validation is overridable before CUDA activity validation, preserving NPU profiler configuration.
- Executor construction is overridable before the lazy elastic EP import.
- Device workers select PP gather groups and process connector output through hooks.
- A pre-execution hook preserves iteration bookkeeping, including empty batches.
- Default GPU behavior, metadata/device handle ownership, and pooling are unchanged.

## Validation
Ruff check and format pass. A CPU regression using the real Worker constructor, a small CPU runner and an external transport double was added to `tests/v1/worker/test_gpu_worker.py` and the CPU CI step.
Attempted `uv run --no-project --python C:/Users/liurong/AppData/Local/miniconda3/python.exe python -m pytest tests/v1/worker/test_gpu_worker.py -k platform_worker_inherits_pp_orchestration --collect-only -q`: collection fails importing local torch (`WinError 1114`, c10.dll). Runtime tests and serving validation are outstanding; no NPU validation was requested or performed. This PR remains draft for validation.

## Details
Based on Ascend's verified vLLM commit 24420b7a so the dependent migration can pin this exact contract. Searches for RFC 18920 and both new hook names found no overlapping open PR; #49700 concerns EPLB lifecycle, not Worker PP/executor construction. The defaults are extracted from the existing methods, with no device detection in the execution path.
AI assistance was used for implementation, tests and this description. Human line review and runtime validation remain pending; publication as a draft is explicitly requested by the submitter's current task.
