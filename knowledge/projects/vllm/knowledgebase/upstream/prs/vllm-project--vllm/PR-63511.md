# [Bugfix][KV Connector] Preserve Mooncake decode saves under async MTP

[Upstream PR](https://github.com/vllm-project/vllm/pull/63511) · state: open · merged: False

## Original PR description

## Overview

Keep Mooncake decode saves within the committed block-hash frontier before advancing the scheduler's save cursor, and flush the final confirmed full blocks when a request finishes. Fixes #51805 while preserving async scheduling, speculative decoding, and decode KV offload.

## Claims

- Defer unconfirmed decode blocks without advancing past them, so delayed hashes do not leave a permanent external-cache gap.
- Snapshot hashes for queued metadata and pin the final confirmed save before the request releases its GPU blocks.
- Preserve current-step prefill overlap and partial-tail behavior; add no CUDA synchronization or execution-mode switches.

## Details

Related open PR #51820 clamps the worker-side save length after scheduler bookkeeping and explicitly leaves a possible resume-offset gap. This change instead caps decode metadata before `RequestTracker.num_saved_tokens` advances, and addresses the request-finish case where no subsequent decode step can pick up the delayed final block. The distinction is also described on #51805.

Minimal PD flow: P computes/transfers the prompt; D's async MTP schedule can run ahead of committed token hashes; Mooncake metadata must only queue confirmed full blocks; after the last accepted output, the finish callback queues any remaining confirmed full prefix while holding the existing block-pool references until every worker acknowledges completion. In-flight tokens are excluded using the same computed-minus-in-flight frontier used by the core scheduler.

The change stays within Mooncake's scheduler/metadata/connector code. The queued finish job reuses the existing store-job pin and acknowledgment lifecycle. Prefill saves keep their existing overlap and partial-tail handling.
