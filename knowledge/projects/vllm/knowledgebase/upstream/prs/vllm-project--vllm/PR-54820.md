# [ROCm] Avoid DSpark placeholder shared vocab allocations

[Upstream PR](https://github.com/vllm-project/vllm/pull/54820) · state: open · merged: False

## Original PR description

## Purpose

DeepSeek-V4 DSpark on ROCm was allocating draft-side placeholder `embed_tokens` and `lm_head` modules even though the AMD DSpark draft model does not own those weights in steady state.

For this model family, `load_dspark_model()` aliases the target model's shared vocab modules into the draft model. That means the placeholder allocations were only transient startup overhead. On the Strix Halo TP=2 bring-up that overhead was large enough to matter: about `0.863 GiB` per placeholder per rank, or about `1.73 GiB` per rank combined.

This also matches an existing DSpark pattern already in tree: `vllm/models/kimi_k3/nvidia/dspark_mla.py` <https://github.com/vllm-project/vllm/blob/main/vllm/models/kimi_k3/nvidia/dspark_mla.py> sets `has_own_embed_tokens = False` and `has_own_lm_head = False`, keeps `embed_tokens` and `lm_head` as `None`, and relies on target-model aliasing after draft loading.

This PR narrows the fix to the ROCm implementation only:

- change `vllm/models/deepseek_v4/amd/dspark.py`
- keep `embed_tokens` as `None` until `load_dspark_model()` aliases the target module
- keep `lm_head` as `None` until `load_dspark_model()` aliases the target module
- add defensive assertions before those modules are used
- remove now-unused placeholder allocation imports

## Test Plan

Validate this change on a 2-node Strix Halo TP=2 ROCm setup by applying the no-placeholder DSpark behavior and checking the following runtime outcomes:

- repeated DSpark server startup tests after removing the placeholder shared-vocab allocations, using `gpu_memory_utilization` values of `0.30`, `0.34`, `0.38`, `0.42`, `0.46`, `0.50`, `0.60`, `0.70`, `0.80`, `0.90`, `0.93`, `0.95`, `0.97`, and `0.99`
- offline DSpark-vs-baseline TP=2 comparison

## Test Result

On a 2-node Strix Halo TP=2 ROCm setup, applying the no-placeholder DSpark change removed the transient draft-side shared-vocab allocations and improved DSpark startup behavior.

Startup-memory impact:

- removed about `1.73 GiB` transient draft-side startup allocation per rank for the shared vocab placeholders combined; this savings comes from eliminating two fixed-size placeholder modules, so it is the same regardless of which `gpu_memory_utilization` setting was used in the startup tests
- after the no-placeholder patch, the old immediate DSpark startup-memory failure mode no longer reproduced in the startup sweep

Offline TP=2 DSpark benchmark summary (E2E latency per request):

| Input -> Output | Baseline E2E latency | DSpark E2E latency | Speedup |
| --- | ---: | ---: | ---: |
| `1024 -> 128` | `178.63s` | `44.39s` | `~4.0x` |
| `4096 -> 256` | `608.98s` | `85.91s` | `~7.1x` |
| `8192 -> 256` | `375.22s` | `86.00s` | `~4.4x` |
