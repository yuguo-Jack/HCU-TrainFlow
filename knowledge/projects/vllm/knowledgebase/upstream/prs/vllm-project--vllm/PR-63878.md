# [ROCm][Perf][DSA] Honor skip_kv_gather in the ROCm sparse-indexer prefill loop

[Upstream PR](https://github.com/vllm-project/vllm/pull/63878) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

On ROCm, the DSA sparse-indexer prefill loop (`rocm_aiter_sparse_attn_indexer`) re-gathers the full indexer K cache for every query sub-chunk of a long request. The metadata builder already marks those continuation sub-chunks `skip_kv_gather=True` and the CUDA path (`sparse_attn_indexer.py`) honors it; this PR adds the same guard to the ROCm loop.

Prior attempts: #46478 and #40049 (both closed unmerged as stale; motivated by #40018). This PR adds the MI300X measurements those lacked.

## Claims

- Removes the redundant per-sub-chunk K gather on ROCm. The logits are unchanged: the skipped gather would write the same rows into the same workspace slice, and nothing writes that slice in between.
- GLM-5.3-FP8 on MI300X (gfx942), warm 512K-context prefill at the default `VLLM_SPARSE_INDEXER_MAX_LOGITS_MB=512`: TTFT **39.2 / 39.8 s → 36.3 / 37.2 s** on a `main` nightly (−7%). In-server K-gather time per request **2.8 s → 0.12 s**. With a 64 MB budget (more sub-chunks), TTFT **70.1 s → 52.2 s**.

## Validation

**Setup.** GLM-5.3-FP8 (`GlmMoeDsaForCausalLM`, DSA indexer on 21 of 78 layers). 1P1D PD disaggregation on 2× 8×MI300X, DP8/EP8 prefill + DP8/EP8 decode, MoRIIO WRITE, prefix caching on, AITER + FlyDSL `fp8_mqa_logits`.

**Workload.** A single request (c1) through the PD proxy, streaming. "Warm 512K" means a 457.5K-token cached prefix plus 65.6K new tokens, so 523K total. The same prompts are used in every arm. Two reps per arm.

**On `main`.** `vllm/vllm-openai-rocm` nightly built from `00b6c4c565` (HIP 7.15, AITER 0.1.26); `rocm_aiter_mla_sparse.py` there is byte-identical to this PR's base. "With guard" is the same image with this PR's file copied in. That image also carried the files of #63879 and #63880, which only touch the MoRIIO connector.

**Correctness with the guard (v0.32.0).**
- NIAH at 256K (261,586 tokens) and 512K (523,205 tokens), depths 0.1/0.5/0.9: 3/3 at each length.
- 8 concurrent distinct 64K needles × 2 rounds: 16/16.
- Coherence gate (chat + completion at c1 and c8): pass.

**Unit tests.** There is no new unit test. This is a performance-only change, and the output is identical with or without the guard, so no output assertion can fail without the fix. The existing ROCm sparse-MLA kernel tests cover the loop's numerics.

<details>
<summary>Why the gather repeats</summary>

`_split_indexer_prefill_chunks` bounds the logits buffer: at depth N, one sub-chunk holds about `MAX_LOGITS_MB / (4·N)` query rows. For one 8192-token prefill step at 491K depth, that is 31 sub-chunks at 512 MB and 241 at 64 MB. All sub-chunks of a request use the same `block_table` / `cu_seq_lens`. `build_prefill_chunk_metadata` sets `skip_kv_gather = query_slice.start > 0` for every sub-chunk after the first. The ROCm loop ignored the flag, so each of those sub-chunks ran `cp_gather_indexer_k_quant_cache_triton` over the full K range again.
</details>

## Details

- The change is the same `skip_kv_gather` guard used by `sparse_attn_indexer.py` (CUDA) and `models/glm5next/amd/sparse_indexer.py`. ROCm has no PCP/DCP-local extents, so there is no `local_total_seq_lens` check. Chunks with `total_seq_lens == 0` are already dropped by the builder.
- There is no new host/device synchronization; the change only skips a kernel launch, based on host-side metadata.
- **CI coverage gap:** CI does not run a long-context DSA prefill on ROCm. The numbers above were measured outside CI on MI300X.
- Not part of this PR: #63038 changes chunk budgeting for CUDA only and does not touch this loop.
