# [Bugfix][Quantization] Reject unsupported compressed tensors KV cache schemes

[Upstream PR](https://github.com/vllm-project/vllm/pull/45312) · state: closed · merged: True

## Original PR description


## Purpose

`CompressedTensorsKVCacheMethod.validate_kv_cache_scheme` uses `and` when checking the supported KV cache scheme:

```python
if type_ != "float" and num_bits != 8:
```

That only rejects schemes where both fields are wrong. Half wrong schemes such as `{"type": "float", "num_bits": 4}` and `{"type": "int", "num_bits": 8}` pass validation even though the validator message says the supported scheme is `num_bits=8, type=float`.

The fix changes the condition to `or`, so either unsupported field rejects the scheme before it reaches the fp8 KV cache path.

## Test Plan

Added one focused validator regression test to the existing compressed tensors quantization test file. The rejected scheme uses a full legal dictionary with `strategy="tensor"` and `symmetric=True`, so the only unsupported field is `num_bits`.

Validation:

- Run the focused KV cache scheme validator test with the fix.
- Revert only the source change and keep the tests.
- Run an A800 engine A/B check with a TinyLlama compressed tensors checkpoint edited to `type=float, num_bits=4`.
- Run the full pre-commit suite on the changed files.

## Test Result

| Check | Result |
|---|---|
| Focused validator test with fix | `1 passed` |
| Source reverted, test kept | `1 failed`; `float/4` did not raise |

| A800 engine A/B, invalid `float/4` scheme after fix | Early `NotImplementedError`: received `num_bits=4, type=float` |
