# [BugFix]/minicpm ocr downsample mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/64105) · state: closed · merged: True

## Original PR description

## Overview

Pass `downsample_mode` through MiniCPM-OCR image resize when counting visual tokens. transformers 5.21 makes this argument required, and the previous call used the 5.20 signature.

## Claims

- `MiniCPMOcrProcessingInfo._compute_visual_tokens` now passes the image processor's `downsample_mode` to both `find_best_resize` calls and to `get_refine_size`.
- The MiniCPM-OCR processing tests use the same signature, so a missing argument fails the token-count tests.

## Validation
when inferencing or starting server with vllm for [MiniCPM-OCR 1.0](https://huggingface.co/openbmb/MiniCPM-OCR-1.0), met this error.

```
TypeError: MiniCPMOcrImageProcessor.find_best_resize() missing 1 required positional argument: 'downsample_mode'
```

## Details

Root cause: token counting still called `find_best_resize` and `get_refine_size` as in transformers 5.20. In 5.21 those methods require `downsample_mode`, so placeholder sizing raises `TypeError` before inference. 
https://github.com/huggingface/transformers/blob/v5.21/src/transformers/models/minicpm_ocr/image_processing_minicpm_ocr.py#L165-L182

The value passed is `image_processor.downsample_mode` from the processor already pinned for the request, so a per-request override and the checkpoint default stay on the same grid as the pixels.
