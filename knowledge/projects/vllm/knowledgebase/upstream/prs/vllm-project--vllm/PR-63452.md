# [CI] Fix the Domyn Edge (ROCm) and Qwen2 embed HF references

[Upstream PR](https://github.com/vllm-project/vllm/pull/63452) · state: closed · merged: True

## Original PR description

- `test_common.py`: on ROCm, generate the HF reference for `domyn/Domyn-Edge-Base` with `use_cache=False`
- `test_embedding.py`: keep the `ssmits/Qwen2-7B-Instruct-embed-base` HF reference on plain text with mean pooling

`test_models[...domyn/Domyn-Edge-Base]` has failed on MI355 since the model was added in #62544 ([build 96933](https://buildkite.com/vllm/ci/builds/96933/list?jid=01a16a2d-3c10-49ad-af03-b262a50862bd&tab=output)). vLLM's output is correct; it is the HF reference that turns to garbage after the first token. Domyn's remote code decodes through `torch.nn.attention.varlen.varlen_attn`, and on ROCm that op aligns the causal mask to the top left when `max_q < max_k`, so with a KV cache every decode step only sees the first key. Recomputing without the cache keeps `max_q == max_k`, where the ROCm kernel is correct, so vLLM's Domyn coverage on ROCm stays in place. The PyTorch fix is pytorch/pytorch#201930; this part can be dropped once it is in the ROCm image.

The embedding test for `ssmits/Qwen2-7B-Instruct-embed-base` has failed on the CPU pooling job since #62835 bumped sentence-transformers to 5.6 ([build 97015](https://buildkite.com/vllm/ci/builds/97015)), with cosine 0.7963. That checkpoint has no sentence-transformers config, and 5.6 now wraps plain text in the tokenizer's chat template and uses last-token pooling for causal LMs, while the test pins vLLM to mean pooling of the plain text. Removing the `"message"` modality and putting a mean `Pooling` back gives the 5.2 embeddings again, and on older versions it is a no-op.

On MI350X with torch 2.12 and the CI pin 2.13.0+rocm10.0.0, `varlen_attn` with `window_size=(-1, 0)` and 1 query against 40 keys matches a top-left reference exactly, and the HF Domyn reference produces `' ItOlimpiadiOlimpiadi...'` with the KV cache and `' It is designed to run large language models (LLMs) on a wide range'` without it. For the embedding model, sentence-transformers 5.2.0 and 5.6.0 differ by exactly cosine 0.7963 on the same input; with this change, the reference from `HfRunner` under 5.6.0 matches 5.2.0 at cosine >= 0.999999 on all 8 example prompts.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
