# [ROCm][Qwen4Exp][DeepSeek-V4.1] Add per_token PLE/Engram lookup mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/64369) · state: open · merged: False

## Original PR description

## Overview

Add a ROCm-only `per_token` lookup mode so a per-token table can replace the hashed n-gram table in 
(a) the DeepSeek-V4.1 Engram layers (`EngramConfig.mode`, `--engram-config '{"mode": "per_token"}'`) and 
(b) the Qwen4Exp PLE embedding (`ple_embedding_mode` text-config field). 
For Qwen4Exp PLE the per-token table is about 1.3 GB instead of the 102.4 GB n-gram table. The default (`ngram`, also used when the field is absent) keeps current behaviour.

## Claims

- New `EngramConfig.mode` (`ngram` | `per_token`) and Qwen4Exp text-config field `ple_embedding_mode` (`ngram` | `per_token`); default `ngram`, existing behaviour unchanged.
- Engram `per_token`: one row per token from the bf16 checkpoint tensor `layers.<i>.engram.per_token_table.weight` (`[compressed_vocab, n_hash_cols, head_dim]`), loaded through a normal safetensors `weight_loader` that keeps this TP rank's hash columns. Only the lookup output is replaced; projection, gate and residual add are unchanged. N-gram table tensors in the checkpoint are skipped.
- PLE `per_token`: one row of a `[vocab_size, ple_embed_dim]` table (`per_token_table.weight`) indexed by token id. A missing table, or a wrong dtype or shape, fails at load time.
- Unsupported combinations are rejected with a clear error instead of being ignored: non-ROCm platforms, non-DeepSeek-V4.1 architectures for Engram `per_token`, `embedding_across_dp`/`dp_shared_memory`/`use_thp` for Engram `per_token`, and PLE sequence parallelism.
- Docs updated in `docs/features/engram.md`; the new CPU tests are wired into `.buildkite/test_areas/models_basic.yaml`.

## Validation

```bash
pytest --noconftest -p no:cacheprovider \
  tests/models/deepseek_v41/test_engram_replacement.py \
  tests/models/qwen4_exp/test_ple_embedding_mode.py
# 62 passed, 1 failed (environment-only, see below)
```

The tests check that `per_token` is selected and read instead of the n-gram path, the missing-table and bad dtype/shape errors, TP column slicing and reassembly, and the config rejections. On a CPU-only machine `test_per_token_dummy_weights_skip_the_loaded_check` fails with "Failed to infer device type", and 6 cases of `tests/models/qwen4_exp/test_ple.py::test_ple_metadata_preserves_request_and_token_order` fail; both also fail before this change.

CI: the DeepSeek test runs in the `:computer: (CPU) Basic Models Other` step and the PLE test in the `:computer: (CPU) Qwen4 Exp` step of `models_basic.yaml`.

## Details

**Not a duplicate.** Searching open PRs for `per_token engram` and for `ple_embedding_mode` returns only this PR.

**Motivation.** The PLE n-gram table is 320,001,536 rows x 160 values in BF16 (102.4 GB). A per-token table of `[vocab_size, ple_embed_dim]` is about 1.3 GB.

**Design.**

- DeepSeek-V4.1: `ReplacementShard`, `PerTokenTable` and `per_token_comp_ids` live in `common/engram_replacement.py`. `Engram` and `DeepseekV4Model` only dispatch to them when `mode == "per_token"`. `load_weights` skips n-gram table tensors and raises if a per-token table was not loaded. `initialize_model_parallel` forms no Engram DP group in this mode.
- Qwen4Exp: `Qwen4ExpPerTokenEmbedding` in `amd/ple_layer.py` and the mode validation in `common/ple_mode.py`; `Qwen4ExpForConditionalGenerationConfig.verify_and_update_config` validates the field. The `ngram` path is unchanged apart from the mode-selection branch and a thin `dequantize` passthrough.
- PLE token ids outside the table are clamped on device (no host sync).
- Following review feedback, the Engram table is a normal checkpoint tensor loaded through standard safetensors weight loading, and the debug-only `zero` mode was removed.

**Limitations.**

- ROCm only; DeepSeek-V4.1 (Engram) and Qwen4Exp (PLE) only.
- `cpu_offload` is ignored in `per_token` mode. Engram `per_token` rejects `embedding_across_dp`/`dp_shared_memory`/`use_thp`; PLE `per_token` rejects sequence parallelism and supports a single PLE layer.
- Host memory while loading: each rank reads the full checkpoint tensor and then keeps only its slice.
- The per-token table is a checkpoint artifact; producing it is out of scope.
- There is no dedicated `torch.compile` / piecewise CUDA graph unit test.

**AI assistance.** AI assistance (Claude) was used to write and review this change. The tests above were run locally on CPU.
