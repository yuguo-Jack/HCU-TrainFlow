# [Perf] Support minimum KV splits configuration for TokenSpeed MLA decode 

[Upstream PR](https://github.com/vllm-project/vllm/pull/60345) · state: closed · merged: True

## Original PR description

## Overview

The TokenSpeed MLA decode kernel supports passing an optional flag `min_split_kv` to force a minimum number of KV splits, which can accelerate performance by up to 4x speedup under certain workloads, see https://github.com/lightseekorg/tokenspeed/pull/1693.

Expose the split floor through `AttentionConfig`:

```bash
--attention-config '{"tokenspeed_mla_min_split_kv": 8}'
```

The default is `1`, preserving automatic scheduling. Values are validated in `[1, 256]`; the setting only applies to TokenSpeed MLA decode.

## Claims

- Configure the decode split floor per engine through the existing attention configuration API.
- Reserve workspace for the configured floor and pass `min_split_kv` directly to the decode kernel; `1` preserves automatic scheduling.

## Details

This updates the existing PR rather than opening a duplicate. `tokenspeed_mla_min_split_kv` follows the other backend-specific split controls in `AttentionConfig`. The backend reads it once during initialization for both kernel dispatch and workspace sizing, and passes `min_split_kv=self._min_split_kv` directly; the proposed env var is removed. The pinned `tokenspeed-mla==0.2.15` supports this keyword, including the default value `1`. Changes to `tests/test_config.py` were removed. Increasing the floor may increase workspace memory.
