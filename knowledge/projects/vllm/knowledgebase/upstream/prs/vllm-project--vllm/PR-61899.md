# [Bugfix][Metrics] Aggregate DP engine samples in ORCA load header

[Upstream PR](https://github.com/vllm-project/vllm/pull/61899) · state: open · merged: False

## Original PR description



## Overview

Fixes #61898. When one API server fronts several data parallel engines, the ORCA `endpoint-load-metrics` header reported one engine's load instead of the endpoint's (this combines the per-engine samples).

## Claims

- With DP, the header reports `num_requests_waiting` summed across engines and `kv_cache_usage_perc` averaged across engines, in both TEXT and JSON.
- Output for a single engine is unchanged.
- The unsupported-format warning logs the requested format instead of `<built-in function format>`.
- `Created ORCA header` logs at debug instead of info, since it fired on every response that includes the header.

## Validation

Run on macOS arm64 (CPU backend), branch based on `4d9a8d6a41`.

```
.venv/bin/python -m pytest tests/entrypoints/serve/instrumentator/test_orca_metrics.py -k aggregates_dp_engines -v
```

- After: 2 passed.


## Details

DP metrics have one sample per engine. ORCA kept the last sample in JSON and repeated keys in TEXT. This sums waiting requests and averages KV usage across engines. Single-engine output is unchanged; `LLM.get_metrics()` still returns per-engine samples.

Mean KV usage assumes engines with equal KV cache capacity. DP does not guarantee this, since each engine sizes its cache from its own memory profile, and the API server only keeps the summed block count, so a capacity-weighted mean would need new plumbing. Also fixes the format warning and moves per-response header logging to debug.

Other changes in the file:
- The warning uses `%r` because the value comes from a request header, so control characters are escaped in the log.
- Removed three comments: two output examples named metrics the header never emits, and one that restated the next line.

No open or closed PR found fixing this ORCA aggregation. Related metrics work exists, such as #46920 in reader.py, but none touch the ORCA header

**Suggestion (non-blocking)**
The test monkeypatches `get_metrics_snapshot`. `tests/AGENTS.md` asks us not to patch internals to reach a state. `get_metrics_snapshot()` reads the global `prometheus_client.REGISTRY`, so the test could instead register two real labelled `Gauge`s (engines `"0"` and `"1"`), as the repro in #61898 does, and unregister them in teardown. The test would then also cover how the reader returns per-engine samples.

Note: #63445 makes the same change without a test. I left a pointer to this PR there.
