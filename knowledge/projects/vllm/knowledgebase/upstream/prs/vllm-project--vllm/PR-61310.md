# [XPU][LoRA] Support FP8 and W4A16 modular MoE experts

[Upstream PR](https://github.com/vllm-project/vllm/pull/61310) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Enable LoRA for native XPU FP8 and W4A16 modular MoE experts. Quantized XPU experts currently do not expose LoRA support, preventing adapters from being applied through `FusedMoEWithLoRA`.

## Claims

- Support per-tensor FP8, 128-block FP8, and symmetric INT4 W4A16 weights with FP16/BF16 inputs, reusing the existing MoE LoRA context and W13/W2 helpers.
- Preserve contiguous SiLU and interleaved SWIGLUOAI gate/up layouts with intermediate padding, expert routing, and output routing weights.
- Keep the existing native path without a LoRA context. No kernel API changes are required.

## Details

Native GEMMs group rows by expert; LoRA helpers address token/top-k rows. Restore token order around LoRA application, then regroup activations for the second native GEMM. For SWIGLUOAI, the helper already produces interleaved gate/up channels, so the logical channel pairs occupy the padded buffer's prefix. Other gated activations retain separate gate/up halves. The strengthened oracle computes these layouts independently.

Use native `moe_gather` for the base output to preserve its FP32 routing-weight multiplication and accumulation. Accumulate weighted W2 LoRA deltas separately in FP32 before adding to that output. This removes the extra per-route BF16/FP16 rounding that broke zero-delta parity. Nonzero adapters still include low-precision GEMM/LoRA stores and are checked against the reference tolerance, not asserted bitwise equivalent to an all-FP32 computation.

This follows `LoRAExpertsMixin` as used by Triton/Marlin. It requires unquantized expert inputs and output-side routing weights. Fully sharded LoRA and MXFP8 remain unsupported. Intermediate storage uses the modular MoE workspace allocator: workspace13 is reused for remapped inputs, token-order W13 output and GEMM2 buffers; workspace2 is reused for grouped W13 output, W13 delta, and activations plus W2 delta. GEMM2 output is kept disjoint from the final output, which can alias workspace13. This removes manual last-use deletion without adding persistent per-expert scratch state. No new host tensor reads or boolean tensor indexing were added to this forward path. `VLLM_GPU_SYNC_CHECK` does not instrument XPU in this revision, so it cannot certify XPU synchronization behavior.

Duplicate-work check: #60539 and #61163 add compilation optimizations and exclude LoRA; #54391 changes AWQ selection and #57558 adds INT4 tuning. None implements this native adapter path. The EP negative-ID handling from #57787 remains intact.
