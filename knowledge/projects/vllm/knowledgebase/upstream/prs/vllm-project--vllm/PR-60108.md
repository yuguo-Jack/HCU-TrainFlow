# [Bugfix][KVConnector][NIXL] Return NumPy descriptors from mixed-memory local registration

[Upstream PR](https://github.com/vllm-project/vllm/pull/60108) · state: closed · merged: True

## Original PR description



## Overview

With mixed DRAM/VRAM registration (HiSparse host-resident regions), `register_local_xfer_handler` returned the local descriptors as a list of tuples instead of its annotated `np.ndarray`. The P_TP > D_TP split path (`_build_local_splits_from_plan`) calls `.tolist()` on them, so a PCP8/DCP8 prefiller feeding a HiSparse decoder failed the NIXL handshake with `AttributeError: 'list' object has no attribute 'tolist'`. Companion fix for the same topology: #60107.

**Fix:** keep the Nx3 `uint64` array in the mixed-memory path. DRAM rows get device 0 via `blocks_data[desc_is_dram, 2] = 0`, and the DRAM/VRAM subsets are array slices.

## Validation

**Unit:** `test_mixed_memory_local_descriptors_split_by_memory_type` now asserts the returned descriptors are an `np.ndarray` (fails before the fix). `test_tp_mapping.py`, `test_nixl_connector.py`, `test_nixl_connector_hma.py`, `test_nixl_desc_geometry.py`: 498 passed (3 GPU e2e tests left to CI).

**End to end**, GLM-5.3 on 2 × 8 H200, PCP8/DCP8/EP8 prefill → DP8/EP8 HiSparse decode, MTP3:

| vLLM | Result |
|---|---|
| main + #60107 | decoder fails in `_build_local_splits_from_plan` on the first request; no KV transferred |
| main + #60107 + earlier revision of this fix | 8 one-hour Agent X points (142K cap c8–64, 1M cap c4–32): 0 errors, 100% external prefix-cache hit rate on the decoder |

The e2e run used this PR's earlier revision, which made the splitter accept the tuple list. Per review, the fix now lives in the producer; the splitter receives the same descriptor values.
