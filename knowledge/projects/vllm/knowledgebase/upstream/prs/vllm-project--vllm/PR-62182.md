# [Perf][Parser] Find the common tool argument prefix with slice comparisons (32 KB Llama 3 JSON call: 9.8 s to 4.9 s)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62182) · state: open · merged: False

## Original PR description

## Overview

`find_common_prefix` in `vllm/tool_parsers/utils.py` builds the shared prefix one character at a time (`prefix += s1[i]`). The Llama 3 JSON, InternLM2, Granite 20B FC and Apertus tool parsers call it on the whole argument JSON on every streamed delta, so on long tool calls this Python loop is the largest part of parser time. This binary-searches the prefix length with slice equality, which runs at C speed.

## Claims

- Parser CPU for a streamed Llama 3 JSON `write_file` call, 4 characters per delta: 4 KB 157 ms to 80 ms, 16 KB 2.56 s to 1.26 s, 32 KB 9.8 s to 4.9 s (about 2x at every size).
- Streamed arguments are unchanged. The remaining cost is `partial_json_parser` re-parsing the argument per delta, which this PR does not touch.

## Validation

- A/B in one process with the old and new function swapped into `llama_tool_parser`, order alternated per round, 5 rounds, median [min-max]: 32 KB 9799 [9757-9953] ms vs 4923 [4903-4985] ms. The concatenated streamed arguments are asserted equal between the two.
- New `test_find_common_prefix` covers empty strings, equal strings, one string a prefix of the other in both orders, a mismatch at the first and at the last position, and non-ASCII text.
- `pytest tests/tool_parsers/test_utils.py` and the apertus, granite, internlm2 and llama tool parser tests pass. The Llama 3 JSON tests that load the gated `meta-llama/Llama-3.2-1B-Instruct` tokenizer could not run locally. ruff check and format are clean.

## Details

Python compares two string slices with `memcmp`, so each probe is cheap and there are O(log n) probes. The common case where one string extends the other returns after a single comparison. The same fix went into ModelTC/LightLLM#1636 and NVIDIA/TensorRT-LLM#20492, which carry copies of this helper.
