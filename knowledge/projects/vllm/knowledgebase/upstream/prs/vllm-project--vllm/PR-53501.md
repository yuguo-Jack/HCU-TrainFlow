# [Bugfix][Frontend] Preserve prefix cache for inline system turns

[Upstream PR](https://github.com/vllm-project/vllm/pull/53501) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Keep Anthropic inline system reminders out of the leading prompt prefix when a template requires system-first ordering. Addresses #53393; refreshed against main `c5f8adc0` and the renderer resolution introduced in #58754.

## Claims

- Re-role inline system messages to user in place and merge adjacent user content only on the existing system-first fallback; preserve inline system roles for accepting templates.
- Retain current renderer and request-conversion APIs, and update the startup warning to describe user-role framing rather than a leading-system merge.

## Validation

- `.venv/bin/python -m pytest tests/entrypoints/anthropic/test_anthropic_messages_conversion.py -v` — **111 passed**.
- After the final warning-only update: the same file with `-k InlineSystem -q` — **15 passed**.
- The three fallback regressions fail against unmodified main production code and pass with this fix.
- Pre-commit on both changed files and `git diff --check origin/main...HEAD` — **passed**.
- No current-head model/serving evaluation ran here; CUDA cannot initialize. The production middleware measurements linked in this discussion support the transformation direction but did not execute this patch.

## Details

Hoisting each per-turn reminder into the leading system block changes the prompt prefix on every request. This preserves reminder text and its conversation position, but intentionally changes its role framing to user. Tool/reasoning-history compatibility still needs current-head model validation.

Duplicate/overlap check: #52978 uses trailing-system hoisting; #47681 changes a shared merge policy. Open Draft #58772 materially overlaps the goal but introduces a broader preserve/fold normalizer, tool-result folding, renderer probes and a CLI policy. This PR retains the narrower existing fallback and adds no normalization policy or CLI option. Maintainer guidance is requested on whether to take this small fix first or consolidate into #58772; no independent-scope claim is made. #58754 fixes template detection and does not remove the rejecting-template fallback.

Open since 2026-08-24. AI assistance was used for the refresh; signed-off, signed commits include Codex attribution. Human review and GPU/model validation remain required.
