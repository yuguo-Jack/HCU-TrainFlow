# [Bugfix][Frontend] Preserve prefix cache for inline system turns

[Upstream PR](https://github.com/vllm-project/vllm/pull/53501) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Keep Anthropic inline system reminders out of the leading prompt prefix when a template requires system-first ordering. Addresses #53393; refreshed against main `7b77ed581d` with the current renderer detection preserved.

## Claims

- Convert inline system text to user content in place on the existing system-first fallback and merge adjacent user messages; accepting templates retain inline system roles.
- Preserve the upstream conditional HF-template warning hint, update the existing `/v1/messages/render` regression, and document the automatic fallback and role-framing tradeoff in the Claude Code integration guide.

## Details

Hoisting each per-turn reminder into the leading system block changes the prompt prefix on every request. This fallback preserves the reminder's text and conversation position but changes its role framing to user; it does not preserve system-level instruction priority. Current-head tool/reasoning compatibility and live serving validation remain outstanding.

Overlap check: open **#63368** targets the same prefix-cache problem by folding inline text into adjacent user/tool content, including structured tool-result handling. That differs materially from this PR's re-role/adjacent-user fallback and may better preserve some templates' reasoning history. Open Draft **#58772** proposes a broader preserve/fold normalizer and policy. Maintainer guidance is needed on which approach to take or consolidate; no independent-scope or merge-readiness claim is made. #58754 improved template detection but did not remove the rejecting-template fallback; #52978/#47681 use different merge policies.

Open since 2026-08-24. AI assistance was used for this refresh; signed-off, signed commits include Codex attribution. Human review and current-head model validation remain required.
