# [Model] Support ViT full CUDA graph for Qwen3-Omni

[Upstream PR](https://github.com/vllm-project/vllm/pull/63809) · state: open · merged: False

## Original PR description

## Overview

Add ViT full CUDA graph support for the Qwen3-Omni thinker (`Qwen3OmniMoeThinkerForConditionalGeneration`, for example `Qwen/Qwen3-Omni-30B-A3B-Instruct`), part of #38175. Only the vision encoder is captured; the audio encoder stays eager. The thinker has its own `Qwen3Omni_VisionTransformer`, so this follows the Qwen3-VL integration (#35963, video in #38061) rather than reusing the Qwen3-VL code.

The eager Omni vision encoder now builds its attention metadata the way Qwen3-VL does, which also makes it run on FlashInfer: on main it fails there with "cu_seqlens must be divisible by 2". SyaOtiLan ran the GPU validation below on an RTX 4090 with the real vision weights. That work also found a FlashInfer replay bug shared with Qwen3-VL, fixed for Qwen3-VL in #64984 and for Omni in this PR.

## Claims

- Qwen3-Omni implements `SupportsEncoderCudaGraph` for images and videos, with the same buffer keys as Qwen3-VL.
- The eager vision encoder and the graph path build their attention metadata through one new `prepare_encoder_metadata`, following Qwen3-VL.
- This changes the eager encoder for every Qwen3-Omni user, with or without the graph flag. On FlashInfer and with FP8 encoder attention, the eager path now gets the same `cu_seqlens` and `max_seqlen` as Qwen3-VL. On main, the Omni encoder computed `max_seqlen` only for FA, ROCm AITER FA and Triton, and passed raw `cu_seqlens` to every backend. The RDNA3 fallback for `torch.repeat_interleave` is removed because that call is gone.
- On FlashInfer, graph replay copies the packed `cu_seqlens` with `_pad_flashinfer_cu_seqlens_buffer`, the helper Qwen2.5-VL registers (#42796). FlashInfer packs the q/k/o and v offsets into one tensor split at its midpoint, and an image replay is padded to a smaller batch bucket than the capture, so the default copy puts both halves into the first half of the buffer. The hook is registered in `get_encoder_cudagraph_config` only when `self.visual.attn_backend` is FLASHINFER, so other backends keep the default copy. #64984 makes the same change for Qwen3-VL; the two PRs are independent and can merge in either order.
- Graph replay matches eager mode on the same padded buffers exactly on FLASH_ATTN and FLASHINFER in every case run below.
- With FLASH_ATTN and budgets [64, 256, 1024], the encoder is faster with graphs when an input nearly fills its budget and slower when it is heavily padded (table below).

In the same run, replay on FLASH_ATTN matched eager on the same padded buffers exactly in the three cases sampled.
- Eager encoder, main compared with this branch, tiny random encoder on CUDA: FLASH_ATTN max abs diff 0 on all three grids of the comparison script. On FLASHINFER, main fails with "cu_seqlens must be divisible by 2" and this branch runs, with max abs error against an FP32 reference of 0.0017 to 0.0028.
- Replay on FLASHINFER before the padding hook, at 3687acad21: three replays of one 224 x 224 image differed by up to 3.84, and the first replay differed from eager by 7.72. With the hook ([report](https://github.com/vllm-project/vllm/pull/63809#issuecomment-6557439065)): replays identical, and replay equal to eager on the same padded buffers.
- Wider replay checks with the hook ([report](https://github.com/vllm-project/vllm/pull/63809#issuecomment-6557974253)), on a branch with this PR's Omni code plus the Qwen3-VL fix from #64984: mixed-size and two-image batches, video, alternating input shapes and oversized inputs that fall back to eager. The per-layer run in the same report also checked replay against eager on both FLASH_ATTN and FLASHINFER for both models, all exact.
- Padded compared with unpadded eager: the output for a 49-token image differs by a max of 0.40625 on FLASHINFER and 0.5 on FLASH_ATTN (RMSE about 0.008 to 0.009), without graph replay. A per-layer trace finds the first difference in `patch_embed.proj`, whose inputs match exactly, which is consistent with the linear kernel giving different BF16 results at 256 rows than at 196. A [follow-up trace](https://github.com/vllm-project/vllm/pull/63809#issuecomment-6560437008) used a 448 x 448 image (784 valid patches padded to 1024) with BF16 reduced-precision reduction disabled. The first difference between padded and unpadded eager is in `blocks.0.attn.qkv` (max abs 0.015625), whose valid input rows are identical. The GPU runs a different BF16 GEMM kernel at 784 rows than at 1024, and the padded and unpadded FP64 references round to the same BF16 values for the valid rows. A model-local prototype that pre-fills the output with the bias and calls an output-aliased `addmm` on the 27 vision QKV projections brought the final difference for this image from 0.28125 to 0. It increased CUDA graph time from 11.82 to 12.06 ms and eager time from 18.73 to 19.92 ms, and the number of graph-covered conditions whose output exactly matched unpadded ordinary eager went from 12 to 14 of 25. It depends on how this PyTorch build dispatches `addmm`, has not been shown to improve accuracy or output quality, and is not part of this PR. The effect on generated text was not measured.

## Details

Differences from the Qwen3-VL integration:

- Absolute position embedding is optional. When `apply_vit_abs_pos_embed` is off, `pos_embeds` is `None` in both the captured inputs and the replay values. The existing manager already skips `None` values when it copies replay values (`_run_budget_graph`), and this PR does not change the manager. The encoder then adds no position embedding.
- Deepstack features come after the main merger (`merger_list`). The output is `[main, deepstack...]` along the hidden dimension, so `out_hidden_size` is `visual_dim + multiscale_dim`, where `multiscale_dim` is `visual_dim` times the number of deepstack layers.
- `rot_pos_emb` takes a list of `[t, h, w]` instead of a tensor, so all metadata is built from Python lists.
- Eager metadata comes from the shared `MMEncoderAttention` helpers: `cu_seqlens` is built with NumPy, `max_seqlen` comes from `compute_max_seqlen`, and `cu_seqlens` goes through `maybe_recompute_cu_seqlens`, for which the encoder now records `tp_size` and `fp8_padded_hidden_size`. Eager and graph share this path so that the graph replays the same metadata the eager encoder uses. If you would rather review the eager change on its own first, I can split it into a separate PR.

Not measured: TTFT and full-model output quality, other budget sets, FlashInfer latency, FP8 encoder attention, ROCm, and GPUs other than the RTX 4090.

```python
"""Eager Qwen3-Omni vision encoder: main vs this branch on one attention backend.

Usage (from the PR branch checkout, with vLLM installed from it):
    git show origin/main:vllm/model_executor/models/qwen3_omni_moe_thinker.py > /tmp/omni_main.py
    python eager_backend_eq.py /tmp/omni_main.py FLASH_ATTN
    python eager_backend_eq.py /tmp/omni_main.py FLASHINFER

Builds a tiny random encoder (hidden 256, 4 heads, head dim 64, depth 3,
deepstack at layers 0 and 1), loads the same weights into main's class and the
branch's class, and runs both on the given backend in bf16. Each output is also
compared with the branch's encoder on TORCH_SDPA in fp32, so a mismatch shows
which side moved away from the reference.
"""

import importlib.util
import sys
import tempfile
from types import SimpleNamespace

import torch
from vllm.config import MultiModalConfig, VllmConfig, set_current_vllm_config
from vllm.distributed import (
    ensure_model_parallel_initialized,
    init_distributed_environment,
)
from vllm.model_executor.models import vision
from vllm.v1.attention.backends.registry import AttentionBackendEnum

main_path, backend_name = sys.argv[1], sys.argv[2]
device = "cuda" if torch.cuda.is_available() else "cpu"
backend = {"value": AttentionBackendEnum.TORCH_SDPA}
_default_mm = MultiModalConfig()


class _MMConfig:
    """Default MultiModalConfig with the encoder attention backend overridden."""

    def __getattr__(self, name):
        if name == "mm_encoder_attn_backend":
            return backend["value"]
        return getattr(_default_mm, name)


vision.get_multimodal_config = _MMConfig

VC = SimpleNamespace(
    hidden_size=256,
    num_heads=4,
    image_size=128,
    patch_size=16,
    spatial_merge_size=2,
    temporal_patch_size=2,
    apply_vit_abs_pos_embed=True,
    deepstack_visual_indexes=[0, 1],
    in_channels=3,
    intermediate_size=512,
    hidden_act="gelu_pytorch_tanh",
    depth=3,
    out_hidden_size=64,
)
GRIDS = ([[1, 4, 6]], [[1, 4, 6], [2, 4, 4], [1, 8, 2]], [[4, 8, 8], [1, 2, 2]])


def build(cls, dtype, state_dict):
    torch.set_default_dtype(dtype)
    model = cls(VC).to(device=device, dtype=dtype).eval()
    model.load_state_dict({k: v.to(dtype) for k, v in state_dict.items()})
    for m in model.modules():
        qm = getattr(m, "quant_method", None)
        if qm is not None and hasattr(qm, "process_weights_after_loading"):
            qm.process_weights_after_loading(m)
    return model


cfg = VllmConfig()
with set_current_vllm_config(cfg):
    init_distributed_environment(
        world_size=1,
        rank=0,
        local_rank=0,
        distributed_init_method=f"file://{tempfile.mktemp()}",
        backend="gloo",
    )
    ensure_model_parallel_initialized(1, 1)
    from vllm.model_executor.models.qwen3_omni_moe_thinker import (
        Qwen3Omni_VisionTransformer as Branch,
    )

    spec = importlib.util.spec_from_file_location(
        "vllm.model_executor.models._omni_main", main_path
    )
    main_mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(main_mod)
    Main = main_mod.Qwen3Omni_VisionTransformer

    torch.manual_seed(0)
    torch.set_default_dtype(torch.float32)
    sd = {k: torch.randn_like(v) * 0.05 for k, v in Branch(VC).state_dict().items()}

    backend["value"] = AttentionBackendEnum.TORCH_SDPA
    ref = build(Branch, torch.float32, sd)
    backend["value"] = AttentionBackendEnum[backend_name]
    models = {}
    for name, cls in (("main", Main), ("branch", Branch)):
        try:
            models[name] = build(cls, torch.bfloat16, sd)
            print(name, "backend", models[name].attn_backend)
        except Exception as e:  # report and keep going
            print(name, "BUILD ERROR", f"{type(e).__name__}: {e}"[:300])
    torch.set_default_dtype(torch.float32)
    print("device", device, "| reference backend", ref.attn_backend)

    for grid in GRIDS:
        n = sum(t * h * w for t, h, w in grid)
        x = torch.randn(n, 3 * 2 * 16 * 16, device=device, dtype=torch.float32)
        with torch.no_grad():
            r = ref(x, torch.tensor(grid)).float()
            outs = {}
            for name, model in models.items():
                try:
                    outs[name] = model(x.bfloat16(), torch.tensor(grid)).float()
                except Exception as e:  # report and keep going
                    outs[name] = f"{type(e).__name__}: {e}"
        line = [f"grid {grid}"]
        for name, o in outs.items():
            if isinstance(o, str):
                line.append(f"{name} ERROR {o[:200]}")
            else:
                line.append(f"{name} vs ref {(o - r).abs().max().item():.4g}")
        if len(outs) == 2 and not any(isinstance(o, str) for o in outs.values()):
            line.append(
                f"main vs branch {(outs['main'] - outs['branch']).abs().max().item():.4g}"
            )
        print(" | ".join(line))
```

It records the patch embedding, each block's norms and QKV, attention and MLP outputs, the deepstack mergers and the final merger during a forward pass, and then compares the valid rows of two passes. It fails with a list of names if any hook does not fire.

```python
import torch


def record_outputs(visual, run):
    """Run `run()` and return {module name: output} for the modules below, in call order."""
    # Hooks on patch_embed and on the blocks themselves did not fire in a CPU run,
    # so record their submodules instead.
    names = ["patch_embed.proj"]
    for i in range(len(visual.blocks)):
        names += [f"blocks.{i}.{m}" for m in ("norm1", "attn.qkv", "attn", "norm2", "mlp")]
    names += [f"deepstack_merger_list.{j}" for j in range(len(visual.deepstack_merger_list))]
    names.append("merger")
    mods = dict(visual.named_modules())
    outs, hooks = {}, []
    for name in names:
        def hook(module, args, out, name=name):
            out = out[0] if isinstance(out, tuple) else out
            outs[name] = out.detach().float().clone()
        hooks.append(mods[name].register_forward_hook(hook))
    try:
        with torch.no_grad():
            run()
    finally:
        for h in hooks:
            h.remove()
    missing = [n for n in names if n not in outs]
    assert not missing, f"hooks did not fire for {missing}"
    return outs


def first_difference(unpadded, padded, num_valid_patches, merge_unit):
    """Print max abs diff over the valid rows of each module, in call order."""
    for name, ref in unpadded.items():
        merged = name == "merger" or name.startswith("deepstack_merger_list")
        rows = num_valid_patches // merge_unit if merged else num_valid_patches
        diff = (padded[name].reshape(-1, ref.shape[-1])[:rows]
                - ref.reshape(-1, ref.shape[-1])[:rows]).abs().max().item()
        print(f"{name:26s} max abs diff {diff:.6g}")
```

Usage, with `run_unpadded` and `run_padded` being the two eager calls you already make (padded with the zero tail, as before):

```python
a = record_outputs(visual, run_unpadded)
b = record_outputs(visual, run_padded)
first_difference(a, b, num_valid_patches=196, merge_unit=4)
```

The useful part is the first line that is not exactly 0, with its value, plus the attention backend and TP size. If that line is `patch_embed.proj`, a `norm` or a `qkv` or `mlp` output, the difference starts in a per-row operation, which points to kernel choice by shape. If it is an `attn` output while the `qkv` before it is exact, the attention kernel or the `cu_seqlens` tail is the place to look. This is optional.
