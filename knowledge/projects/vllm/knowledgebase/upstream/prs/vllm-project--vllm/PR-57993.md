# [Bugfix][KV Cache] Clarify padded-page kernel split validation

[Upstream PR](https://github.com/vllm-project/vllm/pull/57993) · state: closed · merged: False

## Original PR description

## Purpose

Related to #54877.

Current main rejects kernel block splitting for padded KV pages, but the error path is misleading: `create_kv_cache_views()` suggests switching to a layer-compact layout even though a layout change cannot make a padded page splittable, while `compute_layout_strides()` uses an assertion for the same unsupported configuration.

This change gives padded-page splitting its own explicit `ValueError` and preserves the existing layout advice for genuinely non-dense, unpadded layouts.

This does not add support for splitting padded KV pages or change the KV layout contract.

## Test Plan

CPU-only regression coverage verifies:

- padded pages reject kernel block splitting for LBHNC and LBNHC;
- direct `compute_layout_strides()` callers receive an explicit validation error.

Result: 3 regression cases passed locally.

Applicable touched-file pre-commit hooks and `git diff --check` passed.

The tests use the repository-supported `skip_global_cleanup` marker because PyTorch accelerator cleanup segfaults on this macOS ARM64 source checkout.
