# [Metrics] Count finished requests by watermark status

[Upstream PR](https://github.com/vllm-project/vllm/pull/58715) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Add `vllm:watermark_requests{status}`, a Prometheus counter of finished requests by watermark status. It exists only when `watermark_config` is set.

## Claims

- Each finished request gets exactly one status: `watermarked`, `skipped` or `not_watermarked`.
- `skipped` means the request asked for the watermark (omitted or `true`) but could not use it, such as `temperature=0` and trace replay requests.
- `not_watermarked` covers explicit opt-outs, pooling requests and internal requests (beam search steps, generative scoring, language detection).
- On an instance with `watermark_config`, the sum over `status` equals `vllm:request_success`. Both come from the same call in `IterationStats.update_from_finished_request()`.
- Without `watermark_config` the counter is not registered.

## Validation

Unit tests:

- `tests/v1/engine/test_output_processor.py`: requests of every status, including pooling, engine `ABORT`, `ERROR` and an `n=2` parent, finish through `OutputProcessor.process_outputs()` and are recorded by `PrometheusStatLogger`. The labels sum to `vllm:request_success`.
- `tests/v1/metrics/test_histogram_buckets.py`: the counter is registered only with `watermark_config`.

```
pytest tests/v1/metrics/test_histogram_buckets.py tests/v1/engine/test_output_processor.py
64 passed
```

E2E on H200 (`tests/watermarking/test_watermarking_e2e.py`, now also checks the three labels and the sum for a watermarked, an opted-out and a `temperature=0` request):

```
pytest tests/watermarking/test_watermarking_e2e.py
1 passed
```

Manual scrape with `vllm serve facebook/opt-125m --watermark-config '{"key": 42}'` after one watermarked, one `temperature=0` and one opted-out completion:

```
vllm:watermark_requests_total{engine="0",model_name="facebook/opt-125m",status="watermarked"} 1.0
vllm:watermark_requests_total{engine="0",model_name="facebook/opt-125m",status="skipped"} 1.0
vllm:watermark_requests_total{engine="0",model_name="facebook/opt-125m",status="not_watermarked"} 1.0
vllm:request_success_total{engine="0",finished_reason="length",model_name="facebook/opt-125m"} 3.0
```

Without `--watermark-config`, `/metrics` has no `vllm:watermark_requests` series.

## Details

The status reads the same `SamplingParams` flags the GPU sampler reads: `watermarking`, and `_watermarking_skipped`, which the frontend sets when it resolves the request. `RequestState.from_new_request()` copies them into `RequestStateStats` once.

A request resolved again through the deprecated `EngineCoreRequest` path can carry both `_watermarking_skipped=True` and `watermarking=True`. It counts as `watermarked`, because `watermarked` is checked first.

The status is per request, not per token. A `watermarked` request can still contain tokens without the watermark (accepted draft tokens with `allow_target_only_watermarking`, repeated contexts with `deduplicate_contexts`, grammar-forced tokens). The docs list these cases.

Limitations, documented in `docs/features/watermarking.md`:

- In disaggregated prefill/decode, both instances count a request. Sum over decode instances only.
- For streaming input, the first input chunk sets the status.
- Client aborts are in neither counter, as with `vllm:request_success`.

Model Runner V1 cannot watermark, so there is no V1 path.
