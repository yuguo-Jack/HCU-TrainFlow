# [Bugfix][Bench] Support Muse balanced routing

[Upstream PR](https://github.com/vllm-project/vllm/pull/63872) · state: closed · merged: True

## Original PR description

## Overview

Fix Muse Spark forward benchmarks with dummy weights and the default `--routing auto`, which already selects balanced routing. No explicit routing flag is needed.

## Claims

- `BalancedRouting` discovers Muse's gate and suppresses expert selection bias while its synthetic routing fixture is installed.
- Removing the fixture restores the original bias and real model routing.

## Validation

GB200 validation of the retained tests: 2 cases passed (native CLI and router/bias behavior). All targeted pre-commit checks pass.

On GB200, using `.venv/bin/python -m pytest tests/benchmarks/test_forward_cli.py -k test_balanced_routing_restores_expert_bias -v`:

| Configuration | Before | After |
| --- | --- | --- |
| Muse `router` / `expert_bias` layout | `ValueError: No MoE gates found; use --routing real.` | Pass |

The test uses a real GateLinear and Muse router, checks exact per-rank balance despite a large expert-selection bias, and verifies bias restoration and subsequent real routing. Targeted pre-commit hooks passed. The existing Benchmarks CLI Buildkite step selects the layer regression; the B200 Quantized MoE step explicitly selects the native Muse CLI test.

The BF16 TRTLLM test passes without the separate MegaMoE initialization fix. The added `test_bench_forward_muse_balanced_routing` regression fails before the routing fix with `ValueError: No MoE gates found; use --routing real.`. It uses a one-layer Muse text config (512 hidden, 8 experts, top-2) on one GB200, BF16 FlashInfer TRTLLM, balanced routing, and prefill32/decode2@32. Both CUDA graph cases completed and matched eager output exactly (relative RMS 0). Two timing samples are a smoke check, not a speedup claim. Reproduce with `.venv/bin/python -m pytest tests/benchmarks/test_forward_cli.py -k "test_bench_forward_muse_balanced_routing or test_balanced_routing_restores_expert_bias" -v`. The CLI registers the native text class through ModelRegistry because public Muse checkpoints use the multimodal architecture wrapper.


## Details

Gate discovery previously recognized only `gate`, and bias handling recognized only `e_score_correction_bias`. Add fallbacks for Muse's existing names while reusing fixture generation, forward hooks, and bias restoration. This changes only benchmark fixtures; real serving routing is unaffected.

Open-PR searches for `"balanced routing"`, `"Muse" "dummy"`, and `"Muse" "finalize"` found no duplicate. #60217 concerns serving-time EMA routing penalties on ROCm, not synthetic forward-benchmark gate discovery. No associated issue number exists.

AI assistance was used to implement and validate this change. The human submitter confirmed review of every changed line and execution of the relevant tests before submission.
