# [Core][MLA] Cross-layer KV cache sharing for attention layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/64095) · state: open · merged: False

## Original PR description

## Overview

Model-agnostic enablement for MLA models in two areas: cross-layer KV sharing and PCP+DCP decode handling. No behavior change for existing models; each piece is opt-in or additive.

Not a duplicate: searched open PRs for KV-sharing / MLA enablement / PCP+DCP work — the open items cover KV-sharing prefill perf for a specific model family (#60445), DSv4.1 pipeline partitions (#63106), and compressed-MLA offloading (#63586); none generalize cross-layer KV sharing over `AttentionLayerBase` or move the PCP+DCP LSE merge into the base MLA forward.

## Claims

- **Cross-layer KV sharing:** `kv_sharing_target_layer_name` is declared on `AttentionLayerBase` and plumbed through `MLAAttention`. A layer that shares another layer's KV cache skips its own cache write, and the V2 runner resolves consumers to the sharing target's KV cache spec (`get_shared_kv_cache_layers` now walks `AttentionLayerBase`).
- **Sparse MLA only, with forced MQA:** KV sharing is supported by sparse MLA backends, and a sharing layer requires `sparse_mla_force_mqa`. The sparse MHA prefill paths attend over the layer's own new latent KV rather than the cache, and a sharing layer has no latent of its own, so the model must opt into the MQA path; otherwise initialization raises a `ValueError`. Dense MLA still rejects sharing, since its prefill always uses the layer's own latent.
- **PCP+DCP:** the decode-only LSE merge moved into the base `MLAAttention` forward (as DeepSeek-V3.2 does in its own forward), so MLA models opt in with `supports_pcp_dcp` instead of overriding `forward`.

## Validation

Unit tests on GB300:

```bash
pytest tests/v1/worker/test_attn_utils.py        # 53 passed (extended by this PR, wired into CI)
pytest tests/v1/core/test_kv_sharing.py          # 2 passed
pytest tests/v1/worker/test_gpu_pcp_manager.py   # 95 passed
pytest tests/v1/attention/test_dcp_a2a_pack_mask.py  # 354 passed
```

End to end on a tiny DeepSeek-V3-style DSA checkpoint (8 layers, 16 heads, random weights, `index_topk=512`) where layers 4 and 6 share the KV cache of layers 3 and 5 (test-only hook, not part of this PR), TP2 on the V2 runner, greedy 32 tokens, compared by the first diverging token against the same model without sharing:

| Config | Result |
|---|---|
| Sharing without `sparse_mla_force_mqa` (before the guard) | sharing layers ran dense MHA prefill over their own latent; all medium prompts diverged at token 0. Now rejected at init. |
| `sparse_mla_force_mqa`, sharing layers' own latent zeroed | identical to the unzeroed run, so the sharing layers read only the shared cache |
| DCP2, `--dcp-comm-backend ag_rs` | within run-to-run noise, no crash |
| DCP2, `--dcp-comm-backend a2a` (eager and FULL_DECODE_ONLY CUDA graphs) | within run-to-run noise, no crash |
| PCP2xDCP2, `ag_rs`, `fp8_ds_mla` | within run-to-run noise, no crash |
| PCP2xDCP2, `a2a` | rejected at startup by the existing MRV2 PCP check (`dcp_comm_backend='ag_rs'` required) |

On `--dcp-comm-backend a2a`: without PCP the partial-row LSE merge always takes the full-batch path, so a2a behaves as before. The partial-row merge is only reached under PCP, where a2a cannot be selected.

## Details

- The KV-sharing attribute is a typed default (`None`) on `AttentionLayerBase`, so discovery no longer relies on `getattr`/`hasattr` probing of arbitrary layers.
- Under PCP+DCP only the decode rows carry an LSE (prefill rows attended over the gathered KV), so the merge now applies to just those rows; the full-batch path is unchanged.
