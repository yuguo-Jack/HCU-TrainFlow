# [ROCm] Add _maybe_pad_weight guard-condition and RL-reload stability tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/62977) · state: closed · merged: True

## Original PR description

## Summary

Follow-up to #59332, which cut these tests to keep that PR scoped to what
#54966 ("Test padding") originally asked for. Tracked in the progress table
at https://github.com/vllm-project/vllm/issues/54966#issuecomment-6129972192
(item 4, follow-up row) as "4d-1".

Adds three tests to `tests/rocm/test_moe_padding.py`, extending the existing
`_maybe_pad_weight` coverage:

- `test_maybe_pad_weight_eplb_disables_padding` -- EPLB requires contiguous
  weights for its rearrangement ops, so padding must stay off whenever EPLB
  is enabled, even for an otherwise-eligible (512-byte-aligned) shape.
- `test_maybe_pad_weight_non_unit_stride_disables_padding` -- `_maybe_pad_weight`
  requires a unit inner stride; constructs a strided view whose *would-be*
  outer-stride alignment passes, to prove the stride guard specifically (not
  just alignment) is what blocks padding.
- `test_aiter_moe_padding_rl_reload_address_stable` -- simulates an RL
  in-place weight reload (same `RoutedExperts` layer, new weight values) and
  asserts `w13_weight`/`w2_weight`'s storage address is unchanged across the
  reload, confirming `process_weights_after_loading` copies the padded
  weight back into existing storage rather than rebinding `.data` (which
  would silently break CUDA-graph address capture). Also checks the
  post-reload output reflects the new weights.

## Test plan

Ran on an MI355X (gfx950) host, AITER v0.1.26:

```
VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_MOE=1 pytest -v -s tests/rocm/test_moe_padding.py
```

All 10 tests in the file (7 existing + 3 new) pass. `pre-commit run --files
tests/rocm/test_moe_padding.py` is clean.
