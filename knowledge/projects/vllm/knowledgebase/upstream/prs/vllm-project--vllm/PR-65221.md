# [Feature][Model Loader] Expose fastsafetensors transfer-mode selection

[Upstream PR](https://github.com/vllm-project/vllm/pull/65221) · state: open · merged: False

## Original PR description



## Overview

Expose the existing fastsafetensors buffered/GDS selection as the boolean
`fastsafetensors_nogds` model-loader option. Preserve defaults and reject
explicit GDS for initialized multi-rank WORLD before CUDA setup.

## Claims

- `--load-format fastsafetensors --model-loader-extra-config '{"fastsafetensors_nogds": true}'`
  selects existing buffered transfers. Explicit `false` requests existing
  single-rank GDS; omission preserves existing selection.
- Reject non-booleans, use with other load formats, and explicit GDS in a
  multi-rank WORLD group.
- Retain queue-depth control and pre-first-yield unsupported-GDS fallback.
  No startup, steady-state CPU/inference speed or guaranteed-GDS-use claim.

## Details

The existing iterator already chooses buffered transfers for multi-rank groups
and GDS otherwise. Users could not explicitly select buffered transfer without
changing that policy. Pass a validated optional boolean from the existing
loader to its iterator instead of adding a loader or changing defaults.

Explicit `false` cannot override multi-rank safety: GDS setup may initialize
CUDA contexts on visible GPUs. The initialized global WORLD group, not only TP
size, is the relevant boundary. This is load-time/library-lifetime selection;
it adds no steady-state inference work or new transfer/teardown mechanism.
Multi-rank users already buffered by default do not gain a new buffered mode.

Related [PR55985](https://github.com/vllm-project/vllm/pull/55985) adds automatic
memory-budget/chunk planning and associated transfer decisions. This change is
the smaller manual boolean selector, without that planner or dependency-floor
change; the overlapping loader code requires coordination, not a claim of zero
related work. [PR51554](https://github.com/vllm-project/vllm/pull/51554) concerns
a separate sharded-state loader.

Modernization review found no justified CUDA/architecture-specific rewrite for
this mode selector. Existing pipeline, fallback and close behavior are reused.
AI assistance was used in implementation and review preparation. Human review,
accurate attribution and the confirmed NVIDIA-email DCO remain explicit.
The human submitter confirmed line-by-line review before opening this draft;
it remains draft for further author/design review.
