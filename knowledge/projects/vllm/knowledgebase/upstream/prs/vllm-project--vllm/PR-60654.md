# [Attention] Fetch MLA prefill workspace at use instead of init

[Upstream PR](https://github.com/vllm-project/vllm/pull/60654) · state: closed · merged: True

## Original PR description

## Purpose

The TRTLLM-ragged and FlashInfer MLA prefill backends keep a view of the shared workspace from `__init__`. When a later user, such as the sparse indexer's profile, grows the workspace, that view keeps the old buffer alive as an orphan. On GLM-5.3 on B200 that's 394 MB of GPU memory nobody uses.

Both backends now reserve their size at init without keeping a view, and fetch it in `prepare_metadata`, once per step. FlashInfer rebuilds its wrappers if the workspace has moved. The builder runs outside the DBO micro-batch threads, so both still use the micro-batch 0 slot, as on main.

Sharing the workspace is safe: TRTLLM ragged runs with multi-CTA KV off and uses it only for per-launch softmax stats, and FlashInfer cutlass prefill never touches it (it has its own 32 MB buffer).
