# [Perf][DSv4.1] Share MegaAttn int32 positions across layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/61971) · state: open · merged: False

## Original PR description

## Overview

MegaAttn converts the same RoPE positions from int64 to int32 in every layer. In a full CUDA graph those casts are separate GPU kernels: 40 per target forward on DeepSeek-V4.1-Flash. Share the converted tensor within the forward context so the graph records one cast.

## Claims

- Removes 39 redundant cast kernels per 40-layer target forward.
- Target GPU time drops from 17.903 to 17.834 ms (0.39%) in the DEP8 decode measurement below.

## Validation

DeepSeek-V4.1-Flash on 8 x GB300 across two nodes, DP8 x TP1 + EP, 64 requests/rank, 131,072 input tokens, 2,048 output tokens, attention top-k 1024, DSpark with 5 draft tokens (384 target tokens/rank). FlashMLA built with CUDA 13.4, MegaMoE, Engram on GPU, full decode CUDA graphs. Both runs restore and freeze the same EPLB mapping.

| Target forward | Before | Shared positions |
|---|---:|---:|
| GPU time, median (ms) | 17.903 | 17.834 |
| GPU time, p10 / p90 (ms) | 17.847 / 17.996 | 17.793 / 17.941 |
| Full-batch samples | 366 | 342 |
| Kernels in the captured forward | 766 | 727 |

One run per version on a development tree, using real weights and synthetic KV through `DecodeBenchConnector`. Times are CUDA events around the target graph, without the profiler, taking the slowest of eight ranks for each step and discarding the first ten full-batch steps. Kernel counts come from a separate CUDA-only trace. This measures GPU target time, not request latency or serving throughput.

The measurements used the equivalent helper implementation; the final diff inlines it. The final `forward_mqa` was checked locally on GB300 with a copy consumer: 40 uses share one converted buffer during full capture, offset views stay distinct, replays see updated positions, independent captures do not reuse another graph's cast, and separate piecewise graphs sharing a context remain correct. NONE, FULL and PIECEWISE cases pass. These local checks are not added to the PR.

```bash
.venv/bin/python -m pytest tests/kernels/test_dsv41_mega_attn_layouts.py -q
.venv/bin/python -m pre_commit run --files vllm/models/deepseek_v41/nvidia/flash_mla_mega_attn.py
```

Existing layout suite on the development tree: 7 passed. Pre-commit, including Ruff, formatting and mypy: passed. No accuracy evaluation was run; the integer conversion is unchanged. The capture checks above were run outside CI.

## Details

The cache is keyed by the input tensor and scoped to `ForwardContext`. The cast still executes on every graph replay. Eager execution and PIECEWISE capture keep their per-call conversion, since separate piecewise graphs must own their buffers. Check actual stream capture as well as runtime mode: MRV2's full capture can run with mode NONE.

Not a duplicate: searched open PRs for `mega attention positions`, `positions int32`, `mega_attn_positions_int32`, and `MegaAttention reuse`. #60613 fixes a prefill index sentinel; #60543 autotunes the indexer GEMM. Neither shares the RoPE position conversion. No linked issue.
