# [Kernel][SM120] Add small-batch block-FP8 projection routes

[Upstream PR](https://github.com/vllm-project/vllm/pull/60385) · state: open · merged: False

## Original PR description

## Overview

Add two small-batch block-FP8 projection routes on SM120 for N=2560 and K=4096/9216: ordered K128 reduction for M=1..8 and CUTLASS n64 Pingpong for M=16..128 divisible by eight. Both produce BF16 output.

## Claims

- The n64 route uses a 64x32x128 tile with swapped operands and reuses the existing CUTLASS blockwise caller. Each layer prepares scale64 by duplicating its FP32 scale128 rows.
- The ordered route computes FP32 K128 partials, applies block scales in ascending group order, and converts the result to BF16. Each call owns its output and scratch buffers.
- A layer-aware dispatch hook integrates both routes with the existing quantization, bias and reshape logic. Other shapes, architectures and batch-invariant mode use the existing path.
- Derived scales retain their storage addresses during layerwise reload so captured graphs read the updated values.

## Validation

Tested on RTX 5090 SM120 with vLLM base `e11962fc1ce542c725dacda6f641daed8d54337f`, Torch 2.13.0+cu130, Triton 3.7.1, CUTLASS 4.7.1 and FlashInfer 0.7.0.post1. Native validation used an incremental build of the modified translation unit and schema against the matching precompiled libraries.

- **22 GPU pytest cases passed**, including direct native and dispatcher output checks, M=40/72 tail tiles, scale ownership/reload, and changing-input graph replay.
- **14 lifecycle checks passed**: post-capture reload, independent streams, scale layouts and `VLLM_GPU_SYNC_CHECK=error`.
- **64 extended checks passed**: all supported n64 batch sizes, ordered M=1..8, bias/reshape, both weight-scale attribute names and FP16-output fallback.
- Ruff check/format, clang-format, applicable repository policy checks and mypy targets 3.10–3.13 passed. The final test update adds the tail-tile cases and fixes import ordering.

## Details

The n64 configuration uses scale granularity 64/1/128, Pingpong scheduling and swizzle1. The ordered route reads the original scale128. Derived scales are nonpersistent layer buffers; reload updates the saved allocation before restoring layer tensors.

The remaining model question is the M64 graph/compiler difference. In the earlier three-RMS diagnostic, replacing all candidate GEMMs with stock GEMMs produced the same records as the candidate. Further work will trace that graph-level difference. Full CMake target/link validation is also pending.

An October 7 search found no open PR implementing these selected routes. Related work addresses leading strides (#56659), unaligned N (#48588) and reload-owned runtime buffers (#53509).
