# [Bugfix][MRV2] Capture CUDA graphs with execute_model's input_ids

[Upstream PR](https://github.com/vllm-project/vllm/pull/63733) · state: open · merged: False

## Original PR description



## Overview

MRV2 captures CUDA graphs with the `input_ids` buffer even when `execute_model` passes `input_ids=None` alongside `inputs_embeds`. With breakable CUDA graphs and DEBUG logging, the replay address check then fails on the first PIECEWISE replay of a multimodal or prompt-embeds model. This PR applies `execute_model`'s rule at capture. Same block as #61016.

## Claims

- MRV2, `VLLM_USE_BREAKABLE_CUDAGRAPH=1`, `VLLM_LOGGING_LEVEL=DEBUG`, a model that runs with `inputs_embeds` and does not set `requires_raw_input_tokens`: the first breakable PIECEWISE replay no longer fails `Input tensor addresses changed between capture and replay`.
- Capture now calls the model with the same `input_ids` / `inputs_embeds` combination as serving, for FULL graphs too. Greedy output unchanged on `Qwen/Qwen2.5-VL-3B-Instruct` (text and image requests, breakable and default graphs), MI355X.
- Unchanged: models with `requires_raw_input_tokens`, model states that supply `inputs_embeds` through their own inputs (`DiffusionGemmaModelState`, `LongcatNgramModelState`), text-only models without prompt embeds, non-first PP ranks, MRV1.

It runs in the CPU `v1` step (`.buildkite/test_areas/misc.yaml:330`).

- On the base commit: all 4 fail with `TypeError: ModelCudaGraphManager.capture() got an unexpected keyword argument 'uses_inputs_embeds'`.

Dropping any one condition of the rule fails exactly the case for that condition; keying the rule on `inputs_embeds` being in the capture inputs fails the case without `dummy_inputs_embeds` and the `uses_inputs_embeds=False` case.
- Rest of the file on CPU-only torch 2.14.1: unchanged from the base (`test_full_capture_sets_graph_pool_id_before_cuda_graph` fails on both with `Fail to set current stream`; no accelerator for the conftest teardown).

## Details

- **Root cause.** On the first PP rank, `execute_model` sets `input_ids = None` when `uses_inputs_embeds` is set, the model state returned an `inputs_embeds` tensor, and the model does not set `requires_raw_input_tokens` (`vllm/v1/worker/gpu/model_runner.py:1970-1996`). `ModelCudaGraphManager.capture` built its inputs with `input_buffers.input_ids` and only dropped them on later PP ranks (`vllm/v1/worker/gpu/cudagraph_utils.py:688-698`). `BreakableCUDAGraphWrapper` collects the tensor kwargs at capture and, at DEBUG, compares them with the replay call's (`vllm/compilation/breakable_cudagraph.py:361-364`, `:421-427`), so it sees one more tensor at capture (`input_ids`) than at replay. The others keep their addresses; the check fails because the lists differ.
- **Fix.** Capture applies the same rule. The runner passes `uses_inputs_embeds`, and the model state's `dummy_inputs_embeds` decides, as in `execute_model`'s dummy run. Keying on whether the capture inputs contain `inputs_embeds` would be wrong for `DiffusionGemmaModelState` and `LongcatNgramModelState`, which add `inputs_embeds` in `prepare_dummy_inputs` and `prepare_inputs` while `execute_model` keeps `input_ids` for them.
- **FULL graphs.** The change applies to FULL captures as well, which also replay with whatever the capture traced. A model whose forward reads `input_ids` when given `inputs_embeds` without setting `requires_raw_input_tokens` already gets `input_ids=None` in eager, PIECEWISE and startup profiling runs (`profile_run` → `_dummy_run` → `execute_model(dummy_run=True)`), so capture now traces the path those runs take. DBO capture is covered by the same change; `slice_model_inputs` skips `None` (`vllm/v1/worker/gpu/ubatch_utils.py:246-249`).
- **Alternatives.** Skipping kwargs that are `None` at replay in the DEBUG check would hide a tensor that a captured segment read at capture and replay no longer passes. Excluding `input_ids` in `_replay` would copy a model-runner rule into compilation code and leave capture and serving on different Python paths.
- **MRV1** is not affected: its capture dummy run uses `_prepare_mm_inputs`, which drops `input_ids` the same way (`vllm/v1/worker/gpu_model_runner.py:3247-3256`, `:5719-5727`).
- **Default users.** On CUDA, several multimodal architectures enable breakable graphs by default (`default_breakable_cudagraph_architectures`), so DEBUG logging alone reaches the check for those that do not set `requires_raw_input_tokens`. Not run on CUDA.
