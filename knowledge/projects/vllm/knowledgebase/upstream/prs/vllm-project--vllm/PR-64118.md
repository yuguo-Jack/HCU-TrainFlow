# [Test][KV Connector] MooncakeStore: regression test for scattered-head (BHLNC) layouts

[Upstream PR](https://github.com/vllm-project/vllm/pull/64118) · state: open · merged: False

## Original PR description

## Overview

Regression test for the scattered-head (BHLNC) case of `MooncakeStoreConnector`, the bug in #64117. The code fix landed in #63513, which separated `block_stride` from `block_len`; this PR pins that behaviour for layouts where a head's blocks are interleaved with other heads' and layers' pages, which #63513's own tests (padding on a layer-outermost buffer) do not exercise.

## Claims

- Under a BHLNC-shaped tensor, descriptor sizes equal the dense per-head extent, not the block stride.
- For every physical block, every descriptor lies inside the registered storage, so a transfer can never run past the allocation, including from the last block.
- A byte round trip of a middle block and of the last block restores the block and leaves neighbouring layers and the adjacent block untouched.

## Validation

`tests/v1/kv_connector/unit/test_mooncake_store_layout.py::test_rank_local_scattered_heads_transfer_dense_extent_only[1|2]`: passes on `main` (after #63513); fails on `main` before #63513 with `sizes == [block_stride] * heads`. The rest of the file is unchanged.

## Details

A per-layer view under BHLNC has shape `(B, H, N, C)` and strides `(H·L·N·C, L·N·C, C, 1)`: `head_cache[0]` is dense (`N·C` elements) while `head_cache.stride(0)` spans the whole block. The test builds that tensor from a `(B, H, L, N, C)` buffer, registers one layer's view, and checks descriptors and a round trip with bystander data modified in between. No change to connector code.
