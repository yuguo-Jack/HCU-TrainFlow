# [ROCm][Perf] Use Triton split-KV unified attention for decode-width batches on gfx950

[Upstream PR](https://github.com/vllm-project/vllm/pull/62476) · state: open · merged: False

## Original PR description

## Purpose

AITER's `unified_attention` (used by `ROCM_AITER_UNIFIED_ATTN`) now defaults to its new gfx950 Gluon kernel. For long-context batches with only a few queries per sequence — decode and speculative-verification widths, e.g. an EAGLE3 draft attending over a 100k+ token context — its KV split leaves the launch on too few workgroups, and it is much slower than AITER's Triton split-KV kernels.

This PR:
- passes `backend="triton"` to AITER for batches whose max query length is `<= 16` on gfx950 (prefill-sized batches keep AITER's default choice);
- adds `VLLM_ROCM_AITER_UNIFIED_ATTN_BACKEND` (`triton` / `gluon`) to force either backend;
- leaves older AITER builds whose `unified_attention` has no `backend` argument untouched.

## Results (MI355X, MiniMax-M3-MXFP4 TP4, EAGLE3-GQA draft on `ROCM_AITER_UNIFIED_ATTN`)

**Kernel level** (torch profiler, decode step with 24 requests × 4 tokens, ~8.4k context): draft attention per cycle 512 µs (`_unified_attention_gluon_kernel` ×6) → 253 µs (`kernel_unified_attention_3d` + `reduce_segments`); full decode cycle 15.17 ms → 14.78 ms.

## Test plan

- Real EAGLE3 (non-synthetic) correctness smoke on the patched image: 24 concurrent requests with ≥8k-token prompts and 4 short requests, greedy, exact expected output — 24/24 and 4/4 pass.
- Profiler trace confirms every draft attention call takes the Triton kernels and the target model path is unchanged.
- `ruff check` / `ruff format` clean.

## Notes

- The `<= 16` query-length threshold is meant to cover decode and speculative-verification widths; only the MiniMax-M3 EAGLE3 configuration above was measured. Happy to narrow it (e.g. to `== 1` plus the spec-decode width) or tune it per model if reviewers prefer.
- The underlying issue is the Gluon kernel's `kv_split` config for few-query, long-context decode on gfx950; an AITER-side tuning fix would let this default be revisited.
