# [ROCm][MiniMax-M3] Opt-in dense causal attention for short MSA prefill requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/65309) · state: closed · merged: False

## Original PR description

## Purpose

MiniMax-M3's MSA sparse attention runs prefill tokens through the sparse (top-k block) path, which for short prefill requests costs more than plain causal attention: when a request is no longer than the sparse window, the top-k selection keeps every block anyway. This adds an opt-in dense causal attention path for prefill (ROCm, AITER page-16 path) when every prefill request in the step is ≤ N tokens, plus one kernel specialization fix so the dense path does not recompile on data-dependent alignment/stride.

## Test Result

- Correctness (dense vs sparse on real serving data, 32 checks): head-row mean |dense − sparse| ≤ 0.215% of mean |sparse| (stop rule 2%).
- MI355X, TP4, ~12.6k-token prefill steps: MSA attention 228 → 143 µs per layer, −2.4% of the step. Full benchmark passes with it: 118.4% / 117.1% of a B200 reference; MMMU 0.656 / 0.642.

Related: #52963 optimizes the Triton sparse GQA prefill kernel (a different path; complementary). #64172 (BF16 Q/P in the AITER sparse PA): if it lands, the dense path's Q precision should follow it.
