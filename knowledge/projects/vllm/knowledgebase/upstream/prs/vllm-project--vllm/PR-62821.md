# [Bugfix][KV Connector] Forward LMCache adapter shutdown

[Upstream PR](https://github.com/vllm-project/vllm/pull/62821) · state: closed · merged: False

## Original PR description

## Overview

Forward the built-in LMCache connector's shutdown hook to adapters that implement it, releasing LMCache services before EngineCore exits. Fixes #62808.

## Claims

- Both scheduler and worker connectors delegate cleanup through the adapter's public `shutdown()`.
- Native/older adapters without a callable hook retain their existing no-op behavior. This does not add native adapter cleanup.
- Successful shutdown runs once per wrapper; raised cleanup errors propagate and permit retry.

## Validation

H100 PCIe, Qwen3-0.6B, MRV2, TP1, FP16/eager/FlashAttention, built-in connector with `kv_both`, LMCache dev `90a4ae2`, CPU/local-disk caches. Current vLLM Python source `0495a3de32` uses existing precompiled kernels with Torch 2.14/cu130. LMCache CUDA/common extensions were rebuilt from that dev revision against this Torch; there is no adapter or cache-layout compatibility patch.

| Check | Baseline | Change |
| --- | --- | --- |
| Existing connector unit suite plus shutdown regressions | 3 failed, 26 passed | 29 passed |
| Real HTTP completions | Two HTTP200 responses | Same generated text and usage at each corresponding request index |
| Cache store/retrieve | 128 tokens; two disk files | Same |
| SIGTERM to API exit, timeout 28s (one run per arm) | 29.02s; EngineCore force-killed | 9.11s; normal exit |
| Adapter/manager shutdown logs | Absent | Both roles complete cleanup |
| Harness termination / residual children | None / none | None / none |

Baseline stack dumps show EngineCore's main thread in `threading._shutdown` with LMCache lookup/offload and other background threads still running. The patch logs successful worker and scheduler manager cleanup, exits 0 and needs no timeout force-kill.

```bash
.venv/bin/python -m pytest tests/v1/kv_connector/unit/test_lmcache_connector.py -q
pre-commit run --files vllm/distributed/kv_transfer/kv_connector/v1/lmcache_connector.py tests/v1/kv_connector/unit/test_lmcache_connector.py
```

The regression uses a concrete adapter owning a real non-daemon thread; calling the connector's public shutdown must stop it. Additional cases cover adapters without the hook, repeated shutdown, and a raised cleanup error followed by retry. Existing Buildkite `v1/kv_connector/unit` coverage includes these tests. Changed-file pre-commit and `git diff --check` pass.

**Existing validation limitation:** cold and warm generated text differ on unmodified source in this dev stack. The identical difference persists after the patch; corresponding cold/warm outputs and usage match across the A/B arms. Initial strict cold-vs-warm checks failed and were retained. This validates shutdown and preservation of the observed request/cache behavior, not general warm-cache or model correctness. No model quality or performance improvement is claimed. TP>1, remote storage, and native adapter cleanup were not qualified.

## Details

vLLM already calls the connector shutdown hook, but this wrapper inherits the base no-op. Use the same callable-hook compatibility convention as adjacent optional adapter hooks. LMCache 0.3.9 and the in-tree `use_native=True` adapter lack `shutdown`; 0.4.4, 0.5.6 and current dev provide the hook. The adapter owns destruction order; the wrapper does not access manager internals. Mark the wrapper shut down only after successful return, so actual raised errors are not mistaken for success.

Duplicate checks: #36905 was closed unmerged; #62223 guards optional events and does not forward shutdown; #53298 concerns load-rejection recovery. Searches by issue number and LMCache shutdown/teardown found no direct fixing PR. A new independent CPU dispatch-control comment explicitly reports no competing PR and does not test actual LMCache teardown.
