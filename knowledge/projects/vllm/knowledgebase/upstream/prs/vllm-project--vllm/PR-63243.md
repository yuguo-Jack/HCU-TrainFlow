# [ROCm][Perf][DSv4] Use AITER tuned GEMM for the Router GEMM on gfx1250

[Upstream PR](https://github.com/vllm-project/vllm/pull/63243) · state: open · merged: False

## Original PR description

## Purpose

On gfx1250, `GateLinear` sends the BF16 MoE router GEMM to `torch.mm(x, w.T, out_dtype=torch.float32)`, which runs on hipBLASLt. At router shapes the hipBLASLt kernel it picks takes 0.45–0.85 ms per call at any M. On DeepSeek-V4-Pro (61 MoE layers) that adds about 49 ms to every decode step.

This PR sends gfx1250 through the dispatch gfx950 already uses. On CDNA5+, `rocm_fp32_router_gemm` then calls AITER `tgemm` with FP32 output:

- `gate_linear.py`: tier 2 (FP32 weights) and tier 6 (BF16 weights → `fp32_router_gemm_dispatch`) are now gated on `get_cdna_version() >= 4` instead of gfx950 only. On CDNA5+ the dispatch has no token limit. The unused `is_gfx950` attribute is removed.
- `rocm_fp32_router_gemm.py`: on `get_cdna_version() >= 5`, call `tgemm.mm(x, w, otype=torch.float32)`. Validation accepts CDNA4+ and requires BF16 input and weight on CDNA5+; otherwise it falls back as before.
- gfx950 is unchanged: native kernel for small M, `torch.mm` otherwise.

For these shapes on gfx1250, `tgemm` resolves to AITER's Gluon `gemm_a16w16` with per-(N, K) tuned configs.

## Test Plan

```
pytest tests/kernels/test_gate_linear_rocm_dispatch.py \
       tests/kernels/test_rocm_router_gemm_gfx1250.py
```

- `test_gate_linear_rocm_dispatch.py`: adds two gfx1250 dispatch cases (tier 2 and tier 6 routing).
- `test_rocm_router_gemm_gfx1250.py` (new): `rocm_fp32_router_gemm` against an FP64 reference at the DeepSeek-V4 Pro and Flash router shapes, M up to 16384, including top-k expert-set agreement.

Kernel accuracy and timing were also checked standalone at the router shapes of DeepSeek-V4 Pro / Flash, DeepSeek-V4.1 Flash, Kimi-K3 and GLM-5. gsm8k was run on DeepSeek-V4 Pro and Flash.

The gfx1250 runs used ROCm's gfx1250 development branch with the identical patch applied (same patch-id).
