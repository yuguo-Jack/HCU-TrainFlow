# [BugFix][MyPy] Guard Linux-only mmap/fadvise calls with sys.platform

[Upstream PR](https://github.com/vllm-project/vllm/pull/61836) · state: closed · merged: True

## Original PR description

## Purpose

`mmap.MADV_HUGEPAGE`, `os.posix_fadvise` and `os.POSIX_FADV_DONTNEED` are
Linux-only. On macOS, mypy fails with:

```text
vllm/model_executor/model_loader/weight_utils.py:923: error: Module has no attribute "posix_fadvise"  [attr-defined]
vllm/model_executor/model_loader/weight_utils.py:923: error: Module has no attribute "POSIX_FADV_DONTNEED"  [attr-defined]
vllm/models/deepseek_v41/common/engram.py:911: error: Module has no attribute "MADV_HUGEPAGE"  [attr-defined]
```

At runtime the same lines raise `AttributeError`, which the surrounding
`except OSError` does not catch.

This PR adds a `sys.platform != "linux"` early return so that non-Linux
platforms take the existing fallbacks:

- `_allocate_huge_page_storage` returns `None`, so the caller falls back to
  pinned memory.
- `drop_checkpoint_cache` skips page-cache eviction.

mypy understands `sys.platform` checks, so the Linux-only code is no longer
type-checked on macOS. This follows the same approach as #41465.

Both call sites were introduced in #56926.

## Duplicate check

I searched open PRs for `posix_fadvise`, `MADV_HUGEPAGE` and `mypy sys.platform`.
None of the open PRs guards these calls or fixes the macOS mypy errors.
