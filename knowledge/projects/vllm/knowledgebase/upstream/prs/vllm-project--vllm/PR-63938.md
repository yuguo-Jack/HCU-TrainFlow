# [KV Connector] Forward preschedule lookup handles through MultiConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/63938) · state: open · merged: False

## Original PR description

## Overview
Stacked on Dao Le's #61292 (rebased prerequisite `297124bdf`), including #63932. Forward arrival-time lookup through flat/nested MultiConnector while keeping each child's handle isolated and preserving first-hit selection.

## Claims
- Keep unadopted handles valid only within their lookup generation; reset invalidates earlier results, including failed resets.
- Cancel queued work on rejection/finish and give scheduler clients an explicit shutdown owner. Already-running queries may finish; shutdown interrupts blocked replies.

## Validation
Head `e0e5656ad`, rebased onto `main@d929755b7`:

- **159 CPU tests passed**, 1 existing skip and 1 model test deselected.
- Reset fault injection (removing the generation increment) makes all three reset cases fail. Earlier real ZMQ unanswered-lookup shutdown also passed; that standalone probe was not rerun this round.
- Existing MultiConnector storage/load consistency test passed with Qwen3-0.6B on one GPU (eager, 512-token limit, 64 MiB KV cache).
- Whole-diff pre-commit including mypy passed. Source hashes match the tested snapshot.

## Details
Tests reuse real MultiConnector queues for pending/first-hit selection, cancellation and shutdown; reset-invalidated handles and bounded cache reads remain covered. The capacity regression waits for the executor to finish its callbacks instead of retrying after sleeps. Shutdown, generation fencing and child-handle restoration remain necessary lifecycle boundaries. The model check does not validate native Mooncake serving performance. Keep draft pending dependencies/design review and upstream CI. Prerequisite authorship is preserved; AI assistance was used.
