# fix: release committed encoder data for resumable sessions

[Upstream PR](https://github.com/vllm-project/vllm/pull/50871) · state: open · merged: False

## Original PR description

Fixes #50860

## Why this is not a duplicate
Checked `gh pr list --state open --search "50860 in:body"` and issue keywords
"resumable session encoder memory" — no open PR addresses this. The issue has
no assignee and no comments.

## Summary
`Scheduler._free_encoder_inputs` already frees the scheduler/encoder-cache
reference for committed multimodal inputs, but the raw input tensors
(`MultiModalFeatureSpec.data`) stay attached to the request. For resumable
(realtime) sessions, which keep one `Request` alive for the whole stream and
append a new `MultiModalFeatureSpec` per frame via `_update_request_as_session`,
the data for every committed frame is retained until the session ends.

This change nulls `mm_feature.data` at the same point the encoder input is
freed, gated on `request.resumable` so non-session requests are unaffected.
`MultiModalFeatureSpec.data` is documented as "Can be `None` if the item is
cached" (`vllm/multimodal/inputs.py`), and by the time the input is freed its
encoder output is already committed to the decoder KV cache, so the raw
tensors are never read again.

## Model evaluation
No model weights or output-affecting code path is touched; the change only
releases already-committed input tensors. The original reporter measured
1021 MiB engine-core host RSS growth over 4000 frames with this retention.

## Tests

**Preserve multimodal data when the encoder output can be evicted.**

`_free_encoder_inputs()` sets `MultiModalFeatureSpec.data` to `None` after releasing the encoder-cache reference. If another allocation evicts that encoder output before the resumable request is scheduled again, `_try_schedule_encoder_inputs()` schedules the feature, but `EncoderRunner.prepare_mm_inputs()` skips it because its data is `None`. `gather_mm_embeddings()` then raises `RuntimeError("Encoder cache miss for ...")`.

Retain the raw data, or restore it from a valid multimodal cache, whenever the encoder output is not guaranteed to survive preemption and cache eviction. Add a regression test for release → eviction or preemption → reschedule.
