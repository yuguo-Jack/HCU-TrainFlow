# [Bugfix] Consume prompt embedding sentinel IDs before model execution

[Upstream PR](https://github.com/vllm-project/vllm/pull/64367) · state: closed · merged: True

## Original PR description



## Overview

Fix chat requests that mix prompt embeddings and images when the prompt-embedding placeholder ID is outside the model vocabulary. Consume these temporary IDs during preprocessing instead of passing them to token validation and embedding lookup.

Discovered while helping validate vllm-project/vllm#58658 and vllm-project/vllm#63190, but this is a distinct issue: the fix consumes temporary placeholder IDs in the renderer, rather than changing tower/connector LoRA or prompt-embedding passthrough handling in the runner.

## Claims

- Replace only prompt-embedding placeholder spans with safe dummy token IDs after locating all spans.
- Preserve surrounding text IDs, supplied embedding tensors, and embedding offsets.
- Fix the request rejection and avoid the TP=1 out-of-bounds embedding lookup, without tokenizer-cache, model-runner, or model-specific changes.

Save the following script locally and run it with `.venv/bin/python mre.py`. It downloads the tokenizer and the checkpoint shard containing the token embedding weights, constructs real prompt embeddings, and sends them alongside an image. The image URL requires network access. Set `MODEL_NAME` to another listed model and restart the server to compare models.

```python
# SPDX-License-Identifier: Apache-2.0

"""Send multimodal + prompt embeds to a local vLLM server and print the response."""

import json
import pprint

import httpx
import torch
import transformers
from huggingface_hub import hf_hub_download
from huggingface_hub.errors import RemoteEntryNotFoundError
from safetensors import safe_open

from vllm.utils.serial_utils import tensor2base64

# MODEL_NAME = "nvidia/Nemotron-3-Nano-Omni-30B-A3B-Reasoning-BF16"
MODEL_NAME = "Google/gemma-4-E2B-it"
# MODEL_NAME = "Qwen/Qwen3.5-0.8B"
# MODEL_NAME = "Qwen/Qwen3.5-2B"
# MODEL_NAME = "deepseek-ai/DeepSeek-OCR-2"
# MODEL_NAME = "LiquidAI/LFM2.5-VL-450M"
# MODEL_NAME = "HuggingFaceTB/SmolVLM-256M-Instruct"
# MODEL_NAME = "llava-hf/llava-onevision-qwen2-0.5b-ov-hf"
SERVER_URL = "http://localhost:8000/v1/chat/completions"


key_name_lookup = {
    "nvidia/Nemotron-3-Nano-Omni-30B-A3B-Reasoning-BF16": "language_model.backbone.embeddings.weight",
    "Qwen/Qwen3.5-0.8B": "model.language_model.embed_tokens.weight",
    "Qwen/Qwen3.5-2B": "model.language_model.embed_tokens.weight",
    "deepseek-ai/DeepSeek-OCR-2": "model.embed_tokens.weight",
    "Google/gemma-4-E2B-it": "model.language_model.embed_tokens.weight",
    "LiquidAI/LFM2.5-VL-450M": "model.language_model.embed_tokens.weight",
    "HuggingFaceTB/SmolVLM-256M-Instruct": "model.text_model.embed_tokens.weight",
    "llava-hf/llava-onevision-qwen2-0.5b-ov-hf": "language_model.model.embed_tokens.weight",
}


def load_embedding_layer(
    model_name: str,
    key: str | None = None,
) -> torch.nn.Embedding:
    if key is None:
        key = key_name_lookup[model_name]

    try:
        index_path = hf_hub_download(model_name, "model.safetensors.index.json")
    except RemoteEntryNotFoundError:
        shard_name = "model.safetensors"
    else:
        with open(index_path) as f:
            index = json.load(f)
        shard_name = index["weight_map"][key]

    shard = hf_hub_download(model_name, shard_name)
    with safe_open(shard, framework="pt") as f:
        weight = f.get_tensor(key)
    return torch.nn.Embedding.from_pretrained(weight)


def encode(
    tokenizer: transformers.PreTrainedTokenizerBase, embedding_layer, text: str
) -> str:
    token_ids = tokenizer(text, return_tensors="pt", add_special_tokens=False).input_ids
    prompt_embeds = embedding_layer(token_ids).squeeze(0)
    return tensor2base64(prompt_embeds)


def main() -> None:
    tokenizer = transformers.AutoTokenizer.from_pretrained(
        MODEL_NAME, trust_remote_code=True
    )
    embedding_layer = load_embedding_layer(MODEL_NAME)

    messages = [
        {
            "role": "user",
            "content": "This part is text. The part that follows will be prompt embeddings. Please tell me the color they say.",
        },
        {
            "role": "user",
            "content": [
                {
                    "type": "prompt_embeds",
                    "data": encode(
                        tokenizer,
                        embedding_layer,
                        "This part is prompt embeddings. The color is purple. End prompt embeds.",
                    ),
                },
            ],
        },
        {
            "role": "user",
            "content": [
                {
                    "type": "image_url",
                    "image_url": {
                        "url": "https://fastly.picsum.photos/id/373/200/300.jpg?hmac=GXSHLvl-WsHouC5yVXzXVLNnpn21lCdp5rjUE_wyK-8"
                    },
                },
            ],
        },
        {
            "role": "user",
            "content": "Please describe the image to me. Then tell me my favorite color.",
        },
    ]

    request = {
        "model": MODEL_NAME,
        "max_tokens": 1024,
        "temperature": 0.0,
        "messages": messages,
    }

    r = httpx.post(SERVER_URL, json=request, timeout=600)

    print("-" * 30)
    if r.status_code == 200:
        response_json = r.json()
        print("-" * 30)
        pprint.pprint(response_json)
        print("-" * 30)
        print(response_json["choices"][0]["message"]["content"])
    else:
        print(r.status_code, r.text)
    print("-" * 30)


if __name__ == "__main__":
    main()
```

## Details

The mixed-input path already records the positions and tensors needed for embedding splicing, but leaves the temporary sentinel IDs in `prompt_token_ids`. A newly registered sentinel can exceed the cached tokenizer's vocabulary bound, causing HTTP 400. If validation accepts the sentinel, an out-of-range model embedding lookup can instead crash before the supplied embedding is merged. TP>1 shard masking can hide that latter failure.

After locating all spans, replace their token IDs with `0` and write the updated list back to the engine input. The existing multimodal merge overwrites those dummy embeddings with the supplied tensors. Ordinary token IDs are not changed, so their validation remains intact.

The production change is two added lines. Tests cover two embedding spans of different lengths and real TP=1 image/embedding serving; documentation describes mixed image and prompt-embedding inputs.

Duplicate-work checks found no matching open upstream PR. The related vllm-project/vllm#51123 addresses LoRA batch-shape handling in the runner, not mixed-input sentinel consumption in the renderer.

AI assistance was used to investigate, implement, and test this change.
