# [Performance] Whisper: move log-mel extractor to GPU worker and batch conv stem

[Upstream PR](https://github.com/vllm-project/vllm/pull/62413) · state: open · merged: False

## Original PR description

## Background

Two related performance issues surfaced on the vLLM Whisper pipeline, both reported by @Aravind-11:

1. **[#62355](https://github.com/vllm-project/vllm/issues/62355)** — `WhisperFeatureExtractor._torch_extract_fbank_features` (CPU float32 STFT) runs on the renderers single multimodal thread (`max_workers=1`). For Whisper this is the bottleneck before the encoder even starts.
2. **[#62352](https://github.com/vllm-project/vllm/issues/62352)** — `WhisperEncoder.forward` runs a per-item Python loop over `gelu(conv1) → gelu(conv2) → transpose → +embed_positions`, one CUDA launch per audio clip.

Combined fix: ship the resampled PCM to the GPU worker, run STFT + Slaney mel extractor there, and collapse the conv stem loop into a batched op.

## What this PR does

### A. `keep_dtype_keys` infrastructure (foundation)

New processor-level class attr `keep_dtype_keys: frozenset[str]` in `BaseMultiModalProcessor`. `InputProcessingContext._postprocess_output` and `call_hf_processor` accept it as a keyword argument. Fields whose names land in the set skip the model-dtype cast (they are still moved to CPU).

Demonstrated by PR #60352 for Voxtral, needed here to keep Whispers fp32 PCM round-trip safe.

### B. Whisper log-mel on the GPU worker (closes #62355)

- `WhisperMultiModalProcessor._get_hf_mm_inputs` no longer runs the HF extractor. Audio resampling still happens (downstream), but the post-resample mono float32 waveform becomes a passthrough field `audio_pcm` with `keep_dtype_keys={"audio_pcm"}`.
- `_get_mm_fields_config` exports `audio_pcm=MultiModalFieldConfig.batched("audio")` instead of `input_features`.
- `WhisperForConditionalGeneration.__init__` captures extractor constants (`n_fft`, `hop_length`, `win_length`, `feature_size`, `chunk_length`, `sampling_rate`, `mel_filters`, `dither`, `hann_window`) once from `vllm_config.model_config.get_hf_processor().feature_extractor`.
- New `_gpu_log_mel(audio_pcm: list[Tensor])` runs the STFT → Slaney mel → `clamp(log10)` → per-clip max −8 → `/4 + 1` formula on the conv device, in fp32, then casts to the stem dtype. Matches `transformers.WhisperFeatureExtractor._torch_extract_fbank_features` within ~1e-5.
- New `WhisperAudioInputs.audio_pcm` field alongside the legacy `input_features`. `embed_multimodal` prefers `audio_pcm`; `input_features` is accepted as a backward-compat path so existing tests and cached entries still work.

### C. Batched conv stem (closes #62352, 1st half)

`WhisperEncoder.forward` replaces the per-item loop with:

1. `_conv_embed`: pure batched helper — `gelu(conv1) → gelu(conv2) → transpose → +embed_positions → to(dtype)`. Works on both rank-2 and rank-3 inputs.
2. Forward fast paths:
   - Rank-3 tensor → one `_conv_embed`.
   - Equal-shape rank-3 list → `cat(dim=0)` first (Moss path, calls `WhisperEncoder.forward([rank-3])`).
   - Equal-shape rank-2 list → `stack(dim=0)` first.
   - Unequal shapes / mixed ranks → per-item fallback loop.
3. `_static_full_chunk_mel_len` validates stock Whisper conv config (stride 1/2, kernel 3, pad 1) and returns `max_source_positions * 2` for a future CUDA-graph capture.

`UltravoxWhisperEncoder` (which overrides `forward`) and non-standard conv configurations are untouched.

## Not yet in this PR

- **CUDA-graph capture** for the fixed full-chunk mel shape. Requires implementing `SupportsEncoderCudaGraph` on `WhisperForConditionalGeneration` (budget clamp change + static-full-chunk detection + manager contract). Follow-up.
- **hash salt** (`audio_ipc_schema="whisper_pcm_f32_v1"`). Current `passthrough_data` key rename (`input_features` → `audio_pcm`) changes the field name in the final processor output, so any existing UUID cache entry will miss on replay (schema mismatch). A dedicated salt in `get_mm_hashes` is still the cleaner long-term fix; filed as a follow-up task.
- **Unit test file** (`tests/models/multimodal/generation/test_whisper_encoder_cudagraph.py` per issue #62352 check list) — deferred until CUDA graph lands, but will reuse the tiny `max_source_positions=8` local-config pattern from the issue.

## Why this is not a duplicate

Search results confirm no open PR currently addresses #62355 or #62352. The closest upstream PR (#60352) is about Voxtral raw audio in fp32 — it inspired the `keep_dtype_keys` mechanism, which is a subset of this PR.
