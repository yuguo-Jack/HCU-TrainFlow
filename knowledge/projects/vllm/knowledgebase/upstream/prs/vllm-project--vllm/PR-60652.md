# [Bugfix][Spec Decode] Resample grammar-invalid drafts from the residual

[Upstream PR](https://github.com/vllm-project/vllm/pull/60652) · state: closed · merged: False

## Original PR description

Problem: with probabilistic drafting and structured outputs, the token at the position of the first grammar-invalid draft was drawn from the full masked target p instead of the residual max(p - q, 0). The draft was sampled from q and whether it is invalid depends on its value, so this biases the output distribution. In a toy case with p = (.5, .5, 0) and q = (.5, 0, .5) the output goes from .5/.5 to .75/.25. With EAGLE3 (k=3), Qwen3-8B and a city-choice regex at T=1.0, Rome moved from 0.229 to 0.332 (chi-square p = 7e-29 against no speculation, n=4000).

Root cause:
- Async scheduling: `grammar_invalid_drafts` replaced the first invalid draft with -1, and the rejection sampler treats a -1 row like a bonus row and samples from p.
- Sync scheduling: `Scheduler.update_draft_token_ids` truncated the drafts before the first invalid one, so the token at that position was sampled as a bonus token from p.

Fix: keep the first invalid draft's id. `grammar_bitmask` fills row i before it inspects token i, so that draft's row carries the real grammar mask, the target gives it p = 0, verification rejects it, and the existing resample draws from the residual.
- Async: `grammar_invalid_drafts` uses `num_acceptable_drafts + 1`; only later drafts, which met `_full_mask`, become -1. When `num_acceptable_drafts` is unknown, the whole window is still rejected.
- Sync: `update_draft_token_ids` keeps the first invalid draft.
- Synthetic rejection accepts by rate and ignores p, so it could accept the kept draft and the request then ended with "grammar rejected tokens". The Model Runner V2 synthetic kernels now accept only drafts with p(x) > 0. For Model Runner V1, the sync scheduler keeps no invalid draft when `rejection_sample_method` is "synthetic".
- Metrics: the sync scheduler sets `num_invalid_spec_tokens` to 1 for a scheduled kept draft, as the async path does, so it is not counted as drafted. Without this, sync reported 4.9% draft acceptance against 37.4% on async in the city-choice run; both now report 37.4%.
- The bitmask fill no longer logs "Unexpected: grammar terminated or rejected draft token" for the kept last draft with sync scheduling; it still logs it with async scheduling.

Greedy verification is unchanged: it rejects the kept draft as before, because the target argmax is never a masked token.

Verification (Qwen3-8B, EAGLE3 k=3, n=4000, watermark off, T=1.0): city-choice chi-square p goes from 7e-29 to 0.26 on Model Runner V2 with async, sync and block verification, and to 0.42 with sync on Model Runner V1. All outputs are regex-valid with finish_reason=stop. Unit tests cover the new `grammar_invalid_drafts` limits, the kept draft and its `num_invalid_spec_tokens` count in the scheduler (standard and synthetic), and synthetic rejection of a masked draft.

Also clarify the `WatermarkConfig.alpha` docstring: under speculative decoding, accepted drafts use key A and recovered or bonus tokens use key B, so the effective key-B share is 1 - accepted draft tokens / generated tokens, and that is the value to pass as the detector's `alpha`.
