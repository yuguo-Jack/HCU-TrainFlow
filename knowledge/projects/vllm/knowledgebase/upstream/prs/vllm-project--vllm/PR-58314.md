# [Perf][Frontend] Serialize completion responses without an intermediate dict

[Upstream PR](https://github.com/vllm-project/vllm/pull/58314) · state: open · merged: False

## Original PR description

## Purpose

Long non-streaming completions build a nested Python dictionary and then encode it as JSON, concentrating duplicate work when many requests finish or abort together. Render ordinary completion models directly with Pydantic's existing `model_dump_json()`. Reuse `JSONResponse` so headers and background load accounting keep their lifecycle. Runtime change: one file, +44/-2 lines. Direct serialization alone would be +7/-2 (five nonblank added lines: a three-line JSONResponse subclass and two route replacements); the additional 37 lines retain legacy behavior and include imports, comments and spacing. The seven-line variant is illustrative, not the submitted implementation.

Fall back to the original renderer for non-finite logprobs, arbitrary extras, transfer metadata, prompt logprobs, metrics, or fast-path serialization errors. Preserve existing errors; successful JSON number formatting can differ while parsed values match. Error responses and streaming are unchanged.

Part of #57479, independently reviewable from #58278. Open-PR searches for the RFC, completion/native JSON and serialization found no duplicate: #52875 optimizes streaming frames, #54050 caches token decoding, and #48585 changes non-finite-logprob handling; this PR preserves that handling.
