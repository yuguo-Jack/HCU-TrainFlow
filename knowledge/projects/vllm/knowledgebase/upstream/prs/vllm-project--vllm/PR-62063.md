# [Bugfix][Qwen4Exp] Fix PLE layerwise reload with CPU offload and TP

[Upstream PR](https://github.com/vllm-project/vllm/pull/62063) · state: open · merged: False

## Original PR description

## Purpose

Layerwise weight reload of Qwen4Exp with a CPU-offloaded PLE table (`engram_config.cpu_offload`) materializes the replacement table on the GPU, because reload restores every layer on the default device. It also buffers every PLE checkpoint shard until the layer completes, including shards outside the local TP vocab range. At full size this OOMs (+23.8 GiB/rank at TP4).

Fix: skip non-local PLE shards before calling the weight loader, and restore the pinned-host PLE table on the CPU.

## Test Plan

Two new tests in `tests/models/qwen4_exp/test_ple.py`. TP4 on H200 with the Qwen3.8-Flash-Next PLE config (1 GiB table per rank, shards arriving on the GPU): peak extra CUDA memory during reload went from 2.0/3.0/4.0/5.0 GiB (ranks 0-3) to 1.0 GiB on every rank; values, pinned storage and pointer are preserved.

AI assistance (Claude) was used; all changes were reviewed by the submitter.
