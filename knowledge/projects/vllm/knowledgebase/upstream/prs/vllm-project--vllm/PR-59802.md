# [ROCm][DSv4.1][Perf] Overlap the mHC gate projection with attention and FFN

[Upstream PR](https://github.com/vllm-project/vllm/pull/59802) · state: closed · merged: True

## Original PR description

## Overview

On ROCm, each DeepSeek V4.1 mHC seam ran the whole fused AITER kernel pair on the default stream before the next sublayer could start. That pair is the post block, the gate projection, Sinkhorn, and the collapse with RMSNorm. This PR moves the gate projection onto a side stream inside FULL HIP graphs, so it overlaps with the following attention or FFN. The default stream now only runs the post block plus the RMSNorm'd collapse, in one new Triton kernel. This is the ROCm counterpart of the CUDA overlap in [#57603](https://github.com/vllm-project/vllm/pull/57603).

## Claims

- Output throughput is up 0.3% to 5.4% end to end on DeepSeek-V4.1-Flash, EP, FP8 KV, MI355X, at every concurrency from 1 to 128 at TP2, TP4 and TP8.
- The new residual and the gates (post, comb, next pre) are bit-identical to the fused AITER seam. The layer input is bit-identical up to 16 tokens and within one bf16 ulp above that.
- No change outside FULL-graph decode with at most 128 tokens. Prefill, piecewise graphs, eager mode, CUDA and DSpark draft layers keep the current path.

All pass on MI355X. `test_deepseek_v41_rocm_mhc_overlap_matches_fused_seam` is new and runs at 1, 2, 7, 16, 64 and 128 tokens. After joining the side stream, it compares every output with `MHCPreDelayedOp.forward_hip` (the fused AITER seam):

- the residual and gates must match exactly;
- the layer input must match within one bf16 ulp, and it must already be usable before the join;
- the same checks are repeated across three HIP-graph replays with changing inputs.

CI runs it in `:amd: (MI355) mHC Kernels`.

## Details

**Why the split is exact.** In AITER's fused seam (`_mhc_fused_post_pre_delayed_rmsnorm_main_kernel`), the post-mix is rounded to bf16 once, and that rounded `R'` feeds the projection, the square sums and the collapse. This PR splits the seam in two:

- The new kernel recomputes `R'` with the same expression order, so it is bit-identical, then collapses it with the carried pre-mix and applies the RMSNorm.
- The side stream runs AITER's own fused kernel on `R'` without the post (`HAS_POST=False`). Its gates are therefore the same numbers.

Only the RMSNorm's row sum differs. The new kernel holds a token's row in registers and sums it in one pass, while AITER reduces it across split-K programs, so the order changes. That is exact at decode sizes, and within one ulp otherwise.

**Gating.** The overlap runs only inside FULL HIP-graph capture, not in piecewise graphs, with `0 < tokens <= MHC_OVERLAP_MAX_TOKENS` (128). Fork and join then become graph edges; `DeepseekV41ROCMAiterMLAAttention` keeps its aux streams to captured graphs for the same reason. It also requires AITER's fused delayed seam (`HAS_AITER_MHC_FUSED_POST_PRE_DELAYED_RMS_NORM`), `hc_mult == 4`, and no ubatching. The 128-token limit is the largest tested point. The gain was still positive there but shrinking (above), and the overlap was not measured beyond it, although FULL graphs go up to 512 tokens.

**Seams.** The overlap applies to every FFN seam and to the attention seam of every layer after the first. Layer 0's broadcast seam and Engram seams already take a different path and keep it. The gate stream is joined after attention and at the end of each layer, which is where the gates are next read. The stream is separate from the attention aux streams, as on CUDA. `record_stream` keeps the side stream's inputs and the main stream's gate outputs alive across the fork. No host synchronization is added.

**Limitations.**

- **Tuning:** the token limit was tuned on MI355X TP2, TP4 and TP8.



### Existing PRs

I searched vllm-project/vllm PRs (open and closed) for mHC overlap, coefficient and side-stream work on ROCm. None moves the mHC seam off the default stream on ROCm.

- [#57603](https://github.com/vllm-project/vllm/pull/57603) (merged) is the CUDA version. It needs SM100 and DeepGEMM's `tf32_hc_prenorm_gemm`, and stops at 16 tokens. This PR follows its structure, gating and join points.
- [#56853](https://github.com/vllm-project/vllm/pull/56853) (merged) adds an attention-side aux stream for DeepSeek-V4 HCA layers. It keeps the mHC seam serial on the default stream, which is what this PR changes.
- [#58655](https://github.com/vllm-project/vllm/pull/58655) (merged) introduced the fused AITER delayed seam that this PR splits.
