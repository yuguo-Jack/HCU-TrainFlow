# [Bugfix][Gemma4] Quantize audio towers independently

[Upstream PR](https://github.com/vllm-project/vllm/pull/59935) · state: closed · merged: True

## Original PR description

## Overview

Fixes [#59905](https://github.com/vllm-project/vllm/issues/59905) by selecting quantization for Gemma 4 vision and audio towers independently.

## Claims

Quantizable Gemma 4 audio towers now receive the checkpoint quantization config even when the vision tower dimensions are not supported by that kernel.
Non-quantizable towers retain the existing unquantized path.
Methods that support arbitrary tower dimensions keep their existing behavior.

## Validation

Ruff check passed for the changed Python files.
 Ruff format check passed.
Python compileall passed.
 git diff --check passed.
 Added a focused regression test for independent tower dimension checks.
 The focused pytest could not complete in the available Windows environment: the local uv environment lacks pytest, and the prepared pytest environment hung while importing the full Gemma 4 multimodal module. No GPU checkpoint load was available locally.

## Details
The constructor previously computed one tower_quant decision from vision_config and reused it for audio_tower. AutoRound-GPTQ Gemma 4 checkpoints can have a non-quantizable vision tower and quantized audio tower. In that combination, vLLM created an unquantized audio weight, while the checkpoint provided GPTQ tensors such as qweight, scales, qzeros, and g_idx.

The new helper applies the existing dimension and method checks to each tower configuration separately. The change is limited to Gemma 4 multimodal model construction and does not alter quantization behavior for the language model.
