# docs: add NIXL P/D troubleshooting (auth layering, side-channel loopback)

[Upstream PR](https://github.com/vllm-project/vllm/pull/59584) · state: closed · merged: False

## Original PR description

Both items were hit and verified while bringing up a two-node NIXL P/D deployment (vllm-router front-end, TP8 + TP8):

1. **Auth layering** — with `--api-key` set on both backends and on the router, every request through the router returned `{"error":"Unauthorized"}`. The router log showed the first (prefill) stage succeeding and the second (decode) stage getting `401` — the router's internally-issued decode request does not carry the client's `Authorization` header. Removing `--api-key` from the backends (keeping it on the router) fixed it; direct calls to each backend continued to work throughout, which made the root cause non-obvious.

2. **Side-channel loopback** — a prefiller started without `VLLM_NIXL_SIDE_CHANNEL_HOST` advertises `localhost` as its handshake address; the decoder then handshakes with itself and every request logs `Remote NIXL agent engine ID mismatch. Expected <prefiller>, received <decoder's own id>`. Because the decoder falls back to recompute, requests can still return correct output, so nothing else points at the handshake. The env var itself is documented, but the failure signature is not; this adds a short troubleshooting entry (including how to recognize the loopback case: the "received" ID is the decoder's own engine ID). A companion code change that makes the error message name the missing env var directly is #59583.

Docs only; no code change.
