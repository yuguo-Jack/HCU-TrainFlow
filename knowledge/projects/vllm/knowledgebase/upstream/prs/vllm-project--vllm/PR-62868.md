# [Security] Refresh Python and runtime CA certificates

[Upstream PR](https://github.com/vllm-project/vllm/pull/62868) · state: closed · merged: True

## Original PR description



## Overview

Refresh Python and Ubuntu runtime CA bundles following the [eMudhra certificate incident](https://emudhra.we-have-a-problem.com). This certificate-only change is split out of #62835 so it can be reviewed and merged independently of the other dependency upgrades.

## Claims

- Require `certifi>=2026.10.19` in runtime and documentation inputs, and regenerate all five compiled requirements files. Python's [incident guidance](https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576) recommends this minimum.
- Explicitly install `ca-certificates` after `apt-get update` in `vllm-runtime-base`, refreshing the OS trust store used by default `aiohttp` and Rust/native TLS clients. Descendant runtime and test images inherit the bundle when rebuilt.
- Keep the patch limited to certificate inputs, generated certificate pins, the runtime package list, and associated documentation/lint configuration. LMCache and other library upgrades remain in #62835.

## Validation

- Regenerated all five locks using uv 0.11.1 and the exact platform, backend, constraint and exclusion arguments in `.pre-commit-config.yaml`. All applicable `pre_commit run --files <changed files>` hooks and `git diff --check` passed.
- Inspected all layers of Linux AMD64 `nvidia/cuda:13.0.3-base-ubuntu24.04`, platform manifest `sha256:97d085a7423ee18ec483a2878b9be2c976dc4ba908aef96518beb00e1899dcc4`. Its `ca-certificates=20240203` bundle trusts both `emSign ECC Root CA - G3` and `AAA Certificate Services`.
- Extracted the certificates from Ubuntu's [fixed package](https://security.ubuntu.com/ubuntu/pool/main/c/ca-certificates/ca-certificates_20260816ubuntu0.24.04.1_all.deb). Loaded both bundles independently with Python `ssl.SSLContext.load_verify_locations` and checked `get_ca_certs()`: both affected roots are present before the update and absent from the fixed package. The `certifi==2026.10.19` bundle also excludes both roots.
- Confirmed that the Dockerfile change only adds the runtime package and leaves stage dependencies unchanged. Docker is unavailable on this macOS host: the graph hook skips regeneration, and a full container rebuild/in-container TLS test remains pending. No model or inference code changes; model evaluations were not run.

## Details

Updating certifi does not update the operating-system trust store. Installing other runtime packages does not guarantee that an already-installed `ca-certificates` package gets upgraded. Listing it explicitly in the existing runtime installation step selects the current package from freshly updated APT metadata; rebuilding images against a mirror carrying the patched distro package is required. The shared-stage documentation explains this complementary coverage.

**Duplicate-work check:** searched open PRs for the incident, certifi and ca-certificates, and inspected the related diffs. #62835 now contains only the other dependency fixes; its certificate changes are removed by this split. #51503 adds certificates to a separate standalone Rust Dockerfile, not this shared CUDA runtime stage. #59667 covers ongoing dependency-refresh automation and remains separate. Both this PR and #62835 target `main` independently.
