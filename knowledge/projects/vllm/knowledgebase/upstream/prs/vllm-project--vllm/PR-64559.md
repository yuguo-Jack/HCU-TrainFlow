# [HiSparse] Remove dead code, unused custom-op arguments, and a stale connector check

[Upstream PR](https://github.com/vllm-project/vllm/pull/64559) · state: closed · merged: True

## Original PR description

## Purpose

Remove HiSparse state, parameters, and branches that nothing reads or reaches. No behavior change, except the config check and the plugin cache-ops signature under **Behavior change**.

| Removed | Why it is dead | Origin |
|---|---|---|
| `SparseKVPageTransfer.after_forward` and the worker's pre-forward submit | always `not restore`; the pre-forward list is always empty | #53781, made redundant by #57049 |
| `HiSparseCoordinator.managers`, `.max_model_len`, `.has_host_cache` | never read (last `managers` reader removed in #60647) | #53781 |
| worker `hot_backing` arg/attr, `cache_layer_names` attr, duplicate resident assert | never read | #53781 |
| `allocate_hisparse_host_pools` private-pool branch and canonical views | only caller passes `use_shared_host_pool=True` and discards the views | #56629 |
| second NIXL `_mixed_mem_types` assignment | identical to the one 24 lines above | #53781 |
| identical if/else in `DeepseekV32Attention`, plus its unreachable assert | both branches allocate the same buffers | #53781 |
| FlashMLA's `threshold = 1` for HiSparse | `SparseMLACommonMetadataBuilder._init_reorder_batch_threshold` already forces it | #53781 |
| `MLAAttentionImpl.hisparse_cache` | readers use the layer's attribute | #53781 |
| `hisparse_gather_plan`'s `request_state_indices`, `attention_indices`, `attention_block_stride` and 2D `hot_cache` path; `test_hisparse_gather_rejects_short_attention_block_stride` | the only caller (prefill staging) passes `None, None, 0` and a 3D staging cache; the test only exercised the dead stride arg | #53781 |
| `hisparse_resolve_residency`'s `miss_mask`, `resolved_global_indices`, `resident_null_block` and their kernel writes | always `None, None, 0`, set by no test; the null block is now the constant 0, the host-page marker `update_hisparse_residency` writes | #53781 |

Small hot-path tidy-ups:
- `_copy_host_blocks` uses `is_host_writer` instead of re-deriving it with a TP rank lookup, and drops an always-true `if self.host_caches`.
- `invalidate_blocks` reuses an `arange` built once instead of allocating one per call.
- `_enqueue_row_dma` no longer repeats `_init_dma`'s contiguity check for every layer on every step.
- `hisparse_gather_plan` and `hisparse_gather_compact` share one copy-or-zero row helper (`load_hot_row_warp`), which absorbs `zero_cache_row_warp`; comments made stale by the removed paths are fixed.
- `hisparse_resolve_residency` drops its per-call `cudaPointerGetAttributes` pinned check: it never reads host memory, only `host_cache`'s row count. The gather ops, which do read host memory, keep theirs. Kernel SASS is unchanged. Measured on its own (GLM-5.3-NVFP4, TP4 B200, 16k/1k, c=64, spilling to host, 3 runs each): 1020.5 tok/s on `main` vs 1018.7 with the change, within `main`'s 0.5% run-to-run spread; HiSparse unit and e2e tests pass.

None of the removed code was added by a bug fix. The fixes from #59007, #59036, #59282, #59309, #59494, #60161, #60941, #61659 and #63827 are untouched.

### Behavior change

HiSparse without `HiSparseConnector` + `host_pool_gib` (directly or nested in `MultiConnector`) now fails at config time; before, it constructed and only failed in KV planning after model load (`get_hisparse_host_pool_bytes`). The stale connector allowlist warning, which fired on the canonical `HiSparseConnector` setup, is removed. The check reuses `hisparse_host_pool_gib`, the helper planning uses, so it accepts exactly what planning accepts (incl. NIXL P/D and offloading via `MultiConnector`). It runs after `--kv-offloading-size` resolves the connector, so `HiSparseConnector` plus `--kv-offloading-size`, which replaces the connector, also fails at config time.

**Plugin cache ops.** `HiSparseBackend.create_cache_ops()` implementations are now called with the shorter `hisparse_resolve_residency` (3 fewer args) and `hisparse_gather_plan` (3 fewer args) signatures. No out-of-tree implementation exists today (GitHub code search), so nothing breaks; plugins must follow the new signatures.

Repro (macOS CPU, `get_hisparse_backend_cls` patched; `VllmConfig(attention_config=AttentionConfig(hisparse_config=HiSparseConfig()), kv_transfer_config=..., scheduler_config=SchedulerConfig(max_model_len=2048, is_encoder_decoder=False, disable_hybrid_kv_cache_manager=False))`):

| `kv_transfer_config` | `main` | this PR |
|---|---|---|
| `HiSparseConnector`, `host_pool_gib=32` | OK + warning "other connectors are treated as debug/fallback paths" | OK, no warning |
| `None` | OK (fails later in KV planning) | `ValueError: HiSparse requires a KV transfer config with HiSparseConnector and host_pool_gib; ...` |

Test: `pytest tests/test_config.py -k hisparse` → 16 passed; the new `test_hisparse_requires_hisparse_connector` cases (no connector, `MultiConnector` with only NIXL, `HiSparseConnector` replaced by `--kv-offloading-size`) fail on `main`. Full `tests/test_config.py`: 11 failures, identical to clean `main` (macOS platform/defaults tests, unrelated to HiSparse).
