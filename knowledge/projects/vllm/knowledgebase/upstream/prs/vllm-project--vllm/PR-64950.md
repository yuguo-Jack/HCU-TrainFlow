# [Spec Decode] Add an independent first-draft graph ceiling

[Upstream PR](https://github.com/vllm-project/vllm/pull/64950) · state: open · merged: False

## Original PR description



## Overview

Add `draft_prefill_cudagraph_max_tokens` for target-dependent V2 speculators. Users can retain large target prefill coverage while limiting first-draft PIECEWISE captures and preserving FULL decode graphs.

## Claims

- Optional startup control for EAGLE/EAGLE3, single-module MTP and Gemma4; default `None` preserves existing configuration ownership and hashes.
- Larger first-draft inputs use the native eager fallback. Target and later draft graphs retain their configuration and FULL descriptors, including rounded boundaries.
- Unsupported speculators and V1 reject the option; inactive graph modes warn at startup.

## Validation

H100, Torch 2.14.0+cu130, public base `7b77ed581d92fa14e34ab43344837bb1ca1b4257`.

```bash
.venv/bin/python -m pytest tests/v1/cudagraph/test_cudagraph_manager.py -vv
.venv/bin/python -m pytest tests/v1/spec_decode/test_custom_speculator.py -vv
.venv/bin/python -m pytest tests/v1/e2e/spec_decode/eagle/test_eagle_correctness.py -k graph_ceiling -vv -s
```

Graph manager: 44 passed on CPU; all 14 new feature cases fail on base because the new keyword is absent. Registry: 41 passed on the CUDA platform. Trained Qwen3-8B/EAGLE3 regression: 2 passed, breakable graphs on/off, with actual graph-state assertions, nonzero draft acceptance and exact greedy outputs under batch invariance. Normal pre-commit hooks pass. An additional CPU run of the GPU registry suite has two unchanged V2-selection failures, reproduced on base.

One fresh TP=1 process per arm, BF16, max_num_seqs=2, max_num_batched_tokens=256, max_model_len=512, capture sizes 1/2/4/8/16/32/64/128/256, cap 64:

| Arm | First draft PW/FULL | Target PW/FULL | Later FULL | Graph estimate | Torch pool reserved | KV blocks |
| --- | --- | --- | --- | --- | --- | --- |
| Base | 9/2 | 9/2 | 2 | 187 MiB | 104 MiB | 17315 |
| Default | 9/2 | 9/2 | 2 | 187 MiB | 104 MiB | 17315 |
| Cap 64 | 7/2 | 9/2 | 2 | 173 MiB | 90 MiB | 17321 |

All three outputs and draft/acceptance counters match; default/base hashes match. This is one capacity measurement with one trained EAGLE3 pair, not a serving-speed result or a general memory guarantee. AMD, B200, full-model MTP/Gemma4 and actual multi-rank execution were not tested locally. Existing H200/AMD and B200 nightly CI selectors include the regression.

The existing H200/AMD EAGLE-1 jobs now trigger on config changes because graph planning also depends on model, scheduler and compilation settings. This deliberately adds coverage for config-only changes, including unrelated ones.

## Details

Copy and filter the first manager's capture list at startup. Keep the original internal maximum so native FULL descriptors rounded above the last retained size remain available. Reject active caps below `max_num_seqs * (num_speculative_tokens + 1)` and empty retained lists. This trades first-draft graph coverage for eager execution without changing attention or sampling semantics.

Related [#62209](https://github.com/vllm-project/vllm/pull/62209) and [#63406](https://github.com/vllm-project/vllm/pull/63406) change global prefill/decode planning; [#63208](https://github.com/vllm-project/vllm/pull/63208) skips draft prefill capture under PCP. Their diffs do not add this independent user ceiling. Bounded duplicate searches found no matching control. If the global planner changes land first, this change needs rebasing and validation against their actual prefill lists.
