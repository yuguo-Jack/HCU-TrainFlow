# [Bugfix] FlashInfer incompatible with sleep mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/35124) · state: closed · merged: False

## Purpose

Fix FlashInfer incompatibility with sleep mode (#31016).                                                      

After llm.sleep() discards kv_cache-tagged GPU memory, cached FlashInfer wrappers hold stale state referencing zeroed memory, causing incorrect outputs on llm.wake_up(). This PR resets those wrappers during wake up.

## Code Review

This pull request addresses an incompatibility between FlashInfer and vLLM's sleep mode by resetting cached attention wrappers and forcing re-planning upon wake-up. This ensures that stale internal state referencing discarded or zeroed GPU memory is cleared. While the logic added to `FlashInferMetadataBuilder` is sound, the implementation in `gpu_worker.py` contains a critical bug where it incorrectly iterates over the keys of a dictionary instead of its values, rendering the reset logic ineffective for the V2 model runner. Additionally, the current implementation misses resetting builders in the V1 model runner, which stores them within `attn_groups` rather than a top-level `attn_metadata_builders` attribute.

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

There are two issues with this implementation:

1. **Incorrect Iteration (V2 Model Runner)**: In the V2 model runner (`vllm/v1/worker/gpu/model_runner.py`), `attn_metadata_builders` is a dictionary (mapping group IDs or layer names to builder objects). Iterating over it directly (`for builder in ...`) yields the keys (strings or integers), not the builder objects. Consequently, `hasattr(builder, "reset_for_sleep_mode")` will always be `False`, and no builders will ever be reset.

2. **Missing V1 Support**: The V1 model runner (`vllm/v1/worker/gpu_model_runner.py`) does not have a top-level `attn_metadata_builders` attribute. Instead, builders are stored within `attn_groups`. This means FlashInfer will remain broken for V1 users after a sleep/wake cycle.

Please update the logic to correctly iterate over dictionary values and to support the V1 model runner structure.
