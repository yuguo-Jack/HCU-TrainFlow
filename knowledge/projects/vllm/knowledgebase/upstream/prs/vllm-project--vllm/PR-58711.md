# [Bugfix][Rust Frontend] Dedupe chat top_logprobs and reject an over-budget max_tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/58711) · state: open · merged: False

## Original PR description

## Purpose

Fixes #58680.

Chat `top_logprobs` listed the sampled token twice when that token was already in the top-k, so a request for 3 entries came back as `red, red, here` instead of `red, here, three`. An explicit `max_tokens` that did not fit in `max_model_len - prompt_len` was shortened and returned 200. The Python frontend keeps the token once and rejects the request.

An omitted `max_tokens` is still shortened to the remaining context. That matches Python.

`resolve_max_tokens` is shared, so the native generate path rejects an explicit over-budget `max_tokens` too. Python's non-OpenAI generate path still shortens. I kept the check in that one function rather than adding an OpenAI-only flag.


AI assistance was used with `Cursor`. 

The commit has `Co-authored-by: Cursor <cursoragent@cursor.com>`.
