# [Bugfix][Reasoning] kimi_k3: return the reply as content when the think channel is skipped

[Upstream PR](https://github.com/vllm-project/vllm/pull/65169) · state: open · merged: False

## Original PR description

## Purpose

On ~1M-token prompts Kimi K3 sometimes skips the think channel that the prompt pre-fills. It writes the reply directly and closes it with `<|close|>response<|sep|><|close|>message<|sep|>`, and it never emits `<|close|>think<|sep|>` or `<|open|>response<|sep|>`.

`KimiK3ReasoningParser` only leaves the think channel on `<|close|>think<|sep|>`. In this case the whole reply came back as `reasoning`, with `content` empty, both streaming and non-streaming. The Kimi Vendor Verifier's BEAM (1M) benchmark scores `content` only, and **144 of 700** answers came back empty this way.

A `<|close|>response<|sep|>` inside the think channel, before any think exit, shows that the text before it was the response. SGLang reads it the same way in sgl-project/sglang#37743. This PR:

- **Non-streaming** (`extract_reasoning`): returns that text as content, with the response and message wrappers stripped as usual.
- **Streaming**:
  - `is_reasoning_end` and `is_reasoning_end_streaming` treat a response closer that is newer than the last think-open as the end of reasoning. A prior turn's closer kept in the prompt still does not count.
  - The step that sees the closer returns the reply as content and caches its token ids. The delegating `KimiK3Parser` then switches to content and strips the wrappers.
  - Text that already streamed as reasoning stays in reasoning, because it cannot be recalled. SGLang makes the same trade.
- **Partial markers**: a partial response closer is held back from reasoning, so no marker fragment leaks.

Normal outputs (a closed think channel, or a response opener) are untouched. A reply ended by EOS with no closer at all still reads as reasoning: it cannot be told apart from a trace truncated at `max_tokens`.

Related open PRs:
- #53249 also treats the response closer as an implicit think close, but keeps the text before it as reasoning (its target is a tool call after the closer). So it does not recover these replies.
- #60565 and #60655 handle a response opener without a think close.

## Test Plan

- New cases in `tests/reasoning/test_kimi_k3_reasoning_parser.py`:
  - non-streaming: skipped channel with and without the open marker and the message closer; the delegating `parse`;
  - a closed think channel followed by the response closer, which is unchanged;
  - `is_reasoning_end`, including a prior turn's closer in the prompt;
  - streaming through `KimiK3Parser.parse_delta`, with the closer whole, split across steps, and all in one chunk;
  - streaming with a closed channel, which is unchanged.
- `tests/tool_use/test_kimi_k3_tool_parser.py`.
- Replay of 700 real outputs and an end-to-end BEAM (1M) run on 8x MI355X (below).

## Test Result

**Unit tests.** `tests/reasoning/test_kimi_k3_reasoning_parser.py` and `tests/tool_use/test_kimi_k3_tool_parser.py`: 91 passed. Run in the ROCm nightly image `edad8b03`, whose parser, `vllm/parser/kimi_k3.py` and `abstract_parser.py` are identical to main. Against the unpatched parser, the 9 new skipped-channel cases fail and everything else passes.

**Replay.** The 700 raw BEAM outputs from unpatched vLLM, with channel tokens kept, run through the new parser:
- The 141 replies ending in the response closer come back as content. Streaming and non-streaming agree.
- The 3 without it (one at `max_tokens`, two EOS with no marker) stay empty.
- The 556 answered replies are unchanged.

**End to end.** Kimi Vendor Verifier BEAM (1M), 700 questions, Kimi-K3 on 8x MI355X. The client sends KVV's own request: `thinking_effort=max`, temperature 1.0, top_p 0.95, non-streaming. Kimi-K3 is the judge, since KVV names none.

| | empty `content` | BEAM |
|---|---|---|
| vLLM main | 144 | 0.263 |
| vLLM main + this PR | 6 | **0.307** |
| KVV leaderboard (Moonshot / Inferact / RadixArk) | - | 0.31 / 0.3188 / 0.3107 |

The 6 left are 5 EOS inside the think channel with no closer, and 1 cut off at `max_tokens` in a repetition loop.

Not in this PR: `count_reasoning_tokens` still counts a skipped-channel reply as reasoning tokens. SGLang notes the same follow-up.

Thanks for working on this. I think [`_skipped_think_channel`](https://github.com/vllm-project/vllm/blob/a8bac27d43362feb4ebb4aa8cc20e66c55198f05/vllm/reasoning/kimi_k3_reasoning_parser.py#L157) also matches a `<|close|>response<|sep|>` that the model writes as plain text inside reasoning. Here only the last four markers are special tokens:

```
The block ends with <|close|>response<|sep|> so I answer.<|close|>think<|sep|><|open|>response<|sep|>Answer.<|close|>response<|sep|><|close|>message<|sep|>
```

| | `reasoning` | `content` |
| --- | --- | --- |
| main | `The block ends with <\|close\|>response<\|sep\|> so I answer.` | `Answer.` |
| this PR, non-streaming | `None` | `Answer.` |
| this PR, streaming with small deltas | `The block ends with ` | `The block ends with <\|close\|>response<\|sep\|> so I answer.<\|close\|>think<\|sep\|>Answer.` |

Both spellings decode to the same text. Only the token ids tell them apart. To address this issue, could the check look for the `<|close|>response<|sep|>` token ids? Streaming already has `current_token_ids`. For non-streaming, #60655 uses token ids for the think markers and passes them to `extract_reasoning` through `KimiK3Parser.parse`.
