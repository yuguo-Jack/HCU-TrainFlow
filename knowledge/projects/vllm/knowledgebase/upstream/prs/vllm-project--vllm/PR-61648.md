# [CI] Skip exited descendants when finding the worker in the FT e2e test

[Upstream PR](https://github.com/vllm-project/vllm/pull/61648) · state: closed · merged: True

## Original PR description

Failed CI: https://buildkite.com/vllm/ci/builds/94610/list?sid=01a1373d-e190-4447-8cf4-9e6e4180d658&tab=output

_kill_worker_process lists every descendant of the API server and calls cmdline() on each to find the worker. With psutil >= 6 (CI pins 6.1.0), cmdline() raises ZombieProcess for a process that exited but was never reaped, and NoSuchProcess for one reaped mid-scan. One exited helper anywhere in the tree therefore failed the test before any fault was injected.

This happened on every fault-tolerance-e2e-2xh100 run built with the DeepGEMM pin from #59482 (builds 94501, 94505, 94523, 94591, 94610). At import, DeepGEMM starts an MLOPart helper (python3) from each worker; on H100 it exits at once and is never waited on. #61510 reverted that pin, but the test should not depend on every descendant being alive.

Original issue:
```
  >                       raise original_exception
  E                       psutil.ZombieProcess: PID still exists but it's a zombie (pid=8695)
  utils.py:1829: ZombieProcess
  ======================================================================= warnings summary =======================================================================
  <frozen importlib._bootstrap>:488
    <frozen importlib._bootstrap>:488: DeprecationWarning: builtin type SwigPyPacked has no __module__ attribute
  <frozen importlib._bootstrap>:488
    <frozen importlib._bootstrap>:488: DeprecationWarning: builtin type SwigPyObject has no __module__ attribute
```
Skip such descendants. A dead worker still fails the assert.
