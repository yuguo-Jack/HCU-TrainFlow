# [Bugfix][KV Connector][Mooncake] Fix transfer address overflow on Intel XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/65501) · state: open · merged: False

## Original PR description



## Overview

Since #62478, every MooncakeConnector P→D KV transfer fails on Intel XPU with
`OverflowError: Python int too large to convert to C long`. This PR does the
transfer address math in `uint64` so device addresses above 2**63 work.

## Claims

- Fixes MooncakeConnector P→D transfers on Intel XPU, which have failed since #62478.
- No behavior change on other platforms: the same addresses and lengths are produced,
  and `.tolist()` still returns plain Python ints.
- Adds a regression test with device addresses above 2**63.

## Validation

**Unit tests** (on `main` 6dc6d2c0f3 + this PR):
```bash
pytest tests/v1/kv_connector/unit/test_mooncake_connector.py \
       tests/v1/kv_connector/unit/test_mooncake_connector_hybrid_mamba.py
```
- Without the fix, the new test `test_build_transfer_params_handles_addresses_above_int64`
  fails with the same error as on hardware:
  `OverflowError: Python int too large to convert to C long`, raised in
  `MooncakeConnectorWorker._build_transfer_params`.
- With the fix: 190 passed.
- `ruff check` / `ruff format --check` (0.14.0, the pre-commit version) are clean.

**On hardware:** 1P1D Qwen3.8-27B-FP8, TP2 + TP2 on Intel Arc Pro B60, `MooncakeConnector` over RDMA.
- Before: every transfer request failed on prefill with
  `Error processing Mooncake xfer request: Python int too large to convert to C long`.
- After: P→D transfers complete with no errors.

## Details

#62478 vectorized `MooncakeConnectorWorker._build_transfer_params`. Block ids are `int64`
numpy arrays, and the region's base address is added to them:

```python
(local_ids * local_region.block_len
 + (local_region.base_addr + src_region_offset)).tolist()
```

Intel XPU (Level Zero USM) device pointers are above 2**63, for example
`0xff00000000200000`. numpy cannot convert such a Python int to `int64`, so the expression
raises `OverflowError` for every request. CUDA device pointers sit far below 2**63, which is
why CUDA CI and the existing tests (base addresses like `0x1000`) did not catch it. Before
#62478, the pointers were summed as plain Python ints, which have no limit.

The fix casts the ids to `uint64` and adds the block length and base address as `np.uint64`,
for both `src_ptrs` and `dst_ptrs`. Every operand is non-negative, so `uint64` is exact.
`.tolist()` turns the results back into Python ints for `batch_transfer_sync_write`.

#62546 fixes the same overflow in `MooncakeStoreConnector` (`store/data.py`). This PR fixes
the P2P connector path, which #62546 does not touch.
