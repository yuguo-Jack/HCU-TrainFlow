# [Recipe] Qwen3.5-397B-A17B: add the B200 NVFP4 TP2 agentic preset

[Upstream PR](https://github.com/vllm-project/vllm/pull/64607) · state: closed · merged: True

## Original PR description

## Overview

Adds a `b200_tp2_kv_offload` tuned preset to `recipes/models/Qwen/Qwen3.5-397B-A17B.yaml`: NVIDIA's tuned configuration for serving `nvidia/Qwen3.5-397B-A17B-NVFP4` on two B200s for long-context agentic coding traffic. The baseline command and every other rendering are unchanged; the preset appears in the command builder's Preset row for B200 with the `nvfp4` variant.

## Claims

- TP2 with expert parallelism on two B200s, MTP with three draft tokens (the recipe's existing `spec_decoding: mtp` mode), FP8 KV cache, `--mamba-ssm-cache-dtype float16`, `--async-scheduling`, `--block-size 64`, `--max-num-batched-tokens 16384`, `--max-num-seqs 48`, `--no-disable-hybrid-kv-cache-manager`, and vLLM native CPU KV offload with `--kv-offloading-size 160` GiB summed over the two ranks.
- Turns the default-on `encoder_parallel` feature off and selects the Python frontend, matching the measured configuration.
- Measured on `vllm/vllm-openai:v0.32.0`, two B200 SXM 180 GB, a 942-request multi-turn agentic coding trace (about 64k mean input tokens, outputs capped at 12k) at concurrency 16 with real MTP acceptance: 936 output tok/s/GPU, 8.7 ms mean ITL, 0.70 s mean TTFT, all requests completed. The table is in the preset's runbook.
- Bumps `meta.date_updated`.

## Validation

- The exact rendered flag set was served on the pinned image on two B200s on an NVIDIA cluster against the trace above; the startup log shows every flag taken as given (MTP, native offload connector, FlashInfer TRT-LLM MoE backend, 37 GiB of GPU KV per rank). No public run link yet; an InferenceX AgentX lane with the same settings is being prepared, and this preset's `source` will be repointed to it when it lands.
- The `Recipes / Validate` check passes and the preview deployment renders the preset: the B200 NVFP4 Preset row composes `vllm serve nvidia/Qwen3.5-397B-A17B-NVFP4 --trust-remote-code --kv-cache-dtype fp8 --tensor-parallel-size 2 --moe-backend flashinfer_trtllm` plus the preset's flags, the parsers and the MTP speculative config, with `--mm-encoder-tp-mode data` dropped; the baseline B200 command and every other rendering are unchanged. The vLLM `/pr-checklist` skill was not run.

## Details

- A preset rather than a change to `hardware_overrides.blackwell`: these settings are workload-specific (admission cap, offload tier), so they should not alter the baseline B200 command.
- The runbook states that further concurrencies and the same-image comparison against the recipe's baseline command are being collected; they will follow in a separate PR.
- `source` points at this PR.
