# [6/N][KV-Cache Layout Refactor] Standardize KV cache layout

[Upstream PR](https://github.com/vllm-project/vllm/pull/44458) · state: closed · merged: False

## Original PR description

PR #42374 (first part of RFC #42082) has been split into 4 PRs:

#44454 [1/N][KV-Cache Layout Refactor] Refactor DSV4 KV cache config
#44455 [2/N][KV-Cache Layout Refactor] Pack K/V into the content dim across attention backends
#44456 [3/N][KV-Cache Layout Refactor] Standardize Mamba cache; drop `get_transfer_cache_regions`
-> #44458 [4/N][KV-Cache Layout Refactor] Standardize KV cache layout

## Summary

Final step of the KV-cache layout standardization ladder. Introduces standardized layout resolution and `reshape_kv_cache`, removes the legacy `get_kv_cache_shape` / `get_kv_cache_stride_order` APIs, and removes the remaining cross-layer block machinery from connectors. RFC #42082.

Stacked on top of #44456 (`bind_kv_cache`); the chain is #44454 → #44455 → #44456 → this PR. This is the restacked remainder of #42374, not a duplicate implementation of another open PR.

The rebase audit also fixed layout-sensitive regressions in compressed MLA allocation, CPU and XPU attention, NIXL, Mooncake, Mooncake Store, simple CPU offload, and in-place block copying. Coverage now includes layer-compact, cross-layer, separate-head-group, virtual-block-splitting, shared-storage, and host-buffer cases.
