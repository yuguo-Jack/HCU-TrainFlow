# [Core] Packed KV planner: pick the block width that reserves the fewest bytes

[Upstream PR](https://github.com/vllm-project/vllm/pull/64381) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

The packed KV planner caps state buckets (sliding window, circular buffer, mamba) at the widest paged group. That can leave many narrow groups, each reserving its own blocks per request. This PR picks the block width that reserves the fewest bytes per max-length request. The current width is always a candidate, so the new grouping never reserves more per max-length request than the old one.

[#64120](https://github.com/vllm-project/vllm/pull/64120) stacks on this PR. Its smaller records turn into +19% capacity instead of −9% with this fix; the projections are in #64120.

## Claims

- DeepSeek-V4.1-Flash, stock FP8 KV: **+2.5% KV tokens** at the same memory, on real boots (eager 12,205,275 → 12,515,517; graph 11,747,853 → 12,052,038).
- Other packed-path models are unchanged: Qwen3.8-Flash-Next (FP8 KV), DeepSeek-V4-Flash and MiniMax-M3.1-Flash get identical groups (table below).

## Details

**Root cause.** Each packed group reserves `cdiv(max_memory_usage_bytes, page_size)` blocks per request. For a sliding-window group that's the window plus the tokens in flight: 1029 blocks at 64K with 32K in flight. Capping state buckets at a small anchor splits the 40 SWA layers into many narrow groups, each with its own 1029-block reservation.

**Change.** The grouping loop moves into `build_groups(block_bytes)`, unchanged apart from the cap's width. The candidates are the anchor plus every `k × state page` above it. The planner keeps the grouping with the fewest bytes per block × blocks per request, and ties keep the narrower block. It runs once at startup.

**Tradeoffs.**
- The objective is one max-length request's reservation, which is what bounds concurrency at `max_model_len`. The paged MLA group's per-block padding can grow.
- The choice depends on `max_model_len` and `max_in_flight_tokens`, so one model can group differently under different flags.

**Tests.**
- The new case covers the DSv4.1 pattern.
- Two cases that encoded the old cap at `max_model_len=16` now run at 65,536.
- `test_non_cacheable_swa_leaves_hits_to_the_paged_group` pins the new grouping: the paged group plus two SWA groups of 2, where main gives four groups of 1.
