- akii96 · comment · 2026-10-02T10:10:35Z · [source](https://github.com/vllm-project/vllm/pull/58650#discussion_r4164793274)

File: `vllm/v1/attention/ops/triton_unified_attention_diffkv.py` · line None

Good call, adopted, and taken one step further. The 3D split now covers only the sliding window (`compute_3d_segments_diffkv`, same signature as #59349's helper so the two can converge). On top of that, the segment count adapts to the shape: it halves from 16 until every segment gets a tile and the reduce stays cheap, and falls back to 2D below 4. This replaces the fixed `80` threshold, which regressed W≈1024 under CUDA graphs.

It doesn't break it. The 2D output is bitwise identical (`torch.equal`) across 1/2/4-warp launches, and there is now a test for it (`test_triton_unified_attn_diffkv_launch_config_is_bitwise_invariant`). To make sure it can never depend on batch size, the single-wave launch is also disabled under `VLLM_BATCH_INVARIANT`.

**On the nit**:  Also done, it now uses the same `launch_num_warps` / `launch_num_stages` pattern as `triton_unified_attention`.
