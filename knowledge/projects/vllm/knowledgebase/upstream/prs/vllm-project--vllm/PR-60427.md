# Fix boolean parsing for LMCACHE_FORCE_SKIP_SAVE environment variable

[Upstream PR](https://github.com/vllm-project/vllm/pull/60427) · state: open · merged: False

## Original PR description



## Overview

Fixes an issue where `LMCACHE_FORCE_SKIP_SAVE` evaluates to `True` even when explicitly set to `"False"` or `"0"`. Replaces improper `bool(...)` casting with an explicit truthy string check.

## Claims

- Fixes environment variable parsing bug where disabling `LMCACHE_FORCE_SKIP_SAVE` (e.g., `LMCACHE_FORCE_SKIP_SAVE=0` or `LMCACHE_FORCE_SKIP_SAVE=False`) was ignored.
- Correctly parses `"1"`, `"true"`, and `"yes"` as `True`, and all other values (including unset or empty) as `False`.

## Validation

Verified via Python interactive session:

```python
import os

def check(val):
    if val is not None:
        os.environ["LMCACHE_FORCE_SKIP_SAVE"] = val
    else:
        os.environ.pop("LMCACHE_FORCE_SKIP_SAVE", None)
    return os.getenv("LMCACHE_FORCE_SKIP_SAVE", "").lower() in ("1", "true", "yes")

# Validations:
assert check("False") is False
assert check("false") is False
assert check("0") is False
assert check("no") is False
assert check("") is False
assert check(None) is False

assert check("1") is True
assert check("true") is True
assert check("True") is True
assert check("yes") is True
