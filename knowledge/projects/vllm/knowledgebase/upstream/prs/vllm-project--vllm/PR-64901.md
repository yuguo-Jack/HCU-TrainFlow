# [Model] DeepSeek-V4.1: zero frozen FP8 Engram tables in place in the dummy loader

[Upstream PR](https://github.com/vllm-project/vllm/pull/64901) · state: open · merged: False

## Original PR description

## Overview

With `--load-format dummy`, `initialize_single_dummy_weight` fills an FP8 tensor through a full-size FP16 temporary (`uniform_` does not support FP8). For the frozen FP8 Engram tables of DeepSeek-V4.1, that temporary is twice the size of the table. The dummy loader now zeroes these tables in place through a `uint8` view. Tables with an explicit `dummy_weight_value` still use it.

Split from #62365 by @aoshen02.

## Changes

- `vllm/model_executor/model_loader/dummy_loader.py`: FP8 tensors that carry `engram_vocab_start` (set only on Engram table shards) and no `dummy_weight_value` are zeroed with `tensor.view(torch.uint8).zero_()`. Every other tensor goes through `initialize_single_dummy_weight` as before.
- `tests/model_executor/test_weight_utils.py`: `test_dummy_engram_table_avoids_full_precision_temporary` (CPU) fails if `torch.empty_like` is called on the table, and checks that other FP8 weights are still randomized.
