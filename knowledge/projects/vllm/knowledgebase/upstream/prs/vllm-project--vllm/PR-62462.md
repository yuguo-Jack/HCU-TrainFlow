# [Core] Add device-specific hooks to CuMemAllocator

[Upstream PR](https://github.com/vllm-project/vllm/pull/62462) · state: closed · merged: False

## Original PR description

### Overview

Refactor CuMemAllocator to expose narrow device-specific hooks while keeping allocator lifecycle orchestration in vLLM.

This allows device backends to reuse the common sleep/wake, discard, memory-pool, tag-management, and CUDA graph-pool flows without copying the full allocator implementation.

### Claims

- Common allocator lifecycle and state transitions remain owned by vLLM.
- Device-specific mapping, synchronization, memory copies, cache cleanup, allocator configuration, and pool creation use overridable hooks.
- Existing CUDA and ROCm behavior is preserved by the default hook implementations.
- The main-branch behavior for multiple pools per tag, pool trimming, selective wake-up, and ROCm handling is retained.

### Validation

- Python compilation passed for vllm/device_allocator/cumem.py.
- git diff --check passed.
- Pytest and Ruff were not run locally because they are unavailable in the current environment.

### Details

- Added hooks for mapping, unmapping, synchronization, sleep-time synchronization, memory copies, cache cleanup, persistence policy, allocator configuration, and memory-pool creation.
- Routed _trim and cudagraph_pool through device hooks while preserving their existing orchestration.
- Moved use_allocation_tag into CuMemAllocator so device subclasses can inherit it.
- The default sleep-time synchronization hook is a no-op, preserving existing CUDA/ROCm sequencing.
