# Fix GPTQ quantizations loading zero point parameters in symmetric configs

[Upstream PR](https://github.com/vllm-project/vllm/pull/61891) · state: open · merged: False

## Original PR description



## Overview

Fix GPTQ quantizations loading zero point parameters in symmetric configs

## Claims

Fix a bug in GPTQ quantizations where symmetric quants still load the zp tensor for GEMM where it is not needed, and results in a crash.

## Validation

Run the following serve command:
vllm serve JunHowie/Qwen3-32B-GPTQ-Int4 \
  --port 7000 \
  --host 0.0.0.0 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.8 \
  --dtype float16 \
  --tensor-parallel-size 1 \
  --enforce-eager

## Details

Currently if the model config is symmetric, and it still has zero points tensors in the weights, it will be loaded from _get_weight_params() in the MPLinearKernel class since the w_zp_name is not cleared. Afterwards it will fail asserts in the zp tensor shape. But the tensor should not be loaded in this type of config, and we can clear that parameter by setting it to None.
