# [MRV2][Spec Decode] Context Aware Sparse LM Head on quantized lm_heads

[Upstream PR](https://github.com/vllm-project/vllm/pull/60226) · state: open · merged: False

## Original PR description

## Overview

**+7.9% decode at c=1 (+2.8% at c=4) on `nvidia/Qwen3.6-35B-A3B-NVFP4` and +5.9% (+3.5%) on `nvidia/Qwen3.8-27B-NVFP4`, with average AL unchanged**, MTP (k=3) on one DGX Spark: the context-aware sparse LM head from #59740 now works when the lm_head is already quantized in the checkpoint (NVFP4 W4A16 and W4A4 here). Without this, #59740 rejects quantized heads, which covers NVIDIA's own NVFP4 checkpoints.

Stacked on #59740: only the last commit is new. I will rebase once #59740 lands.

## Results

SPEED-Bench qualitative (11 categories, 409 requests, greedy, 256 tokens), MTP k=3, one GB10 node, 32k list + 16k dynamic rows (rank 256) vs. stock, each model's lm_head left in its checkpoint format:

| model (lm_head) | AL avg | AL multilingual | decode c=1 | decode c=4 | GSM8K (200) |
|---|---:|---:|---:|---:|---:|
| Qwen3.6-35B-A3B (NVFP4 W4A16), stock | 2.935 | 3.060 | 118.1 tok/s | 72.9 tok/s | 97.0% |
| + sparse LM head | +0.2% | -1.5% | **+7.9%** | +2.8% | 95.0% |
| Qwen3.8-27B (NVFP4 W4A4), stock | 2.906 | 3.131 | 27.2 tok/s | 25.7 tok/s | 96.5% |
| + sparse LM head | -0.2% | -2.2% | **+5.9%** | +3.5% | 97.5% |

GSM8K is one run per arm; the same stock arm moved by 2.5 points between runs. A static 32k list alone (no dynamic rows) on Qwen3.6-35B: -8.7% AL, -40.6% multilingual AL, +4.0% / -1.4% decode.

Load cost: the drafter keeps a host copy of the quantized head only until the rows are built, and the scorer is built from one chunk of dequantized rows at a time. Peak extra GPU memory during setup is 408 MiB (35B) / 1026 MiB (27B); 361 / 772 MiB stays for the rows and scorer.

## Details

- A quantized lm_head's kernel repacks the weights after loading, so rows cannot be sliced from the live head. The drafter keeps its lm_head's checkpoint tensors while loading (`DraftVocab.keep_head_weights`, one call in `Qwen3_5MTP.load_weights`, enabled only when `draft_token_map` is set), and frees them once the rows are built.
- The listed rows become their own `ParallelLMHead` with the head's `quant_config`: parameters indexed by output row (by their `output_dim` metadata) are sliced, per-tensor scales are copied, and the quantization method loads and repacks the small head as usual. Other layouts raise.
- Dynamic rows on a quantized head need ModelOpt NVFP4: the low-rank scorer is built from rows dequantized one chunk at a time, and the packed rows are gathered directly by the existing NVFP4 gather kernel. On a W4A4 head the dynamic rows run with BF16 activations, so only AL can change.
- `draft_token_map_quantization` is rejected on an already-quantized head rather than re-quantizing it.

This PR does not add the hook to other MTP models (Qwen4Exp builds its head unquantized) or support dynamic rows on non-NVFP4 quantized heads.
