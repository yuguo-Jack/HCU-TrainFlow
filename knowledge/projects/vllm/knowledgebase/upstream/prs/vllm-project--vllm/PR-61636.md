# [Bugfix][LoRA] Fix double pinning of 3D MoE LoRA and EP dummy LoRA sizing

[Upstream PR](https://github.com/vllm-project/vllm/pull/61636) · state: closed · merged: True

## Original PR description

## Purpose

Fixes #61635.

Two small fixes in `LoRAModelManager` for 3D MoE LoRA:

- After stacking, the `experts.base_layer` entry shares its gate_up tensors with the `experts` entry, so the pin loop pinned them twice. Pop the `base_layer` entry at the end of the 3D branch, same as `_convert_3d_to_2d_moe_lora` already does.
- `create_dummy_lora` sized the 3D MoE warmup dummy by local experts, but `_stack_moe_lora_weights` reshapes by `global_num_experts`. Size the dummy by `global_num_experts` so it works when `ep_size` does not divide the warmup rank.

The first fix needs a third change to be safe: `lora_device = next(iter(first_lora.lora_a))` returned a tensor, not a device, so a packed first entry made `str(lora_device) == "cpu"` False and skipped pinning entirely. Once `base_layer` is gone the first entry is the packed `experts` one, so pinning would silently turn off. Read `.device` from the first non-None tensor instead. This also makes packed LoRAs (e.g. a q/v-only adapter on `qkv_proj`) get pinned, which was previously skipped.

Note this device check was also proposed in #44149 (closed as stale).

## Test Plan

```
pytest tests/lora/test_lora_manager.py tests/lora/test_lora_weights.py
```

New CPU tests (`pin_memory` is wrapped to count calls, so no CUDA needed):
- `test_pin_memory_for_packed_lora`: packed LoRA is pinned, including when the first sub-LoRA is None.
- `test_3d_moe_lora_pinned_once`: only the `experts` entry is left and each tensor is pinned once.
- `test_dummy_3d_moe_lora_is_sized_by_global_experts`: dummy rank dimension is `rank * global_num_experts` for ep_size 1, 2, 3.

## Test Result

On current main the new tests fail (6 of 7 cases; the ep_size=1 case passes either way) and pass with the change. The existing LoRA unit tests pass (42 passed). `ruff check` and `ruff format` are clean.

GPU check on an L4 with Qwen2.5-0.5B-Instruct and a q_proj/v_proj adapter through `vllm serve`, counting `pin_memory` calls: the packed-LoRA device fix is consistent with qkv adapters now being pinned (96 pin calls per adapter load before, 528 after). I did not run a real 3D MoE model on GPU, so the double-pin and EP dummy fixes are covered by the CPU tests only.
