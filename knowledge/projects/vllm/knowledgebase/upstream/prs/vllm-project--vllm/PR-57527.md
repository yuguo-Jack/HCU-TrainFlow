## Original PR description

# [Rust Frontend] Support `--max-log-len`

### Summary
Adds `--max-log-len` to the Rust frontend (`VLLM_USE_RUST_FRONTEND=1`), matching the Python
frontend flag: limits the number of prompt characters (text prompts) / token IDs
(pre-tokenized prompts) printed in the per-request log when `--enable-log-requests` is set.

Changes (2 commits, 6 files, +95/-5 vs `upstream/main` @ `39e33db7f3`):
- `rust/src/cmd/src/cli.rs`: new `max_log_len: Option<u32>` clap flag, forwarded to
  `ApiServerOptions::max_log_len` (as `usize`).
- `rust/src/cmd/src/cli/unsupported.rs`: removed the `max_log_len` placeholder from
  `ServerUnsupportedArgs`.
- `rust/src/server/src/config.rs`: `ApiServerOptions::max_log_len` + `format_prompt_token_ids_for_log()`
  truncation helper with unit tests (None / exact-length / truncation / `Some(0)` / empty input).
- `rust/src/server/src/routes/openai/chat_completions.rs`, `completions.rs`: log
  `prompt_token_ids` at DEBUG (INFO stays a summary) with truncation applied.

### Why this is not a duplicate
Revives the closed #46279 (closed 2026-08-17), which implemented the same flag for the Rust
frontend. Verified on network before opening this PR:
- `gh issue view 46279 --comments` — the issue is closed; no active work linked.
- `gh pr list --repo vllm-project/vllm --state open --search "max-log-len"` — no open PR
  implements `--max-log-len`.
- `gh pr list --repo vllm-project/vllm --state open --search "46279"` — no open PR references #46279.

This PR is rebased onto current `main` (rebase was conflict-free) and incorporates review
feedback from #46279: `prompt_token_ids` moved to a separate `debug!` line so INFO remains a
summary and no multi-MB log lines are emitted for long-context requests.

### Tests
- `cargo fmt --check` — **passed** locally.
- `cargo clippy --all-targets -- -D warnings` / `cargo nextest` — locally runnable once the
  `llm-multimodal` git dependency pinned by `Cargo.lock` (upstream rev `24c676dd...`) can be
  fetched; results will be posted once available. CI runs these gates (`cargo nextest`,
  `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`, `cargo sort --check`).
- New unit tests in `config.rs` cover the truncation helper.

### Impact on output / accuracy / serving
None. `--max-log-len` only changes the per-request **log line** content; served responses and
sampling are untouched. No model evaluation needed.
