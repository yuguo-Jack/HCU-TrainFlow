# [Perf][MRV2] Opt-in suffix-only token staging for new requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/63212) · state: open · merged: False

## Original PR description



## Overview

On admission, Model Runner V2 stages a new request's whole token history into `RequestState.all_token_ids`, on the engine main thread. With a prefix-cache hit, almost none of the tokens below `num_computed_tokens` are read again; only a model state's short fixed lookback window is. This adds an opt-in mode that stages only the suffix that can still be read.

## Claims

- With `VLLM_SUFFIX_TOKEN_STAGING=<margin>`, a new request stages only `all_token_ids[start:]`, where `start = min(num_computed_tokens, prompt_len) - margin`. The margin is raised to the model state's new `token_lookback_depth` (default 0). `VLLM_SUFFIX_TOKEN_STAGING_MIN` sets the smallest `start` that is worth skipping.
- Requests that read older history are staged in full: prompt logprobs, repetition penalty, bad words, thinking budget, multimodal inputs, pooling and requests without sampling params. The mode is off with watermarking, custom logits processors, n-gram speculative decoding and KV connectors.
- Outputs do not change. Default behaviour (unset) does not change.

## Details

Most readers start at `num_computed_tokens` or later: prefill input gathering, post-update, speculative drafting, and frequency/presence penalties, which only count output tokens. Some model states look back a fixed number of tokens before `num_computed_tokens`: the DeepSeek-V4.1 engram window and the Qwen4Exp n-gram embedding. They declare that depth as `ModelState.token_lookback_depth`, so those tokens stay staged whatever margin is set. Positions below `start` keep stale data from the slot's previous occupant. It stays opt-in because correctness depends on every reader of `all_token_ids` keeping to that rule. KV connectors are excluded because a failed KV load can rewind `num_computed_tokens` for a request the runner already holds. #59908 and #62702 change the format the token ids are sent in, and #62698 chunks the staged write. None of them skips the prefix. Tests cover the staging start and its fallbacks, the lookback floor on the margin, and check that `RequestState` writes only the suffix.
