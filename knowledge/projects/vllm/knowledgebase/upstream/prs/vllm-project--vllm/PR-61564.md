# [XPU][Platform] Handle nodes with both CUDA and XPU drivers active

[Upstream PR](https://github.com/vllm-project/vllm/pull/61564) · state: open · merged: False

## Original PR description

## Overview

On a host exposing both NVIDIA and Intel GPUs, an XPU wheel currently fails to
start: the CUDA and XPU platform plugins both activate (raising "Only one
platform plugin can be activated"), and Triton disables itself on seeing
multiple active drivers. This makes an XPU build behave correctly on such
mixed-driver nodes.

## Claims

- An XPU build on a node that also has a working NVIDIA/NVML driver now resolves
  to the `xpu` platform instead of erroring with "Only one platform plugin can
  be activated".
- Triton stays enabled on multi-driver nodes by honoring `TRITON_DEFAULT_BACKEND`
  (the same env var Triton's own `_create_driver()` uses) to pin the active
  driver, instead of disabling itself.

## Validation

Validated end-to-end on an XPU wheel running on a node that also exposes a
working NVIDIA/NVML driver (the exact mixed-driver case this PR targets).
Multiple full `vllm serve` + benchmark runs across TP4 and PP2/TP8 configs
(moonshotai/Kimi-K3), each launched with `TRITON_DEFAULT_BACKEND=intel`, which
exercises both halves of the change.

Platform-plugin guard fires and resolution lands on `xpu`:

    DEBUG [platforms/__init__.py:70] CUDA platform is not available because vLLM is built for XPU.
    DEBUG [platforms/__init__.py:290] Automatically detected platform xpu.

Serve command exports the pinned Triton backend so Triton stays enabled:

    TRITON_DEFAULT_BACKEND=intel $(which vllm) serve moonshotai/Kimi-K3 ... -tp 4 ...

Observed on runs dated 2026-10-05 through 2026-10-13.

CI note: upstream CI has no node exposing both NVIDIA and Intel drivers, so this
path cannot be exercised in CI; it was validated locally as above.

## Details

- `cuda_platform_plugin()` declines early (`return None`) when the wheel is an
  XPU build (`vllm_version_matches_substr("xpu")`), mirroring the existing
  CPU-build guard, so only the XPU plugin activates.
- `triton_utils/importing.py` reads `TRITON_DEFAULT_BACKEND` and, when set and
  that backend's driver is active, pins it as the single active driver. Builds
  on the already-merged #53530 (`name != "cpu"` guard).

Not a duplicate — searched upstream (no matching PR/issue): `platform plugin xpu
cuda`, `TRITON_DEFAULT_BACKEND` (only merged #53530), `cuda_platform_plugin xpu
build`, `both NVIDIA Intel multiple drivers triton`, and issue search
`Only one platform plugin can be activated xpu`.
