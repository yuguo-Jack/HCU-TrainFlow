# Optimize atomic MiniMax M3 marker lookup

[Upstream PR](https://github.com/vllm-project/vllm/pull/56498) · state: closed · merged: False

## Original PR description

## Overview

Use native sequence membership when a MiniMax-M3 reasoning marker encodes to one token. Preserve the existing sequence-window fallback for split markers; no parser state is added.

## Claims

- Reduces the cost of `_contains_token_sequence` when that helper is actually reached with atomic markers. The official tokenizer revision below uses IDs 200059/200060.
- This is a narrow host-side optimization, **not a general structured-output or full-model speedup**. Prefilled thinking mode can return before this helper; already-ended reasoning and `enable_in_reasoning` also bypass it.

## Validation

Historical parser-only benchmark, Python 3.12.13, official `MiniMaxAI/MiniMax-M3-MXFP8` tokenizer revision `1c4e6a69f3278df8dd6c9693fcca241efe439b7d`, three alternating paired repeats:

| Growing generated history | Baseline cumulative predicate time | Patch | Ratio |
| ---: | ---: | ---: | ---: |
| 2,048 tokens | 187.65 ms | 11.61 ms | 16.17x |
| 8,192 tokens | 2,999.57 ms | 157.19 ms | 19.08x |

That loop creates the parser without `thinking_mode=enabled`, starts with an explicit generated opening marker, and calls the predicate directly. It does not include engine scheduling, grammar work, model execution or frontend streaming extraction. **Do not transfer these ratios to modes that bypass the lookup.**

Historical correctness: `python -m pytest -q tests/reasoning/test_minimax_m3_reasoning_parser.py` — 23 passed, including split-marker streaming cases. Ruff check/format and diff checks passed. Official tokenizer files were loaded locally and the two marker encodings verified. These historical observations are retained, not represented as a fresh full-main suite or hosted CI.

This uses the real `Request` and `StructuredOutputManager._get_constraint_bounds` with the existing contract-tokenizer fixture. It sets the manager fields through `__new__`, so it is **component reachability evidence only**, not complete manager initialization, a real grammar/backend, official-tokenizer serving, new timing, or model/accuracy qualification. No weights/GPU/network installation were used.

## Details

The generic helper creates one-element tuple slices while searching a list/tuple for a single token. Native membership preserves that result without those allocations. Split-marker fallback and speculative-probe statelessness are unchanged.

Existing #51230 owns the separate thinking-enabled reasoning-gate correctness repair. This PR does not fix that problem. Its proposed incremental history scanner may remove much of the work measured above; if it lands first, this optimization needs remeasurement against that implementation, not reuse of these historical ratios. #50594 addresses prompt reasoning initialization, and #54454 a different Muse-Glimmer classification path. No competing correctness PR is proposed.

The human submitter previously reviewed every line of the unchanged two-file diff. This update narrows evidence/claims only and does not request another review or CI run.
