# [Bugfix][Frontend] Handle FINISHED_ABORTED in streaming logic by emitting error event

[Upstream PR](https://github.com/vllm-project/vllm/pull/57089) · state: open · merged: False

## Original PR description

## Description
This PR updates the streaming logic in `serving.py` to handle engine outputs marked with `FINISHED_ABORTED`.

When an engine request is aborted mid-stream, vLLM will now:
1. Emit an error event payload to inform the client.
2. Skip emitting the final `data: [DONE]` terminal signal.

## Motivation
Previously, when an engine request transitioned into `FINISHED_ABORTED`, the streaming pipeline could still emit `data: [DONE]`. This caused OpenAI-compatible clients to treat the request as a successful completion even though the generation was canceled or interrupted mid-stream.

## Testing Executed
- Verified unit test coverage using `pytest tests/entrypoints/openai/responses/test_streaming_events.py` (7 passed).
- Confirmed with a standalone verification test that `FINISHED_ABORTED` states emit the error event without appending the `[DONE]` signal.
