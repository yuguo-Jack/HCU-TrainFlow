# [Doc] Document multimodal requirements for the Transformers modeling …

[Upstream PR](https://github.com/vllm-project/vllm/pull/65620) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Documents what a custom model needs to run multimodal input through the Transformers modeling backend, as suggested by @hmellor in #36864. I hit most of these while running OmniASR (`ziywang50/omniASR-LLM-300M-hf`, remote code) through the backend.

## Claims

- "Custom models": `auto_map.AutoModel` must point to the base model.
- "Writing custom models": a new step 4, "If your model is multimodal", covering the nested text config, `get_<modality>_features`, and the processor's placeholder token.
- Docs only, no code changes. Updated with @hmellor's review suggestions.

## Validation

vLLM paths are under `vllm/model_executor/models/transformers/` at `0b5a44fe08` unless noted. Transformers references are by function name, since line numbers vary between versions.

**`auto_map.AutoModel` must point to the base model**

- The backend creates the wrapped model with `AutoModel.from_config(...)` and stores it as `self.model` (`base.py` L180, L231-233).
- For remote code, `AutoModel.from_config` instantiates the class named in `config.auto_map["AutoModel"]` (Transformers `_BaseAutoModelClass.from_config`).
- The backend then adds its own `lm_head` (`causal.py` L48).
- The weight name mapping is built from the direct children of `self.model` (`base.py` L315-356), so it also assumes `self.model` is the base model.

So if `AutoModel` points to the model with the head, the backend wraps a model that already has an `lm_head`, and the checkpoint names no longer line up with the module names. OmniASR needed this change to run with the backend (ziywang50/omniasr-hf@fefab6b).

**1. The config must nest the text config**

- Per @hmellor's review: `_get_transformers_backend_cls` only picks the `TransformersMultiModal*` classes when `hf_config is not hf_text_config`, so a flat config silently gets the text-only class.

**2. `get_<modality>_features` on the base model, with `return_dict=True` and `pooler_output`**

- Audio: `self.model.get_audio_features(input_features, return_dict=True, ...)`, then `.pooler_output` (`multimodal.py` L1070-1073, and L1079-1087 for un-padded audio). The output is split per item by the placeholder counts (`_split_embeddings`, L1005; counts from L835).
- Vision inputs (`pixel_values`): `_get_features` looks the method up by name, `getattr(self.model, f"get_{modality}_features")`, calls it with `return_dict=True` and returns `.pooler_output` (L1167-1181).

**3. The processor must define `<modality>_token` and reach `get_text_with_replacements`**

- Per @hmellor's review: `_get_prompt_updates` reads `<modality>_token` with no default.
- The backend asks the processor for `return_text_replacement_offsets` (L774) and raises when a request with multi-modal data gets none back (L798-810).
- In Transformers, `ProcessorMixin.__call__` returns the offsets computed by `get_text_with_replacements`. `_process_audio` builds one replacement per item by calling `replace_audio_token`, and only does so when `audio_token` is set; the default `replace_<modality>_token` raises `NotImplementedError`.
- vLLM also reads `processor.audio_token` to build the dummy text (`get_dummy_text`, L321-323).

## Details

For built-in models, `AutoModel` comes from Transformers' own mapping (e.g. `glmasr` → `GlmAsrModel`), so they are not affected. Remote-code repos sometimes map it to the full model instead (e.g. `zai-org/chatglm2-6b`): that works in Transformers, but not with the backend, and nothing warns about it. OmniASR's first version did the same.

Dropped per review: the audio length item, since a missing field already raises a `ValueError` naming the config class and all three attributes (`get_max_audio_tokens`, L191-202).

Not included: when the number of embeddings doesn't match the placeholders, `_split_embeddings` only logs a warning and pads or truncates (`multimodal.py` L1022-1035, with a TODO to make it an error). I didn't hit this, so I left it out, but I'm happy to add a line if you think it belongs here.

I used Claude to help read the code and draft the wording, and checked every reference above against the code myself.

