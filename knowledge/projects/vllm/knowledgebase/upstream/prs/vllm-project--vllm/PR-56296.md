# [Bugfix] Fix int(None) crash for Nemotron precomputed image embeddings

[Upstream PR](https://github.com/vllm-project/vllm/pull/56296) · state: open · merged: False

## Original PR description

## Summary

Serving `nvidia/Nemotron-3-Nano-Omni-30B-A3B-Reasoning-NVFP4` with `--enable-mm-embeds` and submitting a precomputed embedding through an `image_embeds` content part returns HTTP 400 with `int() argument must be a string, a bytes-like object or a real number, not 'NoneType'`.

The root cause is in `NanoNemotronVLMultiModalProcessor._get_prompt_repl_image`. When the input uses precomputed `image_embeds` (which carry no patch-count metadata), it deliberately builds `image_num_patches = [None] * n`. The nested replacement callback then runs `num_patches = int(local_image_num_patches[item_idx])` unconditionally, which raises `TypeError` on the `None` value before inference begins.

This change only converts the patch count when it is present, leaving `num_patches` as `None` otherwise. The processor's `get_image_repl` already accepts `int | None` and builds the placeholder from `feature_size`, so no further change is needed. This mirrors the behavior of the neighboring InternVL processor, which preserves `None` for embedding inputs.

Fixes #56280.

## Why this is not a duplicate

Searched open PRs for #56280 and for "nano nemotron image embeds" and found none. The issue is open with no linked pull request.

## Testing

- Added `test_prompt_repl_image_embeds_without_patch_count` to `tests/models/multimodal/test_nano_nemotron_vl.py`. It feeds one precomputed image embedding through `_get_prompt_repl_image`, calls the returned replacement, and asserts that no exception is raised and that `get_image_repl` receives `num_patches=None`. The test fails with `TypeError` on the previous code.
- `ruff check` and `ruff format --check` pass on both changed files. The only remaining lint hit is a pre-existing `UP038` on an unchanged line in `nano_nemotron_vl.py`.
- The processor unit test does not require a GPU; the model-level test was not run in this environment.
