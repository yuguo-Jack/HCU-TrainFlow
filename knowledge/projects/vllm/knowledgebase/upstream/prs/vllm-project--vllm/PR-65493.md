# [Benchmark] Add --random-mm-video-encode-fps to random-mm

[Upstream PR](https://github.com/vllm-project/vllm/pull/65493) · state: open · merged: False

## Original PR description

## Summary
`random-mm`'s synthetic video generator hardcodes the MP4 container encode rate at 30fps (`generate_synthetic_video`), so `--random-mm-bucket-config`'s `num_frames` does not reliably map to the frame count a target model actually processes — that depends on the model's own video preprocessing (e.g. duration-based resampling at its own native fps).

Adds `--random-mm-video-encode-fps` so the encode rate can be set to match a target model's native fps, making `num_frames` self-consistent. Backward compatible: defaults to 30.0 (the previous hardcoded value).
