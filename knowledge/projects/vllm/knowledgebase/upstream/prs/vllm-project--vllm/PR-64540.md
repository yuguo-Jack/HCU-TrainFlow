# [BugFix] Ignore CPU device ranks that are not NUMA nodes

[Upstream PR](https://github.com/vllm-project/vllm/pull/64540) · state: closed · merged: False

## Original PR description

## Overview

On a 2-NUMA CPU host, DP=2 × TP=2 assigns device ids `[2, 3]` to DP rank 1. Those ids were filtered as NUMA nodes, the visible-node list became empty, and `CPUWorker` raised `IndexError` on `[0]`. Fixes #64497.

## Claims

- `get_visible_memory_node([2, 3])` returns the real visible nodes `[0, 1]` when neither id is a NUMA node.
- An assigned id that is a real node is still honored (`[1, 4]` on nodes `{0, 1}` stays `[1]`).

## Validation

`python3 -m pytest tests/utils_/test_cpu_resource_utils.py::test_visible_memory_node_falls_back_when_device_ids_are_not_numa_nodes tests/utils_/test_cpu_resource_utils.py::test_visible_memory_node_assigned_ids_are_limited_to_allowed_nodes -q --noconftest`

Before the fallback the new test got `[]`. After it, both tests passed. No GPU.

## Details

`assigned_physical_gpu_ids` is a device-rank block, not a NUMA node list, once TP > 1. If none of those ids exist as memory nodes, keep the process-visible node list instead of returning empty.
