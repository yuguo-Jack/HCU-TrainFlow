# [Chore] Use upstream Transformers DeepseekV4Config

[Upstream PR](https://github.com/vllm-project/vllm/pull/61392) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Split from #60823: deletes the vendored `DeepseekV4Config` and ports the DeepSeek-V4 code to the upstream Transformers 5.16.1 schema. Also updates the `transformers-upgrade` skill.

Related PRs:
- **#60823:** the larger unvendoring PR this is split from; DeepSeek-V4 has been dropped from it.
- **#43443:** patches one reader of the popped `compress_ratios` (`attention.py`). This PR covers every reader, so it supersedes #43443.

## Claims

- Deletes `vllm/transformers_utils/configs/deepseek_v4.py`. Upstream folds `compress_ratios` and `num_hash_layers` into `layer_types` / `compress_rates` / `mlp_layer_types`:
  - V4-only code (attention, decoder, CPU/XPU/NVIDIA MoE, the C4/C128 CuTe DSL kernels) reads the upstream fields directly.
  - Code that also sees DeepSeek-V4.1 configs (the shared MLA backends, `mla_attention`, the arch convertor, the spec-decode proposer and the warmup kernels) uses `get_compress_ratios`. That helper returns V4.1's legacy field, or derives it from the upstream fields with the MTP layers appended. V4.1 can't move to the upstream schema: it uses compress ratios 1 and 2, which have no upstream layer type.
- `mm_prefix_span_leading_pad_modulus` moves from the config onto `DeepseekV4ForConditionalGeneration`, where the model runner already looks for it. The sparse-SWA image-span widening is now keyed on an upstream `DeepseekV4Config` with `vision_n_layers > 0`, matching what the vendored config set.
- `is_rope_parameters_nested` accepts V4's `{"main", "compress"}` rope layout.
- No numerics change for DeepSeek-V4-Flash: greedy outputs are bit-identical to `main`, and GSM8k, GPQA Diamond and MTP acceptance match.
- **`transformers-upgrade` skill:**
  - Models in `vllm/models/` must run GSM8k and GPQA Diamond against `main`, and these evals should disable FlashInfer autotuning.
  - Adds two hazards: undeclared fields with no default, and top-level configs that no longer forward reads to `text_config`.
  - Adds a re-grep for old field names after rebasing.
  - Drops the PR and issue numbers from the skill.

## Validation

`deepseek-ai/DeepSeek-V4-Flash` on 8x B200, `main` (`bc3ddb198a`) on GPUs 0-3 vs this branch on GPUs 4-7, TP4 each, `transformers` 5.19.0.

| Check | `main` | This PR |
|---|---|---|
| GSM8k, 5-shot, 1319 questions, autotune off | 0.944, 0.944 | 0.937, 0.947 |
| GSM8k with MTP (1 token), autotune off | 0.947 | 0.946 |
| MTP draft acceptance | 95.5% (57174 / 59896) | 95.4% (57041 / 59771) |
| GSM8k with MTP, rerun on 84f38ff455 | 0.948 | 0.949 |
| MTP draft acceptance, rerun on 84f38ff455 | 95.4% (57236 / 59977) | 95.5% (57494 / 60209) |
| GPQA Diamond, 8 repeats, reasoning effort high | 0.538 | 0.534 |
| Greedy decode, 4 short prompts x 64 tokens, autotune off | | bit-identical logprobs |

FlashInfer re-tunes its FP4 MoE tactics on every server start, even when given a cache. With autotuning on, the two servers picked different tactics and GSM8k drifted by about 1 point (0.947-0.951 vs 0.939-0.941). With `--kernel-config '{"enable_flashinfer_autotune": false}'` greedy outputs match exactly, so the drift is tactic selection, not this change.

Config dumps for Flash, Flash-Vision-Exp and Pro, using the skill's scripts: `get_compress_ratios`, the per-layer upstream reads, the hash-layer count and the C4/C128 kernel flags all reproduce each checkpoint's legacy values exactly; the mm-prefix clamp is on only for Vision-Exp, as before; and the DeepSeek-V4 RoPE `cos_sin_cache` is bit-identical for sliding, CSA and HCA layers. Vision-Exp and Pro were not served (not enough disk on the host); Vision-Exp's `config.json` sets every `vision_*` field the processor reads.
