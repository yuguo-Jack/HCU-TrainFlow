# [Bugfix][Core] Reject batch-sharded sampling with LoRA at startup

[Upstream PR](https://github.com/vllm-project/vllm/pull/56074) · state: open · merged: False

## Original PR description

﻿## Purpose
Fixes #56068. Models implementing `compute_logits_local` (llama, qwen3_5, deepseek_v4-nvidia, minimax_m3-nvidia) skip the TP logits gather, and the `lm_head` LoRA delta can only be applied after that gather, so `--enable-lora` + `--enable-batch-sharded-sampling` crashed at the first sampling step with `NotImplementedError`. This blocks the combination in `_validate_batch_sharded_sampling` so it fails at startup with a clear reason, matching the existing blockers (return_sampling_mask, adaptive verification).

The rejection is scoped to LoRA configs that target `lm_head` (default targets or an explicit `lm_head` entry), per review feedback; restricted targets such as `["o_proj"]` remain allowed and are covered by a test.

## Test Plan
.venv/bin/python -m pytest tests/test_config.py -k batch_sharded -v

## Test Result
Without fix: the new test fails (no ValueError raised). With fix: 2 passed. The 13 other failures in tests/test_config.py are pre-existing on clean main (network/download tests), verified by stash-compare. Crash link reproduced on CPU: NotImplementedError with the wrapped LogitsProcessor and skip_gather=True.
