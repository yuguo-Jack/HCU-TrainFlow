# [MRV2] Stage decode tokens across captured DBO regions

[Upstream PR](https://github.com/vllm-project/vllm/pull/62430) · state: closed · merged: False

## Original PR description

## Overview

During imbalanced DP decode, a rank can have real requests but leave the last captured microbatch empty, causing MRV2 DBO to fall back from FULL CUDA Graph replay. This first layer of the split of #57184 stages those requests into the captured regions and restores logical order after execution. Related issue: #57177.

## Claims

- Divide real single-token decode rows across the already captured microbatch regions, including odd graph sizes and more than two regions.
- Scatter through temporary buffers so overlapping source and destination rows do not corrupt inputs; restore logical rows for post-forward consumers.
- Retain FULL replay only when every DP rank satisfies the staging contract. Unsupported layouts keep the existing fallback.

## Details

**How it works:** the DP decision checks whether any rank's last captured region would be empty. For eligible uniform single-token decode, staging spreads rows across the existing region slices, rebuilds per-region attention metadata, and restores input and output order after the forward pass. Temporary scatter buffers preserve source rows when regions overlap. The path is gated to specific MRV2 model-state and attention layouts with NIXL EP; unsupported auxiliary inputs and parallel layouts remain excluded.

**Review context:** specture724 asked that the prototype support odd graph sizes and more than two microbatches without hard-coded equal halves; this layer applies that region-based approach. aoshen02 requested that #57184 be split. The original combined PR is closed. All six layers now have official upstream PRs; see the stack above.

**Overlap and cost:** #57020 chooses eager fallback at the empty-tail boundary; this PR stages eligible real rows to preserve FULL replay. The predicates must be reconciled before merge. Staging adds copies and temporary buffers, so this layer makes no performance claim.
