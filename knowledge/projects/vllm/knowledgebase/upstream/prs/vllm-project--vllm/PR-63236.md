# [Doc][Recipe] Add MiniMax-M3.1-Flash recipe

[Upstream PR](https://github.com/vllm-project/vllm/pull/63236) · state: closed · merged: True

## Original PR description



## Overview

Adds `recipes/models/MiniMaxAI/MiniMax-M3.1-Flash.yaml`, the MiniMax-M3.1-Flash serving recipe: single-node TP4 on AMD MI355X and NVIDIA Blackwell (verified on MI355X and GB200), plus 1P1D prefill/decode commands in the guide. Recipe only, split out of the model-support work so it can land on its own.

## Claims

- One `default` variant serves the `MiniMaxAI/MiniMax-M3.1-Flash` checkpoint (MXFP8 dense + NVFP4 experts) on every listed GPU. Per-brand flags live in the recipe-level `hardware_overrides`:
  - **AMD:** `indexer_decode_cp` and `--quantization-config.moe mxfp8` (AITER MXFP8 MoE), plus `VLLM_ROCM_USE_AITER` / `VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS`.
  - **NVIDIA:** `use_prefill_query_quantization` and `FULL_AND_PIECEWISE` CUDA graphs, plus `VLLM_FLOAT32_MATMUL_PRECISION=high`.
- DSpark spec decoding (the draft is in the checkpoint's `dspark/` folder, k=3) is on by default, with a per-brand draft attention backend: `FLASH_ATTN` on NVIDIA, `TRITON_ATTN` on AMD.
- The guide gives the exact 1P1D TP4 + TP4 NIXL commands for both MI355X and GB200. The MI355X prefill node also offloads KV to host memory through SimpleCPUOffload in 1 GiB HugeTLB pages.

## Details

- **Not a duplicate:** #63232 (MiniMax-M3.1-Flash model support) also adds this file. Its version targets GB300 only (DSpark k=7 with `FLASHINFER_TS`, DEP8). This PR carries the recipe on its own and adds MI355X and GB200. The two need to be reconciled before either merges: whichever lands second conflicts on the same path, and they currently disagree on active parameters (23B vs 26B), the DSpark k and draft backend, and the reasoning-mode kwarg (`reasoning_effort` vs `thinking_mode`).
- **Depends on unmerged code:** some rendered and guide commands use flags that are not on `main` yet. `indexer_decode_cp` (AMD single node and PD decode) comes with #63232. `cpu_hugepage_block_size` (MI355X PD prefill offload) is not in #63232 either. Those commands won't run on the current nightly until that code lands.
- **`precision_hardware: {}`:** the renderer assumes NVFP4 means NVIDIA Blackwell only. The empty override removes that assumption so one variant can cover MI355X too, and `supported_hardware` lists the eligible GPUs. Only MI355X and GB200 are marked `verified`.
- **`vram_minimum_gb`:** 533 GB by default (MI355X re-quantizes the experts to MXFP8), with a GB200 override of 285 GB (NVFP4 experts run natively).
- `pd_cluster` is left out of `compatible_strategies`. Its TP pools take the whole node and emit their own NixlConnector config, so the generated commands would not be the ones that were validated. PD stays in the guide.
