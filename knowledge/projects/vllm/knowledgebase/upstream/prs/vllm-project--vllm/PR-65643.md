# [Refactor][PCP] Separate physical topology from attention execution layout

[Upstream PR](https://github.com/vllm-project/vllm/pull/65643) · state: open · merged: False

## Original PR description

## Overview

Separate physical PCP topology from layer backend requirements and per-forward attention layout in Model Runner V2. Replicated DFlash/DSpark drafts retain valid PCP/DCP topology instead of rewriting PCP size to one.

**Draft: constructor, metadata and distributed component checks pass; successful end-to-end generation and model evaluation remain pending.**

## Claims

- Preserve physical world size and DCP KV ownership when constructing replicated drafts. TP1/PCP4/DCP4 previously becomes TP1/PCP1/DCP4 and fails configuration validation.
- Carry an explicit PCP attention context through normal and capture/profile batches, so cache gathering follows the current forward layout instead of tensor-length heuristics.
- Separate repeated PCP query heads from distinct TP head shards in MLA/DCP metadata and workspace sizing.

These attempts do not establish model correctness.

## Details

`prefill_context_parallel_size` continues to describe process topology. Each attention layer declares its backend PCP requirement through `use_pcp`; replicated draft layers request a local-input backend. Physical communication and DCP head ownership retain the original topology. Per-forward `PCPAttentionContext` travels through `InputBatch` and common attention metadata. MLA, indexer and V4.1 compressor/cache metadata consume the current forward layout, including padded/empty owners.

This spans shared configuration, MLA/indexer metadata and model capability checks. The rendered context-parallel deployment documentation describes the distinction. Partitioned K3 target support is still gated; allowing a replicated K3 draft does not establish PCP support for the K3 target.

Duplicate-work checks on 2026-11-04 searched open PCP, DSpark and PCP-topology PRs. No matching topology/execution separation was found. Related #61994 (merged) synchronizes replicated DSpark proposals; #54036 optimizes draft context-KV precompute; #64261 enables a non-causal Triton MLA DCP backend on gfx942. Those address different layers of the problem.

Before readiness: successful generation on a commit-aligned compatible runtime; graph replay and nonzero draft acceptance; token/logit consistency and model evaluation; performance and other-platform qualification; human line-by-line review and confirmation of validation. AI assistance was used for investigation, implementation, testing and this description.
