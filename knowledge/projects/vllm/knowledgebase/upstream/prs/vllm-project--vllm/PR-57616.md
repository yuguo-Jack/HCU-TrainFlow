# [Bugfix] Plain MTP must not trigger the all-groups eagle-group fallback (it zeroes all prefix-cache insertions)

[Upstream PR](https://github.com/vllm-project/vllm/pull/57616) · state: open · merged: False

## Original PR description

## Purpose

On hybrid GDN/mamba models with plain built-in MTP (`method="mtp"`), enabling prefix caching alongside spec decode silently zeroes **all** prefix-cache hits: `vllm:prefix_cache_hits_total` stays at exactly 0 even for byte-identical repeated prompts. Root cause and repro context: #54360 (this PR fixes the mechanism described there).

Chain: no group is identified as the draft's (plain MTP shares the target KV, so there is no draft group by construction) → `KVCacheCoordinator`'s conservative fallback flags **all** groups as eagle → `get_replay_boundaries()` takes the eagle branch and, with `scheduler_block_size` at 3200 and a 4,137-token prompt, both `resend` and `extension` floor to 3200, returning boundaries of `{0}` → `cache_blocks()` inserts nothing → the radix tree is empty and every query misses.

Plain MTP proposes from target hidden states and **has no separate draft KV group**, so "no group identified" is the expected state, not an annotation failure; flagging every group is wrong for it. Methods that do ship a real draft KV (eagle/eagle3/draft_model/dflash/dspark) keep the fallback unchanged.

## Does this introduce a breaking change?

No. Non-MTP methods are unaffected (same `use_eagle` value as before). For plain MTP it restores correct insertion; the trailing-block pollution guard (`use_eagle_block_drop`) remains fully active — this is not the same as the user-side workaround of setting `disable_eagle_block_drop: true`, which additionally disables that guard.

## Testing

DGX Spark GB10 (SM121), Qwen3.8-Flash-Next NVFP4 (125B-A6B hybrid GDN+QSA), MTP k=3, align mode, `--enable-prefix-caching`, piecewise cudagraphs, 262K ctx:

| config | prefix_cache_hits_total | repeat 4,137-token prompt TTFT | MTP acceptance |
|---|---|---|---|
| nightly, no workaround | **0** | 3.6 s every time | 44.5% (piecewise bench) |
| nightly + `disable_eagle_block_drop` (workaround) | 6,400/12,778 = 50.1% | 3.6 → 1.6 s | 44.5% |
| **this PR (no workaround, guard retained)** | **6,400/12,778 = 50.1%** | **3.6 → 1.6 s** | unchanged |

Multiturn conversations stable across all three configs; no regressions in an 8-category decode benchmark (38.9 tok/s median with our disk-backed PLE table, matching the workaround config).
