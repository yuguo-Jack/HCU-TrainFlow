# [CI] Shard Humming B200/H100 evals and two entrypoints AMD mirrors automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/62513) · state: closed · merged: True

## Original PR description



## Overview

Enrolls two long LM eval steps and two entrypoints AMD mirrors in `automatic_shard`. `lm-eval-humming-b200-default` was taken out of #61473 because it failed on main at the time; main passes it again now. `lm-eval-humming-h100-default` also moves from three per-shard config lists to one combined list, as #62120 did for the MoE Refactor steps.

## Claims

| Step | Was | Planned shards |
|---|---|---:|
| `lm-eval-humming-b200-default` | one job | 3 |
| `lm-eval-humming-h100-default` | 3 config-list shards | 5 |
| `amd-entrypoints-integration-api-server-generate` | one job | 2 |
| `amd-entrypoints-integration-api-server-openai-chat_completion` | one job | 2 |

- Every test and every config runs exactly once across the shards, with the same environment as before.
- A config added later to `humming/config-h100.txt` is placed by the planner rather than by editing a shard list.
- The two AMD mirrors' base steps are already enrolled; a native mirror shards only when its own `mirror.amd` sets the flag too.

## Validation

- Planned each step with ci-infra main's `runtime_shard.plan_step` against this branch and main's timings.
- Rendered each step and mirror with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper. Every test of every command ran in exactly one shard, with the same env (4/4 NVIDIA cases for these two steps, 4/4 AMD mirror cases).
- For the two gsm8k steps, also ran the generated shard jobs against vLLM's real `tests/evals/gsm8k/conftest.py` and config lists, with the test body stubbed. All 14 and 15 configs ran once each, and the plan matched every config ID main has timings for.
- `/ci run` [97706](https://buildkite.com/vllm/ci/builds/97706), rebased on main: Humming B200 passed in 3 shards, both AMD entrypoints mirrors passed in 2 shards each, and Humming H100 passed in 4 of 5 shards. Shard 3/5 failed starting the server for `gpt-oss-20b-humming` with `CUDA error: unknown error`, before any shard-specific test logic; it is being retried.

## Details

- **`lm-eval-spec-decode-4xb200` left out.** Its command sets `PYTHONPATH=/vllm-workspace`, which replaces the path the sharding plugin is installed on, so every shard failed with `No module named 'runtime_shard_plugin'` in 97706. ci-infra#825 installs the plugin where that can't happen; steps whose commands set `PYTHONPATH` will be enrolled together after it merges.
- **Planner estimates for eval steps.** The planner counts test time, not the model load and server start that each shard repeats. #62120's H100 MoE Refactor step came in longer than planned for this reason, so `lm-eval-humming-h100-default` (5 shards of about 3 configs) is the one to watch.
- **`caplog`.** Two files in the Generate mirror assert on log text; the same files already run sharded in the enrolled NVIDIA step on main.
- **Timeouts unchanged (human).** As in #62077 and #62120, `timeout_in_minutes` stays per job. A single-job fallback (no plan, or the `VLLM_CI_RUNTIME_SHARD` rollback switch) would outrun it; fallback-aware timeouts belong in a central timeout setting.
- **Left out.** The spec decode AMD mirror runs under 20 minutes as one job. #61473 also touches two of these steps; it continues as #61831, which doesn't include them.
