# [Feature][MRV2] Enable Qwen3.5 GDN ReplaySSM standard decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/64699) · state: open · merged: False

## Original PR description

## Overview

Enable Qwen3.5 GDN standard-decode ReplaySSM on Model Runner V2 by forwarding each request's decode origin to the existing GDN metadata builder.

**Stacked on #62004 at `3c8678368a6358cea60db7841a5cca7c3263ce69`; draft until that dependency lands. Only the final commit is new.** All preceding ReplaySSM commits retain their original authors and SHAs. This adapter adds no ReplaySSM kernel or Skinny GEMM implementation.

## Claims

- Permit Triton ReplaySSM with V2 for `qwen3_5_text`, preserving the guard for other models.
- Snapshot V2's batch-ordered CPU `prefill_len_np`, including resumed-request endpoints, as `replayssm_decode_base_cpu`; zero-fill graph padding.
- Reuse the existing GDN ring/flush calculations and persistent CUDA-graph buffers, without GPU-to-CPU reads or new synchronization.
- Add configuration, metadata, and compiled V2 engine regression coverage, plus usage documentation. Existing compilation mode and Breakable graph settings remain user choices.

## Validation

Single GB10 (SM121), Qwen3.5-4B BF16, FP32 state, TP=1, L16, no speculative decoding or prefix caching.

The V2 engine case explicitly uses compilation mode 3, Breakable off, graph capture size 4, and two prompts with up to 32 output tokens, exercising L16 flushes. It uses the existing parity helper: identical greedy tokens, or mutual top-five membership at the first divergence. This is a limited output regression, not full-vocabulary equivalence or GSM8K/MMLU evaluation.

Earlier standalone validation also passed 24/24 arithmetic checks, C1/C8 generation, and 32/32 mixed requests under GPU sync checking. Historical experiment on main `a9fe30e9f6` plus #62004, both runners compiled with Breakable off, 512 input / 128 output tokens:

These historical measurements support the compiled V2 path on this workload; they are not a fresh benchmark of this exact dependency-head branch. That benchmark build contained a disabled Skinny hook, absent here.

## Details

Relaxing the V2 configuration guard alone leaves the GDN builder without its required CPU decode base. V2 already gathers the prefill endpoint in batch order and refreshes it after preemption. Forwarding a per-step CPU snapshot supplies the builder's existing cursor calculation while keeping request-state ownership in V2. Tests cover a flush boundary, resume origin, final single-token prompt chunk, null graph padding, and persistent device-buffer reuse.

This extends #62004, whose stated scope excludes V2. Related RecoverSSM speculative decoding and Mamba2 FlashInfer lifecycle PRs address different paths. Duplicate searches on 2026-10-30 (`62004 in:body`, `ReplaySSM V2`, and GDN standard-decode keywords) found no existing open PR implementing this adapter. #62004 explicitly lists Model Runner V2 as out of scope.

Standard decoding on one GB10 is validated. Other models, TP>1, V2 align-mode prefix caching, and speculative decoding remain outside this validation. The adapter preserves the kernel mathematics and existing compilation defaults.
