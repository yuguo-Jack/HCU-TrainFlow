# [Bugfix][EPLB] Wait for pending expert buffer copies before NIXL READs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62081) · state: closed · merged: True

## Original PR description

## Purpose

Fixes the intermittent `test_rearrange_expert_weights_with_redundancy[nixl-*]` failure in `mi300_4: (MI300) EPLB Execution`:

```text
verify_redundant_experts_have_same_weights failed: rank=0, layer=0, weight_idx=0, logical_expert=1, physical_pos=4, actual_head=[2100.0, 2101.0, ...], reference_head=[1000.0, 1001.0, ...]
FAILED distributed/test_eplb_execute.py::test_rearrange_expert_weights_with_redundancy[nixl-4-2-2-5] - AssertionError
```

Failing run: <https://buildkite.com/vllm/amd-ci/builds/14810/list?jid=01a143f1-ca27-459c-90a8-b3ef97f5fcaf&tab=output>

The test encodes weights as `logical_expert * 1000 + layer * 100 + ...`, so layer 0 ends up with experts from layer 1. `move_from_buffer` only queues the copies out of `expert_buffer` on the stream, and `add_recv` for the next layer immediately issues NIXL READs into the same buffer from the CPU. The READs are not ordered with the stream, so when the GPU lags (e.g. waking up from idle), they overwrite the buffer before the copies of the previous layer run. Only multi-layer cases fail.

The original NIXL communicator (#36276) synchronized the stream before issuing READs. #41633 removed that sync together with the send buffer packing and made `set_stream` a no-op, while READs now land directly in `expert_buffer`. 

This PR synchronizes the current stream and the EPLB stream in `set_transfer_context`, before the first READ of each layer, and removes the no-op `set_stream` override so the stream is stored. The current stream covers the sync path. In async EPLB, the main thread copies out of the buffer on the main stream, which the worker sees only through `self._stream` waiting on `consumed_event`.

## Test Plan

MI300X (gfx942):

```bash
cd tests
pytest -v -s distributed/test_eplb_execute.py
```

To trigger the race, I ran the `nixl-4-2-2-5` and `nixl-2-2-3-4` cases of `test_rearrange_expert_weights_with_redundancy` in a loop with the same seed and expert mapping as CI, either with the GPU idle for 2 s before each rearrangement or with a `torch.cuda._sleep` delay before `move_from_buffer`.

## Test Result

| Setup | `main` | `main` + this PR |
|---|---|---|
| GPU idle 2 s before each rearrangement | 5/100 failed | 0/100 failed |
| 10-20 ms GPU delay before `move_from_buffer` | 20/20 failed | 0/10 failed |
| Async EPLB flow, 10 ms GPU delay | 40/40 failed | 0/40 failed |

The async flow was emulated with a worker thread calling `transfer_layer` and the main thread calling `move_from_buffer`, as in `async_worker.py` and `eplb_state.py`. All failures had the same signature as CI, while `torch_gloo`, `pynccl` and `torch_nccl` passed under the same delay.

With this PR, `distributed/test_eplb_execute.py` passes: `35 passed, 7 skipped`.

AI assistance was used for diagnosis, implementation and validation. I reviewed every changed line and ran the tests above.
