# [Quantization] NVFP4 W4A16: fall back to weight-only emulation when Marlin is unavailable

[Upstream PR](https://github.com/vllm-project/vllm/pull/47674) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Add a slow weight-only NVFP4 correctness fallback that preserves FP16/BF16 activations when optimized W4A16 kernels are unavailable. **Depends on [#47673](https://github.com/vllm-project/vllm/pull/47673)**; review the fallback changes separately from its registration guard.

## Claims

- Auto-selection preserves current SM100/103 CuteDSL and Humming priorities, considers A16 emulation last, and respects disabled Marlin.
- Explicit unavailable Marlin still errors; explicit emulation selects the weight-only kernel for W4A16.
- Tested FP16/BF16 CPU, CUDA eager and CUDA graph outputs match independently decoded weight-only matmul exactly.

## Validation

Tested base `18c19eaf23`; refreshed stacked head `d277d5d626`, with guard head `a969c9b549` included equivalently. ThinkStation PGX (GB10/SM121), Python 3.12.3, PyTorch 2.13.0+cu130, pytest 9.1.1; real current-source modules imported with prebuilt vLLM extensions. Changed source/test hashes were verified against the final commits.

October 10 rerun under the submitting user's oversight:

- `.venv/bin/python -m pytest tests/quantization/test_marlin_fp4_registration_guard.py tests/quantization/test_nvfp4_w4a16_emulation_fallback.py -k 'not cuda_auto_selection' -v`: **19 passed** in 4.69s.
- `.venv/bin/python -m pytest tests/quantization/test_nvfp4_w4a16_emulation_fallback.py -k cuda_auto_selection -v`: **1 passed** in 0.36s, using actual PGX platform/availability probes with optimized W4A16 kernels disabled.

These are **20 unique tests**, including the five prerequisite guard tests. Selection covers available/missing/disabled Marlin, available Humming, explicit unavailable Marlin and explicit emulation. Numerical tests cover every E2M1 code/sign, unequal block scales, a nonunit global scale, activations between FP4 grid points, bias and 3D shape. The layer has no activation-scale attribute. Four CUDA FP16/BF16 cases also pass exact-reference comparisons through CUDA graph capture/replay, exercising real Triton dequantization.

Configured scoped pre-commit passed on all six changed files (including mypy 3.11 and CI test tethering); nonmatching hooks skipped as configured. `git diff --check` passed. No full-model generation, model-quality or throughput claim.

## Details

Existing NVFP4 emulation and Torch quantize activations; CuteDSL W4A16 is SM100/103-only. This kernel reuses weight dequantization and plain matmul to supply the missing correctness path. It is intentionally slow. Existing batch-invariant W4A16 rejection is unchanged.

[#52974](https://github.com/vllm-project/vllm/pull/52974) overlaps ROCm forced-Marlin selection but adds gfx90a Triton and format detection; this change provides universal A16 emulation without copying those changes. [#59460](https://github.com/vllm-project/vllm/pull/59460) declares/enforces activation schemes and touches selector/base APIs but does not provide A16 emulation. Coordinate selector overlap and recheck compatibility before merge.

AI assistance was used (Codex). The submitting user reported reviewing every changed line and requested the tests under their oversight; Codex executed the rerun with that oversight. Logs and source-hash provenance are retained. Historical July results are not presented as new validation.
