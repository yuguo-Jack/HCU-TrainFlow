# [CI/Build] Add regression coverage for plain and suffixed CUDA arches

[Upstream PR](https://github.com/vllm-project/vllm/pull/56582) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Add regression coverage for the plain CUDA architecture preservation fixed by #56549 (original issue: #56548). This PR now changes only `tests/test_cmake_utils.py`; the CMake implementation comes entirely from upstream.

## Claims

- Preserve plain `10.0` alongside either `10.0a` or `10.0f` for the issue's architecture list.
- Reject an extra plain `9.0` when only `9.0a` was requested, and require exactly the expected nine entries.
- Add coverage missing from #56549, which changed only `cmake/utils.cmake`; no duplicate production fix remains.

## Validation

```sh
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest --noconftest tests/test_cmake_utils.py -q
# 5 passed
.venv/bin/pre-commit run --files tests/test_cmake_utils.py
```

The tests run the real CMake function with `cmake -P`, without a GPU or vLLM installation. `--noconftest` avoids unrelated serving fixtures; these tests use only pytest's `tmp_path` fixture.

Regression sensitivity: in an isolated copy of the test module, using `cmake/utils.cmake` from `072c0886^` (before #56549), both new parameterized cases fail because plain `10.0` is missing. Both pass with current upstream code. The existing Buildkite CPU job in `.buildkite/test_areas/misc.yaml` already installs CMake and runs this test file.

## Details

The symmetric suffix-handling pass used to consume the plain source architecture even when the target list also explicitly requested it. #56549 fixed that logic. Rebasing this PR keeps that upstream implementation and retains the regression test, extended to both supported suffixes.

Validation used Python 3.12 and CMake 4.4.4 on macOS. No CUDA wheel rebuild, GPU runtime test, or model evaluation was performed for this test-only change; production behavior is unchanged.
