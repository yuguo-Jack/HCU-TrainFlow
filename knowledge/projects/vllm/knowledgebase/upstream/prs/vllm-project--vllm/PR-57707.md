# [Bugfix][Frontend] Keep the trailing parameter when qwen3 closes the function without it

[Upstream PR](https://github.com/vllm-project/vllm/pull/57707) · state: open · merged: False

## Original PR description

## Purpose

Fixes #57699. `_qwen3_arg_converter` ended a parameter value only at `</parameter>` or the next `<parameter=`. Models sometimes close `</function>` without closing the last parameter, and then:

- non-streaming: the final conversion (`partial=False`) dropped the trailing value, so `arguments` came back without it (with several parameters, the call silently lost the last one);
- streaming: partial conversions had already streamed the value, but the flush at `TOOL_CALL_END` produced `{}`, shorter than what was already sent, so nothing more was emitted and the client kept the clipped version.

Not a duplicate: the two earlier qwen3 parser fixes I checked (#43243's JSON-first parsing, and the `null`-handling change) cover different shapes; nothing open touches this one.

The fix is to run the trailing-parameter capture in both modes instead of only in partial mode. The accumulated raw body never contains the `</function>` marker (the engine consumes it as a terminal event), so the trailing value runs cleanly to the end of the buffer. Empty trailing values behave exactly like explicitly-closed empty parameters.
