# [Bugfix] Validate global model seed range

[Upstream PR](https://github.com/vllm-project/vllm/pull/65127) · state: closed · merged: True

## Original PR description



## Overview
Fixes #64953. Validate the global model seed at configuration time so unsupported values fail before EngineCore startup.

## Claims
- Constrain `ModelConfig.seed` to NumPy's supported range `[0, 2**32 - 1]`, and document the range.
- Add an LLM initialization regression test for values below and above this range.

## Validation
- Before this config change, the regression test proceeds to worker startup and fails with `ValueError: Seed must be between 0 and 2**32 - 1`, and the caller receives `RuntimeError: Engine core initialization failed`.
- After the change: `.venv/bin/python -m pytest tests/entrypoints/llm/test_prompt_validation.py -k model_seed_out_of_numpy_range -v -s` — 2 passed.
- `uv tool run ruff check vllm/config/model.py tests/entrypoints/llm/test_prompt_validation.py` — passed.
- `uv tool run ruff format --check vllm/config/model.py tests/entrypoints/llm/test_prompt_validation.py` — passed.
- `git diff --check` — passed.
- Model evaluation is not applicable: this change only rejects invalid configuration values and does not alter model outputs for valid seeds.

## Details
`ModelConfig.seed` was previously unbounded. Invalid values would propagate into `np.random.seed()` during worker initialization and crash the engine.
The config field now validates against NumPy's supported range before worker startup.

This applies to the global engine seed. Request-level `SamplingParams.seed=-1` has separate semantics and remains unchanged.
