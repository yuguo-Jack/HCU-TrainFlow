# [Doc] MiniMax-M3.1-Flash: add the B300 single-node AgentX presets

[Upstream PR](https://github.com/vllm-project/vllm/pull/64108) · state: closed · merged: True

## Original PR description

## Overview

Document the B300 MiniMax-M3.1-Flash AgentX lane of [SemiAnalysisAI/InferenceX#4467](https://github.com/SemiAnalysisAI/InferenceX/pull/4467) (head `615ee422`, lane `minimaxm31flash-fp4-b300-vllm-agentic-dspark`) as two opt-in B300 presets in `recipes/models/MiniMaxAI/MiniMax-M3.1-Flash.yaml`. The lane runs one aggregated vLLM engine on a single 8-GPU B300 node with image `vllm/vllm-openai:minimax-m31-flash@sha256:86f582dae25ea92802353727164ae4eb03b37b18baf9119b805ffaec2a7ef07c` (vLLM `0.1.dev23341+g8744dd2fb` in the run logs). The recipe has no B300 preset yet, and no open PR covers this lane.

## Claims

Both presets use the default checkpoint, `single_node_tp`, text only (`--language-model-only`), the recipe's Blackwell NVFP4 KV/indexer settings and seven-token DSpark draft, plus the lane's shared settings: `--enable-prefix-caching`, `--max-num-batched-tokens 32768`, `--stream-interval 20`, `FULL_AND_PIECEWISE` with an explicit `cudagraph_capture_sizes` list up to 8192, `VLLM_HTTP_TIMEOUT_KEEP_ALIVE=600` and `VLLM_CHAT_TEMPLATE_RENDER_TIMEOUT=600`.

**`b300_agentx_tp4` (AgentX TP4, opt-in):** TP4, `--gpu-memory-utilization 0.92`, DSpark draft attention on `FLASH_ATTN` (as qualified; the recipe's NVIDIA default stays `FLASHINFER_TS`). Nine points:

- GPU-resident KV: concurrency 1 / 4 / 8 / 16 / 32 with `--max-num-seqs` 2 / 8 / 16 / 32 / 64.
- Host-DRAM KV offload (the **Simple** KV-offload option, `SimpleCPUOffloadConnector`, `kv_both`, `lazy_offload: true`, `cpu_bytes_to_use: 1499000000000` for the whole engine): concurrency 24 / 40 / 48 / 56 with `--max-num-seqs` 48 / 64 / 64 / 96.

**`b300_agentx_tp2` (AgentX TP2 + KV offload, opt-in):** TP2, `--gpu-memory-utilization 0.9`, DSpark draft attention on the recipe's `FLASHINFER_TS`, Simple KV offload with `cpu_bytes_to_use: 749000000000` and `lazy_offload: true` at every point. Concurrency 24 / 32 / 40 / 48 with `--max-num-seqs` 48 / 48 / 60 / 72.

Each preset has a runbook covering host-memory sizing (each rank pins about 349 GiB), the FLASH_ATTN/FLASHINFER_TS split, and the synthetic acceptance the benchmark used. `meta.date_updated` is bumped to 2026-10-27.

In both server logs the connector comes from `--kv-transfer-config` (`SimpleCPUOffloadConnector: ... per_rank=349.01 GB, world_size=4, mode=lazy` and `per_rank=348.78 GB, world_size=2`), confirming that `cpu_bytes_to_use` is the budget for the whole engine. The logs also show `FLASH_ATTN` on TP4 and `FLASHINFER_TS` on TP2.

## Details

The schema expresses every serving setting of the lane. TP comes from the preset's `tp`; the host-DRAM tier comes from `select.kv_offload: simple`, with `json_args` on its `--kv-transfer-config` that swap the Simple option's per-rank default (`cpu_bytes_to_use_per_rank`) for the lane's engine-wide `cpu_bytes_to_use`, the same pattern as MiniMax-M3's `b200_agentx`. The capture list and the TP4 draft backend are `json_args` edits as well. The lane ran one engine per node; running several TP2 engines on one node is not qualified, and each engine would need its own share of host RAM (noted in the runbook).

Excluded as InferenceX-only or no-op:

- **Benchmark-only settings:** concurrency lists, synthetic acceptance (`rejection_sample_method: synthetic`, `synthetic_acceptance_length: 4.04`, injected by the benchmark; the presets keep block verification), AIPerf settings, `dram-utilization`.
- **Harness plumbing:** `--served-model-name` and the local `/model` path, `--host`/`--port`, `--device-ids` (GPU placement), `--disable-uvicorn-access-log`, `PYTHONUNBUFFERED`, `VLLM_ENGINE_READY_TIMEOUT_S` (the lane is single-engine, with no data-parallel engine wait).
- **Defaults:** `--max-model-len 1048576` equals the checkpoint's `max_position_embeddings`, and the logs report 1,048,576 tokens per request. `--trust-remote-code` is not needed because vLLM registers the `minimax_m3_vl` config itself (`vllm/transformers_utils/config.py`), and the recipe's existing B300 commands, on the same image tag, omit it.
- **`VLLM_USE_SIMPLE_KV_OFFLOAD`:** a no-op here (the lane sets `1` on its offload points and `0` on the resident ones). vLLM reads it only in `VllmConfig._post_init_kv_transfer_config`, to choose the connector when `--kv-offloading-size` is set (`vllm/config/vllm.py` on `main`). The lane never sets `--kv-offloading-size` (absent from the logged non-default args) and passes the connector explicitly. The pinned build's commit `8744dd2fb` is not in this repository, so this is checked against `main` and against the logged connector creation.
