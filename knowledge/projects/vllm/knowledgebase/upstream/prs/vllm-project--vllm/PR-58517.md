# [Core] Bound async GPU output synchronization

[Upstream PR](https://github.com/vllm-project/vllm/pull/58517) · state: open · merged: False

## Original PR description

## Overview

Bound asynchronous GPU output synchronization in both V1 and V2 model runners so a stalled kernel raises `TimeoutError` rather than blocking output indefinitely. Refs #52247.

## Claims

- Poll output-copy events with a five-minute default controlled by `VLLM_ASYNC_OUTPUT_TIMEOUT_S`.
- Log and raise on timeout through the existing engine failure path.
- Wait for pooling output copies before reading the host buffer.

## Details

The output wrappers currently wait indefinitely on CUDA event synchronization. A shared bounded polling helper preserves the existing output path and surfaces a timeout when an event remains incomplete. Polling introduces up to 10 ms between readiness checks; throughput and latency effects have not been measured.

Rebased onto `main` at `111f71a6`. The conflict resolution preserves upstream's removal of the obsolete `VLLM_ENGINE_ITERATION_TIMEOUT_S` entry and retains this PR's `VLLM_ASYNC_OUTPUT_TIMEOUT_S`. The wait helper and tests are unchanged.

Related design history: closed PR #52365 proposed polling for the same async-output problem. A maintainer asked to address it differently rather than introducing polling. This PR also polls `event.query()`, so that concern applies here. The preferred watchdog/timeout layer needs maintainer agreement before further implementation; this is not presented as an approved design or the first attempt at this fix.
