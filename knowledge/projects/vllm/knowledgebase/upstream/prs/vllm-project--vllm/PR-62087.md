#  [CI][Bugfix] Ignore AMD CI webhook no-op builds in /amd-ci run and retry

[Upstream PR](https://github.com/vllm-project/vllm/pull/62087) · state: closed · merged: True

## Original PR description

Every push to a PR creates an amd-ci webhook build. bootstrap-amd.sh exits for those builds without running any tests ("AMD CI does not start automatically on PRs"), so they pass with nothing tested. The bot treated them as real runs:

1. /amd-ci run from a PR author without write access was refused with "AMD CI already ran on this commit" (for example, https://buildkite.com/vllm/amd-ci/builds/14851). Pushing again didn't help, because every push creates another no-op build.
2. /amd-ci retry picked the no-op build and replied "No failed jobs need retrying" instead of telling the author to use /amd-ci run.

The fix skips builds with source webhook for AMD CI commands in both places. This is the same condition bootstrap-amd.sh uses. Builds started from the Buildkite UI, or by comment, still count. /ci behavior is unchanged.

Test plan: new unit tests for both cases; they fail on main and pass with this change. All 62 tests in test_run_ci_command.py pass.


### Replay against real PR data

I replayed `run_ci_command.py` from upstream `main` and from this PR against the real data for #62032:
- the live PR from the GitHub API;
- every amd-ci build on the PR, from Buildkite. The only build on the head commit `f03aefad5b` is [#14851](https://buildkite.com/vllm/amd-ci/builds/14851), a `webhook` build that ran no tests.

All writes (comments, reactions, branch updates, build create, retry) were stubbed and recorded, not sent. The `main` replay reproduces the bot's actual reply on #62032.

| Scenario (PR author without write access) | `main` | This PR |
|---|---|---|
| `/amd-ci run` (bot merges `main` into the stale branch, as in production) | ❌ "AMD CI already ran on this commit: …/builds/14851" | ✅ Merges `main`, then starts an AMD CI build on the new head |
| `/amd-ci run --allow-stale` | ❌ "AMD CI already ran on this commit: …/builds/14851" | ✅ Starts an AMD CI build on `f03aefad5b` |
| `/amd-ci retry` | Retries no-op #14851: "No failed, timed-out, or expired jobs need retrying" | "No AMD CI build exists for the current PR head. Use `/amd-ci run` first." |
| `/amd-ci run` when a comment-triggered build already finished on the head | ❌ "already ran" | ❌ "already ran" (unchanged) |
| `/amd-ci run` when a Buildkite UI build already finished on the head | ❌ "already ran" | ❌ "already ran" (unchanged) |
| `/amd-ci retry` when a comment-triggered build failed on the head | Retries that build | Retries that build (unchanged) |

Unit tests: the two new tests fail on `main` and pass with this change. All 62 tests in `test_run_ci_command.py` pass.
