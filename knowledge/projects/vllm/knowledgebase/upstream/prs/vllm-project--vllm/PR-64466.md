# [Perf][DSv4.1] Apply the output head to the decoder replay rows only

[Upstream PR](https://github.com/vllm-project/vllm/pull/64466) · state: closed · merged: False

## Original PR description



## Overview

With decoder replay layers (#59532), DeepSeek-V4.1's output head (hc collapse + final norm) now runs inside the replay layers on the replay rows only, instead of on the whole batch, whose other rows are zero and unused.

## Claims

- DeepSeek-V4.1-Flash DEP2 prefill: the output head takes 5–6 us instead of 100–200 us per forward (0.1% of a 16K-token forward); outputs are bit-identical.
- GSM8K and DSpark acceptance unchanged.

## Validation

`vllm bench forward`, DeepSeek-V4.1-Flash with dummy weights, DEP2 on one GB200 node, FlashMLA MegaAttn with the MXFP4 indexer, `--kv-len-jitter 0 --max-num-batched-tokens 20480`, rank 0 kernel profile (`--profile-dir`), GPU us per forward:

| kernel | 16K new tokens, main | This PR | 128K cached + 8K new, main | This PR | 128K cached + 16K new, main | This PR |
|---|---|---|---|---|---|---|
| `_hc_head_reduce_store` (collapse) | 122 | 2.2 | 64 | 2.2 | 124 | 2.3 |
| final `rms_norm` | 80 | 3.4 | 39 | 3.3 | 78 | 3.4 |

Accuracy (`vllm serve`, DEP4 on one GB200 node, DSpark K=5 with probabilistic drafting and standard rejection sampling; GSM8K is lm_eval 5-shot, greedy, max 1024 tokens, concurrency 32, strict-match; acceptance length over the GSM8K run; the run had this change and #64467 applied together, both bit-identical): GSM8K strict-match 0.9287, acceptance length 3.447 (reference before these changes, same flags: 0.9265 / 3.451).

```bash
pytest tests/models/test_deepseek_v41_decoder_replay_layers.py  # passed
```

`test_run_gathers_states` now also checks that the output head runs on the replay rows only (the trimmed rows stay zero).

## Details

- `DecoderReplayLayers.finalize` is set by the model when it has replay layers and no MTP hidden buffer (MTP needs the uncollapsed states); the model then skips its own collapse + norm. Without a replay batch the replay layers apply it to their whole output, as the model did.
- The trimmed rows' outputs stay zero, and nothing reads them.
- Not a duplicate: #62817 replays fewer rows for prefill chunks far from the prompt end, which this complements (the output head then runs on even fewer rows).
