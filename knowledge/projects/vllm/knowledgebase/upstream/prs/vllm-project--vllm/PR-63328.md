# [Perf][Attention] FA4 sparse MLA: grouped prefill with an FP8 KV cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/63328) · state: open · merged: False

## Original PR description



## Overview

Lets `FLASH_ATTN_MLA_SPARSE_FA4` serve an FP8 KV cache (`--kv-cache-dtype fp8` / `fp8_e4m3`). Decode runs on trtllm-gen's FP8 kernel, as `FLASHINFER_MLA_SPARSE` does, and the grouped prefill of #63104 reads a BF16 copy of each prefill request's KV.

Stacked on #63104, which depends on vllm-project/flash-attention#205: only the last commit is new. Default backend selection does not change. For a quantized cache the SM100 sparse priority list stays `FLASHINFER_MLA_SPARSE`, `FLASHMLA_SPARSE`, so this path is opt-in with `--attention-backend FLASH_ATTN_MLA_SPARSE_FA4`.

Related work: LiteDSA (arXiv 2607.11976) groups neighbouring queries in the same way for the FP8 sparse MLA path, on a vendored FlashMLA SM100 FP8 kernel. It was proposed in #48726 and removed from it in a later commit, so #48726 now carries only the LiteTopk indexer. This PR instead dequantizes into #63104's BF16 path and FA4's existing kernel. The idea itself is not new (see #63104). #60806 (draft) would let the FA4 masked-MHA prefill serve an FP8 cache when the prefill query is BF16; prefills it routes to masked MHA would not reach this path, as with a BF16 cache in #63104.

## Claims

- **`FLASH_ATTN_MLA_SPARSE_FA4` with an FP8 cache prefills 1.09-1.17x faster than the default FP8 backend** (`FLASHINFER_MLA_SPARSE`) on `nvidia/GLM-5.2-NVFP4` (TP4, B300). With a quantized cache masked MHA is off, so this covers every sparse prefill.
- **No measurable accuracy change:** GSM8K 5-shot exact match (strict / flexible) is 0.9363 / 0.9378 on the baseline and 0.9371 / 0.9393 with this PR (± 0.0067). On the same FP8 values, the grouped path's error against an fp32 reference is 3-9x lower (max) than trtllm-gen's FP8 kernel, because P·V stays in BF16.
- BF16 behaviour and default backend selection are unchanged.

```python
"""FP8 KV cache: error vs an fp32 reference (on the dequantized FP8 inputs) of the grouped FA4
path on its BF16 copy and of trtllm-gen's FP8 kernel, on the same prefill rows. Reuses the unit
test's inputs; run from a vLLM checkout inside the nightly image."""

import torch

import tests.v1.attention.test_sparse_mla_backends as T
from vllm.platforms import current_platform
from vllm.v1.attention.backends.mla import flashattn_mla_sparse as M
from vllm.v1.attention.backends.mla.index_group import SparseMLAIndexGroupBuilder
from vllm.v1.worker.workspace import WorkspaceManager

workspace = WorkspaceManager(torch.device("cuda"))
M.current_workspace_manager = lambda: workspace
q_scale, k_scale = 0.5, 0.25
fp8 = current_platform.fp8_dtype()
for num_heads in (16, 32, 64):
    group = 128 // num_heads
    query_lens = [1, 24 * group + 3, 20 * group + 1]
    inputs = T._fa4_prefill_inputs(num_heads, query_lens, [300, 700, 650], device="cuda")
    q = (torch.cat(inputs.q, dim=-1).float() / q_scale).to(fp8)
    kv_cache = (inputs.kv_cache.float() / k_scale).to(fp8)
    layer = T.SimpleNamespace(_q_scale_float=q_scale, _k_scale_float=k_scale,
                              _k_scale=torch.tensor(k_scale, device="cuda"))
    grouped = torch.zeros(sum(query_lens), dtype=torch.bool, device="cuda")
    first = query_lens[0]
    for n in query_lens[1:]:
        grouped[first: first + n // group * group] = True
        first += n
    for peak in (1, 16):
        inputs.scale = (576 ** -0.5) * peak
        reference = T._fa4_prefill_reference(inputs, q.float() * q_scale, kv_cache.float() * k_scale)[grouped]
        row = {}
        for name, spans in (("grouped FA4 (BF16 copy)", None), ("trtllm-gen FP8", lambda *a, **k: None)):
            impl = T._fa4_impl(inputs.logical, scale=inputs.scale, kv_cache_dtype="fp8", staged_kv_shape=(1024, 576),
                               index_group=SparseMLAIndexGroupBuilder(inputs.logical).register_layer(True)[0])
            if spans is not None:
                impl._query_group_spans = spans
            M.FlashAttnMLASparseFA4Impl._query_group_unions = None
            with torch.inference_mode():
                out = impl.forward_mqa(q, kv_cache, inputs.metadata, layer)[0].float()[grouped]
            err = (out - reference).abs()
            row[name] = f"max {err.max():.4f} mean {err.mean():.5f}"
        print(f"heads {num_heads:2d} | softmax scale x{peak:2d} | {grouped.sum().item()} rows | "
              + " | ".join(f"{k}: {v}" for k, v in row.items()), flush=True)
```

```python
"""Cost of the FP8 path's two extra steps for one prefill request of S tokens on one layer: staging
the request's S cache rows to BF16 (gather_and_maybe_dequant_cache) and dequantizing its packed
FP8 query (16 heads x 576). Median of 50 CUDA-event-timed calls."""

import torch

from vllm import _custom_ops as ops
from vllm.utils.math_utils import cdiv

BLOCK, WIDTH, HEADS, LAYERS = 64, 576, 16, 78


def timed(fn) -> float:
    fn()
    times = []
    for _ in range(50):
        start, end = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
        start.record(); fn(); end.record(); torch.cuda.synchronize()
        times.append(start.elapsed_time(end) * 1e3)
    return sorted(times)[len(times) // 2]


for seq_len in (8192, 16384, 32768, 49152):
    blocks = cdiv(seq_len, BLOCK)
    cache = torch.randint(0, 120, (blocks + 256, BLOCK, WIDTH), dtype=torch.uint8, device="cuda")
    block_table = torch.randperm(blocks + 256, device="cuda")[:blocks].to(torch.int32)[None]
    bounds = torch.tensor([0, seq_len], dtype=torch.int32, device="cuda")
    token_to_seq = torch.zeros(seq_len, dtype=torch.int32, device="cuda")
    staged = torch.empty(65536, WIDTH, dtype=torch.bfloat16, device="cuda")
    scale = torch.tensor(1.0, device="cuda")
    stage = timed(lambda: ops.gather_and_maybe_dequant_cache(
        cache.view(torch.float8_e4m3fn), staged, block_table, bounds, token_to_seq, seq_len, "fp8", scale))
    q = torch.randint(0, 120, (seq_len, HEADS, WIDTH), dtype=torch.uint8, device="cuda").view(torch.float8_e4m3fn)
    dequant = timed(lambda: q.to(torch.bfloat16).mul_(0.5))
    print(f"S={seq_len:6d}: stage {stage:6.1f} us, query dequant {dequant:6.1f} us per layer | "
          f"x{LAYERS} layers {(stage + dequant) * LAYERS / 1e3:5.2f} ms per forward")
```

```python
"""Ways to turn the packed FP8 query (S x 16 heads x 576) into BF16: torch cast, torch cast + scale,
and a Triton dequant kernel. Median of 50 CUDA-event-timed calls."""

import torch

from vllm.triton_utils import tl, triton


@triton.jit
def _dequant_kernel(src, dst, scale, n, BLOCK: tl.constexpr):
    offs = tl.program_id(0).to(tl.int64) * BLOCK + tl.arange(0, BLOCK)
    x = tl.load(src + offs, offs < n)
    tl.store(dst + offs, (x.to(tl.float32) * scale).to(tl.bfloat16), offs < n)


def triton_dequant(q, scale):
    out = torch.empty(q.shape, dtype=torch.bfloat16, device=q.device)
    n = q.numel()
    _dequant_kernel[(triton.cdiv(n, 4096),)](q, out, scale, n, BLOCK=4096)
    return out


def timed(fn) -> float:
    fn()
    times = []
    for _ in range(50):
        start, end = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
        start.record(); fn(); end.record(); torch.cuda.synchronize()
        times.append(start.elapsed_time(end) * 1e3)
    return sorted(times)[len(times) // 2]


for seq_len in (8192, 49152):
    q = torch.randint(0, 120, (seq_len, 16, 576), dtype=torch.uint8, device="cuda").view(torch.float8_e4m3fn)
    ref = q.to(torch.bfloat16).mul_(0.5)
    assert torch.equal(triton_dequant(q, 0.5), ref)
    print(f"S={seq_len:6d}: cast {timed(lambda: q.to(torch.bfloat16)):7.1f} us | "
          f"cast+mul {timed(lambda: q.to(torch.bfloat16).mul_(0.5)):7.1f} us | "
          f"triton {timed(lambda: triton_dequant(q, 0.5)):7.1f} us | "
          f"bytes moved {q.numel() * 3 / 1e6:.0f} MB")
```

## Details

**Why.** FA4's MLA kernel takes no descales, so with an FP8 cache the FA4 backend accepted only BF16 and FP8 deployments could not use the grouped prefill.

**Changes**

- `FlashAttnMLASparseFA4Backend` lists `fp8` and `fp8_e4m3`. With a quantized cache the impl:
  - decodes through the trtllm-gen path it inherits (its LSE converted to base e, as for trtllm-gen prefill);
  - runs decode rows, per-request tails and padding rows of a grouped batch on trtllm-gen too;
  - for each prefill request, copies its rows `[0, seq_len)` to BF16 with `ops.gather_and_maybe_dequant_cache` into a workspace of `max_model_len x 576`. The workspace is reserved at init through the workspace manager, as FlashMLA's prefill workspace is.
- The union then maps positions to themselves (an identity block table), so the 2^24 row limit applies to positions rather than cache rows.
- The packed FP8 query of the grouped rows is dequantized with a small Triton kernel, `sparse_utils.dequantize_fp8`. Torch's FP8 cast reached about 1 TB/s here.
- The layer still quantizes the query (`supports_quant_query_input` is unchanged), so decode is exactly the FlashInfer path.

**Using it.** Pass `--attention-backend FLASH_ATTN_MLA_SPARSE_FA4 --kv-cache-dtype fp8_e4m3` (or `fp8`).
- Grouping needs 16, 32 or 64 query heads per rank: GLM-5.x at TP4, TP2 or TP1, and DeepSeek-V3.2 at TP8, TP4 or TP2. Otherwise prefill silently stays on trtllm-gen; GLM-5.x at TP8 is one such case.
- With NIXL P/D disaggregation, both sides must run the same attention backend, because NIXL's compatibility hash includes it. With an FP8 cache FA4 decodes on trtllm-gen, so a decode instance on this backend decodes as `FLASHINFER_MLA_SPARSE` does.

**Tradeoffs and limitations**

- **Smaller gain than with BF16 KV (1.4-1.5x in #63104).** The baseline gets much faster with an FP8 cache: its 48K prefill takes 1.89 s instead of 2.60 s with BF16, trtllm-gen in both cases. This path stays near 1.72 s because it computes in BF16. A native FP8 grouped kernel, as in #48726, would keep FP8's advantage.
- **Memory.** The workspace is `max_model_len x 1,152 B` (75 MB at 64K). The dequantized query is a temporary of `tokens x heads x 1,152 B` per request, the same size as the head-major query copy of #63104's BF16 path.
- **Query precision.** Grouped rows use the FP8 query the layer already produced for trtllm-gen, dequantized. Keeping a BF16 query for them would need the layer to quantize only the rows trtllm-gen reads.

AI assistance (Claude) was used to write this change, its tests and the benchmarks, which ran on my machine; I reviewed every changed line. This stays a draft until #63104 and flash-attention#205 are merged.
