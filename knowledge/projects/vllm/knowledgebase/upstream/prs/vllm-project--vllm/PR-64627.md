# [Rust][Benchmark] Exclude role-only chunks from vllm-bench token timing

[Upstream PR](https://github.com/vllm-project/vllm/pull/64627) · state: closed · merged: False

## Original PR description



## Overview



## Overview

Some chat completion endpoints emit an opening role-only delta with empty
content before the first generated output. The Rust benchmark treated every
chunk with a non-empty `choices` array as token-bearing output.

As a result, role metadata could set TTFT prematurely, shift the real
first-output delay into ITL, and add a phantom timestamp that skews short-output,
peak-throughput, and steady-state metrics.



## Claims

- Role-only metadata no longer starts TTFT or contributes to ITL.
- Content, reasoning, tool calls, and function calls remain valid streamed
  output.
- Empty content-only deltas remain valid because a generated token can decode
  to an empty string.
- Existing request-success behavior remains unchanged.
- Regression coverage verifies the complete SSE request path.



## Validation

```
cargo nextest run -p vllm-bench
cargo clippy -p vllm-bench --all-targets --locked -- -D warnings
cargo fmt --all -- --check
```



## Details

The previous implementation considered any non-empty choices array to be
token-bearing output. An opening delta such as:

{"choices":[{"delta":{"role":"assistant","content":""}}]}

therefore set first_token_received, recorded TTFT, and advanced the most
recent token timestamp despite carrying no generated output.

The chat delta model now records the fields needed to distinguish generated
output from opening metadata. A shared predicate accepts non-empty content,
reasoning, tool calls, or function calls. It also accepts content: "" when
the delta has no role, preserving empty decoded tokens.

The streaming handler applies this predicate before updating TTFT, ITL,
generated text, or the most recent token timestamp.
