# [Rust Frontend] Add TLS certificate hot-reload (`--enable-ssl-refresh`)

[Upstream PR](https://github.com/vllm-project/vllm/pull/47362) · state: open · merged: False

## Original PR description

### Summary

- Follow-up to #45890 (tracking: #44280): implements the deferred `--enable-ssl-refresh` hot-reload, the last remaining TLS-parity gap with the Python frontend. When the cert/key/CA files change on disk, new TLS handshakes serve the new material with no restart; in-flight connections keep the cert they negotiated with.
- A `notify`-based file watcher rebuilds the OpenSSL context on change and atomically swaps it into the live HTTP and gRPC listeners. Opt-in flag, default off.
- Mirrors Python's `SSLCertRefresher`: reload-and-keep-old on a bad/partial write, watcher stops on shutdown.

### Notes

- **Watches the parent directories, not the leaf files.** This is deliberate so it survives the atomic symlink-swap rotation used by k8s/cert-manager, which a leaf-file watch stops following after the first rotation.
- **Whole-context rebuild, all-or-nothing**: OpenSSL's `SslContext` is immutable once built, so a change rebuilds and swaps a fresh context (Python mutates its context in place and reloads cert-chain vs CA independently).
