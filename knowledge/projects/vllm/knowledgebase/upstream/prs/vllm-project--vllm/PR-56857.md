# [Bugfix] Make hc_expand/hc_contract rank-agnostic

[Upstream PR](https://github.com/vllm-project/vllm/pull/56857) · state: open · merged: False

## Original PR description

## Purpose

`hc_pre` / `hc_post` in `vllm/model_executor/layers/mhc.py` are rank-agnostic — they read `shape[-2:]` as `(hc_mult, hidden_size)` and treat everything before it as outer dims. The two helpers that feed them hardcode rank 2:

```python
def hc_expand(x, n):    return x.unsqueeze(1).expand(-1, n, -1).contiguous()
def hc_contract(x, n):  return x.mean(dim=1)
```

`unsqueeze(1)` only coincides with "second-to-last" for rank-2 input, and `expand` hardcodes three sizes. A model runner that passes bucketed rank-3 `[1, T, hidden]` or rank-4 `[bs, 1, seq, hidden]` activations — the Intel Gaudi backend does — hits:

```
RuntimeError: expand: the requested shape has too few dimensions!
```

`hc_contract` has the matching problem: for rank-3 input, `mean(dim=1)` reduces over the token axis rather than the mHC axis.

Found while bringing up GLM-5.3-Flash on Intel Gaudi 2.

## Test Plan

`test_hc_expand_contract_rank_agnostic` in `tests/kernels/mhc/test_mhc_kernels.py`, CPU-only. Covers rank 2/3/4, checks that `hc_expand` puts the axis second-to-last, and verifies the round-trip `hc_contract(hc_expand(x)) == x` (exact, since `hc_expand` replicates).

```bash
pytest tests/kernels/mhc/test_mhc_kernels.py -k rank_agnostic
```

## Test Result

With the fix, all three ranks pass:

```
3 passed
```

Against the unpatched code:

```
FAILED test_hc_expand_contract_rank_agnostic[4-shape1]   # rank-3
FAILED test_hc_expand_contract_rank_agnostic[4-shape2]   # rank-4
2 failed, 1 passed
```

**The rank-2 case passes both before and after** — that is the evidence CUDA paths are unaffected by this change.
