# [ROCm][CI] Prebuild mamba-ssm and causal-conv1d into the CI test image

[Upstream PR](https://github.com/vllm-project/vllm/pull/64577) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Build mamba-ssm and causal-conv1d once into the ROCm CI test image instead of compiling them from source at the start of every AMD hybrid-model job. This is the AMD counterpart of #58795, which does the same for the CUDA image and does not touch AMD steps, so it is not a duplicate.

## Claims

- Removes a ~3.2 min source build from every run of the MI355 DPX Language Models (Hybrid) shards, Granite Language Model Compatibility and Language Models (Extended Generation), and ~5.5 min from the nightly MI300 Language Models (Extended Generation).
- At the last 14 days' run rate (~157 runs/day of each of the three per-commit MI355 jobs, main + PRs), that frees ~25 MI355 DPX agent-hours per day.
- MI355 DPX Hybrid Shard 2 (29-31 min) is the longest AMD job in recent main builds, so the AMD part of a build finishes up to ~3 min sooner when it is the last job (2 of the last 6 main builds).
- No change to what is tested: the same mamba commit the jobs already resolve (269cbe65, 2.2.6.post3) and causal-conv1d v1.6.0 (da6dbaa9).

## Details

- `HIP_ARCHITECTURES=gfx942,gfx950` is required: both setup.py files default to `native`, which needs a GPU at build time.
- Pins commits instead of branches. The legacy MI355 DPX Extended Generation step in `test-amd.yaml` pinned the `rocm-7.0-v2.3.0` branch; it now uses the same commit as the other steps.
- Drops the `GIT_CONFIG` HTTP/1.1 exports, which only served these git installs.
- Not built for gfx90a. MI250 jobs share the image, but none loads these packages: vLLM does not import them, and the MI250 PPL test uses a stored HF perplexity instead of running transformers.
- Changes the runtime key, so the first build after merge rebuilds runtime/test-deps once (38.5 min in build 98454). After that the wheels rebuild only when the key changes. The wheels add ~40 MB to the image.
- Not covered by the PR's CI: MI300 Language Models (Extended Generation), MI355 DPX Language Models (Extended Generation) and the MI250 jobs. Not run on MI355 locally (no hardware).
- Draft #64604 renames the AMD Hybrid label in `models_language.yaml` and may need a rebase after this.
- AI assistance was used for this PR.

#### 1. 🟠 Should fix: AMD test-deps image build fails on transient clone: this PR dropped the HTTP/1.1 git workaround and retries
`docker/Dockerfile.rocm:223`

The new `build_mamba` stage clones two GitHub repos via `pip wheel git+https://...` without the `http.version=HTTP/1.1` setting the removed MI355 steps exported, and without a retry. It is above the per-commit marker, so it runs only when the runtime key `Kr` changes; the content-keyed `test-deps` image is reused otherwise. A transient clone failure on such a rebuild fails the `refresh-rocm-base-amd` step, which does not auto-retry exit 1. The same image already depends on unprotected clones (`build_deepep`, `build_rdma_core`, NIXL/UCX, LMCache), and the HTTP/2 note was written for the NVIDIA H200 image. Optionally set `GIT_CONFIG_*` http.version in the RUN or fetch archives by SHA.

**Who is affected:** ROCm CI runs that miss the `Kr` runtime key and must rebuild `test-deps`, if GitHub rejects the HTTP/2 clone at that moment.

_Checked against the code by an independent pass._

#### 2. 🟠 Should fix: Broken mamba wheel fails only at test time: this PR adds no arch or import check on the built wheels
`docker/Dockerfile.rocm:376`

The prebuilt `mamba_ssm`/`causal_conv1d` wheels are installed with `--no-deps` and nothing verifies they import or contain `gfx942`/`gfx950` code objects, unlike the adjacent `build_lmcache` stage. Transformers' `hub_kernels.py` swallows import errors and falls back to torch, so a wheel that installs but cannot load leaves hybrid-model references on the slow path (possible timeouts) without a build failure; a future commit bump dropping `HIP_ARCHITECTURES` would silently fall back to `--offload-arch=native` and fail only at kernel launch. Add an `llvm-objdump --offloading` arch assertion like `build_lmcache`'s.

**Who is affected:** ROCm CI hybrid-model language tests that use the `test-deps` image, only if the prebuilt wheel is broken or lacks the runner's arch.

_Checked against the code by an independent pass._

**Related past reviews:** [#51208](https://github.com/vllm-project/vllm/pull/51208) on `docker/Dockerfile.rocm`

#### 3. 🟠 Should fix: MI250 PPL step fails for Qwen3.5-0.8B: this PR puts gfx942/gfx950-only mamba wheels in the shared test image
`docker/Dockerfile.rocm:376`

The `build_mamba` stage builds both wheels with `HIP_ARCHITECTURES="gfx942,gfx950"`. They are installed in `test-deps`, which is the single `test` image (`CI_ARCH="gfx90a;gfx942;gfx950"`) that MI250 steps also run. Before this PR, only the MI300/MI355 hybrid steps installed these packages, so MI250 always took transformers' torch fallback. Now `import causal_conv1d` succeeds on MI250 and `use_kernel_func_from_hub_with_fallback` binds `causal_conv1d_fn`/`causal_conv1d_update` by import alone. The HF reference run of `Qwen/Qwen3.5-0.8B` in the optional `:amd: (MI250) Language Models (PPL)` step should then fail with no gfx90a kernel; add gfx90a to `HIP_ARCHITECTURES` or keep MI250 off these packages.

**Who is affected:** The optional `:amd: (MI250) Language Models (PPL)` CI step on gfx90a agents, for the `Qwen/Qwen3.5-0.8B` case of `generation_ppl_test/test_qwen.py`.

_Checked against the code by an independent pass._
