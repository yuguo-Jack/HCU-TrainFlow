# [3/3][Mamba] Batched two-phase grouped prefill execution for hybrid GDN/Mamba (+7.58x)

[Upstream PR](https://github.com/vllm-project/vllm/pull/55876) · state: open · merged: False

## Original PR description

## Purpose

Implements RFC #55697.

Part 3 of 3 for Application-Directed Mamba Prefix Checkpointing (depends on PR #55873 and PR #55875).

In hybrid GDN/Mamba models (such as Qwen3.5 35B-A3B), prefill batches containing shared prefixes (1 common Producer prompt + N distinct Consumer queries) previously required either sequential per-request execution or full prompt recomputation due to state recurrence.

This PR introduces batched two-phase grouped prefill execution and in-kernel Copy-on-Write (CoW) state sharing in the Model Runner V2 (MRv2) worker and GDN layer:
- **Two-Phase Chunked Tensor Core Execution**: Splits the grouped prefill forward into batched Producer and Consumer phases (`run_phase`) backed by `chunk_gated_delta_rule` (Tensor Core chunked kernel) and zero-copy contiguous `producer_slice` / `consumer_slice` views (`core_attn_out` written in-place).
- **In-Kernel Read/Write Separated CoW (Zero Pre-Copy)**:
  - `causal_conv1d_fn` (`_causal_conv1d_fwd_kernel`): Supports `write_cache_indices` so Consumers read the historical conv window directly from the shared checkpoint block (`cache_indices = src`) and write updated windows directly to private destination blocks (`write_cache_indices = dst`) without pre-copying `conv_state`.
  - `chunk_gated_delta_rule` (`chunk_delta_h`) & `fused_sigmoid_gating_delta_rule_update`: Supports `gather_initial_states` from `src` and direct epilogue writes to `final_state_indices` (`dst`), eliminating per-layer `ssm_state` pre-copies and intermediate state allocations.
  - Same-step consumers invoke `prepare_same_step_mamba_consumer` in the scheduler to bypass redundant pre-forward CoW block copies.
- **Zero-Sync Attention Metadata Builder**: Constructs `prefix_producer_ranges`, `consumer_ranges`, `consumer_shared_state_sources`, and `private_final_state_destination` using cached host metadata and GPU `torch.where` without GPU-to-CPU stream synchronizations.
- **Microbenchmark, Unit Tests & End-to-End Serving Validation**:
  - Kernel microbenchmark demonstrates up to **7.58x speedup** on NVIDIA L40S.
  - End-to-end Qwen3.5 35B-A3B (FP8) serving throughput on NVIDIA L40S improves from **3.50 QPS** (baseline) / **5.90 QPS** (tuned baseline) -> **12.40 QPS** (MRv1) -> **13.80 QPS** (MRv2) -> **13.98 QPS** (contiguous slicing) -> **14.49 QPS** (in-kernel CoW + chunked Tensor Core).
