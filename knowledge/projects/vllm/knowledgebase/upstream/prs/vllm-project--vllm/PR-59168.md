# [Feature] Add an EvenMoE backend: Moe load balancer: pluggable expert placement and replica routing

[Upstream PR](https://github.com/vllm-project/vllm/pull/59168) · state: open · merged: False

## Original PR description

## Purpose

Add an optional expert-parallel load-balancing backend to EPLB: `--eplb-config '{"policy": "mlb", ...}'` delegates expert **placement** (the EPLB rearrangement) and, optionally, **per-token replica routing** to the [EvenMoE](https://github.com/ai-dynamo/evenmoe) (`evenmoe`, formerly the MoE Load Balancer, MLB), a framework-neutral library of load-balancing policies (DeepSeek EPLB hierarchical/global, LPLB, Waterfill for the shared expert, and UltraEP's online placement/quota refresh). vLLM keeps the mechanism, the library keeps the policies.

What the PR adds, all inactive unless `policy: "mlb"` is selected (the package is imported lazily; vLLM starts and runs unchanged without it):

- `vllm/distributed/eplb/policy/mlb.py`: the `mlb` EPLB policy (L1 placement) behind the existing `AbstractEplbPolicy` interface.
- `vllm/distributed/eplb/mlb_runtime.py`: the routing runtime (L2). A policy can answer per token with replica shares or with resolved physical ids; both go through the existing fused EPLB map-and-record Triton kernel in `router/base_router.py`, so load recording, the record gate and the padding mask are untouched. UltraEP's online refresh re-solves placement and per-replica quotas every N representative batches and moves the affected expert weights with a pairwise send/recv mover over the EPLB communicator (a symmetric-memory mover is available for single-host / multi-node-NVLink deployments).
- `--eplb-config` keys `l2_algorithm`, `init_placement_path`, `save_placement_path`: routing expression, and fit-once / serve-with-held-placement (the equivalent of SGLang's `--init-expert-location`).
- `VLLM_FUSE_SHARED_EXPERTS` / `shared_expert_fusion.py`: dispatch the shared expert through the EP all-to-all as one slot per rank instead of a replicated MLP, so a policy (Waterfill) can place it on the least-loaded rank. Off unless requested by the env var or by a policy that needs it.
- A DP-synced `uniform_decode_across_dp` flag on the forward context (one more row in the existing DP coordination all-reduce): a policy that issues a collective inside the forward must reach the same verdict on every rank, and the per-rank `uniform_decode` is exactly the wrong signal when a rank runs a dummy decode while its peers prefill. The dummy-run path replays the policy's per-step collective for the same reason (upstream already replays `eplb_step` there).
- `rank_imbalance` (per-layer peak-rank / mean-rank load) next to the existing `balancedness` in the EPLB log, since the latter reduces over layers rather than ranks.
- Two DeepEP knobs that came out of running EP16 across nodes: `VLLM_DEEPEP_RDMA_BUFFER_SIZE_MB` (size the RDMA buffer separately; DeepEP caps the NVL buffer when RDMA bytes are non-zero) and `VLLM_DEEPEP_HT_USE_MNNVL` (+ `VLLM_DEEPEP_V2_*_GBS`) for multi-node NVLink fabrics. Separable if preferred.
- Docs: an "EvenMoE (MoE Load Balancer) policy" section in `docs/serving/expert_parallel_deployment.md`.

Intrusiveness: the touched core paths (`fused_moe/layer.py`, `router/base_router.py`, `eplb_state.py`, `gpu_model_runner.py`, `dp_utils.py`, `forward_context.py`, `deepseek_v2.py` weight loading) are additive and guarded; with the default policy the fused router kernel compiles the same variant as before (the new constexpr flags are false), the DP all-reduce carries one extra int per rank, and the model runner's replay is skipped when no MLB routing is active.

Tuning knobs are read through `vllm.envs` (`VLLM_MLB_L1_ALGORITHM`, `VLLM_MLB_L2_ALGORITHM`, `MLB_ULTRAEP_*`); we intend to fold the `MLB_ULTRAEP_*` ones into `--eplb-config` fields in a follow-up and would welcome guidance on the preferred shape.

## Test Plan

- Unit tests (skip cleanly without `evenmoe`): `tests/distributed/test_eplb_mlb_policy.py`, `tests/distributed/test_eplb_mlb_routing.py`, `tests/distributed/test_eplb_replica_shares_kernel.py` (fused router kernel with replica shares / resolved ids, no MLB needed), `tests/kernels/moe/test_routing.py` (extended), plus the existing `test_eplb_algo.py`, `test_eplb_utils.py`; wired into the EPLB Algorithm CI step.
- `pre-commit run --files <changed files>`: ruff, ruff-format, typos, SPDX, torch.cuda-call check, markdownlint, test tethering, mypy pass.
- End-to-end, DeepSeek-V3 FP8, DeepEP high-throughput, DeepGEMM, eager, 1000 x 1024-token prompts per round at concurrency 256, `max_tokens=1`: (a) 8 x Hopper, TP1 x DP8, EP8, red16; (b) 2 x 8 Hopper, TP1 x DP16, EP16, red16/red32, placement recorded on one dataset and served on another (gsm8k -> mmlu -> gpqa -> gsm8k rotation).
- Greedy-decode consistency probe (48 prompts x 32 tokens, `temperature=0`) against plain vLLM, with a placement-only (held static placement) reference for the numeric floor.

## Test Result

**Static checks.** `pre-commit run --files <changed files>`: every hook passes (ruff, ruff-format, typos, SPDX, torch.cuda-call check, markdownlint, Buildkite test tethering, mypy 3.10).

**Unit tests** (8 x Hopper, `evenmoe` installed): `tests/distributed/test_eplb_mlb_policy.py test_eplb_mlb_routing.py test_eplb_replica_shares_kernel.py tests/kernels/moe/test_routing.py test_eplb_algo.py test_eplb_utils.py` -> 581 passed, 1 skipped.

**End-to-end** vLLM prefill throughput with **DeepSeek-V3 (FP8)** on **two nodes x 8 NVIDIA Hopper GPUs** (TP1 / DP16 / EP16, DeepEP high-throughput, DeepGEMM, eager). Every EPLB arm holds a placement that was recorded on a *different* dataset than the one it serves (cross-domain) and allocates **16 or 32 redundant expert replicas**; the baseline is plain vLLM with EPLB off. Values are median input throughput in **K tokens/s**; percentages show the change from the baseline on the same dataset; **imb** is the routed-load imbalance, max / mean per-rank routed load averaged over layers (1.000 is perfectly balanced; the shared expert is not counted). The L2 routing is selected with `l2_algorithm`; the UltraEP rows also set `VLLM_MLB_L1_ALGORITHM=ultraep` and `MLB_ULTRAEP_REFRESH_INTERVAL` (i).

## Notes

- `use_async` must be `false` with `policy: "mlb"`; the config validation says so.
- The `evenmoe` package is not added to vLLM's requirements; it is an optional dependency installed by the operator (documented). The library was open-sourced as EvenMoE while this PR was in draft; the vLLM-facing names (`policy: "mlb"`, `VLLM_MLB_*`, `MLB_ULTRAEP_*`) are unchanged.
