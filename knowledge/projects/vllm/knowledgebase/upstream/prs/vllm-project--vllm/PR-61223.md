# [DCP] Make multicast/unicast epoch ordering explicit

[Upstream PR](https://github.com/vllm-project/vllm/pull/61223) · state: open · merged: False

## Original PR description

Add `fence.proxy.alias` after multicast epoch publication in the shared DCP query/KV helper, following [CUDA's documented multicast/unicast pattern](https://docs.nvidia.com/cuda/archive/13.0.0/cuda-c-programming-guide/index.html#use-multicast-mappings). The change is one fence and its comment. No failure caused by the fence's absence has been established.

Validation:

- `prek run --files csrc/attention/dcp_utils/dcp_direct_common.cuh`: passed.
- Prior isolated CUDA 13.0.88 extension check on eight B300s: `pytest /tmp/test_dcp_direct_a2a_lse_reduce.py -v -s -k test_distributed_direct` passed all six selected cases. The baseline also passed. Kernel sources are unchanged after rebase; full-model validation remains outstanding.

No equivalent open PR found for this alias-ordering change (October 13).
