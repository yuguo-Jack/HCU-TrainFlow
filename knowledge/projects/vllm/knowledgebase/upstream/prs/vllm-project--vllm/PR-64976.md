# [Bugfix][Kernel] Honor batched and strided SwiGLU clamp inputs

[Upstream PR](https://github.com/vllm-project/vllm/pull/64976) · state: open · merged: False

## Original PR description



## Overview

Make `SwigluStepAndMul`'s Triton implementation honor the leading-dimension and stride contract already supported by its native path. This is an API/backend consistency fix; no current in-tree model caller was found that triggers the ND or column-strided case.

## Claims

- Flatten leading dimensions for the 2D Triton helper and restore the logical output shape.
- Address input and output using both row and column strides.
- Preserve activation arithmetic and public signatures; existing contiguous 2D behavior remains covered.

## Validation

Base `2eae56c4ba0c`; A100-SXM4-80GB, PyTorch 2.14/cu130. Test commands, source identities, environment details and raw assertion logs are in [validation.zip](https://github.com/user-attachments/files/34236953/validation.zip). Baseline comparisons apply the candidate tests to this pinned base.

```bash
.venv/bin/python -m pytest -v -s tests/kernels/core/test_activation.py -k swiglustep
```

October 30 GPU evidence, with identical final tests and unchanged executable kernel/wrapper logic: **base: 24 failed, 40 passed; candidate: 64 passed**. Failures cover the unsupported rank and stride cases; candidate output is checked against the native formula. The remaining 494 unrelated cases are deselected, not counted as passes. The active kernel CI selection includes the activation tests and now tracks `vllm/model_executor/layers/activation.py`; the existing Triton-directory dependency is unchanged.


Recorded pytest output from the same command with the candidate tests on both trees:

```text
Base:      24 failed, 40 passed, 494 deselected in 26.82s
Candidate: 64 passed, 494 deselected in 24.89s
```

Baseline ND cases report `ValueError: too many values to unpack (expected 2)`; strided cases report `AssertionError: Tensor-likes are not equal!`.

## Details

The helper previously unpacked a 2D shape and assumed contiguous columns. The wrapper now reshapes leading dimensions, while the helper uses the actual strides. A reshape may allocate for a non-contiguous higher-rank view. No throughput improvement or full-model accuracy result is claimed.

The rendered CustomOp snippet states the supported shapes and identifies Triton as the strided-input implementation; its named snippet now has a matching end marker and the changed section is rendered locally. Whole-page rendering also encounters a pre-existing missing `fused_moe` snippet in the base; full documentation-site CI remains unrun.

November 1 duplicate-work checks found no equivalent open PR. Related #61404 changes C++ elementwise launch configurations; #43589 changes MoE clamp-capability declarations. Neither handles the Triton SwiGLU-step rank/stride contract. Existing callers pass flattened contiguous inputs; the expected benefit is consistency for direct and out-of-tree callers.

AI assistance was used for implementation, tests and documentation. Hosted CI and full repository tests have not run.
