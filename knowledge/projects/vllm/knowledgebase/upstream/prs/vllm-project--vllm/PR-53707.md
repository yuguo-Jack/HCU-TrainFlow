# [Bugfix][Tokenizer] Avoid retaining pool overflow copies

[Upstream PR](https://github.com/vllm-project/vllm/pull/53707) · state: open · merged: False

## Original PR description

## Overview

Prevent tokenizer pool overflow copies from remaining resident after a concurrency burst. Also propagate `queue.Empty` raised by a tokenizer method without treating it as pool exhaustion.

## Claims

- Retain only the configured tokenizer copies after calls finish; overflow calls still acquire temporary copies without waiting for the pool.
- Return a configured copy even when the wrapped call raises an exception.

## Details

The unbounded queue previously retained every temporary copy created when exhausted, so a single burst could permanently grow the idle pool to its historical peak. The change returns only originally pooled copies and narrows the `queue.Empty` handler to acquisition.

Tradeoff: repeated bursts or sustained concurrency above the configured capacity can repeatedly pay the deep-copy cost instead of reusing the expanded pool. This bounds retained copies, not peak memory or copy latency; no serving latency improvement is claimed. [Independent GLM-5.2 reproduction](https://github.com/vllm-project/vllm/pull/53707#issuecomment-6485672037) reports retained overflow copies and a roughly 249 ms / 69 MiB cost per copy on that setup; it is not a patched-versus-base serving benchmark.

Duplicate-work review from the original submission: no open PR or issue was found for overflow-copy retention. #47509 adds another consumer, #47583 optimizes encoding above the pool, and #41721 touches another part of `tokenizers/hf.py`; none implements this fix.

We ran into the behaviour this PR fixes and measured it on vLLM 0.23 with GLM-5.2, using a standalone replica of `_borrow_from_pool` as it is today (a `queue.Queue` of deep copies, one more deep copy whenever the queue is empty, every copy put back):

- With HF `tokenizers` 0.23.3 (2 runs, 480 requests each): a burst of 8 concurrent calls into the pool grew it from 2 copies to 5, and it stayed at 5 for the rest of the run. Process RSS rose by about 185 MiB at the burst and was still about 90 MiB above the pre-burst level at the end of the run.
- Each overflow copy is a full `copy.deepcopy` of the tokenizer: about 249 ms and about 69 MiB per copy with the same tokenizer, paid on the request path by the request that found the queue empty.
