# [KV Connector][Mooncake] Share one transfer planner between the protocol directions

[Upstream PR](https://github.com/vllm-project/vllm/pull/64871) · state: open · merged: False

## Original PR description

## Overview

Moves the Mooncake push worker's block descriptor arithmetic into a module-level planner, so a read-mode connector can build descriptors with the two sides exchanged. The push path keeps producing the same descriptors.

First half of #61974, which carries the read direction and stays in draft until this lands. Needed by #60523.

## Claims

- `plan_block_descriptors` owns what `_build_transfer_params` used to inline: the KV group count check, Mamba placeholder trimming, logical-to-kernel block expansion, the per-group contiguous run cache, the callback that returns the byte offsets of one region pair, and the coalescing of adjacent runs into a single descriptor.
- `BlockTransferRequest` carries one request's block ids on the prefill side and on the decode side, so the same planner serves push (local blocks read, remote blocks written) and a future read direction (remote blocks read, local blocks written).
- `_build_transfer_params` now builds one request per ready transfer, passes both sides' regions plus a callback into `_get_sender_transfer_plan`, and returns the planner's tuple. It no longer awaits anything, so its call site and the push tests drop the `await`.
- `_logical_to_kernel_block_ids` is gone. `_kernel_block_ids` takes the group specs as an argument instead of reading them off the worker, and keeps the rule that Mamba groups expand one block per logical block while attention groups expand per kernel block.

Across the three files the run reports `121 passed, 59 failed`: the 120 tests that existed before plus the new regression test. The same 59 tests fail on a checkout of `main` without this commit, and the FAILED lists are identical, so none of them is a regression from this change. A host detail explains them: that machine has a CUDA 12.2 driver with a torch built for CUDA 13, so every test that builds a `VllmConfig` stops at `RuntimeError: The NVIDIA driver on your system is too old (found version 12020)`, and the offline HF cache there also lacks the `facebook/opt-125m` weights. No GPU-executed coverage of the descriptor bytes was possible on that host, so CI is the first full run.

## Details

`_build_transfer_params` had grown to do five jobs in one body: check the group counts, drop Mamba placeholders, expand logical block ids to kernel block ids, cache contiguous runs per group, then call `_get_sender_transfer_plan` for every region pair and coalesce neighbours. The read direction needs the same five steps with the sides exchanged, so the body leaves the worker.

The offset callback stays in the worker because the choice between a dense and a packed transfer reads the registered regions and the peer's TP ratio.

Two invariants moved with the code rather than changed: a request with no decode-side blocks is skipped because such a transfer only releases the source's blocks, while a prefill side that holds fewer blocks than the decode side still fails with `P num blocks less than D` and lands in `err_reqs`. `test_plan_block_descriptors_reports_empty_source` covers that second case, and the planner asserts that the decode side's group count matches the local one before trimming.

**Split boundary.** The read direction, the connector base class, the lease handling, the pull protocol and the pull tests stay in #61974. This PR is the planner alone, so the push path can be reviewed as a refactor with an unchanged output.

**Interface overlap with #64812.** That PR replaces the single-segment TP address plan with a multi-segment one and will overlap `_align_transfer_regions`. It is still a draft. If it lands first, this planner gets rebased onto the new interface rather than merged alongside it.

**Why this is not a duplicate.** No open PR touches the Mooncake descriptor path. #64812 changes TP slicing, not descriptor planning, and is unmerged. #61974 is the parent PR for the read direction and will carry it once this lands.
