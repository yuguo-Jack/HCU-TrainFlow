# [Frontend] Support output logprobs for gpt-oss in the Responses API

[Upstream PR](https://github.com/vllm-project/vllm/pull/64027) · state: open · merged: False

## Original PR description

## Purpose
Fixes #61629. Follow-up to #23319, where "logprobs + harmony" was left as a TODO.

`/v1/responses` returned 400 for gpt-oss when `include=["message.output_text.logprobs"]` was set. This adds logprobs for output text in both streaming and non-streaming, kept in parity.

## Design
- `HarmonyParser.process_chunk` already emits one `Segment` per token; `Segment` now carries `token_index`.
- `HarmonyContext` picks logprobs for output-text tokens (final channel + commentary preambles with no recipient, excluding Harmony control tokens), aligned per segment for streaming and grouped per message for the final output.
- Streaming deltas, `output_item.done`, and the final response all convert from those same entries via one helper, so they report identical logprobs.
- Tokens with an empty delta (partial multi-byte characters) are buffered and attached to the next text delta.

## Test Plan
- New unit tests (`test_harmony_logprobs.py`): real gpt-oss tokens fed in one chunk vs 1/2/3/7-token chunks, asserting identical per-message logprobs; control tokens and reasoning excluded.
- New e2e tests in `test_harmony.py`: non-streaming logprobs cover exactly `output_text`; streaming delta logprobs == done-event logprobs == final response logprobs.

## Test Result
Unit tests pass locally. E2E tests need a GPU and have not been run locally.
