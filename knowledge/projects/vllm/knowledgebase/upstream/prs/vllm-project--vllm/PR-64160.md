# [Perf][DSv4.1] Run the Engram WKV ahead on its own Lamport all-gather

[Upstream PR](https://github.com/vllm-project/vllm/pull/64160) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Stacked on #63921, which adds `LamportAllGather`; review only the commits after it. In the `latency_specialized` decode, the Engram WKV chain now also runs ahead for GPU-resident tables, and its two all-gathers move from NCCL to a `LamportAllGather` of their own.

## Claims

- The median decode step drops from 3998 µs to 3886 µs, a 112 µs (2.8%) gain over #63921 (DeepSeek-V4.1-Flash, TP4, one request, unprofiled). Most of the gain comes from the run-ahead; the Lamport gathers add about 17 µs.
- The output is bitwise unchanged.

## Validation

Unprofiled step time, FlashInfer autotune off (it causes most of the variance between restarts). Each A/B ran on one node, 4 interleaved restarts × 3 samples per arm. Setup: TP4 on GB200, a 128k context, DSpark with 5 tokens, GPU-resident tables.

| Engram path | Median step (µs) | Min (µs) |
| --- | --- | --- |
| Inline (#63921) | 3998 | 3951 |
| Run ahead, Lamport gathers (this PR) | 3886 | 3793 |
| Run ahead, NCCL gathers (second node) | 3886 | 3873 |
| Run ahead, Lamport gathers (second node) | 3869 | 3773 |

Engram cost in the target decode graph = graph time minus the time with the Engram layers skipped, on the same node. Medians over 107 steps on each of 4 ranks, from `nsys --cuda-graph-trace=graph`.

| Engram path | Engram cost (µs) |
| --- | --- |
| Inline (#63921) | 119 |
| Run ahead, NCCL gathers | 84-92 |
| Run ahead, Lamport gathers (this PR) | 17 |

Limitations:

- Measured on GB200 (SM100) with the backend's SM103 gate relaxed locally, and with #61869 also merged (it changes only the draft side). The new code has nothing architecture-specific.
- Each graph-trace number above is one restart. There is no end-to-end serving benchmark.

Tests: the new TP4 check in `test_numerics.py` compares the Lamport path bitwise against the stock NCCL `Engram.forward`. `test_kernels.py` now also covers GPU-resident tables. No accuracy eval was run, because the output is bitwise unchanged.

```bash
pytest -q "tests/models/deepseek_v41/nvidia/specialized_decode/test_kernels.py::test_engram_wkv_prefetch_matches_inline" "tests/models/deepseek_v41/nvidia/specialized_decode/test_numerics.py::test_specialized_decode_numerics"
```

Result on one GB200 node (4 GPUs): `4 passed in 89.30s`.

## Details

- The chain on layer 1 competed with layer 0 for two NCCL gathers per layer. The Lamport gathers take a few µs each.
- The chain runs on a side stream concurrently with the executor's gathers, so it has its own mailbox.
- No open PR changes this path. #63326 and #63367 change Engram on ROCm only.
