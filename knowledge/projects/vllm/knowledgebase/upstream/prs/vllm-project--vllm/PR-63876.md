# [Bugfix][Bench] Warm DeepSeek V4.1 sparse indexer before graph capture

[Upstream PR](https://github.com/vllm-project/vllm/pull/63876) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Make `vllm bench forward` warm up the CUDA graph execution path, including DeepSeek V4.1's short-context sparse indexer and its SWA replay sub-batch.

## Claims

- Short-context DeepSeek V4.1 sparse-indexer benchmarks no longer initialize DeepGEMM's per-stream scheduling workspace inside CUDA graph capture.
- Ordinary eager execution retains the short-context indexer shortcut. Inline SWA replay inherits FULL graph mode; separately captured replay graphs retain their own mode.

## Validation

GB200 validation of the retained tests: Native CLI regression passed; the 3 selected replay cases also passed. All targeted pre-commit checks pass.

Base: `b82393b77315692f390880d2e931fdc1fbd13928`; NVIDIA GB200, shared Torch 2.14 CUDA environment.

The native CLI with the full DeepSeek V4.1 Flash model, dummy weights, DEP2, MegaMoE, sparse MXFP4 indexer, and `--case short=512` failed before the patch:

```
get_sparse_mqa_logits_metadata
RuntimeError: Assertion error (csrc/apis/attention.hpp:332): not torch_compat::is_capturing(stream.second)
```

The reduced four-layer model reproduces the same assertion before the patch; after the patch its native CLI completes short=512 with finite outputs and graph/eager relative RMS 0. No model-quality claim is made from dummy weights.

On GB200, the new CLI regression fails on base with the assertion above and passes with the patch.

```bash
.venv/bin/python -m pytest tests/benchmarks/test_forward_cli.py -k deepseek_sparse_indexer -x -v
.venv/bin/python -m pytest tests/models/test_deepseek_v41_pcp.py tests/models/test_deepseek_v41_replay_batch.py tests/models/test_deepseek_v41_decoder_replay_layers.py -x -v
.venv/bin/python -m pytest tests/benchmarks/test_forward_cli.py -k bench_forward_drafter -x -v
pre-commit run
```

The native CLI regression passes. Additional validation exercised replay/PCP tests and all four drafter CLI methods. The drafter tests cover MTP, EAGLE3, DSpark and DFlash, with/without drafting on prefill, verify and mixed batches. Pre-commit passes.

Full-model dummy-weight DEP2 validation (MegaMoE and sparse MXFP4 indexer):

| Exact batch | Base | Patched |
| --- | --- | --- |
| Short prefill `512` | Capture assertion | Finite, graph/eager RMS 0 |
| Prefill `1024` | Finite, graph/eager RMS ≈0.011 | Same numerical behavior |
| Mixed `256,1@1024` | Finite, graph/eager RMS 0 | Same |
| Verify `2*6@1024:5` | Finite, RMS 0.003082/0.003245 by rank | Identical RMS values |

Full-model prefill already has nondeterministic repeated forwards on base, and verify already has the above eager/graph difference. These observations remain unresolved. Short-case timing was unstable; this PR makes no speedup or accuracy claim.

## Details

The benchmark manually captures FULL graphs while its runner builds an eager forward context. DSV4.1 skips query projection/indexer scoring on short eager batches but executes them during capture. This prevents the capture-stream warmup from preparing DeepGEMM's sparse MQA workspace. SWA bounded replay installs a separate forward context, so it must preserve FULL mode when its layers are captured inline too.

The benchmark now uses the existing ForwardContext execution-mode contract for warmup and capture; the DSV4.1 indexer respects it, as the DSV3.2 indexer already does. No synchronization or configuration option is added.

Duplicate check: open PR #60543 autotunes the indexer's wq_b GEMM, #63819 warms MRV2 speculative-decoding kernels, #58559 warms sparse top-k variants, and #59986 changes serving graph eligibility for sparse prefill. None prepares this native exact-batch benchmark's sparse MQA scheduling path. Open PR searches covered `indexer warmup`, `sparse schedule capture`, and `"bench forward" "warmup"`.
