# [Perf][ToolParser] Scan Kimi K3 streaming tool calls incrementally

[Upstream PR](https://github.com/vllm-project/vllm/pull/62203) · state: open · merged: False

## Original PR description



## Overview

Kimi K3 streaming tool extraction rescanned the accumulated tools section and
redecoded completed calls on every delta. This change resumes parsing from the
last unfinished call boundary and decodes each completed call once.

## Claims

- Reduce CPU parsing time for native Kimi K3 tool streams, including `auto` and
  `required` tool choices.
- Preserve response content, tool-call timing, names, argument bytes, indices,
  types, and ID presence.
- Keep the optimization inside `KimiK3ToolParser` and reuse its existing call
  matching and decoding logic.
- This is separate from [#60882](https://github.com/vllm-project/vllm/pull/60882),
  which optimizes the generic JSON scanner for `tool_choice="required"`.
- [#50627](https://github.com/vllm-project/vllm/pull/50627) streams Kimi K3
  arguments before a call closes; this change preserves the existing
  announcement timing and removes repeated parsing after calls close.

## Validation

Five-run CPU parser medians after warmup, using four-character deltas and
alternating before/after order. Timings include text-history accumulation and
parsing, excluding parser construction.

| Workload | Before | After | Speedup |
| --- | ---: | ---: | ---: |
| 256-character string argument | 0.523 ms | 0.332 ms | 1.57x |
| 4,096-character string argument | 5.463 ms | 2.602 ms | 2.10x |
| 16,384-character string argument | 36.611 ms | 10.000 ms | 3.66x |
| 65,536-character string argument | 401.085 ms | 43.256 ms | 9.27x |
| Truncated 65,536-character argument | 398.718 ms | 42.784 ms | 9.32x |

Response-only parsing remains at baseline speed. These are CPU parser results and
do not establish GPU inference or end-to-end serving throughput.

- Differential replay: 16,540 streams and 189,754 deltas, with no differences.
- Composed `KimiK3Parser` replay matched across `auto`, `required`, and `none`,
  with and without reasoning.
- Relevant tests: 178 passed.
- Ruff, formatting, mypy, and `git diff --check` passed.

## Details

The existing call regex and decoder remain responsible for recognizing and
decoding calls. A call-close regex finds newly completed call blocks; the parser
then scans only the unparsed interval. Partial matching preserves close markers
split across deltas, including whitespace variants. Matched invalid call blocks
still advance the parsed span, so they do not affect later call indices.

The change adds two parser offsets and does not introduce a scanner class or a
second accumulated text buffer. Response extraction and tools-channel discovery
remain unchanged. The optimization reduces repeated tool-call work while the
existing caller-side history concatenation and full response/channel searches
remain. The existing K3 decoder remains responsible for decoding calls after a complete call boundary is found.
