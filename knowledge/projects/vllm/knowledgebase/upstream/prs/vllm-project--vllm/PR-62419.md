# [XPU] Enable kernel/sampler unit tests on Intel XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/62419) · state: closed · merged: True

## Original PR description

## Purpose

Many kernel / sampler / speculator unit tests exercise Triton kernels that are reachable on Intel XPU, but are gated to CUDA only: `torch.cuda.is_available()` module skips, `is_cuda()` / `is_cuda_alike()` skipifs, or hardcoded `"cuda"` devices. On XPU they are skipped or fail with `Torch not compiled with CUDA`, so those kernels have no XPU unit-test coverage even though they run.

This PR enables 27 such test files on XPU. Changes are mechanical and CUDA behaviour is unchanged.

## Changes

27 files under `tests/` (no source changes):

- Gates accept `current_platform.is_cuda_alike() or current_platform.is_xpu()` (inline, the same form already used elsewhere in `tests/`).
- Devices come from `current_platform.device_type` instead of a hardcoded `"cuda"`; `.cuda()` becomes `.to(DEVICE)`.
- Cases that need CUDA-only machinery (CUDAGraph, SM100, CUDA-only extension ops) stay CUDA-only.

Test files that still fail on XPU for unrelated reasons (`test_mrope`, `test_gemma4router`, `test_qkvr_prep`, `test_dflash2`, `test_precopy_mamba_align`, `test_compressor_kv_cache`, ...) are deliberately not part of this PR.

## Method

Each file was run as its own job, one card per job, and the PR versions were compared against the same files at the base commit (`8fa5ae844a`).

- **XPU:** one Arc Pro B60 per file, `vllm/vllm-openai-xpu:nightly` with the python tree from `origin/main` (`8fa5ae844a`).
- **CUDA (regression check):** one NVIDIA L40S per file (8 cards in parallel), vLLM CI CUDA image (`0.31.1rc1.dev253`) with the python tree from the base commit overlaid; PR test files vs. base test files.

After these runs the branch was rebased onto `852989f580`; the only conflict was an import in `test_rejection_sampler_utils.py`, and the new `fly` / multiround / adaptive tests that landed on main there now use `DEVICE` too. The rebased branch was not re-run on hardware.
