# [KV Connector][NIXL] Batch host-buffer KV block copies on CUDA

[Upstream PR](https://github.com/vllm-project/vllm/pull/61056) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

With `kv_buffer_device="cpu"` on CUDA, NIXL P/D stages KV through a host buffer, and both host-buffer copies go through `copy_kv_blocks`. The existing per-layer copy indexes the host tensor on the CPU, which is slow in a serving process and accounts for most of the extra latency P/D adds in the setup below. When the host buffer is already page-locked, this PR copies all (layer, block) pairs with one `ops.swap_blocks_batch` call, the primitive the CPU offloading connector already uses. Host buffer allocation and NIXL registration are unchanged from main. Follows #54483; related to #60181.

## Claims

- P/D `max_tokens=1` request latency (1P1D, Qwen3-0.6B, single request, setup below): about 2.0–2.7x lower for 512–4096-token prompts, e.g. 2048 tokens 398.6 → 159.6 ms median.
- Host buffer allocation, NIXL registration and the amount of locked host memory are unchanged; buffers that are not page-locked, and inputs the fast path does not handle, use the existing per-layer copy.
- No correctness regression observed in the tests and P/D runs below.

## Validation

**Tests**
- New `tests/v1/kv_connector/unit/test_copy_kv_blocks.py` (17 cases, CUDA only; picked up by the existing `v1/kv_connector/unit` GPU job). Both directions on the default stream and on a side stream; pinned (batched) vs pageable (fallback); pageable buffers page-locked after allocation with `cudaHostRegister`, as NIXL registration does, in both directions; tensors on a GPU other than the current one (needs 2 GPUs, skipped otherwise); fallbacks for non-contiguous tensors, mixed block sizes, overlapping destinations and out-of-range block ids. Results are compared with `torch.equal`, and the stream is stalled before the copy so a copy that is not ordered or returns early is caught.
- Each of these changes to the fast path makes at least one case fail: destination pointers built from source ids (8 fail), no stream sync (5), no device guard (2), no overlap check (1). The `swap_blocks_batch` spy wraps the real op; it does not replace the copy.
- `pytest tests/v1/kv_connector/unit/test_nixl_connector.py`: 178 passed.
- `VLLM_GPU_SYNC_CHECK=error`: a P/D serving run completed without errors on an earlier revision (the copy is wrapped in `gpu_sync_allowed()` at both NIXL call sites, as before); a control calling the fast path inside a `with_gpu_sync_check` region raises without `gpu_sync_allowed()` and passes with it.

**End-to-end** (main `187a0eb`, 4x RTX 4090 without P2P, NIXL 1.5.0 with the UCX backend, default UCX settings, 1P1D on two GPUs, Qwen3-0.6B, `--gpu-memory-utilization 0.4 --max-model-len 8192`, `kv_buffer_device="cpu"` on both sides, no other connector options). `max_tokens=1` request latency through the toy proxy, single request, random token prompts, 5 runs per length after warmup, back to back on the same GPUs with only this change toggled:

| prompt tokens | P/D on main, median (min–max) | P/D with this PR, median (min–max) | prefill node only, median |
|---|---|---|---|
| 512 | 173.8 ms (170.1–182.1) | 84.6 ms (82.4–85.2) | 31.8 ms |
| 1024 | 237.2 ms (231.6–265.7) | 118.9 ms (117.7–123.7) | 45.7 ms |
| 2048 | 398.6 ms (389.5–422.7) | 159.6 ms (151.3–162.8) | 53.5 ms |
| 4096 | 745.9 ms (704.4–775.6) | 279.7 ms (206.2–285.9) | 83.4 ms |
| 7000 | 1171.6 ms (1033.1–1268.1) | 344.9 ms (343.7–355.5) | 146.9 ms |

The 7000-token baseline varies between runs (903.9 ms median in an earlier run of the same setup), so I am not quoting a ratio for it. On an earlier base (`f0c44cc7d5`), timing `save_kv_to_host` / `sync_recved_kv_to_device` directly with a stream sync on both sides gave e.g. 128 blocks (224 MiB) D2H 123.5 → 14.5 ms and 438 blocks (766 MiB) H2D 333.7 → 58.4 ms.

**Correctness**: greedy outputs through P/D match prefill-node-only generation token for token in eager mode (4/4 prompts, up to 2694 prompt tokens). With CUDA graphs, 2/4 prompts diverge at near-ties (top-1/top-2 logprob gap 0.0625 and 0.0); the divergence positions and gaps are the same with and without this change.

**Page-locking in this setup**: the host buffer is pageable right after allocation and reports `is_pinned() == True` right after NIXL `register_memory` (checked on the first layer's buffer, on both P and D, on main without this PR as well), and every host-buffer copy in an instrumented serving run took the batched path. A standalone script registering a tensor with a fresh UCX agent did not reproduce the transition, and I have not isolated why, so the PR checks `is_pinned()` at run time rather than assuming registration page-locks the buffer.

## Details

**Flow touched** (P/D with `kv_buffer_device="cpu"`):
1. P runs a prefill step; `NixlConnector.wait_for_save()` → `save_kv_to_host()` → `copy_kv_blocks(device → host, "d2h")`. **Changed.**
2. D admits the request and NIXL READs the blocks from P's host buffer into D's host buffer.
3. When the read completes, D's `get_transfer_results()` → `sync_recved_kv_to_device()` → `copy_kv_blocks(host → device, "h2d")`; the request then decodes. **Changed.**

**Root cause.** `CudaPlatform.swap_out_blocks_to_host` / `insert_blocks_to_device` do `dst[idx] = src[idx].cpu()` / `.to(device)` per layer, so the host side is an advanced-indexing gather/scatter on the CPU, and serving sets Torch to one thread by default (`set_torch_threads_for_runtime`). In a single-thread microbenchmark of 128 blocks (224 MiB, 28 layers, legacy default stream), the per-layer D2H took 87.4 ms, 71.2 ms of it in the CPU scatter, while `swap_blocks_batch` into a pinned buffer took 14.6 ms. A page-locked buffer is not enough on its own; the copy has to skip CPU-side indexing.

**Change.** `copy_kv_blocks` first tries `_try_copy_kv_blocks_batched`. It applies on CUDA when every layer pairs a page-locked host tensor with a tensor on one GPU, both contiguous with the same `shape[1:]` and dtype, with the same bytes per block across layers. It builds one pointer per (layer, dim-0 block), the slice the per-layer path indexes, and calls `swap_blocks_batch` once under the GPU's device guard, so the copies go on the stream the per-layer path's ops would use. Because copies in a batch are unordered, block ids outside `[0, num_blocks)` and destination tensors that overlap (e.g. layers sharing a KV cache, which share one device tensor but have separate host buffers) are left to the per-layer path. It then synchronizes the stream, so on return the host buffer is ready to hand to NIXL (d2h) or reuse (h2d), as with the per-layer path. Everything else, including TPU/XPU, falls back unchanged. Both callers pass the same unique block ids for source and destination, so duplicate destination ids do not arise; as with tensor indexing, they are not supported.

**Trade-offs and limitations.**
- The fast path depends on the host buffer being page-locked at copy time. It was in the tested NIXL 1.5.0/UCX setup; I have not tested other backends or UCX settings, and where the buffer stays pageable the existing copy is used.
- The copies stay synchronous; making them asynchronous (events instead of a stream sync) is left for a follow-up.
- Validated on one model with a single KV cache group. #60181 changes which layers `sync_recved_kv_to_device` copies for multi-group models; it touches the callers, not `copy_kv_blocks`, but I have not tested the two together.
- Measured single node, single request; not measured under concurrency or for small copies of a few blocks.

**History.** An earlier revision also allocated the host buffer with `pin_memory=True`. Following review, I found that in this setup NIXL registration already page-locks it, and removed that change; allocation is now the same as on main. After a further review pass I added the fallbacks for out-of-range ids and overlapping destinations and the device guard above.

**Not a duplicate.** Searched issues/PRs for `save_kv_to_host`, `sync_recved_kv_to_device`, `copy_kv_blocks`, `swap_out_blocks_to_host`, `insert_blocks_to_device`, `use_host_buffer` and pinned host buffers. The closest is #54483, which coalesces calls across cache groups but keeps the per-layer copy. #53263 stages the NIXL READ itself (step 2) through device memory when the destination is host memory; it does not touch the host↔device copies in steps 1 and 3, so the two are complementary.

Independent measurement of this PR on stock RTX 4090s without P2P, in case it helps the review.

**Setup.** One node, prefill on one RTX 4090 and decode on another on the same socket (no GPU peer-to-peer on the stock driver, no RDMA NIC), driver 550.144.03 (CUDA 12.4), vLLM v0.30.0, NIXL 1.4.1 (bundled UCX 1.22.0), Qwen2.5-7B-Instruct bf16 (57,344 bytes of KV per token), `NixlConnector` with `kv_buffer_device: "cpu"`, the toy P/D proxy. This PR's `utils.py` diff at `f5533dc3` was applied to v0.30.0's file (it applies with offsets of -9 lines) and compared with the same build without it; argv and environment were otherwise identical.

**Engagement on NIXL 1.4.1.** With allocation unchanged, the host buffer reports `is_pinned()` after NIXL 1.4.1 registers it, so the batched path ran: an instrumented copy of the patched file logged 22 of 22 host-buffer copies taking the batched path (prefill device-to-host and decode host-to-device, at 2,048 / 8,192 / 28,672 prompt tokens). No extra page-locking was added.

**Result.** Handoff cost = TTFT of the P/D request minus TTFT of the same prompt on a single non-disaggregated instance; bandwidth from the difference between the 8,192- and 28,672-token levels (1.174 GB). Median of 20 requests per level, five rounds; ranges are over the rounds.

| | handoff cost at 28,672 tokens | handoff bandwidth (8,192 → 28,672) |
|---|---|---|
| host buffer, v0.30.0 | 2.02–2.11 s | 0.78–0.81 GB/s |
| host buffer, with this PR | 0.49–0.52 s | 5.0–5.7 GB/s |
| ratio | | 6.2–7.2x in every round |

For scale, a plain pinned device-to-host-then-host-to-device copy between the same two cards measured 12.9 GB/s, and the NIXL host-to-host leg took 0.05–0.11 s per request in both builds, so almost all of the old cost was the per-layer copy this PR replaces. Outputs matched the non-disaggregated reference at the same rate as without the PR, and every request moved exactly N × 57,344 bytes.

The remaining copies are synchronous (as the PR says); about 0.26 s of the 0.50 s at 28,672 tokens is left for the two copies and fixed costs, so an asynchronous follow-up still has room.

I checked the numbers against the raw records.

Thanks for raising this. I agree that pinning a host buffer the size of the KV pool shouldn't happen silently.

I removed the explicit pin_memory=True allocation, so host buffer allocation and NIXL registration are now the same as on main. The batched copy only runs when the host tensors already report is_pinned(), and otherwise the existing per-layer copy is used, so this PR no longer adds locked memory or needs a flag.

In my setup (NIXL 1.5.0, UCX backend, default settings), the host buffer is pageable right after allocation and reports is_pinned() == True right after NIXL registers it, on both P and D, on main without this PR as well.
