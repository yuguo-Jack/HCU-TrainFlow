# [Bugfix] Return HTTP 400 when local media is disabled without --allowed-local-media-path

[Upstream PR](https://github.com/vllm-project/vllm/pull/61907) · state: open · merged: False

## Original PR description

## Overview

Fixes #61874. Return HTTP 400 (`BadRequestError`) instead of HTTP 500 when local media is requested without `--allowed-local-media-path`.

## Claims

- Changes the disabled local media exception in `MediaConnector._load_file_url` from `RuntimeError` to `ValueError`.
- `create_error_response` correctly maps `ValueError` to HTTP 400 `BadRequestError`, preserving the security denial message while correctly categorizing it as a client error rather than an internal server error.
- Updates existing unit tests in `test_connector.py` and adds sync/async regression tests in `test_unprocessable_entity_error.py`.

## Validation

- Verified locally that requesting `file:///...` without `--allowed-local-media-path` raises `ValueError` and produces:
  `code: 400`, `type: BadRequestError`, `message: "Cannot load local files without \`--allowed-local-media-path\`."`.
- Formatted and validated with `ruff format --check` and `ruff check`.

## Details

When `--allowed-local-media-path` is omitted, `MediaConnector.allowed_local_media_path` is `None`. Previously, `_load_file_url` raised a bare `RuntimeError`. When handled by `create_error_response`, unmapped `RuntimeError` instances default to `InternalServerError` (HTTP 500).

In contrast, other client-side URL validation rejections in `MediaConnector` (such as accessing files outside the allowed subpath, disallowed media domains, or unsupported schemes) raise `ValueError`, which maps to HTTP 400. Aligning the disabled local media check with `ValueError` ensures correct HTTP 400 status reporting across both sync and async request pipelines.
