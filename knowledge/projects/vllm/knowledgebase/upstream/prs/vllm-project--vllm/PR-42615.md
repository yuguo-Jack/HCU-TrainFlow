# [Bugfix] Dedup gpu_block_ids in SimpleCPUOffload eager store path

[Upstream PR](https://github.com/vllm-project/vllm/pull/42615) · state: closed · merged: False

## Original PR description

## Fix: Deduplicate blocks in `BlockPool.free_blocks()` to prevent double-free

Fixes #42571

### Problem

When eager `SimpleCPUOffloading` is combined with sliding-window attention, the same physical `KVCacheBlock` can be reused within a single request as the attention window slides. Each time the block re-enters the window, its block ID gets appended to the CPU offload list (`StoreRequestState.block_ids`). When the request is freed, `SingleTypeKVCacheManager.free()` passes `reversed(req_to_blocks)` to `BlockPool.free_blocks()`, which may contain the same block object at multiple positions.

The old `free_blocks()` implementation called `list(ordered_blocks)` and iterated over every element, decrementing `ref_cnt` for each occurrence. For a batched call like `free_blocks([block, block])`:
- `ref_cnt` is decremented twice (underflow to -1 or 0 prematurely)
- The block is appended to `free_block_queue` multiple times
- `num_free_blocks` over-counts, and the free list eventually hands out the sentinel node
- This triggers: `AssertionError: prev_free_block of fake_free_list_tail should always exist`

### Root Cause

`SingleTypeKVCacheManager.free()` (line 316) passes `reversed(req_to_blocks)` directly to `free_blocks()`. The `req_to_blocks` list legitimately contains the same physical block at multiple indices when sliding-window attention reuses a freed block for new KV cache within the same request. This is by design in the sliding-window path — the duplication is a structural property of how blocks are tracked, not a logic error in the list construction.

### Fix

Replace `list(ordered_blocks)` with an identity-based deduplication pass using `id(block)`:

- Each block has `ref_cnt` decremented **at most once** per `free_blocks()` call
- First-seen ordering is preserved (important for eviction priority)
- A `logger.warning` fires when duplicates are detected, keeping the underlying caller-side behavior discoverable for future debugging
- Null blocks (`is_null=True`) are still excluded from the free queue as before
