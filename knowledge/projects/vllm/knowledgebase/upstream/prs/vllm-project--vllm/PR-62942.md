# [Misc] Remove dead chunk_size_in_s variable from speech-to-text serving

[Upstream PR](https://github.com/vllm-project/vllm/pull/62942) · state: open · merged: False

## Original PR description

## Overview

Removes the dead `chunk_size_in_s` variable from `SpeechToTextServing._create_speech_to_text` in `vllm/entrypoints/speech_to_text/base/serving.py`. This is one of the leftover cleanups from #32588 (follow-up to #41131).

## Claims

- `chunk_size_in_s` was assigned from `self.asr_config.max_audio_clip_s` but never read anywhere — it is removed.
- No behavior change: the `assert` that sat under the variable checks a real invariant (chunking disabled → exactly one result generator), so it is kept, reading the config directly instead of through the dead variable.
- Scope is deliberately limited to the dead code. The two docstring leftovers from #32588 are already covered by #49414, so they are not duplicated here.

## Validation

- `grep` over the codebase confirms no remaining references to `chunk_size_in_s`; the variable had exactly one assignment and zero reads.
- The edited file compiles (`py_compile`) and the diff is a single condition line: `if chunk_size_in_s is None:` → `if self.asr_config.max_audio_clip_s is None:`, with the dead assignment deleted.
- No new tests: this is a dead-code removal with no behavior change, so there is no observable behavior to assert. Relying on CI for the existing speech-to-text test coverage.

## Details

#41131 switched speech-to-text chunk timestamps to a cumulative approach, after which `chunk_size_in_s` stopped being used but was left behind. Thanks to @Asthenia0412 for identifying this and the other leftovers in #32588.

Design decision worth noting: an earlier draft of this cleanup (on the reporter's fork) removed the whole `if` block including the assert. I kept the assert because it guards a genuine invariant — if `max_audio_clip_s` is `None`, audio cannot be chunked, so merging more than one result generator would be a bug. Removing the variable does not require weakening that check.
