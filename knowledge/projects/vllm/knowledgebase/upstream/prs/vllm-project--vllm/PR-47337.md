# [Bugfix][Model] Allow Run:ai memory_limit sentinel values

[Upstream PR](https://github.com/vllm-project/vllm/pull/47337) · state: closed · merged: True

## Original PR description


## Purpose

Follow-up to #45291. @svasilinets pointed out that Run:ai documents `RUNAI_STREAMER_MEMORY_LIMIT=-1` as the unlimited/default CPU memory mode, and the same section documents `0` as the minimal CPU buffer. The validation added in #45291 currently rejects both values because it requires `memory_limit > 0`.

This PR keeps `concurrency` as a positive integer, but lets `memory_limit` follow Run:ai's range semantics: `-1`, `0`, or any positive integer. Values below `-1`, bools, and non-integers still raise before any `os.environ` mutation.

Run:ai docs: https://github.com/run-ai/runai-model-streamer/blob/master/docs/src/usage.md#cpu-memory-capping

## Test Plan

Run a loader-construction before/after check over `memory_limit=-1`, `0`, `1024`, `-2`, and `concurrency=-1`. Then run the focused `extra_config` tests and ruff on the changed files.

```python
import os

from vllm.config.load import LoadConfig
from vllm.model_executor.model_loader.runai_streamer_loader import RunaiModelStreamerLoader


def try_loader(extra):
    os.environ.pop("RUNAI_STREAMER_CONCURRENCY", None)
    os.environ.pop("RUNAI_STREAMER_MEMORY_LIMIT", None)
    try:
        RunaiModelStreamerLoader(
            LoadConfig(load_format="runai_streamer", model_loader_extra_config=extra)
        )
    except Exception as exc:
        print(f"{extra}: {type(exc).__name__}: {exc}")
    else:
        print(
            f"{extra}: accepted; "
            f"memory_limit={os.environ.get('RUNAI_STREAMER_MEMORY_LIMIT')!r}; "
            f"concurrency={os.environ.get('RUNAI_STREAMER_CONCURRENCY')!r}"
        )


for extra_config in (
    {"memory_limit": -1},
    {"memory_limit": 0},
    {"memory_limit": 1024},
    {"memory_limit": -2},
    {"concurrency": -1},
):
    try_loader(extra_config)
```
