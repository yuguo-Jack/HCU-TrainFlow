# fix(CPU): fall back to allowed NUMA nodes when assigned ids match none

[Upstream PR](https://github.com/vllm-project/vllm/pull/64507) · state: closed · merged: False

## Original PR description

Fixes #64497

## Problem

DP=2 × TP=2 on a 2-NUMA CPU host with explicit binds crashes `CPUWorker.__init__` with `IndexError`. DP rank 1 gets device ids `[2, 3]`, which `get_visible_memory_node()` reads as NUMA node ids. Neither exists on a 2-node host, so the filter returns an empty list and the `allowed_memory_nodes[0]` fallback (added for s390x in #40714) raises.

`CpuPlatform.get_current_memory_usage()` reads the same ids, so DP rank 1 reports 0 bytes even when the crash is avoided.

## Root cause

`get_physical_gpu_ids_for_local_dp_rank()` gives each DP rank a block of `world_size` device ids. On CPU those are logical device indices, not NUMA node ids. #62867 started passing them to `get_visible_memory_node(assigned_node_ids)`, which filters the allowed NUMA node list by them. The filter is correct only when the ids happen to name existing NUMA nodes (e.g. DP=2 on a 4-node host). When they do not, the list is empty.

## Fix

Fall back to the full allowed NUMA node list when the `assigned_node_ids` filter matches nothing. A partial overlap still narrows to the matching nodes, preserving #62867's DP NUMA affinity intent.

## Duplicate check

No open PR addresses this. #62867 introduced the regression and is merged; this fixes the case it missed.
