# [CI][BugFix] Lower memory utilization of the offline ColBERT plugin tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/62649) · state: closed · merged: False

## Original PR description



## Overview

Fixes the `(L4) Plugin Integration` CI job, where the three offline tests in `plugins_tests/test_colbert_query_io_processor_plugins.py` fail with `Free memory on device cuda:0 (20.25/22.03 GiB) on startup is less than desired GPU memory utilization (0.92, 20.27 GiB)` (e.g. full builds [95829](https://buildkite.com/vllm/ci/builds/95829) and [95887](https://buildkite.com/vllm/ci/builds/95887); the same job passes intermittently in other builds).

## Claims

- The offline ColBERT plugin tests no longer depend on a ~20 MB margin to start their engine while the module-scoped server is running.

## Validation

- `pytest -q tests/plugins_tests/test_colbert_query_io_processor_plugins.py` on 1x GB300: 7 passed.
- I could not reproduce the L4 failure locally: on a 280 GB device the server's ~1.8 GB footprint stays far below the 8% headroom. The fix rests on the numbers in the CI log above. The offline engine now needs 50% of the device free instead of 92%, about 11 GiB on L4, while about 20 GiB is free.

## Details

The `server` fixture is module-scoped, so its engine is only torn down at the end of the module and is still holding about 1.8 GB when the offline tests start. Each offline `vllm_runner` used the default `gpu_memory_utilization=0.92`, which on a 22 GiB L4 requires 20.27 GiB free. With the server alive, 20.25 GiB was free, so whether the engine could start came down to a few MB of allocator noise. ColBERT is a small pooling model and does not need a large KV budget, so the offline runners now use `gpu_memory_utilization=0.5`. The server keeps its default.
