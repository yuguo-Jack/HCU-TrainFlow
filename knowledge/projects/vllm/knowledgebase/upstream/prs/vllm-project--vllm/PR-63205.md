# [Model Runner V2][Spec Decode] Speculator config classes and custom speculators

[Upstream PR](https://github.com/vllm-project/vllm/pull/63205) · state: closed · merged: True

## Original PR description

## Overview

Lets users plug their own speculator into Model Runner V2. Each speculator now has a declarative config class that describes its behavior, replacing the speculative-method name checks spread across config, scheduler, KV cache and model code.

## Claims

- **Custom V2 speculators.** A plugin registers a method name with `register_speculative_method(name, config_cls)`, typically from a vLLM general plugin, and users select it with `method="<name>"`. The implementation is a `BaseSpeculator` subclass, usually via `DraftModelSpeculator` or `TargetDependentARSpeculator`. A config that subclasses a built-in one (e.g. `Eagle3SpeculatorConfig`) inherits that speculator's draft-model setup and behavior. Custom methods require MRV2. A custom speculator can take its own options via `speculator_options`.
- **Declarative speculator configs.** Each V2 speculator has a `SpeculatorConfig` subclass in an import-light `config.py` next to it. The class declares traits such as `uses_target_hidden_states`, `uses_aux_hidden_states`, `num_lookahead_tokens`, `max_model_len`, `supports_watermarking` and `supports_pcp`, and names its implementation class. Callers query `speculative_config.speculator_config` (or shortcut properties for the most widely used traits) instead of comparing method names. The scheduler process never imports a speculator implementation.
- **Per-method setup moves out of `SpeculativeConfig.__post_init__`.** It goes into the config classes: `default_model`, `configure`, draft-checkpoint hooks (`adapt_draft_model_config`, `resolve_num_speculative_tokens`), and `apply_options` for method-specific options. Each config lists the method-specific options it accepts in `supported_options`, and passing another one fails at startup.
- **Draft models declare their speculator.** A draft model sets `speculator_config_class` to its speculator's config class (new `SpeculativeDraftModel` interface, exposed through the model registry by qualified name). This replaces the hardcoded draft-architecture lists used to select DFlash2, LiLiCorr, XPress, DSpark and Gemma4 MTP.
- **Checkpoint detection never overrides an explicitly configured method.** For example, an explicit `mtp` could previously be rewritten to `eagle` by the draft checkpoint's name. An explicit method is now checked against the speculator the draft model declares, if any, and a mismatch fails with an explanatory error. This incorporates the intent of #41834 / #47490.
- `BaseSpeculator` now provides defaults for the members the runner reads (`supports_mm_inputs`, `draft_logits`, `prepare_watermarking()`), so speculators, custom ones included, only define what they use.

New tests are in `tests/v1/spec_decode/test_custom_speculator.py`. They cover:
- registration, validation and V2-only enforcement;

## Details

- **Line count.** About +1430/−750 non-test lines. Much of this moves existing per-method logic out of `speculative.py` (which shrinks substantially) into per-speculator config modules.
- **V1 runner.** `SpeculativeConfig` is shared with the V1 runner, so V1-only pieces are grouped in `v1_speculator_configs.py` (suffix, V1 `custom_class` proposers) or marked "V1 model runner only", to be deleted along with V1. The V1 `custom_class` proposer interface is unchanged on V1 and still rejected by V2. V1-only checks (e.g. P-EAGLE `parallel_drafting`, heterogeneous vocab) stay as method checks rather than declared traits, and `parallel_drafting` is now documented as deprecated.
- **`base_method`.** `method` keeps the registered custom name, for logging, usage stats and the config hash. `SpeculativeConfig.base_method` gives the built-in method a custom config is based on, and is what the `use_*` predicates and model-specific checks consult.
- **Behavior-preserving trait moves.** Upstream logic is kept but expressed as traits:
  - the draft max-model-len cap from #63251 (`SpeculatorConfig.max_model_len`);
  - DSpark's separate workspace lane (`uses_separate_workspace_lane`);
  - target input-embedding sharing under PP, now inferred from the draft model class;
  - the draft-pass `max_num_active_seqs` limit (`max_num_draft_seqs`).
- **Speculators-format checkpoints.** The speculators override no longer replaces a custom method that is based on the checkpoint's method. It rejects one that's based on a different method.
- **Docs.** See "Custom Speculators (Experimental)" in `docs/features/speculative_decoding/README.md`.
- **Reviewing.** The branch has accumulated review and merge commits, so it's best reviewed as a whole diff.
