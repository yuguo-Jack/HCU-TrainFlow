## Overview


ROCm follow-up to [#61978](https://github.com/vllm-project/vllm/pull/61978), which adds day-0 support for Reflection's [Beam 1.0](https://huggingface.co/reflection/Beam-1.0-501B-A23B) and its [DFlash2 drafter](https://huggingface.co/reflection/Beam-1.0-501B-A23B-DFlash2).


EDIT: Since #61978 has been split into smaller PRs (https://github.com/vllm-project/vllm/pull/62042, https://github.com/vllm-project/vllm/pull/62052, and https://github.com/vllm-project/vllm/pull/62074), I've updated against main and now the PR diff isn't swamped by the changes from #61978.

This PR adds AMD-owned implementations under `vllm/models/beam/amd/` for both `BeamForCausalLM` and `DFlash2BeamDraftModel`. The NVIDIA implementation from #61978 is unchanged in the relative diff. Shared package dispatch selects the AMD classes on ROCm and the NVIDIA classes elsewhere.

## Claims

- Beam 1.0 BF16 loads and serves on 8x MI350X with TP8 and expert parallelism through the AMD model path.
- Beam's required FP32 activation, normalization, Q/K preprocessing, attention-output gate, and logit-softcap arithmetic is retained in AMD-local Triton kernels.
- The AMD target uses standard vLLM ROCm attention and KV-cache updates, linear layers, finalized MoE output, and RCCL collectives rather than NVIDIA direct-cache, CuTe/FlashInfer, or MNNVL fast paths.
- The AMD DFlash2 implementation loads the released 1.93B drafter, generates successfully, and delegates cache writes and cache-format handling to the selected ROCm attention backend.
- The change adds no HIP/C++ kernels and does not modify the scheduler, KV-cache manager, model runner, attention backends, or NVIDIA Beam implementation.

Target only:

```bash

  --dtype bfloat16 \
  --tensor-parallel-size 8 \
  --enable-expert-parallel \
  --max-model-len 16384 \
  --max-num-seqs 16 \
  --max-num-batched-tokens 131072 \

  --enable-auto-tool-choice
```

With DFlash2:

## Details

- **Vendor ownership:** All ROCm target and DFlash2 implementation code lives under `vllm/models/beam/amd/`. The relative diff does not modify `vllm/models/beam/nvidia/`.
- **Platform dispatch:** `vllm.models.beam` exports AMD target and draft classes on ROCm and NVIDIA classes on other platforms.
- **Target execution:** AMD attention uses ordinary backend-owned K/V cache updates. AMD projections use standard vLLM linear layers, MoE returns finalized output normally, and distributed reductions use standard RCCL paths.
- **DFlash2 cache handling:** AMD-local Triton computes context K normalization and RoPE. Cache layout, slot scattering, optional shuffling, and quantization are delegated to each ROCm attention backend's native cache-update API rather than hard-coded pointer arithmetic.
- **Numerics:** AMD-local Triton kernels retain Beam's required FP32 operations and intermediate BF16 rounding boundaries.
- **HIP launch compatibility:** AMD kernels omit CUDA-only Triton launch options such as `enable_reflect_ftz` and `launch_pdl`.
- **Footprint:** 1,968 additions and 2 deletions across 12 Beam model files; no core execution or NVIDIA implementation changes.
