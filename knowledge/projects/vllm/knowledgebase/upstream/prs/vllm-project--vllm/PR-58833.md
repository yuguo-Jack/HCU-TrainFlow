# [Bugfix][Spec Decode] Fix GLM-5.3 image-token mapping during MTP initialization

[Upstream PR](https://github.com/vllm-project/vllm/pull/58833) · state: open · merged: False

## Original PR description

## Purpose

Fix an `AttributeError` when `SpecDecodeBaseProposer.load_model()` initializes an MTP draft for `Glm5NextForConditionalGeneration`:

```text
AttributeError: 'Glm5NextConfig' object has no attribute 'image_token_index'
```

`Glm5NextConfig` defines `image_token_id`, but GLM is missing from the existing mapping branch. Add its class name so the draft receives the target's image token ID instead of attempting to read the nonexistent `image_token_index`. This changes initialization only; MTP computation and target/draft weight sharing are unchanged.

Searches for GLM image-token mapping fixes found no overlapping open PR. The related GLM DFlash2 (#56983) and pipeline-parallel (#57171) changes do not modify this proposer mapping.
