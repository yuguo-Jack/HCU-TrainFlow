# [Bugfix][Frontend] Avoid IndexError when an output has fewer logprobs than tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/63775) · state: open · merged: False

## Original PR description

## Overview

Non-streaming `/v1/chat/completions` and `/v1/completions` return 500 (`IndexError: list index out of range`) when a finished output has fewer logprob positions than tokens (#63751). With this PR, an output whose logprob positions and tokens differ in length (shorter, as reported, or longer) is returned without logprobs instead of failing the request, and each occurrence is logged with both lengths. It does **not** fix the upstream mismatch. That fix is #61219: with `logprob_token_ids` and speculative decoding on the V2 model runner, the rejection sampler drops the token-id logprobs on every step that has draft tokens. This PR is a backstop, so a mismatch like that, from this path or another, can't fail the whole request. It addresses the 500s in #63751 without closing it.

**Relation to other work:** #61219 fixes the root cause in the rejection sampler (@kfirtoledo traced #63751 to it). This PR only touches the serving layer, so the two don't overlap and can land in either order. @MarinaMackay, who had planned to work on #63751, stepped back once #61219 was found. No other open PR touches these loops.

## Claims

- When an output has fewer or more logprob positions than tokens, the four logprobs builders (chat, completions, and the tokens endpoint's text and generate shapes) return it without logprobs instead of raising, wherever the positions are missing or extra (end or middle). Every token gets the builder's existing no-logprob entry: `-9999.0` for chat and tokens, `null` for completions.
- No logprob is attributed to the wrong token. Once the lengths disagree, the alignment is unknown, so no position keeps its row. A per-position guard would misattribute after a gap in the middle, and passing a longer list through would misattribute after an extra row in the middle; the new tests catch both.
- Outputs with exactly as many logprob positions as tokens are unchanged. A longer list used to pass through; it is now dropped too. Nothing produces one today (stop-string trimming cuts tokens and logprobs together, and the scheduler slices one row per token), so this only matters if a future bug does.
- Each occurrence logs `Output has N tokens but M logprob positions; returning it without logprobs.`

**Out of scope:** `/v1/responses` asserts the two lengths are equal (`responses/serving.py:986`) and still fails on a mismatch. It isn't in the issue, and the assert looks deliberate. Completions also still raises `KeyError` when a full-length position lacks its sampled token; that is pre-existing and not a length mismatch.

**Streaming is out of scope too:** in DELTA mode, `output_processor.py:498` takes the last N rows of the accumulated logprobs, so a row missing upstream gives a shifted slice of the right length. No length check in the serving layer can catch that; it has to be fixed upstream, as #61219 does for this trigger.

## Details

**Root cause: fixed by #61219.** The builders loop `for i, token_id in enumerate(token_ids)` and read `top_logprobs[i]`, assuming one logprob position per token. When a request sets `logprob_token_ids`, chat and completions pass `logprobs=None` to the engine, so only the token-id logprobs are requested. The V2 model runner leaves those out whenever the batch has draft tokens (`include_token_ids=False` in `model_runner.py`), and the rejection sampler then returns no logprobs. Tokens from those steps get no logprob row. In the repro only the first token, sampled at prefill before any drafts exist, keeps one: 200 tokens, 1 position. #61219 passes the token ids through to the rejection sampler.

**Design:** one helper, `drop_misaligned_logprobs`, in `vllm/entrypoints/generate/base/serving.py` next to the other shared logprobs helpers. Each of the four builders calls it once before its loop, and the loops are unchanged. Nothing changes in the engine, scheduler or model runner.

**Tradeoff:** when only the last positions are missing, the earlier logprobs were probably correct, but they are dropped too, because a missing or extra row can't be shown to be at the end. With this trigger the gaps fall on every step that has drafts, so they are spread through the output, not only at the end. A wrong logprob is worse than a missing one, especially on the tokens endpoint, which RL clients use. The warning fires on every occurrence, so a mismatch from any other source stays visible.

The shared helper in vllm/entrypoints/generate/base/serving.py is the right shape: one alignment guard covering all four call sites instead of a per-site length check, and dropping to all-None positions is clearly safer than the old behavior of indexing past the end or attributing shifted rows.

Three questions on the details:

1. The guard only handles the short case. When top_logprobs is longer than token_ids it passes through untouched, and the callers then use the first len(token_ids) rows. Is longer-than-tokens provably trailing-only at every call site? If an extra row could appear anywhere but the tail, the first N rows would still misattribute, and the guard would silently bless them.

2. When the list is short, all positions are dropped, even though a shortfall caused only by missing trailing rows would leave the leading rows correctly aligned. I assume the conservative choice is deliberate because a missing row cannot be proven to be trailing rather than in the middle. If so, that reasoning is worth one line in the align_step_logprobs docstring, since a prefix-preserving version (aligned prefix plus None tail) is the first alternative a reader will wonder about.

3. Client-side, a dropped set is indistinguishable from the token-not-in-top-k case: both surface as -9999.0 placeholders (or None token_logprobs), and the only trace of the misalignment is the server-side warning. Is that acceptable for callers debugging logprob quality, or should the dropped case be distinguishable in the response?

```python
"""Repro for #63751. Needs one GPU.

Usage: python repro_63751.py [MODEL]   (default: Qwen/Qwen3-0.6B)
"""

import json
import os
import subprocess
import sys
import time
import urllib.error
import urllib.request

MODEL = sys.argv[1] if len(sys.argv) > 1 else "Qwen/Qwen3-0.6B"
PORT = 8011
BASE = f"http://localhost:{PORT}"
LOGPROB_TOKEN_IDS = [11, 13, 220]
PROMPT = "Repeat this line ten times: the quick brown fox jumps over the lazy dog."
NUM_REQUESTS = 5


def post(path, body):
    req = urllib.request.Request(
        BASE + path,
        data=json.dumps(body).encode(),
        headers={"Content-Type": "application/json"},
    )
    try:
        with urllib.request.urlopen(req, timeout=300) as resp:
            return resp.status, json.loads(resp.read())
    except urllib.error.HTTPError as e:
        return e.code, e.read().decode()[:300]


def chat_summary(data):
    content = data["choices"][0]["logprobs"]["content"]
    real = sum(entry["logprob"] != -9999.0 for entry in content)
    return f"{data['usage']['completion_tokens']} tokens, {real}/{len(content)} real logprobs"


def completion_summary(data):
    values = data["choices"][0]["logprobs"]["token_logprobs"]
    real = sum(v is not None for v in values)
    return f"{data['usage']['completion_tokens']} tokens, {real}/{len(values)} real logprobs"


def main():
    spec = {
        "method": "ngram",
        "num_speculative_tokens": 4,
        "prompt_lookup_min": 2,
        "prompt_lookup_max": 4,
    }
    server = subprocess.Popen(
        ["vllm", "serve", MODEL, "--port", str(PORT), "--max-model-len", "4096",
         "--enforce-eager", "--speculative-config", json.dumps(spec)],
        env={**os.environ, "VLLM_USE_V2_MODEL_RUNNER": "1"},
        stdout=open("server.log", "w"),
        stderr=subprocess.STDOUT,
    )
    try:
        for _ in range(600):
            try:
                urllib.request.urlopen(BASE + "/health", timeout=2)
                break
            except Exception:
                if server.poll() is not None:
                    sys.exit("server exited; see server.log")
                time.sleep(1)
        else:
            sys.exit("server did not start; see server.log")

        common = {"model": MODEL, "max_tokens": 200, "temperature": 0,
                  "logprob_token_ids": LOGPROB_TOKEN_IDS}
        cases = [
            ("chat", "/v1/chat/completions", chat_summary,
             {**common, "logprobs": True,
              "messages": [{"role": "user", "content": PROMPT}]}),
            ("completions", "/v1/completions", completion_summary,
             {**common, "logprobs": 1, "prompt": PROMPT}),
        ]
        for name, path, summarize, body in cases:
            for i in range(NUM_REQUESTS):
                status, data = post(path, body)
                detail = summarize(data) if status == 200 else data
                print(f"{name} #{i}: HTTP {status}: {detail}", flush=True)

        metrics = urllib.request.urlopen(BASE + "/metrics").read().decode()
        drafts = [line for line in metrics.splitlines()
                  if line.startswith("vllm:spec_decode_num_draft_tokens_total")]
        print("draft tokens proposed:", drafts or "metric not found")
    finally:
        server.terminate()
        server.wait(timeout=60)

    with open("server.log") as f:
        for line in f:
            if "IndexError" in line or "logprob positions" in line:
                print("server.log:", line.rstrip())


if __name__ == "__main__":
    main()
```

```python
"""Repro for #63751 on chat, completions and the tokens endpoint. Needs one GPU.

The trigger: `logprob_token_ids` without `logprobs` reaches the engine while
speculative decoding runs on the V2 model runner. Every step with draft tokens
then returns no logprob row, so the output has fewer logprob positions than
tokens and the non-streaming logprobs builders raise IndexError.

Usage: python repro_63751.py [MODEL]   (default: Qwen/Qwen3-0.6B)
"""

import json
import os
import subprocess
import sys
import time
import urllib.error
import urllib.request

MODEL = sys.argv[1] if len(sys.argv) > 1 else "Qwen/Qwen3-0.6B"
PORT = 8011
BASE = f"http://localhost:{PORT}"
LOGPROB_TOKEN_IDS = [11, 13, 220]
PROMPT = "Repeat this line ten times: the quick brown fox jumps over the lazy dog."
MESSAGES = [{"role": "user", "content": PROMPT}]
NUM_REQUESTS = 3
MAX_TOKENS = 200


def post(path, body):
    req = urllib.request.Request(
        BASE + path,
        data=json.dumps(body).encode(),
        headers={"Content-Type": "application/json"},
    )
    try:
        with urllib.request.urlopen(req, timeout=300) as resp:
            return resp.status, json.loads(resp.read())
    except urllib.error.HTTPError as e:
        return e.code, e.read().decode()[:300]


def summarize(data):
    choice = data["choices"][0]
    logprobs = choice.get("logprobs")
    if logprobs is None:
        return "no logprobs field"
    if "content" in logprobs:
        values = [entry["logprob"] for entry in logprobs["content"] or []]
        real = sum(v != -9999.0 for v in values)
    else:
        values = logprobs["token_logprobs"]
        real = sum(v is not None for v in values)
    return f"{real}/{len(values)} real logprobs"


def main():
    spec = {
        "method": "ngram",
        "num_speculative_tokens": 4,
        "prompt_lookup_min": 2,
        "prompt_lookup_max": 4,
    }
    server = subprocess.Popen(
        ["vllm", "serve", MODEL, "--port", str(PORT), "--max-model-len", "4096",
         "--enforce-eager", "--enable-scale-out",
         "--speculative-config", json.dumps(spec)],
        env={**os.environ, "VLLM_USE_V2_MODEL_RUNNER": "1"},
        stdout=open("server.log", "w"),
        stderr=subprocess.STDOUT,
    )
    try:
        for _ in range(900):
            try:
                urllib.request.urlopen(BASE + "/health", timeout=2)
                break
            except Exception:
                if server.poll() is not None:
                    sys.exit("server exited; see server.log")
                time.sleep(1)
        else:
            sys.exit("server did not start; see server.log")

        status, tok = post("/tokenize", {"model": MODEL, "messages": MESSAGES,
                                         "add_generation_prompt": True})
        assert status == 200, tok
        prompt_ids = tok["tokens"]

        common = {"model": MODEL, "max_tokens": MAX_TOKENS, "temperature": 0,
                  "logprob_token_ids": LOGPROB_TOKEN_IDS}
        # sampling_params for /inference/v1/generate. `logprobs` is left unset,
        # as chat and completions do when `logprob_token_ids` is set.
        gen_params = {"max_tokens": MAX_TOKENS, "temperature": 0,
                      "logprob_token_ids": LOGPROB_TOKEN_IDS}
        cases = [
            ("chat", "/v1/chat/completions",
             {**common, "logprobs": True, "messages": MESSAGES}),
            ("completions", "/v1/completions",
             {**common, "logprobs": 1, "prompt": PROMPT}),
            ("generate derender", "/inference/v1/generate",
             {"token_ids": prompt_ids, "output_mode": "derender",
              "sampling_params": gen_params}),
            # Controls: at these levels `num_logprobs` is `logprobs`, so with
            # `logprobs` set the engine returns a row per token, and without
            # it no logprobs are built.
            ("generate text, logprobs=3", "/inference/v1/generate",
             {"token_ids": prompt_ids, "output_mode": "text",
              "sampling_params": {**gen_params, "logprobs": 3}}),
            ("generate tokens", "/inference/v1/generate",
             {"token_ids": prompt_ids, "output_mode": "tokens",
              "sampling_params": gen_params}),
        ]
        for name, path, body in cases:
            for i in range(NUM_REQUESTS):
                status, data = post(path, body)
                if status == 200:
                    num_tokens = len(data["choices"][0].get("token_ids") or []) or (
                        data["usage"]["completion_tokens"])
                    detail = f"{num_tokens} tokens, {summarize(data)}"
                else:
                    detail = data
                print(f"{name} #{i}: HTTP {status}: {detail}", flush=True)

        metrics = urllib.request.urlopen(BASE + "/metrics").read().decode()
        drafts = [line for line in metrics.splitlines()
                  if line.startswith("vllm:spec_decode_num_draft_tokens_total")]
        print("draft tokens proposed:", drafts or "metric not found")
    finally:
        server.terminate()
        server.wait(timeout=60)

    with open("server.log") as f:
        for line in f:
            if "IndexError" in line or "logprob positions" in line:
                print("server.log:", line.rstrip())
```
