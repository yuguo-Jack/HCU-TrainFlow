# [BugFix] Accept hyphenated FunctionGemma tool names in non-streaming parse

[Upstream PR](https://github.com/vllm-project/vllm/pull/57989) · state: open · merged: False

## Original PR description

## Summary

Fixes #57950.

Non-streaming `FunctionGemmaToolParser.tool_call_regex` used `\w+` for the function name, so names like `get-weather` failed to match and the raw control frame was returned as content. Streaming already accepted hyphens via `func_part.split("{")[0]`.

Widen the name group to `[\w-]+` in both alternations so non-streaming matches streaming and OpenAI-legal hyphenated tool names.

If the intent is to match OpenAI-style tool name constraints, `\\w` in Python is Unicode-aware by default and will accept non-ASCII letters/digits. Consider using an explicit ASCII-only character class (e.g., `[A-Za-z0-9_-]+`) and/or `re.ASCII` so the regex more precisely matches the documented constraints rather than broad Unicode identifiers.
