# [Observability] Add request tracing for pooling entrypoints.

[Upstream PR](https://github.com/vllm-project/vllm/pull/61785) · state: open · merged: False

## Original PR description



## Overview

Following: https://github.com/vllm-project/vllm/issues/39979  
POC: #43069

Add two levels of observability for pooling entrypoints

- request level
  - prefill span 
  - no decode spam (Pooling models can also be called prefill-only models, because they have no decode stage and do not generate any content.)
- entrypoints level
  - preprocessing span
  - engine_call span
  - postprocessing span

The entrypoint level tracing is affordable, users can consider keeping it always enabled in deployments.
The previous vLLM core engine tracing (llm_request) is expensive. In the upcoming PR, users can disable it.

Explicit attributes override what the env detector reads. <details>
<summary>Why this was flagged</summary>

The trigger is a deployment that sets `OTEL_RESOURCE_ATTRIBUTES="service.name=my-embedder,..."` without `OTEL_SERVICE_NAME`, and then runs `vllm serve --otlp-traces-endpoint ...`. Every tracer goes through the new `init_otel_trace_provider` (vllm/tracing/otel.py:67). At otel.py:83-85 it builds `resource_attrs` with `SERVICE_NAME: os.environ.get("OTEL_SERVICE_NAME", "vllm")` and passes them to `Resource.create`.
