# [Bugfix][Frontend] Preserve Cohere and Anthropic streaming errors

[Upstream PR](https://github.com/vllm-project/vllm/pull/61947) · state: closed · merged: True

## Overview

Preserve parser and generation failures in Cohere and Anthropic streaming responses. Follow the [review feedback](https://github.com/vllm-project/vllm/pull/61947#discussion_r4291298497) by exposing raw chat chunks from the shared generator and converting them at each API's output boundary.

## Claims

- Add `OpenAIServingChat.chat_completion_stream_generator_raw`, yielding `ChatCompletionStreamResponse | ErrorResponse` without SSE framing.
- Convert raw objects directly in Cohere and Anthropic, removing intermediate JSON serialization and reparsing. Both preserve the sanitized original error before or during output and close active blocks before the terminal error event.
- Preserve OpenAI's JSON fields, usage metadata and `[DONE]` termination, including when output serialization itself fails.

## Details

The shared generator can produce either a normal chat chunk or an `ErrorResponse`. Both API adapters previously expected serialized normal chunks, so an error envelope caused a second validation failure. Cohere could discard it before the first normal chunk; Anthropic replaced the original cause with the validation error.

Extract the existing generation loop into `chat_completion_stream_generator_raw`. OpenAI's existing generator serializes these objects and appends `[DONE]`; Cohere and Anthropic override that serialization boundary to produce their own events directly. Request preprocessing, admission checks and KV-transfer rejection cleanup keep their existing entry points.

Cohere retains its `message-end(ERROR)` followed by `[DONE]`. Anthropic now closes an open block, emits an `error` event with the original sanitized message, and terminates without a success `message_stop`. Normal stream exhaustion still performs block flushing and protocol termination. In-stream failures remain HTTP 200 and are communicated through SSE.

This extends the existing PR as requested; no additional PR was opened. Related [#60309](https://github.com/vllm-project/vllm/pull/60309) handles HTTP error mapping and [#61825](https://github.com/vllm-project/vllm/pull/61825) handles Cohere REQUIRED/tools validation; neither fixes these streaming adapters.

- KuanJia · comment · 2026-10-16T04:31:51Z · [source](https://github.com/vllm-project/vllm/pull/61947#discussion_r4290945569)

File: `vllm/entrypoints/cohere/serving.py` · line 1456

The difference is that the OpenAI serving path is the producer of these serialized stream responses, while the Cohere serving path consumes and converts the OpenAI chat stream.

On the normal path, the upstream generator yields ChatCompletionStreamResponse, but on an error it may yield a serialized ErrorResponse. OpenAI serving can return that error directly, so it does not need to deserialize it again. Cohere, however, has to inspect the upstream JSON in order to translate it into Cohere Chat v2 events.

The adapter therefore accepts both response types here so that we can preserve the original OpenAI error message instead of failing validation as a ChatCompletionStreamResponse.
