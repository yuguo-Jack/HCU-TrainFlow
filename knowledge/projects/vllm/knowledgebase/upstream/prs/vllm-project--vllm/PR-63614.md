# [Bugfix][Kernel] hadacore: fix skipped wait_group on partial-chunk warp for odd row counts (#63514)

[Upstream PR](https://github.com/vllm-project/vllm/pull/63614) · state: closed · merged: True

## Original PR description

Fixes #63514

### Problem
When using INT4 per-token-head KV cache (`--kv-cache-dtype int4_per_token_head`), `reshape_and_cache_int4` rotates Key and Value tensors via `hadacore_transform`. 

For `head_dim = 256`, `num_chunks` is 2. When the row count (`num_tokens * num_kv_heads_per_rank`) is odd, the last warp receives only 1 chunk (`real_num_chunks = 1`).

`diff_num_chunks` was calculated as:
```cpp
int64_t diff_num_chunks = real_num_chunks - num_chunks; // 1 - 2 = -1
```
Because `diff_num_chunks` was negative, `switch(k + diff_num_chunks)` evaluated to `-1`. Since the switch statement only contains `case 0..31` and had no `default:` fallback, it silently skipped `cp.async.wait_group` completely. 

The warp proceeded to read shared memory before the asynchronous DMA copy completed, causing:
1. Silent data corruption (relative errors up to 10^36).
2. Intermittent `CUDA illegal memory access` crashes during prefill.

### Fix
1. Correct the difference to `num_chunks - real_num_chunks` so `k + diff_num_chunks` maps to the intended wait barrier count (`wait_group 0` for the single tail chunk).
2. Add `default: asm volatile("cp.async.wait_group 0;\n"); break;` so an unhandled case can never silently skip synchronization.
3. Add parameterized unit test in `tests/kernels/quantization/test_hadacore.py` covering odd and large row counts (`num_rows in [1, 17, 53, 65, 165, 173, 257, 513, 1025, 4097, 8193]`).

### Validation
Verified on NVIDIA A100-PCIE-40GB:
- **Full range test (`N = 1` to `512`):**
  - Unpatched `main` (`2c880f1e`): 39 failing row counts (all odd), errors up to 10^36.
  - With this fix: **0 failures out of 512** (100% bit-exact match against float64 reference).
- Tested small (`N <= 128`), medium (`128 < N <= 513`), and large (`1024 <= N <= 8193`) shapes across both odd and even counts.

<details>
<summary>Reproduction Script</summary>

```python
import math
import torch
from vllm import _custom_ops as ops

D = 256
H = torch.ones(1, 1, dtype=torch.float64, device="cuda")
while H.shape[0] < D:
    H = torch.cat([torch.cat([H, H], 1), torch.cat([H, -H], 1)], 0)
H = H / math.sqrt(D)

bad = []
for n in range(1, 513):
    torch.manual_seed(n)
    x = torch.randn(n, D, dtype=torch.bfloat16, device="cuda")
    y = ops.hadacore_transform(x.clone(), inplace=True)
    ref = (x.double() @ H).to(torch.bfloat16)

    rel_err = ((y.double() - ref.double()).abs().max() / ref.double().abs().max()).item()
    if rel_err > 2e-2:
        bad.append((n, f"{rel_err:.2e}"))

print(f"Tested 1..512 row counts: {len(bad)} failures")
if bad:
    print("Sample failing counts:", bad[:10])
```
