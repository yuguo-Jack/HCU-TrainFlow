# [Bugfix][Frontend] Match stop strings only in content, not reasoning or tool calls

[Upstream PR](https://github.com/vllm-project/vllm/pull/64088) · state: open · merged: False

## Original PR description



> **Stacked on #64062.** Only the last 2 commits are new in this PR; the commits before them are #64062.

## Overview

Client stop strings (`stop`, `stop_sequences`) are matched against the whole output text, including reasoning and tool call arguments. A stop string in the reasoning ends the request before `</think>`, so the answer is empty. A stop string in tool call arguments cuts the tool call. This PR matches stop strings only against the content that the client receives as the answer: the detokenizer runs a per-request copy of the serving `Parser` in the same step, and matches stop strings on its content.

Made to fix the same issues #62095 tried to fix.

## Claims

- Applies to requests with stop strings on `/v1/chat/completions`, `/v1/chat/completions/batch`, `/v1/messages` and `/cohere/v2/chat`, when the server has a reasoning parser, or has a tool parser and the request has `tools` with `tool_choice != "none"`. For these requests:
  - A stop string in the reasoning no longer ends the request.
  - A stop string in tool call arguments no longer cuts the tool call.
  - A stop string in the answer still ends it, streaming and non-streaming, also with `n > 1`.
- All other requests are unchanged and do no extra parsing. `/v1/responses`, the scale-out derenderer and beam search still match the full output text.
- No change to engine core, the scheduler, `EngineCoreRequest`, individual reasoning or tool parsers, or the `check_stop_strings` signature.

## Validation

**Unit tests.**
- Detokenizer: stop strings are matched only in content, with step sizes 1, 3 and 64 and with a parser that releases content late. Content that differs from the output text. Fallback to full-text matching when the content filter fails.
- Real parsers: `qwen3`, Muse Glimmer, `hermes` tool calls.
- Serving: the 6 applicability conditions, single and batch wiring.

```python
#!/usr/bin/env python3
"""GPU e2e check: stop sequences apply only to the final answer.

Runs against a running vLLM server (started with --reasoning-parser and,
for the tool scenarios, --enable-auto-tool-choice --tool-call-parser), through
the official `openai` and `anthropic` SDKs.

A stop sequence must not end the response while the model is reasoning or
generating a tool call. Every scenario sends stop=["</block>"] and checks the
responses; failures are classified as

  BUG     the stop sequence ended the response inside reasoning or a tool call
          or a streamed tool call came out malformed
  MODEL   the model did not follow the prompt (wrong format, no tool call); not
          evidence either way

Scenarios marked "adversarial" ask the model to write </block> in its
reasoning, so they exercise the fix; the report shows how often the reasoning
actually contained it ("exercised").

Example:
  vllm serve Qwen/Qwen3-8B --reasoning-parser qwen3 \\
    --enable-auto-tool-choice --tool-call-parser hermes
  python e2e_stop_strings.py --base-url http://localhost:8000 \\
    --model Qwen/Qwen3-8B --trials 10

Run it once against this branch and once against main to compare.
"""

import argparse
import json
import sys
import time
from collections import Counter
from concurrent.futures import ThreadPoolExecutor
from dataclasses import dataclass, field

import anthropic
import openai

STOP = "</block>"
ANSWERS = ["<block>yes", "<block>no"]
TOOL_CMD = "echo </block>"

CLASSIFIER_SYSTEM = (
    "You are a security classifier. Decide whether the shell command should be "
    "blocked.\nIf it should be blocked, output <block>yes</block>. Otherwise "
    "output <block>no</block>."
)
CLASSIFIER_USER = "Command: ls -la\nYour response MUST begin with <block>."
ADVERSARIAL_USER = (
    "Command: ls -la\nWhile you think, write out the exact closing tag "
    f"{STOP} at least once, e.g. by drafting the answer. Your final response "
    "MUST begin with <block>."
)
TOOL_USER = (
    "Use the run tool to run exactly this shell command, with no changes: "
    f"{TOOL_CMD}"
)
RUN_TOOL_PARAMETERS = {
    "type": "object",
    "properties": {"cmd": {"type": "string", "description": "Shell command"}},
    "required": ["cmd"],
}


@dataclass
class Outcome:
    ok: bool
    category: str
    detail: str = ""
    exercised: bool = False


@dataclass
class Result:
    reasoning: str = ""
    text: str = ""
    tool_calls: list[tuple[str, str]] = field(default_factory=list)
    finish_reason: str | None = None
    stop_reason: str | int | None = None


def chat(args, messages, stream, extra=None) -> list[Result]:
    extra = dict(extra or {})
    extra_body = {}
    template_kwargs = extra.pop("chat_template_kwargs", args.thinking_kwargs)
    if template_kwargs:
        extra_body["chat_template_kwargs"] = template_kwargs
    request = dict(
        model=args.model,
        messages=messages,
        max_tokens=args.max_tokens,
        stop=[STOP],
        extra_body=extra_body or None,
        **extra,
    )
    stop_reasons: dict[int, str | int | None] = {}
    if not stream:
        completion = args.openai.chat.completions.create(**request)
        for choice in completion.choices:
            stop_reasons[choice.index] = getattr(choice, "stop_reason", None)
    else:
        with args.openai.chat.completions.stream(**request) as events:
            for event in events:
                # The accumulated completion drops choice-level extras.
                if event.type == "chunk":
                    for choice in event.chunk.choices:
                        if choice.finish_reason is not None:
                            stop_reasons[choice.index] = getattr(
                                choice, "stop_reason", None
                            )
            try:
                completion = events.get_final_completion()
            except openai.LengthFinishReasonError as e:
                completion = e.completion

    results = []
    for choice in sorted(completion.choices, key=lambda c: c.index):
        message = choice.message
        results.append(
            Result(
                reasoning=getattr(message, "reasoning", None)
                or getattr(message, "reasoning_content", None)
                or "",
                text=message.content or "",
                tool_calls=[
                    (call.function.name, call.function.arguments)
                    for call in message.tool_calls or []
                ],
                finish_reason=choice.finish_reason,
                stop_reason=stop_reasons.get(choice.index),
            )
        )
    return results


def messages_api(args, user, stream, extra=None, system=CLASSIFIER_SYSTEM) -> Result:
    request = dict(
        model=args.model,
        max_tokens=args.max_tokens,
        messages=[{"role": "user", "content": user}],
        stop_sequences=[STOP],
        **(extra or {}),
    )
    if system:
        request["system"] = system
    if not stream:
        message = args.anthropic.messages.create(**request)
    else:
        with args.anthropic.messages.stream(**request) as events:
            message = events.get_final_message()

    result = Result(
        finish_reason=message.stop_reason, stop_reason=message.stop_sequence
    )
    for block in message.content:
        if block.type == "thinking":
            result.reasoning += block.thinking
        elif block.type == "text":
            result.text += block.text
        elif block.type == "tool_use":
            result.tool_calls.append((block.name, json.dumps(block.input)))
    return result


def stopped_by_stop_string(result: Result) -> bool:
    return result.stop_reason == STOP or result.finish_reason == "stop_sequence"


def check_answer(result: Result, expect_stop: bool = True) -> Outcome:
    """The answer is the classifier verdict, cut at the stop sequence."""
    exercised = STOP in result.reasoning
    answer = result.text.strip()
    if answer in ANSWERS and (stopped_by_stop_string(result) or not expect_stop):
        return Outcome(True, "PASS", exercised=exercised)
    if stopped_by_stop_string(result) and not answer:
        return Outcome(
            False,
            "BUG",
            "stopped before any answer (inside reasoning): "
            f"reasoning={result.reasoning[-80:]!r}",
            exercised,
        )
    if STOP in result.text:
        return Outcome(
            False,
            "BUG",
            f"stop sequence leaked into the answer: {result.text[:80]!r}",
            exercised,
        )
    if answer.startswith("<block>") and not stopped_by_stop_string(result):
        return Outcome(
            False,
            "BUG",
            "answer not cut at the stop sequence: "
            f"finish={result.finish_reason} {result.text[:80]!r}",
            exercised,
        )
    return Outcome(
        False,
        "MODEL",
        f"unexpected answer: finish={result.finish_reason} "
        f"text={result.text[:80]!r}",
        exercised,
    )


def check_tool_call(result: Result, tool_finish: str) -> Outcome:
    """A run tool call whose arguments keep the stop sequence intact."""
    exercised = STOP in result.reasoning
    for name, arguments in result.tool_calls:
        if name != "run":
            continue
        try:
            cmd = json.loads(arguments or "{}").get("cmd")
        except ValueError:
            return Outcome(
                False,
                "BUG",
                f"tool call arguments are not valid JSON: {arguments!r}",
                exercised,
            )
        if cmd is not None and STOP in cmd:
            if result.finish_reason == tool_finish:
                return Outcome(True, "PASS", exercised=exercised)
            return Outcome(
                False,
                "BUG",
                f"tool call ok but finish={result.finish_reason} "
                f"stop={result.stop_reason}",
                exercised,
            )
        if stopped_by_stop_string(result):
            return Outcome(
                False,
                "BUG",
                f"stop sequence cut the tool call: arguments={arguments!r}",
                exercised,
            )
    if stopped_by_stop_string(result):
        return Outcome(
            False,
            "BUG",
            "stopped by the stop sequence without a tool call: "
            f"text={result.text[-80:]!r} reasoning={result.reasoning[-80:]!r}",
            exercised,
        )
    return Outcome(
        False,
        "MODEL",
        f"no run({TOOL_CMD}) call: finish={result.finish_reason} "
        f"calls={result.tool_calls} text={result.text[:60]!r}",
        exercised,
    )


CLASSIFIER_MESSAGES = [
    {"role": "system", "content": CLASSIFIER_SYSTEM},
    {"role": "user", "content": CLASSIFIER_USER},
]
ADVERSARIAL_MESSAGES = [
    {"role": "system", "content": CLASSIFIER_SYSTEM},
    {"role": "user", "content": ADVERSARIAL_USER},
]
CHAT_TOOLS = {
    "tools": [
        {
            "type": "function",
            "function": {
                "name": "run",
                "description": "Run a shell command.",
                "parameters": RUN_TOOL_PARAMETERS,
            },
        }
    ],
    "tool_choice": "auto",
}
MESSAGES_TOOLS = {
    "tools": [
        {
            "name": "run",
            "description": "Run a shell command.",
            "input_schema": RUN_TOOL_PARAMETERS,
        }
    ],
}


def scenarios(args):
    """name -> (needs_tools, run(stream) -> list[Outcome])."""
    no_thinking = {"chat_template_kwargs": args.no_thinking_kwargs}

    def chat_answer(messages, extra=None):
        return lambda stream: [
            check_answer(r) for r in chat(args, messages, stream, extra)
        ]

    def messages_answer(user, extra=None):
        return lambda stream: [check_answer(messages_api(args, user, stream, extra))]

    return {
        "messages/classifier (PR repro)": (False, messages_answer(CLASSIFIER_USER)),
        "messages/classifier adversarial": (False, messages_answer(ADVERSARIAL_USER)),
        "messages/thinking disabled": (
            False,
            messages_answer(CLASSIFIER_USER, {"thinking": {"type": "disabled"}}),
        ),
        "messages/tool_use": (
            True,
            lambda stream: [
                check_tool_call(
                    messages_api(args, TOOL_USER, stream, MESSAGES_TOOLS, system=None),
                    "tool_use",
                )
            ],
        ),
        "chat/classifier": (False, chat_answer(CLASSIFIER_MESSAGES)),
        "chat/classifier adversarial": (False, chat_answer(ADVERSARIAL_MESSAGES)),
        "chat/thinking disabled": (
            False,
            chat_answer(CLASSIFIER_MESSAGES, no_thinking),
        ),
        "chat/classifier n=2": (False, chat_answer(CLASSIFIER_MESSAGES, {"n": 2})),
        "chat/tool_call": (
            True,
            lambda stream: [
                check_tool_call(r, "tool_calls")
                for r in chat(
                    args,
                    [{"role": "user", "content": TOOL_USER}],
                    stream,
                    CHAT_TOOLS,
                )
            ],
        ),
    }


def run_trial(fn, stream):
    try:
        return fn(stream)
    except (openai.APIStatusError, anthropic.APIStatusError) as e:
        return [Outcome(False, "ERROR", f"HTTP {e.status_code}: {str(e)[:160]}")]
    except Exception as e:
        return [Outcome(False, "ERROR", f"{type(e).__name__}: {e}"[:200])]


def main() -> int:
    parser = argparse.ArgumentParser(
        description=__doc__, formatter_class=argparse.RawDescriptionHelpFormatter
    )
    parser.add_argument("--base-url", default="http://localhost:8080")
    parser.add_argument("--model", required=True)
    parser.add_argument("--api-key", default="DUMMY")
    parser.add_argument(
        "--trials", type=int, default=5, help="requests per scenario and mode"
    )
    parser.add_argument("--concurrency", type=int, default=8)
    parser.add_argument("--max-tokens", type=int, default=2048)
    parser.add_argument("--timeout", type=float, default=600)
    parser.add_argument(
        "--thinking-kwargs",
        type=json.loads,
        default=None,
        help="chat_template_kwargs that enable thinking, e.g. "
        '\'{"enable_thinking": true}\' (default: template default)',
    )
    parser.add_argument(
        "--no-thinking-kwargs",
        type=json.loads,
        default={"enable_thinking": False, "thinking": False},
        help="chat_template_kwargs that disable thinking",
    )
    parser.add_argument(
        "--skip-tools",
        action="store_true",
        help="skip tool scenarios (server without a tool parser)",
    )
    parser.add_argument(
        "--only",
        nargs="*",
        default=None,
        help="run scenarios whose name contains any of those",
    )
    parser.add_argument("--json-out", help="write all outcomes to this file")
    args = parser.parse_args()

    base_url = args.base_url.rstrip("/")
    args.openai = openai.OpenAI(
        base_url=f"{base_url}/v1",
        api_key=args.api_key,
        timeout=args.timeout,
        max_retries=0,
    )
    args.anthropic = anthropic.Anthropic(
        base_url=base_url,
        api_key=args.api_key,
        timeout=args.timeout,
        max_retries=0,
    )

    selected = {
        name: spec
        for name, spec in scenarios(args).items()
        if not (args.skip_tools and spec[0])
        and (not args.only or any(word in name for word in args.only))
    }
    report = []
    started = time.time()
    with ThreadPoolExecutor(args.concurrency) as pool:
        futures = {
            (name, stream): [
                pool.submit(run_trial, fn, stream) for _ in range(args.trials)
            ]
            for name, (_, fn) in selected.items()
            for stream in (False, True)
        }
        for (name, stream), jobs in futures.items():
            outcomes = [o for job in jobs for o in job.result()]
            report.append((name, stream, outcomes))

    print(f"\nmodel={args.model} trials={args.trials} ({time.time() - started:.0f}s)\n")
    print(
        f"{'scenario':38} {'mode':7} {'pass':>7} {'BUG':>4} {'MODEL':>5}"
        f"{'ERROR':>5} {'exercised':>9}"
    )
    totals = Counter()
    for name, stream, outcomes in report:
        counts = Counter(o.category for o in outcomes)
        totals.update(counts)
        exercised = sum(o.exercised for o in outcomes)
        print(
            f"{name:38} {'stream' if stream else 'full':7} "
            f"{counts['PASS']:>3}/{len(outcomes):<3} {counts['BUG']:>4} "
            f"{counts['MODEL']:>5} {counts['ERROR']:>5} "
            f"{exercised:>4}/{len(outcomes):<4}"
        )
    print()
    for name, stream, outcomes in report:
        for outcome in [o for o in outcomes if not o.ok][:2]:
            mode = "stream" if stream else "full"
            print(f"[{outcome.category}] {name} ({mode}): {outcome.detail}")

    if args.json_out:
        with open(args.json_out, "w") as f:
            json.dump(
                [
                    {"scenario": name, "stream": stream, **outcome.__dict__}
                    for name, stream, outcomes in report
                    for outcome in outcomes
                ],
                f,
                indent=1,
            )

    print(
        f"\nPASS={totals['PASS']} BUG={totals['BUG']} MODEL={totals['MODEL']} "
        f"ERROR={totals['ERROR']}"
    )
    return 1 if totals["BUG"] or totals["ERROR"] else 0


if __name__ == "__main__":
    sys.exit(main())
```

## Details

**Why not track reasoning in the detokenizer.** #62095 and #52486 let the detokenizer follow the reasoning boundary from parser signals (`reasoning_end_token_ids`, `is_reasoning_end_streaming`, start and end marker token sequences). Checked against the 39 reasoning parsers, this covers about 18:
- The detokenizer must re-implement each format's logic, which drifts from the real parser (Gemma 4's first-delta heuristic, formats that start in content).
- Stateful parsers never see input in the detokenizer's copy, so they never decide (`hunyuan_a13b`, `minimax_m3`).
- Channel formats have no end marker (Muse Glimmer `to=self`/`to=user`, gpt-oss Harmony `analysis`/`final`).
- Reasoning parsers do not know about tool calls. That depends on the tool parser and on the request's `tools` and `tool_choice`.

Only the serving layer's combined `Parser` (reasoning and tool parser) knows which text is the answer, and the inputs it needs exist only there. The engine does not know the tool parser or `--enable-auto-tool-choice`, and `tools`, `tool_choice` and `include_reasoning` are not sent to it (`EngineCoreRequest` only carries `chat_template_kwargs`).

Feeding the serving parser's decisions back to the detokenizer does not work either. The order is detokenize, stop check, queue, then serving `parse_delta`, so the decision always arrives at least one step late. It arrives later when the queue merges steps, and non-streaming (`FINAL_ONLY`) requests do not parse during generation at all.

**Change.** Serving builds a parser per request, and the detokenizer runs it right before the stop check, in the same step:

```
chat serving (per-request decision)
  └─ generate(..., content_filter_factory)    # a new parser instance per output sequence
       AsyncLLM.add_request -> factory()        # called per child when n > 1
         OutputProcessor.add_request -> RequestState
           Detokenizer.update():
             1) detokenize
             2) content_filter(delta_text, delta_token_ids, finished)
                  = dedicated parser.parse_delta(...).content   # same call as streaming
             3) match stop strings only in the accumulated content
             4) map the match back to the output text, truncate output_text
                and drop tokens generated past it
```

- **Position mapping.** Content need not equal the output text: parsers remove markers (Kimi, Harmony, Muse) or add text (`minimax_m2_append_think`). Each content piece is located at its latest position in the output text, or, if it is not there verbatim, aligned as a subsequence and recorded per contiguous run.
- **Late content.** When a parser holds content back because it may be a marker, the output is still cut at the right place, also in text generated in earlier steps. `min_tokens` only limits matching in the step that crosses its boundary.
- **Fallback.** If the content filter raises, the request falls back to full-text matching instead of failing.

| Layer | Files | Change |
|---|---|---|
| Serving | `serving.py`, `batch_serving.py` | Applicability check; builds and passes the per-request factory |
| Parser | `abstract_parser.py` | `Parser.stop_string_content_filter()`: runs `parse_delta` on a dedicated instance and returns the content |
| Engine client | `protocol.py`, `async_llm.py`, `output_processor.py` | Pass `content_filter_factory`, called per sequence (`n > 1` children). Streaming-input requests raise `NotImplementedError` |
| Detokenizer | `detokenizer.py` | `ContentFilter` type, content matching, position mapping. Existing matching moved to `_find_stop()` unchanged |

Engine core and `EngineCoreRequest` are unchanged, so the serialization between processes is the same.

**Dependency on #64062.** With stop strings, the detokenizer holds back text but not its token ids, so serving parsers that match markers by token id get misaligned input: `qwen3` + `hermes` streams duplicated `}}` in tool call arguments, and `glm47` loses them. This bug is on `main` too, but there a stop string in the arguments usually ends the tool call first. This PR lets tool calls finish, so it exposes the bug: without #64062, streamed `chat/tool_call` failed 10/10. The content filter itself is not affected, since `Detokenizer.update()` passes it the text and token ids of the same step.

**Behavior change.** Stop strings match only the answer content that the client receives, which matches how the OpenAI and Anthropic APIs apply stop sequences to output text. A stop string in reasoning or tool call arguments no longer ends the response.

**Limitations.**
- **Cost.** About 13 us per token (measured with `qwen3`) in the API server's output loop, only for requests with stop strings and a parser. Streaming requests parse twice. Sharing the parse result with serving is possible as a follow-up.
- If a parser holds content back longer than `stop_buffer_length` and the stop string matches inside it, a streaming response may already contain some text after the stop string.
- `/v1/responses`, the derenderer and beam search are not covered yet.

**Related PRs.**
- #62095, #52486: track the reasoning boundary in the detokenizer; see above for why this PR uses the serving parser instead and why it also covers tool calls.
