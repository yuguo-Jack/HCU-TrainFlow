# [CI] Add DFlash/DSpark issue labeling and Spec Decode matching

[Upstream PR](https://github.com/vllm-project/vllm/pull/63377) · state: open · merged: False

## Original PR description



## Overview

Apply the existing `dflash` label to issue titles containing whole-word DFlash or DSpark, and recognize “spec decode” for `speculative-decoding`. Related: #62939 (labeling example only; this does not fix or close its startup bug).

## Claims

- Match DFlash and DSpark case-insensitively in issue titles using the existing whole-word keyword matcher.
- Add “spec decode” alongside the existing speculative-decoding title phrases.
- Preserve the shared `dflash` label established in #51459 and Ben Chislett’s [DSpark coverage feedback](https://github.com/vllm-project/vllm/pull/51459#discussion_r3770987282); no separate `dspark` label or PR-labeling changes.

Includes #62939’s exact title, mixed/lower/upper capitalization, punctuation, longer-word negatives, unrelated titles, body-only negatives, existing labels, and comparison of every existing configured term in title/body against the baseline.
- #62939’s title produces no labels before this patch and both `dflash` and `speculative-decoding` afterward.
- `.venv/bin/pre-commit run --files .github/workflows/issue_autolabel.yml` — all applicable hooks passed, including actionlint.

## Details

The issue workflow has no `dflash` rule, and its speculative-decoding phrases omit the shorthand used in #62939. This adds seven configuration lines and reuses the existing case-insensitive word-boundary and substring matching logic. Issue bodies remain excluded for these terms.

Duplicate-work checks read #62939 and its comments, searched open PRs referencing it, and searched DFlash/DSpark labeling and issue-autolabel work. No open PR addresses this labeling gap. #63225 addresses the underlying startup failure; #62540 adds unrelated Reflection Beam labeling; #51459 is the merged predecessor establishing the intentional DFlash/DSpark grouping.
