# [Bugfix][Spec Decode] Derive num_speculative_tokens from a speculators draft config

[Upstream PR](https://github.com/vllm-project/vllm/pull/44566) · state: open · merged: False

## Original PR description

## Overview

When the target is `--model` and a speculators-format draft is supplied through `--speculative-config`, config conversion drops the draft's proposal count. Preserve it so `num_speculative_tokens` can be omitted.

Refs #40382. Its attention-backend issue was fixed by #40394; this fixes the remaining config default.

## Claims

- Explicit values win; otherwise non-DSpark drafts prefer `n_predict`, then `num_lookahead_tokens`.
- DSpark keeps its existing block-size default. Inferred values and their source are logged.

## Validation

On candidate `4a93c6d54a`, the following tests passed on an RTX 5090 (64 tests):

```bash
python -m pytest -q \
  tests/config/test_speculative_draft_hf_overrides.py \
  tests/config/test_speculative_draft_limits_max_model_len.py \
  tests/config/test_speculative_draft_max_position_embeddings.py \
  tests/transformers_utils/test_speculators_override.py \
  tests/transformers_utils/test_speculators_dspark_config.py
```

The configuration probe selected 3 tokens when omitted and preserved an explicit value of 2. Restoring main's conversion method reproduced the missing-token-count error. Local checks and the two directly affected CPU test files also passed (42 tests).

Real inference with Llama-3.2-1B-Instruct and its Eagle3 speculator completed four prompts per mode: ordinary decoding, inferred 3 tokens, and explicit 2 tokens. With `VLLM_BATCH_INVARIANT=1`, all three outputs matched token-for-token, as did main `94a29d316e8c` with explicit counts and the candidate (24 requests total). These runs used BF16, eager execution, and up to 32 output tokens. Without batch invariance, all requests completed, but exact token comparisons varied, including ordinary decoding across runs; the equality result applies to the batch-invariant comparison.
