# [Refactor][KV Connector] Share the Prometheus registration between NIXL and Mooncake

[Upstream PR](https://github.com/vllm-project/vllm/pull/63437) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`NixlPromMetrics` and `MooncakePromMetrics` each hand-wrote the same Prometheus plumbing: one metric per stats key, one labeled child per engine, and an `observe()` that walked the stats payload. That code now lives in `KVConnectorPromMetrics`, so each connector only declares which series it publishes. Split out of #56939 at review.

The scope is these two connectors. Offloading, Mooncake store, HiSparse and HF3FS keep their own implementations.

## Claims

- A connector now publishes its series with `HistogramSpec` / `CounterSpec`; the base class registers them per engine and records the payload into them.
- Exported series, labels, buckets and values are unchanged, apart from two NIXL help strings that lose a typo (`transfers` → `transfer`, plus a stray double space).
- The bucket edges the two connectors had copied move into the shared module. A connector that needs different edges passes its own tuple.

## Details

The two copies had drifted already. Mooncake summed each interval's failures before one `inc()`; NIXL incremented per event. NIXL's counter also had to merge three stats keys into one series (transfer, handshake and notification failures). Both are now ordinary declarations.

- `HistogramSpec(stats_key, name, documentation, buckets)` — one series and the stats key that feeds it.
- `CounterSpec(stats_keys, name, documentation)` — one series and the stats keys whose event counts it sums. An empty key list fails when the class body is evaluated.

The base class registers every declared series at construction and its `observe()` records a payload into them. Counter totals are unchanged: each failure event appends 1, so summing then incrementing once lands on the same value with one client call per series.

Things a reviewer may stumble on:

- The per-series attributes (`self.nixl_histogram_xfer_time`, `self.counter_mooncake_num_failed_recvs`) are gone. Nothing in the repository read them.
- `observe()` is now concrete in the base class. A subclass that declares nothing and does not override it raises `NotImplementedError`, as before.
- Stats keys stay plain strings. Every declared key is driven through the connector's own payload by the export tests in `test_nixl_stats.py` and `test_mooncake_stats.py`, so a rename fails there with a `KeyError` rather than reporting zeros at runtime.
- Connectors with other shapes keep their own code: offloading (dynamic label values), Mooncake store (`operation`/`status`), HiSparse (gauges, sampled histograms, registration behind a config flag), HF3FS (scalar counters), `MultiConnector` (dispatch only).

#55969 (open) proposes a broader declarative scheme for connectors whose stats payload describes itself. This change does not require that payload shape: it reads the existing `dict[str, list]` payloads and leaves the stats containers alone, so the two can coexist.

No open PR shares this plumbing. #56939 is merged and only adds the Mooncake series.
