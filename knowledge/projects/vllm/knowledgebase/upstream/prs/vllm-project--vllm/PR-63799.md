# [Docker][Doc] Request the video driver capability for the NVDEC video decoder

[Upstream PR](https://github.com/vllm-project/vllm/pull/63799) · state: closed · merged: False

## Original PR description

## Overview

Request the `video` NVIDIA driver capability in the `vllm-openai` image family and document it for the `pynvvideocodec` (NVDEC) video decoder backend, which otherwise fails to load `libnvidia-encode.so.1` / `libnvcuvid` inside containers.

## Claims

- `VLLM_VIDEO_LOADER_BACKEND=pynvvideocodec` works out of the box in `vllm/vllm-openai` (and the `vllm-sagemaker` / `vllm-openai-nonroot` targets) on hosts where the NVIDIA container runtime honors `NVIDIA_DRIVER_CAPABILITIES`.
- The NVDEC section in `docs/features/multimodal_inputs.md` now states the driver-capability requirement next to the existing MPS and `--mm-ipc-gpu-memory-gb` requirements, with the `docker run -e` form for images built from a plain CUDA base.
- No behaviour change for the default `opencv` decoder; the extra capability only mounts the driver's video libraries.

## Validation

- Root cause: the CUDA base image sets `NVIDIA_DRIVER_CAPABILITIES=compute,utility`; the NVIDIA container runtime mounts `libnvcuvid.so` / `libnvidia-encode.so` only when `video` is requested (NVIDIA Container Toolkit docs, "Driver Capabilities"). With `PyNvVideoCodec` installed from `requirements/cuda.txt` but no `video` capability, decoder creation on the first video request raises `Failed to load NVENC library: libnvidia-encode.so.1`; after `-e NVIDIA_DRIVER_CAPABILITIES=compute,utility,video` the same request decodes on NVDEC. Observed on a B200 host with an image derived `FROM vllm/vllm-openai:v0.30.0` (which inherits the base image's capability list unchanged) and a video prompt; the published image itself was not re-run, which is one reason this is a draft.
- `pre-commit run typos` and `markdownlint-cli2` pass on the touched files.
- Draft until someone with a CI-built image confirms the ENV lands in the `vllm-openai` final stage (it is set in `vllm-openai-base`, which all three targets derive from).

## Details

Setting the variable in the image is the same approach other CUDA media images use; it does not require the host to have a video-capable GPU and is ignored by runtimes that do not implement capability filtering. Users who build their own image from a CUDA base image still need to set it themselves, which the doc note covers. An alternative would be to fail with an actionable message from `vllm/multimodal/video_decoders/pynvvideocodec.py` when the library is missing; that can be a follow-up and does not remove the need for the capability.
