# [CI][ROCm] Fix order-dependent test_rocm_aiter_sampler_defers_import (CPU tensors hit Triton)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62213) · state: closed · merged: True

## Original PR description

## Purpose

Fix the `:amd: (MI355 DPX) V1 Sample shard 1/2` failure on main. It has failed on every main build since [95584](https://buildkite.com/vllm/ci/builds/95584):

```
FAILED tests/v1/sample/test_topk_topp_sampler.py::test_rocm_aiter_sampler_defers_import_when_generators_force_native
ValueError: Pointer argument (at 0) cannot be accessed from Triton (cpu tensor?)
```

**Root cause:** `test_rocm_aiter_sampler_defers_import_when_generators_force_native` (added in #44823) builds `logits`/`k` with no device. When generators are present, the forward goes through the native path, so `apply_top_k_top_p` → `apply_top_k_top_p_triton` runs, which needs GPU tensors. The test only passed because an earlier test file in the same shard leaked a GPU default device. Runtime auto-sharding rebalanced the shards at 95584 (shard 1 went from 236 to 203 tests), so that file no longer runs first and the test now gets CPU tensors. None of the commits between 95583 (pass) and 95584 (fail) touch sampling.

**Fix:** create the test tensors on `DEVICE_TYPE` explicitly.

**Not a duplicate:** no open PR touches this test (searched by test name).

## Test Plan

Not run locally (no ROCm host). CI for the MI355 V1 Sample step will confirm.
