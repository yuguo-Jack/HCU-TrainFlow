# [CI][Test] Use file:// rendezvous in MoE parallel_launch to fix EADDRINUSE flakes

[Upstream PR](https://github.com/vllm-project/vllm/pull/58312) · state: open · merged: False

## Original PR description

## Summary

`tests/kernels/moe/parallel_utils.py::parallel_launch` builds its NCCL rendezvous as `tcp://localhost:<get_open_port()>`. `get_open_port()` closes its probe socket before the spawned workers' `TCPStore` binds it, so on busy CI hosts another process can claim the port in between — producing intermittent `torch.distributed.DistNetworkError: ... EADDRINUSE` failures that pass on retry.

Example: B200 FusedMoE Layer Kernels, build 90548 — `test_deepep_v2_moe` failed with `EADDRINUSE` on port 41137; main's latest run of the lane is green.

## Fix

Use a `file://` rendezvous in a `TemporaryDirectory` — no ports, no race. Same pattern the deepep-v2 config sweep already uses in `test_deepep_v2_moe.py`.

Affects all `parallel_launch` callers: `test_deepep_moe.py`, `test_deepep_v2_moe.py`, `test_deepep_deepgemm_moe.py`, `test_moonep_bf16_poc.py`.
