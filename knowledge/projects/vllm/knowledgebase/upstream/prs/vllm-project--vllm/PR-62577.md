# [Step5] Add opt-in TRT-LLM NVFP4, FP8 tail, and FA4 prefill

[Upstream PR](https://github.com/vllm-project/vllm/pull/62577) · state: closed · merged: False

## Original PR description

## Summary

Enable per-expert ModelOpt NVFP4 checkpoint loading and optional Step5 optimizations on upstream `main`.

- Add per-expert weight loading and the serialized NVFP4 QKV validation workaround.
- Enable experimental TRT-LLM MoE with `STEP5_TRTLLM_APPROXIMATE_SWIGLU=1`.
- Convert routed experts in layers 88–90 to FP8 with `STEP5_FP8_TAIL=trtllm`.
- Enable HD192 FA4 sliding-window prefill with `STEP5_FA4_HD192=1`, using a direct launcher without dependency patches.

All optimizations are opt-in. TRT-LLM activation approximation and FP8 conversion change numerical behavior.

## Validation

On GB300 with `inferactinc/step5-oss:swf-arm64-cu13-b68d986`:

- `bash /sweep/preflight.sh`: 35 local regression tests passed; eight attention cases matched the previous patched implementation bit-for-bit and passed CUDA graph replay.
- `bash /sweep/cupti.sh`: four kernel timings differed by less than 0.6%, using CUPTI, CUDA graphs, and cold L2.
- All applicable pre-commit checks, including mypy, passed.

Validation harnesses remain local; this PR contains six implementation files.

## Previous Performance and Accuracy Results

Earlier revision, TP4/MTP3, C256, 32K shared prefix + 8K input + 1K output:

| Metric | CUTLASS/BF16 control | TRT-LLM + FP8 tail + FA4 |
|---|---:|---:|
| Uncached input + output tok/s/GPU | 3,969.08 | 6,460.10 (**+62.76%**) |
| GSM8K accuracy | 97.42% | 97.12% |

These measurements precede the rebase and launcher refactor. Full-model performance and GSM8K were not rerun for this revision.

## Related Work

This extends merged Step5 support in #61727. Related #62550 implements PrimTS attention; this change adds ModelOpt loading and FA4/MoE optimizations.

AI assistance was used for implementation and validation.
