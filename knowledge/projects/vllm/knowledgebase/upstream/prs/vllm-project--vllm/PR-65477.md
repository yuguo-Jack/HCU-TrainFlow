# [Bugfix][Env] Lowercase VLLM_FLOAT32_MATMUL_PRECISION before torch sees it

[Upstream PR](https://github.com/vllm-project/vllm/pull/65477) · state: open · merged: False

## Original PR description

## Overview

`VLLM_FLOAT32_MATMUL_PRECISION` is declared `case_sensitive=False`, so `HIGH` passes validation, but the raw string went to `torch.set_float32_matmul_precision`, which only accepts lowercase. Torch warns and the mode stays `highest`.

## Claims

- `VLLM_FLOAT32_MATMUL_PRECISION=HIGH` (or `Medium`) now sets the intended precision instead of silently staying on `highest`.

## Validation

`python -m pytest tests/test_envs.py -q --noconftest`: new `test_float32_matmul_precision_env_is_lowercased` fails on main (`assert 'HIGH' == 'high'`, 1 failed, 60 passed), passes with the fix (61 passed). CPU only. Not a duplicate: the only same-bug PR, #36990, was closed by the stale bot on 2026-07-15 and nothing is open.

## Details

Lowercased in the env lambda, as `VLLM_TARGET_DEVICE` does. I left `env_with_choices` alone because existing tests pin its raw-casing return.
