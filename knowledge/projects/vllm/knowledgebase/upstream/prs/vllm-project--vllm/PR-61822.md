# [Docs][KV Offload] Document canonical_layout in the KV offloading usage guide

[Upstream PR](https://github.com/vllm-project/vllm/pull/61822) · state: open · merged: False

## Original PR description



## Overview

Document the `canonical_layout` option of the `OffloadingConnector` (added in #48414) in `docs/features/kv_offloading_usage.md`. The option was missing from the usage guide, so users had no way to find out how to share offloaded KV across engines with different tensor-parallel sizes.

## Claims

- Adds `canonical_layout` to the `kv_connector_extra_config` reference table.
- Adds a "Canonical Layout" section covering what the option does, a `vllm serve` example, how it affects secondary-tier storage namespaces (it must be enabled on every instance that shares a tier), the single-copy behavior for replicated KV (MLA / replicated GQA heads), and the supported configurations and limitations.
- Links the existing "Sharing `root_dir` across runs" tuning tip to the new section.

## Validation

- Docs-only change; no code paths are touched.
- Each statement was checked against the implementation: `vllm/distributed/kv_transfer/kv_connector/v1/offloading/config.py` (option parsing, per-layer certifiability gate), `.../offloading/canonical_mapping.py` (canonical page definition, format id), `vllm/v1/kv_offload/tiering/spec.py` (`_validate_canonical_refs` fail-closed errors), `vllm/v1/kv_offload/file_mapper.py` and the FS/OBJ/P2P managers (namespace collapse and `canonical_format` in the namespace hash), and `vllm/v1/kv_offload/cpu/gpu_worker.py` (scatter/gather copy path).
- `pre-commit run --files docs/features/kv_offloading_usage.md` passes (markdownlint, typos).
- The docs site was not built locally.

## Details

- The limitations list reflects the current certifiability checks. #51691 (draft) would add per-token-head KV quant support to the canonical layout; if it merges, that bullet should be removed.
- The section is written as user guidance: it describes the layout at the level needed to decide whether to enable it, not the copy-run mapping internals.
