# [Build] Prune docs and CI config from the sdist

[Upstream PR](https://github.com/vllm-project/vllm/pull/65485) · state: open · merged: False

## Original PR description



## Overview

Prune `docs/`, `docker/`, `recipes/`, `.buildkite/`, `.github/`, and `.agents/` from the sdist. The sdist drops from 49.7 MB to 23.7 MB, and the wheel built from it is unchanged.

## Claims

- The sdist shrinks by about 52% (49.7 MB to 23.7 MB on current `main`). The v0.33.0 sdist on PyPI is 47.1 MB.
- No build or test input is removed. `tests/`, `examples/`, `benchmarks/`, `tools/`, `rust/`, `csrc/`, `cmake/` and `requirements/` all stay.

## Validation

All runs are on `main` @ ff74259da3, using the release recipe `python setup.py sdist` (`.buildkite/scripts/upload-release-wheels-pypi.sh`).

| | sdist size | files |
|---|---|---|
| before | 49,732,506 B | 8,833 |
| after | 23,746,768 B | 7,973 |

- **What gets dropped:** diffing the two sdist file lists shows only the pruned directories go: docs (364 files), .buildkite (218), recipes (193), .github (44), .agents (23) and docker (18). Nothing is added.
- **CUDA configure:** a CMake configure from the extracted pruned sdist succeeds (`TORCH_CUDA_ARCH_LIST=9.0`, CUDA 13.0, Ninja). That covers `tools/build_deepgemm_C.py`, the external projects, and so on.
- **Wheel contents:** `VLLM_TARGET_DEVICE=empty uv build --wheel --no-build-isolation` works from both sdists. The two wheels have identical file lists (3,833 files, excluding dist-info).
- **Downstream packagers:** I checked conda-forge's [vllm-feedstock](https://github.com/conda-forge/vllm-feedstock). It builds from the PyPI sdist and runs `pytest ./tests/...` from it. Its patches only touch `CMakeLists.txt`, `cmake/`, `requirements/`, `tools/build_deepgemm_C.py` and `vllm/`, none of which are pruned.

I did not run a full CUDA compile from the pruned sdist. The configure step plus the identical file lists cover the files the build reads.

## Details

`pyproject.toml` enables setuptools-scm, and setuptools-scm's file finder adds every git-tracked file to the sdist. `MANIFEST.in` only ever added files, so the sdist shipped the whole repo. Half of it was `docs/assets`: a 7.3 MB HTML timeline, two architecture PNGs of 4.9 MB and 4.0 MB, and many screenshots.

There is no PyPA rule here. The [sdist spec](https://packaging.python.org/en/latest/specifications/source-distribution-format/) requires only `pyproject.toml` and `PKG-INFO`. The [package formats guide](https://packaging.python.org/en/latest/discussions/package-formats/) says sdists "commonly" include tests and docs. In the [discuss.python.org thread](https://discuss.python.org/t/should-sdists-include-docs-and-tests/14578), distro and conda-forge packagers asked for tests so they can run the suite. So `tests/` stays, as conda-forge relies on it. Docs, CI config and Dockerfiles go: the docs build from git on ReadTheDocs, and nothing downstream builds or tests from those directories.

Duplicate check: no open PR touches sdist contents. #54551 also edits `MANIFEST.in`, but it removes the `LICENSE` include, which is unrelated.
