# [CI] Disable jobs with unpinned runtime installs

[Upstream PR](https://github.com/vllm-project/vllm/pull/63609) · state: closed · merged: True

## Original PR description

## Overview

Temporarily disable the Tier 1 CI jobs that install the listed unpinned or range-pinned packages at runtime, including their affected AMD mirrors. This follows the merged Tier 2 disablement in #63608.

## Claims

- Disable **92 job declarations**: 70 top-level definitions and 22 affected AMD mirrors, across the main, standalone AMD, Intel and Ascend pipelines. Preserve the definitions as comments for restoration.
- Cover the KV connector installer and direct connector requirements installs, GGUF/BitsAndBytes plugins, Flint, tracing, regression, batch invariance, CPU params/tokenizers, affected Intel jobs, and Ascend NPU.
- Keep the AMD Model Executor and MoRI healthy EP baseline running as standalone jobs with their existing keys; their overridden commands do not perform the targeted installs.
- Document **118 newly untethered test files** in the coverage allowlist with installation-specific reasons.

## Validation

Passed on the final change:

```bash
.venv/bin/python -m pre_commit run --files $(git diff --name-only)
.venv/bin/python tools/pre_commit/check_buildkite_step_keys.py
git diff --check
```

All applicable pre-commit hooks passed, including the full test-tethering check triggered by the CI edits.

Additional local validation parsed every Buildkite YAML file and compared each changed YAML document with the base: only the intended definitions were disabled, the two unaffected AMD mirrors were preserved, and a shared dependency anchor was moved to its first surviving use without changing its value. The locally available ci-infra loader parsed 347 remaining step entries across all `ci_config*.yaml` configurations. A command-level inventory found no active installation matching the targeted package/script list.

The local pipeline generator also compared the preserved AMD jobs before and after: keys, execution, resources, dependencies and environment are retained, apart from the standalone-job display-label format and test-group metadata.

GPU/model evaluations and live Buildkite execution were not run. This PR changes CI scheduling, not model, serving or test implementations.

## Details

The requested mitigation is to stop scheduling jobs that resolve these packages at runtime until their install environments are locked. This is not a dependency-locking fix or a claim that every listed package is vulnerable. Coverage is intentionally reduced while the jobs are disabled.

Scope details:

- Quantization's `conch-triton-kernels` installs are already disabled by #63608, so there is no duplicate change here.
- Two Intel jobs directly install `requirements/kv_connectors.txt`; these are included along with the connector installer callers.
- The standalone Intel Server Test does not install `av`; it stays enabled. The main-pipeline Server Test that invokes `run-intel-ci-test.sh server` is disabled.
- `run-cpu-test-ppc64le.sh` has the listed unpinned installs, but no current repository CI definition calls it. There is no active ppc64le job to disable here; the unused script is unchanged.
- Preserve unaffected AMD overrides rather than dropping them with their NVIDIA parent. Restore the commented definitions and reconcile those standalone replacements/temporary allowlist entries when re-enabling.

Duplicate-work checks searched open PRs for CI disablement, unpinned installs and dependencies; no open PR implementing this disablement was found. #63608 is merged and addresses the separate Tier 2 list. No issue number was supplied.

AI assistance was used to prepare and validate this change.
