# [Bugfix][NIXL] Don't fail a completed KV transfer when telemetry is unavailable

[Upstream PR](https://github.com/vllm-project/vllm/pull/63787) · state: open · merged: False

## Original PR description

## Problem

`get_xfer_telemetry()` runs inside the `DONE` branch of `_pop_done_transfers`, after NIXL reports the transfer complete. The enclosing `except Exception` sends any telemetry error to `_handle_failed_transfer()`. A transfer that succeeded is then counted as failed.

Telemetry is optional. Builds compiled without it log `NIXL telemetry is disabled; ignoring telemetry requested through agent config` and raise `nixlNoTelemetryError`, even when the agent was created with `capture_telemetry=True`. The code turns telemetry on whenever `nixl_agent_config` imports. There is no capability check, and no code in the tree handles `nixlNoTelemetryError`.

## Impact

On a disaggregated prefill/decode deployment over the UCX backend with `nixl-cu13==1.4.1`, every request failed.

| | unpatched | patched |
|---|---|---|
| 60k-token prompt | `{"error":{"code":500}}` | streams content |
| `nixl_num_failed_transfers_total` | 17,960 | 0 |
| benchmark | every request failed | 3526 valid / 15 errors |

The guard restored serving with no other change. This also shows the KV transfers were correct the whole time.

## Why #57734 does not cover this

#57734 added `if res is None: return` to `record_transfer`. That handles a `None` return, not a raise. ai-dynamo/nixl#2271 turns the raise into a `None`, and it is still open. Released NIXL still raises, and `main` still calls `get_xfer_telemetry()` unguarded at `base_worker.py:3423`.

The two fixes work together. This one guards the exception path and needs no NIXL upgrade.

## Change

`nixl/base_worker.py`: add `_try_get_xfer_telemetry()`. It returns `None` and warns once instead of raising. The stats sample is skipped when telemetry is missing. The transfer is released and counted as DONE either way. Nothing changes for backends that give telemetry.

## Tests

`tests/v1/kv_connector/unit/test_nixl_connector.py`:

- `test_telemetry_exception_does_not_fail_completed_transfer` makes `get_xfer_telemetry` raise on a `DONE` handle. The request must land in `done_req_ids`, the handle must be released, and no failure must be recorded. Without the guard this test does not pass, so it pins the bug.
- `test_telemetry_still_recorded_when_available` pins the no-change case.

Both pass on the `vllm/vllm-openai:nightly` image with this branch on `main` at `4f140a2`. `ruff check` and `ruff format` pass on both files.
