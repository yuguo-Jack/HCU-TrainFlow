# [Bugfix] Register fused_qk_rmsnorm_rope_gate as a custom op to fix AOT compile cache loading ( #64204 fix )

[Upstream PR](https://github.com/vllm-project/vllm/pull/64210) · state: open · merged: False

## Original PR description

## Overview

Fixes #64204. AOT compile cache never loads for Qwen3-Next / Qwen3.5 because the fused QK-norm/RoPE/gate Triton kernel is launched directly inside the compiled graph. This registers it as a vLLM custom op. Also fixes the UTF-8 encoding issue in `_compute_code_hash` noted in the same issue.

No existing open PR addresses this (searched for `id_to_kernel` and `fused_qk_rmsnorm_rope_gate`; related PRs touch overflow/M-RoPE/ROCm, not cache loading).

## Claims

- Warm starts of Qwen3-Next / Qwen3.5 load the AOT-compiled artifact instead of failing with `Kernel index 1 not found in id_to_kernel` and recompiling (~29s per start in the report).
- Compile-cache code hashing no longer fails on non-ASCII source files on Windows.

## Validation

- New CPU test `test_fused_qk_norm_rope_gate_traces_as_custom_op`: fails on `main` (tracing enters the raw Triton launch), passes with this PR.
