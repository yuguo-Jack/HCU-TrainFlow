# [Feature][Parser] Stream strict nested string arguments in Qwen XML

[Upstream PR](https://github.com/vllm-project/vllm/pull/65011) · state: open · merged: False

## Original PR description



## Overview

Stream text inside schema-constrained Qwen XML array/object arguments before the parameter closes. A `write_file(files=[{file_path, content}])` call keeps its array and final argument representation while exposing long file content progressively.

## Claims

- Enable nested streaming only when the request still carries the exact server-attached parameter grammar, for tools constrained to containers with string leaves.
- Preserve append-only argument prefixes and the existing final JSON representation on supported inputs, including chunked escapes and Unicode.
- Keep buffering for non-strict tools, unsupported schemas, disabled constraints, and requests whose constraint provenance is unavailable. No new dependency or public API field is introduced.
- Change argument visibility, not model generation throughput or tool execution/atomic commit semantics. Clients must accumulate and validate the complete call before execution.

## Details

`ParserEngine._safe_arg_prefix` deliberately withholds a trailing container because reparsing/coercion can otherwise invalidate emitted text. This change opts in only to a constrained subset: inline string schemas, homogeneous arrays, and objects with `additionalProperties: false` and every declared property required. References, unions, numeric/boolean/null leaves and optional object fields keep the current path.

The common adjustment path records the installed structural tag and uniquely named strict tools. That small metadata addition is necessary because request rendering constructs the grammar and response parsing uses a different parser instance. It does not alter another parser's conversion behavior or reuse the reasoning-sensitive `_grammar_from_parser` flag. Format unions, replaced grammar and serialized requests without the private metadata do not enable this path.

The Qwen-specific incremental scanner handles only appended text and normalizes JSON whitespace/escapes to the existing converter's representation. It reuses the existing parameter extender and final prefix-consistency check. Reset, multiple calls/files, disabled argument streaming, truncation and fallback gates are covered. The outer argument object is not closed speculatively.

The pre-existing XML delimiter limitation remains: literal `</parameter>` or `<parameter=` inside a JSON string may be read as markup even under JSON constraints. The added regression verifies that the stream does not complete a file batch in this case; this PR does not claim general XML escaping support.

Proxies must preserve tool-schema constraints, including `additionalProperties: false` and `strict` when supplied. If the effective constraints no longer satisfy the eligibility checks, nested arguments retain the existing buffered behavior.

Related work: merged [#46351](https://github.com/vllm-project/vllm/pull/46351) enabled top-level strings. Open [#63385](https://github.com/vllm-project/vllm/pull/63385) repairs/coerces argument types and preserves prefixes; [#55574](https://github.com/vllm-project/vllm/pull/55574) recursively coerces decoded container children. This PR adds earlier nested visibility under an active strict grammar, rather than general coercion. Those overlapping internals will require rebasing/retesting if either lands first; combined compatibility is not claimed.

Also checked before submission: [#53739](https://github.com/vllm-project/vllm/pull/53739) handles completion of unextendable/truncated prefixes, and [#59145](https://github.com/vllm-project/vllm/pull/59145) aligns grammar markers with parser token IDs. Neither implements the strict nested-string visibility path proposed here; combined compatibility has not been tested.
