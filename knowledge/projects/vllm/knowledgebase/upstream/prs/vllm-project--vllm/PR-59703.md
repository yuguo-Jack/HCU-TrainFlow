# [KV Offload] Preserve group classification on placeholder events

[Upstream PR](https://github.com/vllm-project/vllm/pull/59703) · state: open · merged: False

## Original PR description

## Overview

Preserve cache-group classification on hybrid offload placeholder events so consumers can distinguish recurrent-state placeholders from malformed FullAttention events.

Dynamo companion: https://github.com/ai-dynamo/dynamo/pull/15535.

## Claims

- Include kind/window metadata on placeholder stores.
- Retain scheduler group specs across tracker resets, including removals before stores.
- Leave FullAttention payload construction and unknown-group behavior unchanged.

## Validation

CPU validation: **30 event tests + 1 scheduler regression passed**, with four offline model-config tests deselected. The scheduler regression fails on unpatched main. Ruff and whitespace checks passed.

Tests: `tests/v1/kv_connector/unit/offloading_connector/test_events.py` and the scheduler’s `partial_tail_store_uses_attention_and_recurrent_cow_sources` regression.

Earlier paired vLLM/Dynamo smoke: 12 requests completed; four first-use receiver requests each received 32,000 cached tokens, with no quarantine or restarts. This preceded the rebase; current-main validation is CPU-only, not a failover or performance claim.

## Details

Group specs describe event shape, not residency. Preserve that classification without inventing token IDs or nonzero block sizes.

AI assistance was used; every changed line was reviewed by the submitter.

- vMaroon · comment · 2026-10-14T14:01:34Z · [source](https://github.com/vllm-project/vllm/pull/59703#discussion_r4271783340)

File: `vllm/distributed/kv_events.py` · line None

I think we should keep the classification on the placeholder `BlockStored` and leave `BlockRemoved` as is.

https://github.com/vllm-project/vllm/pull/60616 defines a removal for a hash the consumer does not hold as a no-op. With this PR every offloading `BlockStored` carries kind, so a consumer learns a group from its first store, and a `BlockRemoved` for a group it hasn't learned can only name blocks stored before it subscribed, which it never indexed. So that case is already a no-op under the contract, and the fix belongs in the companion's `UnlearnedGroupIdx` handling for removals rather than in the shared schema.

The fields would also only cover this producer: `BlockPool._emit_block_removed_events` (GPU and SimpleCPU) doesn't set them. If a consumer needs classification before any event, `EngineCore.get_kv_cache_group_metadata` already serves kind and sliding window per `group_idx`.

If we keep them, they need rows in the `BlockRemoved` table in `docs/features/kv_events.md` and entries in `OPTIONAL_FIELDS` in `test_kv_events_contract.py`. nit: the new docstring should go below its field; as placed it attaches to `ownership`.
