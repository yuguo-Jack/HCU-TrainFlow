# [Bugfix][MoRIIO] Fail startup when notify listener cannot bind

[Upstream PR](https://github.com/vllm-project/vllm/pull/60743) · state: open · merged: False

## Original PR description

## Overview

Fail MoRIIO startup when its notification listener cannot bind instead of allowing the server to start and report healthy without a working listener. Fixes #60473.

## Claims

- Wait for the notification listener to bind successfully before `MoRIIOWrapper.async_wait_reqid()` returns.
- Propagate listener initialization failures to the startup caller as `HandshakeError`.
- Clear failed thread state so later calls cannot mistake a dead listener for a working one.
- Preserve ZeroMQ socket ownership and message processing in the listener thread.
- Add a CPU regression test that reproduces the failure with a real occupied TCP port.

The issue reporter independently validated the production change from `a19e110541` on an MI355X node using `vllm/vllm-openai-rocm:v0.31.0`. The changed `moriio_engine.py` was applied to the image rather than building the complete branch:

- With the notification port occupied, the unmodified decode completed startup, reported healthy, and later hung. With this change, it failed during startup with the expected `HandshakeError`.
- Without a port conflict, 1P1D XGMI tests passed in both WRITE and READ mode. All four requests returned HTTP 200, and the reported metrics confirmed that prompt KV was transferred through MoRIIO.

Full validation details are available in [the issue comment](https://github.com/vllm-project/vllm/issues/60473#issuecomment-6069197305).

## Details

`async_wait_reqid()` previously started a daemon thread and returned before that thread bound its ZeroMQ socket. If the port was already occupied, the exception terminated only the daemon thread. Startup continued, health checks passed, and later calls skipped listener creation because `notify_thread` was already set.

This change uses a one-result `Queue` to report successful socket binding or the initialization exception to the caller. Socket creation, use, and cleanup remain in the listener thread. Message receiving remains asynchronous after startup succeeds.

The change intentionally covers listener initialization failures. Detecting a listener that dies later during message processing remains outside this scope.

Open PR searches by `#60473`, `async_wait_reqid`, and MoRIIO notification-listener terminology found no overlapping implementation before the branch was pushed.
