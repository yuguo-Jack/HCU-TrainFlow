# [Model] Support MTP drafts in the Transformers modeling backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/61270) · state: closed · merged: True

## Original PR description



## Overview

Serve the MTP layers of any model that opts into the Transformers MTP standard (huggingface/transformers#46229) as a speculative decoding draft in the Transformers modeling backend.

Draft: depends on huggingface/transformers#49544, which adds the `MtpModel` helpers this uses (`forward_layer`, `get_mtp_weights_regex`, `get_weight_conversions`) so vLLM shares the per-layer logic and weight loading with Transformers instead of duplicating them. The minimum version is set to 5.20.0, assuming that PR lands in it.

## Claims

- `--speculative-config '{"method": "mtp", ...}'` works for targets on the Transformers backend whose config sets `num_mtp_layers` (`TransformersForMTP` / `TransformersMoEForMTP`)
- MTP weights are found and renamed by the same `MtpModel` helpers as `MtpModel.from_pretrained`, so new checkpoint layouts only need the Transformers-side mapping
- Multi-module MTP: `spec_step_idx` selects the MTP layer, so `num_speculative_tokens > 1` uses every checkpoint layer
- Covers DeepSeek-V3/R1 and GLM-4.5/4.6/4.7 today, and Mellum with huggingface/transformers#49531

## Validation

GLM-4.5-Air, B200, TP=4, gsm8k (before the `speculative.py` refactor and the switch to the `MtpModel` helpers; to re-run):

| Config | Native MTP | Transformers MTP |
| --- | --- | --- |
| n=1 acceptance | 95.9% | 95.8% |
| n=3 mean acceptance length | 3.13 | 3.15 |
| n=3 per-position acceptance | 95.3 / 76.1 / 41.6% | 95.3 / 76.6 / 42.7% |

Mellum (huggingface/transformers#49531 + #49468, before the switch to the helpers): on a tiny checkpoint in Mellum's `mtp.*` layout, the draft's MTP weights equal those loaded by `MtpModel.from_pretrained` (CPU).

Tiny Llama checkpoint with an appended MTP layer (CPU, against huggingface/transformers#49544): the draft builds as `TransformersForMTP` and its MTP weights load correctly.

```bash
pytest tests/models/transformers/test_backend.py -k mtp  # passed on B200
pytest tests/config/test_speculative_draft_hf_overrides.py tests/test_config.py -k "speculative or mtp or draft or hf_override"
# 98 passed, 1 failed (test_draft_model_enables_async_scheduling_by_default, also fails on main)
```
