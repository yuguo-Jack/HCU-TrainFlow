# [Bugfix][Frontend] Combine consecutive assistant messages in Anthropic requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/65414) · state: open · merged: False

## Original PR description



## Overview

Fixes #65411. `/v1/messages` now combines consecutive assistant messages into one assistant turn before converting them to chat messages, as the Anthropic API does: "Consecutive `user` or `assistant` turns in your request will be combined into a single turn."

## Claims

- A step sent as `assistant: [thinking]`, `assistant: [text]`, `assistant: [tool_use]` converts to the same chat messages as the same blocks in one assistant message, so the chat template renders one assistant turn. `/v1/messages/count_tokens` uses the same conversion and counts the same prompt.
- Histories without consecutive assistant messages convert as before.

## Validation

```
# the new tests against main's serving.py
pytest tests/entrypoints/anthropic/test_anthropic_messages_conversion.py tests/entrypoints/anthropic/test_messages.py -k consecutive
E       AssertionError: assert [{'content': ...': 'toolu_1'}] == [{'content': ...': 'toolu_1'}]
E       assert 54 == 49
2 failed, 144 deselected
# this branch
pytest tests/entrypoints/anthropic
164 passed
```

The server tests ran with `Qwen/Qwen3-0.6B` on an RTX 4070 Ti SUPER, with `VLLM_USE_FLASHINFER_SAMPLER=0` because FlashInfer's sampling JIT build fails on that machine. On main the split history counts 54 input tokens and the merged one 49.

Effect on a real model: vLLM 0.32.0 on one MI300X serving Qwen3.8-27B-FP8 (`--reasoning-parser qwen3 --enable-auto-tool-choice --tool-call-parser qwen3_coder`). The input is a recorded 21-message request that a gateway built from a Codex CLI Responses history, sent 10 times as recorded and 10 times with its consecutive assistant messages merged on the client, which is the merge this change makes on the server:

| History | Replies with `tool_use` |
| --- | --- |
| as recorded, each step split across assistant messages | 5 of 10 (7 of 10 in an earlier run) |
| consecutive assistant messages merged (11 messages) | 10 of 10 |

The replies without a call ended with `end_turn`.

## Details

`_convert_messages` maps each Anthropic message to one chat message. A gateway that builds a Messages history from item-based input, here vLLM Semantic Router translating Codex CLI's Responses history (being fixed on that side in vllm-project/semantic-router#5759), sends one assistant message per item, and the template renders each as its own assistant turn. The model then sees past turns that end in text with no call and ends its own turn the same way. The merge runs before conversion, so `_convert_message_content` sees one message with reasoning, text and tool calls, as it does when a client sends one message.

Only assistant messages are merged. A user message that mixes text and `tool_result` blocks is converted with its tool messages ahead of the user text, so merging consecutive user messages could reorder a history, and merging the assistant messages alone removed the effect above.

No open PR merges consecutive messages. #62894 changes how a final assistant message is continued and touches the same file, but not this behavior.
