# [ROCm][DI][CI]  Add DeepSeek-V3 NIXL accuracy steps

[Upstream PR](https://github.com/vllm-project/vllm/pull/62007) · state: closed · merged: True

## Original PR description

## Purpose

Add DeepSeek-V3 disaggregated prefill/decode accuracy steps that use NIXL over UCX RDMA on MI350, next to the existing MoRIIO steps. Read uses `NixlConnector`. Write uses `NixlPushConnector` for 1P1D TP8, 1P1D EP8, and 2P2D EP16.

The 2P2D EP16 write step needs https://github.com/vllm-project/vllm/pull/62055. That change keeps push heartbeats and outgoing WRITE polling on the writer thread, so a blocked NIXL call cannot miss an expert-parallel collective.

## Changes

- `pipeline-disagg.yaml`: six DeepSeek-V3 steps. Read (`NixlConnector`): 1P1D TP8, 1P1D EP8/DP8, 2P2D EP16/DP16. Write (`NixlPushConnector`): 1P1D TP8, 1P1D EP8/DP8, and 2P2D EP16/DP16.
- `run-slurm-disagg-test.sh`, `run_xPyD_disagg.slurm`: add `KV_CONNECTOR` (default `MoRIIOConnector`) and pass it to the containers. For NIXL, start vllm-router with `--kv-connector nixl` and fixed `--prefill`/`--decode` URLs, because NIXL has no discovery service.
- `vllm_disagg.sh`: when `KV_CONNECTOR` is `NixlConnector` or `NixlPushConnector`, use that name in the NIXL KV transfer config (UCX backend). On 2P2D EP16 prefill, set `--gpu-memory-utilization 0.75`. At 0.85 the AITER MoE sort buffer runs out of memory. EP8 stays at 0.85.
- `cluster.sh`: for either NIXL connector, set UCX defaults for the ionic RoCE NICs (RC verbs on `ionic_0`, GPU-direct RDMA) and run accuracy with one concurrent request. The router flag stays `--kv-connector nixl` for both.

MoRIIO steps do not change. All new settings apply only when `KV_CONNECTOR` is `NixlConnector` or `NixlPushConnector`.

Requirement: the image's UCX must support `rc_verbs` on ionic NICs that report `max_srq=0`. The results below used UCX 1.22 with that support. The 2P2D EP16 write result also used the writer-thread ownership from #62055.

## Test plan

UCX environment (the same on every node):

```bash
export UCX_TLS=rc_verbs,ud_verbs,tcp,self,rocm
export UCX_NET_DEVICES=ionic_0:1,lo
export UCX_IB_GID_INDEX=1
export UCX_UD_VERBS_ETH_DGID_CHECK=n
export UCX_IB_GPU_DIRECT_RDMA=yes
export UCX_RMA_PPLN_ENABLE=y
export UCX_PROTO_EMULATION_ENABLE=n
export UCX_KEEPALIVE_INTERVAL=inf
export UCX_UD_VERBS_RX_QUEUE_LEN=1024
export UCX_RCACHE_MAX_UNRELEASED=1024
```

KV config (`kv_role` is `kv_producer` on prefill and `kv_consumer` on decode):

```bash
KV='{"kv_connector":"NixlConnector","kv_role":"kv_producer","kv_load_failure_policy":"recompute","kv_connector_extra_config":{"backends":["UCX"],"kv_lease_duration":180}}'
```

Write uses the same commands with `"kv_connector":"NixlPushConnector"`.

TP8, prefill (port 8100) and decode (port 8200, `kv_consumer`):

```bash
vllm serve DeepSeek-V3 --host $PREFILL_IP --port 8100 --tensor-parallel-size 8 \
  --trust-remote-code --kv-cache-dtype fp8 --max-model-len 32768 \
  --gpu-memory-utilization 0.85 --kv-transfer-config "$KV"
```

EP8/DP8, prefill:

```bash
vllm serve DeepSeek-V3 --port 20005 -tp 1 --data-parallel-size 8 --data-parallel-size-local 8 \
  --data-parallel-address $PREFILL_IP --data-parallel-rpc-port 13345 \
  --enable-expert-parallel --all2all-backend mori_high_throughput --enforce-eager \
  --no-enable-prefix-caching --api-server-count 8 --trust-remote-code \
  --kv-cache-dtype fp8 --max-model-len 32768 --gpu-memory-utilization 0.85 \
  --kv-transfer-config "$KV"
```

EP8/DP8, decode: the same command with `--data-parallel-address $DECODE_IP`, `--all2all-backend mori_low_latency`, no `--enforce-eager`, `--gpu-memory-utilization 0.75`, and `kv_consumer`.

2P2D EP16/DP16 uses the same EP command with `--data-parallel-size 16` on four nodes. Prefill uses `--gpu-memory-utilization 0.75`. The second prefill node and the second decode node join headless with `--data-parallel-start-rank 8`. The router points only at the two masters. Write uses `NixlPushConnector` and the #62055 writer.

Router (`--intra-node-data-parallel-size 1` for TP8, `8` for EP8 and EP16):

```bash
vllm-router --vllm-pd-disaggregation --kv-connector nixl \
  --prefill http://$PREFILL_IP:8100 --decode http://$DECODE_IP:8200 \
  --worker-startup-timeout-secs 1800 --port 30000 --host 0.0.0.0 \
  --intra-node-data-parallel-size 1 --policy round_robin \
  --prefill-policy round_robin --decode-policy round_robin
```

For 2P2D EP16 the router uses `--worker-startup-timeout-secs 7200` and `--intra-node-data-parallel-size 8`.

Accuracy:

```bash
lm_eval --model local-completions --tasks gsm8k \
  --model_args model=DeepSeek-V3,base_url=http://127.0.0.1:30000/v1/completions,num_concurrent=1,tokenized_requests=False,trust_remote_code=True
```

Script checks: `bash -n` on all changed scripts, YAML parse, NIXL KV config parses as JSON, router arguments checked for 1P1D TP8, 1P1D EP8 and 2P2D EP16, `git diff --check`.

#### 1. 🔴 Blocking: Cross-node NIXL handshake fails or silently skips KV transfer: this PR never sets side-channel host to a routable node IP
`.buildkite/amd-disagg/cluster.sh:159-172`

The NIXL steps never set `VLLM_NIXL_SIDE_CHANNEL_HOST`, and `run_xPyD_disagg.slurm` does not forward it into the node containers, so it defaults to `localhost`. `NixlConnector` binds its handshake listener on that host (`base_scheduler.py` `_nixl_handshake_listener`), which means loopback only. It also advertises it as `remote_host` (pull) or `decode_host` (push). Only the Ray path fills in the node IP (`core.py:_set_nixl_side_channel_host`), and these steps use `docker run`. With prefill and decode on different nodes, the cross-node handshake cannot connect even if vllm-router rewrites the host. With `kv_load_failure_policy: recompute`, the step may fail or may pass accuracy without any KV transfer; export the node IP (e.g. `HOST_IP`) as `VLLM_NIXL_SIDE_CHANNEL_HOST`.

**How it is reached:** pipeline-disagg.yaml NIXL step (e.g. DeepSeek-V3-PD-1P1D-TP8-NIXL-vllm-router, KV_CONNECTOR=NixlConnector NODES=2) -> run-slurm-disagg-test.sh -> run_xPyD_disagg.slurm docker run (no -e VLLM_NIXL_SIDE_CHANNEL_HOST) -> vllm_disagg.sh node -> vllm serve --kv-transfer-config nixl_kv_cfg -> NixlConnectorScheduler.__init__ (base_scheduler.py:76, side_channel_host=envs default 'localhost') -> _nixl_handshake_listener binds tcp://localhost:port; pull_scheduler.py:284 / push_scheduler.py:180 advertise 'localhost' as remote_host/decode_host to a peer on another node

**Who is affected:** Every one of the six new NIXL/NIXL-PUSH CI steps, since prefill and decode always run on separate nodes and nothing sets VLLM_NIXL_SIDE_CHANNEL_HOST.

_Checked against the code by an independent pass._

#### 2. 🟠 Should fix: Broken NIXL KV transfer still passes accuracy: this PR sets kv_load_failure_policy to recompute
`.buildkite/amd-disagg/vllm_disagg.sh:110`

`nixl_kv_cfg` sets `kv_load_failure_policy` to `recompute`, overriding vLLM's default `fail`; the existing MoRIIO configs keep the default. When a NIXL handshake or transfer fails, the decode scheduler resets `num_computed_tokens` to 0 and prefills the prompt locally. The failure shows up only as a warning in the worker log. `run_accuracy` gates only on the gsm8k score, so these NIXL steps can pass even when KV transfer is broken. Use `fail` in CI, or also check that transfers succeeded (NIXL failure metrics or a log grep).

**Who is affected:** The six new DeepSeek-V3 NIXL/NIXL-PUSH CI steps on the amd_mi350_ainic queue.

_Checked against the code by an independent pass._

#### 3. 🟠 Should fix: DeepSeek-V3 gsm8k step likely fails with workload-timeout: this PR sets ACCURACY_NUM_CONCURRENT=1 without raising WORKLOAD_TIMEOUT_S
`.buildkite/amd-disagg/cluster.sh:171`

When `KV_CONNECTOR` is `Nixl*`, `cluster.sh` now defaults `ACCURACY_NUM_CONCURRENT` to 1 instead of 64, with no comment explaining why. The full gsm8k task (1319 requests, no `--limit`) therefore goes through P/D strictly one at a time, so concurrent KV transfers are never exercised. The new NIXL steps run with `WAIT=1` but do not override `WORKLOAD_TIMEOUT_S` (default 1800s in `run-slurm-disagg-test.sh`). That is about 1.4s per request, including the `lm_eval` install and dataset fetch, and a serial DeepSeek-V3 run will likely exceed it and be reported as `workload-timeout`. Document why concurrency is 1 and raise `WORKLOAD_TIMEOUT_S` on these steps, as the MiniMax 2P2D step already does (10800).

**Who is affected:** The six new DeepSeek-V3 NIXL / NIXL-push Buildkite steps on the mi350 SLURM cluster.

_Checked against the code by an independent pass._

#### 4. 🟠 Should fix: Nixl with ROUTER_TYPE=proxy returns 503 and fails lm_eval: this PR wires NIXL worker URLs only into vllm-router
`.buildkite/amd-disagg/run_xPyD_disagg.slurm:251`

`KV_CONNECTOR=Nixl*` combined with `ROUTER_TYPE=proxy` is accepted but cannot work. The in-container MoRIIO toy proxy (`start_proxy_bg`) only learns workers through ZMQ discovery, which NIXL servers never register with. `ROUTER_KV_ARGS` (the explicit `--prefill`/`--decode` URLs) is consumed only by the vllm-router launch. The backend health gate still passes, then every request gets 503 "No prefill or decode instances are registered" and `lm_eval` fails after its retries. No pipeline step uses this combination; consider rejecting it early in `run_xPyD_disagg.slurm` or documenting it.

**Who is affected:** Only someone who manually runs a NIXL connector with `ROUTER_TYPE=proxy`; all six added CI steps use `ROUTER_TYPE=vllm-router`.

_Checked against the code by an independent pass._
