# [Bugfix][Transformers] Infer mm encoder dynamic_arg_dims from forward signature

[Upstream PR](https://github.com/vllm-project/vllm/pull/63636) · state: open · merged: False

## Original PR description

## Overview

`compile_mm_encoder` on the Transformers backend crashes engine init with `ValueError: No dynamic dimensions found` for encoders whose `forward` leaves tensor inputs unannotated (SigLIP, Idefics3/SmolVLM) or uses legacy tensor types (`torch.BoolTensor`). This resolves the `dynamic_arg_dims=None` TODO by inferring the dims from the encoder's `forward` signature. Part of #63635 (blocker 1 of 3); not a fix for blockers 2 and 3 there, so no `Fixes`.

## Claims

- SmolVLM-256M and the SigLIP encoder (LLaVA-OneVision) no longer fail at decoration time; SmolVLM-256M now compiles its encoder end to end and generates the same tokens as with compile off.
- Encoders annotated `torch.Tensor` behave as before (InternVL3-1B-hf checked). The only difference is that legacy-typed arguments such as `bool_masked_pos` (`None` in these runs) are now also listed, and the decorator skips `None`.
- Does **not** make LLaVA-OneVision or Qwen3-VL work: they still fail further down in Dynamo (blockers 3 and 2 in #63635), unchanged by this PR.

## Details

- **Root cause:** `support_torch_compile` infers dynamic args only from `torch.Tensor` / `torch.FloatTensor` / `IntermediateTensors` annotations. SigLIP's `pixel_values` is unannotated; Idefics3 also takes a `torch.BoolTensor` mask that must be dynamic too. With only `pixel_values` marked, Dynamo raises `ConstraintViolationError ... specialized it to be a constant (119)` at `modeling_idefics3.py:167`.
- **Design:** `infer_dynamic_arg_dims` (in `transformers/utils.py`) returns dim 0 for each non-variadic `forward` parameter that is unannotated or annotated with a `torch` tensor type, including legacy ones. It matches the dim-0 assumption the existing warning documents (whose wording I updated). No per-model names, and no change to `support_torch_compile`.
- **Limitations:** an unannotated parameter that receives a non-`None`, non-tensor value raises `Unsupported dynamic dimensions` at call time. A scan of the 36 buildable encoders in transformers 5.9.0 found no such parameter, no string annotations and no `list[Tensor]`, but I have not run them all. `list[torch.Tensor]` would be treated as a tensor.
- **Not a duplicate:** no open or closed issue/PR covers `compile_mm_encoder` on the Transformers backend (searched on 2026-10-26). #63415 is the native RADIO/NaViT path in `radio.py`; #60202 is a separate positional-annotation bug in the decorator.
- **Owners:** `vllm/model_executor/models/transformers/` and `tests/models/transformers/` are `@hmellor`; the two-line `.buildkite/test_areas/models_basic.yaml` wiring is `@khluu @Harry-Chen`.
