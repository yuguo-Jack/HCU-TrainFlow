# [Bugfix][Model] Fix maximum image token profiling for Unlimited-OCR

[Upstream PR](https://github.com/vllm-project/vllm/pull/61946) · state: open · merged: False

## Original PR description

## Overview

Fix Unlimited-OCR's underestimated maximum image-token bound, which can reject valid images with a small encoder budget.

## Claims

- Use a 1×32 profiling crop grid to cover the maximum number of newline features.
- Correct the default per-image bound from 3553 to 3793 tokens.

## Validation

```bash
VLLM_TARGET_DEVICE=cpu .venv/bin/python -m pytest \
  tests/models/multimodal/processing/test_unlimited_ocr.py -v
```

- New regression: 1 passed; it fails on the original code. Existing processor regression tests: 9 passed. Pre-commit passed.
- Actual `baidu/Unlimited-OCR` serving, BF16 / TP=1, official nightly `0.32.0rc1.dev190+g3f1bcfd82`, using a 640×20480 image:

| `max_num_batched_tokens` | Original | Patched |
| --- | --- | --- |
| 2048 | HTTP 400: 3793 image tokens exceed the 3553 cache | HTTP 200 |
| 8192 | HTTP 200 | HTTP 200 |

Small, ordinary, tall and wide synthetic inputs were compared. Same-budget default compile/graph comparisons preserve output tokens and sampled-token logprobs exactly.

Serving used `TRITON_ALLOW_NON_CONSTEXPR_GLOBALS=1` for an unrelated nightly compile issue. Baseline OCR on some synthetic inputs is empty or incorrect; validation covers request acceptance and output regression, without an accuracy claim.

## Details

Both 4×8 and 1×32 grids contain 32 crops, but the latter has more feature rows and therefore more newline tokens. It reaches the true upper bound without changing inference computation.

No matching open fix was found. Related [#54527](https://github.com/vllm-project/vllm/pull/54527) concerns processor kwargs rather than this default crop-grid bound.
