# [ROCm][Step5] Enable shared Step5 Triton kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/61945) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Make the Step5 Triton kernels merged in #61727 usable on ROCm. This complements #61837's model/cache backend with shared fused operators.

## Claims

- Share preparation, summary, scoring, and gated attention kernels in `step5/common/ops`, with HIP-compatible math, launches, and pointer stores.
- Reuse `_prepare_main` for SWA preparation. Support 4/8/16 indexer heads; use BF16 dot operands on ROCm while retaining FP8 summary storage.
- Keep changing capacities, strides, and slot counts as runtime parameters to avoid recompilation.

## Validation

**27 kernel/adapter tests passed on MI355X.** Coverage includes fused preparation, gating, scoring, sparse decode, strided caches, and mixed prefill/decode requests.

Local integration with #61837 (`fcec113ec2`): **4×MI355X, TP4, Step-5-Preview FP8, BF16 KV, PIECEWISE graphs**. GSM8K: **97.04% (1280/1319)** with currency-compatible answer extraction.

| Workload | #61837 (`fcec113ec2`) | Local fused integration |
|---|---:|---:|
| GSM8K, 1,319 questions, concurrency 64 — elapsed time | 394.20 s | **366.88 s** |
| Random 8k/1k, concurrency 8 — output tokens/s | 189.54–192.50 | **211.94–214.79** |
| Random 8k/1k ±20%, concurrency 8 — output tokens/s | 185.54–187.35 | **210.00–210.88** |

Ranges span two runs with identical requests and settings across implementations. All four workers executed the fused paths; preparation JIT variants stayed constant through GSM8K and the serving benchmarks.

## Details

Shared kernels load without importing the NVIDIA model. E2E uses a local preparation/SWA adapter outside this PR and retains the current #61837 model dtypes, paged summary, top-k, and gated sparse decode. RMSNorm is unchanged by this PR.
