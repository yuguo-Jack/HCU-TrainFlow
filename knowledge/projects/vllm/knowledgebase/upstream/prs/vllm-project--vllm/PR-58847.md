# [Bugfix][Frontend] Parse split GLM tool-call markers

[Upstream PR](https://github.com/vllm-project/vllm/pull/58847) · state: open · merged: False

## Original PR description

## Purpose

Fixes #58315.

GLM required-tool grammar can emit `<tool_call>` and `</tool_call>` as ordinary sub-token sequences, while the streaming parser recognizes only their dedicated token IDs. In required-tool mode this mismatch can leave a valid tool call in the response content. This change lets the GLM parser opt into the textual marker forms after the actual reasoning-end token boundary, including the adapter path that skips reasoning parsing. Other parsers and automatic tool choice keep their existing behavior.

Alternative implementation: #59145 now addresses the same issue on the grammar side, binding marker strings to dedicated token IDs across engine parsers and required/named tool choice. This PR takes the narrower parser-side approach for GLM required-tool streams, accepting textual markers after the reasoning boundary. The approaches are alternatives and need a maintainer decision; this PR no longer claims there is no competing fix.
