# [ROCm] TurboQuant KV cache support for Gemma 4

[Upstream PR](https://github.com/vllm-project/vllm/pull/53231) · state: open · merged: False

## Original PR description


## Purpose

Enable TurboQuant KV cache quantization for Gemma 4 models on ROCm.

Gemma 4 has two architectural properties that blocked TurboQuant from working:

- Heterogeneous head dimensions — sliding-window layers use head_dim=256 while full-attention layers use global_head_dim=512. The existing Gemma4Config.verify_and_update_config forced a TRITON_ATTN backend override that conflicted with the TURBOQUANT backend.
- ROCm flash_attn head-dim limit — ROCm's CK-based flash_attn only supports head_dim ≤ 256. Full-attention layers with head_dim=512 caused a RuntimeError: CK only supports head dimension at most 256 at warmup.


Changes:

- vllm/v1/kv_cache_interface.py: Add TQFullAttentionSpec, a FullAttentionSpec subclass with TurboQuant-aware page_size_bytes (using tq_slot_size instead of the standard head_size × dtype formula) and a largest_block_size_within helper for page-size unification.
- vllm/v1/core/kv_cache_utils.py: Extend unify_kv_cache_spec_page_size to handle TQFullAttentionSpec layers whose page does not evenly divide the maximum page size by updating tq_slot_size to the padded value.
- vllm/model_executor/layers/attention/attention.py: Fall back to fp8 for sliding-window layers when the global dtype is turboquant_*; return TQFullAttentionSpec from get_kv_cache_spec for full-attention TurboQuant layers.
- vllm/v1/attention/backends/turboquant_attn.py: Add indexes_kv_by_block_stride (True) and supports_mm_prefix (True) classmethods; add _use_flash_attn per-instance flag that disables ROCm CK flash_attn for head_dim > 256; add _chunked_causal_attn fallback that processes queries in chunks to avoid OOM.
- vllm/model_executor/models/config.py: Skip the FA3/Triton backend override in Gemma4Config when a turboquant_* KV cache dtype is requested.
- vllm/platforms/rocm.py: Short-circuit to TURBOQUANT backend in get_attn_backend_cls for turboquant_* dtypes; exclude kv-first backends (ROCM_ATTN, ROCM_AITER_FA, ROCM_AITER_UNIFIED_ATTN) from get_valid_backends when TurboQuant is active.
- vllm/model_executor/layers/quantization/turboquant/config.py: Skip boundary-layer protection for models with heterogeneous head dimensions (Gemma 4) to avoid inflating the shared page size.
- vllm/platforms/interface.py: Include the fp8 sliding-window page in the LCM when computing attn_page_size_1_token for TurboQuant models with mixed attention types.

## Test Plan

Testing with MI325X. Run vllm with

```
vllm serve google/gemma-4-31B-it \
    --tensor-parallel-size 1 \
    --max-model-len 32768 \
    --gpu-memory-utilization 0.95 \
    --kv-cache-dtype turboquant_k3v4_nc

```
and test accuracy with

```
lm_eval \
    --model local-completions \
    --model_args model=google/gemma-4-31B-it,base_url=http://localhost:8000/v1/completions,tokenized_requests=False,trust_remote_code=True,num_concurrent=256 \
    --tasks gsm8k \
    --num_fewshot 5 \
    --output_path /tmp/lm_eval_gsm8k
```
Compare the result against --kv-cache-dtype fp8.

## Test Result

| Configuration | KV cache capacity (tokens) | Accuracy GSM8K | Throughput (req/s) |
|---|---|---|---|
| Baseline fp8 | 738k | 71% | 1.0 |
| TurboQuant k3v4_nc | 794k | 69% | 0.72 |
