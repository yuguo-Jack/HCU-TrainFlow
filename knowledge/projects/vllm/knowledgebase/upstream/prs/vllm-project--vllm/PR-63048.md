# [ROCm][CI] Enable AITER on for Qwen3-8-Flash-Next-FP8 Accuracy Eval

[Upstream PR](https://github.com/vllm-project/vllm/pull/63048) · state: open · merged: False

## Original PR description

## Overview

With AITER on, the Qwen3-8-Flash-Next-FP8 Accuracy Eval (tests/evals/qwen4_exp/test_accuracy.py) will fail:
1. AITER FP8 MoE kernel supports only (128, 128) quantization block size. Since TP=4, the size for each rank is 640/4=160, not a multiple of 128, so padding is needed. But: I) padding is not equal for all 4 ranks (pad=0, 0, 128, 256, respectively); II) pad value is set to 0 and scale to 1; so AITER MoE kernel could treat padding as real value, and I just explicitly set intermediate_pad = 0;
2. AITER custom all-reduce doesn't supports FP8 dtype but the selection logic didn't check this when selecting all-reduce kernels. I fixed this logic: now it checks the dtype for AITER custom AR, and if not supported, it will fall back to vLLM custom all-reduce.

## Claims

The accuracy is nearly the same for both VLLM_ROCM_USE_AITER=0/1.
