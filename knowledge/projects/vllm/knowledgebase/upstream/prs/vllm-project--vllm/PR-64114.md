# [Doc] MiniMax-M3: GB200 AgentX presets (TP4/TP8)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64114) · state: closed · merged: True

## Original PR description

[by Claude Code]

## Overview

Follow-up to #62543, #63394 and #63534. This PR first added two rows to the guide's GB200 AgentX table: TP8 at concurrency 5 and TP4 at concurrency 22. It now expresses the MiniMax-M3 NVFP4 GB200 AgentX lane (Dynamo + vLLM, aggregated) from [SemiAnalysisAI/InferenceX#4281](https://github.com/SemiAnalysisAI/InferenceX/pull/4281) as two opt-in presets with its eight measured points. #63534 did the same for the H200, B200 and B300 lanes. Picking a point renders the worker's flags, environment and pinned image.

## Claims

- A preset point can't change the strategy, so the two-tray TP8 points need their own preset:
  - `gb200_agentx` ("AgentX TP4", `single_node_tp`, one 4-GPU tray):
    - GPU-resident KV: `tp4_c1`, `tp4_c10`;
    - SimpleCPUOffload host KV: `tp4_c20`, `tp4_c22`, `tp4_c25`, `tp4_c30`.
  - `gb200_agentx_tp8` ("AgentX TP8", `multi_node_tp`, two trays): `tp8_c1`, `tp8_c5`.
- Both presets share:
  - the source: key `minimaxm3-fp4-gb200-dynamo-vllm-agentic-agg-mtp`, `source.revision` `bbebca8b4be98a06401e943bad37874abbd65101`;
  - the image `vllm/vllm-openai:nightly-5555a2d8…@sha256:8896fd7b…` and Dynamo `1.6.0.dev20261016`;
  - the GQA EAGLE3 draft, text-only mode and **Thinking Always On**. Thinking Always On matches the other AgentX presets and the lane's client, which asked for thinking on every request.
- Each point sets its own `--max-num-seqs` and CUDA graph capture sizes. The offload points also set the lane's host KV budget: 181 GiB per rank, lazy offload.
- The guide's GB200 section now links to the presets in place of its table and worker command. The TP4 runbook keeps the etcd, NATS, Dynamo worker and frontend steps. It also says what changes under `python3 -m dynamo.vllm`:
  - drop the API-server flags the builder adds;
  - keep thinking on per request or with `--dyn-default-thinking-mode enabled`.
- A GB200 note keeps the old guide's warning: the KV Offload → Simple default (220 GiB per rank) overcommits a tray's host memory.
- Outside `presets`, `notes`, `guide` and two YAML comments, the parsed recipe equals `main`, so commands built without a preset don't change.

## Validation

- The InferenceX PR's sweep at `bbebca8b` passed all eight points. Each point's eval jobs, which keep real block verification, passed too:
  - GSM8K 0.953 at TP4 C22;
  - the MiniMax-M3 eval set 0.99 at TP4 C22 and TP8 C5.
- A local check script (not part of this PR) layers base, variant, strategy, preset, point, features and KV offload the way `command-synthesis.js` and `recipe-presets.js` do.
  - For each of the eight points, it compares the result with the InferenceX recipe: base plus that point's override.
  - All eight match, apart from the exclusions below and the `vllm serve` equivalents of the lane's Dynamo frontend and client: `--tool-call-parser`, `--enable-auto-tool-choice` and `--default-chat-template-kwargs`.
  - For TP4 C22, TP8 C1 and TP8 C5, it also matches the worker commands in the sweep logs, minus the synthetic-acceptance keys.
  - The script emulates the renderer; it isn't the renderer.
- I didn't run the renderer's strict `validate-source.mjs` build or `pre-commit` locally, because both need a dependency install.
  - The PR's `Recipes / Validate` check runs that strict build: it renders every preset at every point and fails on any error. It passed on the previous commit.
  - `pre-commit` also runs in CI.
  - After this push, I'll check both preset JSONs and the Presets tab on the Vercel preview against the same expectations. I'll tick Testing and Validation once the check and the preview pass.
- `git diff --check` is clean. The branch merges cleanly with `main` and with #63810.

## Details

- Not a duplicate. The only other open PR on this file is #63810, which changes the B300 preset. `meta.date_updated` is left as is so the two PRs don't conflict.
- Left out, judged by effect:
  - synthetic acceptance (`rejection_sample_method`, `synthetic_acceptance_length`): a benchmark control that fixes the acceptance rate; production serving keeps block verification;
  - AIPerf settings: these configure the benchmark client, not the server;
  - Slurm, health-check, etcd-lease, container and placement settings, `--device-ids` and `--dump-config-to`: cluster and harness plumbing;
  - `--kv-cache-metrics`, `VLLM_LOG_STATS_INTERVAL` and OTEL: telemetry only;
  - `UCX_TLS` and `UCX_MEMTYPE_CACHE`: only a NIXL KV transfer would use them, and these workers have none;
  - `UCX_NET_DEVICES` and `NCCL_IB_HCA`: the site's own device names;
  - `--served-model-name` (it equals the model id) and `--pipeline-parallel-size 1` (the default).
- The schema's `image.dynamo` holds a commit, and the Presets tab shortens it to 8 characters. The lane installed Dynamo from PyPI, so the version pins are in `image.pip`.
- Please don't merge yet. A TP4 SimpleCPU point at concurrency 15 is in the InferenceX PR's next sweep. Once that sweep passes, I'll add `tp4_c15` here and bump `source.revision` to match.

Thanks for taking a look!
