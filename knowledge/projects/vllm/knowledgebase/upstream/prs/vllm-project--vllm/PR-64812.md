# [KV Connector] Spec-driven TP slicing for KV transfers

[Upstream PR](https://github.com/vllm-project/vllm/pull/64812) · state: closed · merged: False

## Original PR description



## Overview

[3/N] of RFC #42082. KV cache specs now own `slice_for_tp_transfer`, and NIXL, Mooncake and MoRIIO use it instead of their own head and Mamba byte math. Follows #42374; written so #61452 can land first or second. It conflicts, but the head math moves straight onto that PR's GQA spec.

NIXL goes further: `TPMapping` is gone, each cache group's source ranks come from the specs' slices, and every layer's pages, Mamba state included, move as spec-sliced chunks through one descriptor model.

## Claims

- **`KVCacheSpec.slice_for_tp_transfer`** returns paired views of a block for two ranks of different TP sizes. `jointly_contiguous_chunks` turns those views into byte runs. Generic slicing only covers vanilla GQA (KV heads on dim 1). Anything else is a spec subclass that lives next to its backend.
- **FlashInfer NVFP4 hetero-TP in Mooncake and NIXL:** a FlashInfer-local spec subclass slices NVFP4 pages, where each KV head is four runs of the page. Before this PR, both connectors rejected NVFP4 head re-sharding.
- **Mamba1, Mamba2 and GDN specs** (subclasses in `mamba1_attn.py`, `mamba2_attn.py` and `gdn_attn.py`, built by the new `AttentionBackend.customize_mamba_spec`) declare how their conv and temporal states shard across TP.
  - NIXL Mamba descriptors and SSM source ranks now come from the spec.
  - Mooncake Mamba chunks now come from the spec.
  - MoRIIO conv sub-projection sizes now come from the spec.
  - NIXL's and MoRIIO's conv-split code is removed. `ssm_conv_transfer_utils.py` keeps only the part the Mooncake Store (#54307) still uses.
- **NIXL descriptors:**
  - Every registered layer view is an array of pages: the allocator's kernel blocks. NIXL reads the pages per manager block of each cache group from those views, rather than choosing a kernel block size itself, and advertises them in the handshake.
  - Mamba and PLE state are ordinary page regions (one page per block). The separate SSM/PLE descriptor tracks, `_ssm_region_indices`, the per-source split handles and `_compute_desc_ids` are removed.
  - For each region pair and remote rank, the paired `slice_for_tp_transfer` views of both sides' specs give the byte chunks of a page; a page may move as several chunks. One local descriptor list per distinct chunk set (shared by engines that move the same chunks) and one remote list per rank hold one strided descriptor per region and chunk.
  - Push slices with the sending side's views, so replicated KV (MLA latents, CSA-linear groups) reaches every decode rank exactly once, without push-only special cases.
  - In push, D waits for one notification per P rank whose slices write to it; D counts these from its own specs at the handshake, instead of `P_TP // D_TP`. A P rank with nothing to write (a replica, when P TP > D TP) reports the request done at once.
- **Behavior changes:**
  - Mamba2 with replicated groups (TP does not divide `n_groups`) now fails at the handshake for hetero-TP in NIXL and Mooncake. Before, it silently moved the wrong conv state (#61526).
  - NIXL no longer requires `VLLM_SSM_CONV_STATE_LAYOUT=DS` for same-TP Mamba. Same-TP pages move whole, which also covers the SD layout and Mamba types without a TP layout.
  - The docs footnote for NIXL hetero-TP Mamba and the push design doc's completion accounting are updated to match.
  - NIXL reads a replicated (PLE) Mamba state from one prefill rank instead of every source rank.
  - `NIXL_CONNECTOR_VERSION` is 18: `physical_blocks_per_logical_kv_block`, `ssm_sizes` and `ple_block_len` are replaced by `group_pages_per_block`, so P and D must run the same version.

## Details

- **Peer spec:** the other engine's spec is still derived by scaling the local one (`mamba_peer_spec`, `attention_peer_spec`). The TODO is for engines to advertise their specs in the handshake.
- **Remaining type checks in NIXL:** deriving the peer spec (attention/Mamba); recurrent state pages not splitting with a smaller remote block size (`_splits_with_block_size`); the block-id semantics of state pages in prefix caching; and fail-closed `_has_mamba` guards for unvalidated combinations.
- **Hot path:** desc ids are one broadcast per cache group over a per-rank table of chunks, as before.
- **Replicated Mamba2 groups:** the spec raises `NotImplementedError` rather than modelling replication. MoRIIO keeps its own write path for this case. #61531 adds replicated-segment support to NIXL; under this PR that would become a `Mamba2Spec._tp_segments` extension.
- **#61452:** `AttentionSpec._transfer_kv_heads` carries a note that it moves to the GQA spec subclass there.
- **Mooncake Store:** `ssm_conv_transfer_utils.py` now has one user, the Mooncake Store. It still handles the SD layout and replicated groups, which the spec subclasses don't model, so this PR leaves it in place.

**Why this is not a duplicate**, for the open PRs touching the same code:
- **#53078** (Mooncake Mamba hetero-TP): fixes Mooncake's own region math. Here the Mamba slicing comes from the spec, shared across connectors.
- **#61531** (NIXL replicated B/C): extends `ssm_conv_transfer_utils`. This PR removes NIXL's use of it.
- **#64475** (MiniMax-M3 NVFP4 via `AttentionSpec.kv_head_major_slots`): puts a flag on the generic spec. This PR keeps the format-specific slicing in a backend spec subclass instead.
- **#46387, #64388, #63699:** related registration and transfer-view work under the same RFC; none adds spec-driven TP slicing.

These PRs will conflict and need sequencing with their authors.
