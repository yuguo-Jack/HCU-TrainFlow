# [CI] Shard V1 Attention automatically instead of by fixed pytest shards

[Upstream PR](https://github.com/vllm-project/vllm/pull/61200) · state: closed · merged: True

## Original PR description

## Purpose

The NVIDIA V1 Attention steps (H100 and B200) were split into 2 fixed pytest shards (`--shard-id` / `--num-shards`, `parallelism: 2`), and each shard still takes 46–51 min. This turns each into one plain `pytest -v -s v1/attention` step with `automatic_shard: true`, the same as #60492, #60662, #60757 and #60858.

The pipeline generator then plans the shards at bootstrap from main's per-file timings. It splits the two big MLA files by test function. Planned shards on current timings:

| Step | Shards | Estimated minutes per shard |
|---|---|---|
| `v1-attention-h100-mi300` | 6 | 15.9 each |
| `v1-attention-b200` | 6 | 16.4 ×5, 19.1 |

The AMD mirrors (MI300, MI355 DPX) are unchanged. They keep their fixed pytest shards, because `automatic_shard` covers NVIDIA steps only, so the shard args and `parallelism: 2` move into the mirror config.

## Test Plan

[Buildkite build 94185](https://buildkite.com/vllm/ci/builds/94185) ran only these two steps. Every shard passed, and the shard plugin was active in all of them. The baseline is main build 94136, whose two fixed shards are summed.

| Step | Shards (job min) | Wall, main → PR | Job-min, main → PR | Passed, PR vs main |
|---|---|---|---|---|
| H100 | 6: 11.2, 9.1, 10.9, 15.0, 12.8, 16.9 | 46.5–52.7 → **16.9** | 89–103 → 76 | 2224 = 2224 |
| B200 | 6: 15.4, 16.3, 15.6, 10.2, 9.3, 19.4 | 46.2–52.2 → **19.4** | 100–104 → 86 | 3539 = 3539 |

Skips are 6 lower on H100 and 5 lower on B200. Those files skip at module level on CUDA: five `test_rocm_*` files, plus `test_trtllm_attention_integration` on H100. With fixed shards, every shard collects every file, so main counted each of those skips twice.
