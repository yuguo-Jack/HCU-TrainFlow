# [ROCm][Perf][GLM-5.3-Flash] Enable AITER fused shared experts on gfx942

[Upstream PR](https://github.com/vllm-project/vllm/pull/60604) · state: open · merged: False

## Original PR description

## Overview

Follow-up to #59221, which lets `VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS` fold GLM-5.3-Flash's shared expert into the AITER fused MoE on gfx950. This PR allows it on gfx942 with 304 CUs (MI300X, MI325X) at TP2, TP4 and TP8, the shapes that ROCm/aiter#5953 tunes. Part of #58409.

## Claims

- On MI325X at TP4, GLM-5.3-Flash at 131K in / 1K out, over two runs at concurrency 2-12:
  - output throughput +2.1% to +8.0%;
  - TPOT 1.2% to 11.4% better;
  - TTFT unchanged within noise, gsm8k unchanged.
- With MTP, the draft model's MoE is fused too, and acceptance is unchanged (68.2% vs 68.0%).
- Nothing changes unless the flag is set; it defaults to off. These keep the separate shared-expert MLP, with the one-time warning #59221 added:
  - other gfx942 parts;
  - other TP sizes;
  - data, prefill-context or expert parallelism.

- gfx950, a 304-CU gfx942, an 80-CU gfx942 and another GPU;
- gfx942 at TP1, TP2, TP4 and TP8.

To reproduce:

```bash
# Flag off: VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=0
# MTP runs add: --speculative-config '{"method":"mtp","num_speculative_tokens":5}'
VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_MOE=1 AITER_LOG_TUNED_CONFIG=1 \
VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1 \
vllm serve zai-org/GLM-5.3-Flash --tensor-parallel-size 4 \
  --gpu-memory-utilization 0.85 --max-model-len 262144 \
  --no-enable-prefix-caching --trust-remote-code \
  --compilation-config '{"custom_ops": ["all"]}'

vllm bench serve --dataset-name random --random-input-len 131072 \
  --random-output-len 1024 --num-prompts 20 --num-warmups 2 \
  --max-concurrency {2,4,6,8,10,12,16}
```

## Details

- **Gate structure.** `_fused_shared_experts_tuned()` keeps #59221's structure. gfx950 allows TP4 and TP8 (ROCm/aiter#5735), and 304-CU gfx942 allows TP2, TP4 and TP8 (ROCm/aiter#5953). The data, prefill-context and expert-parallel checks are unchanged.
- **Why the CU check.** #5953's rows are keyed to 304 CUs, so other gfx942 parts (MI308X, MI300A) would miss them and run the fused shape untuned. On MI325X an untuned call is 4289 µs, against 3033 µs tuned, for one 16K-token MoE call.
- **TP coverage.** Only TP4 was measured end to end. TP2 and TP8 rely on #5953's rows, which were tuned and checked for correctness at those sizes in #5953.
