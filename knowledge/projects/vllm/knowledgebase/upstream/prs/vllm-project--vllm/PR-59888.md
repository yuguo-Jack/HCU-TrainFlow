# [Bugfix][Benchmarks] Name the real cause when the /tokenize alignment probe fails

[Upstream PR](https://github.com/vllm-project/vllm/pull/59888) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

`vllm bench serve` aligns `random` / `prefix_repetition` prompts to the server tokenizer through a `/tokenize` probe. Every failure of that probe prints `WARNING: /tokenize unavailable, skipping alignment.`, even when the route exists. This PR names the actual cause instead.

Replaces #58024 (closed when my fork was re-created). Related: #59889 is the server side of the same 404.

## Claims

- A failed probe names its cause: 404 (no route, or `--model` is not a served name), another HTTP status, an unreachable host, or the exception.
- Alignment behavior is unchanged: a failure still skips alignment and never stops the run, and a tokenizer mismatch still re-aligns the prompts.

## Validation

The patched `_align_prompts_to_server_tokenizer` against a local `aiohttp` server for each case (no GPU or model needed):

| Server | Output |
|---|---|
| 404 | ``/tokenize unavailable (404 Not Found: either this server has no /tokenize route, or it does not serve a model named `my-model` (its served names are listed by GET /v1/models))`` |
| 500 | `/tokenize unavailable (HTTP 500)` |
| nothing listening | `http://127.0.0.1:18902 unreachable (ClientConnectorError(... ConnectionRefusedError ...))` |
| tokenizer mismatch (server 6 tokens, local 3) | `tokenizer mismatch (server=6, expected=3), re-aligning prompts.`, then prompt `'a b c'`, `prompt_len=3` |

The 404 on a live server (`--model /models/x --served-model-name my-model`):

```
POST /tokenize {"model":"my-model"}   -> 200
POST /tokenize {"model":"/models/x"}  -> 404 The model `/models/x` does not exist.
```

**Live run on upstream main** (RTX 3090, at the main merge-base `84bcbc626`). The server is `vllm serve Qwen/Qwen3-8B --api-key test-key`. The client is the same checkout, with the `serve.py` from main or from this PR. All runs use `vllm bench serve --dataset-name random --random-input-len 512 --random-output-len 16 --num-prompts 20 --ignore-eos --seed 0` against the same server:

| client | `--model` / `--tokenizer` | probe output | ok / failed | Total input tokens | server `prompt_tokens_total` Δ |
|---|---|---|---|---|---|
| main | `Qwen/Qwen3-8B` / `gpt2` | `tokenizer mismatch (server=696, expected=512), re-aligning prompts.` | 20 / 0 | 10240 | 10240 |
| this PR | `Qwen/Qwen3-8B` / `gpt2` | `tokenizer mismatch (server=696, expected=512), re-aligning prompts.` | 20 / 0 | 10240 | 10240 |
| this PR | `Qwen/Qwen3-8B` / `Qwen/Qwen3-8B` | (no probe line) | 20 / 0 | 10240 | 10240 |
| main | `not-a-served-model` / `gpt2` | `/tokenize unavailable, skipping alignment.` | 0 / 20 | 0 | 0 |
| this PR | `not-a-served-model` / `gpt2` | ``/tokenize unavailable (404 Not Found: either this server has no /tokenize route, or it does not serve a model named `not-a-served-model` (its served names are listed by GET /v1/models)), skipping alignment.`` | 0 / 20 | 0 | 0 |

- Tokenizer mismatch: the server reads the 512 gpt2-token prompt as 696 tokens. After re-alignment, the server counts 10,240 prompt tokens for the 20 requests (512 on average), with and without this PR. I checked the totals, not each request.
- Auth: on this server, `POST /tokenize` without a key returned 200, and `GET /v1/models` without a key returned 401.

`pre-commit` passes. No unit test is added; the harness above can go into `tests/benchmarks/` if you want it in CI.

## Details

**Root cause.** The probe sends `args.model` as the request `model` and catches every exception into one message. With `--served-model-name`, the model check answers 404, which reads as "no `/tokenize` route".

**Review changes.** An earlier revision also sent `OPENAI_API_KEY` with the probe. It is removed: `--api-key` does not guard `/tokenize` on vLLM, and it overrode a lowercase `authorization` passed with `--header`.
