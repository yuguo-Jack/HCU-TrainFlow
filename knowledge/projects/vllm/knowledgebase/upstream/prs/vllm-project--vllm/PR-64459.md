# [ROCm] MXFP8 block32 GEMM: add TP1 tuned configs for DeepSeek-V4.1-Flash DP8+EP8

[Upstream PR](https://github.com/vllm-project/vllm/pull/64459) · state: open · merged: False

## Original PR description

## Purpose

With DeepSeek-V4.1-Flash served as DP8+EP8 (one vLLM instance, 8× MI355X), each rank runs the dense MXFP8 linears at TP1. `rocm_block32_gemm._config()` looks up `_TUNED` by (N, K), but the table only has TP2/TP4 shapes, so every TP1 shape silently falls back to `_default_config()` (at M=64: `tiled(64, 64, 256, ...)` with no split-K). For example, wo_b (N=5120, K=8192) yields only 80 output tiles, which leaves about 70% of the CUs idle.

This PR adds per-M tuned tiers for the TP1 shapes:

| Layer | (N, K) |
|---|---|
| wq_b | (32768, 1280) |
| wo_b | (5120, 8192) |
| shared expert gate_up | (4608, 5120) |
| shared expert down | (5120, 2304) |
| engram wkv | (25600, 6144) |

Tiers were swept for M = 1…512 (median of repeated runs). A tier only gets a new config if it improves by at least 3%; otherwise it keeps the default. M > 512 uses the same config as the default, so prefill is unchanged. For example, wo_b at M ≤ 64 uses `tiled(64, 64, 512, ..., fused=3)`: split-K of 3 gives 240 programs, enough to cover the CUs.

The change only touches the config table; kernel and dispatch logic are unchanged.

## Test Plan

- Kernel microbenchmarks on MI355X at M=64 (decode batch per rank).
- End-to-end decode benchmark: DeepSeek-V4.1-Flash, single-node 8× MI355X, one vLLM instance with DP8+EP8 (MoRI EP), KV prefilled (prefill skipped), BS512 (64 per rank), ISL 1K / 100K, OSL 512, 2048 requests per run after a 512-request 1K warmup.

## Test Result

Kernel latency at M=64:

| Layer | default | tuned |
|---|---|---|
| wo_b | 34.4 us | 15.0 us |
| shared gate_up | 23.8 us | 10.9 us |
| shared down | 10.8 us | 6.8 us |
| wq_b | 11.3 us | 11.0 us |

End-to-end (DP8+EP8):

| | TPOT before | TPOT after | Output throughput before → after |
|---|---|---|---|
| ISL 1K | 19.02 ms | 18.36 ms (−3.5%) | 25,751 → 26,712 tok/s |
| ISL 100K | 21.26 ms | 20.74 ms (−2.4%) | 21,663 → 22,308 tok/s |

Run-to-run noise is about ±0.05 ms (1K) and ±0.1 ms (100K) TPOT. The end-to-end numbers were measured on a downstream vLLM build (0.32.1rc1.dev117) carrying the same table change.

`ruff check` / `ruff format --check` pass.
