# [Bugfix] Handle malformed namespace tools

[Upstream PR](https://github.com/vllm-project/vllm/pull/53763) · state: closed · merged: True

## Original PR description

## Purpose

Named tool-choice validation for the Responses API inspects namespace tools before Pydantic validation. A malformed nested entry such as `null` or a string therefore raises `AttributeError` and returns HTTP 500. This PR uses the same defensive name lookup already used for top-level tools so invalid client input returns HTTP 400 while valid namespace tools remain unchanged.


## Reproducer

```bash
.venv/bin/python - <<'PY'
from vllm.entrypoints.openai.responses.protocol import ResponsesRequest
from vllm.entrypoints.serve.exception_handling.error_response import create_error_response

for value in (None, "bad"):
    try:
        ResponsesRequest(
            model="test",
            input="hi",
            tools=[{
                "type": "namespace",
                "name": "ns",
                "description": "namespace",
                "tools": [value],
            }],
            tool_choice={"type": "function", "name": "f"},
        )
    except Exception as exc:
        error = create_error_response(exc).error
        print(f"{value!r}: {type(exc).__name__}, HTTP {error.code}")
PY
```

## Output on main / on branch

Main:

```text
None: AttributeError, HTTP 500
'bad': AttributeError, HTTP 500
```

Branch:

```text
None: VLLMValidationError, HTTP 400
'bad': VLLMValidationError, HTTP 400
```

Valid named choices using both `f` and `ns__f` remain accepted.
