## Overview

Document the H200 MXFP8 AgentX lane of [SemiAnalysisAI/InferenceX#4429](https://github.com/SemiAnalysisAI/InferenceX/pull/4429) (head `9937960e`, key `minimaxm3-fp8-h200-vllm-agentic-mtp`) in `recipes/models/MiniMaxAI/MiniMax-M3.yaml`, modeled on the B200 section from #63163. Guide only; the command builder already renders every static serving setting of this lane for H200, so no selector change.

## Claims

- New guide section **H200: InferenceX AgentX aggregated (vLLM)**: TP8, single 8-GPU H200 node, GQA EAGLE3 draft with three tokens, image `vllm/vllm-openai:nightly-83c078d955cd6e0c63d3b12abe669c8de936a370@sha256:cb12c3016938a4ee98ed176ac833984089460689a0982cff4b5a60bb45b3cded` (vLLM `0.32.1rc1.dev361+g83c078d95` in the run logs).
- Builder selections (H200, MXFP8, Spec Decoding GQA, Text-only, Thinking Always On, Single-node TP), a per-point table (clients 1/2/4/6/8/10/12/14: `--max-num-seqs` 2/4/8/12/16/20/24/28, `--max-cudagraph-capture-size` 8/16/32/48/64/80/96/112), and the full `vllm serve` command.
- `meta.date_updated` bumped to 2026-10-23.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` passes (vllm-project/recipes @ `92a63ed`).
- Rendered every variant x hardware x strategy x feature set (incl. GQA + Text-only + Thinking) x KV-offload option x PD router x frontend (35,904 renders) before and after: 0 changed, 0 errors (expected, no builder change).
- The builder's H200 + MXFP8 + GQA + Text-only + Thinking + Single-node TP render matches the lane's effective static args (every flag and env var except those listed below).
- Per-point values taken from the effective recipe at the PR head and checked against the config and engine non-default-args line of all eight server logs of run 39956930950: `--max-num-seqs`, `--max-cudagraph-capture-size` and `--gpu-memory-utilization 0.95` agree for every point.

## Details

Excluded as InferenceX-only or cluster-specific: concurrency lists, synthetic acceptance (`rejection_sample_method: synthetic`, mentioned in the guide only as how the throughput points were measured), AIPerf and trace-replay settings, `--served-model-name`, `--enable-prompt-tokens-details`, `PYTHONNOUSERSITE`; `--safetensors-load-strategy prefetch` and `VLLM_ENGINE_READY_TIMEOUT_S=7200` (a workaround for the InferenceX h200-dgxc cluster's VirtIO-FS HF cache, see InferenceX #3493; no evidence it is needed on stock H200 nodes). The builder's pinned H200 MXFP8 image (`nightly-1a001d58`) is unchanged; the guide names the lane's tested image. The lane passes `--trust-remote-code`; the builder's MXFP8 command does not, and the guide only states that.
