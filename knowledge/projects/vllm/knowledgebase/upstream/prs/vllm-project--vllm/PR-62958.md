# [Perf][Spec Decode] DSpark: run the Markov walk in one kernel with int8 W2 on chip (Hopper)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62958) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

DSpark walks its draft block left to right: each step adds `W2 @ W1[prev]` to the base logits (W2 is V x 256) and then takes the argmax or a sample. Today every draft token is a full-vocab GEMV, an add and a sampler, and W2 (78 MB in bf16 at V = 151936) is read from HBM again on every step.

This adds `dspark_markov_quantization="int8"` to the speculative config. With it, sm_90 runs the whole walk in one cooperative kernel. W2 is quantized to int8 with one fp32 scale per row, most of it stays in shared memory across all SMs and the rest streams from L2, and the per-step argmax across CTAs goes through one atomic {key, count} pair. Off by default.

The kernel is adapted from the MIT-licensed int8 Markov walk kernels in https://github.com/tie-pilot-qxw/dspark-markov-walk (notice kept in `csrc/dspark_markov_walk.cu`).

## Claims

- Markov walk on 1x H100, eager loop vs this kernel: 298 -> 60 us at V = 151936 with 7 draft tokens (bs 1, greedy), 431 -> 68 us at bs 16, 563 -> 112 us at bs 64. 3.4-6.3x across the table below.
- Qwen3-4B on 1x H100, output tok/s over the eager loop: +4.3% at c1 and +4.6% at c16 with the 7-token DSpark drafter (greedy), +9.3% and +8.8% with the 16-token one. Probabilistic at c1: +5.5% and +11.7%.
- Greedy outputs at c1 match the eager walk (80/80). Acceptance length moves by at most 0.06 tokens and GSM8K by at most 0.025 on these prompts.

## Details

- Only acceptance can change. int8 W2 can move near-ties, and the target still verifies every draft token. For probabilistic drafting the kernel writes the bf16 logits it sampled from into `draft_logits`, so rejection sampling uses exactly that distribution.
- Sampling noise is Philox keyed by the request seed and the draft position, so seeded requests stay reproducible. A seed draws different tokens than it does with the eager loop.
- TP: every rank runs the whole walk, so with this option the draft logits cache stays replicated and the sequential sampling is not batch-sharded. I only ran it at TP1.
- Supported: sm_90, vanilla Markov head with rank 256 in bf16, fp16 or fp32, full-vocab drafts, up to 16 draft tokens, V up to 270336 on 132 SMs, bs <= 64 (larger batches keep the eager loop). Loading fails with a clear error for draft watermarking, the online acceptance estimator, a logit soft cap or output logit transform, a draft model with its own `sample_sequential`, `dspark_draft_topk`, or a quantized W2.
- Memory: 114 MiB of int8 layouts at V = 151936.
- CI: the kernel test runs on H100. The new `qwen3-deepspec-int8-walk` case skips on GPUs with too few SMs to hold W2 (e.g. a MIG slice), so I ran it on a full H100 (above).
- Not a duplicate: #61869 fuses the Markov loop for DeepSeek-V4.1's specialized decode on GB300. #64442 fuses it for DeepSeek-V4.1 on NVIDIA by inverse CDF, with a bias GEMM per step. #64476 adds the bias inside the Gumbel kernel, also with a GEMV per step, so if it lands first the probabilistic eager column needs a re-measure. #65007 shards the walk over TP, #64033 is the top-k walk and #56694 prunes W2 with top-k. This PR is the generic DSpark path on Hopper with W2 kept on chip.
