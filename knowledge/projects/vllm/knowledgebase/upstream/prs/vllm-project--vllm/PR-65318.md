# [Bugfix][MRV2] Reserve MoE workspace before graph capture

[Upstream PR](https://github.com/vllm-project/vllm/pull/65318) · state: open · merged: False

## Original PR description

## Overview

Follow up on #48179 by reserving MoE workspace in the default Model Runner V2 path. 

As the pooling models use MRV2 by default (#48290), existing fix in #48179 cannot resolve the issue although the idea still works. So this PR includes the rebased changes from #48179 and adds MRV2 integration.

## Claims

- Prevents the privacy-filter test from failing because MoE workspace growth is attempted after the workspace is locked.
- Applies the reservation to the target model and, when present, the draft model's workspace lane.
- Reuses the reservation logic from #48179 for both model runner paths.

## Validation
To reproduce:
```bash
VLLM_DEBUG_WORKSPACE=1 pytest -s -v  tests/models/language/pooling/test_token_classification.py::test_openai_privacy_filter
```

Result with #48179 before this PR (on both CUDA and XPU):
```
(EngineCore pid=15975) ERROR 11-02 04:03:42 [core.py:1649]     raise AssertionError(
(EngineCore pid=15975) ERROR 11-02 04:03:42 [core.py:1649] AssertionError: Workspace is locked but allocation from
 'modular_kernel.py:1210:_allocate_buffers' requires 0.02 MB, current size is 0.00 MB. Workspace growth is not allowed 
after locking.
```

Result after this PR: 
- On cuda, this ut passed.
- On XPU, the vllmrunner completed all prompts. the case failed due to numerical issues instead of workspace crash.
