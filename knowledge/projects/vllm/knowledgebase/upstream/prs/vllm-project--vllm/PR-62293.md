# [Bugfix][Frontend] Render disabled-thinking Messages requests with the server's reasoning effort

[Upstream PR](https://github.com/vllm-project/vllm/pull/62293) · state: closed · merged: False

## Original PR description

## Overview

`/v1/messages/render` converts `thinking: {"type": "disabled"}` with `reasoning_effort="none"`, while `/v1/messages` and `count_tokens` use the probed effort (`low` for templates that ignore `none`, such as GLM-5.3). The render endpoint then returns a different prompt than the server runs, so routers that score prefix-cache affinity from it never match the engine's cached blocks.

## Claims

- `/v1/messages/render` renders disabled-thinking requests with the same `reasoning_effort` as `/v1/messages`, on both the API server and the GPU-less render server
- `--anthropic-disabled-thinking-effort` now applies to the render endpoint too
- No change for requests that don't disable thinking, or for models whose template honours `none`

## Validation

- New tests in `tests/entrypoints/scale_out/render/test_render.py`: rendering with a resolved effort and with `auto` both use `low` (fail on `main` with `'none' == 'low'`); requests without disabled thinking render once, with no effort (pass on both).
- The existing `TestProbeDisabledThinkingEffort` tests pass unchanged after the probe moved into the shared mixin.
- Render server built as `vllm launch render` does, for `zai-org/GLM-5.3` with its chat template, comparing the tokens `/v1/messages` serves with those `/v1/messages/render` returns for the same `thinking: disabled` request:

  | | `/v1/messages` serves | `/v1/messages/render` returns |
  |---|---|---|
  | `main` | `…<\|system\|>Reasoning Effort: Low<\|user\|>Hi<\|assistant\|><think>` | `…Reasoning Effort: Max…` (differs from token 8 of 13) |
  | This PR | `…Reasoning Effort: Low…` | identical |

  Requests with no `thinking` or `thinking: enabled` render identically before and after.
- In production, GLM-5.3 behind an llm-d router using the render endpoint (`messagesRenderMode: native`): repeated disabled-thinking requests read 0 cached tokens, while the same requests with thinking enabled read warm.

## Details

The router builds its prefix-cache block keys from the render endpoint's `token_ids`. The two prompts differ in the effort line at the start, so every block key differs from what the engine cached.

The probe and its cache move from `AnthropicServingMessages` into `AnthropicDisabledThinkingMixin`, which needs only the shared `OnlineRenderer` and `_extract_prompt_components`. `ServingRender` inherits it, so the GPU-less render server probes on its own; `init_render_state` passes the CLI option through. The three probe methods move unchanged, and `_disabled_thinking_effort_for(request)` replaces the same three lines in `create_messages`, `count_tokens` and the render path.
