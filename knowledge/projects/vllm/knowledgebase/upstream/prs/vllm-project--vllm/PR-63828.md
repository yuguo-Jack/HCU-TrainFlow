# [ROCm][CI] Release checkpoint page cache between language generation …

[Upstream PR](https://github.com/vllm-project/vllm/pull/63828) · state: closed · merged: True

## Original PR description

## Purpose
`:amd: (MI300) Language Models (Extended Generation)` lost its pod (exit -7, "Perhaps the container was OOM-killed?") in 3 of its last 5 runs: [amd-ci#15340](https://buildkite.com/vllm/amd-ci/builds/15340), [amd-ci#15350](https://buildkite.com/vllm/amd-ci/builds/15350) and [amd-ci#15384](https://buildkite.com/vllm/amd-ci/builds/15384).
Each time, the pod was killed during `test_granite.py::test_models[5-64-bfloat16-ibm/PowerMoE-3b]`.

The tests in `tests/models/language/generation` load many checkpoints in one pytest process, and their page cache is charged to the pod's memory cgroup. The job reads ~208 GiB of checkpoints against ~133 GiB of effective pod memory, so even passing runs drop below 1 GiB of available RAM.

This PR adds an autouse fixture in this directory that frees the previous test's checkpoint page cache when the model changes, using the same mechanism #61415 added for LM Eval. It applies on ROCm only.
Consecutive tests of the same model keep its cache, as do the HF and vLLM runners within one test.

## Test Plan
MI300X (gfx942), in the `rocm/vllm-dev:ci_base` image. The run used 24 of the job's 76 tests (~89 GiB of checkpoints), evicted the page cache before each run, and sampled the container's cgroup memory every 2 s:
```bash
cd tests
pytest -v -s models/language/generation/test_common.py models/language/generation/test_granite.py \
  -m '(not core_model) and (not hybrid_model)' \
  -k 'Qwen3-8B or stablelm or starcoder2-3b or Apertus or Domyn or PowerLM or PowerMoE or granite-swash'
```

## Test Result
The log shows `Released X GiB of checkpoint page cache` lines as the model changes.

| | main | this PR |
|---|---:|---:|
| Peak container memory | 102.4 GiB | 28.5 GiB |
| Peak page cache | 93.4 GiB | 19.8 GiB |
| Duration | 21:16 | 21:52 |

AI-assisted tooling was used to analyze the CI logs and to run the validation. The results and the change were manually reviewed.
