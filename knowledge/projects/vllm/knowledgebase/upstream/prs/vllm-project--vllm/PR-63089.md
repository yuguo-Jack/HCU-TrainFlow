# [Bugfix] Warn instead of assert on device memory growth in sleep

[Upstream PR](https://github.com/vllm-project/vllm/pull/63089) · state: open · merged: False

## Original PR description



## Overview

Fixes #63057

`Worker.sleep` no longer asserts that device-wide free memory did not drop. It logs a warning instead.

## Claims

- `/sleep` no longer returns a 500 when another process allocates on the same GPU during the sleep window.

## Validation

New CPU-only test `test_worker_sleep_tolerates_other_processes_using_device_memory` in `tests/v1/worker/test_sleep_mode_backend.py` mocks `torch.accelerator.get_memory_info` so free memory drops from 10 GiB to 8 GiB across `sleep()`.

- Before the fix: fails with `AssertionError: Memory usage increased after sleeping.`
- After the fix: passes, along with the other 9 tests in the file.
- `ruff check` and `ruff format --check` pass on both files.

Run with `pytest tests/v1/worker/test_sleep_mode_backend.py --noconftest` (CPU torch, Python 3.12). Not run on a GPU, not run end to end with two real processes.

## Details

Root cause: `vllm/v1/worker/gpu_worker.py` compared `torch.accelerator.get_memory_info()` (device-wide) before and after suspend and asserted `freed_bytes >= 0`. That includes other processes' allocations.

I took the warning option from the issue. Per-process accounting from the allocator was left out as a larger change. The existing ROCm retry loop is unchanged.

Thanks to @zenedgex for the report.
