# [Frontend] Align hybrid LB mode in server CLI with create_engine_config for headless nodes

[Upstream PR](https://github.com/vllm-project/vllm/pull/65614) · state: open · merged: False

## Original PR description





## Overview

  Align the hybrid-LB inference in the `vllm serve` CLI with the one in
  `create_engine_config`: `--data-parallel-start-rank` alone no longer marks a
  node as hybrid LB — the node must also be non-headless.

  Headless nodes run no API servers, so hybrid LB (each node runs API servers
  for its local DP ranks) can never apply to them. `EngineArgs.create_engine_config`
  already encodes this (`if self.data_parallel_start_rank is not None and not headless:`
  in `vllm/engine/arg_utils.py`), but the CLI-side inference in
  `vllm/entrypoints/cli/serve.py` only checked `data_parallel_start_rank`,
  misclassifying internal-LB secondary nodes (`--headless --data-parallel-start-rank N`)
  as hybrid LB. This is a consistency fix, not a behavior fix — see Claims.

  ## Claims

  - **No behavior change for any valid launch configuration.** `is_hybrid_lb` in
    the CLI feeds exactly two things: the LB-mode conflict check and the
    `api_server_count` default. In headless mode `api_server_count` is already
    forced to 0 before either is reached in a way that matters, so the
    misclassification happened to be harmless today; this change makes the
    classification correct rather than coincidentally harmless.
  - Per-mode analysis:
    - **Internal LB, primary node** (no `--data-parallel-start-rank`, not headless):
      condition was and remains `False`; `api_server_count` still defaults to
      `data_parallel_size`.
    - **Internal LB, secondary nodes** (`--headless --data-parallel-start-rank N`):
      previously misclassified as hybrid LB; now correctly `False`. Routing is
      unchanged (`api_server_count == 0` → `run_headless`).
    - **Hybrid LB** (`--data-parallel-start-rank` without `--headless`, or explicit
      `--data-parallel-hybrid-lb`): unaffected — the new `not args.headless` term
      is always true there.

  ## Validation

  - Traced every consumer of `is_hybrid_lb` in `ServeSubcommand.cmd()`
    (LB-mode conflict check and `api_server_count` defaulting) to confirm the
    per-mode analysis above.
  - Verified the new condition is identical to the inference already used in
    `EngineArgs.create_engine_config`.

  ## Details

  In `vllm/entrypoints/cli/serve.py`, when neither `--data-parallel-hybrid-lb`
  nor `--data-parallel-multi-port-external-lb` is set explicitly:

  ```python
  # before
  is_hybrid_lb = args.data_parallel_start_rank is not None
  # after
  is_hybrid_lb = (
      args.data_parallel_start_rank is not None and not args.headless
  )

  The comment above the block is updated to document the headless exclusion and
  point at the matching inference in create_engine_config.
