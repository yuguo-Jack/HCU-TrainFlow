# [Bugfix][Parser] Honor a prompt-closed reasoning block for PLaMo3

[Upstream PR](https://github.com/vllm-project/vllm/pull/62299) · state: open · merged: False

## Original PR description

## Overview

A prompt that already closed its reasoning block must parse the continuation as content on the non-streaming path. For PLaMo3 it was returned as `reasoning` with `content=None`, while streaming returned it as content. This declares the PLaMo3 turn boundary so both agree. Ref #61857.

## Claims

- Non-streaming returns the continuation as `content` instead of `reasoning` when the prompt already closes the PLaMo3 think block.
- `reasoning_tokens` is 0 for such a turn on both paths. On `main` both streaming and non-streaming counted every generated token as reasoning.
- A new turn after an earlier reasoned answer still parses as reasoning (`EOT` ends the earlier turn).
- No behavior change for other parsers.

## Validation

Real checkpoint, tokenizer and chat template: [`pfnet/plamo-3-610m-fin-instruct`](https://huggingface.co/pfnet/plamo-3-610m-fin-instruct) (public PLaMo3 reasoning model). The request goes through `OpenAIServingChat.create_chat_completion` with `--reasoning-parser plamo3`, `continue_final_message=True` and an assistant prefill whose reasoning is closed:

```
prompt tail : ...<|plamo:val|>think<|plamo:msg|><|plamo:begin_think:plamo|>数字を順番に並べるだけです。<|plamo:end_think:plamo|>1、2、3、4、
continuation: 5、6、7、8、9、10です。<|plamo:tag|>
```

The continuation is the checkpoint's greedy output. No GPU was available, so it was generated with the HF reference implementation on CPU and replayed into the serving layer; the rendered prompt token ids are identical to HF's.

Before (`main` at 2365177ddd):
```
non-stream  reasoning='5、6、7、8、9、10です。'  content=None  reasoning_tokens=13
stream      reasoning=''  content='5、6、7、8、9、10です。'  reasoning_tokens=13
```
After (this PR):
```
non-stream  reasoning=None  content='5、6、7、8、9、10です。'  reasoning_tokens=0
stream      reasoning=''  content='5、6、7、8、9、10です。'  reasoning_tokens=0
```

```
.venv/bin/python -m pytest tests/parser/engine/test_plamo3.py -q
122 passed
```
The new test fails on the base for both the direct and registered parser paths.

Not covered: a prefill without a think block (`{"role": "assistant", "content": "1、2、3、4、"}`). The model continues it as answer text, and it is still returned as reasoning, as on `main`. The prompt has no closed think block in that case, so this change does not apply.

## Details

Root cause: `ParserEngine.set_prompt_token_ids` applies the prompt-closed state only when the config declares `turn_boundary_tokens` (ref #61857), and PLaMo3 declared none. 
Fix: add `turn_boundary_tokens=frozenset({EOT})`, where `EOT` (`<|plamo:tag|>`, id 16) is the PLaMo3 turn terminator and already stops `Plamo3Parser.is_reasoning_end`.

Out of scope: the direct-engine streaming path does not apply `_prompt_closes_reasoning`; production uses the registered delegating parser.

Duplicate check: no PLaMo3 issue or PR covers this; #61857 is the parent and is merged.
