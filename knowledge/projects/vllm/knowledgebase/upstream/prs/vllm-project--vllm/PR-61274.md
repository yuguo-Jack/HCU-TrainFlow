# [Quantization] Auto-disable DeepGEMM for Kolibri 1 on SM12x

[Upstream PR](https://github.com/vllm-project/vllm/pull/61274) · state: closed · merged: True

## Original PR description

## Overview

Auto-disable DeepGEMM for Kolibri 1 on SM12x, next to the existing Qwen3.5 exclusions, and apply the exclusions to automatic FP8 MoE backend selection. Follow-up to #60827; 

## Claims

- On B200, Kolibri 1 FP8 is faster at the defaults than with `VLLM_USE_DEEP_GEMM=0`., no claimed accuracy issues could be found
- On SM12x, FP8 MoE layers of excluded models select Triton instead of DeepGEMM. SM90 and SM100 selection is unchanged.
- On DGX Spark, Kolibri 1 and Qwen3.5-35B-A3B FP8 now run as fast at the defaults as with `VLLM_USE_DEEP_GEMM=0`, with GSM8K unchanged.

## Details

The exclusions only reached the dense DeepGEMM kernel; `select_fp8_moe_backend` checked only the environment variables. On SM12x, block-FP8 MoE has no TRTLLM or FlashInfer CUTLASS backend, so DeepGEMM was selected. With E8M0, `TritonOrDeepGemmExperts` then runs DeepGEMM for every shape, including the N ≤ 512 experts it otherwise leaves to Triton; Kolibri 1 and Qwen3.5-35B-A3B both use 512. On SM100 these models select TRTLLM ahead of DeepGEMM, so only the dense kernel is affected there.

Kolibri's entry is for latency, so the warning no longer cites accuracy. An explicit `VLLM_USE_DEEP_GEMM=1` still selects DeepGEMM for MoE.
