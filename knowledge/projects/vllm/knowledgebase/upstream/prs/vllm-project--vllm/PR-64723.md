# [Perf][Qwen3.5] (NVIDIA path) Fused AR+norm+quant

[Upstream PR](https://github.com/vllm-project/vllm/pull/64723) · state: closed · merged: True

## Original PR description

## Overview

Fuses the consumer's activation quant into the TP all-reduce + Gemma RMSNorm on the Qwen3.5 NVIDIA path, via FlashInfer's `kARResidualRMSNormOutFP8Quant` / `kARResidualRMSNormOutFP4Quant`. Targets `nvidia/Qwen3.8-2.4T-A95B-NVFP4`.

## Claims

- On `nvidia/Qwen3.8-2.4T-A95B-NVFP4` (MoE, no EP) at TP8, all **92 input norms per decode step** produce the static FP8 input of their projection (69 GDN `in_proj_qkvz` + 23 attn `qkv_proj`); 91 of them in the same kernel as the all-reduce (layer 0 has no all-reduce and uses #64509's norm-quant).
- The fused kernel's outputs (new residual, bf16 norm output, FP8 / NVFP4 codes, swizzled 128×4 NVFP4 scales) are bitwise identical to FlashInfer AR + norm followed by `scaled_fp8_quant` / `scaled_fp4_quant`.
- Above the FlashInfer workspace budget, static FP8 / NVFP4 use an explicit all-reduce + #64509's Triton norm-quant, keeping quant fusion at every batch size.
- Model-private: no torch.compile pass or custom op, and no changes to shared code.

## E2E perf

`nvidia/Qwen3.8-2.4T-A95B-NVFP4` (MoE, no EP), TP8 across two 4× GB300 nodes (FlashInfer MNNVL all-reduce). `vllm bench serve`, random 8192 input / 1024 output tokens, `--ignore-eos`, 10 warmups, 8 × concurrency prompts, median TPOT. Base = merge-base `main`. Same two nodes for both arms, alternating; ranges over 3 base runs and 2 PR runs.

| Concurrency | Base TPOT | PR TPOT | Change |
|---:|---:|---:|---:|
| 1 | 8.28–8.30 ms | 7.95 ms | −4.0 to −4.2% |
| 16 | 17.24–17.38 ms | 17.18–17.34 ms | −1.2 to +0.6% |
| 64 | 39.89–40.33 ms | 39.47–39.84 ms | −2.1 to −0.1% |

At c1 the step saves ~0.34 ms, ~3.7 µs per fused input norm, consistent with removing the consumer's standalone FP8 quant kernel per norm. At c16/c64 the change is within run-to-run spread.

## Validation

- `tests/models/qwen3_5/test_fused_allreduce_norm_quant.py` (TP2, one spawn): `Qwen3_5RMSNorm.forward_fused` against the chain it replaces, with real ModelOpt static FP8 and NVFP4 linears as consumers.
  - AR + norm + quant, M = 1/17/333: residual, bf16 norm output, codes and NVFP4 scale bytes bitwise identical to FlashInfer AR + norm + `scaled_fp8_quant` / `scaled_fp4_quant`.
  - M = 8192 (above the TP2 workspace budget, Triton fallback): residual bitwise; norm output and codes within the Triton norm-quant's reduction-order tolerance (≤ 1 code step, ≤ 1e-4 of entries).
  - No all-reduce, and unquantized consumers: same paths as before this PR.
- `tests/models/qwen3_5/`: 50 passed on 2× GB300.

## Details

- `ops/fused_allreduce_norm_quant.py` calls `flashinfer_comm.allreduce_fusion` directly on the quant workspace (`get_fi_ar_quant_workspace`). It returns the `QuantizedActivation`, the bf16 norm output (GDN's `in_proj_ba` reads it) and the new residual, or None when the fused kernel does not apply.
- `Qwen3_5RMSNorm.forward_fused(x, residual, linear, *, write_y)` is the single entry point for the decoder-layer norms: it absorbs the deferred all-reduce when the norm was built with `reduce_inputs` (input norm: MLP output is a TP partial; post-attention norm: attention all-reduce deferred) and a residual is given, and quantizes for `linear`'s input when the norm can produce its key. `forward()` keeps the plain `(y, residual)` contract (final and MTP norms).

Dispatch (decoder-layer norms):

| Case | Path |
|---|---|
| TP>1, FlashInfer AR, static per-tensor FP8 consumer | AR + norm + FP8 (FlashInfer) |
| Same, NVFP4 with no K padding and `K % 64 == 0` | AR + norm + NVFP4 (FlashInfer) |
| Static FP8 / NVFP4, above the FlashInfer workspace budget | Explicit AR + Triton norm-quant |
| Everything else (block FP8, dynamic per-token FP8, padded NVFP4, BF16, W4A16, LoRA; MoE router input) | AR + norm; consumer quantizes as before |
| TP1 or non-FlashInfer-AR model path | Norm(-quant) from #64509, unchanged |

Complementary to @benchislett's draft #56530: that PR targets torch.compile/Inductor AR+norm+FP8 patterns with Gemma support and shared qkvz/ba quantization for 2.4T. This PR targets the eager NVIDIA path and retains the bf16 `ba` input; the open-PR search found no other change covering this scope.
