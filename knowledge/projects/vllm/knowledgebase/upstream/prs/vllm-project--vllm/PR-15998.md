🟢 **bug** (low)

The new `AIMODataset` branch hardcodes the split to `"train"`, whereas the sibling HuggingFace branch right above it forwards the user-supplied value (`common_kwargs['dataset_split'] = args.hf_split`). As a result, `--hf-split` is silently ignored for the AIMO dataset paths, and the new README example for `AI-MO/aimo-validation-aime` even passes `--hf-split train`, which gives users the impression that the flag is honored. Impact is limited today because the `AI-MO/*` datasets only expose a `train` split, but the inconsistency is easy to trip over later (e.g. if another split is added, or if `--hf-split` is used with one of the other paths in `AIMODataset.SUPPORTED_DATASET_PATHS`).

**建议**: Either forward the CLI value, matching the surrounding code:

```python
common_kwargs['dataset_split'] = args.hf_split
```

(optionally with `dataset_split: str = "train"` as the default in `AIMODataset`), or, if `"train"` is genuinely required for these datasets, add a short comment explaining why and drop/adjust the `--hf-split train` line in the README example so the documentation is not misleading.

**证据**: `common_kwargs['dataset_split'] = "train"`
