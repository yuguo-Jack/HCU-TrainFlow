# [Bugfix][MoE][NVFP4] Keep the derived NVFP4 MoE input global scales as layer parameters

[Upstream PR](https://github.com/vllm-project/vllm/pull/61166) · state: open · merged: False

## Original PR description



## Overview

`make_nvfp4_moe_quant_config` recreates `a1_gscale = 1 / a13_scale` (read by `prepare()` for input quantization) on every `process_weights_after_loading`. Because it is not a parameter, weight reload never restores it into the storage captured by CUDA graphs. After `sleep(level=2)` that storage is gone and MoE outputs become garbage. This PR keeps the reciprocal scales as layer parameters, like `g1_scale_c`. It covers the "NVFP4 reciprocal-scale chains" item of #48312.

## Claims

- `sleep(level=2)` + `wake_up` + `reload_weights` no longer corrupts NVFP4 MoE outputs under CUDA graphs.
- No change for plain reloads, or when no layer is passed.

## Validation

GB300, RedHatAI/Qwen3.6-35B-A3B-NVFP4 (FlashInfer TRT-LLM MoE), TP1, CUDA graphs. 8 greedy prompts compared with the cold run:

| | `reload_weights` | `sleep(2)` + `wake_up` + `reload_weights` |
|---|---|---|
| main | 8/8 | 0/8 |
| this PR | 8/8 | 8/8 |

GSM8K (1319, 5-shot): main 59.89% cold → 16.83% after `sleep(2)` + reload; this PR 59.89% → 59.89%.

```python
llm = LLM("RedHatAI/Qwen3.6-35B-A3B-NVFP4", enable_sleep_mode=True)
cold = llm.generate(prompts, greedy)
llm.sleep(level=2); llm.wake_up(); llm.collective_rpc("reload_weights")
after = llm.generate(prompts, greedy)   # main: every prompt differs
```

```bash
pytest tests/kernels/moe/test_nvfp4_moe_quant_config_reload.py   # 1 passed (new)
pytest tests/kernels/moe/test_trtllm_nvfp4_moe.py                # 23 passed on main and this PR
```

## Details

- With a layer, the two reciprocals are kept via `replace_parameter(layer, "moe_a1_gscale"/"moe_a2_gscale", ..., prefer_copy=True)`. Layerwise reload restores parameters into their capture-time storage. New names avoid clashing with compressed-tensors' `w13_input_global_scale` checkpoint parameter.
- #49789 (`ReloadArena`) also stabilizes these tensors, but only for the CUTLASS backends. This 9-line fix also covers TRT-LLM.
- Not tested with EPLB.
- No other open PR addresses this (searched "nvfp4 a1_gscale reload", "48312 in:body nvfp4").
- AI assistance (Claude Code) was used; I reviewed every changed line and the results.
