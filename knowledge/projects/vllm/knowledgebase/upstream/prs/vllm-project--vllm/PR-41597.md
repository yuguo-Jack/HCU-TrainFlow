Slicing a Hadamard matrix $H_N$ to $d \times d$ (where $d < N$) results in a matrix that is no longer orthogonal ($H' (H')^T \neq I$). This is a critical issue for the TurboQuant algorithm because the rotation logic relies on an orthonormal transformation to preserve the distribution of values and allow for accurate reconstruction. For example, the inverse rotation in the continuation prefill path (lines 770-771) will fail to recover the original values if the matrix is not orthogonal.

For non-power-of-2 dimensions (like Phi-2 with $d=80$), a better approach is to generate a proper $d \times d$ symmetric orthogonal matrix. This can be done by taking a random orthogonal matrix $Q$ and forming $S = Q D Q^T$ where $D$ is a diagonal matrix of $\pm 1$. This ensures the matrix is both orthogonal and symmetric, maintaining compatibility with the existing code that assumes $Pi = Pi^T = Pi^{-1}$.

```suggestion
    if H.shape[0] == d:
        return (H / math.sqrt(d)).to(torch.device(device_str))

    # For non-power-of-2 dimensions (e.g. d=80), slicing a Hadamard matrix
    # breaks orthogonality. Generate a symmetric orthogonal matrix instead.
    g = torch.Generator(device='cpu').manual_seed(42)
    Q, _ = torch.linalg.qr(torch.randn(d, d, generator=g))
    # S = Q * D * Q^T is symmetric and orthogonal if D has elements in {-1, 1}
    D = torch.ones(d)
    D[1::2] = -1
    S = (Q * D) @ Q.t()
    return S.to(torch.device(device_str))
```
