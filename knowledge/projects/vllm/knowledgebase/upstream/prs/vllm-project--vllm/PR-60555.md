# [Bugfix][Anthropic] Preserve inline system messages for native encoders

[Upstream PR](https://github.com/vllm-project/vllm/pull/60555) · state: open · merged: False

## Original PR description



## Overview

Preserve mid-conversation `system` messages in `/v1/messages` for native
encoders (DeepSeek V4.1) instead of hoisting them into the leading system
prompt when `--chat-template` is omitted. Fixes #60537.

## Claims

- `deepseek_v41` deployments without `--chat-template` no longer merge
  inline system messages; prompt prefixes stay stable across turns.
- Fallback preserved: renderers without native support still merge
  (conservative default unchanged).

## Validation

- Issue repro on current code: `Default True` (wrong) / `Official False`;
  the `True` comes from probing the missing CLI override instead of the
  encoder's capabilities.
- New tests: `test_native_encoder_without_cli_template_preserves` and
  `test_no_marker_without_template_still_merges`.
- Commands run:
  - `.venv/bin/python -m pytest tests/entrypoints/anthropic/test_anthropic_messages_conversion.py -q` → **107 passed**
  - `pre-commit run --files vllm/tokenizers/deepseek_v41.py vllm/entrypoints/anthropic/serving.py tests/entrypoints/anthropic/test_anthropic_messages_conversion.py` → all hooks passed (ruff, mypy, test-tethering, config-defaults).
- Duplicate checks: no open PR references #60537; complements merged
  #58754 (HF-renderer path) and is narrower than stalled draft #58772
  (full preserve/fold redesign).

## Details

Root cause: `DeepseekV4Renderer` extends `BaseRenderer`, not `HfRenderer`
(`vllm/renderers/deepseek_v4.py:24`), so `_should_merge_inline_system`
(`vllm/entrypoints/anthropic/serving.py:243`) probed only the CLI
`chat_template` (`None` when unset) and `_detect_merge_inline_system(None)`
returned `True`. The registry maps both `deepseek_v4` and `deepseek_v41`
to the shared renderer class, so renderer type alone cannot distinguish
them — the fix reads a `supports_inline_system_messages` capability flag
from the tokenizer (set by the V4.1 wrapper, whose Python
`encode_messages` renders mid-conversation systems in place per
`deepseek_v41_encoding.py:297`). Absent flag → current behavior.
`getattr(..., False) is True` keeps the check safe against mock
tokenizers in existing tests.
