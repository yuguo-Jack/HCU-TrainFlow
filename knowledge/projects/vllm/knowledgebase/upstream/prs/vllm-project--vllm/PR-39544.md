# [Bugfix][V1] Retain encoder cache entries for multimodal models under async scheduling

[Upstream PR](https://github.com/vllm-project/vllm/pull/39544) · state: closed · merged: False

## Original PR description

## Purpose

Fixes https://github.com/vllm-project/vllm/issues/38551. Builds on #38907 (intra-step reorder fix, merged).

With async scheduling + MTP, the scheduler frees encoder cache entries before the GPU has consumed them. This causes `AssertionError: Encoder cache miss` in `_gather_mm_embeddings` via three paths:

- **Speculative rollback** — scheduler frees based on speculative `num_computed_tokens`; MTP rollback needs the entry again next step
- **Preemption** — `num_computed_tokens` resets to 0 but entry already freed based on pre-preemption value
- **Hash reuse** — sequential requests share an image hash; first request's completion evicts it, second request crashes

This PR suppresses eviction at the scheduler level for multimodal models: `_get_freed_encoder_hashes()` drains the bookkeeping buffer but returns `[]`. Entries are retained in GPU memory. Encoder-decoder models (e.g. Whisper) are unchanged.

**Related:** #38907 (intra-step reorder), #38622 (graceful skip, based on workaround in #38551)

## Evidence

Tested on Qwen3.5-VL-27B-FP8 + MTP on L40S, vLLM v0.19.1.

**The bug exists without this fix:**
- Under sustained multimodal traffic (~60K requests across 4 instances), `_gather_mm_embeddings` encounters missing encoder cache entries despite #38907 being active — confirming the cross-step race is independent of intra-step timing.
- Under 80 concurrent multimodal requests with diagnostic patches, we observed entries freed by the scheduler that MTP still needed on the next step after speculative rollback.
- An intermediate fix based on `num_computed_tokens` (evict only after GPU progress passes the entry) still crashed: preemption resets `num_computed_tokens` to 0 and sequential requests reuse the same image hash after the prior request evicted it.

**With this fix (full retention):**
- 33 concurrent multimodal requests including repeated identical images across requests — zero `AssertionError`, zero missing entries. Stable for 29+ minutes under continuous load.

### Workload that triggers this

- 1-2 large images per request (base64 data URI, ~1000x1400 px)
- Long generated output (`max_tokens >= 2048`)
- Multiple concurrent requests
- High KV cache pressure triggers preemption, which resets `num_computed_tokens` and re-requests encoder outputs

## Code Review

This pull request transitions encoder cache eviction for multimodal models from the scheduler to the model runner, utilizing actual GPU progress to determine when entries can be safely removed. This modification prevents premature cache clearing and potential misses during speculative decoding. Feedback was provided concerning the performance of the linear scans implemented in the new eviction methods, which may become a bottleneck as the number of requests and features per request increases.
