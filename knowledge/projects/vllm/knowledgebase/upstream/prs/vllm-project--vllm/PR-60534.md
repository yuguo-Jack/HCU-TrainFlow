# [Bugfix][Multimodal] Count frames when OpenCV metadata is missing

[Upstream PR](https://github.com/vllm-project/vllm/pull/60534) · state: closed · merged: False

## Original PR description

## Overview

Fixes #60518 by counting frames when OpenCV reports a non-positive frame count, then reopening the stream before normal sampling.

## Claims

- Finite WebM streams without index metadata and raw H.264 inputs return all decoded frames with valid duration metadata.
- Videos with a reported frame count continue through the existing metadata path.

## Validation

- `.venv/bin/python -m pytest tests/multimodal/test_video.py::test_opencv_counts_frames_when_video_metadata_is_missing tests/multimodal/test_video.py::test_video_backend_handles_edit_list_trimmed_video -q` — 2 passed.
- Manual loader checks: streamed WebM returned 20/20 frames (2.0 s); raw H.264 returned 20/20 frames (0.8 s).
- Pre-commit hooks passed, including ruff, mypy, test tethering, and DCO.
- CPU-only validation is sufficient; this path does not use model inference or accelerator kernels.

## Details

OpenCV can expose a large negative `CAP_PROP_FRAME_COUNT` for finite streams without container indexes. The OpenCV backend now counts successful grabs for that case and reopens the byte stream before sampling, since stream backends can report a successful seek without actually rewinding.
