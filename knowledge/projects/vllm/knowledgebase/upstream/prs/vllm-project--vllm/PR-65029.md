# [Bugfix][Frontend] Report the line of a run-batch request rejected by request validators

[Upstream PR](https://github.com/vllm-project/vllm/pull/65029) · state: open · merged: False

## Original PR description

## Overview

`vllm run-batch` checks every input line before loading the model and reports a bad one as `Invalid request on line N: ...`. That only works for pydantic errors. A line that fails one of vLLM's own request checks, such as an empty `prompt`, `stream_options` without `stream`, or `top_logprobs` without `logprobs`, crashes the run with a bare `VLLMValidationError` traceback that doesn't say which line is bad.

## Claims

- `validate_batch` now reports `VLLMValidationError` from the chat and completion request models the same way as pydantic errors: `Invalid request on line N: <message>`, before the model loads.

## Validation

Repro (3-line batch, line 3 has `"prompt": ""`), `vllm run-batch -i bad.jsonl -o out.jsonl --model Qwen/Qwen3-0.6B`:

- Before: `vllm.exceptions.VLLMValidationError: Either prompt or prompt_embeds must be provided and non-empty. (parameter=prompt)` (no line number).
- After: `ValueError: Invalid request on line 3: Either prompt or prompt_embeds must be provided and non-empty. (parameter=prompt)`, exit 1 after about 10 seconds, without loading the model. Same for a chat line with `top_logprobs` but no `logprobs`.

Tests (RTX 4070 Laptop, WSL2 Ubuntu, Python 3.12):

```
pytest tests/entrypoints/launchers/test_run_batch.py -k validate_batch
```

- Without the fix: the new `test_validate_batch_reports_request_validation_errors` fails in both cases with `VLLMValidationError` (2 failed, 2 passed).
- With the fix: 4 passed.

## Details

The request models' `mode="before"` validators raise `VLLMValidationError`, which is a `VLLMClientError`, not a `ValueError`, so pydantic doesn't wrap it in a `ValidationError` and it escapes the `except` in `validate_batch`. The fix adds it to that `except`. The runtime path (`run_one_request`) is unchanged; it only parses lines that already passed validation. The test calls `validate_batch` directly, like the existing `validate_batch` tests, because the failure happens before any engine starts.

This doesn't overlap #64102, which handles a missing or non-string `url` (a `KeyError` in `check_type_for_url`). The code changes don't conflict, but both PRs add a test right after `test_validate_batch_rejects_malformed_request`, so whichever lands second needs a small test-file merge.

I found this while using Claude Code to test `vllm run-batch` on main against deliberately invalid batch files, on a local Qwen3-0.6B. Claude Code also wrote the first version of the fix and the test. I reproduced the crash on my machine, reviewed every changed line, and ran the tests and pre-commit above myself.
