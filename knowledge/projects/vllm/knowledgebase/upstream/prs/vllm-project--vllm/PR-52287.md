# [Bugfix] Preserve SWA replay windows after EAGLE tail pop

[Upstream PR](https://github.com/vllm-project/vllm/pull/52287) · state: open · merged: False

## Original PR description

Fixes #51761.

This updates the existing offload replay-window PR in response to the maintainer's request; it does not introduce a competing PR or a separate lookup algorithm.

The offload configuration records the drafter chunk sizes once. During prefill, EAGLE groups receive the prompt store horizon. The existing reachable-block mask also retains the drafter window ending at that horizon, including its peek chunk, and the other SWA groups' window one drafter chunk earlier. The horizon respects the existing full-attention alignment. Per-request replay-boundary state and the duplicated lookup traversal are removed.

The store/completion/replay regressions keep their observable checks: a 30,208-token prompt replays 30,144 tokens with the required C4 keys resident; aligned and full-attention controls retain no extra keys; decode storage remains monotonic. The focused store/replay cases pass (4/4), and the combined replay plus unaligned-SWA suite passes (100 tests). Ruff formatting and lint checks pass. Model-level serving/accuracy evaluation was not run in this CPU environment.
