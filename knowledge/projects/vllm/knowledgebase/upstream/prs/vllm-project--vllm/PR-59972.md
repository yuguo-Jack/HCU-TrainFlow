# [Docs] Update batch invariance tested models (Blackwell validation)

[Upstream PR](https://github.com/vllm-project/vllm/pull/59972) · state: open · merged: False

## Original PR description

## Overview

Update the batch invariance tested-models list from validation runs on NVIDIA GB300 (SM 10.3): add six models that pass the full suite, and correct two entries that no longer work. Part of the model-coverage request in #27433.

## Claims

- Add `Qwen/Qwen3-32B`, `Qwen/QwQ-32B`, `Qwen/Qwen3-235B-A22B`, `Qwen/Qwen3-Coder-30B-A3B-Instruct`, `Qwen/Qwen2.5-72B-Instruct` and `deepseek-ai/DeepSeek-R1-Distill-Qwen-32B`. Each passes all 22 tests in `tests/v1/determinism/test_batch_invariance.py`.
- Remove `Qwen/Qwen3-Next-80B-A3B-Instruct` and the GPT-OSS entries (`openai/gpt-oss-20b`, `openai/gpt-oss-120b`) from the tested list, and note why. These models no longer start in batch-invariant mode.

## Validation

NVIDIA GB300 (SM 10.3, 278 GB per GPU), driver 580.167.08, CUDA toolkit 13.1, vLLM `f590eb2448`, torch 2.13.0+cu130, Triton 3.7.1.

```bash
VLLM_TEST_MODEL=<model> VLLM_TP_SIZE=<tp> VLLM_TEST_TP_SIZE=<tp> \
  pytest -v tests/v1/determinism/test_batch_invariance.py
```

| Model | GPUs (TP) | Memory setting | Result |
| --- | --- | --- | --- |
| `Qwen/Qwen3-32B` | 1 | default | 22 passed |
| `Qwen/QwQ-32B` | 1 | default | 22 passed |
| `Qwen/Qwen3-235B-A22B` | 2 | `VLLM_GPU_MEMORY_UTILIZATION=0.95` | 22 passed |
| `Qwen/Qwen3-Coder-30B-A3B-Instruct` | 1 | default | 22 passed |
| `Qwen/Qwen2.5-72B-Instruct` | 1 | `VLLM_GPU_MEMORY_UTILIZATION=0.9` | 22 passed |
| `deepseek-ai/DeepSeek-R1-Distill-Qwen-32B` | 1 | default | 22 passed |

All runs cover FLASH_ATTN, FLEX_ATTENTION and TRITON_ATTN. The memory setting is raised only where the weights do not fit in the suite's default 50% of GPU memory. For the last three models each test id ran in its own pytest process.

Entries that no longer start:

- `Qwen/Qwen3-Next-80B-A3B-Instruct`: `test_simple_generation` fails at engine start on all three backends with `RuntimeError: VLLM batch_invariant mode is not supported for GDN_ATTN.`
- `openai/gpt-oss-20b` and `openai/gpt-oss-120b`: 20 of 22 tests fail at engine start; the two that pass are negative-control tests that run with batch invariance off. FLASH_ATTN and FLEX_ATTENTION are rejected with `attention sinks not supported`, and with TRITON_ATTN the MoE backend selection fails with `NotImplementedError: No MXFP4 MoE backend supports the deployment configuration` (reason given for the Triton and Marlin kernels: `kernel does not support batch invariance`). `test_simple_generation` for `openai/gpt-oss-20b` fails the same way on an NVIDIA A10.

## Details

**Qwen3-Next.** It was added to the tested list with the original doc (#27839). Since #40193, the attention selector raises when a Mamba-type backend does not support batch invariance, and Qwen3-Next's Gated DeltaNet layers use `GDN_ATTN`. #42960 tracks GDN support and #45819 is the open PR. `Qwen/Qwen3.5-35B-A3B` and `Qwen/Qwen3.5-122B-A10B` fail the same way, which is why the note mentions Qwen3.5.

**GPT-OSS.** The entries were added in #33688. Since #36286, MoE kernels are filtered out in batch-invariant mode unless they declare `_supports_batch_invariance()`, which defaults to false, and the MXFP4 MoE kernels do not declare it. So no MoE backend is left for these models.

In both cases the list currently names models that cannot start in this mode. I removed them and added a short note below the list. The entries can come back once support lands.
