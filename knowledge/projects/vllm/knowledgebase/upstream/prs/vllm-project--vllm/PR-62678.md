# [ROCm][Bugfix] Keep model-dtype Q for FP8-KV sink layers in sparse MLA (HY V4)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62678) · state: closed · merged: False

## Original PR description

Fixes #58487

Depends on and is stacked on [#57134](https://github.com/vllm-project/vllm/pull/57134) at `736e56464049241385735657f682c606d7c66453`.

## Problem

`tencent/Hy4-preview-FP8` ships no KV/Q scales (`kv_cache_quant_algo: null`). With `--kv-cache-dtype fp8` on `ROCM_AITER_MLA_SPARSE`, HY V4's RoPE + learnable-sink layers quantize the absorbed query to e4m3 with a static scale of 1.0. They then run AITER's non-persistent FP8 return-LSE decode and fold the sink in afterwards. GSM8K drops from 95% to 50% in #58487.

Measured on real checkpoint weights, Q and K stay far inside e4m3 range (`|Q| <= 17`, `|K| <= 6.5`). Calibrated per-tensor or per-token scales leave the rounding error unchanged (K relative error 2.65% with scale 1.0 and with an amax scale, across all 79 layers). Keeping Q in model dtype reduces the measured per-layer logit error by about 30%.

## Change

- Route FP8-KV layers with attention sinks to the ragged Triton sparse-MLA kernels. Those kernels take model-dtype Q, dequantize FP8 KV rows with the layer `k_scale` from #57134, and apply the sink in-kernel.
- Use split-K decode only for power-of-two row widths. The split-K reduce spans the whole row and cannot compile for 576-wide RoPE rows.
- Preserve existing routing for models without sinks (DeepSeek V3.2) and NoPE models (GLM-5.3-Flash).

## Validation

CPU/Triton-interpreter validation used the patched source with `TRITON_INTERPRET=1` in `vllm/vllm-openai-rocm:nightly` (`sha256:52260b1287846e11a3b8f6ae37747ff2b59af7220027da8e5bc44d2899076114`):

```text

negative control ignoring kv_scale: relative error 8.32e+01
512-wide FP8 KV split-K(4): relative error 2.29e-04
576-wide split-K: rejected with "arange's range must be a power of 2"
forward_mqa, H=8, 700-key row: relative error 2.20e-04; Q stayed fp16; AITER was not called
ALL CHECKS PASSED
```

Touched-file pre-commit checks and `git diff --check` pass.

MI355X source tests on card 1 / HIP 3, using the same nightly image:

```text
pytest tests/kernels/attention/test_rocm_aiter_mla_sink.py \
       tests/v1/attention/test_rocm_glm5next_sparse.py \
       tests/v1/attention/test_rocm_aiter_triton_sparse_mla.py \
       tests/models/test_hyv4_rocm.py
102 passed, 1 skipped, 15 warnings in 275.85s
```

The pre-fix long-row attribution case (`H=8`, FP8 Q/K, sequence lengths `0,1,600,2048,1500`, top-k 2048) fails on AITER's FP8 return-LSE path:

```text
LSE max absolute error: 4.376829688e-02
LSE elements outside rounding budget: 8/40
LSE max budget ratio: 1802.094777x
output max absolute error: 1.404914021e-02
output relative L2 error: 2.863572161e-02
output max budget ratio: 1.418165x
```

This confirms the long-row AITER path is incorrect for the tested shape. It does not by itself quantify how much of the reported end-to-end accuracy collapse comes from that path versus accumulated double-FP8 Q/K noise.

Matched TP8 end-to-end GSM8K and GPQA-Diamond results are pending. Six cards remained occupied by other users when cards 1 and 2 became free, so no safe TP8 window was available. The mandated local occupancy checker was then removed by an external cleanup, at which point GPU work stopped. No end-to-end BF16/FP8 accuracy or truncation result is claimed.
