# [Doc] Fix Case 4 math rendering in hybrid KV cache manager

[Upstream PR](https://github.com/vllm-project/vllm/pull/64188) · state: closed · merged: True

## Original PR description

## Overview

Fix the two Case 4 equations in the Hybrid KV Cache Manager design document that render as literal LaTeX on the published documentation site. Resolves #64178.

## Background and fix status

Issue #64178 records that the published Case 4 equations appear as literal LaTeX. The underlying `main` Markdown lacks blank lines around display math inside numbered list items; the full MkDocs build reproduces raw `$$` in the generated HTML. This PR proposes the four-line spacing fix. It is open for review and has not been merged or deployed.

## Claims

- Add the blank lines required for Arithmatex to parse display math inside numbered list items.
- Preserve the existing equations and the display-math style used elsewhere in this document.
- This does not duplicate #63717 or #63728: those PRs modify other equations in the same file, while this PR changes only Case 4.

## Validation

- `API_AUTONAV_EXCLUDE=vllm PYTHONUTF8=1 python -m mkdocs build --clean`: completed before and after the change using the repository's pinned docs dependencies.
- In the generated Case 4 HTML, Arithmatex nodes changed from 1 to 3 and literal `$$` delimiters changed from 4 to 0. The malformed `<em>` tag disappeared.
- `git diff --check`: passed.
- `pre-commit run markdownlint-cli2 --files docs/design/hybrid_kv_cache_manager.md`: passed.
- Browser automation could not inspect localhost due to its URL security policy. The human submitter reviewed the four-line diff and confirmed the local document change before submission.
- The full pre-commit hook could not complete in the Windows environment while initializing unrelated hook environments; the targeted Markdown lint and full docs build above completed.

## Details

Arithmatex requires block math to be separated by empty lines. In Case 4, the opening `$$` followed the numbered-list text immediately, so Markdown emitted raw delimiters and interpreted underscores in the first equation as emphasis. Adding blank lines before and after the two display-math blocks makes them parse like other block equations in the same document. No formula content or vLLM runtime code changes.

AI assistance was used to investigate the Markdown rendering, prepare the four-line change, and run the documentation builds. The human submitter reviewed every changed line and validated the rendered page before submission.
