# [Perf][DSv4.1] DeepSeek-V4.1-Flash specialized decode on Hopper (H200 TP4)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64893) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Add a Hopper (SM90) backend to DeepSeek-V4.1's specialized decode executor (#61868), for DeepSeek-V4.1-Flash at TP4 on H200 with DSpark k=5. It is opt-in, as on GB300, through `--additional-config '{"decode_backend":"latency_specialized"}'`. Decode steps of up to 192 rows run in the executor; larger steps, prefill and anything it does not serve fall back to the stock path over the same weights.

Stacked on #61869 (DSpark low-latency decode), #57770 (split-vocabulary greedy argmax) and #64892 (SM90 mHC overlap behind the fused all-reduce). Pure TP4 with Humming MoE also needs humming#177 (humming-kernels 0.1.19, #64802).

**Reviewing:** the Hopper executor commit is the new work, plus the merge of main on top of it, which adapts the stack to main's `DraftLogitsCache` and the moved CuTe DSL primitives. Everything before them comes from #61869 and #64892. #57770 is merged in main. #61869 is still open, so its changes are in this diff until it lands.

**Duplicate check:** there is no other open Hopper backend for the specialized decode. #62958 and #64442 only touch DSpark sampling.

## Claims

- Median ITL on H200 TP4, DSpark k=5, on this branch merged with main: −38% at c1 (8.65 → 5.34 ms) and about −5% at c8 on real prompts; −37% at c1 and −14% at c8 at 64K context. At c16 and above the gain was about 5–7% before the merge and has not been re-measured since.
- Quality is unchanged within noise on GPQA-Diamond, AIME25 and 128K needle retrieval; greedy logprob drift is within the stock run-to-run floor.
- No host syncs in steady-state decode (`VLLM_GPU_SYNC_CHECK=error`, re-run on the merged build: 0 at c1, c8 and c32).
- The Hopper commit changes no core components (model runner, scheduler, KV cache manager); the `model_runner.py` changes in this diff come from #61869. Everything in the Hopper commit is under `vllm/models/deepseek_v41/nvidia/specialized_decode/`, and SM100 behavior is unchanged.

Reproduce:

```bash

  --max-model-len 200000 --max-num-seqs 64 --tokenizer-mode deepseek_v41 \
  --speculative-config '{"method":"dspark","num_speculative_tokens":5}'
```

## Details

**Where the time goes.** At c1 the stock step is mostly fixed per-kernel cost, not bandwidth:
- an isolated ~10 MB GEMV reaches only about 50% of HBM;
- each kernel boundary costs ~0.7–1.8 µs.

So the executor:
- chains kernels with PDL;
- replaces the small-batch MoE, dense FP8 linears, sparse MLA and indexer with SM90 CuTe DSL kernels written for these shapes;
- fuses the small ops around them.

The MoE runs near its streaming limit (about 4 TB/s).

**Compatibility.** The kernels read the weights in stock's layouts:
- Humming MXFP4 × block-FP8 for experts;
- Humming W8A16 for dense layers.

So steps the executor doesn't serve fall back to stock with one copy of the weights. The exception is an FP8 copy of `wo_a`, because stock SM90 keeps it only as BF16. It costs about 0.36 GB per GPU (1.44 GB in FP8 across 43 layers, sharded TP4).

**Size.** About 10.8K lines under `hopper/`, mostly kernels:

| Area | Lines |
|---|---|
| MoE | 4.4K |
| sparse MLA | 2.3K |
| dense GEMM | 1.6K |
| indexer | 0.9K |
| attention-chain fusions | 0.7K |

Plus +342/−85 in the shared specialized-decode package, which lets the executor select its backend by architecture and records metadata builds for the Hopper builders. Plus 1.0K lines of tests.

It mirrors the GB300 backend's structure, so the two share the executor runtime, step schedule and fallbacks.

**Limitations.**
- TP4 on H200 only.
- Steps above 192 rows use stock.
- The gain shrinks with batch size, as the per-kernel overhead is amortized.
