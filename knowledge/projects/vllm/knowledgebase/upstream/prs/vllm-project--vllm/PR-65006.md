# [Model] Nemotron-H: serve FP8 linears as W8A16 with bf16_activations

[Upstream PR](https://github.com/vllm-project/vllm/pull/65006) · state: open · merged: False

## Original PR description

## Overview

`hf_overrides={"bf16_activations": true}` now keeps every activation of a ModelOpt FP8 / W4A16 NVFP4 Nemotron-H checkpoint in BF16. On main the override is ignored: the per-tensor FP8 linears still quantize their inputs (W8A8), and a quantized KV cache or a non-BF16 dtype is accepted.

- `ModelOptFp8W8A16LinearMethod` loads the checkpoint's FP8 `weight`, per-tensor `weight_scale` and `input_scale` like the W8A8 method, dequantizes the weight to the activation dtype once after loading and runs the layer as an unquantized linear. A layerwise reload restores the FP8 parameters and dequantizes again.
- `use_fp8_w8a16()` switches a ModelOpt FP8 (or mixed-precision) config to it. FP8 experts are refused, since the method covers linear layers only.
- `NemotronHForCausalLM` calls `use_fp8_w8a16()` when the HF config sets `bf16_activations`, and `NemotronHForCausalLMConfig` rejects, in that mode, a non-BF16 `--dtype`, a quantized KV cache, and quantization other than ModelOpt FP8 / W4A16 NVFP4.

Split from #62017 by @aoshen02.

## Changes

- `vllm/model_executor/layers/quantization/modelopt.py`: `ModelOptFp8W8A16LinearMethod`, `use_fp8_w8a16()`, the `w8a16` flag on `ModelOptFp8Config`, the dispatch in `build_linear_method`, and the refusal in `ModelOptFp8MoEMethod`.
- `vllm/model_executor/models/nemotron_h.py`: call `use_fp8_w8a16()` before the model is built.
- `vllm/model_executor/models/config.py`: `verify_bf16_activations()`, called from `verify_and_update_config`.
- Tests:
  - `tests/quantization/test_modelopt.py`: dispatch, the dequantize formula (bitwise), and a reload that dequantizes again (GPU);
  - `tests/model_executor/test_nemotron_h_quantization.py`: the config checks, and the lm_head test parametrized over the mode.
