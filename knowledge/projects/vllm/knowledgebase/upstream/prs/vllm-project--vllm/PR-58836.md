# [Bugfix][Metrics][MFU] Bill linear-attention layers of hybrid models separately

[Upstream PR](https://github.com/vllm-project/vllm/pull/58836) · state: open · merged: False

## Original PR description

## Purpose

Fixes #58597.

`AttentionMetrics` bills every layer of hybrid linear-attention models (Qwen3-Next, Qwen3.5) as full attention. `SlidingWindowAttentionParser` only reads `layer_types` when `sliding_window` is set and only counts `"sliding"` entries, so the `"linear_attention"` (Gated DeltaNet) layers are never subtracted. For a 32-layer Qwen3-Next config with `full_attention_interval=4`, `layer_types` has 8 full and 24 linear layers, but `_layer_counts()` returns `(32, 32, 0)`. As the issue shows, the reported MBU then goes past the GPU's peak bandwidth.

As the reporter pointed out, removing those layers from attention alone under-bills (about 0.75x of the bytes actually moved), so this PR does both:

1. `LinearAttentionLayerParser` counts `"linear_attention"` entries in `layer_types` whether or not `sliding_window` is set. `AttentionMetrics._layer_counts` bills only `num_hidden_layers - num_linear_attn_layers`. The SWA split and the per-count `pp_size` division from #55624 are unchanged.
2. New `LinearAttentionMetrics` component (`linear_attn`) for Gated DeltaNet layers, built from `linear_num_{key,value}_heads`, `linear_{key,value}_head_dim` and `linear_conv_kernel_dim`:
   - weights: `in_proj_qkvz` + `in_proj_ba`, `conv1d`, `out_proj`
   - per scheduled request, the conv state (`conv_dim * (kernel - 1)`) and recurrent state (`Hv * dv * dk`) are read and written once per step, with dtypes resolved from `mamba_cache_dtype` / `mamba_ssm_cache_dtype` the same way as `MambaStateDtypeCalculator`
   - no term that grows with context length
   - FLOPs: projections, the conv, and three `dk x dv` matrix-vector products per token and value head for the recurrence
   - heads split across TP (as in `gated_delta_net_state_shape`), layers divided across PP (as in `_layer_counts`)

   The component raises `InvalidComponent` when a model has no linear-attention layers, so dense, SWA and MLA models are unaffected.

Not duplicate work: `gh pr list --state open --search "58597 in:body"` returns nothing, and a search for MFU / linear-attention / hybrid PRs finds only #55624 (merged, SWA only). The two open PRs touching `perf.py` (#55474 logging interval, #54228 MoE expert activation) do not touch layer counting.

Left for follow-ups:
- Mamba / Mamba2 hybrids that use `layers_block_type` (Jamba, Falcon-H1, NemotronH) are still billed as full attention.
- The Qwen3.5 / Qwen3-Next attention output gate (`attn_output_gate: true` doubles the `q_proj` width) is not in `qkv_weight`.
- Small GDN parameters (`A_log`, `dt_bias`, gated norm weight) are left out.
- Models that label non-GDN layers `"linear_attention"` in `layer_types` without the `linear_num_*` fields (for example `glm5_next`, and `bailing_moe_v3_vl`, which maps mamba/conv to that label) now drop those layers from attention but get no `linear_attn` component. They need their own component.

## Test Plan

Six new tests in `tests/v1/metrics/test_perf_metrics.py`, using `create_mock_vllm_config` with `Qwen3NextConfig(num_hidden_layers=32, full_attention_interval=4)`:

- `test_attention_metrics_excludes_linear_attention_layers`: `_layer_counts(per_gpu=False) == (8, 8, 0)`
- `test_model_metrics_includes_linear_attention_for_hybrid`: `ModelMetrics` has a `linear_attn` component with 24 layers
- `test_model_metrics_excludes_linear_attention_for_dense`: a dense `Qwen3Config` gets no `linear_attn` component and its attention counts are unchanged
- `test_linear_attention_decode_read_bytes_independent_of_context`: 8 decode requests at 1k and 32k context give the same linear-attention reads, writes and FLOPs
- `test_linear_attention_state_bytes_per_request`: state read/write bytes match `R * (conv_state + recurrent_state) * L` by hand
- `test_linear_attention_per_gpu_layers_sum_to_whole_model`: per-GPU bytes times `pp_size` equal the whole model

`create_mock_vllm_config` now sets `mamba_cache_dtype` and `mamba_ssm_cache_dtype` to `"auto"` on the mock `cache_config`, matching the `CacheConfig` defaults. The existing SWA, dense, MoE and MLA tests are unchanged.
