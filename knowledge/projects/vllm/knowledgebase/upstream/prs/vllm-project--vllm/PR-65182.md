# [Perf][MRV2][Mamba2] Fuse aligned metadata CUDA graph inputs

[Upstream PR](https://github.com/vllm-project/vllm/pull/65182) · state: open · merged: False

## Original PR description

## Overview

This PR computes align-mode state indices for all Mamba groups once, binds the
persistent group outputs directly as Mamba2 FULL CUDA-graph inputs, and shares
one accepted-token graph buffer across speculative Mamba2 groups.

This removes repeated metadata kernels and graph-staging copies from the
single-request decode path.

## Motivation

This optimization is platform-neutral, but its largest measured impact is on
WSL2, where each eager launch or copy crosses the virtualized host submission
path. The implementation contains no WSL-specific branch or option.

## Claims

- Replaces per-group aligned-state preparation with the existing all-group
  `MambaSpecDecodeGPUContext` launch.
- Avoids one state-index D2D copy per Mamba2 group and speculative step.
- Avoids one accepted-token D2D copy per Mamba2 group and speculative step.
- For the tested eight-group Nemotron 3.5 Super VL configuration, reduces
  `cudaMemcpyAsync` from 25 to 9 calls per step.
- Adds no kernel, user-visible option, or model-specific branch.
- Preserves fallback behavior for non-align, non-MRV2, and non-speculative
  configurations.

## Similar work

Open PR [#58851](https://github.com/vllm-project/vllm/pull/58851) was identified
during duplicate-work review. It introduces broad cross-group metadata caching
for GDN, Mamba, and KDA and extends all-group aligned-index precomputation to
Mamba2, while retaining group-local FULL CUDA-graph staging buffers.

As of 1 Nov, #58851 remains open and review-required, with no update since
16 Oct. It changes 12 files with +395/−249 lines.

- **Production vLLM change:** +69/−15 lines across two runtime files:
  - `vllm/v1/attention/backends/mamba_attn.py` (+45/−12).
  - `vllm/v1/worker/gpu/model_states/mamba_hybrid.py` (+24/−3).
- **Test coverage:** +85 lines in one test file.

This PR is narrower and focuses on the graph-input transport path:

- Mamba2 align mode only.
- No generic cross-group metadata cache.
- No GDN, KDA, ShortConv, or checkpoint changes.
- Direct graph-input aliasing and shared accepted-token metadata, which #58851
  does not implement.

Both approaches opt Mamba2 into the existing all-group aligned-index context.
The similarity is disclosed upfront; the shared precomputation is not claimed
as new work.

## Details

MRV2 already owns persistent block-table pointers and an
`aligned_state_indices[num_groups, max_num_reqs, num_slots]` output in
`MambaSpecDecodeGPUContext`. Mamba2 did not consume that output, so every group
prepared its state indices independently and copied both state indices and
accepted-token counts into graph-stable buffers.

This change:

1. Opts MRV2 Mamba2 builders into the existing all-group aligned-index output.
2. Keeps a batch-sized runtime view while binding a graph-sized persistent
   slice as `state_indices_tensor_d`.
3. Reuses one GPU-resident batch-ordered accepted-token tensor.
4. Skips staging when source and graph input already have the same `data_ptr`.

The graph input is sliced to `decode_cudagraph_max_bs`, so
`max_num_seqs > max_cudagraph_capture_size` remains valid. Non-speculative
Mamba2 binds only aligned state indices.
