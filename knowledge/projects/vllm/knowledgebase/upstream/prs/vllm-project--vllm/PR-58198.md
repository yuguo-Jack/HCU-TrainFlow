# [KV Offload] Request-free CPU->GPU prefetch primitive

[Upstream PR](https://github.com/vllm-project/vllm/pull/58198) · state: open · merged: False

## Original PR description

## Purpose

A paused agentic session's KV is stored on finish and loaded back only when a later request's prefix lookup hits the offloaded tier, so the load sits on that request's critical path. Measurements posted on #57103 put it at 34 / 65 / 104 ms for 4k / 8k / 16k prefixes on one L20 (6.4 µs per prefix token), 1.2–1.4× the resume's own prefill. A request-free prefetch during the tool wait recovered 52–57% of resume TTFT.

This PR adds the engine-side execution primitive for that, and nothing else.

```
OffloadingConnector.request_free_prefetch(block_hashes) -> PrefetchSubmitResult
    outcome: ACCEPTED | DEFERRED | MISSING | ALREADY_AVAILABLE | UNSUPPORTED
OffloadingConnector.take_prefetch_completions() -> list[PrefetchCompletion]
    status:  COMPLETED | CANCELLED
```

**Pipeline:** resolve the target against the GPU prefix cache and the offloaded tier → check free GPU blocks behind a configured reserve → reserve destination blocks → submit the existing async load → register the blocks in the prefix cache when the load finishes.

**Submission and completion are separate.**

| synchronous outcome | meaning |
| --- | --- |
| `ACCEPTED` | destination blocks reserved and load submitted; not readable yet |
| `DEFERRED` | not feasible now: too few free blocks behind the reserve, or the offloaded tier cannot serve yet (`HIT_PENDING` / `RETRY`); nothing reserved, submitted or reclaimed |
| `MISSING` | the target does not resolve to loadable offloaded content |
| `ALREADY_AVAILABLE` | every requested block verified in the GPU prefix cache |
| `UNSUPPORTED` | feature off, prefix caching off, no block pool bound, more than one KV cache group, or block size ≠ hash block size |

Each `ACCEPTED` prefetch produces exactly one completion:
- `COMPLETED` once its blocks are registered as reusable prefix-cache residency.
- `CANCELLED` if `reset_cache()` abandons it.

The submission result also carries block counts: requested, already available, to load, and unresolved. A partial prefix is therefore reported as partial, never implied done.

**Mechanism, not policy.** The primitive does not decide whether, when or for whom to prefetch. It has no lead time, no predictor and no ranking. The #57103 measurements showed "prefetch at pause" keeps 95–100% of the oracle gain while fixed-lead and EWMA predictors keep 5–50%. Under sustained occupancy, every admission policy, including one that knows the true resume order, raised aggregate resume latency (+10…57%).

The reserve is a resource-safety constraint for execution-time feasibility, not an admission policy. A prefetch never preempts a request and never takes a block a request references. Its reservation is an ordinary free-pool allocation, so, like any allocation, it may reclaim unreferenced prefix-cache blocks LRU-first. Whether a prefetch should be allowed to displace idle cached content is a policy question for the caller; a strict "no displacement" mode would need allocator support for drawing only uncached free blocks, which this PR does not add.

## Implementation notes

- **Worker side unchanged.** `OffloadingWorker.submit_load()` already takes a job id and a GPU destination spec with no request attached.
- **While in flight,** destination blocks are ordinary allocated blocks (`ref_cnt == 1`, no hash), so nothing can read a half-filled block.
- **Skipping resident chunks.** Leading chunks already in the GPU prefix cache are skipped. The load is the contiguous run of offloaded chunks after them, and `block_indices` gives the worker the logical start. It stops at the first chunk that is neither resident nor offloaded, since a hole would not serve a prefix lookup.
- **Publication** goes through the new `BlockPool.cache_prefetched_blocks()`, which inserts the caller-supplied hashes and releases the blocks via the existing `unpin_blocks()` path. They are readable but last-resort eviction candidates, which is what makes a wrong prefetch cheap. A block whose hash was cached while the load was in flight (for example recomputed by a request) is released instead of being registered twice.
- **Single KV cache group only for now.** A prefix hit needs every group, so a single-group load on a hybrid model would not be usable residency; such deployments get `UNSUPPORTED`. The destination spec carries one entry per group.
- **Off by default.** It requires prefix caching plus `extra_config["enable_request_free_prefetch"]`; `extra_config["prefetch_reserve_blocks"]` sets the reserve.
- **Metrics:** three counters, `prefetch_accepted`, `prefetch_deferred` and `prefetch_blocks_published`.

**Out of scope:** ingress and result transport. `KvHintsEnvelope` (#53423, merged) is attached to an inference request; a request-free control entry point, the action / target contract, capability advertisement and `(message_id, action_id)`-correlated results belong in a follow-up once agreed on #57103. This PR exposes the primitive to in-engine callers and tests only.

## Test Plan

```bash
pytest -q tests/v1/kv_connector/unit/offloading_connector/
```

`test_prefetch.py` has 31 tests. Most are parametrized over 1 and 4 GPU blocks per offloaded chunk. They cover every outcome and the completion path. The main semantic ones:
- nothing offloaded → `MISSING`, not done;
- partial chunk → `MISSING`;
- `ALREADY_AVAILABLE` only when every block is verified on the GPU;
- resident prefix with nothing offloaded after it → `MISSING`;
- `HIT_PENDING` / `RETRY` → `DEFERRED`;
- deferral leaves cached blocks alone;
- the reservation never takes a referenced block;
- accepted is not readable and records no completion;
- the load stops at the first missing chunk, with the rest reported unresolved;
- resident leading chunks are skipped, with the right `block_indices`;
- `COMPLETED` is recorded only after publication and makes every block readable;
- no duplicate registration when a request cached a block mid-flight;
- `reset_cache()` gives `CANCELLED`;
- published blocks are the last reused;
- more than one KV cache group → `UNSUPPORTED`.

## Test Result

- `test_prefetch.py`: **31 passed**.
- **Mutation checks:** removing the GPU residency check, the publish-time dedup, the pending-lookup deferral or the `block_indices` offset each makes the corresponding tests fail.
