# [Transformers backend] Migrate OLMoE and fix MoE LoRA

[Upstream PR](https://github.com/vllm-project/vllm/pull/63384) · state: closed · merged: True

## Original PR description

## Overview

Migrate OLMoE to the Transformers modeling backend and fix MoE LoRA on that backend.

## Claims

- OLMoE on the Transformers backend matches native performance and gains LoRA.
- MoE LoRA on the Transformers backend no longer asserts in `pack_moe`. The expert mapping included the Mixtral `w1`/`w2`/`w3` aliases, so LoRA saw twice the experts.
- Native MoE test coverage is kept. Tests that used OLMoE as their small MoE model now also run `ibm-granite/granite-3.0-1b-a400m-base` (native, already used in CI), except GGUF, whose plugin does not support GraniteMoE.
- Known gap: OLMoE GGUF needs vllm-project/vllm-gguf-plugin#149, because the plugin assumes 2D linear inputs.

## Validation

`allenai/OLMoE-1B-7B-0924` on B200, mean ± stdev of 3 runs:

| | Native | Transformers |
|---|---|---|
| Throughput (tok/s) | 172.5k ± 3.7k | 173.7k ± 3.0k |
| Latency, batch size 1 (ms) | 447 ± 14 | 411 ± 7 |
| GSM8K, 5-shot | 9.6% | 9.8% |

```bash
vllm bench throughput --model allenai/OLMoE-1B-7B-0924 --model-impl {vllm,transformers} --input-len 1024 --output-len 256 --num-prompts 1000
vllm bench latency --model allenai/OLMoE-1B-7B-0924 --model-impl {vllm,transformers} --input-len 1024 --output-len 256 --batch-size 1
python tests/evals/gsm8k/gsm8k_eval.py
```

`pytest lora/test_olmoe_tp.py` fails without the fix (`assert w1_lora is not None`) and passes with it. The FP8, MXFP8, peak-memory and DP+EP determinism tests pass for both Granite MoE and OLMoE. The bitsandbytes MoE test is skipped on main (bitsandbytes#1849).
