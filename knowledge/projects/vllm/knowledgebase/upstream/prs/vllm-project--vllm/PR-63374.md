# [MM][CG] Support ViT full CUDA graph for Qwen2.5-Omni

[Upstream PR](https://github.com/vllm-project/vllm/pull/63374) · state: open · merged: False

## Original PR description



## Overview

Add ViT full CUDA graph support for Qwen2.5-Omni (`Qwen2_5OmniThinkerForConditionalGeneration`), part of #38175. The Omni thinker uses the same `Qwen2_5_VisionTransformer` as Qwen2.5-VL (#40830), so the Qwen2.5-VL encoder CUDA graph methods move into a shared mixin and both models use it.

No other PR covers this: the model was claimed in #38175, and there is no open PR for Qwen2.5-Omni encoder CUDA graphs.

## Claims

- Qwen2.5-Omni supports `cudagraph_mm_encoder` for images and videos. The audio encoder stays eager.
- Graph replay is bit-identical to eager on the same inputs (same padded buffers and the same max-seqlen values), with FA3 and FlashInfer.
- Encoder-only speedup on H200 is up to 5.5x for small inputs. For large inputs, padding to the token budget makes graphs slower than eager (details below).
- Refactor only for Qwen2.5-VL: its encoder CUDA graph methods move to `Qwen2_5_VLEncoderCudaGraphMixin` without changing behavior.

## Validation

**Correctness (graph vs eager)**

In encoder-only mode I ran the eager encoder on the exact padded buffers that the graph replayed, with the same captured `max_seqlen_full` / `max_seqlen_window`. The output matched the graph replay exactly (`max abs diff = 0`) for single images of 96, 128 and 192 tokens in a 256-token budget, with both `FLASH_ATTN` (FA3) and `FLASHINFER`. Full budgets (no padding) also match the plain eager path exactly.

## Details

- **Mixin instead of copying.** 11 of the 12 Qwen2.5-VL encoder CUDA graph methods work for Omni unchanged. Copying them would add about 300 duplicated lines, so they move to `Qwen2_5_VLEncoderCudaGraphMixin` in `qwen2_5_vl.py`. The only per-model difference is EVS. Qwen2.5-VL disables encoder graphs when EVS pruning is on, and Omni has no EVS, so the mixin calls `_get_encoder_cudagraph_modalities()` and Qwen2.5-VL overrides it. Apart from that, the methods are moved without edits.
- **Omni changes:** use the mixin, set `self.model_config` (two mixin methods need it), and use `get_multimodal_config()` so the attribute matches the mixin's non-optional type.
- **Not added to `test_eonly_vit_cudagraph_outputs`.** That test requires graph output within rtol/atol 0.016 of unpadded eager. Qwen2.5-VL and Qwen2.5-Omni cannot meet this even without CUDA graphs: the same image encoded alone vs batched with another image differs by about 4-8% relative in plain eager (BF16 rounding differences grow through the 32 ViT blocks). Qwen3-VL is batch-invariant here, which is why it passes. Qwen2.5-VL is not in that test either, and fails it in the same way when added. Graph replay itself is exact (see Correctness).
- **Tradeoff: padding.** Graphs remove the ~23 ms launch floor of the eager encoder, so small inputs gain a lot. Inputs are padded up to the next token budget, so with the default power-of-two budgets a 1196-token image runs in a 2048 budget and is slower than eager. Finer budgets reduce this cost. On H200 the end-to-end TTFT gain is small, because the language model prefill takes most of the time. The feature is opt-in (`cudagraph_mm_encoder` is off by default).
- **Not tested:** FA2, Blackwell, ROCm, Qwen2.5-Omni-7B, and video with `use_audio_in_video=True` (the video encoder path is the same, and the audio encoder stays eager).
