# [Model] Add LoRA support for GteNewModel, NomicBertModel, and XLMRobertaModel

[Upstream PR](https://github.com/vllm-project/vllm/pull/40581) · state: open · merged: False

## Original PR description

## Purpose

Add LoRA adapter support for encoder-only embedding models that currently lack it:

- **BertWithRope-based**: `GteNewModel`, `NomicBertModel`, `SnowflakeGteNewModel` (`GteModel`), `JinaRobertaModel`
- **RobertaEmbeddingModel**: `XLMRobertaModel` (e.g., `BAAI/bge-m3`)

These are popular encoder-only embedding models used in retrieval and similarity tasks. LoRA support enables efficient fine-tuning and multi-tenant serving with per-request adapters.

**No duplicate PRs exist** — searched upstream for encoder-only LoRA, BertWithRope LoRA, RobertaEmbeddingModel LoRA, GTE LoRA, and RoBERTa LoRA. Zero open PRs found.

### What changed

**Model changes (minimal):**
- `vllm/model_executor/models/bert_with_rope.py` — Add `SupportsLoRA` mixin to `BertWithRope` with `packed_modules_mapping` for fused QKV (`qkv_proj → [qkv_proj]`) and gated MLP (`gate_up_proj → [gate_proj, up_proj]`)
- `vllm/model_executor/models/roberta.py` — Add `SupportsLoRA` mixin to `RobertaEmbeddingModel` with `hf_to_vllm_mapper` that strips the `roberta.` prefix and prepends `model.` for PEFT weight name translation. Also expose `self.config` (required by the LoRA model manager's `_create_lora_modules`)

**Tests (no network dependencies):**
- `tests/lora/test_gte_new_lora.py` — 4 tests for `Alibaba-NLP/gte-multilingual-base` (GteNewModel)
- `tests/lora/test_roberta_lora.py` — 4 tests for `BAAI/bge-m3` (XLMRobertaModel)
- `tests/lora/test_nomic_bert_lora.py` — 4 tests for `nomic-ai/nomic-embed-text-v1` (NomicBertModel)
- `tests/lora/test_snowflake_gte_lora.py` — 4 tests for `Snowflake/snowflake-arctic-embed-m-v2.0` (GteModel/SnowflakeGteNewModel)
- All tests generate synthetic PEFT adapters locally using `safetensors` (no S3 or HuggingFace adapter downloads)

**Docs:**
- `docs/models/pooling_models/embed.md` — Mark LoRA support for `GteModel`, `GteNewModel`, `NomicBertModel`, `XLMRobertaModel`

**AI assistance:** This PR was developed with AI assistance (Claude). All changes have been reviewed by the human submitter and tests have been run on a GPU machine.

The `packed_modules_mapping` for `qkv_proj` is currently too restrictive as it only maps to `["qkv_proj"]`. While the integration tests for GTE and Nomic BERT use fused QKV targets, many existing PEFT adapters for BERT/RoBERTa architectures target `query`, `key`, and `value` separately. To ensure broader compatibility with standard LoRA adapters, please include these individual components in the mapping.

```suggestion
    packed_modules_mapping = {
        "qkv_proj": ["qkv_proj", "query", "key", "value"],
        "gate_up_proj": ["gate_proj", "up_proj"],
    }
```

I tested the suggestion, it broke LoRA. `n_slices = len(packed_modules_list)`, so a 4-element list produces `n_slices=4`. Yet only 1 (QKVParallelLinearWithLoRA) or 3 (MergedQKVParallelLinearWithLoRA) are supported for QKV layers.

`BertWithRope` models have a single fused qkv_proj in HF, so `["qkv_proj"]` with `n_slices=1` is correct.
