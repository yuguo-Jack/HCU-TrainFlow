# [Bugfix][DSv4.1] Preserve BF16 Engram checkpoint tables

[Upstream PR](https://github.com/vllm-project/vllm/pull/65129) · state: open · merged: False

## Original PR description



## Overview

Load unquantized DeepSeek V4.1 BF16 Engram tables without requiring FP8 scale tensors. Preserve checkpoint precision in GPU and CPU-offloaded lookups while retaining the existing FP8 path.

## Claims

- BF16 SFT checkpoints without quantization metadata load Engram rows as BF16, without `weight_scale_inv` checkpoint parameters or silent casts to FP8.
- BF16 lookup works with GPU, pinned-host, huge-page and DP-shared storage, including uneven TP/DP head shards and CUDA graph replay.
- Existing FP8 scale decoding and packed lookup remain covered by the Engram regression suites.

## Validation

Tested on NVIDIA H200, CUDA driver 595.91.07, Python 3.12.14, PyTorch 2.14.0+cu130, Triton 3.8.0, Transformers 5.22.1, and the precompiled vLLM artifacts for base commit `51c6dfd8c86cebc3ede6f8f15207d0bbd2b1f1fd`.

## Details

`ParallelEngramEmbedding` previously always allocated FP8 rows and registered a scale parameter. A BF16 SFT export contains BF16 rows without that scale, so loading casts rows to FP8 and then fails its missing-weight check. Lookup also unconditionally applies UE8M0 scales.

`EngramLayout` now selects table precision from HF checkpoint quantization metadata, independently of runtime quantization. No quantization metadata selects BF16; existing nonempty quantization metadata retains FP8. The loader rejects mismatched checkpoint dtypes and still accepts UE8M0 scale bytes. The lookup kernel bypasses scale reads for BF16, and storage byte accounting handles two-byte rows. A nonpersistent one-byte scale buffer avoids allocating an empty UVA mapping without adding a required checkpoint tensor.

BF16 uses the existing ordinary head/DP collective path. Packed FP8 batch staging and GPU peer-table reads remain FP8-only. BF16 tables cost approximately 1.94 times the FP8-plus-scale storage at a 32-element scale block. Selectively BF16 Engram tensors in an otherwise quantized checkpoint are outside this contract; mismatches fail loading.

Duplicate-work checks searched open PRs for BF16/unquantized Engram support. Related work such as #56989 (packed FP8 exchange), #57195 (shared-host lookup), #64500 (prefetch), and #64369 (alternate lookup modes) addresses different behaviors, not loading scale-free BF16 checkpoint tables.
