# [Feature][Kernel] Triton autotune block fp8

[Upstream PR](https://github.com/vllm-project/vllm/pull/61686) · state: open · merged: False

## Original PR description

## Purpose

Depends on #59492.

Builds on the generic Triton autotune warmup (`--kernel-config.enable_triton_autotune`) and its block-FP8 table. The earlier version swept the full ~1,280-config grid per M bucket, which was too slow to use at startup. Its search space also copied the grid that produced the bundled tables.

This PR replaces the sweep with a bounded search that does not read any bundled or user tables. It stays useful on new GPUs and models that have no shipped configs.

cc @vanshbhatia-amd 

Changes:

- **Bounded search.** At most 48 configs are timed per M bucket. The search starts from the default config, 8 random configs and up to 2 nearby-M winners, then expands neighbors of the fastest config that hasn't been expanded yet.
- **Backend-derived search space.** Launch options (`waves_per_eu`, `matrix_instr_nonkdim`, `kpack`) and the shared-memory limit come from the installed Triton backend. Nothing is keyed on GPU name. Configs that spill across a quant block are rejected, and `GROUP_SIZE_M` is collapsed when M fits one tile.
- **Correctness and noise guard.** A winner must match the default config's output. It must also beat the default by at least 2% in a side-by-side re-timing, otherwise the default is kept.
- **Nearby-bucket seeding.** Winners tuned on the same rank seed later buckets. This matters under TP, where ranks split the work and the neighboring bucket is often tuned elsewhere.
- **Partial-cache resume.** Only missing M buckets are tuned. Shapes with a user or bundled table are skipped unless `VLLM_TRITON_AUTOTUNE_FORCE=1`.
- **Config lookup cleanup in `fp8_utils.py`.**
  - Path resolution is shared by the loader and the warmup table.
  - Non-dict JSON is ignored.
  - `w8a8_triton_block_scaled_mm` takes an optional keyword-only `config` so candidates run through the real kernel path. Default behaviour is unchanged.

Lookup priority is unchanged: `VLLM_TUNED_CONFIG_FOLDER`, then the autotune cache, then bundled configs, then the default.

## Testing

AMD Instinct MI300X, ROCm container, Triton 3.8.0.

```bash
pytest tests/kernels/quantization/test_block_fp8_autotune.py   # 27 passed
pytest tests/model_executor/test_triton_autotune.py            # 5 passed (2 GPUs visible)
pytest tests/kernels/quantization/test_block_fp8.py            # 125 passed, 356 platform skips
pytest tests/quantization/test_fp8.py                          # 11 passed, 33 skips
pytest tests/compile/passes/test_fusion.py                     # 75 passed, 36 skips
```

**End to end.** Qwen3-30B-A3B-FP8, which uses the same 128×128 block-FP8 format, with TP=8 on 8×MI300X. Settings were `--max-model-len 4096`, input 128, output 32, batch 8 and `VLLM_ROCM_USE_AITER=0`. vLLM started and served requests with TP=8. The warmup tuned 36 items: 2 weight shapes × 18 M buckets, with 4–5 items per rank and 0 failures and a second launch reused the saved cache and did not retune.

**Model latency** (50 iterations, batch 8):
- Autotuned was 6.2% faster

**Single kernel** (speedup over the default config, median of 4 interleaved runs):
| Weight shape (N, K) | M=8 (small batch) | M=1024 (large batch) |
|---|---|---|
| 2048, 512 | 1.78× | 1.24× |
| 768, 2048 | 3.06× | 1.53× |

## Notes for reviewers

- **Fewer candidates, not exhaustive.** A 48-config budget can miss the true optimum. The post-search check against the default keeps a bad result from replacing it.
- **Wider search space than the bundled tables.** It adds `BLOCK_SIZE_K=32`, `num_stages=1` and ROCm launch options. All are validated against the default output before they can win.
- **Inference path is unchanged.** Only the optional `config=` override and the shared path resolution were added to `fp8_utils.py`.
