# [Frontend] Return Anthropic-format errors for request validation on /v1/messages

[Upstream PR](https://github.com/vllm-project/vllm/pull/64879) · state: open · merged: False

## Original PR description



## Overview

Request validation errors on `/v1/messages` and `/v1/messages/count_tokens` now come back in Anthropic's error format instead of vLLM's OpenAI-style one. Third work item of #64810.

## Claims

- A malformed body or a wrong `content-type` on either route returns `{"type": "error", "error": {"type": "invalid_request_error", "message": ...}}` with status 400. The message is the same bounded, sanitized text as before.
- Every other route is unchanged, including `/v1/messages/render`, whose callers (e.g. llm-d's EPP) parse the OpenAI-style `ErrorResponse`.

## Details

**Root cause.** The Anthropic endpoints already translate errors raised by the serving layer (`translate_error_response`). Body validation runs earlier, inside FastAPI's route handler, so its `RequestValidationError` reaches the app-wide handler registered in `register.py` and gets the OpenAI shape (`"type": "Bad Request"`). Anthropic SDKs dispatch on `error.type`, so these errors don't map to `invalid_request_error`. `validate_json_request`'s content-type check raises the same exception and had the same problem.

**Fix.**
- The Anthropic `APIRouter` uses an `APIRoute` subclass, `AnthropicRoute`, that catches `RequestValidationError` around FastAPI's route handler and passes the error through the existing `translate_error_response`. This is the pattern FastAPI documents for per-router request handling.
- To reuse the existing message formatting (error-count/size bounds, `loc` cleanup, path sanitization), `validation_exception_handler` is split into `create_validation_error_response`, which returns the `ErrorResponse`, and a thin handler that wraps it in a `JSONResponse`. The handler's behaviour is unchanged.

**Alternatives considered.**
- *Branch on the request path in the app-wide handler:* this couples the shared handler to one API surface.
- *Cohere-style middleware that rewrites error bodies by path prefix* (`CohereErrorEnvelopeMiddleware`): that parses and rebuilds response bodies, and Anthropic's routes share the `/v1/` prefix with OpenAI's.

The route class keeps the change inside the Anthropic router.

**Limitations.** Only `RequestValidationError` is translated. Other exceptions that escape these routes before the endpoint body still use the app-wide handlers, which is unchanged. The endpoints already catch serving-layer exceptions themselves.
