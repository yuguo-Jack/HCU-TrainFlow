# [Bugfix][NIXL] Release unreachable prefill peers on failed heartbeat

[Upstream PR](https://github.com/vllm-project/vllm/pull/60268) · state: open · merged: False

## Original PR description



## Overview

In pull mode, the decoder does not release a remote prefill's NIXL state on failed heartbeat (which is detectable from UCX disconnection error, but current code does not check it).

When a prefill node crashes, its rkeys stay loaded on the decode nodes it recently communicated with, which results in MNNVL stale mappings. When the prefill node attempts to restart, it is unable to remap memory.

The current implementation of heartbeat could detect this, but they are only sent by decoders when they need to extend KV leases for pending requests.

This patch adds periodic sending of heartbeats, with detection and cleanup of disconnected peers.

Addresses https://github.com/vllm-project/vllm/issues/58063

## Claims



## Validation

On a GB200 NVL72 system, we ran vLLM v0.31.0 with this patch and NIXL 1.5.0, with --enable-cumem-allocator, on every instance, serving with two prefill and two decode instances under continuous traffic. We killed one prefill instance six times and each time started a replacement on the same GPU, restarting one decode instance along the way. In every cycle the decode instances released the killed prefill within about 10 seconds (about 25 seconds with the two keepalive variables left at their defaults), its GPU memory dropped to zero, the replacement started with its full memory budget and served all requests from both decode instances, and the other prefill instance kept serving, with no errors on the decode side.

## Caveat

Two workarounds are needed until upstream changes land; two more to shorten detection.

| Variable | Purpose | Without it | Obsoleted by |
| --- | --- | --- | --- |
| `UCX_CUDA_IPC_CACHE=n` | Workaround: the UCX CUDA IPC cache keeps imported fabric mappings after the rkey is destroyed, so the released prefill's GPU memory stays allocated | Memory stayed pinned although the decode instances released the prefill | openucx/ucx#11870, plus NIXL setting `UCP_EP_PARAMS_FLAGS_RKEY_BOUND_LIFETIME` |
| `UCX_RC_GDA_EP_ALLOC_MODE=direct` | Workaround: the UCX `rc_gda` QP pool returns QPs still connected to the old peer, and the next connection fails `INIT2RTR` (syndrome `0x5d668c`) | The replacement served 0 of 16 requests | Upstream change to reset or destroy connected `rc_gda` channel blocks instead of pooling them |
| `UCX_KEEPALIVE_INTERVAL=2s` | Optional tuning: shortens detection of a failed peer | Detection takes about 25 s instead of about 10 s | n/a |
| `UCX_UD_TIMEOUT=5s` | Optional tuning: shortens the UD keepalive timeout | As above | n/a |
