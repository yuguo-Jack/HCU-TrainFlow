# [Bugfix][Tool Parser] llama4_json: parse parallel tool calls without ";" separator

[Upstream PR](https://github.com/vllm-project/vllm/pull/65651) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`llama4_json` loses parallel tool calls. vLLM's Llama 4 JSON chat template (`examples/tool_chat_template_llama4_json.jinja`) renders parallel calls back to back (`{...}{...}`), but the `llama_json` parser only accepts `;` between calls. Non-streaming returns the whole output as `content`; streaming emits only the first call and leaks the rest into `content` as raw JSON.

Related: #46863 (Llama 4 JSON tool calls), #63569 (migration of `llama3_json` to the parser engine). cc @arpera

## Claims

- Non-streaming: `{...}{...}` returns two tool calls instead of the raw output as `content`.
- Streaming: the second call is emitted as a tool call instead of leaking into `content`.
- `;`-separated Llama 3 output is unchanged.

## Validation

**End to end (OpenAI server, CPU).** Served a small model with the `llama4_json` parser and pinned its output to the Llama 4 format with a structured-output regex, so the request goes through the real chat-completions path (`adjust_request` → detokenization with special tokens kept → parser):

```
VLLM_CPU_KVCACHE_SPACE=1 vllm serve HuggingFaceTB/SmolLM2-135M-Instruct --port 8011 \
  --enable-auto-tool-choice --tool-call-parser llama4_json --dtype float32 --max-model-len 2048
python check_parallel.py HuggingFaceTB/SmolLM2-135M-Instruct        # {...}{...}
python check_parallel.py HuggingFaceTB/SmolLM2-135M-Instruct '; '   # {...}; {...}
```

| Output format | Mode | Before (`0db3734d5`) | After |
|---|---|---|---|
| `{...}{...}` | non-streaming | `tool_calls=[]`, whole output in `content` | `tool_calls=[get_weather, get_time]` |
| `{...}{...}` | streaming | `tool_calls=[get_weather]`, second call in `content` | `tool_calls=[get_weather, get_time]` |
| `{...}; {...}` | both | — | `tool_calls=[get_weather, get_time]` |

```python
import json
import sys
import urllib.request

SERVER_URL = "http://127.0.0.1:8011/v1/chat/completions"
MODEL = sys.argv[1]
SEPARATOR = sys.argv[2] if len(sys.argv) > 2 else ""
EXPECTED_NAMES = ["get_weather", "get_time"]
FORCED_OUTPUT = (
    '{"name": "get_weather", "parameters": {"city": "Paris"}}' + SEPARATOR +
    '{"name": "get_time", "parameters": {"tz": "CET"}}'
)
REGEX_METACHARS = set(r"\.^$*+?{}[]|()")
TOOLS = [
    {
        "type": "function",
        "function": {
            "name": name,
            "parameters": {
                "type": "object",
                "properties": {arg: {"type": "string"}},
                "required": [arg],
            },
        },
    }
    for name, arg in [("get_weather", "city"), ("get_time", "tz")]
]


def escape_regex(text: str) -> str:
    return "".join("\\" + ch if ch in REGEX_METACHARS else ch for ch in text)


def request_body(stream: bool) -> bytes:
    body = {
        "model": MODEL,
        "messages": [{"role": "user", "content": "Weather and time in Paris?"}],
        "tools": TOOLS,
        "tool_choice": "auto",
        "temperature": 0,
        "max_tokens": 128,
        "structured_outputs": {"regex": escape_regex(FORCED_OUTPUT)},
        "stream": stream,
    }
    return json.dumps(body).encode()


def post(stream: bool) -> urllib.request.addinfourl:
    req = urllib.request.Request(
        SERVER_URL,
        data=request_body(stream),
        headers={"Content-Type": "application/json"},
    )
    return urllib.request.urlopen(req, timeout=300)


def non_streaming() -> tuple[list[str], str | None]:
    message = json.load(post(stream=False))["choices"][0]["message"]
    names = [call["function"]["name"] for call in message.get("tool_calls") or []]
    return names, message.get("content")


def streaming() -> tuple[list[str], str]:
    names: dict[int, str] = {}
    content = ""
    for raw_line in post(stream=True):
        line = raw_line.decode().strip()
        if not line.startswith("data: ") or line == "data: [DONE]":
            continue
        delta = json.loads(line[len("data: ") :])["choices"][0]["delta"]
        content += delta.get("content") or ""
        for call in delta.get("tool_calls") or []:
            name = (call.get("function") or {}).get("name") or ""
            names[call["index"]] = names.get(call["index"], "") + name
    return [names[index] for index in sorted(names)], content


def main() -> int:
    ok = True
    for mode, run in [("non-streaming", non_streaming), ("streaming", streaming)]:
        names, content = run()
        passed = names == EXPECTED_NAMES
        ok &= passed
        print(f"{mode}: tool_calls={names} content={content!r} -> "
              f"{'PASS' if passed else 'FAIL'}")
    return 0 if ok else 1


if __name__ == "__main__":
    sys.exit(main())
```

## Details

**Root cause.** In `SEMICOLON_SEQUENCE` mode, two places required `;` between calls:

- `_validate_complete_tool_output` (`vllm/parser/llama_json.py`) returned `False` on any character other than `;` after a complete call, so the non-streaming parse fell back to content.
- `_feed_semicolon_sequence_delimiter` (`vllm/parser/engine/streaming_parser_engine.py`) bailed to content when `{` followed a complete call without `;`. By then the first call had already been streamed, so only the rest leaked into content.

**Fix.** `;` is now optional: a `{` directly after a complete call starts the next call. Validation of each object (`name` plus `arguments` or `parameters`) is unchanged. `SEMICOLON_SEQUENCE` is only used by `llama_json`, so no other parser is affected.

**Tradeoff.** In streaming, a JSON object directly following a tool call is now treated as another tool call rather than content. This matches the existing behavior after `;`, where the engine also commits to a tool call on `{`.

**Not a duplicate.** #49923 and #48295 also touch `llama3_json` parallel and streaming handling, but they modify `vllm/tool_parsers/llama_tool_parser.py`, which #63569 replaced. No open PR touches `vllm/parser/llama_json.py` or `SEMICOLON_SEQUENCE`.
