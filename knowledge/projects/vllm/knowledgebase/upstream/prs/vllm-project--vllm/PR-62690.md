# [Feature] Layered prefill: advance prefill one decoder layer group per iteration

[Upstream PR](https://github.com/vllm-project/vllm/pull/62690) · state: open · merged: False

## Original PR description



## Overview

Adds opt-in layered prefill (`--num-layer-groups N`): a prefill batch advances one group of decoder layers per iteration, while running requests decode through all layers every iteration. Implements RFC #62689 ([paper](https://arxiv.org/abs/2510.08055)).

## Claims

- New `SchedulerConfig.num_layer_groups` (default 1, off) for MRV2 with synchronous scheduling, supporting TP, PP and EP. With PP, each rank prefills its own batch, overlapping batches across ranks.
- Model-agnostic: any decoder following the PP contract (`layers[start_layer:end_layer]`, embed on first rank, `IntermediateTensors` before last) works without model changes. Unsupported models are rejected at load time.
- CUDA graphs: breakable prefill graphs per layer group, plus full decode graphs.
- On Qwen3-30B-A3B and GPT-OSS-20B (2× A100), SLO attainment improves at high load over chunked-512 and chunked-8192 (table below), with higher TTFT at light load.

## Details

- **Scheduler.** `LayeredPrefillScheduler` (new file) emits, per iteration:
  - one local stage per PP rank;
  - a full-depth decode batch;
  - the completed rows to sample.

  Partial prefill KV stays out of the prefix cache until every group has run (`delay_cache_blocks`).
- **Worker.** `LayeredPrefillRunner` (new file) handles retained activations, the PP send after the last local group, and a single sampling pass. Activation memory is reserved before KV cache sizing.
- **Models.** `layer_group_context` narrows `start_layer`/`end_layer` and the PP group's first/last flags, so each group runs as its own pipeline stage.
- **Breakable graph fix.** `eager_break_during_capture` decided at decoration time whether to wrap an op, but `VllmConfig` may auto-enable `VLLM_USE_BREAKABLE_CUDAGRAPH` later.
  - If attention ops were imported first (e.g. `LLM(...)` in a process that already imported `vllm.model_executor.model_loader`), they were never breaks. Attention was then frozen into the graph: 0 eager breaks, with wrong outputs on DeepSeek-V2-Lite.
  - The decorator now always wraps; without an active capture the call passes through.
- **Limitations.**
  - Synchronous scheduling only; `torch.compile` is disabled.
  - Not supported: speculative decoding, DP, CP, DBO, EPLB, KV/EC connectors, multimodal and hybrid models.
  - The worker waits on a CUDA event two iterations back before reusing inputs. This wait falls within synchronous scheduling and was not flagged by `VLLM_GPU_SYNC_CHECK`.
- **Benchmark SLO.** The 150 ms TBT SLO replaces the paper's 100/125 ms, chosen after observing PP=2 results; `figure3.json` keeps the paper's values.
- **Duplicate check.** Searched open and closed PRs and issues for "layered prefill", "layer group prefill" and "num_layer_groups"; no existing work. Design discussed in RFC #62689.
