## Summary

This preserves @gcanlin’s complete implementation from #53380 and adds focused Rust frontend follow-ups: Responses API parity fixes, isolated HTTP tests, a rebase onto `68088ed392`, and a Codex/Agentic compatibility review.

- `POST /v1/responses` lowers string or item-list input, streaming/non-streaming modes, reasoning, and function calls into the shared `vllm-chat` pipeline.
- The endpoint uses the frontend-wide `sse_response` helper and `--sse-keep-alive-interval`, matching Chat Completions, Completions, and Generate.
- Request handling matches sibling endpoints for request-runtime offloading, `watermarking`, `top_k=-1`/`0`, cache-salt validation, zero-argument function tools, and empty-model defaults. Empty converted histories and invalid empty assistant continuations return 400 with `param: input`.
- Length-limited streams terminate with `response.incomplete`. Aborted streams retain `cancelled` status on the terminal response, matching Python behavior.
- Reasoning emits `response.content_part.added/done` with `reasoning_text` parts, alongside reasoning-text deltas. Streamed and final tool calls reuse the IDs assigned by `vllm-chat`.
- Developer-role fallback preserves template-selected content shape and all multimodal parts. It now reports media source order after consolidation, so moved image placeholders stay aligned with their image data. This shared renderer change affects Chat Completions too.
- Responses audio input uses the SDK-compatible nested `input_audio` object and reuses the shared Chat Completions audio envelope type.
- Failed streams close started output items, include completed partial output, and retain usage when the terminal engine event supplied it.
- `ChatTokenUsage` preserves cached prompt tokens and reasoning-token counts. SSE serialization consumes event payloads without cloning them.
- HTTP coverage is isolated in `rust/src/server/src/routes/tests/responses.rs`, under the test-only `routes::tests` module. Renderer regressions are also `#[cfg(test)]`-gated.

## Scope and coordination

This supersedes #53380 because its original head is not writable from the maintainer handoff fork. The authored implementation remains the first commit in this stack; this is not parallel endpoint work.

The shared typed Responses event contract is tracked separately in vllm-project/agentic-api#382, scoped by vllm-project/agentic-api#359. This PR is the stateless vLLM Rust HTTP/frontend adapter: it accepts full client replay, including `function_call` and `function_call_output`, but does not embed Agentic persistence, orchestration, or tool execution. **It does not yet provide one shared in-process Responses implementation used by both repositories.** HTTP integration tests do not establish that architectural goal.

Out of scope: Harmony channel rendering, built-in/custom/namespace tool execution, response persistence/retrieval/cancellation, output logprobs, and `allowed_tools`. Unknown `previous_response_id` returns HTTP 404 with `param: response_id`; its body retains the existing Rust string error code, not Python's numeric code. The cancelled-status terminal mapping also remains Python-compatible; neither should be read as complete Codex abort handling.
