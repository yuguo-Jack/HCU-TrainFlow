# [Bugfix][Mooncake] Fix MultiConnector stats and proxy SSE responses

[Upstream PR](https://github.com/vllm-project/vllm/pull/61218) · state: closed · merged: True

## Original PR description

## Overview

Using direct Mooncake with Mooncake Store can fail in MultiConnector's metrics handler, and the Mooncake example proxy labels SSE responses as JSON, causing clients such as AIPerf to reject them. Fix both integration issues by respecting optional metrics exporters and returning the correct streaming Content-Type.

## Claims

- Skip children without Prometheus exporters while continuing to forward supported metrics and `engine_idx`.
- Return `text/event-stream` for streaming requests on `/v1/completions` and `/v1/chat/completions`; preserve JSON responses for non-streaming requests and forward response bytes unchanged.

```diff
 P transfer stats -> MultiConnector metrics
-  require an exporter for every child with stats
+  forward stats only to registered exporters

 D SSE frames -> Mooncake proxy -> client
-  Content-Type: application/json
+  Content-Type: text/event-stream
```

Earlier ROCm end-to-end validation used integration commit `b41cf676db9cc124fffbcf305f7fa8c8d2f895b8`, containing the identical proxy file and metrics `observe()` implementation:

- [Before the proxy fix](https://github.com/ROCm/ATOM/actions/runs/38169410559): AIPerf attempted JSON parsing of SSE frames; all 13 sampled warmup responses were rejected.
- [C16 serving](https://github.com/ROCm/ATOM/actions/runs/38174661539): Kimi-K3 + DSpark3, 1P1D/16 MI355X, Mooncake RDMA + TCP Store completed a 3600-second performance window with 2006 successes and 4 errors. The workflow later failed while importing the separate GSM8K evaluator.
- [Natural GSM8K](https://github.com/ROCm/ATOM/actions/runs/38203116096): flexible extraction 1269/1319 (96.21%).

GPU evidence belongs to that integration revision; the current main-based PR branch has local regression coverage. Store lease timeouts and empty-response failures remain separate limitations. No additional GPU experiment was dispatched for this PR.

## Details

**Metrics:** `KVConnectorBase_V1.build_prom_metrics()` may return `None`. MultiConnector's metrics factory already excludes null exporters, while stats collection independently includes stats-only children. Direct Mooncake provides stats without an exporter, so its worker stats trigger the assertion in the API output handler. A conditional exporter lookup follows the existing optional-interface contract. Stats collection is unchanged; missing exporter IDs are skipped, so this assertion no longer detects inconsistent IDs in the metrics path.

**HTTP:** `_handle_completions` already forwards the request's streaming mode to D. Use the same flag to select the response media type. KV transfer and generation logic are unchanged.

The metrics portion follows up the **same fix proposed in #43836 for #43828**, adapted to the current flat stats payload with regression coverage. That PR remains open; this is not a distinct solution. The submitting operator explicitly requested including it here to cover both direct-Mooncake integration failures. Searches found no overlapping proxy SSE-header fix.

Both changes are reversible and scoped to metrics forwarding and the example proxy. AI assistance (Codex) was used; this remains a draft submitted at the human operator's request.
