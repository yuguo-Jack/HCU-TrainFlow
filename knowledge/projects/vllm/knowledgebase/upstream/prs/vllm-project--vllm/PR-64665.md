# [Doc] Kimi-K3: move the GB300 AgentX presets to the Oct 26 points with KV-balanced decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/64665) · state: closed · merged: True

## Original PR description

## Overview

Update the two GB300 Kimi-K3 AgentX disaggregated presets in `recipes/models/moonshotai/Kimi-K3.yaml` to the lanes qualified in [SemiAnalysisAI/InferenceX#4638](https://github.com/SemiAnalysisAI/InferenceX/pull/4638) (head `bc4d49f5`, sweep run [40830592414](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/40830592414), attempt 1): `kimik3-fp4-gb300-dynamo-vllm-agentic-dspark-mooncake-dcp8-disagg` (preset `gb300_agentx_pd`) and `kimik3-fp4-gb300-dynamo-vllm-agentic-dspark-mooncake-dep16-disagg` (preset `gb300_agentx_pd_dep16`). Both lanes now run image `vllm/vllm-openai:nightly-3966924d566340e971a6da313e790d05492aa505` (vLLM `0.33.0rc1.dev229+g3966924d5` in the run logs) with Dynamo `a0de541ea8c861d5ac01d15953ca529bea68637b`, and their throughput points run decode attention on `KIMI_K3_KV_BALANCED_MLA`.

Each preset now has one `points.<id>` per measured operating point, and the worker commands, environment block and Mooncake connector move out of the runbooks into structured fields. No open PR updates these lanes or their points; #64586 (drop dead envs from Kimi-K3) and #64617 (a B300 preset) edit the same file, so whichever merges second needs a rebase.

## Claims

**`gb300_agentx_pd` (AgentX xPyD, default on GB300 `pd_cluster`, as before):**

- `source` is #4638 at `bc4d49f5df307680be5a1567e01b838b83b31b62`. The image is pinned by digest (`@sha256:f255c4fa…`), and the Dynamo commit is unchanged.
- There are 10 points with stable ids, one per measured point, matching the lane's search space:
  - **Specialized decode** (`TOKENSPEED_MLA`, `latency_specialized`, `--max-num-seqs 12`): `1p3d_c16`, `1p2d_c24` (the default point, as the preset rendered before) and `1p2d_c32`.
  - **Regular decode** (`KIMI_K3_KV_BALANCED_MLA`): `2p4d_c112`, `2p4d_c128`, `2p3d_c128`, `2p3d_c152`, `3p4d_c240`, `3p3d_c240` and `3p3d_c264`.
  - The 1P2D c48/c64 and 2P3D c240 points are no longer run, so they are dropped.
- Regular points use these settings:
  - **Both roles:** BF16 SSM state and FlashInfer autotune on.
  - **Decode:** `--attention-backend KIMI_K3_KV_BALANCED_MLA`, with the DSpark draft's `attention_backend` on the same backend; `tokenspeed_mla_min_split_kv: 8` in `--attention-config`; `--max-num-seqs 128`, `--max-cudagraph-capture-size 512` and `--use-replayssm`; vLLM's default CUDA graph mode.
  - **Prefill:** stays on `TOKENSPEED_MLA` for target and draft.
- Specialized points keep the earlier profile on both roles: FP32 SSM state, `--cp-kv-cache-interleave-size 1` and autotune off.
- Both roles move the NIXL + Mooncake store `MultiConnector` from the runbook into structured fields. It comes from `select.kv_offload: kv_store_distributed_mooncake`, with `json_args` for the lane's connector options: recompute on failed loads, `kv_buffer_device: cuda`, `enforce_handshake_compat: false`, `enable_cross_layers_blocks: false` and `enable_offload: false`.
- The decode role drops the DEP-only `--data-parallel-hybrid-lb` and `--no-enable-prefix-caching` with `remove_args`, replacing the earlier undo flags.
- Environment additions on both roles, as the lane sets them: `VLLM_KIMI_K3_SHARD_SP_SHARED_EXPERT=0` on decode too, `DYN_TCP_REQUEST_TIMEOUT=120` and `ETCD_LEASE_TTL=600`.
- Prefill KV events (`--kv-events-config`) are removed, because the lane no longer publishes them.

**`gb300_agentx_pd_dep16` (AgentX 3P1D DEP16, opt-in):**

- `source` is #4638 at the same commit, and the image is the same digest-pinned image.
- The decode role runs target and draft attention on `KIMI_K3_KV_BALANCED_MLA`. Prefill stays on `TOKENSPEED_MLA`.
- There are three points, `c256`, `c288` and `c336` (default). The lane runs one configuration at all three client counts.
- The KV connector comes from the same `select` + `json_args`. The decode role also sets the store child to `kv_consumer` with `enable_lookup: false`.
- Prefill KV events are removed.

**Runbooks** keep the evidence and processes the builder does not render:

- the worker-count table;
- multi-tray launch notes;
- the specialized-decode and KV-balanced notes;
- the Dynamo parser flags;
- the etcd/NATS/Mooncake master commands and the lane's store configuration (160GB per rank, 60 s lease);
- the frontend (`least-loaded`, session affinity).

The duplicated Workers/Environment command blocks are removed. `meta.date_updated` is set to 2026-10-29.

## Details

**Schema limitations:**

- **Worker counts:** the builder renders one prefill and one decode worker per pool, so the xPyD counts (for example 2P4D) cannot be expressed. Each point's label, description and the runbook table give them. Role `nodes` stays at two trays per TP8 worker, because a larger `nodes` would render one wider TP group instead of more workers.
- **Mooncake master and store sizing:** the master options and store sizing are not preset fields. The builder's Mooncake option shows its own defaults (100GB segment, 30 s lease), so the runbook gives the lane's values.
- **Router and session affinity:** the Dynamo frontend's router mode and session affinity are not builder fields.

**`gb300_low_latency` is unchanged.** The #4638 aggregated `dcp8-agg` c1 point is an image-only bump, and its serving flags already match that preset's `tp16` point, apart from the image and the synthetic acceptance. A point can pin its own `image`, but `source` (href/key/revision) exists only on the preset, and that preset cites vllm-project/recipes#1134 with the rolling `nightly` image for both its points. Citing the InferenceX key would mean re-sourcing or splitting that preset, so I left it.

**Excluded as InferenceX-only, placement or no-op:**

- **Benchmark controls:** concurrency lists, synthetic acceptance (`rejection_sample_method: synthetic`, `synthetic_acceptance_length` on throughput runs; the presets keep block verification), AIPerf/trace-replay settings, `dram-utilization` and Tachometer (disabled in #4638).
- **Harness plumbing:** `--served-model-name` and the local `/model` path, `--device-ids`, `--dump-config-to`, `--request-plane tcp` (the builder sets `DYN_REQUEST_PLANE=tcp`), Slurm/container/health-check settings, `VLLM_SERVER_DEV_MODE`, `TILELANG_CLEANUP_TEMP_FILES`, `WITH_NVIDIA_PEERMEM`, `NCCL_NET_PLUGIN`, the per-host Mooncake/NIXL/OTEL addresses, and `NVSHMEM_HCA_LIST` (a site value; the runbook says to set it).
- **Eval-only parsers:** `--dyn-tool-call-parser`, `--dyn-reasoning-parser` and `--dyn-enable-structural-tag`, which the runbook documents.
- **No-op envs:** `VLLM_RPC_TIMEOUT` and `VLLM_PREFIX_CACHE_RETENTION_INTERVAL`. The lane sets them, but vLLM at the pinned commit `3966924d` reads neither (`git grep` finds no reference under `vllm/`), and `prefix_cache_retention_interval` already defaults to 0 (`vllm/config/cache.py`). #64586 removes them from the other Kimi-K3 presets.

**Known renderer behaviour:** like the other presets that tune a composed connector by name, the `json_args` on `--kv-transfer-config` assume the Mooncake store selected by the preset. If a user turns that KV offload option off while the preset is active, the renderer raises an error for the missing `MooncakeStoreConnector` child.
