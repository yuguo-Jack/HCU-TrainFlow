# [Kernel][Perf] Add H20 block-FP8 fused MoE config for E=512,N=128 (Qwen3.5-397B-A17B-FP8 TP8, up to 2.0x)

## Overview

Add the missing H20 block-FP8 fused-MoE preset for `Qwen/Qwen3.5-397B-A17B-FP8`, TP=8 (`E=512, N=128, K=4096`, top-k 10, 128x128 weight blocks). This adds one config file and uses the existing dispatch path.

## Claims

- Select tuned parameters for this shape instead of the generic fallback, without changing kernel code or other devices' configs.
- Previously recorded Triton 3.8.0 kernel measurements show about 1.8–2.0x speedup at M=96–512. The earlier Triton 3.7.1 eight-H20 serving run reports +31.4% output throughput at concurrency 128.
- This maintenance update synchronizes main while preserving the approved config byte-for-byte. It makes no new GPU performance or numerical claim for the current main revision.

## Details

The default switches to a 64-row M tile above M=64. With 512 experts and top-k 10, each expert receives roughly M*10/512 rows, leaving much of that tile padded. The tuned preset uses M=16 through M=512 and mostly M=32 for larger batches.

Duplicate check: current main has no config at this exact filename. Inspected open H20 tuning PRs #44152, #44273 and #58986; none adds this `E=512,N=128,NVIDIA_H20,fp8_w8a8,[128,128]` file. The existing H20-3e/H200 unquantized files do not cover this dtype/device combination.

## Performance

Environment:

- 8x NVIDIA H20 (96 GB), driver 595.58.03
- `vllm/vllm-openai:v0.31.0` (digest `c1c9f6fd5c10…`), torch 2.13.0+cu130, Triton 3.7.1
- Model shape: `Qwen/Qwen3.5-397B-A17B-FP8`, TP=8, block-FP8 W8A8

Method: the official `benchmark_moe.py` (no `--tune`) on the same GPU. The baseline arm has no config file (default config); the tuned arm points `VLLM_TUNED_CONFIG_FOLDER` at the new file. ## Test Plan and Results

Numerical check: the tuned config and the default config run on the same inputs through `fused_experts` (`override_config` for the tuned arm). Each output is compared with an fp32 torch reference that dequantizes the 128x128-block FP8 weights. The check covers 3 seeds x 20 batch sizes (1–4096, including M values between tuned keys, such as 3 and 200).

- Tuned vs default output: max relative L2 difference 0.0043, at the M values whose tuned config uses `BLOCK_SIZE_K=64` (1536, 3072, 4096). It is exactly 0 for every M up to 64 and for M=2048, and below 3e-4 everywhere else.
- Tuned vs reference and default vs reference: agree within 1e-5 at every point (about 0.046 relative L2). This error comes from FP8 activation quantization, which both arms share.
- All outputs finite.

```bash
python benchmarks/kernels/benchmark_moe.py --model Qwen/Qwen3.5-397B-A17B-FP8 \
  --tp-size 8 --dtype fp8_w8a8 --trust-remote-code \
  --batch-size 1 2 3 4 6 8 16 24 32 48 64 96 128 192 256 384 512 1024 1536 2048 3072 4096
```

- `python -m json.tool <config>`: passed.
