# [Bugfix] Handle empty CUDA all-reduce tensors

[Upstream PR](https://github.com/vllm-project/vllm/pull/64977) · state: closed · merged: False

## Original PR description

## Overview

A valid empty all-reduce can reach a GPU backend and fail with
`trtllm_mnnvl_allreduce_fusion failed with error code invalid argument`.
Handle empty tensors in `CudaCommunicator.all_reduce` before backend selection,
returning a fresh empty tensor with the same out-of-place contract as the fake
implementation.

### Example: one empty TP group

Consider four GPUs with DP=2 and TP=2. GPUs 0/1 form one TP group; GPUs 2/3
form another. At the TP reduction, the first group has no token rows and the
second has eight:

| TP group | Input on each member | Before | With this change |
| --- | --- | --- | --- |
| GPUs 0/1 | `[0, 768]` | The empty tensor can reach a backend and trigger an invalid GPU launch. | Each member returns a fresh `[0, 768]` tensor; no GPU reduction is needed. |
| GPUs 2/3 | `[8, 768]` | Sum the two members' partial results for the eight token rows. | The same normal reduction runs; both members receive the summed `[8, 768]` output. |

Both members of the empty group agree on the empty shape. This is not a case
where one member skips a collective while its peer still expects data. Only
this empty TP reduction is skipped; earlier expert work and communication are
unaffected.

The guard is:

```python
if input_.numel() == 0:
    return torch.empty_like(input_)
```

## Claims

- Avoid zero-block GPU launches for valid empty all-reduces, including calls
  made during CUDA-graph capture.
- Preserve shape, dtype, device and the fresh-output contract.
- Leave nonempty backend selection and reduction code unchanged.

## Details

Zero bytes satisfy the custom-allreduce size/alignment gate. Its native launch
computes the block count from the element count, producing zero blocks for an
empty tensor. FlashInfer can also admit a zero-row input. Rejecting zero only
in one backend selector can therefore expose the same invalid launch through
another backend.

The common dispatcher handles this case before choosing a backend.
`torch.empty_like(input_)` is intentional: returning `input_` itself would alias
the argument and disagree with `all_reduce_fake`. `numel()` reads tensor
metadata and introduces no GPU-to-CPU synchronization. All participating ranks
must still obey the existing equal-shape collective contract.

Open-PR searches for empty/zero-size all-reduce and `CudaCommunicator` found no
equivalent fix. Related open PRs address different behavior:
[#43588](https://github.com/vllm-project/vllm/pull/43588) changes nonempty
custom-allreduce warmup values;
[#64420](https://github.com/vllm-project/vllm/pull/64420) changes FlashInfer PDL
completion; [#48877](https://github.com/vllm-project/vllm/pull/48877) adds a
PIECEWISE eager-allreduce split. This change adds none of those features.

AI assistance was used to prepare the patch, regression and description.
There is no throughput or model-accuracy claim.

The original failure came from a standalone distributed MoE layer benchmark with DP=2/TP=2 that explicitly constructed per-DP token counts [0, 8]. It bypassed the serving scheduler’s dummy-batch handling.

closing it




• Idle DP ranks don't run empty. A rank with no requests runs a dummy batch of uniform_decode_query_len tokens, or 1 (gpu_worker.py#L1476-L1482).
• All-empty steps skip the forward. When every DP rank has 0 tokens, model runner V2 doesn't call the model at all (gpu/dp_utils.py#L121-L125, gpu/model_runner.py#L1877-L1880).
• Microbatching pads. Empty microbatches run as padded dummy batches (gpu/ubatch_utils.py#L57-L63).
