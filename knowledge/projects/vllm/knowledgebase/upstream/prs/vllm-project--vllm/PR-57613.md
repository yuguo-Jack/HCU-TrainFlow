# [Bugfix] Retain one alignment block below sliding-window replay boundaries so a same-turn extension still hits the prefix cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/57613) · state: open · merged: False

## Original PR description

## Purpose

Fixes #57610.

Under sparse retention (`prefix_cache_retention_interval` 0 or > 0) `SlidingWindowManager.reachable_block_mask` keeps, below each reachable boundary, exactly the `need`-block run that a hit *at that boundary* needs. A later request that shares the prompt but diverges inside the last alignment block (the same user turn with a few tokens appended) gets a full-attention hit one alignment block shorter, so its sliding lookup needs the run to end `alignment_tokens / block_size` blocks earlier. Only `need - extra` of those blocks are cached, the sliding group returns no hit, and the coordinator reduces the common hit to zero: the whole prompt is recomputed on every layer.

Measured on Gemma 4 26B (full-attention blocks of 32, sliding blocks of 16, window 1024): a 4100-token prompt extended by a few tokens in the same turn hit 0 blocks (2.2 s prefill) while 4110 → 4096 hit (0.13 s); the outcome depends only on where the divergence falls relative to the 32-token alignment.

The change keeps `alignment_tokens // block_size` extra blocks below each reachable boundary, so the shorter hit's run is long enough. Cost: one alignment unit of sliding-window blocks per cached prompt (32 tokens for Gemma 4). Dense retention (`None`) already caches every block and is untouched.

## Test Plan

New tests in `tests/v1/core/test_prefix_caching.py`:

- `test_swa_reachable_block_mask_keeps_one_alignment_block_below_boundary`: the mask now covers `[end - need - extra, end)`.
- `test_swa_latest_only_retention_hits_when_prompt_diverges_in_last_aligned_block`: on a hybrid 32/16 layout with window 1024 and `retention_interval=0`, prompts of 4100 and 6980 tokens re-sent with the last tokens changed hit 4064 and 6944; a prompt diverging after the aligned boundary still hits 4096.

Existing tests that pinned the exact retained sets are updated to the longer tail with comments explaining the extra block(s). `test_hybrid_local_kv_retention_latest_only_reuses_replay_boundary` now also checks that a prompt one alignment unit shorter hits and two units shorter does not. `test_swa_shared_prefix_reuse_under_zero_retention` uses a longer distinct suffix so that its "without the pin the junction is lost" case is still about the pin and not about the replay tail reaching the junction.

```
pytest tests/v1/core/test_prefix_caching.py
```

## Test Result

Before the change the two new divergence cases return 0 and the mask test finds the run starting at block 192 instead of 190; after it `tests/v1/core/test_prefix_caching.py` passes (163 passed), as do `test_single_type_kv_cache_manager.py`, `test_kv_cache_utils.py`, `test_swa_inflight_window_free.py` and `test_scheduler.py`.

In production, with this change applied through a plugin patch (`Foresko/vllm-metal@25e7752`) on vLLM 0.29: the same-turn extension after 4100 tokens went from 0 hits / 2.2 s to 4064 hits / 0.16 s, after 6980 tokens from 0 / 3.95 s to 6944 / 0.12 s; the cases that already hit are unchanged.
