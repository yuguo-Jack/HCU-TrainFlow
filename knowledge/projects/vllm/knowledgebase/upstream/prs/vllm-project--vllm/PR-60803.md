# [Perf] Reuse the trtllm-gen sparse MLA decode runner and preallocate its output

[Upstream PR](https://github.com/vllm-project/vllm/pull/60803) · state: open · merged: False

## Original PR description

## Description

Every sparse-MLA layer calls the FlashInfer `trtllm_batch_decode_with_kv_cache_mla` wrapper per step with no `out=`. The wrapper re-validates inputs, constructs a fresh `TrtllmGenMlaDecodeRunner` plus `TuningConfig`, runs `AutoTuner.choose_one`, and `torch.empty`s the output (up to 33.5 MB at 4096-row batches), per layer, per step. Under `FULL_AND_PIECEWISE` attention is an eager break in the piecewise sections, so prefill-mixed steps re-execute that whole Python chain once per sparse layer, about 12 times per engine step.

The runner bakes no query-shape state, so one runner per layer keyed by the KV cache (data_ptr/shape/dtype/top-k capacity) serves every batch. This launches it directly with `tactic=-1` into a per-layer bf16 output buffer sliced per call, with module-scope imports. The DCP path (`return_lse`) keeps the public wrapper because it needs per-call LSE; the HiSparse mixed-step second call gets an `out_offset` so decode and prefill slices stay disjoint before the concat. Runner construction asserts the same two hard constraints the wrapper enforces (head count, block size). Complements #60070 (the counter buffer kwarg) without overlapping it.

Measured on GLM-5.3-Flash (NVFP4), 8x B300 (SM103), TP8, FP8 KV cache, MTP k=7, 1M context, `vllm bench serve`, random dataset, seed 42, medians of 3 warm runs, patch applied alone:

| workload (1024-in / 1024-out) | TPOT mean | TPOT p99 |
|---|---|---|
| 8 concurrent | 5.40 -> 4.82 ms (-10.7%) | 8.26 -> 7.07 ms (-14.4%) |
| 32 concurrent | 7.85 -> 6.74 ms (-14.1%) | 12.24 -> 12.14 ms (-0.8%) |
| 32K prompt, 64 out | 7.96 -> 7.59 ms (-4.6%) | 8.13 -> 8.10 ms |
| 512K prompt, 64 out | 4.32 -> 4.10 ms (-5.1%) | 4.32 -> 4.10 ms |

Medians of 3 warm passes within one boot per arm; across reboots of the unpatched build, c8 and c32 TPOT varied by roughly 25% and 12% on this setup, so the smaller deltas are directional and the workload-level trend is the signal. Spec-dec acceptance rates were not separately instrumented; the win is attributed to the removed launch-path work, not to acceptance changes.
