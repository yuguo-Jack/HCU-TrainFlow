# [BUG] Fix KV offload shared-memory slot selection using worker rank

[Upstream PR](https://github.com/vllm-project/vllm/pull/58497) · state: closed · merged: True

## Original PR description

# KV offload selects the wrong shared-memory slot when device index differs from worker rank

## Description

CPU and Tiering KV offload select a worker's shared-memory slot using the
physical device index modulo the worker world size. The device index is not
necessarily the worker's rank, so this can select the wrong slot in a
non-replicated layout.

For example, with `world_size=4`, `rank=1`, and `device_index=6`, the current
calculation selects slot `6 % 4 = 2` instead of slot `1`. Workers can therefore
read or write a different slot from the one assigned to their rank.

## Expected behavior

Non-replicated layouts should select the shared-memory slot using the worker
rank. Replicated layouts should continue to use slot `0`.
~

```
class HostMemoryRegistrar(ABC):
    """Registers host memory so the device can DMA directly into it."""

    # Bound per-call size to avoid driver limits on large registrations.
    max_chunk_bytes: int = 64 * 1024**3

    @classmethod
    def is_available(cls) -> bool:
        return True

    @abstractmethod
    def register(self, ptr: int, size: int) -> bool: ...

    @abstractmethod
    def unregister(self, ptr: int) -> bool: ...


class CudaHostRegistrar(HostMemoryRegistrar):
    ...

class XpuHostRegistrar(HostMemoryRegistrar):
    ...

```
