# [Doc] Fix %% rendering in CLI reference for --safetensors-load-strategy

[Upstream PR](https://github.com/vllm-project/vllm/pull/46335) · state: closed · merged: True

## Original PR description

## Summary

While exploring the [`--safetensors-load-strategy`](https://docs.vllm.ai/en/latest/configuration/engine_args/#-safetensors-load-strategy) feature, I noticed the CLI reference docs showed `90%%%%` instead of `90%`.

## Root cause

`arg_utils.py` unconditionally escaped `%` → `%%` in all docstring-derived help text for argparse. This is correct for terminal `--help` because argparse's `_expand_help` does `help % params`, collapsing `%%` → `%`. But `MarkdownFormatter.add_arguments` in the docs generator reads `action.help` directly, bypassing `_expand_help`, so `%%` was never unescaped before writing to markdown.

Additionally, the `load.py` docstring had `90%%` instead of `90%` (manually pre-escaped to compensate for the old unconditional escaping), causing a double-escape to `90%%%%` in the rendered output.

## Changes

- `vllm/config/load.py`: `90%%` → `90%` in docstring (source must be plain `%` with the new approach)
- `vllm/engine/arg_utils.py`: extract `IS_ARGPARSE` and guard the `%` → `%%` escaping with `if IS_ARGPARSE:`, so escaping only runs on the terminal `--help` path, not when building docs

## Verification

Served docs locally with `API_AUTONAV_EXCLUDE=vllm mkdocs serve` and confirmed:

```
None (default): Uses memory-mapped (lazy) loading. When an NFS filesystem is
detected and the total checkpoint size fits within 90% of available RAM,
prefetching is enabled automatically.
```

Also confirmed `vllm serve --help` still renders `90%` correctly (argparse `_expand_help` collapses `%%` → `%` as before).

## Known limitation

[`--bin-by`](https://docs.vllm.ai/en/latest/cli/bench/sweep/plot/#-bin-by) in `sweep/plot.py` hardcodes `%%1` directly in `add_argument(help=...)`, bypassing `arg_utils.py` entirely, so `IS_ARGPARSE` has no effect there — the docs still render `%%1`. Fixing it cleanly requires refactoring `SweepPlotArgs` to use docstrings like other config classes; leaving as a follow-up.

Hi @yewentao256  Thanks for the review.

The root cause is that [`arg_utils.py:319`](https://github.com/vllm-project/vllm/blob/main/vllm/engine/arg_utils.py#L319) unconditionally escapes `%` → `%%` for all docstring-derived help text:

```python
help = help.replace("%", "%%")
```

This is needed for terminal `--help` because argparse's `_expand_help` does `help % params`, which collapses `%%` → `%` as a side effect:

```python
"90%% of RAM" % {"default": None}  # → "90% of RAM" 
```

But [`MarkdownFormatter.add_arguments`](https://github.com/vllm-project/vllm/blob/main/docs/mkdocs/hooks/generate_argparse.py#L201) bypasses `_expand_help` and reads `action.help` directly, so `%%` is never unescaped. This affects multiple args today — [`--safetensors-load-strategy`](https://docs.vllm.ai/en/stable/configuration/engine_args/#-safetensors-load-strategy), [`--gpu-memory-utilization`](https://docs.vllm.ai/en/stable/configuration/engine_args/#-gpu-memory-utilization), and [`--cp-kv-cache-interleave-size`](https://docs.vllm.ai/en/stable/configuration/engine_args/#-cp-kv-cache-interleave-size).

Two options:

**Option 1 — Fix in `generate_argparse.py` (current approach):** unescape `%%` → `%` in `MarkdownFormatter`. Systemic — covers all current and future docstrings with `%`.

**Option 2 — Fix in `arg_utils.py`:** skip escaping when running under mkdocs, since `_expand_help` is never called in that path:

```python
IS_MKDOCS = (
    sys.argv[0].endswith("mkdocs")
    or sys.argv[0].endswith("mkdocs/__main__.py")
)

if not IS_MKDOCS:
    help = help.replace("%", "%%")
```

Happy to switch to Option 2 if preferred.
