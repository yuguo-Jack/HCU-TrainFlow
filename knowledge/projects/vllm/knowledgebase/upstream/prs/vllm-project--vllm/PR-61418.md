# [Multimodal] Add GLM-5.3-Flash and DeepSeek V4/V4.1 routing-metadata adapters

[Upstream PR](https://github.com/vllm-project/vllm/pull/61418) · state: open · merged: False

## Original PR description

## Overview

Add exact image routing-metadata adapters for
GLM-5.3-Flash (`zai-org/GLM-5.3-Flash`) and DeepSeek V4/V4.1 so `/render`
can skip vision-tower inputs.

Production code under `vllm/` once merged, assuming rebased on #13 : **+401 / −25** (approx).

## Claims

- Image-only GLM-5.3-Flash and DeepSeek V4/V4.1 routing metadata matches
  full processing exactly.
- DeepSeek live HTTP `/render` on the mixed
  `text+image+text+image+text` prompt (840 tokens), unique media,
  `return_mm_kwargs=false`:

| offered load | unoptimized p50 / p95 | adapter p50 / p95 |
| --- | --- | --- |
| sequential n=15 | 102.2 / 117.5 ms | 10.2 / 11.4 ms |
| 20 RPS × 8s | 51.0 / 67.0 ms | 9.4 / 10.6 ms |
| 25 RPS × 8s | 444 / 1064 ms | 9.1 / 10.2 ms |

- GLM processor A/B (same commit, in-process): 4.0–4.3× p50, exact parity.
  Live GLM `vllm launch render` was not started; see Details.

## Validation

    pytest -q tests/models/multimodal/processing/test_glm5next.py \
      tests/models/multimodal/processing/test_deepseek_v4_vl.py \
      -k routing_metadata

CI: multimodal processor shard. DeepSeek GPU generate / KV hits were not
measured: NVIDIA sparse-MLA requires compute capability 9/10, and the
available cluster has A100/L40S.

## Details

These processors currently derive image replacements from processed tensors
or layout types. The adapters compute the same geometry from source
dimensions. DeepSeek V4 and V4.1 keep separate preprocess modules because
their existing image math already lives in those files.

The DeepSeek CPU placeholder is registered as multimodal so a CPU render
process can build routing metadata. Instantiating that placeholder for
generation remains unsupported.

GLM-5.3-Flash `vllm launch render` currently fails while constructing
`VllmConfig`: encoder-only/CPU launch disables prefix caching after the
hybrid-Mamba hook sets `mamba_block_size`. That is an existing config-order
issue, not introduced here. GPU `vllm serve` is a separate path.

AI assistance was used. A human submitter reviewed the diff.
