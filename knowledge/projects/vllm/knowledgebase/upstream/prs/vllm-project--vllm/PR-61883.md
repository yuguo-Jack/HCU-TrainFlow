# [Chore] Use upstream Transformers InklingProcessor

[Upstream PR](https://github.com/vllm-project/vllm/pull/61883) · state: closed · merged: True

## Original PR description



## Overview

Split from #60823: deletes the vendored Inkling processor and builds Inkling's multimodal inputs with upstream Transformers `InklingProcessor`.

Related PRs:
- **#60823:** the larger unvendoring PR this is split from; Inkling has been dropped from it.
- **#61392** and **#61813:** the same split for DeepSeek-V4 and MiniMax-M3.

No other open PR touches `vllm/models/inkling/common/mm_preprocess.py` or the vendored processor.

## Claims

- Deletes `vllm/transformers_utils/processors/inkling.py` (504 lines). `InklingProcessingInfo.get_hf_processor` loads upstream `InklingProcessor` from the checkpoint, which ships in every Transformers version vLLM supports (>= 5.16.1).
- Images: the upstream image processor patchifies, but vLLM still does the 2x long-edge upscale with PIL LANCZOS, because upstream defaults to no rescale and torchvision LANCZOS does not match the reference.
- Audio: the upstream feature extractor computes the mel features and `InklingProcessor._extract_dmel_bins` (private) quantises them to dMel ids. The dMel parameters now come from the checkpoint's `preprocessor_config.json` instead of being copied from the vLLM config.
- The multimodal kwarg names are unchanged (`input_audio_features` stays), so the model code and the Rust frontend, which sends Inkling audio under that key, are untouched. The only output difference is that the dMel ids are int32 instead of float32 holding the same integers; the audio tower casts to int32 anyway.
- No numerics change: processor outputs and greedy decode are bit-identical to `main`.

## Validation

Processor outputs on CPU, `thinkingmachines/Inkling-NVFP4`, `main` vs this PR: 4 images (224x224 to 1920x1080, and 37x501), 3 audio clips at 16 kHz (1 s to 31 s), one 44.1 kHz clip, and a mixed image + audio prompt. Prompt token ids, `pixel_values` and `num_patches` are identical; the dMel ids have identical values.

Greedy decode, `thinkingmachines/Inkling-Small-NVFP4` on 2x B200 (TP2), `transformers` 5.19.0, FlashInfer autotuning off, 128 tokens with logprobs:

| Prompt | `main` run 1 vs run 2 | `main` vs this PR |
|---|---|---|
| Text only | identical | identical |
| 1 image (x2 prompts) | identical | identical |
| 2 images | identical | identical |
| 1 audio (x2 prompts) | identical | identical |
| Image + audio | identical | identical |

"Identical" means the same prompt token count, text and logprobs (max |Δ logprob| = 0). With FlashInfer autotuning on, two `main` launches already differ from each other, so it was turned off.

  --kernel-config '{"enable_flashinfer_autotune": false}'
