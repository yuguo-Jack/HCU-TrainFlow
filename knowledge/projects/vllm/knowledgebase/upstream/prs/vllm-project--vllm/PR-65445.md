# [Model] Canary: require `language` and test translation

[Upstream PR](https://github.com/vllm-project/vllm/pull/65445) · state: closed · merged: True

## Original PR description



## Overview

Follow-up to #64215. Canary transcription requests without `language` now return HTTP 400, and Canary translation gets CI coverage.

## Claims

- `nvidia/canary-1b-v2` cannot detect the audio's language, but transcription defaulted a missing `language` to `en` and only logged a server warning, so non-English audio came back as English text with HTTP 200. It now fails with HTTP 400, as translation already does since #64215.
- `test_translation_validation.py` now covers Canary: one en->de translation, plus the 400s for a missing `language` and a non-English pair (de->fr).

## Validation

German speech (macOS `say -v Anna`), `POST /v1/audio/transcriptions`, CPU (M5 Pro):

| `language` | main | this PR |
| --- | --- | --- |
| omitted | 200 `"Good morning, today is the weather in Berlin sunny and warm, ..."` | 400 `Canary cannot detect the audio's language; pass language (...)` |
| `de` | 200 `"Guten Morgen, heute ist das Wetter in Berlin sonnig und warm, ..."` | 200, unchanged |

```
pytest -v -s "tests/entrypoints/speech_to_text/translation/test_translation_validation.py::test_canary_translation"
main:    E   Failed: DID NOT RAISE BadRequestError   (transcription without language -> 200 OK)
this PR: 1 passed in 45.08s
```

The en->de output matches Transformers `generate` (fp32): "Mary hatte ein kleines Lamm ...". I did not use the module's `foscolo` it->en clip because canary-1b-v2 leaves most of that poem in Italian, in Transformers too. The WER test already sends `language="en"`, so its result does not change.

## Details

This departs from Cohere ASR, FunASR and FireRedASR2, which default to `en` with a warning. For Canary, that default produced an English translation labelled as a transcription. The test uses the platform default attention backend, like the Canary WER test, because the file's ROCm helper selects `ROCM_AITER_FA`, which rejects cross-attention. The docs note that Canary requires `language` and translates to or from English only.

No duplicate: there are no open PRs for Canary (searched `canary-1b-v2`, `CanaryForConditionalGeneration`).
