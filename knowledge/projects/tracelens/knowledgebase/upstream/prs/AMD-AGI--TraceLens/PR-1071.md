# PerfModel: plug your own op projections into perf reports with an (OpWork, arch) API

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1071) · state: closed · merged: True

## Original PR description

## Summary

TraceLens perf reports compare each op's measured time with a roofline. This PR lets you add your own op projection from an `--extension_file`, with no change to TraceLens. An op projection reads an op's work (its category, parameters, FLOPs, and bytes) and returns values to report, usually a predicted time but also anything else per op, such as the kernel configuration a library would pick. Its values show up as columns in every perf sheet.

```python
# my_extension.py
def my_gemm_projection(work, arch):
    if work.category != "GEMM":
        return None                                   # not covered
    p = work.params
    return {"time_us": predict(p["M"], p["N"], p["K"]),
            "Tile": "256x128x64"}                     # extra columns are optional

op_projections = {"MyModel": my_gemm_projection}
```

```bash
TraceLens_generate_perf_report_pytorch --profile_json_path trace.json.gz \
  --gpu_arch_json_path mi300x.json --extension_file my_extension.py
```

This adds `MyModel Time (µs)`, `MyModel TFLOPS/s`, `MyModel TB/s`, `MyModel Tile`, and `Pct MyModel` (the prediction as a percentage of the measured time) to the per-op sheets and the summaries.

## How it works

- A *perf model* describes an op's work: shapes, FLOPs, bytes. An *op projection* turns that work into per-op values: a time, extra columns, or both.
- `compute_perf_metrics` now measures the op, describes its work once as an `OpWork`, and runs every registered op projection through one loop and one column writer.
- Every op projection has the same interface: `fn(work, arch)` returns a dict or `None`. `time_us` fills the time, TFLOPS/s, TB/s, and Pct columns; every other key becomes a `<label> <key>` column. If one raises or returns anything else, its columns stay empty for that op and TraceLens warns once; the rest of the report is unaffected.
- `OpWork` carries `category` (backward ops get the backward category), a copy of `params` (the report's `param:` columns), `gflops`, `bytes_moved`, `compute_spec`, `bwd`, and the `perf_model` itself. Every op projection gets the whole `OpWork` and uses whatever it needs: Origami reads the GEMM parameters, and the roofline reads FLOPs and bytes.
- Roofline and Origami are op projections too, written the same way, so built-in and external ones produce the same columns. Summary sheets find labels from the columns, so a new op projection needs no report code.
- From Python: `analyzer.register_op_projection(label, fn)`.
- Kernel filters (`kernel_filters = {"label": fn}`) report an op's throughput over a subset of its kernels. They replace the hardcoded non-data-movement option.

Built-in op projections:

| Label | Enabled by | Covers |
|---|---|---|
| `Roofline` | a GPU arch | every op with a perf model |
| `Origami` | `--enable-origami-gemm` | GEMMs |
| `SDPA Tile Origami` | `--enable-origami-sdpa-tile` | attention, forward and backward |

The SDPA tile model splits attention into one Q·Kᵀ and one P·V tile GEMM on one CU, timed by Origami, and adds softmax and memory terms. `sdpa_tile_time_us` takes a `gemm_time` callable, so another GEMM model can reuse the tiling.

Docs: "Add an op projection" in the PyTorch report how-to, op-projection columns in the column reference, and a stub in `examples/external_op_projection_stub.py`.

## Behavior changes

- `--enable-origami` is now `--enable-origami-gemm`, and the Python keyword `enable_origami` is now `enable_origami_gemm`. There's no alias.
- Attention times moved out of the `Origami` columns, behind `--enable-origami-sdpa-tile` with their own `SDPA Tile Origami` columns. With real Origami they're now filled: one-CU tiles used to fail Origami's architecture lookup, so no time was produced.
- The external GEMM simulator backend and `GEMM_SIMULATOR_PATH` are removed, and so is `python_path`, which only chose that simulator's interpreter: the `--python_path` flag, the `TreePerfAnalyzer` and report-generator keyword, and the perf model constructor argument. Perf models that subclass a built-in one and pass `python_path` to `super().__init__` should drop it.
- `TraceLens/PerfModel/run_perf_model.py` is removed. The Origami how-to shows the equivalent Python call.
- `GEMM.get_simulation_time_func` is replaced by `TraceLens.PerfModel.origami_helper.gemm_time_us`, which also owns the Origami dtype map. `simulation_dtype_map` is removed.
- Perf models no longer take `enable_origami`. The SDPA tile model moved out of the `SDPA` class into `TraceLens/PerfModel/sdpa_tile.py` (`sdpa_tile_time_us`, `sdpa_fwd_time_us`, `sdpa_bwd_time_us`), unchanged. It times its tiles with the `gemm_time` it's given, and the `SDPA Tile Origami` op projection passes Origami's. `SDPA.get_simulation_time*` and `SDPA.tile_gemm_time` are removed.
- The `non_data_mov` argument of `compute_perf_metrics` is replaced by kernel filters; `examples/kernel_filter_example.py` reproduces the old `Non-Data-Mov` columns.
- In summary sheets, Origami `TB/s` is aggregated once per shape, like its time.
- JAX reports gain roofline columns when an arch is given.

GEMM Origami values are otherwise unchanged from `main`.

## Not in this PR

- Numeric fixes to the attention tile model, such as backward tiling and choosing flash tiling by `flash_impl` instead of by class name. These change numbers, so they'll come separately with a before/after comparison.
- Six common attention ops are missing a dtype, so they get no roofline or Origami columns: #1099.

## Testing

- `tests/test_op_projections.py` and `tests/test_external_op_projection.py` cover the `(work, arch)` interface, the column writer, error isolation (including return values other than a dict or `None`), extension loading, kernel filters, and end-to-end reports. `tests/test_origami_reference.py` pins real Origami GEMM and SDPA tile times on a bundled trace.
- CI's unit test command (`-m "not gpu"`) on Linux with real `rocm-origami`: 3689 passed, 46 skipped. The one other failure was the pytest 9.2 break fixed on `main` in #1167, which this branch now includes.
- Every report sheet (8 bundled traces × 8 configurations, 696 CSVs) was compared commit by commit. Every difference is one of the behavior changes above. The final rename to op projections and the move to `(work, arch)` change no values; the perf-report regression tests pass against their reference CSVs.
