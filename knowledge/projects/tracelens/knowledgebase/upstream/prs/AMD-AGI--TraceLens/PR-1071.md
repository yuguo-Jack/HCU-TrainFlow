# PerfModel: plug your own op models into perf reports with a (category, params, arch) API

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1071) · state: open · merged: False

## Original PR description

﻿## Summary

TraceLens perf reports compare each op's measured time with a roofline. This PR lets you add your own op model from an `--extension_file`, with no change to TraceLens. An op model reads each op's category and parameters and returns values to report, usually a predicted time but also anything else per op, such as the kernel configuration a library would pick. Its values show up as columns in every perf sheet.

```python
# my_extension.py
def my_gemm_model(category, params, arch):
    if category != "GEMM":
        return None                                   # not covered
    return {"time_us": predict(params["M"], params["N"], params["K"]),
            "Tile": "256x128x64"}                     # extra columns are optional

op_models = {"MyModel": my_gemm_model}
```

```bash
TraceLens_generate_perf_report_pytorch --profile_json_path trace.json.gz \
  --gpu_arch_json_path mi300x.json --extension_file my_extension.py
```

This adds `MyModel Time (µs)`, `MyModel TFLOPS/s`, `MyModel TB/s`, `MyModel Tile`, and `Pct MyModel` (the prediction as a percentage of the measured time) to the per-op sheets and the summaries.

## How it works

- A *perf model* describes an op's work: shapes, FLOPs, bytes. An *op model* turns that work into per-op values: a time, extra columns, or both.
- `compute_perf_metrics` now measures the op, describes its work once, and runs every registered op model through one loop and one column writer.
- Roofline and Origami are op models too, so built-in and external models produce the same columns. Summary sheets find labels from the columns, so a new model needs no report code.
- An op model returns `None`, a time in µs, or a dict. If one raises, its columns stay empty for that op and TraceLens warns once; the rest of the report is unaffected.
- External models get the perf-model category (backward ops get the backward category), a copy of the op's parameters (the report's `param:` columns), and the arch dict.
- From Python: `analyzer.register_op_model(label, fn)`.
- Kernel filters (`kernel_filters = {"label": fn}`) report an op's throughput over a subset of its kernels. They replace the hardcoded non-data-movement option.

Built-in op models:

| Label | Enabled by | Covers |
|---|---|---|
| `Roofline` | a GPU arch | every op with a perf model |
| `Origami` | `--enable-origami-gemm` | GEMMs |
| `SDPA Tile Origami` | `--enable-origami-sdpa-tile` | attention, forward and backward |

The SDPA tile model splits attention into one Q·Kᵀ and one P·V tile GEMM on one CU, timed by Origami, and adds softmax and memory terms. `SDPA.tile_gemm_time` takes a `gemm_time` callable, so another GEMM model can reuse the tiling.

Docs: "Add an op model" in the PyTorch report how-to, op-model columns in the column reference, and a stub in `examples/external_op_model_stub.py`.

## Behavior changes

- `--enable-origami` is now `--enable-origami-gemm`, and the Python keyword `enable_origami` is now `enable_origami_gemm`. There's no alias.
- Attention times moved out of the `Origami` columns, behind `--enable-origami-sdpa-tile` with their own `SDPA Tile Origami` columns. With real Origami they're now filled: one-CU tiles used to fail Origami's architecture lookup, so no time was produced.
- The external GEMM simulator backend and `GEMM_SIMULATOR_PATH` are removed, and so is `python_path`, which only chose that simulator's interpreter: the `--python_path` flag, the `TreePerfAnalyzer` and report-generator keyword, and the perf model constructor argument. Perf models that subclass a built-in one and pass `python_path` to `super().__init__` should drop it.
- `TraceLens/PerfModel/run_perf_model.py` is removed. The Origami how-to shows the equivalent Python call.
- `GEMM.get_simulation_time_func` is replaced by `TraceLens.PerfModel.origami_helper.gemm_time_us`, which also owns the Origami dtype map. `simulation_dtype_map` is removed.
- Perf models no longer take `enable_origami`. The SDPA tile model moved out of the `SDPA` class into `TraceLens/PerfModel/sdpa_tile.py` (`sdpa_tile_time_us`, `sdpa_fwd_time_us`, `sdpa_bwd_time_us`), unchanged. It times its tiles with the `gemm_time` it's given, and the `SDPA Tile Origami` op model passes Origami's. `SDPA.get_simulation_time*` and `SDPA.tile_gemm_time` are removed.
- The `non_data_mov` argument of `compute_perf_metrics` is replaced by kernel filters; `examples/kernel_filter_example.py` reproduces the old `Non-Data-Mov` columns.
- In summary sheets, Origami `TB/s` is aggregated once per shape, like its time.
- JAX reports gain roofline columns when an arch is given.

GEMM Origami values are otherwise unchanged from `main`.

## Not in this PR

- Numeric fixes to the attention tile model, such as backward tiling and choosing flash tiling by `flash_impl` instead of by class name. These change numbers, so they'll come separately with a before/after comparison.
- Six common attention ops are missing a dtype, so they get no roofline or Origami columns: #1099.

## Testing

- `tests/test_op_models.py` and `tests/test_external_op_model.py` cover the op-model contract, the column writer, error isolation, extension loading, kernel filters, and end-to-end reports. `tests/test_origami_reference.py` pins real Origami GEMM and SDPA tile times on a bundled trace.
- CI's unit test command (`-m "not gpu"`, 95% coverage gate) passes on Linux with real `rocm-origami`: 3527 passed, 42 skipped, 95.48% coverage.
- Every report sheet (8 bundled traces × 8 configurations, 696 CSVs) was compared commit by commit. Every difference is one of the behavior changes above.
