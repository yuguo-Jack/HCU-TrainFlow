# feat(perfmodel): roofline projection CLI + finish vLLM/SGLang class expansion

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1175) · state: closed · merged: True

## Original PR description

## What this does

Two pieces landed together in this branch (opening as one PR since they built on the same working tree):

### 1. Trace-free model roofline projection CLI
Adds `TraceLens_model_roofline_projection`: projects a kernel-by-kernel roofline (COMPUTE_BOUND/MEMORY_BOUND, time, unmodeled-op callouts) for a checkpoint from its config and modeling source alone — no trace or GPU run required. Reuses the Model Explorer AST backend and stops expansion at ops with a direct `TraceLens.PerfModel` formula.

- `TraceLens.ModelUtils.roofline_projection`: `RooflineOp`, `project_roofline`.
- `TraceLens.ModelUtils.roofline_cli`: the console script.
- `TraceLens.ModelUtils.cli_common`: shared `--engine`/`--code-path`/`--github`/runtime-regime argument helpers, factored out of the Model Explorer export CLI so both CLIs parse checkpoint sources alike.
- `basic_ops.ROOFLINE_LEAF_PATTERNS` / `loader.build_roofline_basic_ops`: the GEMM/CONV/Normalization/Softmax leaf set a roofline projection can cost.
- `tree_perf.compute_roofline_time_and_bound`: shared roofline bound/time formula.
- Docs: [`docs/how-to/generate-model-roofline-projection.md`](../blob/feat/gweisz_roofline_projection/docs/how-to/generate-model-roofline-projection.md), linked from the README and `perf-model-without-trace.md`.

### 2. Re-enable vLLM/SGLang modeling-class expansion
Follow-up to #1155 / #1156. Re-enables expanding a vLLM/SGLang modeling class into its real ops (instead of leaving it an opaque leaf), fixing the three gaps that previously blocked it:

- `ast_analyze`: detect a kernel boundary reached through a conditionally-assigned pluggable attribute (`self.quant_method.apply(...)`), not just a bare imported-class call; climb same-file base-class inheritance (`_resolve_inherited_forward`) so a subclass with no `forward` of its own (`MergedColumnParallelLinear(ColumnParallelLinear)`) is analyzed as its base; thread the analyzed module's own name through a new `ANALYZED_MODULE_KEY` config key instead of hardcoding transformers'.
- `source`/`extract`: register vLLM's and SGLang's own pinned-source fetches (`resolve_engine_modeling_files`) the same way transformers' modeling files already were, so a model's sibling imports resolve at the same pinned commit instead of falling back to an unavailable `sys.path` lookup — the actual reason cross-file class resolution never worked for these engines before.
- `shape_inference`: extend `QKVParallelLinear`'s output-width formula to its indexer subclass (`...WithIndexer`), which the inheritance climb above now reaches.

Expanding more classes surfaced two further wiring gaps, fixed at their root:

- `computation_graph._add_kernel_port_nodes` read every repeat of a `(source, target)` link off the same dict key, so q/k/v split outputs feeding a newly kernel-tagged attention call collapsed onto one port and the rest were left as I1 dead nodes. Each repeat now resolves its own entry off the parallel ports list.
- `type_check._kernel_interface_tile_warnings` flagged a kernel whose output fed two allocation calls (`qkv.new_empty(...)` borrowing `qkv`'s dtype as a buffer template) as if it were a kernel returning several untiled values. Allocation-call readers never read the kernel's value, so they no longer count toward that check.

`overview`/`shapes`/`ast_build`/`merge`/`parallel_plan` pick up the same class expansion elsewhere it changes what the graph now sees.

Deliberately out of scope: a *general* pinned-source/class-expansion mechanism beyond the vLLM/SGLang engines above (risk of a `quant_method.apply()`-style regression for other engines not yet audited).
