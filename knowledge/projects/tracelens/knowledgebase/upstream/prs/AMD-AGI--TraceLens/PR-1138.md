# ci(skills): pin skillscope to v0.1.3

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1138) · state: closed · merged: True

## Original PR description

## Why

`AMD Skills Checks` runs on every pull request and is meant to be a required check, but it calls skillscope's `main` branch in two places. That makes the merge gate depend on whatever lands in skillscope, the same day it lands. A regression there would turn unrelated TraceLens pull requests red with nothing changed in this repository, and the only fix would be to wait for upstream or edit this workflow under pressure.

#1000 pointed this workflow at skillscope `main`, and #1112 kept it there on purpose, so that upstream regressions show up early. That visibility is real, but a required check is the wrong place to get it: the people it blocks are TraceLens contributors who cannot act on a skillscope failure.

## What changes

Both references are pinned to the [`v0.1.3`](https://github.com/amd/skillscope/releases/tag/v0.1.3) release: the reusable workflow behind `Results`, and the action that checks external references. The check then runs the commit that tag names, so what merges to skillscope `main` reaches it only when someone bumps the pin, and that bump is reviewed like any other change. The header comment says both lines carry the pin and should move together.

Nothing else in the workflow changes: triggers, the nightly schedule, inputs, and secret handling are as they were.

## Verification

- Ran `v0.1.3` through the action's own launcher against this branch, for the three commands the workflow runs on a pull request: `list-skills` finds `analysis-orchestrator`, and `structural` and `structural --external` pass with the same counts as on skillscope `main` (12 cases, 65 internal references).
- `v0.1.3`'s reusable workflow reports the same `Results` job that branch protection is meant to require, and accepts every input this workflow passes (`skills`, `structural`/`routing`/`behavioral`, the `api_key` secret).
- The only difference between `v0.1.3` and skillscope `main` is optional API-gateway authentication (`api_base_url`, `api_custom_headers`), which this workflow does not use.
- `actionlint` passes on the changed file.

**Not verified:** the `routing` and `behavioral` legs against a live model. They only run on a manual dispatch with an API key, which this change does not touch.

## Scope

The pin covers skillscope's own code, not everything the check depends on. `v0.1.3` is an ordinary git tag, so it is only as fixed as skillscope keeps it, and the tools the action installs (uv, Python, and skillscope's unlocked dependencies) still resolve fresh on each run. A full commit SHA would close the first gap, at the cost of readability.

Not done here: a separate scheduled job that keeps following skillscope `main` for early warning. It would keep the visibility #1112 wanted without blocking pull requests, and can be added on its own if that signal is wanted.
