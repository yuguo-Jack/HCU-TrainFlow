# Feat/devalshah/spec decoding

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1127) · state: closed · merged: True

## Original PR description

## Trace splitter

- `scheduler.run_batch` is the preferred iteration root.
- A preferred root that does not parse inherits the single known annotation inside it.
- Split filenames include that preferred-tier label.
- A detailed `step[VERIFY]` / `step[TARGET_VERIFY]` with `sqsq` is a decode iteration root.
- `sample_`, `draft`, `draft_extend`, and `propose_*` are not split roots.

## Capture classification

- Filename role: `DraftExtend` → `drafter_extend`, `Draft` / `_speculator` / `draft_step_forward` → `drafter`, otherwise `target`.
- `request_bs` is the filename request count, or null.
- `token` is the most common leading input dimension.
- `batch_size` is `N` from `capture_{N}_{mode}` when those annotations line up with `_dummy_run`; otherwise it is `token`.
- `num_captures` is the `StreamBeginCapture` count: one or fewer is `FULL`, more is `PIECEWISE`.
- Merge key: `{capture_type}_{batch_size}_{mode}`.

## Graph capture merge

- Verify, `sample_`, `draft`, `draft_extend`, and `propose_*` are merged with the iteration roots.
- `sample_` looks up generation requests. Verify looks up context plus generation requests. `draft`, `draft_extend`, and `propose_*` borrow the nearest verify. Other roots use the annotation token batch.
- The file is the smallest stored batch of that role at or above the lookup.
- Identical launch sequences use `FULL`; differing sequences use `PIECEWISE`.
- One capture root is copied onto every graph launch.
- Captures are limited to the replay rank when that rank is present.

## Misc

- The inference how-to documents `execution_details.json` and the spec-decode merge rules.
- The Magpie profiling reference notes ATOM `draft_step_forward_bs_{bs}_rank{N}` files.
- SGLang MTP splitter fixtures are renamed to the contained `step[TARGET_VERIFY ...]` label.

- kyle-hoffmeyer · comment · 2026-10-30T00:17:51Z · [source](https://github.com/AMD-AGI/TraceLens/pull/1127#issuecomment-6511689317)

@devalshahamd, changed algorithm for kernel matching when capture trace to execution root isn't a clean 1:1 mapping. 
`_match_graph_roots_to_captures` now classifies graph roots as PIECEWISE or FULL based on kernel count.
The most frequent kernel count among graph roots is considered to be the dominant kernel count (ties broken by largest value). Graph roots below dominant are piecewise and at or above is full. Piecewise graph roots match only against piecewise capture roots, full against full. If the kernel count based classification failed, then it reattempts classification with all the potential capture roots regardless of compilation strategy.

## Examples
7, 6 are drafter prefill -> piecewise
`[7, 6, 23, 23]` → dominant=23 → roots 0-1 PIECEWISE, roots 2-3 FULL

31 is drafter extend -> full
`[31, 23, 23]` → dominant=23 → all FULL
