# fix: include parent_module in ops_summary merge keys to prevent cross-product

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1053) · state: open · merged: False

## Original PR description

### Summary

This PR fixes a bug in `compare_perf_reports_pytorch`. `compare_perf_reports_pytorch` merged `ops_summary` sheets on `["name"]` alone. When reports are generated with `--group_by_parent_module` or `is_recompute`, `name` is no longer unique since the report emits one row per `(name, parent_module, is_recompute)` combination, so the outer merge degenerates into a full cross-product.

The fix promotes these optional grouping columns into merge keys when they are present in all input reports, and raises an error when some reports have them and others don't.

### Implementation

**Root cause.** `SHEETS_COMPARE_CONFIG` defined `ops_summary` merge keys as `["name"]` and did not consider the optional grouping columns:

```python
"ops_summary": {
    "keys": ["name"],
    ...
}
```

There are exactly two columns that can make `name` non-unique in `ops_summary`:

| Column | Trigger |
|---|---|
| `parent_module` | `--group_by_parent_module` flag |
| `is_recompute` |  `--detect_recompute` flag |

In `process_summary_sheet`, after loading the dataframes, optional keys are promoted to merge keys when present in all input reports. When a key is present in some reports but not all (i.e. comparing a `--group_by_parent_module` report against a non-grouped one), a `ValueError` is raised, since the granularities are incompatible and merging would still produce a partial cross-product.

### Tests

Three unit tests in `test_compare_perf_reports.py` using synthetic `ops_summary` CSVs via `tmp_path`:

| Test | Setup | Assertion |
|---|---|---|
| `test_ops_summary_no_cross_product_with_parent_module` | Both reports have `parent_module`, 2 rows each with duplicate `name` but distinct `parent_module` | Result has 2 rows (not 4), `parent_module` in output columns |
| `test_ops_summary_merge_without_parent_module` | Neither report has `parent_module`, 2 rows each with unique `name` | Result has 2 rows, `parent_module` not in output columns |
| `test_ops_summary_mismatched_parent_module_raises` | One report has `parent_module`, the other doesn't | `ValueError` raised matching `"parent_module"` |

All three tests verified to fail on the original code and pass on the fix.

Closes #1014
