# Aggregate perf reports

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1126) · state: closed · merged: True

## Original PR description

This pull request adds support for aggregating multiple performance report CSVs into a single combined report, controlled by a new `aggregation` configuration option. The main changes introduce a new aggregation utility, update the report generation flow to optionally combine results after all jobs, and enforce configuration and validation for aggregation policies and job phases.

The most important changes are:

**Aggregation Utility and Core Logic:**

* Added `TraceLens/Reporting/aggregate_perf_reports.py`, which implements the logic to combine multiple perf report CSVs according to a specified policy, including detailed rules for how to aggregate different columns and error handling for unsupported cases.
* Exported constants `POLICIES`, `aggregate_perf_report_csvs` for use in configuration and validation.

**Configuration and Validation:**

* Updated `TraceLens/Reporting/generate_perf_report_from_config.py` to support an `aggregation` section in the config, validate its structure and policy, and require a `phase` field for each job when aggregation is enabled. [[1]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeR48-R59) [[2]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeL337-R385) [[3]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeR411-R417) [[4]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeR157-R165)
* Enhanced job validation to enforce presence and correctness of the `phase` field when aggregation is used. [[1]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeR411-R417) [[2]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeR474)

**Report Generation Flow:**

* Modified the report generation pipeline to call `aggregate_perf_report_csvs` after all jobs complete when aggregation is configured, writing the combined CSVs to a new output directory.
* Ensured resolved config files include aggregation settings and job phases when applicable. [[1]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeR197-R205) [[2]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeL228-R253) [[3]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeR266-R267) [[4]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeL258-R290) [[5]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeR106)

**Constants and Grouping Columns:**

* Centralized group-by column definitions such as `UNIQUE_ARGS_GROUPING_COLS` and `PERF_PARAM_PREFIX` in `TraceLens/TreePerf/tree_perf.py` for consistency and reuse in aggregation logic. [[1]](diffhunk://#diff-c6829d7e6fecf943b1d04eeb7977eaa986bce837199c1ee587284a9638dc09c5R41-R57) [[2]](diffhunk://#diff-c6829d7e6fecf943b1d04eeb7977eaa986bce837199c1ee587284a9638dc09c5L719-R736) [[3]](diffhunk://#diff-c6829d7e6fecf943b1d04eeb7977eaa986bce837199c1ee587284a9638dc09c5L1427-R1444)

**Documentation:**

* Updated docstrings and comments in both the new aggregation module and report generation script to describe the new aggregation workflow and configuration requirements. [[1]](diffhunk://#diff-74968b3bdbf3a87e73187d3628166aaae2bc73f8c92e85869278778929feee79R1-R326) [[2]](diffhunk://#diff-c210137461180d1a715020df058659e0322f9371a64e28b792772fac76476fbeR33-R36)

These changes together enable robust, configurable post-processing of multiple perf report jobs into a single, policy-driven summary.
