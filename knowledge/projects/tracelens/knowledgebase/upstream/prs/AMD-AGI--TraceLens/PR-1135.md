# fix(ci): skip dedicated-suite core shards and install a container Python

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1135) · state: closed · merged: True

## Original PR description

## Summary
- Skip the general `unit-tests` shards when a pull request only selects ModelUtils or Visualizer tests. `--exclude-test-prefix` turns a dedicated-suite-only selection into `mode=none` instead of an empty list that fails every core shard. A skipped core job still counts as success for the Codecov gate.
- Before `setup-python` in the Ubuntu 24.04 container, remove the host toolcache's Python 3.10. Ubuntu 26 runners reuse that build inside the container, where its `ssl` module does not load and pip cannot reach PyPI. The cached copy is always removed: an `import ssl` probe can pass before `apt` updates the container libraries and fail during installation.
- This pull request changes `.github/workflows/unit-tests.yml` and `scripts/select_related_tests.py`. Both are in `RUN_ALL_PATHS`, so the selector returns `mode=all` and the core shards run the full suite even though no `TraceLens/` package code changed. The workflow file is also a shared input for the ModelUtils and Visualizer jobs, so those suites run as well.

## Test plan
- [x] `python3 -m pytest tests/test_select_related_tests.py tests/test_reset_incompatible_toolcache_python.py -q`
- [x] A ModelUtils-only selection with the dedicated-suite prefixes yields `mode=none`
- [x] The toolcache reset removes only the requested Python version
- [x] Confirm `unit-tests (1–4)` are skipped on a ModelUtils- or Visualizer-only pull request that does not change `RUN_ALL_PATHS`, and that mixed changes still run the core shards
- [x] Confirm the container jobs download a Ubuntu 24.04 CPython and pip can install dependencies
