# fix(perfmodel): use the 16-bit matrix peak for MX formats on GPUs without native FP4/FP6

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1097) · state: closed · merged: True

## Original PR description

## Problem

On GPUs without FP4/FP6 matrix instructions, MX GEMMs are dequantized and run on the 16-bit matrix units. The microbenchmark still reports separate `matrix_fp4` / `matrix_fp6` peaks measured with its own `tl.dot_scaled` kernel. That figure reflects the quality of that one kernel rather than a hardware ceiling, so MX kernels get misleading roofline percentages, often well above 100%.

## Fix

- Add `NATIVE_MX_GFX_ARCHS` (currently `gfx950`) as the single list of targets with native MX matrix support.
- In `bench_matrix_tflops`, on any other gfx target set `matrix_fp4` and `matrix_fp6` to the measured `max(matrix_fp16, matrix_bf16)`, and print a note saying so. This is still a measured, achievable value, consistent with the other `matrix_*` entries.
- The aiter MXFP4 gate in `fp4fp6_helpers.py` uses the same list, so support is declared in one place.
- A README note explains the behaviour and how to add an architecture.

## Tests

- New `TestMxPeakWithoutNativeSupport` (placeholder values only):
  - `gfx_target` strips feature suffixes such as `:sramecc+:xnack-`.
  - Non-native targets (e.g. gfx1201, gfx1151, gfx942) get the 16-bit peak.
  - gfx950 and an empty arch string (non-AMD devices) keep the measured MX values.
