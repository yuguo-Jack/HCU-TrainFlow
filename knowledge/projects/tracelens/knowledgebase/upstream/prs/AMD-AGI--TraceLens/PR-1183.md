# TL Agent Multi-Trace By Node

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1183) · state: closed · merged: True

## Original PR description

# Multi-trace analysis on `combine_by_node`

This PR adds the `combine_by_node` aggregation and moves the agent's multi_trace report onto it. Until now, multi_trace stopped after the per-job reports.

`combine_by_node` stacks one block of CSV rows per node instead of summing them. The multi_trace report was written for summed data and would get several numbers wrong on stacked data:
- The manifest's GPU utilization takes whichever row comes last.
- Top Operations adds time across nodes, and its op counts grow with the number of nodes.
- The fallback divides by surviving kernel time.
- The priority-consistency check sums per-node findings.

`node` is now the one identity from the YAML through to `analysis.json`. The report uses two denominators:
- **T**, one node's captured GPU time. Every number a reader sees uses T.
- **T_all**, the sum over nodes. Ranking, `impact_score`, `pct_e2e` and every gate use T_all.

On a single trace T equals T_all, so the single-trace report does not change.

## Change

- **Aggregation.** In `Reporting/aggregate_perf_reports.py`, `combine_by_node` is the supported policy.
  - The aggregated CSVs hold one block per node, tagged with `node` and `phase`.
  - `Percentage (%)` is a share of that node's kernel time.
  - `gpu_timeline` ends with an `all` block summed over the nodes. A node named `all` is rejected.
- **Config.** Changed in `Reporting/generate_perf_report_from_config.py` and `utils/config_utils.py`.
  - Under `combine_by_node`, the YAML `node` is required and is a non-negative index within its phase.
  - The node id is `<phase>_<index>` (`prefill_0`), and a job's `name` defaults to it.
  - `phase` must match `[A-Za-z0-9_.-]+`.
  - The resolved config re-runs unchanged.
  - multi_trace requires `combine_by_node`, rejects two jobs on the same node, and names the focus job by its node id.
- **Denominators.** The GPU-utilization reader moves to `category_analyses/analysis_utils.py` as `gpu_utilization_from_timeline(gpu_timeline) -> dict`.
  - It selects the `all` block by name and adds `nodes{}` with each node's metrics.
  - The manifest, the per-category metadata and the fallback all read T and T_all from it.
  - Moving it out of `orchestrator_prepare` also avoids an import cycle with the fallback.
- **Report.** Changed in `analysis_template.md`, `sub_agent_spec.md`, `kernel-fusion-analyzer.md`, `reference.md`, `report_utils.py`, `kernel_fusion.py` and `kernel_fusion_analysis.py`.
  - The Executive Summary has a Total column and one column per node, in job order.
  - Top Operations is one table per node, with its own `top_ops node=` marker and global ranks.
  - Each finding carries `**Node**` and `node=` on its markers.
  - Detail tables show `% of Node` in place of `%E2E`.
  - Priorities are ranked globally on T_all, with no recommendation cap.
- **Plot.** In `utils/plot_utils.py`, `generate_perf_plot` draws one bar per node. Each axis is scaled to that node's time, and each category keeps one color across nodes. Single-trace plots are unchanged.
- **Fallback.** Changed in `utils/deterministic_fallback.py`.
  - With nodes, it reads each node's time from the sibling `gpu_timeline.csv` and writes the per-node Executive Summary, `**Node**` and `% of Node`.
  - It also fixes a pre-existing double count that affects every scope. Several CSV rows can resolve to the same op, and each became its own P-item carrying the whole group's impact, so `analysis.json` counted that impact more than once. The fallback now writes one P-item per op, and the gate, cap and drop note count ops.
- **Validation.** Changed in `utils/validation_utils.py` and `workflow_scripted_evals.py`.
  - The Executive Summary header must be Total plus the node names, and each node's Total Time must match the manifest.
  - R4 runs per `top_ops` block.
  - R6 compares `node` on the card and the detail estimate.
  - INV7 is keyed on (node, category).
  - The marker eval checks every `top_ops` block.
- **`analysis.json`.** Changed in `post_processing/analysis_json.py` and `candidate_schema.py`.
  - Tasks carry `node`, which replaces `phase` and is `null` outside multi_trace.
  - `executive_summary.node_metrics` holds the node columns.
  - `top_operations` reads every block and stamps `node`.
  - It also fixes a pre-existing Top Ops parser bug. The parser took cells by position, so it dropped rows without a trailing row comment (unmodeled categories) and shifted the comparative table's columns. Cells now map by header name.
- **Docs.** `docs/how-to/agent.md`, `generate-perf-report-from-config.md` and `api-reference.md` describe `combine_by_node` and the node index.
- **Example.** `build_docker_vllm.sh` adds vLLM v0.32.0.

31 files changed, 1695 insertions(+), 653 deletions(-).

## Observable effect

Single trace:
- The report markdown and plot are unchanged.
- `analysis.json` tasks carry `"node": null`.
- Top Ops rows parse by header.
- Fallback reports list each op once.

Config (Reporting/generate_perf_report_from_config.py)
  - node is an index. It must be a non-negative integer, the node's index within its phase. Before, it was any non-empty string such as prefill_w0. Booleans and
    negative numbers are rejected.

  - phase rule. phase now follows the same character rule as name ([A-Za-z0-9_.-]+), because it becomes part of the node id and the output file names.
