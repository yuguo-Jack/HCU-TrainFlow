# Fix Muse Spark graph wiring and extend model tracing

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1139) · state: closed · merged: True

## Original PR description

## Summary
- Repair Muse Spark architecture-graph export: loop operands follow their own `zip` source, residual-gate ports carry the sum, vision window lengths stay connected, and config-selected mask builders expand into shaped operations (`[B, 1, S, S] bfloat16`).
- When a checkpoint pins an unpublished transformers release, install the newest published release after that pin, or transformers git HEAD when nothing newer is published, and locate the wrapper modeling file without downloading weights.
- Trace `--torch-module` with `torch.export` and named symbolic inputs, and keep CI off host Pythons whose `ssl` module does not work inside the container.

## Test plan
- [ ] Export `unsloth/Muse-Spark-Open-816B-A42B` and `meta-models/Muse-Spark-Open-816B-A42B` and confirm there are no integrity, type, or group-cycle warnings.
- [ ] Confirm both causal-mask builders expand and their outputs are `[B, 1, S, S] bfloat16`.
- [ ] Run `tests/ModelUtils/test_ast_analyze_coverage.py`, `tests/ModelUtils/test_reshape_by_frame_input.py`, and the visualizer merge, return-slot, boundary, and loop-invariant suites.
- [ ] Run `tests/ModelUtils/test_model_env.py`, `tests/ModelUtils/test_size_provenance.py`, and `tests/ModelUtils/test_torch_export_introspect.py`.
- [ ] Confirm a checkpoint config that names an unpublished transformers pin resolves without downloading weight blobs.
