# feat(ci): agent-driven PR self-review

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1084) · state: open · merged: False

## Original PR description

## Summary

Adds an agent-driven PR review that reports judgment-based findings deterministic CI cannot catch; duplicated implementations, bypassed owning layers, guessed values, unstable output contracts, and stale docs. It runs on demand, posts a request-changes or an LGTM comment, and never approves or merges. Implements issue #1076.

## What this adds

- **Review skill** (`.claude/skills/review-pr/`): `SKILL.md` (the Step 0–8 procedure), `rules.md` (the canonical S/L/Q/D rule set from issue #1076 §2), `references/tiers.md` (owning-layer table + backbone tiers), and `fetch.sh` (collects PR evidence into a scratch dir).
- **Workflow** (`.github/workflows/pr-review.yml`): three privilege-separated jobs — `gate` → `review` → `publish`.
- **Publish script** (`.github/scripts/pr-review-publish.sh`): turns the review's `card.md` into a verdict.

## Privilege model

- Top-level `permissions: {}`; each job gets only what it needs.
- `review` is **read-only** to GitHub (`contents: read`, `pull-requests: read`) and is the only job holding the LLM API key.
- `publish` is the only writer (`pull-requests: write`) and posts a verdict only — never approve, never merge. It aborts if the PR head moved since the review ran.
- The review uploads `card.md` only, not the work folder (log masking does not cover artifacts).

## Guardrails

- Manual trigger only: runs on a `/review` comment, never on push/synchronize.
- Hard cap of 2 automated reviews per PR; refuses the 3rd.
- Commenter must have write access; fork and closed PRs are refused.
- Per-PR concurrency (no cancel-in-progress); 30-minute per-run timeout.

## Rule ownership

Each check has exactly one owner — deterministic CI **or** this review, never both. The review never flags what `black`, the narrow `ruff` set, `import-linter`, CodeQL, the copyright test, or the 95% coverage floor already gate. A set of further `ruff`/`import-linter` checks is listed as proposed; until one lands the review flags it on changed lines, then it moves to CI.

## Validation

- `fetch.sh` dry-run against 8 real PRs (merged + one open): every artifact populated, merge-base diff correct, `files`/`numstat` agree.
- Hand-walked 7 PRs through the rules: findings mapped to the right families, no finding duplicated a static gate, tiering behaved. One real finding surfaced (an undeclared console-script rename).
- Workflow YAML parses; publish script dry-run posts LGTM on a clean card and request-changes on a blocking card.

## Provisioning before first run

- Add the `review` job's LLM API key as a repository secret.
- Set repo variables: `PR_REVIEW_MODEL`, `PR_REVIEW_CLAUDE_CLI_VERSION`, `PR_REVIEW_TIMEOUT_MIN` (and optional `PR_REVIEW_RUNNER_LABEL`).

Closes #1076.
