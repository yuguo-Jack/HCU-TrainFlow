# feat(visualizer): draw vLLM/SGLang model partitions via --engine

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1155) · state: closed · merged: True

## Original PR description

## Summary

Adds `--engine {vllm,sglang}` to the Model Explorer export CLI so a checkpoint's
device-partitioned architecture graph can be drawn from vLLM's or SGLang's own
pinned modeling source (instead of transformers'), with `--tp`/`--pp`/`--ep`
read from each engine's own sharding idioms.

- Whitelists `vllm-project/vllm` and `sgl-project/sglang` in `SourcePolicy`,
  pinned the same way `huggingface/transformers` already is
  (`vllm-project/vllm@v0.32.0`, `sgl-project/sglang@v0.5.22`).
- Documents `--engine`/`--tp`/`--pp`/`--ep` in `TraceLens/Visualizer/README.md`
  (the pre-existing partition flags were previously undocumented).

## Introspection fixes found validating against real MiniMax-M3 source

Running `--engine vllm --tp 2 --ep 4` against `MiniMaxAI/MiniMax-M3.1-flash`
exposed two genuine fidelity gaps (not engine-specific opacity — both are fixed
at the introspection layer so the real sparse-attention module is drawn, not
approximated):

1. **`block_tree.py`** — a side-feed chain's own producer (e.g. a fused `qkv`
   projection feeding a private `_run_attention` helper as a side input) was
   dropped from the segment list whenever it appeared in that chain, even when
   it also had an *independent, ordinary* forward consumer elsewhere in the
   same block (`qkv.new_zeros(...)`, `qkv.split(...)`). That silently dropped
   its node and tripped `DroppedSubmoduleProducerError`. Fixed by keeping the
   segment when the producer has an ordinary consumer.
2. **`extract.py`** — per-layer dense/sparse attention-class selection fell
   back to whichever class the AST last saw assigned, because the real
   choosing condition is an arbitrary free-function call it can't evaluate
   (`layer_id in _sparse_attention_layer_ids(config)`). Added recognition of
   the `sparse_attention_config.sparse_attention_freq` per-layer convention
   vLLM/SGLang use for this (same shape as the already-supported
   `moe_layer_freq` FFN convention) and resolve the attention class from it,
   so `MiniMaxM3SparseAttention` is correctly selected for every sparse layer.

Checked SGLang's `minimax_m3.py` too: it uses a single `MiniMaxM3Attention`
class gated by an `is_sparse_attention_layer` constructor flag rather than two
classes, so the class-misselection bug doesn't apply there; generation
succeeds without it.

## Validation

- `python -m pytest tests/ModelUtils/ tests/Visualizer/` — 2438 passed.
- `black .` on all touched files.
- Generated and manually inspected both requested visualizations end-to-end:
  - `MiniMaxAI/MiniMax-M3.1-flash --engine vllm --tp 2 --ep 4`
  - `MiniMaxAI/MiniMax-M3.1-flash --engine sglang --tp 2 --ep 4`

  Both complete and correctly render `MiniMaxM3SparseAttention` as genuinely
  introspected sub-ops (not opaque) for all 60 layers.
