# feat(perfmodel): add expert-parallel mega-MoE pseudo ops and perf models

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1205) · state: open · merged: False

## Original PR description

## Summary

Adds perf models for the expert-parallel mega-MoE operators listed in #1174 (DeepSeek-V4-Pro). Today every kernel under `aiter::moe_forward` lands in "other", and `aiter::fused_moe_` is the largest uncategorized op in the trace.

## Changes

| File | Change |
|---|---|
| `TraceLens/Trace2Tree/extensions/moe_mega_ep_pseudo_ops.py` | New: injects one pseudo op per mega-MoE kernel under `aiter::moe_forward` |
| `TraceLens/Trace2Tree/extensions/pseudo_ops_registry.py` | Auto-detects the path when both `aiter::moe_forward` and `aiter::fused_moe_` are present |
| `TraceLens/PerfModel/extensions/moe_perf_model_extensions.py` | New models: `mega_moe_plan`, `mega_moe_dispatch`, `mega_moe_gemm_up`, `mega_moe_gemm_down`, `mega_moe_combine` |
| `TraceLens/PerfModel/extensions/pseudo_ops_perf_utils.py` | Registers the five models, and classifies the combine barrier as `MoE_comm_fwd` |
| `TraceLens/Reporting/generate_perf_report_pytorch_inference.py` | Adds `pseudo_op::mega_moe_` to the inference report's op list |
| `tests/test_pseudo_ops_extension.py` | Tests for the injection and the five models |

## Models

The token count and hidden size come from `aiter::moe_forward`. The expert geometry and the wire format come from the expert GEMM's `aiter::fused_moe_` call. Routing is assumed balanced: each GPU receives tokens × topk rows spread over its local experts.

| Pseudo op | Kernel | FLOPs | Bytes |
|---|---|---|---|
| `mega_moe_plan` | `tdm_compact_plan` | 0 | 16 per route (read the expert ids, write the route map, then read it back and rewrite it) |
| `mega_moe_dispatch` | `ep_dispatch_tdm_*` | 0 | each token's wire row and scales read once, plus one wire row and 8 bytes of metadata written per route |
| `mega_moe_gemm_up` | `a8w4_tdm_fp4_*_K{hidden}_*` | 2 × routes × hidden × 2·inter | received rows and scales, the gate/up weights of the experts in use, and the MX-quantized intermediate |
| `mega_moe_gemm_down` | `a8w4_tdm_fp4_*_K{inter}_*` | 2 × routes × inter × hidden | the intermediate, the down weights of the experts in use, and one BF16 row per route written to the source GPU |
| `mega_moe_combine` | `ep_combine_fused_*` | tokens × (topk − 1) × hidden | topk BF16 rows read per token and one BF16 row written |
| `mega_moe_combine_sync` | `ep_combine_fused_sync_*` | classified only | a cross-GPU barrier; its time is the wait for the other GPUs |

## Validation

- Each formula was checked against the aiter mega-MoE source (`mega_moe.py`, `compact_plan.py`, `dispatch_tdm.py`, `grouped_moe_gfx1250.py`, `combine.py`).
- `python -m pytest tests/test_pseudo_ops_extension.py -k "MegaMoE or registry"`: 9 passed.
- `black` (26.3.1) clean.

## Open items (why this is a draft)

- The aiter source used is newer than the build that produced the trace.
- Each dispatched row may be padded to 128 bytes in the recv buffer (3,840 B instead of 3,808 B for DeepSeek-V4-Pro). This will be confirmed from the trace's recv buffer strides.
- The trace has a separate `dynamic_per_group_scaled_quant` kernel that may be the dispatch-side MXFP4 quantize. If it runs inside `aiter::moe_forward`, it still needs a model.
- The combine is assumed to use aiter's default BF16 wire.
- Not yet compared against measured kernel times or hardware counters.
