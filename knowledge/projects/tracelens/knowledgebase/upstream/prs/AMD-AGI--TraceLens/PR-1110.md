# TraceLens Agent: class-based kernel taxonomy and one fusion module

## Summary

Kernel fusion analysis made the same decisions ("already fused?", "norm?", "matrix op?", "which kind?") in several places, with separate name lists and type-string checks in `orchestrator_prepare.py`, `kernel_fusion_analysis.py` and the LLM spec. This PR derives every fusion decision from one `KernelTaxonomy` and gives each decision one owning class in a new `utils/kernel_fusion.py`. Candidates and metrics now carry a deterministic `fusion_kind` and `confidence`, and the report and `analysis.json` carry the kind.

Core commits: `808c218f` (`KernelTaxonomy`) and `09b173ca` (`kernel_fusion` module).

## Why

| Pain point | Old | New |
|---|---|---|
| Duplicated decisions | Already-fused, norm, matrix and gate checks each existed in 2 to 3 places (builder, pricer, spec), keyed on substrings and type strings that `classify_kernel` never emitted | One owner per decision, all read from `KernelClass.covers` |
| Two candidate record shapes | Module pass wrote `{name, type}`, sibling pass wrote `{kernel_name, kernel_type}` with no gates; every reader carried `name`/`kernel_name` fallbacks | One frozen `KernelRecord`; both passes go through `FusionLabeler.label` |
| Kind left to the LLM | No kind emitted; the spec's prose pattern table picked one per run | `fusion_kind` computed in code; the spec writes a title that may not contradict it |
| Confidence from module names | `_CONFIDENCE_NAME_HINTS` plus a composition ladder | One structural rule in `FusionLabeler` |
| Cap applied late | Builder emitted over-cap groups; the CLI dropped them after counting | `FusionLabeler` excludes them before emission |
| Over-suppression | A high finding suppressed every op it touched, including GEMMs that keep running after the fusion | Only the ops the fusion removes are suppressed |
| Flat classifier | Two duplicated rule blocks; partial perf_category map (granular types fell to `Others`); no Softmax, TopK, Reduce, BatchNorm, Add, Mul, Convolution or fused-norm types | One rule table, a full type map, ordered `covers` per type |

### Decision ownership, before and after

| Decision | Before | Now |
|---|---|---|
| Already fused | `FUSION_ALREADY_FUSED` substrings and `_has_fused_kernel` (`orchestrator_prepare.py`), re-checked in the CLI; sibling pass forced `has_fused_kernel: False` | `FusionForms.is_fused` (covers two or more primitives), in `FusionLabeler.label` for both passes |
| Fusable | `FUSION_EXCLUDED_KERNELS`, `_is_fusion_eligible` | `FusionForms.is_fusable` (`copy`, `library_collective` primitives) |
| Norm | `_NORM_KERNEL_PATTERNS`, `_NORM_TYPES`, `_NORM_NAME_PATTERNS`, `_is_norm_kernel` | `norm` / `batchnorm` primitives, `FusionLabeler.NORM_ONLY` |
| Matrix | `_is_matrix_op` (type strings, `_MATRIX_SPECS`), `_is_gemm_norm_only` (type strings never emitted) | `FusionForms.is_matrix`, `FusionForms.matrix_mask` |
| Kind | Not emitted; spec pattern table | `FusionForms.forms` + `FusionLabeler` |
| Confidence | `_CONFIDENCE_NAME_HINTS`, `_classify_confidence`; spec fallback rule | `FusionLabeler.label` |
| Kernel cap | `MAX_FUSION_KERNEL_COUNT` in the CLI, after emission | `FusionLabeler.MAX_FUSION_KERNEL_COUNT`, before emission |
| Attention core | `_extract_attention_core` | `attention` form with `replaces_span`, `Label.span` |
| Case-A layout check | `_LAYOUT_TRANSFORM_PATTERNS` | `LayoutTransform` type, `FusionCandidateBuilder._passes_gates` |
| Dedup | `_dedup_by_kernel_set` plus the CLI's `_filter_and_dedup` key | `FusionCandidateBuilder._dedup_by_kernel_set` only |
| Suppression | Inline list in the CLI: every op key of every high finding | `FusionPricer.suppressed_op_keys` |

## What changed

### Kernel taxonomy (`TraceLens/Agent/Analysis/utils/classify_kernels.py`)

- `KernelTaxonomy` (module singleton `TAXONOMY`) maps a kernel name to a frozen `KernelClass(type, perf_category, covers)`. `covers` is the ordered tuple of primitives a type implements, drawn from the closed set `PRIMITIVES` (gemm, moe_gemm, softmax, topk, route, norm, batchnorm, quant, rope, kv_store, collective, act, mul, add, pointwise, reduce, copy, library_collective). Fused means two or more covers; matrix means covers include gemm or moe_gemm.
- One rule table `KERNEL_TYPE_RULES` replaces the two duplicated blocks; `KERNEL_TYPES` gives every type its perf_category and covers. Priority lives on the rule: highest wins, the earlier rule wins a tie (`KernelTaxonomy._match`).
- `classify_kernel` keeps its `(type, perf_category, priority)` return and shares `_match` with `classify`, so existing callers keep their shape; the `classify_all` output drops the unused `confidence` key.
- `MIN_CONFIDENCE` and the sub-5 catch-all rules (which could only yield Unknown) are removed; `run_assertions` drops the low-confidence warning and keeps the Unknown check.
- New or renamed types: Add+RMSNorm, RMSNorm+Quant, Add+RMSNorm+Quant, AllReduce+RMSNorm, BatchNorm, Attention (flash) widened to `attn_fwd`/`fmha`, Attention (MLA), RoPE+KV Store, TopK, Act+Mul (was Activation (SiLU+Mul)), Collective, Library Collective, MemSet, Softmax, Reduce, Add, Mul, LayoutTransform, Convolution, Compiled.
- ck_tile `Rmsnorm2dFwd` covers add or quant only when its `Rmsnorm2dFusedAddEnum` / `Rmsnorm2dFusedQuantEnum` template flag is non-zero.
- aiter `mfma_moe` kernels type as MoE GEMM (CK) and MoE GEMM+SiLU (aiter); PyTorch `silu_kernel` types as Activation (SiLU); RMSNorm (fused triton) covers `(add, norm)`.
- Compiled-ness is a per-kernel fact from the `COMPILED_PREFIX` name prefix (`is_compiled`), since many inductor kernels type as the op their name mentions.
- Convolution is narrowed to `fprop|wgrad|grouped_conv|naive_conv|igemm_(fwd|bwd|wrw)_gtc`; a bare `conv` alternative would mistype `triton_poi_fused_convolution_*`. `\breduce_kernel` no longer catches `multimem_all_reduce_kernel`.

### Fusion module (`TraceLens/Agent/Analysis/utils/kernel_fusion.py`, new)

| Class | Decision it owns | Interface |
|---|---|---|
| `FusionForms` | Fused forms derived from `covers` (one per distinct covers tuple of a fused type, excluding Compiled and types covering `moe_gemm` or `route`); kind names (`KIND_NAMES`, else joined elements); `SPAN_KINDS`; matrix and fusable predicates | `forms`, `kinds`, `is_fused`, `is_matrix`, `matrix_mask`, `is_fusable`, `replaces_span` |
| `FusionLabeler` | Exclusions, the 15-kernel cap, seam matching (`MAX_GAP = 1`), kind and confidence. Pure: names and op keys in, `Label` out | `label(names, op_keys) -> Label \| None` |
| `FusionCandidateBuilder` | Tree walk, module grouping, scoped sibling fallback, Case-A gates (`CASE_A_MAX_DELTA`, `CASE_A_MAX_N1`), span narrowing per instance, the one dedup, data in/out split. `OpResolver` moves here unchanged | `standalone()`, `comparative(diff_stats)` |
| `FusionPricer` | Time shortlist, roofline and measured-gap cost model (unchanged), detail rows, suppression | `shortlist`, `price_all`, `price`, `price_comparative`, `build_rows`, `suppressed_op_keys` |

Kinds derived from the current taxonomy: `attention`, `add_norm_quant`, `add_norm`, `norm_quant`, `allreduce_norm`, `rope_kv_store`, `routing_topk`, `act_mul`, plus the generic `gemm_epilogue` and `elementwise_chain`. A new fused-kernel rule in the taxonomy adds both already-fused recognition and its seam kind; there is no second table.

Matrix ownership is per launching op: `matrix_mask` marks a kernel matrix when any kernel with the same perf key in the group covers gemm or moe_gemm. The layout and zero-fill kernels a GEMM or convolution op launches are part of that op, not an epilogue. The labeler and `FusionPricer.price` both use the mask.

## Contract changes

| Artifact | Change |
|---|---|
| `fusion_candidates.json` | Gains `fusion_kind` and `confidence`. Drops `has_fused_kernel`, `eligible_kernel_count`, `kernels[*].eligible`, `lca_id` and the sibling `op`. Sibling kernels use `name`/`type`. Fields with no value are omitted instead of written as null. Groups the labeler excludes (over cap, all matrix, already fused, compiled) are no longer emitted, and neither is a sibling sequence that is a contiguous run inside an accepted module candidate. Only `kernel_fusion_analysis` reads this file |
| `kernel_fusion_metrics.json` | `impact_estimates[*]` carry `fusion_kind`. `candidate_count` counts after the labeler's exclusions, so it drops wherever the old CLI counted a group and then excluded it in pricing (for example the convolution groups of a ResNet training trace, now excluded as all-matrix); impact scores are unchanged |
| `high_confidence_op_keys` | A high finding suppresses only the ops its fusion removes. An `act_mul` finding on `Qwen2MLP` suppresses the silu and mul ops; its two `aten::mm` ops leave the set, lose `fusion_flagged` and regain their own GEMM findings. An `attention` finding still suppresses its batched GEMMs |
| Confidence | A fully classified pointwise chain is high regardless of module name, so a pointwise sibling sequence in a Qwen2 decoder frame, previously medium for lack of a name hint, is now high; any Unknown kernel gives low; `gemm_epilogue` is medium |
| Labels on matrix groups | Conv and `Linear` groups whose non-GEMM kernels are launched by the matrix op itself (layout transforms, zero-fill) are excluded as all-matrix instead of priced as an epilogue. An elementwise prologue followed by a GEMM (`aten::matmul`) is `gemm_epilogue`, medium |
| `analysis.json` | `FusionTask.kind`, parsed from `**Kind:**` and validated against `FusionForms.kinds` (null otherwise). Additive; `operation` keeps the LLM title |
| `classify_kernels` types | Type strings change as listed above. perf_category moves: normalization types from `Others` to `Normalization`; `igemm_*_gtc` from `GEMM` to `Convolution`; MemSet is `MemCpy`. The pipeline reads only the type, so these do not reach category tables; they affect the `classify_all` output used by semantic comparison |

## Validation

- Exact-bytes regression of the deterministic pipeline (perf report CSVs, `orchestrator_prepare`, category scripts, `priority_data.json`) plus `analysis.json` renders across the fusion regression corpus.   - Taxonomy: 24 pipeline cases and 23 renders, 173 expected diffs. Pass, 0 unexpected, 0 unused.
  - Fusion module: 46 cases, 246 expected diffs. Pass, 0 unexpected, 0 unused. One MI355X FP4 inference trace with no fusion findings was excluded; its MoE GEMM retype is pinned by real-name unit tests.
- Unit (`analysis_agent`, `reporting_utils`, `test_util`): 1043 passed. Each new behavior was mutation-tested against its test.
- `black` clean. Merges cleanly with `staging_agent` and `main`.
