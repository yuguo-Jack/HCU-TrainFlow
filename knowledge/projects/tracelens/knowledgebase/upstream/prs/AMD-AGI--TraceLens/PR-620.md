# Add IdleTimeAnalyser: classify GPU idle gaps by root cause

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/620) · state: open · merged: False

## Original PR description

## Summary

Adds `IdleTimeAnalyser`, which explains every gap between consecutive GPU events (kernels, memcpy, memset) in a PyTorch profiler trace instead of reporting GPU idle time as one number. It's opt-in; existing reports are unchanged.

For each gap, the analyser looks at the thread that launched the GPU op ending the gap and **measures** what that thread did, as parts that add up to the gap:

| Case | Parts |
|---|---|
| Next op launched during the gap (*unqueued*) | `cpu_op_us`, `cpu_runtime_us`, `cpu_untraced_us`, `launch_call_us`, `submit_latency_us` |
| Next op already queued before the gap | `gpu_wait_us` |
| No traced launch | `unattributed_us` |

The label names the largest part: `CPU_OP_DOMINATED`, `RUNTIME_DOMINATED`, `UNTRACED_DOMINATED`, `LAUNCH_DOMINATED`, `UNEXPLAINED_GPU_WAIT`, or `UNATTRIBUTED`. Independently, `drain_type` says why the GPU queue was empty: `sync_drain` (a sync call blocked the CPU while the GPU drained its queue) or `starved` (the CPU didn't submit work in time). They call for different fixes: move or remove the sync, or make the CPU do less per GPU op.

## Output

Three sheets, coarse to fine:

- **`idle_overview`**: GPU utilization, noise vs. macro idle, and rows per label and `drain_type`, each with the parts as columns. Sync-drain rows are per sync call, or per line of code with `--include_call_stack`, and carry `sync_gain_ms`, an upper bound on what removing that sync could save.
- **`idle_groups`**: gaps grouped by label, `drain_type`, and `covering_op` (the CPU op running on the launching thread during the gap), with `top_runtime`, `top_launch`, `top_next_gpu_op`, gap statistics, and cumulative share. Small groups are folded.
- **`idle_intervals`**: one row per gap, with the parts, launch and sync details, TraceLens UIDs, and call stacks for the sync call and the covering op with `--include_call_stack`.

`--enable_augmented_trace` also writes the trace with three idle annotation tracks for Perfetto.

## Usage

```bash
TraceLens_generate_perf_report_pytorch --profile_json_path trace.json \
    --enable_idle_analysis --include_call_stack --enable_augmented_trace

# Standalone: overview on stdout, Excel workbook, augmented trace
python -m TraceLens.Reporting.classify_idle_time trace.json --include-call-stack
```

```python
from TraceLens import TreePerfAnalyzer
from TraceLens.IdleTimeAnalyser import IdleThresholds, IdleTimeAnalyser

pa = TreePerfAnalyzer.from_file("trace.json", add_python_func=True)
dfs = IdleTimeAnalyser(pa.tree, IdleThresholds(), include_call_stack=True).get_dataframes()
```

## What's new

- `TraceLens/IdleTimeAnalyser/`: `classify.py` (per-gap measurement and labels), `report.py` (sheets, Excel), `IdleTimeAnalyser` and `IdleThresholds` exported from `TraceLens`.
- `generate_perf_report_pytorch`: `--enable_idle_analysis`, `--enable_augmented_trace`, `--idle_launch_latency_us` (15 µs default). `--micro_idle_thresh_us` doubles as the noise threshold (5 µs default), and `--include_call_stack` also adds the idle call-stack columns.
- `TraceLens/Reporting/classify_idle_time.py`: standalone CLI over the module.
- Docs: `docs/how-to/analyze-idle-time.md` (a step-by-step diagnosis, common patterns, and two worked examples) and `docs/reference/idle-time-columns.md` (every column, rule, and threshold), linked from the TOC, the PyTorch report page, and the API reference.

## Validation

- The classifier was checked gap by gap against an independent prototype on 6 traces (17,860 gaps); every gap matches.
- It was run on training, inference, and serving traces from AMD Instinct and NVIDIA GPUs, and individual gaps were spot-checked against the raw trace. Analysis cost is listed in the how-to (for example, 3.4 s of analysis after a 5.8 s load on a 5.5 MB vLLM trace).
- The sheets were also given to LLM agents as the starting point for diagnosing traces. `sync_gain_ms` and `covering_call_stack_full` were added because the agents worked them out by hand or asked for them.

## Tests

`tests/test_classify_idle_time.py` (90 tests):

- Unit tests for each part, label, and `drain_type` rule on synthetic traces, including queued vs. unqueued, blocking copies, other-thread runtime calls, sync drain vs. late sync, stream switches, and slow launch calls.
- Sheet construction: overview rows, grouping and folding, sorting, the new columns, and call-stack columns present only with `--include_call_stack`.
- Real-trace regression on a DDP ResNet-18 fixture and the existing FSDP trace (parts add up to each gap).
- End to end: standalone CLI outputs, and `generate_perf_report_pytorch` with and without `--enable_idle_analysis`.

## Follow-ups (not in this PR)

- Name the blocking thread for `RUNTIME_DOMINATED/other_thread` (per-thread totals and a thread id column).
- Speed up classification on very wide traces (hundreds of thousands of gaps), where it takes longer than loading the trace.
- Factor the GPU timeline, host-side index, and launch links into reusable pieces, so that kernel queue time and launch analysis work outside idle analysis and can be exported for large-scale analytics.
- Multi-rank: this PR analyzes one rank per trace; cross-rank views come later.
