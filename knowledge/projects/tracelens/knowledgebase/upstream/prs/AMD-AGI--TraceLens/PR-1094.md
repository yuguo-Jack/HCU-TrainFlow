# Generate perf reports from one YAML config

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1094) · state: closed · merged: True

## Original PR description

﻿## Summary
- Add `TraceLens_generate_perf_report_from_config --config run.yaml`, also available as `python -m TraceLens.Reporting.generate_perf_report_from_config`. One YAML describes a run, and each job produces one report. The whole file is checked before any trace is opened.
- Two modes: `default` calls the training report, and `inference` calls the inference report. Graph capture is an optional per-job `capture_folder`. Speculative decoding uses the same capture folder, and prefill and decode are two inference jobs.
- Per job: `name` (required when there is more than one job), `trace_path`, `platform` or `gpu_arch_json_path`, `capture_folder`, `compare_to`, and `precomputed_diff_stats`. `compare_to` behaves exactly like `--comparison_json_path`: it adds diff columns to that job's report and writes no report for the compared trace.
- Report options are top-level keys named after the report function's parameters. An option the YAML doesn't set gets the same default as in the matching CLI, including `collective_analysis` off in inference, so a YAML with no options produces the same report as the CLI with no flags.
- Outputs are `perf_report.xlsx` and `perf_report_csvs/` for one job, or `perf_report_<name>.*` per named job, plus `run_config.resolved.yaml` with every option spelled out.
- New docs topic, `how-to/generate-perf-report-from-config`, recommends this path. Both existing scripts are unchanged.

## Test plan
- [x] `tests/test_perf_report_from_config.py`: schema validation, dispatch, CLI-matching defaults, naming, comparison passthrough, resolved config, and stop-on-first-failure
