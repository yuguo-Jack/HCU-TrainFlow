# Hyperloom Non-LLM Path Changes

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1168) · state: closed · merged: True

## Original PR description

Hyperloom's non-LLM route reads a TraceLens perf report and writes `analysis.json` with no agent and no
`analysis.md`. Hyperloom builds the file; the rules it needs (task grouping, impact, member formatting, platform
metadata and the category rollup) stay in TraceLens and are exposed here as public functions, so Hyperloom calls them
instead of copying them.

Public names:

- `compute_tasks(op_metrics) -> list[ComputeTask]` in `post_processing/analysis_json.py`, re-exported from
  `post_processing`. It turns `build_operation_metrics` rows into one finding per row and runs them through the
  existing `TaskGrouper`, so grouping by op and phase, sorting, capping and impact are the code the md-driven renderer
  uses.
- `TASK_SOURCE_COLUMNS`: the raw perf-report columns (`Input Dims`, `Input type`, `call_stack_full`) a caller passes
  to `build_operation_metrics` as `extra_fields` so `compute_tasks` can fill task members.
- `perf_report_metadata(csv_dir, platform) -> dict` in `utils/orchestrator_prepare.py`: platform peaks plus the perf
  report's GPU utilization, the metadata `build_operation_metrics` reads. `orchestrator_prepare.main()` uses it for
  the values it computed inline. Import it from the submodule; re-exporting it from `utils` would close an import
  cycle.
- `ops_summary_by_enhanced_category(csv_dir) -> list`, renamed from the private
  `_build_trace2_ops_summary_by_enhanced_category(trace2_csv_dir)`. It rolls `unified_perf_summary.csv` up by enhanced
  category, sorted by GPU kernel time. Hyperloom writes these rows as `top_operations`; the agent route keeps calling it
  for trace 2 of a comparison. Logic unchanged.

Three formatters are split into a structured part and the existing renderer on top, so members can be built from
values instead of display strings: `_kernel_name_list` under `_extract_kernel_names`, `_arg_pairs` under
`format_args`, `_efficiency_parts` under `FusionPricer._efficiency_cells`. The renderers return the same strings.

## Observable effect

None on the agent route. `orchestrator_prepare`, the category and fusion outputs, the deterministic fallback and
`render_analysis_json` produce the same output. The new names are additive; the rename has one in-repo caller,
updated.

## Validation

- From #1163: `tests/test_analysis_agent_utils.py` and `tests/test_analysis_agent_post_processing.py`, 310 passed;
  `test_compute_tasks_group_rows_by_op` pins the `compute_tasks` contract. Output identity against the base:
  `_extract_kernel_names` and `format_args` on 167 perf-report CSVs (about 1M rows), `_efficiency_cells` on about 65K
  real cells across MI300X, MI325X and Radeon_8060S, `orchestrator_prepare` plus the category and fusion scripts on
  6 cases, and `render_analysis_json` on 43 `analysis.md` files: all identical.
- Rename: the four existing rollup tests pass under the new name; `black` clean.
- Category check of the rollup on 85 real perf reports: `cpu_idle` and `multi_kernel` never appear (they are added
  separately on the agent path). `other` tops 31 of them, where kernels are unclassified.
- The re-landed tip differs from `staging_agent` in exactly the 7 files of #1163 and the rename (+217/-66).
