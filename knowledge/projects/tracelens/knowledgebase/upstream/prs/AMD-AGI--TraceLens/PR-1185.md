# feat(roofline): introspect custom (vLLM) model layers generally

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1185) · state: closed · merged: True

## Original PR description

## What

`TraceLens_model_roofline_projection` costs a custom model from the drawn graph, the parsed modeling source, and the checkpoint. The rules are role, class, and config driven. They do not special-case model names.

A row uses the first source that applies:

1. A drawn leaf with a PerfModel formula, at that node's shape. A linear already under an attention tile, or a router or shared expert already under a MoE tile, is not costed again.
2. A constructor width from the class that assigns the linear. Two classes that disagree on one attribute each keep their own size. An engine parallel linear is sharded on the axis that class shards.
3. The checkpoint, for any width the source did not resolve.
4. An explicit fallback, only for a speculative draft whose source has no draft class.

## Coverage

- **Attention.** An opaque tile gets the SDPA core plus the projections packed inside it. The attention class's own linears are used when their constructor widths resolve. Otherwise the tile is a packed QKV plus output projection, or the latent projections when `kv_lora_rank` is set. The latent score width is `kv_lora_rank + qk_rope_head_dim`. The query width is `qk_nope_head_dim + qk_rope_head_dim`, and the value width is `v_head_dim`, when those ranks exist. QK-norm, RoPE, relative attention, and a short conv inside a fused leaf are separate rows when the checkpoint declares them.
- **Indexer.** `index_n_heads` and `index_head_dim` add the query and key GEMMs, a score over the context, and a top-k reduction. `index_topk` limits indexed attention. A layer that already has a window keeps it: `local_layer_ids` paired with `layer_types` selects `sliding_window`, and the other layers attend the full context.
- **Causal attention.** The checkpoint's `is_causal` / `causal` wins. Otherwise a decoder-only model is causal and an encoder, BERT, T5, or vision model is not. The mask applies on cold prefill.
- **Quantized weights.** fp4/MXFP4, fp8/int8, and int4/NF4 set the weight traffic. Weight-dequant (and fp8 activation quant) sits beside the GEMM. `modules_to_not_convert` stays at the activation dtype, including a listed LM head. An fp4 or fp8 matrix peak applies only to a GEMM or MoE row when the GPU publishes it. Attention stays at the activation dtype.
- **MoE and dense MLP.** Selected experts only, as a grouped GEMM over the experts this GPU streams. Tensor parallel shards the intermediate width. Expert parallel takes the floor of the routed rows and adds dispatch/combine. The router, its softmax, the combine, and a shared expert are their own rows when the graph did not draw them. A dense MLP on the same attribute is a SwiGLU at `intermediate_size`. Bias follows the node or `attention_bias` / `mlp_bias` / `lm_head_bias`.
- **Convolutions.** A graph conv is costed from the geometry the meta-device pass threaded onto the node. A meta-device forward can replace those rows. A conv with no geometry stays unmodeled. Embeddings and reshapes stay unmodeled.
- **Speculative draft.** `--num-predicted-tokens` adds one depth per token, capped at the checkpoint's draft depth. The depth is the parsed MTP / NextN / EAGLE class: its norms, its own projections, its attention, and its dense or MoE feed-forward. An LM head is included only when the draft class assigns one. Drawn draft leaves are not repeated. An attention core or expert GEMM the graph inlined away still is. With no draft class, the depth is the fixed template: two RMSNorms, a 2H→H projection, one attention, a dense MLP, and the LM head.
- **Engine source.** A vLLM or SGLang run whose modeling source did not load, or whose constructors did not resolve, says so in the JSON rollup's `notes`. The widths then come from the checkpoint. Parallel-plan discovery reads imported sibling modules, not every cached file beside the model.
