# feat(roofline): introspect quant precision, MoE, and attention

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1178) · state: closed · merged: True

## Original PR description

## Summary

The model-explorer roofline (`TraceLens_model_roofline_projection`) left custom architectures partly unmodeled. On a quark-MXFP4 MoE model like **Inkling** it:

- matched only vLLM's `FusedMoE` by class name for the MoE boundary (so `InklingMoE` fell through),
- costed **every** GEMM operand at the activation dtype, ignoring quantized **weight storage** (MXFP4 weights counted as BF16 → ~4× too many weight bytes),
- had no formula for non-SDPA attention, so the custom `Inkling Attn` op was dropped as "unmodeled".

Those two ops are the bulk of the work, so the roofline covered only ~83% of output elements and said nothing about the dominant kernels.

This makes all three **config-driven (introspected) rather than name-driven**:

### 1. Quantized weight precision
`_quant_storage_dtype` now understands quark's nested `global_quant_config.weight.dtype` (MXFP4 → `fp4`). `_moe_cost` costs the weight operands at the introspected **storage** dtype (MXFP4 ≈ 0.53 B/elem = 4-bit + e8m0 scale per 32), while **compute precision stays the activation dtype** — correct for the common dequantize-to-bf16 emulation path.

### 2. MoE detection
A small per-run `_RuntimeIntrospection` context is populated from the `ArchitectureSpec`. An FFN module in a model that declares experts is costed as MoE via its **module role** (`role="ffn"` + `num_experts_per_tok`), with `FusedMoE` kept as the generic engine fallback. No per-model class names.

### 3. Attention
New `_attention_boundary_cost` models an attention layer from the spec (query/kv heads, head dim) and the **sliding-window / global layer mix** (`sliding_window_size`, `local_layer_ids`), averaging the effective KV length across layers so per-layer cost × repeat count matches the aggregate. Uses the existing `SDPA` formula.

## Result

On `Inkling-MXFP4` (vLLM `--engine vllm --tp 8`): **100% of ops modeled** (was ~83%). Decode comes out **attention- and memory-bound** (KV-cache streaming), prefill **MoE-compute-bound** — matching the captured torch trace where the attention kernel was ~58% of E2E GPU time.

## Tests

- quark case added to `test_quant_storage_dtype_across_methods`
- `_introspect_weight_bpe` across quant methods
- MXFP4 weight dtype shrinks MoE bytes
- sliding-window layer mix reduces attention FLOPs/bytes
- updated the `_parse_op_node` unpack test for the new `role` field

All 253 tests in the two affected suites pass.

## Notes / limitations

- `_moe_cost` still assumes well-batched experts (weights read once, amortized over `tokens × experts_per_tok`); at low decode batch real per-expert weight re-reads make it more memory-bound. This PR fixes the **precision**, not that batching model.
- Attention omits short-conv / relative-attention-bias terms (small vs core QK/softmax/AV).
- The vLLM Inkling module declares no HF `tp_plan`, so FLOPs/bytes remain whole-model under `--tp` (unchanged behavior).
