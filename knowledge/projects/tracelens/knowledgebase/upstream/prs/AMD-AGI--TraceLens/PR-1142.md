# feat(perfmodel): Added VLA specific perf models

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1142) · state: open · merged: False

## Original PR description

## Summary
Adds perf-model coverage for ~36 previously-unmodeled `aten` ops observed in VLA/robotics workloads (CogACT, GR00T, DDVLA):

- **unary_elemwise_ops**: `_to_copy`, `fill_`, `zero_`, `clone`, `gelu`, `cos`, `sin`, `exp`, `log`, `sqrt`, `clamp`, `clamp_`, `bitwise_not`, `uniform_`, `normal_`, `exponential_`
- **binary_elemwise_ops**: `sub`, `sub_`, `eq`, `ne`, `gt`, `lt`, `ge`, `le`, `bitwise_and`, `bitwise_or`
- **reduce_ops**: `argmax`, `all`, `any`
- **New dedicated classes** (variable arity or index-tensor-driven output shape): `aten::cat`, `aten::index_select`, `aten::gather`, `aten::_index_put_impl_`, `aten::masked_scatter_`, `aten::arange`, `aten::where` — new `DataMovement`/`TernaryElementwise` sheet categories.

## Reference outputs updated (`--update-references`)
Some ops in these traces previously fell into `category=other`/unmodeled time and are now correctly attributed. New sheets (`DataMovement_fwd.csv`, `TernaryElementwise_fwd.csv`) appear where traces had no prior coverage in those categories. No kernel-time/roofline methodology changed, only op-name coverage/categorization. 
Affected: `tests/traces/{h100,mi300}/*`, `tests/traces/compare_test*/reference/*`, `tests/traces/inference/*`, `tests/traces/perf_model/normalization`, `tests/traces/torch_compile_triton`.
