# fix(validation): require the Data table on every compute finding of analysis.md

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1169) · state: closed · merged: True

## Original PR description

## Problem

`analysis.json` names a compute finding's kernels from its `**Data:**` table only. When the orchestrator writes a compute finding into `analysis.md` as prose, with no table, the rendered finding lists no kernels, which reads as "nothing hot". `validate_findings_file` already requires the table in each category's findings, but `validate_report` does not check the final report, so the orchestrator is never asked to fix it.

Seen on a Radeon AI PRO R9600D run (Qwen3.5-9B): the trace analysis produced no hot kernels for the kernel phase to tune.

## Change

- `validate_report` (rule R5 in `_validate_report_reasoning_candidates`) reports each compute reasoning-candidate block that has no `**Data:**` table, with its rank and line. The orchestrator's existing report-validation loop then regenerates the report.
- `render_analysis_json` is unchanged and still renders a report it is given; one bad finding does not fail the whole analysis.

## Tests

- `test_validate_report_r5_compute_block_needs_its_data_table` fails with `main`'s validator and passes here.
- `test_analysis_agent_utils.py`, `test_analysis_agent_evals.py` and `test_analysis_agent_post_processing.py`: 452 passed. `black --check` and the CI `ruff` selection: clean.
