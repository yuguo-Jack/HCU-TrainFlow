# fix(visualizer): resolve remaining shape/wiring gaps in MiniMax export

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1156) · state: closed · merged: True

## Original PR description

## What this does

Continues the Model Explorer export shape/wiring fidelity work on MiniMax-M3.1-flash (SGLang/vLLM). Root-causes and fixes several AST-analysis and shape-inference gaps found by direct inspection of the exported JSON (not absence-of-warnings alone):

- **`embed_tokens` dead-node / `self_attn/@input:hidden_states` sourceless** (the main fix): `MiniMaxM3Attention.forward` is nothing but a dispatch to sibling stage methods (`forward_prepare`/`forward_core`), so `_primary_forward_input_name` had no local evidence and fell back to signature order (`positions`) instead of `hidden_states`. New `_delegate_primary_name` resolves the tie by asking what each delegate's own submodule calls touch. Also fixes two supporting gaps found along the way: a pipeline-parallel single-rank boolean predicate (`self.pp_group.is_first_rank`), and seeing through a trivial getter-call alias (`self.get_input_embeddings()(input_ids)`), applied consistently across the three independent AST dataflow entry points.
- **`stack_entry_dataflow`'s per-layer loop detection**: now finds the loop when it's nested inside a scheduling `if/else` wrapper, and recognizes both an all-keyword call site and a direct `for layer in self.layers:` iteration alias (the alias resolver rewrites both forms to `self.layers(...)`, so neither names the call by the loop target directly any more).
- **`_swiglu_oai_mxfp8` sourceless**: `_forward_mixes_modules_and_inline_ops` only looked for a surviving inline op as evidence of real wiring; a pruned Merge/Phi (one arm ruled out by a config-gated unbuilt submodule, e.g. MiniMax's `swigluoai` activation) collapses its wiring onto the surviving arm but leaves no operation node behind. Now also treats a predecessor rewired away from plain source order as evidence worth keeping.
- **Pack "no shape inference rule" warning**: a `Pack` bundles independently-shaped tensors, not slices of one tensor, so it has no honest "whole" shape. Skips the generic rules instead of publishing a bogus `inputs[0]` passthrough; per-port shapes are already handled by `_publish_output_port_specs`.

## Verification

Ran the real `MiniMaxAI/MiniMax-M3.1-flash` SGLang and vLLM exports before/after and confirmed via direct JSON inspection (not just warning counts) that `embed_tokens` and `self_attn`/`mlp`'s `_swiglu_oai_mxfp8` now have real producer edges, with no new warnings introduced. Added regression tests for the sibling-delegate primary-parameter resolution (`tests/ModelUtils/test_method_primary_parameter.py`).

Full `python -m pytest tests/` passes except pre-existing, unrelated failures (JAX-trace/hardware-dependent tests, confirmed identical with these changes stashed out). `black .` is clean.

## Remaining (tracked separately / in progress)

- `_split_index_qkv` dead-node/type-check warnings tied to MiniMax's `disable_index_value` per-layer frequency list (needs a `ModuleDimRegistry`-level fix, not yet done).
- Full zero-warning vLLM export verification and the final HTML artifact generation.

## This round: MiniMax dispatch-only \`forward_core\` + remaining residual warnings

Picked up where the previous round left off (the \`is_sparse_attention_layer\` ctor-default fix had eliminated the "Mutually exclusive branch" warnings but left a new gap exposed): once the sparse-attention branch prunes away, \`forward_core\` is left with **zero inline tensor ops**, just \`self.attn(q, k, v, forward_batch)\` then \`self.o_proj(...)\`. A zero-op sibling method never earned a \`multi_op_methods\` entry and was silently skipped, so it rendered opaque and its submodule call's four arguments — all sharing one undifferentiated boundary token — couldn't be told apart.

### Fixes (ast_analyze.py / block_tree.py / computation_graph.py)
- Preserve a zero-op method's submodule-call wiring when it has a **real submodule predecessor** with resolved arguments — narrowly scoped to exclude a plain-method delegate (handled separately by \`_alias_delegating_self_methods\`) and a method still hiding unresolved HW-flag branches or empty argument names (verified against vLLM's own \`_run_attention\`, which matches a similar "dispatch with no own tensor ops" shape but must stay opaque).
- New \`step_predecessor_ordinals\` map (threaded through \`ClassStructure\`/\`BlockNode\`) records which producer **slot** each argument reads when several arguments share one boundary token, and \`_record_output_unpack\` now tags ordinals for a bare tuple-unpack of the method's own input (\`q, k, v = inner_state\`).
- \`build_block_node\` materialises real \`attn\`/\`o_proj\` children for the dispatch-only method instead of a bare opaque leaf.
- The computation-graph wiring pass revisits a block with ordinal-ambiguous arguments and resolves a submodule step's (not just an operation's) boundary input — both changes scoped tightly to steps that actually carry ordinal evidence, confirmed to leave GLM vision attention's \`qkv\` and vLLM's \`_run_attention\` untouched (an earlier, broader version of this regressed both).
- \`_settled_ctor_defaults\` also resolves a constructor arg passed by **name** (\`is_sparse_attention_layer=is_sparse_attention_layer\`) against the caller's own settled locals, not just a literal default nobody overrides.

### Remaining known gap
The \`Pack\` producing k/v (\`forward_prepare\`'s \`inner_state\`) still can't fan out a distinct consumer edge per ordinal through the merge-time boundary-tile stitching (\`_route_frame_exits_through_output_tiles\` in \`merge.py\`), which only ever materialises one edge per newly-minted tile. Until that's reworked, \`forward_core\`'s k/v slots are correctly flagged by the I1 dead-node check rather than silently pruned — documented in a comment at the fallback site.

### Verification

- vllm export: warning-free beyond its own pre-existing, documented \`_run_attention\` opaque-leaf passthrough.
- Added regression tests (\`test_dispatch_only_forward_method.py\`, extended \`test_settled_ctor_defaults.py\`).
- \`black .\` clean.
- Full \`pytest tests/\` suite: no new failures beyond the pre-existing JAX-trace / hardware-benchmarking ones (confirmed against a stashed baseline).

## Follow-up: direct JSON inspection caught a silent mis-wiring

Per the goal's own bar ("verified by direct inspection of exported JSON node shapes, not just the absence of warning log lines"), I inspected \`attn@l1465\`'s own incoming edges directly rather than stopping at the warning log. Before this fix, \`k\`/\`v\`/\`forward_batch\` each silently fell back to \`forward_core\`'s generic primary-input boundary (\`@input:hidden_states\`) — a real edge, but labeled with an unrelated tensor's identity, not a missing one. No integrity check catches this (I1 only flags *missing* consumers), so it was invisible to every warning-based check.

Fixed by skipping that fallback specifically for an argument \`ordinal_map\` itself already flags as unresolvable (a non-first slot sharing the method's bound boundary token) — leaving it honestly unwired instead of mislabeled, which the pre-existing I1 dead-node check on the \`Pack\`'s own k/v slots already correctly reports.

No warning text changed. Verified via direct re-export + JSON inspection that \`k\`/\`v\`/\`forward_batch\` no longer mint wrong-identity \`@input\` tiles on \`attn\`. Full \`tests/ModelUtils\` + \`tests/Visualizer\` suite (2478 tests): all pass.
