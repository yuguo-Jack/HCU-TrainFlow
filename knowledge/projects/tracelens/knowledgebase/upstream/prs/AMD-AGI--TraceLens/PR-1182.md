# feat(modelutils): Loom loom-port-llm cfg.json architecture-facts CLI

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1182) · state: closed · merged: False

## Original PR description

## What

Adds `TraceLens_loom_port_cfg`: loads a Hugging Face checkpoint through the same AST backend as `TraceLens_visualize_model_in_explorer`/`TraceLens_model_roofline_projection`, and derives the subset of [`loom-port-llm`](https://github.com/loom-fun/loom-skills/tree/main/skills/loom-port-llm)'s `cfg.json` architecture fields that follow directly from the checkpoint's own `config.json`/modeling source: `hidden`/`layers`/`heads`/`kv_heads`/`head_dim`/`ffn`/`vocab`/`context_length`/`tied_embeddings`, `rms_eps`, `rope_theta`/`rope_dims`, `qk_norm`, `sliding_layers`/`sliding_window`, `recurrent_layers`.

## Why this scope

A runnable Loom model needs hand-authored `.loom` kernel/control/prepare programs (e.g. `hrx-loom-library`'s `Qwen3.8-27B` card wires ~150 hand-written kernel files) — TraceLens's AST backend only has analytical FLOPs/bytes formulas, with no notion of GPU kernel bodies or quantization packing, so it can't author those.

The real opening is `loom-port-llm`'s config-driven generator (`starter/gen_llm.py`), which turns a declarative `cfg.json` into actual kernels for the dense-transformer family. That `cfg.json` comes from the skill's own `inspect_gguf.py`, which reverse-engineers GGUF tensor names and either hardcodes or leaves several fields blank (`rope_type`, `embed_scale`, `sliding_layers`, `nope_layers`) for a human to fix by reading `llama.cpp`'s `src/models/<arch>.cpp`. `TraceLens.ModelUtils.extract.ArchitectureSpec` already parses the checkpoint's real config/source (ground truth, no GGUF round-trip) and already carries most of this, so this PR is a thin, honestly-scoped mapping from that spec to the `cfg.json` fields TraceLens can state with confidence — plus a `--check` mode that diffs against an already-authored `cfg.json`.

`--tp`/`--pp`/`--ep` and the roofline CLI's `--batch-size`/`--seq-len`/`--gpu-arch-name` do not apply: `loom-serve` runs a model whole on one device, and `cfg.json` is a static architecture description, not a workload projection.

**Deliberately left alone** (documented, never guessed): `rope_type` (a `llama.cpp` GGUF weight-permutation convention, not an HF-source property), `attn_gate`/`post_norms`/`embed_scale`/`embed_norm` (need AST submodule/weight-name inspection this repo doesn't do yet), `gdn` kernel geometry, `tensors`/`gguf`/`chat`/`eos_id`/`bos_id` (GGUF conversion and Jinja-chat-template concerns, owned by `inspect_gguf.py`/`chat_probe.py`).
