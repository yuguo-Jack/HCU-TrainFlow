# TraceLens Agent: route every core category to a specialist sub-agent

## Summary

Every category label TraceLens core emits today now routes explicitly to a sub-agent, and a test derived from core keeps the routing map in lockstep with the labels. The category scripts share one required `--category` contract, a few script bugs are fixed, and the sub-agent specs gain rows for the categories they now own. TraceLens core is unchanged.

## Why

| Pain point | Old | New |
|---|---|---|
| Unrouted labels | `groupquant`, `rope_fwd`, `rope_bwd`, `fusedrope`, `multi_tensor_apply`, `moe_aux`, `crossentropy_fwd` and `crossentropy_bwd` fell through to the generic analyzer | Routed to elementwise, moe and reduce. Generic-by-design labels are listed explicitly; unknown labels still fall through at runtime |
| Map drift | Dead `norm`, `convolution` and `cpu_idle` keys; nothing caught a new core label | `test_category_skill_map_matches_core_emittable_labels` asserts the map equals the set core can emit |
| Grouped GEMM route | `gemm_analysis.py` hardcoded `gemm`, so `groupedgemm_*` read the wrong CSV | Required `--category` on every multi-label script, no hardcoded `choices`; the manifest is the only source |
| Quantized GEMM detection | Name substrings (`fp8`, `w4a16`, ...) | `Compute Spec` in {`matrix_fp8`, `matrix_fp4`, `matrix_int8`} |
| Inference attention workload type | Read `sum_ctx_tokens` / `sum_gen_tokens`, which the InferenceAttention model does not emit, so it was always `unknown` | Reads `c_sq` / `g_sq` |
| D2D copies | Collected, never reported | Flagged when their time share exceeds 5%. Count alone does not flag D2D, since on-device copies are routine in a step |
| Broken spec commands | The triton, kernel-fusion and generic-op specs had a missing line continuation that dropped the scope flag | Fixed |

## Architecture

```
category_manifest.json  categories[].name   (normalized core label)
        │
        ▼
orchestrator_prepare.CATEGORY_SKILL_MAP ─► categories[].skill
        │                                 (unknown label ─► generic-op-analyzer)
        ▼
agents/<skill>.md   <cat> = manifest name
        │
        ▼
category_analyses/<x>_analysis.py --category <cat>
        reads  category_data/<cat>_ops.csv, metadata/<cat>_metadata.json
        writes category_data/<cat>_metrics.json ─► category_findings/<cat>_findings.md
```

## Compatibility

`--category` is now required on the gemm, elementwise, reduce, sdpa, moe, norm, convolution and other scripts. Any caller outside the orchestrator specs must pass it.

## Known limitations

- Labels core does not emit yet (linear attention, softmax, collective classification, data movement) are not routed; they follow the matching core changes.
- Prepare's per-category `sync_time_ms` and `has_sync_bottleneck` treat CPU op duration as sync time. On graph-replay traces every merged op carries the graph-launch duration, so most categories flag. No sub-agent spec cites them. Fix tracked separately.
- `cpu_idle_analysis.py` `kernel_analysis` reads perf-report columns that no longer exist and is empty; the spec no longer cites it. Fix tracked separately.

## Test plan

- [x] Every edited script exits 0 with `--category` on category data from two inference traces and a training trace; missing `--category` exits 2.
- [x] `other_analysis.py` output is byte-identical to the previous version for `other` and `customcollective`.
- [x] FP4 GEMMs report `is_quantized`, bf16 GEMMs do not; inference attention reports `decode_heavy` on a decode trace.
- [x] D2D is not flagged on any of the three traces.
- [x] The coverage test fails on an added dead key and on a removed real key.
- [x] Affected tests pass by node id; `black` and `ruff` clean on the touched `.py` files.
