### issue_comments

- eppaneamd · comment · 2025-05-02T19:10:04Z · [source](https://github.com/AMD-AGI/TraceLens/pull/138#issuecomment-2847911854)

This (draft) PR introduces new custom workflows as a starting point, with the possibility of adding them as new features in the future:

- More comprehensive generate_perf_report.py script
- Shows how the new node replay feature can be used together with low-level microbenchmarking tools such as hipblaslt-bench and MIOpenDriver
- Adds a README for the purpose of providing a possibility to describe what is done in the examples

Main goal:
- One of the major goals of the tool is to enable customers to quickly do perf analyses on their proprietary models so they can say what ops are slow, without sharing the actual profile traces
- TraceLens is starting to have a lot of features, which are showcased individually in separate notebooks
- These changes aim to provide a unified script including most (if not all) features so that clients can leverage them as easily as possible, and view the results of those in the resulting performance report (excel file)
  - Works for both single- and multi-GPU cases
- Microbenchmarking torch and low-level tools against metrics reported during the workload can indicate possible issues with the workload, or if there is something wrong with torch itself vs. the low-level tools 

Main improvements:
- Previous performance report analyzes only individual trace files, while the new one supports distributed traces and attempts to utilize traces from all ranks whenever possible

  - Reads and analyzes operations from all ranks and provides performance metrics based on those
    - gemm, conv, attention, elemwise 
    - GPU timelines from all ranks and their averages
    - Kernel launchers from all ranks
    - High-level grouped breakdown summary of ops
    - Benchmark most time-consuming gemms and convs with torch using the node replay feature, and low-level microbenchmarking tools such as hipblaslt-bench and MIOpenDriver
        - Compare those to metrics observed during the actual workload
    - Incorporate NcclAnalyzer for further analysis of comms in distributed runs

- Stand-alone node replay script which can be incorporated as a module as well
    - Benchmark and compare gemms and convs that contribute 99pct to the overall group-specific execution time
    
Status:
- While functional, still work in progress
  - Docstrings, function typing, logging, handling of error situations for enhancing user experience, further refactorings
  - Stand-alone node replay still outputs to console
  - Unit-tests
  - Forward and backward sheets for perf report
  - Check if hipblaslt-bench and MIOpenDriver are available
- What are the minimum changes for making this a viable, mergeable PR, so it can be developed in further PRs?

New feature ideas:
- Support for cublas-bench and cudnn-bench?
- hipblaslt gemm and miopen conv tuning capabilities? 
- Incorporate other TraceLens features, such as module tree view?
- Calculate TFLOPs and GB/s also in node replay?
  - These are already available in hipblaslt-bench and MIOpenDriver microbenchmarking results
