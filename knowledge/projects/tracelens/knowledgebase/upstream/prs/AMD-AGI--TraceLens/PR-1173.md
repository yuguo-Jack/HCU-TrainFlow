# Add vLLM 0.33 graph-capture profiler patch

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1173) · state: closed · merged: True

## Original PR description

## Summary
Adds `config_vllm_v0.33.0.patch` to `examples/custom_workflows/inference_analysis/vllm_patches/`, porting the inference-analysis profiler `record_function` instrumentation to **vLLM 0.33**.

## Why
vLLM 0.33 moves Inkling-class models onto the **V2 Model Runner** (`[gpu_worker.py] Using V2 Model Runner`). The existing patches stop at v0.31; without a 0.33 patch the graph-capture (cudagraph) regions emit no `graph_capture_profiler`/`graph_capture_step` annotations, so TraceLens can't attribute captured kernels to prefill/decode stages or modules.

## What changed vs v0.31
The v0.31 patch applied to 0.33 except two hunks, both in the cudagraph-capture path, due to upstream drift:
- `vllm/v1/worker/gpu/model_runner.py`: 0.33 inserts `model_state.capture_inner_cudagraphs(...)` after `cudagraph_manager.capture(...)` — the `graph_capture_profiler(self.vllm_config)` scope now wraps both.
- `vllm/v1/worker/gpu/cudagraph_utils.py`: 0.33 wraps `torch.cuda.graph(...)` in a `capture_pool(...)` context — `graph_capture_step(...)` is added as the first context of that `with`.
The other files (`graph_capture.py` new file, V1 `gpu_model_runner.py`, `gpu_worker.py`, `encoder_cudagraph.py`) carry over unchanged.

## Validation
- Applies with **0 rejected hunks** (`patch -p1 --dry-run`) against `vllm 0.33.0rc1.dev229+g3966924d5`.
- `import vllm` + `from vllm.profiler.graph_capture import graph_capture_profiler, graph_capture_step` succeed in the patched image (`vllm/vllm-openai-rocm:nightly-rocm100`, ROCm 10.0, MI350X/gfx950).

## End-to-end validation ✅

Ran a live cudagraph profiling run with this patch applied (Inkling 975B MoE, TP=8, MI350X/gfx950, ROCm 10.0, vLLM `0.33.0rc1.dev229`, V2 Model Runner, via Magpie + TraceLens inference flow).

**Result:** the graph-capture profiler fires and emits a `capture_traces/` directory with **54 per-capture traces** + `execution_details.json`. The patch's instrumentation shows up in the trace event names:
- `capture_496_FULL` — the `graph_capture_step(desc.num_tokens, desc.cg_mode.name)` label
- `vllm/profiler/graph_capture.py(126): graph_capture_step`
- `vllm/v1/worker/gpu/model_runner.py(1149): capture_model` and `vllm/v1/worker/gpu/cudagraph_utils.py(506/798): capture` — the V2-runner capture sites ported here

And the captured kernels now carry **module/source attribution** (previously `NA` in graph mode): e.g. `vllm/models/inkling/amd/ops/fa4_rel_attention.py`, `rel_attention_decode.py`, `model_executor/layers/fused_moe/*`.

TraceLens inference post-processing (prefill/decode roofline CSVs) completed successfully on the run. (Left as draft pending your review.)

@devalshahamd good call — added in 8c4106b.

`build_docker_vllm.sh` now has a **v33** target that applies `config_vllm_v0.33.0.patch`:
```
case v33) BASE_IMAGE="vllm/vllm-openai-rocm:nightly-rocm100"; PATCH_FILE="config_vllm_v0.33.0.patch" ;;
```
Since v0.33.0 isn't released yet, the default base is the ROCm 10 nightly (the patch was validated against `0.33.0rc1.dev229+g3966924d5`); `--base-image` can override it to pin a specific nightly digest or the official `v0.33.0` tag once published. Also updated the usage/error version lists and added a short note describing the v33 target.

Usage: `./build_docker_vllm.sh v33 /path/to/TraceLens -t tracelens-vllm:v33`
