[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/991) · state: open · merged: False

## Original PR description

## Summary
- Add a Visualizer that parses Hugging Face modeling code into block trees and computation graphs, then exports a Model Explorer view (CLI extra `Visualizer`, `visualize_model_in_explorer`).
- Infer symbolic tensor shapes (`B`, `S`, `H`, …) by default, keep nested diagrams in their tile slots, and label collapsed groups with boundary shapes so Model Explorer no longer shows `?` on those edges.
- Ship self-contained HTML exports, a fact sheet, kernel/MoE wiring, and Visualizer unit tests with ~95% patch coverage on the new code.

## Zero-width tensors in the exported graphs are real

Five nodes in GLM-5.3-Flash and twenty-one in DeepSeek-V4-Flash carry a `0`
axis. Both are the model, not the export, so they are worth recording rather
than "fixing".

**GLM-5.3-Flash — `k_rot` is `[B, S, 0]`.** Its config declares:

```
qk_rope_head_dim: 0     qk_nope_head_dim: 256     qk_head_dim: 256     head_dim: 0
```

`qk_head_dim == qk_nope_head_dim + qk_rope_head_dim` is self-consistent, so this
variant has **no RoPE component** on the keys — the whole 256-wide head is the
NoPE part. The split that produces it therefore yields an empty second piece:

```python
kv_pass, k_rot = torch.split(compressed_kv, [self.kv_lora_rank, self.qk_rope_head_dim], dim=-1)
```

The `view`/`expand` downstream of it inherit the zero. (`config.head_dim` is 0
for the same reason — the config class sets `self.head_dim = self.qk_rope_head_dim`.)

**DeepSeek-V4-Flash — `[batch, 0, 512]` and `[batch, 0, 128]`.** Written
literally in the model, allocating an empty compressed state when there is
nothing to compress:

```python
compressed = chunk_kv.new_zeros((batch, 0, self.head_dim))
```

### What was *not* legitimate

GLM had six more zero-width tensors that were export defects, now fixed:

- its sparse indexer splits with `[self.head_dim, self.head_dim, 1]` where
  `self.head_dim = config.index_head_dim` (**128**), but the sizes resolved
  against the config's *global* `head_dim` (0), so `keys` and `gate_scores`
  both came out `[B, S, 0]`;
- fixing that uncovered `pool_indices[batch_idx, selected]` — a table of ids
  indexed by ids, so every operand is `int64` and the rule separating base
  from indices by dtype found no base and returned the index's own shape. The
  base is whichever operand the call passes first. The pooled selection now
  reads `[B, S, K, P]`, as the comment beside it in the model says.

GLM went 11 zero-width tensors → 5, all five of them real.
