# Revert "Updates for TraceLens non-LLM path in Hyperloom"

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1162) · state: closed · merged: True

## Original PR description

# Build `analysis.json` compute tasks from a perf report, without the agent

## Summary

Hyperloom's non-LLM route reads a TraceLens perf report and writes `analysis.json` directly, with no `analysis.md` and no agent. It has to produce compute tasks in the same format and with the same rules as the agent route: grouping, priority, impact, how kernel names, args and efficiency are rendered. Those rules live in TraceLens. This PR exposes them so the consumer calls TraceLens instead of copying them.

Three public names:

- `compute_tasks(op_metrics) -> list[ComputeTask]` in `post_processing/analysis_json.py`, re-exported from `post_processing`. It turns `build_operation_metrics` rows into one single-member finding per row and runs them through the existing `TaskGrouper`. Grouping by op and phase, sorting, capping and impact are the same code the md-driven renderer uses.
- `TASK_SOURCE_COLUMNS`, the raw perf-report columns (`Input Dims`, `Input type`, `call_stack_full`) a caller passes to `build_operation_metrics` as `extra_fields` so `compute_tasks` can fill task members.
- `perf_report_metadata(csv_dir, platform) -> dict` in `utils/orchestrator_prepare.py`: the platform peaks plus the GPU utilization of a perf report, which is the metadata `build_operation_metrics` reads. `orchestrator_prepare.main()` now uses it for the values it already computed inline. Import it from the submodule; re-exporting it from `utils` closes an import cycle.

To build members from structured values instead of display strings, three formatters are split into a structured part and the existing renderer on top:

- `_kernel_name_list` under `_extract_kernel_names`
- `_arg_pairs` under `format_args`
- `_efficiency_parts` under `FusionPricer._efficiency_cells`

The renderers return the same strings as before.

## Observable effect

None on the agent route. `orchestrator_prepare`, the category and fusion outputs, the deterministic fallback and `render_analysis_json` produce the same output. The new names are additive.

## Validation

- Targeted tests: `tests/test_analysis_agent_utils.py` and `tests/test_analysis_agent_post_processing.py`, 310 passed. The wider agent suites (category utils, deterministic, evals) also pass. `black` is clean.
- New test: `test_compute_tasks_group_rows_by_op` pins the `compute_tasks` contract on synthetic rows: grouping, priority, impact, and the member fields for a full row and an empty one.
- Output identity against the base commit:
  - `_extract_kernel_names` and `format_args` on 167 perf-report CSVs (about 1M rows): no mismatches.
  - `_efficiency_cells` on a synthetic edge-case grid and on about 65K real cells across MI300X, MI325X and Radeon_8060S: identical.
  - `orchestrator_prepare` plus the category and fusion scripts on 6 cases (standalone, comparative, multi-job): identical output trees apart from the output-dir path.
  - `render_analysis_json` on 43 `analysis.md` files: byte-identical.
