# Run pull-request tests related to the changed files

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1101) · state: closed · merged: True

## Original PR description

## Summary
Addresses #1100.

- Pull-request CI runs only the tests related to the files the PR changes. A push to main still runs the full suite and the 95% coverage gate.
- A test is included when it imports a changed module (directly or through another module) or when its source names a changed data path.
- The full suite still runs for changes that can break collection of every test, including `tests/conftest.py`, package metadata, and modules imported while loading `TraceLens`.

## Test plan
- [ ] On a PR that changes a leaf module, confirm unit CI runs only the related tests and skips the coverage gate.
- [ ] On a PR that changes `tests/conftest.py` or a module imported by `TraceLens/__init__.py`, confirm the full suite and coverage gate still run.
- [ ] Confirm a push to main still runs the full suite and the 95% coverage gate.

File: `scripts/select_related_tests.py` · line 147

Currently, dependent tests are identified via import statements and paths with "/". However tests such as `test_collective_analysis` invoke TraceLens modules directly as console subprocesses: https://github.com/AMD-AGI/TraceLens/blob/main/tests/test_collective_analysis.py#L18 without "/" separated paths or imports.
Running `python3 scripts/select_related_tests.py --changed-file "TraceLens/Reporting/generate_multi_rank_collective_report_pytorch.py"` thus does not expose `test_collective_analysis`.

Similar limitation with https://github.com/AMD-AGI/TraceLens/blob/main/tests/test_event_replay.py#L300.

Simple solution may be to just change how these modules are invoked in the tests to keep invocations consistent.
