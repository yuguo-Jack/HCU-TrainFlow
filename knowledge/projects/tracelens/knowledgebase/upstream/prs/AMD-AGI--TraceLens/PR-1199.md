# fix(trace-utils): recognise SGLang speculative-decoding step annotations

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1199) · state: open · merged: False

## Original PR description

## Problem

With speculative decoding, SGLang annotates each decode round as two iteration spans: the draft-model step and the target verify step.

```
step[DRAFT bs=2 g_sq=16 g_sqsq=128 g_sqsk=22944 g_sk=2868 forward_id=14960]
step[VERIFY bs=2 g_sq=16 g_sqsq=128 g_sqsk=670032 g_sk=83754 forward_id=15173]
```

These labels come from builds whose `build_step_span_name` names the target-verify step `VERIFY` and every draft-model step `DRAFT`. Both steps carry `g_` aggregates.

`SGLANG_DETAILED_PATTERN` only matches `EXTEND`, `DECODE` and `MIXED`, so on these traces only the prefill steps become iteration roots. I tested on a real draft-model benchmark trace (TP rank 0, 9.2M events, concurrency 8). The splitter found 11 `EXTEND` roots, and only 36% of the GPU work fell inside their spans. Root detection graded the split `DEGRADED`, and `split_trace` printed *Refusing to split*. As a result, the trace yields no steady-state window.

## Fix

- Match `DRAFT` and `VERIFY` in `SGLANG_DETAILED_PATTERN`. They are listed in a new `SGLANG_SPECULATIVE_MODES` constant.
- Parse both as generation steps, the same way as `DECODE`. Each one serves requests that are already past their prompt.

On the same trace, `split_trace --find-steady-state --llm-inference --CONC 8` now finds 501 roots and grades the split `SPLITTABLE`. The roots cover 97.4% of the GPU work, and 95.1% of that falls inside their spans. It writes a 32-step `decode_only` steady-state window at concurrency 8, plus the `mixed` and `prefilldecode` windows.

## Scope

- `TARGET_VERIFY` is deliberately not matched. The older roofline patches emit `step[TARGET_VERIFY ... c_...]`, and those traces already split today through the unknown-family path: `scheduler.run_batch` roots, 99.5% of the work inside spans, decode-only. `test_trace_split[sglang_mtp_speculative]` pins that path. I first tried matching `TARGET_VERIFY` as a known root, and that test caught a regression: it switched to roots with 75% of the work inside spans and classified the run as all-prefill.
- The native tier (labels without aggregates) is unchanged.
- This overlaps with #1068. That PR adds the same modes plus `TARGET_VERIFY`, capture roles and MLA perf-model mappings, but in the detailed tier it parses `DRAFT`/`VERIFY` as context requests. For the `g_` format above, that labels every decode round as prefill, so `--find-steady-state` would still find no `decode_only` window. This PR is the narrow change splitting needs. If #1068 lands first, I'll rebase onto it.

  - `test_speculative_decode_steps_are_decode_iterations`, which checks that `EXTEND`, `DRAFT` and `VERIFY` are all found as roots and that their phases are prefill-only, decode-only and decode-only.
  - With the parametrized tests that consume the case table, 9 tests fail on `main` and pass here.
