## Summary

Adds perf models for the GEMM operators listed in #1174 (DeepSeek-V4-Pro) that had none: the MX128 GEMM, the batched MX128 GEMM and the MXFP8 GEMM.

## Model Operators

- **MX128 GEMM** (`gemm_a8w8_mx128_*`): reads tile size and split-K from the kernel name. FLOPs use the padded tile grid. Scales are applied inside the matrix instruction, so they add no FLOPs. Bytes include the fp32 split-K partials: written and read back for a separate reduce, or exchanged between peer splits for fused split-K (`_fsk`).
- **Batched MX128 GEMM** (`aiter::batched_gemm_a8w8_mxscale_bpreshuffle`): x `[M, G, K]`, w `[G, N, K]`, e8m0 scales, BF16 output `[M, G, N]`. FLOPs are G × 2 × M × N × K, padded to the launched tile. Bytes cover all inputs plus the output.
- **MXFP8 GEMM** (`aiter::_mxfp8_mxfp8_gemm_asm`, kernels `f8gemm_bf16_mxfp8fp8_*`): tile size comes from the kernel name, and FLOPs pad M and N to it. Bytes include A, B, the 1x32 e8m0 scales and the BF16 output, or the `[splitk, M, N]` partials. The split-K reduce runs as a separate kernel and is not counted here.

When the kernel name is missing, M is padded to 16 rows.

## Validation

- Formulas checked against the aiter source and the op shapes recorded in the traces. The MXFP8 kernel is a prebuilt assembly binary, so its scale handling and K tiling are assumptions.
- Not validated against hardware counters or measured kernel times.
