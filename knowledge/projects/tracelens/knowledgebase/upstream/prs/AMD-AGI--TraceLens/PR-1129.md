# fix(perf-model): cap TileLang SparseMLA KV to indices topk

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1129) · state: closed · merged: True

## Original PR description

## Summary

TileLang SparseMLA (`sglang::tilelang_sparse_fwd`) was already mapped in the perf model, but it was still treated as dense full-context MLA, so GLM-5.3 decode with a huge generation KV length produced absurd roofline numbers (~87 TB/s and ~1815 MiB moved). This PR reads the sparse topk from the indices tensor (`Input Dims[2][-1]`), sets it as `sliding_window`, and lets existing `_cap_gen_kv` cap generation KV to that topk so bytes and bandwidth stay in a realistic range.
