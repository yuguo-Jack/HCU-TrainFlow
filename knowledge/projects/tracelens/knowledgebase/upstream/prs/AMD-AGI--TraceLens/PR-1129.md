# fix(perf-model): cap TileLang SparseMLA KV to indices topk

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1129) · state: open · merged: False

## Original PR description

## Summary

TileLang SparseMLA was mapped but treated as dense full-context MLA (`g_sk≈1.75e6` → ~1815 MiB / ~87 TB/s). Cap generation KV to indexer topk from `Input Dims[2][-1]` via existing `sliding_window` / `_cap_gen_kv`, matching SGLang `tilelang_sparse_fwd` (`topk = indices.shape[-1]`):

https://github.com/sgl-project/sglang/blob/b498f462/python/sglang/kernels/ops/attention/dsa/tilelang_kernel.py#L1310-L1322

## Test plan

- [x] Unit test: glm53 dims, capped `g_sk`, bytes ≪ 1815 MiB, BW ≪ 7.4 TB/s
- [x] Fail-closed when indices dims missing
- [ ] Smoke: glm53 decode report with `--capture_folder` → `TB/s_mean` order ~1 TB/s, `has_perf_model=True`

## Follow-up (out of scope)
