# feat(roofline): CONV + MoE comm/GroupedGemm coverage (#1180)

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1181) · state: closed · merged: True

## Original PR description

Addresses all three op-coverage gaps in #1180 for the static roofline projection (`TraceLens.Visualizer.model_explorer_export.roofline_projection`). #1184, merged into this branch, is the graph-path counterpart: a convolutional encoder now renders as real nodes instead of a single uniform decoder stack.

## 1. CONV — the main gap

Convolutions were reported **unmodeled**: a graph node carries only in/out shapes, which can't recover the weight's kernel size or group count.

- **`roofline_projection`** recognizes `Conv{1,2,3}d` / `ConvTranspose{1,2,3}d`, parses the weight geometry from the node's `details` attr (`conv_weight=[C_out, C_in/groups, *kernel]; conv_bias=0|1; conv_transposed=0|1`), and costs it with `PerfModel.CONV`. Strides/padding/dilation only determine the (already-resolved) output shape, so the static formulas need just the three shapes + two flags. A conv with no threaded geometry stays unmodeled.
- **`meta_trace.conv_geometry_detail(module)`** produces that detail string from a live `_ConvNd` on the meta device (read for free — no forward pass).
- **`meta_trace.trace_meta_conv_ops`** runs a meta-device forward on the model's own main input (`pixel_values` for a vision model) and captures every live conv's concrete `[B,C,H,W]` plus weight geometry. **`roofline_projection.conv_ops_from_meta`** costs each captured conv through `PerfModel.CONV`. The CLI lets these supersede the graph's conv rows, so a repeated stage is not double-counted.

On `facebook/convnext-base-224-22k` the meta pass models all 40 convs (stem + 36 depthwise + 3 downsamplers), 99.9% of output elements covered.

## 2. MoE dispatch/combine communication (`MoEComm`)

When expert-parallel (`--ep > 1`), the all-to-all that moves token hidden states between EP ranks was entirely absent. `_moe_cost` now adds it as FLOPs-free data movement (`2 * active_tokens * hidden * bpe`, dispatch + combine) — the MoE op's own intrinsic comms, distinct from the `@comm:` TP/PP collectives the projection deliberately leaves to TreePerf.

## 3. GroupedGemm for the expert GEMMs

The expert GEMMs were costed with a **single shared weight matrix**, understating decode weight traffic by ~`num_experts/experts_per_tok`. They now use `GroupedGemm` over **G = min(num_experts, active_tokens)** distinct expert weight matrices — the weights actually streamed from HBM for this token count. FLOPs are unchanged (only the selected token-expert pairs compute); only the weight-byte term grows, and **G falls back to 1** (the prior cost) when `num_experts` is unknown.

On `Inkling-MXFP4` decode this correctly flips the MoE from the old **compute-bound artifact** to **memory-bound** (expert-weight streaming dominates), and `--ep 8` adds exactly the dispatch/combine volume on top.

`num_experts` and `ep` are introspected into the per-run context from `spec.num_experts` and `spec.parallel_layout.degree.ep`.

## 4. Non-uniform graph expansion (#1184)

The static graph modeled every checkpoint as one uniform decoder stack (`num_hidden_layers` + one `decoder_class`; `_select_primary_group` picks one `nn.ModuleList`). ConvNeXt's 4 non-uniform stages (`depths=[3,3,27,3]`) never became nodes, and ResNet's stage bodies are `nn.Sequential`, so a ModuleList-only walk missed them. Repeat structure now comes from the live meta tree. The AST is unchanged, and a uniform LLM stays on the single-stack path: `_is_non_uniform` fires only on differing positive per-position counts, so a standard MoE and a dense-replace MoE stay uniform.

- **Stage banners** — each stage is a flat `N×` container (`stage 2 · 27× ConvNextLayer`) whose element body goes through the existing `_append_section`.
- **Leading convs** — the stem stays the patch-embedding conv at the front of the encoder. A mixed-class list (ConvNeXt's downsample is LayerNorm then Conv2d) is drawn element by element ahead of that stage's repeated body, not as `N×` the first class. `ast_build._attach_conv_meta_shapes` stamps each conv's concrete per-stage `[B,C,H,W]`, matched by `meta_path`. Modules named `convolution` match the same way, so a ResNet stem and its bottleneck convs carry weight geometry too.
- **Stage Sequentials** — `repeated_module_groups` records a homogeneous `nn.Sequential` whose parent is a `ModuleList` element (ResNet's `stage.layers`). A Sequential nested inside the block is expanded from the live descriptor into its children, so a bottleneck's 1×1 / 3×3 / 1×1 stack is three conv nodes rather than one opaque tile.
- **Stage depth in the cost** — `s2_27x_ConvNextLayer` counts as 27 for the roofline and for collectives. The count is the node's `repeat_count` (a projection shortcut, present only on the first block, is stamped `1`), and the namespace reader accepts the `sN_` prefix. `project_roofline(..., checkpoint=)` builds that nested graph first. The CLI still replaces graph conv rows with the meta conv pass, so a repeated conv is not double-counted.
- **Tiles beside the conv** — the meta forward is fed `pixel_values`, and every module under the stage (norm, pointwise linear, activation, drop path, residual) takes that module's concrete spatial shape. A permute applies the dims recorded on the node. A layer-scale phi keeps an arm's shape instead of the rank-1 scale.
- **One-off stage modules** — a module on the stage that is not part of the repeated body (Swin patch merging) is drawn once, after the blocks.
- **Fact sheet** — a non-uniform model lists the stage tree, pipeline first (`stage 2: ConvNextLayerNorm → Conv2d, 27× ConvNextLayer`).

`facebook/convnext-base-224-22k`: stages `3×` / `3×` / `27×` / `3×` `ConvNextLayer`; depthwise convs `[B,128,56,56]` / `[B,256,28,28]` / `[B,512,14,14]` / `[B,1024,7,7]`; stem `[B,3,224,224]→[B,128,56,56]`; downsample convs lead stages 1–3 at `[B,256,28,28]` / `[B,512,14,14]` / `[B,1024,7,7]`. The pointwise linears, the residual, and the stage boundaries use those same spatial shapes.

`microsoft/resnet-50` (`depths=[3,4,6,3]`): stages `3×` / `4×` / `6×` / `3×` `ResNetBottleNeckLayer`. The stem conv is `[B, 64, 112, 112]`. Each bottleneck's three convs are drawn; the projection shortcut counts once per stage and the body convs once per block.

`microsoft/swin-tiny-patch4-window7-224`: each stage's `SwinLayer` blocks, then that stage's `SwinPatchMerging` once.

## Tests

- CONV: `_parse_conv_details`, `_conv_cost` (vs `PerfModel.CONV`), dispatch routing + unmodeled-without-geometry; `conv_geometry_detail` across plain/grouped/transposed/non-conv. Meta pass: `_meta_main_input`, `trace_meta_conv_ops`, `conv_ops_from_meta`.
- MoE: GroupedGemm scales weight bytes by experts-touched while leaving FLOPs fixed; EP>1 adds the dispatch/combine volume and EP=1 does not.
- Graph: `tests/ModelUtils/test_nested_module_groups.py` and `tests/ModelUtils/test_meta_trace.py` (reconstruction, the uniform-LLM predicate, ResNet Sequentials). `tests/Visualizer/test_nested_stage_graph.py`, `test_fact_sheet.py`, `test_convnext_graph.py`, `test_resnet_graph.py`, and `test_swin_graph.py` (per-stage banners, fact-sheet stage lines, concrete spatial shapes, stage-depth repeat counts, the shortcut counted once, patch merging between Swin stages).

## Scope

A uniform LLM is unchanged: `_is_non_uniform` still returns before any of this, and `project_roofline` only walks the meta tree when a checkpoint is passed. The detailed ConvNeXt export builds on the same path.
