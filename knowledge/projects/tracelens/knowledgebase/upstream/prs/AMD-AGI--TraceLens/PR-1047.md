# fix: from_file with capture_trace_filepath no longer crashes

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1047) · state: open · merged: False

## Original PR description

### Summary

There are two ways to build a tree with graph-capture data:

1. Direct merge (what the CLI and tests use): Call merge_capture_trace_into_graph() to get a fully built tree, then pass it to TreePerfAnalyzer() with rebuild_tree=False. This works because the tree is already constructed and the constructor skips the build step.
2. `TreePerfAnalyzer.from_file()` with `capture_trace_filepath` (the SDK entry point): This path always crashed with KeyError: t_end.

The bug arose in this second method. `from_file()` correctly calls `merge_capture_trace_into_graph()` and gets back a fully built tree, but then passes it to `__init__` without setting rebuild_tree=False. The constructor defaults to `rebuild_tree=True` and re-runs `build_tree()`, which iterates over all events and expects a `t_end` field on each one. The merged tree contains thousands of events without `t_end` (async-CPU-to-GPU launch links). The redundant rebuild crashes on these events.

Existing tests used the first method of building a tree, so CI never caught this

### Implementation

**`TraceLens/TreePerf/tree_perf.py`**

When `TreePerfAnalyzer.from_file()` with `capture_trace_filepath` is called, skip the redundant tree rebuild by passing `rebuild_tree=False` to the constructor automatically.

### Tests

**`tests/test_inference_perf_report.py`**

Added a test that runs `TreePerfAnalyzer.from_file()` with `capture_trace_filepath` on the xDiT Flux.1-dev trace. Fails on old code and now passes.

Closes #1013
