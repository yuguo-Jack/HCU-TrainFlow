# Release Notes (11/2)

## Summary

This release merges `staging_agent` into `main` for the TraceLens Agent. It has three
themes. The **semantic analysis** path gets validators on every LLM-authored JSON file and
moves onto the canonical trace splitter. The **multi_trace** scope moves onto a new
`combine_by_node` aggregation with one report column and one Top Operations table per node.
TraceLens now exposes the **non-LLM path** helpers Hyperloom uses to build `analysis.json`
from a perf report without the agent. Net: **59 files changed, +3696 / −976**, about half of
it tests.

---

## Key Features

### 1. Semantic Analysis Follow-up

(PR #1148)

- New validators in `utils/validation_utils.py` for the semantic sub-agents' JSON:
  `validate_stem_rules`, `validate_kernel_unification_map` and
  `validate_kernel_coherence_decisions`. The agent specs run them as retry gates, so a
  malformed file is caught at the step that wrote it.
- The unification agent emits decisions by id, and `expand_unification_map` in
  `kernel_unification.py` expands them into the kernel map, so the agent no longer
  retypes long kernel names.
- Kernel coherence accepts optional **regex remaps** (`fallback_remap_regex_a` / `_b`),
  which group many near-identical kernel names with one rule. A bad pattern fails with
  the pattern named.
- `trace_split_adapter.py` drops its own splitting logic and calls a new in-process
  entry point in `TraceUtils/split_trace` (`run()` / `split_and_enumerate()`). The
  canonical splitter's CLI behavior is unchanged.
- `pattern_finder.py` leaves the coverage `omit` list and gets its own test file. The
  eval scripts read source trace paths from the emitted CSVs instead of constants.

### 2. Multi-Trace Analysis by Node

(PR #1183)

- New `combine_by_node` aggregation in `Reporting/aggregate_perf_reports.py`. It stacks
  one block of CSV rows per node instead of summing them, and `gpu_timeline` ends with an
  `all` block. It is the only supported policy; `combine_only_same_phase` is removed and
  the other names are reserved.
- Each job in the run config needs a `node` under `combine_by_node`. `node` is the one
  identity from the YAML through to `analysis.json`.
- The report uses two denominators. **T**, one node's GPU time, drives every number a
  reader sees. **T_all**, the sum over nodes, drives ranking, `impact_score`, `pct_e2e`
  and every gate. On a single trace they are equal, so the single-trace report is
  unchanged.
- The Executive Summary gains a column per node, Top Operations is one table per node with
  global ranks, each compute card names its `**Node**`, and the plot has one bar per node.
  `validate_report` checks the node columns against the manifest, and R4, R6 and INV7 work
  per node.
- `analysis.json` tasks carry `node` (replacing `phase`, `null` outside multi_trace), and
  `executive_summary.node_metrics` holds the node columns.
- Two pre-existing bugs fixed for every scope. The deterministic fallback wrote one P-item
  per CSV row, so ops that resolved to several rows counted their impact more than once;
  it now writes one per op. The `analysis.json` Top Ops parser read cells by position,
  dropping rows without a trailing comment and shifting the comparative table; it now maps
  cells by header.

### 3. Non-LLM Path Helpers for Hyperloom

(PR #1168, which re-lands #1161 and #1163)

- Hyperloom's non-LLM route writes `analysis.json` from a perf report with no agent. The
  rules it needs stay in TraceLens as public functions:
  - `compute_tasks(op_metrics)` in `post_processing/analysis_json.py` runs perf-report
    rows through the existing `TaskGrouper`, with `TASK_SOURCE_COLUMNS` naming the raw
    columns it needs.
  - `perf_report_metadata(csv_dir, platform)` in `utils/orchestrator_prepare.py`.
  - `ops_summary_by_enhanced_category(csv_dir)`, renamed from a private helper.
- Three formatters split into a structured part plus the existing renderer, which
  returns the same strings.
- No change on the agent route; output identity was checked on real perf reports.

### 4. Report Validation: Data Table on Every Compute Finding

(PR #1169)

- `analysis.json` names a compute finding's kernels from its `**Data:**` table. A finding
  written as prose rendered with no kernels.
- `validate_report` rule R5 now flags each compute block without a `**Data:**` table, so
  the orchestrator's report-validation loop regenerates it.

### 5. Eval References and Upstream Syncs

- The four `analysis_tests/*.tar.gz` eval reference archives are regenerated for the
  changes above (`919f4399`).
- `main` was merged into `staging_agent` on 10/28, 10/30 and 11/2. The 11/2 merge brings in
  everything up to `eb876047` (#1181), so `staging_agent` contains all of `main` and the
  merge is conflict-free.
