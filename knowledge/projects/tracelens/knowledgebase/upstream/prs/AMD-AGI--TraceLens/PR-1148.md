# Semantic analysis follow-up

[Upstream PR](https://github.com/AMD-AGI/TraceLens/pull/1148) · state: closed · merged: True

## Original PR description

# Context

This is a follow-up PR to #951 , addressing the deferred issues, plus adding some minor extra functionality.

# Issues addressed

#1089 Validation & JSON generation utils.
The goal was to add validators to LLM-generated intermediate JSON files, as well as reduce the amount of directly generated JSON.

Added validators in utils/validation_utils.py and wired them as retry gates in the agent docs, so malformed LLM-authored JSON is caught early. For json generation, the main motivation was to reduce context usage & improve reliability. I changed the way the agent generates the kernel map, and now it doesn't need to "retype" lengthy kernel names. That said, most context usage there is on the input side, and so this move, while helpful, is unlikely to be very impactful in terms of context usage savings.

#1082 Unify trace splitting: remove bespoke adapter, extend canonical splitter. Dropped the bespoke semantic trace-split adapter logic and extended the canonical splitter (TraceUtils/split_trace) with an in-process entry point (run() / split_and_enumerate(), exported from __init__.py) that trace_split_adapter.py now calls. Semantic path still has a special wrapper, but it's now much thinner. I tried to keep changes to the shared splitter to the minimum to avoid affecting other workflows in any way.

#1073 Replace pattern_finder.py with a different implementation. Unfortunately, the implementation the pattern finder is based on is not public and I wasn't able to reach the person who was working on it to find out whether there is a plan to make it public soon. For now, I kept the current implementation. Previously it was not tested since there was a plan to replace it with a different implementation. I removed it from testing exceptions and added tests.

#1090 Read eval source paths from the CSVs instead of hardcoding Eval scripts (quality_scripted_evals.py, workflow_scripted_evals.py, semantic_partition_scripted_evals.py, run_post_processing.py) now read source trace paths from the emitted CSVs rather than hardcoded constants.

#1091 Deduplicated the CSV writing snippet that was repeated in many parts of the code, abstracting into a small function evals/eval_utils/csv_io.py (write_csv), and routed the eval scripts + aggregators through it.

# Extra functionality

Added a small extra bit of functionality: the agent now can emit not only direct kernel mappings, but also regexp-based kernel mappings. This can dramatically reduce context usage in cases where there are many slightly-differently named kernels that should be semantically grouped together.

# Validation

Apart from local tests for specific functions, etc. I ran the full agentic test suite to check for regression once, and observed no drop in performance. Also, ran the semantic-specific agentic tests multiple times in slightly different settings, with all tests passing on the current version. 

## Caveats: 

- There were a few minor changes I added after the full test suite run, those were only validated via semantic agentic test reruns, not the full suite. But they are extremely unlikely to affect anything outside semantic analysis workflow.
- The trace splitter as applied in the semantic case is not thoroughly tested. I applied it to a few traces I had to check that the format conforms to what we expect. But the gold standard traces in the semantic-specific agentic tests are too small to fully validate semantic analysis in this setting. I am planning to run a deeper validation of this aspect along with cross-platform extension follow-ups.
