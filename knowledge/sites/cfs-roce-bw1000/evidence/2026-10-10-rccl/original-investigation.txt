# 用户现场 RCCL 配方复测与先前测试对比

日期：2026-10-10。仅为本次私有现场记录，不发布到公共 TrainFlow 或 HCU-Knowledge。

## 结论

先前测试遗漏了 `/cfs/env.sh`，不能称为此集群完整现场配方的性能。此次按 **DTK 激活 → 现场脚本 → 用户测试二进制** 的顺序复现，在不改变配方的三次独立启动中，1 GiB out-of-place `busbw` 为 **41.44 / 41.68 / 42.25 GB/s，中位 41.68**，比先前 30.99 高约 **34.5%**。扫描最高值为 **42.94 GB/s（第二轮 2 GiB）**。

这证明完整现场配方与此次执行方式的组合性能更好，并不证明某一个开关单独贡献了这些收益。相对于条件不完全匹配的历史 44.83，中位仍低约 7.0%；尚未证明根因，也没有将此项或整套环境验收强行改成通过。

## 1. 原命令与本次执行调整

用户提供的原命令：

```bash
mpirun -np 16 \
  --allow-run-as-root \
  --hostfile hostfile_slots \
  -bind-to none \
  -map-by slot \
  --mca plm_rsh_args "-p 12333" \
  --mca coll_hcoll_enable 0 \
  --mca pml ob1 \
  --mca btl_tcp_if_include eth0 \
  --mca btl ^openib \
  bash -c 'source /opt/dtk/env.sh && source /cfs/env.sh && /cfs/xingjl/multi/rccl-test/build/alltoall_perf -b 1M -e 4G -f 2 -g 1'
```

此次保留 16 ranks、每节点 8 ranks、slot 映射、不绑定 CPU、禁用 HCOLL、PML ob1、BTL `^openib`、TCP eth0、测试参数与加载顺序。下列差异显式保留：

- 原 `/cfs/xingjl/multi/hostfile_slots` 为 67、93，每台 slots=8。两台初检虽利用率为 0，但每卡约 0.8–0.9 GB 显存占用，不能视为空闲；本次使用反复检查空闲的 **110、76**，与此前自建测试节点一致。
- 使用本任务已有的 DTK 26.10 镜像及自己创建的容器。原路径未映射到任务容器，因此保留现场脚本和原二进制的**逐字节副本**到 `/cfs/yuguo/kimi-k3-pretrain`，每个 rank 执行源快照中的副本。不修改 `/cfs/env.sh` 或他人测试目录。
- MPI 5.0.3 使用任务专属、限时的 SSH 28476 与固定主机身份配置，代替原 12333，未接管其他容器的 SSH 服务。MPI 启动参数做了对应 PRRTE 配置；实际 CPU-only 16-rank 映射、每台 8 local ranks、Allreduce sum=120 已验证。完整 argv 保留在各轮 `native-group/node0/alltoall/mpi-started.json`。
- 增加任务超时、逐 rank 回执、身份与库映射、INFO 通信日志、前后网络计数和退出核销。INFO 日志用于机制验证，此处没有宣称正式的 profiler-off 性能验收。
- 每轮重新检查设备与进程占用，串行测量。私有资源租约不能证明外部用户不占用共享交换网络。

因此这是在授权空闲节点上对用户配方的有记录复现，**不是原节点、原 SSH 入口与完整历史环境的严格重放**。

## 2. 与先前测试的关键差异

| 项目 | 先前测试 | 本次用户配方 |
| --- | --- | --- |
| 激活链 | 仅 DTK，自建显式参数 | 每个 rank 先 DTK，再现场 env |
| QP | 默认 1；另做过单独 QP=4 对照 | `NCCL_IB_QPS_PER_CONNECTION=4` |
| Traffic class | 未显式设置 | `NCCL_IB_TC=160` |
| RoCE 源端口 | 未显式固定 | `60000,60051,57663,57804` |
| GDR 路径等级 | 未显式设置该等级 | `NCCL_NET_GDR_LEVEL=2`，本版源码映射为 PXB |
| IB / 超时 | 自建 `NCCL_NET=IB` | `NCCL_IB_DISABLE=0`、`NCCL_IB_TIMEOUT=22` |
| HCA | 自建固定四个 mlx5_bond HCA | 不追加该限制，按现场配方及库探测 |
| 其他现场参数 | 未显式设置或采用库默认 | `RCCL_MODEL_MATCHING_DISABLE=1`、`HSA_FORCE_FINE_GRAIN_PCIE=1`、`NCCL_PXN_DISABLE=1`、`NCCL_ALGO=Ring` |
| 测试二进制 | `/opt/rccl-test/build/alltoall_perf` | 用户 `/cfs/xingjl/multi/rccl-test/build/alltoall_perf` 的原字节副本 |
| 数据范围 | 固定 1 GiB、每次 3 个 cycles | 1 MiB–4 GiB 倍增共 13 点，每次 1 cycle，共 3 次独立启动 |
| placement | 仅 out-of-place | 原命令输出 out/in 两列，仅 out 列进入正确性与性能汇总 |
| MPI 配方 | ppr:8:node、显式 self,tcp 等 | slot、`^openib` 等用户参数；任务 SSH 安全适配单列记录 |

“未设置”不等于功能关闭。例如 XDP 前后都已开启，模块值均为 14，RCCL 路径日志也保留；此次提升不能解释成“新开启了 XDP”。

现场脚本还会条件设置 `fix_topo.xml` / `fix_graph.xml`。当前镜像两个文件均不存在，**没有将它们标成已加载**。`/tmp/topo.xml` 的自动加载路径及各节点文件哈希另有证据。脚本中的 apt 修改函数仅直接执行或 source 时传入 `apt` 才会调用，本次正常 source 不触发。

## 3. 实测结果与口径

全部为十进制 GB/s 的 out-of-place **busbw**，不是 algbw，也不是每个物理网口的线速。每个点是 rccl-test 默认 5 次预热、20 次计时迭代所得；下表跨三次独立启动计算中位，不构造 p95。

| 消息大小 | 第一次 | 第二次 | 第三次 | 中位 |
| --- | ---: | ---: | ---: | ---: |
| 1 GiB | 41.44 | 41.68 | 42.25 | **41.68** |
| 2 GiB | 40.73 | 42.94 | 42.57 | **42.57** |
| 4 GiB | 41.66 | 42.06 | 42.32 | **42.06** |

对比先前 1 GiB：

- 初始自建配置三 cycles 中位 30.99 → 此次三独立启动中位 41.68：**+34.5%**。
- 之前最后一个恢复默认对照中位 31.63 → 41.68：约 **+31.8%**。
- 之前仅设置 QP=4 的单次启动、三 cycles 中位 37.33 → 41.68：约 **+11.7%**。

以上是不同配方及不同重复层级之间的观察性对比，未消除所有时间漂移、二进制构建和共享网络差异，不能用于单参数因果归因。

日志末尾约 33 的 `Avg bus bandwidth` 汇总了不同消息量和两种 placement，不是最大值。in-place alltoall 源码明确关闭该路径错误校验、输出 N/A，不能将此列当作独立正确性通过；本报告只用 out-of-place 列。

全 13 点见 [sweep.csv](sweep.csv)、[results.json](results.json)。

## 4. 生效与正确性证据

- 三次各 16 ranks，共 48 份回执；所有 rank 正常退出，全部 13 个 out 数据点错误数为 0，结尾 `Out of bounds values : 0 OK`。
- 逐 rank 校验现场参数与原始脚本哈希；实际 `/proc/<pid>/maps` 确认当前 DTK 的 RCCL、HIP、MPI、verbs 与 mlx5 库。用户 binary 的 RUNPATH 虽含旧 DTK 路径，本次加载的实际 RCCL 是 **3b793e3**，并非凭编译路径推定旧库。
- 48 ranks 全部有四个固定源端口的逐 QP 成功日志，共 10,368 条；不能仅以 env 或 exit0 证明成功，因为该版源码调用方丢弃了修改端口函数的错误返回。此次未发现 NCCL WARN。
- 三次每个 bond 的两个物理从口 TX 分流均接近 50/50，最大从口占比约 **50.0422%**；此前单独 QP=4 时最偏约 **58.53%**。这与固定源端口机制一致，但不是单开关贡献率证明，也不能证明交换机 QoS/PFC 配置。
- 两台任务容器每轮进行了终态检查，共 96 个 rank wrapper/child 进程身份核销。临时 sshd/wrapper 已按固定身份停止，新临时密钥删除，资源租约释放，清理后 16 卡均恢复约 2.2 MB 空闲基线、无负载 PID。

## 5. 当前需要用户决定的部分

问题已登记到任务看板与本会话：此配置显著改善后，是否**采用现场配方继续模型适配，历史对标暂留待复核**，或**先对齐历史镜像、原节点和完整测试口径，继续追剩余差距**。

推荐前者，因为当前通信正确性、机制生效和重复性均已有证据，剩余约 7% 对比条件未齐；但这属于工程优先级决定，不由 Agent 擅自把历史验收目标降低。等待答复时停止扩大参数搜索与当前 Task 的执行推进，继续只读复核和本次收尾。

## 6. 工作流改进

公共 TrainFlow 仅沉淀通用规则：先发现现场启动/激活链、保留加载顺序和每个 rank 的生效证据；用户给完整配方时优先复现，再拆变量；基本排查后仍有显著差距，明确给用户证据、推荐方案与备选项，并登记需要答复的问题。现场值与原始实验数据不进入公共仓库。
