# [train] check TRL version for PPO when parsing arguments

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10882) · state: open · merged: False

## Original PR description

# What does this PR do?

The PPO trainer only checked the TRL version inside `CustomPPOTrainer.__init__`, after the model, dataset and reward model were already loaded. The error message told you to set `DISABLE_VERSION_CHECK=1`, but the check called transformers' `require_version` directly, so that variable did nothing.

I moved the check to `_check_extra_dependencies` with `check_version("trl>=0.8.6,<=0.9.6", mandatory=True)` for `stage=ppo`, and dropped the old one from the trainer. Now a wrong TRL version fails at argument parsing and tells you the required range and the install command.

This only makes PPO fail earlier, it doesn't fix PPO. `pyproject.toml` pins `trl>=0.18.0,<=0.24.0`, so PPO fails on every default install. Before, it failed after loading the models, now it fails right away. Actually making PPO work would need a separate env with `trl==0.9.6` or a port to the new TRL API. I left the pin alone.

Related to #10757
