# [data] fix gemma4 tool_extractor reading colons inside string arguments as keys

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10885) · state: open · merged: False

## Original PR description

# What does this PR do?

`Gemma4ToolUtils.tool_extractor` converts the Gemma 4 call syntax to JSON in two regex passes: first `<|"|>...<|"|>` becomes a JSON string, then every bare identifier followed by `:` gets quoted. The second pass also runs inside the strings produced by the first one, so a string argument such as `Hi Tom, Re: the plan` becomes `"Hi Tom, "Re": the plan"`. `json.loads` then fails and the extractor returns the raw text as the arguments string.

This also means `function_formatter` output does not round-trip:

    <|tool_call>call:f{text:<|"|>Dear John, Re: the meeting<|"|>}<tool_call|>
    -> FunctionCall(name='f', arguments='text:<|"|>Dear John, Re: the meeting<|"|>')

The fix does both steps in one left-to-right `re.sub` with alternation. A whole `<|"|>...<|"|>` string is matched first, so its content is never treated as a key. Key quoting outside strings is unchanged.

Tests: `test_gemma4_tool_extractor_colon_in_string` and `test_gemma4_tool_round_trip` in `tests/data/test_formatter.py`. Both fail on main with `JSONDecodeError` and pass with this change. `tests/data/test_formatter.py`: 48 passed. `ruff check` and `ruff format --check` are clean.
