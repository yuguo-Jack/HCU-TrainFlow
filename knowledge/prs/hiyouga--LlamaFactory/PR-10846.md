# [Fix] Preserve EOS labels when pretraining with a shared PAD token

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10846) · state: closed · merged: False

## Original PR description

# What does this PR do?

Preserves real EOS labels during pretraining when the tokenizer uses the same token for PAD and EOS.

## Motivation

`Template.fix_special_tokens()` sets PAD to EOS when the tokenizer has no padding token. `PretrainDatasetProcessor` deliberately appends EOS to each document, but the PT workflow then uses `DataCollatorForLanguageModeling(mlm=False)`, which masks every label whose token ID equals `pad_token_id`. With a shared PAD/EOS ID, this silently removes all EOS targets, including document boundaries inside packed sequences.

For example, with EOS/PAD ID `1`:

```text
input_ids:      [3, 1, 4, 1]
attention_mask: [1, 1, 1, 1]
old labels:     [3, -100, 4, -100]
new labels:     [3, 1, 4, 1]
```

Training still runs, but the intended document-end tokens never contribute as targets to the causal loss. Token-ID masking works when padding has its own distinct token; the attention mask distinguishes actual padding even when PAD and EOS share an ID.

## Changes

- Add `PretrainDataCollatorWithPadding`, which pads the batch and masks labels only where `attention_mask == 0`.
- Use it in both the standard PT and HyperParallel PT workflows.
- Keep preprocessing and the tokenized-dataset format unchanged, including compatibility with existing cached PT datasets.
- Add offline tests that exercise the collator selected by the PT workflow, left/right padding, separate/shared PAD tokens, padding to a multiple, and both packed and unpacked preprocessing. Tests also check that source features and input tensors are not overwritten.

## Validation

- Baseline: **6 failed, 4 passed**. All failures involve real EOS targets being masked.
- Fixed: **10 new tests pass** on Transformers **5.8.0** and **4.55.0**. Including the existing processor-utility tests: **17 passed** on 5.8.0.
- RTX 5090, Qwen3-0.6B, BF16/SDPA, two LoRA PT steps on each version. An isolated tokenizer copy has PAD unset to exercise LlamaFactory's normal PAD=EOS fallback; model weights are unchanged. Instrumentation of three collated batches (including prefetch) observes **0/6 real EOS targets supervised before**, **6/6 after**, and **4/4 padding positions ignored on both**. Both runs finish with finite loss. This validates supervision and execution, not long-run generation quality.
- `make commit`, `make style`, `make quality`, `make license`, and `make build` pass.
- Full-suite attempt (`HF_HUB_OFFLINE=1 PYTEST_ADDOPTS=--maxfail=1 make test`) stops at the first existing feedback-processor test because its tokenizer is not cached. This host cannot reach Hugging Face; the full suite is not claimed to pass. HyperParallel distributed execution was not run; both PT entry points now select the same tested collator.
