# [v1] Support multimodal Ulysses CP and memory-efficient chunk loss for SFT

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10762) · state: closed · merged: True

## Original PR description

# What does this PR do?

- adds memory-efficient Chunk Loss, including composition with context parallelism.
- extends Ulysses context parallelism to multimodal models;

## Multimodal CP

This change keeps media inputs replicated while the outer model runs the encoder, multimodal fusion, and mRoPE preparation. It then shards the fused language sequence at the language-model boundary.

- pads full-length language inputs while preserving multimodal encoder tensor layouts.
- globally shifts labels and loss weights before selecting each CP rank's contiguous shard.
- shards fused `inputs_embeds`, attention masks, position IDs, and aligned DeepStack features at the language-model boundary.
- aggregates differentiable weighted loss numerators across CP ranks before applying the global normalization.

## Multimodal CP validation

The end-to-end validation uses Qwen3.5-0.8B full SFT with FSDP2, FlashAttention 2, FP32, `cutoff_len: 2048`, global batch size 4.

## Chunk Loss

Instead of materializing full `[batch_size, sequence_length, vocab_size]`
logits, Chunk Loss intercepts the model's linear output head and computes
cross-entropy in smaller sequence chunks.

- Adds `chunk_loss_size` for fixed-size sequence chunking.
- Adds memory-efficient chunked linear cross-entropy for SFT.
- Keeps the default eager loss path unchanged when Chunk Loss is disabled.
- Keeps DPO and RM unsupported when Chunk Loss is enabled.

## Chunk Loss benchmark

The benchmark uses Qwen3.5-35B-A3B with LoRA, FSDP2, BF16, 16 cards, a 4K sequence length, global batch size 16, and 100 optimizer steps. All runs use the same data and seed.

| Configuration | Peak Torch allocated (GiB/device) | Change vs. baseline | Throughput (input tokens/s) | Change vs. baseline |
| --- | ---: | ---: | ---: | ---: |
| Baseline (eager loss) | 22.19 | — | 14.79k | — |
| Chunk Loss 512 | 13.53 | -39.01% | 13.51k | -8.65% |
| Chunk Loss 2048 | 17.49 | -21.16% | 13.49k | -8.81% |

Peak Torch allocated is the maximum of `torch.npu.max_memory_allocated()` across all 16 ranks. Throughput is calculated from the mean step time after excluding the first warm-up step.

File: `src/llamafactory/v1/plugins/model_plugins/chunk_loss/linear_cross_entropy.py` · line None

`grad_weight` accumulates across chunks in the head's dtype, which is bf16 in practice. The unchunked path accumulates inside a single matmul at fp32, so with many chunks this is measurably less precise than the loss it replaces. Allocating the buffer as fp32 and casting once at the end would keep the two equivalent. Same in `linear_log_probs.py`.

- khazic · comment · 2026-08-29T08:08:26Z · [source](https://github.com/hiyouga/LlamaFactory/pull/10762#discussion_r3886003865)

File: `src/llamafactory/v1/core/base_trainer.py` · line 273

This moves the context-parallel loss dispatch out of the shared training loop and into `SFTTrainer.compute_loss`. It is correct today, since the only other two trainers both reject `cp_size > 1` in their constructors, but the invariant is now implicit: any future `compute_loss` that forgets the branch silently trains without the sequence-parallel loss instead of failing. Worth stating it in the `BaseTrainer.compute_loss` docstring so the contract travels with the abstract method.

On the feature itself, a 485-line change with its own `autograd.Function` and CP sharding is hard to review without numbers. Loss deltas against the non-chunked path on a small model, plus peak memory and throughput at a couple of `chunk_loss_size` values, would carry most of the argument.
