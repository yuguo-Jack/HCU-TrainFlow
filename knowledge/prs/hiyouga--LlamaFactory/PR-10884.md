# [data] pad position_ids before unpadding on the neat_packing FA2 path

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10884) · state: open · merged: False

## Original PR description

# What does this PR do?

Follow-up to #10737 and #10783, for the `neat_packing` + `flash_attention_2` path.

The SFT collator uses `pad_to_multiple_of=8`, so a packed row of `cutoff_len + 1` tokens (for example 2049) is padded to 2056 for `input_ids`, `attention_mask` and `labels`, while `position_ids` stays at 2049. #10737 fixed this by right-padding `position_ids`, but only in the non-FA2 branch. On the FA2 neat-packing branch, `_unpad_packed_features` trims `position_ids` only when `value.size(-1) == seq_len`. Because the lengths differ, `position_ids` is left untrimmed while `input_ids` and `labels` are trimmed. For text-only models (where `position_ids` come from `PackedSupervisedDatasetProcessor`) this gives a rotary length mismatch.

Minimal case with the tiny Llama 3 model, one packed row of 9 tokens:

    before: input_ids (1, 7), position_ids (1, 9)
            forward -> RuntimeError: The size of tensor a (7) must match the size of tensor b (9) at non-singleton dimension 2
    after:  input_ids (1, 7), position_ids (1, 7) = [[0, 1, 2, 0, 1, 2, 3]]

The change moves the existing `position_ids` right-pad before the FA2/non-FA2 branch, so the unpad step trims it together with the other tensors. The non-FA2 path behaves as before, and for mrope models `position_ids` already has the full length, so the pad does nothing.

Tests: the new `test_neat_packing_fa2_collator` in `tests/data/test_collator.py` fails on main (`torch.Size([1, 9]) != torch.Size([1, 7])`) and passes with this change. `tests/data/test_collator.py`, `tests/data/processor/test_processor_utils.py` and `tests/data/processor/test_supervised.py` give 16 passed on CPU, including the Qwen2-VL packing collator test. I could not run FA2 itself (no suitable GPU). The forward-pass check above used SDPA with `attention_mask=None`, which goes through the same rotary code.

Fixes # (no issue filed; related: #10736, #10782, #10659)

AI assistance: I used Claude Code to help find the bug and draft the patch and tests. I reviewed and ran everything myself.
