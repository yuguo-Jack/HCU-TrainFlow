# fix(inference): manage PRM scorer lifecycle in the v1 proxy

[Upstream PR](https://github.com/areal-project/AReaL/pull/1744) · state: open · merged: False

## Original PR description

## Description

#1735 added asynchronous construction, startup rollback, and scorer cleanup to the shared `PRMRunner`, and integrated that lifecycle with the v2 data proxy. The v1 proxy still uses synchronous construction and does not automatically close its scorers.

For scorers that own async clients, background writers, or buffered audit records, this can leave resources open after partial startup or let shutdown finish without flushing pending records.

This PR integrates v1 with the existing lifecycle contract and fixes cancellation drainage in the shared runner, so scoring tasks have actually exited before their resources are closed.

### Changes

1. **Use asynchronous construction and startup rollback in v1.**
   - Construct the runner with `await PRMRunner.create()`.
   - Publish the client and related configuration, and report readiness, only after setup succeeds.
   - Reuse successful engine initialization and an existing ready runner for identical initialization retries; reject retries with different arguments instead of replacing live resources.
2. **Share one shutdown path between the destroy RPC and ASGI lifespan.**
   - Stop admitting new PRM scoring, wait for admitted scoring to exit, close owned scorers, then destroy the engine.
   - Still attempt engine destruction after ordinary scorer cleanup failures.
   - Retain the engine after failed destruction so later cleanup can retry, without repeating scorer cleanup.
   - Return HTTP 503 when a PRM-enabled export needs a runner that is not ready or is shutting down, rather than silently exporting unscored data.
3. **Drain cancelled scoring tasks in the shared runner.**
   - A self-cancelled child of `asyncio.gather` previously allowed sibling evaluations to outlive `run()`.
   - Explicitly cancel and await remaining tasks before propagating cancellation. This fixes the shared path used by both v1 and v2 while preserving normal scoring concurrency and result order.

Regression tests and English/Chinese lifecycle documentation are included. Existing scorer interfaces, configuration schemas, and reward calculations are unchanged.
