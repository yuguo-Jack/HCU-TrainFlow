# feat(engine): add CPU-staged Megatron AdamW

[Upstream PR](https://github.com/areal-project/AReaL/pull/1613) · state: open · merged: False

## Original PR description

## Description

Keep authoritative FP32 AdamW master parameters and moments in pinned CPU memory and stream updates through bounded reusable CUDA buffers. The staged optimizer integrates with Megatron checkpointing and AWEX colocation while preserving ordinary optimizer residency behavior.

- Select precision-aware distributed AdamW automatically when CPU staging is enabled.
- Reuse bounded CUDA slots for H2D, optimizer computation, and D2H state updates.
- Keep managed optimizer slabs CPU-resident across AWEX phase transitions and checkpoint them synchronously.
- Rebuild staged CPU masters and moments after model-only HF weight reloads.
- Preserve optimizer-chain handling for dense/expert parameter groups and mixed managed/ordinary optimizers.

Muon support is split into a separate stacked PR based on this branch. Activation-storage tracking is split into independent draft #1779; ordinary Megatron training no longer installs its patches or mutates activation storage in this PR.

## Examples

`examples/cpu_staged_offload/` contains DAPO-Math configurations for Qwen3-30B-A3B-Base and Qwen3.5-35B-A3B-Base, sharing one training entry point. The Qwen3.5 configuration defaults to three training steps on eight GPUs with attention TP2/DP4, MoE EP8, and four TP2 rollout servers.

```bash
export AREAL_PROXY_ADMIN_API_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
# Set QWEN3_5_35B_A3B_BASE_MODEL_PATH and DAPO_MATH_17K_PATH to local directories.
python examples/cpu_staged_offload/dapo-math_rl_cpu_staged.py \
  --config examples/cpu_staged_offload/dapo-math_grpo_qwen3_5_cpu_staged.yaml \
  trial_name=staged
```

Repeat with `trial_name=baseline actor.megatron.cpu_staged_offload.enabled=false` for the baseline. Precision-aware mode stays enabled in both runs.

- yulangz · comment · 2026-10-12T08:50:10Z · [source](https://github.com/areal-project/AReaL/pull/1613#issuecomment-6120905187)

Updated the code and addressed the correctness feedback:

- **IPC export lifetime** (`1d0f81a3`): release packed export storage immediately after a successful AWEX reader ACK, before `write_finished`, instead of retaining it until final engine completion. Failed/timed-out acknowledgements retain the export; the final engine synchronization remains.
- **HF reload** (`4a2a6773`): rebuild CPU master weights from the newly loaded model and reset staged optimizer moments/step, preserving the scheduler and parameter identities. Regression coverage includes resident/released staging slots and partial-load failure.
- **Transfer ranks** (`37431a68`): subtract the SGLang server's `base_gpu_id` before applying the dense transfer-rank base, avoiding the double offset when all node GPUs are visible. Regressions cover four TP2 servers with full visibility and isolated device masks, plus multiple-node rank layouts.

Independent activation-storage tracking/reclamation has been removed from this PR and moved to **[PR #1779](https://github.com/areal-project/AReaL/pull/1779)**, based directly on main, for separate ownership/safety review. Muon support remains in the stacked **[PR #1743](https://github.com/areal-project/AReaL/pull/1743)**.

The redundant AWEX packing clone and post-insertion size-limit check are reported upstream in **[inclusionAI/Awex issue #128](https://github.com/inclusionAI/Awex/issues/128)**, with reproducible CPU/CUDA cases and proposed fixes. A 20-byte limit currently yields a 24-byte group; packing 256 MiB has a 512 MiB extra allocation peak with `cat().clone()`, versus 256 MiB with `cat()` alone. No tensor-value corruption was observed; these are memory/copy overhead and size-bound issues that can cause OOM. The local bounded packer remains a workaround pending an upstream fix.

Latest local validation: **109 related tests passed**, including ACK success/failure/timeout lifetime checks; **10 consecutive exchanges on two GPUs passed** with actual MetaServer/CUDA IPC/native AWEX reader/bounded NCCL and exact received weights, while checking exports were reclaimed before final engine completion; **full pre-commit passed**. The two-GPU exchange validation does not replace full SGLang training or multi-node convergence testing.
