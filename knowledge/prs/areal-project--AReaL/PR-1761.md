# fix(dataset): forward configured dataset_kwargs to local loaders

[Upstream PR](https://github.com/areal-project/AReaL/pull/1761) · state: open · merged: False

## Original PR description

## Description

`dataset_kwargs` on a dataset config is documented as "passed to the dataset loading function `get_custom_dataset`", and each routed source has its own `dataset_kwargs` for "this source's loader". `get_custom_dataset` only merged them into the `RDataset` built for the data service. When the dataset is loaded in process, which happens with the SPMD launchers (local/ray/slurm set `AREAL_SPMD_MODE=1`) or with `scheduling_spec=None`, only the call kwargs reached `_get_custom_dataset`, so the configured kwargs were silently dropped, including per-source kwargs of a routed mixture (`get_routed_dataset` merges them into the source config).

Repro (AREAL_SPMD_MODE=1, `_get_custom_dataset` patched to record its kwargs):

```python
cfg = TrainDatasetConfig(path="swe-data.jsonl", type="sft", dataset_kwargs={"num_proc": 4})
get_custom_dataset(split="train", dataset_config=cfg)
# before: num_proc missing from the loader kwargs; after: num_proc=4
```

This PR merges the configured kwargs once, before the remote/local branch, and passes them on both paths. Call kwargs still take precedence, as they already did for the remote path.
