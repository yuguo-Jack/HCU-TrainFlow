# feat(engine): add distributed Muon optimizer offload

[Upstream PR](https://github.com/areal-project/AReaL/pull/1743) · state: open · merged: False

## Original PR description

## Description

Add Megatron distributed Muon as an optimizer choice and support CPU-staged Muon state on top of the staged AdamW infrastructure in #1613.

- Map AReaL's `dist_muon` choice to Megatron-Core 0.19's native `muon` optimizer with layer-wise distribution.
- Build both native and staged optimizers through MCore 0.19's `get_megatron_optimizer`, including scalar-only and all-expert models; retain the empty-gather guard for MCore's all-expert edge case.
- Keep Muon master parameters and momentum in pinned CPU slabs while streaming bounded matrix units through reusable CUDA buffers.
- Reuse staged AdamW for Muon's scalar and non-matrix parameter groups.
- Preserve Muon optimizer state through synchronous distributed checkpoints, including DP ownership resharding while model-parallel topology remains fixed.
- Validate BF16, data-parallel, tensor-parallel, expert, and checkpoint configurations explicitly.
- Pin `emerging-optimizers==0.3.0` for Megatron-Core 0.19.

This is a stacked PR based on `feature/optimizer_offload`. After #1613 merges, its base should be changed to `main`.

The multi-node suite and full distributed checkpoint restore were not run. The local environment lacks the `flash_attn` exports needed to collect `tests/test_megatron_optimizer_config.py`; remote CI will cover that module.
