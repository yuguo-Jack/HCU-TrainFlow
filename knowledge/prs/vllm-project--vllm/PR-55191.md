# [Bugfix][KV Offload] Keep direct caches topology-specific

[Upstream PR](https://github.com/vllm-project/vllm/pull/55191) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->
## Overview

Keep direct filesystem KV offload caches topology-specific to prevent silent corruption when tensor-parallel size changes. Only certified canonical layouts are parallelism-agnostic; the replicated-layout exception remains separate.

## Claims

- Direct storage concatenates each worker's local layers, so changing TP changes byte offsets even when read sizes still match.
- Cross-TP direct-layout runs receive different persistent filenames.
- Same-TP reuse, canonical layouts, and replicated-layout controls retain their intended behavior.

## Validation

Validated on 2026-10-10 at published head `1c034ceeb4` and in a temporary merge with upstream `276fbcff2717bd934cfa37c8a2e4c391f3e7237b`. The published branch was not rebased.

```sh
VLLM_TARGET_DEVICE=cpu CUDA_VISIBLE_DEVICES='' .venv/bin/python -m pytest tests/v1/kv_connector/unit/offloading_connector/test_config.py tests/v1/kv_offload/test_file_mapper.py tests/v1/kv_connector/unit/offloading_connector/test_canonical_mapping.py -q
VLLM_TARGET_DEVICE=cpu CUDA_VISIBLE_DEVICES='' .venv/bin/python -m pytest tests/v1/kv_offload/cpu/test_canonical_layout.py -q -k 'not gpu_roundtrip and not cross_topology'
.venv/bin/pre-commit run --hook-stage manual --files vllm/distributed/kv_transfer/kv_connector/v1/offloading/config.py tests/v1/kv_connector/unit/offloading_connector/test_config.py
```

Published-head config, mapping, canonical, and filesystem suites pass **158 tests**. Current-upstream mapping/config/canonical controls pass **118 tests**; unchanged filesystem suites were not repeated. Filesystem validation used the real extension built from unchanged `csrc/fs_io.cpp`, resolving an older installed-extension mismatch. All applicable scoped hooks pass. Restoring the original predicate produces **2 direct-layout failures and 2 passing canonical controls**.

The previously recorded CPU filesystem reproduction uses real registration, shared mmap views, direct-copy descriptors, FileMapper, and batch I/O. TP1-to-TP2 and TP2-to-TP1 baseline reuse return **32,222 incorrect FP16 elements** with deterministic random data; same-TP controls have zero mismatches. The fix separates cross-TP filenames and preserves same-TP reuse. CPU copying substitutes for GPU DMA.

Real TP1↔TP2 model inference remains outstanding; only one GPU is available locally.

## Details

The current-upstream integration also removes a now-unused `single_group_spec` assignment after upstream changed its replicated-layout predicate.

Fresh overlap review found #55907 and #58196 concern physical-layout identity, a different dimension from TP topology. Neither replaces this fix.

Existing direct-layout caches become cold because their namespace changes; no files are deleted. Reverting restores ambiguous topology reuse. A separate filesystem root per topology is an operational workaround.

Upstream CI is blocked at contributor authorization. Only one GPU is available locally; TP1-to-TP2 model validation has not been run. AI assistance was used for investigation, implementation, tests, and review.
