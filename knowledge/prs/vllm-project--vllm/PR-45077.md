# docs: Add GKE Autopilot deployment & Prometheus monitoring guide

[Upstream PR](https://github.com/vllm-project/vllm/pull/45077) · state: closed · merged: False

## Original PR description

### What this PR does / why we need it?
This PR adds a new deployment and monitoring section specifically for **GKE Autopilot** under the Kubernetes deployment documentation (`docs/deployment/k8s.md`). 

Currently, vLLM's Kubernetes guides assume standard K8s setups where users have node-level administrative privileges. In GKE Autopilot:
1. Privileged DaemonSets (such as `node-exporter`) violate Warden security policies and fail to schedule.
2. Control plane scraping (coredns, proxy, etcd, etc.) inside the `kube-system` namespace is restricted, causing Helm installation errors for `kube-prometheus-stack` out-of-the-box.
3. GPU quota limitations of `1.0` during rolling updates require a `Recreate` deployment strategy to avoid node deadlock.

This guide provides the necessary overrides for `kube-prometheus-stack` and configures `ServiceMonitor` to scrape vLLM's main port (8000) instead of the invalid port 8090, enabling seamless out-of-the-box observability on Autopilot.

### Does this PR introduce any user-facing change?
Yes, it adds a new documentation section to `docs/deployment/k8s.md` detailing GKE Autopilot deployment and metrics scraping.

### How was this patch tested?
The documentation configurations were fully verified on a live GKE Autopilot cluster:
1. Deployed `kube-prometheus-stack` using the customized values overrides.
2. Deployed vLLM with GCS Fuse volume mount.
3. Verified that the `ServiceMonitor` successfully scrapes vLLM metrics at `10.x.x.x:8000/metrics`.
4. Verified that metrics are successfully populated in Grafana.

A complete, runnable template project is linked here: https://github.com/obaida7/gke-vllm-serving
