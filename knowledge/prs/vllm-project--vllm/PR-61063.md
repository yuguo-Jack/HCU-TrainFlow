# [Bugfix][Anthropic] Count tool prompts without an output parser

[Upstream PR](https://github.com/vllm-project/vllm/pull/61063) · state: open · merged: False

## Original PR description

## Overview

Allow Anthropic `/v1/messages/count_tokens` to count prompts containing tools without requiring an output tool parser. Keep parser validation on generation requests.

## Claims

- Counting includes the rendered tool schemas instead of rejecting the request because generation parsing is disabled.
- `/v1/messages` retains its existing validation.

## Validation

Real Qwen3-0.6B HTTP before/fix/revert: counting with tools changes from HTTP 400 to HTTP 200 with 150 tokens, matching the tokenizer's rendered prompt. Plain counting remains 15 tokens and generation remains HTTP 400. The 108 conversion tests and the extended parser-validation test pass, as do applicable manual pre-commit hooks.

assert generate.status_code==400,'generation validation unexpectedly bypassed'
if with_tools.status_code==200:
 assert with_tools.json()['input_tokens']==expected,(with_tools.json(),expected)
 assert expected>plain.json()['input_tokens'],'tools missing from prompt'
 print('COUNT_TOOLS_PASSED')
else:
 assert with_tools.status_code==400 and 'tool' in with_tools.text
 print('COUNT_TOOLS_PARSER_REJECTED')

## Details

Token counting needs tool-aware prompt rendering, but never parses generated output. Pass an internal keyword-only flag through the existing rendering path to skip only the output-parser availability check; its default remains enabled.

Duplicate check: #59718 validates tool choices after tool removal in the Anthropic conversion path. It does not remove the generation-parser requirement from token counting. #52896 implements a Rust frontend surface, not this Python renderer path.
