# [Perf][MoE] Batch per-expert token count GPU sync into single transfer

[Upstream PR](https://github.com/vllm-project/vllm/pull/61132) · state: open · merged: False

## Original PR description

## Overview

Batch per-expert token count GPU synchronization into a single CPU transfer in MoE eager-mode paths, eliminating N sequential `.item()` GPU syncs per forward pass.

## Claims

- Eliminates per-expert `.item()` GPU synchronization in `fused_batched_moe.py` eager path
- Eliminates per-expert `.item()` GPU synchronization in `batched_deep_gemm_moe.py` UE8M0 scale packing loop
- Reduces 64+ sequential GPU syncs to 1 GPU-to-CPU transfer for 64-expert models

## Validation

- `ruff check` and `ruff format --check`: all passed
- Code path: the `_is_capturing_or_compiling()` guard ensures CUDA graph / inductor paths are unaffected (they use `hidden_states.shape[1]` directly, no GPU sync)
- The `.tolist()` call produces a Python list of ints, equivalent to `int(tensor[i].item())` for each element but in a single transfer

## Details

The eager-mode MoE expert loop called `.item()` on the GPU tensor `expert_num_tokens` once per expert, forcing a GPU synchronization each time. With 64+ experts this adds 64+ sequential GPU syncs per forward pass.

Replace with a single `.tolist()` call before the loop, then index the CPU list. Each `.tolist()` is one GPU-to-CPU transfer; each `.item()` is a separate synchronization point.

Apply the same fix to the UE8M0 scale packing loop in `batched_deep_gemm_moe.py`, where `tokens_per_expert[e_idx].item()` was called per expert.
