# [Refactor][KV Offload] Split shared offload regions into concrete classes

[Upstream PR](https://github.com/vllm-project/vllm/pull/60782) · state: open · merged: False

## Original PR description



## Overview

Refactor shared CPU offload storage into explicit region implementations while preserving main's layout, population, pinning, barrier, and cleanup behavior.

This provides a stable foundation for future offloading optimizations, including the work in [#59544](https://github.com/vllm-project/vllm/pull/59544), [#59545](https://github.com/vllm-project/vllm/pull/59545), [#59546](https://github.com/vllm-project/vllm/pull/59546), and [#59547](https://github.com/vllm-project/vllm/pull/59547).

## Claims

- **Decoupled responsibilities:** common mmap lifetime management stays in the base class; layout-specific view, populate, and pin behavior stays in concrete classes.
- **Explicit implementation selection:** each caller constructs the intended implementation directly (`DirectRankRegion`, `ReplicatedRegion`, `GlobalRegion`, `CanonicalRegion`, or `HiSparseRegion`).
- **Independent optimization surface:** each layout can later optimize its own populate, pin, or address strategy without adding branching to shared code.
- **Clear ownership:** the region owns tensors backed by its mmap, including CUDA registration, rollback, and release.
- **No performance behavior change in this PR:** current byte ranges, barrier ordering, view layout, and registration behavior remain unchanged.

## Details

`SharedOffloadRegion` now owns mmap creation, mapping synchronization, low-level page population, pinned-address tracking, cleanup, and failure rollback. Typed view interfaces separate tensor views from complete memoryviews:

```python
region.populate()
region.pin()
view = region.get_view(...)
region.cleanup()
```

Region implementations:

- `DirectRankRegion`: rank-local strided worker slots.
- `ReplicatedRegion`: replicated data in slot 0.
- `GlobalRegion`: complete row-major memoryview for the Tiering scheduler; no CUDA pin.
- `CanonicalRegion`: canonical tensor views with existing population and pin behavior.
- `HiSparseRegion`: creator-only population, HiSparse registration ranges, and segmented pinning.

This is separate from the mmap ownership and startup-cleanup fix in [#53073](https://github.com/vllm-project/vllm/pull/53073), which changes pathname ownership semantics. It is also not a duplicate implementation of Etelis's recent optimization PRs [#59544](https://github.com/vllm-project/vllm/pull/59544), [#59545](https://github.com/vllm-project/vllm/pull/59545), [#59546](https://github.com/vllm-project/vllm/pull/59546), or [#59547](https://github.com/vllm-project/vllm/pull/59547). Those PRs change offloading behavior and performance; this PR only establishes the concrete region boundaries needed to integrate similar optimizations cleanly in follow-up changes.
