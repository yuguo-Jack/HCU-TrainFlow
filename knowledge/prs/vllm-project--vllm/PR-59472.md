# [Bugfix][CPU] Report the real cause when the worker outgrows its memory reservation

[Upstream PR](https://github.com/vllm-project/vllm/pull/59472) · state: open · merged: False

## Original PR description

## Purpose

Fixes #59471.

When the CPU worker's own footprint (model weights plus runtime) exceeds the memory reserved by `--gpu-memory-utilization`, `CPUWorker.determine_available_memory` computes a negative KV cache budget. That case shared the "available < requested" error, which printed the negative size and told users to reduce memory used by other processes, the opposite of the fix:

```
ValueError: Available memory on node 0 (1.34/8.0 GiB) on kv cache allocation is less than requested memory for kv (-0.6/0.16 GiB). Reduce CPU memory used by other processes.
```

This PR splits the two conditions:

- **Worker outgrew its reservation** (`requested_memory_for_kv <= 0`): a new error states the footprint and the reservation, and points to what actually works. That is a larger `--gpu-memory-utilization`, with the smallest fraction that could fit, or an explicit `--kv-cache-memory-bytes` / `VLLM_CPU_KVCACHE_SPACE`. The wording follows #42479's CPU messages.
- **Node short of free memory** (`requested_memory_for_kv > available_memory`): the existing error is unchanged.

Only the error path changes. When the budget fits, sizing and startup behave exactly as before, and nothing runs after startup.

**Not a duplicate.** No open issue or PR covers this branch. #42479 reworded the neighbouring CPU memory errors (the startup check in this file, and two in `kv_cache_utils.py`) but not this one. Among open PRs touching `cpu_worker.py`, #51876 changes only `__init__`, with no overlap.

## Test Plan

- New `tests/v1/worker/test_cpu_worker_kv_budget.py`, CPU-only, no model. It covers three cases:
  - the worker outgrew its reservation: the new error with the right remedy, no negative size and no "other processes" advice;
  - the node is short of memory: the existing message still fires;
  - the budget fits: the KV size equals the reservation minus the footprint.
- Real engine on the CPU backend: `LLM(model="HuggingFaceTB/SmolLM2-135M", dtype="float32", gpu_memory_utilization=0.02)` on `main` and on this branch.

Real engine (macOS 27.0, Apple M1, 8 GiB, CPU backend built from `main` `fc2c801ad9`), `gpu_memory_utilization=0.02`:

- `main`:
  ```
  ValueError: Available memory on node 0 (1.34/8.0 GiB) on kv cache allocation is less than requested memory for kv (-0.6/0.16 GiB). Reduce CPU memory used by other processes.
  ```
- this branch:
  ```
  ValueError: The worker already uses 0.64 GiB (model weights and runtime), more than the 0.16 GiB of CPU memory reserved for it on node 0, leaving none for the KV cache. On the CPU backend, the `--gpu-memory-utilization` flag controls the fraction of CPU memory reserved (despite its name). To resolve: increase `--gpu-memory-utilization` to more than 0.09, or set the KV cache size explicitly with `--kv-cache-memory-bytes` or VLLM_CPU_KVCACHE_SPACE.
  ```

Separately observed, and identical with and without this change: on this machine the engine process sometimes does not exit after this worker startup error (2/2 runs on each side hung past a 240 s timeout; an earlier run on `main` exited promptly). This PR does not touch shutdown.

`pre-commit` on both files: ruff check and format, typos, mypy, SPDX and the remaining hooks passed. `check-test-tethering` and `check-root-lazy-imports` also pass when run with Python 3.12. The new test sits in `tests/v1/worker/`, which the `v1-executor-worker` job runs as a directory.

No model evaluation: the change only affects an error raised before the engine starts, so no model output changes.
