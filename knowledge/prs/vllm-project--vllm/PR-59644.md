# [Bugfix] Validate offline prompt embedding shapes before engine submission

[Upstream PR](https://github.com/vllm-project/vllm/pull/59644) · state: closed · merged: False

## Original PR description



## Overview

Validate the rank and hidden width of offline/rendered prompt embeddings before submitting them to EngineCore, so malformed input raises a request validation error and leaves the engine usable.

## Claims

- Rank and width errors are reported as `VLLMValidationError(parameter="prompt_embeds")` before worker submission.
- Valid pure embeddings and mixed token/embedding inputs retain their original tensors and metadata.

## Validation

Tested source base: `cfd54ca881`; Python 3.12.13, Torch 2.13.0+cu132, Transformers 5.14.1. Model validation used Qwen2.5-0.5B-Instruct on one NVIDIA A30, TP1, BF16, MRV2, eager, TRITON_ATTN, three prompt rows, four greedy output tokens, and prefix caching disabled.

| Check | Base | Fixed |
| --- | --- | --- |
| Invalid rank/width admission regression | 6 failed | Passed |
| Full request-input-bounds suite | — | 45 passed |
| Width 0 after a valid generation | EngineDeadError; later valid input also failed | VLLMValidationError |
| Widths 895 and 897 for hidden_size 896 | — | VLLMValidationError |
| Valid generation after all invalid requests | Engine dead | Token IDs and top-5 logprobs exactly matched the valid generation before them |

All applicable manual hooks passed, including mypy for Python 3.10–3.13 and CI test tethering. No Markdown files change. The existing bounds test file is already in CPU CI.

Minimal model trigger: with `enable_prompt_embeds=True`, call `llm.generate({"prompt_embeds": torch.zeros(3, 0, dtype=torch.bfloat16)}, SamplingParams(temperature=0, max_tokens=4))` on the configuration above, then submit a valid embedding prompt to the same `LLM`. The base worker fails staging a zero-width tensor into its 896-wide buffer, and the valid follow-up fails too. The fixed input processor rejects the malformed tensor before submission.

## Details

`safe_load_prompt_embeds()` already checks serialized HTTP embeddings, but offline and pre-rendered tensors bypass it. Apply the same rank/hidden-size contract at the common InputProcessor admission boundary, before `len()` and engine submission. This protects both runner paths without introducing copies, casting, dependencies, or public settings.

Duplicate check: searched open PRs for prompt_embeds shape and hidden-size validation. #55451 handles HTTP deserialization failures; #51123 handles LoRA batch metadata; #53496 handles ExampleConnector cache keys. None covers offline tensor-shape admission.

Local model validation used existing precompiled native extensions and a Humming dependency overlay; neither is changed. The editable environment's version metadata is stale, so the source SHA above is the tested identity. This validates targeted request recovery, not a performance or broad model-accuracy claim.
