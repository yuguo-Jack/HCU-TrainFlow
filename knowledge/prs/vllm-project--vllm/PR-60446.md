# [Bugfix][Kernel] Remove invalid NC from Kimi-K3 KDA autotune keys

[Upstream PR](https://github.com/vllm-project/vllm/pull/60446) · state: closed · merged: True

## Original PR description



## Overview

Both AMD and NVIDIA Kimi-K3 KDA kernels list `NC` in their autotune keys even though they have no `NC` argument. Older Triton ignored this unused entry but Triton 3.9 rejects it at import so this PR removes `NC` from both copies (fixes [test-infra #9028](https://github.com/pytorch/test-infra/issues/9028)).

## Claims

- AMD and NVIDIA KDA modules import with Triton 3.9, without changing kernel computation or the effective autotune key used by older Triton.

## Validation

  - With `torch==2.15.0+cu130` and `triton==3.9.0`, unchanged `main` (`a8260cbc5c`) fails during KDA test collection with `ValueError: key contains names that are not kernel arguments: NC`. Importing the NVIDIA copy separately fails the same way.
  - With the fix, both modules import, and `VLLM_TARGET_DEVICE=cpu .venv/bin/python -m pytest --collect-only -q tests/models/kimi_k3/test_kda.py` collects 102 tests. Local `pre-commit run --all-files` passes.
  - On an AMD MI350 (`gfx950`), compared Triton-ROCm `3.8.0+git10f6be36` and `3.9.0+gitaad2a60d` with the same Torch build, GPU, inputs, and vLLM sources. The unpatched AMD and NVIDIA modules both fail to import on 3.9; both import with this fix. Both versions import on 3.8.
  - Ran the actual vendored AMD `chunk_kda_fwd_intra(safe_gate=True)` kernels on MI350. For a synthetic BF16 input (`B=1, T=1024, H=HV=12, K=128`, chunk size 64), the defined outputs on patched 3.9 were bit-identical to unpatched 3.8. A ragged input with sequence lengths `[63, 73]` also matched within `rtol=1e-4, atol=1e-6`

## Details

[Triton #11602](https://github.com/triton-lang/triton/pull/11602) added validation of autotune key names. `NC = ceil(BT / BC)` is computed for the launch grid, not passed to the decorated kernel. The KDA test imports the AMD vendored copy first, masking the same bug in the NVIDIA copy.
