# [Bugfix] Respect the configured offline chat template

[Upstream PR](https://github.com/vllm-project/vllm/pull/61061) · state: closed · merged: True

## Original PR description

## Overview

Use the template configured through `LLM(chat_template=...)` in `chat()` and `enqueue_chat()`. Explicit per-call templates continue to override the constructor default.

## Claims

- Both offline chat entry points use the configured template instead of silently falling back to the tokenizer template.
- Per-call template overrides retain their existing behavior.

## Validation

Real Qwen3-0.6B inference: both constructor-default cases fail on main, pass with this change, and fail again after reverting it. Both explicit override controls pass throughout. Applicable manual pre-commit hooks pass.

```python
import json,sys,pathlib
from vllm import LLM,SamplingParams
MODEL='./model'
TEMPLATE="User: {{ messages[0]['content'] }}\nAssistant:"
OVERRIDE="Question: {{ messages[0]['content'] }}\nAnswer:"
def main():
 llm=LLM(model=MODEL,chat_template=TEMPLATE,enforce_eager=True,max_model_len=512,gpu_memory_utilization=0.25)
 tokenizer=llm.get_tokenizer();messages=[{'role':'user','content':'What is the capital of France?'}]
 results=[]
 for entry in ['chat','enqueue_chat']:
  for override in [None,OVERRIDE]:
   kwargs=dict(sampling_params=SamplingParams(temperature=0,max_tokens=4),use_tqdm=False)
   if override is not None:kwargs['chat_template']=override
   outputs=getattr(llm,entry)(messages,**kwargs)
   if entry=='enqueue_chat':outputs=llm.wait_for_completion(use_tqdm=False)
   expected=tokenizer.apply_chat_template(messages,chat_template=override or TEMPLATE,tokenize=True,add_generation_prompt=True,return_dict=False)
   result=dict(entry=entry,override=override is not None,expected=expected,actual=outputs[0].prompt_token_ids,text=outputs[0].outputs[0].text)
   result['matches']=result['actual']==expected;results.append(result);print(json.dumps(result),flush=True)
 pathlib.Path(sys.argv[1]).write_text(json.dumps(results,indent=2))
 print('CHAT_TEMPLATE_PASSED' if all(r['matches'] for r in results) else 'CHAT_TEMPLATE_MISMATCH',flush=True)
if __name__=='__main__':main()
```

## Details

The shared offline preprocessing path passed `None` through to the renderer when no per-call template was given, despite the constructor having saved a template. Resolve that default before preprocessing. No new test file or abstraction is needed for this wiring change.

Duplicate check: #60877 concerns Sentence Transformers scoring templates; #46801 concerns dictionary-valued HF templates. Neither connects the offline constructor default to these two entry points.
