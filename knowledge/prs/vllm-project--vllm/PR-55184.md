# Fix/dsv4 pre-sm89/sm90 (software fp8) sparse mla omnibus

[Upstream PR](https://github.com/vllm-project/vllm/pull/55184) · state: open · merged: False

## Original PR description



## Purpose

DeepSeek V4 Pro and DeepSeek V4 Flash cannot complete compiled sparse-MLA serving on A100/SM80 from the pre-omnibus code state. The blockers occur sequentially, so repairing one exposes the next:

```text
ValueError: type fp8e4nv not supported in this architecture
NVVM backend compilation failed
No common block size for 16.
CUDA error: an illegal memory access was encountered
```

The failures come from several connected assumptions in the sparse-MLA path:

1. Triton cannot lower direct `tl.float8e4nv` conversions for SM80 or SM86.
2. DeepSeek V4 selects DeepGEMM or CuTeDSL paths on GPUs that cannot execute them.
3. The paged-MQA fallback can write past a non-aligned logits tail and can overflow 32-bit physical-block addressing for large strided KV pools.
4. DeepSeek V4 supplies one compressed context length per generated token, while the generic paged-MQA path previously assumed one final length per request.
5. Invalid CUDA-graph padding rows can retain a derived compressed length and publish physical cache indices.
6. The output projection uses fused FP8 conversion and DeepGEMM even when DeepGEMM is unavailable.
7. K-cache gather accepts narrowed block-table views but advances rows using the logical width rather than the backing tensor's physical row stride.
8. The generic Triton sparse-MLA backend advertised SM75 despite its hard-coded BF16 output, and its autotune warmup used BF16 query and KV tensors even for FP16 configurations.

This omnibus assembles the already-separated and independently testable fixes into one consolidated SM8x sparse-MLA stack:

1. Add shared FP8 E4M3 encode/decode helpers backed by always-inline CUDA conversion routines linked from portable SM75 LLVM bitcode. SM80 and SM86 use the helper; SM89 retains native conversion.
2. Add `TRITON_MLA_SPARSE` as the fallback sparse-MLA backend, addressing [#38006](https://github.com/vllm-project/vllm/issues/38006), retain optimized backends ahead of it, gate the fused indexer-Q conversion on SM89+, require a block-size multiple of 64, bound paged-MQA tail stores, and promote physical block indices to 64-bit before multiplying by the KV-pool stride.
3. Route DeepSeek V4 SM8x systems without DeepGEMM through the Triton sparse-MLA implementation, restrict CuTeDSL selection to SM90+, use the shared conversion helper at the compressor, indexer, cache, and sparse-decode call sites, support two-dimensional per-token context lengths, and mask invalid graph-padding rows.
4. Reuse the existing BF16 grouped output projection when DeepGEMM is unavailable. Scaled weights still pass through `wo_a`, so their quantization backend applies the scale; unscaled BF16 weights keep the direct grouped einsum.
5. Pass `block_table.stride(0)` into K-cache gather rather than allocating and copying a contiguous table. Contiguous inputs retain identical addressing, while narrowed views use their real backing layout.
6. Keep the capability guard at the sparse-MLA backend boundary, document that dtype-aware output is required before enabling SM75, and warm the exact configured model-activation and resolved KV-cache dtype pair before CUDA-graph capture.

The omnibus adds no new feature implementation beyond the commits listed below. Its only rebase adaptation preserves current `main`'s head-size-aware FlashInfer sparse-backend ordering and appends `TRITON_MLA_SPARSE` as the final fallback.

### A100/SM80 end-to-end reproduction

Build this branch together with the co-pending #50645 and #53376 changes noted above to reproduce the complete validation stack.

The following Slurm script uses vLLM's native multiprocessing: one `vllm serve` process per node, `--headless` on nonzero node ranks, and no Ray or `torchrun`. Both configurations retain the production compiled path and CUDA graphs; neither uses eager mode.

Save as `dsv4-a100.sbatch`:

```bash
#!/bin/bash
#SBATCH --ntasks-per-node=1
#SBATCH --gpus-per-node=8
#SBATCH --time=02:00:00

set -euo pipefail

: "${MODEL:?set MODEL}"
: "${REVISION:?set REVISION}"
: "${SERVED_MODEL:?set SERVED_MODEL}"
: "${TP:?set TP}"
: "${PP:?set PP}"

MASTER_ADDR=$(scontrol show hostnames "$SLURM_JOB_NODELIST" | head -n1)
export MASTER_ADDR
export MASTER_PORT=29501
export COMPILATION_CONFIG='{"cudagraph_capture_sizes":[1,2,4,8,16,32,64],"inductor_compile_config":{"enable_auto_functionalized_v2":true}}'

srun \
  --nodes="$SLURM_NNODES" \
  --ntasks="$SLURM_NNODES" \
  --ntasks-per-node=1 \
  bash -lc '
    headless=()
    if (( SLURM_NODEID > 0 )); then
      headless=(--headless)
    fi

    exec vllm serve "$MODEL" \
      --revision "$REVISION" \
      --served-model-name "$SERVED_MODEL" \
      --host 0.0.0.0 \
      --port 8000 \
      --trust-remote-code \
      --tokenizer-mode deepseek_v4 \
      --load-format fastsafetensors \
      --safetensors-load-strategy lazy \
      --distributed-executor-backend mp \
      --master-addr "$MASTER_ADDR" \
      --master-port "$MASTER_PORT" \
      --nnodes "$SLURM_NNODES" \
      --node-rank "$SLURM_NODEID" \
      --tensor-parallel-size "$TP" \
      --pipeline-parallel-size "$PP" \
      --enable-expert-parallel \
      --kv-cache-dtype fp8 \
      --block-size 256 \
      --max-model-len 10240 \
      --max-num-seqs 64 \
      --max-num-batched-tokens 16384 \
      --gpu-memory-utilization 0.9 \
      --linear-backend auto \
      --moe-backend auto \
      --no-enable-prefix-caching \
      --distributed-timeout-seconds 7200 \
      --cpu-distributed-timeout-seconds 7200 \
      --compilation-config "$COMPILATION_CONFIG" \
      "${headless[@]}"
  '
```

### A100/SM80 end-to-end results
