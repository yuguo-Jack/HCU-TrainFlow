# [Bugfix] Fix hf_overrides text_config on DeepseekV41Config

[Upstream PR](https://github.com/vllm-project/vllm/pull/60575) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fix `hf_overrides={"text_config": {...}}` for DeepSeek-V4.1. `DeepseekV41Config` flattens its text config onto itself, so the override replaces `text_config` with a partial dict and model config creation fails with `ValueError` (missing `num_attention_heads`). Not a duplicate: #57818 (open) edits the same file for an unrelated bug and does not conflict.

## Claims

- `hf_overrides={"text_config": {...}}` on `DeepseekV41Config` now merges the given fields into the config instead of raising `ValueError`. Before this fix the override values were also never applied.
- The fix is a 6-line `text_config` property on `DeepseekV41Config`; `vllm/config/model.py` is unchanged.
- No behavior change when `hf_overrides` is unset (shared call sites are checked under Details).

## Validation

Reproducer, fails on `main` and passes with this PR:

```python
cfg = DeepseekV41Config(text_config={"num_attention_heads": 128})
ModelConfig._apply_dict_overrides(
    ModelConfig.__new__(ModelConfig), cfg, {"text_config": {"num_experts_per_tok": 8}}
)
get_hf_text_config(cfg)  # main: ValueError
```

## Details

**Root cause.** `DeepseekV41Config.__init__` copies every `text_config` key onto `self` and stores no `text_config` attribute. `ModelConfig._apply_dict_overrides` therefore gets `None` from `getattr(config, "text_config", None)`, treats the value as a plain field, and runs `setattr(config, "text_config", {...})`. `PreTrainedConfig.get_text_config()` then returns that partial dict as the text sub-config, and `get_hf_text_config()` raises because it has no `num_attention_heads`.

**Fix.** Expose `text_config` as a property returning `self`. `_apply_dict_overrides` then takes its existing nested-config branch and merges the override into the flattened fields. Other call sites already read this config the same way (`getattr(config, "text_config", config)`, e.g. `vllm/models/deepseek_v41/nvidia/flash_mla_mega_attn.py:163`), and keeping the fix in the model config avoids a special case in `vllm/config/model.py`.

**Compatibility.** Shared call sites that read `hf_config.text_config` now get `self` instead of `None` for this model. `model_loader/weight_utils.py` and `ModelArchConfigConvertor.get_quantization_config` only consult it when the top-level config has no quantization config, so they re-read the same object; `v1/metrics/perf.py` resolves to the same object; `config/speculative.py:941` only runs for `intern_s2*` models. `vision_config` overrides are left alone on purpose: DSV4.1 stores vision fields under different names (`vision_dim`, `vision_n_heads`, ...), so routing them through the same path would overwrite text fields such as `hidden_size`.

AI assistance (Claude) was used to localize the root cause, draft the patch and tests, run them against pre-fix and post-fix code, and prepare this description.
