# [Bugfix] Name the cause when a compile cache dir cannot be created

[Upstream PR](https://github.com/vllm-project/vllm/pull/60863) · state: open · merged: False

## Original PR description

## The problem

An unwritable cache root ends engine startup with a bare `PermissionError` from `os.makedirs()`. What the user sees is:

```
RuntimeError: Engine core initialization failed. See root cause above. Failed core proc(s): {}
```

The traceback belongs to the engine-core subprocess and `finished` is empty, so the real cause sits tens of lines up in another process's output. Diagnosing it means reading the whole boot log.

Two calls can raise it, and neither says anything actionable:

- `compilation/backends.py` — the standard backend's `cache_dir` and `local_cache_dir`
- `compilation/decorators.py` — the AOT path's `inductor_cache`

## The change

Both go through one helper in `compilation/caching.py`, which both modules already import, re-raising with the directory and `VLLM_CACHE_ROOT` named. `errno` and `filename` are preserved by using `OSError`'s three-argument form rather than the single-argument one, which drops them.

Behaviour is otherwise unchanged. The happy path creates the directory exactly as before, and the failure is still fatal — only legible:

```
[Errno 13] Permission denied: cannot create the compile cache directory
/home/u/.cache/vllm/torch_compile_cache/torch_aot_compile/394b2ca3…/inductor_cache.
Set VLLM_CACHE_ROOT to a writable directory, or make the existing one writable by
this user (an earlier run under a different user can leave it unwritable):
'/home/u/.cache/vllm/torch_compile_cache/torch_aot_compile/394b2ca3…'
```

An earlier revision of this PR fell back to a temporary directory instead of raising. That was wrong: it guarded only the AOT call, so the process reached the unguarded one in `backends.py` and then disagreed with itself about where artifacts live. It added three failures to `tests/compile/test_aot_compile.py`, which is how the narrower scope was chosen. Degrading instead of failing would need both sites to resolve one writable root together, and that is a design change rather than a bug fix.

## How it showed up

A host where an earlier containerised run (as root, no `--user`) left `~/.cache/vllm/torch_compile_cache` owned by `root:root` with mode `755`. A later run as the service account could read it but could not create the hash-level subdirectory.

On that host, **`tests/compile/test_aot_compile.py::test_no_dynamo_cache_entry` fails with the bare `PermissionError` on unpatched `main`** — that is how this was found, rather than from the serving path.

## Not a duplicate

```
gh search issues --repo vllm-project/vllm "torch_compile_cache permission denied"
gh search issues --repo vllm-project/vllm "VLLM_CACHE_ROOT permission"
gh search issues --repo vllm-project/vllm "compile cache not writable"
gh search issues --repo vllm-project/vllm "permission denied"
gh pr list --repo vllm-project/vllm --state open --search "compile cache permission"
```

No open PR or issue covers these call sites. The closest prior reports are #41410 (TileLang under `/tmp` on a shared multi-user host, closed with a `TMPDIR` workaround) and #28440 (Cutlass JIT in a Docker image, closed by the stale bot) — the same shape in a different cache directory, neither changing vLLM's own behaviour.

## Test plan

Environment: 1 × NVIDIA GB10, aarch64, `uv venv --python 3.12` + `VLLM_USE_PRECOMPILED=1 uv pip install -e . --torch-backend=auto` + `requirements/test/cuda.in`, as `AGENTS.md` describes.

New tests:

```
pytest tests/compile/test_aot_compile.py -k make_compile_cache_dir
2 passed, 27 deselected
```

- `test_make_compile_cache_dir_creates_the_directory` — the normal path still creates it.
- `test_make_compile_cache_dir_names_the_fix_when_not_writable` — a parent with mode `0o500` raises `PermissionError` whose message contains `VLLM_CACHE_ROOT` and the offending path. Skipped as root, where directory permissions do not apply.

Regression check, same machine, unpatched `main` vs this branch:

| | `main` | this branch |
|---|---|---|
| `tests/compile/test_aot_compile.py` | 3 failed, 23 passed, 1 skipped | 3 failed, **25** passed, 1 skipped |
| `tests/compile/test_config.py` | 10 failed, 79 passed | 10 failed, 79 passed |

The same tests fail in both columns. They are environmental on this host: `test_no_dynamo_cache_entry` is the root-owned-cache `PermissionError` above, and the `test_config.py` failures are all `vllm_runner` cases that start real engines. No test changes status because of this patch.

Nothing here affects model output, accuracy or serving behaviour.
