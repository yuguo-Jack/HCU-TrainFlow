# [Perf][Model][Qwen4Exp] QSA: decode FP8 e4m3 bytes four per register on sm_80

[Upstream PR](https://github.com/vllm-project/vllm/pull/60992) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

On sm_80, the FP8 (e4m3) QSA reader decodes four cache bytes per 32-bit register in inline PTX instead of one byte at a time. This makes long-prompt prefill about 5 % faster (TTFT) on Qwen3.8-Flash-Next-FP8 with 8 × A100. The output is bit-identical.

Depends on #60602 (FP8 QSA main KV cache on Ampere). **Until #60602 merges, this branch also contains its commits. The change in this PR is commit `2b3fabb7f`** (`vllm/models/qwen4_exp/nvidia/ops/qsa.py`, `tests/models/qwen4_exp/test_qsa_reference.py`). Draft for that reason. If reviewers prefer, I will fold it into #60602.

## Claims

- **Exact:** the decode gives the same fp16 bits as the current byte decode for all 256 codes in every byte lane. The reader output is bit-identical at every tested row count. Scale folding and the ±480 NaN-code behaviour do not change.
- **Kernel (A100):** the FP8 QSA reader takes 0.68–0.85× of its current time at 128–2,048 query rows and ~1.0× at 8–32 rows (3 runs).
- **End to end, long uncached prompts:** median TTFT is 4.7–5.1 % lower at 8,192–131,072 input tokens (Qwen3.8-Flash-Next-FP8, TP8 + EP, 8 × A100-SXM4-40GB).
- **No change** in decode-dominated agentic serving (goodput and TPOT within noise). The gain is prefill-bound.
- sm_80 only, through the existing `_is_sm80()`. Other GPUs compile the unchanged path.

```python
# SPDX-License-Identifier: Apache-2.0
# SPDX-FileCopyrightText: Copyright contributors to the vLLM project
"""Time the Qwen4Exp FP8 QSA sparse paged reader on sm_80 with the packed
e4m3 decode off (the current byte decode) and on (#60992).

One GPU, synthetic inputs, no model. The shapes are one TP8 rank of
Qwen3.8-Flash-Next: 3 query heads, 1 KV head, head_dim 256, and 2,048 selected
tokens per row from one 131,072-token request. K/V are e4m3 views of one uint8
cache with per-tensor scales, as the layer passes them. Both arms call
qsa_sparse_paged_attention with the same launch configuration; only the
FP8_PACKED_DECODE constexpr of the reader kernel differs.

Usage: python bench_qsa_fp8_packed.py [--rows 8 16 ...] [--samples 31]
"""

import argparse
import statistics

import torch

from vllm.models.qwen4_exp.nvidia.ops import qsa

QUERY_HEADS, KV_HEADS, HEAD_DIM = 3, 1, 256
SELECTED_TOKENS = 2048
SEQUENCE_TOKENS = 131072
PAGE_SIZE = 208  # a multiple of 16, as the QSA backend requires
FP8_MAX = 448.0
PREFILL_CONFIG_MIN_ROWS = 512
WARMUP_ROUNDS = 3
SEED = 20261006
ROWS = (8, 16, 32, 64, 128, 256, 512, 1024, 2048)
READER_KERNEL = qsa._qsa_sparse_paged_gqa_splitk_kernel


class PackedDecodeLauncher:
    """READER_KERNEL[grid](...) with FP8_PACKED_DECODE set; other args unchanged."""

    def __init__(self, enabled: bool):
        self.enabled = enabled

    def __getitem__(self, grid):
        def launch(*args, **kwargs):
            kwargs["FP8_PACKED_DECODE"] = self.enabled
            return READER_KERNEL[grid](*args, **kwargs)

        return launch


def make_inputs(rows: int, generator: torch.Generator) -> dict:
    """Keyword arguments of qsa_sparse_paged_attention for `rows` query rows."""
    def randn(*shape):
        return torch.randn(shape, generator=generator, device="cuda")

    pages = SEQUENCE_TOKENS // PAGE_SIZE + 1
    kv = randn(pages, KV_HEADS, PAGE_SIZE, 2 * HEAD_DIM)
    k_scale = kv[..., :HEAD_DIM].abs().amax().item() / FP8_MAX
    v_scale = kv[..., HEAD_DIM:].abs().amax().item() / FP8_MAX
    kv[..., :HEAD_DIM] /= k_scale
    kv[..., HEAD_DIM:] /= v_scale
    # [pages, heads, page, K|V] uint8 storage, viewed as the layer views it.
    storage = kv.to(torch.float8_e4m3fn).view(torch.uint8)
    cache = storage.view(torch.float8_e4m3fn).transpose(1, 2)
    keys, values = cache.split(HEAD_DIM, dim=-1)
    # Each row selects 2,048 distinct tokens of the request, in random order.
    selected = torch.stack(
        [
            torch.randperm(SEQUENCE_TOKENS, generator=generator, device="cuda")[
                :SELECTED_TOKENS
            ]
            for _ in range(rows)
        ]
    )
    counts = torch.full((rows, 1), SELECTED_TOKENS, device="cuda")
    query = randn(rows, QUERY_HEADS, HEAD_DIM).bfloat16()
    return dict(
        q=query,
        k_cache=keys,
        v_cache=values,
        logical_indices=torch.cat([selected, counts], dim=1).int(),
        block_table=torch.randperm(pages, generator=generator, device="cuda")
        .int()
        .unsqueeze(0),
        token_to_req=torch.zeros(rows, dtype=torch.int32, device="cuda"),
        use_prefill_config=rows >= PREFILL_CONFIG_MIN_ROWS,
        out=torch.empty_like(query),
        k_scale=k_scale,
        v_scale=v_scale,
        output_gate=randn(rows, QUERY_HEADS, HEAD_DIM).bfloat16(),
    )


def reader_call(inputs: dict, packed_decode: bool):
    launcher = PackedDecodeLauncher(packed_decode)
    arm_inputs = {**inputs, "out": torch.empty_like(inputs["out"])}

    def call():
        qsa._qsa_sparse_paged_gqa_splitk_kernel = launcher
        try:
            return qsa.qsa_sparse_paged_attention(**arm_inputs)
        finally:
            qsa._qsa_sparse_paged_gqa_splitk_kernel = READER_KERNEL

    return call


def median_ms(calls, samples: int) -> list[float]:
    """CUDA-event medians; the arm order alternates on each sample."""
    for _ in range(WARMUP_ROUNDS):
        for call in calls:
            call()
    times = [[] for _ in calls]
    for sample in range(samples):
        for arm in range(len(calls))[:: 1 if sample % 2 == 0 else -1]:
            start, end = (torch.cuda.Event(enable_timing=True) for _ in range(2))
            start.record()
            calls[arm]()
            end.record()
            end.synchronize()
            times[arm].append(start.elapsed_time(end))
    return [statistics.median(arm_times) for arm_times in times]


def main() -> None:
    parser = argparse.ArgumentParser(
        description="FP8 QSA reader time with the packed e4m3 decode off and on."
    )
    parser.add_argument("--rows", type=int, nargs="+", default=ROWS)
    parser.add_argument("--samples", type=int, default=31)
    args = parser.parse_args()
    if not (qsa._is_sm80() and qsa._fp8_as_bits()):
        raise SystemExit("The packed decode is used only on sm_80 (A100/A30).")
    print(
        f"{torch.cuda.get_device_name()}, torch {torch.__version__}, "
        f"{args.samples} samples per arm and row count"
    )
    print("| Rows | Current (ms) | Packed (ms) | Packed / current | Identical |")
    print("|---:|---:|---:|---:|---|")
    failed = []
    for rows in args.rows:
        generator = torch.Generator(device="cuda").manual_seed(SEED + rows)
        inputs = make_inputs(rows, generator)
        calls = [reader_call(inputs, enabled) for enabled in (False, True)]
        current, packed = (call().clone() for call in calls)
        identical = torch.equal(current.view(torch.int16), packed.view(torch.int16))
        if not (identical and torch.isfinite(packed).all()):
            failed.append(rows)
        current_ms, packed_ms = median_ms(calls, args.samples)
        print(
            f"| {rows} | {current_ms:.3f} | {packed_ms:.3f} | "
            f"{packed_ms / current_ms:.2f} | {'yes' if identical else 'NO'} |"
        )
    if failed:
        raise SystemExit(f"Outputs differ or are not finite at rows {failed}")


if __name__ == "__main__":
    main()
```

## Details

- **Root cause of the cost:** below sm_89, Triton cannot load `fp8e4nv`. So #60602 loads `uint8` and decodes each value with 16-bit shifts and masks. At prefill-sized row counts this decode dominates the reader.
- **Design:** `_e4m3_bits_to_scaled_fp16_packed` uses `tl.inline_asm_elementwise` with `pack=4`. Six instructions decode four values: `shf.r.wrap`, `lop3 0xE4`, two `prmt` and two `and 0xBF80BF80`. PTX instructions per 256 decoded values fall from 2,291 to 947. The result is exact by construction, so the test asserts bit equality (no tolerance, no flakiness).
- **Selection:** the `FP8_PACKED_DECODE` constexpr, set from `is_fp8 and _is_sm80()` at both launch sites (reader and its warmup). The reference decode stays for other byte-path GPUs and as the test oracle.
- **Scope of the gain:** the reader is faster per call, so TTFT drops where prefill dominates (long, uncached prompts). Decode steps have few query rows (~1.0× above) and the reader is a small part of them.
- **Measurement setup notes:** our serving runs used the vLLM 81198e97 nightly image with the reader files bound in. The packed arm used an earlier revision of this commit whose selector was sm_80 or sm_86. On A100 it selects the same decode, and the decode code is the same. Both arms also had a local scheduler patch that admits prefill on every 16th step (not in upstream; identical in both arms).
- **No new host/GPU synchronisation.** 48 added lines of runtime code (low complexity), plus the test.
- **Limitation:** sm_80 only. sm_86 can opt in after a benchmark on that architecture.
- **CI:** the new test needs a CUDA GPU. It runs where the other QSA kernel tests run. CI has no A100 with this checkpoint, so the end-to-end results above come from our cluster.
