# [ROCm][Perf] Gather MLA DCP query with AITER all-gather

[Upstream PR](https://github.com/vllm-project/vllm/pull/60606) · state: open · merged: False

## Original PR description



## Overview
On ROCm, DCP's query all-gather runs through RCCL. This PR routes it through AITER's custom all-gather, which has already existed in vLLM's AITER custom collectives, through a dedicated communicator instance for the aiter DCP group.


## Claims
- On Kimi-K3, MI355X x8 with TP8 and DCP8, using AITER's all-gather achieves ~1% - ~4% output throughput across concurrency
- The aiter gathered query is identical to gathering through the RCCL path, and end-to-end accuracy is unchanged.
- Settings with DCP disabled are unaffected

## Details

When DCP is enabled, each MLA layer gathers the decode query across ranks in the DCP group before attention. On ROCm, it currently goes through RCCL, and since RCCL concatenates along dim 0, this path requires copying results so that the head ordering is correct. AITER's all-gather gathers along the last dimension, so gathering a query viewed as `[T, H * D]` is exactly gathering along the heads, and it's able to write into the final layout with no reordering copy. Measuring on Kimi-K3 with TP8 and DCP8, this decreases per-layer gather latency from RCCL path's 31.9us to AITER path's 16.2us in decode traces.

The is enabled for ROCm and only in single-node DCP settings when AITER custom all-reduce is enabled. When its requirements are not met, this gather falls back to using RCCL.
