## Original PR description



## Purpose

Fixes https://github.com/vllm-project/vllm/issues/55635.

Install the pinned AWS EFA userspace runtime when building the vLLM image with
`INSTALL_KV_CONNECTORS=true`. This provides the libfabric runtime required by
NIXL's bundled `LIBFABRIC` plugin and is expected to support the Mooncake
TransferEngine path as well.

The EFA installer automatically selects the appropriate packages for `amd64`
or `arm64`, allowing both platforms to use the same Dockerfile implementation.
Kernel modules and host limit configuration are deliberately excluded from the
container installation and remain the responsibility of the host.

The installation:

- Pins AWS EFA installer version `1.50.0` and verifies its SHA-256 checksum.
- Installs the EFA userspace stack without kernel modules or host limit changes.
- Verifies that `/opt/amazon/efa/bin/fi_info` is executable.
- Verifies that NIXL's `libplugin_LIBFABRIC.so` is present.
- Removes installer artifacts and APT lists after installation.
- Documents the behavior and records the new build arguments in
  `docker/versions.json`.

Duplicate-work checks found no open PR referencing issue #55635 or implementing
the same AWS EFA runtime support for KV connectors.

AI assistance disclosure: Codex was used to help inspect the relevant build
paths, implement the change, and prepare validation. I reviewed and understand
the submitted changes and can explain and maintain them.

Good catch. I selected 1.47.0 as a conservative known-good baseline because it is documented as the minimum EFA installer version for current NIXL/EFA deployments. I have not found a hard dependency requiring it from NIXL 1.3.2, PyTorch 2.13, or NCCL 2.30.7.
This integration primarily uses NIXL’s LIBFABRIC backend directly, so the PyTorch/NCCL versions do not appear to dictate the EFA installer version. AWS currently recommends 1.50.0 for NIXL, and its removal of Amazon Linux 2 support does not affect this Ubuntu 24.04 image.
I’ll update the pin and checksum to 1.50.0 and rerun the container build and plugin checks. Thanks for catching this.
