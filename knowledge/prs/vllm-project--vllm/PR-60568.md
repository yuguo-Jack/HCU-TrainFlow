# [Docs] Add host kernel tuning guidance for engine-core polling and KV offload

[Upstream PR](https://github.com/vllm-project/vllm/pull/60568) · state: open · merged: False

## Original PR description

## Summary

Adds a new "Host Kernel Tuning" subsection to `docs/configuration/optimization.md` covering two Linux host-level knobs that aren't documented anywhere in the repo today, plus a cross-referencing bullet in `docs/features/kv_offloading_usage.md`'s existing "Tuning Tips" section:

- **CPU frequency governor / C-states / `isolcpus`+`nohz_full`**: the engine-core busy loop and the shared-memory IPC readers between engine core and workers (`vllm/distributed/device_communicators/shm_broadcast.py`'s `SpinCondition`) use a spin-then-block polling strategy. A power-saving governor or deep C-states on the pinned cores (see the existing `--numa-bind`/`--numa-bind-cpus` docs just above this section) undermines that design, adding latency jitter that's easy to misattribute to the GPU or network.
- **`vm.swappiness` / `vm.overcommit_memory`**: hosts using CPU KV offloading (`docs/features/kv_offloading_usage.md`) have the offloaded tier competing with the page cache and other host memory. Default swappiness can swap out offloaded blocks instead of reclaiming page cache first; a permissive overcommit policy combined with a large offload tier can let the OOM killer take a worker process instead of vLLM's own admission control handling it gracefully.

This is docs-only — no code changes, no behavioral changes.
