#  [MiniMax-M3 Performance] Prefer CuTe for MiniMax M3 FP8 indexer prefill

[Upstream PR](https://github.com/vllm-project/vllm/pull/60930) · state: open · merged: False

## Original PR description

## Overview

Add automatic dispatch to MSA’s dedicated CuTe prefill scorer for supported MiniMax M3 FP8 indexing, retaining FMHA for BF16 and explicit rollback.

Related: #59979 (https://github.com/vllm-project/vllm/pull/59979), which improves splitting within the FMHA scorer. This change selects a different existing scorer and preserves vLLM’s native Top16 selection.

## Claims

- Select the prefill backend once at initialization: CuTe for supported FP8 indexer Q/K, FMHA for BF16.
- Reuse the existing persistent CuTe scorer, plan once per batch, and write directly into the shared score buffer across layers.
- Expose auto, cute, and fmha controls without changing indexer precision.
- Preserve native Top16 selection and decode routing; reject mismatched indexer Q/K before scoring.

## Validation

Passed: applicable pre-commit hooks, including Ruff, mypy, configuration validation, and CI test tethering; Python syntax checks; git diff --check; and isolated CMake configuration checks.

The existing MiniMax M3 kernel suite was extended with 18 parameterizations covering pure/mixed batches, backend selection, BF16 fallback, explicit overrides, unsupported configurations, shared-plan reuse, and dtype mismatch rejection.

Measurement protocol:

- SM107, 212 SMs, two indexer heads per rank, verified maximum memory clock of 4752 MHz.
- Three independent process groups, one backend per process; 20 warmups and 50 samples per point.
- Cold measurements evicted 512 MiB outside timing, against 126 MiB L2.
- Latencies are medians of process p50s. Speedups are medians of paired PR/CuTe ratios, so they can differ from ratios of the displayed latency medians.

## Details

The current prefill path uses FMHA OnlyScore. This change invokes MSA’s existing dedicated persistent scorer through plan(..., score_out=...) and run_scores(), then uses vLLM’s native Top16 selector. It introduces no new scheduler or query/KV-length heuristic.

Configure automatic selection with:

--attention-config \
  '{"indexer_kv_dtype":"fp8","minimax_m3_indexer_prefill_backend":"auto"}'

| Setting | Behavior |
|---|---|
| auto | Use CuTe when precision, geometry, hardware, and dependency API are supported; otherwise FMHA. |
| cute | Require CuTe; reject unsupported configurations or a missing API. |
| fmha | Force FMHA while retaining the configured indexer precision. |

Indexer Q follows the index K-cache dtype, independently of main-attention Q. Leaving indexer precision at MiniMax M3’s BF16 default retains FMHA.

CuTe admission requires SM100/103/107, FP8 E4M3, head dimension and page size 128, 1/2/4 index heads per rank, and at least one forced local block. The scorer omits the current page’s score, so native Top16 must force that page into the result.

Dependency prerequisite: the public MSA score-output/score-only API must land and vLLM’s dependency pin must be updated. With the current pin, a stock build still falls back to FMHA under auto; explicit cute reports the missing API. The default backend switch therefore remains gated on that dependency update and qualification.
