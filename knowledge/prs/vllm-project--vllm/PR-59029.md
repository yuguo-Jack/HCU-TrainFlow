# [Bugfix][Core] Schedule encoder-only prompts larger than one step

[Upstream PR](https://github.com/vllm-project/vllm/pull/59029) · state: closed · merged: True

## Original PR description

## Purpose

An encoder-only instance (`mm_encoder_only`, e.g. image-only serving) holds no KV cache, so `EngineCore.__init__` turns chunked prefill off *after* config validation has already passed (`"Disabling chunked prefill for model without KVCache"`, `vllm/v1/engine/core.py`). `SchedulerConfig.verify_max_model_len` only rejects `max_num_batched_tokens < max_model_len` while chunked prefill is off at validation time, so such an instance starts normally with a per-step budget smaller than its largest prompt.

At scheduling time `Scheduler.schedule` then reaches:

```python
if (
    not self.scheduler_config.enable_chunked_prefill
    and num_new_tokens > request_token_budget
):
    break
```

The request is only peeked from the waiting queue and never popped, and neither its prompt length nor the budget ever changes, so the same `break` fires on every step: the request waits forever and no error is raised anywhere.

This PR exempts encoder-only instances from that break with one clause, `and not self.is_mm_encoder_only`, so the existing `num_new_tokens = min(num_new_tokens, request_token_budget)` splits the prompt across steps. That is safe here specifically because an encoder-only instance keeps no KV cache for a resumed prefill to lose.

### Changes

- `vllm/v1/core/sched/scheduler.py` — skip the "chunked prefill is disabled" break for encoder-only instances, letting the token budget split their prompt.
- `tests/v1/core/utils.py` — `create_scheduler(..., mm_encoder_only=True)` sets `model_config.multimodal_config.mm_encoder_only` after the model config is built.
- `tests/v1/core/test_scheduler.py` — `test_encoder_only_prompt_longer_than_budget_is_chunked`: a 2500-token prompt with `max_num_batched_tokens=1024` and `enable_chunked_prefill=False` schedules 1024 / 1024 / 452 over three steps.

### Duplicate-work check

Searched open issues and PRs for "encoder-only prompt", "max_num_batched_tokens validation", "mm_encoder_only stall" and related terms. No open PR makes the scheduler split an encoder-only prompt that exceeds one step; the nearest open work (#56826, #57368) concerns encoder input lifetimes across steps, which this does not touch.
