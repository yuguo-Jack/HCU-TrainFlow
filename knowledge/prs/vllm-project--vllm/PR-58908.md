# [Bugfix][Rust Frontend] Guard every route by default in the API-key middleware

[Upstream PR](https://github.com/vllm-project/vllm/pull/58908) · state: open · merged: False

## Original PR description

## Purpose

Fixes the Rust-frontend half of #58144.

`GUARDED_PREFIXES` only matched `/v1`, `/v2` and `/inference`, so any route outside those prefixes was reachable without a bearer token even when `--api-key` was configured. This includes `/tokenize`, `/detokenize`, `/metrics`, `/reset_prefix_cache`, `/reset_mm_cache`, `/reset_encoder_cache`, `/collective_rpc`, `/update_weights`, `/abort_requests`, `/sleep`, `/wake_up`, `/pause`, `/resume`, `/server_info`, `/get_world_size`, and `/start_profile`/`/stop_profile`.

This mirrors the same allowlist-of-guarded-prefixes defect that #58028 fixes on the Python frontend for the same issue. As noted in a comment on #58144: "The Rust frontend has the same bug ... `--api-key` behaves differently per frontend." This PR closes that gap on the Rust side.

## Fix

Replace `GUARDED_PREFIXES` (allowlist of what's guarded, fails open on new routes) with `UNGUARDED_PATHS` (allowlist of what's exempt — `/health`, `/load`, `/version`), so every route, present or added later, requires a token by default.
