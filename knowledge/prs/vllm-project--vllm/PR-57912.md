# [KV Offload][FS] Opt-in per-block CRC32C checksums

[Upstream PR](https://github.com/vllm-project/vllm/pull/57912) · state: open · merged: False

## Original PR description

## Purpose
Implements item 1 of #54363. The FS tier catches a truncated block (short read) but not one whose bytes changed at the same size, e.g. bit rot; such a block is loaded as KV silently.

New tier option `checksum_blocks` (default `false`), using the xattr approach preferred in the #54363 discussion:

* **Store:** the block's CRC32C is set as xattr `user.vllm.kv_crc32c` on the temp file, before the rename.

* **Load:** verified after the read. A checksum verification failure removes the file and fails the load with `EBADMSG` through the existing `num_succeeded` partial-keep path, with `checksum_failed` set on the exception. The tier reports it as `JobResult.checksum_failed`, and `TieringMetricsTracker` counts it in `vllm:kv_offload_tiering_checksum_failures` under the indexed tier label (e.g. `1:fs`). An `EBADMSG` from the filesystem itself (as ext4/xfs report metadata checksum errors) is not flagged, so it fails the load without removing the file or being counted.

* **Backward compatible:** a block with no recorded checksum still loads, so the option can be enabled on an existing cache. For the same reason `FileMapper.fields` is not bumped, unlike the RFC text: the file contents do not change, so there is no cold start.

* **xattrs unavailable at `root_dir`:** the tier fails at startup (see the design decision below).

* Implemented in both `csrc/fs_io.cpp` (SSE4.2, table fallback) and the Python fallback in `fs/io.py`. With the option off, no CRC or xattr call is made and the metric is not registered.

`batch_store_block` / `batch_load_block` in `fs_io_C` gain a trailing `checksum` argument, so the extension must be rebuilt with this change.

Limitation: hardware CRC32C is x86-64 only. Other architectures, including ARM, use the table implementation (same value, slower); ARM hardware CRC can follow separately.

No other open PR references #54363, and searches for `checksum kv offload`, `crc32c` and `xattr` find none in this area.

### Design decision to confirm

#54363 did not settle what checksum mode should do when xattrs are unavailable: fail, or disable itself with a warning. I chose to fail at startup, because a silent fallback hides that blocks are no longer verified. Is that acceptable?

## Notes

* No behavior change by default: `checksum_blocks` is off unless explicitly enabled, so no model evals were run. When enabled, a checksum failure turns a corrupted cache hit into a miss and recompute instead of returning the corrupted KV block.

@varun-sundar-rabindranath 

I re-measured through `FileSystemTierManager` itself using the default pool (16 read / 16 write threads). Each benchmark job contains 16 blocks, N jobs are submitted at once, and I measured wall-clock time until the last job completed. The setup is otherwise the same as before: i7-14700F, ext4 / NVMe, `O_DIRECT`, `fs_io_C`, with checksum off/on runs interleaved.

For the same 4 GiB workload as my earlier table (4 MiB blocks × 64 jobs), the pool finished in 716.5 → 717.2 ms for store and 603.5 → 607.1 ms for load. With several jobs in flight, the pool e2e time does not show a consistent regression from checksumming, while process CPU time increases by about 1.4–3.0x. This is consistent with I/O becoming the limiting factor at higher concurrency, with CRC work overlapping with I/O across pool threads.

With only one job in flight, that overlap is not available at the job level: one pool task processes its blocks serially, so the checksum cost is directly visible in job latency. At 1 MiB and above, I measured roughly +34–89%.

So the checksum cost is reflected in single-job latency, but not in pool e2e time when several jobs are in flight; there it is absorbed as additional CPU time on the pool threads.

I'd request to keep the dedicated `CHECKSUM_FAILURES` counter, but I agree the errno check is the weak spot (any unrelated `EBADMSG` would be miscounted. 

My Recommendation on this is to have the verifier explicitly mark its exception, e.g. exc.checksum_failed = True, with the C++ extension attaching the same attribute via PyObject_SetAttrString only when its internal verifier detects a mismatch or invalid xattr. The manager should then check getattr(exc, "checksum_failed", False) instead of relying on errno.
This mirrors how num_succeeded is already carried on these exceptions in both the Python and C++ paths, keeping it consistent with the existing partial-keep mechanism. Add a regression test that injects a non-checksum OSError(errno.EBADMSG) and confirms the checksum-failure counter does not increment.

A filesystem `EBADMSG` from `fgetxattr` in the C extension can't be monkeypatched from pytest, so I verified it locally with an `LD_PRELOAD` shim and confirmed it works as expected: the block file is kept and not counted as a checksum failure. The check I used is below, in case it helps.

<summary>Manual check</summary>

Run on ext4 with `LD_PRELOAD=./shim.so python check.py {c,py} {corrupt,fs_ebadmsg}`; "before" is the C path with `fs_io_C` built from before this change.

```

# after
c  corrupt    errno=EBADMSG checksum_failed=True num_succeeded=1 file_kept=False
c  fs_ebadmsg errno=EBADMSG checksum_failed=False num_succeeded=1 file_kept=True
py corrupt    errno=EBADMSG checksum_failed=True num_succeeded=1 file_kept=False
```

```c
// gcc -shared -fPIC -o shim.so shim.c -ldl
#define _GNU_SOURCE
#include <dlfcn.h>
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

// Fail fgetxattr with $SHIM_ERRNO for the file at $SHIM_TARGET.
ssize_t fgetxattr(int fd, const char* name, void* value, size_t size) {
  static ssize_t (*real)(int, const char*, void*, size_t);
  if (!real) real = dlsym(RTLD_NEXT, "fgetxattr");
  const char* target = getenv("SHIM_TARGET");
  char link[64], path[PATH_MAX];
  snprintf(link, sizeof link, "/proc/self/fd/%d", fd);
  ssize_t n = readlink(link, path, sizeof path - 1);
  if (target && n > 0) {
    path[n] = '\0';
    if (strcmp(path, target) == 0) {
      errno = atoi(getenv("SHIM_ERRNO"));
      return -1;
    }
  }
  return real(fd, name, value, size);
}
```

```python
# LD_PRELOAD=./shim.so python check.py {c,py} {corrupt,fs_ebadmsg}
import errno, mmap, os, sys, tempfile
from vllm.v1.kv_offload.tiering.fs import io

path_kind, case = sys.argv[1:]
io._HAS_FSIO_C = path_kind == "c"
bs = 4096
buf = mmap.mmap(-1, 4 * bs)
paths = [os.path.join(tempfile.mkdtemp(), f"b{i}") for i in range(2)]
io.batch_store_block(paths, memoryview(buf), [0, bs], bs, False, True)

if case == "corrupt":  # same-size data corruption
    with open(paths[1], "r+b") as f:
        f.write(b"\xff" * 16)
else:  # the filesystem returns EBADMSG for the xattr lookup
    os.environ["SHIM_TARGET"] = paths[1]  # C path
    os.environ["SHIM_ERRNO"] = str(errno.EBADMSG)
    real_getxattr = os.getxattr

    def getxattr(fd, *args):  # Python path
        if os.readlink(f"/proc/self/fd/{fd}") == paths[1]:
            raise OSError(errno.EBADMSG, os.strerror(errno.EBADMSG))
        return real_getxattr(fd, *args)

    os.getxattr = getxattr

try:
    io.batch_load_block(paths, memoryview(buf), [2 * bs, 3 * bs], bs, False, True)
except OSError as e:
    print(f"{path_kind:2} {case:10} errno={errno.errorcode[e.errno]} "
          f"checksum_failed={getattr(e, 'checksum_failed', False)} "
          f"num_succeeded={e.num_succeeded} file_kept={os.path.exists(paths[1])}")
```
