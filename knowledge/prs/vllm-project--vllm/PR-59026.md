# [Bugfix] Read Ling quantization_config from top-level config for Bailing V3 VL

[Upstream PR](https://github.com/vllm-project/vllm/pull/59026) · state: closed · merged: True

## Original PR description

## Purpose

`inclusionAI/Ling-3.0-flash-VL-fp4` fails at weight loading on every platform:

```
RuntimeError: The size of tensor a (3) must match the size of tensor b (12) at non-singleton dimension 1
  (routed_experts.py, _load_w2)
```

The routed experts are MXFP4 (`routed_experts_quant_method: mxfp4`). `_configure_ling_fp8_quant_config` reads that from `config.quantization_config`, but the VL model builds its language model from `text_config`, which has no `quantization_config` (it lives on the top-level VL config). The helper returns early, `store_dtype` stays unset, and the experts get `Fp8MoEMethod` instead of `Mxfp4MoEMethod`. The same bug makes the model OOM at TP=1, because FP8 expert buffers are ~2x the MXFP4 size.

This PR makes the helper fall back to the current vLLM config's top-level `hf_config` when the config it receives has no `quantization_config`. Text-only Ling and the MTP draft (whose config already carries `quantization_config`) are unchanged.
