# [Fix][Compile] Declare group_shape in the static FP8 quant fusion …

[Upstream PR](https://github.com/vllm-project/vllm/pull/61108) · state: open · merged: False

## Original PR description


Fix https://github.com/pytorch/test-infra/issues/9053
### Purpose
On recent torch (main, and the 2.15.0 RC from rc3), the fusion passes stop matching static per-tensor FP8 quant: RMSNormQuantFusionPass.matched_count == 0. CI shows it as All nodes remain for op _C::static_scaled_fp8_quant and rms_quant_fusion expected: [12], found: [0] (pytorch/test-infra#9053).

### Root cause

- QuantFP8 calls the static quant op with group_shape=[-1, -1] for per-tensor (input_quant_fp8.py). The shared pattern in MatcherQuantFP8 doesn't declare group_shape at all.
- Older torch matchers silently dropped any kwarg a pattern didn't declare, so this matched.
- pytorch/pytorch#199871 makes the matcher refuse a node that sets an undeclared kwarg to a non-default value, so a replacement can't silently lose it. pytorch/pytorch#200442 extends that check to auto_functionalized by reading the wrapped op's defaults.
- The schema default is group_shape=None, and the graph carries [-1, -1]. So even with #200442 the match is still refused.

### Fix
Declare group_shape in the static quant pattern, taken from the quant key: group_shape=[group_shape.row, group_shape.col]. That's the value QuantFP8 passes, and it's how rope_kvcache_fusion.py and qk_norm_rope_kvcache_fusion.py already write their static quant patterns. The pattern now states exactly what it matches, and it works with both old and new torch.
