# [Bugfix][LoRA] Confine FilesystemResolver to VLLM_LORA_RESOLVER_CACHE_DIR

[Upstream PR](https://github.com/vllm-project/vllm/pull/59474) · state: open · merged: False

## Original PR description

## Purpose

Fixes #59270.

`FilesystemResolver.resolve_lora` built the adapter path with a bare `os.path.join(self.lora_cache_dir, lora_name)`. `lora_name` is the client-supplied `model` field, so `"../x"` or an absolute path (which makes `os.path.join` discard the cache dir) resolved to a directory anywhere on the server, bypassing `VLLM_LORA_RESOLVER_CACHE_DIR`.

The resolver now normalizes the joined path and returns `None` unless it stays inside the cache dir. The check is lexical (`abspath` + `commonpath`) rather than `realpath`, so symlinks an operator places inside the cache (e.g. `cache/my-adapter -> /mnt/adapters/my-adapter`) keep working. Clients can't create symlinks, so `..` segments and absolute names are the actual attack surface.
