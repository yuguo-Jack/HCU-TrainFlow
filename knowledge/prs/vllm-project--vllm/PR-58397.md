# [Tracing] Parent llm_request span to the active FastAPI span

[Upstream PR](https://github.com/vllm-project/vllm/pull/58397) · state: open · merged: False

## Original PR description

## Purpose

Rebased port of #39905 by @faucct, which was approved by @robertgshaw2-redhat, passed full CI, and had auto-squash enabled, but then stalled on merge conflicts once `vllm/entrypoints/openai/generative_scoring/` moved to `vllm/entrypoints/generate/generative_scoring/`. It has had no activity since April and is marked `stale`. The original author is credited with `Co-authored-by`.

When OTel FastAPI instrumentation is active, `_get_trace_headers()` forwards the **inbound** request headers to the engine. The `llm_request` span is built from those headers later, so it never sees the FastAPI server span that is active at that point:

- **No inbound `traceparent`:** `llm_request` starts a second, unrelated trace, so the FastAPI span and the vLLM span end up in separate traces (see the screenshot in #39905).
- **Inbound `traceparent` present (e.g. llm-d):** `llm_request` becomes a sibling of the FastAPI span instead of its child.

Changes:
- `extract_trace_headers()` now builds `traceparent` from the active span when there is a valid one, and keeps any inbound `tracestate`. With no active span, for example when FastAPI instrumentation is not installed, it falls back to the inbound headers as before.
- Generative scoring's `_get_trace_headers()` gets the same structure that the generate and pooling base classes already use: when tracing is enabled it forwards context even if the request has no trace headers.

Both of @markmc's questions on #39905 were answered in that thread. With no active span, `is_valid` is `False`, so behaviour is unchanged. With an upstream `traceparent` (llm-d), the FastAPI span is parented to it, and `llm_request` is now parented to the FastAPI span.

**Duplicate check:** #43005 (@bbartels) addresses the same symptom by adding `inject_current_trace_headers()` in `openai/engine/serving.py`. That file no longer exists on main. #43005 has had no reviews since May and needs a rebase. This PR takes the #39905 approach instead because it was already reviewed and approved, and because it fixes the shared helper, which covers generate, pooling and generative scoring together. Happy to close this in favour of #39905 if @faucct rebases it. #38672 and #33272 (both closed) were large unrelated bundles and were not rejected on the substance of this fix.

## Test Result

- New test fails on `main` (the inbound `traceparent` is forwarded unchanged) and passes with this change.
- `tests/tracing`: 3 passed. Generative scoring unit tests: 10 passed. pre-commit and mypy-3.12 passed.
- Manual SDK check:
  - With an inbound `traceparent`, the forwarded header keeps the inbound trace id and uses the FastAPI span's id as the parent.
  - Without one, it carries the FastAPI span's trace and span id. Before this change it was empty, which created a new trace.
  - With no active span, the inbound headers are forwarded unchanged.
- Not run: `test_traces`, which needs a GPU.
