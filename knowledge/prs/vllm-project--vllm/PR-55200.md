# [Bugfix][Pooling] Validate truncated Jina ranking prompts

[Upstream PR](https://github.com/vllm-project/vllm/pull/55200) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->
## Overview

Reject Jina score/rerank prompts when truncation removes the markers needed to associate embeddings with the query and original documents.

## Claims

- Left truncation can silently relabel surviving document scores from index zero.
- Right truncation can remove the query marker and use a document embedding as the query.
- Validate rendered token IDs before engine dispatch. Marker-preserving truncation remains supported through the shared online/offline render path.

## Validation

Validated on 2026-10-10 at published head `491c21294b` and in a temporary merge with upstream `276fbcff2717bd934cfa37c8a2e4c391f3e7237b`. The published branch was not rebased.

```sh
VLLM_TARGET_DEVICE=cpu CUDA_VISIBLE_DEVICES='' .venv/bin/python -m pytest tests/entrypoints/pooling/scoring/test_jina_ranking_io_processor_unit.py -q
.venv/bin/pre-commit run --hook-stage manual --files vllm/entrypoints/pooling/scoring/io_processor.py tests/entrypoints/pooling/scoring/test_jina_ranking_io_processor_unit.py
```

The focused suite passes **17 tests** on both versions; all applicable scoped hooks pass. Removing the render guard gives **2 marker-loss failures and 4 passing controls**.

**Real model and HTTP evaluation:** published Python source, `jinaai/jina-reranker-v3` (`d7d7e73b6ea138ced340b83865931b5dfb6c97aa`), RTX 5070 Ti, BF16, MRV2, TP1, eager execution, maximum length 1024, existing precompiled extensions. The published 1:1 reference differs by 0.00114; six-document references have maximum absolute error **0.00352**, below tolerance 0.01.

The actual two-document prompt has 221 tokens. Left/right truncation to 220 preserves the markers and yields identical baseline/patched scores. Left truncation to 69 loses a document marker; right truncation to 207 loses the query marker. The baseline returns one misattributed score in both cases; the patch rejects before dispatch.

Across `/score` and `/rerank`, ordinary and preserving-left/right controls produce **6 HTTP 200 results**, retaining both document indices and matching offline scores exactly. Removing-left/right cases produce **4 HTTP 400 results**, `BadRequestError` with `param="truncate_prompt_tokens"`.

GPU results cover the published head; the current-upstream GPU run was not repeated.

## Details

Count expected document markers after prompt sanitization and before rendering, then check the actual rendered IDs. Validation errors replace previously plausible but misattributed scores; callers can shorten input or increase the truncation limit.

Fresh open-PR searches for Jina truncation found no competing fix. Upstream CI is blocked at contributor authorization. AI assistance was used for investigation, implementation, tests, and review.
