# [CI] Group dependency updates into reviewable PRs

[Upstream PR](https://github.com/vllm-project/vllm/pull/59667) · state: open · merged: False

## Original PR description

## Overview

Replace individual pip Dependabot bumps with a weekly artifact containing regenerated requirement locks, and group GitHub Actions and Rust dependency updates. Compilation and publishing use separate jobs; publishing is explicitly disabled while maintainers open lockfile PRs manually.

## Claims

- GitHub Actions updates are grouped into one weekly PR. Minor and patch Rust updates are grouped; `llm-multimodal` and `openai-harmony` stay pinned.
- The compile job reruns the five pre-commit compile commands with `--upgrade`, then without it to preserve their headers, and uploads `requirements.patch` plus `base-sha.txt` for review.
- `GITHUB_TOKEN` has only `contents: read`; checkout credentials are not persisted and the compile job has no App secret or shared dependency cache.
- The publisher is disabled with `if: ${{ false }}`. When enabled, it validates the patch on a fresh runner before creating a repository-scoped GitHub App token to push and open a PR.

## Validation

- `pre-commit run --files .github/workflows/refresh-compiled-requirements.yml .github/dependabot.yml` passed, including actionlint.
- `git diff --check` passed.
- A local temporary-repository harness executed the workflow's artifact-generation and validation shell blocks: all 15 cases passed. Valid updates to one or all five locks produced the expected commit; empty patches skipped publishing. Outside paths, mixed paths, additions, deletions, renames, executable modes, symlinks, malformed patches, stale bases, and missing artifacts were rejected. Git hooks and shell text embedded in lockfiles did not execute. The harness was run with `.venv/bin/python /private/tmp/validate-requirements-workflow.py`; it is local validation, not a committed CI test.
- Full dependency resolution, the artifact service, App authentication, and live publishing have not been exercised end to end. No model execution code changed; model evaluation is not applicable.

## Details

The existing pre-commit commands preserve the repository's `-c`, `--torch-backend`, `--python-platform`, `--index-strategy`, and ROCm `--no-emit-package` arguments. Hand-written requirement pins remain human-managed.

During rollout, maintainers download the weekly artifact, review and apply its patch to the recorded base commit, and open the PR manually. To enable publishing later, configure `REQUIREMENTS_APP_CLIENT_ID` and `REQUIREMENTS_APP_PRIVATE_KEY` for an App installed on this repository with contents and pull-request write permissions, then explicitly change the disabled job condition. An App-backed publisher has write access even though `GITHUB_TOKEN` remains read-only.

The publisher downloads the named artifact from the same workflow run and validates against the workflow's own commit SHA. It applies the patch only to Git's index and permits regular-file modifications only to `requirements/docs.txt` and `requirements/test/{cpu,cuda,rocm,xpu}.txt`. It installs no packages, runs no compile or pre-commit hooks, and disables Git hooks for the commit. Dependency changes still require human review before merging.

This does not duplicate the individual-package Dependabot PRs such as #59570, #41608, and #33056: those update package lines, while this change replaces that updater with regeneration using the repository's compile commands. AI assistance was used, and the `pr-checklist` skill was applied.
