## Overview

Fuse native BF16 ReLU2 + NVFP4 quantization for Nemotron shared experts on SM10x/FlashInfer CuTe-DSL. Reuses the consumer from [#59612](https://github.com/vllm-project/vllm/pull/59612); GEMM is unchanged.

## Claims

- **3 → 2 kernels; 1.08× warm component geomean.**
- Bit-exact packed values and live scales; existing SiLU/LoRA fallbacks preserved.

## Validation

**C50 serving:** one GB200, TP1 aggregated, ISL/OSL 2048/1024; six 100-request trials across two processes per implementation, with fixed compiler settings:

| Output tokens/s | Baseline | Fused |
|---|---:|---:|
| Median [min–max] | 2,359 [2,332–2,385] | 2,375 [2,360–2,406] |

Observed **+0.66% median**, +0.84% matched geomean; matched changes −0.49% to +1.91%, including two slower trials. All 1,200 requests succeeded. Ranges overlap: this is **not a robust serving-speedup claim**. Separate short CUDA traces show 320 fewer launches with unchanged GEMM counts.

**GSM8K:** four full runs—two per implementation, GPU crossover—all score **1,209/1,319 (91.66%)**, with identical per-question records and token sequences. 5-shot, max 256 tokens; zero invalid answers, 16 capped per run. This is controlled-cohort evidence, not population noninferiority.

**Correctness (`462744b0`):** 325 GPU checks pass, no failures/skips; pre-commit and mypy pass. A full-model oracle checks 707,680 fused calls with zero packed-value/scale/padding errors and no producer compilation after startup. Its instrumented GSM8K score is 90.75% with async scheduling/stochastic Mamba rounding; not a paired accuracy comparison.

## Details

Reuses QuantizedActivation/startup warmup; opaque dispatch preserves dynamic rows under guard-free Dynamo. Native ReLU2 only; the separately selected CUDA activation is unchanged. No scheduler, runner or dependency changes. The component gain must be weighed against 400 production additions (269 in the producer) and modest end-to-end benefit.

Distinct from routed-MoE [#56740](https://github.com/vllm-project/vllm/pull/56740), GELU [#59467](https://github.com/vllm-project/vllm/pull/59467) and normalization [#61073](https://github.com/vllm-project/vllm/pull/61073). No DISAGG, TP>1 or default-stack performance claim. GPU validation ran outside CI; upstream CI still needs [contributor authorization](https://github.com/vllm-project/vllm/actions/runs/37487663579/job/112351835909).
