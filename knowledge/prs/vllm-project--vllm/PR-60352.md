# [Multimodal][Voxtral] Keep raw audio waveforms in fp32

[Upstream PR](https://github.com/vllm-project/vllm/pull/60352) · state: open · merged: False

## Original PR description



## Overview

Voxtral's processor returns raw waveforms (`audio_arrays`), and `call_hf_processor` casts every float output to the model dtype. With `--dtype bfloat16` the log-mel is computed from bf16 audio. This lets a processor keep named fields out of that cast; Voxtral opts in for `audio_arrays`.

## Claims

- `audio_arrays` reaches Voxtral in fp32 under a bf16 model. Before this change it was bf16.
- The log-mel is computed from full-precision audio, as in transformers and mistral-common.
- No change for any other model (the default is an empty set).

## Validation

Processor output dtype, `mistralai/Voxtral-Mini-3B-2507`, `dtype="bfloat16"`, current main:

| | `audio_arrays` dtype |
|---|---|
| main | `torch.bfloat16` |
| this PR | `torch.float32` |

Effect on the mel: `VoxtralEncoderModel.compute_whisper_melspec` on 18 TED-LIUM clips (CPU), bf16 vs fp32 waveform input: max abs diff 0.244 and mean relative L2 8.4e-3 (mel range is about [-1.5, 1.5]).

New unit test: `tests/multimodal/test_processing.py::test_call_hf_processor_keep_dtype_keys`.

<details>
<summary>Reproduce</summary>

```python
from vllm.config import ModelConfig
from vllm.multimodal import MULTIMODAL_REGISTRY
from vllm.multimodal.processing.context import TimingContext

mc = ModelConfig("mistralai/Voxtral-Mini-3B-2507", tokenizer_mode="mistral", dtype="bfloat16")
proc = MULTIMODAL_REGISTRY.create_processor(mc)
inputs = proc.get_dummy_inputs(seq_len=2048, mm_counts={"audio": 1}, mm_options={})
res = proc.apply(inputs, TimingContext(enabled=False))
print(res["mm_kwargs"].require_data()["audio"][0].get_data()["audio_arrays"].dtype)
```
</details>

## Details

Root cause: `InputProcessingContext._postprocess_output` mirrors `BatchFeature.to(dtype)`, which is right for features (`pixel_values`, `input_features`) but not for a raw waveform that the model turns into features itself. Voxtral also casts the mel to the model dtype after computing it, so this only changes the mel's input precision.

Design: a `keep_dtype_keys` class attribute on `BaseMultiModalProcessor`, passed through `call_hf_processor`. Kept opt-in and per-field to avoid changing other models. Other processors that return raw audio could opt in the same way. I have only validated Voxtral.

No end-to-end WER number is included. I did not have a GPU run of Voxtral before and after for this PR.
