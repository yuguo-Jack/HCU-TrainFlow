# [Rust Frontend] Build the Kimi K3 full-output grammar from its parser mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/59190) · state: closed · merged: True

## Original PR description

## Purpose

Kimi K3 grammars only cover the output after reasoning. `KimiK3StructuralTagBuilder` takes a `reasoning` option that stands for both the request's thinking mode and the grammar's starting point, so the engine's reasoning gate decides when the grammar activates. The builder also requires a response channel on every path, which rejects tool calls directly after reasoning.

Step 3 of the parser-owned output grammar rollout, following the grammar replay harness (#59143), the argument grammar split (#59395), and the shared schema root (#59408), all merged. The Kimi K3 parser already derives its starting channel from the prompt. This PR builds the whole generation's grammar from that initialized mode, so the engine constrains K3 from token zero (`reasoning_ended = Some(true)`). The open-PR search found no other Rust K3 full-output grammar work; token-aware K3 parsing (#58358, merged) is a separate track.

- New `unified/kimi_k3/grammar.rs` builds the topology from `KimiK3Mode`:

  | Tool choice | After `think` closes | After `response` closes |
  | --- | --- | --- |
  | `auto` | `response [tools]`, or `tools` | `[tools]` |
  | `required` | `[response] tools` | `tools` |
  | named | `[response] tools`, one call | `tools`, one call |

  A prompt-opened `think` or `response` channel continues its body. A prompt that opened no channel may first emit a whole `think` channel. Every path may end with the message close. Named choices and `parallel_tool_calls=false` allow one call.
- Free-text regions keep today's string-level exclusions, which stay within what the token-aware parser (#58358) accepts. Token-level exclusions are a follow-up.
- `KimiK3StructuralTagBuilder` is removed. Its call tag and `XtmlArguments` syntax, with the `xtml_type` mapping from #59408, move into `grammar/arguments.rs`. The call tag no longer reads the builder's `any_order` and `max_whitespace_cnt` options, so it uses their defaults, as the serving path already did.
- Model-owned grammars normalize the request's tools with `xgrammar_structural_tag::normalize_tool_choice`, public since 0.4.1 (bumped in #59148). This is the same normalization `build_structural_tag` applies before a crate builder, so K3 sees the same tools, `BuilderToolChoice`, and validation errors as builder-backed models.

Out of scope: answer constraints (Step 4) and the ordinary-chat grammar skeleton. Requests without a tool grammar still get none.

## Test Result

- Grammar replay (#59143): Kimi K3 changes from compile-only to token-zero replay for all three variants, with its arguments rendered through #59395. All 36 cases pass with the harness's pinned XGrammar 0.2.7 and with 0.2.8, the version `requirements/common.txt` serves.
  - `auto`: 130 tokens from inside `think`, through `response` and `tools`, then terminated.
  - `required`: 124 tokens, with `tools` directly after `think`, which the removed builder rejected.
  - Named: 59 tokens with one call.
- `vllm-parser` + `vllm-chat`: 947 tests passed. Workspace Clippy and rustfmt passed.
- No GPU end-to-end run yet. Model evaluation of the token-zero K3 grammar is pending.
