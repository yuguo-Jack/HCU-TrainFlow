# [Bugfix] Match dotted fused layer names in quantization configuration

[Upstream PR](https://github.com/vllm-project/vllm/pull/60746) · state: open · merged: False

## Original PR description

## Overview

Fix quantization configuration matching for fused layer names such as `attn.qkv`. Settings for the separate Q, K and V layers now apply to the combined layer.

## Claims

- Recognize fused names containing dots, including Qwen2.5 Omni and Cohere ASR mappings.
- Match whole names and leave earlier parts of the layer name unchanged.
- Keep direct layer-name matches unchanged. Continue checking that settings agree across the individual layers combined into a fused layer.

## Validation

`.venv/bin/python -m pytest tests/quantization/test_config_utils.py -q`

| Code | Result |
| --- | --- |
| Original, with regression tests | 4 failed, 20 passed |
| Patched | 24 passed |

Tested `Qwen/Qwen2.5-Omni-3B` on a Tesla T4 with a custom online FP8 configuration. Before the fix, settings that targeted the separate Q, K and V layers left `visual.blocks.0.attn.qkv` unquantized. After the fix, the combined layer uses the intended FP8 method. On three image prompts, its generated tokens match those from targeting the combined layer directly.

## Details

The old lookup reduced `visual.blocks.0.attn.qkv` to `qkv`, missing the mapping stored as `attn.qkv`. The fix checks the full mapping key at the end of the layer name, requiring a preceding dot when more of the name comes before it. It replaces only that ending, avoiding changes to repeated names earlier in the string.

Open-PR searches on 2026-10-08 found no equivalent fix. #48564 changes WeightsMapper remapping, a different code path.
