# Use NCCL2 peer groups and reuse singleton world group

[Upstream PR](https://github.com/vllm-project/vllm/pull/60720) · state: closed · merged: False

## Original PR description

Co-authored-by: OpenAI Codex <codex@openai.com>

Signed-off-by: Tushar Jain <tushar00jain@users.noreply.github.com>

### Summary

#### NCCL2 peer groups

Fix pipeline-parallel group creation when `split_group` is enabled. NCCL pipeline-parallel groups now consistently use `new_group` instead of `split_group`.

For the NCCL2 path, the device group uses `nccl-lazy`, which creates lazy per-peer communicators.

This allows pipeline-parallel communication with different peers to overlap instead of serializing through one shared communicator.

####  Reuse singleton world group

Avoid creating a redundant device `ProcessGroup` when distributed world size is one. Instead, reuse the default world group while retaining a separate Gloo group for CPU coordination.

This prevents NCCL2 eager initialization from registering memory for an unused singleton communicator, reducing avoidable GPU memory consumption and preventing OOMs in single-rank tests.

The split-group path now falls back appropriately for singleton groups, and group teardown avoids destroying the shared world group.

### Test Plan

- Verified NCCL2 singleton group construction reuses the default WORLD
  device ProcessGroup and creates no additional NCCL2 device groups.
- Measured incremental GPU memory for seven singleton logical groups:
  0 MiB after the fix, versus approximately 2.3–2.7 GiB with the old
  behavior.
- Verified pipeline-parallel groups use ProcessGroupNCCLLazy.
- Verified disjoint pipeline-parallel P2P transfers overlap.

## Results on the torch 2.15.0 RC (nccl2 on)

I tested this change on the torch 2.15.0 RC PR #60324 (commit `c75b0acf8a`, nccl2 enabled). Run: [#93726](https://buildkite.com/vllm/ci/builds/93726). It fixes the single-rank case. Multi-rank jobs on L4 still fail the startup free-memory check by a small margin.

**Startup free-memory check failures (pytorch/test-infra#8940)**

| Run | Setup | Jobs failing the check | GPU memory already used at startup |
|---|---|---|---|
| [#93300](https://buildkite.com/vllm/ci/builds/93300) | nccl2, without this PR | 120 | ~2.9 GiB |
| [#93464](https://buildkite.com/vllm/ci/builds/93464) | `TORCH_DIST_USE_NCCL2=0` (legacy NCCL) | 0 | 0.1–0.3 GiB |
| [#93726](https://buildkite.com/vllm/ci/builds/93726) | nccl2 **with this PR** | **17** | single-rank 0.67–0.85 GiB; L4 multi-rank ~1.9 GiB |

**Single-rank: fixed.** Reusing the WORLD group removes the eager communicators for singleton groups. All the H200 MIG jobs that used to fail now pass, with 0.67–0.85 GiB in use at startup (e.g. [`(H200 MIG 18GB) Basic Correctness Models 1`](https://buildkite.com/vllm/ci/builds/93726#01a11dda-715d-4545-af91-f355d09aff15)). That's still about 0.5 GiB more than legacy NCCL, but within budget.

**Multi-rank (TP/DP ≥ 2) on L4: still failing.** 15 L4 distributed jobs start with **~1.89–1.92 GiB** already in use. At `gpu_memory_utilization=0.92` on a 22.03 GiB L4, at most ~1.76 GiB can be in use, so they miss by 130–160 MiB per GPU:

```
ValueError: Free memory on device cuda:0 (20.14/22.03 GiB) on startup is less than desired GPU memory utilization (0.92, 20.27 GiB).
```

Examples: [`(L4) Distributed Torchrun + Examples`](https://buildkite.com/vllm/ci/builds/93726#01a11e2b-0fef-4d1c-9dd6-401bab9f281b), [`(L4) Pipeline + Context Parallelism`](https://buildkite.com/vllm/ci/builds/93726#01a11e47-adff-47b7-89a6-f555a6fee567), [`(L4) RayExecutorV2`](https://buildkite.com/vllm/ci/builds/93726#01a11e44-f7ee-4430-878c-d1d1bf305611). Also Distributed Compile + Comm/RPC, DP Basic/Extended, Models Shard 1/2, Torchrun + Shutdown, LoRA TP (Distributed) 2/3, Plugin Integration and Rust Frontend Distributed. Twelve of these passed with legacy NCCL on #93464, so what remains is still the nccl2 communicators for the multi-rank groups.

The same memory pressure also shows up as OOMs: `(H100) Fusion E2E TP2 Quick` ([job](https://buildkite.com/vllm/ci/builds/93726#01a11dda-718e-4ed0-bde6-8ff67dd96988), passes with legacy NCCL), `(H200 MIG 18GB) Multimodal Processor Shard 2/4` and `(B200) LM Eval Qwen3.5 Models`. One job, [`(L4) Distributed DP Extended`](https://buildkite.com/vllm/ci/builds/93726#01a11e4a-afa1-4b36-a21b-424c4f573cdc), also hits the nccl2 `Failed to initialize NCCL communicator: unhandled cuda error` from pytorch/test-infra#9006.

**Possible next steps for multi-rank:** create communicators lazily for groups that are rarely used (DP/EP/DCP/PCP at size 1–2), share NCCL resources across split communicators (`NCCL_COMM_SPLIT_SHARE_RESOURCES=1`), or the torch-side fix in pytorch/pytorch#199957.

Not related to this PR, for completeness: `(H100) Distributed Features` has ~25.6 GiB left over from an earlier test in the same job (pytorch/test-infra#9052), and the Inductor fusion-pass failures from pytorch/test-infra#9053 do not reproduce on the 2.15 RC.
