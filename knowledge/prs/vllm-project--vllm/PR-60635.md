# [KVConnector] Track MultiConnector completion owners independently

[Upstream PR](https://github.com/vllm-project/vllm/pull/60635) · state: open · merged: False

## Original PR description

## Overview

Prevent one MultiConnector child from losing another child's completion or releasing KV blocks while another load/save owner is still using them. Extracted from #58968 onto main; independent of ROCm and of the two MRV2 fixes split from that PR.

Rebased onto main `bfa7e5b7afe40ebe48288801a2baf5c1135cd881`. This remains an independent child of closed #58968.

## Claims

- Keep request, child and distinct worker-rank identities through send completion aggregation, including completions received before request finish.
- Reconcile each child's completion independently; release a finished request only after all registered load/save owners finish.
- Preserve nested receive completions and wait for newly registered partial-tail saves without reusing an earlier save's ACK.

```text
child/rank completion -> that child's completion state
all request owners complete -> scheduler may release KV blocks
```

## Details

Previously, children mutated the same aggregated `KVConnectorOutput`, and additional saves were counted without preserving their child identity. A MoRI producer could filter an LMCache completion absent from its own deferred-send records; a scheduler-generated child completion could bypass another child's outstanding save. The scheduler treats a surfaced send completion as permission to free blocks.

Worker metadata now carries per-child rank sets. Scheduler-side ownership reconciles child callbacks and preserves non-completion error/stat/event updates. This uses existing connector APIs, adds no GPU synchronization, and retains main's loaded-group and cache-hit-source delegation.

This replaces the corresponding section of #58968. #52954 filters unexpected request-level sends; it does not isolate child callbacks, reconcile multiple owners or track distinct ranks across steps. #51864 filters receives from unselected loaders; #51595 introduces counting for future composed loads. This change does not enable multiple loaders or claim to resolve those separate selection contracts.

**Merge impact:** reversible code change; shared MultiConnector completion bookkeeping. Child connectors must still report their own transfer completion correctly. Single-connector deployments do not use this aggregation.

AI assistance was used for implementation, rebase, regression checks and this description. Human line-by-line review and the runtime acceptance items above remain pending. No performance improvement is claimed.
