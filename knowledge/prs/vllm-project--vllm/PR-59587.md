# bench: add --metrics-url override for metrics scraping behind a router

[Upstream PR](https://github.com/vllm-project/vllm/pull/59587) · state: open · merged: False

## Original PR description

## Problem

`vllm bench serve` collects speculative-decoding (and diffusion) stats by scraping `{base_url}/metrics` before and after the run (`fetch_spec_decode_metrics` / `fetch_diffusion_metrics`). When the benchmark targets a **PD-disaggregated deployment through `vllm-router`**:

- `{router}/metrics` is not proxied to the backends (it answers `405 Method Not Allowed`),
- the actual `vllm:spec_decode_*` counters live on the **decode instance**,

so `fetch_spec_decode_metrics` returns `None` and every PD benchmark silently loses the acceptance section — no error, no hint.

## Change

Add an optional `--metrics-url` that overrides where server metrics are scraped from (defaults to the request base URL = previous behavior). For PD, point it at the decode instance.

## Verification (two-node DeepSeek-V4.1-Flash P/D, vllm-router front-end, DSpark speculative decoding in both pools)

Without the flag (status quo):

```
Successful requests: 4        # ... but no Acceptance section at all
```

With `--metrics-url http://<decode-node>:8123`:

```
Successful requests:                     4
Acceptance rate (%):                     28.62
Acceptance length:                       2.43
  Position 0:                            60.24
  Position 1:                            35.86
  Position 2:                            21.89
  Position 3:                            14.67
  Position 4:                            10.41
```

Also confirmed directly: `curl {router}/metrics` → `405`; `curl {decode}/metrics` → 8 `vllm:spec_decode_*` series present.
