# [Attention] Set ALWAYS cudagraph support for FA4

[Upstream PR](https://github.com/vllm-project/vllm/pull/60908) · state: open · merged: False

## Original PR description

# Summary
This PR enables `AttentionCGSupport.ALWAYS` cudagraph support for Flash Attention 4. The primary motivation is to enable adaptive verification (AV) with MiMo-V2.5-Pro-FP4 + DFlash using the default attention backend (`FLASH_ATTN_DIFFKV`) on GB200.

`AttentionCGSupport.ALWAYS` means a FULL cudagraph captured for one batch layout can be replayed for any other layout with the same token count, including mixed prefill+decode batches and variable per-request query lengths. That holds for FA4 for three reasons:

1. No host-side scheduling state. Unlike FA3, FA4 builds no AOT scheduler metadata (aot_schedule is gated on fa_version == 3). All per-batch tiling is derived on device from cu_seqlens_q/seqused_k inside the captured kernels, so replays with a different layout recompute it correctly.
2. The grid does not depend on per-request lengths. The varlen tile scheduler sizes its grid from total_q (the padded token count, fixed per graph) and the batch size, not from max_seqlen_q.
3. Host-side specializations are conservative under an upper bound. FA4 does specialize on the host max_seqlen_q: it selects q_stage and, when max_seqlen_q * qhead_per_kvhead <= q_stage * tile_m, a static persistent scheduler that assumes at most one M-block per request. These are correct for any replay whose real query lengths do not exceed the captured max_seqlen_q. The runners guarantee that: mixed FULL graphs are captured with max_query_len = num_tokens, the worst case for the token count (MRV2 prepare_inputs_to_capture, V1 _dummy_run); decode and varlen-decode graphs are captured with the decode width and only replay batches within it; and dispatch matches a graph only when its max_query_len covers the batch.

FA2 still needs `AttentionCGSupport.UNIFORM_BATCH` because of its packed-GQA special case for max_query_len == 1 captures.

# Test Plan
- Kernel-level graph-replay checks, FA4 on GB200, MiMo-V2.5-Pro TP4 attention geometry (32/2 heads, head dims 192/128, SWA 128 with sinks, page sizes 16/64):
  - Varlen-decode replay (42 configs) and mixed prefill+decode full-graph replay (18 configs) both match eager bit-for-bit, including captures with tiny max_seqlen_k.
  - A negative control that captures with max_seqlen_q below the replayed lengths fails (max abs error 2.05), so the checks detect a broken replay.
- Without AV: Qwen3-8B gsm8k with FLASH_ATTN + cudagraph_mode=FULL, main vs PR: 88.48% vs 88.55%, within noise.
- With AV: MiMo-V2.5-Pro-FP4 + DFlash gsm8k (full 1319 questions), AV off vs on: 95.83% vs 96.29%, within noise. It also starts and serves coherent output with no attention overrides.
