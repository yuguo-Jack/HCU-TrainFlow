# [Bugfix][Parser] Preserve quoted think markers in Kimi K3 non-streaming responses

[Upstream PR](https://github.com/vllm-project/vllm/pull/60655) · state: open · merged: False

## Original PR description

## Overview

Kimi K3 can lose or truncate non-streaming JSON content when a response-only answer quotes a think marker. This fix recognizes the actual response control tokens before searching the answer for reasoning markers, preserving the complete JSON and any following tool calls.

Supported workflow: non-streaming K3 output beginning with the response control prefix, through the unified parser used by Chat Completions and Responses. For example, `{"marker":"<|open|>think<|sep|>"}` currently produces reasoning `"}` and no content; the fix returns the original JSON in `content`.

## Claims

- Preserve JSON string values containing either a think opener or closer after the response control prefix.
- Keep ordinary text spelling a response opener in completed reasoning, including when the prompt already supplied the think opener.
- Reuse K3's existing content cleanup and tool extraction, without changing shared parser interfaces or streaming behavior.

<summary>Minimal CPU reproduction</summary>

Run in a dependency-prepared vLLM checkout. Only the pinned official tokenizer is loaded; no model weights are needed. Encode the response wrapper as control tokens and the JSON string as ordinary text.

```python
from transformers import AutoTokenizer
from vllm.entrypoints.openai.chat_completion.protocol import ChatCompletionRequest
from vllm.parser.kimi_k3 import KimiK3Parser
from vllm.reasoning.kimi_k3_reasoning_parser import KimiK3ReasoningParser

class K3(KimiK3Parser):
    reasoning_parser_cls = KimiK3ReasoningParser

tokenizer = AutoTokenizer.from_pretrained(
    "moonshotai/Kimi-K3",
    revision="f831ab66814297da540d832a5235f8e904f29d06",
    trust_remote_code=True,
)
request = ChatCompletionRequest(model="kimi-k3", messages=[])
for marker in ("<|open|>think<|sep|>", "<|close|>think<|sep|>"):
    body = f'{{"marker":"{marker}"}}'
    ids = (tokenizer.encode("<|open|>response<|sep|>")
           + tokenizer.encode(body, allow_special_tokens=False))
    result = K3(tokenizer).parse(
        tokenizer.decode(ids), request, model_output_token_ids=ids,
    )
    print(result)
    assert result == (None, body, [])
```

Both assertions fail on base `29ae81fe` and pass with the fix. The tracked regressions also guard the inverse case: ordinary response-marker text inside reasoning must not become final content, and a tool call following the quoted-marker JSON must survive.

## Details

The current K3 non-streaming extractor searches decoded text for think markers. Its response-only fallback runs only when neither think marker appears, so quoting one inside valid JSON defeats that fallback. A decoded response opener alone is not sufficient evidence of a channel transition: ordinary reasoning can spell the same characters.

The serving layer already passes generated token IDs to `KimiK3Parser.parse`. The fix checks only the leading response token sequence there, then uses the existing content cleanup and tool handoff. Other inputs retain the inherited path. The extra method stays local to K3; changing the shared reasoning-parser interface or migrating the parser engine is unnecessary. Calls without token IDs retain the pre-existing text-only behavior.

This investigation followed JSON failures in Moonshot AI's official [Kimi Vendor Verifier (KVV)](https://github.com/MoonshotAI/Kimi-Vendor-Verifier). The endpoint's engine/version was unavailable. The reproduction establishes a vLLM source defect, not the cause of those endpoint failures.

With the streaming fix in [#60565](https://github.com/vllm-project/vllm/pull/60565) at `16bcdb5`, both quoted-marker JSON samples parse correctly when streamed, including one-token and whole-output delivery, but still fail in that revision's non-streaming path. This PR fixes the non-streaming path; streaming, grammar gating and token accounting are unchanged. The pre-existing handling of quoted response-close markers and text before the response opener remains outside this fix. Model inference and actual grammar-mask execution have not been exercised.

Related work: [#57098](https://github.com/vllm-project/vllm/pull/57098), [#57366](https://github.com/vllm-project/vllm/pull/57366) and [#50291](https://github.com/vllm-project/vllm/pull/50291) address truncated or markerless reasoning. Their inspected changes do not preserve JSON quoting think markers after a leading response control prefix. Source baseline: [29ae81fe](https://github.com/vllm-project/vllm/commit/29ae81fe83712bb74c00a4ce0515d031f1225c9b).
