# [Chore] Remove vendored code made redundant by Transformers 5.16.1

[Upstream PR](https://github.com/vllm-project/vllm/pull/60623) · state: closed · merged: True

## Original PR description

## Overview

Now that the minimum Transformers version is 5.16.1, delete vendored configs, a processor and compat shims that upstream Transformers now provides, porting the model code to the upstream config schemas. Also adds a `transformers-upgrade` agent skill so this unvendoring pass happens on every future floor raise.

## Claims

- Deletes 16 vendored configs (`afmoe`, `AXK1`, `cosmos3`, `diffusion_gemma`, `granite4_vision`, `hy_v3`, `hyperclovax`, `kimi_k25`, `lfm2_moe`, `nemotron`, `nemotron_h`, `olmo_hybrid`, `qwen3_5`, `qwen3_5_moe`, `qwen3_next`, and `AIMv2Config` in `ovis.py`), the vendored `Granite4VisionProcessor`, and dead shims for older Transformers versions:
  - the `ALLOWED_LAYER_TYPES` patch;
  - the Transformers v4 rope branches in `gemma3`, `gemma3n` and `modernbert`;
  - the `audio_token` fallbacks in `granite_speech`.
- Model code reads the upstream fields instead:
  - kimi_k25 vision position embeddings and projector size;
  - Cosmos3-Edge `layers_block_type`;
  - Gemma 4 MoE from `num_experts`.
- Fixes A.X-K1 silently ignoring the checkpoint's YaRN rope scaling. The vendored `AXK1Config` dropped `rope_scaling`, so vLLM ran with plain RoPE at `max_position_embeddings=131072`.
- Fixes `get_processor` for HF-format InternVL checkpoints (e.g. `OpenGVLab/InternVL3-1B-hf`). The vendored processor was registered under the upstream name `InternVLProcessor`, which hijacked lookup and raised `TypeError: ... missing ... 'image_seq_length'`. The vendored class still serves the original `internvl_chat` checkpoints.
- `hyperclovax` and `kimi_k25` register the upstream classes in `_CONFIG_REGISTRY`, so `--trust-remote-code` keeps using them. Their hub remote config is broken (HyperCLOVAX) or uses an old schema (Kimi).
- Adds the `transformers-upgrade` skill, with scripts that:
  - list vendored code upstream now covers (`find_upstreamed.py`);
  - dump the config and the meta-device model vLLM builds, before and after a change (`dump_configs.py`, `dump_model.py`), and diff the two (`diff_dumps.py`).

## Validation

`main` vs this branch, `transformers` 5.19.0. Each registry checkpoint was built on the meta device with dummy weights (`dump_model.py`): ModelConfig sizes, every parameter shape, and every module's scalar attributes.

| Checkpoint | Model diff vs `main` |
|---|---|
| `google/gemma-4-E2B-it`, `gemma-4-26B-A4B-it`, `gemma-4-31B-it`, `gemma-4-12B-it` | 0 |
| `google/diffusiongemma-26B-A4B-it` | 0 |
| `Qwen/Qwen3.5-0.8B` | 0 |
| `nvidia/Cosmos3-Nano` | 0 |
| `skt/A.X-K1` | YaRN applied: `layers.*.self_attn.scaling` 0.0722 → 0.1309 (x61) |

The resolved configs (`dump_configs.py`) of these checkpoints only gain upstream defaults or rename fields; no value the model code reads changes, A.X-K1 aside:
- Qwen3.5 (0.8B, 4B, 35B-A3B), Qwen3-Next, LFM2, Olmo-Hybrid, Trinity, Minitron, Nemotron-Mini, Nemotron-H (3 checkpoints), Hy3-preview, HyperCLOVAX, Kimi-K2.5/K2.6, granite-vision-4.1, Cosmos3-Edge, Ovis2-1B.

A.X-K1 is 1 TB in bf16, which doesn't fit on the test host's disk, so the YaRN fix is checked on [`thkim93/axk1-2layers`](https://huggingface.co/thkim93/axk1-2layers), a 2-layer cut of A.X-K1 with the same rope config. The check compares teacher-forced prompt logprobs over 2048 tokens of English text, with vLLM measured against the HF Transformers implementation (which applies YaRN), 1x B200, bf16. Absolute logprobs are meaningless for a 2-layer model; only agreement with HF matters.

| Tokens | mean \|Δ logprob\| vs HF, `main` | mean \|Δ logprob\| vs HF, branch |
|---|---|---|
| 0-256 | 0.044 | 0.028 |
| 256-1024 | 0.052 | 0.026 |
| 1024-2047 | 0.058 | 0.027 |

With the fix, vLLM sits at the bf16 noise floor across all positions. `main`'s error is twice as large and grows with position, as expected from missing YaRN. A full-model gsm8k comparison is still pending.
