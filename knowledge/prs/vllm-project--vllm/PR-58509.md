# [ROCm][Perf] HY4 preview perf boost

[Upstream PR](https://github.com/vllm-project/vllm/pull/58509) · state: open · merged: False

## Original PR description

## Purpose
Improve the performance of HY 4 preview FP8 on ROCm platform. What this PR contains:

1. Enable AITER MoE for HY4 FP8. Actually AITER FP8 MoE already supports Silu activation, so we just change the vLLM side code to utilize it;
2. Rewrite iHC kernels with Triton to replace the default PyTorch impl (with fusions);

## Test Plan
**Server side:**
export VLLM_ROCM_USE_AITER=1
vllm serve tencent/Hy4-preview-FP8  \
  -tp  8 \
  --tool-call-parser hy_v4 \
  --enable-auto-tool-choice \
  --reasoning-parser hy_v4 \
  --max-model-len 65536 \
  --moe-backend aiter

**Client side:** 
vllm bench serve \
  --model tencent/Hy4-preview-FP8  \
  --host localhost \
  --port 8000 \
  --dataset-name random \
  --random-input-len 1024 \
  --random-output-len 1024 \
  --num-warmups 5 \
  --num-prompts 100 \
  --max-concurrency 32

**accuracy:**
lm_eval \
  --model local-chat-completions \
  --apply_chat_template \
  --tasks gsm8k \
  --num_fewshot 10 \
  --output_path ./results \
  --log_samples \
  --model_args model=/data/tencent-Hy4-preview-FP8/,base_url=http://localhost:8000/v1/chat/completions,num_concurrent=32,max_retries=3,timeout=3000,seed=1234,temperature=0 \
  --gen_kwargs '{"temperature": 0.0, "thinking_token_budget": 0, "chat_template_kwargs": {"reasoning_effort": "no_think"}}'
