# [Frontend][Metrics] Count requests cancelled by client disconnect

[Upstream PR](https://github.com/vllm-project/vllm/pull/60135) · state: open · merged: False

## Original PR description



## Overview

Adds `vllm:http_requests_client_disconnected_total`, a counter of HTTP requests whose client disconnected before the response was complete. There is currently no metric that shows how often clients cancel requests.

Related: #55634, #55940.

## Claims

- A client that closes the connection mid-response (streaming or non-streaming) increments the counter once.
- Completed requests, including several on one keep-alive connection, do not increment it.
- No engine, scheduler, or output-processor changes: the counter lives in a 59-line ASGI middleware.

## Validation

|---|---|---|
| 5 streaming chat completions, closed after 3 chunks | +5 | +5 |
| 3 non-streaming chat completions, closed while generating | +3 | +3 |
| 2 streaming completions, closed after 3 chunks | +2 | +2 |
| 4 streaming chat completions, read to completion | +0 | +0 |
| 4 non-streaming chat completions, completed | +0 | +0 |

In the same run `vllm:request_success_total{finished_reason="abort"}` stayed at 0, which is the gap reported in #55634.

## Details

**Why this is not a duplicate of #55940.** #55940 makes the existing `finished_reason="abort"` series record engine-level aborts, whatever their cause (client disconnect, internal error in `generate()`, engine-initiated abort). This PR counts only disconnects observed at the HTTP layer, where the cause is known, and it shares no code with #55940. The two are complementary. No other open PR or issue adds a client-disconnect metric (searched `client disconnect metric`, `cancelled requests metric`, `disconnected counter prometheus`).

**How it works.** The middleware wraps the ASGI `receive` and `send` callables. An `http.disconnect` message seen before the final response body counts as a client cancellation. Servers also report `http.disconnect` after a response completes, so the final body message marks the request finished first. Servers implementing ASGI spec >= 2.4 raise `OSError` from `send` on a closed connection instead; that is counted too.

**Limitations.**

- Counts HTTP requests, not engine requests: a request with `n > 1` or several prompts is one cancellation.
- A disconnect is only observed while something awaits it, which is the case for streaming responses and handlers using `with_cancellation`. Other handlers are not cancelled by a disconnect today and are not counted.
- No labels (model, endpoint).
- Python API server only; the Rust frontend is not covered.

**Import placement.** `PrometheusStatLogger.__init__` unregisters every `vllm:`-prefixed collector, so the middleware module is imported inside `init_entrypoints_middleware` (after engine start), as `WebSocketMetricsMiddleware` already is.
