# [Perf] Reduce RMSNorm metadata work

[Upstream PR](https://github.com/vllm-project/vllm/pull/60688) · state: open · merged: False

## Original PR description

## Overview

Reduce CPU work during compilation for the shared RMSNorm and fused add RMSNorm IR ops. Infer their output metadata with fewer fake tensor operations.

## Claims

- Reduce norm fake-call time by 21–22% in the tested Qwen3.8-27B startup, saving about 0.5 seconds per GPU worker.
- Keep the real normalization formulas and provider selection unchanged. Add metadata checks to the existing test file.

## Validation

Qwen3.8-27B, BF16, TP=2, two H100 80 GB GPUs, Torch 2.13.0+cu130. Both runs used fresh vLLM, Inductor, and Triton compile caches, with one compile thread per worker. The model settings were 16,384 maximum context tokens, 32 sequences, and 8,192 batched tokens.

| Norm metadata work | Baseline | Change | Reduction |
| --- | ---: | ---: | ---: |
| Worker 0, 535 calls | 2.418 s | 1.886 s | 22.0% |
| Worker 1, 535 calls | 2.396 s | 1.887 s | 21.2% |

This was one baseline/change pair. Worker times overlap, so their savings must not be added. These numbers measure norm metadata work. A reliable total startup gain is not established by this pair.

Five prompts were run twice per version. Answers, token IDs, and reported log probabilities matched exactly. The prompts covered arithmetic, a factual answer, code, and an explanation.

Focused CUDA test run: **19 passed**. This includes ten new metadata cases and nine existing native/CUDA opchecks across FP16, BF16, and FP32. The root `conftest.py` was excluded from this isolated run.

```bash
.venv/bin/python -m pytest tests/kernels/ir/test_layernorm.py \
  --confcutdir=tests/kernels/ir \
  -k 'norm_fake_metadata or (test_torch_opcheck and 1e-05-2048-8 and (native or vllm_c))' -v
```

After the main update, the exact fake functions passed 104 CPU metadata cases with PyTorch 2.14.1. These cover layouts, broadcasts, dtypes, aliases, symbolic shapes, and fallback inputs. The probe does not load vLLM IR registration. The production and test files are unchanged. All applicable pre-commit hooks passed. GPU and model checks were not rerun; the measurements above retain their recorded scope. Upstream test CI is blocked by the contributor gate.

## Details

During compilation, PyTorch uses fake tensors to track shape, data type, and memory layout. They do not contain model values. The current fake path follows the full normalization formula. Squaring, averaging, adding epsilon, and taking an inverse square root each add work to calculate metadata.

This change uses a fake scale tensor with the required shape. It keeps the casts, weight multiplication, and residual addition that determine the output metadata. The real model still uses the same normalization math when it processes requests.

Scalar inputs, non-strided inputs, and explicit `variance_size` inputs keep the native fake path. The fused path also retains it for non-strided residuals. This reduces work per norm call; the asymptotic complexity stays unchanged.

Open PR and issue checks found no PR for this fake metadata shortcut. Related [native compilation work](https://github.com/vllm-project/vllm/pull/38775) changes executable implementations. This change only reduces metadata work in the fake path.
