# [Bugfix][Model] Fix crash loading Mamba/Mamba2 checkpoints without an `architectures` field

[Upstream PR](https://github.com/vllm-project/vllm/pull/46037) · state: closed · merged: True

## Original PR description


## Purpose

Loading a Mamba/Mamba2 checkpoint whose `config.json` omits the top-level `architectures` field crashes engine core init with a bare, message-less `AssertionError: mamba_block_size is not None`. This hits the official HF mamba2 conversions such as `AntonV/mamba2-130m-hf` and `AntonV/mamba2-370m-hf`.

```python
from vllm import LLM
LLM("AntonV/mamba2-130m-hf")  # AssertionError: mamba_block_size is not None
```

Root cause is an arch-name mismatch inside vLLM itself:

1. When `architectures` is absent, vLLM injects the base HF arch name from `MODEL_MAPPING_NAMES`, i.e. `"Mamba2Model"` (`vllm/transformers_utils/config.py`).
2. Model class resolution normalizes that to the runnable `"Mamba2ForCausalLM"` (via `_normalize_arch`), so weights load fine, but `ModelConfig.architecture` keeps the un-normalized `"Mamba2Model"`.
3. The per-arch config hook that sets `mamba_block_size` is dispatched in `VllmConfig.try_verify_and_update_config` by that un-normalized name: `MODELS_CONFIG_MAP.get("Mamba2Model")`. `MODELS_CONFIG_MAP` is keyed by `"Mamba2ForCausalLM"`/`"MambaForCausalLM"`, so the lookup misses, `MambaModelConfig.verify_and_update_config` never runs, `mamba_block_size` stays `None`, and KV cache init asserts.

Fix: when the direct lookup misses, normalize the arch the same way model class resolution does, then retry the lookup.

```python
cls = MODELS_CONFIG_MAP.get(architecture, None)
if cls is None:
    architecture = ModelRegistry._normalize_arch(architecture, self.model_config)
    cls = MODELS_CONFIG_MAP.get(architecture, None)
if cls is not None:
    cls.verify_and_update_config(self)
```

This only kicks in when the raw lookup fails (already-resolved arches like `Mamba2ForCausalLM` are untouched) and does not change `ModelConfig.architecture` itself, so there is no effect on normally-specified checkpoints.

Scope note: this fixes the crash. With the fix, an `architectures`-less checkpoint loads as an embedding model, which is vLLM's existing convention for a bare base-model arch (the injected `Mamba2Model` defaults to the pooling runner). To use these checkpoints for generation, pass the resolved arch explicitly, e.g. `LLM("AntonV/mamba2-130m-hf", hf_overrides={"architectures": ["Mamba2ForCausalLM"]})`. Changing the default runner for `architectures`-less checkpoints is a separate behavioral change and is intentionally out of scope here.
