# [KV Connector][Mooncake] Expose transfer stats via Prometheus

[Upstream PR](https://github.com/vllm-project/vllm/pull/56939) · state: open · merged: False

## Original PR description

## Purpose

`MooncakeConnector` collects per-transfer stats but never exports them: it does not override `KVConnectorBase_V1.build_prom_metrics`, which returns `None`, so the stats only reach the periodic `KV Transfer metrics: ...` log line. `mooncake/stats.py` carried a `TODO(mooncake-stats)` for exactly this.

This adds `MooncakePromMetrics` and wires it through `MooncakeConnector.build_prom_metrics`: histograms `vllm:mooncake_xfer_time_seconds`, `vllm:mooncake_bytes_transferred`, `vllm:mooncake_num_descriptors`, and counters `vllm:mooncake_num_failed_transfers`, `vllm:mooncake_num_failed_recvs`, `vllm:mooncake_num_kv_expired_reqs`, all with the standard `model_name`/`engine` labels. Mooncake is push-based, so the histograms are only populated on the prefiller instance.

It also fixes a latent crash: `MultiKVConnectorPromMetrics.observe` asserts that every connector id in the stats payload has registered metrics, and `MultiConnector` only registers sub-connectors whose `build_prom_metrics` returns non-`None`. With `MooncakeConnector` inside a `MultiConnector`, the first stats report therefore raised `AssertionError` in the stats logger.

`observe()` indexes the stats snapshot directly, the way the stats containers themselves read `data`, so a renamed stats key surfaces as a `KeyError` rather than silently reporting zeros.

## Changes

- `vllm/distributed/kv_transfer/kv_connector/v1/mooncake/stats.py`: add `MooncakePromMetrics` and the bucket edges it publishes; drop the TODO
- `vllm/distributed/kv_transfer/kv_connector/v1/mooncake/mooncake_connector.py`: add `MooncakeConnector.build_prom_metrics`
- `tests/v1/kv_connector/unit/test_mooncake_stats.py`: cover the wiring and the exported series
- `docs/features/mooncake_connector_usage.md`: document the new metrics

No wiring is needed elsewhere: `KVConnectorProm` resolves the class through `connector_cls.build_prom_metrics(...)`, and `MultiConnector` delegates to each sub-connector.

Sharing the plumbing that `NixlPromMetrics` duplicates is left to a separate PR, as requested in review.
