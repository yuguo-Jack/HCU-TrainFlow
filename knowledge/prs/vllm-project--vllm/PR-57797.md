# [Bugfix][RL] Load attention sinks through weight_loader for layerwise reload

[Upstream PR](https://github.com/vllm-project/vllm/pull/57797) · state: open · merged: False

## Original PR description

Attention sinks were previously loaded through model-specific `load_weights` logic. These direct writes bypassed the standard `weight_loader` pipeline, leaving stale sink values after layerwise reload during RL weight updates.

This change registers checkpoint-backed attention sinks with a common `load_attention_sink` weight loader in `model_loader/weight_utils.py`, and adds `make_attention_sink()`, which creates the sink parameter with `-inf` padding and registers that loader in one place. DeepSeek V4/V4.1, HY-V4, MiMo-V2, GPT-OSS, Laguna, and Qwen3-DFlash build their sinks through the factory and load them through their normal parameter loading paths. MiMo-V2 MTP and its Omni MTP subclass no longer pre-slice sinks before the common loader, which previously caused double TP sharding after the attention parameter was migrated. GPT-OSS sinks use the parameter loader across MXFP4, Quark, and other quantization paths; quantization-specific handling stays confined to quantized weights.

The loader validates one-dimensional shapes, rejects an empty sink checkpoint instead of silently disabling the sink, reports the offending head counts when the checkpoint is not divisible by the TP size or does not fit the runtime parameter, takes the TP-local head slice, and restores any runtime padding to `-inf` on every load — the old per-model copies never rewrote the padded heads. Unpadded sinks (GPT-OSS, MiMo-V2, Laguna, Qwen3-DFlash) are loaded in place without rebuilding the tensor. Its documentation records the even-head-partition assumption; uneven TP partitions require explicit head-range handling in a future extension.

## Consolidation

This PR replaces the split attention-sink series: #57798, #57801, #57803, #57804, #57805, and #57806. It rebuilds the implementation on current upstream `main` around parameter-level weight loading instead of squashing the model-specific fixes. The sibling PRs are superseded, so this is the single review target for the fix.

## Tests

- `test_attention_sink_uses_common_factory` checks that every sink model creates its parameter through `make_attention_sink`; a hand-built parameter would bypass the `-inf` padding and the registered loader. It replaces the earlier audit that imported and executed production statements.
- `test_attention_sink_model_loading_shards_once` calls the real model loading entry points (MiMo-V2 MTP, Omni MTP, Laguna, Qwen3-DFlash) and checks the parameter loader receives the unsliced global checkpoint exactly once.
- `test_gpt_oss_attention_sink_uses_parameter_loader` is renamed so that `-k attention_sink` selects it (it was previously missed by that filter), and covers MXFP4, Quark and the unquantized path. `test_gpt_oss_attention_sink_skips_missing_parameter` covers the pipeline-parallel skip path, the only guard the removal of the per-model sink branches leaves implicit.
- `test_attention_sink_layerwise_reload` covers both TP ranks, padded and exact runtime shapes, cold loading, two live updates, restored padding, and preservation of the sink storage referenced by kernels.
- Loader unit tests in `tests/model_executor/test_weight_utils.py`: exact/padded shapes across every rank at TP=1/2/4, invalid dimensionality, empty checkpoint, uneven head counts, oversized local shards, padding restore, dtype cast, CPU checkpoint to CUDA parameter, and the factory contract.

### What changed in this revision

- The helper moved out of `vllm/models/deepseek_v4/sink.py` into `vllm/model_executor/model_loader/attention_sink.py`, next to `default_weight_loader`. It is part of the loading interface that HY-V4 loads through, so it does not belong under one model package.
- The reconstructed runtime tensor is built with `torch.empty(param.shape, dtype=param.dtype, device=local_weight.device)` instead of `torch.full(..., -inf, dtype=...)` plus an implicit dtype cast, so a checkpoint/parameter dtype mismatch is resolved before the load rather than relied on implicitly. - A head range wider than the padded parameter now raises `ValueError` instead of silently truncating; this is the one way the old shape could load the wrong heads. Coverage added.
- Added a CUDA-parametrized case to the reload suite (`torch.cuda.is_available()` skip guard) so CI exercises the device boundary, not just CPU. It passes on H20 (see above).
