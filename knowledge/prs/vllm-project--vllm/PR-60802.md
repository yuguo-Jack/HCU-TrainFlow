# [Perf] Prefer DeepSelect over persistent_topk for large indexer top-k batches on SM100/SM103

[Upstream PR](https://github.com/vllm-project/vllm/pull/60802) · state: open · merged: False

## Original PR description

## Description

The sparse indexer decode top-k auto chain is `cooperative -> persistent -> per_row`. `cooperative_topk` applies only within `AUTO_COOPERATIVE_MAX_ROWS`, so anything larger goes to `persistent_topk`. For GLM-5.3-Flash with MTP k=7 at 32 seqs that is every verify batch: 256 rows, all on `persistent_topk`, which bins logits into a coarse histogram and can silently drop true top-k candidates when a trained indexer clusters its scores in one bin (#51782). The vendored DeepSelect extension handles exactly these shapes on the SM100/SM103 family and measured 191 us vs 616 us at 256 rows / 1M KV when it landed (#56464), but it stayed opt-in only.

This adds a `deep_select` branch in `_resolve_auto` between cooperative and persistent. The existing support checks (`_has_deep_select`, `_HAS_DEEP_SELECT_C`, `is_deep_select_supported`) stay, so other devices and unsupported strides/dtypes fall through to `persistent_topk` unchanged.

Measured on GLM-5.3-Flash (NVFP4), 8x B300 (SM103), TP8, FP8 KV cache, MTP k=7, 1M context, `vllm bench serve`, random dataset, seed 42, medians of 3 warm runs:

| workload (1024-in / 1024-out) | TPOT mean | TPOT p99 | TTFT median |
|---|---|---|---|
| 8 concurrent | 5.40 -> 5.05 ms (-6.5%) | 8.26 -> 7.05 ms (-14.6%) | 288 -> 341 ms |
| 32 concurrent | 7.85 -> 6.89 ms (-12.2%) | 12.24 -> 12.84 ms | 1113 -> 1073 ms |
| 128K prompt, 64 out | 8.24 -> 6.82 ms (-17.2%) | 8.24 -> 6.82 ms | 502 -> 477 ms |

These are medians of 3 warm passes within one boot per arm; across reboots of the unpatched build, c8 and c32 TPOT varied by roughly 25% and 12% on this setup, so the smaller deltas are directional and the workload-level trend is the signal. Measured on GLM-5.3-Flash only; the auto choice also covers the DSA indexer path on this device family, which I have not benchmarked here.
