# [Attention][TurboQuant] Refine Gemma 4 KV-cache skip-layer handling

[Upstream PR](https://github.com/vllm-project/vllm/pull/60799) · state: closed · merged: False

## Original PR description



## Overview

Improve TurboQuant KV-cache configuration and attention backend selection by combining existing and boundary skip layers, removing an overly restrictive head-size check, and adding debug output to help diagnose attention backend selection.

## Claims

* KV-cache skip layers: Merge existing KV-cache dtype skip layers with TurboQuant boundary skip layers while preserving and numerically sorting the combined set.
*  Attention backend debugging: Print the layer name, KV-cache dtype, and sliding-window configuration when the attention backend is selected automatically.
*  TurboQuant compatibility: Remove the explicit head_size > 256 rejection for turboquant_k8v4, allowing backend selection to proceed without this additional restriction.


## Validation

* Verify that existing and TurboQuant boundary skip layers are both preserved and correctly sorted.
* Verify that the debug output includes the layer name, KV-cache dtype, and sliding-window value.
* Test attention backend selection with turboquant_k8v4 and head sizes above 256 on a supported configuration.

## Details

TurboQuant KV-cache configuration needs to account for both pre-existing skip-layer settings and layers identified by TurboQuant boundary logic. Combining these sets avoids overwriting existing configuration.

The attention backend selection path also benefits from debug information about the layer's KV-cache dtype and sliding-window setting, making backend-selection issues easier to investigate.

Finally, the explicit head-size restriction for turboquant_k8v4 is removed so that the restriction does not reject configurations before backend compatibility is otherwise determined. Actual support still depends on the selected backend and the configuration being used.
