# Create cuBLAS handles before memory profiling to avoid OOM

[Upstream PR](https://github.com/vllm-project/vllm/pull/61044) · state: open · merged: False

## Original PR description

Fix https://github.com/pytorch/pytorch/issues/199944
Purpose
On small GPUs (e.g. an H200 35GB MIG slice), engine startup can fail during the memory profiling run with:
```
RuntimeError: CUDA error: CUBLAS_STATUS_ALLOC_FAILED when calling `cublasCreate(handle)`
```
This was seen in tests/v1/e2e/general/test_kv_sharing_fast_prefill.py with google/gemma-3n-E2B-it on torch 2.14.1 and the 2.15.0 RC (pytorch/pytorch#199944).

### Root cause

cuBLAS(Lt) asks CUDA for its handle memory directly. When torch's own cudaMalloc fails, torch frees its unused cache and retries, but a cuBLAS request never triggers that because torch doesn't see it. Profiling can grow torch's cache until the GPU is full, and the first cuBLAS call then fails even though torch holds idle memory it could have given back.
In this case:

- Loading weights does no matmuls, so the first cuBLAS call in the process happens inside profile_run, at the gemma3n vision projection. That call creates the handle.
- By then, torch had reserved 29.5 GiB, while live tensors peaked at 21.9 GiB. That left 0.04 GiB free on the device, and cublasCreate failed with about 19 GiB sitting unused in torch's cache.
- The scoped max_split_size_mb:20 from #58430 makes this more likely, adding about 2.9 GiB of reserved memory during profiling.

### Fix

Create the handles while memory is still free. At the start of Worker.determine_available_memory, call torch.cuda.current_blas_handle() and run one tiny linear with a bias, which also sets up cuBLASLt. Every GEMM during profiling then reuses the existing handles, so profiling needs no allocations outside torch's allocator.

The handles are created after init_snapshot, so their memory is still counted in total_consumed and comes out of the KV-cache budget as before. In the repro the KV cache was about 0.1 GiB smaller, which is the handle cost.

### Test Result

Without fix (2 runs) | FAIL ×2, CUBLAS_STATUS_ALLOC_FAILED | 29.52 / 0.04 GiB
With fix (4 runs) | PASS ×4 | 29.43 / 0.07 GiB
