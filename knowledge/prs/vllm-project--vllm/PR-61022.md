# [Docs] Fix broken llm-d.ai links on the llm-d integration page

[Upstream PR](https://github.com/vllm-project/vllm/pull/61022) · state: open · merged: False

## Original PR description

## Overview

Every llm-d.ai documentation link on the [llm-d integration page](https://docs.vllm.ai/en/latest/deployment/integrations/llm-d/) returns 404. This repoints all nine at their current published URLs. Docs only, no link text changed.

## Claims

- Fixes 9 broken links (all returning 404) on `docs/deployment/integrations/llm-d.md`.
- No remaining `llm-d.ai` link on the page 404s.
- Link text and prose are untouched, so the rendered page reads identically.

A `grep -c 'docs/guides'` on the file now returns 0, and the only remaining `getting-started` reference is `/getting-started/quickstart`, which is valid.

## Details

Root cause: `/docs/guides/...` has never been a route on llm-d.ai. The `llm-d/llm-d` repository has a top-level `guides/` directory holding deployment recipes (Helm values, scripts), but the website is built from `docs/`, which publishes the well-lit paths under `/docs/well-lit-paths/foundations/`. `git log` on `llm-d/llm-d` confirms no `docs/guides` directory has ever existed, and the llm-d.ai sitemap has no `/docs/guides` entry in any published version (0.7, 0.8, 0.9, current). So these are not links broken by a later rename; they have never resolved.

Two links needed more than the path prefix swap:

| Old | New | Why |
| --- | --- | --- |
| `/docs/guides/precise-prefix-cache-aware` | `/docs/well-lit-paths/foundations/precise-prefix-cache-routing` | The page was additionally renamed from `precise-prefix-cache-aware` to `precise-prefix-cache-routing` in llm-d/llm-d#1560. |
| `/docs/guides#advanced-kv-cache-management` | `/docs/architecture/advanced/kv-management` | That anchor does not exist. The topic now has its own page, titled "KV Cache Management". |

Separately, `/docs/getting-started` 404s even though `docs/getting-started/README.mdx` exists, because that file sets `slug: /` and is therefore served at the `/docs` root. The "Introduction" link now points at `/docs`.

Since these URLs were never published, there is nothing for llm-d.ai to redirect from, so the fix belongs here rather than in the llm-d website.
