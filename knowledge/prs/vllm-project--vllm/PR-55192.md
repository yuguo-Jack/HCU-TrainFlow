# [Bugfix][Pooling] Clear V1 pooling state after preemption

[Upstream PR](https://github.com/vllm-project/vllm/pull/55192) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->
## Overview

Clear accumulated V1 pooling state when a chunked request resumes after preemption. Preserve chunks across ordinary scheduling pauses.

## Claims

- Preemption recomputes the prompt from zero, so retained partial pooling rows would be duplicated.
- The reset uses the existing resumed-request branch.
- MRV2 already clears this state when the request is removed.

## Validation

Validated on 2026-10-10 at published head `0758f7cabc` and in a temporary merge with upstream `276fbcff2717bd934cfa37c8a2e4c391f3e7237b`. The published branch was not rebased.

```sh
VLLM_TARGET_DEVICE=cpu CUDA_VISIBLE_DEVICES='' .venv/bin/python -m pytest tests/v1/worker/test_gpu_model_runner.py -k 'token_pooling_after_request_resumes or update_states' -q
.venv/bin/pre-commit run --hook-stage manual --files vllm/v1/worker/gpu_model_runner.py tests/v1/worker/test_gpu_model_runner.py
```

The nine selected worker cases pass on both versions; all applicable scoped hooks pass. Removing the reset fails the preemption regression with **5 rows instead of 3** while the ordinary-pause control passes.

**Real GPU reproducer:** published Python source, `Qwen/Qwen3-Embedding-0.6B` (`97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`), RTX 5070 Ti, BF16, MRV1, eager FlashAttention 2, existing precompiled extensions, 256 prompt tokens, maximum length 512, 64-token chunks, and 64 KV blocks. After the first chunk, 64 pooling rows were retained. The supported `reset_prefix_cache(reset_running_requests=True)` call triggered actual scheduler preemption: the count increased from 0 to 1 and computed tokens reset from 64 to 0.

The completed `token_embed` output had shape **(256, 1024)** and matched an unpreempted reference with maximum/mean absolute difference **0.0**. Removing only the two reset lines reproduced incorrect **(320, 1024)** output. Supported kernel settings disabled optional FlashInfer autotuning and JIT warmup.

This completes the previously pending MRV1 model check. The earlier 512-token attempt stalled in an unrelated scheduler reservation path; the 256-token reproducer avoids that issue without expanding this PR.

## Details

The scheduler resets computed-token state during preemption, but the worker's `PoolingStates` otherwise retains old chunks. `AllPool` then concatenates those chunks with recomputed tokens. Only requests explicitly marked resumed from preemption are reset.

Fresh pooling/preemption searches found no replacement for this worker-state reset. #58778 concerns resumable scheduler sessions, a different state lifecycle.

Upstream CI is blocked at contributor authorization. AI assistance was used for investigation, implementation, tests, and review.
