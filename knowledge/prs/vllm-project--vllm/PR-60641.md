# [MoRIIO] Reserve RDMA listener ports atomically

[Upstream PR](https://github.com/vllm-project/vllm/pull/60641) · state: open · merged: False

## Original PR description

## Overview

MoRIIO probes a free TCP port, closes the socket, then asks its RDMA backend to bind it. Another worker can take the port in between. Pass zero so the backend reserves and publishes its actual listener port atomically.

Rebased onto main `bfa7e5b7afe40ebe48288801a2baf5c1135cd881`. This remains an independent child of closed #58968.

## Claims

```diff
initialize RDMA control listener
- get_open_port -> close probe -> bind previously free port
+ bind(0) -> getsockname -> publish bound port in EngineDesc
```

xGMI and the separate handshake/notification port paths retain their existing behavior.

## Details

The current ROCm base image pins MoRI `v1.2.3.post1`. Its [IOEngine](https://github.com/ROCm/mori/blob/v1.2.3.post1/src/io/engine.cpp#L234) obtains the bound port after RDMA initialization and writes it into the descriptor/config; [TCPContext](https://github.com/ROCm/mori/blob/v1.2.3.post1/src/application/transport/tcp/tcp.cpp#L166) binds then calls `getsockname`. Both paths were rechecked during extraction. The gfx1250 image separately pins `v1.1.0`; its [IOEngine](https://github.com/ROCm/mori/blob/v1.1.0/src/io/engine.cpp#L139) and [TCPContext](https://github.com/ROCm/mori/blob/v1.1.0/src/application/transport/tcp/tcp.cpp#L84) also publish the ephemeral bound port (source rechecked on 2026-10-12). No MoRI patch is required for either pin.

Open MoRIIO/port searches found no competing atomic RDMA bind fix apart from the implementation extracted from #58968, which was closed after the split. No new model, device-level RDMA handshake or performance run was made.

**Merge danger:** two-way door; blast radius: MoRIIO RDMA startup. Custom older MoRI builds must support publishing the port selected by `bind(0)`.

#60743 propagates failures from the separate ZeroMQ notification listener. This PR reserves the native RDMA control listener's port; they address different listeners.

AI assistance was used for implementation, rebase, regression checks and this description. Human line-by-line review and the runtime acceptance items above remain pending. No performance improvement is claimed.
