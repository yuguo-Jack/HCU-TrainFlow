# [Test] Allow one bf16 ulp in the fused mHC post/pre residual check

[Upstream PR](https://github.com/vllm-project/vllm/pull/60724) · state: closed · merged: True

## Original PR description



## Overview

Makes `test_deepseek_v41_mhc_fused_post_pre_delayed` tolerate a one-ulp rounding difference between the fused and unfused TileLang kernels. It fails on MI355 with the ROCm 10.0 (TheRock) stack (#58761) and in main's scheduled ROCm 10 AMD CI lane.

## Claims

- The residual check allows one bf16 ulp (`rtol=2**-7`) instead of requiring bit equality.
- `layer_input` is still checked exactly, against the collapse of the fused kernel's own residual.

## Validation

`pytest tests/kernels/mhc/test_mhc_kernels.py -k fused_post_pre_delayed` (test body run directly on MI300X; the test is gated to TileLang mHC hardware), all 12 parametrizations:

| | ROCm 10 image | ROCm 7.2 image |
|---|---|---|
| before | 2 failed (`[*-7168-8]`, as in CI) | pass |
| after | pass | pass |

## Details

One of 229,376 residual values differs by 1 bf16 ulp. Its exact value sits 1.6e-7 below a rounding midpoint. ROCm 10's clang 23 packs two multiplies in `mhc_post_tilelang` into `v_pk_mul_f32`, which stops them being contracted with the following adds. That is legal under hipcc's default `-ffp-contract=fast-honor-pragmas`, and the fused kernel's result is the correctly rounded one. Comparing the reference collapse against the fused residual keeps that check exact without carrying over this rounding difference.

Not a duplicate: no open PR touches this test.
