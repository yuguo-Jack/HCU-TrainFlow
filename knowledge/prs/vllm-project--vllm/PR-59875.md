# [Bugfix][EC Connector] Release shared memory on NIXL setup failure

[Upstream PR](https://github.com/vllm-project/vllm/pull/59875) · state: closed · merged: True

## Original PR description



## Overview

Prevent leaked shared memory when ECCPU scheduler initialization fails with NIXL enabled. The constructor currently raises without releasing the region it has already allocated.

## Claims

- Failed NIXL setup releases the scheduler-owned mmap file, file descriptors, and mapping while preserving the original exception.

## Validation

Review validation with NIXL 1.4.1: the previous constructor test file reproduced the test-order failure (6 passed, 1 failed); importing `data.nixl` before monkeypatching fixes its cached bindings, and all 7 constructor tests pass together. The suites below were rerun after merging upstream main.

The missing-NIXL regression fails against the unchanged scheduler because the mmap file remains, and passes with this fix. A second CPU regression raises during control-transport creation after data transport setup, and checks deregistration, shared-region release, and preservation of the original exception.

  tests/v1/ec_connector/unit/cpu/test_ec_shared_region.py -q
# 76 passed (NIXL 1.4.1 installed)

A separate CPU check exercised `ECConnectorFactory` through `ECCPUConnector` using real `VllmConfig`/`ModelConfig` objects and a local tiny Llava configuration, without replacing the shared-memory factory. The unchanged scheduler left the file, two file descriptors, and a mapping after the missing-NIXL error; the fixed scheduler left none, with the same error. Descriptors and mappings were checked through `/proc/self/fd` and `/proc/self/maps`.

Environment: Ubuntu 24.04 under WSL, Python 3.12.14, torch 2.13.0+cpu, editable source with official v0.30.0 CPU precompiled binaries. Exact-commit CPU binaries were unavailable. NIXL 1.4.1 was installed for this review revision, and the constructor wiring test exercised real NIXL registration and ZMQ session startup. Full GPU serving and cross-process NIXL data transfer were not run; local validation covers scheduler construction and startup-failure cleanup. The new test is selected by the existing CPU EC connector job in `.buildkite/test_areas/misc.yaml`.

## Details

The region is allocated before `_setup_nixl`; if setup raises, the caller never receives a scheduler to shut down. The constructor owns failure unwinding through `shutdown()`, releasing NIXL resources before the shared region. `_setup_nixl()` propagates errors without a second cleanup handler.

Related: #56507, #56508. The related test/doc PR covers import isolation and documentation, rather than constructor cleanup. Searches for EC scheduler cleanup, NIXL initialization, and shared-memory leaks found no equivalent open PR.
