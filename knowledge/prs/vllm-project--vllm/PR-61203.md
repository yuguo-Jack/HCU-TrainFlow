# [Bugfix][KV Connector] NIXL: reject a known engine_id seen at a different address

[Upstream PR](https://github.com/vllm-project/vllm/pull/61203) · state: open · merged: False

## Original PR description



## Overview

When two prefill instances use the same `engine_id` (for example a hardcoded `engine_id` in `--kv-transfer-config` copied across replicas), the NIXL pull-mode decode worker skips the handshake for the second one and reads its KV blocks through the first peer's agent. This PR makes decode fail that request instead. Related: #39276 (another source of duplicate engine_ids).

## Claims

- A known `engine_id` seen at a different address while the original peer is still registered now fails the request with a clear error, instead of reading KV from the wrong peer.
- With `kv_load_failure_policy=recompute`, decode recomputes locally and outputs stay correct.
- The `engine_id` docstring now states it must be unique per vLLM instance.

## Validation

Unit test: `test_duplicate_engine_id_from_different_address_fails` fails on main and passes with this change.
`pytest tests/v1/kv_connector/unit/ -k nixl`: 602 passed. 3 tests fail locally on both main and this branch (`test_abort_timeout_on_prefiller` x2: needs a GPU with more than 4 GB; `test_fewer_blocks_with_hma[gemma-3-1b-it]`: gated model).

E2E on an RTX 3090 (vLLM main d4e92cc + this PR, Qwen3-0.6B, 2 prefill + 1 decode, NixlConnector, 8 prompts, temperature 0, compared to non-disaggregated output):

| Setup | Outputs differing | Guard log lines |
|---|---|---|
| Distinct engine_ids | 1/8 (benign numerical divergence) | 0 |
| Shared engine_id, default policy | 4/8, all returned as request errors | 8 |
| Shared engine_id, `recompute` | 0/8 | 4 |

## Details

Flow:
1. Prefill A and prefill B both run with `engine_id=X` on different side-channel addresses.
2. Decode handshakes with A first and registers X -> A's agent.
3. A request prefilled on B arrives with `remote_engine_id=X` and B's host/port.
4. Before this change: X is already known, so decode skips the handshake and reads B's block IDs through A's agent.
5. After this change: decode sees X is registered at A's address, logs an error and fails the request.

The check reuses the existing `_engine_by_address` map (no new state) and only runs when the address does not match, so the normal path is unchanged. If the old peer has been evicted, the new address handshakes normally. Limitation: pull mode only, matching where `_engine_by_address` is tracked.
