# [Docs] [Multimodal] Note that per-request media_io_kwargs needs --trust-request-mm…

[Upstream PR](https://github.com/vllm-project/vllm/pull/60598) · state: closed · merged: True

## Original PR description

## Purpose

The multimodal inputs guide shows a chat-completions request that sends `media_io_kwargs` in the request body. Since #58830, the server rejects this request by default. A user who copies the example gets a `VLLMValidationError`.

#58830 added the `--trust-request-mm-kwargs` option. Without this option, the server rejects per-request `media_io_kwargs` and `mm_processor_kwargs`.
The same PR added the "Per-request multimodal arguments" section to `docs/usage/security.md`. The multimodal guide does not link to that section.

What changed:

- `docs/features/multimodal_inputs.md`, section "Pre-extracted Frame Sequences with `media_io_kwargs`": a new warning. It says that the server rejects per-request `media_io_kwargs` and `mm_processor_kwargs` by default. It tells the user to start the server with `--trust-request-mm-kwargs` only when the API clients are trusted. It also links to the section in the security guide.
- The comment in the example now says that the server must start with `--trust-request-mm-kwargs`.

Docs only. No functional changes.

I checked the open PRs that touch `multimodal_inputs.md` (#55478, #55583, #46153, #52759). None change this section. 

I used Claude Code to find the stale text and to trace the validation path. I reviewed each changed line myself.
