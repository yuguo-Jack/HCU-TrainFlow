# [Bugfix][Rust Frontend] Restore DP wave delivery after XPUB reconnects

[Upstream PR](https://github.com/vllm-project/vllm/pull/60249) · state: closed · merged: True

## Original PR description



## Overview

Fix the Rust in-process coordinator so an EngineCore that reconnects its
XPUB/XSUB control connection can receive DP wave notifications again.

Previously, a reconnected engine could permanently miss `START_DP_WAVE`.
Other ranks could then wait for it in distributed communication, causing
the DP group to hang.



## Claims

- Continuously processes XPUB subscription notifications after the startup handshake.
- Restores the XPUB subscription table when an EngineCore reconnects.
- Replays the current DP wave when a subscribe-all notification arrives during an active wave.
- Avoids replaying a stale wave when the coordinator is paused.
- Adds regression coverage for a subscriber joining during an active wave.




## Validation

```
cargo nextest run -p vllm-engine-core-client
cargo clippy -p vllm-engine-core-client \
  --all-targets \
  --all-features \
  --locked \
  -- -D warnings
```

Manual validation on a two-GPU DP=2 MoE setup confirmed that requests
continued to complete after an engine connection was interrupted and
restored. Repeated reconnects returned HTTP 200 without stalling the DP
group or replaying completed work.



## Details

The `zeromq` XPUB implementation applies subscription changes while
`recv()` processes subscription messages. The in-process coordinator
previously called `recv()` only during the startup gate. A reconnecting
XSUB resent its subscribe-all command, but that command remained
unprocessed and the XPUB subscription table stayed empty for the new
connection.

The coordinator event loop now receives XPUB subscription notifications.
When it receives the EngineCore subscribe-all message during an active
wave, it broadcasts the current `START_DP_WAVE` again. Engines already
running that wave ignore the duplicate notification, while the
reconnected engine receives the wave it missed.

When the coordinator is paused, receiving the subscription only restores
the subscription table. The next normal wave broadcast then reaches the
reconnected engine without replaying completed work.

Peer-specific network and codec errors are logged without terminating the
coordinator. Other XPUB errors retain the existing fail-closed behavior.
