# [ROCm][Perf][MiniMax-M3] Fused sparse-layer decode via AITER

[Upstream PR](https://github.com/vllm-project/vllm/pull/59653) · state: open · merged: False

## Original PR description

# Overview

Adds an opt-in decode path for MiniMax-M3 on ROCm that runs each sparse MoE layer as one AITER kernel launch per GPU, with both tensor-parallel all-reduces inside the kernel. The kernels come from ROCm/aiter#6047, a port of ROCm/ATOM#2419 by @valarLip.

## Motivations

A MiniMax-M3 decode step runs 57 sparse MoE layers. In vLLM each one is a chain of small kernels plus two all-reduces, so at low batch sizes decode time is dominated by launches and synchronization rather than memory bandwidth. Fusing the layer removes that overhead and speeds up decode by up to 2x.

## Technical Details

### New option

`--attention-config '{"minimax_m3_fused_decode": true}'` (default off):

| | |
|---|---|
| What it does | Each sparse MoE layer of a decode step runs as one AITER kernel launch per GPU |
| Which steps | Pure decode steps of up to 16 tokens, speculative verify included. Prefill, mixed and larger steps keep the regular layers |
| Requirements | ROCm gfx950, TP=4, `--kv-cache-dtype fp8`, `--block-size 128`, `indexer_kv_dtype: "fp8"`, `--moe-backend aiter`, `VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1`. Anything else fails at startup with the reason |
| Quantization | The kernel reads FP8 per-channel attention projections. Unless `--quantization-config` is given, the sparse layers' `qkv_proj` and `o_proj` are quantized to FP8 per-channel at load; every other weight keeps the checkpoint's precision |
| Speculative decoding | Supported; the fused path returns the EAGLE3 auxiliary hidden states |

### Design

| Point | How |
|---|---|
| Same decision on every rank | The in-kernel all-reduces need every rank in the same kernel. Eligibility depends only on the step's token count and attention metadata, which every rank builds from the same scheduler output |
| CUDA graphs | The kernel binds on the first eager decode step, before capture, and rebinds whenever the KV cache tensor moves. It holds raw pointers, and the cache is reallocated after memory profiling. Reaching the fused path inside capture without that eager step raises an error |
| KV cache size | The kernel addresses each layer's KV cache with 32-bit byte offsets; a larger cache fails at bind time with a fix suggestion |
| Model glue | `vllm/models/minimax_m3/amd/fused_decode.py` holds the gating and binding. `MiniMaxM3Model.forward` calls it first and falls through to the regular layers when a step is not eligible. The attention layer gains two small accessors for the cache page stride and KV scales |

### Files

| File | Change |
|---|---|
| `vllm/config/attention.py` | `minimax_m3_fused_decode` flag and its documentation |
| `vllm/model_executor/models/config.py` | Quantizes the sparse attention projections when the flag is on |
| `vllm/models/minimax_m3/amd/fused_decode.py` | Gating, binding, forward |
| `vllm/models/minimax_m3/amd/model.py` | Hook in `MiniMaxM3Model`, two accessors |
| `tests/models/test_minimax_m3_fused_decode_gating.py` | Startup checks and the quantization hook |

Needs an AITER build that includes ROCm/aiter#6047.

## Results

4x MI350X, `amd/MiniMax-M3-MXFP4`, TP=4:

```bash
VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_MOE=1 VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1 \
VLLM_ROCM_SHUFFLE_KV_CACHE_LAYOUT=1 \
vllm serve amd/MiniMax-M3-MXFP4 \
  --tensor-parallel-size 4 --trust-remote-code --language-model-only \
  --kv-cache-dtype fp8 --block-size 128 --max-model-len 133120 \
  --moe-backend aiter \
  --attention-config '{"backend":"ROCM_AITER_UNIFIED_ATTN","indexer_kv_dtype":"fp8","minimax_m3_fused_decode":true}'
```

The unfused baseline is the same command without `minimax_m3_fused_decode`.

GSM8K, full set, chat template, 8-shot multiturn, 4 concurrent requests (every decode step takes the fused path):

| | Unfused | Fused |
|---|---|---|
| GSM8K | 0.948 ± 0.006 | 0.948 ± 0.006 |
| GSM8K with EAGLE3 (3 spec tokens) | 0.941 ± 0.007 | 0.939 ± 0.007 |
| EAGLE3 acceptance | 0.696 | 0.696 |
