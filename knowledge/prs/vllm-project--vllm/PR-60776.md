# [Perf][Qwen4Exp] Retune H200 M=4 merged QSA LL-GEMM plan

[Upstream PR](https://github.com/vllm-project/vllm/pull/60776) · state: closed · merged: True

## Original PR description

## Overview

Follow-up to #59533 for the H200 (SM90) merged QSA projection plan. An exhaustive sweep of the legal `SkinnyGemmConfig` space for `(4224, 2560)` found a better M=4 entry: `k_unroll=1, vector_width=8` instead of `k_unroll=2, vector_width=4`. One-line change; M=1/2 plans are already optimal and untouched.

- Swept space (per M, `static_k` in {2560, None}): `block_size` x `vector_width` in {(32,2),(32,4),(32,8),(64,2),(64,4),(64,8),(128,2),(128,4),(256,2)} x `outputs_per_block` in {1,2,3,4,6,8} x `k_unroll` over all legal values — every legal config family for this shape; ~750 configs measured.
- The winner at M=4 dominates the committed entry in **both** L2-flushed and hot-cache regimes, on 4 distinct H200 GPUs, in a paired-order randomized benchmark.

## Validation

Merged GEMM `X=[4,2560] @ W=[4224,2560]` BF16, H200 (4 GPUs), FlashInfer CUPTI + CUDA graphs, median of 50 replays x 21 paired rounds with alternating arm order per round (84 paired samples), cold = 2xL2 flush before each replay:

| regime | committed `(2, 4)` | this PR `(1, 8)` | paired delta | 95% CI | win rate |
|---|---:|---:|---:|---|---|
| cold L2 | 9.06 us | 8.96 us | **-0.89%** | [-1.06%, -0.71%] | 82/84 |
| hot | 6.21 us | 6.14 us | **-1.28%** | [-1.53%, -1.05%] | 73/84 |

All four GPUs agree in sign and magnitude (per-GPU medians: 8.96-8.98 vs 9.06 cold). Against cuBLAS the M=4 plan goes from 1.069x to 1.080x cold and from 0.977x to 0.987x hot. The M>=8 cutoff stays on cuBLAS (re-confirmed). M=1/2: the committed `(128, 2, vw=2, static_k=2560)` family is a plateau — all k_unroll variants within noise — so no change.

Serving impact is small (this GEMM alone, ~0.1 us/layer-step); the change is justified by the sweep being exhaustive and the delta being unambiguous rather than by its size.

```python
import statistics
import torch
from flashinfer.testing import bench_gpu_time_with_cupti
from vllm.model_executor.kernels.linear.cute_dsl.skinny_gemm import (
    SkinnyGemmConfig, shape_dynamic_skinny_gemm)

M, N, K = 4, 4224, 2560
ARMS = {
    "cublas": None,
    "committed": SkinnyGemmConfig(M, 64, 4, k_unroll=2, vector_width=4),
    "candidate": SkinnyGemmConfig(M, 64, 4, k_unroll=1, vector_width=8),
}
def timing(fn, cold):
    s = bench_gpu_time_with_cupti(fn, dry_run_iters=5, repeat_iters=50,
                                  use_cuda_graph=True, cold_l2_cache=cold)
    return statistics.median(s) * 1000  # us

torch.manual_seed(42)
w = torch.randn(N, K, device="cuda", dtype=torch.bfloat16) * 0.02
x = torch.randn(M, K, device="cuda", dtype=torch.bfloat16)
ref = torch.nn.functional.linear(x.float(), w.float()).bfloat16()
fns = {"cublas": lambda: torch.nn.functional.linear(x, w)}
for name, cfg in ARMS.items():
    if cfg is not None:
        out = shape_dynamic_skinny_gemm(x, w, cfg)
        torch.testing.assert_close(out, ref, rtol=2e-2, atol=1e-2)
        fns[name] = (lambda c=cfg: shape_dynamic_skinny_gemm(x, w, c))
for cold in (True, False):
    t = {n: [] for n in fns}
    for run in range(21):
        order = list(fns)[::-1] if run % 2 else list(fns)
        for n in order:
            t[n].append(timing(fns[n], cold))
    print("cold" if cold else "hot",
          {n: statistics.median(v) for n, v in t.items()})
```
