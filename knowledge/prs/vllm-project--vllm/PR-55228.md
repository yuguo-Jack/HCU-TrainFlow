# [Bugfix][EPLB] Reject unsafe dynamic weight updates

[Upstream PR](https://github.com/vllm-project/vllm/pull/55228) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->
## Overview

Reject dynamic reloads and update-session starts for an EPLB-managed target before weights or session state change. This is a bounded mitigation for checkpoint placement mismatch and stale asynchronous rebalance transfers.

## Claims

- Reloading after a completed rebalance can load checkpoint weights into initial physical slots while inference uses the current routing map.
- An outstanding asynchronous rebalance can overwrite newly updated weights with retained old values.
- Dense main or draft targets remain updatable when the other model uses EPLB. Initial loading and expert parallelism without EPLB remain supported.

## Validation

Validated on 2026-10-10 at published head `9a56699aad` and in a temporary merge with upstream `276fbcff2717bd934cfa37c8a2e4c391f3e7237b`. The published branch was not rebased.

```sh
VLLM_TARGET_DEVICE=cpu CUDA_VISIBLE_DEVICES='' .venv/bin/python -m pytest tests/v1/worker/test_gpu_worker_weight_transfer.py -q
.venv/bin/pre-commit run --hook-stage manual --files vllm/v1/worker/gpu_worker.py tests/v1/worker/test_gpu_worker_weight_transfer.py docs/training/weight_transfer/README.md
```

The complete native worker suite passes **20 tests** on both versions; all applicable scoped hooks pass. Tests use the pinned Humming 0.1.16 dependency through an isolated overlay. Restoring baseline Worker methods gives **6 unsafe-operation failures and 2 passing dense-target controls**.

Previously recorded CPU proofs exercise the actual expert loader/map manager, EPLB policy, transfer/map commit, and reload lifecycle. A completed rebalance changes placement from `[0,1,2,3]` to `[0,2,1,3]`; reloading weights intended as `[110,120,130,140]` yields routed values `[110,130,120,140]`. A separate async lifecycle proof observes old values restored after update.

These tensor/lifecycle proofs are not multi-GPU model evaluations. Multi-GPU validation remains outstanding. Upstream CI is blocked at contributor authorization.

## Details

The target is matched against actual EPLB model registrations using the existing MoE resolver. Rejection occurs before reload delegation, draft retargeting, or update-session mutation.

The restriction applies even before the first rebalance and to kernel-format updates. Draining pending work alone cannot fix a completed placement mismatch. Callers needing dynamic updates must disable EPLB until reload supports live placement and asynchronous coordination.

Fresh overlap review included #59063 at `d88f64d8731219a19dc1c6475d0966dbfe0ecdf0`. Its proposed DeepSeek mapping still delegates to the static initial-placement builder, so its reload synchronization does not remove the completed-rebalance hazard addressed here.
