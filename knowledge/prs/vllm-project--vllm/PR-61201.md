# [CI] Shard PyTorch Fullgraph automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/61201) · state: open · merged: False

## Original PR description

## Purpose

`(H200 MIG 35GB) PyTorch Fullgraph` takes about 55 min. It ran one pytest per file through `find | xargs`, which the runtime sharder can't plan, because it handles plain pytest commands only. This replaces that with one `pytest -s -v compile/fullgraph --ignore=compile/fullgraph/test_full_cudagraph.py` and sets `automatic_shard: true`, as in #60492 and the batches after it.

- The per-file processes were a workaround for #28965 ("Cannot re-initialize CUDA in forked subprocess"). That issue is closed. The Buildkite run below checks that the files now pass in one process.
- On current timings the generator plans 4 shards (est. 17.1 / 16.0 / 14.8 / 8.3 min) and splits `test_basic_correctness.py` by test function.
- The AMD mirror keeps the `find | xargs` command as is.
