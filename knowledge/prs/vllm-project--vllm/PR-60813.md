## Original PR description

## Summary

Fixes #60703

When a GLM-4.7 model emits a stray <tool_call> in prose
(e.g. "I will issue a <tool_call> for it"), the parser opens
a phantom tool call and silently drops everything that follows:
the rest of the content, the real tool call, all lost with
HTTP 200, finish_reason=stop, no tool_calls, no log warning.

## Root cause

The  state machine was missing a
 transition. When in TOOL_NAME state
and encountering another TOOL_START, the engine falls through to
_emit_for_state() which appends the tag text to the phantom
call name buffer. The call is then rejected by
_accept_tool_name() under validate_tool_names=True.

## Fix

Add the missing transition:



This closes the phantom call (TOOL_CALL_END) and starts a
fresh one (TOOL_CALL_START), staying in TOOL_NAME to read
the new call name.
