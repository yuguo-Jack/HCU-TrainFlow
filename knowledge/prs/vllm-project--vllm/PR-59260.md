# [Spec Decode][MRV2] Warm up top-k/top-p and greedy rejection kernels for speculative decoding

[Upstream PR](https://github.com/vllm-project/vllm/pull/59260) · state: open · merged: False

## Original PR description

## Purpose

With speculative decoding, Model Runner V2 compiles sampling kernels in the first verification steps instead of at startup, so the first requests stall.

- **Commit 1:** register the native top-k/top-p warmups on CUDA when speculative decoding is configured. #58465 limited them to ROCm, but verification always masks top-k/top-p with these kernels, never with FlashInfer's fused sampler. Target-only CUDA engines are unchanged.
- **Commit 2:** when a rejection sampler exists, run the scheduler warmup a second time with greedy requests. All-greedy batches skip logits processing, so the rejection kernels see BF16 logits, a variant the warmup never compiled. Fixes #54455.

Not a duplicate: #56654 and #58465 removed CUDA sampler registration for its startup cost; this re-enables only what speculative decoding needs. #54630 (open) targets #54455 with mixed warmup configs, but on current main it calls `Sampler.add_request` with the signature from before #56497.

## Test Plan

- `pytest tests/v1/worker/test_mixed_warmup_gate.py tests/v1/worker/test_gpu_warmup_blocks.py tests/v1/sample/test_topk_topp_sampler.py tests/model_executor/test_jit_warmup*.py`, and pre-commit including mypy.
- DeepSeek-V4.1-Flash + DSpark (5 speculative tokens), TP4 on one GB300, `VLLM_USE_V2_MODEL_RUNNER=1`. Main, commit 1 and this PR were started interleaved on one node with a fresh Triton cache per start (4 starts each; other caches warm). After `/health`, each server got one streaming request (top-p 0.9 or greedy), then 64 concurrent mixed requests. Compiles were counted with `--jit-monitor-verbose`.

## Test Result

Unit tests: 219 passed, 1 skipped on main and on this PR. pre-commit and mypy pass.

| | main | + commit 1 | this PR |
|---|---|---|---|
| First top-p request, 2nd token | 2.07 / 2.09 s | 0.45 / 0.44 s | 0.43 / 0.45 s |
| First greedy request, 2nd token | 1.58 / 1.50 s | 1.47 / 1.62 s | 0.42 / 0.42 s |
| Compiles in the 64-request burst | 27 | 0–5 | 0 |
| Warmup time¹, cold Triton cache | 37.2 s | 52.9 s | 55.0 s (greedy pass 2.0 s) |
| Warmup time¹, warm Triton cache | 26.6 s | 26.1 s | 27.0 s (greedy pass 1.0 s) |

¹ JIT kernel warmup plus `warmup_kernels`. Commit 1 adds 22.1 s of registry warmup (120 more keys) and saves 6.5 s in `warmup_kernels`, which on main compiled these kernels itself.

TTFT doesn't change (0.40–0.57 s on all builds); the first token comes from prefill. The stall was in the first verification step, before the 2nd token. Greedy outputs are byte-identical across the three builds, and acceptance length is unchanged (2.84).

Limits: target-only batches that can't use the fused sampler still compile on first use, as on main. Seeded requests (#54425) aren't covered. Only tested on GB300 with DeepSeek-V4.1-Flash + DSpark; ROCm and pipeline parallelism are untested.
