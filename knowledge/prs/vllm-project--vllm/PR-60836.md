# [CI] Use readable titles for nightly perf-eval builds

[Upstream PR](https://github.com/vllm-project/vllm/pull/60836) · state: open · merged: False

## Original PR description



## Overview

Make perf-eval build titles readable. Before: `(NIGHTLY=1) Evaluate vLLM 8cbd5d03... (CUDA)` ([example](https://buildkite.com/vllm/perf-eval/builds/658)). After: `[Nvidia] Nightly run 2026-10-09: commit 8cbd5d03...` (and `[AMD] ...` for ROCm).

## Claims

- Nightly perf-eval builds are titled `[<Nvidia|AMD>] Nightly run <YYYY-MM-DD>: commit <sha>`.
- Manual runs (`RUN_PERF_EVAL=1`, `NIGHTLY` unset) are titled `... Manual run <date> ...`.
- The triggered build's branch, env (`NIGHTLY`, `VLLM_COMMIT`, `VLLM_IMAGE_*`), `async`, and `soft_fail` are unchanged.

## Validation

- Ran `.buildkite/scripts/trigger-perf-eval.sh cuda|rocm` with a stubbed `buildkite-agent` that prints the uploaded YAML. Output for `cuda` with `NIGHTLY=1`:
  ```yaml
  steps:
    - trigger: "perf-eval"
      label: "perf-eval (Nvidia)"
      async: true
      soft_fail: true
      build:
        branch: "main"
        message: "[Nvidia] Nightly run 2026-10-09: commit 8cbd5d03006c33185f402249ff2b448efd594986"
        env:
          NIGHTLY: "1" # run all perf-eval workloads
          VLLM_COMMIT: "8cbd5d03006c33185f402249ff2b448efd594986"
          VLLM_IMAGE_CUDA: "public.ecr.aws/q9t5s3a7/vllm-release-repo:8cbd5d03006c33185f402249ff2b448efd594986-x86_64"
  ```
  `rocm` gives `[AMD] ...` with `VLLM_IMAGE_ROCM: ...-rocm`. Without `NIGHTLY`, the title is `Manual run`.
- Both generated YAMLs and `release-pipeline.yaml` parse with PyYAML; `shellcheck` is clean.
- Not yet run end to end on the release pipeline. The next nightly will show the new titles.

## Details

Buildkite pipeline-upload interpolation has no date variable and can't run commands, so a static `message:` can't include the date. The two `trigger:` steps are now small command steps on `small_cpu_queue_release` (same `key`, `if`, `depends_on`, `soft_fail`). Each one runs `.buildkite/scripts/trigger-perf-eval.sh`, which uploads the same trigger step with the computed title. Nothing else depends on the `trigger-perf-eval-*` keys. The date is in UTC, taken when the image build finishes. Tradeoff: each run now uses one short CPU job per platform.

Not a duplicate: no open PR touches the perf-eval triggers. AI assistance (Claude Code) was used; the human submitter reviews and owns the change.
