# [Bugfix][NIXL] Guard record_transfer against None telemetry

[Upstream PR](https://github.com/vllm-project/vllm/pull/57734) · state: closed · merged: True

## Original PR description

> Supersedes #57403, which was closed because its head picked up merge commits from an updated `main` (354 files, diff unreadable). This PR carries the same single-commit fix (patch-id `c182a17c19c1538a7e4fe2fb84217732e7ae2371`), rebased onto current `main`. cc @NickLucche

### Problem
Some NIXL backends do not capture transfer telemetry by default (UCX without `NIXL_TELEMETRY_ENABLE=1`, and OBJ in some configs). For these, `get_xfer_telemetry()` returns `None` instead of a `nixlXferTelemetry` struct.

`NixlBaseConnectorWorker._pop_done_transfers()` in `vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py` passes that result straight to `self.xfer_stats.record_transfer(res)`. When `res is None`, the call raises `AttributeError: 'NoneType' object has no attribute 'xferDuration'`. The surrounding `try/except Exception` catches it and treats it as a transfer failure (`transfer_exception`): the blocks are invalidated and downstream workers report the request as failed. With Dynamo P/D disaggregation, the frontend then returns HTTP 500 to the client.

The bug does not depend on any one backend. It triggers whenever a backend reports `xfer_state == "DONE"` but cannot fill in telemetry.

### Reproduction
Deploy DeepSeek-V4.1-Flash with P/D disaggregation on NVIDIA H200 using the NIXL UCX backend. `NixlBaseConnectorWorker` calls `get_xfer_telemetry()` for each DONE handle, and the UCX plugin returns `None` because it allocates no telemetry buffer by default. `record_transfer(None)` then raises `AttributeError`, the request is marked failed, and Dynamo returns HTTP 500. Stack trace excerpt from a production deploy (2026-09-17):

```
ERROR vllm.distributed.kv_transfer.kv_connector.v1.nixl.base_worker:_pop_done_transfers:3031
Marking blocks as invalid
transfer_exception
AttributeError: 'NoneType' object has no attribute 'xferDuration'
```

This error is logged on every KV transfer completion, so the log noise alone makes it a production problem.

### Fix
Make `NixlKVConnectorStats.record_transfer()` (`nixl/stats.py`) accept `None` and skip recording when the backend returned no telemetry:

```python
def record_transfer(self, res: "nixlXferTelemetry | None"):
    # Keep metrics units consistent with rest of the code: time us->s
    if res is None:
        return
    ...
```

The guard sits inside `record_transfer()` rather than at the call site, so every caller is covered, including future ones. Nothing changes for backends that do return telemetry. For backends that don't, that transfer simply isn't recorded in the metrics. That's better than marking a successful transfer as failed.

### Related
- #55576 (open) handles a sibling case: the OBJ tier explicitly enabling telemetry. This fix complements it. Even with telemetry fully enabled, the `None` guard stops future backends from hitting the same crash.
- #35876 (open) reworks throughput computation, which is a different metric path.
