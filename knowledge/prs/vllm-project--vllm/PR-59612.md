# [Fusion] Support 3D activation quantization fusion and enable it for Pixtral

[Upstream PR](https://github.com/vllm-project/vllm/pull/59612) · state: closed · merged: True

## Original PR description

## Overview
Extend the shared manual SiLU+multiply+quantization producers to accept 3D activations, add pre-quantized input support to the FlashInfer CuTe-DSL NVFP4 consumer, and update the FlashInfer-CUTLASS NVFP4 consumer to handle the resulting 3D packed data. These changes enable both Pixtral vision encoder MLP implementations to use `maybe_fused_act_quant` directly.

Related: #43501

## Claims

- Extend the shared dynamic block-FP8 and NVFP4 SiLU+multiply+quantization producers from 2D-only input to 2D or 3D input, preserving leading dimensions in `data` and `orig_shape`.
- Make the FlashInfer-CUTLASS NVFP4 consumer accept 3D packed activation data by flattening it before GEMM and restoring the output shape afterward.
- Enable these existing manual activation+quantization producers for both native and Hugging Face Pixtral vision MLPs.
- Preserve the ordinary activation path for unsupported activation/quantization combinations and consumers.
- Measured Ministral 3B prefill throughput on RTX6000D for requests containing **1700 × 2200 pixel images of scanned US Letter pages** increased from 6.521 to 6.642 requests/s with an NVFP4 vision encoder: approximately **1.9% over the compiled baseline**.

## Validation

### Performance

Ministral 3B prefill throughput on RTX6000D for requests containing 1700 × 2200 pixel images of scanned US Letter pages from vidore v3:

| Revision | Encoder compilation | BF16 ViT (req/s) | NVFP4 ViT (req/s) | NVFP4 vs BF16 on the same revision |
|---|---|---:|---:|---:|
| `cb6458c` | Disabled | 4.977 | 5.937 | +19.3% |
| `ab52667` (#57168 merged) | Enabled | 5.390 | **6.521** | **+21.0%** |
| `ab52667` + this change | Enabled | 5.402 | **6.642** | **+23.0%** |

The relevant comparison for this PR is the last two rows: NVFP4 throughput improves by approximately 1.9%. The BF16 difference is approximately 0.2%.

### Tests and checks

- Extended the existing static-FP8 and dynamic block-FP8 fusion tests with 3D inputs, checking numerical parity, output shapes, and quantization metadata.
- Added a FlashInfer-CUTLASS NVFP4 consumer regression test. It calls `apply_weights` with equivalent flat and 3D `QuantizedActivation` inputs and checks matching results, output dtype, and restored token dimensions.

```bash
  -k preserves_quantized_input_shape -v
```


## Details

### Shared fused-operator changes

Pixtral feeds its vision MLPs tensors with shape `[batch, tokens, hidden]`. Passing their gate/up projection output directly to the existing dynamic block-FP8 and NVFP4 producers would fail their 2D-only assertions. The shape handling belongs in the shared producers so callers can use the fusion helper without model-specific reshapes.

In `fused_act_quant.py`, `_silu_and_mul_fp8_dynamic_block` and `_silu_and_mul_nvfp4_dynamic` now accept 2D or 3D input. They save the activation output shape before flattening the token dimensions, invoke the existing kernels with 2D input, and restore the activation data shape and original shape metadata. Existing 2D behavior is retained. The static-FP8 producer already accepts leading dimensions and needs no implementation change.

### Pixtral integration and backend applicability

Both Pixtral MLP forwards now call `maybe_fused_act_quant` between the gate/up and down projections. With shape handling in the shared producers and consumer, the model forwards need no explicit reshaping.
