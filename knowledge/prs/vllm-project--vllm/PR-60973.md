# [Bugfix][Responses API] Complete cache-write token accounting

[Upstream PR](https://github.com/vllm-project/vllm/pull/60973) · state: closed · merged: True

## Original PR description

## Overview

Complete `usage.input_tokens_details.cache_write_tokens` accounting in `HarmonyContext` and `ParsableContext`, following #57222's `SimpleContext` support.

## Claims

- Accumulate cache writes across generation turns, without double-counting Harmony streaming chunks.

## Validation

The regression tests fail without the fix. **220 passed, 1 xfailed** with the fix:

```bash
HF_HUB_OFFLINE=1 .venv/bin/python -m pytest \
  tests/entrypoints/unit_tests/test_context.py \
  tests/entrypoints/openai/responses/test_parsable_context_unit.py \
  tests/entrypoints/openai/responses/test_serving_responses.py \
  tests/entrypoints/openai/responses/test_streaming_events.py \
  tests/entrypoints/openai/responses/test_protocol.py \
  tests/entrypoints/openai/responses/test_harmony_utils.py \
  tests/entrypoints/openai/responses/test_response_input_to_harmony.py \
  -q --tb=short
```

Applicable pre-commit hooks and `git diff --check` passed.

Live Qwen2.5-0.5B-Instruct on RTX PRO 4000 Blackwell, with `VLLM_USE_EXPERIMENTAL_PARSER_CONTEXT=1`: six non-streaming requests verified the actual `ParsableContext` path and engine counts. Generated token IDs were unchanged.

| Case | Engine Writes | API Before | API After |
| --- | --- | --- | --- |
| Cold cache | 928 | 0 | 928 |
| Warm cache | 0 | 0 | 0 |
| Cache disabled | 0 | Not run | 0 |

Harmony unit tests and 33 captured-output accounting replays passed; replays use a fake parser, not live gpt-oss. Live Harmony validation and human review/test confirmation remain pending.

## Details

Both contexts lacked `num_cache_creation_tokens`, so the serializer fell back to zero. Track it per generation turn and read it directly. No other usage fields, cache behavior, or ParsableContext streaming support are changed.

Duplicate check on October 10, 2026: #57222 only covered `SimpleContext`; open #49709 and #54064 address other usage counters, not cache writes.
