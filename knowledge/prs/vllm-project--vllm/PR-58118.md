# Enable gated RMSNorm decode fast path for Qwen3.5/3.6-A3B on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/58118) · state: closed · merged: False

## Original PR description

## What

Adds an XPU dispatch branch in `RMSNormGated.forward_xpu` that routes decode-shape calls to the fused `rms_norm_gated_decode` kernel (vllm-xpu-kernels side companion PR) instead of the generic Triton `rmsnorm_fn` path.

Gate: fp16, `x.shape` in ((16,128), (24,128)) (heads x head_v_dim), contiguous, `z` present with matching shape/dtype/device, `weight (128,)`, `bias is None`, `group_size is None`, `norm_before_gate=True`, activation silu/swish. Everything else falls through to the existing path unchanged.

## Scope

Model: Qwen3.5/3.6-A3B (Gated DeltaNet linear attention). XPU-only dispatch path; no changes to CUDA/native code paths.

## Validation

Tested on Qwen3.6-35B-A3B, per-tensor fp8 on-the-fly quantization, 2x Intel Arc Pro B70 (Xe2) TP2, eager, chunked prefill: outputs byte-identical with the fast path enabled vs. the existing path; no regressions observed across a range of concurrent request batch sizes.

Companion PR: vllm-xpu-kernels (kernel side).
