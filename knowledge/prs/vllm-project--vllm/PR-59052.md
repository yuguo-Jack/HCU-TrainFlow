# [Feature][Attention] Partition mixed batches and gate cudagraphs in Triton DiffKV

[Upstream PR](https://github.com/vllm-project/vllm/pull/59052) · state: open · merged: False

## Original PR description

## Purpose

This PR upstreams work from the patch set of the MiMo recipe we deploy — Diffbot's MiMo-V2.6-Flash-RL FP8KV/W4A8 recipe (Hugging Face: diffbot/MiMo-V2.6-Flash-RL-FP8KV-W4A8-2x-RTX-PRO-6000, built by Mike Tung), itself porting parts from the local-inference-lab/vllm fork: the idea and the original implementation belong to the recipe's authors, not to us. Their version of this change is tracked in local-inference-lab/vllm#848; we re-derived the diff against upstream main, wrote or extended the tests, and ran the checks.

### Motivation

The Triton DiffKV backend handles mixed batches poorly in two ways:

1. **Cudagraphs.** The DiffKV metadata builder inherited `AttentionCGSupport.ALWAYS` from `TritonAttentionMetadataBuilder`, so cudagraphs were captured and replayed for mixed batches too — a graph may only replay for batches whose call structure matches the one it was traced on. This PR pins the builder to `AttentionCGSupport.UNIFORM_BATCH` and initializes the decode reorder threshold the runner needs before it orders decodes first.

2. **Split-KV is lost on mixed batches.** A mixed batch runs as a single 2D call today, so its decode rows never take the split-KV path. The builder now produces a `TritonAttentionDiffKVMetadata` carrying `partitions`: when the actual token count exceeds the softmax-segment buffer capacity, the batch splits into a decode partition and a prefill partition, each with its own `query_start_loc` / `seq_lens` / `block_table` / `slot_mapping` slices, and the impl runs `unified_attention_diffkv` once per partition over its own token range of `q` and `out`. The split only engages when it can pay: a shared predicate (`can_use_split_kv`, the launcher's own gate exported as one function) keeps the batch unpartitioned whenever the decode side's max query length exceeds 1 or `VLLM_BATCH_INVARIANT` disables the 3D path.

Three signed commits: cudagraph gating first, partition support second, partition-path tests third.

## Test Result

Results, stated exactly:

- ruff format/check clean on all three touched files (repo-pinned ruff 0.14.0); `pre-commit run` itself cannot execute in this NixOS environment (its hook environments fail with the `stub-ld` dynamic-linker error), so ruff was run directly;
- **unit coverage** in `tests/v1/attention/test_triton_diffkv_metadata_partitioning.py` (11 passed) for: the DiffKV builder's V-shaped softmax scratch vs the parent builder, `build()`'s partition threshold and buffer wiring, the cudagraph capture-size threshold snap, the forward KV-split and partition-buffer handoff (kernel stubbed), the forward guards (no-metadata zeros, `output_scale` `NotImplementedError`, cascade `AssertionError`), and the launcher's 3D/2D partition dispatch including the per-segment reduce launch (both Triton kernels stubbed — this box has no FA3/FA4 and `triton` cannot import without `libz.so.1`, so no kernel executes in these tests);
- the kernel-facing suites: **83 passed, 118 skipped** — the 118 skips are the 96-case DiffKV kernel suite (`FA DiffKV needs FA3/FA4`, not installed here) plus 22 skips in `test_attention_selector.py`; the selector suite passes 83/83 identically on this branch and on pristine `ccfd1ce`;
- `tests/v1/attention` could not be completed in this environment: 2 collection errors (`FileNotFoundError: /sbin/ldconfig`, a NixOS issue) identical on pristine `ccfd1ce`, and runs with `--continue-on-collection-errors` hung and were aborted twice;
- **no model eval was run.** The partition moves oversized mixed-batch decode rows onto the 3D split-KV kernel — a different reduction order — and AGENTS.md asks for eval numbers on output-affecting changes; running one needs a model and free GPUs that were unavailable here. Stated plainly rather than argued away.
