# [Bugfix] Reject non-int values for integer SamplingParams fields

[Upstream PR](https://github.com/vllm-project/vllm/pull/60999) · state: open · merged: False

## Original PR description



## Overview

Fixes #60998. `SamplingParams` now rejects a float or bool in its integer fields at construction, instead of letting `LLM.generate()` hang on an EngineCore msgspec decode error.

## Claims

- `SamplingParams(max_tokens=2.5)` (also `4.0` or `True`) raises `VLLMValidationError` instead of hanging `LLM.generate()`.
- The same check covers `top_k`, `seed`, `min_tokens`, `logprobs`, `prompt_logprobs`, `prompt_logprob_start` and `stream_interval`. All of them are `int` fields on the msgspec struct, and all hit the same decode failure.

## Validation

End-to-end with the issue's reproducer (`Qwen/Qwen2.5-0.5B-Instruct`, `enforce_eager=True`, CPU backend on macOS arm64, 60 s timeout around `llm.generate("Hello", SamplingParams(max_tokens=2.5))`):

| | Result |
|---|---|
| main (`2bea220`) | EngineCore logs ``msgspec.ValidationError: Expected `int \| null`, got `float` - at `$[3].max_tokens` ``; `generate()` hangs (no response after 60 s) |
| this PR | `VLLMValidationError: max_tokens must be an int, got float. (parameter=max_tokens, value=2.5)` raised at construction |

Without loading a model, a msgpack round-trip of `SamplingParams` through `MsgpackEncoder`/`MsgpackDecoder` fails the same way on main for every field listed above, and for `bool`.

Tests:

```bash
pytest tests/test_sampling_params.py tests/test_request_input_bounds.py tests/v1/test_request.py \
  tests/entrypoints/openai/completion/test_completion_error.py \
  tests/entrypoints/openai/chat_completion/test_chat_error.py
# 186 passed
```

The new `test_non_int_token_fields_rejected` fails on main for 8 of its 9 cases. `top_k` already had a type check.

## Details

**Root cause:** `_verify_args()` only range-checks these fields (e.g. `max_tokens < 1`), and a float or bool passes a range check. `EngineCoreRequest` is decoded with msgspec, which is strict about `int`. The decode runs in `EngineCore.process_input_sockets` outside any try/except, so the input thread dies and the client never gets a response or an error.

**Fix:** one loop at the top of `_verify_args()` checks that each field is an `int` and not a `bool`. It replaces the existing `top_k`-only check. The `top_k` message changes from "must be an integer" to "must be an int"; no test depends on it.

**Compatibility:**
- Whole floats like `4.0` are now rejected rather than coerced, matching what msgspec accepts.
- numpy integers are also rejected. They already failed on main with a `TypeError` at encode (not serializable without `VLLM_ALLOW_INSECURE_SERIALIZATION`), so nothing that works today breaks.
- OpenAI server behavior is unchanged. Pydantic already rejects fractional values and coerces `4.0` to `4` and `true` to `1` before `SamplingParams` is built (checked with `CompletionRequest.model_validate_json(...).to_sampling_params(...)`).

**Not in scope:** making `process_input_sockets` survive a decode error, which would turn any future decode failure into an error response instead of a hang. That is a larger change to core and is better as a separate PR.

**Why this isn't a duplicate:** no open PR references #60998, and no open PR touches `SamplingParams` type validation (checked with `gh pr list --search` before opening).
