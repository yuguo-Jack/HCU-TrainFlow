# [Perf][GDN] Internal prefill checkpoints for the Triton/FLA and AITER FlyDSL GDN prefill backends

[Upstream PR](https://github.com/vllm-project/vllm/pull/60659) · state: open · merged: False

## Original PR description

## Overview

Internal prefill checkpoints (#52789, generalized in #57783; Mamba2 in #57329) export a prefill's block-boundary state from inside one forward, so in `mamba_cache_mode="align"` the scheduler no longer stops the prefill at its last block boundary. For Qwen3.5 / Qwen3-Next GDN, #60050 does this on the FlashInfer prefill backend. This PR does it for the **Triton/FLA** (CUDA, ROCm) and **AITER FlyDSL** (ROCm) GDN prefill backends, whose chunk kernels only return each sequence's final state. No kernel changes.

## Claims

- Qwen3.5-27B on 8x MI308X (TP8, AITER FlyDSL prefill), 8000-token prompts, two runs: TTFT −11% to −12% at concurrency 4 and −16% to −17% at 16 (mean; p50 −24% to −25% and −18%). Throughput unchanged, TPOT +3%. At concurrency 1, TTFT is +9% to +11% on this setup; see Details.
- GSM8K unchanged: 0.9636 baseline, 0.9651 with this PR.
- Outputs, final states and exported checkpoints match the unsplit computation (both backends, fp32 and bf16 state).
- Unchanged: batches without a checkpoint, and configs with speculative decoding or `prefix_match_unit` < block size, where this is not enabled.

## Details

- **Split**: the builder cuts each checkpointed row at its checkpoint in the prefill varlen batch; only a row's first segment gets the row's initial state. One chunk-kernel call over the segments leaves each checkpoint as the final state of its row's first segment. The tails (shorter than one block) started from a zero state there, so a second, small call reruns them from their checkpoints, and their outputs and final states replace the first call's. Both calls get kernel metadata from the existing per-backend code, factored out of `build()` into `_build_prefill_kernel_metadata`.
- **Export**: conv window and recurrent state are stored by the existing `FlashKDAPrefillCheckpointExporter` kernel, which #60050 generalizes as `ConvRecurrentCheckpointExporter`; nothing in it is KDA-specific.
- **Opt-in**: `QwenGatedDeltaNetAttention.get_kv_cache_spec` sets `num_prefill_checkpoint_blocks=1` and `prefill_checkpoint_alignment=1` (any offset can be cut). The builder keys off that alignment, as #60050 keys off 64, so KDA layers on the GDN backend are unaffected.
- **Cost**: only steps with a checkpointed prefill pay: per GDN layer, a second chunk-kernel call over the tails, one export kernel and a few gathers. Where both arms run the same single step (an 8000-token prompt on a 400-token block, which main did not split before #60533), this measured +2 ms (+0.4%) at concurrency 1.
- **Concurrency 1**: TTFT is +11% because the PR runs the 8000-token prompt in one step (578 ms) where the baseline runs 7616 + 384 tokens in two (520–531 ms over two runs). The baseline's own single 8000-token step also takes 579 ms, so on this setup one big step costs more than the two smaller ones, and with no queueing the saved step does not make up for it. At concurrency 4 and 16, the baseline's extra tail step delays other requests' prefills, and that dominates. Where the per-step cost grows faster than linearly is still being investigated.
- **Limitations**: not enabled with speculative decoding or `prefix_match_unit` < block size. Partial-block prefix hits and speculative block relocation interact with checkpoint blocks in ways not validated here. CUDA and ROCm only.
- **Not a duplicate**: #60050 covers only FlashInfer and leaves Triton/FLA, CuteDSL and ROCm unchanged. #55873 / #55875 / #55876 add application-directed checkpoints. This PR and #60050 touch the same two files with the same export call; whichever lands second rebases, switching to `ConvRecurrentCheckpointExporter` if #60050 lands first.
- **Size and placement**: about 235 non-test code lines excluding comments and docstrings, 17 of which are the existing chunk call re-indented under the new branch. Unlike FlashInfer in #60050, these kernels cannot emit intermediate states, so the split itself (the host plan and the two chunk calls, about 115 lines) is done here. It is backend-neutral and lives in a new `gdn/prefill_checkpoint.py` rather than growing `qwen_gdn_linear_attn.py` (2.1k lines), which also keeps the overlap with #60050 in the two shared files to a few lines. It can move into `gdn_attn.py` / `qwen_gdn_linear_attn.py` if reviewers prefer.
