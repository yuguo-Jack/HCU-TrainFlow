# [KV Connector][NIXL] Transfer DeepSeek-V4.1 packed MLA rows whole

[Upstream PR](https://github.com/vllm-project/vllm/pull/61121) · state: open · merged: False

## Original PR description



## Overview

> **Stacked on #61074.** Only the last commit (`c673ff04e9`) belongs to this PR: +8/−4 in `base_worker.py`, and one test case.

#61074 registers packed MLA rows as one NIXL region, but DeepSeek-V4.1 does not reach that path: its compressor-state `CircularBufferSpec` ring sets `_is_csa_linear`, which forces `packed_storage=False`. This PR replaces that gate with the property it was protecting, so DSV4.1 transfers whole rows.

## Claims

- DeepSeek-V4.1-Flash P/D (pull): about 11k → about 430 NIXL descriptors and 179 → 104 MB per 100k-token transfer. GSM8K does not change.
- No other model changes behavior: Qwen3.8-Flash-Next (Mamba) and non-MLA models keep per-layer regions.

## Validation

GSM8K varies by ±0.6 pt between runs of identical code (14 runs: 0.920–0.933). Each column above is one run; earlier runs of the same change gave the same descriptor counts.

The deselected `ray` case also fails on main, because the environment has no reachable Ray address.

## Details

**Root cause.** DSV4.1 packs all layers into one shared storage with a 135,168-byte block row. Seven transfer groups alias each row from byte 0: five SWA groups, the compressed MLA + indexer group, and the compressor-state ring. `_is_csa_linear` was added for Qwen3.8-Flash-Next (#53896) and is true when any group is a `CircularBufferSpec`. It sets `packed_storage=False`, so DSV4.1 registers per-layer regions. Those regions overlap, and the `_SHARED_REGION_GROUP_ID` ones are read for the blocks of every group. The result is about 14 overlapping descriptors per block.

**Fix.** A row may transfer whole only if every page in it is replicated across TP ranks: MLA without SSM state. The gate is now `use_mla and not _has_mamba` instead of `not _is_csa_linear`. The ring itself is TP-replicated, so it never needed the exclusion. What the exclusion really protected was Qwen3.8-Flash-Next's head-sharded attention and SSM state; `_has_mamba` still excludes that model.

**Behavior by model.**

| model | before | after |
|---|---|---|
| DeepSeek-V4.1 (MLA + `CircularBufferSpec` ring) | per-layer regions | whole rows (#61074 path) |
| Qwen3.8-Flash-Next (CSA + Mamba) | per-layer | per-layer (`_has_mamba`) |
| GLM-5.3-Flash (KDA Mamba) | per-layer | per-layer (`_has_mamba`) |
| non-MLA target with an MLA draft, BLHNC | MLA draft layers took whole rows that also hold head-sharded target pages | per-layer (`use_mla`) |
| other packed MLA (V4.0, GLM-5.3) | #61074 path | unchanged |

The non-MLA row is the only other behavior change. On #61074, such a row also carries the target's head-sharded pages, so transferring it whole is wrong under heterogeneous TP.

**Limitation.** On #61074 only MLA layers join the whole-row region. A ring page that does not start at byte 0 keeps its own region. DSV4.1 holds one ring block per request, so this adds two descriptors per request.

**Versioning.** The metadata schema does not change. Mixed versions fail at handshake because the region counts differ; they do not silently transfer wrong bytes.
