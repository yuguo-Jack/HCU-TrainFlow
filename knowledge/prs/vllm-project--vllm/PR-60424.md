# [HiSparse] Stage host-backed prefills into a reserved buffer

[Upstream PR](https://github.com/vllm-project/vllm/pull/60424) · state: open · merged: False

## Original PR description

## Purpose

Fixes scenario 2 of #60420. When a prompt's KV has spilled to host (e.g. a 1M-token prompt on a HiSparse decoder), prefill copies its history into a GPU buffer one layer at a time. Startup never reserves that buffer, so a long prompt can OOM a running server.

- Stage into the shared workspace, reserved before profiling and sized for one `max_model_len` request (about 0.55 GiB at 1M tokens).
- Split prefill requests into groups that each fit, one staging plan per group. The four sparse MLA backends loop over the groups through `HiSparseMLAIndexGroup.staged_prefills`.

Two related fixes are split out so this one stays small: #60706 bounds two other staging temporaries, and #60707 removes the decode/prefill `torch.cat`.

The builder no longer replaces `prefill.block_table` with the staged block table; only the MHA prefill paths read it, and they're off under HiSparse.

## Test Result

1×B200, GLM-5.3-NVFP4 cut to 4 layers with dummy weights, fp8 KV (FlashInfer), 1.04M-token prompt with 2 requests decoding. "Over profile" is the largest per-step peak above the profiled activation peak:

| case | main | this PR | + #60706 + #60707 |
|---|---|---|---|
| prompt spilled to host (util 0.90) | +2.05 GiB | +1.50 GiB | +0.50 GiB |
| all KV on GPU (util 0.97) | OOM | completes, +1.50 GiB | completes, +0.50 GiB |

The remaining +1.0 GiB here is the decode/prefill `torch.cat`, which #60707 removes. The last column is a local merge of 695cace918, #60706 (973e59af8f) and #60707 (b41fdb34fb).

- Greedy token ids and logprobs are bit-identical to main on FlashInfer fp8 and FlashMLA BF16 (B200), with batches that need 2–3 plans and spilled prompts up to 524K with decodes running.
- `pytest tests/v1/attention/test_sparse_mla_backends.py tests/v1/kv_connector/unit/test_hisparse_connector.py` on B200: 413 passed.
- `-k "hisparse or HiSparse or flashattn"` on H100 (FlashAttn sparse): 66 passed.
- New tests:
  - `test_hisparse_staging_plans_fit_reserved_capacity`
  - `test_hisparse_staged_prefills_rebase_to_plan`
  - `test_hisparse_mixed_batch_bf16_row_split[two_plans]`: fails if the per-plan token offset is wrong, and checks that staging lands in the shared workspace
- FlashInfer SM120: not validated (no SM120 GPU available).
- Perf: with a single group, which is the normal case, this launches the same plan-build ops as main and stages into a reserved view instead of a per-layer `torch.empty`. Groups add small ops only when a batch overflows the buffer. The earlier combined version (d28b093bfb, which also included #60706 and #60707) showed no regression in a `vllm bench serve` A/B on GLM-5.3 TP4 at c=16/64, and scored 0.916 on GSM8K vs 0.905 on main.
