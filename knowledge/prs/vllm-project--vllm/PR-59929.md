# [DeepSeek-V4-P4] Align batch-invariant mHC and o-proj paths

[Upstream PR](https://github.com/vllm-project/vllm/pull/59929) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4 batch-invariant execution needs the same token-level arithmetic path when mHC projections or FP8 o-proj run in a different batch. Fused mHC and token-count-based split selection do not supply that contract for this rollout path.

## Changes

- In `VLLM_BATCH_INVARIANT`, execute explicit mHC pre, attention/FFN, and mHC post stages instead of the fused model-layer path. Keep fused mHC for default execution; preserve sequence-parallel operations and auxiliary hidden-state reconstruction in the unfused branch.
- Select the mHC projection split count as though there were one token in both prenorm and delayed post/prenorm paths. Actual token count still determines tensor sizes, but not that reduction split.
- For batch-invariant FP8 o-proj on the Hopper/non-TMA scale path, use per-group Triton block-scaled matmul. Keep the TMA-packed Blackwell scales on DeepGEMM `fp8_einsum` without reshaping them into an invalid logical layout; non-FP8 execution still uses `torch.bmm`.
- Keep the first-layer mHC broadcast as a non-persistent derived buffer and update its graph-visible storage in place after weight reload.
- Register JIT warmups during model initialization and add an exact-equality mHC regression for an anchor token at first, middle, and last positions over token counts around split boundaries (including 63/64/65 and 127/128/129).

The scope is mHC and o-proj alignment plus their broadcast refresh after weight reload; general reload mechanics remain outside this PR. No end-to-end performance claim is made.

## Validation

- H100 DP4/EP4, four-layer, two-step integration with the other split PRs and weight reload: `training/rollout_probs_diff_valid=1`, `diff_max=0`, `diff_mean=0`, and KL=0 at both steps. The run uses `max_num_batched_tokens=1024` and `gpu_memory_utilization=0.55`; the original 2048-token setting OOMs on this 80 GB setup.
- Local Ruff, compile, and diff checks passed. The standalone mHC exact-equality test was not run separately in this Windows environment. The integrated H100 run validates the reload and graph lifecycle but is not an isolated o-proj benchmark.
