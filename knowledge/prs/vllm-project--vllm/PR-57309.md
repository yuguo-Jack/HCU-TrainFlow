# [KVConnector] Classify transfer groups from the framework's spec kinds

[Upstream PR](https://github.com/vllm-project/vllm/pull/57309) · state: open · merged: False

## Original PR description

Stage 1 of #57373: the classification the KV transfer components dispatch on becomes one table over the kinds the framework already publishes, and every connector and scheduler classification site reads it.

## What changes

**Core.** `vllm/v1/kv_cache_interface.py` gains `get_kv_cache_spec_kind_for_class(spec_cls)`, the class-level form of the existing lookup: the same ordered chain over `issubclass` instead of `isinstance`. `get_kv_cache_spec_kind` keeps its `UniformTypeKVCacheSpecs` branch and delegates the rest to it. The wrapper class has no class-level kind, which the docstring states and a test pins.

**Shared module** `vllm/distributed/kv_transfer/kv_connector/v1/transfer_planning.py`, which imports no connector package:

- `TransferClass` with `ATTENTION`, `SSM` and `OTHER`, and `transfer_class(spec_or_class)`;
- `is_attention_spec`, `is_ssm_spec`, `is_mla_spec`;
- `get_representative_spec` and `get_representative_spec_type`;
- `build_layer_to_spec`, moved out of `moriio/moriio_layout.py`.

`transfer_class` reduces its argument to a class, reads `get_kv_cache_spec_kind_for_class`, maps the named kinds through one table, and decides the kinds the enum reports as `UNKNOWN` from the spec hierarchy. A group is asked as a group: every layer of a `UniformTypeKVCacheSpecs` has to agree on the transfer class, so the answer does not depend on the order of `kv_cache_specs`, and a group that cannot move as one class fails closed. MLA stays a per-layer question: `is_mla_spec` answers for one spec or spec class and rejects a group, which callers ask through `iter_layer_specs`. Passing the wrapper class and passing an empty wrapper both raise, and `get_representative_spec` answers the group-level questions for the representative spec. Participation is not part of the module: the framework exposes it as `KVCacheConfig.transfer_groups` and `transfer_group_ids`, which is what the connectors filter on.

**Adoption.** NIXL: `nixl/tp_mapping.py` drops its private predicates, `nixl/utils.py` drops `get_representative_spec_type`, and every call site imports from the shared module. `_group_spec_types` still holds classes, which the API accepts, and `_compute_desc_ids` keeps its `CircularBufferSpec` identity check. MooncakeConnector: the three cache-group sites pass the spec instance instead of wrapping it in `type(...)`. MoRIIOConnector: `build_layer_to_spec` comes from the shared module, and `moriio_layout.is_mla_cache_layer` uses `is_mla_spec` while keeping its `ValueError` for a missing layer. Two scheduler sites replace a bare `isinstance` switch with the wrapper-aware framework helpers: the sliding-window budget in `nixl/base_scheduler.py`, and the hybrid whitelist together with its window budget in the MoRIIO scheduler. The whitelist keeps the set of specs it serves (full attention, sliding window and mamba) and asks each layer of a group instead of the group wrapper.

**Unchanged.** Descriptor geometry, descriptor ids, notification counts and wire formats. `TPMapping`, `compute_tp_mapping` and `ReadSpec` change only the module they are imported from, and the Mooncake transfer plan (`_get_tp_ratio`, `_compute_sender_transfer_plan`, `TransferRegion` and its validation) is untouched.

## Two deliberate behavior changes

Both follow from asking the wrapper-aware helpers instead of the wrapper itself, and both land with tests that pin the wrapped and the unwrapped answer:

1. A `UniformTypeKVCacheSpecs` group whose layers are all full attention is fully attended, so `_is_hma_required` is False. Pinned by `test_nixl_connector_hma.py::test_wrapped_full_attention_group_needs_no_hma` and `test_moriio_connector.py::test_wrapped_full_attention_group_needs_no_hma`.
2. A wrapped sliding-window group reports the window its layers carry: `blocks_per_sw` becomes the real budget instead of 0, and in MoRIIO such a group passes the hybrid whitelist instead of raising `NotImplementedError`. Pinned by `test_nixl_connector_hma.py::test_sw_sizes_wrapped_groups` and `test_moriio_connector.py::test_hma_blocks_per_sw_wrapped_groups`. A spec the whitelist does not serve still fails closed, which the connector's own `test_non_sliding_window_hybrid_is_rejected` covers.

That gate also skips the two new MoRIIO scheduler tests on this host, so they were exercised directly through the file's own fixtures: the wrapped Full + sliding-window config builds a scheduler with `_is_hma_required` True, `blocks_per_sw == [0, 3]`, `_full_attn_group_idx == 0` and a clipped window tail, and the wrapped full-attention-only config builds one with `_is_hma_required` False and `blocks_per_sw == [0]`. Running the file itself needs an ROCm host with aiter, which the machines used for this work are not.

The `get_kv_cache_spec_kind` callers are `vllm/v1/core/kv_cache_manager.py`, `vllm/v1/engine/core.py`, `vllm/v1/worker/gpu_model_runner.py`, `vllm/v1/simple_kv_offload/manager.py` and `vllm/distributed/kv_transfer/kv_connector/v1/offloading/events.py`; `vllm/v1/attention/selector.py` mirrors the function in a docstring and `vllm/config/attention.py` validates `KVCacheSpecKind` values without calling it. All five are covered by the runs above.

This branch carries a merge of `main`, which rewrote the MoRIIO layout and connector for hybrid mamba/KDA state (#51052). The resolution keeps that geometry and its whitelist and asks them through the wrapper-aware helpers.

`pre-commit run --files <changed files>` passes every hook (ruff check and format, typos, mypy, SPDX headers, forbidden imports, torch.cuda calls, config validation, CI wiring for new tests) and modifies nothing.
