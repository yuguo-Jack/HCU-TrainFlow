# [ROCm][CI][Bugfix] Free in-process engine VRAM in voxtral realtime test to fix teardown OOM

[Upstream PR](https://github.com/vllm-project/vllm/pull/47533) · state: closed · merged: False

## Original PR description

## What

On ROCm, `test_voxtral_realtime_generator` OOMs at startup because the previous test (`test_voxtral_realtime_forward`) never releases its in-process engine. Both build an engine at `gpu_memory_utilization=0.9` in the same pytest process, and pytest keeps the fixture value alive through teardown, so the first engine's VRAM is still held when the second one starts.

## Fix

Drop the engine reference in the fixture teardown and reclaim memory via the same helpers `VllmRunner`/`HfRunner` already use (`cleanup_dist_env_and_memory` + `wait_for_rocm_memory_to_settle`). No-op off ROCm.

## Test

`pytest tests/models/multimodal/generation/test_voxtral_realtime.py` on MI300X: before `1 passed, 1 error` → after `2 passed`.

## TODO

- [ ] Validate on MI325 (`mi325_1`), the original failing job. Same `gfx942` arch, so the fix should carry over, but it hasn't been run there yet.
