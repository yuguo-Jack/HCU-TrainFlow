# [Bugfix][RL] Load HY-V4 learnable sinks through weight_loader

[Upstream PR](https://github.com/vllm-project/vllm/pull/57803) · state: closed · merged: False

## Original PR description

Fix HY-V4 checkpoint-backed learnable sink loading in NVIDIA target/MTP and AMD target models. The AMD target path was omitted from the original series and is included here.



The runtime parameter already has local TP shape. `load_weights` takes the rank slice once and passes it to the parameter's current `weight_loader`; no padded helper or second sharding loader is needed. The AMD and NVIDIA target paths preserve their TP slicing, load the local shard through the current `weight_loader`, and use the same shared `loaded_params` path.

### What changed in this revision

- The AMD and NVIDIA target sink branches still fell through into the generic weight-remapping code after loading the sink. They now `continue`, matching the MTP branch.
- Both target branches also now add the sink to `loaded_params`, so callers that validate "all parameters loaded" see the truth. The MTP branch already did.
- All three sites use the shared `load_padded_attn_sink` helper instead of a second copy of the inline loader lookup. HY-V4's parameter already has the local head shape, so the helper's padding path is a no-op there.
