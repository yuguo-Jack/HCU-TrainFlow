# [Bugfix][LoRA] Validate incompatible MoE adapter formats

[Upstream PR](https://github.com/vllm-project/vllm/pull/59924) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Reject fused 3D MoE LoRA weights on a 2D wrapper when the required format settings are missing, with an error naming both settings.

Addresses the actionable-error follow-up in item 4 of #59799; complements #59801.

## Claims

- Detect this incompatible layout before adapter registration and activation.
- Explain how to enable `enable_mixed_moe_lora_format` and set `is_3d_lora_weight`.
- Check during worker loading before replacing or evicting a cached adapter.

## Validation

Validated on one NVIDIA A10G (AWS g5.2xlarge), FP16, using a tiny random Qwen3-MoE model and a PEFT 0.21.2 adapter, based on commit `6f75cc7d5d1b5adfb399cbf79a8231ae66844fcf`.

These results cover the patch committed as `2f8c900063f3`, before the subsequent merge of `main` into this branch. They are not CI results for the updated PR head.

- `python -m pytest tests/lora/test_lora_manager.py -v`: **28 passed**, including eight new cases.
- `pre-commit run --files vllm/lora/model_manager.py vllm/lora/worker_manager.py tests/lora/test_lora_manager.py docs/features/lora.md`: all applicable hooks passed.
- `git diff --check`: passed.

| Full-engine case | Result |
| --- | --- |
| Original reproducer, missing both settings | Bare assertion replaced by a descriptive worker `ValueError`; generation still ends with `EngineDeadError`. |
| Original reproducer, both settings enabled | Generates `[190, 737, 34, 78]`, matching the baseline control. |
| Dynamic `add_lora`, each of the three missing-flag combinations | Returns the actionable error; generation continues afterward. |
| Dynamic rejection with a valid adapter already filling the cache | Valid adapter ID remains registered; deterministic generation is unchanged. |

The original generation reproducer is in #59799; these runs use FP16 on the
A10G. The dynamic-loading harness below is self-contained:

```sh
VLLM_WORKER_MULTIPROC_METHOD=spawn python validate_59799.py
VLLM_WORKER_MULTIPROC_METHOD=spawn python validate_59799.py --mixed
```

Both commands complete successfully. New unit cases run in the existing LoRA CI
job. Multi-GPU behavior and HTTP serving were not tested.

This is a loading/activation smoke test, not a model-quality evaluation. The change does not alter LoRA scaling, conversion or kernels.

```python
"""Validate dynamic loading errors and continued generation on a CUDA engine."""
import argparse
from pathlib import Path
import tempfile
import torch
from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM, Qwen3MoeConfig
from vllm import LLM, SamplingParams
from vllm.inputs import TokensPrompt
from vllm.lora.request import LoRARequest


def make_checkpoint(directory):
    torch.manual_seed(0)
    config = Qwen3MoeConfig(
        vocab_size=1024, hidden_size=256, intermediate_size=512,
        moe_intermediate_size=128, num_hidden_layers=2,
        num_attention_heads=4, num_key_value_heads=2, head_dim=64,
        num_experts=8, num_experts_per_tok=2, tie_word_embeddings=False,
    )
    model = AutoModelForCausalLM.from_config(config, dtype=torch.float16)
    model.save_pretrained(directory / "base")
    lora = LoraConfig(
        r=16, lora_alpha=32, target_modules=[],
        target_parameters=["mlp.experts.gate_up_proj", "mlp.experts.down_proj"],
    )
    get_peft_model(model, lora).save_pretrained(directory / "lora")

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--mixed", action="store_true")
    args = parser.parse_args()
    with tempfile.TemporaryDirectory() as tmp:
        directory = Path(tmp)
        make_checkpoint(directory)
        llm = LLM(str(directory / "base"), skip_tokenizer_init=True,
                  dtype="float16", enable_lora=True, max_lora_rank=16,
                  max_cpu_loras=1, max_loras=1, max_model_len=256,
                  gpu_memory_utilization=0.3, enforce_eager=True,
                  enable_mixed_moe_lora_format=args.mixed)
        prompt = TokensPrompt(prompt_token_ids=list(range(10, 40)))
        params = SamplingParams(max_tokens=4, temperature=0, detokenize=False)
        engine = llm.llm_engine
        good = LoRARequest("good", 1, str(directory / "lora"), is_3d_lora_weight=True)
        if args.mixed:
            assert engine.add_lora(good)
            before = llm.generate(prompt, params, lora_request=good)[0].outputs[0].token_ids
            expected_ids = {1}
        else:
            before = llm.generate(prompt, params)[0].outputs[0].token_ids
            expected_ids = set()
        declarations = [False] if args.mixed else [False, True]
        for declared in declarations:
            bad = LoRARequest("bad", 2, str(directory / "lora"), is_3d_lora_weight=declared)
            try:
                engine.add_lora(bad)
            except Exception as exc:
                message = str(exc)
                assert "enable_mixed_moe_lora_format=True" in message, message
                assert "is_3d_lora_weight=True" in message, message
                print("EXPECTED REJECTION:", type(exc).__name__, message, flush=True)
            else:
                raise AssertionError("Incompatible adapter was accepted")
            actual_ids = engine.list_loras()
            print("REGISTERED ADAPTERS:", repr(actual_ids), flush=True)
            assert set(actual_ids) == expected_ids, actual_ids
            after = llm.generate(prompt, params, lora_request=good if args.mixed else None)[0].outputs[0].token_ids
            assert after == before, (before, after)
            print("PASS: engine remains usable; adapters", expected_ids, "tokens", after, flush=True)

if __name__ == "__main__":
    main()
```

## Details

Without both format settings, fused expert tensors reach `FusedMoEWithLoRA.set_lora`, which expects packed lists and raises a bare assertion. The validator checks actual loaded weights and wrapper type, preserving native 3D wrappers and the supported mixed-format conversion path. Per-expert and attention-only adapters are not rejected.

The check runs on adapter loading, not each token. It is deliberately limited to this layout mismatch; it does not provide general adapter validation or change exception handling during generation. Lazy loading through `LLM.generate()` can still terminate the engine, now with actionable configuration guidance in the worker error.

No duplication: #59801 handles per-module scaling and rank validation and explicitly leaves this error-handling follow-up open. #52198 handles tensor orientation, and #59915 handles Inkling-specific conversion.

AI assistance: Codex was used for implementation, regression tests, and GPU validation.
