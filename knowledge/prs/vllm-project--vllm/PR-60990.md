# [Bugfix][ROCm][MiniMax-M3] Reject unbuilt index-head counts in the AITER indexer

[Upstream PR](https://github.com/vllm-project/vllm/pull/60990) · state: open · merged: False

## Original PR description



## Overview

The MiniMax-M3 AITER MSA indexer selector now rejects index-head counts AITER has no score kernels for, so attention TP=1 fails at load with a clear error instead of crashing on the first decode step.

## Claims

- `aiter_indexer_unsupported_reason` only accepts 1 or 2 index heads, the counts AITER instantiates its MSA score kernels for.
- `test_minimax_m3.py` gains a regression test that fails without the fix and passes with it.

## Validation

- Reproducer on MI355 (gfx950), unfixed: driving the AITER indexer with 4 index heads gets past the selector and fails in AITER with `pa_sparse_block_score_decode: no build for num_idx_heads=4 num_waves=4`. With the fix, the selector rejects it and the caller falls back.
- `test_aiter_indexer_rejects_unbuilt_index_heads`: fails without the fix, passes with it.
- `pytest tests/kernels/attention/test_minimax_m3.py` on MI355: 10/10 runs passed (157 passed, 14 skipped each).

Before/after on `amd/MiniMax-M3-MXFP4`, MI355, TP=2 (2 index heads per rank, so the AITER indexer is selected before and after: every run logs `MiniMax M3 indexer: selected AITER`), with `VLLM_ROCM_USE_AITER=1 VLLM_ROCM_SHUFFLE_KV_CACHE_LAYOUT=1` and `--attention-config '{"indexer_kv_dtype":"fp8"}'`, which is what selects that indexer. 5 runs per column, interleaved, fresh server each run; mean ± sd.

- `pre-commit run` on the changed files passes; mypy is clean for Python 3.11 and 3.12.

## Details

MiniMax-M3 has 4 index heads, so each rank gets 4 at attention TP=1, for example with DP attention. The selector only rejected head counts above the 16 MFMA columns, but AITER builds its sparse score kernels for 1 or 2 index heads only (`SPARSE_DECODE_TABLE`/`SPARSE_PREFILL_TABLE` in `pa_sparse_block_select.hpp`, the same at the `v0.1.24.post1` pin and at AITER main `b0c4209d4d`). The AITER indexer was therefore selected and then failed inside the kernel dispatch. A rejected config falls back to the platform-neutral indexer; with the AITER sparse attend still requested, the attend then rejects the configuration at load (`AITER sparse paged attention requires num_kv_heads == 1 per tensor-parallel rank`), and without it the Triton indexer rejects the fp8 index cache, so that config now gets a clear load-time error. Nothing that works today changes: TP ≥ 2 still gives each rank 1 or 2 heads and keeps the AITER path. The new test asks the selector itself whether the AITER indexer is available rather than naming an architecture, so it follows the selector when more CDNA targets are added. It runs on AMD CI once a follow-up PR adds the MI355 mirror for MiniMax-M3 Attention Kernels; other platforms skip it.

No open PR fixes this. #57909 moves this selector into `msa_indexer_unsupported_reason` in a new `indexer_msa.py`, and its unsharded path (`cp_world=1`) has no head-count check either, so if #57909 lands first the same guard belongs there.
