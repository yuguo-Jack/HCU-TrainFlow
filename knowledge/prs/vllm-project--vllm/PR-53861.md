# [Bugfix] Harden streaming-input session lifecycle

[Upstream PR](https://github.com/vllm-project/vllm/pull/53861) · state: open · merged: False

## Original PR description

## Purpose

Fix four independent bugs in resumable (streaming-input, #28973) sessions. I hit all of
them while running multi-hour video streaming sessions for RFC #51948. None of them changes behavior
for normal (non-streaming) requests.

**1. The output collector can erase chunk boundaries.**
`RequestOutputCollector` merges DELTA outputs when the producer runs ahead of the
consumer, and `RequestOutput.add()` overwrites `finish_reason`. For streaming-input
requests, the per-chunk boundary is exactly such a transient `finish_reason` on a
non-finished output. So when a merge happens across a boundary, the marker is lost and
the consumer sees two chunks' replies glued together as one.
Fix: replace the single-slot collector with a small deque that never merges into an
entry that is finished or already carries a `finish_reason`. For non-streaming requests
the `finish_reason` output is always the last one put, so nothing changes for them.

**2. An engine-side ABORT/ERROR is treated like a normal chunk boundary.**
`process_outputs()` treats any `finish_reason` on a streaming-input request as "chunk
done, wait for the next one". But ABORT and ERROR are terminal for the whole session.
Masking them leaves the consumer waiting forever, and the frontend and scheduler chunk
queues go out of sync by one.
Fix: only treat the non-terminal reasons as chunk boundaries. On ABORT/ERROR, finish
the request state and route an abort back to the engine core (idempotent if it already
finished there).

**3. A chunk racing behind an abort can resurrect the session as a zombie.**
`close()` on the collector only cancels the input-stream task, it does not wait for it.
So an in-flight chunk ADD can still be sent after the abort went out. The scheduler
then sees a resumable request with an unknown id and admits it as a brand-new session,
which parks in `WAITING_FOR_STREAMING_REQ` forever and pins its KV blocks until server
restart. There is no way to abort it, because no client is attached to it.
Fix, two layers: (a) `_stop_input_stream()` cancels AND awaits the input task before
the abort is sent, so the window closes. (b) Every chunk now carries
`EngineCoreRequest.first_chunk`; the scheduler drops non-first chunks for unknown ids.
Only first chunks can create sessions, so the zombie can't happen by construction.

**4. Three smaller ones in the same area.**
- A stream that ends without ever sending a chunk used to run the placeholder final
  request (a 1-token dummy prompt) as a real generation, just to unblock the consumer.
  Now it just puts `STREAM_FINISHED` on the queue.
- With data parallelism, each chunk of a session was load-balanced independently, so a
  session's chunks got split across engines that don't share its KV. Now chunks of an
  in-flight request are routed to the engine that already holds it (reusing the
  existing `reqs_in_flight` map).
- Sessions rewrite their KV blocks in place at chunk folds while the prefix-cache hashes stay stale, so another request matching a stale hash would read changed content. Fix: a per-session cache_salt makes the session's blocks unmatchable by anyone else.

## Test Plan

New tests: 6 in `tests/v1/streaming_input/test_session_hardening.py` (abort race,
first_chunk stamping and scheduler drop, task-pointer lifetime, zero-chunk stream,
sticky DP routing) and 4 in `tests/v1/engine/test_output_processor.py` (collector
boundary merge, STOP as chunk boundary, ABORT/ERROR as terminal).

## Test Result

- 9 of the 10 new tests fail on current main without the fixes. All 10 pass with the fixes.
- Full `tests/v1/streaming_input/` + `test_output_processor.py`: all pass; the failure
  set of the pre-existing tests is identical to main on the same machine.

        tail = self.pending[-1] if self.pending else None
        if (
            isinstance(tail, RequestOutput)
            and isinstance(output, RequestOutput)
            and not tail.finished
        ):
            finished_indices = {
                completion.index for completion in tail.outputs if completion.finished()
            }
            if not any(
                completion.index in finished_indices for completion in output.outputs
            ):
                tail.add(output, aggregate=self.aggregate)
                return
        elif isinstance(tail, PoolingRequestOutput) and isinstance(
