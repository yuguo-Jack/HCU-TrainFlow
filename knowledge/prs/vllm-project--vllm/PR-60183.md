# [Core] Add fail-closed engine-level LLM.reload_weights with derived-cache invalidation

[Upstream PR](https://github.com/vllm-project/vllm/pull/60183) · state: open · merged: False

## Original PR description

## Overview

Reloading model weights through the worker RPC can leave scheduler-owned prefix KV entries from the previous checkpoint available for reuse (#48312). This PR adds `LLM.reload_weights(weights_path=None)` to reload an offline checkpoint and invalidate engine-owned caches together.

## Claims

- Reload only when the engine is idle and awake; reject data-parallel configurations.
- Drain pending execution, synchronize the device, reload weights, then clear prefix KV, encoder, and multimodal caches through the existing reset path.
- Require engine reconstruction after an execution failure, preventing further inference with potentially partially updated weights.

## Validation

The reproducer warms a prompt with checkpoint A, reloads B, and submits the same prompt again. The first post-reload request must use **zero cached tokens**; output is compared with a cold-loaded B. Restoring A and repeating reloads check that cache invalidation works across weight changes.

| Check | Result |
| --- | --- |
| Cache invalidation | First request after each reload uses 0 cached tokens. An earlier-base worker-RPC control reused 496 stale cached tokens. |
| Qwen3-0.6B, TP=2 | A→B→A→B cycles match cold-reference generated tokens; maximum generated-logprob difference 3.45e-6. |
| Qwen3-8B BF16, TP=1 and TP=2 | Under eager execution, per-state warmup, and one request at a time: generated tokens and measured logprobs match cold references exactly. Each state has two measured repeats over 20 prompts, with up to 32 generated tokens. |
| Qwen3-8B BF16, TP=2 baseline comparison | Default compilation, fixed request admission, warmup, batch size 4: all eight corresponding state/repeat comparisons have identical generated tokens and zero measured logprob difference between the PR and unpatched baseline. The baseline uses worker reload plus manual cache invalidation. |
| Loading failure | Truncated safetensors raises; reload/resume and inference cannot continue. Reconstructing the engine restores generation. |
| Regression tests | 20 engine tests, 1 scheduler regression, and 1 GPU reload regression passed. Scoped pre-commit and mypy-3.12 passed. |

**Numerical limits.** Uncontrolled batched comparisons exceed the 0.001 tolerance even without reload. With fixed admission, repeat measurements stabilize and the PR matches the unpatched baseline exactly in every corresponding state. Both arms still fail the same six reload-B-versus-cold-B checks, including generated-token comparisons; this shared difference is unresolved. No additional PR discrepancy was observed under the tested conditions; these results do not establish universal cold-load equivalence.

## Details

**Why the engine owns this operation.** Workers can reload parameters but cannot invalidate scheduler-owned KV entries. The new entry point coordinates reload with the existing engine cache-reset path; direct worker RPC behavior is unchanged.

**How validation was refined.** Cold-reference comparisons initially exposed numerical differences. For 0.6B, bidirectional single-kernel swaps isolated the measured difference to distinct compiled RMSNorm configurations. For 8B, warmup with single-request eager execution gave exact cold-reference agreement. A subsequent batched comparison queued all requests before resuming scheduling: the PR and unpatched baseline then produced identical corresponding outputs. This isolates the observed PR delta under those conditions; it does not explain the shared cold-B/reloaded-B difference.

**Failure contract and coverage.** Reload has no rollback. After execution failure, reconstruction is required; in multiprocess mode, a new request can terminate EngineCore. The real loading-failure check covers metadata validation, not failure after partial parameter mutation or detection of every incomplete checkpoint. Connector, multimodal, and AsyncLLM paths lack end-to-end coverage; DP is rejected.

**Related work.** #51378 resets the prefix cache after `finish_weight_update()` for weight-transfer sessions. This PR covers offline checkpoint reloads through `LLM`; it overlaps in `entrypoints/llm.py` but changes a different flow. Duplicate-work checks were completed before submission.

AI assistance was used. The human submitter reviewed the changed lines and reran the original tests; additional GPU experiments were agent-run.
