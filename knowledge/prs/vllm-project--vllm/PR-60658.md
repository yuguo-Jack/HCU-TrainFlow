# [ROCm][Perf] TRITON_ATTN: tuned launch configs for gfx1100 and gfx1201

[Upstream PR](https://github.com/vllm-project/vllm/pull/60658) · state: open · merged: False

## Original PR description

## Purpose

Tune `kernel_unified_attention` launch parameters (TRITON_ATTN) for gfx1100 and gfx1201. The upstream defaults (2D: `BLOCK_M=16`, `TILE_SIZE=32`, Triton default warps/stages) leave a lot of prefill/mixed-batch performance on the table on both architectures.

Only launch parameters change (`BLOCK_M`/`BLOCK_Q`, prefill `TILE_SIZE`, `num_warps`, `num_stages`); kernel math is untouched. All changes are gated on the exact arch (`on_gfx1100()`, new `on_gfx1201()`) and skipped under batch invariance; fp8 queries keep `TILE_SIZE >= 32`.

| arch | path | change |
|---|---|---|
| gfx1100 | 2D (`max_seqlen_q > 1`, `num_queries_per_kv <= 32`) | `BLOCK_M=32`, `TILE=16`, 4 warps, 1 stage |
| gfx1100 | 3D (decode) | 8 warps, 1 stage |
| gfx1201 | 2D, avg query tokens/seq `< 8` | unchanged (default) |
| gfx1201 | 2D, avg 8–63 | `BLOCK_M=32`, `TILE=32`, 4 warps, 1 stage |
| gfx1201 | 2D, avg 64–159 | `BLOCK_M=64`, `TILE=16`, 4 warps, 1 stage |
| gfx1201 | 2D, avg `>= 160` | `BLOCK_M=128`, `TILE=16`, 8 warps, 1 stage |

gfx1201 decode (3D) is unchanged.

## How the configs were found

1. A sweep (autotuning) over the launch parameters: `BLOCK_M`, `TILE_SIZE`, `num_warps`, `num_stages`, `waves_per_eu`, the 3D segment count and the 2D/3D path. On gfx1100 that is 559 decode and 217 mixed variants per batch.
2. Every variant runs through vLLM's own `TritonAttentionImpl.forward` with the tensor layouts vLLM uses (paged KV cache, block tables, sequence lengths), on Qwen3.5-9B attention shapes: decode, mixed prefill + decode, and long prefills. Every variant's output was checked against the default launch (atol 2e-2, rtol 1.6e-2): **0 wrong outputs**. The only failures were `TILE=64` variants that exceed LDS/register limits.
3. Configs were picked by total attention time over the batches:
   - **gfx1100:** one fixed config per path is within 1% of the per-shape best (3.14x vs 3.17x mixed, 1.07x vs 1.08x decode), so no further heuristic was added.
   - **gfx1201:** the best `BLOCK_M` grows with prefill length per sequence, hence the three average-query-length tiers.

- One long-prompt batch at the 64–159 tier boundary (1070 tokens / 15 seqs, avg 71, 6.4k context) is 0.68x.

### gfx1100: generalization beyond the tuned shape

The configs were tuned on one attention shape (head_dim 256, 16/4 heads). To check other shapes, I ran a standalone TRITON_ATTN benchmark matrix: 32 configs × 7 cases (decode, mixed, prefill) across head_dim 64/96/128/192/256, GQA 1:1 to 8:1, block sizes 16/32/64/528, bf16/fp32, fp8 KV cache, sliding window and sinks. It ran before and after this change, with every output checked against an fp32 reference.

|---|---|---|
| 64 | 1.42x | 1.05x |
| 96 | 1.35x | 1.05x |
| 128 | 1.43x | 1.02x |
| 192 | 3.14x | 1.06x |
| 256 | 3.02x | 1.08x |

- **Correctness:** 224/224 rows OK against the fp32 reference; 0 mismatches, errors or crashes.

- **Worst cases:** 0.91x on one d128 decode case (4 seqs × 4k context, block size 528), and 0.85x on one fp8-KV d128 decode case.

## Relation to #52684

#52684 also tunes the gfx1100 2D path. It only covers long prefill (`max_seqlen_q >= 512`, `BLOCK_M=64`) and leaves decode, mixed batches and short prefill on the default. This PR:
- tunes all 2D batches with prefill tokens on gfx1100, chosen on mixed prefill + decode batches, which make up most steps when serving;
