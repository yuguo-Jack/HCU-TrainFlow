# [Refactor] Move Humming MoE setup into the oracle

[Upstream PR](https://github.com/vllm-project/vllm/pull/57538) · state: open · merged: False

## Original PR description

## Overview

Move `HummingMoEMethod` expert selection, weight conversion, quant configuration, and kernel construction into `fused_moe/oracle/humming.py`, addressing the Humming portion of #54959. Checkpoint parameter creation/loading stays in the quantization method.

## Claims

- Preserve existing kernel preference and execution behavior while putting MoE setup behind the oracle boundary.
- Incorporate merged #56685: retain its modular schema/linear helpers, runtime input-schema fallback, Hadamard handling, and input-scale propagation. Update the new W4A8 caller as well as existing callers.
- Shared `HummingMoEQuantConfig` and its factory remain in `quantization/utils/humming/moe.py`; no quantization modes or expert kernels are added.
- Preserve the upstream `prefers_humming` and `prioritize_humming` exports introduced by #56997 when resolving the latest merge conflict.
