# [Bugfix][Model] Validate runai_streamer model_loader_extra_config

[Upstream PR](https://github.com/vllm-project/vllm/pull/45291) · state: closed · merged: True

## Original PR description


## Purpose

`RunaiModelStreamerLoader` reads `model_loader_extra_config` with `isinstance` guards that silently drop anything unexpected:

```python
if isinstance(concurrency := extra_config.get("concurrency"), int):
    os.environ["RUNAI_STREAMER_CONCURRENCY"] = str(concurrency)
```

So invalid configs are accepted silently instead of being reported:

- unknown keys (e.g. `{"typo_key": 1}`) are ignored;
- a wrong type (`concurrency="16"`) is dropped, so the requested concurrency is never applied;
- a negative value (`concurrency=-1`) sets `RUNAI_STREAMER_CONCURRENCY=-1`.

Validate the extra config at loader construction: reject unknown keys, require a bool `distributed`, and a positive int `concurrency`/`memory_limit`. All values are validated before any `os.environ` mutation, so an invalid config cannot leave a partially-applied global state.

Scope note: the unknown-key rejection mirrors what `DefaultModelLoader` already does. The type/range checks are stricter than the previous runai behavior: a config that used to be silently dropped (e.g. `concurrency="16"`, a typo'd key, or a non-positive `concurrency`/`memory_limit`) now raises. This is intentional (silently ignoring a requested value is worse than failing), but it is a behavior tightening, so flagging it for maintainer judgment; it could be relaxed to a warning if preferred.

## Test Plan

```bash
pytest tests/model_executor/model_loader/runai_streamer_loader/test_runai_model_streamer_loader.py -k extra_config
```

Folded into the existing `runai_streamer_loader/test_runai_model_streamer_loader.py` (no new file), over the real `RunaiModelStreamerLoader`: unknown key, non-bool `distributed`, and string/negative `concurrency` are rejected; a valid config is accepted and applies the env vars.

With the fix the tests pass; reverting it fails the six "reject" cases (the invalid configs are silently accepted).
