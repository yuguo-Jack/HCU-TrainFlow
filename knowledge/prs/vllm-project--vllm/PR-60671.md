# [Bugfix][DCP] Finalize layout-dependent config before profiling

[Upstream PR](https://github.com/vllm-project/vllm/pull/60671) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Summary

NIXL P/D with DCP finalized `cp_kv_cache_interleave_size` during connector initialization, after profiling. `SparseAttnIndexer` could therefore use a stale interleave while the final cache and transfer layouts used the resolved value, corrupting sparse indices.

- Resolve global KV-cache groups once after layout selection, publish the same groups to workers before profiling, and reuse them for allocation.
- Keep NIXL-specific resolution in `VllmConfig`; connector initialization no longer mutates configuration.
- Read the interleave directly from `ParallelConfig` instead of caching it in `SparseAttnIndexer`.
- Remove the duplicate `dcp_kv_cache_interleave_size` field while retaining `--dcp-kv-cache-interleave-size` as a CLI alias.
