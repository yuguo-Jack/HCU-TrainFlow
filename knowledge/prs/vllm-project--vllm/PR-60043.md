# [Core][Mamba] Remove leftovers of mamba_cache_mode="all"

[Upstream PR](https://github.com/vllm-project/vllm/pull/60043) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Follow-up to #58997. Removes what was left of `mamba_cache_mode="all"` and deprecates `--mamba-cache-mode`, which no longer has any effect.

## Changes

- **KV cache manager:** `MambaManager` asserts that prefix caching runs only with `mamba_cache_mode="align"`. A `"none"` group under a caching manager used to silently run all-mode dense caching. Production never pairs them: `MambaModelConfig` ties `"align"` to prefix caching on and `"none"` to off.
- **CLI:** deprecated `--mamba-cache-mode`. `MambaModelConfig` already overwrote any user value (`"align"` iff prefix caching is on), so the flag is now ignored with a warning and will be removed in v0.33.0. ReplaySSM/RecoverSSM errors, config docstrings, docs, CI configs and e2e tests now refer to prefix caching instead of the flag.
- **Kernels:** dropped the APC per-block state inputs from Triton `causal_conv1d_fn` / `causal_conv1d_update`. No caller used them, and the non-APC path is unchanged. XPU is untouched.
  - Two all-mode leftovers are kept on purpose:
    - SSD's `return_intermediate_states`: #57329 uses it for Mamba2 internal prefill checkpoints.
    - CUDA `selective_scan_fwd`'s per-block state outputs: Mamba1 internal checkpoints will need mid-prefill state output from that kernel.
  - Conv-window checkpoints do not need the `causal_conv1d` inputs, because they are written from the pre-conv input.
- **Models:** removed the `supports_mamba_prefix_caching` flag. Its only reader was the all → align fallback deleted in #58997. Dropped the `SupportsMambaPrefixCaching` base from hybrid models, since `IsHybrid` already declares `get_mamba_state_copy_func(s)`. Only attention-free `Mamba`/`Mamba2` keep it.
- **Docs/comments:** fixed stale all-mode descriptions.
- **Tests:**
  - Mamba prefix-caching tests use `"align"`. `req0` is split so align keeps a state at the shared prefix.
  - Dropped `test_mamba_shared_prefix_survives_zero_retention`. Its flow is covered by `test_mamba_shared_prefix_reuse_under_zero_retention`.
  - The simple-offload DCP geometry test uses a replicated attention group.
  - `test_p_side_chunked_prefill_mamba` runs without prefix caching.
  - Fixed `test_mixer2_gated_norm_multi_gpu`, which also failed on `main`: its spawned workers had no vLLM config.

## Compatibility

- `ModelConfig.supports_mamba_prefix_caching` is removed. A leftover `supports_mamba_prefix_caching` class attribute is ignored.
- `--mamba-cache-mode` / `EngineArgs.mamba_cache_mode` is deprecated: ignored with a warning, removed in v0.33.0. Behavior is unchanged for Mamba models, since the value was already overwritten. `CacheConfig.mamba_cache_mode` stays and is still derived from `enable_prefix_caching`.
