# [Bugfix][Weight Cache] Include RoPE parameters in IPC cache key

[Upstream PR](https://github.com/vllm-project/vllm/pull/60994) · state: open · merged: False

## Original PR description



## Overview

Prevent IPC weight cache reuse across different text RoPE configurations, which could otherwise cause engines to use incompatible cached rotary buffers.

## Claims

- Reject incompatible RoPE configurations through the existing cache-key mismatch and disk fallback handling.
- Preserve cache reuse for matching configurations, including explicitly specified defaults.
- Preserve standalone in-place weight reloading when model construction normalizes RoPE parameters.

## Validation

```bash
HF_HUB_OFFLINE=1 CUDA_VISIBLE_DEVICES=0 .venv/bin/python -m pytest \
  tests/model_executor/model_loader/test_weight_cache.py \
  -k 'not cold_start_and_warm_restart' -q
```

18 passed, 3 deselected. Tests cover RoPE configuration differences, explicit defaults, nested multimodal text configs, and startup versus reload matching.

Separately validated with DeepSeek-R1-Distill-Qwen-1.5B on an H800 (TP=1, V1 runner, eager mode):

- Matching configurations load through IPC and match normal disk loading.
- Different theta values raise a configuration mismatch when fallback is disabled.
- With fallback enabled, both `zero_copy` and `copy` modes match normal loading with the requested configuration in generated token IDs and prompt logprobs.

A CPU regression check using the DeepseekV2 attention constructor and IPC protocol verified that standalone `load_weights` accepts constructor-normalized RoPE parameters and rejects mismatched theta values.

All applicable pre-commit checks passed. The three existing model E2E tests were not run. GPU validation covers startup, not in-place reloading.

## Details

The daemon exports non-persistent buffers, including rotary caches, but `WeightCacheKey` previously omitted RoPE parameters. Engines using the same checkpoint with different RoPE settings could therefore reuse incompatible buffers.

Add a fingerprint of `hf_text_config.rope_parameters` to the cache key. For standalone in-place reloading, also accept the daemon's post-construction RoPE fingerprint, since model constructors can normalize these parameters. Startup still requires the original fingerprint, and all other cache-key checks remain unchanged.
