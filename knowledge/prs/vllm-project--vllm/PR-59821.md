# [Bugfix][Parser] Preserve quoted Qwen3 tool markup in reasoning

[Upstream PR](https://github.com/vllm-project/vllm/pull/59821) · state: open · merged: False

## Original PR description



## Overview

Fixes https://github.com/vllm-project/vllm/issues/58147. A ⁠ <tool_call> ⁠ block quoted as an example inside explicitly closed Qwen3 reasoning was executed as a real tool call. The parser now defers a tool opener seen during reasoning until ⁠ `</think>` ⁠ or the end of the stream.

## Claims

•⁠  ⁠Tool-shaped text inside explicitly closed Qwen3 reasoning stays reasoning and is never executed.
•⁠  ⁠Implicit-end tool calls (no ⁠ `</think>` ⁠) keep working, including through the reasoning adapter.
•⁠  ⁠Qwen3-derived parsers (Nemotron, MiMo, SeedOSS, Granite) are unchanged.

## Validation

•⁠  ⁠⁠ python -m pytest tests/parser/engine/ ⁠: 5,352 passed (14 pre-existing Torch JIT deprecation warnings).
•⁠  ⁠Broad shared-parser regression run covering Nemotron v3, SeedOSS, Granite, engine/parser-engine, Qwen3 and related reasoning suites, Gemma4 streaming reasoning, and Inkling: 693 passed.
•⁠  ⁠New tests cover quoted markup in streaming reasoning, explicit close, a later real tool call, implicit-end calls, adapter finish with complete and partial spans, split markers, multiple quoted spans, empty spans, reset, and skip-tool-parsing mode.
•⁠  ⁠Existing implicit-end streaming expectations pass unchanged; neither existing Qwen3 reasoning test file was edited.
•⁠  ⁠Ruff check, Ruff format check, and ⁠ git diff --check ⁠ passed.

Reproduce the quoted-markup bug and check the fix with the Qwen3/parser-engine suites: `python -m pytest tests/parser/engine/test_qwen3.py tests/parser/engine/test_parser_engine.py -q` (204 passed; 14 pre-existing Torch JIT deprecation warnings). Full parser directory: `python -m pytest tests/parser/engine/`.

## Details

Root cause: the parser fired the implicit (REASONING, TOOL_START) transition on sight, so a quoted example inside reasoning became a real call. Design: hold the opener and its span while reasoning is open. An explicit `⁠ </think>` ⁠ returns the span as reasoning; reaching stream end replays it through the existing implicit-end path. The hold is an opt-in config flag, default off, enabled only for base Qwen3 with thinking on and a prompt inside an open think block.

In the issue thread, I reproduced and diagnosed the behavior. ArtyomITA explored an environment-flag alternative, then abandoned it because it broke seven implicit-end tests and the use case in #39056. #57553 is related follow-up work for Qwen3-derived parsers.

Tradeoffs: for Qwen3 thinking requests, implicit-end tool calls resolve at stream end rather than incrementally; the held span stays buffered until resolution; a small public finish option was added to the parser engine so the reasoning adapter can resolve a held span at stream end.

AI-assisted with Cursor; all changes reviewed and verified by me.

`resolve_deferred_tool_start` is an internal parser-engine finish hook used by the Qwen3 reasoning adapter to preserve existing implicit-end tool-call behavior; it is not a public serving/API option.
