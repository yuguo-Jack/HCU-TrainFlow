# [MoRIIO] Preserve hybrid READ tracking on failure and timeout

[Upstream PR](https://github.com/vllm-project/vllm/pull/60640) · state: open · merged: False

## Original PR description

## Overview

Hybrid READ completion cleanup can discard transfer tracking, or notify P to release blocks, while another transfer remains pending. Raise `TransferError` on failure or timeout before cleanup changes ownership.

Rebased onto main `bfa7e5b7afe40ebe48288801a2baf5c1135cd881`. This remains an independent child of closed #58968.

## Claims

```diff
D observes hybrid READ [FAILED, PENDING] or an expired pending READ
- enter completion cleanup and lose in-flight tracking
+ raise before release notification or tracking deletion
```

Successful hybrid completion and existing attention-only recovery retain their behavior.

## Details

The normal layer/step wait already raises on failed transfers. The missing guard is in `_pop_done_transfers`, reached from READ completion collection. Hybrid state has no safe fallback through the attention-only invalid-block recovery path.

Raising prevents this cleanup path from releasing ownership; it does not drain/revoke DMA or provide automatic recovery. Producer retention until a real ACK is separate work in #56465. That PR also modifies consumer timeout notification, so composition must preserve this hybrid exception before any timeout release. #58962 concerns WRITE consumer timeout; #60544 adds hybrid WRITE and batch waits. Neither is this READ cleanup guard. #58968 was closed after the split.

**Merge danger:** two-way door; blast radius: MoRIIO hybrid READ error handling. A failed hybrid transfer aborts instead of continuing with incomplete recurrent state.

#60808 moves input waits into `start_load_kv`; it does not provide DMA drain/revoke or replace this completion-cleanup guard. Producer ACK retention remains separate in #56465.
