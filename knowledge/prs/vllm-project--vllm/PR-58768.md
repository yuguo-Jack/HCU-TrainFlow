# [docker] add vllm-openai-efa target

[Upstream PR](https://github.com/vllm-project/vllm/pull/58768) · state: open · merged: False

## Original PR description

This PR is to improve vLLM out-of-box experience on AWS GPU clusters.

1. Added a new build target `vllm-openai-efa` to build image with EFA user space libraries and mooncake-transfer-engine-efa.
2. Extended CI workflow scripts to build and publish the newly added target images.
NOTE:
The PR adds a new target `vllm-openai-efa` instead of updating the existing `vllm-openai` because the `rdma-core` version from EFA installer is different from the version comes with distro. Though the latest `rdma-core` version from the EFA installer should work for non-EFA platforms as well, we didn't test that configuration. And also not to interfere with the existing build configurations, we took a new target approach.

## Purpose
To improve vLLM out-of-box experience on AWS GPU clusters.


## Test Plan
1. P-D disaggregated inference on AWS p5en.48xlarge 2 node cluster with NIXL LIBFABRIC (efa provider) backend - to be specific, I ran vllm multi-turn conversation benchmark with Qwen3-32B model.

2. TBD - test Mooncake TransferEngine with EFA trasport

- snadampal · comment · 2026-09-25T20:03:11Z · [source](https://github.com/vllm-project/vllm/pull/58768#issuecomment-5838765882)

Here are the steps to build and run image from this PR on a AWS GPU cluster:


**Build**
pre-requisites: docker installed, vllm cloned and cherrypicked this PR
~~~
cd ~/vllm

DOCKER_BUILDKIT=1 docker build . \
    --target vllm-openai-efa \
    --tag vllm/vllm-openai:efa_pr_58768 \
    --file docker/Dockerfile \
    --build-arg INSTALL_KV_CONNECTORS=true \
    --build-arg max_jobs=$(nproc) \
    --build-arg nvcc_threads=2
~~~

**Testing P/D disagg with NIXL+ libfabric/EFA backend**
note: Qwen3-32B model is used here on a AWS p5en.48xlarge 2 node cluster with 1P-1D topology

~~~
1. Launch prefill server 

docker run --gpus all \
    --network host \
    --ipc=host \
    $(for d in /dev/infiniband/uverbs*; do echo -n "--device $d "; done) \
    --ulimit memlock=-1 \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    --env "HF_TOKEN=$HF_TOKEN" \
    --env "VLLM_NIXL_SIDE_CHANNEL_HOST=<PREFILL_NODE_IP>" \
    --env "VLLM_NIXL_SIDE_CHANNEL_PORT=5600" \
    vllm/vllm-openai:efa_sn \
    --model Qwen/Qwen3-32B --served-model-name Qwen --dtype bfloat16 \
    --max-num-seqs 8 --port 8100 --max-model-len 32768 --tensor-parallel-size 8 \
    --kv-transfer-config '{"kv_connector":"NixlConnector","kv_buffer_device":"cuda","kv_role":"kv_producer”,”engine_id":"prefill-engine-001","kv_rank":0,"kv_parallel_size":2,"kv_connector_extra_config":{"backends":["LIBFABRIC"]}}'


2. Launch decode server 

docker run --gpus all \
    --network host \
    --ipc=host \
    $(for d in /dev/infiniband/uverbs*; do echo -n "--device $d "; done) \
    --ulimit memlock=-1 \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    --env "HF_TOKEN=$HF_TOKEN" \
    --env "VLLM_NIXL_SIDE_CHANNEL_HOST=<DECODE_NODE_IP>" \
    --env "VLLM_NIXL_SIDE_CHANNEL_PORT=5600" \
    vllm/vllm-openai:efa_sn \
    --model Qwen/Qwen3-32B --served-model-name Qwen --dtype bfloat16 \
    --max-num-seqs 8 --port 8200 --max-model-len 32768 --tensor-parallel-size 8 \
    --kv-transfer-config '{"kv_connector":"NixlConnector","kv_buffer_device":"cuda","kv_role":"kv_consumer”,”engine_id”:”decode-engine-001","kv_rank":0,"kv_parallel_size":2,"kv_connector_extra_config":{"backends":["LIBFABRIC"]}}'

3. Launch router on any one of the above two nodes or launch on a different node

python3 ~/vllm/examples/disaggregated/disaggregated_serving/disagg_proxy_demo.py \
  --model Qwen \
  --port 8000 \
  --prefill <PREFILL_NODE_IP>:8100 \
  --decode <DECODE_NODE_IP>:8200

4. Issue requests. Here i'm issuing requests from the router node, hence use localhost.

curl -s http://localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
        "model": "Qwen",
        "messages": [{"role": "user", "content": "Explain KV cache in detail."}],
        "max_tokens": 128,
        "temperature": 0
      }' | python3 -m json.tool


~~~
