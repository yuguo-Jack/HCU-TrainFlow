# [ROCm][Perf] Add opt-in prequantized FP8 attention for the Qwen3.8 model family

[Upstream PR](https://github.com/vllm-project/vllm/pull/53823) · state: open · merged: False

## Purpose

This PR adds an opt-in ROCm/AITER FP8 attention path for the Qwen3.8 model family. The path prepares Q/K/V in FP8 and consumes the prequantized tensors directly in prefill and chunked-prefill attention.

The feature remains disabled by default and is enabled with:

```bash
VLLM_ROCM_USE_PREQUANTIZED_QKV=1
```

Once enabled, the ROCm AITER backend uses the prequantized FP8 Q/K/V for causal attention within the current prefill chunk. For chunked-prefill requests that already have cached tokens, the current chunk's queries also attend over the gathered K/V cache in FP8 when the hardware, attention shape, and KV-cache configuration support it.

Today, Q/K normalization, partial RoPE, and gate extraction produce BF16 attention inputs. Chunked prefill then runs two attention calls: causal self-attention within the current chunk, followed by non-causal attention from the current chunk's queries to previously cached K/V. The second call gathers the cached K/V into a BF16 workspace, and both calls consume BF16 inputs.

The new gfx950 path fuses Q/K normalization, RoPE, gate extraction, and FP8 quantization. The causal current-chunk call consumes the resulting FP8 Q/K/V directly. For the second call, an FP8 KV cache remains FP8 while it is gathered, while a BF16 KV cache is quantized as it is gathered into the FP8 workspace. `merge_attn_states` combines the two attention results.

The implementation:

- adds a backend-neutral `PrequantizedQKV` attention input contract;
- adds ROCm AITER support for prequantized Q/K/V and their descales;
- wires the Qwen3.8 model family to fused Q/K norm, RoPE, gate extraction, and FP8 preparation;
- forwards `max_num_seqs` through the Qwen3.8 model wrapper so the preparation workspace is sized correctly;
- keeps pure decode on the existing paged-attention path;
- supports both FP8 and BF16 persistent KV caches;
- automatically uses FP8 for the current chunk's queries attending over gathered cached K/V when supported.

AITER dependency:

- ROCm/aiter#5002
- Target: gfx950

Production A/B:

| Arm | Configuration |
|---|---|
| A | Existing BF16 attention path with `VLLM_ROCM_USE_PREQUANTIZED_QKV=0` |
| B | FP8 attention with `VLLM_ROCM_USE_PREQUANTIZED_QKV=1`; cached K/V is gathered into the FP8 workspace automatically |

Server command:

```bash
VLLM_ROCM_USE_AITER=1 \
VLLM_ROCM_USE_AITER_MHA=1 \
VLLM_ROCM_USE_PREQUANTIZED_QKV=<0-or-1> \
vllm serve MODEL \
  --tensor-parallel-size 8 \
  --attention-backend ROCM_AITER_FA \
  --kv-cache-dtype <auto-or-fp8> \
  --max-model-len 131072 \
  --max-num-batched-tokens 8192 \
  --no-enable-prefix-caching \
  --compilation-config \
    '{"pass_config":{"enable_qk_norm_rope_fusion":true}}'
```
