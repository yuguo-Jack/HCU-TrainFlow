# [Bugfix][Frontend] Return all top_logprobs when Responses API requests top_logprobs=-1

[Upstream PR](https://github.com/vllm-project/vllm/pull/61141) · state: open · merged: False

## Original PR description

## Overview

`top_logprobs=-1` means "every candidate" and Chat Completions returns them all, but `/v1/responses` with `include=["message.output_text.logprobs"]` returns an empty `top_logprobs` list for each token. The request is accepted and the engine still computes full-vocabulary logprobs (`SamplingParams.logprobs == -1`); `_topk_logprobs` then stops at `i >= top_logprobs`, which is true on the first item when the value is -1. I made that loop treat -1 as no limit, the way `_get_top_logprobs` does for chat.

## Claims

- `top_logprobs=-1` on `/v1/responses` returns every candidate per token, streaming and non-streaming (both go through `_create_response_logprobs`).
- Positive values and `0` behave as before.

## Validation

Noticed while reading the Responses serving code next to the chat one. No GPU here, so I called `_create_response_logprobs` directly with a three-candidate step:

```python
serving = OpenAIServingResponses.__new__(OpenAIServingResponses)
serving.return_tokens_as_token_ids = False
step = {i: Logprob(logprob=-float(i), decoded_token=t) for i, t in enumerate("abc", 1)}
for k in (2, -1):
    (lp,) = serving._create_response_logprobs([1], [step], MagicMock(), top_logprobs=k)
    print(f"top_logprobs={k}:", [t.token for t in lp.top_logprobs])
```

```text
# main (03091e28b)            # this PR
top_logprobs=2: ['a', 'b']    top_logprobs=2: ['a', 'b']
top_logprobs=-1: []           top_logprobs=-1: ['a', 'b', 'c']
```

Added `test_response_logprobs_honor_top_logprobs` (-1, 2, 0); the -1 case fails on main. `pytest tests/entrypoints/openai/responses/test_serving_responses.py` passes locally, ruff is clean. I did not run a live server.

## Details

Not a duplicate as far as I can tell: #55717 fixes the same -1 handling for `/v1/completions` and doesn't touch the Responses path, and I didn't find an issue or PR for this one.
