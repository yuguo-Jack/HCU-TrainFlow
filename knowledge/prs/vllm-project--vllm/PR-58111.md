# [Frontend] Add text /v1/translations endpoint with encoder-decoder dispatch

[Upstream PR](https://github.com/vllm-project/vllm/pull/58111) · state: closed · merged: False

## Original PR description

## Summary
Add a text-to-text `/v1/translations` OpenAI-compatible endpoint — distinct from the audio `/v1/audio/translations` (Whisper) endpoint. It takes source text plus structured language parameters (`target_language`, optional `source_language`) and returns translated text.

## Details
The endpoint dispatches per model on `model_config.is_encoder_decoder`:
- **Encoder-decoder MT models** (MarianMT, NLLB) take a direct-generate path: the source text is fed to the encoder as its single `"text"` modality via an `ExplicitEncoderDecoderPrompt` and generation runs straight through the engine. Target-language conditioning and streaming for this path arrive in follow-up PRs; a streaming request is rejected cleanly for now.
- **Decoder-only / instruct models** delegate to `OpenAIServingChat`, wrapping the request in an instruction prompt and reshaping the chat response (and SSE stream) into the translation schema — reusing the full generation pipeline rather than reimplementing it.

Changes:
- New `vllm/entrypoints/openai/translation_text/` package (protocol, serving, api_router) exposing `POST /v1/translations`.
- Wired the handler + router into `vllm/entrypoints/generate/api_router.py`.

## Test
- 13 GPU-free unit tests (`tests/entrypoints/unit_tests/test_translations.py`) covering prompt templating, response/stream mapping, both dispatch branches, the direct-generate path, and route wiring — all passing.
