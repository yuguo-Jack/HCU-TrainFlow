# [Bugfix][Attention] Honor the largest shared block-size preference

[Upstream PR](https://github.com/vllm-project/vllm/pull/60892) · state: open · merged: False

## Original PR description

## Overview

When a model has more than one attention backend, `_preferred_block_size_for_backends` returns 16 whenever every backend accepts the default, and never calls `get_preferred_block_size`. Use the largest preferred size when every backend accepts it. Fixes #60871.

## Claims

- Several backends that all accept the largest `get_preferred_block_size` now get that size instead of 16.
- A single backend is unchanged.
- If the largest preference is not accepted by every backend, the old path stays: default 16 when all accept it, otherwise the LCM search.

## Validation

`ruff` 0.14.0 format and check pass on the two changed files.

```bash
pytest -q tests/v1/worker/test_gpu_model_runner.py::test_preferred_block_size_satisfies_every_backend tests/v1/worker/test_gpu_model_runner.py::test_preferred_block_size_keeps_default_when_largest_preference_is_rejected tests/v1/worker/test_gpu_model_runner.py::test_preferred_block_size_searches_past_an_exact_size_backend tests/v1/worker/test_gpu_model_runner.py::test_preferred_block_size_rejects_backends_with_no_common_size
```

Result: 8 passed in 0.42s.

Two `MultipleOf(16)` backends that both prefer 64 return 64. A larger preference that one backend rejects stays at 16. The existing single-backend, LCM, and no-common-size cases are unchanged.

## Details

`Platform._preferred_block_size_for_backends` (from #49845) calls `get_preferred_block_size` only for one backend. With two or more, `supports_block_size(16)` is true for `MultipleOf(16)` and for an exact 16, so the function returns 16. That skips preferences of 64 (`FLASH_ATTN` on XPU, `ROCM_AITER_UNIFIED_ATTN`) and 128 (`HPUAttentionBackendV1`).

In-tree platforms do not crash on this. The HPU plugin does: the runner snapshots 128 before this selection overwrites the block size with 16, and prompt warmup then fails unflatten. vllm-gaudi works around it in https://github.com/vllm-project/vllm-gaudi/pull/1871. This change makes that workaround removable for the case where every backend accepts the larger preference.

Each backend can prefer a different size, so the shared choice is the largest preference that every backend accepts. Anything else keeps the current default-or-LCM path. #58630 changes how specs are queried. It does not apply this rule.
