# [Build] Reuse the CMake build directory for editable installs

[Upstream PR](https://github.com/vllm-project/vllm/pull/60906) · state: open · merged: False

## Original PR description



## Overview

Make `uv pip install -e . --no-build-isolation` rebuild incrementally. Today, every editable install reconfigures CMake and recompiles all extensions, because setuptools builds editable installs in a throwaway temp directory.

Related: #54532 adds a CI smoke test for `pip install -e .`. This PR conflicts with #56409 (which moves the Marlin MoE block) and #57625 (which adds a method at the same spot in `cmake_build_ext`); I'm happy to rebase whichever lands second.

## Claims

- Re-running `uv pip install -e . --no-build-isolation` recompiles only changed files. Commands are unchanged.
- A40 (`sm_86`): a no-op rebuild takes ~25s and a one-`.cu` change 32s, instead of a ~34 min full rebuild.
- Reuse is safe across venv, torch and CMake generator changes, `git clean -X`, interrupted kernel generation, and build dirs with different arch lists.

## Validation

A40, torch 2.13.0+cu126, `TORCH_CUDA_ARCH_LIST=8.6`, `uv pip install -e . --no-build-isolation --no-deps`:

| Step | Time | Objects compiled |
|---|---|---|
| Cold build (every install on `main`) | ~34 min | 359 |
| No-op rebuild | 26s | 0 |
| Touch one `.cu` | 32s | 1 |
| After `git clean -X`, an interrupted generation, or another build dir regenerating for `8.6;9.0a` | 2–5 min | 15–30 (only Marlin regenerated) |

- After the arch switch: `test_marlin_gemm.py` (394 passed) and `test_moe.py -k marlin` (244 passed).
- macOS CPU: no-op rebuild takes 6–7s with 0 objects (vs ~90s with 16 on `main`). Also checked: a Ninja ↔ Makefiles switch, a corrupt marker, and a failed configure.

## Details

**Root cause.** setuptools' PEP 660 `editable_wheel` uses a `TemporaryDirectory` for `build_temp`, which for vLLM holds the whole CMake/Ninja tree.

**Changes**

- `setup.py`: editable builds use the persistent `build/temp.<plat>-<cache_tag>` directory. A `vllm_build_env.json` marker (Python, torch dir and version, generator) drops the CMake cache when the environment changes.
- Marlin, Marlin MoE, Machete: the "already generated" hash moves from `CMakeCache.txt` to a gitignored file next to the generated sources in `csrc/`, so the two can't disagree.
- The torch 2.13 header hotfix and the CPU attention dispatch header are now rewritten only when their content changes. Before, they forced 58 and 16 recompiles per install.
- Docs: the CUDA install guide and `incremental_build.md` describe the pip rebuild loop.

**Limitations**

- With build isolation, every build still recompiles everything, as it does today.
- `build/` now persists (several GB for CUDA); `rm -rf build/` resets it.
- Not tested: ROCm, and running Machete kernels (needs SM90+).

**Follow-ups**

- Replace `tools/generate_cmake_presets.py`, which has drifted from `setup.py`.
- Generate the Marlin/Machete sources into the build dir, so build dirs with different arch lists stop regenerating on each switch.

**Duplicate check.** No open PR changes the editable build dir or the generator caching.
