# [NIXL] Prepare KV transfer descriptors as NIXL 1.5 strided lists

[Upstream PR](https://github.com/vllm-project/vllm/pull/61032) · state: open · merged: False

## Original PR description

NIXL 1.5 accepts a compressed Nx5 descriptor list in `prep_xfer_dlist`: each `(addr, len, dev_id, stride, count)` row stands for `count` blocks of `len` bytes whose starts are `stride` bytes apart. The connector built one `(addr, len, dev_id)` row per block per region instead, so a large KV pool meant millions of descriptors materialized in NumPy and copied into NIXL at startup and again on every handshake.

Emit one strided row per region:
- `_build_fa_local`, `_build_fa_remote` and the Mamba/PLE builders return Nx5 rows. Padded blocks split by a block-size ratio get one row per block.
- Local, per-source split and remote dlists are prepared directly from the Nx5 arrays with an explicit memory type; `get_xfer_descs` is no longer used. Descriptor ids are unchanged because NIXL indexes a strided list by flat block index.
- Split handles (P_TP > D_TP) slice each row's length and address, and the REPLICATE/SPLIT flag is computed once per row from the region owning its first block, honoring per-region block counts, instead of once per block.
- Mixed DRAM/VRAM registrations split rows by memory type; the per-block maps used by the READ path are unchanged.
- The worker refuses to start with NIXL < 1.5.

The transfer path is unchanged: request descriptors are built from the same flat indices, and NIXL 1.5 already compresses flat lists internally.

## Performance

Qwen3-8B P/D on one GB300 node, NIXL 1.5.0, `main` (f2376cdc4d) vs this PR. Each decode rank has a ~1.48M-token KV pool (~3.3M per-block descriptors before this change). Method timings come from a wrapper around `register_local_xfer_handler` / `add_remote_agent`; request times are end-to-end through the toy proxy (`max_tokens=1`, ~700-token prompt). Medians of 3 rounds with alternating run order, ranges in brackets.

**Prefill TP1 → decode TP1**

| | main | this PR |
|---|---|---|
| Local descriptor setup (`register_local_xfer_handler`, startup) | 52 ms | 0.2 ms |
| Handshake (`add_remote_agent`) | 156 ms [153–162] | 109 ms [108–113] |
| Cold first request (includes the handshake) | 307 ms [299–341] | 259 ms [255–296] |
| Warm requests | 65–77 ms | 64–73 ms |

**Prefill TP2 → decode TP1** (decode builds per-source split handles and handshakes with two prefill ranks)

| | main | this PR |
|---|---|---|
| Prefill local descriptor setup (twice the tokens per rank) | 107–112 ms | 0.1–0.2 ms |
| Handshake with first prefill rank | 2,255 ms [2,242–2,258] | 118 ms [113–118] |
| Handshake with second prefill rank | 145 ms | 42 ms |
| Cold first request | 2,656 ms [2,625–2,661] | 425 ms [415–444] |
| Warm requests | 76–89 ms | 77–99 ms |

On `main`, building the split handles looped in Python over every per-block row, costing ~2.1 s on the first handshake; it now operates on a handful of strided rows. The gain grows with KV pool size and with the prefill/decode TP ratio. The remaining ~110 ms of handshake is NIXL loading remote metadata and connecting, which this change doesn't touch. Warm request latency is unchanged, as expected, since transfer-time descriptor lookup is the same.
