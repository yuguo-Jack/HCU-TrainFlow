## Original PR description

# [Bugfix][collect-env] Distinguish CUDA Toolkit and Runtime versions

## Before

`vllm collect-env` used `nvcc --version` for the field named `CUDA runtime
version`:

```text
CUDA runtime version : 13.3.73
```

This value was actually the CUDA Toolkit version. The output did not identify
the CUDA Runtime loaded by the process, and the two versions can differ.

## After

The output distinguishes the two sources:

```text
CUDA Toolkit version : 13.3.73
CUDA Runtime version : 13.0
```

`CUDA Toolkit version` continues to come from `nvcc --version`. The new
`CUDA Runtime version` is obtained through `cudaRuntimeGetVersion()`, with
fallbacks for CUDA libraries in `CUDA_HOME`/`CUDA_PATH`, NVIDIA CUDA Python
wheels, and the system linker path. The lookup targets Linux/WSL, which is
vLLM's supported CUDA platform; native Windows support is outside the scope of
this change. The cuDNN field is unchanged.

## Validation

- Installed the current worktree into the existing venv with
  `VLLM_USE_PRECOMPILED=1 uv pip install -e . --torch-backend=auto`.
- Ran `vllm collect-env` successfully.
- Verified the output:

  ```text
  Is CUDA available            : True
  CUDA Toolkit version         : 13.3.73
  CUDA Runtime version         : 13.0
  ```

- `git diff --check` passed.
- No model evaluation is needed; this changes diagnostics only.

No open PR was found addressing this CUDA Toolkit/Runtime reporting issue.
Existing `collect-env` work is focused on ROCm reporting or other unrelated
diagnostics.
