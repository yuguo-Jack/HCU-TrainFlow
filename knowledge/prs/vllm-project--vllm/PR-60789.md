# Feat/return logprobs via auxoutput connector

[Upstream PR](https://github.com/vllm-project/vllm/pull/60789) · state: open · merged: False

## Original PR description


## Overview

Add `logprobs` and `prompt_logprobs` replay support to the AuxOutput Connector for reinforcement-learning and scoring workloads.

The implementation preserves the existing non-RL path. Requests only use the AuxOutput logprob data plane when they explicitly set:

```python
SamplingParams(
    logprobs=0,  # or a fixed top-k value
    prompt_logprobs=0,  # optional
    extra_args={"aux_output_replay": True},
)
````

The change also allows logprob replay on non-MoE models. Routed-expert capture retains its existing MoE-specific validation.

## Claims

- Generated-token logprobs can be captured, stored, and replayed across prefix-cache hits.
- Prompt logprobs can be reconstructed from cached artifact blocks and combined with newly computed suffix rows.
- Replay preserves token IDs, selected-token ranks, and logprob values.
- Generated logprobs continue to support speculative-decoding truncation and rejected-token handling.
- Prompt logprobs support chunked prefill and partial prefix-cache hits.
- Artifact identity includes generation, logprob layout, KV block hash, and boundary target token ID to prevent incorrect reuse.
- Missing, malformed, or evicted artifacts fail closed instead of returning incomplete results.
- Requests without `aux_output_replay=True` continue to use the existing sampler and prompt-logprob path.
- Logprob-only replay does not require an MoE model.
- The implementation supports both selected-token logprobs and fixed top-k logprobs. Public rows may contain `top_k` or `top_k + 1` entries because the selected token is deduplicated when already present in the top-k set.

## Details

### Configuration

Two disabled-by-default settings are added:

- `enable_logprobs_replay`
- `enable_prompt_logprobs_replay`

Prompt logprob replay requires generated logprob replay because causal rows at block boundaries are completed through the generated-token path.

Prefix caching remains required for logprob replay because the artifact key is based on KV block hashes.

### Data path

Generated and prompt logprob rows are converted into versioned variable-size artifacts stored in the AuxOutput variable block store.

Artifacts contain:

- absolute token positions;
- token IDs;
- logprob values;
- selected-token ranks;
- schema version.

The worker reuses the existing request lifecycle, capture cursor, emit cursor, scheduled cursor, and pending-output handling. Prompt logprobs use an additional replay prefix and cache-merge path.

### Current limitations

The initial implementation intentionally supports a restricted contract:

- Only `raw_logprobs` mode is supported.
- Full-vocabulary logprobs (`-1`) are not supported.
- Custom `logprob_token_ids` and `prompt_logprob_token_ids` are not supported.
- Generated and prompt logprobs must use the same top-k width when both are requested.
- Prompt logprob replay currently requires generated logprob replay.
- Prefix caching must be enabled.
- Replay is intended for explicitly opted-in internal/RL requests; it is not exposed as a new OpenAI API field.
- Online weight transfer/update configurations are rejected because artifact identity does not yet include a weight-version fingerprint.
- The implementation does not replay processed logprobs after arbitrary logits processors, penalties, temperature, or top-p transformations.
- Exact full-vocabulary entropy and KL computation are not supported by the replay artifacts.
- GPU end-to-end and performance validation must be run on a CUDA/ROCm machine; they were not executed in the CPU-only development environment.

AI assistance was used during implementation and test development. The submitting human should review every changed line and rerun the relevant GPU validation before merging.
