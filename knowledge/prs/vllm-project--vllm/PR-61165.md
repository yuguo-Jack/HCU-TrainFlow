# [Bugfix][MoE][LoRA] Use LoRA MoE kernels only when target_modules reaches the experts

[Upstream PR](https://github.com/vllm-project/vllm/pull/61165) · state: open · merged: False

## Original PR description



## Overview

`FusedMoEConfig.is_lora_enabled` is `lora_config is not None`. With attention-only LoRA (`--lora-target-modules q_proj k_proj v_proj o_proj`) the experts are never LoRA-wrapped, but every MoE layer still switches to its LoRA-capable kernel. This PR applies the same `target_modules` check the LoRA manager uses.

## Claims

- BF16 MoE + attention-only LoRA no longer fails at startup with `LoRA context must be set`.
- NVFP4 MoE + attention-only LoRA keeps the FlashInfer TRT-LLM experts instead of Marlin: +25% throughput on Qwen3.6-35B-A3B-NVFP4.
- No change when `target_modules` is unset or names the MoE module.

## Validation

GB300, TP1, random rank-8 adapter on q/k/v/o, 256 requests × 256 tokens:

| Model | main, no LoRA | main, attention LoRA | this PR, attention LoRA |
|---|---|---|---|
| Qwen3.6-35B-A3B-NVFP4 | TRT-LLM, 19190 tok/s | Marlin, 15691 tok/s | TRT-LLM, 19681 tok/s |
| Qwen3.6-35B-A3B (BF16) | TRT-LLM, 15503 tok/s | startup fails | TRT-LLM, 15509 tok/s |

Adapter requests still apply with this PR (4/8 greedy prompts differ from base). GSM8K (1319, 5-shot, NVFP4, base requests): no LoRA 59.89%; main with the attention-LoRA engine 64.75% (MoE on Marlin); this PR 59.89%, identical to no LoRA.

```bash
pytest tests/model_executor/layers/test_fused_moe_lora_target.py   # 3 passed
```

## Details

- `_is_moe_lora_target` returns `True` when `target_modules` is unset, and otherwise `is_in_target_modules(layer_name, target_modules)`, the check `LoRAModelManager._match_target_modules` uses. It is evaluated once at construction.
- Limitation: the manager also consults `packed_modules_mapping`, which `FusedMoEFactory` cannot see. No in-tree model maps the MoE module as a packed parent.
- No open PR addresses this (searched "moe lora target_modules is_lora_enabled", "lora attention only moe kernel").
- AI assistance (Claude Code) was used; I reviewed every changed line and the results.
