# [Frontend] Resolve target language to decoder token ids for /v1/translations

[Upstream PR](https://github.com/vllm-project/vllm/pull/58187) · state: closed · merged: False

## Original PR description

Resolves the requested target language into the decoder prompt in the API process instead of forwarding the raw code string to the engine.

`_resolve_decoder_prompt` calls the model's `create_decoder_prompt` hook and forwards the returned decoder token ids as `{"prompt_token_ids": [...]}`, so the engine renderer no longer re-tokenizes the code.

This fixes two problems with forwarding the raw string:
- An invalid code would tokenize to subwords and produce garbage instead of an error.
- The tokenized code **leaked into a bilingual model's decoder** — MarianMT saw a spurious leading `"de"` → `": ..."`.

Behavior: NLLB/M2M100 normalize an ISO code / name to the checkpoint's tag and resolve to a forced-BOS token; MarianMT resolves to an empty prompt. Resolution falls back to the raw string when no processor is available, and an unrecognized code still yields a clean 400 before generation.

Adds a bilingual empty-decoder-prompt test and updates the valid-code test to assert token-id forwarding.
