# [Bugfix][Frontend] Explain invalid double-dash short aliases

[Upstream PR](https://github.com/vllm-project/vllm/pull/60975) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Show registered spellings when the first unrecognized option is an existing short alias with an extra dash, including `vllm serve MODEL --cc.mode=none`. Addresses the diagnostic alternative described in #55125.

## Claims

- Suggest `-cc` / `--compilation-config` (and other registered aliases) without accepting new option spellings or changing parsed configuration.
- Resolve the active parser along the CLI's leading command chain, including nested subcommands. Reusing a parser for another command does not suggest a sibling command's aliases.
- Document JSON short-alias syntax and cover flat/subcommand diagnostics plus existing behavior controls in the current parser test suite.

## Details

Argparse returns unknown child arguments to the root parser. Looking only at the root registry misses aliases registered by `serve`; the hint uses the registry selected by the leading command chain instead. Custom root options placed before the command are outside this diagnostic enhancement; exit behavior is preserved.

Duplicate checks found no core PR addressing #55125. Recipes #997 changed one recipe to the existing single-dash spelling; #53946 handled an offline recipe converter, rather than this live parser diagnostic.
