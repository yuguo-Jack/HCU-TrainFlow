# [Bugfix][Core] Fix num_output_placeholders underflow with async scheduling + spec decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/46066) · state: closed · merged: True

## Original PR description


## Purpose

Under async scheduling with speculative decoding, `reset_prefix_cache(reset_running_requests=True)` force-preempts the running requests, zeroes each request's `num_output_placeholders`, and records the in-flight frame count in `async_tokens_to_discard` so those now-stale frames are dropped when they return. This path is reached by the `/reset_prefix_cache` dev endpoint and, more commonly, by RLHF weight updates and `sleep(level>=1, mode="keep")`.

The problem: the speculative-rejection adjustment in `Scheduler.update_from_output` runs *before* that discard. When a stale in-flight frame returns, it subtracts its pre-reset `num_rejected` from the resumed request's freshly re-added (small) placeholder count:

```python
if request.num_output_placeholders > 0:
    request.num_output_placeholders -= num_rejected
```

The `> 0` guard only checks the value is positive, not that the subtraction stays in range, so `num_output_placeholders` underflows below zero. The negative value is then retained silently, because the async `_update_request_with_output` early-returns on `async_tokens_to_discard > 0` before reaching `assert num_output_placeholders >= 0`. It still feeds real scheduling math (prefill/decode classification, the running-loop early-stop check, `num_new_tokens`), and if the discard counter drains while the count is still negative, the next normal frame trips that assert and crashes EngineCore. In the repro below the negative count is what is directly observed; the assert is bypassed there because every offending frame is on the discard path.

Fix: skip the speculative-rejection counter adjustment for frames that are pending discard (`async_tokens_to_discard > 0`). Such a frame is dropped whole, so its pre-reset rejection count must not be applied to the resumed request. Synchronous scheduling never sets `async_tokens_to_discard`, so it stays `0` and non-async paths are unchanged.

This is a distinct trigger of the assertion reported in #30142; the configuration there does not use speculative decoding, so this change does not address that reporter's exact scenario. Refs #30142.

## Test Plan

- Real `vllm serve` before/after on a single GPU: `Qwen3-0.6B`, `--async-scheduling`, `--speculative-config '{"method":"ngram_gpu","num_speculative_tokens":5,"prompt_lookup_max":4,"prompt_lookup_min":2}'`, small KV (`--gpu-memory-utilization 0.45 --max-num-batched-tokens 512 --max-num-seqs 48`) to force frequent preemption, sustained completions load, plus `POST /reset_prefix_cache?reset_running_requests=true` every 10s. A negative `num_output_placeholders` is counted via in-process instrumentation that wraps `AsyncScheduler._update_request_with_output`.
- New deterministic unit test `tests/v1/core/test_async_scheduler.py::test_no_placeholder_underflow_on_discarded_spec_frame`.
- Existing `tests/v1/core/test_async_scheduler.py` as a negative control (spec-decode paths with `async_tokens_to_discard == 0` are unaffected).

## Test Result

- Real engine, identical config, 11 resets over 100s of load: **before fix 9 `num_output_placeholders < 0` events; after fix 0**, the engine stays alive and every request returns 200.
- The new unit test fails on the unpatched scheduler (`num_output_placeholders == -4`) and passes with the fix.
- `tests/v1/core/test_async_scheduler.py` passes; `ruff check` and `ruff format` are clean.

<summary>Repro command + instrumentation + before/after logs</summary>

Instrumentation (loaded via `PYTHONPATH`, wraps the method in-memory, no source edit):

```python
from vllm.v1.core.sched.async_scheduler import AsyncScheduler
_orig = AsyncScheduler._update_request_with_output
def upd(self, request, new_token_ids):
    before = request.num_output_placeholders
    r = _orig(self, request, new_token_ids)
    if request.num_output_placeholders < 0:
        print(f"NEGATIVE req={request.request_id} before={before} "
              f"after={request.num_output_placeholders} discard={request.async_tokens_to_discard}")
    return r
AsyncScheduler._update_request_with_output = upd
```

Serve:

```bash
VLLM_SERVER_DEV_MODE=1 vllm serve Qwen3-0.6B --async-scheduling \
  --speculative-config '{"method":"ngram_gpu","num_speculative_tokens":5,"prompt_lookup_max":4,"prompt_lookup_min":2}' \
  --max-num-seqs 48 --max-model-len 2048 --max-num-batched-tokens 512 \
  --gpu-memory-utilization 0.45 --enable-chunked-prefill
```

Load: 24 concurrent `/v1/completions` (`max_tokens=400`, `ignore_eos`) for 100s, with `POST /reset_prefix_cache?reset_running_requests=true` every 10s.

Before fix (sample):

```
NEGATIVE req=cmpl-... before=-4 after=-4 discard=5
... (9 events; first one immediately follows a "Successfully reset prefix cache")
resets fired: 11 ; NEGATIVE events: 9 ; engine alive
```

After fix (same config):

```

```
