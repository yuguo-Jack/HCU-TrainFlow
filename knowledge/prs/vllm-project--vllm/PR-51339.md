# [Model Loader][Perf] Auto-prefetch VirtioFS checkpoints

[Upstream PR](https://github.com/vllm-project/vllm/pull/51339) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->
## Overview

Enable the existing RAM-guarded safetensors auto-prefetch path for VirtioFS checkpoints. Explicit `lazy` remains an opt-out.

## Claims

- Automatic selection includes `virtiofs` alongside NFS, NFS4, and Lustre, only when the strategy is unset and checkpoint size is at most 90% of available RAM.
- The change reuses the existing prefetch helper and renames the internal filesystem classification to cover host/guest shared filesystems.
- A prior GLM-5.2 loading run demonstrated the benefit of that helper on one VirtioFS configuration; the measurements below are not a fresh benchmark of automatic selection.

## Validation

Validated on 2026-10-10 at published head `899bca4acb` and in a temporary merge with upstream `276fbcff2717bd934cfa37c8a2e4c391f3e7237b`. The published branch was not rebased.

```sh
VLLM_TARGET_DEVICE=cpu CUDA_VISIBLE_DEVICES='' .venv/bin/python -m pytest tests/model_executor/model_loader/test_weight_utils.py tests/test_config.py -k 'auto_prefetch_selection or safetensors_load_strategy' -q
.venv/bin/pre-commit run --hook-stage manual --files vllm/config/load.py vllm/model_executor/model_loader/weight_utils.py tests/model_executor/model_loader/test_weight_utils.py
```

The five loader/config cases pass on both versions; all applicable scoped hooks pass. Removing `virtiofs` from the filesystem set gives **1 failure and 4 passes**. Tests replace filesystem/RAM detection and prefetch selection, then load real safetensors values.

Historical GLM-5.2 loading measurement, with a 1403.19 GiB checkpoint fitting available RAM:

| Configuration | Model loading |
| --- | ---: |
| Default path before this change, VirtioFS detected but prefetch disabled | 1596.999 s |
| Explicit `prefetch`, application startup completed | 70.676 s |

These are individual original runs, not repeated measurements. No VirtioFS mount was available for this review. The automatic branch selects the same helper after the RAM guard.

## Details

VirtioFS backing storage, cache policy, and DAX configuration vary; the filesystem type does not guarantee a speedup. The demonstrated scope is a single VM. The existing helper partitions files by global rank, so multiple guests with separate page caches may each prefetch only part of a checkpoint. This PR does not change that existing limitation.

Fresh VirtioFS issue/PR searches found no competing fix. CephFS work in #47412 concerns a different filesystem type. Upstream CI remains stopped at the contributor-authorization gate; local hooks are not upstream CI evidence.

AI assistance was used for investigation, implementation, tests, and review.

File: `vllm/model_executor/model_loader/weight_utils.py` · line 67

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Prefetch every shard within each VirtioFS guest**

When distributed ranks span multiple VMs using VirtioFS guest page caches, enabling this default does not warm the complete checkpoint on any VM: `_prefetch_all_checkpoints` partitions files using the global rank and world size, even though those page caches are not shared between guests, while every rank subsequently iterates all checkpoint files. Each guest therefore prefetches only roughly `1 / num_nodes` of the data and must still perform uncached reads for the remaining shards, potentially negating the startup improvement and adding redundant I/O. Partition prefetch work only among ranks that share a page cache, or prefetch all shards once per guest.

Useful? React with 👍 / 👎.

- bvolpato · comment · 2026-08-07T03:39:57Z · [source](https://github.com/vllm-project/vllm/pull/51339#discussion_r3733275263)

File: `vllm/model_executor/model_loader/weight_utils.py` · line 67

Valid multi-node limitation. Global-rank sharding is existing prefetch behavior and also affects NFS, Lustre, and explicit prefetch. This PR only enables that path for VirtioFS. Our tested run used this exact implementation and reduced GLM-5.2 loading from 1597s to 70.7s. Node-local prefetch partitioning deserves a separate change with multi-node validation rather than a VirtioFS-specific fix here.
