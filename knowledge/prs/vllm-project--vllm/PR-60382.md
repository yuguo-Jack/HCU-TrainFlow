# [Bugfix][Tool Parser] Stream InternLM2 non-plugin action content instead of dropping it

[Upstream PR](https://github.com/vllm-project/vllm/pull/60382) · state: open · merged: False

## Original PR description

## Overview

Fixes #60341. In streaming mode `Internlm2ToolParser` stops emitting anything once `<|action_start|>` appears and waits for the full `<|action_start|><|plugin|>` marker. When the action turns out to be a non-plugin block (`<|interpreter|>`), or the generation ends right after `<|action_start|>`, the rest of the output is never streamed, while the non-streaming path returns the same text verbatim as content.

## Claims

- Streaming now holds text back only while the tail after `<|action_start|>` is still a prefix of `<|plugin|>`; anything else streams through as content, matching `extract_tool_calls`.
- `finalize_generation` gives a legacy tool parser that defines `finish_streaming()` one chance to release held text at end of stream (opt-in via `getattr`, same shape as the reasoning fallback right above it). This also wires up the existing `K2HorizonToolParser.finish_streaming()`, which was previously only called from its own test.
- Plugin-call streaming is unchanged: while the tail can still grow into `<|plugin|>` the parser waits exactly as before, and the name/argument partial-JSON path is untouched.

## Validation

Issue reproducer (an `<|interpreter|>` block, and a stream ending right after `<|action_start|>`), run against current main and against this branch:

- before: streaming returned only the prefix `"Let me compute that. "` in both cases
- after: concatenated streaming content equals the non-streaming content in both cases

Tests (CPU, `.venv/bin/python -m pytest`):

- `tests/tool_parsers/test_internlm2_tool_parser.py`: 14 passed, 8 xfailed. New tests cover non-plugin release, hold-then-release across a chunk boundary inside `<|plugin|>`, end-of-stream flush, and that a truncated plugin call is not re-emitted as content.
- `tests/parser/test_streaming.py tests/tool_parsers/test_k2_horizon_tool_parser.py`: all passed, including a new test driving `parse_delta(..., finished=True)` through `DelegatingParser` for the finalize wiring.
- `ruff check` / `ruff format --check` clean on the touched files.

## Details

Root cause: the streaming guard required the combined marker `<|action_start|><|plugin|>` in the unstreamed tail and returned `None` otherwise, so any non-plugin action wedged the parser for the rest of the stream. There was also no end-of-stream hook on the tool-parser side, so even a legitimately held ambiguous window (a strict prefix of `<|plugin|>`) was dropped when generation stopped inside it.

`vllm/parser/abstract_parser.py` is touched on purpose, and the `vllm/tool_parsers` guidance says to call that out: releasing held text at end of stream is missing for every legacy tool parser with a hold-back, not just InternLM2, so the flush lives in `finalize_generation` next to the reasoning fallback. It is opt-in: parsers without `finish_streaming()` see no behavior change, engine-based parsers keep flushing through `_flush_engine_parsers`, and the hook name/signature follows the convention already used by the reasoning parsers and `K2HorizonToolParser`.

Tradeoff to be aware of: `K2HorizonToolParser` streams that end mid-parse now emit their unresolved tail as final content instead of dropping it. That is what its `finish_streaming()` was written for, and its test suite passes unchanged.

AI assistance was used in preparing this PR (Kimi Code); the change was validated locally as described above. On duplication: no open PR references #60341, and the other active InternLM2 streaming PR (#60363) fixes a different bug (argument characters dropped as partial JSON grows), so the two do not overlap.

This branch built from source on the macOS CPU backend (there are no prebuilt arm64 wheels), serving `internlm/internlm2_5-1_8b-chat` in fp16 with `--enable-auto-tool-choice --tool-call-parser internlm`. A dummy `get_weather` tool is registered so the parser path is active, and both runs below are streamed chat completions at temperature 0.

Case 1, the non-plugin action from #60341. A computation prompt puts the model into its trained interpreter format, so the generated stream starts with `<|action_start|><|interpreter|>`:

- with the two parser files checked out from the parent commit (same build; this PR touches no C++, so the extension is identical): `content=''`, `finish_reason=stop`. The whole answer is swallowed.
- with this branch: content arrives across 21 deltas and concatenates to `<|action_start|><|interpreter|>\n```python\nresult = 123456 * 789\nresult\n```<|action_end|>\n`, byte-identical to what the non-streaming path returns for the same text.

Case 2, stream ends immediately after `<|action_start|>` (`max_tokens=1`, `finish_reason=length`):

- pre-fix: `content=''`, the held marker is lost.
- this branch: `content='<|action_start|>'`, released by the new end-of-stream flush.

The plugin-call path is untouched by this change. I could not coax the 1.8B model into emitting its trained plugin format on demand, so that path is asserted by the parser unit tests at this head (16 passed, 8 xfailed) rather than by a server transcript here.
