# [CI][ROCm] Match the AMD steps to the mirror declarations they carry

[Upstream PR](https://github.com/vllm-project/vllm/pull/57972) · state: open · merged: False

## Original PR description

Fixes [#57956](https://github.com/vllm-project/vllm/issues/57956).

`mirror.amd` blocks in `.buildkite/test_areas/*.yaml` declare, per suite, the label it carries in the AMD pipeline and the device class it runs on. `test-amd.yaml` is the file those declarations point at: its header describes `mirror_hardwares` as the selector tags for the AMD pipelines that should include the test. For 24 suites the two files disagreed, so the selectors and the agent pool pulled those suites somewhere other than the labels declared.

## What changed

- 23 steps re-tiered in `.buildkite/test-amd.yaml` to the tier and the device their mirror declares: label tier, the `mirror_hardwares` lane tags and `agent_pool`. Several of them are suites whose mirror came with [#57876](https://github.com/vllm-project/vllm/pull/57876); the others are mirrors from the earlier MI355 reallocation ([#57080](https://github.com/vllm-project/vllm/pull/57080)) whose step stayed on MI300. Each edit moves the label tier, `amdgfx942nightly` to `amdgfx950nightly`, `amdmi300` to `amdmi355`, and `agent_pool` to the device the mirror declares.
- two MI355 entrypoints steps, `Entrypoints Integration (Speech to Text)` and `Entrypoints Integration (Multimodal)`, carried `amdgfx942nightly` next to `amdmi355`. Their label, their device and their `amdmi355` tag all say MI355, so the gfx942 tag is dropped.
- three drifted names aligned: `Qwen3-8-Flash-Next-FP8` to `Qwen3.8-Flash-Next-FP8` (the checkpoint reference and the eval configs spell the model `Qwen3.8`), `Rust Frontend Serve-Admin Coverage` to `Rust Frontend Serve/Admin Coverage` (the H200 group it mirrors spells it `Serve/Admin`, `.buildkite/test_areas/rust_frontend.yaml:70`), and the `Entrypoints Integration (Pooling)` mirror label gained the ` Shard %N` suffix its step has had since the sharding.
- new `.buildkite/scripts/check-amd-mirror-parity.py`: reports every AMD mirror that disagrees with its step and exits non-zero on a violation of the MI355 invariant. It is deliberately not wired into a pipeline step: that kind of change wants a container run to validate, and I could not run one here.

## What is left, and why

The checker reports 39 of 141 mirrors. All of them are either a mirror declaring a lower tier than the step it names (33 rows: `attention.yaml` declares `(MI300) V1 Attention Shard %N` against an MI355 step, `cuda.yaml` and `engine.yaml` declare MI250 against MI355 and MI300 steps, `Mamba Kernels`, `Plugin Integration`, `Samplers`, `Language Models (MTEB)` declare MI250 against MI300 steps), or a mirror naming a step `test-amd.yaml` does not have (6 rows: `LM Eval Spec Decode`, `Qwen4 Exp`, `Multimodal Models (PPL)`, `Spec Decode DeepSeek MTP Parallel Load`, `Spec Decode AL DFlash Nightly`, `Spec Decode AL DSpark Nightly`). Both need a placement call on the AMD side rather than a typo fix, so the checker reports them instead of failing on them.

The `test-amd.yaml` diff touches label, `mirror_hardwares` and `agent_pool` lines only: no `commands`, `timeout_in_minutes`, `source_file_dependencies` or `working_dir` value changed. No model-facing code, prompt or serving path is touched, so no eval run applies here.

## Duplication

No open pull request touches the AMD mirror/step agreement: `gh pr list --search "mirror parity"`, `--search "test-amd"` and `--search "57956"` come back with nothing on it. The closest earlier work is [#50519](https://github.com/vllm-project/vllm/pull/50519) (`[ROCm][CI] Add missing test coverage for upstream parity`), which adds coverage but does not reconcile the two files, and [#53840](https://github.com/vllm-project/vllm/issues/53840), which is about a `num_devices`/`num_gpus` mismatch, a different invariant.

AI assistance was used: the audit of the two files, the re-tier edit and the checker were produced with an AI coding agent under line-by-line review; the checker was run before and after the change.
