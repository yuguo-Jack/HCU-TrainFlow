# [Model Loader] Apply model-owned MTP shard selection to RunAI

[Upstream PR](https://github.com/vllm-project/vllm/pull/60759) · state: open · merged: False

## Original PR description

## Overview

Apply the existing model-owned checkpoint selection hook to RunAI ModelStreamer before reading safetensors shards. Closes #60691; extends the DefaultModelLoader optimization in #60152 without duplicating MTP naming rules.

## Performance: Qwen3.5 MTP with remote RunAI

Five alternating baseline/patch pairs ran on the same H20×8 node (TP=8), with the same checkpoint, serving arguments, resources and experiment-only quantization compatibility setting. Both images shared the same runtime base; only the RunAI loader override differed. All ten replicas reached Kubernetes Ready with zero restarts. Each passed four fixed HTTP requests (256 output tokens total) with nonzero draft acceptance.

| Metric | Baseline median (range), 5 runs | Patch median (range), 5 runs | Median improvement |
| --- | ---: | ---: | ---: |
| Scheduled → Kubernetes Ready | 473 s (450–511) | 360 s (326–394) | 1.31×; 113 s less |
| Draft load and weight-finalization window | 143.646 s (135.974–147.128) | 14.908 s (14.444–15.724) | 9.64×; 128.738 s less |

The five paired observations, in execution order (baseline → patch, seconds), were:

- Scheduled → Ready: 473 → 360, 477 → 394, 462 → 379, 450 → 353, 511 → 326.
- Draft window: 143.646 → 14.572, 146.395 → 14.444, 141.378 → 15.724, 135.974 → 14.908, 147.128 → 15.054.

The median improvements are separately calculated statistics, not additive stage savings. The main-load window varied considerably and showed no stable improvement. Compilation, CUDA Graph capture, and warmup remained enabled and still contribute to Ready time.

RunAI checkpoint iterator entries for the draft fell from **75,881 to 1,121**; main remained at 75,881. The code path therefore ran, but entries are not measured object-store bytes, and the draft window includes more than pure I/O. Pending time is excluded. Pod events showed cached application images in every run. One patch run had a 58 s post-scheduling, pre-main interval, retained in the total. OSS/network load was not controlled, and no independent I/O/CPU bottleneck profile was taken; this is a result for this checkpoint and environment, not a general speedup guarantee.

Initial TP=8 runs had near-zero draft acceptance in **both** arms: this checkpoint's compressed-tensors ignore entry for mtp did not match its BF16 draft subtree under this runtime's exact-name matching. The reported pairs apply the same experiment-only subtree regex to **both** arms. That configuration change is not in this PR. Across restarts, some generated continuations differed even baseline versus baseline, so the fixed requests demonstrate working serving and nonzero draft use, not numerical equivalence or a full accuracy evaluation.

The final PR commit **41eccda** was separately rebuilt and checked on GPU: Ready, zero restarts, four HTTP 200 responses, 256 output tokens, and 122/133 draft tokens accepted/proposed. This one final-image check is not mixed into the five-pair performance medians. A local RunAI Qwen3.5 smoke test also reached Ready with nonzero draft acceptance. Exact OSS bytes were not measured.

GLM-5.3 uses the existing DeepSeek-V3.2/GLM MTP model hook; this PR adds no GLM-specific naming rule. Both replicas reached Ready with zero restarts and served four HTTP 200 requests (256 output tokens total per arm) with nonzero draft acceptance.

## Design and implementation

- **Why before the iterator:** RunAI previously prepared the complete checkpoint file list before the model's load_weights method could discard unwanted MTP tensors. A later filter cannot undo whole-file RunAI reads. The loader now obtains the existing model-owned is_unused_checkpoint_weight predicate and selects complete shards before constructing the RunAI iterator. This PR does not define new MTP naming rules or add hooks to model classes; #60152 introduced the hook for opted-in models.
- **How selection works:** Local checkpoints reuse the safetensors-header selector. For S3-compatible and other remote storage, the loader reads model.safetensors.index.json at the resolved weights URI (including model_weights overrides) and maps wanted tensor names to files before RunAI reads payloads. Mixed and unindexed shards remain included. Only selection metadata is fetched locally; weight payloads are not staged to disk.
- **Safety and distributed behavior:** Selection retains original file order. WORLD CPU ranks agree on a conservative union of required files; differing original file lists disable selection. Without a model hook, or with missing/unusable optional index metadata, the original full file list is used. If the predicate rejects every shard, the full list is retained so the model's own missing-weight error can still surface. Model-rule and tensor-read errors propagate.
- **Scope and tradeoff:** This is file-level selection, not tensor-range filtering: a mixed shard is still read in full. The extra metadata fetch and CPU collective are the cost. Earlier Hugging Face checkpoint download and runai_streamer_sharded are unchanged. Examples of existing hook-bearing MTP implementations include Qwen3.5, Qwen3-Next, Nemotron-H and DeepSeek-V3.2/GLM; unadapted models keep the full-list fallback.

This complements #60152 (Default loader) and #58016 (lazy per-tensor reads): the former owns the model rule, while this PR applies it to RunAI whole-file loading. It also complements #48023/#42060 (draft weights URI inheritance).
