# [Core][Refactor] Move KV cache planning logic to kv_cache_planning.py

[Upstream PR](https://github.com/vllm-project/vllm/pull/61183) · state: open · merged: False

## Original PR description

## Overview

Move the KV cache grouping, sizing, and capacity-planning logic from `vllm/v1/core/kv_cache_utils.py` into a new module, `vllm/v1/core/kv_cache_planning.py`. This is a pure code move with no behavior change.

Split out from #53558 so the large move can be reviewed separately from the pluggable `KVCacheConfigBuilder` change.

## Claims

- `kv_cache_utils.py` goes from about 2.8k to about 1.2k lines. It keeps the block, hash, and free-queue utilities, plus the helpers that consume a finished `KVCacheConfig`: `get_max_concurrency_for_kv_cache_config`, `generate_scheduler_kv_cache_config`, `get_kv_cache_capacity`, and `update_kv_cache_capacity`.
- `kv_cache_planning.py` holds the planning path: `get_kv_cache_configs`, `get_kv_cache_groups`, `get_kv_cache_config_from_groups`, page-size unification, packed/hybrid grouping, memory and max-model-len estimation, auto-fit, and TP-replica helpers (38 functions).
- Function names and bodies are unchanged. No compatibility re-exports are left in `kv_cache_utils.py`; all in-tree callers are updated.

## Validation

- Every moved function is byte-identical to `origin/main`. This was checked by comparing each top-level definition with the AST. Reviewers can confirm with:
  ```bash
  git diff --color-moved=dimmed-zebra origin/main...HEAD -- vllm/v1/core/
  ```
- `pre-commit` passes (ruff, mypy, typos, and the test-tethering checks).
- Ran the affected unit tests on CPU, on both this branch and `origin/main`. Both give the same result: **294 passed, 19 skipped**.
  ```bash
  pytest tests/v1/core/test_kv_cache_utils.py \
    tests/v1/core/test_contiguous_kv_packing.py \
    tests/v1/engine/test_init_error_messaging.py \
    tests/v1/kv_connector/unit/offloading_connector/test_config.py \
    tests/v1/simple_kv_offload/test_worker.py \
    tests/v1/kv_connector/unit/test_hidden_states_connector.py \
    tests/v1/attention/test_sparse_mla_kv_cache_layout.py \
    tests/v1/worker/test_dsv4_packed_zeroer_geometry.py
  ```
- `tests/models/test_initialization.py`, `tests/models/test_dspark_mla.py`, and `tests/v1/worker/test_gpu_model_runner.py` import and collect cleanly. They need a GPU, so they are left to CI.

## Details

Besides the move itself, these updates keep behavior and CI coverage the same:

- **Imports:** updated in `v1/engine/core.py`, `v1/hisparse/layout.py`, `v1/worker/gpu_model_runner.py`, `v1/worker/gpu/cudagraph_utils.py`, and the affected tests.
- **Monkeypatch targets:** the `get_hisparse_host_pool_bytes` patches and the `max_memory_usage_bytes` patch string now point at `kv_cache_planning`. Patching the old module would silently stop taking effect.
- **Subprocess test:** the import embedded in the script string of `test_is_kv_cache_spec_uniform` now uses the new module.
- **Buildkite:** wherever `.buildkite/test-amd.yaml` and `.buildkite/test_areas/lm_eval.yaml` list `vllm/v1/core/kv_cache_utils.py` as a source dependency, `vllm/v1/core/kv_cache_planning.py` is now listed too. Changes to the moved code still trigger the same jobs.

Out-of-tree code that imports planning functions from `vllm.v1.core.kv_cache_utils` needs to switch to `vllm.v1.core.kv_cache_planning`.

Follow-up: #53558 can rebase on top of this, so its diff only contains the builder changes.
