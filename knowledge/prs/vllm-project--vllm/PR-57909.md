# [ROCm][PERF] Enable MiniMax-M3 Indexer CP

[Upstream PR](https://github.com/vllm-project/vllm/pull/57909) · state: open · merged: False

## Original PR description

## Purpose

Adds **indexer-only context parallelism** for the MiniMax-M3 lightning indexer on ROCm (gfx950), opt-in behind `--attention-config '{"indexer_cp": true}'`. Under tensor parallelism each rank owns one index head and scores *every*
128-token block, so at long context every rank re-reads the whole index cache on every decode step and that cost grows linearly with the context. This PR inverts the split: every rank projects **all** index heads and scores **1/P of the
blocks**, then one small exchange gives each rank every shard's candidates for the heads it owns. That turns the index-cache reads into `1/P`, which is the only term here that scales with context.

This PR depends on Aiter PR: https://github.com/ROCm/aiter/pull/6359

#57909. Needs both indexer_kv_dtype=fp8 and indexer_cp=true. fp8 e4m3 only; indexer_aiter.py is removed on this head. Decode uses CP. Prefill slices the replicated index_q to this rank's heads and uses the normal top-k. decode_context_parallel_size > 1 turns CP off. M3 has 4 index heads, TP must divide 4, and TP * 16 <= 64, so the working size is TP4. Against the non-CP baseline: throughput +3% at C15 up to +15% at C32; interactivity p90 goes from 148 to 190 at C15 and up to about 1.5x later.
