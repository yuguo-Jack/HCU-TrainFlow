# [Bugfix] DeepSeek-V4.1 parser: tolerate drifted DSML tool-call openers

[Upstream PR](https://github.com/vllm-project/vllm/pull/61142) · state: open · merged: False

## Original PR description

## Overview

DeepSeek-V4.1-Flash can emit DSML tool-call blocks with a `parameter`-style tool-name opener and no outer `calls` wrapper. This change lets the V4.1 parser return structured tool calls for those variants instead of exposing the block as plain content.

## Claims

- Recognize canonical `invoke`, DSML-prefixed `parameter`, and bare `parameter` tool-name openers in the existing V4.1 parser configuration.
- Close reasoning and start a tool call when the block arrives without a preceding `</think>` marker.
- Cover streaming, non-streaming, thinking on/off, and small-chunk parsing in the existing V4.1 regression suite.

## Details

The canonical V4.1 invoke opener can already be recognized from `CONTENT` without the outer wrapper. The missing pieces are recognition of the two parameter-style opener variants and an `INVOKE_PREFIX` transition directly from `REASONING`. The fix extends the existing configuration inherited from `deepseek_v4_config`; it adds no parser engine or serving-layer implementation.

Related work: #52645 addresses DeepSeek V4 missing/malformed outer wrappers with provisional recovery, tool-name validation, and rollback. This PR targets V4.1's different DSML spelling and parameter-style tool-name openers. It does not implement or replace #52645's broader recovery policy. Bare parameter text remains ambiguous when it appears as prose; this patch retains the existing parser's acceptance policy rather than adding a new validation layer.
