# [Perf][CPU] Reduce AVX2 prefill attention register spills

[Upstream PR](https://github.com/vllm-project/vllm/pull/58514) · state: open · merged: False

## Original PR description

## Overview

Reduce register spills in the AVX2 VEC and VEC16 prefill attention kernels. Use smaller GEMM tiles while keeping the accumulation order and the existing single-token path.

## Claims

- On an Intel Core Ultra 7 255H, the eight tested prefill cases take 13.2–26.4% less time than main at `c41b2639`.
- All 3,060 operator comparisons have identical outputs at the new base.
- An earlier Pythia-410M test showed a 4.7% reduction for long FP32 prompts. BF16 and short prompts did not show a stable model-level gain. This model test was not repeated after the rebase.

The four decode conditions gave median changes from −6.6% to +0.1%, with overlapping process ranges. These results do not establish a decode gain or rule out a small regression. An earlier baseline-to-baseline check also showed variation of about 6%.

### Earlier model test

Pythia-410M was tested through `LLM.generate()`: 4 threads, one request, eager mode, and prefix cache disabled. The table shows 2,047 input tokens and one output token. It includes scheduling and sampling, but excludes model loading and tokenization. Values are medians of three process medians, each with three measured calls after warm-up.

| Dtype | Baseline ms | This change ms | Time change |
|---|---:|---:|---:|
| FP32 | 4803.8 | 4577.6 | −4.7% |
| BF16 | 4550.6 | 4607.0 | +1.2% |

The model test used base `feb87b1` and an official CPU wheel at `e975732`, with only its attention operators replaced. It was not a full source build. Long FP32 prompts improved in all three process pairs, by 4.7–6.4%. Long BF16 results ranged from −2.8% to +1.2%. These results do not establish a speedup over the stock wheel or the latest main.

Attention outputs, final logits, and generated tokens matched for FP32/BF16 at 256, 1,024, and 2,047 input tokens. A four-token generation check also passed. Other CPUs and concurrent serving were not tested.

## Details

The full VEC and VEC16 GEMM tiles need 32 YMM registers for their accumulators. AVX2 has 16. The compiler spills accumulators to the stack inside the K loop.

Use 4×16 tiles for FP32 and up to 8×8 tiles for BF16/FP16 when a query tile has more than one token. Keep the accumulation order, vector operations, and scratch size. Single-token work, including GQA decode, keeps the existing tiles. The change is guarded by `__AVX2__ && !__AVX512F__`. FP8 keeps its existing path. The isolated library text size grows by 258,513 bytes, from 1,154,115 to 1,412,628 bytes.

This does not duplicate #58257, which changes RVV decode tiles, or #58298, which adds a Zen CPU SDPA path. The stable ABI migration in #52635 does not apply this VEC/VEC16 tile change.
