# [Bugfix][Distributed] Prevent silent split-brain in stateless DP on port collision (#61049)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61102) · state: open · merged: False

## Original PR description

Fixes #61049

## Purpose

When forming a stateless DP group in port-pool mode (`not self._coord_store_port`), all ranks derive the same initial rendezvous port from a shared port list. If rank 0 encounters `EADDRINUSE`, it previously caught the error, logged a generic warning without port numbers, and popped the next port to retry. Because peer member ranks connect to the first port via PyTorch's C++ TCPStore client and have no mechanism to observe the leader's rebind, the entire group hung until the distributed timeout (default 1800s) before crashing.

This PR:
1. In port-pool mode with `data_parallel_size > 1`, fails fast upon `EADDRINUSE` with an informative `RuntimeError` logging the collided port, candidate next port, and troubleshooting guidance (releasing orphaned processes or specifying ports).
2. When retrying is safe (`data_parallel_size == 1`), explicitly logs both the collided port and the new port being attempted.
3. Logs the rendezvous IP and port at INFO level during DP group initialization for observability.
4. Adds unit tests covering multi-rank fail-fast and single-rank retry behaviors.
