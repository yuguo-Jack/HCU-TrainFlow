# [WideEP] Explain how to fix a too-old NCCL for DeepEP v2

[Upstream PR](https://github.com/vllm-project/vllm/pull/60449) · state: closed · merged: True

## Original PR description



## Overview

Make a too-old NCCL for DeepEP v2 self-explanatory on pip/uv installs. PyTorch pins an NCCL older than the 2.30.4 that `--all2all-backend deepep_v2` needs (PyTorch 2.13 pins `nvidia-nccl-cu13==2.29.7`). The Docker images override it since #45321, but installs outside the images fail with a message that states the requirement and not the fix. This does not change any dependency.

## Claims

- The startup log line and the `DeepEPV2All2AllManager` assertion now name the cause and the upgrade command for the installed CUDA major.
- `tools/ep_kernels/install_python_libraries.sh` warns, before and after the build output, when the installed NCCL is too old for DeepEP v2. It does not fail, so DeepEP v1 builds are unaffected.
- `tools/ep_kernels/README.md` reflects the current PyTorch pin, explains that later `uv pip install` runs restore it without `UV_OVERRIDE`, and that DeepEP must be rebuilt after upgrading NCCL.

## Validation

On an environment with torch 2.13.0, `nvidia-nccl-cu13==2.29.7`, and DeepEP 2.0.0:

```console
$ python -c "from vllm.utils.import_utils import deep_ep_v2_unavailable_reason as r; print(r())"
DeepEP v2 requires NCCL >= 2.30.4 but found 2.29.7. PyTorch pins an older NCCL; upgrade it with `pip install "nvidia-nccl-cu13>=2.30.4" --no-deps` and rebuild DeepEP against it. See tools/ep_kernels/README.md.
```

The NCCL check from the install script, run in isolation against the same environment:

```console
WARNING: nvidia-nccl-cu13 2.29.7 is installed, but the deepep_v2 backend
requires NCCL >= 2.30.4 when DeepEP is built and when it runs. To use deepep_v2, run
    uv pip install "nvidia-nccl-cu13>=2.30.4" --no-deps
and then run this script again. See tools/ep_kernels/README.md.
```

pre-commit (including shellcheck and markdownlint) and `mypy-3.12` pass on the changed files.

Not validated: the full install script was not re-run end to end, the Docker build was not run (it sets `UV_OVERRIDE`, so the warning should not trigger there), and the available path (NCCL >= 2.30.4) was not exercised on a real environment. No tests were added; the change is message text plus a shell warning.

## Details

`has_deep_ep_v2()` now delegates to a new `deep_ep_v2_unavailable_reason()`, so the log line and the assertion share one message. One behavior difference: an environment with a pre-v2 DeepEP installed now also gets the one-time INFO line saying `deepep_v2` is unavailable.

The alternative of forcing a newer NCCL through `[tool.uv] override-dependencies` in `pyproject.toml` was left out on purpose to avoid changing dependencies.

Not a duplicate: searches for `deepep_v2 NCCL` and `nccl install_python_libraries` found no open PR addressing this.

AI assistance was used to investigate and implement this change.
