# [Perf][MoE] Add tuned Triton FusedMoE config for Gemma 4 26B-A4B on H20 (E=128,N=704)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60849) · state: open · merged: False

## Original PR description

## Purpose

Add a Triton FusedMoE config measured on NVIDIA H20 for Gemma 4 26B-A4B (E=128, N=704, TP1, BF16). Without it, vLLM logs `Using default MoE config` and falls back to the heuristic.

Only one file is added: `E=128,N=704,device_name=NVIDIA_H20.json`. No code changes.

### Relationship to existing PRs

- #60504 also ships `E=128,N=704,device_name=NVIDIA_H20.json`. Its description does not include H20 measurements, and the config appears to be derived from a Hopper template. This PR is a config **searched and measured on H20** with `benchmarks/kernels/benchmark_moe.py --tune`. If #60504 lands first, this PR would only replace that single file; I am happy to rebase or close in favor of updating it there, whichever the maintainers prefer.
- #45789 (benchmark_moe Gemma4 support) is not duplicated here. On v0.31.0 the script needs a one-line local patch to recognize `Gemma4ForConditionalGeneration` (same branch as `DiffusionGemmaForBlockDiffusion`) before it can tune this model.

## Test Plan

Environment: 1x H20 96GB, driver 595.58.03, `vllm/vllm-openai:v0.31.0` (PyTorch 2.13.0+cu130, Triton 3.7.1), model `google/gemma-4-26B-A4B-it`.

Tuning:

```bash
python3 benchmarks/kernels/benchmark_moe.py --model google/gemma-4-26B-A4B-it \
  --tp-size 1 --dtype auto --tune --save-dir tuned \
  --batch-size 1 2 4 8 16 24 32 48 64 96 128 256 512 1024 1536 2048 3072 4096
```

Kernel A/B: the same script without `--tune`, with `VLLM_TUNED_CONFIG_FOLDER` unset (default) / pointing at #60504's H20 file / pointing at this file.

End to end: single replica, TP1, `--kv-cache-dtype fp8 --max-num-seqs 32 --max-num-batched-tokens 8192`, MTP (`num_speculative_tokens=4`), guidellm 0.7.4. Decode uses 2000 real first-turn ShareGPT conversations (`/v1/chat/completions`, no `ignore_eos`, `max_tokens=1024`, 90 s per level). Prefill uses 1024-token unique-prefix prompts (60 s per level, prefix-cache hits verified 0). Startup log confirms `Using configuration from .../E=128,N=704,device_name=NVIDIA_H20.json for MoE layer.`
