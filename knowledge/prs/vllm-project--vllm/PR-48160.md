# [Bugfix] Migrate Olmo3 reasoning parser to the streaming parser engine

[Upstream PR](https://github.com/vllm-project/vllm/pull/48160) · state: open · merged: False

## Original PR description

## Purpose

Fix content being silently dropped by the Olmo3 reasoning parser when a single streaming delta carries the closing `</think>` together with the content after it (stream interval > 1, chunked prefill), by migrating the parser onto the streaming parser engine as suggested in review.

The legacy buffer parser processed at most one `<think>`/`</think>` transition per delta: `process_buffer()` emitted the reasoning and left the trailing content in the buffer, where it was never flushed. The first revision of this PR patched the buffer with an unconditional drain, which (as review pointed out) broke 4 existing tests by flushing text the buffer was intentionally holding back.

This revision does the migration instead, following the qwen3/gemma4/nemotron_v3 pattern:

- `vllm/parser/olmo3.py` — declarative `ParserEngineConfig`: initial state REASONING, optional leading `<think>`, text-lexed terminals (the Olmo3 markers are ordinary text split across multiple vocabulary tokens, so there are no `token_id_terminals`), `strip_trailing_reasoning_whitespace=False` to keep reasoning verbatim. The legacy multi-token `is_reasoning_end` / `extract_content_ids` behaviour is preserved on the engine subclass.
- `vllm/reasoning/olmo3_engine_reasoning_parser.py` — adapter shim; `olmo3` now registers `Olmo3ParserReasoningAdapter`.
- `vllm/reasoning/olmo3_reasoning_parser.py` — legacy buffer parser removed (−320 lines).
- The engine's incremental lexer handles partial-marker buffering across deltas, and a boundary-spanning delta returns reasoning and content together, matching DeepSeek-R1.

**Behaviour note:** output containing no `</think>` at all is now classified as reasoning in both streaming and non-streaming modes (engine convention, as qwen3). The legacy parser was internally inconsistent here: non-streaming returned it as content, streaming as reasoning. Happy to preserve the legacy non-streaming fallback instead if preferred.

- lucaluo925 · comment · 2026-09-24T18:18:43Z · [source](https://github.com/vllm-project/vllm/pull/48160#issuecomment-5819682368)

Related finding on current `main` (8b84e15) that this migration may or may not cover: the **non-streaming** `Olmo3ReasoningParser.extract_reasoning` returns truncated reasoning as `content`, while streaming returns it as `reasoning`.

When generation stops before `</think>` (max_tokens, a stop string, a thinking budget), `reasoning_regex` doesn't match, and the fallback is `return None, model_output`. The streaming buffer starts in the reasoning state, because the Olmo-3-Think template pre-fills `<think>`, so the two modes disagree:

```
output: 'Let me think about this step by step. First, 17 * 23'
  non-streaming: reasoning=None content='Let me think about this step by step. First, 17 * 23'
  streaming    : reasoning='Let me think about this step by step. First, 17 * 23' content=None
```

A minimal fix in the legacy parser is, in `extract_reasoning` before the final fallback:

```python
if self.think_end not in model_output:
    return model_output.removeprefix(self.think_start) or None, None
```

It comes with two test cases (`"<think>unfinished"` and `"unfinished"`, each expecting `reasoning="unfinished", content=None`, streaming and non-streaming). With the fix `tests/reasoning` passes (436). Question for the author/reviewers: should this go into this PR, or be a separate small `[Bugfix]` PR against the current parser?
