# [Bugfix] Reject incompatible unquantized 16-bit kv_cache_dtype with model dtype (#60859)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60951) · state: open · merged: False

## Original PR description

## Overview

Fixes #60859. Reject incompatible unquantized 16-bit kv_cache_dtype against model dtype early in VllmConfig._validate_cache_config() and attention backend selection (FlashAttention, FlashInfer, FlashAttnMLA).

## Claims

Prevents engine crashes during CUDA graph capture when mixing bf16 model with fp16 KV cache (or vice versa) under FlashAttention, raising a clean ValueError at initialization time and properly filtering backend selection.

## Validation

Added unit tests in tests/test_config.py verifying ValueError is raised when mismatched 16-bit unquantized cache dtypes are configured with model dtype, and verified supports_combination deselects mismatched combinations in tests/kernels/attention/test_attention_selector.py. All matching, auto, and fp8 combinations remain unaffected.

## Details

When a model uses bfloat16 and kv_cache_dtype='float16', CacheConfig._validate_cache_dtype only logged an info string without checking cross-field compatibility with model dtype. During warmup and graph capture, the backend forwarded mismatched query and key dtypes into FlashAttention kernel, triggering RuntimeError: query and key must have the same dtype (flash_api.cpp:601). Because unquantized 16-bit KV cache requires matching precision between query and key across attention backends, cross-field validation is enforced in VllmConfig and reported as unsupported in backend selection.
