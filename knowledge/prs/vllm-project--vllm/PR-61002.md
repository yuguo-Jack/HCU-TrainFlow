# [Bugfix][KV Connector] Pair non-divisible hybrid MLA block sizes in NixlConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/61002) · state: open · merged: False

## Original PR description



## Overview

NixlConnector now pairs P/D blocks of a hybrid MLA model when neither block size divides the other, which happens when P and D run different TP on a backend that accepts any kernel block size. Kimi-K3 with P TP2 and D DP2 (TP1) on ROCm crashed at the handshake and now runs.

## Claims

- Hybrid MLA P/D with non-divisible block sizes (e.g. P 2944, D 5760) pairs the blocks in gcd-sized units instead of failing the handshake.
- Configurations that work today are unaffected: every pair that reaches the new code failed the handshake before, and every other pair returns at its first check.

## Details

Hybrid blocks are sized so one attention block covers the SSM state page, and that page is TP-sharded, so P and D choose different block sizes when their TP differs. On CUDA, FlashInfer/TokenSpeed MLA only accept 32/64-token kernel blocks, so NIXL transfers 64-token kernel blocks on both sides and the sizes always divide. ROCm AITER MLA accepts any kernel block size, so NIXL keeps the whole TP-dependent blocks, and `TransferTopology.block_size_ratio` asserts that one divides the other. For Kimi-K3 that is 5760 at TP1 and 2944 at TP2 (gcd 128). With DSpark the sizes happen to be 6144/3072 and work.

A pull request through the changed path, P TP2 and D DP2 (TP1):

1. D handshakes with each P rank. P's metadata advertises 2944-token blocks, and D's own block is 5760.
2. New: `_split_remote_blocks` views P's blocks as 23 kernel blocks of 128 tokens each (block size, block lengths, strides and kernel blocks per logical block scaled accordingly), as a P with a 128-token kernel block would have advertised.
3. The existing `block_size_ratio > 1` path then splits D's blocks into 45 sub-blocks of 128 tokens, pairs them with P's, reads, and zeroes the untransferred tail on receive.

The rewrite only runs for hybrid MLA, when the local block size is not a multiple of the remote one and the remote regions are plainly strided; otherwise the handshake behaves as before. With prefix caching on, D still rejects such a pair through the existing check for Mamba hybrids with different kernel blocks per logical block, as on CUDA, so these deployments need `--no-enable-prefix-caching` on D. The test harness now registers MLA caches as `[B, 1, N, C]`, as on device, so the partial-tail zeroing in the receive path is exercised.

Not a duplicate. #45575 makes the hybrid block size TP-stable, which would avoid this pair at its source but changes block sizes (and SSM page padding) for every hybrid deployment with TP > 1. This change is connector-local and composes with it, since P and D can still be launched with different block sizes. #59746 fixes pairing for divisible block sizes and still rejects this non-divisible case; the two touch the same pull path and test harness.
