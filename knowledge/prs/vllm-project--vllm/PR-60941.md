# [Bugfix][HiSparse] Fix TP group hang on steps without scheduled tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/60941) · state: open · merged: False

## Original PR description



## Overview

With a host pool shared across TP ranks (#56629), a TP group can hang forever on a step with no scheduled tokens. On such steps, every TP rank now waits at a CPU barrier right after its event wait.

## Claims

- Fixes a hang between TP rank 0 and a TP rank whose host is one step behind, on steps with no scheduled tokens (`no_forward`).
- Steps with tokens are unchanged.

## Validation

**Reproducer.** The script below copies the shared-event protocol from `hisparse/worker.py` onto 2 GPUs and holds rank 1's host for 0.5 s before one wait. Run on H100s:

```
torchrun --nproc-per-node 2 hisparse_event_hang.py {zero_next|zero_now|tokens} {none|sync|barrier}
```

| Case | `main` (`none`) | rank 0 host sync (`sync`) | this PR (`barrier`) |
|---|---|---|---|
| `zero_next`: rank 1 late, next step has no tokens | HANG 3/3 | PASS 3/3 | PASS 3/3 |
| `zero_now`: rank 1 late on a step with no tokens, next step has tokens | HANG 3/3 | HANG 3/3 | PASS 3/3 |
| `tokens`: rank 1 late, every step has tokens | PASS 3/3 | | |

When it hangs, GPU 0 is at 100% (spinning in the all-reduce) and GPU 1 is at 0% (its stream is blocked on the event).

**Unit test.** `test_zero_token_step_holds_tp_ranks_after_host_write_wait` checks that start_step waits at the TP barrier after the event wait on steps with no tokens, and only when the host region is shared.

```
pytest tests/v1/kv_connector/unit/test_hisparse_connector.py -k "zero_token_step or draft_layer or full_graph_step or no_forward"
```

| | Result |
|---|---|
| `main` `worker.py` | 1 failed (`shared=True, num_tokens=0`), 7 passed |
| this PR | 8 passed |

These tests ran in a vLLM 0.31.0 H100 image (`f6d5a33`) with this branch's `worker.py` and test file swapped in. The image has no pytest, so a small runner expanded the parametrization. `pre-commit run --files <changed files>` passes.

**Production.** A P/D decode deployment hit this hang. It runs HiSparse and NIXL through `MultiConnector`, at TP8 x DP4 with EP32 and MTP:
- One TP rank's GPU sat at 0% while its 7 TP peers sat at 100%.
- The other DP ranks then hit DeepEP dispatch timeouts.
- Each time, the engine was in its first minutes, when first contact with new prefill engines slows the NIXL read post on the main thread (0.1 to 2.4 s).

The reproducer shows the same GPU pattern. This patch has not yet run end to end on that deployment.

## Details

The protocol uses two shared events, A and B:
- Every step, each TP rank's stream waits on the event rank 0 recorded in the previous step.
- Rank 0 then records the other event in `finish_forward`.
- A stream wait binds to the most recent record at the time of the wait call.

**Trigger.** A TP rank's host falls one step behind rank 0, and the next step has no scheduled tokens.

**Mechanism:**

| | TP rank 0 | TP rank 1 (host late) |
|---|---|---|
| 1 | step 5: wait A, launch forward 5, record B | still before its step 5 wait |
| 2 | step 6, no tokens: wait B, record A right away | |
| 3 | | step 5: wait A. The wait binds to rank 0's step 6 record |
| 4 | GPU: the forward 5 all-reduce waits for rank 1 | GPU: waits for the step 6 record, which is queued behind rank 0's forward 5 |

**Effect.** The TP group hangs and nothing times out. With DP and EP, the other DP ranks then block in their MoE collectives.

**Why steps with tokens are safe.** Before recording, rank 0 host-syncs on staging (`_finish_mirror_phase`). That staging is queued behind the previous forward's TP collectives, and every rank joins those only after its wait. A step with no tokens has no forward, so nothing orders rank 0's record after the other ranks' waits.

**Fix.** On steps with no tokens, every TP rank joins `get_tp_group().barrier()` (the CPU group) right after its wait. Every rank has then issued its wait before rank 0 can record again, on this step and the next.
- `num_tokens` comes from the same scheduler output on every TP rank, so all ranks take the barrier on the same steps.
- Without a shared host region, each rank uses its own local events, so there is no barrier.

**Why not a host sync on rank 0 alone.** The `zero_now` row: a sync can only prove that the other ranks reached the last step with a forward. A step with no tokens followed by a step with tokens still hangs.

**Cost.** One CPU barrier per step with no tokens. Those steps launch no forward.

**Not a duplicate.** I checked the 30 open PRs matching `hisparse`, plus searches for `host_write_event`, `hisparse hang`, `hisparse deadlock` and `hisparse barrier`. None changes how the shared host write events are ordered. #59877 fixes a separate NIXL thread-safety bug found in the same investigation.

AI assistance (Claude Code) was used for the investigation, the change, the test and the reproducer.

```python
"""Two-rank model of HiSparse's shared host write events (hisparse/worker.py).

Rank 0 creates two IPC events and shares them. Every step, each rank flips to the
other event and its stream waits on the previous one (`start_step`). Rank 0 alone
records the current event at the end of the step (`finish_forward`), after a host
sync on staging queued before the step on steps with tokens (`_finish_mirror_phase`).
The forward is matmuls plus an all-reduce, standing in for the TP collectives.
Rank 1's host is held DELAY s before its step 5 wait.

  PLAN  zero_next  step 6 has no tokens
        zero_now   step 5 has no tokens, step 6 has tokens
        tokens     every step has tokens
  FIX   none       as on main
        sync       rank 0 also host-syncs before recording on steps without tokens
        barrier    every rank joins a CPU barrier after its wait on steps without tokens

torchrun --nproc-per-node 2 hisparse_event_hang.py PLAN FIX [DELAY]
Prints PASS, or HANG with per-GPU utilization after 20 s.
"""
import os, subprocess, sys, threading, time

import torch
import torch.distributed as dist

plan, fix = sys.argv[1], sys.argv[2]
delay = float(sys.argv[3]) if len(sys.argv) > 3 else 0.5
zero_step = {"zero_next": 6, "zero_now": 5, "tokens": None}[plan]
assert fix in ("none", "sync", "barrier")
rank = int(os.environ["RANK"])
torch.cuda.set_device(rank)
dist.init_process_group("nccl")
cpu_group = dist.new_group(backend="gloo")
stream = torch.cuda.current_stream()

handles = [None]
if rank == 0:
    events = (torch.cuda.Event(interprocess=True), torch.cuda.Event(interprocess=True))
    for e in events:
        e.record(stream)
    handles = [tuple(e.ipc_handle() for e in events)]
dist.broadcast_object_list(handles, src=0)
if rank != 0:
    device = torch.device("cuda", rank)
    events = tuple(torch.cuda.Event.from_ipc_handle(device, h) for h in handles[0])
torch.cuda.synchronize()
dist.barrier()

done = threading.Event()


def watchdog():
    if not done.wait(20):
        util = subprocess.run(
            ["nvidia-smi", "--query-gpu=index,utilization.gpu", "--format=csv,noheader", "-i", "0,1"],
            capture_output=True, text=True).stdout
        print(f"rank{rank} HANG at step {step}, GPU util: " + util.strip().replace("\n", " | "), flush=True)
        os._exit(2)


threading.Thread(target=watchdog, daemon=True).start()
a = torch.randn(4096, 4096, device="cuda", dtype=torch.bfloat16)
cur, nxt = events[1], 0
for step in range(10):
    has_tokens = step != zero_step
    staging = torch.cuda.Event()
    staging.record(stream)
    if rank == 1 and step == 5:
        time.sleep(delay)  # e.g. a slow NIXL read post before start_step
    prev, cur = cur, events[nxt]
    nxt ^= 1
    stream.wait_event(prev)
    if not has_tokens and fix == "barrier":
        dist.barrier(group=cpu_group)
    if has_tokens:
        y = a
        for _ in range(8):
            y = y @ a
            dist.all_reduce(y)
            y = y / 4096
    if rank == 0:
        if has_tokens or fix == "sync":
            staging.synchronize()
        cur.record(stream)
torch.cuda.synchronize()
done.set()
print(f"rank{rank} PASS", flush=True)
dist.destroy_process_group()
```
