# [Bugfix] Exchange MiniMax Lamport IPC handles through their pointer

[Upstream PR](https://github.com/vllm-project/vllm/pull/61037) · state: open · merged: False

## Original PR description



## Purpose

`lamport_workspace.py` exchanges the CUDA IPC handles of the MiniMax fused allreduce+RMSNorm workspace through `cudaIpcMemHandle_t.reserved`. cuda-bindings 13 (the version pinned for CUDA 13 builds, e.g. `requirements/rubin-prerelease.txt`) no longer exposes that attribute, so on every CUDA 13 build the workspace fails to initialize:

```text
Failed to initialize MiniMax fused allreduce+RMSNorm Lamport workspace: 'cuda.bindings.runtime.cudaIpcMemHandle_t' object has no attribute 'reserved'. This is expected on GPUs without P2P (IPC peer access) support. Falling back to the eager allreduce + RMSNorm path.
```

The warning blames missing P2P support, and MiniMax-M2 TP runs on such builds silently use the slower eager path (the TP=4 server log below prints it 124 times, once per layer and rank). `tests/kernels/core/test_minimax_reduce_rms.py` fails on such builds for the same reason.

This PR reads and writes the 64 handle bytes through `getPtr()` (`ctypes.string_at` / `ctypes.memmove`), which cuda-bindings 12 and 13 both provide, instead of the `reserved` attribute.

## Test Plan

- `tests/kernels/core/test_minimax_reduce_rms.py` on a GB300 node (CUDA 13 build, cuda-bindings 13.4.3) on two of its GPUs, before and after the change.
- `vllm serve MiniMaxAI/MiniMax-M2.5 -tp 4` on the same node before and after the change: count of the warning in the server log.

Note for anyone who already served a MiniMax-M2 model on a CUDA 13 build: the fused kernel changes the compiled graph, and a `torch.compile` cache written before this change is reused as is (its key does not cover this file). On the node above that showed up as `ValueError: too many values to unpack (expected 10)` inside the cached graph during the profile run; starting once with `VLLM_DISABLE_COMPILE_CACHE=1` (or clearing `~/.cache/vllm/torch_compile_cache`) fixes it. I did not change the cache key here.
