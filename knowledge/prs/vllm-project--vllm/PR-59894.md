# [Perf][DSv4.1] Trim the last KV-source layer in decoder replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/59894) · state: closed · merged: True

## Original PR description

## Purpose

In decoder replay steps, the last KV-source layer (layer 20 on DSV4.1-Flash) still ran on every row, though for the trimmed rows only its KV (SWA, compressed, index K) is read. Its indexer scoring and top-k, sparse MLA, wo and MoE feed only the replay layers.

- The cut layer now writes its KV for every row (`DeepseekV4DecoderLayer.write_kv` → `DeepseekV4Attention.forward_kv`), then runs as the first replay layer (`decoder_replay_start = cut`) on the replay rows, in the replay batch and its CUDA graphs. Its sliding-window metadata keeps the batch's window starts, so it stays exact. The indexer row-buffer compaction goes.
- PIECEWISE graphs now decide the replay break (and `write_kv`) by graph size (`DecoderReplayLayers.replays()`) instead of `replay_batch is not None`, which is unset at capture: before, the break was never captured and PIECEWISE steps did not trim.
