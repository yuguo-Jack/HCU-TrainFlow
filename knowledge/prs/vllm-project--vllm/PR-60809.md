# [Bugfix][Quantization] Use absolute maxima for vision FP8 scaling

[Upstream PR](https://github.com/vllm-project/vllm/pull/60809) · state: open · merged: False

## Original PR description

## Overview

Use the absolute maximum when recording Q/K/V history for vision FP8 dynamic scaling. A negative outlier currently produces an undersized scale and clips during quantization: `[-8, 1]` dequantizes to `[-1, 1]` instead of `[-8, 1]`.

## Claims

- Negative values contribute their magnitude to the dynamic FP8 scale, including all-negative tensors.
- Extend the existing scale-update regression with a negative outlier in Q, all-negative K, and positive V. No new test cases or backend-selection changes.

## Validation

Tested the actual `MMEncoderAttention._quantize_qkv_fp8` path on one H20-3e (SM90), torch 2.13.0+cu130 / vLLM 0.31.0, with the affected Python module matching upstream main. The probe initializes the scale buffers directly, without constructing an unsupported cuDNN FP8 attention backend, and compares the original method with the one-line fix.

Both the aligned-head CUDA quantizer (head dimension 64) and padded-head Triton quantizer (72) produced:

| Q input | Before: dequantized Q | After: dequantized Q |
| --- | --- | --- |
| `[-8, 1]` | `[-1, 1]` | `[-8, 1]` |
| `[-8, -1]` | both approximately `-1.18e-38` | `[-8, -1]` |
| `[8, 1]` | `[8, 1]` | `[8, 1]` |

K/V use the same inputs scaled by 2/4. All six fixed configurations recovered these exactly representable inputs with zero error; the positive controls also passed before the fix. The CPU reproduction independently produced the same results.

Commands run:

```bash
.venv/bin/python probe_cpu.py
/runtime-venv/bin/python /work/probe_gpu.py
.venv/bin/pre-commit run --files \
  vllm/model_executor/layers/attention/mm_encoder_attention.py \
  tests/kernels/core/test_vit_fp8_scaling.py
```

All probes and pre-commit checks passed. The probe scripts are local validation harnesses; the existing regression remains in `tests/kernels/core/test_vit_fp8_scaling.py`.

The existing pytest module is gated on supported FP8 attention hardware and was not run on H20. Validation here targets the deterministic scale calculation and real GPU quantization; no full-model quality or performance claim is made.

## Details

`Tensor.amax()` returns the largest signed value. FP8 scaling needs the largest magnitude; use `tensor.abs().amax()` before updating the existing circular history. This applies to models using the shared vision FP8 dynamic-scaling path, including DeepSeek V4.1. Static-scale loading and BF16 attention are unchanged. The added absolute-value operation stays on device and introduces no host synchronization.

Targeted searches for open PRs covering `MMEncoderAttention`/`amax`, vision FP8 scaling, and absolute-maximum fixes found no duplicate.

AI assistance was used to identify, implement, and validate this change with Codex.
