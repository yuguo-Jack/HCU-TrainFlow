# docs(envs): fix stale VLLM_CPU_KVCACHE_SPACE default comment (follow-up to #60048)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60772) · state: open · merged: False

## Original PR description

## Impact

Anyone reading vllm/envs.py, the canonical registry of every vLLM env var, is told VLLM_CPU_KVCACHE_SPACE "will be set as 4 GB". That is false in both halves: when unset the value resolves to None, and no code path anywhere sets 4 GB. This leftover wrong comment re-seeds exactly the confusion #60048 was filed to kill.

## Cause

The comment predates the current lambda, which returns None when the variable is unset, and vllm/platforms/cpu.py only reads the variable when it is explicitly set (values are GiB, multiplied by GiB_bytes). Open PR #60053 fixed the docs files and cpu.py but did not touch envs.py, so this comment survived.

## Fix

Comment-only change in vllm/envs.py: state the unit (GiB), that the default is None (unset), that it only takes effect when explicitly set, and that it is a legacy setting superseded by --kv-cache-memory-bytes. Code untouched.

Follow-up to #60048.
