# [KV Connector] Enable DFS in MooncakeStoreConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/61175) · state: open · merged: False

## Original PR description

## Overview

Enable opt-in DFS support in `MooncakeStoreConnector` by initializing the native backend and forwarding DFS replica settings.

This extends the storage support introduced in #42689. No open PR addressing the same DFS initialization and replica forwarding was found.

## Claims

- Initialize DFS when `enable_dfs=true` and request one DFS replica plus at least one memory replica.
- Reuse existing GET batch splitting with `local_buffer_size` as the DFS budget.
- Validate SDK support, replica settings, and tenant restrictions; reject DFS in the RAM-only cross-encoder cache.

## Validation

```bash
.venv/bin/python -m pytest tests/v1/kv_connector/unit/test_mooncake_store_worker.py -q
```

229 tests passed. File-scoped pre-commit checks passed for all five changed files.

Native E2E used Qwen2.5-0.5B-Instruct on one RTX PRO 4000 Blackwell GPU with 3FS, TCP, eager MRV1, and one receive thread. Mooncake revision `e88aacf20cd83461ac4e6ff18a8b50a1e2b3f349` was built with `USE_3FS=ON`.

After removing memory replicas and clearing the local prefix cache:

| Check | Result |
| --- | --- |
| DFS KV reuse | 26 successful GETs; 416 cached prompt tokens |
| Generation | All 32 output token IDs matched the initial generation |

Native E2E ran locally, outside CI. A test-only `NonNvmlCudaPlatform` selection bypassed the node's NVML mismatch. Embedded-mode E2E, multi-node operation, RDMA, and long-duration stress were not tested.

## Details

`enable_dfs` initializes DFS independently of vLLM's `enable_offload` setting and takes precedence for GET budgeting. 
Both embedded and standalone-store modes use this setup.

Mooncake's `enable_ssd_offload=True` argument initializes `FileStorage`, including the selected DFS backend. 
Clients select `distributed_storage_backend`; the Master enables DFS through `MOONCAKE_ENABLE_DFS=1`.

DFS currently requires the default tenant. Concurrent GETs can exhaust the shared buffer; aggregate accounting is deferred, so the documented configuration keeps `VLLM_MOONCAKE_LOAD_RECV_THREADS=1`.
