[P2] Scope and runtime semantics need coordination before this lands. #44055 already merged the user-facing docs-page item, and the maintainer's note on #41230 says the remaining work is items 1-3 in `stats.py` / `metrics.py`: https://github.com/vllm-project/vllm/issues/41230#issuecomment-4692806369. Older open PRs #45494, #45607, #50799, #50828, #51512, and #52200 also predate this PR for that remaining scope. Because this PR only changes the already-covered docs page, `Fixes #41230` would close the issue without completing the remaining work; please use `Refs` / `Partially addresses` and explain the material difference, or coordinate with the existing work per `AGENTS.md`.

If this follow-up section is retained, two factual corrections are needed. `KVOutputAggregator` does not sum or average metrics: `aggregate()` concatenates rank-level observation lists, and `NixlKVConnectorStats.reduce()` later computes count/mean/P90 over the combined pool when logging. The current throughput is `sum(bytes) / sum(per-transfer durations)`, not wall-clock aggregate bandwidth (see #48224/#48368), so the existing "aggregate throughput" wording also needs correction. Finally, there is no `--log-stats-interval` CLI flag; the supported setting is `VLLM_LOG_STATS_INTERVAL` (default 10 seconds).
