# [Bugfix][DSv4.1] Preserve partial external hits under bounded replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/58504) · state: closed · merged: False

## Original PR description

## Purpose

When a KV connector reports a non-block-aligned prefix hit for DeepSeek-V4.1 bounded replay, the scheduler rounds it down to a whole block before applying the replay window. With a 64-token block, a 128-token replay window, and an 8,439-token remote hit, this reduces the adopted hit to 8,384 tokens, moves the replay start from 8,311 to 8,256, and can make the Decode block range disagree with the Prefill block range.

The rounding introduced in #56227 protects the SWA block containing the first replay token. This PR instead ensures generated bounded-replay SWA cache specs retain that boundary block, then preserves the exact connector hit only when every replay-enabled group has this guarantee. Direct or legacy configs without the guarantee keep the existing rounding fallback. The attention window is unchanged.

## Relationship to other work

This fixes a mainline scheduler/cache-config interaction from #56227 and does not depend on #58132. It is distinct from #57613's sparse local prefix-cache retention, #56709's native-offloading coverage for already configured `extra_retained_tokens`, and #58289's NIXL-specific source-block alignment. This PR does not claim to fix every connector's legacy block-mapping behavior.

Serving tests used Mooncake. I reviewed the corresponding NIXL hit and block-pairing code, but did not run NIXL transport or NIXL serving tests for this PR; I can add that validation if reviewers need it.

The unmodified nightly encountered an unrelated Mooncake release-only-pull issue before the target test: `MooncakeConnectorWorker.process_pulling_result` could report receive completion for a pull with no local destination blocks, although Decode had not entered `WAITING_FOR_REMOTE_KVS`, triggering a scheduler request-ID assertion. We applied the same temporary guard to both arms so testing could proceed: report receive completion only when `pull_tasks_count == 0 and any(local_block_ids)`. This guard is not part of this PR; the only A/B code difference was the PR.

All 400 measured requests per arm completed with exactly 512 output tokens. The baseline's lost external-hit tokens matched the sum of actual input lengths modulo 64, while the candidate lost none; one nominally aligned 1,088-token request tokenized to 1,089. Mean TTFT in the non-aligned group rose 14.4% under this saturated workload, so the demonstrated performance gain is in Decode TPOT and output throughput.

### Accuracy: full GSM8K A/B

EvalScope ran the complete 1,319-sample GSM8K test split at 0-shot with `temperature=0.2`, `top_p=0.95`, `seed=42`, and `reasoning_effort=high`. Baseline scored **1,269/1,319 (96.209%)**; this PR scored **1,268/1,319 (96.133%)**, a difference of −0.076 percentage points. Both arms completed every request, with no statistically distinguishable accuracy regression in this run. Their generated output-token totals differed, so this evaluation is not used for a throughput claim.
