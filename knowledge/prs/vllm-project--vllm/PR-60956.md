# [Bugfix] drop every copy when removing one scheduled request

[Upstream PR](https://github.com/vllm-project/vllm/pull/60956) · state: open · merged: False

## Original PR description

## Summary
- `remove_all` used `list.remove` for a one-item set, so only the first match was deleted.
- A request object queued twice could stay in `running` after it was supposed to be removed.
- The single-item path now drops every equal element in place. The multi-item path still returns a new list.
