# [Model] Welcome Kolibri; add support for Kolibri-1

[Upstream PR](https://github.com/vllm-project/vllm/pull/60026) · state: closed · merged: False

## Original PR description

## Overview
This change introduces [Kolibri](https://huggingface.co/Aleph-Alpha/Kolibri-1). 

Kolibri is Aleph Alpha's mixture-of-experts reasoning model (78B total / 3.46B active parameters), focused on German and English, with selectable reasoning effort and tool calling. Until now it has been served through an out-of-tree [plugin](https://github.com/Aleph-Alpha/aleph-alpha-inference); this PR adds native support.

`Kolibri1ForCausalLM` reuses the Qwen3-MoE model, decoder layer and MoE block,
with these differences:
- 4:1 sliding-window (513 tokens) to full attention with RoPE only on sliding-window layers, no positional encoding on full-attention layers.
- Sandwich norms after attention and after the MoE.
- 384 routed experts (top-6) plus one shared expert without a shared-expert gate.
- Router: fp32 logits, top-k selection on `logits + bias` and the weights are `sigmoid(logits)`. This differs from the built-in `scoring_func="sigmoid"`, which selects on `sigmoid(logits) + bias`.

The attention, MoE block and `ForCausalLM` constructors are re-implemented, because the Qwen3-MoE versions always apply RoPE, only support a gated shared expert, and hard-code the model class.

The `kolibri1` reasoning parser is based on the Qwen3 grammar, with the starting state taken from the Kolibri 1 chat template, where `reasoning_effort` takes precedence over `enable_thinking`.
Also adds the `kolibri1` tool parser name, which maps to `Hermes2ProToolParser`, `Kolibri1Config`, and updates `supported_models.md`, `reasoning_outputs.md` and `tool_calling.md`.

For model accuracy in FP8 checkpoints, `VLLM_USE_DEEP_GEMM` and `VLLM_USE_DEEP_GEMM_E8M0` default to 0, since E8M0 would round the checkpoint's fp32 block scales to powers of two, and DeepGEMM on Blackwell only accepts UE8M0 scales. These are process-wide switches, so this follows the existing `scale_fmt: ue8m0` handling in `get_config`. User-set values win, and the model refuses to load if `E8M0` is still in use or DeepGEMM is re-enabled on Blackwell.

There are no PRs or issues mentioning Kolibri.

## Test Plan
```
# Custom MoE router 
pytest tests/kernels/moe/test_routing.py -k kolibri1

# Custom reasoning parser
pytest tests/parser/engine/test_kolibri1.py

# Registry and initialization
pytest tests/models/test_registry.py tests/models/test_initialization.py -k Kolibri1

# Serving
vllm serve Aleph-Alpha/Kolibri-1 \
    --reasoning-parser kolibri1 --tool-call-parser kolibri1 --enable-auto-tool-choice
```

## Test Result

- Routing: 5 passed. Parser: 13 passed. Registry and initialization: 2 passed (RTX PRO 6000 Blackwell).
- The two non-streaming starting-state tests, fail with the stock `qwen3` reasoning parser, since qwen3 reads enable_thinking alone.
- Against the server above: JSON-schema and regex structured outputs (thinking on and off) and tool calls (streaming and non-streaming).
- CI has no end-to-end correctness test, since the model is 78B and Transformers has no `kolibri1` implementation to compare against. Instead we report a benchmark score comparison below.

## Validation

AIME2026 avg@16 with [eval-framework](https://github.com/Aleph-Alpha-Research/eval-framework) on RTX PRO 6000 Blackwell, with the [tech report](https://aleph-alpha.com/downloads/tech-report.pdf)'s settings: 256k-token window, reasoning effort high, temperature 1.0, top_p 0.97, top_k 128.
(Note AIME was chosen as a benchmark due to the very long rollouts used. Long rollouts tend to be much more sensitive on changes)

| Checkpoint | Setup | AIME2026 avg@16 |
| --- | --- | --- |
| Tech report |  | 96.0 |
| `Aleph-Alpha/Kolibri-1-BF16` | TP2 | 96.5 |
| `Aleph-Alpha/Kolibri-1` (FP8) | TP1 | 96.7 |

with a standard error of ±3.1 across the 30 problems.
