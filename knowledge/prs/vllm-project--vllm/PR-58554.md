# [Feature][Frontend] Add opt-in chat message truncation

[Upstream PR](https://github.com/vllm-project/vllm/pull/58554) · state: open · merged: False

## Original PR description

## Purpose

Fixes #58423.

A long candidate response can overflow a Chat Completions prompt. `truncate_prompt_tokens` cuts the rendered token sequence and can remove the instructions or rubric needed to interpret that response.

This PR allows one plain-text message to opt in with `"truncate": true`. On overflow, vLLM shortens the end of that message and renders the chat template again, preserving other messages and template markers. Requests without the marker retain their existing behavior. Ambiguous and unsupported uses return an error.

After updating to current `main`, the rendering path also preserves a marked message when its full prompt fits. Requested output limits remain upper bounds: generation can use fewer tokens if the prompt leaves less room.

The docs explain both truncation options and how `/tokenize` reports the original prompt length. This is separate from #58500, which addresses the Responses API rather than Chat Completions.
