# [Bugfix][Test] Run the FlashInfer prefill tests causally, like their reference

[Upstream PR](https://github.com/vllm-project/vllm/pull/60955) · state: open · merged: False

## Original PR description



## Overview

`test_flashinfer_prefill_with_paged_kv` and `test_flashinfer_prefill_with_paged_fp8_kv` compare FlashInfer against `ref_paged_attn`, which applies a causal mask, but they call `BatchPrefillWithPagedKVCacheWrapper.plan()` without `causal=True`, and `plan()` defaults to `causal=False`. This passes `causal=True` and tightens the prefill tolerance so that the test can catch masking errors.

## Claims

- The prefill tests have been comparing **non-causal** FlashInfer attention with a **causal** reference. They pass only because the key and value caches are scaled down, so every output stays below about 0.1, under `atol=5e-2`.
- With `causal=True`, FlashInfer matches a float64 reference to 3e-5, the same as the test's own reference and `torch.nn.functional.scaled_dot_product_attention`. Without it, single-query sequences are exact but multi-query sequences are off by up to 0.0545 (80% of the true value at the worst element).
- Tightening the prefill tolerance to `atol=1e-2` (what the decode tests in this file already use) turns the test into one that catches the bug: 32/32 pass with the fix, 32/32 fail without it.

## Validation

Tesla T4 (SM75), FlashInfer 0.7.0.post1, vLLM at 193922d. FlashInfer has no bfloat16 kernels below SM80, so on the T4 the same cases were run in float16 (`DTYPES = [torch.float16]`, local change only, not part of this PR).

| | max \|FlashInfer − float64 reference\| | prefill tests (`-k "prefill and not num_heads2"`) |
|---|---|---|
| main (no `causal`, `atol=5e-2`) | 0.0545 | 4–6 failed on T4: the 4 page-32/head-128 cases always, 2 head-256 cases depending on test order; elsewhere it passes only because of the tolerance |
| this PR (`causal=True`, `atol=1e-2`) | 3e-5 | **32 passed**, 16 skipped (the fp8 test's existing skip) |
| this PR's tolerance without `causal=True` | — | **32 failed** |

Per sequence (page 32, head 128; sequences `(1, 1328), (5, 18), (129, 463)`), max error against float64:

| | seq 0 (1 query) | seq 1 (5 queries) | seq 2 (129 queries) |
|---|---|---|---|
| FlashInfer, main | 0.0 | 0.0545 | 0.00857 |
| FlashInfer, `causal=True` | 0.0 | 3e-5 | 1e-5 |
| test reference (`ref_paged_attn`, fp16) | 0.0 | 4e-5 | 1e-5 |
| `scaled_dot_product_attention`, fp16 | 0.0 | 3e-5 | 1e-5 |

Reproduction scripts (Kaggle T4): https://github.com/Shakhtar-Sankur/switchyard/tree/main/upstream (`kaggle_vllm_causal.sh`, `kaggle_vllm_pr_check.sh`, `flashinfer_fp64_check.py`).

`ruff check` and `ruff format --check` pass on the changed file.

## Details

- **Root cause:** `plan(..., causal: bool = False)` in FlashInfer; the tests never set it, while `ref_paged_attn` builds a causal mask. vLLM's FlashInfer backend itself passes `causal=True` for new tokens (`vllm/v1/attention/backends/flashinfer.py`), so serving is unaffected; only the tests were blind.
- **How it was found:** running these tests in float16 on a T4, 4 page-32/head-128 cases failed by a small margin. Comparing FlashInfer, the test's reference and PyTorch's SDPA against a float64 reference showed FlashInfer alone was off, only for multi-query sequences.
- **Tolerance:** CI runs this test in bfloat16, which I could not run on a T4. In float16 the fixed test has about 170× headroom under `atol=1e-2` (max difference 6e-5), and the decode tests already pass at `1e-2` in bfloat16; CI is the check for bfloat16.
- **fp8 test:** `test_flashinfer_prefill_with_paged_fp8_kv` stays skipped ("TODO: fix the accuracy issue"). It gets `causal=True` for the same reason, but on the T4 it passes with and without the flag, so I can't say whether the flag is that issue.
- **Not a duplicate:** no open or closed issue or PR matches `test_flashinfer causal` or `test_flashinfer prefill causal`.
