# [Bugfix] Reject LoRA adapters with lora_bias, PiSSA-style init or layer_replication instead of serving wrong outputs

[Upstream PR](https://github.com/vllm-project/vllm/pull/60503) · state: closed · merged: False

## Original PR description

## Overview

Fixes #60223. vLLM loaded three kinds of PEFT LoRA adapters with no error or warning. It then served logprobs that were off by about as much as the whole adapter effect. vLLM now refuses these adapters with a clear message, in the same check that already refuses DoRA. Part of the bug is a regression from #53555.

## Claims

- `lora_bias=True` adapters: the `lora_B.bias` tensor is no longer loaded under the same key as `lora_B.weight`. The adapter is refused with `... is unsupported LoRA weight`, as it was before #53555. The `score` / `classifier` bias support from #53555 is kept.
- Adapters with `init_lora_weights` set to `pissa`, `pissa_niter_*`, `olora`, `loftq` or `corda`, and adapters with `layer_replication`, are refused in `PEFTHelper._validate_features`. Before, they were served on the wrong base model.
- Plain LoRA adapters and inits that do not touch the base model (`true`, `false`, `"gaussian"`, `"eva"`, `"lora_ga"`) load as before and still match PEFT.

## Validation

Setup: 1× NVIDIA GeForce RTX 3090 (24 GiB), vLLM at `43b4aaea3e40e20ef53ce2bfecfa1b72060bf2b5` (`0.31.1rc1.dev23+g43b4aaea3`), PEFT 0.21.2, attention backend `FLASH_ATTN`.

**Reproducer.** This is the script from the issue. It builds a small random Llama model, saves four PEFT adapters, and compares vLLM's prompt logprobs with PEFT's.

```
pip install peft==0.21.2
VLLM_USE_FLASHINFER_SAMPLER=0 VLLM_ENGINE_READY_TIMEOUT_S=3600 python -P repro.py
```

```python
import os
import sys
import tempfile

import torch
from peft import LoraConfig, PeftModel, get_peft_model
from transformers import AutoModelForCausalLM, LlamaConfig
from vllm import LLM, SamplingParams
from vllm.inputs import TokensPrompt
from vllm.lora.request import LoRARequest

T = ["q_proj", "v_proj", "down_proj"]
CASES = {
    "plain": dict(),
    "lora_bias": dict(lora_bias=True),
    "pissa": dict(init_lora_weights="pissa"),
    "layer_replication": dict(layer_replication=[[0, 2], [1, 2]]),
}


def main():
    tmp = tempfile.mkdtemp()
    torch.manual_seed(0)
    cfg = LlamaConfig(vocab_size=1024, hidden_size=256, intermediate_size=512, num_hidden_layers=2,
                      num_attention_heads=4, num_key_value_heads=2, head_dim=64, tie_word_embeddings=False)
    AutoModelForCausalLM.from_config(cfg, dtype=torch.bfloat16).save_pretrained(f"{tmp}/base")

    def base():
        return AutoModelForCausalLM.from_pretrained(f"{tmp}/base", dtype=torch.bfloat16).cuda()

    prompts = [torch.randint(10, 1024, (48,), generator=torch.Generator().manual_seed(i)).tolist() for i in range(4)]

    def peft_logprobs(model):
        out = []
        with torch.no_grad():
            for ids in prompts:
                x = torch.tensor([ids], device="cuda")
                logp = torch.log_softmax(model(input_ids=x).logits[0, :-1].float(), -1)
                out.append(logp.gather(-1, x[0, 1:, None])[:, 0].tolist())
        return torch.tensor(out)

    ref = {}
    for name, extra in CASES.items():
        torch.manual_seed(1)
        model = get_peft_model(base(), LoraConfig(r=8, lora_alpha=16, target_modules=T, **extra))
        with torch.no_grad():
            for n, p in model.named_parameters():
                if "lora_" in n:
                    p.normal_(0, 0.05)
        model.save_pretrained(f"{tmp}/{name}")
        # reload the way a user would, so PEFT applies the config on load
        ref[name] = peft_logprobs(PeftModel.from_pretrained(base(), f"{tmp}/{name}"))
    ref_base = peft_logprobs(base())

    llm = LLM(f"{tmp}/base", skip_tokenizer_init=True, enable_lora=True, max_lora_rank=8, max_model_len=256,
              gpu_memory_utilization=0.3, enforce_eager=True)
    params = SamplingParams(max_tokens=1, prompt_logprobs=0, detokenize=False)
    for i, name in enumerate(CASES, start=1):
        try:
            outs = llm.generate([TokensPrompt(prompt_token_ids=p) for p in prompts], params,
                                lora_request=LoRARequest(name, i, f"{tmp}/{name}"), use_tqdm=False)
        except Exception as e:
            print(f"{name:18s} {type(e).__name__}")
            sys.exit(0)
        lp = torch.tensor([[o.prompt_logprobs[j][t].logprob for j, t in enumerate(p) if j > 0]
                           for p, o in zip(prompts, outs)])
        print(f"{name:18s} mean |vLLM - PEFT|: {(lp - ref[name]).abs().mean():.4f}   "
              f"adapter effect in PEFT: {(ref[name] - ref_base).abs().mean():.4f}")


if __name__ == "__main__":
    main()
```

## Details

**Root cause 1: `lora_bias` (regression from #53555).** vLLM removed LoRA bias support on purpose in #25807. After that, `parse_fine_tuned_lora_name` accepted only `lora_A.weight` / `lora_B.weight`. #53555 wanted `.bias` only for `score` / `classifier` heads, but its check also let `lora_B.bias` through and parsed it to the same key as `lora_B.weight`. In `LoRAModel.from_lora_tensors` the later tensor overwrites the earlier one. Safetensors keys are sorted, so `lora_B.bias` comes first and the weight overwrites it. The bias is dropped and nothing says so. Debug prints on the base commit showed `lora_B.bias` `(256,)` and `lora_B.weight` `(256, 8)` mapped to the same module. Fix: in `vllm/lora/utils.py`, the `lora_A` / `lora_B` branch accepts only `.weight` again. `score.weight`, `score.bias` and `classifier.bias` still map to the head.

**Root cause 2: `PEFTHelper.from_dict` drops unknown config keys.** So `_validate_features`, which refuses DoRA, never saw these two fields:

- `init_lora_weights`. With `pissa`, `pissa_niter_*`, `olora` or `loftq`, PEFT 0.21.2 rewrites the base layer weight every time it loads the adapter (`pissa_init`, `olora_init`, `loftq_init` in `peft/tuners/lora/layer.py`). The saved A and B are only correct on that rewritten base. A separate check on the base commit confirmed this for PiSSA. PEFT's load changed the `q_proj` weight by up to 0.0366, and the change equals the top-8 SVD part of the weight. With the same A and B and `init_lora_weights=true`, vLLM matched PEFT at 0.0022 instead of 0.1019. So the whole gap comes from the base rewrite. `corda` also rewrites the base on load, and without its preprocessing data PEFT refuses to load it at all.
- `layer_replication`. PEFT builds a deeper model whose new layers share base weights, and each new layer gets its own LoRA. `[[0, 2], [1, 2]]` gives layers `0, 1, 1`. vLLM keeps 2 layers, so the `layers.2.*` LoRA weights match no module and are skipped.

Fix: add `init_lora_weights` and `layer_replication` to `PEFTHelper` and refuse them in `_validate_features`, next to DoRA.

**Why refuse, and not implement.** One vLLM base model serves many adapters at once. It cannot rewrite the base weights or add layers for one adapter. Folding the PiSSA change into the adapter would need rank `2r` and the full, unsharded base weight. `pissa_niter_*` uses a random SVD. CorDA needs calibration data that is not in the adapter. LoRA bias was removed on purpose in #25807. The error message tells users to convert the adapter into a regular LoRA first. PEFT has a converter for this (`path_initial_model_for_weight_conversion`), and it sets `init_lora_weights` back to `true`, so converted adapters load.

**`"lora_ga"` is not refused.** On load no gradient is attached, so PEFT falls back to the default init and does not touch the base. PEFT then serves the adapter as a plain LoRA, which is what vLLM does. A real LoRA-GA adapter on its own base gave mean |vLLM - PEFT| 0.0018 with this patch.

**Limitations.**

- The issue also lists aLoRA (`alora_invocation_tokens`), BD-LoRA (`use_bdlora`) and QALoRA (`use_qalora`). These were not reproduced here, and this PR does not touch them.
- When a refused adapter is first used inside `LLM.generate`, the error is raised in the worker, and the caller gets `EngineDeadError` with the reason only in the engine log. This is the existing behaviour for every adapter check, DoRA included. This PR does not change it; the issue leaves it to #59924. Through `add_lora` (the path of `/v1/load_lora_adapter`), the caller gets the `ValueError` and the engine keeps running.
- A `lora_bias` adapter gets the generic message from before #53555 (`... lora_B.bias is unsupported LoRA weight`). It names the tensor, not `lora_bias`.

**Size.** 1 line changed in `vllm/lora/utils.py` and 15 lines added in `vllm/lora/peft_helper.py`. New test functions are in existing test files. No existing test was changed.

AI assistance was used to reproduce the bug, find the root cause, write the patch and run the validation above.
