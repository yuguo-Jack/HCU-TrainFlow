# [Rust Frontend] Box rarely-set fields of per-token output types

[Upstream PR](https://github.com/vllm-project/vllm/pull/60588) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Box the rarely-set fields of the Rust frontend's per-token output types (`EngineCoreOutput`, `GenerateOutput`, `ChatEvent`, and the internal `AssistantEvent`). These values are moved by value through the output dispatcher, the per-request channel, and the `llm`/`chat` layers once per engine step, so their inline size is paid on every token.

This is the base of a stack; the `--stream-interval` support PR sits on top of it.

## Claims

- `EngineCoreOutput` 648 → 264 bytes (`EngineCoreStreamOutput` 664 → 280), `GenerateOutput` 472 → 168, `ChatEvent` 232 → 104, `AssistantEvent` 208 → 80.
- Mock-engine throughput with 32 tokio workers +18.8%; frontend pinned to 8 cores +4.5%; 8 workers on a large host unchanged.
- No wire or API behavior change: the msgpack format is unchanged (`Box` is transparent to serde), and per-request types keep their unboxed fields.

## Details

**Why.** While implementing `--stream-interval`, a few refactors that only changed how outputs are wrapped (a `SmallVec` channel item, iterator adapters around a delivery) regressed throughput by 7–17%. Disassembly showed one to three extra full-size `memcpy`s of the 664-byte `EngineCoreStreamOutput` per token in the dispatcher and the request task. With 32 workers the single output dispatcher is the bottleneck, so its per-token copy cost turns directly into throughput. Shrinking the moved types makes every copy on this path cheaper and makes the path less sensitive to such wrapping.

**What is boxed.** Only fields that are absent on most outputs:

- `EngineCoreOutput`: `pooling_output` (pooling only), `kv_transfer_params` / `ec_transfer_params` (final output, disaggregated serving), `trace_headers` (tracing), `prefill_stats` (first output), `routed_experts` (opt-in), `spec_decode_metrics` (final output, opt-in), `prompt_token_id_logprobs` (first output, opt-in). Per-step fields (`request_id`, `new_token_ids`, `new_logprobs`, `new_sampling_mask`, `events`, ...) stay inline.
- `GenerateOutput`: `prompt_info` (first output), `kv_transfer_params`, `ec_transfer_params`, `spec_decode_metrics`. The boxes are moved through from the engine output, so no extra allocation per step.
- `ChatEvent::Done` and the internal `AssistantEvent::Done`: `kv_transfer_params`, `ec_transfer_params`, which made every per-token `ChatEvent` 232 bytes and `AssistantEvent` 208 bytes. `text::Finished` carries the same boxes through unchanged, so the streaming path never unboxes and boxes them again.

`serde_json::Value` is 72 bytes here because the workspace enables `preserve_order`, which is why the two transfer-params fields were large in every layer.

**Allocation cost.** A boxed field allocates only when present: `prefill_stats` and `prompt_info` once per request, the rest only when the feature is used. Per-request collected types (`CollectedGenerateOutput`, `CollectedTextOutput`, `CollectedAssistantMessage`) and response DTOs keep unboxed fields and unbox at collection, so downstream code is unchanged.
