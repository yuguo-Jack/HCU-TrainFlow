# [Bugfix][Kernel] Fix direct NVFP4 KV writer V-scale layout on SM12x

[Upstream PR](https://github.com/vllm-project/vllm/pull/55976) · state: open · merged: False

## Original PR description

## Overview

Fix the retained `reshape_and_cache_flash` CUDA operation's NVFP4 V-scale layout on SM120/SM121, including `nvfp4_4over6`. This addresses the direct-operation mismatch in #50084. Current SM12x serving uses FlashInfer's replacement writer from #46963; this PR does not fix that serving path.

## Claims

- Capability family 12 writes linear V scales, matching the existing operation tests and reader layout. K scales remain linear.
- Valid SM100 layouts retain their V-scale swizzle. Invalid swizzle dimensions are rejected before launch.
- Extend the existing K/V roundtrip tests to `nvfp4_4over6` and enable their existing head-size-80 cases on family 12.

## Validation

Tested main `18c19eaf23` with refreshed head `1be231ee8c` on ThinkStation PGX / GB10 SM121, CUDA 13.0 and PyTorch 2.13.0+cu130. A fresh isolated environment built and installed the full upstream `_C_stable_libtorch` component. Tests use the actual exported `_C_cache_ops` binding without an adapter; the patched arm rebuilt the changed CUDA object and relinked.

`pytest tests/kernels/attention/test_cache.py -k 'nvfp4 and 1024' -q`: **stock 36 failed; patched 36 passed**. Both arms had 252 skips and 1256 deselected cases. Coverage includes BF16, NHD/HND, head sizes 64/80/256, page sizes 8/16/32, and both NVFP4 variants. The existing test halves the selected 1024-block/42-token parameters to 512 blocks/21 tokens.

Stock failures were numerical assertions: 34 V failures and two K failures in the NHD/head-80/page-8 cases, where the invalid V swizzle can overrun its page. SM100 hardware was unavailable; its valid branch is unchanged by inspection. Configured scoped pre-commit checks and `git diff --check` pass.

On October 10, after the author confirmed line-by-line review and requested tests under their oversight, the same patched binding passed again: **36 passed**, 252 skipped, 1256 deselected. Codex operated the tests. No serving-model quality or performance claim is made.

## Details

#46963 bypasses this operation in SM12x serving; #60452 retains that replacement writer when enabling XQA decode. The exported CUDA operation and its tests still admit SM12x NVFP4, so their layout contract remains worth fixing.

The architecture gate targets family 12 exactly. The device guard precedes the capability query; four-token/four-scale alignment checks apply only to the swizzle path; launch errors are checked immediately. The separate MiniMax-M3 fused writer is unchanged.

AI assistance was used for the original patch and refresh. Original authorship and attribution are retained; Codex assisted with the audit, refresh and validation under human review and oversight.

- TensorRaya · comment · 2026-09-09T05:32:05Z · [source](https://github.com/vllm-project/vllm/pull/55976#issuecomment-5596336613)

Follow-up to my note above about the needle probe: I now have the measurement that closes the gap between "24 failed in the unit test" and "what the reader actually computes".

**Writer → real reader → attention output**, sm_120. Random Q/K/V (8 heads / 2 KV heads / head 128, block 16, causal, HND), written by each writer into an NVFP4 page cache, then read by the kernel this path uses in production on SM12x: `BatchPrefillWithPagedKVCacheWrapper(backend="fa2")` with `kv_data_type=uint8` and `kv_cache_sf=(k_sf, v_sf)` from `nvfp4_split_data_scale`. Output compared against bf16 reference attention. 5 seeds each.

| KV len | writer | rel. L2 error vs bf16 | cosine | max abs err |
|---|---|---|---|---|
| 256 | `main` (V swizzled) | 0.338 ± 0.012 | 0.946 | 2.38 |
| 256 | V linear (this PR) | **0.122 ± 0.002** | **0.993** | 0.45 |
| 1024 | `main` | 0.340 ± 0.007 | 0.945 | 1.54 |
| 1024 | V linear | **0.127 ± 0.001** | **0.992** | 0.50 |
| 2048 | `main` | 0.349 ± 0.010 | 0.943 | 1.95 |
| 2048 | V linear | **0.128 ± 0.002** | **0.992** | 0.47 |

So the FA2 reader on SM12x does read V scales linearly: with the swizzled writer the attention output carries ~2.7× the error of the linear writer, and the ~0.12 residual with the linear writer is the NVFP4 quantisation itself (K and V both 4-bit, no scale mismatch left). No NaN in either case on this input; the NaN in the unit test comes from denormal/garbage fp8 scale bytes landing on real-data positions, which random-normal inputs happen to avoid.

This also explains my earlier observation that a coarse needle-recall probe passed with both writers: 0.34 relative error on attention output is a lot of noise, but a 27B model still finds a verbatim string through it. It is not "still correct", it is degraded in a way that recall probes do not detect.

Script: https://gist.github.com/TensorRaya/660ddfbe4b84aaefee1a446dd4e16e1f (needs the overlay op for the linear writer until this PR is in; swap `ov.reshape_and_cache_nvfp4_linear` for `ops.reshape_and_cache_flash` built from this branch).
