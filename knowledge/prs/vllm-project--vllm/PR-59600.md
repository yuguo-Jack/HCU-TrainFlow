# [Bugfix][Spec Decode] Restore ShortConv drafter state in MRV2

[Upstream PR](https://github.com/vllm-project/vllm/pull/59600) · state: open · merged: False

## Original PR description



## Overview

Restore ShortConv history between speculative rounds in MRV2's independent draft-model path. Temporary draft steps and rejected input slots could contaminate the next round's state, reducing acceptance even with identical target and drafter weights.

Related: #49112.

## Claims

- Restore per-request convolution history at the start of step 0, preserve a checkpoint before the correction token, and leave temporary state after correction for subsequent draft steps.
- Use the next prompt token during chunked prefill when the target has not sampled, rather than a stale last-sampled token.
- Cover history recovery, chunked-prefill input preparation, and consecutive speculative rounds in the existing test suites.

## Details

Let `H(p)` denote the convolution state after consuming positions `[0, p)`. If the current correction token is at position `c`, step 0 saves `H(c)` for the next round and leaves runtime state at `H(c+1)` for further drafting. The next target input starts with that correction token, so saving only the post-correction state would consume it twice on replay.

Each ShortConv draft layer owns a preallocated checkpoint indexed by stable request slot. Metadata carries the checkpoint and correction boundary into the existing convolution forward kernel, which restores initial history and writes both state windows. Runtime state continues to use cache-block indices. Per-layer `dataclasses.replace` keeps checkpoint metadata local to the draft layer.

The checkpoint path supports convolution widths 2–4 and requires `mamba_cache_mode="none"` with prefix caching disabled.

Related-work review found no open PR implementing this recovery. #44296 handles target-side rollback, #56531 handles zero-draft recurrent-row classification, and #58851 shares batch metadata. #55990's standalone-draft refactor excludes hybrid models. The closed #50146 attempted post-step-0 snapshot/restore in MRV1; this patch preserves the pre-correction history required by MRV2's replay contract and excludes the rejected step-0 tail from saved state.
