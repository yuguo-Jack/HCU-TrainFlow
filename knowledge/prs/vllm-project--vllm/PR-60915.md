# [Frontend] generate: packed top-k logprobs (return_top_k_logprobs)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60915) · state: open · merged: False

## Original PR description

## Overview

Adds `return_top_k_logprobs` to `/inference/v1/generate`: top-k output logprobs as one packed base64 block per choice instead of per-token JSON objects. Part of RFC #57479.

> **Draft, stacked.** This branch sits on #60542 (numpy-backed `FlatLogprobs` + fast default render) and on a cherry-pick of #57442 (`return_token_logprobs`). Only the last commit, "packed top-k logprobs (return_top_k_logprobs)", is new here. The Rust frontend counterpart is #60916.
>
> **Rebased** onto #60542's current head (227e42a2f7), which replaced `ArrayLogprobs` with a numpy-backed `FlatLogprobs`. The packed block is now built from `FlatLogprobs.rows()`; the #57442 cherry-pick reads sampled logprobs via a new `FlatLogprobs.sampled_logprobs()`.

## Claims

- New request flag `return_top_k_logprobs`. With `sampling_params.logprobs = k >= 1`, each choice's `logprobs` is `{"content": null, "top_k": {...}}`:
  ```python
  class PackedTopK(BaseModel):
      num_positions: int
      k: int
      token_ids: str  # base64, little-endian int32, num_positions x k (engine slots 1..k)
      logprobs: str   # base64, little-endian float32, num_positions x k (raw values)
  ```
- With `return_token_logprobs` also set, `sampled` (slot 0, clamped as in #57442) comes before `top_k`. The sampled token isn't always in the top-k, so this keeps its logprob for one float per token.
- `stream=true`, `output_mode="text"` and `logprobs` 0 / −1 with the flag return 400. `k = 0` is what `return_token_logprobs` is for.
- Responses without the flag are byte-for-byte unchanged. `top_k` is omitted unless requested.

Result on GB200 after the rebase: 214 passed, 0 failed, including the live-server tests in `test_serving_tokens.py`. `pre-commit`, including the manual-stage mypy, is clean.

New tests (in `test_logprobs_render.py`):
- the spliced body equals what `JSONResponse` gives for the same values, across k, position counts, and with and without `return_token_logprobs`;
- decoded `top_k` and `sampled` match the `content` entries rendered from the same rows;
- the 400 cases;
- responses without the flag keep their schema and bytes;
- with `return_token_logprobs` and top-k, `sampled` matches the per-entry path (fast render forced off).

**Default path unaffected by this branch.** The #60542 CPU benchmark (12.5k tokens × top-128, through `LogprobsProcessor` and `_build_full_response`) gives the same numbers on this branch as on #60542 alone: 4.4 µs ingest per engine row, 10.6 stored bytes per entry, 0.41 s response build, 181 MiB build peak, and an identical body hash. See #60542 for the end-to-end abort results of the default render (`/pause?mode=abort` about 0.4 s vs 92 s on main).

**Packed top-k performance (prototype, not yet rerun on this rebase).** On the earlier compact-format prototype, an RL `pause(mode="abort")` with 245,760 output tokens at top-128 produced about 2.2 GB per response in per-token form and 337 MB as the packed block. On DP8 with 32 such requests, the Python frontend went from about 21 s to about 1.8 s. I'll rerun this end to end on this branch before marking it ready.

## Details

- **Rendering.** The block is built from `FlatLogprobs.rows()` (#60542). Rows that don't fit the packed shape (irregular widths, ids beyond int32) return a 500 rather than a silently different layout. It's one base64 pass over `arrays[:, 1:]` per choice, spliced into the rendered body. There's no per-token Python object and no `model_dump()`, like #57442's `k = 0` path.
- **Two flags rather than one switch.** They're separate so #57442 can land unchanged. A single logprobs-options design can follow.
- **Encoding.** Raw little-endian arrays rather than `.npy` (which `routed_experts` uses): there's no header, the Rust writer can stream it in segments, and `num_positions` / `k` already give the shape. Happy to switch to `.npy` for consistency.
- **Known gap.** The #57442 cherry-pick predates its latest commit (1b3dc5b2fc, "reject logprob_token_ids, read any logprobs layout"). It will be dropped when #57442 merges.

**Not a duplicate.** #57442 adds only the `k = 0` sampled-token path. #60789 replays logprobs through the AuxOutput connector, a side channel rather than the HTTP response. No open PR returns packed top-k logprobs on this endpoint (`gh pr list --state open --search "57479 in:body"` and `"top_k logprobs generate"`).
