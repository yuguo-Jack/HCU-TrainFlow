# [reward] fix: read APPS/TACO call-based tests in prime_code

[Upstream PR](https://github.com/verl-project/verl/pull/8175) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #8174. prime_code's call-based path only parsed LiveCodeBench-style tests (each input a string of JSON lines). APPS and TACO publish call-based tests with each input as a list of arguments, so every such task crashed before running and scored 0, even for a correct solution. This reads both layouts: a string input is parsed as before, a list input is used as the arguments with the output as given.

### Test

New CPU test `tests/utils/reward_score/test_prime_code_call_based_on_cpu.py` (both layouts, right and wrong solution):

    # on main: 1 failed, 3 passed (apps_layout, correct solution scores 0.0)

On real data (codeparrot/apps train, 30 call-based problems, seed 7, the dataset's first solution):

| | full reward |
|---|---|
| main, tests as published | 0/30 |
| this PR, tests as published | 28/30 |
| main, tests re-encoded as JSON-line strings | 28/30 (unchanged by this PR) |
| this PR, a solution that returns None | 0/30 (nothing got looser) |

The 2/30 that still fail, fail identically on both layouts, so they are unrelated to this change.

`pre-commit run` on the changed files: all hooks pass.

### API and Usage Example

No API change. Existing string-layout data is handled exactly as before.

### Design & Code Changes

`verl/utils/reward_score/prime_code/testing_util.py`: in `run_test`'s call-based branch, parse JSON lines only when the input is a string; otherwise keep the list as the arguments and the expected output as is, and JSON-encode both only for the truncated metadata.
