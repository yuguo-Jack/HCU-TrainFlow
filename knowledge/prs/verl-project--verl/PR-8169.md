# [data, rollout, vllm] fix: Qwen video placeholder collapse for vLLM rollout

[Upstream PR](https://github.com/verl-project/verl/pull/8169) · state: open · merged: False

## Original PR description

### What does this PR do?

#### Fix Qwen video prompt placeholder mismatch for vLLM rollout

Qwen video preprocessing expand a single raw video into multiple timestamp-prefixed compact video groups, for example:
```bash
<0.6 seconds><|vision_start|><|video_pad|><|vision_end|>
<3.0 seconds><|vision_start|><|video_pad|><|vision_end|>
<5.4 seconds><|vision_start|><|video_pad|><|vision_end|>
...
```

However, vLLM raw video inputs expect one video placeholder per input video:
```bash
<|vision_start|><|video_pad|><|vision_end|>
```

If the timestamp-expanded prompt is passed directly to vLLM together with one raw video input, vLLM/Qwen-VL placeholder replacement sees multiple <|video_pad|> placeholders for a single raw video. This can lead to malformed prompt replacement or a mismatch between video placeholders and raw video inputs.

The issue is more subtle for prompts with multiple videos, because adjacent timestamp groups must be collapsed per video rather than merged blindly.

#### Solution
This PR adds qwen2_5_vl_dedup_video_tokens() to collapse Qwen timestamp-expanded video groups before constructing the vLLM TokensPrompt.

The function uses video_grid_thw[:, 0] as the source of truth for grouping:
```python
group_counts = [int(row[0]) for row in video_grid_thw.tolist()]
```
Each row in video_grid_thw corresponds to one raw video, and its temporal dimension indicates how many timestamp-prefixed compact groups belong to that video. This allows the code to safely collapse:
```bash
<0.6 seconds><|vision_start|><|video_pad|><|vision_end|>
<3.0 seconds><|vision_start|><|video_pad|><|vision_end|>
...
```

into:
```bash
<|vision_start|><|video_pad|><|vision_end|>
```
