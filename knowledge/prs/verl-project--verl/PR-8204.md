# [trainer] feat: record uid / data_source / index join keys in rollout jsonl

[Upstream PR](https://github.com/verl-project/verl/pull/8204) · state: open · merged: False

## Original PR description

### What does this PR do?

Add three identity columns to both training rollout JSONL (from _log_rollout_data) and validation JSONL (from _validate) so offline analysis can:
  * group the n rollouts of each prompt by `uid`, and
  * left-join back to the source parquet by `(data_source, index)`.

### Design & Code Changes

- All three columns piggyback on `reward_extra_infos_dict` to avoid changing the `_dump_generations` signature.
- `uid` is canonicalized via `str()` (training/validation uids are already `str(uuid.uuid4())`); `data_source` and `index` keep native dtype so offline join does not need either side to pre-cast.
- Column collisions with reward-manager output warn + skip (keeping the reward value). Dump is an observability path; it must not be able to halt training.
- Length mismatch between join columns and `n` fails loud inside the `_build_join_keys` helper, bypassing the silent `len(v) == n` filter inside `_write_generations`.
- The validation dump branch uses a local copy of `reward_extra_infos_dict` so the join keys never reach `process_validation_metrics` or the `merged` return path.
- `rl_dataset.py:419` defaults `extra_info["index"]` to 0; datasets that fail to populate `extra_info["index"]` during preprocessing will have index=0 for every sample, which makes join-back infeasible. This is a dataset-provider responsibility and the dump path does not add defensive heuristics for it.

`_build_join_keys` uses `assert` for its length checks. If `flat_data_sources` has a different length from `sample_inputs`, the assertion fails. One cause is a `data_source` value that is a scalar string, where `np.asarray(...).tolist()` returns a string rather than a list. Another cause is a `data_source` array that disagrees with the batch size.

The assertion then fails the whole validation run, only for an observational dump. Also, `assert` is stripped under `python -O`. Consider logging a warning and skipping the bad column. If you want a hard failure, raise `ValueError` instead of using `assert`.
