# [trainer, rollout] fix: honor V1 standalone rollout memory budget

[Upstream PR](https://github.com/verl-project/verl/pull/7926) · state: closed · merged: True

## Original PR description

### What does this PR do?

V1 `separate_async` currently ignores `standalone_gpu_memory_utilization` when creating the standalone rollout manager. Apply the existing override to a copied config so dedicated rollout GPUs can use a different budget while hybrid replicas retain their own setting.

Fixes #7795. This follows the runtime semantics introduced for experimental fully async in #6556. Missing or explicit `null` values retain the fallback to `gpu_memory_utilization`.

- [x] Use the required module/type title format.

Open #7430 adds a broader set of missing rollout YAML keys but does not implement this V1 runtime fix. Following [maintainer feedback](https://github.com/verl-project/verl/pull/7926#discussion_r4059130980), this PR also declares this one field in `rollout.yaml` and updates the four generated trainer configs. Other configuration-parity work remains outside this PR.

### Design & Code Changes

- Copy the full config before standalone manager creation, preserving OmegaConf interpolation context and leaving the trainer/hybrid config unchanged.
- Declare `standalone_gpu_memory_utilization: ${oc.select:actor_rollout_ref.rollout.gpu_memory_utilization}` in the default rollout YAML and regenerate the DP, Megatron, VeOmni, and TorchTitan reference configs.
- Cover default inheritance, explicit `null`, and ordinary Hydra overrides across all four model-engine configurations, with hybrid replicas enabled and disabled.
- Remove the unsupported `flush=True` argument from `logger.info` in standalone-only setup; the regression tests exposed the existing TypeError on that path.
- Update the V1 documentation to use an ordinary override without `++`.

### API and Usage Example

```bash
actor_rollout_ref.rollout.gpu_memory_utilization=0.5 \
actor_rollout_ref.rollout.standalone_gpu_memory_utilization=0.85
```

Choose fractions suitable for each GPU pool. The standalone value follows `gpu_memory_utilization` by default. An explicit `null` also falls back to that value. The override applies when `actor_rollout_ref.hybrid_engine=False` too.

### Test

Executed on the remote Linux host with Python 3.12.14 and `PYTHONPATH` unset:

```bash
env -u PYTHONPATH CUDA_VISIBLE_DEVICES= TORCH_COMPILE_DISABLE=1 TORCHINDUCTOR_DISABLE=1 \
  ../.venv/bin/python -m pytest -s -x --asyncio-mode=auto \
  tests/trainer/ppo/v1/test_separate_async_step_switch_on_cpu.py \
  tests/trainer/ppo/v1/test_trainer_base_on_cpu.py \
  tests/trainer/ppo/v1/test_v1_async_warmup_on_cpu.py \
  tests/trainer/ppo/v1/test_v1_async_alignment_on_cpu.py \
  tests/trainer/ppo/v1/test_rollout_profiling_on_cpu.py
```

- **107 passed**: 67 target tests and 40 adjacent tests.
- The 24 Hydra composition/setup cases all failed before adding the YAML field and pass afterward. They exercise DP, Megatron, VeOmni, and TorchTitan configuration composition, default inheritance, explicit `null`/numeric overrides, and hybrid enable/disable.
- The original runtime regression had 11 failures / 4 passes before the production fix.
- All four generated configs were regenerated with `scripts/generate_trainer_config.sh`; a second run passed without further changes.
- All 14 equivalent local pre-commit hooks passed with Ruff 0.12.2 and mypy 1.17.0; generated-config verification was included. The original isolated hook installation again exceeded a 60-second limit before hooks started, so this does not claim the original isolated pre-commit run passed.

The setup tests invoke the actual V1 `_setup` while mocking expensive base setup, LLM server creation, and checkpoint manager construction. They test configuration behavior, not execution of the four training engines. Existing CPU CI collects this `*_on_cpu.py` file.

The remote tests use the prepared environment, not the complete frozen CI environment: an earlier `uv run --frozen --all-packages --extra cpu` bootstrap timed out during downloads. A previous broader V1 directory run reached 36 passes before Ray/TransferQueue fixture initialization failed to create worker threads. No real multi-GPU hybrid/standalone vLLM/SGLang end-to-end job or performance measurement was run.
