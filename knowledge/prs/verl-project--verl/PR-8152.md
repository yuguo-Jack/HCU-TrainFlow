# [fsdp] fix: fail fast when LoRA parameter collection is empty

[Upstream PR](https://github.com/verl-project/verl/pull/8152) · state: open · merged: False

## Original PR description

### What does this PR do?

An empty LoRA state dict reaches vLLM's adapter registration, where v0.23.0 raises StopIteration while accessing the first adapter weight. The receiver then exits without acknowledging the final weight bucket, leaving the sender blocked waiting for a reply.

Assert that collected LoRA parameters are non-empty before returning them for synchronization. Apply the assertion only when `base_sync_done` is true, limiting this validation to LoRA adapter weights.
