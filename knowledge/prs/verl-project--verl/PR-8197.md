# [data] fix: preserve reasoning content in multi-turn SFT tokenization

[Upstream PR](https://github.com/verl-project/verl/pull/8197) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #7807. `MultiTurnSFTDataset` rendered each message in isolation with `apply_chat_template([message])`, but chat templates such as Qwen3 build the `<think>` block from `reasoning_content` only when the assistant message is rendered together with its preceding conversation. Per-message rendering therefore silently dropped the reasoning channel: `sanity_check()` raised `AssertionError` on reasoning conversations, and with `ignore_input_ids_mismatch=True` the trained sequence never contained any `<think>` section, which teaches the model to put final answers into the reasoning channel.

The fix uses the previously unused `full_message` argument: for conversations that carry a `reasoning_content` field, assistant turns are rendered as part of the conversation prefix (`full_message[:index+1]`), and the tokenized `full_message[:index]` prefix is sliced off to obtain the per-turn increment. Every other turn, and the whole VLM/processor path, keeps the previous per-message rendering, so token sequences stay byte-identical for conversations without `reasoning_content` and for templates without position-dependent rendering.

### API and Usage Example

No API or config change. Behavior for a Qwen3 multi-turn conversation whose assistant messages carry `reasoning_content`:

```python
item = dataset[0]  # no longer raises AssertionError from sanity_check
# item["input_ids"] now equals tokenizer.apply_chat_template(
#     whole_conversation, tools=tools, enable_thinking=True)
# tokenizer.decode(item["input_ids"][item["loss_mask"] == 1]) contains
# "<think>reasoning ...</think>\n<tool_call>...</tool_call>" for every assistant turn,
# so ignore_input_ids_mismatch=True is no longer needed for this scenario.
```

### Design & Code Changes

- `verl/utils/dataset/multiturn_sft_dataset.py` (`_process_single_message`): added a gated context-rendering branch (text-only path, `index != 0`, assistant role, conversation contains a truthy `reasoning_content`). It renders `full_message[:index+1]` via verl's `apply_chat_template` wrapper and slices off the tokenized `full_message[:index]` prefix; if the shorter prefix is not a token-level prefix of the longer render, it warns and slices by length (the existing `sanity_check` remains the final sequence oracle). `__getitem__` now passes `tools` ungated and the per-message branch applies the historical `tools if index == 0 else None` gating internally, keeping VLM behavior identical.
- New CPU test `tests/utils/dataset/test_multiturn_sft_qwen3_reasoning_on_cpu.py` (auto-picked-up by `cpu_unit_tests.yml`, which globs `**/*.py`).
