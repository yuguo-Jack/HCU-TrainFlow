# [hardware, model, cfg, tests] feat: Ascend CANN fused linear cross-entropy

[Upstream PR](https://github.com/verl-project/verl/pull/8143) · state: open · merged: False

## Original PR description

### What does this PR do?

Adds Ascend NPU support for fused `linear_cross_entropy` via CANN / `torch_npu` vocab-parallel fused CE APIs, so `use_fused_kernels=True` can run without the CUDA Triton path that overflows UB on 910B.

Fixes #7950.

Related open PR [#8001](https://github.com/verl-project/verl/pull/8001) falls back to torch fused kernels on Ascend. This PR keeps a real fused CE path on NPU (CANN) instead of materializing full logits. Hybrid backward: `dentropy==0` uses CANN CE; `dentropy!=0` (e.g. PPO `entropy_coeff!=0`) uses chunked PyTorch CE+entropy grads aligned with Triton `efficient_entropy`. `use_fused_kernels` is not force-disabled by `entropy_coeff`.

Also fixes a training crash after fused CE: on some NPU builds, `postprocess_thd_engine` / `postprocess_bshd_engine` built jagged NestedTensors from sliced views that still referenced the full packed storage, so `unbind()` failed with `split_with_sizes` mismatch. Sequence slices are now `.contiguous()` before `as_nested_tensor`, and CANN logprobs/entropy are flattened contiguous for `reduction="none"`.

AI assistance was used to implement and iterate on this change.

### Test

- CPU: `pytest tests/utils/test_cann_linear_ce_on_cpu.py -q` (policy / gate / chunked CE+H backward helpers; no NPU required)
- NPU (910B / torch_npu with fused linear-CE APIs): `pytest tests/utils/test_cann_linear_ce_on_npu.py -sv` (includes hybrid `dentropy!=0` grad check)
- Enable in training: `actor_rollout_ref.model.use_fused_kernels=True` (works with `entropy_coeff=0` or `!=0`)
- Optional: `VERL_NPU_LCE_BACKEND=auto|cann|triton`, `VERL_NPU_LCE_RETURN_LOGITS=0|1`, `VERL_NPU_LCE_CHUNK_SIZE` (default 2048)
- Training regression: fused actor update after NestedTensor contiguous fix (previously failed in `postprocess_batch_func` / `nt.unbind()`)

### API and Usage Example

```bash
# Launch (NPU)
actor_rollout_ref.model.use_fused_kernels=True
# entropy_coeff may be 0 or non-zero; hybrid backward handles dentropy

# Optional env
export VERL_NPU_LCE_BACKEND=auto   # default: use CANN when APIs exist
# export VERL_NPU_LCE_RETURN_LOGITS=1  # optional metric entropy (less stable on some builds)
# export VERL_NPU_LCE_CHUNK_SIZE=2048  # vocab chunk for hybrid CE+H backward
```

No new Hydra keys. On NPU, `linear_cross_entropy` dispatches to CANN when APIs are available (supports both `npu_*` and older `fused_*` / `*_grad` symbol names).

### Design & Code Changes

- New `verl/utils/kernel/npu/cann_linear_ce.py`: wrap `fused_linear_online_max_sum` + `fused_cross_entropy_loss_with_max_sum` + backward; default memory-saving path (`return_logits=False`); `vocab_end` is half-open `[start, end)`.
- Hybrid backward: CANN CE when `dentropy==0`; chunked PyTorch CE+entropy (`_chunked_ce_entropy_backward`) when `dentropy!=0`.
- `linear_cross_entropy`: on `device.type=="npu"`, prefer CANN; otherwise keep CUDA Triton path unchanged.
- Do not force-disable `use_fused_kernels` when `entropy_coeff!=0` (fused always returns logprobs+entropy; coeff only scales the loss).
- `postprocess_thd_engine` / `postprocess_bshd_engine`: `.contiguous()` on per-sequence slices before `as_nested_tensor` to avoid NPU NestedTensor values/lengths mismatch.
- Tests: CPU policy + chunked CE+H tests; NPU numerical / CE-only and hybrid entropy backward / last-vocab-id regression tests.
