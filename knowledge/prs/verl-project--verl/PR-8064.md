# [rollout, vllm] fix: drop tied-embedding alias in fp8 weight sync

[Upstream PR](https://github.com/verl-project/verl/pull/8064) · state: closed · merged: True

## Original PR description

### What does this PR do?

The quantized (fp8) branch of the async weight sync feeds every bucket straight into `load_quanted_weights`. For a model with `tie_word_embeddings=True` the trainer state dict carries both `model.embed_tokens.weight` and its alias `lm_head.weight`, and the two can land in different buckets. vLLM 0.29 checks skipped aliases per `load_weights` call, so a bucket that carries only the alias fails the check and the first sync aborts:

```
ValueError: 'lm_head.weight' was skipped because it is tied to 'model.embed_tokens.weight' in Qwen3ForCausalLM, but 'model.embed_tokens.weight' was not found in the checkpoint, so the tied weight is uninitialized.
```

The standard (non-quantized) branch already filters the alias through `drop_tied_alias_updates` (#7973); the fp8 branch was left out. This PR applies the same filter there, including the MTP drafter call, and adds a CPU regression test.

Reproduced with Qwen3-0.6B, `actor_rollout_ref.rollout.quantization=fp8`, vLLM 0.29.0: the first weight sync failed before the fix and a 3-step GRPO run completed after it.
