# [megatron,worker] fix: offload actor parameters after disaggregated weight sync

[Upstream PR](https://github.com/verl-project/verl/pull/7631) · state: closed · merged: True

## Original PR description



### What does this PR do?

This PR fixes Megatron actor parameters remaining on GPU after update_weights() in disaggregated mode with a non-naive checkpoint backend. It moves the parameters back to CPU after weight synchronization when parameter offloading is enabled. No API or configuration changes are introduced.

- wuxibin89 · comment · 2026-10-09T09:19:16Z · [source](https://github.com/verl-project/verl/pull/7631#issuecomment-6078074894)

Thanks for the fix. Deferring the offload until `send_weights` has returned successfully is the right call: Megatron bridge exports can alias live parameter storage, so offloading inside the generator (the FSDP-style `finally`) could free storage while a consumer still holds the final bucket. A few suggestions:

**1. We may not need the new `finalize_weight_sync()` API.** The Megatron override only does what the naive path already does inline, so the disaggregated path can reuse the same guard:

```python
if effective_mode != "naive":
    if effective_mode == "delta_sharded":
        metrics = await self.checkpoint_engine.send_weights(self.actor.engine, global_steps=global_steps)
    else:
        per_tensor_param, _ = self.actor.engine.get_per_tensor_param()
        metrics = await self.checkpoint_engine.send_weights(per_tensor_param, global_steps=global_steps)
    if self.actor.engine.is_param_offload_enabled:
        self.actor.engine.to("cpu", model=True, optimizer=False, grad=False)
    return metrics or {}
```

This is safe for every engine, because `to("cpu")` is idempotent when params are already on CPU:
- **Megatron:** `offload_megatron_model_to_cpu` skips buffers whose storage size is already 0.
- **FSDP1:** `flat_param_to(cpu)` on a CPU flat param is a no-op, and the `data_ptr`/size asserts still hold.
- **FSDP2 / VeOmni / Automodel:** `reshard()` + `model.cpu()` are no-ops once the model is resharded and on CPU.
- **FSDP2 with `CPUOffloadPolicy` or `forward_only`:** skipped. `_is_offload_param` is forced to `False` (so `is_param_offload_enabled` is false), and FSDP's `to()` returns early for `forward_only`.

Engines that already offload inside `get_per_tensor_param` (FSDP1, VeOmni, Automodel, TorchTitan) only pay one extra traversal plus `empty_cache()`. The `delta_sharded` path is also fine: `hf_delta_export` refreshes snapshots with `snap.copy_(local)`, so they don't alias param storage.

The parts worth keeping are:
- offloading only after a successful send, not in a `finally`;
- the new `CheckpointEngine.send_weights` docstring contract. NCCL, HCCL, NIXL, Mooncake and Kimi all copy into their own buffers and synchronize before returning, so they already satisfy it.

**2. `tests/workers/engine/megatron/test_weight_sync_offload_on_cpu.py` breaks on current main.** #8051 removed legacy mbridge, so `vanilla_bridge` / `bridge.export_weights` no longer exist. `get_per_tensor_param` now goes through `_mbridge_export_tasks()` + `bridge.export_hf_weights(...)`. Because the test builds the engine with `object.__new__`, it will first fail with `AttributeError: _hf_export_tasks`. GitHub reports the PR as mergeable, but this is a semantic conflict. Please rebase onto main. If you adopt (1), this test can be dropped; the `engine_workers` tests only need the fake engine's `finalize_weight_sync` replaced with `to`. (I traced this by reading the code against main and haven't run it.)

**3. Please fill in the Test section of the PR description.** Concretely:
- **The config where this shows up.** The leak window is only from `update_weights` until the next actor train/eval ctx exits, so it matters when other models (a standalone ref, a critic, a teacher/RM) run on the trainer GPUs before the actor's next phase.
- **Before/after GPU memory numbers.**
