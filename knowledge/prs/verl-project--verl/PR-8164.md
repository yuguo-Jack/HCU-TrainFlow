# [doc, ci] feat: add Ascend tutorial doc translation pipeline

[Upstream PR](https://github.com/verl-project/verl/pull/8164) · state: closed · merged: True

## Original PR description

## 背景

此 PR 添加了一个**跨仓库自动文档翻译工作流**（`schedule_doc_translate_ascend.yaml`），它能自动将 `docs/ascend_tutorial/zh/` 下的中文文档翻译为 `docs/ascend_tutorial/en/` 下的英文文档，并按周计划执行。


## 工作原理

此工作流在 `verl-project/verl` 仓库中运行，并使用**独立的私有 Fork 仓库**来存储翻译工具（Python 翻译引擎、技能/提示文档以及 `.po` 翻译记忆库）。这使得上游仓库保持整洁——它仅接收 `en/` 文档和工作流文件的更改。

**工作流步骤：**

1. **检出（Checkout）** Fork 私有仓库的 `main` 分支（包含 `translate_md.py`、`skill.md`、`.po` 缓存）。
2. **同步（Sync）** Fork 的 `main` 分支与最新的上游 `main` 分支（通过 `git merge`），然后将同步后的 `main` 分支推送回 Fork。
3. **翻译（Translate）** — 运行 `translate_md.py`，将每个中文文档拆分为块，复用 `.po` 文件中的缓存翻译，仅对更改/未翻译的块调用 OpenAI 兼容的 LLM API（默认：Volcengine `glm-5.2`）。
4. **提交翻译记忆库（Commit translation memory）** — 将更新后的 `.po` 缓存提交回 Fork 的 `main` 分支，以便下次运行可以复用缓存翻译并仅对更改的块调用 LLM API（增量翻译）。
5. **创建干净分支（Create clean branch）** — 从 Fork 的 main 分支新建固定名称分支 `auto-pr/doc-translate`，`git rm` 删除 `.po` 缓存、`translate_md.py` 和 `skill.md`，仅暂存 `en/` 文档和工作流文件。
6. **发起跨仓库 PR** — 从 `fork-owner:auto-pr/doc-translate` 向 `verl-project/verl:main` 发起 PR。使用固定分支名 + force-push，若 PR 已存在则更新原 PR，避免重复 PR 堆积。

**安全保障：**

- **故障关闭（Fail-closed）**：如果任何块翻译失败，将跳过整个文档（不提交半翻译的输出）。
- **分支安全（Branch safety）**：仅暂存 `docs/ascend_tutorial/en/` 和 `.github/workflows/` 路径；PR 中绝不会出现 `.po`、`.py` 或 `skill.md` 文件。
- **增量翻译（Incremental）**：基于 Git Blob ID 的块级 `.po` 翻译记忆库，实现了高效的增量重翻译——只有源文档发生变更时才会触发 API 调用。

## 必要配置

**仓库变量**（在 `verl-project/verl` 中设置）：

| 变量 | 描述 |
|----------|-------------|
| `FORK_REPO` | 包含翻译工具的私有 Fork 仓库（例如 `my-org/verl-translation-fork`） |

**仓库密钥**（在 `verl-project/verl` 中设置）：

| 密钥 | 描述 |
|--------|-------------|
| `FORK_TOKEN` | 对 Fork 仓库具有 `contents:write` 权限的 PAT |
| `TRANSLATION_ASCEND` | LLM API 密钥（Volcengine `glm-5.2`，主要） |
| `LLM_API_KEY` | LLM API 密钥（通过工作流调度覆盖 `api_base`/`model` 时使用） |
