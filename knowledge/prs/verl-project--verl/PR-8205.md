# [fsdp] fix: use current compressed-tensors API for QAT export

[Upstream PR](https://github.com/verl-project/verl/pull/8205) · state: open · merged: False

## Original PR description

### What does this PR do?

FSDP NVFP4 QAT weight export fails with the compressed-tensors versions in the current lockfile (0.17 and 0.18). `QATQuantizer` imports the removed `compressors.quantized_compressors.fp4_quantized` module and calls the removed `compress_weight` method when the engine exports rollout weights.

Import the compressor from its public namespace and pass the existing weight, block scale, and global scale through `compress(state_dict, QuantizationScheme)`. Preserve the streamed output names, scale fusion, passthrough weights, and W4A4 input scales.

### Checklist Before Starting

- [x] Checked [NVFP4 compressor PRs](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+NVFP4+compressor) and [QAT compressed-tensors PRs](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+QAT+compressed-tensors). No matching fix found. Closed #6815 concerned an older installation stack; this change targets the current locked dependencies. #6992 concerns W4A8 simulation and #7895 concerns Megatron MXFP4.
- [x] Title follows the module/type convention.

### Test

```bash
python -m pytest tests/utils/test_qat_quantizer.py -q
pre-commit run --all-files --show-diff-on-failure
```

On RTX 5090 with PyTorch 2.13.0+cu130, the new tests pass with compressed-tensors 0.17.0 and 0.18.0: **12 passed per version**. Unmodified main fails to import the quantizer with both versions.

The regression covers FP32/FP16/BF16 weights, W4A16/W4A4, CPU/GPU destinations, multiple decoder layers, QKV/GateUp scale fusion, zero blocks, excluded weights, exact source preservation, and actual packed-weight decompression against an independent E2M1 rounding reference.

Additional local integration checks use a real two-rank FSDP2 QAT engine and a locally constructed tiny Qwen2. Both dependency versions pass with CPU offload on/off: two training steps, export after each step, all seven projections packed and decompressed, source parameters preserved exactly, and exported weights updated after the next optimizer step. These validate the training/export path; they do not run a vLLM generation workload.

### API and Usage Example

No configuration change. Existing FSDP NVFP4 QAT rollout-weight export uses the current compressor API.
