# [ckpt] feat: expose Hugging Face export kwargs

[Upstream PR](https://github.com/verl-project/verl/pull/7997) · state: closed · merged: False

## Original PR description

### What does this PR do?

When using verl, we needed to customize the exported safetensor shard size (e.g., saving in 5GB shards), but verl provided no configuration seam for HF transformers `save_pretrained` in the checkpoint manager. Rather than add a one-off shard-size field, this PR exposes the kwargs mapping so users can compose any HF transformers `save_pretrained` customization supported by their installed Transformers version.

Expose an optional `hf_save_pretrained_kwargs` mapping for Hugging Face model exports written by `FSDPCheckpointManager`. The mapping is forwarded directly to Transformers [`PreTrainedModel.save_pretrained`](https://github.com/huggingface/transformers/blob/main/src/transformers/modeling_utils.py#L3235-L3248). When it is `null`, verl forwards no extra keyword arguments and preserves the installed Transformers defaults; `max_shard_size` is the motivating example rather than a special verl field.

This applies only to in-training `hf_model` exports through `FSDPCheckpointManager` (FSDP and VeOmni). Standalone `verl.model_merger` is out of scope because it has its own CLI and `ModelMergerConfig`; Megatron merger exports use a separate sharding path and are unchanged.

Related issues #298 and #533 document demand for deployable Hugging Face checkpoints. This does not duplicate #1288, which added direct FSDP Hugging Face export but did not expose `save_pretrained` kwargs. The open-PR searches found no other PR adding this general configuration seam.

Fixes one part of https://github.com/verl-project/verl/issues/8027

### API and Usage Example

`hf_save_pretrained_kwargs` is consumed only when the checkpoint includes an `hf_model` export. For example:

```bash
# PPO actor, with either the FSDP or VeOmni engine
actor_rollout_ref.actor.checkpoint.hf_save_pretrained_kwargs='{max_shard_size:5GB}'

# SFT, with engine=fsdp or engine=veomni
checkpoint.hf_save_pretrained_kwargs='{max_shard_size:5GB}'
```

The critic YAML intentionally omits this field because standalone HF critic exports are uncommon; opt in with `+critic.checkpoint.hf_save_pretrained_kwargs='{max_shard_size:5GB}'`.

When `hf_save_pretrained_kwargs` is `null`, verl passes no extra arguments to `save_pretrained`; otherwise it forwards the configured mapping unchanged.

### Test

Six 8-GPU training runs with `Qwen/Qwen3-8B` verified `hf_save_pretrained_kwargs=null` and the `max_shard_size:5GB` override across FSDP actor, SFT, and VeOmni actor. Each export contains FP32 tensors (the current default), has the expected `8,190,735,360` parameters, and reloads through Transformers:

| Path | Export dtype | Default | `5GB` | HF reload |
|---|---|---:|---:|---|
| FSDP actor | FP32 (default) | 1 file | 7 shards | Passed |
| SFT | FP32 (default) | 1 file | 7 shards | Passed |
| VeOmni actor | FP32 (default) | 1 file | 7 shards | Passed |
