# [fsdp, veomni, ckpt] feat: use get_per_tensor_param to save hf format checkpoint

[Upstream PR](https://github.com/verl-project/verl/pull/8171) · state: closed · merged: True

## Original PR description

### What does this PR do?

Save the `hf_model` checkpoint content for the FSDP and VeOmni engines by streaming weights from the engine's `get_per_tensor_param` (the same path used for rollout weight sync) into safetensors shards on rank 0, instead of gathering a full state dict to CPU and re-instantiating an HF model via `AutoModel.from_config` + `save_pretrained`.

Benefits:

- Host memory peaks at roughly one shard (5 GB) instead of the whole model, so models larger than host memory can be exported.
- No dependency on mapping `architectures` to an `AutoModel*` class, so any model the engine can sync to rollout can be exported (including VeOmni models with custom checkpoint tensor converters, e.g. FP8 export).
- Exported names follow the HF checkpoint format via `get_per_tensor_param`, so names stay consistent with what rollout loads.

Related: #8019 (configure HF export dtype) and #7997 (expose HF export kwargs) tweak the existing `save_pretrained` path; this PR replaces that path entirely, so it is not a duplicate.

### Design & Code Changes

- `FSDPCheckpointManager`
  - New args `per_tensor_param_fn` (required when `hf_model` is saved) and `hf_export_dtype`.
  - `_save_hf_weights_from_per_tensor_param`: every rank drains the generator (it issues collectives); rank 0 copies each tensor to CPU, packs safetensors shards up to 5 GB, writes them as `.tmp` files and renames them to `model-XXXXX-of-YYYYY.safetensors` with a `model.safetensors.index.json` at the end.
  - Tied aliases (e.g. `lm_head.weight` when tied) are skipped, since HF re-ties them on load.
  - fp32 parameters are narrowed to `hf_export_dtype` (the mixed-precision `param_dtype`), except buffers and parameters of modules excluded from mixed precision, which the forward uses unconverted. The saved `config.json` (and sub-configs) records `hf_export_dtype` as `dtype`.
- `FSDPEngine`: passes `get_per_tensor_param` and `_autocast_dtype`; raises `NotImplementedError` if `hf_model` is saved with LoRA or QAT.
- `VeOmniEngine`: passes `get_per_tensor_param`; uses the mixed-precision `param_dtype` as export dtype unless the model's checkpoint tensor converter defines `export_weights` (it then picks its own dtypes, e.g. FP8 weights with FP32 scales).
- `docs/examples/config.rst`: document the new behavior and the LoRA/QAT limitation.
