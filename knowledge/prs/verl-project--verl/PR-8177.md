# [fsdp] fix: copy offloaded shards in fsdp2_sharded_save_to_cpu

[Upstream PR](https://github.com/verl-project/verl/pull/8177) · state: closed · merged: True

## Original PR description

### What does this PR do?

Fix `fsdp2_sharded_save_to_cpu` when `param_offload=True` in the fully async trainer.

With offload on, the local shards are already on CPU, so `.detach().cpu()` returns a tensor that shares memory with the live shard, not a copy. In `FullyAsyncTrainer._compute_old_log_prob`, `restore_model_from_cpu(1)` then also overwrites the snapshot from `save_model_to_cpu(k)`, and `restore_model_from_cpu(k)` brings back the weights from the start of the sync window instead of the current ones. As a result, every local step trains again from the weights at the start of the window. A sign of this is a PPO ratio of exactly 1, so actor/ppo_kl and actor/pg_clipfrac are exactly 0.

This PR makes a real copy with `.to("cpu", copy=True)`, the same method that the FSDP1 helper `fsdp1_sharded_save_to_cpu` from #7306 uses, and adds a CPU unit test for it.
