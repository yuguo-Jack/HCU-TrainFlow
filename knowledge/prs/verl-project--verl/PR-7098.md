# [utils] Remove hardware dispatch from attention padding helpers

[Upstream PR](https://github.com/verl-project/verl/pull/7098) · state: closed · merged: False

## Original PR description

## What does this PR do?

Removes hardware-dependent dispatch from `verl.utils.attention_utils` and makes the existing pure PyTorch/einops padding helpers the shared implementation on every PyTorch device. The redundant `npu_flash_attn_utils.py` copy is removed.

The public index helpers also normalize indices to `torch.int64`, so direct callers can safely pass either `int32` or `int64` indices to gather/scatter/indexing operations.

## Why this approach?

The NPU implementation was already copied from flash-attn and only uses PyTorch and einops, so selecting it based on available hardware was unnecessary.

I did not directly replace it with Transformers' private `_index_first_axis`. That helper merges the first two input dimensions, whereas verl and flash-attn expect the input to already be flattened along the first dimension. Direct replacement would silently turn an `(N, 1)` result into `(N,)`.

The shared implementation retains the existing verl/flash-attn shape, metadata, and gradient semantics.

## Duplicate-work check

Before implementation and again before the latest update, I checked issue #7088 and searched open PRs by the issue number and by `attention_utils`, `index_first_axis`, `pad_input`, and `npu_flash_attn_utils`. No overlapping implementation was found. Draft PR #7172 explicitly depends on this PR and is downstream work.

Closes #7088.

## Code Review

This pull request refactors `verl/utils/attention_utils.py` to replace the dynamic device-specific dispatching with a unified, device-agnostic implementation using PyTorch and einops. It also adds CPU-based unit tests for these attention utility functions. The code review identified critical compatibility issues in the new implementation: `torch.gather` and `torch.scatter_` require `int64` indices and will fail if `int32` tensors are passed, and using the `+` operator on boolean masks will raise a runtime error in PyTorch and should be replaced with the bitwise OR `|` operator.

In PyTorch, `torch.gather` strictly requires the `index` tensor to be of type `torch.int64` (`LongTensor`). If `indices` is passed as `torch.int32` (which is very common in optimized attention/padding pipelines to save memory), this will result in a runtime `RuntimeError: gather(): Expected dtype int64 for index`.

To prevent this, cast `indices` to `.long()` before repeating and gathering.

```suggestion
        return torch.gather(
            rearrange(input, "b ... -> b (...)"),
            0,
            repeat(indices.long(), "z -> z d", d=second_dim),
        ).reshape(-1, *other_shape)
```

Similarly to the forward pass, `torch.scatter_` strictly requires the `index` tensor to be of type `torch.int64` (`LongTensor`). If `indices` is `torch.int32`, this will raise a runtime `RuntimeError: scatter(): Expected dtype int64 for index`.

Cast `indices` to `.long()` to ensure compatibility with `int32` index tensors.

```suggestion
        grad_input.scatter_(0, repeat(indices.long(), "z -> z d", d=grad_output.shape[1]), grad_output)
```

- gemini-code-assist · comment · 2026-07-19T09:17:59Z · [source](https://github.com/verl-project/verl/pull/7098#discussion_r3610277719)

File: `verl/utils/attention_utils.py` · line 83

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

Using the `+` operator on boolean tensors is not supported in PyTorch and will raise a `RuntimeError: Addition, the '+' operator, with two bool tensors is not supported. Use the '|' operator or torch.logical_or() instead.`.

Since `attention_mask` and `unused_mask` are commonly boolean tensors in LLM pipelines, you should use the bitwise OR operator `|` (or `torch.logical_or`) instead of `+`. This is fully compatible with both boolean and integer tensors.

```suggestion
    all_masks = (attention_mask | unused_mask) if unused_mask is not None else attention_mask
```
