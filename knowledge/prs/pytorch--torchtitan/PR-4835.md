# [Deepseek V4] Dsv4 sparse indexer loss

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4835) · state: open · merged: False

## Original PR description

## Summary

Add DeepSeek V4 sparse indexer auxiliary loss for CSA layers.

This change wires the community `AuxLoss` framework into DeepSeek V4 compressed sparse attention so the sparse indexer can be trained from the main attention distribution. The loss is implemented as `SparseIndexerLoss` under `deepseek_v4/compressor.py` and is configured only for `compress_ratio == 4` CSA layers.

## Changes

- Add `SparseIndexerLoss(AuxLoss)` for indexer distillation.
- Update `Indexer.select(...)` to return both:
  - `topk_indices`
  - differentiable `topk_scores`
- Inject indexer loss through FlexAttention `out_transform`, using attention LSE as teacher normalization.
- Keep teacher tensors detached while preserving gradient through indexer scores.
- Register `register_aux_loss_zero_hook` in the DeepSeek V4 optimizer post-build hook.
- Add unit coverage for loss value/gradient/metric accumulation, DSV4 config wiring, and `Indexer.select(...)`.

**Overall:** The design fits the existing framework: it hooks into `out_transform` to get the LSE and uses `AuxLoss.inject` with `out` as the carrier. I checked the `select` rewrite: it picks the same entries as before. Valid scores keep their order, and masked slots still end up as `-1`. So the main-loss selection should be bit-identical. It would still be good to confirm that with a `--debug.deterministic` loss comparison.

### 🔴 1. The result depends on the TP degree: gradient is scaled by `tp` and the metric isn't reduced over TP

`attention.py:248` / `compressor.py:264`

- `q` goes into the inner attention as `tp=S(1)` (`sharding.py:73`), and so does `lse`. So `_teacher` computes `(...).sum(dim=1) / q_THK.size(1)` using only the **local** heads, divided by the **local** head count.
- Each TP rank therefore gets a different teacher `p_TJ`.
- The student (`idx_q/idx_k/idx_w`, `sharding.py:84-86`) and the indexer weights (`sharding.py:183-189`) are `tp=R`. Their backward is Partial, so the per-rank gradients get summed over TP.
- The gradient term `-p · log_softmax(s)` is linear in `p`. Summing it over TP ranks gives `tp ×` the gradient you would get from the teacher averaged over all heads.
- So the effective `coeff` grows with the TP degree. With `tp=2` in your smoke test, the effective coefficient was 0.02.
- If these gradients are *not* summed on some path, the problem is worse: the replicated indexer weights drift apart across TP ranks without any error.
- The logged metric has the same issue. `reduce_mesh="loss"` reduces over dp+cp only, so each TP rank logs its own local-head value.

Suggested fix: divide by the **global** `n_heads` (pass it in `SparseIndexerLoss.Config`) instead of `q_THK.size(1)`. Then the per-rank partial teachers add up to the global teacher, and the summed gradient is exact. For the metric, the `xlogy(p, t)` term isn't linear, so it needs an explicit TP reduction, or you could all-reduce `p_TJ` (small: T×J fp32, no grad) before computing the loss.

Please also add a test that checks `tp=1` and `tp=2` give the same indexer gradient (for example in the fake-pg suite). The CLAUDE.md rules ask for this for distributed changes.

### 🔴 2. `Indexer.select` now keeps a T×H_idx×N score tensor alive until backward

`compressor.py:208-222`

Before this PR, the `sht` scores tensor was dropped as soon as `topk` returned its indices. Now `topk_scores` is kept in the autograd graph, so the full `einsum`, `relu` and `* idx_w` intermediates are saved for backward.

For the 284B-A13B config (`index_n_heads=64`, ratio 4) at T=8192 per rank, that is 8192 × 64 × 2048 ≈ 1.07e9 elements. That's about 2 GiB in bf16 per saved tensor, several saved tensors per layer, across 21 CSA layers. It also grows as O(T²), even though only `topk` of the N columns ever get a gradient.

Suggested approach: do the selection under `torch.no_grad()` (and put back the in-place `relu_`). Then recompute the student scores only for the selected entries: gather `idx_k[topk_indices]` to get `[T, J, D]`, then `einsum("thd,tjd->thj")`, `relu`, `* w`, and sum over `h`. That costs O(T·H·J) with a fixed J=`index_topk`, and it keeps the eval and no-loss paths exactly as cheap as before.

The second commit folded the scoring into `select`. I'd undo that and use a separate gather-based `score(...)` step.

### 🟡 3. The teacher needs a lot of temporary memory, and one step isn't in fp32 as the comment says

`compressor.py:256-262`

- `cmp_k_NK[topk_indices_TJ]` builds a `[T, J, head_dim=512]` tensor. At T=8192 and J=512 that's about 4 GiB in bf16.
- `logits_THJ` in fp32 adds about 1 GiB (with 64 heads per rank).
- Nothing is saved for backward, but it's a large per-layer peak. Under FullAC/SAC the whole block is re-run in backward, so this cost is paid twice.
- Consider chunking over T.
- Precision: `einsum(...).float()` runs the matmul in bf16 and only casts the result. The comment says the computation is in fp32 to protect `exp(comp_lse - lse)`, but these logits have already lost precision in bf16. Cast `q`/`cmp_k` to fp32 before the einsum, or pass `dtype`/accumulate in fp32.

### 🟡 4. The test compares the implementation to a copy of itself

`test_deepseek_v4_indexer_loss.py:21-53` copies `_teacher` and `_logged_kl` line for line. That checks the plumbing but not the math.

It would be much stronger to build a small dense case and compare against it. Compute the full softmax over `[swa | cmp | sink]` by hand with the sink logit, sum the probabilities per head on the selected compressed entries, and take the lse from a real `flex_attention(return_aux=AuxRequest(lse=True))` call. That checks two assumptions nothing currently tests: that flex returns the LSE in natural log (not log2), and that the sink and SWA entries are really in the denominator.

### 🟡 5. Please explain why the loss is weighted by mass

`SparseIndexerLoss` weights each row by the raw mass `p` (not the normalized `t`), so rows dominated by SWA or the sink contribute little. DSA in V3.2 uses KL against the L1-normalized head-summed attention. If V4 changed this, please cite the source in the docstring. If it's your own choice, please show convergence evidence (for example a C4 run of indexer recall / main loss vs. the unweighted KL). CLAUDE.md asks for this for computation changes.

### 🟢 Smaller items

- **`__init__.py:1032`**: `_post_optimizer_build_fn` is an exact copy of `deepseek_v3/__init__.py:692`. DSV4 already imports from `deepseek_v3`, so reuse that one, or move it to common code.

### Compatibility with #4452

I couldn't open #4452 in this run: `gh` and web fetch both need permission I don't have. So this part is based on the extension points documented in this PR's `DSV4FlexInnerAttention` docstring, not on the other PR's code. The risk depends on what #4452 changes:

- **Replacing `_build_block_mask` only (e.g. a faster mask or varlen kernel):** compatible. The loss only needs `out` and `lse` from the same softmax.
- **Overriding `forward` / `_forward_impl` with a fused sparse kernel (SMLA/CSA):** the loss would be **dropped with no warning**. It is only wired up through `FlexInnerAttention.forward(out_transform=...)` inside `_forward_impl`. To make both work, the fused kernel has to return the LSE, and the loss has to be triggered from a small shared helper (e.g. `self._maybe_inject_indexer_loss(out, lse, q, cmp_k, cmp_topk, topk_scores)`) that any backend can call, instead of from the flex call site.
- **Fused top-k or indexer kernel (index-only output):** this conflicts with the new `(indices, scores)` return type of `Indexer.select`. The gather-and-recompute design from item 2 separates the two steps: a fused kernel can do the no-grad selection, and the small gathered rescoring gives the student scores. I'd recommend that design anyway because of the memory issue.
- **CP all-gather of `cmp_k`/`idx_k`:** compatible, and it would make the teacher correct under CP. The teacher gathers from whatever `cmp_k` it gets, so a global `cmp_k` is handled correctly.

If you share the key change in #4452 (kernel swap vs. mask or indexer optimization), I can give a precise answer.

### 🔴 1. The gradient still scales with the TP degree (still open)

`compressor.py` `_teacher`, last line: `... .sum(dim=1) / q_THD.size(1)`

Inside the CSA inner attention, `q` is `tp=S(1)` (`sharding.py:70`), and so is `attn_sink` (`sharding.py:29`). So each TP rank builds its teacher `p_TK` from its **local** heads, divided by the **local** head count. The student inputs `idx_q/idx_k/idx_w` are `tp=R` (`sharding.py:81-83`), so their gradients are summed over TP. The loss is linear in `p`, so the summed gradient is `tp ×` the gradient for the head-averaged teacher. In effect, `coeff` becomes `0.01 * tp`.

The logged metric has the same problem, and it is worse there: `xlogy(p, t)` is not linear, and `reduce_mesh="loss"` doesn't reduce over TP.

Suggested fix: divide by the global `n_heads` (add it to `SparseIndexerLoss.Config` and set it in `_make_v4_attn_config`). Then the per-rank partial teachers add up exactly to the global teacher. An all-reduce of `p_TK` over TP before computing `t_TK` and the metric fixes both problems at once, and it's cheap (T×K fp32, no grad). Please add a check that `tp=1` and `tp=2` give the same indexer gradient (fake-pg would work, since this PR already has `ciflow/fake-pg`).

### 🔴 2. The teacher's softmax denominator is rebuilt by hand, and nothing checks it against `gather_attn`

`compressor.py` `_window_logits` / `_teacher`

`mass_TH = exp(cmp_lse - logsumexp([window_lse, cmp_lse, sink]))` is only correct if three things match `gather_attn` exactly:

- **Window semantics:** keys `t-W+1 .. t`, inclusive of the query, with exactly `W` entries.
- **Sink semantics:** the sink is a logit in the denominator only, not scaled by `softmax_scale`.
- **Overlap:** the SWA keys and compressed keys don't overlap or get deduplicated.

If any of these is off by one (for example, the window is `W+1` wide or excludes self), the loss trains toward the wrong target, and nothing will warn you. The test can't catch it, because `_reference_teacher` uses the same formula.

The cheapest strong check: in the test, rebuild the attention output from the teacher's per-head probabilities (`softmax([swa | cmp | sink])` · V) and `assert_close` it against `gather_attn(..., impl="reference")` on the same inputs, including a packed `cu_seqlens` case. If `gather_attn` can return its LSE, use that LSE directly in the loss. That also removes the duplicated window and denominator work (see item 3).

### 🟡 3. The teacher needs a lot of temporary memory and computes logits in bf16

The new `_window_logits` builds `swa_k_TD[key_TW]` → `[T, W, 512]`, on top of the existing `cmp_k_SD[gather]` → `[T, K, 512]`. At T=8192, W=128, K=512 that is about 1 GiB + 4 GiB in bf16, plus `[T, H_local, W+K]` fp32 logits, on each of the 21 CSA layers. Under FullAC the whole thing runs again in backward.

Neither einsum can use `einsum("thd,tkd->thk")` as a matmul without first materializing the gathered keys. Consider chunking over T, or using `gather_attn`'s LSE as in item 2.

`einsum(...).float()` still runs the matmul in bf16 and only casts the result. Cast the inputs to fp32 (or chunk and then cast) if the precision of `exp(cmp_lse - full_lse)` matters.

### 🟡 4. Padded tokens add to `raw_sum` but are excluded from the denominator

`aux_loss_denominator` is the routed-token count, which excludes padding (`collators.py:113`, built from `padding_mask`). `SparseIndexerLoss` sums over all T, including padding positions. Padding blocks get their own `cu_seqlens` segment, so their teacher is finite and non-zero. The result: the loss scale depends on how much padding there is, and the indexer is trained on padding attention.

Pass `padding_mask` down (the block already has it) and mask those rows out of `slot_valid_TK`.

### 🟡 5. Please explain why the loss is weighted by mass (still open)

`weighted = xlogy(p, t) - p * log s` is a KL weighted by the raw compressed mass. DSA in V3.2 uses an unweighted KL against the L1-normalized, head-summed attention. Please cite the V4 source in the docstring, or show convergence evidence (CLAUDE.md asks for this for computation changes).

Consider returning global gather indices from `select`, or sharing one helper that takes `ratio`.

### 🔴 1. The TP-equivalence GPU test is skipped in CI

`tests/unit_tests/gpu/test_deepseek_v4_indexer_loss.py:22`

`unit_test_gpu.yaml` runs `pytest tests/unit_tests/gpu -m "not multi_gpu"` on the single-GPU runner and `-m multi_gpu` on the multi-GPU runner. This test has no `multi_gpu` marker, so:

- On the single-GPU lane, `skipUnless(device_count() >= 2)` skips it.
- The multi-GPU lane never selects it.

So the one test that checks the TP fix never runs. Add `pytestmark = pytest.mark.multi_gpu`, as `test_mxfp8_fsdp.py` and `test_fsdp_moe_sharding.py` do.

There is also a smaller gap. The test runs the inner module without its `ShardingConfig`, and it does `dist.all_reduce(tensor.grad)` itself to stand in for the TP gradient sum. So it checks the loss math, not that the real model sums the `idx_*` gradients over TP. A `tp=1` vs `tp=2` loss/grad_norm comparison on the debug model (fake-pg, or `scripts/loss_compare.py`) would cover the actual wiring.

### 🟡 2. The default objective differs from the paper and has no evidence

`compressor.py` `SparseIndexerLoss.Config.mass_weighted: bool = True`, and `flavors.py` `indexer_loss_mass_weighted: bool = True`

The docstring now says mass weighting is "not a claim about the paper's objective". Even so, every DSV4 run gets it by default.

Under CLAUDE.md, a computation change needs convergence evidence. Either:

- default to `False` (the V3.2 normalized KL), or
- attach a C4 run comparing the two (main loss plus indexer recall / KL) to justify `True`.

The PR description also still has no `--debug.deterministic` loss comparison. That comparison should show the main loss is bit-identical before and after with `indexer_loss_coeff=0`, which checks the new `no_grad` selection and `return_aux` path. A second, short convergence run with the loss on would also help.

### 🟡 3. The student rescoring keeps about 2 GiB per CSA layer alive for backward

`compressor.py` `Indexer.select`, the `return_scores` branch

The teacher is now chunked, but the student is not:

- `selected_TKD = idx_k[gather_indices_TK]` (`[T, K, D_idx]`) and the `[T, H_idx, K]` relu/mul intermediates are all saved for backward.
- For the 284B config at T=8192 (H_idx=64, D_idx=128, K=512), that is about 1 GiB for the gathered keys plus about 0.5 to 1 GiB of logits intermediates, per CSA layer, in bf16.
- With 21 CSA layers and no AC, that adds tens of GiB.

This is much better than the original O(T·H·N), and AC hides most of it. Still, a small custom `autograd.Function` would avoid saving the gathered `[T, K, D]` tensor. It would save `idx_q`, `idx_k`, `idx_w` and the indices, then re-gather in backward. Chunking the rescoring over T would also work. Fine as a follow-up TODO.

### 🟢 Smaller items

- **`compressor.py` `_teacher`:** use `MeshAxisName.TP` instead of the string `"tp"` in `spmd_mesh_size` / `spmd_mesh_group`, to match the rest of the DSV4 code.
- **`compressor.py` `_teacher`:** the head-count check raises `ValueError`. But `num_heads` comes from `n_heads` in `_make_v4_attn_config`, so a mismatch means a programmer error. CLAUDE.md says to use `assert` for that.
- **`Indexer.select(..., return_scores: bool = True)`:** the default builds the autograd graph. The only caller passes the flag explicitly, so a default of `False` (or making the argument required) would keep a future caller from paying this cost by accident.
- **`flavors.py` `build_model_config`:** `indexer_loss_chunk_size <= 0` is checked here and again in `SparseIndexerLoss.Config.__post_init__`, which `dataclasses.replace` re-runs. The `coeff=0.01` default is also set in two places (`_make_v4_attn_config` and the `build_model_config` default). Keep one of each.
- **`SparseIndexerLoss.forward`:** returning early on `numel() == 0` is safe under TP, because every rank has the same shape and so they all skip the all-reduce together.
