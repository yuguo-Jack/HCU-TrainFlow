# [distmuon] Isolate redistribution NCCL communicators

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5183) · state: open · merged: False

## Original PR description

## Summary

- add an opt-in `redistribution_max_ctas` setting for DistMuon
- run optimizer redistribution on cached, resource-independent NCCL child process groups
- keep FSDP on its original communicator and default channel policy
- configure the Kimi K3 DistMuon recipe to use eight redistribution CTAs

## Why

DistMuon uses all-to-all redistribution. Letting that traffic initialize on the FSDP communicator can create direct peer/channel connection state for the whole group. Reducing channels globally would also constrain FSDP collectives. A dedicated child communicator lets DistMuon cap only its redistribution concurrency while preserving FSDP behavior. The option defaults to `None`, so existing users are unchanged.

For a 64-rank all-peer group with 12 MiB of measured connection storage per peer/channel pair, reducing 32 channels to 8 changes the fan-out estimate from 23.625 GiB to 5.906 GiB per rank.
