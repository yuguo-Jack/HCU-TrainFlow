# [rl] hold each multi-turn session's KV between its turns (5/5)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5220) · state: open · merged: False

## Original PR description

**TLDR:** opt-in `VLLMGenerator.Config.hold_session_kv`. vLLM holds each multi-turn session's reusable prefix between its turns, so no other request can evict it. When memory runs short, it releases whole idle sessions, oldest first. It also covers hybrid models (Qwen3.5). On vLLM's real KV manager, a next turn after full churn hits 48 of 50 prompt tokens with the hold and 0 without; on GPU the gain under memory pressure is unmeasured, so this is headroom.

**Problem**
1. A multi-turn rollout re-sends its whole history every turn. vLLM skips recomputing it only while the history is still cached.
2. When a turn finishes, its blocks become "free but cached", and any new request can take them.
3. For a hybrid model, a continuation also needs the Gated-DeltaNet state saved at the previous prompt's end. vLLM's "align" mode hands that block back to the free pool as soon as decode starts, ~1-3 min before the turn ends.
4. Under load, the turn's next call misses and recomputes its whole history. A CPU probe on vLLM's real KV manager: hold at finish -> 0 tokens hit after churn; hold right after prefill -> full hit.

**Solution**
1. `SessionKVHolder` (`torchtitan/rl/session_kv_holder.py`):
   - Right after a request's prefill, hold the blocks vLLM's own prefix lookup says a continuation would hit: attention plus the matching GDN state blocks (`block_pool.touch`).
   - The session's next prefill takes a new hold, then drops the old one.
2. Release:
   - when the rollout ends (`release_session`, which the router forwards to the generator the session is pinned to; without sticky routing, at group end);
   - at group end (`release_groups`);
   - when fewer than `session_kv_free_floor` blocks are free: sessions idle longest first, including those whose next request is still waiting (it references none of its blocks yet, so the cost is at most a recompute); only sessions with a running request are skipped. Skipping waiting ones too livelocked a full engine in an admission simulation.
3. Releases ride the engine-loop decision that every rank receives, so all TP ranks apply them at the same point.
4. Held blocks count in vLLM's KV usage, and the watermark keeps headroom for running requests. Config checks: `session_kv_free_floor` > vLLM's `watermark` (`extra_vllm_engine_args`, default 0.0); incompatible with `reset_kv_cache_on_weight_sync`.
5. Off by default.

**Results**
```
GB300, 35B-A3B chess self-play, hold_session_kv on (floor 0.05, watermark 0.03), steps 2-6:
  sessions held per generator    126-252
  released by the free floor     0
  prefix hit                     93-96%
  KV use                         52-66%
A run without the hold had the same prefix hit (93-96%): with KV use under ~66%, little was evicted either way.

CPU (vLLM KVCacheManager, 1 attention + 3 Mamba align groups):
  next turn hits 48/50 prompt tokens after full churn with the hold, 0 without
```
The GB300 run also used a KV admission gate that is not in this stack, and its releases went to the generator that gate placed the group on.

You may ask: why hold right after prefill, not when the request finishes? The GDN state block leaves the request when decode starts, and under load a freed block survives ~78 s (estimate) while a turn decodes for ~1-3 min.

NOTE:
- The hold may take an older duplicate of a block that the request also owns, about one extra block per session while it decodes.
- Asserts no partial hash hits and no speculative decoding, since both move the replay point.
- After any re-pin (opt-in `repin_load_ratio`, or an LRU eviction), the session's hold on its old generator is freed at group end or by the free floor.
- Hybrid models likely need TP=1: with TP>1 vLLM hashes finer than the Mamba block (partial-block hits), which generator init asserts against. Not verified on GPU.
- Not run on GPU with this branch. The GB300 run used a different router release path and never reached the free floor.
