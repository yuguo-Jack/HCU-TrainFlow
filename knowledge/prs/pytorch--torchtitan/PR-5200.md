# [dsv4][perf] Compile the Compressor's pooling (compressor region)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5200) · state: open · merged: False

## Original PR description

**TLDR:** Compile the Compressor's post-GEMM pooling as the `compressor` region: 16k step -1.9%.

**Problem**
1. **Compressor.** After its projections, it gathers each document's groups of tokens.
2. **Overlap.** It appends overlap candidates with two cats.
3. **Pool.** Then it softmax-pools, normalizes and rotates them.
4. **Cost.** About 30 eager kernels per call; 1.5 ms of the 76.4 ms step at 16k goes away (Results).

**Solution**
1. **Region.** The post-GEMM path becomes `Compressor._pool` (`compressor` region).
2. **Metadata stays eager.** Group boundaries are computed outside the region.
3. **One graph per compressor.** The group dim is marked dynamic, so CSA, Indexer and HCA each use one graph per grad mode.
4. **Unchanged:** the projections and the math.

```text
before:  wkv/wgate -> gather groups -> cat, cat -> softmax pool -> norm -> rotate   (~30 eager kernels)
after:   wkv/wgate -> [Compressor._pool]                                          (one region)
```

**Results**
```text
DeepSeek-V4 Flash layers 4+5, fwd+bwd wall, 1x GB300, FA4, median of fresh processes within 1% of best
measured with #5157's moe_dispatch_combine applied (it sat before this PR in the original stack)
16k   76.40 -> 74.93 ms  (-1.9%)
4k    32.77 -> 32.00 ms  (-2.3%)
correctness: compiled vs eager rel L2 < 1e-2 per tensor, packed and unpacked, ratio 4 and 128
graphs: Compressor._pool 6 (3 compressors x 2 grad modes) over training 4k/16k/2k + no_grad (limit 8)
```

NOTE: reaches DeepSeek-V4 CSA and HCA layers.
NOTE: not yet measured under CUDA graphs. Not tested: loss curve, multi-GPU.

**Test plan**
`pytest tests/unit_tests/gpu/test_deepseek_v4_compressor_compile.py`

Stack: 6 of 7. Branch `felipemello1/lcp/dsv4-6-compressor-pool`.
