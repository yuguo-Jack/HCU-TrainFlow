# [kimi_k3][perf] Compile the attention residual with a hand-written backward

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5156) · state: open · merged: False

## Original PR description

**TLDR:** Kimi K3's attention residual becomes one autograd Function with compiled fwd and bwd regions: 16k step 304.6 -> 220.0 ms (-27.8%), peak 73.5 -> 51.7 GB.

**Problem**
1. **What it does.** Each layer mixes a stack of N earlier block outputs with the current partial sum (2 calls per layer, plus the output).
2. **Concat + upcast.** Eager concatenates stack and partial into `[T, N+1, D]` and upcasts it to fp32.
3. **fp32 GEMV.** It then reduces that fp32 copy with a GEMV, and autograd saves the big intermediates.
4. **Cost.** ~100 ms of the 305 ms 2-layer step at 16k tokens.

**Solution**
1. **One Function.** `attention_residual` is an autograd Function; its forward and backward are separate compile regions.
2. **No concat, no fp32 copy.** Stack entries and the partial block are scored separately.
3. **One kernel for any width.** The forward always sums 8 entry slots; slots past the real width read the last entry with weight 0, so the symbolic width (as in production) still lowers to one pointwise kernel.
4. **Small saved state.** The hand-written backward saves only `[T, N+1]` fp32 probs/scores/rstd. Its weight grad is one GEMM on the bf16 rows, with the fp32 coefficients split into three exact bf16 pieces by bit masking (Inductor would remove a bf16 round trip).
5. **One graph for training and `no_grad`.** Inputs are detached before the compiled forward (requires_grad is part of the guards).
6. **Unchanged.** Call sites: a block's first layer passes (previous stack, partial=x), the same values as the grown stack, so there is one signature.

```text
before:  cat(stack, partial) -> [T,N+1,D] -> .float() -> GEMV          (eager, fp32 copy saved)
after:   fwd region: score entries + partial, 8-slot sum               (bf16 in, fp32 stats out)
         bwd region: grads from saved [T,N+1] stats, weight grad = 1 GEMM (3 bf16 pieces)
```

Region options:
- `triton.mix_order_reduction_non_strict_mode`: no `T >= 4096` guard.
- `triton.prefer_nd_tiling`: tiles `[T, N, D]` as rows x D, so the symbolic width is not divided into every element index. Dynamic-width grad kernel 1409 -> 571 us.

One path, no gate: the new form is also faster in eager (2-layer eager 370.4 -> 348.0 ms).

You may ask:
- Why not a plain region with Inductor's autograd? Same static speed, but `no_grad` doubles graphs and the dynamic-width weight grad took 2.3 ms.
- Why not a static width per call site? 8 graphs; past the limit once T varies.

NOTE:
- Reaches every Kimi K3 config with the default `local_compile_regions` (all in-tree Kimi K3 recipes).
- Eager numerics change slightly too (not bitwise).
- Not tested: loss curve; multi-GPU (TP/SP rows are independent, weight grads stay per-shard partials; PP; FSDP); GraphTrainer/make_fx; CUDA graphs/decode shapes; H100.

Rejected:
- static stack width per call site: 8+ graphs, fails once T varies
- plain region for the residual: `no_grad` doubles graphs, dynamic-width weight grad 2.3 ms
- an earlier compiled residual path: 4366 vs 2142 us per call at N=7
- saving the residual output as a remat region under SAC: estimated < 1%, costs memory, not done

Compile limits hit:
- Inductor removes a bf16 round trip, so `x.bfloat16().float()` splits silently become inexact: split the fp32 coefficients with bit masks (PR 1).
- A sum over a symbolic small dim lowers to a slow strided reduction: a Python loop over 8 entry slots instead (PR 1).
- An opaque custom op can't fuse: combine compiled as written (`deterministic_scatter_add`) 4.3 vs 1.3 ms op level (PR 2).

Not tested: loss curves, multi-GPU (TP/EP/PP/FSDP), GraphTrainer, CUDA graphs/decode, H100.
