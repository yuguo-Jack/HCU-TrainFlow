# [rl] verifiers: route each generation request to its own group's GenerateFn (2/3)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5238) · state: open · merged: False

## Original PR description

**TLDR:** The Verifiers generation server now calls the `GenerateFn` of each request's own rollout group, not the one the last-started group set. No run on main hits the old behavior: validation runs only before and after training, so its groups never share the server with training groups. Periodic or overlapped validation would, and would log validation generator metrics under `generator/`, and the reverse.

**Problem**
1. `VerifiersRollouter.run_group_rollouts` called `GenerationServer.set_generate_fn(generate_fn)` for every group, and the server kept one function.
2. The controller passes training groups a function that logs under `generator/` and validation groups one that logs under `validation_generator/`.
3. When groups of both kinds run at once, every request uses the function of whichever group started last.
4. That happens whenever validation and training groups generate at once: with periodic validation (training groups keep generating while the trainer waits) and with overlapped validation, both proposed separately.
5. Routing and rollouts don't change; only the metric labels do. But when a validation pass is logged at a training step, its mislabeled `generator/*` values land in the training step's row.

**Solution**
1. `GenerationServer.generate_fns` maps group id to `GenerateFn`.
2. `run_group_rollouts` sets its group's entry before the rollouts and removes it in a `finally`, so a rollout that raises doesn't leave it behind.
3. A request whose group has no entry gets a 503 instead of another group's function.

**Test plan**
```
pytest tests/rl/unit_tests/cpu/test_verifiers.py tests/rl/unit_tests/cpu/test_verifiers_terminal_bench.py   # Verifiers 0.3.1: 22 passed, 2 failed (previous PR: 19 passed, the same 2 failed)
pytest tests/rl/unit_tests/cpu   # 511 passed, 8 skipped (the Verifiers tests skip without verifiers)
```
- `test_generation_server_uses_each_groups_generate_fn`: a validation group's second request still uses its own function after a training group registers one.
- `test_rollouter_registers_the_groups_generate_fn_while_it_runs`: the entry lives while the group's rollouts run, even as another group starts, and is gone after.
- `test_rollouter_removes_the_groups_generate_fn_when_a_rollout_raises`: the entry is gone after a rollout raises.

The 2 failures also fail on main: they read `Config.train_dataset`, which main renamed.
