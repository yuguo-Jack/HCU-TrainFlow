# [graph_trainer][pp][bitwise] Match eager bucketing in UNSHARD

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5207) · state: closed · merged: True

## Original PR description

Imagine one pipeline stage owns two transformer blocks:
```
Pipeline stage
|-- layers.0
|   |-- weight A
|   `-- weight B
`-- layers.1
    |-- weight C
    `-- weight D
```

GraphTrainer's configured FSDP plan says:

bucket 0 = layers.0 parameters
bucket 1 = layers.1 parameters

The desired communication is therefore:

AG(A, B)   # layer 0 bucket
AG(C, D)   # layer 1 bucket

and similarly for reduce-scatter/all-reduce during backward.

### What GraphPP did

GraphPP removes those collectives from the compute graph and creates separate actions:

UNSHARD action:
    all parameter all-gathers

FORWARD:
    compute only

BACKWARD:
    compute only

REDUCE_GRAD action:
    all gradient reductions

Changing bucketing changes numerics, so bitwise numerics require preserving the eager bucketing structure.
