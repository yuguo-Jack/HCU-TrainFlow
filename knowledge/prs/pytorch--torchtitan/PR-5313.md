# [train] Require one device for a seed checkpoint

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5313) · state: open · merged: False

## Original PR description

## Summary

`create_seed_checkpoint=True` is documented as a one-device run: every parallelism degree is 1, and initialization must not be sharded. `torchtitan/train.py` enforced that with `assert int(os.environ["WORLD_SIZE"]) == 1`.

Pure fake mode does not set `WORLD_SIZE`. `docs/debugging.md` lists it as unused there, and `NGPU` is the logical world size. `run_train.sh` with `COMM_BACKEND=fake` therefore raised `KeyError` before the message. Under `python -O` the assert is removed, so a multi-device launch can save a sharded checkpoint and still log that the seed checkpoint was created. A missing `checkpointer` was the same kind of assert; `save_checkpoint` then returns `False` because the manager was never built.

The check now runs after distributed init and uses `torch.distributed.get_world_size()`, which is `NGPU` in fake mode and the launched process count under `torchrun`. World size other than 1, a missing checkpointer, and a process group that was not initialized raise `ValueError`.

This is separate from the `pipeline_parallel_layers_per_stage` check. That one is a config value and does not depend on how the job was launched.

## Test plan

- [ ] CPU: `tests/unit_tests/cpu/test_seed_checkpoint_launch.py` accepts world size 1 with `WORLD_SIZE` unset, and rejects world size 4, a missing checkpointer, and an uninitialized process group.
