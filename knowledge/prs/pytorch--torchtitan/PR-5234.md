# [rl] One step-time ratio per loop phase; fwd_bwd no longer counts the optimizer (2/2)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5234) · state: open · merged: False

## Original PR description

**TLDR:** `perf/trainer/step_time_ratio/fwd_bwd` and `perf/trainer/tokens_per_second_fwd_bwd` also counted the optimizer step, which includes checkpoint saves. This PR gives each loop phase its own ratio, so forward/backward and the optimizer are reported separately. (2/2; independent of 1/2, stacked only for merge order.)

**Problem**
1. The loop times each phase under `timing/step/<phase>`, and `compute_perf_ratio_metrics` turns them into `perf/trainer/step_time_ratio/*`.
2. `step_time_ratio/fwd_bwd` is (forward_backward + optimizer) / total, and `tokens_per_second_fwd_bwd` divides tokens by the same sum.
3. The optimizer phase includes checkpoint saves. So on save steps, "fwd_bwd" grows and its tokens/s dips, while forward/backward itself didn't change.

**Solution**
1. One ratio per phase: `perf/trainer/step_time_ratio/<phase>` = `timing/step/<phase>` / `timing/step/total`.
2. Each ratio takes its phase's name, which renames three keys:
```text
perf/trainer/step_time_ratio/batch      -> perf/trainer/step_time_ratio/wait_for_training_batch
perf/trainer/step_time_ratio/fwd_bwd    -> perf/trainer/step_time_ratio/forward_backward
  (forward/backward + optimizer)           + perf/trainer/step_time_ratio/optimizer (new)
perf/trainer/tokens_per_second_fwd_bwd  -> perf/trainer/tokens_per_second_forward_backward
  (over forward/backward + optimizer)      (over forward/backward only)
```
3. Unchanged: every `timing/*` key and trace span, `step_time_ratio/blocking_*`, `step_time_ratio/unaccounted`, `tokens_per_second_full_step`.

You may ask: what replaces tokens over forward/backward + optimizer? Nothing exactly. The closest is the trainer's `trainer/tokens_per_second` (per device, all tokens), timed from forward/backward start to the optimizer update: no checkpoint save, but it includes the blocking push wait.

NOTE: dashboards that read the three old keys need the new names.

**Test plan**
- `test_compute_perf_ratio_metrics_reads_flushed_means`: the exact output dict, so every phase ratio, `unaccounted` and both tokens/s keys, with no extras.
- `pytest tests/rl/unit_tests/cpu -q` on torchmonarch 0.7.0: 448 passed, 5 skipped, plus the same 3 failures as main (2 Terminal-Bench, 1 `test_metrics` fold).
