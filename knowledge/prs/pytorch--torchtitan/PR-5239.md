# [rl] Terminal-Bench recipes: vLLM watermark 0.03 (3/3)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5239) · state: open · merged: False

## Original PR description

**TLDR:** Both Terminal-Bench recipes set vLLM's `watermark` to 0.03 through `extra_engine_args`: vLLM keeps 3% of KV blocks free when it admits a request, so running agent turns are preempted less often. It costs nothing until the KV cache fills, so today it is headroom. Assumes the `extra_engine_args` passthrough PR lands first.

**Problem**
1. When a generator's KV cache fills, vLLM still admits a waiting request whenever one fits at that moment.
2. The next running request that needs a block finds none, so vLLM preempts the newest one and later recomputes it.
3. A Terminal-Bench turn re-sends a long history, so a preempted turn recomputes many tokens.
4. Today this is headroom: a GB300 35B-A3B Terminal-Bench run (8 one-GPU generators, 131K context, a different layout than these recipes) used 31-37% of KV and logged 0 preemptions.

**Solution**
1. `extra_engine_args={"watermark": 0.03}` in `rl_grpo_qwen35_9b_terminal_bench` and `rl_grpo_qwen35_35b_a3b_terminal_bench`.
2. Unchanged: everything else in the recipes.

**Results**

CPU sim on vLLM's real scheduler, single-turn KV-bound workloads (W1, W2: two response-length mixes), mean of 2 seeds; generated tokens per unit of compute, higher is better:
```
watermark                          0       0.01    0.02    0.03    0.05    0.1
W1 steady                          174.2   185.1   185.3   184.1   180.4   171.3
W2 steady                          180.5   187.0   187.5   186.6   184.6   179.1
within 1% of the best, 10 regimes  0/10    9/10    8/10    8/10    2/10    0/10
worst of 10 regimes vs the best    -9.7%   -3.8%   -4.0%   -4.7%   -5.8%   -11.1%
```
- The best fixed value was always 0.01-0.03. Its cost is roughly its own size in KV-bound concurrency.
- Zero preemptions is the wrong target: in W1, 0.05 and 0.1 reach ~0 preemptions and lose 2.7% and 7.6%.

You may ask: why 0.03 and not 0.01? The curve is flat over 0.01-0.03, and each Terminal-Bench preemption recomputes a long history, which favors the top of that range. It also matches the math recipes.
You may ask: why not 0.05? vLLM's default is 0.0; 0.05 is what vLLM's benchmark picked on one workload when it added the option. In the sim it was within 1% of the best in 2 of 10 regimes.

NOTE: the sim does not model multi-turn agents that re-send their history; Terminal-Bench is not one of its regimes.
NOTE: needs the `extra_engine_args` passthrough on `VLLMGenerator.Config`; until it lands, these recipes fail to build. Not run on GPU with this change.

**Test plan**
With the passthrough applied: both recipes build with `generator.extra_engine_args == {"watermark": 0.03}`, and `pytest tests/rl/unit_tests/cpu/test_verifiers_terminal_bench.py tests/rl/unit_tests/cpu/test_verifiers.py tests/rl/unit_tests/cpu/test_generator.py` gives 61 passed, 1 skipped, and the same 2 failures as main.
