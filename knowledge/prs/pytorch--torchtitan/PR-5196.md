# [rope][perf] Compile ComplexRoPE in real arithmetic (complex_rope region)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5196) · state: open · merged: False

## Original PR description

**TLDR:** Spell `ComplexRoPE`'s rotation in real arithmetic under compile, as the opt-in `complex_rope` region. Inert alone; PR 3 turns it on for DeepSeek-V4 (part of that PR's -22.2%).

**Problem**
1. **ComplexRoPE.** `apply_rotary_emb` rotates q/k with `view_as_complex` and a complex multiply.
2. **No complex codegen.** Inductor can't generate kernels for complex tensors.
3. **Fallbacks.** So a compiled `ComplexRoPE` still runs those ops as eager kernels.
4. **Cost.** DeepSeek-V4's rope channels: 480.5 us fwd+bwd at 16k in eager.

**Solution**
1. **Real arithmetic under compile.** Cast each half to the output dtype, rotate, and stack per half.
2. **Custom backward.** An autograd Function whose backward is the rotation by the opposite angle.
3. **Region option** `max_pointwise_cat_inputs=0`, so the stack lowers as per-input copies.
4. **New opt-in region** `complex_rope` over `ComplexRoPE.forward`.
5. **Unchanged:** eager. Not enabled for any model in this PR.

```text
eager:      x -> view_as_complex -> * freqs_cis -> view_as_real          (unchanged)
compiled:   x -> (x_even, x_odd) -> real rotation -> stack    bwd: rotate by -angle
```

**Results**
```text
op level, DeepSeek-V4 rope channels, fwd+bwd, GB300 (earlier measurement, same code)
16k   480.5 us eager -> 142.5 us

DeepSeek-V4 Flash layers 4+5, fwd+bwd wall, 1x GB300, FA4: inert alone (region not enabled)
16k   154.49 -> 154.54 ms
4k     54.73 ->  54.70 ms
correctness: region bitwise vs eager on the tested inputs
graphs: complex_rope 3 with PR 3 (DeepSeek-V4, training 4k/16k/2k + no_grad 4k/2k)
```

You may ask: why not enable it here? Enabled alone on DeepSeek-V4 it exceeds the graph limit; PR 3 enables it together with the glue regions, and then it uses 3 graphs.
You may ask: other models? Llama3, DeepSeek-V3 and Kimi K2.x could opt in; not part of this stack.
You may ask: alternatives? A masked pointwise stack, a flip formulation, and the cast without the region option were slower.
NOTE: the CosSinRoPE 1-ulp test fails the same way on main.
NOTE: not yet measured under CUDA graphs. Not tested: GraphTrainer (traces the eager branch), H100, the other ComplexRoPE models.

**Test plan**
`pytest tests/unit_tests/gpu/test_rope_compile.py`

Stack: 2 of 7. Branch `felipemello1/lcp/dsv4-2-complex-rope`.
