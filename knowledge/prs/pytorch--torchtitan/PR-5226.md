# [kimi_k3] KDA: Attention Gym's cuDNN chunk kernels on Blackwell

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5226) · state: closed · merged: False

## Original PR description

Stack:
* #5222
* #5223
* #5225
* __->__ #5226

Stacked on #5225 (review only the last commit).

**TLDR:** same as #5225, for Kimi K3's KDA layers: `chunk_kda` runs Attention Gym's cuDNN chunk kernels on Blackwell and the fused ones elsewhere.

**Problem**
1. KDA's training kernel is Attention Gym's `chunk_kda`, which has the same `fused` / `cudnn` backends as GDN's.
2. TorchTitan always runs `fused`.

**Solution**
1. `KDAKernel.forward` passes `kernel_options=chunk_kernel_options(q_1THK)` (added in #5225): `cudnn` for packed fp16/bf16 inputs on SM100/SM103, `fused` elsewhere and in deterministic mode.
2. cuDNN KDA needs batch 1 and a gate lower bound >= -5.45. The model always calls the kernel packed (batch 1), and `KDAKernel.Config.lower_bound` is validated to `[-5, 0)`. Callers with batch > 1 (e.g. tests) get `fused`.
3. `autotune` stays as is; cuDNN ignores it.

NOTE: not measured for KDA. The GDN cuDNN kernels are 2.3-3.9x faster than fused on GB300 (#5225).

**Test plan**
- On B200 CI, the existing KDA and Kimi K3 GPU tests run cuDNN where their inputs are packed bf16, and fused otherwise.
- Not run locally on this branch: my torch nightly predates main's imports.
