# [Attn] Default compatible models to Varlen attention

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5307) · state: open · merged: False

## Original PR description

Use Varlen attention by default for compatible decoder models and GraphTrainer/TorchFT recipes. Size C4 document capacity as `max(32, ceil(tokens_per_microbatch / 256))` for CUDA graphs, while retaining Flex for Kimi-K2 QK clipping and Flex-specific CP paths. Flux and GPT-OSS already use Varlen; specialized linear, sparse, and vision attention stay unchanged.

Preserve FP16/BF16 values and align upcast Q/K with the value dtype instead of forcing BF16. Keep the existing BF16 conversion for FP32 callers.

### Testing
- 133 CPU tests and 45 recipe configurations passed. Varlen dtype checks also passed 15 GPU tests, including FP16/BF16 vs FP64 SDPA, bitwise FP32 fallback agreement with the legacy path, and exact eager/compiled/traced agreement.
- Eight debug models: 10 steps with bitwise-matching outputs, losses, gradients, and weights between the new default and explicit Varlen.
- Llama3 C4 smoke training: 10 steps with CUDA graph capture/replay. Flex vs Varlen maximum relative difference: loss 0.26%, gradient norm 0.58%.
- Full pre-commit: all hooks passed except Pyrefly; its 49 errors exactly match the base branch. Broader CPU/GraphTrainer coverage has existing PyTorch/optional-dependency blockers.

C4 packing check: 16,384 training documents from four shards, Llama-3.1 tokenizer, actual packer; final corpus-tail padding excluded. This is a sampled default, not exhaustive tuning.

|---:|---:|---:|
| 8,192 | 32 | 0.053% |
| 32,768 | 128 | 0% |
| 131,072 | 512 | 0% |
