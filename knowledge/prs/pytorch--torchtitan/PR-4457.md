# [metrics] Log host memory and CPU utilization

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4457) · state: open · merged: False

## Original PR description


Summary:
TensorBoard metrics cover device memory in six series but report nothing
host-side, so a run's CPU utilization and host resident memory are
invisible. That gap matters most for checkpointing: both the native DCP
`async_with_pinned_mem` stager and the torch_checkpointing backend stage
device state into pinned host memory, and pinned pages are resident by
definition, so a save can move host RSS by tens of GiB without moving any
device metric.

Add a `HostMonitor` alongside `DeviceMemoryMonitor`. Each rank measures its
current RSS, process-lifetime peak RSS, and process CPU time over the log
interval using `/proc/self/statm` and `resource.getrusage`. The current RSS
source has the same Linux semantics as `psutil.Process().memory_info().rss`
without adding a dependency.

TensorBoard normally records only one metrics rank, so local host values can
hide the worst rank at scale. Reduce the three samples over the world mesh and
emit:

    memory/host_rss_avg(GiB)             current RSS, rank average
    memory/host_rss_max(GiB)             current RSS, rank maximum
    memory/host_peak_rss_max(GiB)        lifetime RSS peak, rank maximum
    cpu/process_utilization_avg(%)       process CPU, rank average
    cpu/process_utilization_max(%)       process CPU, rank maximum

The CPU percentage sums CPU time across all process threads, so it can exceed
100%. The peak RSS metric uses a kernel high-water mark that is never reset,
which catches a staging buffer allocated and freed between log calls.

Test Plan:
`pytest -q tests/unit_tests/observability/test_host_monitor.py
tests/unit_tests/cpu/test_metrics_config.py tests/unit_tests/cpu/test_trainer.py`
passes 19 tests, including a real two-rank Gloo reduction test.

All applicable pre-commit hooks pass for the two changed files. A direct
Pyrefly check of `torchtitan/components/metrics.py` reports zero errors. The
whole-project Pyrefly hook still reports four unrelated missing `attn_gym`
imports in Kimi K3 and Qwen3.5 files.
