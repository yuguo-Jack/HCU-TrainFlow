# [Linear] In-place WGRAD accumulation for the bf16 Linear

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5248) · state: closed · merged: False

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.18.0) (oldest at bottom):
* __->__ #5248
* #5137

----

- Move `inplace_wgrad_accum: bool = True` to Linear.Config; MXFP8Linear and
  HiMidLoLinear inherit it. NVFP4Linear and the async TP linears compute
  WGRAD themselves, so they default to False and reject True.
- Linear._linear uses a new autograd Function (_LinearFunction) when in-place
  accumulation is active, plain F.linear otherwise (tracing, no grad, frozen
  weight). Without a running grad its gradients are bitwise identical to
  F.linear's; autocast is replicated by casting the operands explicitly.
- Numerics change: later microbatches / chunks add the GEMM's fp32
  accumulator into the running grad (addmm(out=weight.grad)) instead of
  rounding each WGRAD to bf16 first. Loss goldens for FSDP runs with PP or
  gradient accumulation need regenerating.
- Linear.forward reads weight and bias once and passes them to _linear as
  stored (stacked weights unflattened); implementations flatten. Fixes
  SimpleFSDP's double all-gather + quantize in MXFP8Linear (quantize count
  back to 1) and lets HiMidLoLinear support stacked weights with an fp32
  grad.
- MXFP8 converter and LoRA adapters carry the option; GraphTrainer disables it
  on every Linear.Config.
