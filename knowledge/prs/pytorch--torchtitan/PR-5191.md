# [CI Fix] Kimi K3 DistMuon layouts under context parallelism

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5191) · state: closed · merged: True

## Original PR description

## Summary

Kimi K3 DistMuon layouts currently declare only the `dp_shard` storage axis. Under context parallelism, FSDP flattens `dp_shard` and `cp` into `dp_shard_cp`, so DistMuon fails during optimizer initialization before the two Kimi CP integration tests reach step 1.

This change:

- declares both `dp_shard` and `dp_shard_cp` directly in the dense Kimi Muon layouts; and
- applies the same declarations to the shared EP=1 routed-expert layout.

`ComputeLayout` resolves only declarations present in the parameter storage mesh, so non-CP runs continue to select `dp_shard` with unchanged behavior.

This addresses the main-branch H100 failures introduced when #4639 added the Kimi CP integration cells. Related draft: #5145.
