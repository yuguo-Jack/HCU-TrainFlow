# [dsv3][perf] Compile MLA q/k RoPE and concat glue as a local region

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5161) · state: open · merged: False

## Original PR description

**TLDR:** DeepSeek-V3 attention's q/k split + RoPE + cat becomes the `mla_qk` region: 16k step -7.5%, attention glue 9.67 -> 3.62 ms per layer.

**Problem**
1. **q today.** Split, apply RoPE to one part, cat back.
2. **k today.** Split, expand the rope part to 128 heads, cat back.
3. **Slow copies.** Those cats and their split backwards run as non-vectorized `CatArrayBatchedCopy` on `[T, 128, 192]`.
4. **Cost.** 13.2 ms per 2 layers at 16k.

**Solution**
1. **Region.** `mla_qk` wraps the q and k assembly; Inductor fuses the cats and splits.
2. **Dense v under compile.** A strided `v` view got its gradient from flex in another layout, and AOTAutograd copied it (556 us) before the region backward. Returning v dense avoids the copy.
3. **Enabled** in the DSv3 model config.
4. **Unchanged.** Recipes with the `fused_mla` override replace this code and are not affected.

```text
before:  q: split -> rope -> cat       k: split -> expand(128 heads) -> cat     (eager CatArrayBatchedCopy)
after:   mla_qk region: same math, fused; v returned dense under compile
```

**Results**
```text
DSv3 671B layers 2-3, flex attention, fwd+bwd wall, 1x GB300 (shared), median [range] of 3 fresh processes, no AC
16k            173.80 [173.29-173.99] -> 160.75 [160.25-160.76] ms  (-7.5%)
peak             40.3 -> 39.2 GB
attention module alone (layer 2, 16k, 1 process): 59.33 -> 53.48 ms; glue 9.67 -> 3.62 ms

fused_mla instead of mla_qk, whole stack (n=2 at 16k)
16k   159.74 -> 156.94 ms
4k     39.28 ->  38.63 ms
32k   300.44 -> 298.14 ms
SAC   179.97 -> 176.48 ms

correctness: bf16 output and all 27 grads bitwise identical to eager (2 layers, 4k)
graphs: mla_qk 3 per method (static T, dynamic T, no_grad), shared across attention instances
```

You may ask:
- Why not `fused_mla` everywhere? It is ~1.5-2% faster, but it is an opt-in Triton kernel; this region is default-on and kernel-free. Enabling `fused_mla` in the base recipe is the owners' call.
- Why not real-arithmetic RoPE? With ConcatKernel it ties complex RoPE inside the region (53.35 vs 53.48 ms per attention module).

NOTE:
- With #5196 (RoPE in real arithmetic under compile), this region also needs plain cat lowering (`max_pointwise_cat_inputs=0`, second commit): 16k layer fwd+bwd 46.34 -> 45.85 ms, bitwise vs eager. Alone, the option is neutral (46.37 ms).
- Reaches recipes using the stock DSv3 `Attention` (deepseek_v3_671b with flex, Kimi K2.x).
- Not tested: TP/SP (regions are disallowed under SPMD type checking), GraphTrainer, varlen attention, loss curve, H100.

**Test plan**
`pytest tests/unit_tests/cpu/test_deepseek_v3_mla_compile.py` (fp32; fails before, passes after)

@SherlockNoMad FusedMLA is ~2.6% faster than this PR's region at 16k (45.10 vs 46.34 ms per attention fwd+bwd). Two small changes get the region to 45.48 ms. CUDA graphs don't change the picture: one attention layer at these sizes is GPU-bound.

```text
DeepSeek-V3 671B attention (one layer), packed 4k-token docs, bf16, fwd+bwd, 1x GB300, 3 fresh processes
                          T=4k     T=16k    T=16k CUDA graph
eager glue               13.33    52.18    52.26 ms
mla_qk (this PR)         11.84    46.34    46.42
+ real-arithmetic RoPE   11.72    45.85    45.96
+ V as a view of kv      11.62    45.48    45.59
FusedMLA                 11.49    45.10    45.22
all bitwise identical to eager, with and without graphs
```

- **RoPE (0.5 ms):** Inductor can't codegen complex multiply, so `q_pe * freqs_cis` stays an ATen kernel inside the region. Real arithmetic (the `complex_rope` PR, #5196) plus `max_pointwise_cat_inputs=0` (second commit here) fixes it.
- **V (0.3 ms):** a dense V costs a clone and a slower attention fwd; returning the view from a region makes AOTAutograd copy its grad. An `autograd.Function` around two regions returns the view, like FusedMLA. ~35 lines for ~0.6% of the layer, so not in this PR.
- **Left (0.4 ms):** mostly FusedMLA rotating `grad_q` in place, which a compiled region can't do.
- **One or the other:** FusedMLA replaces `Attention.forward` and is opt-in per recipe; without it, every DeepSeek-V3 config gets `mla_qk`.

```python
"""DeepSeek-V3 671B MLA attention, fwd+bwd: eager q/k glue vs the mla_qk region vs FusedMLA,
without and with CUDA graphs.

usage (from the repo root, 1 GPU): PYTHONPATH=. python compare_mla.py 2>/dev/null
(stderr carries flex attention's autotuning log)
"""

import torch
from torch.nn.attention.flex_attention import and_masks

from torchtitan.distributed.local_compile import apply_local_compile
from torchtitan.models.common.attention import (
    create_attention_mask,
    get_causal_mask_mod,
    get_efficient_causal_mask_mod_for_packed_document,
)
from torchtitan.models.deepseek_v3.flavors import build_model_config
from torchtitan_recipes.overrides.fused_mla import fused_mla

DOC_LEN = 4096  # packed documents of 4k tokens
attn_config = build_model_config("671B").layers[3].attention


def build(config):
    torch.manual_seed(0)
    with torch.device("cuda"):
        attn = config.build()
        attn.init_states(buffer_device=torch.device("cuda"))
    return attn.bfloat16()


stock = build(attn_config)
fused = build(fused_mla(attn_config))
fused.load_state_dict(stock.state_dict())


def step(attn, x, mask, positions):
    """One fwd+bwd. Grads are overwritten, not accumulated, so a captured step replays exactly."""
    for p in [x, *attn.parameters()]:
        p.grad = None
    out = attn(x, mask, positions)
    out.float().square().mean().backward()
    return out


def time_ms(fn, iters=10):
    for _ in range(3):
        fn()
    start, end = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
    start.record()
    for _ in range(iters):
        fn()
    end.record()
    torch.cuda.synchronize()
    return start.elapsed_time(end) / iters


def capture(attn, x, mask, positions):
    """Warm up on a side stream, then record one fwd+bwd into a CUDA graph."""
    side = torch.cuda.Stream()
    side.wait_stream(torch.cuda.current_stream())
    with torch.cuda.stream(side):
        for _ in range(3):
            step(attn, x, mask, positions)
    torch.cuda.current_stream().wait_stream(side)
    graph = torch.cuda.CUDAGraph()
    with torch.cuda.graph(graph):
        out = step(attn, x, mask, positions)
    return graph, out


def rel_l2(a, b):
    return ((a.float() - b.float()).norm() / b.float().norm()).item()


for num_tokens in (4096, 16384):
    torch._dynamo.reset()  # training runs one T; a second T would recompile flex with a symbolic T
    positions = torch.arange(num_tokens, device="cuda") % DOC_LEN
    mask_mod = and_masks(
        get_causal_mask_mod(), get_efficient_causal_mask_mod_for_packed_document(positions)
    )
    mask = create_attention_mask(
        mask_mod, 1, None, num_tokens, num_tokens, device="cuda", BLOCK_SIZE=128
    )
    x = torch.randn(num_tokens, 7168, device="cuda", dtype=torch.bfloat16, requires_grad=True)

    eager_ms, graph_ms, results = {}, {}, {}
    for name, attn, regions in [
        ("eager-glue", stock, []),
        ("mla_qk", stock, ["mla_qk"]),
        ("FusedMLA", fused, []),
    ]:
        apply_local_compile(regions)
        eager_ms[name] = time_ms(lambda: step(attn, x, mask, positions))
        out = step(attn, x, mask, positions).detach()
        results[name] = (out, x.grad.clone())

        graph, graph_out = capture(attn, x, mask, positions)
        graph_ms[name] = time_ms(graph.replay)
        graph.replay()
        torch.cuda.synchronize()
        replay_match = torch.equal(graph_out, out) and torch.equal(x.grad, results[name][1])
        print(f"T={num_tokens // 1024}k {name}: replay bitwise equal to eager run: {replay_match}")
        del graph, graph_out

    for label, ms in [("no graphs", eager_ms), ("CUDA graph", graph_ms)]:
        row = " | ".join(f"{k} {v:.2f} ms" for k, v in ms.items())
        print(f"T={num_tokens // 1024}k {label:10s} {row}")
    ref_out, ref_grad = results["eager-glue"]
    for name in ("mla_qk", "FusedMLA"):
        out, grad = results[name]
        print(f"       {name} vs eager-glue: out {rel_l2(out, ref_out):.1e}, x.grad {rel_l2(grad, ref_grad):.1e}")
```
