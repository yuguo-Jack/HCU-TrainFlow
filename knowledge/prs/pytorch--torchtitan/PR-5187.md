# [Draft][KimiK3][Optimizations]Reduce Kimi K3 attention-residual backward memory

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5187) · state: open · merged: False

## Original PR description

Kimi K3 attention-residual scoring materializes normalized FP32 keys before the dot product. Apply the per-entry inverse RMS after the dot-product reduction instead. This preserves FP32 arithmetic and lets Inductor avoid an additional full-sized backward intermediate.

Register an opt-in `kimi_attention_residual` region using the existing local compilation mechanism:

```python
config.model.local_compile_regions.append("kimi_attention_residual")
```

Default compile regions are unchanged. The new region does not support batch-invariant mode.

## Memory benefit

GB200, PyTorch `2.15.0.dev20260928+cu130`, BF16 inputs/parameters, width 7,168, eight committed residuals plus one partial, RMS epsilon 1e-6, TF32 disabled. Both formulas were compiled with the same wrapper and measured under the production FullAC policy; medians of ten iterations after warmup:

| Tokens | Original peak (MiB) | New peak (MiB) | Saved (MiB) | Reduction |
|---:|---:|---:|---:|---:|
| 1,024 | 659.89 | 392.14 | 267.75 | 40.57% |
| 4,096 | 2,765.47 | 1,568.48 | 1,196.98 | 43.28% |
| 8,136 | 5,306.27 | 3,115.49 | 2,190.78 | 41.29% |

These are **residual-only peak allocated bytes above the pre-forward baseline**, not whole-model GPU memory. The largest measured saving is **2.14 GiB**. Allocator snapshots identify an extra 1,008 MiB FP32 backward allocation in the original compiled formula at 4,096 tokens. Eager forward also saves 1,008 MiB at that shape, but eager backward peak is unchanged.

The included benchmark supports eager/compiled execution, FullAC, numerical capture, and allocator snapshots. For the original-formula control, retain the compile decorator and restore only the old scoring expression.

## Validation

- CPU unit tests: 12 FP32/BF16 cases against an independent FP64 reference, including all input/parameter gradients, partial/committed-only stacks, noncontiguous inputs, low variance, and concentrated scores.
- GPU integration test: both residual calls in a real dense MLA Kimi block under FullAC, including all block parameter gradients.
- 32 benchmark cases passed on the upstream-based patch. GPU tensor comparisons passed; maximum observed relative L2 difference across outputs and gradients was `5.53e-5`.
- Formatting, lint, and documentation hooks pass. Targeted Pyrefly passes for the changed production and benchmark files in the GPU runtime. Full local Pyrefly was blocked by missing training dependencies.

The reassociation changes floating-point rounding and is not bitwise identical. **Draft pending representative training-convergence and full-model memory validation.**
