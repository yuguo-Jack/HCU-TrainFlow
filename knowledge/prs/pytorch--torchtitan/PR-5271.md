# [rl] RL model defaults in every run: fp32 lm_head, frozen MoE expert bias and router gate

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5271) · state: open · merged: False

## Original PR description

**TLDR:** Every RL run now gets fp32 lm_head logits, a frozen MoE expert bias, a frozen MoE router gate and no router aux loss, through `RLModelDefaults` on `Controller.Config`. The moving expert bias made the trainer-vs-vLLM logprob gap grow every step on MoE models: 0.053 -> 0.157 in 30 steps at lr=0, flat (0.054 -> 0.053) with the bias frozen.

**Problem**
1. **The bias moves.** Every MoE RL recipe registers a balancing hook that moves `expert_bias_E` before each optimizer step (~1.4e-3 per step on Qwen3).
2. **Near-ties flip.** The trainer and vLLM score experts with tiny numeric differences, so tokens near the top-k boundary pick different experts.
3. **More flips each step.** The moving bias pushes experts onto that boundary: 3.2% -> 9.0% of tokens per layer route differently after 30 steps.
4. **The gap grows.** At lr=0 with bitwise-correct weight sync, the logprob abs mean grows 0.053 -> 0.157 on Qwen3-30B-A3B.
5. **The router gate trains too,** at the policy lr.
6. **fp32 logits are opt-in.** Each recipe has to remember `LMHeadFP32OutputConverter`.

**Solution**
1. `RLModelDefaults` on `Controller.Config`, applied once in `Controller.__init__` to the shared model config, before the trainer and the generators copy it.
2. Its fields, each an opt-out:
   - `fp32_lm_head`: the lm_head becomes `HiMidLoLinear` (fp32 logits).
   - `freeze_expert_bias`: the balancing hooks still zero their counts but skip the bias update; a no-op on MoEs without a bias.
   - `freeze_router_gate`: the router gate (and gpt-oss's gate bias) gets `requires_grad=False`; the Qwen3.5 shared-expert gate still trains.
   - `disable_router_aux_loss`: no router aux loss (only the DeepSeek-V3 flavors build one today).
3. Recipes drop their 14 explicit fp32 converters and 3 helpers. Muse Glimmer opts out of the fp32 head (its `SoftCappedLinear` can't be converted yet).
4. Unchanged: pretraining. The new MoE fields default to False, and only the RL controller applies `RLModelDefaults`.

```text
recipe -> Controller.Config(model=<as for pretraining>, model_defaults=RLModelDefaults())
Controller.__init__: model = model_defaults.apply_(model)
    lm_head: Linear -> HiMidLoLinear              (fp32 logits)
    every MoE layer: freeze_expert_bias=True      (no-op on dense models)
    every router: freeze_gate=True, aux_loss=None
-> the trainer and each generator deep-copy config.model
```

**Results**
```text
Qwen3-30B-A3B, first 8 layers, real weights, H100, earlier main. Real trainer + vLLM actors and weight sync,
no RL loop: 30 x (generate -> score -> optimizer_step(lr=0) -> push/pull).

trainer-vs-vLLM logprob abs mean, step 0 -> 29
main (bias moves)        0.053 -> 0.157
bias frozen              0.054 -> 0.053

tokens whose top-8 experts differ, per layer, step 0 -> 29
main (bias moves)                         3.2% -> 9.0%
main, load_balance_coeff=None (control)   3.2% -> 3.5%
```

```text
One AdamW step on each MoE family's debug flavor (Qwen3 incl. no expert bias, Qwen3.5/3.6/3.8,
Kimi K2.7/K3, DeepSeek-V3/V4, gpt-oss), CPU, defaults vs opted out
router gate (and gpt-oss gate bias)    moves -> unchanged, no AdamW state
expert_bias_E                          moves -> unchanged (absent: no error)
every other parameter                  moves -> moves (incl. the Qwen3.5 shared-expert gate)

RL smoke: Qwen3 debug MoE, 1 trainer + 1 generator GPU, 5 steps, random init
trainable params                       75 -> 67 (the 8 router gates)
bit_wise/logprob_diff max per step     same level (0.007-0.018): the frozen gate still syncs
```

You may ask:
- Why not `load_balance_coeff=None` in the recipes? It deletes the bias buffer, so a checkpoint bias (DeepSeek-V3, Kimi) is dropped, and it doesn't stop Kimi K3's quantile hook.
- Why `Controller.__init__`, not `Config.__post_init__`? `__post_init__` runs when the recipe builds the config; the lm_head swap can't be undone, so a later opt-out would be lost.
- Why freeze the gate instead of training it? No freeze-vs-train ablation at 30B+ is published, so the default keeps it fixed, like the expert bias. A lower gate lr also works: `freeze_router_gate=False` plus a gate-only optimizer group (TODO in the code).

NOTE:
- A checkpoint saved before this PR keeps its drifted bias, now frozen. Start MoE runs fresh.
- A checkpoint saved with the gate frozen can't resume with `freeze_router_gate=False` (no optimizer state for the gate). The other direction works.
- `--print-config` prints the recipe's config before `RLModelDefaults` is applied.
- `generate.py` and the GPU tests that build actors without the controller call `model_defaults.apply_` themselves.
- Not run on this commit: GPU unit tests, multi-GPU trainer layouts, and the MXFP8 and dist_moe recipes (their packages aren't installed; the recipe test skips those two by name).
