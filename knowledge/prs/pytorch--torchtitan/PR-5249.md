# [Linear] Pass parameters to _linear as stored and read them once

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5249) · state: closed · merged: True

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.18.0) (oldest at bottom):
* #5250
* __->__ #5249

Why:
- In-place WGRAD accumulation (#5137, and the bf16 Linear next in this
  stack) needs the parameter itself in backward, to read and clear its
  .grad and return a gradient in its shape. _linear only got a flattened
  view, so implementations re-read self.weight or gave up on stacked weights.
- Re-reading self.weight is not free: SimpleFSDP's parametrization
  all-gathers on every read, and MXFP8Linear also quantizes, so each MXFP8
  forward did both twice (the quantize-count test asserted 2).
- A stacked weight's flattened view routes its gradient through the view's
  backward, which rounds HiMidLoLinear's fp32 grad_weight to bf16
  (pytorch/pytorch#189633), so HiMidLoLinear rejected stacked weights with
  inplace_wgrad_accum on.

What:
- Linear.forward reads weight and bias once and passes them to _linear
  unflattened ([N, K] or [num_linears, N, K]); implementations flatten them
  with the static Linear._flatten_weight_and_bias(). Updates the TP, vision,
  async TP, LoRA and NVFP4 call sites.
- MXFP8Linear uses its weight argument (quantize count back to 1).
- HiMidLoLinear's Function takes the parameter and flattens inside, so
  stacked weights accumulate in place and keep an fp32 grad.
- No numerics change for unstacked linears.

File: `torchtitan/quantization/mxfp8/linear.py` · line 455

> MXFP8Linear also quantizes, so each MXFP8 forward did both twice

I'm a bit surprised by this, could you say more?

For traditional bf16 weights, my mental model was that FSDP2 has a state machine, which works roughly as follows:
- when getting to the module forward boundary, it calls all-gather and points to the unsharded params when calling things like `self.weight`
- after forward, it goes back to sharded, if `reshard_after_forward` is on
- this mxfp8 impl has a post-all-gather hook which does quantization

Accoding to this mental model, on this line, I'm not calling all-gather again, so I thought we won't quantize again.
