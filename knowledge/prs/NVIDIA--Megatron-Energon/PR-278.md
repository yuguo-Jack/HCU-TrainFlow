# fix(loader): close dataset and reader resources deterministically

[Upstream PR](https://github.com/NVIDIA/Megatron-Energon/pull/278) · state: closed · merged: True

## Original PR description

## Summary

Makes resource ownership explicit so reader handles and worker processes are freed
deterministically instead of relying on garbage collection.

## Changes

- `SavableDataset.close()` plus context-manager support (`with dataset: ...`).
- `BaseWrapperDataset.close()` closes every child dataset exactly once.
- `DatasetSampler.close()` closes its reader(s) once; also called from `__del__`.
- `SavableDataLoader` / `BasicDataLoader`: `close()`, `__enter__`/`__exit__`, and shutdown of
  worker processes before closing the main-process dataset tree; the command thread of
  `SavableDatasetWrapper` is no longer joined from itself.
- `get_loader` / `get_savable_loader` docstrings document that the loader owns the dataset's
  reader resources.

## Tests

- `test_dataset.TestDataset.test_loader_close_propagates_to_indexed_reader_once`.

## Validation

- Full unit test suite on this layer: 142 tests passed (CPU).
- `ruff check`, `ruff format --check`, license headers: clean.
- Sphinx docs build (`-E -a`): no warnings.

### inline_comments

- Copilot · comment · 2026-10-07T09:15:32Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/278#discussion_r4205140301)

File: `src/megatron/energon/savable_loader.py` · line 58

With zero workers, neither loader retains its returned iterator in `_epoch_iterator` or `_iterator`. Thus `it = iter(loader); next(it); loader.close()` leaves the dataset generators suspended. When `GcDataset` uses freezing, its `finally: gc.unfreeze()` does not run, leaving frozen objects excluded from cyclic garbage collection. Track and finalize active single-process iterators before closing the dataset tree, including on context-manager exit.

- Copilot · comment · 2026-10-07T09:15:33Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/278#discussion_r4205140384)

File: `src/megatron/energon/savable_loader.py` · line 853

`SavableDataLoader` also owns `cmd_queues` and `result_queues`, but this helper never releases them. PyTorch's worker shutdown handles its own queues, not these checkpoint queues. A retained closed loader therefore still holds pipe handles and, after checkpoint commands, command-queue feeder threads. Release the custom queues and their references after stopping workers, with repeat-close handling and a safe way to drain or discard pending commands without hanging cleanup.

- Copilot · comment · 2026-10-07T09:15:33Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/278#discussion_r4205140454)

File: `src/megatron/energon/wrappers/base.py` · line None

This set is recreated on every call, so repeated `close()` calls invoke each child's `close()` repeatedly. The loader destructor also repeats propagation after explicit closure. `DatasetSampler`'s guard hides this in the new test, but custom leaf datasets need not have that guard. Persist the successfully closed child IDs on the wrapper to honor its once-only closure guarantee.
