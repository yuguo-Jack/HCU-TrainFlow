# feat(decision): schema augmentation, generic_decision LLM migration, verbalizer fix

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10317) · state: open · merged: False

## Original PR description

## Summary

This PR adds three groups of changes to the typed-decision (System-1) subsystem:

### 1. Decision schema augmentation (`DecisionAugmentConfig`)
Adds training-time data augmentation for `decision` task_type datasets:
- **`--decision_drop_instructions`** — randomly drop the question instruction text (layout still rendered), forcing the model to infer intent from options alone.
- **`--decision_subsample_options`** — subsample choice question options to at most N (gold + N-1 distractors), only for `choice` questions.
- **`--decision_state_as_text`** — randomly flatten dict `state` to human-readable text instead of JSON, so the model sees different renderings of the same record.
- **`--decision_shuffle_fields`** — shuffle dict state field order and question order in multi-question records.

All options are disabled by default (zero-cost passthrough). Wired through `DataArguments`, `loader.init_decision_augment`, and all `ScoringPreprocessor` subclasses (`ClefPreprocessor`, `JevPreprocessor`, `OmniJevPreprocessor`, `OpenJevPreprocessor`).

### 2. Move `generic_decision` to LLM type
`generic_decision` loads `AutoModelForCausalLM` (a text-only model), not a multimodal model. Moved from `MLLMModelType` / `MLLMTemplateType` to `LLMModelType` / `LLMTemplateType`. This fixes the model registration to match the actual loader behavior.

### 3. Fix `JevVerbalizerHead` token resolution
Previously, `get_verbalizer_token` silently returned `ids[0]` when a label encoded to multiple tokens, even when only the first token was the intended verbalizer. Now:
- Only returns the single token when the label encodes to exactly 1 id.
- Falls back to `unk_token_id` with a warning explaining the degenerate case (multiple labels collapsing to the same unk id).
- Error message includes the full token list for debugging.

Also normalizes JEV synonyms: `yes`/`y`/`1` → `true`, `no`/`n`/`0` → `false` (previously `yes` and `true` were distinct).
