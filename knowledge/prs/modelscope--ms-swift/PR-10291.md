# fix(cli): handle `--help`/`-h` and missing subcommand in cli_main

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10291) · state: open · merged: False

## Original PR description

## Summary

Running `swift --help` currently raises `KeyError: '--help'` instead of showing top-level help, and running `swift` with no arguments raises `IndexError`. The CLI entry point looks up the first argument directly in `ROUTE_MAPPING` without special-casing help flags.

## Change

In `cli_main` (swift/cli/main.py), before the routing lookup:

- print `Usage: swift <command> [options]` and the sorted list of available subcommands
- return successfully when the first argument is missing, `-h` or `--help`

The routing path for real subcommands is unchanged.

## Verification

Local matrix (with heavy deps stubbed):

- `swift --help` → prints usage + 12 commands, exits 0
- `swift -h` → same
- `swift` (no args) → same (previously IndexError)
- `swift sft --model ...` → still routed to `swift.cli.sft` unchanged

Fixes #10287
