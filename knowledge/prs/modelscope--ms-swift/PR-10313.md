# fix(dpo): stabilize the modulated exponential in DiscoPOP loss

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10313) · state: open · merged: False

## Original PR description

DiscoPOP computes `exp(-logits) * sigmoid(logits / tau)` as separate factors. With the default `beta=0.1`, `tau=0.05`, chosen/rejected sequence log probabilities of -1100/-100, and equal reference log probabilities, FP32 produces NaN loss and gradients from `inf * 0`; FP64 gives loss 100 and chosen-log-prob gradient -0.1.

Evaluate the same product as `exp(logsigmoid(logits / tau) - logits)`. This preserves the objective without clipping and avoids the intermediate overflow when the product is representable.

Validation:
- CPU tests import the actual DPO trainer. Three unittest methods cover 17 configurations: large-margin FP32 loss and all four input gradients against the original FP64 formula, ordinary FP32/FP64 values, and the BF16 regression. Nine regression configurations fail on the original implementation; all 17 configurations pass with the fix. Adjacent DPO configuration tests also pass (6 methods total).
- All applicable configured pre-commit checks pass for the two changed files.
- The existing RLHF alignment suite still has two fixture failures (`SimpleNamespace` missing `tuner_backend`), reproduced on unchanged main. No GPU training was run.

AI assistance: Codex assisted with diagnosis, implementation, and regression tests.
