# PR information

Expose Megatron Core's native training MLP chunking through `--mlp_chunks_for_training`, with a default of `1` that preserves existing behavior. Dense-model training can set a larger value on Core >=0.18 without passing the field through raw `megatron_extra_kwargs`. This integrates [NVIDIA/Megatron-LM#3656](https://github.com/NVIDIA/Megatron-LM/pull/3656) into the Megatron training path.

Validate the effective configuration after extra-kwargs overrides in both bridge backends. Reject invalid counts, unsupported older configurations, MoE, and selective MLP recomputation (which bypasses the upstream chunk branch). Keep the default, including an explicit raw override of `1`, compatible with older Core configurations. The global dependency minimum is unchanged.

Include Chinese/English parameter documentation, a dense BF16 full-parameter SFT example, and configuration/bridge regression tests.

## Experiment results

- `pre-commit run --all-files`: passed.
- Targeted tests: Core 0.18: **11 passed, 1 version-specific skip, 26 subtests passed**; Core 0.16: **7 passed, 5 version-specific skips, 24 subtests passed**. Test files: `tests/megatron/test_mlp_chunking.py`, `tests/megatron/test_megatron_model_utils.py`.
- Real Qwen3-0.6B-base BF16 full-parameter SFT on one H800, Core 0.18 / mcore-bridge 1.6.3 / PyTorch 2.10 / TE 2.11: chunks 1/2/4 each completed 6 optimizer steps at 2048 tokens; chunks 1/4 each completed 2 steps at 257 tokens. All runs saved checkpoints. First-layer hooks observed `[2048]`, `[1024, 1024]`, `[512, 512, 512, 512]`, and the nondivisible split `[65, 65, 65, 62]`.
- With identical seeds, inputs, and initial weights, the largest BF16 loss difference was 2.02e-4. First-layer post-clipping gradients differed by 1.17%–2.23% in relative L2; one-step updated weights differed by at most 3.06e-5 absolute. These short synthetic-data runs are execution and numerical checks, not convergence evidence.
- An additional upstream FP32 single-layer control at lengths 256/257 and chunks 1/2/4 passed output, parameter-gradient, and SGD-update comparisons with `atol=1e-6, rtol=1e-5`; maximum errors were 2.39e-7, 4.71e-9, and 3.73e-9 respectively.

For the 2048-token run, steps 3–6 (after two warmup steps), micro/global batch 1:

| Chunks | Median step time | Input tokens/s | Peak allocated GiB |
| --- | --- | --- | --- |
| 1 | 0.14513 s | 14,111.7 | 16.11150 |
| 2 | 0.16769 s | 12,213.0 | 16.11150 |
| 4 | 0.19831 s | 10,327.3 | 16.19060 |

This workload showed no steady-state memory reduction and lower throughput with chunking; the documentation makes no universal memory-saving or speedup claim. GPU validation covered the default mcore-bridge path with selective `core_attn` recomputation. The megatron-bridge path has a provider-mock configuration regression test; distributed parallelism, other precisions, LoRA, and RLHF were not validated.
