# refactor(modelopt): delegate real-quant export to ModelOpt

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/5812) · state: open · merged: False

## Original PR description

### Summary

Delegates real-quant packing and deployment metadata to ModelOpt while keeping distributed topology and Hugging Face naming in Megatron-Bridge.

- Reuses existing TP, PP, EP, and ETP conversion tasks for quantized weights.
- Handles fused QKV and gate/up projections.
- Resolves grouped Hugging Face expert mappings to canonical per-expert gate, up, and down tensors for online refit.
- Stores only topology and format metadata in the reusable plan.
- Recaptures current amax and scale tensors for each export stream.
- Uses object collectives only for small metadata and typed collectives for tensor state.
- Forwards every ModelOpt-emitted packed weight and sidecar without format-specific scale tables.
- Preserves ModelOpt output order while gathering expert outputs across EP.

Unmerged adapter export and quantized mappings requiring dimension permutation are rejected explicitly. Ordinary non-ModelOpt and grouped offline-export paths are unchanged.

### Ownership

- ModelOpt: format interpretation, state transforms, packing, sidecars, and `quantization_config`.
- Megatron-Bridge: topology conversion, expert identity, and canonical Hugging Face names.

### Validation

- Ruff and formatting checks passed.
- 197 focused conversion/export tests passed, including distributed state transport and grouped expert weight-and-sidecar gathering.
- Four-rank Transformer Engine `GroupedLinear` NVFP4 export passed with finite calibrated state.
- A downstream four-node Qwen3.5 grouped-MoE W4A4 job completed two GRPO steps and repeated native vLLM refits with finite loss, KL, and reward.

### Dependency

Requires https://github.com/NVIDIA/Model-Optimizer/pull/2251.

### Checklist

- [x] Added topology, grouped-weight, expert, and state-refresh tests.
- [x] Updated ModelOpt quantization documentation.
- [x] Kept optional ModelOpt imports scoped to ModelOpt paths.

- kevalmorabia97 · comment · 2026-09-30T21:50:47Z · [source](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/5812#issuecomment-5920346230)

From the ModelOpt side, we want this PR (with NVIDIA/Model-Optimizer#2251) to be the basis for fully deprecating ModelOpt's custom Megatron→HF exporter (`unified_export_megatron.py` + `plugins/mcore_*.py`). Overall plan is in #4804. Below are the items we'd need here or in follow-ups for this path to replace the custom exporter. Line refs are at 283019a.

**1. Rebase.** The PR is ~126 commits behind `main`. There are textual conflicts in `auto_bridge.py` and `model_bridge.py`. #6074 (`with_megatron_names` / `HFSourcedWeightTuple` in `stream_weights_megatron_to_hf`) also needs to be threaded through the new events/groups wrappers.

**2. Offline save path (follow-up is fine).** Besides online refit, we need a `save_hf_pretrained`-style API that consumes `ModelOptExportPlan`. It should:
- write the packed tensors plus `quantization_config` inline in `config.json`;
- drop any source-checkpoint `quantization_config` and `*_scale_inv` companions (bridges that dequantize FP8/MXFP4 sources on import).

No `hf_quant_config.json` is needed: vLLM prefers the inline config ([config.py#L921-L933](https://github.com/vllm-project/vllm/blob/73c7cae4d746f64c22677348d1cc120eea6f7439/vllm/transformers_utils/config.py#L921-L933)), and TRT-LLM accepts it since v1.3.0rc16. This replaces `examples/quantization/export.py`'s use of `mtex.export_mcore_gpt_to_hf`.

**3. Mapping coverage.** `_mapping_parallelism` (L81-L96) raises for everything outside Auto/Column/Row/Replicated/QKV/GatedMLP. That rejects models the custom exporter supports today:

| Mapping | Models |
|---|---|
| `MambaInProjMapping` | Nemotron-H / Nemotron-3, Falcon-H1 |
| `GDNLinearMapping(Separate)` | Qwen3.5/3.6 (+VL), Qwen3-Next |
| `_MTPFlatteningMapping` / `_MTPFlatteningQKVMapping` | Nemotron-H MTP (quantized MTP) |
| `QKVGMapping`, `ConcatenatedQKVMapping` | Step, Bailing, Sarvam, Exaone |

All of these only select or re-group **rows**. A generic option instead of per-class branches: derive row indices by running the mapping's own `megatron_to_hf` on a row-index proxy (`torch.arange(rows)[:, None]`), then apply `select_quantized_weight_export_state` with those indices. That would also cover custom subclasses correctly.

**4. `isinstance` dispatch accepts subclasses that change the layout.**
- `MiMoV2FlashQKVMapping(QKVMapping)` has an asymmetric V head dim, but state is split with the generic `split_qkv_weights` layout (L360-L379).
- That's fine for per-tensor state, but wrong for per-row or per-block state such as static NVFP4 or FP8 per-channel.
- Either the row-index proxy above, or rejecting subclasses that override `megatron_to_hf`, would avoid a silent mismatch.

**5. Transposed experts.** `FusedExpertMapping` / `FusedGatedExpertMapping.local_hf_param_specs` return `()` when `transpose_on_export` is set (`param_mapping.py` L3432, L3518 on main). So Qwen3-VL-MoE experts are rejected (L672), even though per-expert 2D canonical names need no transpose. It would be good to allow the per-expert specs in that case.

**6. Fused-sibling scale check.** Serving engines fuse some HF projections that come from *different* Megatron quantizers: MLA `q_a_proj` + `kv_a_proj_with_mqa` → vLLM `fused_qkv_a_proj` / TRT-LLM `fused_a`. vLLM NVFP4 takes the max `weight_scale_2` without requantizing ([modelopt.py#L1975-L1986](https://github.com/vllm-project/vllm/blob/73c7cae4d746f64c22677348d1cc120eea6f7439/vllm/model_executor/layers/quantization/modelopt.py#L1975-L1986)).
- We'll unify these at quantization time in ModelOpt.
- A cheap export-time assertion here would make a regression fail loudly: equal `weight_scale_2` / `input_scale` across q/k/v, gate/up and q_a/kv_a siblings.

**7. Bridges that requantize to the source format** in `maybe_modify_converted_hf_weight` (DeepSeek V4, Kimi K3, Kimi K2.5-VL) need to be bypassed on the ModelOpt export path.

What's needed to take this out of draft? Happy to help with any of the above.
