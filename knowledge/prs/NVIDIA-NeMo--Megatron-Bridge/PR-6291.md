# feat: support pipeline-stage-local HF export

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6291) · state: closed · merged: True

## Original PR description

## Summary

Closes #6268.

This adds an opt-in `current_pp_stage_only=True` mode to Megatron-Bridge HF weight streaming for RL trainer-to-inference weight synchronization.

## Design

- Default export behavior is unchanged: every PP rank still receives the complete HF stream.
- In pipeline-stage-local mode, each PP stage exports only its canonical local parameters.
- PP tensor and metadata broadcasts are suppressed for the local export operation.
- TP and EP gathering remain enabled, as do existing HF layout conversions such as fused-QKV splitting, gated MLP conversion, and MoE expert reconstruction.
- Duplicate logical parameters use the lowest PP-group rank as the canonical owner.
- MTP duplicate embedding sources are filtered consistently in global-name collection, normal conversion task construction, and FP8 task construction.
- Lazy `AutoMapping` delegates are kept operation-local so a local export cannot poison a later full export.
- ContextVar scope covers mapping and adapter materialization without leaking across generator yields.
- Custom Kimi K3 and Nemotron Omni streamers forward the new option and emit source-only passthrough tensors from PP rank 0.

## API

```python
for name, weight in bridge.export_hf_weights(
    megatron_model,
    current_pp_stage_only=True,
    show_progress=False,
):
    send_to_inference_workers(name, weight)
```

TP/EP replicas within one PP stage produce the same reconstructed HF tensors; consumers should select one representative stream per PP stage.

## Tests

Validated on an NVIDIA H20-3e GPU host (2-GPU runs):

- Qwen2 TP=2, PP=1: passed
- Qwen2 TP=1, PP=2: passed
- Qwen3 MoE TP=2, PP=1: passed
- Qwen3 MoE TP=1, PP=2: passed
- Qwen3 MoE TP=1, PP=1, EP=2: passed
- Core affected unit tests: 219 passed, 1 environment-related failure
- Dedicated Qwen current-PP-stage functional tests: TP=2, PP=1 and TP=1, PP=2 passed
- Focused current-stage/MTP/mapping regression tests: 12 passed
- Untied MTP HF-import regression: 2 passed (tied and untied)
- Ruff, Python compile checks, and `git diff --check`: passed

The dedicated Qwen functional verifier checks per-rank shape, dtype, and SHA-256 signatures; same-stage TP/EP replica equality; no overlap between PP-stage streams; and union equality with the baseline full export.

One pre-existing modelopt dynamic-module test is environment-dependent and failed because of an installed modelopt incompatibility. Kimi tests could not be collected on the test host because the optional `fla` dependency was unavailable.

## Follow-up coverage

The current 2-GPU functional matrix does not include TP+PP or EP+PP combined 4-GPU topologies. Cross-PP duplicate LoRA adapter ownership is also not exercised by these tests.
