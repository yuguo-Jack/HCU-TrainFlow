# fix(ckpt): preserve NemotronH checkpoint embedding keys

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6343) · state: closed · merged: True

## Original PR description

# What does this PR do?

Fix NemotronH checkpoint conversion when native Transformers saves the input embedding as `backbone.embedding.weight`. The bridge previously required `backbone.embeddings.weight`, causing strict mapping validation to reject import and PP=2 export.

Fixes NVBug 6612509.

# Changelog

- Select the embedding key present in the source checkpoint, preserving the legacy plural name and config-only behavior.
- Keep strict missing-weight validation and add regression coverage for both spellings, config-only mappings, and missing embeddings.

# GitHub Actions CI

Local validation uses the existing Bridge APIs with a deterministic, four-layer BF16 NemotronH model (`M-M*`, hidden size 512, vocabulary 1024, TP=1/PP=2) on two H100 GPUs. Before the fix, both import and cold export fail the missing-embedding mapping check. With the fix:

- All 29 tensors round-trip exactly; rank results and repeated exports agree.
- Strict save/reload has no missing or unexpected keys, and HF logits match exactly with finite, nonconstant values.
- Cold export without a preceding import has complete finite tensors, matching rank/repeat results, and an embedding equal to the owning Megatron parameter.
- All 91 NemotronH bridge unit tests pass; the new singular-key test fails on the original code.
- Pre-commit hooks and `git diff --check` pass. Strict mypy remains limited by existing typing errors and missing type information in the lightweight local environment.

Remote CI is pending. These checks validate checkpoint export and HF reload, not Megatron forward parity.
