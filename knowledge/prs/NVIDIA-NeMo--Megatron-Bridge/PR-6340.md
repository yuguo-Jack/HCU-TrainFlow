# fix(conversion): sanitize nested PEFT hooks before pipeline export

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6340) · state: closed · merged: True

## Original PR description

## Summary

Pipeline-parallel HF export after PEFT training can fail with `Can't pickle local object '...peft_pre_wrap_hook'` when configuration cleanup leaves nested construction hooks in metadata sent between ranks. The cleanup returns objects unchanged at its recursion limit, and treats `OrderedDict` hook registries as attribute containers without cleaning their entries.

Clean container entries before object attributes, and discard unpicklable subtrees at the depth limit while retaining serializable metadata. The original training configuration and hooks remain unchanged. Regression tests cover both nesting depths used by export and verify that the cleaned copy can be serialized without removing live hooks.

## Validation

- On latest `main` (`19129960d`), ran the exact cleanup function and added regression function in isolation: both depth-2 and depth-3 cases fail before the fix and pass after it. This is a dependency-light check, not a full pytest run on main.
- Earlier container validation on the model-support snapshot passed the conversion-utility tests and a real two-process pipeline object collective with this same fix.
- `uv run pre-commit run --all-files` passed on this branch.

Two files, +45/−13 lines. No dependencies or public API changes. This PR targets `main` and contains only the shared serialization fix and its tests; tutorial and checkpoint-layout changes are excluded. Full model export was not rerun on this main-based branch.

[P2] Sanitize the retained defaultdict factory

**Failure:** Inside a function, construct `cfg = SimpleNamespace(defaults=defaultdict(lambda: 0, head_dim=8))`. At either export depth, cleanup returns successfully, but `pickle.dumps(cleaned)` still fails on the local factory. Unlike mapping entries, `defaultdict.default_factory` is not in `__dict__`, so neither cleanup loop visits it. The [base implementation](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/19129960dea96c8cfcea111af398192cb1953e72/src/megatron/bridge/models/conversion/utils.py#L282-L284) converted this mapping to a serializable ordinary dictionary; the new shallow copy retains its unsafe factory. [QKV export](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/e6a5b8eb9d255a9857d1bf07f9e7caf3034ba59a/src/megatron/bridge/models/conversion/param_mapping.py#L2222-L2228) hands the cleaned configuration to the PP object broadcast, so returning this object defeats the serialization fix.

**Correction:** Clean this standard mapping's factory on the detached copy, using the same known-callable removal contract as its values. Suggested addition immediately after this shallow copy, with `from collections import defaultdict` added to the imports:

```python
if isinstance(obj, defaultdict):
    cleaned_obj.default_factory = remove_non_pickleables(
        obj.default_factory, max_depth, current_depth + 1
    )
```

This suggestion was traced through the branches but not executed; verify it before adoption. The invariant is to remove known runtime leaves without losing stored mapping metadata or mutating the original.

**Preservation / acceptance:** Proposed regression: at depths 2 and 3, the local-factory example must pickle-round-trip as a `defaultdict`, retain `head_dim == 8`, and have `default_factory is None`; the original must retain its callable factory and still return `0` for a missing key. Retain the [existing mapping test](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/e6a5b8eb9d255a9857d1bf07f9e7caf3034ba59a/tests/unit_tests/models/test_conversion_utils.py#L84-L101): `defaultdict(int)` must retain `int` and return `0` for missing keys, while `OrderedDict` must retain order and `.description`, clean function values to `None`, and leave the original hook untouched.

[P2] Preserve stored metadata on sequence subclasses

**Failure:** These early returns now bypass attribute cleanup for every list/tuple subclass, replacing it with a plain sequence and discarding its serializable attributes. Minimal setup, with the class defined at module scope:

```python
class MetadataList(list):
    pass

values = MetadataList([1, 2])
values.head_dim = 8
cfg = SimpleNamespace(values=values)
cleaned = remove_non_pickleables(cfg, max_depth=2)
```

`cleaned.values.head_dim` now raises `AttributeError`; the same happens with `class MetadataTuple(tuple): pass`. The [base object-first branch](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/19129960dea96c8cfcea111af398192cb1953e72/src/megatron/bridge/models/conversion/utils.py#L257-L272) retained these types and attributes. This contradicts the new [no-silent-metadata-discard contract](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/e6a5b8eb9d255a9857d1bf07f9e7caf3034ba59a/src/megatron/bridge/models/conversion/utils.py#L229-L231).

**Correction:** In the list/tuple branches of `remove_non_pickleables`, distinguish ordinary sequences from attribute-bearing subclasses. Reconstruct a detached, type-preserving subclass with cleaned entries, then run the existing raw-attribute cleanup instead of returning early. For mutable list subclasses, a shallow copy plus per-index cleaning provides that path. Tuple reconstruction must respect the subclass's construction/reduction contract; a blanket `type(obj)(items)` is not safe for namedtuple-like constructors. A generic tuple replacement is uncertain from the inspected source, so no universal patch is suggested. The required invariant is preservation of serializable stored attributes and sequence semantics while cleaning runtime leaves and leaving the original unchanged.

**Preservation / acceptance:** Proposed module-level `MetadataList` and `MetadataTuple` regressions should pickle-round-trip with the original subclass type, entries `[1, 2]` / `(1, 2)`, and `head_dim == 8`. Also test an entry containing a local callback: it must become `None` without dropping safe attributes or altering the original entry. Ordinary lists/tuples must still clean callbacks, and the existing [PEFT regression](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/e6a5b8eb9d255a9857d1bf07f9e7caf3034ba59a/tests/unit_tests/models/test_conversion_utils.py#L58-L81) must retain `safe_metadata == {'layers': [1, 2, 3]}` and the original live hooks. Keep the `vars()`-based attribute reads so the previously fixed rejecting-accessor case remains valid. These are proposed checks, not executed results.
