# refactor(model): build Hy V3 and MiniMax-M2 from builder-backed model configs

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6392) · state: open · merged: False

## Original PR description

# What does this PR do ?

Moves **Hy V3** and **MiniMax-M2** onto the builder-backed `ModelConfig` / `ModelBuilder` path for checkpoint conversion, following Muse Glimmer. Neither family has library recipes.

# Changelog

- **`HYV3Bridge`**: `provider_bridge()` is replaced by `hf_config_to_model_config_kwargs()`, and the provider path reuses the same kwargs. The builder config leaves `transformer_layer_spec` unset because MCore's builder default for MoE models is already `get_gpt_decoder_block_spec`, which honors the dense-first `moe_layer_freq`. The deprecated provider path keeps its explicit decoder block spec in `hf_config_to_provider_kwargs()`. The forced bf16 dtype fields carry over. `USE_MODEL_CONFIG_FOR_CONVERSION = True`.
- **`MiniMaxM2Bridge`**: same kwargs migration. The builder config carries `transformer_layer_spec=minimax_m2_layer_spec`; that spec reads only fields the builder config resolves (`num_moe_experts`, `moe_grouped_gemm`), so both paths build the full-dimension QK norm. `rotary_dim` → `rotary_percent` handling is unchanged. `USE_MODEL_CONFIG_FOR_CONVERSION = True`.
- **Tests**:
  - New `tests/unit_tests/models/hy_v3/`; Hy V3 had no bridge unit tests. It covers the builder mapping, provider/builder parity for bf16 and fp16 sources, and `megatron_to_hf_config` from a builder config.
  - MiniMax-M2 covers the builder mapping, parity with and without `rotary_dim`, and layer-spec equivalence between provider and builder config.

# Verification

Each family was validated separately on tiny random-weight checkpoints (single GB200 node, NeMo 26.10 container, transformers 5.15 for both HF models).

**Conversion paths:**
- `scripts/conversion` GPU import at TP2 and export.
- `AutoBridge.import_ckpt` / `export_ckpt`.
- Load + forward as in `compare.py`.
- `roundtrip_checkpoint`.

Each was run on this branch and on `main`.
