# fix(training): reuse Megatron-Core determinism setup under --deterministic

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6271) · state: open · merged: False

## Original PR description

# What does this PR do ?

Make Bridge's `--deterministic` delegate to Megatron-Core's determinism setup (`megatron/training/determinism.py`) instead of a hand-maintained copy that had drifted from it.

# Changelog

- `ConfigContainer._validate_and_apply_deterministic_mode` calls `apply_determinism_to_args`: required option values (cross-entropy loss fusion, TP comm overlap, MoE aux-loss fusion), env-var validation and defaults, and torch deterministic algorithms.
- `apply_determinism_overrides` disables only the MoE aux-loss fusion (fused TopK routing stays on, per NVIDIA/Megatron-LM#6967), exports Megatron-Core's `DETERMINISM_ENV_VAR_DEFAULTS` at launch, and pins `MAMBA_DETERMINISTIC` / `CAUSAL_CONV1D_DETERMINISTIC`.
- Tests: new `test_determinism_utils.py`; `test_config.py` covers the rejected options, env validation/defaults and the torch state; `test_recipe_environment.py` expects Megatron-Core's string value `"0"` for `NVTE_ALLOW_NONDETERMINISTIC_ALGO`.

**Behavior changes (inherited from Megatron-Core's rules):**

| | before | after |
|---|---|---|
| `NCCL_ALGO=Tree` | accepted | rejected (Megatron-Core accepts Ring, CollnetDirect, CollnetChain, ^NVLS) |
| unset `NCCL_ALGO` | assertion error | defaults to `Ring` |
| `NVTE_ALLOW_NONDETERMINISTIC_ALGO` set to a non-deterministic value | not checked | rejected |
| MoE aux-loss fusion | not checked | must be off (set by `--deterministic`) |
| `torch.utils.deterministic.fill_uninitialized_memory` | on (torch default) | off |

No Megatron-LM bump needed: the pinned Megatron-LM already provides `megatron/training/determinism.py` and `moe_router_aux_loss_fusion`.

Context: this came out of making DeepSeek-V3 MXFP8 on 256 GB300 GPUs bitwise reproducible; a 50-step A/B with this setup (plus kernel-level fixes outside this repo) matched on all 550 logged metric values. A follow-up PR adds the deterministic DSv3 GB300 recipe on top of this change.
