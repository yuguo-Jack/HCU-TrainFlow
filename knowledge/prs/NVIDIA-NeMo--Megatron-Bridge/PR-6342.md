# LoRA: Stop pre-quantizing input to LoRA branch

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6342) · state: closed · merged: True

## Original PR description

# What does this PR do ?

With FP8 delayed scaling, we preemptively quantize the LoRA branch input to enable a fused RMSNorm + FP8 quant kernel and a [FP8 dropout+dequant kernel](https://github.com/NVIDIA/TransformerEngine/pull/2014). However, this does not generalize to more modern recipes like MXFP8 and NVFP4, so this PR removes this optimization.

Previous FP8 path:
```
-> RMSNorm+quant -> main GEMM -> ...
                \-> dropout+dequant -> LoRA A GEMM -> ...
```
Previous NVFP4 path:
```
-> RMSNorm -> quant -> main GEMM -> ...
                   \-> dequant -> dropout -> LoRA A GEMM -> ...
```
New path for both FP8 and NVFP4:
```
-> RMSNorm -> quant -> main GEMM -> ...
          \-> dropout -> LoRA A GEMM -> ...
```
