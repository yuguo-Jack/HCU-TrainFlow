## Background

Nightly Megatron-Core bump for the `main` lane. The `dev` lane is paused, so `.dev.commit` is unchanged.

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` gitlink: `fde43b6d` → `a8a5977f7611e9a8aac205eabd2f9b43f786bc8f` (17 MCore commits).
- `uv.lock` regenerated with `uv lock --upgrade`. Only minor bumps: aiohttp, narwhals, platformdirs, python-discovery, soupsieve and the deep-gemm git rev. `nvidia-modelopt` stays at `0.46.0rc1` through the existing Bridge override, even though MCore's dev extra now asks for `>=0.47`.
- `tests/unit_tests/models/qwen_vl/modelling_qwen3_vl/test_text_model_forward.py`: removed the `runtime_gather_output` argument, which NVIDIA/Megatron-LM#7682 dropped from `process_mtp_loss`.

## Details

Areas of the MCore delta with Bridge consumers:
- multi-token prediction: padding mask, loss signature
- Gated DeltaNet: new `gdn_kernel_backend` setting, TE adapter
- Mamba/SSM: Triton autotune moved to `megatron.core.tuning`
- MoE: fused shared-expert residual add, aux-loss clamp
- Megatron-FSDP v2
- generalized tensor parallelism: grad fix
- clamped SwiGLU backward
- Megatron-LM training arguments

Bridge dependency metadata already matches MCore at this pin; no edits were needed.

## Tested

- `uv lock --check` passes (uv 0.7.2, matching `docker/Dockerfile.ci`).
- `ruff check` and `ruff format --check` pass on the changed test file.
- Local GPU unit and functional tests were **skipped at the requester's direction**. Main CI is the validation gate for this PR.
