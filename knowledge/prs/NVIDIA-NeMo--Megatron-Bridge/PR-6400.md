# docs(model): verify Gemma 3 4B card SFT on 8 H100 GPUs

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6400) · state: closed · merged: True

## Original PR description

# What does this PR do ?

The Gemma 3 4B card's SFT command asked for 1 GPU, which runs out of memory on an H100 80GB. QA re-ran the published command on 8 H100s, it passed, and the item is now verified with that run's metrics.

# Changelog

- `examples/model_verification_cards/gemma-3-4b-it/card.yaml`: sft.H100 `--gpus-per-node 1` -> `8`; status verified; item `bridge_commit` b2ebece6a; `last_verified` 2026-10-09; QA metrics and expected result; verification index and summary updated.
- `docs/_static/model-verification/catalog-v1.json`, `docs/models/gemma/gemma3-vl.md`, `docs/fern/versions/nightly/pages/models/gemma/gemma3-vl.mdx`: regenerated.
- `tests/unit_tests/skills/create_model_verification_card/test_validate_card.py`: audited entry for the new leaf; asserts each verified training leaf's published nodes x GPUs equals the GPU count its metrics were measured on.

# Additional Information

- **Root cause:** the card prescribed 1 GPU for full SFT of `gemma3_vl_4b_sft_config` (TP1/PP1); unsharded fp32 grads and optimizer state do not fit in 80 GB.
- **QA run:** EOS job 6223695 (import on 4 H100 + SFT on 8 H100, both completed) in `nvcr.io/nvidia/nemo:26.06`; Bridge `b2ebece6a` (main squash of the card's recorded `330f87c0`), MCore `cd4afffa6`.
- **Result:** 10/10 steps, GBS 32, seq 4096, 0 skipped / 0 NaN iterations, iteration-10 checkpoint saved. Metrics (mean of all 10 rows incl. cold start, same policy as other cards): loss 1.163850 -> 0.143927; 5461.010 ms/step; 22.450 TFLOP/s/GPU; 3000.178 tokens/s/GPU.
- **Test:** fails on main, fails if the command is set back to 1 GPU, passes on this branch. `validate_card.py` valid; catalog `--check` clean; card/doc-consistency tests pass.
- **Follow-up (not in this PR):** the recipe is still named and documented as 1-GPU (`gemma3_vl_4b_sft_1gpu_h100_bf16_config`, "Default configuration: 1 GPU"), and the card's `peft` item still prescribes 1 GPU and has not been run.

- **NVBug:** 6631271.

**Failure:** The PR identifies the new SFT measurements as coming from `nvcr.io/nvidia/nemo:26.06`, but this commit override leaves the card's [verification environment](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b9a4f59871063fcda4d60fac2d971da11ce9eeb7/examples/model_verification_cards/gemma-3-4b-it/card.yaml#L35-L37) at `nvcr.io/nvidia/pytorch:26.04-py3`. The published provenance should describe the environment that produced these metrics, not merely its Bridge checkout.

**Correction:** The current format permits a leaf commit override but no leaf container override. Either rerun this SFT workload in the declared PyTorch container and record that result, or add a supported public per-leaf container override before retaining the reported NeMo run. The latter requires corresponding changes to `ITEM_KEYS`, `_validate_item`, the public-container exemption in `_validate_privacy`, and `_entry`/`normalize_card`, plus regeneration. Do not simply replace the global container: that would relabel the older conversion and inference evidence. No YAML-only patch is safe without deciding which provenance contract to use.

**Preservation:** Keep the 1-node/8-GPU command and its audited topology. Preserve the existing environment for earlier conversion, forward-pass, and inference items, and leave PEFT and post-SFT export/inference unverified.

**Acceptance — proposed/static checks:** If an override is added, use a fixture with the existing PyTorch default and the NeMo container on SFT only; validation must accept both public identifiers, normalized SFT provenance must be NeMo 26.06, and all other entries must retain the PyTorch default. If rerunning instead, check that the QA environment and published container agree and replace the five metrics with that run's observations. In either case, regenerate the catalog and guides and retain the 8-GPU throughput assertion. These checks were not executed.

- svcnvidia-nemo-ci · comment · 2026-10-09T22:31:02Z · [source](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6400#discussion_r4235060083)

File: `tests/unit_tests/skills/create_model_verification_card/test_validate_card.py` · line 516

Accept supported equals-form resource options in this audit.

**Failure:** Changing only the Gemma command to `--nodes=1 --gpus-per-node=8` preserves its launcher behavior and GPU count, but `argv.index("--nodes")` now raises `ValueError`. Both forms are accepted by the [launcher parser](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b9a4f59871063fcda4d60fac2d971da11ce9eeb7/scripts/training/setup_experiment.py#L78-L85) and the [card validator's argument parsing](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b9a4f59871063fcda4d60fac2d971da11ce9eeb7/skills/create-model-verification-card/scripts/validate_card.py#L739-L741). This test should reject a topology mismatch, not an equivalent supported spelling.

**Correction:** Replace the resource extraction at this location with parsing of both canonical option forms. A small suggested replacement, retaining the existing `shlex.split`, is:

```python
options = {}
for i, token in enumerate(argv):
    name, separator, value = token.partition("=")
    if name in {"--nodes", "--gpus-per-node"}:
        options[name] = int(value if separator else argv[i + 1])
published_gpus = options["--nodes"] * options["--gpus-per-node"]
```

The invariant is that equivalent accepted resource arguments produce the same audited total. Please verify the suggestion before adopting it.

**Preservation:** Keep the existing spaced arguments working for direct training leaves, both independently commanded FSDP precision variants, and every weak-scaling point. Preserve the equality check against the audited GPU count and the existing TPS/GPU calculation; unverified leaves must still have null TPS.

**Acceptance — proposed checks:** Test spaced, equals-form, and mixed forms of `1 × 8`, all expecting 8. Retain the existing FSDP `2 × 4 = 8` cases and Qwen weak-scaling totals 8, 32, 128, and 256. The shipped Gemma command must pass with 8 GPUs and still fail the equality assertion when changed to 1 GPU with its audit and metrics unchanged. These outcomes follow from source inspection; tests were not executed.
