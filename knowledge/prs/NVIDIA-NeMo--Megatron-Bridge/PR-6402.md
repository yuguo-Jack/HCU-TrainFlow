# docs(model): teach builder-backed model configs in the adding-model-support skill

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6402) · state: open · merged: False

## Original PR description

# What does this PR do ?

Updates the `adding-model-support` skill to teach the builder-backed `ModelConfig` / `ModelBuilder` path instead of `provider_bridge()` / `to_megatron_provider()`. Documentation only; no code changes.

The skill still directs new bridges to override `provider_bridge()`. For a family that only does that, `get_model_config()` returns a config built from `CONFIG_MAPPING` alone, and every attribute set in `provider_bridge()` is silently dropped. Its YaRN example also described `yarn_*` as fields missing from the provider; since #6365 they are declared on Bridge `TransformerConfig`.

# Changelog

- **`SKILL.md`**:
  - LLM bridges implement `hf_config_to_model_config_kwargs()`, make `hf_config_to_provider_kwargs()` return the same kwargs, and set `USE_MODEL_CONFIG_FOR_CONVERSION = True`.
  - Models that `BridgeGPTModelConfig` cannot represent (multimodal, hybrid) get a `ModelConfig` subclass and a `ModelBuilder`, following Muse Glimmer.
  - The hook table marks `provider_bridge()` as legacy.
  - Recipes use `get_model_config()`, and the smoke test builds through `get_model()`.
  - The LLM reference moves from Qwen2 to Qwen3 (Qwen2 is not migrated yet).
- **`llm-patterns.md`**:
  - Model config pattern and a full bridge example.
  - Table of the three defaults that differ between the builder config and the legacy provider: `position_embedding_type`, `masked_softmax_fusion` and `rope_scaling_factor`. Missing one of these silently changes the model.
  - Layer-spec guidance, including that MCore's builder default handles dense-first MoE.
  - YaRN guidance that replaces the stale provider-subclass example.
  - A checklist for migrating an existing provider-based bridge.
- **`recipe-patterns.md`**: recipes use `get_model_config()`; the recipe-test pattern uses a strict builder config and rejects the provider API.
- **`tests-and-examples.md`**: builder unit-test template covering config mapping, provider/builder parity, and the conversion flag.
  - Also fixes the existing mapping-registry template, which raised `TypeError` because `QKVMapping.hf_param` is a dict.
  - Replaces the `Mock()` HF config, which fails on both paths because unset attributes such as `hidden_act` come back as `Mock` objects.
- **`vlm-patterns.md`**: adds the builder-backed multimodal pattern (Muse Glimmer) and labels the provider snippets as legacy.
- **`parity-testing/SKILL.md`**: config-mapping checks point to `hf_config_to_model_config_kwargs()` first.

# Verification

The snippets were run against `main` (MCore 8949def81) in the NeMo 26.10 container, with Qwen3 standing in for the placeholder model:

- **Snippets:** the unit-test template, the recipe-test stub, and the bridge example from `llm-patterns.md` were extracted from the Markdown and executed. 16 tests passed.
- **Defaults table:** measured on a bridge with no overrides. Builder: `learned_absolute`, `False`, `8.0`. Provider: `rope`, `True`, `1.0`.
- **Other claims checked:**
  - Unknown kwargs raise `ValueError`.
  - Undeclared attribute assignment raises `AttributeError`.
  - Flat assignment routes to the nested transformer config.
  - `AutoBridge.from_hf_config(...).get_model_config()` works.
  - Qwen3 fills the HF YaRN defaults.
- **Smoke test:** the `SKILL.md` smoke snippet (`get_model_config()` → `get_model()` → `export_hf_weights()`) passed on one GB200 GPU with a tiny Qwen3 checkpoint.
