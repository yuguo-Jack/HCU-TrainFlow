# Migrate GLM from GPTModel to HybridModel

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6158) · state: closed · merged: True

## Original PR description

# What does this PR do ?

This PR aims to migrate GLM-5 series models arch from legacy `GPTModel` to new `HybridModel`.

# Changelog

- `glm5_bridge.py`: register `target=HybridModel, provider=GLM5ModelProvider`; derive `hybrid_layer_pattern` / `moe_layer_freq` from the HF config; `megatron_to_hf_config` maps 156 physical layers back to 78 HF layers; MTP mappings target the `/DE` MTP pattern; `hf_config_to_model_config` raises `ModelConfigNotSupportedError` instead of silently building a GPT model.
- `glm5_provider.py` (new `GLM5ModelProvider(HybridModelProvider, MLATransformerConfig)`): validates the `D-/DE` pattern, auto-splits pipeline stages on DSA compute layers so index-sharing groups stay whole (`split_glm_pattern`), rejects VPP and selective `core_attn` recompute, enables `sequence_parallel` for TP>1 (AbsorbedMLA requirement), derives physical `num_layers` / `moe_layer_freq` and the MTP override pattern.
- `glm5_hybrid.py` (new): `GLMHybridStack` rescales the HF index-sharing cadence to physical layer coordinates and replays a whole stage under full recompute; `GLMHybridMTPLayer` reuses the same stage runner for the nested MTP stack; private `glm_hybrid_stack_spec`.
- `glm5_hybrid.py`: forward-local DSA top-k state is scoped with a `ContextVar` read by a thin `GLMDSAttention` subclass instead of attributes injected on mask/packed-seq/config carriers.
- `training/model_load_save.py`: single-rank flex→allgather dispatcher fallback also disables `moe_shared_expert_overlap`.
- `training/utils/flop_utils.py`: reuse the DSA FLOPs estimator in logical coordinates for `D-/DE` hybrid patterns (incl. MTP and top-k reuse).
- Recipes (`recipes/glm/{h100,gb200}`, `perf_recipes/glm_moe_dsa/{h100,gb200}`): explicit per-stage `block_counts` via `split_glm_pattern`; VPP disabled.
- Tests: bridge/provider/recipe/FLOPs unit tests updated for the Hybrid layout; new `test_glm5_provider.py`; functional toy conversion adds the GLM-5.2 index-share strict round-trip and checks HF config keeps the logical layer count.
- Model cards + docs (`glm5`, `glm5-2`): GB200-only; verified on real checkpoints with the Hybrid path — GPU import, GPU/CPU export (bit-exact vs. source, MTP excluded by default) and deterministic legacy full-prefix inference; H100 entries removed, `manual_forward_pass` and training items remain unverified.

Breaking: GPT-layout GLM checkpoints and optimizer states are not migration inputs — re-import from the pinned HF revision into a fresh Hybrid checkpoint root.

## Review: Migrate GLM from GPTModel to HybridModel (light, broad)

I reviewed all 43 changed files. For the 33 files left out of the inline diff, I compared head against base directly. The core migration looks correct:
- **Provider:** pattern derivation, the PP split that keeps each DSA sharing group whole, and the rejections for VPP and selective `core_attn` recompute.
- **Bridge:** the 156↔78 layer coordinate mapping and the `/DE` MTP mappings.
- **FLOPs:** the estimator in logical coordinates.
- **Recipes:** the `split_glm_pattern` block counts sum to 78 and start every stage on a compute layer.
- **Conversion:** distributed CPU import validation in `run_conversion`/`setup_conversion`.
- **Scripts:** `compare.py` `_build_inference_context` and the `verify_hf_inference.py --tp-plan` path.

I also re-derived the training throughput numbers recorded in both cards from tokens per step, step time and GPU count. They are consistent.

**Prior review comment, now fixed.** cuichenx's point on `glm5_hybrid.py` ("`value` could be None on non-first pipeline stages") is fixed in head. [`_forward_glm_stack`](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/fafe304122c7acbd7eebd6e3dbb3566abab436b9/src/megatron/bridge/models/glm_moe_dsa/glm5_hybrid.py#L61-L84) now resolves `stack.input_tensor` before the checkpoint. It also points `input_tensor` at the checkpointed `value` during the run and restores it afterwards. `test_non_first_stage_full_recompute_keeps_autograd_graph` and `test_run_restores_input_tensor_when_stage_forward_raises` cover this.

### Findings

As a result, these "verified" entries can't be reproduced with the public launcher, and the new `compare.py --legacy-full-prefix` flag can't be reached through it. (Inline comment on the glm5 card.)

4. **Non-blocking (low):** the conversion README's intro and its export section still describe distributed CPU conversion as export-only.
5. **Non-blocking (low, missing test):** nothing tests the new `gpu_backend.import_checkpoint(use_cpu=True)` path, which uses Gloo/CPU init and rejects `--low-memory-save`.
6. **Non-blocking (low, outdated docstring):** `test_glm5_h100_parallel_topology` still documents VPP2 while asserting VPP is `None`.
