# docs(misc): point GB200 fine-tunes at the card's own import

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6366) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes five verified GB200 fine-tune commands on the Qwen3.6-35B-A3B and DeepSeek-V4-Flash cards that load a `--pretrained_checkpoint` no item on their card writes, by pointing them at the card's own GPU import.

# Changelog

- `examples/model_verification_cards/qwen3.6-35b-a3b/card.yaml`: GB200 `sft`/`peft` read `imported-megatron/iter_0000000` instead of `gb200-imported/iter_0000000`.
- `examples/model_verification_cards/deepseek-v4-flash/card.yaml`: GB200 `sft`/`sft_long_context`/`peft` read `dsv4-flash/import-gpu/iter_0000000` instead of `work/models/deepseek-v4-flash-megatron`.
- `docs/_static/model-verification/catalog-v1.json`, `docs/models/...`, `docs/fern/.../*.mdx`: regenerated (`--check` passes).

# Additional Information

- **Root cause:** the card's import writes one directory and the fine-tunes read another. The H100 siblings (Qwen) and `pretrain.GB200` (DeepSeek) already read the import path. Same class as #6286.
- **Unchanged:** statuses, dates, metrics and hardware claims. Only the paths changed. No GB200 rerun was done.
- **Regression?** No. The paths have been wrong since the items were added (#5055, #5724).
- **Verification:** each new path equals the `--megatron-path` written by the card's own `hf_to_megatron_gpu` item. `validate_card.py` passes for both cards, `generate_model_verification_catalog.py --check` is clean, and the card/catalog/doc-consistency unit tests pass (70). QA's card audit (nmfw_tests) flagged exactly these 5 leaves on main.
- **Left for maintainers:** GLM-5.2 GB200 `sft`/`sft_long_context` read a Hugging Face directory (`glm5-2/hf-<rev>`) that no item stages. They are not changed here, because repointing would change the checkpoint format.
- **NVBug:** 6875021.

**Failure (source reasoning):** This walker stops at the hardware container, but supported cards also publish commands under `variants` and `points`. For example, appending `--pretrained_checkpoint work/missing` to the [Lightning BF16 FSDP variant](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/3a2884ca8bbbfb5e7ad992a003c3a62ff4b9418d/examples/model_verification_cards/nemotron-3.5-lightning/card.yaml#L237-L260) produces no reader here: the outer GB200 record has no command. The same omission affects [Qwen weak-scaling points](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/3a2884ca8bbbfb5e7ad992a003c3a62ff4b9418d/examples/model_verification_cards/qwen3-30b-a3b/card.yaml#L587-L600), which inherit their status. The new guard therefore overlooks these unwritten paths instead of rejecting them, although [checkpoint loading rejects a missing pretrained directory](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/3a2884ca8bbbfb5e7ad992a003c3a62ff4b9418d/src/megatron/bridge/training/checkpointing.py#L2536-L2543).

**Correction:** Scan the complete command tree and retain each concrete configuration’s identity. The existing `_walk_commands` already traverses variants, points, and ordered command lists. Suggested, unexecuted replacement for `_unproduced_checkpoints` in [this file](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/3a2884ca8bbbfb5e7ad992a003c3a62ff4b9418d/tests/unit_tests/doc_consistency/test_verification_card_published_commands.py#L173-L191); verify before adopting:

```python
def _unproduced_checkpoints() -> dict[str, str]:
    unproduced = {}
    for slug, document in _card_documents():
        writers, readers = [], []
        for location, command in _walk_commands(document.get("items") or {}):
            key = location.rsplit("/", 1)[0].lstrip("/")
            item = key.split("/", 1)[0]
            for tokens in _leaf_invocations({"command": command}):
                if item.startswith("hf_to_megatron"):
                    writers += [(key, path) for path in _option_values(tokens, "--megatron-path")]
                writers += [(key, path) for path in _option_values(tokens, "--save_dir")]
                readers += [(key, path) for path in _option_values(tokens, "--pretrained_checkpoint")]
        for key, path in readers:
            if not any(
                writer != key and (path == written or path.startswith(written + "/"))
                for writer, written in writers
            ):
                unproduced[f"{slug}/{key}"] = path
    return unproduced
```

**Preservation:** Direct imports and ordinary hardware leaves retain their existing identities, so the five repaired commands and GLM baseline keys remain unchanged. Ordered commands within one configuration remain the same leaf and cannot manufacture a different-leaf producer. Distinct variants or points must remain distinct, including when one legitimately consumes another’s saved checkpoint.

**Acceptance (proposed tests):** Monkeypatch `_card_documents` with a direct import at `work/c/imported`, an H100 SFT reader of its `iter_0000000`, a GB200 FSDP variant reading `work/missing`, and a weak-scaling point reading another missing path. `_unproduced_checkpoints()` must report the variant and point with their full identities, but not H100 SFT. Repoint those nested readers to the import and expect `{}`. Also check that a different variant’s `--save_dir` can satisfy a reader, while that reader’s own save directory cannot. Retain the existing regression assertion identifying only `card/sft/GB200`.

**Failure (source reasoning):** With the existing regression fixture, change the invalid GB200 argument to `--pretrained_checkpoint=work/c/gb200-imported/iter_0000000`. This helper returns no reader value, so `_unproduced_checkpoints()` no longer reports GB200. That is a supported argparse spelling of the option declared by [the training parser](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/3a2884ca8bbbfb5e7ad992a003c3a62ff4b9418d/scripts/training/run_recipe.py#L253-L257), and [the launcher forwards training arguments unchanged](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/3a2884ca8bbbfb5e7ad992a003c3a62ff4b9418d/scripts/training/setup_experiment.py#L303-L305). Conversely, using `--save_dir=work/c/trained` hides a legitimate producer and falsely rejects a matching reader. The guard should give the same result for both option-value forms.

**Correction:** Replace `_option_values` in [this file](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/3a2884ca8bbbfb5e7ad992a003c3a62ff4b9418d/tests/unit_tests/doc_consistency/test_verification_card_published_commands.py#L168-L170) with the following suggested, unexecuted implementation, and verify it before adopting:

```python
def _option_values(tokens: list[str], flag: str) -> list[str]:
    values = []
    for index, token in enumerate(tokens):
        if token == flag and index + 1 < len(tokens):
            values.append(tokens[index + 1].rstrip("/"))
        elif token.startswith(flag + "="):
            values.append(token[len(flag) + 1 :].rstrip("/"))
    return values
```

**Preservation:** Keep separate-token parsing, all occurrences, trailing-slash normalization, and exact flag matching. Apply the same parsing to `--pretrained_checkpoint`, import `--megatron-path`, and training `--save_dir`; do not alter checkpoint-format selection or the GLM exceptions.

**Acceptance (proposed tests):** Parameterize the existing regression fixture over separate-token and equals-form reader options; both must return the same unwritten GB200 path and accept the valid H100 import reader. For a producer at `work/c/imported/`, test both forms of `--megatron-path` and expect its `iter_0000000` reader to be accepted. For a different training leaf saving to `work/c/trained/`, test both forms of `--save_dir` and expect a matching reader to be accepted. A similarly named option such as `--save_directory=...` must not count as a producer.
