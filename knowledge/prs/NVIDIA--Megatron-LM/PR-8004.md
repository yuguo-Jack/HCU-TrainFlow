# Add semantic per-head Muon for fused projections

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8004) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Add opt-in **per-head Muon with semantic projection routing**. Fused attention/GDN weights can contain independent heads and output/control gates; this change applies independent matrix updates to the heads and AdamW to the control rows, while retaining fused model weights and forward GEMMs.

```bash
--optimizer muon --muon-split-qkv-per-head --use-distributed-optimizer
```

The flag defaults to false. Existing upstream Muon routing and global gradient clipping remain unchanged when it is absent.

## Issue tracking

The shared splitting API and landing sequence are being discussed with #6326; see the [integration proposal](https://github.com/NVIDIA/Megatron-LM/pull/8004#issuecomment-6094928018).

## Implementation

| Projection | Muon matrices | AdamW slices |
| --- | --- | --- |
| Standard/output-gated attention | Each Q/K/V head | Output gate |
| GDN1 | Each Q/K/V head | z, beta, alpha |
| GDN2 | Each Q/K/V head, from the variant's actual section table | z, f, b, w |
| Dense SwiGLU FC1 | Separate gate/up feature matrices | None |
| MLA | Per-head up-projection components; separate latent/RoPE down components | None |

- Batch equal-sized matrices with independent normalization, Gram matrices and real-shape scaling. Retain individual 2-D calls for older Emerging-Optimizers and SYRK.
- Reconstruct fragmented TP/GTP heads, exclude padding, and restore shard order. Handle TP-local SwiGLU storage and fused MLA down-projection reordering explicitly.
- Copy layout metadata to master parameters. Use raw gradients, configured Adam betas/epsilon, scheduled group LR and decoupled decay for mixed AdamW rows.
- Preserve per-parameter AdamW update counters when gradients are absent; reject incompatible older semantic optimizer states.
- Integrate with current upstream group resolution and optimizer registry. Reject per-head + `muon_tp_mode='layer_sharded'`; keep the existing whole-matrix backend usable when per-head is disabled.

## Compatibility and remaining validation

- Kitchen is unsupported in per-head mode and rejected explicitly. Flattened semantic Muon parameters are rejected; Muon matrix ownership must use the layer-wise path.
- The GPU unit tests above are complete. **Full training and official upstream GPU CI on this commit remain unvalidated**. Earlier downstream training results are not presented as validation of this port.
- Ordinary state-dict resume and sharded-state conversion are tested; **native distributed on-disk checkpoint save/load/resume remains unvalidated**. Distributed checkpoints require equal per-parameter step counters and reject divergent counters.
- Mixed AdamW routing supports plain Muon with decoupled decay. Mixed AdaptiveMuon/coupled-L2 routing is rejected. Grouped MoE expert FC1 layouts remain outside the dense SwiGLU change.
- Adam moments use full parameter-shaped tensors for native sharding, increasing optimizer-state memory. Incompatible all-Muon/older semantic checkpoints require loading model weights with a fresh optimizer (`--no-load-optim`). No topology-changing resume or universal loss/speed improvement is claimed.

- Copilot · comment · 2026-10-10T05:21:24Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8004#discussion_r4236538880)

File: `megatron/core/optimizer/emerging_optimizers.py` · line 495

This semantic path assumes that every optimizer parameter remains a 2-D row-sharded projection, but `DistributedOptimizer` replaces each model parameter in the inner optimizer's `param_groups` with a flattened 1-D data-parallel shard (see `distrib_optimizer.py:509-511` and `:593-603`). On the first step, `_semantic_plan` therefore uses `p.shape[0]` as a row count and later accesses `grad.shape[1]`, so `--use-distributed-optimizer` will either reject a valid projection layout or fail on the flattened gradient instead of applying per-head updates. Preserve the original 2-D shape and shard offsets for semantic parameters, or explicitly reject this mode before constructing the distributed optimizer.

This issue also appears on line 495 of the same file.

- Copilot · comment · 2026-10-10T05:21:24Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8004#discussion_r4236538889)

File: `megatron/core/transformer/mlp.py` · line None

This metadata assumes the physical FC1 rows are `[gate_local, up_local]`, but the surrounding constructor sets `fc1_stride = 1` when `config.use_kitchen` is enabled (lines 208-216). In that configuration TP stores a contiguous output slice rather than the interleaved local halves, so per-head mode splits/orthogonalizes unrelated gate rows as two feature matrices and can mix gate/up boundaries. Do not attach this `tp_local` layout for the stride-1 Kitchen path, or add a layout/reconstruction that matches its actual storage order.
