# What does this PR do?

Add an unpadded layout for MFSDP v2 RowAtomic/BlockAtomic parameter groups: tensors are packed back to back and rank boundaries snap to the nearest row (32-row block for MXFP8) boundary, giving generally unequal shards with zero padding.

Currently, every group is padded to a multiple of `dp_size * LCM(row sizes)` (`* 32` for MXFP8). For groups mixing many row widths this is large: the DeepSeek-V3-shaped dense group measured for #7585 pads 13% at DP=4 and over 80% at DP=16.

Changes:
- `GlobalLayout.build_for_row_atomic_unpadding`: padding-free builder; shards differ by at most one row/block and may be empty.
- `GlobalLayout.validate_for_row_atomic`: checks only that no rank boundary splits a row/block of the tensor it falls in, instead of requiring equal segments and globally aligned offsets. Padded layouts still pass.
- `DBuffer`: the list-based `all_gather`/`reduce_scatter` paths slice per-peer chunks via `GlobalLayout.get_peer_ranges`, so uneven layouts work on multi-axis (HSDP/HFSDP) meshes, not only TensorAtomic on 1-D.
- `QuantizedDBuffer`: scale-plane layouts derive from the unpadded data layout.
- Knob: `fully_shard(uneven_shards=...)`, `DistributedDataParallelConfig.megatron_fsdp_uneven_shards`, `--megatron-fsdp-uneven-shards`. Incompatible with `nccl_ub` (symmetric memory needs equal shards); default behavior is unchanged.

Tests: layout builder/validation, 1-D and 2-D DBuffer round trips, QuantizedDBuffer planes with empty ranks, MXFP8 MLP training parity, SGD/HFSDP parity, adapter flag, all parametrized against the padded default. `tests/unit_tests/distributed/mfsdp_v2` passes on 4xGB200.
