# What does this PR do?

This PR adds an opt-in `share_rotary_pos_emb` flag (default off) that collapses all identically-configured rotary modules to a **single shared instance**. It is numerically exact and reversible.

## What changed

- `maybe_share_rotary_pos_emb(config, cache_key, rotary_pos_emb)` helper: returns the module unchanged when off; otherwise caches the first module per `cache_key` on the config and reuses it (sharing scoped per-model).
- `MLATransformerConfig.share_rotary_pos_emb: bool = False` + `--share-rotary-pos-emb`.
- One call-site in each MLA-family variant (`MultiLatentAttention`, `AbsorbedMLASelfAttention`, `DSAIndexer`, `DSv4HybridAttention`), keyed by the rotary config so distinct configs get distinct shared instances.

Default off + unconditional call → the default path is a no-op.

## Memory gain — DSv4-flash, 1M seqlen, 128× GB200

Per attention layer, at `S = 1,048,576` and `d = qk_pos_emb_head_dim = 64`:

| buffer  | dtype | size            |
|---------|-------|-----------------|
| `emb`   | fp32  | S·d·4 = 256 MiB |
| `cos`   | bf16  | S·d·2 = 128 MiB |
| `sin`   | bf16  | S·d·2 = 128 MiB |
| **total** |     | **512 MiB**     |

The last pipeline stage has **21 attention layers** with the same rotary config (snapshot confirms 21 identical copies/rank): `21 × 512 MiB ≈ 10.5 GiB/rank` duplicated. Sharing collapses 21 → 1, reclaiming ~10 GiB/rank.

Measured peak reserved memory (last-stage rank):

| run                      | baseline  | shared RoPE | gain                  |
|--------------------------|-----------|-------------|-----------------------|
| eager                    | 137.5 GiB | 125.2 GiB   | **−12.2 GiB (−8.9%)** |
| chunk-graph (CUDA graph) | 156.7 GiB | 146.9 GiB   | **−9.8 GiB (−6.3%)**  |

## Correctness

The shared buffers are a function of `(rotary config, position)` only, so all same-config layers compute identical `cos`/`sin`; sharing changes the module object, not any value. Rotary modules have no parameters and their `cos`/`sin` are `persistent=False` buffers allocated lazily on first forward, so discarded duplicates never allocate them and the state dict is unchanged.

## Testing

`tests/unit_tests/transformer/test_shared_rotary_pos_emb.py`: helper-contract checks plus a two-layer MLA proxy (`rope`/`yarn`) that runs one forward/backward off vs on (identical weights, dropout off) and asserts **bit-identical loss** and matching grad norm. Validated on GB200.

## Strict review: shared rotary position embeddings for MLA-family layers

The review found nothing that must be fixed. There is one should-fix memory issue and one docstring correction. With the flag off (the default), behavior is unchanged: [`maybe_share_rotary_pos_emb`](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/models/common/embeddings/rotary_pos_embedding.py#L36-L64) hands back the module it was given and never touches the config.

**Findings:** CRITICAL: 0, IMPORTANT: 1, SUGGESTION: 1

1. **[IMPORTANT Performance]** The module cache is stored on the config, so `deepcopy(config)` clones it. [`SharedExpertMLP.__init__`](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/transformer/moe/shared_experts.py#L124) deep-copies the config for every MoE layer that has shared experts. Each of those layers then carries private, never-used copies of the cached rotary modules. For YaRN that includes the GPU cos/sin tables built in `__init__` and the `cp_group` handle. A small `__deepcopy__` patch is in the inline comment.
2. **[SUGGESTION Other]** The helper docstring has two inaccuracies:
   - It says cos/sin buffers are allocated lazily, but [`YarnRotaryEmbedding.__init__`](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/models/common/embeddings/yarn_rotary_pos_embedding.py#L98-L104) builds them eagerly.
   - It says sharing is scoped to one model; it is actually scoped to the config object.

**What I checked and found correct:**
- **Cache keys.** `(rope_type, rotary_base)` is enough for MLA, AbsorbedMLA and the DSA indexer. All three build identical modules from the same config fields (`qk_pos_emb_head_dim`, `rotary_percent`, YaRN params, `pg_collection.cp`). DSv4 uses keys of the form `(bool, base)`, which cannot collide with those.
- **No cache thrash after sharing.** MLA and the DSA indexer call `get_cached_cos_sin` with the same `seq_len`, dtype, `packed_seq` and `mscale=None`. DSv4 attention, its compressor and its indexer all pass `mscale=1.0`. The cos/sin cache only rebuilds when it has to grow, and slicing a prefix of a longer table is exact here:
  - CP slicing only happens for non-packed input with CP > 1.
  - DSv4/CSA reject CP > 1 unless the format is THD.
  - All MLA/DSA callers ask for the same length.
- **Checkpoints.** The state dict is unchanged: no parameters, non-persistent buffers, and `_load_from_state_dict` drops `inv_freq`.
- **CLI wiring.** `--share-rotary-pos-emb` reaches `MLATransformerConfig` through the `dataclasses.fields` loop in `core_transformer_config_from_args`.
- **Test.** The new test confirms the wiring (`is` checks) and that sharing on/off gives bit-identical loss for `rope` and `yarn`.

**Overall risk: low.** The feature is opt-in and does not change numerics on the paths I traced. The remaining issue is hidden module state on a config dataclass that the codebase routinely deep-copies.

Limitation: the style guide referenced by the review skill (`style-guide.md` at the repo root) is not in the base tree, so no style audit was done against it.

**[IMPORTANT Performance]** Because the cache lives on the config, every deep copy of the config clones it.

**Failure**
- [`SharedExpertMLP.__init__`](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/transformer/moe/shared_experts.py#L124) runs `config = deepcopy(config)`.
- [`MoELayer`](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/transformer/moe/moe_layer.py#L384-L389) passes it the same `self.config` object that the attention in that layer just used.
- `TransformerConfig` / `MLATransformerConfig` define no `__deepcopy__`, so the copy goes through the instance `__dict__`, which now includes `_shared_rotary_pos_emb_cache`.

Trigger: `MLATransformerConfig(share_rotary_pos_emb=True, rope_type="yarn", num_moe_experts=..., moe_shared_expert_intermediate_size=...)`, then build any layer whose attention is built before its MoE (every DeepSeek-style layer).

Actual: every `layer.mlp.shared_experts.config._shared_rotary_pos_emb_cache` holds private deep copies of all rotary modules cached so far. For YaRN those copies include:
- the GPU `cos_cached`/`sin_cached` tables that [`YarnRotaryEmbedding.__init__`](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/models/common/embeddings/yarn_rotary_pos_embedding.py#L98-L100) builds eagerly (`original_max_position_embeddings x qk_pos_emb_head_dim` fp32, twice);
- the `inv_freq*` tensors;
- a deep copy of the `cp_group` ProcessGroup ([L117-L121](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/models/common/embeddings/rotary_pos_embedding.py#L117-L121)).

None of the copies is ever used. The flag therefore adds a duplicate per MoE layer, which is what it is meant to remove. Model construction also now depends on ProcessGroup objects being deep-copyable.

Expected: deep-copying a config does not clone shared modules. The shared-expert config never builds attention, so an empty cache is correct for it.

**Correction** (suggested patch; verify before adopting). Add next to the helper:

```python
class _SharedRotaryPosEmbCache(dict):
    """Per-config cache of shared rotary modules (see ``maybe_share_rotary_pos_emb``).

    ``copy.deepcopy(config)`` (e.g. in ``SharedExpertMLP``) yields an empty cache instead of
    cloning the cached modules, their GPU buffers and their process-group handles.
    """

    def __deepcopy__(self, memo):
        return type(self)()
```

Then, in `maybe_share_rotary_pos_emb`, replace `cache = {}` with `cache = _SharedRotaryPosEmbCache()`. `copy.deepcopy` finds `__deepcopy__` on dict subclasses and records the result in `memo`.

Invariant to restore: only the config object that layers are built from holds rotary modules; copies of it never clone them.

**Preservation**
- (a) Flag off: the attribute is never created, so nothing changes.
- (b) The original config still returns one instance per key to every MLA / AbsorbedMLA / DSA-indexer / DSv4 layer.
- (c) The shallow `copy.copy(config)` calls ([dsa.py#L1500](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/transformer/experimental_attention_variant/dsa.py#L1500), [csa.py#L1098](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/transformer/experimental_attention_variant/csa.py#L1098)) still alias the same dict. They only build norms, so this is harmless.
- (d) `copy.deepcopy(model)` still gives one shared rotary instance per key inside the copy, because the module tree is copied through the memo.

**Acceptance** (proposed test, not run)
1. With `share_rotary_pos_emb=True`, build `a = MLASelfAttention(config, ...)`, then run `c = copy.deepcopy(config)`.
2. Expect `len(c._shared_rotary_pos_emb_cache) == 0` and `config._shared_rotary_pos_emb_cache[(config.rope_type, config.rotary_base)] is a.rotary_pos_emb`.
3. A second `b = MLASelfAttention(config, ...)` must still satisfy `b.rotary_pos_emb is a.rotary_pos_emb`.

Today step 2 fails: `c` holds a cloned module. The existing `test_loss_and_grad_norm_are_unchanged` assertions (`on[0].rotary_pos_emb is on[1].rotary_pos_emb`, bit-identical loss) must keep passing.

**[SUGGESTION Other]** The docstring is wrong in two places.

1. "The cos/sin buffers are allocated lazily on first use, so the extra modules that are built but not kept never allocate them." This holds for `RotaryEmbedding`, but not for YaRN. [`YarnRotaryEmbedding.__init__`](https://github.com/NVIDIA/Megatron-LM/blob/6618d1003dab23229a4349cd52d959772268464c/megatron/core/models/common/embeddings/yarn_rotary_pos_embedding.py#L98-L104) calls `_set_cos_sin_cache(self.original_max_position_embeddings, ...)` on the GPU. YaRN is the `MLATransformerConfig` default and is also used by the DSv4 compressed layers. So every YaRN module that the helper discards still allocates a cos/sin table and launches kernels, and the memory is only freed when the module is dropped. The PR description makes the same claim.
2. "so sharing is scoped to a single model": sharing is actually scoped to the config object. Two models built from one config object share modules, and deep copies of the config carry the cache (see the other comment).

**Correction:** reword lines 43-48, for example:

```
    single instance. When ``config.share_rotary_pos_emb`` is set, the first module built for a
    given ``cache_key`` is cached on ``config`` and returned to every later caller that passes the
    same config and an equal key, so sharing is scoped to that config object; otherwise
    ``rotary_pos_emb`` is returned unchanged. Modules that are built but not kept are dropped
    (``YarnRotaryEmbedding`` still materializes its ``original_max_position_embeddings`` table in
    ``__init__`` before being dropped), so only one instance per key ever grows its cos/sin
    buffers to the training sequence length. Numerics are unchanged.
```

Optional simplification: have the helper take a zero-argument builder and check the cache before building. That avoids the throwaway YaRN construction (and its `forward.cache_clear()`) for every layer after the first. It would require changing all four call sites.

**Preservation:** documentation only; no behavior changes.

**Acceptance:** static check. The docstring must match `YarnRotaryEmbedding.__init__` lines 98-104 and the config-scoped cache at lines 60-64.
