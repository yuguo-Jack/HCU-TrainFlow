# Pass the model's pipeline rank to spec builders outside core

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8048) · state: open · merged: False

## Original PR description

**Why.** The GPT block spec builders (MoE, experimental attention, heterogeneous) keep one pipeline stage's layers, selected by `pp_rank` or else by the global pipeline rank. `gpt_builder`, `GPTModelBuilder`, the ModelOpt builder and its distillation teacher, and the multimodal example hold the model's collection but did not pass its rank. A model on its own pipeline grid, such as a separate RL inference model with its own pipeline size, got the global stage's layers. With a PP=2 collection over a PP=1 global grid and three layers split 1 + 2, stage 1 built one layer instead of two.

**What.**
- Pass the collection's pipeline rank to the block spec builders, as these builders already did for the MTP spec. Without a collection, `pp_rank` stays `None`.
- `default_layer_spec` takes an optional `pp_rank`.
- The heterogeneous and multimodal MoE specs also get the builder's `vp_stage`; with a virtual pipeline they asserted.

Complements #8033, which makes custom layouts honor the given `pp_rank`; with both, a layout on its own grid builds the right stage.

**Tests.** New `test_builders_pipeline_stage.py` builds four builders on a PP=2 collection over a PP=1 global grid, with and without the global rank accessor patched to raise, and checks `gpt_builder` forwarding per spec: 14/14 on 4 GPUs, while on main every case fails on the second stage. `test_gpt_builder.py` checks the forwarded rank. Existing GPT model, builder, heterogeneous and post-training tests match main.

**Compatibility.** On the standard grid the collection's rank is the global one. Tools that pass no collection are unchanged. The ModelOpt GPT spec does not take a pipeline rank yet.

Part of #6307.
