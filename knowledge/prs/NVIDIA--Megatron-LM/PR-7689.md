# fix(optimizer): handle missing keys in _set_main_param_and_optimizer_states

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7689) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fix `KeyError: 'step'` crash in `DistributedOptimizer._set_main_param_and_optimizer_states` when resuming from checkpoint with native `torch.optim.AdamW` (noApex/TE).

## Issue tracking

Related to: DistributedOptimizer checkpoint resume with native PyTorch optimizers.

## Root cause

When using native `torch.optim.AdamW` without Apex or Transformer Engine (`HAVE_APEX_OR_TE=False`), `load_state_dict` injects a per-parameter `'step'` tensorinto each optimizer state entry (line 1043):

```python
for s in state_dict_state.values():
    s["step"] = step
```

However, `load_parameter_state_dp_zero` scatters only `optimizer_state_keys` which returns `("exp_avg", "exp_avg_sq")` for Adam — `'step'` is excluded. The scattered `tensors` dict arriving at `_set_main_param_and_optimizer_states` therefore lacks `'step'`, while `dst_tensors` (built from live optimizer state) contains it. The copy loop then crashes on `tensors["step"]` → `KeyError`.

## Fix

Add `key not in tensors` guard in the copy loop of `_set_main_param_and_optimizer_states` (1-line change in `distrib_optimizer.py`):

```python
# Before
if not isinstance(tensors[key], torch.Tensor):

# After
if key not in tensors or not isinstance(tensors[key], torch.Tensor):
```

This matches the defensive pattern already used in `load_parameter_state_from_fully_reshardable` (line 2411) and `load_parameter_state_from_fs_model_space` (line 2129), which explicitly skip `'step'` before calling this method.
