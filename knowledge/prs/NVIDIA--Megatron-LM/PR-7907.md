# What does this PR do?
<!-- Add a one line overview of what this PR aims to accomplish. -->

MFSDP v2 all-gathered both rowwise and columnwise MXFP8 weight
  planes (data and scales) at every unshard, although forward GEMMs read only rowwise
  planes and backward data-gradient GEMMs read only columnwise planes. This PR enables that unshard
  gathers only the planes its compute phase reads, roughly halving MXFP8 weight
  all-gather bytes.

## Issue tracking

## Design

  - `FsdpModule.unshard(compute_phase, prefetch)` takes a dtype-agnostic `ComputePhase`
    (`FORWARD`/`BACKWARD`); prefetch follows that phase's module order. `unshard()` with
    no arguments still unshards every phase, so external schedulers are unchanged.
  - `FsdpParameterGroup` translates the phase into the data to unshard and tracks what is
    already installed. MXFP8 groups gather rowwise planes for forward and columnwise planes
    for backward; regular groups and already-unsharded compute weights install everything
    at once.
  - Activation recomputation gathers rowwise planes on demand, since backward prefetch
    cannot tell whether a module recomputes (same strategy as MFSDP v1).
  - Compute tensors carry only installed planes, with a quantizer advertising the same
    usages. TE saves the weight Parameter itself for backward, and reassigning `.data`
    updates it in place, so backward reads columnwise planes gathered after forward.
  - `QuantizedDBuffer.redistribute` accept `rowwise=`/`columnwise=`.

  ## Tests

  - Forward unshards only rowwise planes and backward only columnwise planes.
  - Reentrant and non-reentrant recomputation match no recomputation bit-exactly
    (losses, gradients, updated weights), with shapes needing padded scales.
  - Partial-plane redistribution and compute tensors, including rowwise-only (TN) and
    columnwise-only (NN) GEMMs against TE references.
