# Pass the owner's collection to FP8/FP4 quantization contexts

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8035) · state: open · merged: False

## Original PR description

**Depends on #8034**, which adds `amax_reduction_group` and the `pg_collection` keyword. Until it merges, please review [the scoped diff](https://github.com/NVIDIA/Megatron-LM/compare/Connor-XY:yx/pstate-b2-amax-group...Connor-XY:yx/pstate-b2-amax-callers), the last four commits, one per owner.

**Why.** These components hold their model's collection, but their FP8/FP4 autocasts still reduce amaxes over the global group, or over WORLD when there is no global grid:
- transformer blocks and layers, MTP, recompute;
- HybridStack;
- CUDA graph runners;
- the multimodal projector and the TE wrappers.

On 4 GPUs, a layer whose own TP×DP×CP ranks are [0, 2] reduces over [0, 1] on main.

**What.** Each owner passes `pg_collection=`:
- TE wrappers, the LM head and the projector. `TELinear` gains an optional `pg_collection`.
- Block, layer, recompute and MTP. `MultiTokenPredictionBlock` and `T5Model` add `tp_cp` and `tp_dp_cp` to their default collections.
- HybridStack. `MambaLayer` keeps its collection.
- The CUDA graph runner. `TECudaGraphHelper` uses `amax_reduction_group`, which removes a dead branch that read a nonexistent `tp_dp` field.

**Tests.**
- Per-owner tests record the group of each autocast, with the global accessor patched to raise. They pass on 4 GPUs and fail on main.
- FP8/FP4 training (delayed, tensorwise, MXFP8, NVFP4, TE CUDA graphs) gives the same results as main.
- The FP8, hybrid and TE regression sets give the same results as main.

**Compatibility.** On the standard grid the collection holds the same group objects, so numerics are unchanged. A caller-built collection without `tp_dp_cp` (or without `tp_cp` when `tp_only_amax_red` is set) now raises `ValueError` under FP8/FP4. Needs `determinism-exempt`.

Part of #6307.
