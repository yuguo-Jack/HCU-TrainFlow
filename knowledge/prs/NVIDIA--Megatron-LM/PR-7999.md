# fix(inference): clean up failed NIXL transfers

## What does this PR do?

NIXL 1.3.2 raises exceptions for failed transfer status queries. These previously bypassed `NixlPullHandle`'s terminal-state handling, leaving failed imports quarantined and logging the same exception on every scheduling pass.

Cache terminal failures and explicitly release every transfer in the failed pull using NIXL's release/cancel API. Storage becomes reusable only when every release succeeds; failed releases retain their handles and buffers until teardown, without retrying terminal status queries or cleanup. Other KV/SSM handles continue progressing, and each quarantined import logs only its first unreported error. Partial-submission cleanup now checks `storage_safe` for every exception instead of assuming non-timeout exceptions are safe.

Fixes #7996.

Stacked on #6675 (`pull-request/6675`). Retarget to `main` after the parent lands.
