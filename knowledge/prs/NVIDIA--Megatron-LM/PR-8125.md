# fix: omit empty MFSDP v2 optimizer shards on all TE versions

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8125) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

MFSDP v2 currently retains empty local shards in the optimizer with TE >= 2.18. These entries have no values to update but still create gradient-cast tensors, saved-gradient tuples, and clipping/Adam bookkeeping. Exclude them on every TE version, while preserving group containers on newer TE and the existing empty-group workaround on older TE.

Always clear model-owned gradients as well as optimizer-owned gradients. This is necessary once empty shards are omitted: otherwise the second backward sees a mixture of set and unset gradients in an FSDP parameter group. Preserve the existing CUDA-graph behavior that zeros gradients in place.

## Evidence

A sequential comparison on the same 64 GB300 GPUs ran 128 steps per variant, with 64K context and CP=EP=8. Both MFSDP variants use upstream `main` at `daa007400639a7ed63db6b98b989ad7367c629e4` plus the NT4 training patches, including #7322, early NUMA binding, and unchanged automatic-GC thresholds `(2000, 10, 10)`. Statistics cover steps 51–128; full-GC counts sum all 64 ranks.

| MFSDP variant | Mean step time | Full GC events | Objects promoted per rank per step |
| --- | ---: | ---: | ---: |
| Before | 4.1940 s | 237 | 17,449 |
| Omit empty optimizer entries | 3.9337 s | 109 | 7,961 |

Mean step time improved **6.2%** in this pair. Optimizer entries fell from 4,459 per rank to 668–808, preserving every nonempty shard and the local element counts. The number of tensor-view calls was unchanged. Full collections still affected 44/78 steps versus 35/78 before; the remaining DDP/MFSDP gap is not resolved by this change.

Initial/final main losses were **12.865110 / 7.719327** before and **12.865089 / 7.719135** after. Maximum/mean absolute loss differences over 128 steps were **0.014230 / 0.003239**. Main/MTP losses and gradient norms stayed finite, with zero OOMs or allocation retries on all ranks. These are observed sequential-run differences, not a numerical-equivalence tolerance.

This PR targets current `main` (`e30d863a6`) independently of #7322, so its local-shard check uses the existing DTensor API. The benchmark applied the equivalent filter to #7322's local tensors; it is not a benchmark of otherwise unmodified current main.

## Validation

- Two-GPU `torch.distributed.run` on this PR: **5 tests passed per rank**, covering ten training steps with two microbatches each for ordinary and precision-aware Adam, FusedSGD gradient conversion, and both gradient-clipping modes. The training test now requires actual empty model shards, checks their exclusion from optimizer groups, and checks all model gradients are cleared before every step.
- Two-GPU follow-up on this PR: **3 additional tests passed per rank**, covering FP32/BF16 optimizer checkpoint round trips and full-iteration plus optimizer CUDA graph replay.
- Prior four-GB300 integration on the benchmark source: ten updates in both Adam modes; loss trajectories exactly matched the unsharded reference.
