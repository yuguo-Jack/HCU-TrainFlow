# Add owner-compute P2P gather/scatter

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7432) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

Add owner-based compute P2P APIs that gather parameter shards onto their assigned owners to reconstruct full tensors, then scatter results back to the shard holders.

Shard geometry comes from `GroupOwnerLayout`'s shared `GlobalLayout`. `tensor_to_owner` maps participating tensor indices to owner global ranks. Sends follow tensor-index order, and gather reconstructs tensors in buffer order. The tests cover noncontiguous input tensors and subgroups with noncontiguous global ranks.

Gather/scatter operations run on the caller's current CUDA stream. Callers explicitly select streams and wait for input dependencies and results.

Based on #7966 through `pull-request/7966`. Retarget this PR to `main` before merging #7966.

Validation:
- CPU-supported owner-planning tests passed across eight ranks. All four P2P round-trip cases passed across four CPU ranks. The three CUDA-only FSDP construction tests and the CUDA stream test were not run locally.
- Black, isort, pylint, and Ruff passed. The nonblocking mypy step reported missing torch/pytest dependencies in the isolated lint environment.
- CUDA/NCCL validation was unavailable locally.

Related to #5533. Previous design discussion: #7412.
