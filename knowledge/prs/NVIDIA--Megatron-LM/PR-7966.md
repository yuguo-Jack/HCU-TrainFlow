# Reuse GlobalLayout in owner planning

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7966) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

Owner planning duplicates tensor shapes and shard counts in `ParameterLayout`. Reuse the group's existing `DBuffer.layout` and the range APIs from #7963 instead, removing `ParameterLayout`.

`GroupOwnerLayout` stores the device mesh, shared `GlobalLayout`, and owner assignments using global process ranks. Cost functions receive full tensor shapes. Owner assignment accounts for single-candidate tensors first, then assigns the remaining tensors by descending cost. Gather/scatter plans derive shard ranges from the layout and reconstruct tensors in buffer order, including for noncontiguous, reordered, and multidimensional meshes.

Rebased onto `main` at `43ecc88de`. This branch includes the prerequisite range changes from #7963 while that PR remains open.

Validation:
- All 93 owner-planning, layout, and DBuffer cases passed on nsc-lhr across eight GB300 GPUs (job 137895, exit 0). Submesh nonmembers skipped the appropriate cases. NCCL emitted shutdown warnings after the passing pytest summaries.
- Owner-planning tests use real device meshes, the public `fully_shard` API, and distributed gather/scatter exchanges. Coverage includes owner balancing, eligibility, global rank mappings, padding, empty plans, and prioritizing single-candidate work regardless of input order.
- Black, isort, pylint, and Ruff passed for all seven changed files.

Refactors owner-planning code originally authored by @janEbert. Related to #5533.
