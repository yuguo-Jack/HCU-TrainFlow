## Problem

After `load_checkpoint()` returns, the restored execution parameters, optimizer
moments, and step counters match the checkpoint, but the public model parameters
can remain stale.

This means the first resumed forward can use parameters that differ from the
restored optimizer execution state.

## Fix

After the HybridDeviceOptimizer state is restored, copy the restored FP32 master
parameters back to the model parameters when `param_update_in_fp32` is enabled.

## Tests

The regression checks the restore boundary before any resumed optimizer update,
then checks the first resumed loss/update and three continuation steps.

Validated on two ranks across:
- precision-aware full CPU offload, BF16
- precision-aware full CPU offload, BF16 + FP32
- precision-aware partial CPU offload, BF16
- precision-aware partial CPU offload, BF16 + FP32
- non-precision-aware partial-offload control

All repaired configurations match the reference.
