# What does this PR do?

Lets users resume training from pre-0.14 distributed checkpoints that contain a serialized Adam, AdamW, or SGD optimizer.

For example, loading a legacy AdamW checkpoint with PyTorch 2.6 previously raised an `UnpicklingError` for `torch.optim.adamw.AdamW`. This change allows that optimizer to load through the existing weights-only loader. It registers the three optimizer classes and the `defaultdict(dict)` container used by their state. Checkpoints still use `weights_only=True`, and the existing test for rejecting an unregistered class continues to pass.

- claude · comment · 2026-09-03T16:54:35Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/6814#issuecomment-5529127817)

Light review — the fix is correct and minimal. Both `dict` and `defaultdict` are genuinely needed (a pickled optimizer carries `self.state = defaultdict(dict)`, so both the container and its `default_factory` get emitted as `GLOBAL` opcodes, and neither is in torch's default weights-only allowlist). Two things:

**1. The same failure still exists for `torch.optim.Adam` and `torch.optim.SGD`.**

In the Torch-fallback path the optimizer class is not always `AdamW`:

- `megatron/core/optimizer/__init__.py:565` — `adam_cls = torch.optim.AdamW if config.decoupled_weight_decay else torch.optim.Adam`
- `megatron/core/optimizer/__init__.py:32` — `from torch.optim import SGD` (used when `config.optimizer == "sgd"`)

A pre-0.14 `common.pt` produced with `decoupled_weight_decay=False` or `--optimizer sgd` serializes those classes and hits the identical `UnpicklingError`. Since the container types are now allowlisted, covering them is one line each — suggest adding `torch.optim.Adam` and `torch.optim.SGD` next to the new `torch.optim.AdamW` entry in `SAFE_GLOBALS`, and asserting on them in the test (parametrize `test_legacy_adamw_optimizer` over the three classes).

**2. Add a rationale comment for the new container entries.**

Non-obvious entries in `SAFE_GLOBALS` currently carry an explanatory comment (see the one on `torch._C.Generator`). Without one, `dict`/`defaultdict` look redundant with torch's built-in container handling and are easy to "clean up" later, which would silently re-break legacy loads. Suggest a short comment above `dict` noting that `optimizer.state` is a `defaultdict(dict)`, so both the container and its `default_factory` must be allowlisted.

Nit: `load_common` is deprecated and logs a warning on every call, so the new test will emit it. Harmless, just noting it in case a future `-W error` run trips on it.

- deepujain · comment · 2026-09-04T02:57:03Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/6814#issuecomment-5535013592)

Thanks — I pushed `8c87a79b0`, which adds `Adam` and `SGD` coverage alongside `AdamW`, parameterizes the regression test across all three, and documents why `optimizer.state` requires `defaultdict(dict)`.

On the security question: allowlisting `dict` and `defaultdict` permits only those built-in container types; it does not permit an arbitrary class carried inside their serialized state. The weights-only unpickler still rejects any non-allowlisted global referenced by a checkpoint. `defaultdict` additionally needs its `default_factory`, which is constrained here to the allowlisted `dict`. Calling `torch.serialization.add_safe_globals` is an explicit application-level opt-in for a trusted checkpoint, outside this library's default trust boundary.

Local validation: `py_compile` and `git diff --check` passed. This checkout does not include PyTorch or pytest, so the parameterized regression test is left for the approved CI run.
