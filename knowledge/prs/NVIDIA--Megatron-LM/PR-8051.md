# Create Megatron-FSDP v1 TP groups collectively and validate pg_collection

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8051) · state: open · merged: False

## Original PR description

**Why.** `FullyShardedDataParallelV1` fills an unset `tp` or `expt_tp` in `pg_collection` with
`dist.new_group(ranks=[rank])`, a different rank list on every rank. Group creation must be identical on
all ranks: this works only while every rank takes the same branch, and otherwise later groups mismatch or
hang. Dense models also create an expert TP group they never use, and a collection that lacks a needed
group fails with an `AttributeError` on `None` deep in mesh construction.

**What.**
- Create single-rank TP groups once, with `new_subgroups_by_enumeration` over every rank, and only for
  the axes the model uses.
- Check the groups the configuration needs (`dp_cp`; `intra_dp_cp`, `inter_dist_opt` for HSDP; `ep`,
  `expt_dp`, `intra_expt_dp` for MoE) and raise `ValueError` naming the missing ones.
- Read collection fields directly. Comment the global branch as the migration fallback; its groups are
  unchanged.

The collection path keeps the replicate data-parallel fields. With GTP weight remat off they hold the
same ranks as the fallback's GTP-inclusive groups.

**Tests.** New `test_mcore_fsdp_dist_index.py` (4 GPUs): a HyperCommGrid collection laid out unlike the global grid,
with every `parallel_state` accessor patched to raise; identical group creation on every rank;
`ValueError` for missing groups; explicit-vs-fallback rank parity on eight standard-grid layouts. 10 of
the 20 cases fail on main. The existing MFSDP v1 tests match main on 4 and 2 GPUs.

**Compatibility.** No change for the standard grid or for collections that set the needed groups. A collection missing one
now raises `ValueError` instead of `AttributeError`.
