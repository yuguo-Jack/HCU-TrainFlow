# [dev] Make DSv4 bit-reproducible under --deterministic-mode

## Original PR description

# What does this PR do?
Under --deterministic-mode, a DSv4 run was not reproducible even against itself: the loss diverges from iteration 2 (grad norm from iteration 1). All sources are kernel-level and independent of CUDA graphs. This PR fixes them, gated on deterministic mode only; the default path is unchanged.

Source 1: cuDNN compact indexer Top-K returns the selected ids in a run-dependent slot order, and its compact
softmax is accumulated in that order (FlashMLA and the indexer backward consume both in slot order)
Fix: _canonicalize_compact_topk: sort ids per row (padding last), recompute the softmax in that order.  

Source 2: cuDNN sparse-attention backward accumulates dK/dV with atomics
Fix: pass deterministic=True + a retained scratch workspace on all three sparse_attention_backward_wrapper call
sites; raise if the installed cudnn-frontend / GPU / head count cannot provide the deterministic kernel.  

Source 3: cuDNN indexer backward accumulates dK with atomics
Fix: _deterministic_sparse_indexer_grads_wk: atomic-free dK (dW on SM90) via torch's deterministic index_add_ (fallback: stable sort + prefix sum), padding slots spread over dummy rows; computes the same clipped-log KL gradient as cuDNN (predict · Σ kept_target − kept_target, targets clamped at e⁻¹⁰⁰) with per-sample key ids, and overrides cuDNN's dK on the fused and CP call sites (indexing and gradient-formula fixes by @Connor-XY, from #7706)  

Source 4: TE fused grouped-MLP backward accumulates the routing-prob gradient (dprob) with atomics (newer TE
raises for this)
Fix: feed a unit scale to the fused op and apply the probs on the FC2 output (exact without FC2 bias; raises
otherwise).  

Source 5: TE fused router aux loss (fused_moe_aux_loss) uses float atomicAdd
Fix: --moe-router-fusion is rejected in deterministic mode via ARG_VALUES_REQUIRED_FOR_DETERMINISM (explicit,
no silent kernel swap)

Relation to #7169: that PR aligns the id order between the no-grad and grad forward paths and stable-sorts the standalone Top-K fallback. It does not touch the compact cuDNN Top-K path used in training (slot and softmax order still vary run to run) nor any backward kernel; with #7169 alone the DSv4 proxy is still not reproducible. This PR builds on it.

- Unit tests: test_csa_deterministic_indexer.py (GPU): deterministic dK/dW vs an fp64 reference across B=1/2, fp32/bf16, padding, cross-sample chunks and both reduction paths, bit-identical on replay; on SM100 a direct comparison against cuDNN's indexer_backward_wrapper (rel. L2 < 1e-2 on rows whose targets sum to 0.5). test_indexer_topk_thd_compact_dispatch updated to expect the canonicalized softmax.
- Also validated at CP=2 (PP1×EP2×CP2, with and without --dsa-cp-balance-indexer): two runs bitwise identical on every logged scalar for 10 iterations. Not covered: CP>2, multi-node, mixed-length packed sequences.

Performance (iteration time vs the non-deterministic run, same kernels otherwise)

- --deterministic-mode with this PR: +14.8%, almost entirely PyTorch's torch.utils.deterministic.fill_uninitialized_memory, a default side effect of use_deterministic_algorithms(True) that adds one fill kernel per allocation (~40k launches/step here).
- Setting fill_uninitialized_memory = False has no effect on DSv4 reproducibility (bitwise identical losses with it on or off) and brings the total cost down to +6.1%. It is not changed in this PR because it is a global switch and was only validated on DSv4; users can set it in their launcher.

Notes

- Requires nvidia-cudnn-frontend ≥ 1.28 and SM100 for the deterministic sparse-attention backward; otherwise deterministic mode fails fast with a clear error.
- Numerics under deterministic mode differ slightly from the default path (fixed reduction orders; probs applied after FC2 instead of before); this is expected and only affects deterministic mode.
- Overlaps with #6944 (deterministic DSA backward in dsa_cudnn_kernels.py, which dsv4_hybrid does not use).

- Connor-XY · comment · 2026-10-05T16:31:47Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7441#issuecomment-5998707446)

Hi @HaochenYuan, two things we hit while stacking #7706 on this PR:
1. The deterministic dK/dW path uses `predict - target`, but cuDNN's indexer backward uses the clipped KL gradient `predict * sum(kept_target) - kept_target`. CSA targets don't sum to 1 (sink and local keys take mass), so deterministic mode changes the gradient, not only the reduction order. The fix is in #7706 if you want to fold it in.
2. `test_indexer_topk_thd_compact_dispatch` fails on this branch and passes on `dev`. The conflict with `dev` is a single hunk where dev added `_align_topk_width`; keeping both resolves it.

If you rebase onto `dev`, feel free to fold #7706's commits in and I'll close #7706.
