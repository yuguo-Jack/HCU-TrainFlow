# Add independent projection and sigmoid scaling for latent MoE

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8111) · state: open · merged: False

## Original PR description

Latent MoE changes expert preactivation scale as latent width changes. Add three independent controls, with defaults that preserve existing computation:

- `--moe-latent-projection-scaling`: multiply the hidden-to-latent output by `sqrt(hidden_size / moe_latent_size)` before expert dispatch.
- `--moe-latent-up-projection-scaling`: separately multiply the latent-to-hidden output by the same gain after optional normalization and projection, before shared expert addition.
- `--moe-latent-sigmoid-input-scale KAPPA` (default `1.0`): replace only `sigmoid(gate)` with `sigmoid(kappa * gate)` in routed latent experts.

Both projection gains default to false and remain independent of the sigmoid setting. The sigmoid scale preserves SwiGLU's multiplicative gate factor, the linear branch, and SiTU's gate/linear tanh arguments. Dense/shared experts and router inputs are unaffected. No parameters or checkpoint tensor shapes change; reuse the same settings when loading a checkpoint.

Thread the sigmoid scalar through eager and custom fused SwiGLU, hard-clamped SwiGLU, and SiTU, including biased and router-weighted variants. The manual backward includes the chain-rule factor: SwiGLU uses `sigmoid(kappa*v) * (1 + kappa*v*(1-sigmoid(kappa*v)))`; SiTU preserves its tanh derivative and multiplies the sigmoid derivative term by `kappa`. Router-probability gradients use the same scaled forward activation.

Non-unit sigmoid scales require positive latent width, MoE experts, and gated SiLU; all scales must be finite. TE native activations select the standard activation path for non-unit values. The integrated TE op fuser and inference-optimized MoE kernels reject non-unit values explicitly; use `--bias-activation-fusion` with the standard grouped or sequential expert implementation.

The README documents the computation, initialization dependence, and independent projection/sigmoid/normalization ablations. The up-projection gain is generally unnecessary with latent fan-in-aware initialization. No training-quality improvement or end-to-end variance preservation is assumed.

- iloshchilov · comment · 2026-10-10T21:02:45Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8111#issuecomment-6102145239)

Could we also add an independent, user-defined sigmoid-input scale, e.g. `--moe-latent-sigmoid-input-scale`, defaulting to `1.0`?

The down-projection gain scales the entire expert input. We also need the ability to adjust only the sigmoid argument:

$$
\sigma(v)\\rightarrow\\sigma(\kappa v).
$$

This would allow tuning sigmoid sensitivity while leaving the multiplicative branches and SiTU’s tanh arguments unchanged. It should be independent of both projection gains and apply only to routed latent experts.

Please update the fused backward as well, including the $\kappa$ chain-rule factor, and check forward/backward agreement with the unfused reference for a non-unit scale.
