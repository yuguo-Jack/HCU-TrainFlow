# What does this PR do?
Adds `megatron/core/ops`, the implementation home for SSM, sparse-attention and future fused operations, together with its **contributor guide** and the two shared helpers every later move uses. No existing code changes.

- `megatron/core/ops/README.md`: layout and file roles; **how to add a new operation**; **how to add a new backend kernel to an existing operation**; dependency checks; kernel selection; deprecated import paths. Pointers added to `megatron/core/README.md` and `docs/developer/contribute.md`.
- `ops/_compat.deprecated_module`: PEP 562 forwarders for moved import paths (one `DeprecationWarning`, lazy attribute resolution, `from old import *` and legacy pickles keep working).
- `ops/_backends.require`: construction-time optional-dependency checks with one exception type and the cause chained.
- `tests/unit_tests/ops/test_deprecated_imports.py` and a CI bucket: the regression suite for deprecated paths. Its table (`deprecated_paths.py`) is empty here and filled by each move PR, so family-specific tests skip until their move lands.

This is **PR 1 of 4** re-slicing #7239 (which the stack supersedes), per the "Unified Kernel Backend Management" design doc. The moves themselves follow, each a pure move leaving deprecated aliases at the old paths:
2. `ops-move/2-ssm` — SSM helpers, Mamba2, GDN/GDN2, GDP, chunkwise CP → `megatron/core/ops/ssm` (149 files, 39 renames)
3. `ops-move/3-attention` — DSA, CSA, absorbed MLA, DeepSeek-v4 → `megatron/core/ops/attention` (78 files, 24 renames)
4. `ops-move/4-layers-configs` — `MambaLayer`, `MLPLayer` and the per-layer configs → `megatron/core/transformer` (63 files)

The previous single-PR head is kept at `guihong-nv:pr1/move-into-ops-full` for reference; the stack's end state is identical to it apart from dropping an unused test helper.
