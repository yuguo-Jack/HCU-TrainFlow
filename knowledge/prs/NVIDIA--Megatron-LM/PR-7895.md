# What does this PR do?

`fully_shard_context` duplicates `FsdpContext`'s constructor options and performs device selection outside the constructor. Forward the options through `**kwargs` and move current-CUDA-device defaulting and CUDA validation into `FsdpContext`, so adding a context option only requires changing the constructor.

Accept all options, including `device`, through `**kwargs`; existing repository callers already pass `device` by keyword or omit it. Preserve the wrapper's activation, nesting checks, finalization, and cleanup. Consolidate option documentation in `FsdpContext`.

- ahmadki · comment · 2026-10-07T14:15:33Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7895#issuecomment-6039864647)

LGTM, but couple of suggestions:

(1)
I hate that the signature of `fully_shard_context`  is now just (**kwargs). Its docstring points to FsdpContext, but `fully_shard_context` is the actual public entry point.
how about making `FsdpContext` itself the context manager, with `fully_shard_context = FsdpContext`. That gives one typed signature instead of `**kwargs`. Maybe can be added with #6369 ?
Also related here is the message in the `ValueError`: `FsdpContext requires a CUDA device`. But the user uses `fully_shard_context`, so it can be confusing. Maybe the message can be changed to:
```python
raise ValueError(
    f"fully_shard_context/FsdpContext requires a CUDA device, got {device}."
)
```

(2)
Test seems a bit weak, there are no asserts which device you get, or that a non CUDA device is rejected. The current tests will not catch if someone breaks the default (wrong device index) or drops the CUDA check. Fix is very simple change to `test_context.py`:
```python
assert FsdpContext().allgather_stream.device == torch.device("cuda", torch.cuda.current_device())
with pytest.raises(ValueError, match="CUDA device"):
    FsdpContext(device=torch.device("cpu"))
```


- wujingyue · comment · 2026-10-07T17:25:03Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7895#issuecomment-6043143688)

Great suggestions, @ahmadki! 

> how about making FsdpContext itself the context manager

I'm a big fan of [SRP](https://blog.cleancoder.com/uncle-bob/2014/05/08/SingleReponsibilityPrinciple.html). So, I plan to keep fully_shard_context (the scope) and FullyShardContext (the actual context object) separate, but make fully_shard_context to simply take the context. 
```
context = FsdpContext(...)
with fully_shard_context(context):
  ...
```
This distinction is similar to torch.cuda.Stream vs torch.cuda.stream. 

Let me know if you dislike it. Otherwise, I'll update the PR and merge.
