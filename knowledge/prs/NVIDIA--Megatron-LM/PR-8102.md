# What does this PR do?

Adds configurable H100 CI traffic routing and keeps both cloud paths ready:

- `H100_RUNNER_TRAFFIC_MODE` selects `aws`, `gcp`, or `50-50` for PRs whose preflight membership check identifies the author as an NVIDIA org member.
- External contributors continue to use ephemeral AWS H100 runners. Merge queue and non-PR runs stay on AWS.
- H100 Docker builds, unit tests, and functional tests follow the selected route and registry. GB200 routing and its original approval/unit-test functional gate remain unchanged.
- After relevant changes reach `main`, cache population builds and publishes the main-commit H100 image and BuildKit cache to both AWS ECR and Singapore GAR.
- Testmon keeps one H100 baseline per recipe platform and bucket. Its cache identity is shared by AWS and GCP H100, so a second cloud-specific publisher would race on the same cache keys.

Successful run on GCP H100 with `H100_RUNNER_TRAFFIC_MODE=gcp`:
https://github.com/NVIDIA/Megatron-LM/actions/runs/38181812427

With `H100_RUNNER_TRAFFIC_MODE=50-50`, this is example where it selected gcp:
https://github.com/NVIDIA/Megatron-LM/actions/runs/38181812427/attempts/2

Then I retried again and it selected AWS:

### 1. Restore the configure dependency in the final validator

**Failure:** `Nemo_CICD_Test` now reads `needs.configure.outputs.run_h100_functional`, but `configure` is absent from its [direct dependencies](https://github.com/NVIDIA/Megatron-LM/blob/e3b78b3a4e597b4c7e67e72481958afaa71f4244/.github/workflows/cicd-main.yml#L1387-L1395). GitHub's `needs` context does not include transitive dependencies, so [this environment value](https://github.com/NVIDIA/Megatron-LM/blob/e3b78b3a4e597b4c7e67e72481958afaa71f4244/.github/workflows/cicd-main.yml#L1423) is empty. With unit tests successful, H100 functional tests unexpectedly skipped, and no failed jobs, the [new skip branch](https://github.com/NVIDIA/Megatron-LM/blob/e3b78b3a4e597b4c7e67e72481958afaa71f4244/.github/workflows/cicd-main.yml#L1458-L1462) accepts the skip even when configure emitted `run_h100_functional=true`. Expected: only a deliberately disabled H100 scope may pass with skipped functional tests.

**Correction:** Add the direct dependency; retain the existing result-checking branches. Suggested replacement for the job's `needs` block:

```yaml
    needs:
      - pre-flight
      - configure
      - is-not-external-contributor
      - cicd-unit-tests-latest
      - cicd-unit-tests-latest-gb200
      - cicd-integration-gate
      - cicd-integration-tests-latest-h100
      - cicd-integration-tests-latest-gb200
```

**Preservation and acceptance:** Proposed checks should establish that the validator receives configure's actual output. With successful units and no other failures, `run_h100_functional=true` plus H100 `skipped` must fail; `false` plus H100 `skipped` must pass; H100 `success` must pass. Retain the docs-only/deployment early exit, unit-failure failure result, and rejection of skipped GB200 functional tests when maintainer testing is enabled and `should_run_gb200=true`. Static invariant: every referenced `needs.<job>` in this validator must name a direct dependency.

### 2. Update the workflow-shell test harnesses for the new inputs

**Failure:** Existing tests execute the actual workflow scripts under `bash -e -u -o pipefail`, but their environment dictionaries were not updated. In a clean test environment, maintainer cases in [the build-matrix test](https://github.com/NVIDIA/Megatron-LM/blob/e3b78b3a4e597b4c7e67e72481958afaa71f4244/tests/test_utils/test_testmon_workflow.py#L81-L101) now terminate with `USE_GCP_H100: unbound variable` at the [new build condition](https://github.com/NVIDIA/Megatron-LM/blob/e3b78b3a4e597b4c7e67e72481958afaa71f4244/.github/workflows/_build_ci_container.yml#L115). Likewise, [configure tests](https://github.com/NVIDIA/Megatron-LM/blob/e3b78b3a4e597b4c7e67e72481958afaa71f4244/tests/test_utils/test_testmon_workflow.py#L383-L412) terminate at [the new `IS_PR` check](https://github.com/NVIDIA/Megatron-LM/blob/e3b78b3a4e597b4c7e67e72481958afaa71f4244/.github/workflows/cicd-main.yml#L310), rather than reaching their selective-testing assertions. Workflow `env` declarations are not automatically applied by this harness.

**Correction:** Update both harness environments, without weakening nounset or removing assertions. Add these entries to the producer test's build environment:

```python

"INCLUDE_GCP_H100": "false",
"REGISTRY_GCP_H100": "gcp.example.test/team",
"SELECTED_RUNNER_GCP_H100": "gcp-build-runner",
```

Add these defaults to `configure_environment`:

```python
"H100_TRAFFIC_MODE": "aws",
"PREFLIGHT_IS_MEMBER": "true",
"IS_MAINTAINER": "true",
"EPHEMERAL_RUNNER": "nvidia-ci-aws-gpu-x8-ephemeral",
"RUN_ATTEMPT": "1",

```

In `_run_configure`, immediately before `_run`, derive `IS_PR` from the effective event/ref so existing scenario overrides remain meaningful:

```python
environment = {
    **environment,
    "IS_PR": str(
        environment["EVENT_NAME"] == "push"

    ).lower(),

```

**Preservation and acceptance:** Run the existing workflow test module and retain its assertions for platform sets, exact bucket lists, runner/image pairs, selective-label precedence, and full-test guards. Add proposed routing cases: member PRs in `aws` and `gcp` must emit matching build runner, GPU runner, registry, cloud suffix, and use-GCP flag; both controlled `50-50` outcomes must produce those same coherent tuples. Non-member PRs must remain AWS/ephemeral, including `ephe-v2-example` with attempt `2` producing `ephe-v2-example-a2`; merge-group and dispatch cases must remain AWS. For cache population, an AWS+GCP build matrix must publish only one H100 Testmon entry per bucket while retaining enabled GB200 entries. These cover the new feature rather than merely repairing the old fixtures.
