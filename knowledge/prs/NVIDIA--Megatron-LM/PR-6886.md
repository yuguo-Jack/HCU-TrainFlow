## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Adds GTP_remat + Context Parallelism (CP) support: **optionally fold the CP axis into the
dense GTP_remat weight-sharding group**, so CP ranks also shard dense weights.

- **`--gtp-remat-fold-cp`** (default **off**): dense weight group becomes `cp × gtp_remat`
  (at GTP_remat 1: the CP group). Off keeps the plain `gtp_remat` group, giving a clean
  with/without-folding baseline on the same config. Expert weights never fold.
- **Correctness under folding**: DDP bucket skips CP for folded params
  (`excludes_cp_from_bucket`); checkpoint writer election excludes CP when folded, includes it
  when not; init seeds use the folded group.
- **Optimizer checkpoint fix**: `dp_reshardable` keys of folded buffers get a `.cp_rank_{i}`
  suffix — previously CP ranks' FP32 masters / Adam moments aliased on one key. Other keys
  unchanged; `fully_reshardable` unaffected.
- Docs: §2.1 knob table, §3.8 rewritten to match the code.

### Most impactful findings

**1. CRITICAL — `gtp_remat_cp_size()` can return 1 while `resolve_gtp_remat_group()` returns the CP-*merged* group** (`megatron/core/process_groups_config.py:748-754`). The group resolver falls back to MPU globals when the caller's collection lacks both GTP fields; the size function does not, and returns 1. The weight is then sharded over `cp × gtp_remat` but stamped `gtp_remat_cp_size=1`, so `excludes_cp_from_bucket` is False, DDP reduces over `dp_cp`, and **CP is summed twice — silently wrong gradients, no assert**. The new unit tests are well-scoped (writer-election gaps, embedding wiring under CP, a DCP roundtrip), but the **existing** GTP tests — `test_gtp_grad_correctness.py`, `test_attention_gtp.py`, `test_gtp_partial_cg.py` — all build `use_mpu_process_groups(required_pgs=['tp', 'cp', 'gtp_remat'])`, which carries the plain group but **not** `cp_gtp_remat`. So this is safe to land once the merged-group path either derives the CP degree consistently and covers the remaining checkpoint paths, or carries an explicit startup guard narrowing the supported configuration set.

**1. `parallel_state.create_all_gather_groups` now double-counts CP (bug)**

`get_gtp_weight_remat_world_size()` is CP-*inclusive* after this PR (it reads `_GTP_WEIGHT_REMAT_GROUP`, which is now `cp x gtp_remat`). `create_all_gather_groups` (`megatron/core/parallel_state.py:1660-1677`) feeds that value into a `RankGenerator` that *also* gets `cp=cp_size`:

```python
    cp_size = get_context_parallel_world_size()
    ...
    gtp_remat_size = get_gtp_weight_remat_world_size() or 1

    decoder_rank_gen = RankGenerator(
        tp=tp_size, ep=1, dp=dp_size, pp=pp_size,
        cp=cp_size,
        gtp_remat=gtp_remat_size,   # <-- already includes cp_size
        order=_inject_gtp_remat_axis("tp-cp-ep-dp-pp", after="cp"),
    )
```

`RankGenerator.__init__` computes `world_size = tp * dp * pp * cp * ep * gtp_remat`, so with CP+GTP both active the generator world size is `cp_size` times the real world size and the `dp-cp` rank sets it emits do not match `_DATA_PARALLEL_GROUP_WITH_CP`. Since `dp_cp_ag` is meant to be a same-ranks alias of `dp_cp` for AG/RS overlap, this yields wrong groups (or an out-of-range rank) whenever `--create-all-gather-group` is used with CP and GTP together. This function needs the CP-free degree the PR added:

```python
    gtp_remat_size = get_gtp_weight_remat_size_no_cp() or 1
```

The expert branch is fine — `get_expert_gtp_weight_remat_world_size()` is unchanged and the expert grid has `cp=1`. `tests/unit_tests/test_parallel_state.py::test_separate_all_gather_group` only runs `cp=world_size` with GTP inactive, so this combination is untested; a CP+GTP case there would cover it.

**2. `get_parameter_state_dp_zero` was not given the per-buffer-group fix**

`sharded_param_state_dp_reshardable` was correctly switched to the buffer own group, with the comment "a buffer own `data_parallel_group` can differ from the optimizer-wide default". Its sibling `get_parameter_state_dp_zero` (`megatron/core/optimizer/distrib_optimizer.py:1313-1354`) still uses the optimizer-wide `self.data_parallel_group`, which is `intra_dp_cp_group` (CP-inclusive):

```python
        data_parallel_world_size = data_parallel_group.size()   # dp x cp
        ...
                        assert gbuf_world_numel % data_parallel_world_size == 0
                        gbuf_local_numel = gbuf_world_numel // data_parallel_world_size
```

An `excludes_cp_from_bucket` buffer is padded and sharded over `dp` only, so `gbuf_world_numel` is a multiple of `dp_size`, not of `dp_size * cp_size` — the assert fires, and where it happens to pass, the gather is laid out against shard boundaries the buffer does not use. This path is reachable under GTP: `save_parameter_state` (legacy `--ckpt-format torch`, which the GTP validation in `arguments.py` explicitly permits) and `sharded_param_state_fully_reshardable` (`--dist-ckpt-optim-fully-reshardable`, only forbidden in combination with `--distrib-optim-fully-reshardable-mem-efficient`) both call it. Same substitution as the reshardable path:

```python
            buf_dp_group = self.buffers[gbuf_idx].data_parallel_group
            buf_dp_world_size = buf_dp_group.size()
            buf_dp_rank = buf_dp_group.rank()
```

**[CRITICAL Correctness]** `gtp_remat_cp_size()` and `resolve_gtp_remat_group()` disagree on the same inputs, which silently double-counts CP in the DDP bucket reduction.

**What.** `resolve_gtp_remat_group()` (lines 700-734) falls back to MPU globals when the caller's collection carries neither `cp_gtp_remat` nor `gtp_remat`, and returns the **CP-merged** group (`cp × gtp_remat`). `gtp_remat_cp_size()` has no such fallback: if either attr is missing from `vars(pg_collection)` — or `pg_collection is None` — it returns **1**. So for the same `(pg_collection, is_expert)` pair the weight gets sharded and reduce-scattered over `cp × gtp_remat`, but is stamped `param.gtp_remat_cp_size = 1`.

**Why it matters.** The stamp is the *only* signal DDP and the optimizer use:
- `param_and_grad_buffer.py:934` computes `excludes_cp_from_bucket = getattr(param, 'gtp_remat_cp_size', 1) > 1 and not is_expert_parallel` → **False**.
- `distributed_data_parallel.py:298-311` therefore reduces this buffer over `intra_dp_cp_group` with `1/dp_cp_size`, while the GTP reduce-scatter has *already* summed CP → **CP contribution counted twice**, silently wrong gradients (no assert fires).
- `param_layout.resolve_buffer_dp_world_size` also skips the `// cp_size` division, so the layout is computed over a different world size than the collective actually runs on.

**This is reachable in production, not hypothetical.** `megatron/core/transformer/attention.py:336-337`:
```python
if pg_collection is None:
    pg_collection = ProcessGroupCollection.use_mpu_process_groups(required_pgs=['tp', 'cp'])
```
That collection carries neither GTP field and is forwarded straight to `linear_qkv` / `linear_proj` (lines 389, 423-424). Any `SelfAttention` constructed without an explicit `pg_collection` hits exactly this asymmetry under `gtp_remat_size > 1 and context_parallel_size > 1`. TE constructors also default `pg_collection=None`, which returns 1 here but still resolves the merged group above. Note this also contradicts the new doc's claim in §3.8 that reading the CP degree off the param "makes it impossible for DDP and the optimizer to disagree" — the two *derivations* can disagree before the stamp is ever written.

**Fix.** Derive the CP degree through the same resolution path as the group, so the two can never diverge:
```python
def gtp_remat_cp_size(pg_collection, is_expert) -> int:
    if is_expert:
        return 1
    plain = None if pg_collection is None else vars(pg_collection).get('gtp_remat')
    merged = None if pg_collection is None else vars(pg_collection).get('cp_gtp_remat')
    if plain is None or merged is None:
        # Same fallback resolve_gtp_remat_group() uses, so the returned group and the
        # CP degree reported for it always come from the same source.
        mpu_pgs = ProcessGroupCollection.use_mpu_process_groups(
            required_pgs=['gtp_remat', 'cp_gtp_remat']
        )
        plain, merged = mpu_pgs.gtp_remat, mpu_pgs.cp_gtp_remat
    if plain is None or merged is None:
        return 1
    return merged.size() // plain.size()
```
