# Discard core attention outputs during selective recomputation

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7237) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Make selective `core_attn` recomputation release the attention output retained by the output projection, reducing activation memory with fused attention.

In our fused-attention comparison, enabling ordinary `core_attn` checkpointing did not reduce peak activation memory. The output projection still saves the core-attention output for its weight gradient. This PR replaces ordinary checkpointing with `CheckpointWithoutOutput`: discard the attention output after projection and restore it before projection backward consumes it. The existing selective-recompute configuration remains the entry point.

Register recomputation on the projection output so that restoration precedes both projection backward and optional output-gate backward. When `mla_up_proj` recomputation is also enabled, register its hook first on the same tensor: restore Q/K/V, then recompute core attention.

Reject selective `core_attn` recomputation combined with `attn_proj` activation offloading during configuration validation, because both manage the projection-input storage. Remove the obsolete fused-attention recomputation warning and update the existing documentation to classify `core_attn` as output-discarding checkpointing.

## Issue tracking

Related to [#1886](https://github.com/NVIDIA/Megatron-LM/issues/1886), which reports no memory reduction with `core_attn` checkpointing and uses fused attention in its reproducer. This change improves memory savings by releasing the attention output retained for projection backward.

**Restore input-layernorm output before MLA up-projection replay.**

**Failure:** Build a training `TransformerLayer` with the TE MLA submodules, `q_lora_rank=None`, and selective `recompute_modules=["layernorm", "mla_up_proj"]`; run forward and backward on a gradient-enabled input. Without Q-LoRA, [`_qkv_down_projection`](https://github.com/NVIDIA/Megatron-LM/blob/091d511c133395734cbffe805191959cfbd6430a/megatron/core/transformer/multi_latent_attention.py#L727-L746) passes the normalized hidden states directly through as `q_compressed`. That tensor becomes a saved input of the up-projection checkpoint.

This change registers up-projection replay on the projection output **before** the enclosing layer registers its [input-layernorm restoration hook](https://github.com/NVIDIA/Megatron-LM/blob/091d511c133395734cbffe805191959cfbd6430a/megatron/core/transformer/transformer_layer.py#L743-L749) on the same tensor. Hooks execute in registration order, so up-projection replay reads the still-discarded, zero-byte normalized input. Backward must instead restore that input before recomputing `linear_q_proj`. The [base implementation](https://github.com/NVIDIA/Megatron-LM/blob/b67127774ca558442fb566a3df6a50862c04e4b8/megatron/core/transformer/multi_latent_attention.py#L538-L548) registered up-projection replay on the core-attention output, allowing the parent's projection-output hook to run first.

**Correction:** Make the attention/TransformerLayer hook boundary enforce `input-layernorm restoration → MLA up-projection replay → core-attention replay → projection backward`. Account for both `attention_bda_and_cross_attention` and [`_forward_self_attention_output_with_bias`](https://github.com/NVIDIA/Megatron-LM/blob/091d511c133395734cbffe805191959cfbd6430a/megatron/core/transformer/transformer_layer.py#L717-L720). The exact graph-boundary implementation needs verification against CUDA-graph/offload contracts; simply reversing all hooks or restoring the old up-projection placement is not a complete fix.

**Preservation:** Keep the current Q/K/V-before-core-attention ordering when both recomputation modules are selected. Retain ordinary MLA with Q-LoRA, up-projection-only recomputation, MHA/gated attention, and the packed/unpacked cases.

**Acceptance — proposed regression checks, not executed:** Use the new test's small BF16 MLA dimensions inside a full `TransformerLayer`, but set `q_lora_rank=None`; compare `["layernorm", "mla_up_proj"]` and `["layernorm", "mla_up_proj", "core_attn"]` against identical non-recomputed models. Backward must complete, the normalized input storage must be restored before up-projection replay reads it, and outputs plus input/parameter gradients must match. Retain the [existing test's](https://github.com/NVIDIA/Megatron-LM/blob/091d511c133395734cbffe805191959cfbd6430a/tests/unit_tests/transformer/test_core_attention_recompute.py#L92-L124) two-outstanding-graph, zero-storage-before-backward, restored-storage-after-backward, and gradient-parity assertions.

Thanks for catching this. I confirmed that this PR introduces a hook-ordering regression with `q_lora_rank=None` and selective `layernorm` + `mla_up_proj` recomputation, both with and without `core_attn` recomputation. We will submit the fix and its regression tests in a single follow-up commit.

The fix creates a separate autograd boundary after the projection offload group commit and before MLA returns, using `make_viewless_tensor(output.view_as(output), requires_grad=output.requires_grad, keep_graph=True)`. The returned tensor shares the original output storage and remains viewless without copying the output data. The enclosing layer registers its layernorm recomputation hook on this new tensor, while the up/core hooks retain their existing order on the original projection output. This enforces **input-layernorm recomputation → MLA up-projection recomputation → core-attention recomputation → projection backward**.

We will also update the TransformerLayer regression tests to cover this recomputation combination and both call paths.
