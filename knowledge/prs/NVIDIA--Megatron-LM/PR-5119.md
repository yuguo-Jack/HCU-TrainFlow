# What does this PR do ?
Right now, prefix caching is closely intertwined with the rest of the inference context, making it very difficult to make incremental modifications to the inference context code. This PR factors it all prefix caching logic into separate classes and files so that targeted modifications can be made more easily.

<h3>Greptile Summary</h3>

This PR refactors prefix caching by extracting the logic from `KVBlockAllocator` and `MambaSlotAllocator` into two new focused classes (`PrefixCacheBlockState`, `PrefixCacheRegistry`) and a `PrefixCachedMambaMetadata` subclass of `MambaMetadata`. The `DynamicInferenceContext` now owns a shared `PrefixCacheRegistry` that both allocators delegate to for hash lookups, registration, and eviction.

- **`PrefixCacheBlockState`** takes over per-block tensor bookkeeping (hashes, ref counts, LRU timestamps) that lived inside `KVBlockAllocator`, exposing clean mutation primitives.
- **`PrefixCacheRegistry`** centralises all `hash→block_id` maps for KV and Mamba, replacing scattered dicts on the allocators, and owns the cascade-eviction callback wiring.
- **`PrefixCachedMambaMetadata`** absorbs intermediate-state extraction buffers and per-request CPU bookkeeping that previously lived on `MambaSlotAllocator`, with `MambaSlotAllocator` slimmed down to cache-pool resources and commit orchestration.

<h3>Confidence Score: 4/5</h3>

The refactor is a clean structural separation; the core allocation, eviction, and hash-registration paths are functionally equivalent to the old code and all changed tests have been updated to match the new API.

The compute_and_store_offsets method still hardcodes mamba_chunk_size=128 while _update_intermediate_metadata uses the configurable self.mamba_chunk_size — a non-default chunk size would produce mismatched filtering and invalid chunk indices. MambaSlotAllocator also has implicit coupling to PrefixCachedMambaMetadata with no runtime guard.

megatron/core/inference/contexts/attention_context/mamba_metadata.py (compute_and_store_offsets chunk size mismatch), megatron/core/inference/contexts/mamba_slot_allocator.py (implicit PrefixCachedMambaMetadata dependency in reset and _collect_commit_data)

<a href="#"><img alt="P2" src="https://greptile-static-assets.s3.amazonaws.com/badges/p2.svg?v=9" align="top"></a> The hardcoded `mamba_chunk_size = 128` is inconsistent with `self.mamba_chunk_size` inherited from `MambaMetadata`. `_update_intermediate_metadata` (also in this class) correctly uses `self.mamba_chunk_size` for the same chunk-alignment arithmetic. If the two values ever diverge — e.g. a non-default `mamba_chunk_size` is passed at construction — offsets that pass the filter here would produce invalid chunk indices inside `_update_intermediate_metadata` (e.g. `offset // actual_chunk_size - 1 < 0`).

```suggestion
        # Use the configured chunk size so this filter stays consistent with
        # the chunk-index arithmetic in _update_intermediate_metadata.
        mamba_chunk_size = self.mamba_chunk_size
```

Note: If this suggestion doesn't match your team's coding style, reply to this and let me know. I'll remember it for next time!

<a href="#"><img alt="P2" src="https://greptile-static-assets.s3.amazonaws.com/badges/p2.svg?v=9" align="top"></a> **Implicit dependency on `PrefixCachedMambaMetadata` not enforced**

`reset()` calls `self.context.mamba_metadata.reset_intermediate_state()` and `_collect_commit_data()` accesses `metadata._intermediate_block_ids_cpu` / `metadata._eos_cache_block_id_cpu` — both of which are defined only on `PrefixCachedMambaMetadata`. `MambaSlotAllocator` is constructed only when `use_prefix_cached=True` (which guarantees `mamba_metadata` is `PrefixCachedMambaMetadata`), so this is always safe at runtime. However, there is nothing in the call sites to make this relationship explicit, so a future refactor that changes the construction logic would produce a silent `AttributeError` rather than a clear type error. An `assert isinstance(self.context.mamba_metadata, PrefixCachedMambaMetadata)` guard in `__init__`, or typing `context.mamba_metadata` as `PrefixCachedMambaMetadata` in `MambaSlotAllocator.__init__`, would make the coupling explicit.
