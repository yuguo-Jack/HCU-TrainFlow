# What does this PR do?
With the MTP KV cache on, the EP dummy draft depths and the commit-pass placeholder called the MTP layer with no inference context, so attention took the static core-attention path, and the engine captured a cache-free MTP graph just for them. That path is TE DotProductAttention, which has no backend for head_dim 256 under --attention-backend flash, so speculative decoding died on its first request ("No dot product attention backend is available").

Stage the dummy forwards' draft metadata on the dummy block, as the warmup capture already does, and pass the context like the base dummy step: the draft depths replay the same ("mtp_kv", ...) graphs as real ranks, and the placeholder writes only scratch KV. Staging on the dummy block rather than the context's requests matters because the dummy also runs on ranks holding real requests (the async-scheduling primer, or an empty commit pass), whose draft KV it must not overwrite. The cache-free capture is skipped when the MTP KV cache is on.

The staging goes through the shared GPU bookkeeping buffer and the MHA metadata bounds, and the dummy runs before the step's own forward (in the primer and on idle ranks), so the dummy restores both afterwards; otherwise that forward ran with the dummy's max_seqlen_q=1. The MTP CUDA graph test helper now also counts the KV-aware graphs.
