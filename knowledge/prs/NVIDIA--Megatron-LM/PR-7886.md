# What does this PR do?

`dynamic_engine.py` goes down from 5000 lines down to 1000 lines.

I was doing a Claude de-tox this weekend, reading code with my own eyes.
That made me notice dynamic_engine.py is now very long, and honestly pretty hard to read because the logic is not really organized.

I wanted to try cleaning it up, so I used mix-ins and just literally copy-pasted the methods into other files.
Only one line of code had to actually change, inside shutdown.

I think this looks cleaner, what do you think?

- lmcafee-nvidia · comment · 2026-10-05T20:28:32Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7886#discussion_r4188427183)

File: `megatron/core/inference/engines/dynamic/loop.py` · line 107

the five new mixin classes are not covered by `DynamicInferenceEngine`'s `@experimental_api` marker, so their moved methods become subject to normal compatibility checks. we probably want to mark all five as `@internal_api` so internal changes do not create new compatibility obligations.

an example flow:

- a release includes the new helper classes.
- a later change adds a required argument to `EngineLoopMixin.wait_until`.
- the compatibility checker can reject that change even though the engine is experimental.
- marking the helpers internal keeps their methods outside that stability promise.
