# Make the global process-group usage check report-only

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7986) · state: closed · merged: True

## Original PR description

**Why.** #6258 added a ratchet against new reads of global process-group state in `megatron/core`. It fails CI in two places: the workflow's checker step, which is not a required check, and `TestCommittedBaseline.test_matches_current_tree`, which compares the real tree with the allowlist. The H100 catch-all unit-test bucket collects that test, and the bucket feeds the required `Nemo_CICD_Test`, so the ratchet is in effect a merge gate. It rejects any new read, including a `pg_collection=None` fallback to `parallel_state` for callers that don't pass a `ProcessGroupCollection`. It also rejects refactors that move a grandfathered read, or remove one without refreshing the allowlist. Whether new code may add such fallbacks hasn't been agreed yet. The repository's agent guidance (`CLAUDE.md`, "Megatron Core Process Groups") also treats the rule as advisory rather than a CI gate. This PR makes the check report-only until the policy is settled in #6307.

**What.**
- The workflow's checker step gets `continue-on-error: true`. New and stale entries are still listed in the job log, but the job passes.
- `TestCommittedBaseline` is removed. The remaining 29 tests run the checker on synthetic sources in temporary directories and don't depend on the tree.
- The checker, the allowlist, and `--update`/`--stats` are unchanged.

**Tests.**
- The 29 checker tests pass when the file is run directly (Python 3.12), and the checker passes on current main (210 grandfathered reads).
- I copied the tree twice: (a) adding a new fallback read to `megatron/core`, and (b) removing a grandfathered read without running `--update`. In both, the test file from main fails and this version passes. The checker still reports both cases and exits 1.
- There are no runtime code changes, so no performance impact.

Related to #6307.
