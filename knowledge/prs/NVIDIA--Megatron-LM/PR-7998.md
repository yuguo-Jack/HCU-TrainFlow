# Record and replay runtime prefetch order for MFSDP v2

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7998) · state: open · merged: False

## Original PR description

## Summary

MFSDP v2 currently derives prefetch order from module construction order, which cannot represent repeated calls to the same module. In MTP, the shared output layer is called consecutively for auxiliary and main logits. This PR records actual forward/backward module calls for one complete training iteration and uses those sequences for subsequent parameter prefetch.

## Changes

- Add `FsdpContext.record_prefetch_order()`. Recording disables speculative prefetch, preserves repeated module occurrences, and installs the observed sequences as `context.forward_order` and `context.backward_order` after successful completion. Recompute calls using `prefetch="none"` are excluded.
- Extend `IndexedOrder` to replay occurrences while retaining `next_item()` and existing prefetch budgets. Demand calls advance the cursor; prefetch lookahead does not. Replay raises on a mismatched module call.
- Allow repeated backward-pre hooks for shared modules while keeping parameter release and gradient reduction tied to completion of parameter-gradient accumulation.
- Add `--megatron-fsdp-record-prefetch-order` to record the first executed training iteration, including all microbatches. Shared contexts across model chunks are entered once.

## Usage and scope

Enable with `--use-megatron-fsdp --megatron-fsdp-version 2 --megatron-fsdp-record-prefetch-order --cuda-graph-impl none`.

Recording requires a complete, repeatable forward/backward call pattern and collective-compatible orders across ranks. The context API can record again when the pattern changes. Construction order remains the default when recording is disabled.

This change uses the existing prefetch path; scheduler compilation and parameter-retention optimizations are deferred.

## Validation

- Added occurrence-replay tests covering different successors for a reused module, prefetch budgets, cursor reset, and mismatched calls.
- Added a distributed numerical regression with two consecutive calls to a shared projection, modeling MTP output-layer reuse. It compares outputs, gradients, and parameter updates against a dense model across recording and replay iterations.
- Local source-level replay checks and real CPU autograd checks passed, with CUDA communication mocked. Formatting and lint checks passed.
- The distributed GPU regression has not been run in this environment.
