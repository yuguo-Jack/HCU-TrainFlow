# sdpa: bound Rubin paged split grids by packed query capacity

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1476) · state: closed · merged: True

## Original PR description

## Problem

The Rubin paged D128 split chooser estimates a rectangular `batch * ceil(max_q / token_tile)` grid even when the graph declares a smaller packed-query capacity. Mixed batches can therefore appear to fill the GPU although that grid cannot occur under the declared total-token bound.

## Change

Reuse the existing `_d128_thd_split_units` bound already used for Blackwell. It counts the first partial tile of each live sequence and bounds all additional tiles by the declared packed-token capacity. No runtime sequence lengths are read. Empty capacity retains the unsplit fallback.

When loop work and partial count tie, prefer the candidate with fewer physical CTAs, then the existing unpacked preference. This avoids discarding packing merely because the tighter bound makes both candidates fit in the same wave. The first-wave budget, split cap and minimum KV work per partition remain unchanged; there are no new knobs, kernels or public APIs.

This is stacked after #1469; keep Draft until that dependency and CI/review close out. The current develop-based diff includes #1469's bounded-override eligibility fix. Blackwell selection is unchanged by the incremental change here. No capability row or engine specification changes, so SDPA Rule S2 does not require a support-matrix update.

## Validation

- Equivalent-capacity geometry tests fail before the change and pass afterward. They compare declarations admitting the same query-length distributions, without pinning a winning split, packing choice or timing.
- Full geometry suite:652 passed.
- Target-SM107 public-wrapper qualification covers44 initial and independent shapes, including mixed batches, MHA/GQA, fixed/bounded graphs, no Stats/HN Stats, full-prefill and short-KV controls. O and requested LSE are checked against FP64 references; changed-input capture replay is checked separately. No performance numbers are published here.
- Changed-file pre-commit hooks and `git diff --check` pass.

The wrapper supplies a lifetime-enforced capacity. A current runtime token sum is not silently treated as a bound for future captured calls. These checks do not enable SM107 auto dispatch in FlashInfer.
