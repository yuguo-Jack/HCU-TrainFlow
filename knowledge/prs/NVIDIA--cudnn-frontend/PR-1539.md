# frost(gated_attention_block): `QsaSpec` declares block-sparse attention -- the indexer band as a fifth band of `W_qkvg` (unfused projection), the raw indexer key as a zero-copy view, `execute(block_ids=, block_lens=)`; every sparse request a typed decline

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1539) · state: closed · merged: True

## Original PR description

**Builds on #1471** (merged: the Qwen3.8 family geometries in the layout contract, the HF loader `qkvg_from_hf`, the doc's Flash-Next identity bound) -- which left the indexer band and the sparse layer as its open items 2 and 4. This PR lands the DECLARATION half of Qwen Sparse Attention in the gated attention block: **`QsaSpec`, a frozen declaration attribute appended to `GatedAttentionBlockGeometry` as `qsa`, `ProjBlock.INDEX` as the fifth band of `W_qkvg` (the indexer's query heads then its raw key head, below V) on the UNFUSED projection, the loader's `index_qk_proj_weight` arm, a zero-copy view of the raw indexer key, and the appended `execute(block_ids=, block_lens=)` -- while every request for the sparse attention itself is a typed decline naming the feature.** No kernel changes. **6 commits on `develop`, no merge commits; 7 files, +1261 / -66**, one new test module (`test/python/gated_attention_block/cutedsl/test_block_qsa.py`, 604 lines). Per file: `python/cudnn/gated_attention_block/api.py` +545 / -55, the new module +604, `docs/fe-oss-apis/gated_attention_block.md` +47 / -2, `test_layout_contract.py` +30 / -7, `api_bwd.py` +11 / -2, `__init__.py` +4, and the repository's public API index `test/python/api_index/api_index.txt` +20 (the new names, below).

The band has consumers queued behind it, each its own PR against this surface: the index-list sparse d256 forward (the sparse core), the block's sparse stage that routes stage (4) to it (inverting the `check_support` decline below), the in-block indexer (`index_source="indexer"`, which derives the block list from this band), and the paged KV-cache write-through, which writes the raw indexer key exposed here into the cache beside K / V.

## What

**1. `QsaSpec` -- a declaration attribute, never a knob** (`api.py`). `QsaSpec(block_size=4, top_k=512, index_source="caller", index_band=False, index_heads=4, index_kv_heads=1, index_head_dim=128, index_norm_eps=1e-6)`, frozen, attached as `GatedAttentionBlockGeometry(qsa=...)` (appended, default `None`: every existing geometry is unchanged). It declares block-sparse attention -- every query attends to the keys of its SELECTED 4-token blocks and to the open tail block of its visible range, under the causal mask (Qwen Sparse Attention: a 2048-token budget at block size 4 = the defaults) -- so it changes the FUNCTION and lives beside the geometry, not in a knob dataclass. `validate()` runs its own rows (`block_size == 4`; `top_k` a multiple of 4 in `[4, 512]` -- it sizes the kernel's per-query index staging, so the list is exactly `top_k` wide; `index_source` in `{"caller", "indexer"}`; the indexer fields positive) and the cross-field ones (`rope_dim <= index_head_dim`, `is_causal`, no sliding window: the selection IS the sparsity). `identity_bound` = `top_k * block_size + block_size - 1` = 2051 at the defaults: the visible-token count up to which every query's complete blocks fit the list, so a full list reproduces dense causal attention exactly. There is no `index_dtype` field: int32 is the one legal list dtype (an int64 list is refused, not converted), and the four indexer fields size the band only -- no kernel of this PR reads them.

**2. `ProjBlock.INDEX = 4` -- the fifth band, present iff `index_band`** (`api.py`, `test_layout_contract.py`). `qkvg_blocks` / `qkvg_block_widths` / `qkvg_offsets` / `qkvg_heads` / `qkvg_head_dims` grow a fifth entry iff the geometry declares the band: at `d_model = 2560, h_q = 24, h_kv = 2` the slab is `N = 13312 + 640 = 13952` columns (offsets `0, 6144, 12288, 12800, 13312`; `640 = (4 + 1) x 128`), the 64- and 128-column tile plans are well defined and the 256-column one is the typed refusal (`13952 = 109 x 128`, not a multiple of 256 -- pinned on the real method). Every geometry WITHOUT the band keeps its four-band tuples bitwise (the layout snapshot of the shipped 397B geometry is extended with `blocks == (Q, GATE, K, V)`, `head_dims == (256,) * 4`, `index_band False`, `qsa None`, every tuple of length 4, `index_k_raw_offset` refused). `block_for_column` decodes the band at the indexer's head dim; `n_qkv` stays Q + K + V. Consumers enumerate `geometry.qkvg_blocks`, never `ProjBlock` itself; the one place that unpacked `qkvg_offsets` into four names on the execute path now takes the first four (the band is never an SDPA operand) -- a latent `ValueError: too many values to unpack` on the first five-band execute, found while making such a block executable, fixed here where the five-band slab is introduced (the third commit).

**3. The band through the library** (`api.py`). `build_fused_qkvg_weight(..., index_qk_proj_weight=None)` (appended) and `qkvg_from_hf(..., index_qk_proj_weight=None)` (#1471 reserved the argument and accepted only `None`; it is functional now) take the indexer projection `[(index_heads + index_kv_heads) x index_head_dim, d_model]` -- its query heads then its raw key head, the checkpoint's own row order -- REQUIRED iff the geometry declares the band and REFUSED otherwise (a geometry without the band has exactly four bands); the dtype must be the other matrices'. The UNFUSED projection writes the wider slab (one GEMM over `N = 13952`); `saved_slab_views` returns the four dense bands only; `index_k_raw_view(proj_slab, geometry, B, S)` and `GatedAttentionBlockFwd.index_k_raw(workspace)` expose the raw indexer key -- the band's last `index_kv_heads x index_head_dim` columns, pre-norm, un-rotated, what a serving cache keeps -- as a zero-copy `[B, S, index_kv_heads, index_head_dim]` view of the stage-(1) slab, so a serving caller keeps ONE projection GEMM. The fused projection fork (`fuse_norm_rope`) declines a band, typed and geometry-first: its 256-column tiles cannot end mid-band.

**4. Every sparse request is a typed decline today; the execute surface is appended** (`api.py`, `api_bwd.py`). A block declared with `qsa` builds a sparse SDPA stage in stage (4)'s slot that declines at `check_support` ("the sparse attention core has not landed") AFTER the projection (with the band) and norm + RoPE accepted the five-band geometry -- so the stage list, the workspace carve (the dense carve + `B x S x 640 x 2` bytes for the band) and the raw-key view are exercised end to end short of the attention launch. At declaration, naming the feature: `thd`, `save_for_backward` (sparse training is out of scope; `GatedAttentionBlockBwd` refuses a `qsa` geometry at declaration, so its four-band unpacks never meet a fifth band), `quant`, `fuse_gate`, `fuse_norm_rope` together with `index_band`, `causal_bottom_right`, an fp32 activation, `h_q // h_kv > 16`, `index_source="indexer"`, `d_head != 256`. `execute(..., block_ids=None, block_lens=None)` (appended after the last existing keyword): `block_ids` `[T, top_k]` int32 (or `[B, S, top_k]`), per query the ids of its selected complete blocks (block `b` = tokens `[4b, 4b + 4)` of its own sequence), the valid prefix then `-1`; `block_lens` `[T]` int32 optional. Checked for FORM only -- dtype, rank, shape, contiguity, device -- never a value read on the host (an int64 list is refused, not converted); refused on a block declared without `qsa`.

**5. Docs** (`docs/fe-oss-apis/gated_attention_block.md`). A "Sparse attention (QSA)" section: the `QsaSpec` fields, the identity bound, what is served (the layout's fifth entry, the loader's band argument, the unfused projection's wider slab with `index_k_raw_view` / `index_k_raw`, the appended `execute` inputs and their form checks) and what is a typed decline until the sparse core lands; the `W_qkvg` bullet names the fifth block; a requirements bullet.

## Why

A serving stack that loads a Qwen3.8-Flash-Next checkpoint needs the layer's geometry stated once, before any sparse kernel exists: which weights go where (the indexer's `index_qk_proj` is ONE more band of the same projection GEMM, so the raw indexer key costs no extra launch and no copy), what a legal block list is (int32, `top_k` wide, the valid prefix then `-1`, blocks relative to the sequence), and which combinations the block will never serve. Landing the declaration first makes those facts tested and documented while the kernel (the index-list sparse d256 forward, its own PR) and the block's sparse stage (the PR after it) follow; a stack can build its loader and its list plumbing against this surface today, and a block that declares `qsa` fails LOUDLY at `check_support` rather than silently running dense attention past 2051 visible tokens (#1471's doc states exactly where the dense block IS the layer and where it is not). The band sits on the UNFUSED projection because the fused fork renders 256-column tiles and 640 is not a whole number of them -- a typed decline, not a slower block.

## Numerics

* No kernel change, no tolerance change. The one numerical fact is the band itself: on a Rubin GPU (cc 10.7) the `[512, 640]` band of the five-band slab written by the block's own unfused projection at `N = 13952` matches the fp64 `h @ W_qkvg^T` with `cos` 0.9999987 and `max |err|` 1.508e-2 at a column scale of 5.33 (half a bf16 ulp at the top magnitude; the GEMM suite's bar is 2 ulps of the max + 1e-3 x scale = 0.047), 99.85 % of the elements bitwise the rounded fp64 reference; the four dense bands are 100 % bitwise the four-band projection of the same `h` (max |diff| 0), 100 % bitwise after norm + RoPE, and norm + RoPE leaves GATE / V / INDEX bitwise untouched.
* `index_k_raw_view` and `GatedAttentionBlockFwd.index_k_raw(workspace)` are the SAME storage (the slab's columns 13824-13951) and equal `h @ W_i[512:]^T` within the same bar.
