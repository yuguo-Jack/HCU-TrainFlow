## Affected area

FE OSS kernels or CuTeDSL (FROST shared tile scheduler, `SCHED_LPT_L2` decode).

## Summary

`lpt_l2_tile_coords` puts as many KV groups in a block as the L2 budget allows. When the group count is not a multiple of that width, the last block can hold a single group and run under one wave. For example, 9 groups at a budget of 8 become blocks of 8 and 1.

This PR keeps the same block count and spreads the groups evenly, so the same example becomes blocks of 5 and 4. The width can only shrink, so blocks stay within the L2 budget. The tile -> (row, head, batch) map stays a bijection, so this changes scheduling only, not numerics.

All SM100/SM103, SM120 and SM90 LPT_L2 users share this decode.
- SM90's d512 kernel already floors its budget to a power of two. For the usual power-of-two group counts its width is unchanged; for other counts it is now balanced.
- The `SUPPORT_MATRIX_TRACKER.md` note that listed "a balanced width" as a follow-up is updated.

## Why

Setup: B300 SXM6 (148 SMs), cuDNN 9.27.0.42, CuTeDSL 4.8.0. I ran the 144-case dense fwd set (d64-d512, causal and non-causal, fwd and fwd_train) four times, alternating new, old, old, new. Each variant has its own Python tree and fresh compiled caches. Times are warm CUDA-graph replays of the first FROST plan, median of 11.

| Plans | n | new / old median | range | repeat noise (max) |
|---|---|---|---|---|
| `SCHED_LPT_L2` | 46 | 0.996 | 0.948-1.010 | 1.6% |
| `SCHED_LPT` / `SCHED_NATURAL` (control) | 98 | 1.000 | 0.986-1.014 | 2.0% |

The gains are concentrated in large-batch causal d512/d256 (DSv4 b16-b32, Qwen3.5 d256), at 4-5%. No LPT_L2 case is slower beyond the run-to-run noise.

Not measured: SM120, SM90 and Rubin timing. No RTX PRO 6000 was free for the A/B, so I am not claiming anything for those archs beyond the unchanged-width argument above.

## API and compatibility impact

None; scheduling order only.

## Testing

- No new unit test. The decode only runs inside kernels, and the existing GPU suites cover it, including the SM80 bitwise LPT_L2 short-last-block tests and the SM100/SM107 LPT_L2 plan tests.
- The B300 runs above executed every LPT_L2 plan in the fwd set with the new decode.
