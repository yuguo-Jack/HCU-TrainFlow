# FROST GEMM heuristic: sm120 cost-model profiles + opt-in eligibility for real workload graphs

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1500) · state: closed · merged: True

## Original PR description

Follow-up to #1460; one file: `python/cudnn/gemm/frost/planning.py`.

---

The joint geometry/split-K/orientation stage (`planning.select_strategy`) is gated per device profile and, until now, had no sm120 entries — on that part the production pick stopped at the rule-based baseline. While adding the profiles we found something broader: **the stage's strict graph gate rejects nearly every real priority workload**, verified on real chains on the target silicon — per-tensor- and global-scale GEMMs carry trailing scalar-scale MULs (with an fp32→bf16 epilogue output), and common fp16 GEMMs carry an n-major B. The recorded weekly sweeps confirm the stage changed zero picks on any architecture. Three changes:

1. **Opt-in eligibility relaxations.** `CostProfile` gains `b_n_major_ok` and `scalar_scale_epilogue_ok`; `profile_for` honors them. Both preserve the cost model's validity by construction: a scalar-scale epilogue adds a near-constant per-element cost that is identical for every candidate of the same layer (the ranking is unchanged by ignoring it), and operand majorness enters no cost feature. **Profiles that do not opt in keep the strict gate bit-for-bit** — existing architectures' behavior is unchanged, verified by test.
2. **Candidate-generation fix.** `candidate_configs` now passes the view's B layout (`b_n_major`, `b_elem_bytes`) to `select_config`; it was silently using the defaults, which mis-shapes auto candidates for n-major B.
3. **sm120 profiles** — f16, f8, block-scale f4 — for the RTX PRO 6000 Blackwell Server Edition, opted into both relaxations. Coefficients fitted by non-negative least squares on the weekly exhaustive sweep's measured kernel times (rows weighted by each layer's best time so small and large layers count equally; median model error 6–10% per dtype); extra candidate geometries are the sweep's most-frequently-optimal bases; the f16 and block-f4 entries carry `switch_margin=0.15` (at the default margin the model overrides baselines it cannot beat on this part). Device resolution, gate verdicts, profile lookup and end-to-end selection verified on the target silicon.

**Validation** — the full candidate ranking replayed against the same sweep, picks restricted to measured configs (every scored pick is a validated kernel). Geomean heuristic efficiency on governed layers (M, N ∈ [32, 4096], K ∈ [1024, 16384]):

| profile | baseline (#1460) | with profile | regressions |
|---|---|---|---|
| f8 | 0.873 | **0.925** | 0 (n=36) |
| block-f4 | 0.835 | **0.901** | 0 (n=50) |
| f16 | 0.934 | 0.934 | 0, 1 win (n=41) |

Projected set-level geomeans over the full priority-model GEMM shapes (profiles where they govern, #1460 elsewhere): **fp4 0.907, fp8 0.917, fp16 0.857**.

**Notes.** The model ranks the full split range and its runtime probe accepts anything that compiles, so production can pick splits outside the sweep's validated axis; the next weekly sweep audits production picks directly. f16 coverage is structurally limited (most f16 priority shapes carry epilogue fusions beyond the scalar-scale relaxation). The sm100/sm107 profiles remain on the strict gate here — enabling them on real workloads would first need refitting against those architectures' sweeps, since offline replay shows interventions with mixed outcomes under the relaxed surface.
