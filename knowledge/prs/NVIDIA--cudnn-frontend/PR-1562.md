## Affected area

C++ header `include/cudnn_frontend_shim.h`: the dynamic loading of the CUDA driver and runtime libraries (`NV_CUDNN_FRONTEND_USE_DYNAMIC_LOADING`, which the Python package uses)

## Summary

Fixes #809.

On Windows, `graph.build()` raised `RuntimeError: Unable to load any libcudart.so.* library.`. Every platform used the same library names: `load_cuda_so()` opened `libcuda.so.1`, and `load_cudart_so()` tried `libcudart.so.12` / `libcudart.so.13`.

- **Library names:** on `_WIN32` the shim now opens `nvcuda.dll` and tries `cudart64_12.dll` / `cudart64_13.dll`. This matches what `nvrtc_shim.h` already does for NVRTC (`nvrtc64_*.dll`). Linux names are unchanged.
- **Error handling:** on Windows `dlerror()` is `#define`d to `GetLastError()`, an integer error code.
  - The shim cast that integer to `const char *`. On a failed load, it then built a `std::string` from it.
  - A successful `LoadLibrary` / `GetProcAddress` does not reset the last error, so a stale code from an earlier call would also turn a successful load into a failure.
  - Now success is judged by the returned handle or symbol alone. A new `last_dl_error()` helper formats the error: the `dlerror()` text on POSIX, `Windows error <code>` on Windows.
  - On POSIX, the behavior is unchanged.
- **`get_cuda_symbol()`:** `GetProcAddress` returns a function pointer, so the lookup now goes through `reinterpret_cast<void *>`. The symbol check follows the same rule.
- **Message:** the "no runtime found" message now names the candidates it tried.

The one failure is `test_stream_captured_graph_outlives_the_cudnn_graph` ("OSS RmsNorm+SiLU engine not built."). It fails the same way with a pybind module built from `develop`, so it is a local-environment issue unrelated to this change. It is green in CI.

Windows branch, syntax only:
- **Method:** I compiled the shim on Linux with `_WIN32` defined and a stub `windows.h`, after the CUDA/cuDNN headers were parsed.
- **Strict GCC:** `develop` reports the `GetProcAddress` → `void *` conversion in `get_cuda_symbol`, and this branch removes it. The remaining errors are the same on both: the existing `get_symbol` → `void *` lines for backend symbols, which MSVC accepts.
- **`-fpermissive`:** both compile.
