## Affected area

C++ headers: `include/cudnn_frontend/backend/`

## Summary

Fixes #1559.

Three backend headers included the cuDNN backend header as `"cudnn.h"`:
- `backend_descriptor.h`
- `execution_helpers.h`
- `plan_helpers.h`

A quoted include searches local directories before the `-I` paths:
- **GCC/Clang:** the including file's own directory, then `-iquote` directories.
- **MSVC:** the directories of every file up the include chain, including the user's source directory.

So on Windows, a user's `CUDNN.h` next to their source was picked up instead of cuDNN's header, because Windows filenames are case-insensitive. This PR changes all three to `#include <cudnn.h>`, which is what `cudnn_frontend.h` already uses.

After the change, no quoted include of a CUDA or cuDNN system header remains on `develop`. I checked with `git grep` for `cudnn.h`, `cudnn_{backend,graph,ops,adv,cnn,version}.h`, `cuda*.h`, `nvrtc.h` and `cublas*.h`.

## Testing

Linux reproduction of the same mechanism:
- **Command:** `g++ -std=c++17 -fsyntax-only` on a TU that only includes `<cudnn_frontend.h>`.
- **Setup:** cuDNN 9.27 headers. An `-iquote` directory holds a stray `cudnn.h` containing `#error`. On GCC, an `-iquote` directory is searched for quoted includes only.

| | without stray header | with stray `-iquote` `cudnn.h` |
