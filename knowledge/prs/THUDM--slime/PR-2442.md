# fix(weight-sync): honor checkpoint shard indexes in disk delta sync

[Upstream PR](https://github.com/THUDM/slime/pull/2442) · state: closed · merged: True

## Original PR description

Disk-delta sync can report success while leaving the model's indexed weights unchanged when a checkpoint directory contains unreferenced safetensors files with duplicate tensor names. Both the trainer's baseline reader and the engine's local checkpoint writer scan every safetensors file, so a stale file visited last can override the indexed tensor location. The sender and receiver can agree on that stale file, pass checksum verification, and still leave the weights used for model reload untouched.

Read the shard list from `model.safetensors.index.json` when present, matching the model loader's indexed-file selection. Apply this to the trainer and both SGLang patch bundles. Missing indexed shards fail instead of falling back to stale files; unindexed checkpoints retain the existing behavior.

### Validation

- Added 13 CPU regression cases covering indexed selection, missing shards, unindexed checkpoints, and actual pull/apply round trips for both encodings and both patch bundles. The tests execute the receiver module extracted from each shipped patch.
- On baseline `8c17b676`: **10 failed, 3 passed**. With this change: **13 passed**.
- Additional local H20 probe: four GPUs tested independently × two encodings × two patch bundles. All 16 cases failed before and passed after; each passing case applies three successive BF16 SGD updates and checks reloaded weights and forward outputs with zero tolerance. This is a checkpoint/transport integration probe, not a full SGLang serving or RL run.
- Black, isort, Ruff, `git diff --check`, and `git apply --check` for the modified standalone receiver module in both bundles passed.

Reproduce the committed regression suite with:

```bash
python -m pytest tests/test_disk_delta_checkpoint_index.py -q
```

Prepared with Codex assistance; validation results above were observed on the actual before/after implementations.
