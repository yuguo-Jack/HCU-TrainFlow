# fix(args): reject unsupported colocated offload sync

[Upstream PR](https://github.com/THUDM/slime/pull/2311) · state: closed · merged: False

## Original PR description

## Summary

- Reject the known-incompatible Megatron configuration that combines colocated local rollout engines, training offload, full weight sync, and the NCCL transport.
- Run the validation after custom YAML overrides, so a dangerous `custom_config` cannot bypass it.
- Keep valid boundaries unchanged: no-offload, zero local rollout GPUs, `debug_train_only`, non-colocated runs, and full+disk sync.
- Point users to the two supported choices: full+disk with a shared `--update-weight-disk-dir`, or `--no-offload-train` when memory permits.

Colocated full sync currently uses `UpdateWeightFromTensor` and CUDA IPC even when `--update-weight-transport=nccl` is selected. torch_memory_saver-backed offload allocations are not compatible with that PyTorch CUDA IPC serialization path, so this turns a late `storage._share_cuda_()` failure into an actionable startup error.

This is the narrow fail-fast stage; it does not claim to add a new non-disk colocated transport.

- liuhao-labs · comment · 2026-10-10T08:40:41Z · [source](https://github.com/THUDM/slime/pull/2311#issuecomment-6095769152)

Withdrawing this blanket validation rule after rechecking current main (`22a89f9`). The standard Docker dependency was updated in #2448 to [zhuzilin/torch_memory_saver@4d525cf](https://github.com/zhuzilin/torch_memory_saver/commit/4d525cf378fdbfe7eb044909b8e66e112a508624), whose “Fix shared stream” change addresses the disabled-allocation IPC failure.

The fixed `disable()` owns a non-pooled CUDA stream and avoids reusing tracked/VMM blocks in that stream's cache. Its `test/examples/disable_ipc.py` regression pauses tracked allocations, allocates an update tensor inside `disable()`, and successfully exercises `storage._share_cuda_()`. Slime's colocated updater already builds/serializes its fresh flattened bucket inside that disabled region.

This PR would reject the fixed standard environment unconditionally, so it is no longer an appropriate restriction for current main. Older environments (including the legacy GB10 Docker pin of `torch_memory_saver==0.0.9`) may still need an upgrade or disk transport; this withdrawal does not claim that every historical installation is fixed or close #2188.

This conclusion is based on the pinned dependency source and upstream regression; I have not run the CUDA IPC test on this local CPU Python environment. The branch and local worktree remain available for historical reference.
