**runner/primus-cli-direct.sh:1**
* This changes exit-code semantics compared to the previous implementation. Using `$?` after `eval` only captures the status of the last command executed (and for pipelines, typically only the last pipeline element), whereas the previous `${PIPESTATUS[0]}` captured the first command’s status. Also, removing `set +e`/`set -e` can cause the script to terminate early under `set -e` before `exit_code` is recorded. Consider restoring the prior pattern (temporarily disable `errexit` and use `PIPESTATUS`) or explicitly decide and document which pipeline element’s exit code should drive `exit_code`.
