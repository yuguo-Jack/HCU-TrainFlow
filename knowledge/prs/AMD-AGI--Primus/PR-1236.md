# ci: bump Primus-Turbo to e2d9f1d7 and stop forcing the DeepEP cheap fence in MoE recipes

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1236) · state: closed · merged: True

## Original PR description

## Why
#1218 set `PRIMUS_TURBO_DEEPEP_DISABLE_CHEAP_FENCE: "0"` in the DSv2-Lite / Mixtral / Qwen3 recipes. On the pinned Turbo `ae1ac068` that forces the pre-#539 intranode cheap fence, which can drop the system-scope write-back and corrupt DeepEP dispatch-backward rows (seen in 3/15 reps on DSv3, up to 34900x the cross-rank bound).

Primus-Turbo #539 repairs the cheap fence and makes it the default, so the env is no longer needed.

## What
- `PRIMUS_TURBO_COMMIT`: `ae1ac068` -> `e2d9f1d7` (Turbo main: #539 + #538). The old comment cited `a26a5066`, which is the gelu clamp (#506), not the fence fix.
- Drop the fence env from 13 MI355X / MI325X recipes. Mixtral 8x7B FP8 and 8x22B never enable `use_turbo_deepep`, so the env was a no-op there.

Both changes are needed together: removing the env on the old pin falls back to the full fence.

## Results (MI355X, 1 node, 50 iters, mock data, same node; Turbo 53099da3 = #539)
| model | cheap (default) tok/s/GPU | full tok/s/GPU | speedup | max abs loss diff |
|---|---|---|---|---|
| DSv3 4-layer | 26912 | 26293 | +2.35% | 0.0012 |
| DSv2-Lite BF16 | 41169 | 38204 | +7.76% | 0.0011 |
| Mixtral 8x7B BF16 | 13293 | 12642 | +5.15% | 0.0010 |
| Qwen3-30B-A3B BF16 | 28011 | 26256 | +6.68% | 0.0065 (run-to-run noise; full-vs-full is 0.0064) |

No NaN or skipped iterations. Rowmap probe on DSv3 4-layer: #539 cheap 0/14 reps with bad rows, full 0/4.
