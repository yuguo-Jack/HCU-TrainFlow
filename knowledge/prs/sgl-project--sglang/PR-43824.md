# [NPU] Preserve CPU offload state and dynamic compiled graph replay

## Original PR description

# Draft: [NPU] Preserve CPU offload state and dynamic attention during compiled graph replay

## Problem and change

On the evaluated SGLang 0.5.20 NPU stack, CPU weight offload together with torch.compile and prefill/decode graphs encountered host-copy, state-dictionary tracing, kernel-launcher tracing and attention graph-dispatch incompatibilities. The proposed package keeps offloaded weights in pinned host memory, creates a fresh metadata-preserving state dictionary, selects the decode graph path while compilation is enabled, and introduces an opaque BSH FIA compile boundary that lowers to the existing native FIA capture handler. The companion sgl-kernel-npu change provides the QKV compile boundary.

No FIA mathematics, native kernel implementation, model weights or output text is replaced. The capture adapter is required: the earlier wrapper without it replayed lengths 1 -> 2 -> 1 as outputs 2 -> 2 -> 2; the final adapter produces 2 -> 4 -> 2 using the existing native update mechanism.

## Base and scope

The measured patch is based on v0.5.20 (94602c9c2b7cbdb8efd5c52802dac6a1c180089e). The original offloader.py and ascend_backend.py retrieved from that commit match the saved baseline SHA-256 values byte for byte. Strict git apply --check --whitespace=error passed on those files.

The existing upstream release/v0.5.20 branch points exactly to 94602c9c2b7cbdb8efd5c52802dac6a1c180089e and is the proposed PR base. This draft deliberately targets that measured release, not current main. Any later main forward port requires a separate explicit integration review. At main f006fb49ecd93322802ddebff80821f8e6296893, the patch does not apply to offloader.py: upstream now uses _get_offloaded_device_state(keep_vars=True), preserves tied parameter transfers and excludes cached MLA/KDA weights from offload. Those changes must be retained. Do not replace current files with the measured old package. Evidence below belongs to the measured v0.5.20 candidate, not an untested forward port.

The metadata change affects all OffloaderV1 users, not only NPU. The graph-mode dispatch change affects the shared Ascend backend. The BSH helper is narrower than that dispatch change. The capture adapter imports TorchNPU private _IFAv1DefaultHandler/register_npu_graph_handler interfaces at backend import time; compatibility is established only for the archived torch_npu 2.10.0 implementation. It registers the new custom-op name, not a replacement native FIA handler. OffloaderV2 and the existing global offloader singleton are unchanged.

## Existing validation (not rerun for submission)

Environment: SGLang 0.5.20, sgl-kernel-npu 2026.6.1, torch/torch_npu 2.10, Qwen3-ASR 0.6B. Both prefill and decode graph replay and compilation were observed in the server logs.

- Offload 0 and 4: 20 real requests per arm, 40/40 complete; paired text identical, each arm 2/216 word edits.
- Ready allocated memory: 2.409 -> 1.589 GiB. This is a ready-state snapshot, not request peak memory.
- Request median: 0.229 -> 0.446 s; P95: 0.300 -> 0.571 s. Offload trades latency for memory.
- Compiled CPU-weight changes remain live (output 16 -> 24).
- Same captured FIA graph, lengths 1 -> 2 -> 1: output 2 -> 4 -> 2.
- Metadata hook regression against ordinary dict retained; final fresh OrderedDict subclass preserves metadata and ordinary hook/buffer behavior.
- Matching QKV companion patch: original/candidate equality, output layout and no-alias checks, same-graph changed input.
