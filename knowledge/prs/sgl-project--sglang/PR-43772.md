# [Core] Add request-level customized_info keys and mark Full prefill capture batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/43772) · state: open · merged: False

## Original PR description

## Motivation

`customized_info` values are token-sliced: `_GenerationStreamAccumulator` appends `values[send_token_offset:len(output_ids)]` for each request and pads requests without the key with one `None` per output token. A value that describes the whole request rather than one position per token does not fit that shape:

- a request that finishes with no output tokens slices its value down to `[]`, so the only value it produced is lost;
- a streaming request re-sends the value on every chunk, and `TokenizerManager` accumulates the chunks into duplicates;
- cumulative (non-incremental) streaming returns only the last queued output when several are waiting, so a value that arrived on an earlier queued chunk never reaches the client.

Separately, Full prefill CUDA graph capture pads the request axis with zero-length slots, but nothing on the `ForwardBatch` tells a model that it is running inside such a capture. A model that selects rows per request (for example, the last token of each request) has no way to keep the inactive slots out of a data-dependent selection.

## Modifications

- `SchedulerOutputStreamer.is_request_level_customized_info_key(key)` lets a subclass declare keys whose value is emitted once per request. The default returns `False`, so existing keys are unchanged.
- `_GenerationStreamAccumulator.accept` emits a request-level key on the first chunk of a streaming request, or with the terminal output of a non-streaming one, and pads requests without the key with `[]` instead of token-shaped `None` padding.
- `TokenizerManager._wait_one_response` copies `customized_info_accumulated` into the `meta_info` of the output it returns under cumulative streaming, with `setdefault` so keys already present on that output win.
- `ForwardBatch.full_prefill_cuda_graph_capture` is a new flag; `PrefillCudaGraphRunner.capture_prepare` sets it when the prefill backend is Full.

Tests: four cases in `test_output_streamer_customized_info.py` (zero-token finished request, streaming emits once, non-streaming waits for finish, empty slot for a request without the key), one in `test_tokenizer_manager_rid_cleanup.py` (cumulative backlog keeps the accumulated key), and one in `test_prefill_cuda_graph_runner.py` (Full capture sets the flag, Breakable does not). The existing `_make_accumulator` helper in `test_output_streamer_logprobs.py` passes the new required field.

## Accuracy Tests

Not applicable: no kernel or model forward change. The new flag is set during capture only and no in-tree model reads it yet.

## Speed Tests and Profiling

Not applicable: the request-level path only runs for keys a subclass declares, and the default declares none.
