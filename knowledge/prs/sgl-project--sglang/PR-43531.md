## Motivation

The `direct + page_first_direct` H2D path allocates CPU copy-descriptor arrays on every invocation and repeatedly obtains tensor base addresses inside the page/layer loop.

This PR reduces CPU preparation overhead without changing transferred data, CUDA submission count, or cache lifecycle semantics.

## Modifications

- Reuse thread-local capacity for source pointers, destination pointers, and copy sizes.
- Retain workspace capacity for calls with up to 65,536 descriptors; larger calls use temporary storage.
- Precompute per-call layer base addresses and calculate page offsets outside the layer loop.
- Replace the single-element H2D attributes-index vector with a stack variable.
- Clear workspace logical sizes on exit to prevent stale descriptors between calls.
- Add registered CUDA regression tests for layouts, repeated calls, workspace boundaries, storage-offset views, and separate host threads.

Copy addresses, sizes, descriptor ordering, current-stream behavior, CUDA 12/13 ABI dispatch, and fallback behavior remain unchanged.

No changes to scheduler synchronization, events, ACKs, buffer/lock ownership, or D2H transfer semantics.

## Accuracy Tests

A/B microbenchmark validation passed raw-byte copy checks and confirmed execution of the CUDA batch-copy path using the original image binaries.

The newly added registered regression suite has **not yet been executed**. It checks selected and unselected destination bytes across:

- MLA and MHA K/V layouts.
- `uint8`, FP16, and BF16.
- Page sizes 1, 16, and 256.
- Repeated calls, workspace boundaries, and storage-offset views.
- Separate host threads with independent streams and buffers.

The final workspace-selection cleanup passed static/style checks but has not been separately rebuilt or GPU-tested.

No model-level accuracy improvement is claimed.

## Speed Tests and Profiling

Same-GPU A/B measurements used four stages, 12 independent timing processes, and 24,000 raw timing samples. No `.so` reconstruction or replacement was used.

Representative CPU submission measurements:

| Case | Baseline | Optimized | Reduction |
| --- | ---: | ---: | ---: |
| C1 KV, 256 physical pages | 111.65 μs | 109.16 μs | 2.23% |
| C2 KV, 128 physical pages | 58.09 μs | 56.55 μs | 2.65% |
| SWA, 512 physical pages | 215.33 μs | 211.74 μs | 1.67% |

These cases showed repeatable savings of approximately **1.5–3.6 μs per invocation**. Single-page and indexer cases did not establish a reliable benefit.

Measurements cover CPU submission overhead, including wrapper and CUDA API costs—not isolated descriptor preparation or GPU transfer duration. They correspond to the tested A/B binaries, before the final source-only cleanup.

No model-level TTFT or throughput improvement has been demonstrated. This optimization does not reduce transfer bytes or CUDA submission count.
