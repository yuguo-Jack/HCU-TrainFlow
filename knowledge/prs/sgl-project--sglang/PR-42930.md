# [unified-memory] trtllm_mha on the unified pool: decode graphs and speculative decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/42930) · state: open · merged: False

## Original PR description

## Motivation

Under `--enable-unified-memory`, trtllm_mha could not run with decode CUDA graphs (the gate refused them, because each replay's page-table refill took the previous replay's lengths), and it was off `TRANSLATED_MHA_RAILS`, so no speculative algorithm could use it as a target or a draft. #42753's per-iteration `KVLocPlan` closes the read side: the graph refill copies the plan's table, built from this batch's `seq_lens` plus the window it writes, and the graphs-off path reads the same table. This PR fixes the remaining trtllm_mha defects on the unified pool, two of which also affect the static pool, and admits trtllm_mha on the translated MHA rails. Seven commits on main: 11 files, +735/-60.

## Modifications

1. **Lift the decode-graph refusal** (`arg_groups/kv_cache_hook.py`). With #42753 the refill covers every page a replay reads: plain decode, and the draft decode, target verify and draft extend replays of speculative decoding.
2. **Zero MHA page envelopes on hand-out** (`allocator/unified_sub_pool.py`, `unified_memory_pool.py`, `kernels/ops/kvcache/zero_pages.py`). trtllm_mha's fmha_v2 prefill (SM90/SM120) loads K and V a whole page at a time and masks the positions past a request's length only in the scores, so their V rows still enter P·V with a zero probability, and 0 × NaN is NaN; XQA decode does the same with an fp8 KV cache (its bf16 kernel zero-fills those rows). MLA pools already zero on hand-out (#33974); MHA pools did not, and under a mamba hybrid those bytes can hold fp32 recurrent state that reads as bf16 Inf/NaN (Qwen3.5-9B GSM8K 0.49 against 0.90 at `--mem-fraction-static 0.30`).
3. **Require packed page tables on the graphs-off path** (`layers/attention/trtllm_mha_backend.py`). XQA decode and fmha_v2 prefill are handed only a page table's data pointer and take its row length from its width; they ignore its strides. The plan's table is a column view of a wider tensor only when a captured graph had it built in its own buffer earlier in the same iteration and the batch is narrower than that buffer, which no known configuration produces; such a table would be misread silently. The backend now asserts that both of its tables (full and sliding-window) are packed. These tables stay as wide as the batch needs, while the captured and static ones are `max_num_pages` wide, and XQA sizes its multi-block split from the width: graphs-off decode can round differently, the same attention but not bit-identical.
4. **Keep the slot-0 sink out of the debug poison fill** (`unified_memory_pool.py`). `SGLANG_DEBUG_POISON_POOL` also filled the page-0 sink, which XQA reads at zero weight for a sliding window's freed pages, so a poisoned window-model run reported NaN that serving never sees.
5. **Keep fmha_v2 prefill out of XQA's workspace semaphores** (`trtllm_mha_backend.py`; static pool too). On SM90/SM120 both kernels share one workspace, and fmha_v2's tile counter sat on XQA's first multi-block semaphore. After any prefill, the next small-batch XQA launch dropped a tile of its output: Qwen3.5 with NextN or DFLASH on trtllm_mha hit NaN in the first draft step and scored 0.19-0.55 on GSM8K, against 0.89 on triton. fmha_v2 now gets the workspace past XQA's 8 MiB.
6. **Copy only the batch's pages for the fmha_v2 prefill** (`trtllm_mha_backend.py`; static pool too). fmha_v2 takes K and V as one `[pages, 2, page_size, heads, head_dim]` tensor, and the backend stacked the layer's whole pool for every prefill layer: 0.4-2.6 ms per layer, about 6x that on the unified pool's strided views. It now gathers the batch's pages into a compact copy.
7. **Admit trtllm_mha on `TRANSLATED_MHA_RAILS`** (`kv_cache_hook.py`, `mem_cache/kv_cache_configurator.py`). trtllm_mha reads every path a draft forward takes through the plan, so it joins the rails: the EAGLE/EAGLE3 target on an MHA host, the EAGLE/EAGLE3 draft on every host, the DFLASH target, and the fused-draft decision. DSPARK's target set is unchanged. The comment and docstring that named trtllm_mha as a draft that declines fusion go.

Tests (each fails without its change):

- `test_trtllm_mha_graph_metadata.py`: decode, draft-decode, target-verify, draft-extend and ragged-verify replays, through the real `KVLocPlan` and a page map rewritten before every replay, read only the current replay's pages (a refill bounded by `cache_seqlens_int32`, or a table without the read extent, fails them); a graphs-off table that is a strided view of a wider buffer fails the packed-table assert; fmha_v2's workspace stays off the semaphores and its prefill copies only the batch's pages.
- `test_unified_handout_zeroing.py`: MHA, mamba and tri-pool pages are zeroed on hand-out; the poison spares the sink.
- `test_unified_prefill_cuda_graph_gate.py`, `test_unified_memory_spec_gate.py`, `test_fused_draft_placement.py`: decode capture boots; trtllm_mha is admitted for EAGLE/EAGLE3 (target and draft) and DFLASH and stays refused for DSPARK's target; a trtllm_mha draft fuses.

## Accuracy Tests

SM90, TP1, radix cache, trtllm_mha on both arms (page size 64). Baseline: the static pool. Unified: `--enable-unified-memory` with lazy compaction (the default), plus eager compaction (`SGLANG_DISABLE_LAZY_COMPACTION=1`) where a table lists it. GSM8K, all 1314 test questions, 5-shot, greedy. Every unified arm ran on a poisoned pool (`SGLANG_DEBUG_POISON_POOL=1`, every never-written byte a bf16 NaN), so a read of a slot nobody wrote collapses the score instead of hiding.

Qwen3.5-9B with NextN and DFLASH on trtllm_mha (`--mem-fraction-static 0.3`, overlap scheduler). The draft fuses into the target's pages on every unified arm; the NextN draft runs on trtllm_mha itself.

## Speed Tests and Profiling

`bench_serving` with random prompts at concurrency 64, in two shapes: 2048 input / 512 output tokens (200 prompts) and 8192 input / 64 output tokens (100 prompts). trtllm_mha on both arms, radix cache, overlap scheduler, CUDA graphs on, `--mem-fraction-static 0.55`; the speculative runs one server at a time. The baseline runs twice, and each delta is unified against the mean of the two baseline runs, with the spread between those two runs (A/A) beside it. These ran on this PR's commits before #42753 and the PRs under it merged, with the four fixes below applied: without #43170 and #43171, main's own unified-pool costs on these two models (host syncs in gpt-oss-20b's sliding-window frees, Triton GDN prefill on Qwen3.5) dominate the gaps.

## Notes for reviewers

- The gpt-oss-20b EAGLE3 accuracy runs and the speed tests ran with four other unified-memory fixes applied on top of this PR: #43168 (page-aligned sliding-window retention for unaligned windows), #43170 (sliding-window frees without a host sync), #43171 (FlashInfer GDN prefill on page-major pools) and #43169 (allocation eviction against the joint full/sliding-window fit). Each is independent of this PR.
- Validated on SM90 only. Through the shared rails, a draft that a model hook puts on trtllm_mha on SM100 (Kimi-Linear / Kimi-K3 with DSPARK) now fuses into the target's pages, and an MLA host's EAGLE draft may run on trtllm_mha; neither runs on this hardware.
