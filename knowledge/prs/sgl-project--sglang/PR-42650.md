# [Mamba2] Add checkpoint-preserving FlashInfer SSD prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/42650) · state: open · merged: False

## Original PR description

## Summary

Add opt-in FlashInfer SSD prefill for Mamba2 with
`--mamba-prefill-backend flashinfer` (default remains `triton`). This accelerates
recurrent prefill while preserving live states and reusable checkpoints.

**Draft, dependent on #41968.** This targets `main` and includes an older replay
parent snapshot; reconcile/drop those commits before merging.

## Implementation

- Prepare packed-sequence/checkpoint metadata once per forward. Capture selected
  checkpoints in the same scan, without changing checkpoint policy.
- Isolate padding in a discarded sequence so it cannot alter real final states.
- Use upstream exact scan with `dt_limit=(0.0, inf)` and FP16 processed delta.
  Decode kernels, cache policy and pool allocation are unchanged.

Code: [SSD adapter](https://github.com/NVShreyas/sglang/blob/8118f9dcf2dd1bb07cefde6267cc17420e4a3d9b/python/sglang/kernels/ops/mamba/flashinfer_ssd.py),
[correctness tests](https://github.com/NVShreyas/sglang/blob/8118f9dcf2dd1bb07cefde6267cc17420e4a3d9b/test/registered/kernels/ops/mamba/test_flashinfer_ssd_prefill.py).
Currently requires SM100 and static contiguous pools; unified/page-major pools
are unsupported.

Validated with unmodified FlashInfer
[`461037fbf`](https://github.com/flashinfer-ai/flashinfer/commit/461037fbf52227e6343ccbc9fc977337c1bf672b)
(`0.7.2+g461037fbf`). **No custom FlashInfer patch is needed** for the tested path;
FlashInfer #6080 is no longer a dependency. The repository dependency pin still
needs updating; stock 0.7.0.post1 is not the qualified SSD implementation.

## AgentX results

Public model: [NVIDIA Nemotron 3 Super 120B A12B NVFP4](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4),
revision `ff433f5493e25d631c9f12b5d55c674229923d02`; one B200, TP1 per variant.
All three use the same instrumented SGLang base (main `41cbe65de0`) and upstream
FlashInfer `461037fbf` build. Only replay and recurrent-prefill selection vary.
“Stock” is the default snapshot/Triton path on that build, not pristine/latest main.

### Public trace and replay settings

- AIPerf AgentX MVP, pinned dataset
  [`semianalysisai/cc-traces-weka-062126-256k`](https://huggingface.co/datasets/semianalysisai/cc-traces-weka-062126-256k),
  alias `semianalysis_cc_traces_weka_062126_256k`; all eligible sessions, seed42.
- **900 measured seconds per point**, one run; concurrency counts **session
  trees** including subagents, not in-flight requests. Preserve recorded turn
  delays, trajectory-start ratios0–1 and global idle-gap cap10s.
- Flush cache before each point; retain AgentX trajectory warmup into measurement
  and use `first_turn_prefix` cache-busting. No extra session cap.
- FP8 KV, FP16 state, EAGLE three steps/four positions, **synthetic AL3.2527**
  (`match-expected`, fixed-token mode). Context1,048,576; prefill/chunk32768;
  page64; `extra_buffer`, tracking128; stochastic rounding/Philox5;
  memory fraction0.85; max-running256; graph cap256; `trtllm_mha`.
  No offloading/unified pools. AIPerf commit `754356e9a39acc6cc6afb242d123bb57c3fb6f75`.

| Session trees | Stock output tok/s | + replaySSM | + replaySSM + SSD | SSD gain over replay |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 340.09 | 358.63 | 358.63 | 0.0% |
| 32 | 859.83 | 906.82 | 960.78 | +6.0% |
| 64 | 840.75 | 1,216.77 | **1,393.49** | **+14.5%** |

At C64, the combined gain is **65.7% over stock**; SSD's incremental gain is
14.5%, not 65.7%. Stock peaks at C32; both optimized variants peak at C64 among
tested points. C64 usable prefix reuse is **81.98% /89.08% /89.73%**;
trim is **12.80% /5.71% /5.45%** of raw KV hits. Cache counters cover profiling
plus drain with <1s boundary uncertainty. SSD adds throughput with little reuse
change, consistent with cheaper prefill rather than another capacity increase.

All nine points passed `submission_valid`. C16/C32 had no client errors;
each C64 point had one (stock: connection reset; replay and SSD: empty-content
response), with 940/1249/1428 successful requests. All C64 points reached the40s
drain timeout; attribution remains pending. Client ITL was zero, so no TPOT claim
is made here. Single runs, no confidence intervals; faster variants traverse
more turns and realized AL can differ. Replay/SSD ran on distinct GPUs sharing
a host; host-resource interference is a possible caveat.

## Validation and remaining work

- Passed 6 SSD adapter tests, 7 numerical cases, 3 replay-verifier tests and
  4 native-materialization tests, with unchanged numerical tolerances.
- Passed 10 real-acceptance requests covering chunked prefill, packed inputs
  and checkpoint restoration; synthetic acceptance was disabled for these checks.

These are numerical/runtime checks, not model-level accuracy. E2E used an
instrumented experiment tree, not a separate run of the
sanitized public branch. Before merge: reconcile #41968, adopt the qualified
FlashInfer dependency, and complete public-tree CI, documentation and accuracy
validation.
