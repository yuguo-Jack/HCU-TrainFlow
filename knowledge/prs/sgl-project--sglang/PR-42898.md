## Motivation

Three Kimi K3 configurations still ran the decoder's own communication, because each fuses a collective with work that stage boundaries had no way to hand to a model-supplied kernel:

- **Fused all-reduce.** With the attention-residual bank, attention TP equal to TP, and a multicast-capable node, K3 writes o_proj's output into a multicast buffer. It then completes the all-reduce together with the pending residual add in one kernel (`k3_ar_fusion.all_reduce`).
- **Tuned SP collectives.** On a node with K3's SP collectives (multicast, a tuning table for the device, DeepEP or MegaMoE), the bank completes the attention output's sum onto each rank's attention-TP shard in a tuned reduce-scatter that also adds the residual. Each MoE layer's output goes back to every row through a tuned all-gather.
- **Shard mode (`SGLANG_K3_SP_ATTN_RES`).** The residual stream and the bank stay on each rank's attention-TP shard across consecutive SP-MoE layers. Each read happens on the shard and is then gathered.

## Modifications

**Stage boundaries**
- A stage's read may supply kernels of its own (`completing_fusions`, `ReadoutFusion`) that complete the sum its input owes together with the residual add:
  - the all-reduce entry tries them first, for a plain residual add, and reads the stream such a kernel wrote;
  - a kernel that declines the batch leaves the sum to the boundary's own collective;
  - `ReadoutFusion.scatters` marks one that completes the sum onto this rank's slice, which the reduce-scatter entry tries;
  - `ReadoutFusion.reads` marks one that also performs the read and returns its result.
- A stage may declare its own implementation of the gather over attention TP its boundaries run (`attn_tp_gather`, on `declare_ffn` and `declare_attn`). It is tried before the default per batch, and declaring one that no batch variant runs is an error. Neither kind of kernel is registered globally: the tuned kernels' own eligibility checks would also take other models with the same hidden size.
- `ExitRows.SLICE`: an FFN that declares it leaves its output on the rows it ran on, at the stack's end too, so the model's final read takes the slice. An unpadded batch, whose rows stay whole, keeps them whole.
- A read may supply `gathering_reads`, kernels that read the slice and gather what they read in one call; the entry then skips its own gather. They take a pending residual add themselves, so the entry binds them only after a plain add or when the producer writes the stream at its exit (`EdgeContract.arrives_written`).
- `ops.attn_tp_gather(..., owned=True)` gathers into a buffer of its own, for an output that outlives the layer stack.

**Kimi K3**
- The bank's FFN read supplies the fused all-reduce for an o_proj output in the multicast buffer, the condition under which the decoder used it. When o_proj cannot write into that buffer (a quantized o_proj), the attention leaves the sum to the boundary's all-reduce.
- The bank's FFN read on the shard supplies the tuned reduce-scatter, and the bank's MoE layers declare the tuned all-gather.
- Shard mode is decided at construction, since it changes which rows each stage leaves its output on. It requires all of these:
  - an a2a MoE backend with attention TP;
  - the bank;
  - K3's tuned SP collective;
  - `SGLANG_K3_SP_ATTN_RES`;
  - a single pipeline rank;
  - no EAGLE3, DFLASH or DSPARK draft capturing the target's hidden states;
  - every layer from the first MoE layer on is an SP-MoE layer.

  A model built in this mode raises when asked to capture hidden states.
- In shard mode:
  - the SP-MoE layers declare `ExitRows.SLICE`;
  - the bank's FFN read reduce-scatters, adds the residual and aggregates in one kernel;
  - the attention read and the final read aggregate and all-gather in one kernel;
  - the final read falls back to the tuned or the boundary's all-gather (`owned`).
- `AttnResidual` raises on a read of every row after a write of only this rank's rows, which would aggregate stale snapshots of the other ranks' rows.
- Two move-only commits: the stage declarations move into `_declare_stages`, and the SP-MoE o_proj setup moves into the attention classes. Neither changes behavior.
- With this PR every Kimi K3 configuration builds stage boundaries, so the decoder's own communication code becomes unreachable; #42936 removes it.

**Tests**
- `test_append_stages.py`:
  - `TestSliceExitRows`: the last FFN stays on its slice; an unpadded batch leaves it on the attention rows; the next attention gathers in the declared gather; a gathering read needs a plain add or a written stream.
  - `TestReadKernels`: a gathering read passes through the entry gather; a kernel that reads returns the read.
- `test_attn_bank_residual_ops.py`:
  - `TestAttnBankFusedAllReduce`: the stream the fused kernel writes reads as the entry's own all-reduce and add would leave it.
  - The exit gather falls back when its kernel declines; the shard entry reads the tuned reduce-scatter's stream as its own.
  - `TestAttnBankOnShards`: the final read of a shard gathers what it read; a read of every row after a shard write is refused.
- `test_kimi_k3_stage_kernels.py`, driving the layer's stage declarations with both collectives stubbed available:
  - The standard residual path keeps the boundary collectives; the bank takes the fused all-reduce and the tuned reduce-scatter and gather.
  - Consecutive MoE layers stay on their shards.
  - The shard mode is decided at construction.

## Accuracy Tests

B200, synthetic Kimi K3 (`moonshotai/Kimi-K3` config at full width, 8 layers, 64 experts, dummy weights), deterministic inference.
- **Fused all-reduce**, where it does not run (custom all-reduce off under deterministic inference): bank TP 4 is equivalent to the decoder's own path, with decode 1606 = 1606 and extend 431 = 431 kernels.
- **Tuned SP collectives**, where unavailable (no tuning table for B200): bank SP-MoE at DeepEP TP 2 is bit-identical to the decoder's own path, with decode 1462 = 1462 and extend 465 = 465 kernels.
- **Shard mode with its criterion forced on** (the three fused kernels then fall back to NCCL), TP 4 + DeepEP, with block sizes 2 and 4: every pair of runs from the two trees whose layer 0 matches is bit-identical on all 8 layers and in its outputs. All 80 terminal reads per run took the shard.
- At the top of this stack against `main`, per layer: TP 4 with and without the bank, the bank with SP-MoE at TP 4 × EP 4, and PP 2 are equivalent.

- **Fused all-reduce with the real kernel.** Deterministic inference turns the custom all-reduce's multicast off, so these launches are not deterministic: TP 4 with the bank, custom all-reduce on, 4 launches per tree. Every rank logs `K3 all-reduce fusion enabled` on both trees, and both call the fused all-reduce on the attention sum 1264 times per rank per run. All 10 pairs of a `main` and a stack launch whose layer-0 outputs match are bit-identical on every layer and in their outputs. The spread between the trees (2–3 of 3 prompts identical, logprobs within 0.023) is the same as within each tree.

**Tuned SP collectives, shard mode and the fused all-reduce with the real kernels**, at the top of this stack against `main`, on an HGX B300 (SM103, NVLink multicast). The SP collectives' tuning tables name the GB300 (TP 4 / 8 / 16) and GB200 (TP 16); for this run the GB300 tables were copied under the B300's device name (`NVIDIA B300 SXM6 AC`) in both trees. Synthetic K3 as above, with the bank; custom all-reduce on, which these kernels need, so launches are not deterministic; 4 launches per tree per configuration.
- Every rank of both trees logs `K3 SP collective enabled`, plus `K3 SP attention-residual carry enabled` in shard mode and `K3 all-reduce fusion enabled` at TP 8 without SP-MoE. Counted at the kernels, the tuned ones take every call: the reduce-scatter with the residual add and the all-gather (SP-MoE); the bank's fused reduce-scatter-and-read and aggregate-and-gather, and the attention-residual reduce-scatter and gather (shard mode); the fused attention all-reduce (208 per rank per run). In shard mode every final read takes the shard.
- Grouping each configuration's 8 launches by bit identity over every layer of every rank and the outputs, the largest group always holds launches of both trees. A launch outside it differs as much from its own tree's other launches as from the other tree's.

  | Configuration | Largest group (`main` + stack) | Other groups |
  |---|---|---|
  | SP-MoE, DeepEP TP 4 × EP 4 | 3 + 3 | 1 + 1 |
  | SP-MoE, DeepEP TP 8 × EP 8 | 4 + 3 | 0 + 1 |
  | Shard mode, TP 4 × EP 4 | 4 + 2 | 0 + 2, already apart at layer 0 |
  | Shard mode, TP 8 × EP 8 | 3 + 3 | 1 + 0, 0 + 1 |
  | Fused all-reduce, bank TP 8 | 3 + 3 | 1 + 0, 0 + 1 |

- Output spread between the trees equals the spread within each tree in every configuration (2–3 of 3 prompts identical, logprobs within 0.008).

## Speed Tests and Profiling

B200 with custom all-reduce on, where K3's fused all-reduce is enabled on both trees (`K3 all-reduce fusion enabled`). `offline_throughput`, generated-shared-prefix 16 × 16, synthetic K3, bank, TP 4: 10742 output tok/s on `main`, 10708 at the top of this stack (median of 6 launches each; ranges overlap).

HGX B300, the same benchmark at TP 8 (DeepEP EP 8 for SP-MoE), with the GB300 tables as above. Every run logs the tuned collectives (or the fused all-reduce) enabled on all 8 ranks of both trees. Output tok/s, median (range):
- SP-MoE: `main` 5631 (4066–5853), this stack 5643 (5395–5720), 6 launches each.
- Shard mode: `main` 5548 (5273–5996), this stack 5463 (5194–5829), 9 launches each; the ranges overlap and a rank-sum test does not separate them.
- Bank, fused all-reduce: `main` 12474 (12442–12755), this stack 12882 (12691–12936), 3 launches each.
- Memory after init is the same in every pair (`max_total_num_tokens` and free memory).
