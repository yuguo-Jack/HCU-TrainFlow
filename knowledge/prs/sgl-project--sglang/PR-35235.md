# feat(bench): add `--insecure` to skip TLS verification

[Upstream PR](https://github.com/sgl-project/sglang/pull/35235) · state: open · merged: False

## Original PR description

## Motivation

Benchmarking against a server behind a self-signed certificate or an internal CA currently fails *silently*: every health check (readiness poll, model discovery, `/server_info`, cache flush) raises an `SSLError` that `wait_for_endpoint` swallows, so the bench exits with only "Server did not become ready" — no hint that TLS verification is the cause. There is no way to benchmark such servers without changing CA trust at the system level.

## Modifications

- Added a `--insecure` flag to `python -m sglang.bench_serving` that disables TLS certificate verification and is propagated as `verify=False` (requests) / `ssl=False` (aiohttp connector) on every server-bound call in `serving.py`: readiness poll, cache flush, `/server_info` (x2), `/v1/models`, `/model_info`, and the per-request bench session.
- `wait_for_endpoint` now surfaces the underlying exception when the server never becomes ready, so a self-signed-cert SSLError is diagnosable instead of invisible.
- Added `--insecure` / `BenchArgs.insecure` to `one_batch_server.py` and threaded `verify=` through every requests call (metrics, cache flush/warmup, the request itself, `/server_info`).
- Added a `verify_ssl` parameter to `endpoint.py`'s `server_is_up` / `launch_or_reuse_server` / `acquire_endpoint`.
- Added `--insecure` to the standalone `python -m sglang.profiler` CLI and a `verify` parameter to `run_profile()`.
- Suppresses urllib3's `InsecureRequestWarning` under `--insecure`.
- Documented `--insecure` in the bench-serving guide ("Other key options" + troubleshooting).
