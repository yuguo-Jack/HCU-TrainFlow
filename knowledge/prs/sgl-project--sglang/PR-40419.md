# :bug: [NPU] Allocate BF16 SSM state for speculative verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/40419) · state: open · merged: False

## Original PR description

## Problem and change

NPU speculative verify requires BF16 persistent and intermediate SSM state. `MambaPool` can otherwise allocate FP32 from the configured temporal-state dtype. The already-merged sgl-project/sgl-kernel-npu#808 rejects that mismatch; older kernels could interpret the buffer incorrectly.

Resolve the local SSM dtype to BF16 before allocating either buffer when speculative decoding is enabled on NPU, with a warning explaining the override. Non-NPU and non-speculative allocations retain their configured dtype. Convolution buffers retain their separate dtype.

The final delta is confined to `memory_pool.py`. Main already supplies the current AscendC GDN prefill path and state-layout integration; those files match main. No earlier gating/prefill replacement is included in this PR.

## Dependencies

Updated on 2026-10-10 with ordinary merges; base remains `main`. Branch head: `756dac5a66`. Includes official main `c55790d38b`.

This fix is independent of the Gemma/MXFP stack and matches the BF16 contract of merged kernel #808. Model-level Qwen3.5 validation on Ascend 950 still needs the paired Gemma wheel/API. Unmerged kernel #651/#742 state-migration fixes must be evaluated separately when assembling an MTP test wheel.

## Validation

- Eight isolated CPU allocation cases exercised the actual pool constructor and NPU convolution-layout helper: NPU/non-NPU, speculative/non-speculative, configured FP32/BF16. Persistent and intermediate SSM dtypes and shapes matched the expected contracts.
- Applicable pre-commit hooks and `git diff --check` passed.
- Main's GDN backend and prefill kernel files are unchanged.

These are CPU/static checks, not 910/950 operator, model-load, warmup, accuracy, or performance validation. Full SRT test collection was unavailable in this environment because its serving dependencies are not installed. Target hardware validation remains required.

Earlier device diagnosis established the dtype mismatch, but no new prefill/decode/verify or Qwen3.5 MTP run was performed for this refreshed head.
