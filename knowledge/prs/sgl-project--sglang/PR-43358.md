# [Fix] move torch_native/flex_attention CUDA graph disable after platform fallback

[Upstream PR](https://github.com/sgl-project/sglang/pull/43358) · state: open · merged: False

## Original PR description

## Motivation

- When the attention backend is auto-selected on a CPU platform without AMX support, the platform fallback logic (_attention_backend_platform_fallbacks) rewrites intel_amx to torch_native. However, the CUDA graph disable check for torch_native was placed before this fallback in handle_attention_backend_compatibility, so it saw the pre-fallback value (intel_amx) and skipped the disable logic. 
- This resulted in CUDA graphs remaining enabled for the auto-selected torch_native path, while explicitly-set torch_native correctly disabled them — an inconsistency that violates the expected behavior described in issue #43142.
- This PR fixes the ordering so that the CUDA graph disable checks for torch_native and flex_attention run after the platform fallback, ensuring both auto-selected and explicitly-set backends behave identically.

## Modifications

1. pythonattention_hook.py

- Moved the torch_native and flex_attention CUDA graph disable blocks from before _attention_backend_platform_fallbacks to after it, so the checks see the post-fallback backend value.

2. test_server_args.py

- Added TestAttentionBackendCudaGraph with 3 regression tests:

  - test_auto_fallback_and_explicit_torch_native_disable_cudagraph: Both auto fallback and explicit torch_native correctly disable CUDA graphs.
  - test_auto_and_explicit_yield_same_cudagraph_config: Both paths produce identical cuda_graph_config.
  - test_round_trip_stability: ServerArgs round-trip via asdict preserves cuda_graph_config.

- Tests use _create_model_dir() to avoid the model_path="dummy" early return, and @override_platform(is_cuda=False, has_amx=False) to simulate CPU without AMX.
