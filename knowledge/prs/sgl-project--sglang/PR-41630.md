# [Fix] Refresh attn_sink after loading weights

## Motivation

When attention TP > 1, `MqaAttentionBase._local_attn_sink()` builds a padded, TP-local copy of `attn_sink` (`_attn_sink_local`) on the first forward, and never refreshes it afterwards. Online weight updates (e.g. `update_weights_from_tensor` in RL) write new values into `attn_sink`, but `MQALayer.forward()` keeps reading the stale copy. As a result, the model silently serves the startup sinks; with `load_format=dummy`, the sinks stay dummy for the whole run.
## Modifications

- Record the head slice used to build the copy, and add `MqaAttentionBase.refresh_attn_sink_cache()`. It copies the updated `attn_sink` slice into the existing `_attn_sink_local` in place.
- Call it from `DeepseekV4ForCausalLM.post_load_weights()`, next to `refresh_mhc_norm_weight_cache()`.
