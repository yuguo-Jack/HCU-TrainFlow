# [diffusion] torch.compile: keep the TP all-reduce inside the graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/43602) · state: closed · merged: True

## Original PR description

## Motivation

Under `--enable-torch-compile` with `--tp-size > 1`, every row-parallel layer breaks the DiT graph at its all-reduce. `GroupCoordinator.all_reduce` calls the custom all-reduce inline, and Dynamo cannot trace its tvm_ffi communicator:

```
Graph break in user code at sglang/kernels/ops/communication/all_reduce.py:169
  Explanation: Dynamo does not know how to trace method `get_world_size` of class `Communicator`
  Explanation: torch.compile detected a graph break in a for/while loop. Skipping the frame and falling back to eager
```

The break is inside the block loop, so Dynamo gives up on the whole frame and compiles each block separately, with a break at every all-reduce. srt avoids this by routing its all-reduce through an opaque custom op (`outplace_all_reduce`). Diffusion has its own `GroupCoordinator` and never did.

## Modifications

- `diffusion_all_reduce`: an out-of-place custom op (`register_custom_op(out_shape="tensor")`). Like srt's ops, it takes the group by name, from a weak-reference registry filled in `GroupCoordinator.__init__`.
- Under `torch.compiler.is_compiling()`, a SUM all-reduce on a group that has the custom all-reduce goes through the op. The op runs `_all_reduce_out_of_place`: the custom all-reduce when the tensor qualifies, otherwise NCCL on a copy, because a custom op may not mutate or return its input.
- Eager is unchanged. Groups without the custom all-reduce keep tracing `torch.distributed.all_reduce` natively.

## Accuracy Tests

The math is identical (the same custom all-reduce or NCCL sum). Moving the all-reduce into an opaque op changes how inductor fuses the code around it. Qwen-Image-2.1, TP2, compile, seed 42, against the same tree without this PR: MAE 0.415/255, PSNR 46.4 dB. That is floating-point reordering.

## Speed Tests and Profiling

4xGB300, served, 1024x1024. Baseline: main 3831e7e09 plus the open GB300 fixes (#43565 NUMA binding, #43568, #43577, #43575, #43576, #43584, #43586). Each cell is the median of 5 requests after warmup. Rounds are interleaved (ABAB), and every arm runs on a fresh server.

| case (TP2) | compile, baseline | compile, this PR | change |
|---|---:|---:|---:|
| FLUX.1-dev, round 1 / 2 | 3.651 / 3.702 s | **2.647 / 2.588 s** | −28% / −30% |
| Qwen-Image-2.1, `--offload-during-compile false`, round 1 / 2 | 2.199 / 2.138 s | **1.501 / 1.496 s** | −32% / −30% |
| Qwen-Image-2.1, default (offload during compile on), round 1 / 2 | 2.219 / 2.280 s | 2.179 / 2.181 s | −2% / −4% |

For reference, eager is FLUX.1 ~4.0 s and Qwen-Image-2.1 1.70–1.73 s. With this PR, compile beats eager on both.

Qwen-Image-2.1 gains little with offload-during-compile on (the default), for an unrelated reason. Its warmup traces the layerwise-offload hooks, and the `torch.compiler.disable` calls inside them graph-break inside the block loop. Dynamo then skips the transformer frame for good (`ConvertFrameReturn` defaults to SKIP with `apply_to_code=True`), so serving keeps per-block graphs even after the hooks are removed. That is a separate fix.
