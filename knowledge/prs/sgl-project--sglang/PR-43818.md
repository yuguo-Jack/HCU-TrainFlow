# [Perf] Avoid dtype conversion in decode page count

[Upstream PR](https://github.com/sgl-project/sglang/pull/43818) · state: open · merged: False

## Original PR description

## Motivation

The decode allocation path calls `get_num_new_pages` on CPU tensors for every scheduling step. The existing `.int().sum()` sequence copies the boolean mask to int32 before reducing it. This removes that unnecessary dtype conversion from the host-side hot path.

Related to #24922.

## Modifications

- Replace the decode-path `.int().sum()` with `torch.count_nonzero`.
- Correct the helper return annotation to `int`.
- Add a regression test that verifies the page count and absence of `aten._to_copy`.
- Add a focused host-side microbenchmark comparing the legacy and current implementations.

## Accuracy Tests

This does not change model outputs. The unit test covers page-boundary counting and passes:

`python test/registered/unit/mem_cache/test_num_new_pages.py`

## Speed Tests and Profiling

Command:

`python benchmark/scheduler/bench_num_new_pages.py --iterations 5000 --repeats 5`

WSL2, PyTorch 2.10.0+xpu, CPU host path:

| Batch | Legacy (us) | Current (us) | Helper speedup |
|---:|---:|---:|---:|
| 1 | 4.670 | 3.094 | 1.51x |
| 8 | 4.728 | 3.195 | 1.48x |
| 32 | 4.935 | 3.315 | 1.49x |
| 128 | 4.985 | 3.545 | 1.41x |

The local Intel XPU runtime currently reports zero devices, so these results only measure the CPU helper. End-to-end GPU performance has not been measured, and this PR does not claim a GPU performance improvement.
