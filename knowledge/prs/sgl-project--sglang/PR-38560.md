# [Fix] Autotune the breakable prefill graph path before capture

[Upstream PR](https://github.com/sgl-project/sglang/pull/38560) · state: closed · merged: False

## Original PR description

## Motivation

Startup FlashInfer autotuning runs before the breakable prefill graph capture context. A model can select a different MoE path in graph mode: deferred finalize uses an `(N, 0)` output placeholder instead of the eager path's `(N, hidden_size)` output. These produce different tuning keys, so startup tuning can complete while the recorded prefill graph still uses a fallback tactic.

Tune the actual breakable prefill graph forward before recording its graphs. Related PR [#32556](https://github.com/sgl-project/sglang/pull/32556) adds eager EXTEND warmup for larger token buckets; this change addresses the distinct tuning keys selected inside the BCG context.

Baseline: `a6b542813ff46de8ba3856e0236f1af35f4fca54`. Reviewed patch head: `6ad552c579`.

## Modifications

- In the existing breakable graph capture session, run FlashInfer autotuning using the largest configured prefill shape before recording capture buckets. The additional pass applies only to the breakable backend.
- Reuse `capture_prepare`, attention metadata preparation, and `_run_forward` so tuning follows the same model path as graph capture.
- Reuse the existing autotune eligibility check and context, including the disable/deterministic gates and configured skip operations. No new CLI flags or cache format changes.
- Exercise `capture()` with the real BCG capture session; the fake model selects its tuning key from the actual BCG context. Cover smaller buckets and disabled/deterministic modes. A separate boundary test verifies that Full and TC-piecewise only run their existing capture passes.

## Accuracy Tests

- Existing registered component test file: 11 tests passed. In-memory mutations restoring the upstream capture loop, removing the BCG context during tuning, or extending the new pass to all backends each fail the strengthened regression.
- Full-model bounded GSM8K regression: both baseline and patched scored **60/64 (93.75%)**, using the unchanged SGLang five-shot completion scorer, temperature 0, max tokens 512, and 8 threads.
- Four fixed greedy generation smoke cases produced identical text.

The 64-question evaluation is a sanity check; matching aggregate scores does not imply identical per-question outputs.

## Speed Tests and Profiling

Full `nvidia/GLM-5.2-NVFP4` (`aec724e8`), B200 TP4, FlashInfer 0.6.18, PyTorch 2.13.0, 2048-token prefill chunks, breakable prefill graphs, FP8 KV, prefix cache disabled. Official SGLang serving benchmark: 240 requests, 4096 input / 8 output tokens, concurrency 24, seed 42, temperature 0; separate 240-request warmup before measurement. The `random` dataset mode samples ShareGPT prompts and repeats or truncates their token IDs to exactly 4096 input tokens.

| Condition | Three run durations (s) | Median (s) |
| --- | --- | --- |
| Baseline | 44.770 / 44.873 / 44.889 | 44.873 |
| Patched | 42.414 / 42.503 / 42.647 | 42.503 |

Median workload duration decreased **5.28%**; input throughput increased **5.58%**. All six runs completed 240/240 requests with exactly 983,040 input and 1,920 output tokens and no request errors. These are unprofiled measurements, with three repeats within one warmed server instance per condition. Measurements preceded the final BCG-only eligibility restriction and test strengthening; the BCG forward and tuning sequence are unchanged.

Baseline used GPUs 4–7; patched used GPUs 0–3 on the same B200 host, with serialized benchmark load. GPU groups were not swapped. Both conditions independently generated their normal autotune caches; only compiled FlashInfer binaries were shared. Results apply to this prefill-heavy workload and deployment.

Persistent rank-0 cache evidence shows 20 eager / 0 graph MoE keys in baseline and 20 eager / 16 graph keys in patched. First graph-path tuning took approximately 91 seconds by logs; with cache reuse, it completed within the same logged second. Total initial startup times are confounded by compilation and checkpoint-cache state and are not compared as a patch effect.

Bounded Nsight Systems captures used the same node-level CUDA graph tracing and native NVTX switches, after the same warmup, for 24 requests of 4096 input / 8 output tokens at concurrency 24. Both traces contain 116,339 kernels per GPU, including 92,320 graph nodes. The selected prefill MoE boundary has exactly 75 layers × 48 chunks per GPU; decode graph nodes are present and excluded from this boundary.

| Prefill kernel metric, mean per call | Baseline (μs) | Patched (μs) | Reduction |
| --- | ---: | ---: | ---: |
| GEMM1 + GEMM2 interval union | 331.604 | 256.269 | 22.72% |
| Routing + GEMM1 + GEMM2 + finalize interval union | 386.667 | 314.115 | 18.76% |

The recorded GEMM1 tactic changes from `t128x32x512u2_s4` to `t128x128x512_s3x3x3x3x1x3`; GEMM2 changes from `t128x32x512_s5` to `t128x128x256_s6`. Interval unions account for overlapping kernels. This boundary excludes input quantization, shared-expert work, collectives, and subsequent fused operations. These profiled kernel measurements support the mechanism; they do not replace the unprofiled end-to-end score. Independent normal autotuning also selected different decode tactics, whose measured GEMM time was essentially unchanged; non-target tactics were not artificially synchronized.
