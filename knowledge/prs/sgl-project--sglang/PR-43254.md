# feat(model-loader): reuse model-owned MTP rules for shard selection

**Validation status: Three interleaved H20×8 Qwen3.5 MTP baseline/patch pairs completed on the exact current PR head (`2557998e0a`). All six runs reached Ready and passed a limited serving smoke check. Engine-start → Kubernetes Ready showed no measurable improvement; non-Qwen GPU and model-accuracy validation remain pending.**

Current commit: `2557998e0a29ef83522b648d8182dab3eb77d937` (base `bd2d73daa5`). The separate RunAI integration is #43255 and depends on this PR. The focused tests below were rerun after this rebase.

## Motivation

Refs #43196. MTP workers load a main model and a draft, but rejecting unused checkpoint tensors inside `load_weights` is too late to keep an earlier reader or prefetcher from touching unnecessary shards.

Inspired by [vLLM #60152](https://github.com/vllm-project/vllm/pull/60152), this change lets each model declare which raw checkpoint names it cannot use. The model's existing load loop and the generic file selector use the same rule. The generic loader does not assume an `mtp.` prefix.

Related SGLang proposals #35395 and #39365 also select Default-loader shards. This approach differs by sharing each model's existing role-selection rule with its actual load loop, covering multiple architecture families and exposing the same optional contract for the separate RunAI integration. The maintainers should decide whether these approaches should converge before merge.

## Modifications

- Add the optional, instance-bound `is_unused_checkpoint_weight(name)` contract. `True` means the model can definitely skip that raw checkpoint name; a missing hook preserves existing behavior.
- Extract role-selection predicates from Qwen3.5/Qwen3-Next and DeepSeek/GLM NextN loading rules. Preserve Qwen3.5 draft PP embedding requirements, NextN layer selection, and shared-weight exclusions. Leave tensor renaming, quantization, fusion and assignment in their existing model loaders.
- Select complete local safetensors files before both ordinary Default iteration and startup prefetch. Keep any file with at least one potentially required tensor, preserve order and retain the existing all-rejected fallback.
- Leave unsupported name transformations and non-safetensors loading on their original paths. Opt out wrappers whose inherited predicate does not describe their raw checkpoint namespace.

This is file-level selection, not tensor/range-level I/O. Mixed shards can still be read by both roles. Hugging Face files resolved to local storage may already have been downloaded; local read reduction is not a claim of reduced HF download traffic. No RunAI, ModelExpress P2P, model forward or scheduler behavior is added by this commit.

The cost depends on the reader: ordinary mmap without prefetch does not necessarily read all unused tensor payloads. Disabling mmap, enabling checkpoint prefetch, or using fastsafetensors has different read/transfer behavior. Benchmarks will report those settings separately; Default results cannot be inferred from RunAI measurements.

## Reviewer focus

The intended boundary is: each model owns the raw-name rule used by its existing `load_weights` loop; the generic Default loader only maps that rule to whole-file selection **before** iterator/prefetch creation. Please pay particular attention to Qwen3.5 pipeline-parallel embeddings, DeepSeek/GLM NextN shared weights, mixed shards, and the conservative fallback when a name transformation is not understood. This is deliberately distinct from RunAI in #43255 and from vLLM's [Default PR #60152](https://github.com/vllm-project/vllm/pull/60152) / [RunAI PR #60759](https://github.com/vllm-project/vllm/pull/60759).
