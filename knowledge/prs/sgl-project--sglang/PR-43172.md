# Clamp default decode CUDA graph max_bs to max_running_requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/43172) · state: closed · merged: True

## Original PR description

When --max-running-requests is small (e.g. single-request latency tiers) and --cuda-graph-max-bs-decode is unset, the GPU-capacity default (up to 512) dwarfs the running batch. The server then captures - and reserves memory for - batch sizes it can never replay.

This clamps the default to the running limit. An explicit --cuda-graph-max-bs-decode keeps its existing semantics, and the materialized capture list follows via the existing max_bs filter.
