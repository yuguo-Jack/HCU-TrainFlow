# [AMD][V4.1] Optimize FP4 indexer with shared K loads and candidate-only scoring

[Upstream PR](https://github.com/sgl-project/sglang/pull/43073) · state: open · merged: False

## Original PR description

### Motivation

The current low-ratio FP4 indexer loads K separately for each query row and requires schedule construction. Candidate consumers also score the full context before gathering candidate blocks, resulting in redundant K loads and unnecessary scoring.

### Modification

- Use AITER’s row-group FP4 MQA kernel to share K loads across query rows of the same request and eliminate schedule construction for decode and target verification.
- Add an optional page-8 layout for the ratio-1 index-K cache, allowing candidate consumers to score selected blocks directly.
- Reuse prefill page tables and query offsets across layers.
- Add correctness tests for cache writes, logits, ragged prefill, and candidate top-k.

Requires ROCm/aiter#6145. Need set:
`SGLANG_HIP_FP4_INDEXER_ROWGROUP=1`: enable row-group decode and target verification
`SGLANG_HIP_DSV41_INDEX_K_PAGE8=1`: enable the page-8 layout and direct candidate-block scoring
