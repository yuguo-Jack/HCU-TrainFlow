# Prebuild fixup_zero_kv JIT module at TRTLLM-MLA backend init

[Upstream PR](https://github.com/sgl-project/sglang/pull/37525) · state: open · merged: False

## Original PR description

## Motivation

`fixup_zero_kv` is JIT-built lazily on first use, but its only call sites fire when a chunked-prefix extend batch contains a zero-KV row — a condition that depends on radix-cache state and request timing. On a cold JIT cache the first hit therefore pays the nvcc build in the middle of live serving (~6s measured on GB300 with tp4; all TP ranks convoy on the build lock), showing up as a one-time multi-second engine stall at an unpredictable moment. Profiled root cause: scheduler blocked in `_build_lock`/`flock` for 5.7s inside `trtllm_mla_backend.forward_extend → _chunked_prefix_attn_mha → fixup_zero_kv_rows`.

## Modifications

Build the module at `TRTLLMMLABackend.__init__` (keyed on the model dtype), moving the one-time cost into startup. When the JIT cache is warm this is a ~ms load.

Validated on an internal bench (8× repeats of a bs512/in256/out256 mixed prefill+decode row): 0/24 stalled rows with this change vs exactly one ~6.5s stall per server without it (3 jobs each arm); startup time unchanged.
