# [DeepSeek-V4] Fix duplicate shared-expert execution for built-in TP MoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/37948) · state: closed · merged: False

## Original PR description

## Motivation

`SGLANG_DP_SHARED_EXPERT_LOCAL=1` computes the shared-expert output on the DP-local hidden states before the DP gather, then invokes the MoE layer with `skip_shared_experts=True` so that the gathered path does not add the same shared-expert output again.

For `moe_a2a_backend=none`, `DeepseekV2MoE.forward_normal()` honors this flag, but the built-in TP MoE piecewise CUDA Graph and capture-mode dual-stream paths did not. When either fast path was selected, the flag was silently bypassed and the shared expert was executed a second time. On DeepSeek-V4-Pro with DP attention and CUDA Graphs enabled, this corrupted model output. Disabling CUDA Graphs avoided the fast paths and restored accuracy.

A2A backends such as DeepEP use `forward_deepep()` and do not enter the branch changed by this PR.

## Modifications

- Bypass `dsv2_flashinfer_moe_dual_stream_graph` when `skip_shared_experts=True`.
- Bypass `forward_normal_dual_stream` under the same condition so execution falls back to `forward_normal()`, which propagates the flag correctly.
- Add a CPU regression test that verifies:
  - both graph paths are skipped when shared experts were already computed;
  - the existing graph fast path remains selected when shared experts are enabled normally.

## Accuracy Tests

DeepSeek-V4-Pro was evaluated on 50 GSM8K questions with the same deployment and benchmark settings before and after this change. CUDA Graphs were enabled in both runs.

| Result | Before | After |
|---|---:|---:|
| Accuracy | 0.020 | 0.980 |
| Invalid | 0.200 | 0.000 |
| Latency | 94.210 s | 21.855 s |
| Output throughput | 271.734 token/s | 212.998 token/s |

The pre-fix throughput is not directly comparable because the model produced incorrect and invalid output. The accuracy recovery from 2% to 98%, together with the eager-mode control, confirms that the duplicate shared-expert execution was the correctness issue.

Focused regression test:

```text

```

## Speed Tests and Profiling

This change only changes built-in TP MoE routing when `skip_shared_experts=True`. A2A backends are unaffected. The existing CUDA Graph fast path is unchanged for normal calls, which is covered by the regression test. No standalone performance claim is made from the GSM8K throughput values because the pre-fix run generated corrupted output.
