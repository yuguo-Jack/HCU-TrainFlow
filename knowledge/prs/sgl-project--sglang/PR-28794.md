# fix(frontend): reject out-of-range top_logprobs_num

[Upstream PR](https://github.com/sgl-project/sglang/pull/28794) · state: open · merged: False

## Original PR description


## Motivation

`top_logprobs_num` is a public logprob request parameter on the native `/generate` path. OpenAI `/v1/completions` `logprobs` and `/v1/chat/completions` `top_logprobs` are converted into the same internal field.

The tokenizer-side admission path validates `token_ids_logprob`, but it does not validate `top_logprobs_num`. The scheduler later calls `logprobs.topk(max_k, dim=-1)`, where the last dimension is the model vocab size. If one request asks for more top logprobs than the vocab contains, PyTorch raises `RuntimeError: selected index k out of range`; that scheduler exception triggers process-tree shutdown and makes the server unavailable for later requests.

I reproduced this on current main with a single native `/generate` request using `top_logprobs_num=100000` against a 32000-token vocab: the attack request disconnects, the server exits with `-9`, and both `/health_generate` and a normal `/generate` fail afterward.

## Modifications

- Add `_validate_top_logprobs_num` in `TokenizerManager`.
- Call it next to the existing `token_ids_logprob` validation for `GenerateReqInput`.
- Reject bool, non-integer, negative, and above-vocab values before the request reaches the scheduler.
- Keep `0 <= top_logprobs_num <= vocab_size` valid.
- Add focused unit coverage in the existing TokenizerManager unit test file.
