# [AMD] DeepSeek-V4: ROCm (gfx950) FP4 sparse indexer

[Upstream PR](https://github.com/sgl-project/sglang/pull/37062) · state: closed · merged: False

## Original PR description

## Summary

Enable the DeepSeek-V4 **FP4 sparse indexer** on AMD ROCm (gfx950 / MI355X). Today `--enable-deepseek-v4-fp4-indexer` hard-requires SM100/SM120 because the score path calls DeepGEMM's `fp8_fp4_paged_mqa_logits`, which has no ROCm kernel. This PR adds a fused **Triton** paged-MQA-logits path for gfx950 that consumes the fp4 KV cache natively, and gates the flag on `is_hip()`.

On **TP8 + DP-attention** at 128k context the fp4 indexer delivers a **+37–61% decode-throughput uplift** over the fp8 indexer at **identical accuracy** (GSM8K 0.947 = 0.947).

Key ideas of the ROCm path:
- **Native mxfp4 MFMA** via `tl.dot_scaled` — the fp4 KV is fed straight into the matrix cores with its UE8M0 block scales; no dequant-to-bf16 materialization of the KV cache.
- **fp8 q × fp4 KV** — q stays fp8 (only KV is fp4), so the per-step q-quant kernel is dropped.
- **Fused fp4 KV store** and an **occupancy-aware, SplitKV-style tiling** for the score kernel to keep the CUs busy at long context.

## What changed

- **`python/sglang/srt/arg_groups/serving_hook.py`** — allow `--enable-deepseek-v4-fp4-indexer` on `is_hip()` (gfx950) in addition to SM100/SM120; update the error message.
- **`python/sglang/srt/layers/attention/dsv4/indexer.py`** — on HIP, route the indexer score to the fused Triton `fp4_paged_mqa_logits` instead of DeepGEMM; keep q fp8 (KV-only fp4) so the q path skips fp4 quant. Adds a reference `fp4_paged_mqa_logits_torch` / `_dequant_fp4_indexer` correctness mirror.
- **`python/sglang/kernels/ops/attention/dsv4/fp4_indexer.py`** — the ROCm Triton kernels: fp4 KV store, branchless E2M1 decode, tiled page-aligned MFMA score via `tl.dot_scaled`, and occupancy-aware NP tiling.
- **`python/sglang/kernels/ops/attention/dsv4/elementwise.py`** — small helper wiring for the fp4 store path.

## Validation

All numbers on **1× MI355X node, TP8, DP-attention** (`--enable-dp-attention --dp 8`), DeepSeek-V4-Pro, 128k input / 1k output, `--kv-cache-dtype fp8_e4m3`. `fp8` = existing fp8 indexer, `fp4` = this PR.

### Accuracy (GSM8K, 1319/1319)

| indexer | accuracy |
|---|---|
| fp8 (baseline) | 0.947 |
| **fp4 (this PR)** | **0.947** |

Bit-for-bit-equivalent task accuracy — the fp4 indexer only selects which KV blocks are scored; it does not change the attention output precision.

### Performance (128k input, 1k output, decode tok/s)

| concurrency | fp8 (tok/s) | fp4 (tok/s) | Δ |
|---|---|---|---|
| 32  | 1041 | **1672** | **+61%** |
| 64  | 1585 | **2400** | **+51%** |
| 128 | 1895 | **2599** | **+37%** |

### Commands used

Server (TP8 + DP-attention, fp4 indexer on; drop `--enable-deepseek-v4-fp4-indexer` for the fp8 baseline):

```bash
export SGLANG_USE_AITER=1
export SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton
python3 -m sglang.launch_server \
  --model-path deepseek-ai/DeepSeek-V4-Pro --served-model-name dsv4 \
  --trust-remote-code --host 0.0.0.0 --port 30000 \
  --tensor-parallel-size 8 --dp 8 --enable-dp-attention \
  --moe-dense-tp-size 1 --enable-dp-lm-head \
  --attention-backend dsv4 --page-size 256 --swa-full-tokens-ratio 0.10 \
  --kv-cache-dtype fp8_e4m3 --enforce-shared-experts-fusion \
  --chunked-prefill-size 8192 --context-length 131072 \
  --mem-fraction-static 0.85 --max-running-requests 128 \
  --speculative-algorithm EAGLE --speculative-num-steps 3 \
  --speculative-eagle-topk 1 --speculative-num-draft-tokens 4 \
  --enable-deepseek-v4-fp4-indexer
```

Accuracy (GSM8K):

cd benchmark/gsm8k && python3 bench_sglang.py \
