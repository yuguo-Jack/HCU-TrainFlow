# [Transformers] Skip checkpoint keys HF ignores on load in the fallback loader

[Upstream PR](https://github.com/sgl-project/sglang/pull/43208) · state: open · merged: False

## Original PR description

## Motivation

Models served through the Transformers fallback fail to load when the checkpoint ships tensors that the HF model never constructs. For example, `LGAI-EXAONE/EXAONE-4.5-33B` (`Exaone4_5_ForConditionalGeneration`) has no native SGLang implementation, and its checkpoint includes an MTP head (`mtp.*`) that is not used for serving:

```
ValueError: No module or parameter named 'model.mtp' in TransformersMultiModalForCausalLM.
```

HF declares such keys on the model class (`Exaone4_5_PreTrainedModel._keys_to_ignore_on_load_unexpected = [r"mtp.*"]`) and drops them in `_adjust_missing_and_unexpected_keys`. The fallback loader has no equivalent, so it raises on them.

## Modifications

- `AutoWeightsLoader` gets an `ignore_unexpected_patterns` argument (regexes, matched with `re.search` like HF). It sits next to the existing `ignore_unexpected_prefixes` / `ignore_unexpected_suffixes`.
- `TransformersBase.load_weights` passes `self.model._keys_to_ignore_on_load_unexpected`. This is the HF model's own list; `post_init` aggregates it from submodules.

The patterns apply only on the "no module or parameter" path (`_can_ignore_unexpected`). This matches HF, which filters only keys that are already unexpected. Some HF patterns also name real layers, so this ordering matters. GLM-4-MoE uses `[r"model\.layers\.92.*", r"model\.layers\.46.*"]`, one for the MTP layer of each model size. Applied as a pre-filter, these patterns would drop the real layer 46 of the 92-layer model. Here that parameter still loads.

Models that don't set the attribute get an empty set or `None`, so their behavior is unchanged. A checkpoint key that matches no module, parameter or pattern still raises.

## Accuracy Tests

`LGAI-EXAONE/EXAONE-4.5-33B` on Intel XPU (Arc Pro B60 x4), transformers backend:

```
SGLANG_USE_SGL_XPU=1 sglang serve --model-path LGAI-EXAONE/EXAONE-4.5-33B --device xpu --tp-size 4 \
  --mem-fraction-static 0.80 --max-prefill-tokens 4096 --trust-remote-code --attention-backend intel_xpu
```

(`--max-prefill-tokens 4096` is an XPU memory-headroom setting, unrelated to this change.)

On main the server fails at weight load with the error above. With this PR it loads (17.55 GB per GPU, 24192 KV-cache tokens) and answers image prompts correctly (it reads "XPU 42" from a rendered text image).

gsm8k, all 1319 questions, 5-shot, chat template, 16 concurrent:

| Filter | exact_match |
| --- | --- |
| flexible-extract | 0.2092 ± 0.0112 |
| strict-match | 0.0182 ± 0.0037 |

All 1319 requests completed without errors. The score is low because EXAONE-4.5 is a reasoning model: lm_eval's default 256-token generation limit for gsm8k cuts the `<think>` block off before the final answer. A native SGLang implementation of the model (local, not upstreamed) scored the same with the same eval command (flexible-extract 0.1986), so the low score does not come from the fallback.

Unit tests: `test/registered/unit/model_loader/test_transformers_fallback.py` (CPU suite) gets 2 new cases:
- a pattern that matches a real parameter still loads that parameter, while a key with no parameter is dropped;
- a key that matches no pattern still raises.

All cases in the file pass.
