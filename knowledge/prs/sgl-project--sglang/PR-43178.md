# [diffusion] comfyui: report the real runtime import error

[Upstream PR](https://github.com/sgl-project/sglang/pull/43178) · state: closed · merged: True

## Original PR description

## Motivation

Fixes #43175.

`executors/base.py` and `core/generator.py` caught any `ImportError` from the SGLang runtime imports, printed "sglang.multimodal_gen is not installed", and continued with `SamplingParams` / `prepare_request` / `DiffGenerator` undefined. When sglang is installed but a dependency is missing, that message is wrong, the real missing module is never shown, and the user later gets a `NameError` on the first DiT step or model load.

## Modifications

- Both modules now report the real `ImportError` (so the missing module is named) and keep importing, so ComfyUI still loads the nodes and shows the error. Re-raising here would make the plugin's `__init__.py` turn it into empty node mappings without a word.
- The error is stored and re-raised as `RuntimeError("SGLang diffusion runtime failed to import")` chained to the original at first use: `SGLDiffusionExecutor._execute_packed` and `SGLDiffusionGenerator.init_generator`.
- Tests load private copies of both modules with the runtime import blocked (`mock.patch.dict(sys.modules, ...)`, nothing leaks into other tests) and check the message and the chained error.
