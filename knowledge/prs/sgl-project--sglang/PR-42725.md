# [XPU] Fix SWA paged allocator

[Upstream PR](https://github.com/sgl-project/sglang/pull/42725) · state: open · merged: False

## Original PR description

## Motivation

`baidu/Unlimited-OCR` crashes at startup with a bare `AssertionError` on any
backend that needs a paged KV cache. Every layer of the model uses sliding-window
attention, so SGLang picks `PureSWATokenToKVPoolAllocator`. That allocator only
supported `page_size == 1`: it asserted it in `__init__`, and `alloc_extend` /
`alloc_decode` raised `NotImplementedError`. The Intel XPU attention backend
requires page_size 64/128 and rewrites it to 128, so the server died before it
could serve a request.

## Modifications

- `PureSWATokenToKVPoolAllocator` now builds a `PagedTokenToKVPoolAllocator`
  when `page_size > 1` and implements `alloc_extend` / `alloc_decode` by handing
  off to it. This is safe because the pure-SWA pool uses an identity
  full->SWA mapping: there is no second slot to allocate per token and no
  mapping to write.
- The `page_size == 1` path is unchanged. It builds the same
  `TokenToKVPoolAllocator` as before, and `alloc()` still asserts
  `page_size == 1`, like the parent class.
- Added `test/registered/unit/mem_cache/test_pure_swa_paged_allocator.py`
  (CPU, 9 cases). 8 of them fail on the old code.

## Review and discussion

### reviews

- mingfeima · CHANGES_REQUESTED · 2026-10-09T05:32:42Z · [source](https://github.com/sgl-project/sglang/pull/42725#pullrequestreview-5466093910)

Prefer aligning XPU with CUDA over an XPU-only allocator path.

The all-SWA crash comes from `_intel_xpu_page_constraint` rewriting page_size to 128, which then hits `PureSWATokenToKVPoolAllocator` assert `page_size == 1`. CUDA's default MHA path (fa3 / flashinfer / triton) stays at `page_size == 1` and already serves this allocator. XPU should do the same: leave an unset page size at 1, and do not snap it to 64/128.

NOTICE that `page_size == 1` is already a real kernel path, not a missing feature. `XPUAttentionBackend._forward_attn_flat_page_table` reshapes the KV cache to (tokens, 1, heads, dim) and calls flash_attn_with_kvcache; the main path only strides and divides the page table when page_size > 1. If some kernel still rejects 1, fix the kernel. Do not teach the shared allocator a paged pure-SWA path just to absorb this rewrite.


- siju-samuel · CHANGES_REQUESTED · 2026-10-09T09:37:31Z · [source](https://github.com/sgl-project/sglang/pull/42725#pullrequestreview-5468360080)

I'd go with mingfeima and Valentine233's suggestion of running this model at page_size 1 on XPU instead. As written this isn't XPU-gated, so it turns on pure-SWA with page_size > 1 for every backend, and the tests are mostly mocks. If you keep this approach, the PD-decode crash below needs a fix first.
