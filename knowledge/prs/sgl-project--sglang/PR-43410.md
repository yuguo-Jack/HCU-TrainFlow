# [PD] Receive decode KV into separate paged SWA host pools; let host-capable receivers own abort drain tracking

[Upstream PR](https://github.com/sgl-project/sglang/pull/43410) · state: closed · merged: True

## Original PR description

Stacked on #43407, which flips the host-receive threshold semantics (`1` disables, `0` always receives into the host pool). Only the top commit is this pull request; review it after the parent.

## Motivation

Decode host receive (`--disaggregation-decode-host-receive-threshold`) receives prefill KV into the pinned retraction host pool when device KV is scarce, then restores it once device capacity frees up. It only accepted models whose every pool shares the primary KV indices, so hybrid models with a separate paged SWA pool failed at startup with "Host receive requires KV pools sharing the primary indices". A transfer backend that supports host destinations also had no way to say when writes to an aborted host destination had drained: the deferred-release path only knew the manager's per-room prefill acknowledgement counts, which describe device destinations.

## Modifications

- `HostPoolGroup.get_contiguous_buf_infos(pool_names=None)` publishes the KV and SWA pool groups separately, accepts `MHATokenToKVPool` subclasses, and checks that the buffers it returns are the contiguous per-layer K/V tensors (pointer, byte length, page stride) with no embedded state instead of trusting the pool's own report.
- `KVArgs` gains `host_state_data_ptrs/lens/item_lens` for the SWA host buffers. The device buffers published for host receive must equal the KV and state transfer layouts, or startup raises.
- `DecodePreallocQueue`: an SWA host reservation bounded by `min(retraction max, window + one page)`; `_pre_alloc_host` allocates only the page-aligned sliding-window tail in the SWA host pool, evicts and checks both host pools independently, frees the KV allocation when the SWA allocation fails, and records one `PoolTransfer` per pool so restore and discard return both. Host-staged device admission goes through the SWA-aware allocatable budgets, so SWA pressure alone delays admission even when full KV fits.
- `BaseKVReceiver.is_abort_release_safe()`: host-capable receivers own drain tracking for aborted host destinations; device destinations keep the manager's acknowledgement counts and `clear_deferred_abort_state`. Aborting a failed host-staged transfer and recording a transfer failure become `_abort_failed_transfer` / `_record_transfer_failure(failure_reason)` hooks on `DecodeTransferQueue`.
- Help text for the threshold names the supported layouts (dense NHD MHA, including separate paged SWA pools). No built-in backend supports host destinations yet; this is for backends that implement `supports_host_destination`.

Tests (`test/registered/unit/mem_cache/test_decode_retraction_backup.py`, `test/registered/unit/disaggregation/test_deferred_decode_kv_release.py`):

- `test_host_receive_swa_tail_capacity_restore_and_release` builds a hybrid `SWAKVPool` (window 8, page 4, 23-token prompt), blocks the SWA host pool so only the reservation remains and asserts the pre-alloc is refused without touching the full pool, then checks 24 full and 12 SWA host tokens are allocated, device admission is delayed by SWA device pressure alone, restored K/V match per pool and per layer after `restore_kv_cache`, and both host pools return to their starting capacity after release and after `discard_kv_cache_backup`. On the parent commit this case fails at startup with `ValueError: Host receive requires KV pools sharing the primary indices`.
- `test_host_receive_dense_subclass_checks_actual_buffer_geometry` accepts an `MHATokenToKVPool` subclass and rejects a pool whose reported item stride disagrees with its buffers.
- The host-staged deferred-release fixture now carries `is_abort_release_safe`, matching the receiver contract.
