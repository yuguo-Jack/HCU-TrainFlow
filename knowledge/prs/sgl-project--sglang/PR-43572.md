# [Fix] Propagate Mooncake batch memory registration failures

[Upstream PR](https://github.com/sgl-project/sglang/pull/43572) · state: open · merged: False

## Original PR description

## Motivation

`MooncakeKVManager.register_buffer_to_engine()` and `_register_staging_memory()` ignore the return value of `batch_register()`. That wrapper logs nonzero status at debug level and converts backend exceptions into `-1`, so initialization can continue after memory registration fails.

## Modifications

- Raise on a nonzero batch registration status, matching single-region `register()`.
- Preserve backend exceptions as the cause and retain the existing missing-API upgrade message.
- Extend the existing registration fixture to exercise the real KV and staging callers with success and failure statuses.

## Accuracy Tests

Unmodified main (`44bc4788`): both caller subcases and the backend-exception regression fail. With the fix:

```bash
CUDA_VISIBLE_DEVICES=99 PYTHONPATH=python python -m pytest \
  test/registered/unit/disaggregation/test_encode_server.py \
  test/registered/unit/disaggregation/test_mooncake_transfer_batching.py \
  test/registered/unit/disaggregation/test_mooncake_custom_mem_pool_batch.py -q -rs
```

**81 passed, 39 subtests passed, 6 skipped.** The six existing gRPC tests skip because the optional `grpc_health` dependency is unavailable; all new registration cases run. The tests use the production wrapper and caller methods and inject failures only at the external Mooncake SDK boundary. GPU/RDMA end-to-end validation was not run.

## Speed Tests and Profiling

Not run; the success return remains `0` and buffer registration stays outside inference.
