# [HiCache] Preserve device coverage for admission-time prefetch recovery

[Upstream PR](https://github.com/sgl-project/sglang/pull/43466) · state: closed · merged: False

## Original PR description

A buffer-mode request can look up L3 with no device prefix, then cancel the read because another request has populated the same prefix. If that prefix is evicted before admission, the loss check still sees the original zero match and skips recovery, recomputing a prefix available in L3. Releasing an already-staged hit as device-covered has the same missing-boundary problem.

Preserve the device coverage observed when cancelling the read and consume it at admission. Also retain the joint match when releasing staging. Eviction of either span now reaches the existing bounded re-query path. Cancellation and reset clear the pending coverage metadata. This does not change the retry limit or add device pins.

Validation:
- Isolated CPU execution of the actual source methods: both hit-commit and staged-admission paths fail to re-query on main and re-query after this change; the existing retry cap is still honored.
- One regression test covers both paths and cancellation/reset cleanup. On the GB300 devbox: `pytest test/registered/unit/mem_cache/test_storage_prefetch_lifecycle.py -k device_covered_prefetch_preserves_loss_detection_boundary -q` — 1 passed, 2 subtests passed.
- All repository pre-commit hooks pass.
- The targeted test above uses the real imports and dependencies in the devbox environment; end-to-end cache pressure validation is still pending.

The observed pressure-workload misses also include requests that exhaust the existing retry cap. This change addresses the lost coverage boundary; it does not claim to fix every miss or the separate TP cancellation-consensus issue in #43108.
