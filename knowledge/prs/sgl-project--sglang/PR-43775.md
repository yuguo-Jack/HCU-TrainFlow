# [DSA] Route the k-pool indexer top-k through the top-k v2 kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/43775) · state: open · merged: False

## Original PR description

## Motivation

The GLM-5.3-Flash k-pool indexer selects its top-k pooled groups with `kpool_topk_transform`, which runs one thread block per row. At decode time there is one row per request, so a single block scans the whole pooled history while the rest of the GPU idles. At 1M context this costs about 84 us per DSA layer per decode step, which is most of the decode slowdown from short to long context.

The top-k v2 kernel already splits long rows across thread-block clusters. This PR routes the k-pool indexer through it, with pool expansion, tail append and the output transform fused into the same kernel.

## Modifications

- **Fused k-pool mode in top-k v2** (`TopKMode::KPOOL`, `transform_kpool`): selection over pooled scores plus pool expansion, tail append and page-table or offset mapping in one launch, on every dispatch route (register, streaming, cluster, persistent cluster). The launch dispatch is shared with `transform_paged` through `launch<kMode>()`.
- **Ragged k-pool entry point** (`transform_kpool_ragged`): per-row windows (`row_starts`, `page_table_row_index`) for prefill and for any caller without a plan. Its select-then-transform body is shared with the ROCm `topk_packed_kernel` through `ragged_select_transform`.
- **Plans live in metadata**: decode and verify metadata build the top-k v2 plan once per forward, before the logits kernel, and refresh it on CUDA-graph replay. Rows without a matching plan take the ragged path.
- `topk_from_pooled_history_logits` dispatches to the planned path, then the ragged path, then the existing kernels. `SGLANG_OPT_USE_TOPK_V2=0` keeps the existing kernels.

## Accuracy Tests

- Kernel parity against the existing fused kernel: every output mode (no transform, page table, page table with row index, offsets), with and without tail columns, aligned and unaligned `row_starts`, short and zero-length rows. All selections match, up to exact score ties at the cut-off.
- CUDA-graph replay with the plan refreshed between replays, batch 1 to 300, covering every cluster dispatch route including the persistent cluster: 0 mismatches.
- GSM8K with `sgl-eval run gsm8k --max-tokens 16384 --temperature 1.0 --top-p 0.95` (1319 questions), GLM-5.3-Flash FP8 on B300 with the cookbook commands:

| Configuration | main | this PR | Eval time main | Eval time this PR |
|---|---|---|---|---|
| High Throughput | 97.04% | 96.89% | 1m 55s | 1m 55s |
| Low Latency (MTP 5/1/6) | 97.12% | 96.89% | 1m 37s | 1m 28s |

Both gaps are 2 to 3 questions, within run-to-run spread at temperature 1.0. GSM8K sequences mostly stay below the 2048-token top-k budget, so this run validates the metadata, plan and transform path end to end.

- Long-context selection with `sgl-eval run ruler2 --max-tokens 16384 --temperature 1.0 --top-p 0.95` (all 12 subtasks, the same generated datasets on both servers), High Throughput cookbook command. Score is the RULER2 headline; the family columns average the four multi-key NIAH, four multi-value NIAH and four QA subtasks:

| Context | Samples | Score main | Score this PR | MK-NIAH main / PR | MV-NIAH main / PR | QA main / PR | Eval time main / PR |
|---|---|---|---|---|---|---|---|
| 128K | 300 | 86.63% | 88.41% | 93.0 / 95.0 | 79.9 / 79.2 | 87.0 / 91.0 | 21m 0s / 18m 44s |
| 512K | 120 | 79.12% | 77.66% | 92.4 / 92.5 | 54.9 / 53.0 | 90.0 / 87.5 | 28m 5s / 25m 50s |

The headline differences change sign across lengths and stay within sampling noise (about 2 points at 128K and 3.5 points at 512K). At 1M each subtask has 5 samples, so family averages move by up to 20 points per sample in both directions. Error rate is 0% and truncation at most 3.3% on every run.

Eval times are the wall-clock time of each `sgl-eval` run (256 concurrent requests for GSM8K; 16 for RULER2 at 128K and 512K, 8 at 1M). In total the accuracy evals took 2h 35m: GSM8K 6m 55s (four runs), RULER2 1h 17m on main and 1h 11m on this PR.
