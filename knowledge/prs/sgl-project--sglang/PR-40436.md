# [DSV4.1][PD][8/N][Perf] Fuse candidate selection and masking for DeepSeek V4.1 prefill

## Summary

Reduce memory traffic and kernel launches in the DeepSeek V4.1 prefill candidate indexer.
Previously, candidate selection materialized a causally masked and padded logits tensor before block reduction. Consumer layers expanded block candidates into token-level masks, modified dense logits, and separately filtered invalid top-k results.
This change fuses these operations and keeps candidate metadata at block granularity.

## Changes
### Candidate source
- Fuse causal masking, partial-block handling, block-max reduction, and newest-block score assignment into a Triton kernel.
- Read strided logits directly without materializing masked or padded copies.
- Keep context width and block count as runtime arguments to avoid compilation for each context length.

### Candidate consumer
- Store one boolean per candidate block.
- Apply candidate filtering inside the prefill top-k kernel.
- Remove invalid selected indices in the same kernel, including underfilled results.
- Preserve request-local offsets and CP/DSPARK tail-row mappings.
Dense logits computation remains unchanged. Existing decode/paged top-k paths retain the default identity score filter.

## Validation

- 112 candidate-indexer GPU tests passed, covering strided inputs, ragged lengths, partial blocks, empty/underfilled candidates, nonfinite values, CUDA Graph replay, and CP backend integration.
- 288 existing top-k regression tests passed.
- Forced-chunk CP integration test passed after the temporary-memory budget adjustment.
- Service benchmarks completed with 512/512 successful requests at each concurrency.
- Four-rank prefill traces confirm both fused kernels execute and eliminate the large logits-shaped mask/pad operations.
