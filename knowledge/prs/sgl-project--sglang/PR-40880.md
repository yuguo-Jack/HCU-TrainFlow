# [NPU] Fix W4A8 MoE scale_bias sharding for tensor parallelism

[Upstream PR](https://github.com/sgl-project/sglang/pull/40880) · state: open · merged: False

## Original PR description

## Motivation

Fix incorrect down-projection compensation in the Ascend INT4-weight / INT8-activation W4A8 MoE path when `moe_tp_size > 1`.

The per-channel loader copies the complete checkpoint `w2_scale_bias` into each rank, while `w2_weight` is sharded along K. `_update_bias()` then sums all compensation segments on every rank. Each rank therefore applies compensation for K partitions it does not own. In the affected ModelSlim checkpoints the last dimension contains 16 compensation segments.

This reproduced as incoherent GLM-5.2-W4A8C8 output with EP1, including on both CANN 9.0 and CANN 9.1. It is related to the W4A8-without-DeepEP accuracy item in #22521; this PR does not claim to resolve the other items in that roadmap.

## Modifications

- Before reducing `w2_scale_bias`, select the contiguous segment range for `layer.moe_tp_rank` using `layer.moe_tp_size`. Reject a segment count that cannot be evenly partitioned.
- Use the actual **MoE** TP group, so mixed TP/EP layouts use the correct rank and EP with MoE TP=1 retains all segments.
- Preserve the existing reduction and `w13` behavior. The activation-clipping branch does not call `_update_bias()` and is unchanged. No checkpoint conversion, new flag, kernel change, or inference-time dispatch change is required.
- Add six regression tests registered in `base-a-test-npu`: every rank at MoE TP1/2/4/8/16, conservation across ranks, mixed TP/EP rank selection, MoE TP1 with global TP16, unchanged `w13`, missing compensation, and rejection of incompatible segment counts. Nonuniform segment values also rule out replacing the correction with `full_bias / tp_size`.

Both ModelSlim and the non-clipping compressed-tensors W4A8 scheme use this backend method and allocate the full compensation segment dimension. Hardware validation below covers ModelSlim; no compressed-tensors model-level run is claimed.

These are focused accuracy smoke tests, not a GSM8K/MMLU evaluation. EP16 end-to-end correctness is also **not** claimed: separate trials were blocked by DeepEP/NPU errors before useful generation.

A single-expert NPU grouped-matmul experiment additionally compared the sum of K-partitioned outputs against the unpartitioned output, using real `model.layers.3.mlp.experts.0.down_proj` weights and fixed INT8 input (seed 52):

| Compensation handling | TP8 relative L2 error | TP16 relative L2 error |
| --- | ---: | ---: |
| Full compensation on every rank | 0.971464 | 2.081729 |
| Matching compensation segments per rank | 0.002361 | 0.002371 |
| No-bias additivity control | 0.002343 | 0.002340 |

The corrected error is close to the no-bias partition/reduction rounding control. These numbers are for this single-layer experiment, not model accuracy scores.

## Speed Tests and Profiling

No throughput benchmark was run. The correction executes once during weight post-processing, before serving; it adds a view selection and reduces fewer compensation elements per TP rank. The inference kernels and forward path are unchanged. No inference throughput speedup claim is made.

In the [review discussion](https://github.com/sgl-project/sglang/pull/40880#discussion_r4236940760), @xiedeyantu reported identical results and approximately 3.1x (TP8) / 5.5x (TP16) faster execution of the original `narrow` block than the proposed `chunk` alternative on Ascend 910B4. This is reviewer-reported weight-post-processing microbenchmark evidence, not an independently repeated result or a decode TPS measurement. `narrow` is retained.
