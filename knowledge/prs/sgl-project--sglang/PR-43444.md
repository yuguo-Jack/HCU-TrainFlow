# [Scheduler] Fix the deterministic-inference hang when a prefill chunk is shorter than its alignment

[Upstream PR](https://github.com/sgl-project/sglang/pull/43444) · state: closed · merged: True

## Original PR description

- Deterministic inference truncates each prefill chunk to a multiple of an alignment (4096 by default). A per-rank chunk below it, from `--chunked-prefill-size` < 4096 or from DP attention splitting the chunk across ranks, truncated every chunk to zero tokens, so a prompt longer than the chunk waited in the queue forever
- Triton: drop the alignment; `align_window_kv_to_tiles` pads each sliding-window KV list to an absolute multiple of 128, so a chunked prefill sums keys in the same tiles as an unchunked one (built once per forward, deterministic inference only; the attention kernel is unchanged)
- Flashinfer and the DSA kpool alignment: a per-rank chunk shorter than the alignment fails at startup instead of hanging; decode servers are exempt
- Deprecate `SGLANG_TRITON_PREFILL_TRUNCATION_ALIGN_SIZE`
- Add `test_deterministic_chunk_align.py` and a chunked-vs-unchunked sliding-window case in `test_triton_attention_kernels.py`

No behavior change without deterministic inference. With it, triton prefill chunks are no longer aligned (chunked and unchunked outputs stay bitwise equal), and flashinfer configurations that used to hang now fail at startup.
