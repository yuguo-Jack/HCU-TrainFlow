# Preserve serialized page dtype in NIXL copy fallback

[Upstream PR](https://github.com/sgl-project/sglang/pull/43593) · state: closed · merged: True

## Original PR description

## Motivation

NIXL allocated copy buffers with the pool dtype while calculating transfer sizes from serialized pages. DSA index pages and mixed Mamba checkpoints serialize as uint8, so a bf16 pool dtype could silently corrupt a successful storage round trip. Use the serialized page dtype for primary and sidecar copy buffers.

Validation: the NIXL storage module passes 22 tests with one stress test skipped. Real DSA and mixed-dtype Mamba POSIX round trips fail before and preserve every byte after the fix. A Kimi restart diagnostic with Mamba copy fallback explicitly forced reproduces two corrupted checkpoints on main and restores all 86,835,200 bytes after the fix, including two storage-only restores. This diagnostic does not validate default path selection or O_DIRECT alignment.
