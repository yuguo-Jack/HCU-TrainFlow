# [diffusion] Bound frame_interpolation_exp to RIFE's supported range

[Upstream PR](https://github.com/sgl-project/sglang/pull/43014) · state: open · merged: False

## Original PR description

## Motivation

`frame_interpolation_exp` was never validated. Output frames grow as `2**exp`, so a large value means unbounded RIFE work and memory. Values below 1 are worse: `n_intermediate = 2**exp // 2` becomes 0 and `_make_inference` only stops at `n == 1`, so the request recurses forever.

A second bug in `Model.inference` caused crashes at `frame_interpolation_scale=0.5` on 480p and 720p input. The padding was always rounded to a multiple of 32, but at scale=0.5 the deepest IFBlock divides spatial dims by 2, so input must be divisible by 64. The fix mirrors upstream RIFE: pad unit = `max(32, int(32/scale))`.

## Modifications

- Add `MIN_FRAME_INTERPOLATION_EXP = 1` and `MAX_FRAME_INTERPOLATION_EXP = 4` (16x) in `sampling_params.py`. The upper bound is a judgment call; happy to change it.
- Check the range in `SamplingParams._validate`. This covers HTTP (JSON and multipart, returns 400 before admission), realtime and offline.
- Same check at the top of `FrameInterpolator.interpolate`, before weights load, for direct callers.
- Fix `Model.inference` to pad to `max(32, int(32/scale))` instead of always 32.

## Tests

- `test_multiple_task_types.py`: `/v1/videos` rejects exp -1, 0, 5 over JSON and multipart with 400 and nothing admitted; max value still accepted.
- `test_output_materialization.py`: `materialize_output_sample` raises for 0 and 5 without loading RIFE weights. Two new cases confirm `Model.inference` returns the correct shape at 480p and 720p with `scale=0.5` (both crashed before the fix).

New invalid-value cases fail on main and pass with this change. Formatted with the pinned ruff and isort.
