# [Diffusion] AITER Sage: support packed varlen attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/43686) · state: open · merged: False

## Original PR description

## Motivation

`--attention-backend aiter_sage` cannot be used with models that require packed varlen attention. MiniMax-H3 is one of them: all its self-attention calls go through `forward_varlen` (`AttentionRequirements(packed_varlen=True)`).

`AITERSageImpl` only implements `forward()`, so `AttentionBackend.supports_packed_varlen()` returns `False`. Selecting the backend for MiniMax-H3 therefore fails on any ROCm GPU:

```
ValueError: Attention backend 'aiter_sage' does not implement packed varlen attention
```

The `SAGE_ATTN` backend (CUDA) already supports this case.

With varlen added, the run completes, but the video is noise. That comes from two further bugs on the path, fixed here as well.

## Modifications

1. **Packed varlen.** `AITERSageImpl.forward_varlen()` runs the existing kernel once per `cu_seqlens` segment, in the same way as `SageAttentionImpl._sage_packed`:
   - **Trailing padding.** With `packed_trailing_padding` (MiniMax-H3 packs one live document as `bounds=(0, used, total)`), only the live prefix is computed, and the padded tail rows stay zero.
   - **Single segment.** A segment that covers the whole tensor is computed with one call and no copy.
   - **Empty segments.** These are skipped.
2. **`causal` and `softmax_scale`.** `AITERSageImpl` called `fav3_sage_wrapper_func(q, k, v)` and dropped the layer's `causal` flag and `softmax_scale`, so causal layers ran non-causal attention. With `--attention-backend aiter_sage`, MiniMax-H3's text encoder (Qwen3-VL, causal) uses this backend too, and its output was wrong (relative error 0.89 vs. causal SDPA). The kernel accepts both arguments; they are now passed through.
3. **Contiguous Q/K/V.** aiter's Sage quantization (`sage_quant`) allocates its outputs with `empty_like` but indexes inputs and outputs with one set of strides taken from the inputs, and reads V with K's strides (ROCm/aiter#6222, fix ROCm/aiter#6400). Strided views are therefore quantized from the wrong elements: on a MiniMax-H3 shape, a non-contiguous V gives relative error 1.3, a non-contiguous Q or K gives NaN, and some layouts fault. MiniMax-H3 passes `qkv.split(...)` views. `forward` now passes `.contiguous()` tensors (a no-op for dense inputs); the copies can be dropped once aiter includes the fix.

The kernel itself is unchanged. Unit test: `test/unit/test_aiter_sage_attn_backend.py`. It uses a stubbed aiter, so it needs neither a GPU nor aiter. It covers varlen segmentation, the passed `causal` / `softmax_scale`, and that strided inputs reach the kernel contiguous.

## Accuracy Tests

- **Direct comparison on the GPU (Radeon AI PRO R9700, gfx1201, ROCm 7.15 / PyTorch 2.11).** `forward_varlen` with the real `fav3_sage` kernel matches per-segment direct calls bitwise for:
  - H3-style trailing padding, `(0, 4100, 4160)`;
  - two segments, `(0, 1000, 1000, 3000)`;
  - one full segment, `(0, 4160)`.

  The tail rows are zero.
- **End to end.** MiniMax-H3 with the case parameters of `minimax_h3_t2va_2gpu_h100`: t2va, 1344x768, 4 s, 8 steps, seed 42, TP2, on 2x R9700. Same flags as that case. Video PSNR and audio cosine are against the `torch_sdpa` run; for scale, SDPA with K/V token order reversed (mathematically identical, only rounding differs) gives 34.41 dB / 0.991.

  | branch | `--attention-backend` | result | denoise stage | video PSNR / audio cos vs SDPA |
  |---|---|---|---|---|
  | main | `torch_sdpa` | completes | 152.3 s | - |
  | main | `aiter_sage` | `ValueError: ... does not implement packed varlen attention` | - | - |
  | this PR, varlen only (1.) | `aiter_sage` | completes, frames are noise | 428.8 s | 15.02 dB / 0.08 |
  | this PR (1.-3.) | `aiter_sage` | completes, clean frames | 412.7 s | 26.42 dB / 0.68 |

Notes on the end-to-end run:

- **Accuracy.** The remaining gap to SDPA is the precision of `fav3_sage` on gfx1201: on dumped MiniMax-H3 DiT inputs its relative error vs. BF16 is 0.054 on average (0.11-0.16 in the last layers), against 0.013 for aiter's gfx1201 SageAttention kernel. gfx942 / gfx950 were not tested here (no hardware).
- **Speed.** On gfx1201, `fav3_sage` is slower than BF16 SDPA. The gfx1201 kernel is wired in by a follow-up PR (#43687, stacked on this one).
- **Test environment.** The R9700 runs used `sgl-kernel` built for gfx1201 (#43679), and the custom all-reduce was disabled because R9700s connect over PCIe (#43676). Neither affects the code changed here.
