# [CP] Support interleave prefill for dense MHA, GQA and MLA

[Upstream PR](https://github.com/sgl-project/sglang/pull/43276) · state: open · merged: False

## Original PR description

## Motivation

Enable interleave prefill context parallelism for dense MHA/GQA and absorbed MLA with FlashAttention. A rank's queries are noncontiguous in the original requests, so treating them as a contiguous causal suffix exposes the wrong keys.

## Modifications

Gather K/V into global token order and write the existing paged cache. Dispatch each local query as a one-query logical sequence with its original request's page table and prefix-plus-position causal extent. Preserve physical padding, per-request scales, sliding-window locations, and the distinct dense/DSA MLA gather contracts. Reject unsupported attention options before writing KV.

Also use attention-TP head/projection/cache-scale layouts in Qwen2. The previous global-TP layout makes Qwen1.5 MHA fail under both zigzag and interleave CP when the gathered keys are written to the cache.

This is an independent main-based PR; it does not depend on the sparse-attention CP PRs.

## Accuracy Tests

Production revision `4ebadc2b82`; current head `eee4227d93` adds only test formatting. Six focused regression methods and 24 existing CP tests pass through normal package imports on H200. Coverage includes causal/SWA positions, physical padding, real backend dispatch with mocked kernel boundaries, per-request descales, MLA cache ownership, early unsupported-option gates, unchanged zigzag geometry, and Qwen2 CP/off projection layouts.

FA3, 2x H200, TP2/CP2, 200 GSM8K examples per cell:

| Attention / public model | CP off | Zigzag | Interleave |
| --- | ---: | ---: | ---: |
| MHA / Qwen1.5-7B-Chat | 58.5% | 56.5% | 56.0% |
| GQA / Qwen3-8B | 95.0% | 95.5% | 95.5% |
| MLA / DeepSeek-Coder-V2-Lite-Instruct | 83.5% | 84.5% | 85.5% |

GQA/MLA off and zigzag controls are from `fa5514a0d5`; the subsequent production change only fixes Qwen2's head/projection layout. All MHA cells and both GQA/MLA interleave repeats use `4ebadc2b82`. All listed GSM8K runs have zero request errors. At the common 2,048-token output limit, MLA off/zigzag/interleave truncation rates are 0.5%/1.0%/0.5% (1/2/1 of 200); these samples are included in the reported scores. MHA/GQA truncation is zero.

MHA interleave/zigzag input logprobs match exactly across 1,709 teacher-forced smoke tokens. Unequal-length FA3 prefix probes have positive cache hits and identical cached/cold replay text.

FA4 interleave on the same H200 pair scores MHA 59.5% and GQA 95.5% (200 examples each; zero request errors/truncation). GQA cached/cold text matches on 2/3 prompts; the remaining prompt differs in wording, with first-token logprob difference 0.01193 (CP-off control: 0.04478). FA4 absorbed MLA requires Blackwell and has only mocked-kernel integration coverage here.

These small samples do not establish statistical accuracy equivalence or bitwise equivalence across backends.

## Speed Tests and Profiling

Correctness-first implementation; no speedup claim. Per-query page-table expansion costs O(local queries × page-table width) metadata and currently runs per layer. Optimization should follow correctness qualification.

Unsupported options remain explicit, including noncausal/cross attention, local chunked attention, custom score/bias, MXFP8, LSE output, and raw/chunked MLA. FA4 absorbed MLA additionally rejects finite windows, softcap, and forced split-KV.
