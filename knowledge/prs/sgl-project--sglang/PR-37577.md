# [Feature] Add Aaronson-Gumbel text watermarking

[Upstream PR](https://github.com/sgl-project/sglang/pull/37577) · state: open · merged: False

## Original PR description

## Motivation

Some deployments need a machine-readable signal that text was generated by an AI system, including provenance workflows and transparency obligations such as [Article 50 of the EU AI Act](https://eur-lex.europa.eu/eli/reg/2024/1689/oj/eng). This PR adds opt-in text watermarking to sampled generation without adding tokens or changing default serving behavior.

## What this PR adds

- Keyed Aaronson-Gumbel sampling over the post-penalty, grammar-masked, top-k/top-p/min-p distribution, with model-free Gamma-test detection from token IDs.
- Returned logprobs reflect the pre-watermark target distribution (the sampler computes them from the unforced distribution when `return_logprob` is set, matching the speculative-decode semantic).
- Server configuration through `--enable-watermark` plus one `--watermark-config` JSON object, given as a file path or inline (`key`, `key_b`, `context_window`, `mixing_probability`, `max_probability`, `default_enabled`, `enforce_all`), with explicit opt-in, default-on, and enforce-all policy modes and secret redaction.
- Per-request enablement, keys, and context windows, including mixed watermarked and unwatermarked batches.
- Opt-in dual-key selection with a deterministic per-context coin and matching detector views; single-key behavior is unchanged when key B is absent.
- Verified normal decode plus NGRAM, EAGLE, EAGLE3, and NEXTN, including TP2/TP4 and DP2/TP2 normal/NEXTN service gates.
- An in-tree `WatermarkDetector` that also works as a copied package without SGLang or PyTorch, plus a reference HTTP detection server that uses the same `--watermark-config`.
- Repeated-context loop prevention, greedy bypass, fused normal/speculative state kernels, and a host-gated path that launches no watermark kernels for fully disabled batches.
- Fail-closed admission for unsupported modes, including DFLASH/DSPARK, pipeline-parallel speculation, rejection-sampling speculation, beam search, PD disaggregation, custom logit processors, and non-CUDA devices.

## Performance and evidence

Relative results are within-engine ON/OFF comparisons. Finite-top-k and speculative rows use random 1,024/512 requests, c8, temperature 0.8, top-p 0.95, top-k 20, 10 warmups, 100 measured requests, and three repetitions unless noted.

| Workload | Result |
| --- | --- |
| Qwen3-8B, GSM8K-100 (sgl-eval) | 95-97% accuracy / 100% stop across normal decode (B200), NGRAM with `--disable-overlap-schedule` (H200), and EAGLE3; detection ON p=`1.09e-20` to `4.18e-27`, OFF p=`0.325-0.995`; greedy stopped safely in every gate |
| Qwen3-8B H200, no spec, finite top-k, c1 / c8 | Output throughput `+0.13% / +0.02%` (run-to-run noise) |
| Qwen3-8B GB300, no spec, unlimited top-k, c8 | `224.88 → 212.84` output tok/s per stream (`−5.35%`) |
| Qwen3.5-9B GB300 TP2, NEXTN 3/1/4 | TPOT `2.246 → 2.451 ms` (`+9.17%`); final-head same-pair spot check `+8.92%` |
| Capability enabled, fully disabled EAGLE3 traffic | TPOT `2.465 → 2.469 ms` versus merge-base (`+0.14%`) |
| Dual key versus single key, GB300 | Output throughput `−0.21%` c1 / `−1.50%` c8, within repetition variance |
| Speculative accept length | `2.759 → 2.783` (`+0.85%`) |

The DP2/TP2 gate used Qwen3-8B on two H200 GPUs: GSM8K-100 was 95% with 100% stop, both ranks detected at p=`1.84e-23`, disabled controls were p=`0.358`, repeated one-rank-idle batches remained healthy, and a DP2/TP2 NEXTN smoke detected at p=`2.14e-36` on both ranks.

## Limitations

- Temperature 0 carries no signal. Short or low-entropy spans are weaker, and `max_probability` trades signal for ordinary sampling at low-entropy positions.
- Paraphrase and translation erase the signal; edits reduce the number of usable contexts.
- Murmur32 is a keyed, non-cryptographic mix. Key holders can both detect and forge; inline `--watermark-config` JSON is process-visible, and core dumps may contain in-memory keys.
- Unlimited top-k requires a full-vocabulary sort and measured `−2.8%` to `−7.2%` per-stream throughput; finite `top_k=20` was within noise. Unlimited-top-k speculative verification uses the slower tensor path.
- Watermarking stops after `min(4,096, per-request token-pool capacity)` admitted contexts. Runtime uses 32-bit context-hash admission while the detector deduplicates exact tuples; rare collisions and conservative sibling suppression only dilute signal.
- Speculative cost and acceptance are model- and workload-dependent, especially for top-k-1 draft chains, although the public NEXTN/EAGLE3 measurements above preserved acceptance.

The in-tree [`watermarking/README.md`](https://github.com/JustinTong0323/sglang/blob/watermark/python/sglang/srt/sampling/watermarking/README.md) is the design reference. Evaluation results remain in **Performance and evidence** and **Cross-engine reference** above. Configuration, request semantics, the normative detector contract, standalone use, and the compatibility matrix are in the [`text_watermarking.mdx` operator guide](https://github.com/JustinTong0323/sglang/blob/watermark/docs/docs/advanced_features/text_watermarking.mdx).
