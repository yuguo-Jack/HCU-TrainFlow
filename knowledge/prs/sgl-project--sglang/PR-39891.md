# [XPU] Enable RL feature on Intel XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/39891) · state: open · merged: False

## Original PR description

## Motivation

Enable SGLang's RL features on Intel XPU (in addition to CUDA/ROCm) and enable the corresponding tests.

**Depends on #40720.** `test_update_weights_from_tensor.py`, `test_weight_checker_e2e.py` and `test_patch_torch.py` send device tensors through `MultiprocessingSerializer`. XPU has no tensor IPC, so on XPU these tests need #40720 (XPU tensors staged through host shared memory). Please merge this PR after #40720. #40720 also edits `test_patch_torch.py`; the only overlap is the `sglang.srt.utils` import line.

Source changes:
- weight_checker.py: synchronize through `get_device_module()` instead of `torch.cuda`.
- weight_checker_comparator.py: move chunks to the current device instead of `.cuda()`.
- indexer_topk.py: enable the capturer on XPU (`Indexer.forward_xpu` runs the same capture sites as CUDA).
- attention_hook.py: with deterministic inference and TP > 1 on XPU, set `CCL_ALLREDUCE=recursive_doubling`. oneCCL's default XPU all-reduce kernels switch by message size and are not batch-invariant at 3+ ranks, and CUDA's `NCCL_ALGO=allreduce:tree` has no effect on XCCL. A proper oneCCL fix will be tracked separately.
- weight_updater.py: restore `model_config.model_path` on every failure exit of `update_weights_from_disk`. Not XPU-specific: a failed update left the path on the rejected checkpoint, so the rollback reload read it again.

### Supported and Verified following Features

- Weight refit from a distributed trainer over XCCL (Engine and Server; tp1dp1, tp1dp2, tp2dp1, tp2dp2; default and flattened_bucket load formats)
- Live refit with `pause_generation` in `in_place` and `retract` modes
- Weight update from disk, including rollback on missing or malformed weights
- Weights checker (snapshot / compare / checksum)
- Routed-experts capture (MoE, TP4, deterministic)
- Indexer-topk capture (DSA)
- Release / resume memory occupation (sleep / wake)
- Deterministic inference with TP > 1

Test changes:
- `test_update_weights_from_tensor.py`, `test_weight_checker_e2e.py`: device-agnostic (`get_device()` / `get_device_module()`) and registered for `nightly-xpu-1-gpu`. `test_weight_checker_e2e.py` also calls `monkey_patch_torch_reductions()` in `setUpClass`, as SGLang's own clients do, because it serializes tensors itself; with #40720 this routes XPU tensors through host shared memory.
- `test_patch_torch.py`: picks `ZE_AFFINITY_MASK` on XPU.
- `test_multi_instance_release_memory_occupation.py`: device-agnostic; skipped on XPU because `ProcessGroupXCCL` has no comm splitting.
- `test/manual/rl/test_xpu_rl.py`: manual XPU suite covering the distributed refit matrix, disk refit, and routed-experts / indexer-topk capture. Distributed updates are wrapped in `begin_weight_update` / `end_weight_update`, as required since #40777.

## Accuracy Tests

Weight correctness after refit is checked bit-exactly, not by comparing generated text (measured before the rebase):
- After alternating refits between Llama-3.2-1B-Instruct and Llama-3.2-1B base, the per-rank, per-tensor checksums from `/weights_checker` matched references from servers that loaded each checkpoint from disk: 0 mismatched tensors over 35 cycles, on both TP ranks.
- Requests that kept generating across live updates (`retract` and `in_place`) had correct weight-version spans: 0 violations in 3,648 requests.
- `TestUpdateWeightsFromDisk` compares logprobs to 1e-4 after refit (above).

## Speed Tests and Profiling

RL rollout/refit performance with a simulated trainer (not end-to-end training throughput), measured before the rebase. Llama-3.2-1B-Instruct BF16; trainer on 1 card, SGLang TP2 on 2 cards; 5 warmup + 30 measured cycles; median / p95.
