# [SM90] Use native block32 DeepGEMM for DeepSeek-V4.1

## Motivation

DeepSeek-V4.1-Flash stores its dense FP8 weights in [32,32] blocks, compared with [128,128] in DeepSeek-V4-Flash.
These GEMMs cover attention, the shared expert, indexer, Engram, and DSPARK linears.
On Hopper, the SGLang dispatcher routes K-block != 128 to Triton, while the DeepGEMM wrapper only accepts [128,128]. Larger prefill GEMMs can use the existing BF16 weight-cache fast path.
https://github.com/sgl-project/DeepGEMM/pull/95 added native SM90 block32 support. This PR integrates that path into SGLang using sgl-deep-gemm==0.2.2

## Modifications

Routes supported SM90 block32 linears through the existing DeepGEMM wrapper with:
`fp8_gemm_nt((Aq, As), (Wq, Ws), D, recipe=(1, 32, 32))`
The integration preserves checkpoint FP8 weights and UE8M0 activation rounding, passes the block dimensions through the GEMM wrapper, and prepares block32 scale buffers during kernel warmup.
Both prefill and decode use native DeepGEMM. The unused BF16 weight expansion is skipped when DeepGEMM is selected. Explicit Triton selection and unsupported shapes retain their fallback.

Server configuration for the tests listed below

```
SGLANG_ENABLE_DSV41_ENGRAM_HOST_TABLE=1 \
sglang serve \
  --model-path deepseek-ai/DeepSeek-V4.1-Flash \
  --trust-remote-code \
  --random-seed 42 \
  --tp 4 \
  --mem-fraction-static 0.8 \
  --attention-backend dsv4 \
  --moe-runner-backend flashinfer_mxfp4 \
  --ep-size 4 \
  --enable-decoder-swa-bounded-replay \
  --cuda-graph-max-bs-decode 64 \
  --reasoning-parser auto \
  --tool-call-parser auto \
  --speculative-algorithm DSPARK \
  --speculative-dspark-block-size 5 \
  --host 0.0.0.0 \
  --port 30000
```
