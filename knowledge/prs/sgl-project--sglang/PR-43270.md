# [Fix] GLM-4.7/5 tool parser: stop turning comma-containing values into arrays

[Upstream PR](https://github.com/sgl-project/sglang/pull/43270) · state: open · merged: False

## Original PR description

## Motivation

Part of #43147, for the GLM-4.7 / GLM-5 parser.

#43147 reports that `parse_arguments` in `glm4_moe_detector.py` falls back to `ast.literal_eval`, which turns a bare comma into a Python tuple, so a scalar the model wrote as `1,000` reaches the tool as the JSON array `[1, 0]`. #43264 fixes that file.

`glm47_moe_detector.py` (used by `--tool-call-parser glm47` for GLM-4.7 and GLM-5) has its own copy of `parse_arguments` with the same Strategy 3 and the same bug, and #43264 doesn't touch it. On current main:

```
parse_arguments("1,000", "number")   -> ((1, 0), True)
Glm47MoeDetector, <arg_value>1,000</arg_value> for a number param -> {"n": [1, 0]}   (streaming and non-streaming)
```

## Modifications

- `glm47_moe_detector.py`: when Strategy 3 returns a tuple, fall through to Strategy 4 (keep the raw string), unless the argument is array-typed. Array-typed arguments get the tuple as a list, which is exactly what the client saw before (`json.dumps` already turned the tuple into an array), so `1, 2` for an array param still becomes `[1, 2]`. Only non-array arguments change.
- `test_glm47_schema_types.py`:
  - `test_bare_comma_value_is_not_split_into_an_array` runs end to end through `Glm47MoeDetector` with the existing `check_arguments` helper (non-streaming, plus streaming at chunk sizes 1, 7 and full).
  - `test_parse_arguments_bare_comma` covers the reported inputs and pins the array-typed behaviour.

Both tests fail on current main and pass with this change. Tests live in the GLM-4.7 test file, so this doesn't overlap with #43264's changes.
