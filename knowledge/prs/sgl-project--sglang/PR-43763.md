# [Fix] Mistral: map control tokens back to ids on the multimodal text path

[Upstream PR](https://github.com/sgl-project/sglang/pull/43763) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43761. A small, self-contained fix (15 source lines added and 6 removed, no new flag, option or dependency) that lifts image answers on the Ministral-3 models from 1-39% to 91-98% correct on a smoke test and lets `--reasoning-parser mistral` see the end of thinking. Prompt ids now match `mistral_common` exactly outside the image patches, text-only requests are untouched and the image tokenizer step gets faster (11 to 4 ms for one image).

The cause: for `MistralCommonBackend` tokenizers the image path tokenizes the rendered chat template as text, and the table that maps control-token spellings back to ids only knew `[IMG]`, `[IMG_BREAK]` and `[IMG_END]`. Image prompts reached the model without `<s>`, `[INST]` and `[/INST]`. The same table answers `tokenizer.encode("[/THINK]")`, which `--reasoning-parser mistral` uses for `think_end_ids` (scheduler and `ReasonerGrammarBackend`), so the end of thinking was never matched.

## Modifications

4 files, +111/-6, of which 21 source lines are changed and 96 are tests.

- `mistral_utils.py` (+10/-5): build `marker_to_id` from every named special token (skipping the unnamed `<SPECIAL_n>` fillers), including `[THINK]` and `[/THINK]`. The marker search caches each marker's next position, so the larger table does not slow encoding down.
- `serving_chat.py` (+5/-1): the startup probe message is now `[INST]` instead of `x`. With this fix the text route (images) maps that spelling to the control token while the ids route keeps plain text, so the probe still reports a difference and text-only requests keep the ids route from #39773. The old x message would no longer show a difference, which is why it changed.
- Tests (+96, CPU suite `base-a-test-cpu`): new `test_mistral_control_token_markers.py` (80 lines, 3 tests) and one probe test in `test_chat_prompt_round_trip.py` (16 lines).

## Accuracy Tests

**Setup:** one A100 80GB, default server flags, main at 7760d5264a against this PR on top of it. Every result below reads "main to this PR".

- **Image smoke test** (generated 224x224 images, e.g. "How many circles are in the image?" for 1 to 5 circles, plus shape color and left or right of a red dot): share answered correctly. Ministral-3-3B **1.1% to 91.1%**, 8B **38.9% to 97.8%**, 14B **10.0% to 95.6%**, Mistral-Small-3.1 **19.7% to 97.3%**, Devstral-Small-2 **1.1% to 68.9%**.
- **Prompt ids vs the reference** (token ids SGLang builds for a chat compared with those from `mistral_common`, Mistral's own tokenizer library; 15 hand-written and 40 random conversations on each model above, plus Medium-3.5 with 2 random-weight layers): **identical** everywhere except the image-placeholder slots, which are not compared.
- **Text and mixed benchmarks** (Mistral-Small-3.1): GSM8K 94.0% to 93.5%, MMMU (300) 59.7% to 61.3%, **no regression** (both within noise).
- **Reasoning** (`--reasoning-parser mistral`, Ministral-3-3B-Reasoning, 8 `/generate` requests with `require_reasoning` and a `json_schema`): answers matching the schema **0/8 to 8/8**, and `reasoning_tokens` equals the true thinking length instead of all output tokens.
- **Anthropic adapter (`/v1/messages`):** its 63 unit tests pass and nothing gets worse. Image chats with thinking in history now get the real `[THINK]` tokens.
- **Unit tests:** the 13 tests in the two touched files pass on current main.

## Speed Tests and Profiling

The tokenizer step on image requests (Mistral-Small-3.1) measured 11 to 4 ms for one image and 58 to 17 ms for four. The cached marker search helped: the same loop without it takes 107-170 ms against 5-7 ms on a 21k-character image prompt. Text-only requests are unchanged.

## Known limits

- On image requests (also raw prompts, `/tokenize`, `--chat-template` and `continue_final_message`), a message that contains `[INST]` or `<s>` now becomes the control token. **Every other model family already behaves this way** (39 of 39 stock chat tokenizers I checked map typed special strings to ids), `[IMG]` already did here, and it only reaches the sender's own request. Escaping such input belongs in a cross-model change (#30962), and without this mapping every image request loses its chat structure (1-39% correct above). Ids-first tokenization (as #41176 does for Voxtral) would avoid it but is larger.
- The vendor system prompt of the reasoning models spells `[THINK]` as text, so on image requests it is 158 tokens instead of 163.
