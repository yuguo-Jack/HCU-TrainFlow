# [PD] Use 1 to disable decode host receive and 0 for always-on

[Upstream PR](https://github.com/sgl-project/sglang/pull/43407) · state: closed · merged: True

## Original PR description

## Motivation

`--disaggregation-decode-host-receive-threshold` is a device token usage fraction: once usage reaches it, incoming KV is received into the decode retraction host pool instead of device memory. The previous encoding used `0` both as the default and as "disabled", which left no way to express "always receive on host" and made the flag read backwards for a usage threshold, where a lower value should make host receive kick in earlier.

## Modifications

Make the flag a plain threshold over its whole range:

- `1` (the new default) disables host receive;
- `0` always receives into the host pool;
- values in `(0, 1)` receive on host once device usage reaches that fraction.

Every `> 0` gate on the flag becomes `< 1` (arg hooks, `DecodePreallocQueue`, `DecodeTransferQueue`, the scheduler decode mixin, metrics reporter, retraction-backup sizing), and the scheduler path that moves preallocated requests straight to the transfer queue when host receive is off now keys on `== 1`.

**Behavior change:** configurations that passed `0` explicitly to disable host receive must pass `1` instead. The default stays "disabled".

Tests follow the new encoding: fixtures that disabled host receive with `0` now use `1`, including `test_mamba_capacity.py`, whose `pop_preallocated` mock would otherwise take the host-receive path; `test_decode_retraction_backup.py` gains a case for `0` always staging; and `test_server_args.py` checks that the default resolves to `1` and leaves the retraction backup unresolved.
