# [HiCache] Re-admit a split node's queued buffer-mode write instead of dropping it

[Upstream PR](https://github.com/sgl-project/sglang/pull/43174) · state: closed · merged: True

## Original PR description

## Motivation

A buffer-mode backup intent snapshots the node it was admitted for. If that node is split before the D2H write is launched (a shorter prefix arrives, the SWA window boundary lands inside it, or the finish path splits the leaf at the prompt/output boundary), the queued intent no longer matches its node and `_sweep_stale_backup_intents` dropped it. The span then only reached L3 storage if a later hit happened to re-trigger a backup, so its KV could stay out of storage indefinitely while the backlog metric counted it as "dropped".

## Modifications

- Replace `_sweep_stale_backup_intents` with `_refresh_pending_backup_intents`, which repairs split intents instead of dropping them. For a split intent it walks parents from the original node until the admitted span is covered (`_split_pieces`), re-admits one intent per piece (parents first) in the original FIFO position, and carries over inflight ownership and the queued-span refs so the backlog accounting stays balanced.
- The earliest intent for each `(node, pool)` wins, including repaired pieces. A piece that is already staged or awaiting its storage ack, or whose write is already covered since admission, is skipped. Spans that are really gone (evicted or deleted) are still dropped and counted as before.
- `test_unified_radix_cache_unittest.py`: two regression tests. `test_buffer_only_split_intent_writes_every_piece` splits a queued node twice and checks every pool's write survives exactly once, parents first, with a balanced backlog, then drains the pipeline and checks every hash of the original span exists in storage. `test_buffer_only_finish_writes_prompt_and_output` covers the finish-path prompt/output split on FULL-only caches.

Both new tests fail on current main (the split intent is swept and the span never reaches storage) and pass with this change, across every `Test_FULL_*` and `Test_FULL_SWA_*` page-size / window configuration.
