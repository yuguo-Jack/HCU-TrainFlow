# [sgl-router] Rewrite POLICY_DESIGN.md as a layered reference for reorg routing

[Upstream PR](https://github.com/sgl-project/sglang/pull/43592) · state: open · merged: False

## Original PR description

## Motivation

`experimental/sgl-router/POLICY_DESIGN.md` mixed target design with current behavior, had no overview or configuration reference up front, and had drifted from the code (e.g. it listed P/D compatibility filtering as unimplemented although version-group pairing exists in `buckets_reorg.rs`). This rewrite makes it a concise reference for how `--chat-routing reorg` picks engines today.

## Modifications

- **`POLICY_DESIGN.md`** (655 → 439 lines), organized by layer:
  1. Overview: architecture diagram (bucket → engine group → policy), policies at a glance (`power_of_two`, `cache_aware`, `session_aware`, admission caps), and a full configuration reference (flag, default, per-group JSON key) with a CLI-only example and an annotated `--bucket-config`.
  2. Load signals: each metric's source, freshness rules, and stage-specific ranking order.
  3. Buckets, 4. Engine groups (incl. P/D version-group pairing diagram), 5. Policies: selection for each policy, prefer vs balanced (switch formula + worked numbers), and admission (caps, fail-open semantics, where each policy checks).
  6. Failures/retries → HTTP status, 7. code map, and an appendix of legacy options rejected under reorg.
  - Describes current behavior only; target-design and implementation-status lists are removed.
- **`README.md`**: link the doc from the "Reorg routing" section and fix the anchor that pointed at the old configuration section.

Docs only; no code changes.
