# [Bugfix] Honor preferred sampling parameters in chat completions

[Upstream PR](https://github.com/sgl-project/sglang/pull/39201) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #39096.

Chat requests eagerly materialize sampling defaults before the tokenizer manager merges `--preferred-sampling-params`, so an omitted `top_k` becomes `-1` even when the operator configured `20`. The same issue affects temperature, top-p, penalties, and other request defaults.

## Modifications

Resolve chat sampling settings in `ChatCompletionRequest.to_sampling_params()` with **explicit request > preferred server settings > model generation config > protocol defaults**. `serving_chat` passes the existing preferred settings into this conversion; no IPC fields or parallel field-name tables are added.

The server settings intentionally outrank the checkpoint configuration: #39096 needs operators to select a different published sampling profile without changing every client. The closed #21821 proposed model configuration above preferred settings, which would leave that reported use case unresolved.

- Distinguish omitted fields from explicitly supplied values, including values equal to protocol defaults, `0`, and `False`. Preserve the existing null semantics of nullable fields.
- Preserve the unlimited `max_new_tokens=None` default when no limit is configured, and retain `max_completion_tokens=0` when resolving the deprecated alias.
- Keep template stop strings, request/tool constraints, and parser-required special tokens. Mask only active conflicting preferred grammar keys so the tokenizer manager's final merge cannot reintroduce them. Add preferred stop strings to template stops without mutating either input.
- Keep the effective `n` consistent between engine batch expansion, response grouping, and usage accounting.

## Accuracy Tests

CPU-only tests use real Pydantic requests and production conversion/batch-normalization methods, without launching a model:

```bash
for test_file in \
  test_chat_preferred_sampling_params.py \
  test_protocol.py \
  test_serving_chat.py \
  test_serving_completions.py \
  test_serving_responses.py; do
  PYTHONPATH=python python -m pytest -q \
    "test/registered/unit/entrypoints/openai/$test_file" || exit 1
done
```

Result: **243 passed, 253 subtests passed** across five separate test processes on macOS/Python 3.12.13. The new serving-conversion regression fails on base `6ba96d32` with `AssertionError: 0.5 != 0.7` and passes with this change. The grammar matrix checks all four preferred grammar kinds against four request formats and two tool constraints through the final merge and real `SamplingParams.verify()`. Response tests also check choice indexes and prompt/cache/image-token deduplication for effective `n=1/2/3`. Changed-file pre-commit checks pass.

## Speed Tests and Profiling

No model or GPU benchmark was run; this change only resolves parameters before generation. Sampling behavior changes when preferred settings are configured.
