# [Perf] trtllm_mla: pass host q/kv lengths to the ragged prefill to avoid a device sync

[Upstream PR](https://github.com/sgl-project/sglang/pull/43272) · state: open · merged: False

## Original PR description

## Motivation

`TRTLLMMLABackend` calls flashinfer's `trtllm_ragged_attention_deepseek` once per prefix chunk and once for the causal pass of every MLA layer in an eager prefill. Before launching, flashinfer (≥ 0.6.18, including the 0.7.0.post1 pinned on main) checks for empty rows. Without host lengths it reads them off the device:

```python
has_inactive_rows = bool((~active_rows).any().item())   # D2H copy + stream sync
```

sglang never passes `q_seq_lens_cpu` / `kv_seq_lens_cpu`, so every call blocks the host until the GPU drains, and the GPU then idles while the host relaunches. Both lengths already exist on the host: `extend_seq_lens_cpu` and `prefix_chunk_seq_lens_cpu`.

## Modifications

- `TRTLLMMLAPrefillMetadata.host_seq_lens`: an int32 CPU copy of `extend_seq_lens_cpu` and its sum, built once per forward. The prefix-chunk lengths and totals come from the existing `prefix_chunk_seq_lens_cpu` / `prefix_chunk_num_tokens` (None-checked).
- `_run_prefill_kernel` takes optional `q_seq_lens_cpu` / `kv_seq_lens_cpu` and forwards them to flashinfer. `TokenspeedMLABackend`'s override accepts them.
- Both ragged call sites go through `_host_seq_lens`, which passes the lengths only when they cover q/k exactly and no graph is being captured. Otherwise the stock call runs.

There is no new flag. flashinfer makes the same empty-row decision from the same values, so the same kernel launches on the same inputs.

## Accuracy Tests

DeepSeek-V2-Lite-Chat, `--attention-backend trtllm_mla --disable-prefill-cuda-graph`, which routes every extend through the ragged kernel. 2 boots per arm, 1×GB300.

| | main (2 boots) | this PR (2 boots) |
|---|---|---|
| GSM8K (1319 q, 5-shot) | 0.654 / 0.657 | 0.660 / 0.660 |
| greedy outputs, 32 prompts (short and 19.8k shared-prefix) | identical across all 6 boot pairs | identical across all 6 boot pairs |

**Profile** (same setup, 2 requests with a cached 19.8k prefix):

**bench_serving**, 1×GB300, one arm at a time in off/on/on/off order. Each cell lists the individual runs, then the change in means.

| workload | prefill graph | input tok/s: main → PR | mean TTFT (ms): main → PR |
|---|---|---|---|
| random-ids 8k in / 16 out, conc 8 | default | 77,721, 78,406 → 86,986, 84,415 (**+9.8%**) | 631, 617 → 493, 535 (**−17.6%**) |
| random-ids 32k in / 16 out, conc 4 | default | 54,521\*, 71,363 → 70,932, 74,409 (**+1.8%** vs the second main run) | 1,982\*, 1,416 → 1,326, 1,271 (**−8.3%**) |
| generated-shared-prefix 16k + 512, conc 16 | disabled | 205,567, 205,966 → 212,733, 211,137 (**+3.0%**) | 978, 982 → 965, 859 (**−7.0%**) |

\* The first long-prompt run after the pod started; it is an outlier and is excluded from the 32k means. In an earlier round of the same A/B, main read 69,263 and 72,701 tok/s on this workload.

With the default breakable prefill CUDA graph, extends of 2,048 tokens or fewer run in-graph, where trtllm_mla falls back to FlashInfer, so the change only affects longer (eager) prefills.

Tested on v0.5.21 (the `lmsysorg/sglang:v0.5.21-cu130` image; main needs sglang-kernel ≥ 0.4.9). The diff applies to v0.5.21 unchanged, and the code it touches is the same on main.
