# [CPU] Routes all_gather_into_tensor and reduce_scatter_tensor to shm kernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/41521) · state: open · merged: False

## Original PR description

## Motivation

#13397 added the CPU shm kernels `shm_allgather_into_tensor` and `shm_reduce_scatter_tensor` to sgl-kernel. #12961 routed CPU through `GroupCoordinator._all_gather_into_tensor` / `_reduce_scatter_tensor`, but left `TODO: add optimized ... kernel for cpu` and never called those kernels. So on CPU, the DP attention gather/scatter still went through `torch.distributed` (gloo).

This PR routes `all_gather_into_tensor` and `reduce_scatter_tensor` to shm kernels.

## Modifications

- `distributed/parallel_state.py`
  - `_all_gather_into_tensor`: on CPU, call `sgl_kernel.shm_allgather_into_tensor` when `is_shm_available(dtype, world_size, local_size)` holds.
  - `_reduce_scatter_tensor`: on CPU, call `sgl_kernel.shm_reduce_scatter_tensor(..., REDUCE_OP_SUM)` under the same condition.
  - Remove the two TODOs left by #12961.
  - If the condition does not hold (no AMX or arm64, dtype outside bf16/fp16/fp32, or multi-node), fall back to gloo as before.
- `model_executor/cpu_graph_runner.py`: register fake impls for both ops. They mutate `output` in place and return nothing, like `shm_allreduce`, so `--enable-torch-compile` works on CPU.
