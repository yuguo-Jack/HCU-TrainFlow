# [DSv4.1] Initialize the full-to-SWA mapping for request-window pools

[Upstream PR](https://github.com/sgl-project/sglang/pull/43165) · state: closed · merged: True

## Original PR description

## Motivation

```bash
python3 -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V4.1-Flash --trust-remote-code \
  --tp 4 --ep-size 4 --cuda-graph-backend-prefill disabled \
  --enable-encoder-swa-bounded-replay          # no --speculative-algorithm
```

Startup completes, then the first request (the warmup) fails:

```
File ".../layers/attention/deepseek_v4_backend.py", line 2457, in _build_sparse_prefill_chunk_cache
    full_to_swa=self.token_to_kv_pool.full_to_swa_index_mapping,
AttributeError: 'DeepSeekV4TokenToKVPool' object has no attribute 'full_to_swa_index_mapping'
```

Without speculative decoding the request-window target pool has no paged SWA allocator, so `register_mapping()` never runs, but the sparse-prefill path still reads the attribute. With a speculative algorithm the target keeps a paged SWA allocator for the draft layers, which hides the bug. The new unit test below hits the same error on current main.

This is the configuration where the flag frees the most KV memory: `max_total_num_tokens` is 64,858,624 with the flag vs 62,784,256 without (+3.3%).

## Modifications

`DeepSeekV4TokenToKVPool.__init__` sets `full_to_swa_index_mapping = None`. With a request window, `SparsePrefillChunkCache.build` takes its indices from the window layout and never reads the mapping. Paged pools still get the mapping from `register_mapping()`.

## Accuracy Tests

- `test/registered/unit/mem_cache/test_dsv4_compressed_pools.py::TestEncoderReplayWithoutSpeculation` (new) builds the pool and the sparse-prefill chunk cache without speculation. On main it fails with the same `AttributeError`; with this PR it passes. The whole file: 13 passed (17 subtests).
- Server with the flag and no speculation: a 6,144-token prompt sent twice hits 5,888 cached tokens on the second request, with 128 tokens replayed.

## Speed Tests and Profiling

No hot-path change.
