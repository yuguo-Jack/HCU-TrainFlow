# [AMD] Fuse Qwen3.8 GDN prefill prologue and MXFP4 output epilogue

[Upstream PR](https://github.com/sgl-project/sglang/pull/39912) · state: open · merged: False

## Original PR description

## Summary

- Fuse the Qwen3.8 TP1 GDN prefill producer’s causal Conv1D, state update, raw contiguous Q/K/V emission, and raw A/B to FP32 g/beta preparation on gfx950.
- Keep Q/K raw at the producer boundary and preserve the existing chunk scan’s `use_qk_l2norm_in_kernel=True` path for exact BF16 behavior.
- Fuse per-head gated RMSNorm with MXFP4 activation quantization before `out_proj`, supporting row-major EVEN output for Triton and native shuffled RoundUp output for the AITER ASM consumer.
- Keep both additions fail closed: unsupported architecture, topology, dtype, stride, execution mode, state layout, or quantization contract retains the existing path.

## Dependency and scope

This PR is stacked on [#39598](https://github.com/sgl-project/sglang/pull/39598), whose Quark AITER ASM FP4 GEMM input contract it extends.

The prefill producer targets Qwen3.8 TP1 GDN extend layers on gfx950 and is opt-in through `SGLANG_QWEN38_GDN_PREFILL_PROLOGUE_FUSION=1`. Decode, target verification, MIS, page-major state pools, DP padding, tracked-state batches, deterministic inference, and the model’s softmax-attention layers retain their existing paths.

The producer emits raw BF16 post-Conv Q/K because the existing scan’s Q/K L2Norm reduction order is part of the exact numerical contract. V, FP32 g/beta, Conv state updates, packed-varlen boundaries, initial-state behavior, scheduler tails, and scan normalization remain unchanged.

## Update: Conv1D bias is optional

Qwen3.8 checkpoints have no GDN Conv1D bias, so the earlier eligibility check rejected every real prefill and the fused producer never ran on the target model. The producer now accepts `bias=None` and selects the existing `HAS_BIAS=False` kernel variant, and rank 0 logs once whether the prologue is enabled, or why not. New tests: bias-free output is bit-exact against `causal_conv1d_fn`, and bias shape/dtype/stride mismatches are rejected.

A/B of this fix, MI355X TP1, `amd/Qwen3.8-27B-Quark-AWQ-MXFP4`, 5 serving rows, same image with and without it: throughput +0.43% geomean, TTFT −8.39% (8K c4 −34.6%), TPOT +0.18%. The performance sections below predate this fix and will be re-measured.

## Correctness

Exact HIP6 parity passes for dense and packed-varlen batches, one/four/sixteen sequences, 64-token and scheduler tails, initial and no-initial state, signed-zero and softplus-threshold gates, raw Q/K/V/g/beta boundaries, Conv state, scan output, recurrent-state updates, packed MXFP4 values, and valid E8M0 scales.

The focused producer test reports the first mismatching index, values, bit patterns, mismatch count, and maximum absolute difference so future compiler regressions localize to raw Conv output, gating, or the unchanged scan normalization boundary.

## Component accounting

The complete producer-plus-normalization boundary changes from 10 launches to 3 while retaining both existing Q/K L2Norm launches. It removes 82,304 semantic bytes and 41,152 allocation-volume bytes per token/layer.

Across 48 GDN layers at scheduler chunk 16,384, this removes 30.140625 GiB of semantic traffic and 336 launches at 8K, 220.756531 GiB and 1,344 launches at 60K, and 482.25 GiB and 2,688 launches at 128K.

## Focused performance

Measured on MI355X TP1 using the pinned image `amdsiloai/vllm-private:v0.5.19-rocm10-mi35x-20260909_qwen38_pr40410_39998_aiter5598_tritonci7cb7b059_20260920@sha256:5a6c954b1264cf750d9aca0b069a33b05c92365bd606025b6b96ecbeed560478`, fixed server arguments, FP8 KV cache, and 16,384-token chunked prefill.

The HIP7 component benchmark reduces prologue latency by 34–36% across `T={8192,10848,13312,16384}` and one/four/sixteen sequences. Launch profiling confirms the 10-to-3 boundary.

Two-direction HIP6/HIP7 serving crossover, reported as the symmetric geometric delta versus the same image with the existing output epilogue but without the new prefill producer:

- 8K input, concurrency 4: output throughput −0.08%; TTFT −3.45%.
- 60K input, concurrency 4: output throughput +1.21%; TTFT −2.54%.
- 60K input, concurrency 16: output throughput +1.96%; TTFT −2.47%.
- 128K input, concurrency 4: output throughput +1.03%; TTFT −1.82%.

The 8K output-throughput metric is decode dominated; the prefill-only optimization is visible in TTFT. Both directions improved 60K and 128K throughput.

Keep the producer opt-in and do not promote the candidate image as a default until these regressions are resolved and revalidated.
