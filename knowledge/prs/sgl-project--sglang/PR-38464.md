## Motivation

<!-- Describe the purpose and goals of this pull request. -->

NVIDIA Dynamo builds `ServerArgs.from_cli_args(...)`, then calls `model_config_of(server_args)` / `ModelConfig.from_server_args(...)` before creating `Engine`. General plugins loaded only through SGLang's launch entry points can miss that first model-config read.

For example, ModelExpress uses the `sglang.srt.plugins` entry-point group and `HookRegistry` to fetch model/config/tokenizer metadata from its server before SGLang reads files. These hooks must already be installed for workers without shared storage or direct Hugging Face access.

This is complementary to [sgl-project/sglang#26723](https://github.com/sgl-project/sglang/pull/26723): that proposal addresses startup plugins and subprocess bootstrap for early import-time compatibility shims; this change activates general plugins when constructing or reconstructing `ServerArgs`.

vLLM provides a precedent in `vllm/engine/arg_utils.py:EngineArgs.__post_init__`, which calls `load_general_plugins()`.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Add one idempotent `load_plugins()` call in `ServerArgs.__post_init__`, using the loader's existing process-local `_plugins_loaded` guard.
- Rely on the existing constructor-based `_rebuild_server_args`: pickle and deepcopy reconstruction invoke `__post_init__`, so spawned workers receiving `ServerArgs` also load their own plugins before model/config/tokenizer reads.
- Keep SGLang's own launch paths and the plugin-loader implementation unchanged. No additional child-entry calls or engine reordering are needed.
- Keep the construction test covering hook application and repeated-construction idempotence. Replace the mock-only detokenizer test with real entry-point discovery during unpickling in a fresh interpreter: no marker before unpickling, then a marker containing the child's PID immediately afterward.
- Document general-plugin activation on construction and reconstruction.
