# [Memory] Share one full prefill graph output buffer across shapes for tuple and list outputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/43176) · state: closed · merged: True

## Original PR description

## Motivation

`FullCudaGraphBackend(reuse_output_buffer=True)` lets every captured prefill shape return its output through one shared buffer, so the eager tail reads each shape's output from the same storage instead of keeping one output allocation per graph in the graph pool.

That only worked when the model forward returned a single tensor. A model whose forward returns a tuple or list of per-token tensors made `_allocate_output_buffer` return `None`, which silently turned sharing off and left every captured shape holding its own output allocation.

## Modifications

- `_allocate_output_buffer`, `_output_fits_buffer` and `_copy_output_to_buffer` in `python/sglang/srt/model_executor/runner_backend/full_cuda_graph_backend.py` now handle a tensor or a (nested) list/tuple of row-major tensors. The shared buffer mirrors the output's structure, and each capture gets back the same structure of buffer views.
- Anything without a shareable form keeps independent storage exactly as before: a zero-dim or non-tensor leaf disables sharing, and a later output whose structure, shape, dtype or device does not match the buffer is kept as-is and switches sharing off for the rest of the capture.
- `test/registered/unit/model_executor/runner_backend/test_full_cuda_graph_backend.py` (CPU-only, `base-a-test-cpu`) gains two cases: a tuple output shares one buffer per leaf across shapes while a mismatched later output keeps its own storage, and a tuple with a scalar leaf falls back to independent storage. The first case fails on the previous code (`_output_buffer` stays `None`) and passes with this change.

## Accuracy Tests

Not applicable: the shared buffer is filled by `copy_` from the captured output, so the values each shape returns are unchanged. The unit tests assert both value equality and storage sharing.

## Speed Tests and Profiling

No kernel or scheduling change. The effect is on graph-pool memory for models with tuple/list outputs, which now reuse one output buffer across prefill shapes as single-tensor outputs already do.
