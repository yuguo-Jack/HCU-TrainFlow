# [DSpark][NPU] Fix attn_tp > 1 draft wo_b all_reduce group

## Motivation
DSpark speculative decoding with a DeepSeek-V4 (MoE) draft supports DP attention
(`attn_tp_size < tp_size`) on Ascend NPU, but the draft attention's output
projection `wo_b` reduced its partial results over the wrong process group,
which corrupted the draft output and collapsed the accept rate to ~0.

`DSparkAttention` (`python/sglang/srt/models/deepseek_v4_dspark.py`) subclasses
`MqaAttentionBase` and hard-codes `wo_b_reduce_results=True`, overriding the
base's default `reduce_results = (attn_tp_size == tp_size and attn_tp_size > 1)`.
As a result, under DP attention (`attn_tp_size < tp_size`) `wo_b` still performed
a row-parallel all-reduce, but over the **full DP × TP** group, while its weight
is sharded over the **attn-TP** group only. That summed partial outputs that
belong to different DP ranks' _different_ batches, so the draft attention output
was garbage and the accept rate collapsed to ~0.

A guard in `DSparkWorkerV2` rejected this whole configuration
(`attn_tp > 1` + DP attention + MoE draft), which blocked the feature on NPU.

(Note: the guard's error string referred to the "MoE-under-DP all-reduce", but
the actual corruption was the draft attention's `wo_b` reduce group; the draft
MoE path itself handles `attn_tp > 1` via `_dp_gather_via_all_gather`.)

## Modifications

1. `python/sglang/srt/models/deepseek_v4.py`
   - `MqaAttentionBase.wo_b` now passes
     `use_dp_attention_reduce=is_dp_attention_enabled()`, so its row-parallel
     all-reduce runs over the attn-TP group (`get_parallel().attn_tp_group`)
     when DP attention is enabled, matching the weight sharding.
   - `DSparkAttention.forward` calls `self.wo_b(...)` directly (it does not use
     `_project_wo_b`), so this single flag fixes the draft reduce with no
     double-reduce.

2. `python/sglang/srt/speculative/dspark_components/dspark_worker_v2.py`
   - Allow the `attn_tp > 1` MoE-draft + DP-attention configuration on NPU by
     adding `and not _is_npu` to the guard. CUDA/ROCm still reject it.

3. `python/sglang/srt/hardware_backend/npu/attention/ascend_dsv4_backend.py`
   - Pad the draft `ori_sparse_indices` tail with `-1` ("skip") up to the
     attn-TP-padded token count, matching `out_cache_loc`
     (`prepare_mlp_sync_batch` pads the query to an attn_tp multiple, but
     `seq_lens` is not).
