# [AMD] Refuse RCCL all-reduce in deterministic mode above TP2

[Upstream PR](https://github.com/sgl-project/sglang/pull/43809) · state: open · merged: False

## Original PR description

## Motivation

This PR makes `--enable-deterministic-inference` on ROCm refuse `--disable-custom-all-reduce` when `--tp-size` is above 2. That combination sends every tensor-parallel all-reduce through RCCL, which is not batch-invariant at four or more ranks: the server starts normally, but a request's output depends on what else is in its batch.

On ROCm, deterministic mode relies on SGLang's one-stage custom all-reduce, in which every rank reduces all inputs in a fixed order. CUDA instead disables the custom all-reduce and pins NCCL (tree algorithm, fixed channel count); ROCm has no such pinning, and pinning RCCL's algorithm and protocol (`NCCL_ALGO=Ring NCCL_PROTO=Simple`) does not make it batch-invariant either (results below). At TP2 each output element is the sum of two operands, which has only one order, and RCCL passes every check there, so TP2 stays allowed.

Impact: only ROCm users who pass both flags with `--tp-size` above 2. They now get a startup error instead of silently batch-dependent results; dropping `--disable-custom-all-reduce` fixes it.

## Modifications

- `arg_groups/overrides.py`: a validation pass, `_deterministic_rocm_rccl_check`, raises a `ValueError` for deterministic mode + ROCm + `tp_size > 2` + `disable_custom_all_reduce`.
- `arg_groups/attention_hook.py`: runs it in the ROCm branch of the existing tensor-parallel check in `handle_deterministic_inference`.
- `test/registered/unit/test_model_overrides.py`: two CPU cases. One for the refusal; one for the setups it must leave alone (CUDA, deterministic mode off, TP2, custom all-reduce on).
- Unchanged: deterministic mode without the flag, TP1 and TP2, CUDA, and everything without `--enable-deterministic-inference`.

Independent of #34543, which makes the custom all-reduce itself batch-invariant for inputs larger than its buffer.

## Accuracy Tests

**Why RCCL is refused.** Qwen3-8B, BF16, `SGLANG_USE_AITER=0 python3 -m sglang.launch_server --model-path Qwen/Qwen3-8B --tp <N> --attention-backend triton --enable-deterministic-inference --disable-custom-all-reduce`, `rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261006`. Checks: `python3 -m sglang.test.test_deterministic --test-mode prefix --return-logprob` and `--test-mode radix_cache` (50 trials), plus a bitwise comparison of 1,275 responses (batch sizes 1-50) against batch size 1.

| RCCL setting | GPU | TP2 | TP4 | TP8 |
| --- | --- | --- | --- | --- |
| default | MI350X | pass all | fail all | - |
| default | MI355X | pass all | fail all (81/1275 bitwise-identical) | - |
| `NCCL_ALGO=Ring NCCL_PROTO=Simple` | MI355X | pass all | fail all (347/1275) | fail all (121/1275) |

**This PR.** MI350X, `rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261011`, the image's files before and with this change.

| Deterministic, `--attention-backend triton` | Before | After |
| --- | --- | --- |
| TP2, TP4, TP8 | accepted | accepted |
| TP2 + `--disable-custom-all-reduce` | accepted | accepted; the server starts and generates |
| TP4 or TP8 + `--disable-custom-all-reduce` | accepted | `ValueError` at startup |

- Checked with `ServerArgs.resolve_once()` for all six combinations, and with `launch_server` for TP2 and TP4.
- The new test cases pass, and every other test in `test_model_overrides.py` has the same outcome with and without this PR.
