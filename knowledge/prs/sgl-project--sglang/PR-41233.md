# [Fix] Disable the GLM47 tool grammar for tool_choice="none"

[Upstream PR](https://github.com/sgl-project/sglang/pull/41233) · state: open · merged: False

## Original PR description

## Motivation

With `--tool-call-parser glm47`, a request that supplies tools but explicitly sets `tool_choice="none"` still receives the GLM47 `full_assistant_ebnf` grammar.

That grammar describes a complete assistant turn. Reaching its terminal state finishes generation through the grammar path, which does not consult `ignore_eos`. An `ignore_eos=true` request can therefore stop at the model's end-of-turn token instead of reaching `max_tokens`, even though the request disabled tool calls.

### Behavior scope

| Request | Expected behavior | Ownership |
|---|---|---|
| No `tools` | Do not install the GLM47 tool-call grammar | Already fixed and tested by #39273 |
| `tools` + `tool_choice="none"` | Do not install the GLM47 tool-call grammar | Core fix in this PR |
| `tools` + `tool_choice="auto"` | Preserve the existing GLM47 grammar behavior | Regression coverage |
| `tools` + `tool_choice="required"` | Preserve the existing behavior | Regression coverage |
| `tools` + named tool choice | Preserve named-tool selection semantics | Regression coverage |
| Tools on `system`/`developer` messages | Include them in the active GLM47 grammar | Adjacent consistency fix requested during review |

### Relationship to #39273

The original version of this PR covered two cases:

1. requests with no tools; and
2. requests with tools plus `tool_choice="none"`.

While this PR was under review, #39273 independently added the `bool(effective_tools)` guard and a no-tools regression test as part of its GLM-5.3 work. Commit `f17f7705a5a67c137edf279edfdbd5460f2ceb6e` therefore already fixed case 1.

This branch was subsequently rebased onto main commit `4b384df0c94dbd0fe30627c27c98c0441b4ebd96`, which contains #39273. The duplicated no-tools production change and duplicated test were removed. The remaining core fix in this PR is case 2: tools are available, but the request explicitly disables tool calls with `tool_choice="none"`.

The no-tools history is retained here so reports that found the original analysis through this PR can follow that part of the fix to #39273.

## Modifications

Scope the GLM47 grammar to requests that provide tools and allow tool calls:

```python
glm_constraint = (
    self.tool_call_parser == "glm47"
    and bool(effective_tools)
    and request.tool_choice != "none"
    and not any(tool.function.strict for tool in effective_tools)
)
```

`auto`, `required`, and named-tool choices retain their existing grammar behavior. Other tool-call parsers are unchanged.

### Message-scoped tool consistency

`_effective_tools(request)` includes tools declared on `system` and `developer` messages. That effective set decides whether the GLM47 grammar is active, but the parser previously received only top-level `request.tools`. A request with message-scoped tools could therefore activate a grammar that omitted those functions.

The GLM47 parser now receives `effective_tools`. The regression test uses the real XGrammar parser and verifies message-scoped tools for `auto`, `required`, and named-tool choices, as well as the disabled `none` case.

### Test cleanup

- Keep the existing #39273 no-tools regression test.
- Remove the combined mocked no-tools/none test, which duplicated #39273 and the retained real-parser matrix.
- Remove the mocked auto test, which passed before this fix and only checked mock-result propagation.

Deliberately not changed:

- GLM47 grammar generation or grammar-terminal finish handling.
- Generic Jinja rendering of message-scoped tools, which affects multiple model families and needs separate cross-model coverage.
- Template compatibility for the `developer` role.
