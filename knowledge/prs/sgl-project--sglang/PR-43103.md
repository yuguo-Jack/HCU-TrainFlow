# [AMD] [Fix] Skip Flux2 residual_gate_add PTX on ROCm to enable flux.2 on MI355

[Upstream PR](https://github.com/sgl-project/sglang/pull/43103) · state: closed · merged: False

## Original PR description

## Motivation

FLUX.2 on MI355 aborts during the first compiled DiT forward. `residual_gate_add` takes the CUDA Triton fast path because `tensor.is_cuda` is true under HIP. That kernel emits PTX `cvt.rn.bf16.f32` with the CUDA register constraint `=h`. ROCm LLVM treats the constraint as a fatal register-allocation error (`couldn't allocate output register for constraint 'h'`) and kills the diffusion worker before the eager fallback can run. Wan2.2 does not call this kernel, so the same launch script succeeds there.

`main` already skips the path when `torch.version.hip` is set. This change uses the diffusion platform predicate `is_hip()` instead, which is the same check neighboring ROCm kernels use. On NVIDIA, `is_hip()` is false, so the CUDA fast path is unchanged.

## Modifications

- `can_use_residual_gate_add_cuda` returns false when `is_hip()` is true, so Flux2 uses eager `residual + update * gate` on ROCm.
- Added `test/registered/unit/kernels/test_residual_gate_add_hip.py`, registered in CPU CI (`base-a-test-cpu`). One test asserts the CUDA fast path is rejected on HIP. The other asserts `residual_gate_add` matches the eager formula.

## Accuracy Tests

The HIP fallback is eager `residual + update * gate`. Measured max absolute error against that formula:

| Check | Shape | Dtype | Max abs error |
| --- | --- | --- | --- |
| GPU, MI355 | [1, 128, 6144] | bf16 | 0.0 |
| CPU unit test | [2, 8] | fp16 | 0 (`assert_close`) |

FLUX.2-dev text-to-image at 720p, 8 steps, seed 42, completed and wrote a 1280×720 PNG. The previous run died in kernel compilation and produced no image.

## Benchmarking and Profiling

Same command as the crash, after the guard. One MI355 GPU, `--enable-torch-compile`, `--warmup-mode request`, `--dit-layerwise-offload`.

| Segment | Time |
| --- | --- |
| Full generate, including torch.compile | 176.36 s |
| Request, warmup excluded | 5.00 s |
| Denoising, 8 steps | 4.87 s (0.078 s/step) |
| VAE decode | 0.0049 s |
| Peak memory | 108274 MB |

There is no before-latency. The unguarded PTX path aborts the worker.
