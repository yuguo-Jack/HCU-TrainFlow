# [sgl-router] Render GLM-5.3 and GLM-5.3-Flash through sglang-processor

[Upstream PR](https://github.com/sgl-project/sglang/pull/43625) · state: open · merged: False

## Original PR description

> [!NOTE]
> **Stack 1/3**, merge in order: #43625 (GLM-5.3) → #43608 (Kimi-K3) → #43689 (Qwen3.8). This PR is based on `main`.

Adds GLM-5.3 and GLM-5.3-Flash to sglang-processor. The router renders them, so every text chat forwards the `input_ids` SGLang would build, and chats without tools are served through the engine's `/generate`. Follows #43000.

## Modifications

- **Render** (`render/models/glm53.rs`): picked by the template, as `_is_glm53` does. It builds the template context SGLang's Jinja path builds (Pydantic dumps of messages, history tool calls and tools, `_validate_request`'s schema-type rewrite, kwargs over effort and server defaults) and renders it with Dynamo's Jinja formatter.
- **Left to the engine:** media, a `chat_template` kwarg, `-0`, and U+001C..U+001F in assistant content (until ai-dynamo/frontend-crates#395). Kwargs SGLang rejects (`apply_chat_template`'s own arguments, invalid `documents`) are rejected here too.
- **`/generate`:** ports the `glm45` reasoning parser, adds `ChatModel.always_thinks`, and accepts assistant thinking and `tool_reference` parts. With `glm47`, chats with tools stay on the engine's route, still with router `input_ids`. **`/generate` must accept `ebnf_full_assistant` before tool requests can go through the `/generate` path**; SGLang constrains them with a grammar flagged that way.
- **Also:**
  - dynamo-renderer 7.0.1 → 7.1.1, for Python floats in `tojson`.
  - The schema-type rewrite also fixes DeepSeek-V4/V4.1.
  - The fixture generators run `_validate_request` and load a Jinja checkpoint's `TemplateManager`.
  - The `processor-model-parity` skill now states the goal: all text works, and chat and completions go through `/generate`.

## Checks

- **Render:** 112 cases per checkpoint (`GLM-5.3@aca966e`, `GLM-5.3-Flash@eb9eb20`), generated with transformers 5.19.0. Each matches SGLang's prompt text and token ids or is rejected as SGLang rejects it, except 3 known gaps left to the engine. The DeepSeek fixtures still pass with token ids.
- **OpenAI layer:** `openai_parity/glm-5.3.json` (SGLang's handler on hand-written GLM outputs) and `reasoning_parity/glm45.json`.
- **Real weights:** GLM-5.3-Flash on 8×B300 with the cookbook's FP8 low-latency recipe and the real router:
  - **`/generate`:** 20 chats. The engine logged the same `GenerateReqInput` for each as when sent directly, and the responses are identical, except two cases that vary between direct runs too (sampling, a 9.8k-token prompt).
  - **Engine route:** 6 chats with tools; the responses are identical.
  - **Also identical:** the image chat and the completion.
- `cargo test`, `clippy -D warnings` and the pre-commit hooks pass.
