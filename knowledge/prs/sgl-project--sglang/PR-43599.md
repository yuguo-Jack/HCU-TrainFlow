# [Spec] Kimi-K3 EAGLE3 MLA draft under DCP + HiCache: draft routing, aux capture, physical draft KV pools

[Upstream PR](https://github.com/sgl-project/sglang/pull/43599) · state: open · merged: False

## Original PR description

## Motivation

EAGLE3 with an MLA draft (e.g. [lightseekorg/kimi-k3-eagle3.1-mla](https://huggingface.co/lightseekorg/kimi-k3-eagle3.1-mla)) on Kimi-K3 does not run under decode context parallelism (DCP) + HiCache on main, and once it is made to run, two problems in the draft KV pools show up:

1. **The draft pools are 8x larger than what can ever be written.** Under DCP the MLA draft writes and reads owner rows at `loc // dcp_size`, but both its device pool and its HiCache host sidecar are sized at the logical token count (physical rows x dcp_size). On TP8/DCP8 with `--hicache-size 100`, the draft used 9.95 GiB of device memory and 27.84 GB of host memory per rank, and only about 1/8 of that could ever be written.
2. **Host-tier restores put draft KV in the wrong rows.** The draft host sidecar was built without `dcp_size`, so its L2 transfer copied raw widened rows (`loc`), while draft attention reads `loc // dcp_size`. After a prefix was evicted to host and hit again, the draft read stale rows. The output is still correct because target verification catches it, but the accept length drops: 2.06 -> 1.45 in the measurement below.

Beyond the pools, the series covers what a K3 EAGLE3-MLA deployment under DCP needs end to end: the default attention mode for EAGLE3 target-verify / draft-extend under DCP, the draft loader's extra config, the PD transfer layout of a physical MLA draft pool, EAGLE3 aux capture on a pipelined (PP) prefill, two blockers for a TP1 pipelined K3 prefill, and a KDA prefill dispatch fix for packed one-token batches (#43615; the same fix is proposed standalone in #43629).

## Modifications

1. **attention: run an EAGLE3 MLA draft under DCP and on a pipelined K3 prefill** (core routing from 602578ab49 on `yanbo/pd-k3-rebase-0919` by @yhyang201, plus the K3 override). `draft_extend_v2` joins the DCP MLA decode phase; cutedsl_mla gets a real draft prefill backend; trtllm_mla handles DCP for any dense draft window (fp8 KV on draft-extend too), refuses a padded window, and picks the cute-dsl runner for `64 < q_heads < 128` (a TP1 K3 stage) where trtllm-gen has no MLA decode kernel; the eager runner skips the prefill DCP gather for MLA target verify; the K3 override forces `speculative_attention_mode=decode` for EAGLE3 as for DSPARK. Unit test: EAGLE3 under DCP resolves to the decode mode.
2. **kimi_k3: EAGLE3 aux capture, including across pipeline stages** (port of 51010f6085 onto the current `residual_batch` / `attn_bank` forward). `capture_layer_ids` gives DSPARK and EAGLE3 one shared index set; on the bank path EAGLE3 snapshots the plain prefix stream while DSPARK keeps the AttnRes aggregate; captures are banked per PP stage and forwarded on the PP proxy; the validation hook admits EAGLE3 behind a PD prefill like DSPARK. Unit tests: id mapping, EAGLE3 bank path, PP proxy sizing.
3. **hicache/dcp: size the MLA draft KV pool and its host sidecar in physical rows.** `KVCacheConfigurator.draft_mla_rows_are_physical` names the case; `loc_space_scale` and the unified-allocator draft override keep physical rows; the host sidecar gets `dcp_size`/`dcp_rank` with a physical/physical ratio; the HiCache+DCP gate admits EAGLE3; `topk > 1` with an MLA draft under DCP raises. MHA drafts unchanged (`test_dcp_logical_capacity.py` fixture updated and asserts MLA-physical vs MHA-logical capacities).
4. **model loader: draft load format and the PP draft embedding re-open.** `--model-loader-extra-config` reaches the draft only when its resolved load format equals the target's; the PP draft embedding re-opens a runai_streamer target that is a local safetensors directory with AUTO and no extra config.
5. **disaggregation: transfer a DCP-collapsed MLA draft pool with the target's row mapping.** `KVCache.rows_are_dcp_collapsed` names the layout, the decode registers it (one trailing frame on the Mooncake and NIXL registration messages; absent means the old layout), and the DCP transfer plan maps a collapsed draft with the target's owner rows and a physical-page item length. Unit test.
6. **kda: keep packed one-token prefill batches off the FlashInfer recurrent kernel** (#43615; the same routing is proposed standalone in #43629). `num_tokens <= num_sequences` batches go to the Triton kernel; the tracked-state check asks the dispatcher with the same sequence count. GPU regression cases `(1,1)` / `(2,0)` with an FP32-state assertion.
7. **hicache: let later PP stages consume PP0's ack counts as their queues fill.** PP1+ pop exactly the number of completed acks PP0 reports, from queues that fill only when a batch reaches the stage; under a burst of prefix hits PP0's count ran ahead and `ack_load_queue.pop(0)` raised IndexError on a PP8 prefill at 32-48 concurrency (every run, until this change). The surplus is carried to the next check; write acks the same. Unit test (fails on the pre-change tree with the IndexError).

## Accuracy Tests

Setup: Kimi-K3 + kimi-k3-eagle3.1-mla on GB300, TP8 / DCP8, HiCache `--hicache-size 100`, EAGLE3 steps 3 / topk 1 / draft tokens 4; target via runai_streamer, draft via `auto`. The "after" numbers are from this branch on main (also identical on a v0.5.21 backport with byte-identical hunks); the "before" numbers from that backport with commits 1-3 only.

Per-rank pools (unified 2-node service):

| pool | before | after |
|---|---|---|
| draft device KV | 9,273,856 rows / 9.95 GiB | 1,159,232 rows / 1.24 GiB (= target rows) |
| draft host sidecar | 24,162,816 / 27.84 GB | 3,020,352 / 3.48 GB |
| target device / host KV | unchanged | unchanged |

Host-tier restore check (15.4k-token prompt, evicted by 70 x 17.6k prompts, recalled from host with cached_tokens 15,360):

| | anchor accept_length | recall accept_length |
|---|---|---|
| before (commits 1-3 only) | 2.06 | **1.45** |
| after | 2.37 | **2.37** (same verify_ct) |

DSpark regression (v0.5.21 backport, same commit-4 hunks): draft pools unchanged (5,513,216 device rows, 55.32 GB host per rank), no configurator assert.

PD disaggregation (EAS LLMGateway, sglang-mooncake, 1P1D, 2 nodes per role, decode TP8+DCP8 with the EAGLE3 draft, `--max-running-requests 16`), measured after a warm-up (the first request after boot pays Mooncake buffer and RDMA setup, 40-80 s), per prefill layout: single-stream TTFT and prefill throughput on unique prompts with `max_new_tokens=1`; GSM8K (100 questions, 8-shot, greedy, every record checked: all 100 reached the model and all 100 were correct for every layout with EAGLE3 on both sides); and a closed-loop mixed load (50% short, 20% 4k, 30% 17.6k prompts from a 120-document pool) at 1/4/8/16/32/48 concurrency, 120-180 s per stage, 0 failed requests in every stage below.

| P / D | single TTFT 2.4k / 9.4k / 16.4k tok | prefill tok/s, 16 conc, 2.4k / 9.4k / 16.4k | mixed load tok/s at 1 / 16 / 32 / 48 conc | p50 at 32 conc | accept (32 conc) |
|---|---|---|---|---|---|
| TP8 / TP8+DCP8 | 0.57 / 0.82 / 1.21 s | 21.3k / 23.0k / 22.6k | 101 / 839 / 1,127 / 1,117 | 5.5 s | 2.81 |
| TP8 / TP8 (no DCP) | 0.57 / 0.82 / 1.21 s | 21.3k / 23.0k / 22.6k | 99 / 816 / 1,101 / 1,110 | 5.6 s | 2.83 |
| TP4+PP2 / TP8+DCP8 | 0.57 / 0.99 / 1.58 s | 19.7k / 28.7k / 28.6k | 89 / 842 / 1,148 / 1,135 | 5.3 s | 2.74 |
| PP8 / TP8+DCP8 | 0.96 / 1.89 / 2.85 s | 21.3k / 26.3k / 38.6k | 71 / 628 / 969 / 951 | 6.3 s | 2.76 |
| PP8 **without** EAGLE3 / TP8+DCP8 | - | 21.1k / 28.6k / 41.4k | 63 / 536 / - / - | - | 2.03 (GSM8K accept 1.98) |

Accept lengths are the same within 0.1 across the layouts with EAGLE3 on both sides, so the DCP8 decode draft reads the KV that a TP8, TP4+PP2 or PP8 prefill transferred into the collapsed pool, and the PP prefill's cross-stage capture matches TP8. DCP8 costs nothing against plain TP8 in this context range (<= 17.6k) at batch <= 16. The mixed load saturates the decode at 32 concurrency; the PP8 prefill wins only when the prefill itself is the bottleneck (16 x 16k prompts: 38.6k vs 22.6k tok/s) and loses 15% on the mixed load because a single long prefill occupies the pipeline (TTFT 2.4x TP8). A prefill without the draft leaves the decode draft with no prompt KV and no aux hidden state (accept 3.5 -> 2.0 on GSM8K, 2.6 -> 1.5 on 12k prompts) and does not prefill faster. Decode with attention DP does not fit K3's weights on a 288 GB GB300 (255.9 GB per GPU at attn-dp 8).

## Speed Tests and Profiling

No kernel changes. Per rank under DCP8 the series frees about 8.7 GiB of device memory and about 24 GB of host memory that the draft pools reserved but could never use.
