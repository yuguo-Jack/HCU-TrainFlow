# [Fix] Load compressed-tensors NVFP4 KV calibration with matched cache format

[Upstream PR](https://github.com/sgl-project/sglang/pull/43510) · state: open · merged: False

## Original PR description

## Motivation

Calibrated compressed-tensors NVFP4 checkpoints declare a static symmetric per-tensor float4 KV scheme. SGLang currently recognizes only float8, so it skips creating the KV scale parameters and discards calibrated checkpoint scales. This affects checkpoint scale loading independently of the selected attention backend.

Validated functional head `bcf389e43c4202d2bb129404eaaf53f65a59f449` (subsequent commit `faed03c92a` adjusts formatting for Python 3.12 CI only), based on main `6e8f3e09dd03a95e9a903d940427d007427bff47`.

## Modifications

- Accept static symmetric per-tensor float4 alongside existing float8 KV calibration. Dynamic, asymmetric and per-head/per-channel schemes remain unsupported.
- Reuse existing scalar parameter creation, checkpoint name remapping, singleton-tensor weight loading and post-load handling.
- Report the float4 scheme as `NVFP4`, preserving float8's `FP8` identity. This prevents four-bit calibration from accidentally selecting an FP8 cache through the existing auto resolver. NVFP4 cache/backend selection remains manual; use explicit `--kv-cache-dtype nvfp4` with a supported attention configuration.
- Reject a mismatched effective recipe or final cache dtype after draft overrides and DFLASH/FA4 fallback. NVFP4 calibration with auto/BF16/FP8 or the distinct MXFP4 recipe must not silently rescale ordinary attention. BF16/FP8 controls require a metadata/scales-free checkpoint overlay that preserves the model weights.
- Extend the existing CPU regression suite. No backend, quantization kernel, warmup calibration or scale-sharing logic changes.

## Accuracy Tests

The unchanged production code fails two initial regression checks: it provides no float4 KV method and no NVFP4 calibration identity. Final candidate results: **10 tests and 12 subtests pass**, including scalar scale retention through the real name remapper and singleton-tensor loader, unchanged float8 behavior, unsupported-scheme rejection, effective cache-dtype mismatches and draft/DFLASH overrides.

Pinned isolated environment: Torch 2.14.1, FlashInfer 0.7.0.post1, Transformers 5.19.0, compressed-tensors 0.18.0, pytest 9.1.1. CPU-only command:

```bash
CUDA_VISIBLE_DEVICES=99 PYTHONPATH=python \
  ~/sglang-stage1-20261010/venv/bin/python -m pytest \
  test/registered/unit/layers/quantization/test_compressed_tensors_kv_cache.py -q
```

There were 21 warnings, including an unknown `asyncio_mode` configuration option in the probe environment. Full configured scoped pre-commit checks and `git diff --check` passed. These tests establish scale-loading contracts, not generation quality.

CPU checkpoint integration instantiated all 35 actual `Gemma4Attention` modules on meta and loaded 30 real checkpoint scalar tensors into their CPU `RadixAttention` parameters through the normal remapper/loader. The fixture was `gemma-4-E2B-it-NVFP4KV`, config SHA256 `f7ec28f96e58d148e8474834c55f625b0b7750cc224bb6a74a804e3fe92a6c16`. Both integration arms use the loader at `e0f9675741`; the subsequent recipe-guard amendment is covered by the final unit run above. With the separate writer-ownership fix [#43509](https://github.com/sgl-project/sglang/pull/43509) (`4025d6b`), all 20 shared readers and both pool scale tensors match writer-only controls; without that fix, 0/20 readers match. This verifies checkpoint scalar plumbing and distinguishes the separate sharing prerequisite. It does not run model forwards, load all model weights, start a server or establish generation quality.
