# [Unified Cache][UMBP] Support DeepSeek-V4.1 and packed draft layers in the UMBP direct linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/42197) · state: open · merged: False

## Original PR description

## Motivation

The UMBP direct linker fails at startup for DeepSeek-V4.1 + DSpark:

1. V4.1 has only ratio-1/2 compressed layers, so `c4_kv_pool` / `c128_kv_pool` are `None`, and `_build_deepseek_v4_device_pool_group` crashes with `AttributeError: 'NoneType' object has no attribute 'kv_buffer'`. The linker also never registers the V4.1 C1/C2 pools, which only HiCache ships.
2. The UMBP linker (#37578) predates packed draft layers (`(target, draft)` tuples, #37914) and assumes one buffer per layer, so they are rejected: `UMBP pool swa has 43 buffers per component but 40 mapped layers`.

## Modifications

- Build the C4/C128 linker entries only when the model has those layers. Register the C1/C2 KV and indexer pools via `_dsv4_low_ratio_regions`, shared with HiCache.
- UMBP linker: move a draft buffer together with its target layer. Emit packed-object ranges in offset order.

## Accuracy Tests

DeepSeek-V4.1-Flash, MI355X, TP4, DSpark, `lmsysorg/sglang-rocm:v0.5.21-rocm724-mi35x-20261001` + this PR:

| | Result |
|---|---|
| 110K-token needle, sglang restarted against the same UMBP server (prefix fully restored from UMBP) | correct, greedy output identical to the cold run |
| Same, without the C1/C2 entries (control) | wrong output |
| GSM8K 5-shot, 400 questions, cold / after `flush_cache` | 0.910 / 0.900 (no offload: 0.900) |

## Speed Tests and Profiling

AgentX: InferenceX aiperf trace replay (`semianalysis_cc_traces_weka_062126`), 1800 s measurement after warmup, one fresh server per point. Same model, image and flags as above; TP4, so each instance uses 4 GPUs. No request errors in any run. "Prefix hit" is the server-side cached-token ratio over the measurement window.

### Takeaways

- Under the cap, the linker restores 95-97% of prefix tokens, versus 51-55% for HiCache + UMBP L3 at c64/c128. That gives 4.45x the throughput of no offload at c64, and 3.5x that of HiCache + UMBP L3.
- With full HBM the linker still raises the prefix hit: 78% -> 96% at c64 and 67% -> 95% at c128. That is 2.46x / 4.07x throughput, TTFT p90 20.6 -> 3.2 s / 26.8 -> 3.1 s, and TPOT p50 29.9 -> 15.1 ms / 184 -> 42 ms.
- Capped linker runs have a high TTFT p50 because the 3.1M-token GPU pool is full and requests queue for KV space. Full HBM removes that.
- At c16 the working set mostly fits on the GPU, so the gain is mainly tail latency (TTFT p90 ~5 s -> ~1 s).
- DSpark acceptance length stays at 3.4-3.5 in every arm.
