# Time out decode preallocation waits and clear stale lifecycle state

[Upstream PR](https://github.com/sgl-project/sglang/pull/38164) · state: open · merged: False

## Original PR description

## Motivation

With prefill and decode served by separate workers, a decode request can wait indefinitely before KV-cache allocation because its receive timeout does not start until transfer metadata is sent. Starting the waiting deadline at the first receiver poll lets participating ranks agree on failure before allocation or transfer proceeds.

An emptied prefill-only batch also retains its prefill-only flag, and pending health-check signals are returned only one per scheduler pass. This PR clears that stale batch state and drains the pending signals.

The chunk-budget admission changes previously included here are removed in favor of #35645, which addresses #35642. That work is maintained by @imReese with regression tests contributed by @Kangwenqiao.

## Modifications

- Start the waiting deadline before allocation and report expiry through receiver polling before the existing rank consensus. The preallocation wait is tracked in its own field, so `init_time` still marks metadata publication. Abort notification relies on `init_time` to decide whether to arm deferred KV release, and preallocation-queue cleanup never clears that state, so a request aborted or timed out before publication must not arm it. Metadata submission starts a fresh transfer deadline.
- Clear the prefill-only flag when filtering empties a batch.
- Return all pending health-check signals in the scheduler pass.

## Accuracy Tests

92 CPU tests and 6 subtests passed across the five changed test files. The timeout regression uses two Gloo ranks with the real receiver poll/consensus path and mocked clocks/transport status; both ranks report failure when only one reaches the deadline. Two regressions abort or time out a receiver after a preallocation poll with deferred release enabled and assert that no deferred-release state is left behind; both fail if the preallocation deadline is stored in `init_time`. Other cases cover batch flags, receiver lifecycle and health signals. Live disaggregated GPU transport has not been tested.
