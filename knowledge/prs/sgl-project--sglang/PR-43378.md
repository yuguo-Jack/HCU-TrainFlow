# fix: propagate data-parallel scheduler startup errors

[Upstream PR](https://github.com/sgl-project/sglang/pull/43378) · state: open · merged: False

## Original PR description

## Motivation

If `launch_tensor_parallel_group` raises in a DP launcher thread, that thread exits before setting its readiness event. The controller then waits indefinitely instead of reaching its existing startup-error handling.

## Modifications

- Report each launcher's success or exception through a completion queue.
- Raise on the first reported failure, preserving the DP rank and original exception. A later rank's failure no longer waits for an earlier rank to finish loading.
- Keep successful launcher threads alive as before, preserving the scheduler's parent-thread lifetime requirement.
- Add regressions for failure reporting, a later-rank failure while an earlier rank is blocked, and successful startup.
