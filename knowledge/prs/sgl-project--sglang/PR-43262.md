Unfortunately yes, for now. The kernel scores the whole token block and checks `isfinite` on every row [before](https://github.com/sgl-project/DeepGEMM/blob/cbe1727eacd9ad704795584ce1421dd1f5a8d67e/deep_gemm/include/deep_gemm/impls/sm100_bf16_mega_gate.cuh#L286-L296) it looks at the [mask](https://github.com/sgl-project/DeepGEMM/blob/cbe1727eacd9ad704795584ce1421dd1f5a8d67e/deep_gemm/include/deep_gemm/impls/sm100_bf16_mega_gate.cuh#L329), then [traps](https://github.com/sgl-project/DeepGEMM/blob/cbe1727eacd9ad704795584ce1421dd1f5a8d67e/deep_gemm/include/deep_gemm/impls/sm100_bf16_mega_gate.cuh#L457) if anything was NaN/inf. So garbage in padded rows would kill a graph replay. This only runs on padded batches. Proper fix is in DeepGEMM (skip the check on masked rows), will do that and drop this.
