# [Diffusion] Add native MLX support for Qwen-Image 2.1

[Upstream PR](https://github.com/sgl-project/sglang/pull/41073) · state: closed · merged: False

## Original PR description

## Motivation

Add an experimental native MLX pipeline for Qwen-Image 2.1 on Apple Silicon. The standard `sglang generate` and `sglang serve` entry points can use the community `toxicdog/Qwen-Image-2.1-MLX` weight pack for text-to-image generation, reference-image editing, and RGBA output.

## Modifications

- Implement the Qwen3-VL text/vision encoders, block-causal DiT, and four-channel VAE with MLX. Reuse request-owned conditioning KV during denoising and load/release model components sequentially.
- Keep native architectures and model-specific checkpoint mappings in `runtime/models/`, execution in a model-specific stage, and shared MLX loading in `runtime/loader/`. The developer guide documents these backend ownership and optional-import boundaries.
- Add strict affine-quantized checkpoint loading, including quantized vision position embeddings, pipeline discovery, the `diffusion_mlx` source extra, and MLX peak-memory reporting through the existing worker.
- Update the cookbook with Apple Silicon installation, generation/editing examples, HTTP serving, and supported-feature boundaries. Document distinct seeds for generated-reference editing, while preserving user-supplied seeds.

The MLX pack uses lossy Q4 weights and is not numerically equivalent to the full BF16 checkpoint. This pipeline is single-device; CUDA graphs, distributed inference, LoRA, Cache-DiT, Torch compilation, and VAE tiling are outside its supported scope. Multiple outputs run sequentially.

## Accuracy Tests

Added tests cover FP32/BF16 model operations, prefix-cache isolation, compiled/eager output equality, strict checkpoint conversion, quantized embedding interpolation, prompt/image processing, scheduling, RGBA output, the actual top-level CLI with offline Hub-cache and multi-reference fixtures, and standard model/pipeline discovery with MLX unavailable.

On an Apple Silicon environment with the MLX extra, run:

```bash
python -m pytest python/sglang/multimodal_gen/test/mlx \
  --confcutdir=python/sglang/multimodal_gen/test/mlx -q
```

The BF16 vision reference specifically requires Transformers 4.57.3: v5 changes positional-embedding interpolation arithmetic, so it is not the same precision oracle. Run that reference test in a separate 4.57.3 environment; the runtime environment also covers FP32 vision, RoPE, and real CLI tests. The dependency-specific tests report explicit skips when their reference environment is unavailable. NVIDIA CI does not exercise the Metal kernels.

## Speed Tests and Profiling

This PR introduces a backend and makes no cross-platform or end-to-end speedup claim. Per-step durations and MLX allocation peaks are exposed through the existing performance metrics. The cookbook keeps runnable recipes and feature limits; experiment history is not included.
