## Summary

**Track the three TweetEval failures caused by an invalid DiffusionGemma answer prefix.**

- **[WIP] · Stack 3/3.** Depends on #43752, which depends on #41232.
- **Merge order:** #41232 → #43752 → this PR.
- **[Review this layer only](https://github.com/Hangzhi/sglang/compare/6d92bcc6b0d198025fa2884dfc1a35647da3b6f9...74e6ea716b0493e3d5f9bede67107ee8cf580f22).** GitHub's default diff also includes PR1 and PR2.
- **Current scope:** a runnable regression reproducer and a fix plan. The decoding fix is pending.

## Problem

The decision API expects four header tokens before the answer. Three TweetEval cases emit `**` or `<eos>` where `<channel|>` is required. The prefix check rejects these outputs with HTTP 400.

The requests are valid. The same bad tokens occur on the tested upstream commit without either earlier PR. We still need to determine whether SGLang differs from the reference decoder.

## Changes

- Add a manual replay for the three failing cases from the user's frozen TweetEval data.
- Check data and question hashes before sending requests. Do not retry failures.
- Require HTTP 200, finite probabilities, a normalized distribution, and zero output-token usage.
- Document the launch command, diagnosis, and acceptance checks.

## Fix plan

- [ ] Compare the pinned checkpoint and prompts with Google's reference path.
- [ ] Fix any decoder or template mismatch.
- [ ] If needed, prototype a fixed four-token header during denoising and self-conditioning. Keep label tokens free.
- [ ] Keep the prefix guard. Validate raw-score replay with the same prefix mode.
- [ ] Check eager execution, CUDA graphs, batches, streaming, and retraction.
- [ ] Rerun all 1,381 frozen cases. Report valid responses, accuracy, and latency.

**The fixed-prefix approach is a proposal. It is not yet a verified fix.**
