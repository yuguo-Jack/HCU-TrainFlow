# [Perf] Autotune M128 BF16 projections on SM103

[Upstream PR](https://github.com/sgl-project/sglang/pull/43424) · state: closed · merged: False

## Original PR description

## Motivation

The default BF16 GEMM selection leaves measurable performance available for M128 gate/up and down projections on SM103. Tune these two projection shapes during startup through FlashInfer's public BF16 cuBLASLt API, then use the verified cached tactics during inference.

## Modifications

- Tune M/N/K = 128/19456/2560 and 128/2560/9728 for eligible unquantized BF16 models using the CuteDSL backend on SM103.
- Verify each cached tactic before enabling dispatch; preserve bias/addend, layout, dtype, deterministic-mode and unsupported-shape fallbacks, including caller-owned outputs.
- Keep weights, inputs and outputs BF16. Skip draft/speculative workers and disabled autotuning.
- Keep new imports at module scope with CUDA/optional-dependency guards. Store readiness in resettable runtime resources and clear it during backend initialization and autotuning.

Based directly on upstream main `2f1acef3d8`; no dependency on the other optimization PRs. This extraction adjusts import placement and readiness ownership. No new benchmark or test files are included.

## Accuracy Tests

Prior validation of the autotuning integration: 33 existing tests and nine subtests passed, plus GPU fallback guards and graph-capture/replay checks. Two full C128 GSM8K runs scored 1213/1314 and 1223/1314, versus 1217/1314 and 1219/1314 controls with GPUs swapped. Equal aggregate scores do not establish numerical or statistical equivalence; individual outputs and scores differ.

These are prior results, not fresh GPU validation of this main-based branch. Current-branch pre-commit, Python AST and static import/dependency checks pass. Runtime/CPU suites were not run because local PyTorch is unavailable and the remote source transfer was not approved. No server validation was restarted.

## Speed Tests and Profiling

Prior production measurements: one B300 per run, TP1, Qwen3-VL-4B, BF16 weights/queries/KV, nominal 8192-input/1024-output requests, concurrency 128, 640 measured requests after 128 warmups and cache flush. Eight same-GPU crossover pairs across two periods used fresh tuning caches and shared compiled kernels.

| Metric | Prior dispatch | Public autotuning |
| --- | ---: | ---: |
| Mean output tokens/s | 3809.82 | 3822.62 |
| Geometric paired throughput change | — | +0.336% |

All eight pairs improved and completed exact request/token counts. The descriptive paired bootstrap 95% interval was +0.280% to +0.403%; it describes those pairs, not repeated-day variation. Both arms included common earlier optimizations, so these numbers are not a clean-main full-stack comparison. Lower-concurrency single paired checks at C1/4/8/16/32/64 changed throughput by -0.075%/-0.116%/+0.208%/-0.061%/-0.056%/-0.024%.
