# [HiCache] Key MLA Mamba state per TP rank in the SeaweedFS backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43816) · state: open · merged: False

## Original PR description

## Summary

Fix an existing `main` bug in the SeaweedFS L3 backend. MLA KV is replicated across TP ranks, but Mamba state is TP-sharded and `should_backup` makes every TP rank back up its own shard. `key_scope()` drops the TP rank for MLA models, so every rank writes the same `<key>.mamba` object and restores another rank's state.

Following #43594 (the same fix for NIXL): on MLA models, Mamba component keys carry the TP rank (`<key>.mamba.tp{rank}of{size}`); KV and other pools keep their keys. Existing rank-ambiguous Mamba objects are not reused because their owning rank is unknown, so they read as misses.

Split out of #41907 so each storage backend is reviewed on its own.
