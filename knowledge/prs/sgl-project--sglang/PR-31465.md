# [Spec] perf: Fuse draft-extend topk=1 postprocess

[Upstream PR](https://github.com/sgl-project/sglang/pull/31465) · state: closed · merged: False

## Original PR description

This PR was originally stacked on #30947, which is now merged.

## Motivation

After draft-extend CUDA graph replay, the top-k=1 decode path still materializes selected logits, hidden states, and optional DSA indices with eager indexing, then launches `argmax` and `ones_like`. For wide vocabularies, these small eager launches form a visible tail after the graph and unnecessarily materialize the selected full-vocabulary logits.

The draft-extend path needs the same split argmax reduction introduced by #30947, with one difference: it reduces selected rows from a larger logits tensor. This PR extends that implementation instead of adding a second draft-extend reduction kernel.

cc @kpham-sgl 

## Modification

- Reuse #30947's `_draft_topk1_partial_argmax_kernel` for both paths. A compile-time `USE_ROW_INDICES` specialization either loads the selected source row for draft-extend or compiles the row-indexing branch away for regular draft.
- Reuse a common `_draft_topk1_finalize` helper for the second-stage reduction.
- Replace separate `tl.max` and `tl.argmax` partial reductions with one `tl.max(..., return_indices=True)` reduction. This also improves the already-merged #30947 regular-draft path.
- Fuse final argmax assembly, `topk_p = 1`, hidden-state gathering, and optional DSA-index gathering into the draft-extend final Triton launch.
- Overlay hidden-state and DSA gathering on the same task grid, using `max(hidden_blocks, dsa_blocks)` gather tasks rather than separate task ranges.
- Replace three eager indexed gathers plus `argmax` and `ones_like` with two Triton launches.
- Enable the path only for CUDA, `topk == 1`, and non-rejection sampling; preserve the existing fallback for other modes and backends.
- Add focused exactness coverage at the traced GLM dimensions and CUDA graph benchmarks for both the new path and the inherited #30947 path.

## Speedup

All microbenchmarks use CUDA graph replay (`triton.testing.do_bench_cudagraph`) on an idle NVIDIA B300 SXM6 AC GPU with CUDA 13.0.

### Draft-extend postprocess

Fused draft-extend path versus the eager indexed-gather reference. The benchmark uses FP32 logits shaped `[6 * batch_size, 154880]`, BF16 hidden states of width 6144, and INT32 DSA top-k indices of width 2048.

| Batch size | Fused indexed Triton | Eager index + argmax | Speedup |
|---:|---:|---:|---:|
| 1 | 3.84 us | 24.52 us | 6.39x |
| 2 | 3.84 us | 17.50 us | 4.56x |
| 4 | 4.04 us | 18.10 us | 4.48x |
| 8 | 4.18 us | 18.45 us | 4.41x |
| 16 | 4.91 us | 21.97 us | 4.47x |
| 32 | 5.71 us | 26.59 us | 4.66x |
| 64 | 8.29 us | 39.36 us | 4.75x |
| 128 | 13.89 us | 71.46 us | 5.14x |

## Code Review

This pull request introduces optimized Triton kernels for topk=1 speculative decoding postprocessing, specifically `draft_topk1_postprocess` and `draft_extend_topk1_postprocess`. These kernels fuse argmax reduction, position advancement, and draft token writing to bypass slower eager PyTorch operations during speculative steps. The changes integrate these kernels into the Eagle speculative worker (`eagle_worker_v2.py`) and add comprehensive unit tests and benchmarks to verify correctness and performance.
