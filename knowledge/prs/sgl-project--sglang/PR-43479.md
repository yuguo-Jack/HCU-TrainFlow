# [Scheduler] Keep waiting-prefix LRU refresh consistent across TP ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/43479) · state: closed · merged: True

## Original PR description

Waiting-prefix LRU refresh from #41593 uses a rank-local 0.5-second timer. One TP rank can refresh the waiting queue while peers skip it, changing recency and eventually selecting different eviction victims.

Refresh on the first eligible scheduling call and every 32 eligible calls thereafter. This retains a bounded scan cadence without a per-call collective. The cadence now follows scheduling progress rather than elapsed wall time.

Validation:
- One added regression in the existing test file simulates scheduler clocks on opposite sides of the old interval while keeping cache operations identical. It fails on main with different surviving prefixes; the updated test file passes all 3 tests after this change.
- Repository pre-commit checks pass.
- An Inkling TP4 / buffer-only / file-L3 run with unified memory disabled still diverged after applying #43108 alone. A tree-state probe found the first difference before `inc_lock_ref`: rank 2 had performed 122 extra recency updates; tree structure, locks, capacities, and prior existence beliefs agreed. Only node recency differed.
- Disabling waiting-prefix refresh completed a 10-minute TP4 mixed-pressure control plus drain: 531 requests, 56 L3-hit requests; all 56 hits were included in the 130 scored requests / 40,567 tokens with exact logprob equality and sampled KL=0. The cache flushed successfully. All 200,707 recorded cache-boundary events agreed across all four ranks.
- With refresh re-enabled, the original #36345 head plus only this scheduler fix (without #43108) completed another 10-minute TP4 mixed-pressure run plus drain: 407 requests (386 generations and 21 intentional aborts), 48 L3-hit requests; 109 scored requests / 34,831 tokens had exact logprob equality and sampled KL=0, including all 48 L3 hits. All 205,441 recorded cache-boundary events agreed across four ranks. Backup, prefetch, and FULL/SWA/Mamba load-back all transferred data; the final cache flush succeeded. Unified memory was disabled. These instrumented asynchronous runs establish correctness for the exercised workload, not throughput equivalence.

#43108 fixes a separate prefetch-cancellation belief race; this change addresses the scheduler's LRU refresh decision. The admission-time device-coverage recovery fix in #43466 is also independent.
