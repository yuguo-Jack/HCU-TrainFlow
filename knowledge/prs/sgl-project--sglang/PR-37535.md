# Reduce KDA prefill OOM risk with opt-in workspace limits

[Upstream PR](https://github.com/sgl-project/sglang/pull/37535) · state: open · merged: False

## Original PR description

## Motivation

Long or batched prefills can run out of GPU memory inside KDA attention because its temporary workspace grows with every token passed to `chunk_kda`. Lowering the global prefill chunk size also changes batching for the rest of the model.

This PR lets KDA process a large extend in smaller internal blocks while preserving the global prefill limits. It bounds each KDA call's workspace, not total model or request memory.

## Modifications

- Add `SGLANG_KDA_EXTEND_BLOCK_TOKENS`, disabled by default. Values below 64 retain the original call; larger values round down to a 64-token boundary.
- Group whole sequences that fit and split longer sequences. Carry split-sequence recurrent state through FP32 scratch, rounding reduced-precision pool state only on the final writeback.
- Translate FP32 checkpoint rows and chunk indices for each call. For example, a checkpoint at token 2048 of a 2110-token extend belongs to chunk zero of the second block. Forwarding the original chunk index 32 leaves the snapshot unwritten and can corrupt a later prefix-cache restore.
- Give every blocked call the intra-chunk kernel choice of the whole extend. `chunk_kda` picks a fused or non-fused intra-chunk kernel from each call's grid size, and the two are not interchangeable without `lower_bound`: the fused kernel clamps per-token gate offsets, so with strong gate decay a block that switched kernels could change outputs well beyond rounding. `chunk_kda` gains an optional `fuse_intra` argument for this; existing callers keep the per-call choice.
- Preserve padded-row handling, untracked checkpoint rows, and intermediate-state ordering. Fall back to the original call under graph capture or incompatible host metadata.
- Do not pass the caller's precomputed `chunk_indices` and `chunk_offsets` to blocked calls. They describe the whole extend, so each blocked call derives its own from its `cu_seqlens`.
- Cache block-boundary metadata by device, stream, dtype and content. Full-extend output storage and tracked intermediate states still scale with the complete extend.

## Accuracy Tests

12 CPU tests/19 subtests pass on main 3831e7e0 with this branch. On RTX PRO 6000 Blackwell Max-Q (SM120), torch 2.14.1+cu130 and Triton 3.8.0, with this branch's head imported:

- `test_kda_extend_blocked.py`: 21 passed, 29 subtests (GPU and CPU).
- `test_kda_kernels.py`: 19 passed, 11 subtests.
- `test_kda_track_state.py`: 1 passed, 1 skipped (Helion not installed).
- `test_kda_gate_beta_cumsum.py`: passed in 4 of 6 runs. In the other 2, the three `fused_gate=True` subtests of `test_chunk_raw_beta_matches_activated_beta_and_final_state` differed in 8-20 of 8704 elements. Unmodified main 3831e7e0 shows the same three subtests and element counts in 4 of 8 runs, so this is pre-existing and not caused by this PR.

Tests cover outputs, final states, intermediate states and FP32 checkpoints; the checkpoint regression fails without the chunk-index translation. A standard-gate case (no `lower_bound`, a 2**-20 decay per token, 8 heads, 2112 tokens) checks that a 2048-token block keeps the whole extend's non-fused intra kernel, and compares the output with an FP32 token-by-token recurrence: the exact output at token 8 is about 3e-8, while the fused kernel's gate clamp gives 0.03125. A CPU test checks that every blocked call receives the whole extend's kernel choice and fails without it. Another checks that the unblocked call keeps the caller's chunk tables while blocked calls receive none, and fails without that change. Every blocked-versus-unblocked comparison requires bitwise equality, with each call given independent input copies.

## Speed Tests and Profiling

Blocking reduces per-call workspace and adds kernel launches. Full-extend output and tracked-state storage still scale with the complete extend. Memory savings and throughput were not benchmarked.
