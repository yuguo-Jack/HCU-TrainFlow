# [BugFix] Preserve calibrated FP8 scales for Gemma4 shared KV readers

[Upstream PR](https://github.com/sgl-project/sglang/pull/43532) · state: open · merged: False

## Original PR description

## Motivation

Gemma4 FP8 shared-cache readers use the writer's cache layer ID but retain their
own default calibration. A writer loaded with K/V scales 0.125/0.25 can therefore
be read with reader scales 1/1. The backends consume both host scalar mirrors
and tensor scales, so aliasing the cache ID does not repair the mismatch.

## Modifications

Bind FP8 readers to their writer's scale finalization during Gemma4TextModel
construction. Finalize the writer once, copy its finalized K/V tensor values
and host mirrors to readers, and skip independent reader postprocessing. Keep
reader parameter identities and support either postprocessing order and reloads;
reject a calibrated reader whose writer is missing from its pipeline rank.

This is a two-file standalone fix on main
`ff19159e162595f26e6d01eabcbbd4638b3bd228`, candidate
`8f920a83dadf69137f01fb14d93a9638e98a15c7`. It changes neither model weights,
per-token work nor attention geometry. BF16/unquantized and NVFP4 recipe binding
remain unchanged. No #43247/#43471 dependencies are imported.

#43509 addresses NVFP4 pool-owner scales; this addresses FP8 model reader
postprocessing. Open Gemma4 YOCO #27183 and QKV refactor #25461 do not propagate
these scales. Their composed execution has not been tested here.

**5 passed, 4 subtests passed.** Covers tiny actual TextModel constructor wiring,

Kernel/pool boundaries are substituted; this is not GPU kernel coverage.

The same bounded 35-layer checkpoint-scalar harness was run on archived exact
main and this candidate. It calls real Gemma4 weight loading and
DefaultModelLoader postprocessing with real runtime configuration:

- Stock main: **15/15 writer scales match; 0/20 FP8 readers match**, exit 1.
- Candidate: **15/15 writers and 20/20 readers match**, exit 0.
- BF16 control preserves absent calibration on all 35 layers in both arms.

The harness constructs actual attention modules on meta with CPU calibration
parameters and calls the binding helper directly because it omits TextModel.
The registered constructor test separately verifies automatic binding. No
full Gemma4 serving or GPU numerical result is claimed for this source.

## Separate integration evidence

On 2026-10-10, a composed evaluation source at
`bbd1a811894ec5d52aa6c35abdd083e5e2baa1c2` containing this correction plus
separate heterogeneous-pool/shared-reader routing fixes served Gemma4 E2B
with BF16 weights and freshly calibrated FP8 KV on GB10 SM121.
The real multimodal model weight iterator discovered all 30 writer scalars;
all 15 writer pairs and 20 reader pairs matched the calibration. Instrumented
actual FlashInfer shared-reader calls verified FP8 cache dtype and owner scale
arguments for all 20 readers. Frozen cold16 and reused-prefix16 smoke requests
completed with all expected-answer checks passing and no legacy detector flags.

This is evidence for the composed integration, **not a GPU/model test of this
standalone main-based PR head**. It establishes neither quality parity nor a
performance gain. Original failed startup attempts were retained: an inherited
allocator keyword collision and an evaluation hook aimed at the wrong model
entrypoint were corrected before these observations. The passing CPU evidence
above is on this exact PR head; no unrelated integration changes are included.
