# [Diffusion] fp8_fa_sm120: keep listed attention layers in BF16

[Upstream PR](https://github.com/sgl-project/sglang/pull/43433) · state: open · merged: False

## Original PR description

## Motivation

`fp8_fa_sm120` quantizes Q/K/V to E4M3 per head. Most attention layers handle that well: about 5% relative RMS error per call. Layers whose heads have very peaked scores do not.

On MiniMax-H3 a per-call probe gave these errors against BF16 attention:

- `blocks.49`: 26-45%
- `blocks.45`: 15-17%
- `blocks.1`: large on early steps
- the audio rows of `blocks.48`: 10-13%
- every other layer: 3-7%

Q/K rounding is the dominant term. Running the whole DiT in FP8 changes the generated scene: SSIM 0.85 against the BF16 run, against 0.97-0.99 for simply swapping BF16 kernels.

Smoothing did not fix those few layers: K-mean subtraction, Q/K balancing and V normalization barely helped and cost about 45 s unfused. Keeping them in BF16 did: the change keeps most of the speedup and stays close to BF16.

## Modifications

- `--attention-backend-config` gains two keys for `fp8_fa_sm120`. Both are read once in `FP8FlashAttentionSM120Impl.__init__`.
  - `bf16_layers`: a list of exact attention-layer prefixes that run cuDNN SDPA (BF16) instead. Matching is exact on purpose: substring matching would also catch `token_refiner.*` and vision-tower layers.
  - `min_seq_len`: sequences shorter than this run cuDNN SDPA. Short calls gain little from FP8, and each new length costs a compile of about 10 s.
- `forward` and `forward_varlen` check both before dispatching. Without either key, the backend behaves exactly as before.
- Docs: the `fp8_fa_sm120` row in `attention_backends.mdx` documents both keys and the H3 layer list.
- Tests (`test_fp8_fa_sm120_attn.py`):
  - `test_bf16_layers_match_exact_layer_prefixes`: a listed layer returns the cuDNN result bit for bit, and an unlisted layer whose name is contained in a listed one (`blocks.4.attn` in `blocks.45.attn`) still runs FP8.
  - `test_min_seq_len_runs_short_sequences_in_bf16`: a short call returns the cuDNN result and compiles no FP8 kernel.
  - The existing tests patch `get_global_server_args`, because the impl now reads it.

Usage for MiniMax-H3:

```
--attention-backend fp8_fa_sm120 \
--attention-backend-config '{"bf16_layers": ["blocks.1.attn", "blocks.45.attn", "blocks.48.attn", "blocks.49.attn"], "min_seq_len": 4096}'
```

## Accuracy Tests

`python/sglang/multimodal_gen/test/unit/test_fp8_fa_sm120_attn.py` on an RTX PRO 6000 (SM120): 11 passed.

MiniMax-H3 on one RTX PRO 6000: 4 s, 16:9, 50 steps, same seed and prompt. The comparison is against the BF16 run, as video SSIM / PSNR over all frames. These runs used a deployment that applies the same per-layer exception logic through a patched copy of this backend, not this branch.

| run | t2va SSIM / PSNR | fl2va SSIM (seeds 7 / 11 / 12) |
|---|---|---|
| BF16 cuDNN kernel swap (noise floor) | | 0.987 (seed 7) |
| `fp8_fa_sm120`, all layers | 0.847 / 21.6 dB | |
| `fp8_fa_sm120` + the 4 `bf16_layers` + `min_seq_len` 4096 | 0.942 / 30.6 dB | 0.984 / 0.943 / 0.893 |

Diffusion outputs move by seed, so the fl2va row covers three. All-FP8 changed the composition (a shoreline moved). With the four layers kept in BF16 the scenes match the BF16 run.

## Speed Tests and Profiling

Same settings, end-to-end wall time:

| run | t2va | fl2va |
|---|---|---|
| BF16 (cuDNN) | 519.5 s | 560.8 s |
| `fp8_fa_sm120`, all layers | 449.0 s | |
| `fp8_fa_sm120` + 4 `bf16_layers` | 458.9 s (-11.7%) | 485.4 s (-13.4%) |

Keeping 4 of 50 blocks in BF16 gives back about 10 s of the 70 s that FP8 saves on t2va.
