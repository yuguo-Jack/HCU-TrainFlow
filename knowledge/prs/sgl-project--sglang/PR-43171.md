# [GDN] Auto-select FlashInfer prefill on a page-major pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/43171) · state: open · merged: False

## Original PR description

## Motivation

`flashinfer_gdn_prefill_default` declined whenever `enable_page_major_kv_layout` was set. `--enable-unified-memory` runs page-major, so Qwen3.5 GDN prefill stayed on the Triton chunk kernels there while the default pool on the same GPU auto-selected FlashInfer. On SM90 (Qwen3.5-9B, page size 256, no speculative decoding) unified prefill cycles ran +1.24..+1.41% longer than the default pool's at matched batch size, all of it GPU time: the Triton chunk kernels cost +17.8 ms per cycle where the FlashInfer GDN kernels cost 10.7 ms. End to end that was -1.1..-1.5% throughput on every attention backend.

## Modifications

`layers/attention/linear/gdn_backend.py`: page-major no longer disqualifies the FlashInfer prefill. For prefill the layout does not matter: `forward_extend` gathers a non-contiguous pool's conv and SSM state into contiguous per-sequence copies before any prefill kernel runs and scatters them back after (`needs_state_gather`), so FlashInfer's extend sees the same contiguous, identity-indexed state as on the default pool. Decode and verify are unaffected; their backends resolve separately (verify follows decode, Triton by default).

Test (`test_gdn_prefill_backend_policy.py`): `test_selects_flashinfer_for_a_page_major_pool` (SM100 with a bf16 state, SM90 with an fp32 state) fails before (the policy returns None) and passes after; page-major leaves `test_rejects_unvalidated_runtime_modes`.

## Accuracy Tests

SM90, TP1, Qwen3.5-9B, no speculation, page size 256, radix cache, overlap scheduler, CUDA graphs on, `--mem-fraction-static 0.8`. Baseline: the default pool. Unified: `--enable-unified-memory`. Every unified server now logs `Linear attention kernel backend: decode=triton, prefill=flashinfer, verify=triton`, as the default pool's does (on main its unified servers log `prefill=triton`). GSM8K, all 1314 test questions, 5-shot, greedy:

| attention backend | baseline | unified |
|---|---|---|
| fa3 | 0.897 | 0.901 |
| flashinfer | 0.898 | 0.900 |
| triton | 0.899 | 0.898 |

GPU unit suite (unified-memory scope): all pass except the 2 cases of `test_swa_write_back_host_full_preserves_full_and_continues`, which force the Rust TreeCore that our test image does not build.

## Speed Tests and Profiling

`bench_serving` with random prompts at concurrency 64, in two shapes: 2048 input / 512 output tokens (200 prompts) and 8192 input / 64 output tokens (100 prompts). Qwen3.5-9B, no speculation, page size 256, radix cache, overlap scheduler, CUDA graphs on, `--mem-fraction-static 0.55`. Each entry is the unified pool's gap to the default pool on the same tree, before (main) and after this PR; the default pool runs twice and the gap is against the mean of the two runs, with their spread (A/A) as the noise floor.

| attention backend | shape | req/s, main -> this PR | mean TTFT | mean E2E | A/A (req/s / TTFT / E2E) |
|---|---|---|---|---|---|
| fa3 | 2048 / 512 | -0.9% -> -0.4% | +3.6% -> +2.5% | +1.0% -> +0.4% | 0.2 / 0.3 / 0.2 |
| fa3 | 8192 / 64 | -1.2% -> -0.2% | +2.0% -> +0.8% | +1.2% -> +0.2% | 0.1 / 0.1 / 0.1 |
| flashinfer | 2048 / 512 | -1.2% -> -0.7% | +3.9% -> +2.8% | +1.2% -> +0.8% | 0.1 / 0.1 / 0.1 |
| flashinfer | 8192 / 64 | -1.3% -> -0.2% | +2.5% -> +1.0% | +1.4% -> +0.2% | 0.1 / 0.2 / 0.1 |
| triton | 2048 / 512 | -0.7% -> -0.4% | +3.5% -> +2.0% | +0.8% -> +0.5% | 0.1 / 0.1 / 0.2 |
| triton | 8192 / 64 | -1.1% -> -0.2% | +2.1% -> +0.9% | +1.2% -> +0.2% | 0.0 / 0.0 / 0.0 |

- The triton rows compare with the first default-pool run only, and their A/A is main's: on this PR's tree the second run compiled kernels during the benchmark.
- The TTFT gap left on the 2048 / 512 shape comes from scheduling, not from the prefill kernels: on the unified pool the radix cache keeps more (about 61k vs 19k cached tokens over the run), so the two arms schedule different prefill batches. On prefill batches with identical new and cached token counts in both arms' logs, unified prefill throughput is 0.998 of the default pool's with this PR on every backend (0.994-0.996 on main).
