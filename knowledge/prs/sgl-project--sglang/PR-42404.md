# [Perf] Skip cached-prefix queries in torch-native attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/42404) · state: open · merged: False

## Original PR description

## Summary

Torch-native extend pads Query to the full KV length, computes cached-prefix Query rows, and discards their outputs. Run SDPA only for new tokens, and reuse existing CPU length/request-index mirrors to avoid scalar synchronization.

```text
before: SDPA([unused prefix Query; new Query], cached KV) → discard prefix output
after:  SDPA(new Query, cached KV, prefix-aligned causal bias) → new output
```

- Ordinary prefix causality uses PyTorch `causal_lower_right`; eligible fused CUDA dispatch is retained. Sliding-window masks use absolute Query offsets. Prefix-free causal attention retains `is_causal=True`.
- CPU mirrors are used only for non-speculative extend. Missing/length-mismatched mirrors fall back per field; no new device-to-host transfer or persistent batch state is introduced. Decode is unchanged.
- Tests separate input preparation, independent reference math, and backend execution, with public ENCODER_ONLY coverage as well as causal/cross-attention paths.

Each model has 160 timed groups / 280 timed responses in ABBA order and 28 exact baseline/PR natural-stop output pairs. For Qwen3, cached-4096 TTFT drops 117.30 → 97.13 ms (17.2%); concurrent cached TTFT drops 196.84 → 159.13 ms (19.2%). Qwen3.5 has smaller cached TTFT reductions (1.6–4.2% single-request, 6.3% concurrent).
