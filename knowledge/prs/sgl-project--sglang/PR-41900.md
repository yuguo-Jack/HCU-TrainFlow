# [AMD][MoE] small-batch sort: histogram + bitonic sort kernel for 32 < P <= 256

[Upstream PR](https://github.com/sgl-project/sglang/pull/41900) · state: open · merged: False

## Original PR description

## Motivation

On the aiter MoE runner, the small-batch sort patch (`moe_sorting_small.py`, #36559) handles `P = M * topk <= 256`. Without the fused mxfp8 emit (e.g. DeepSeek-V4, hidden 7168), `P > 32` goes to the P x P compare kernels: 4.0 us (P <= 63), 9.5 us (P <= 126) and 14.8 us (P <= 252) per MoE layer on MI355X. Every MoE layer runs this once per decode/verify step.

## Modifications

- New `_moe_sorting_small_kernel_sorted`, used for no-quant `32 < P <= 256`. One CTA builds a histogram of the expert ids, cumsums the per-expert block padding, pads the used region, bitonic-sorts `(expert, pair)` keys (`tl.sort`) and scatters `sorted_ids` / `sorted_weights` / `sorted_expert_ids` / `num_valid_ids`. The other CTAs zero `moe_buf` as before.
- `P <= 32` and the `EMIT_MX` path keep the existing kernels.
- New test `test/registered/amd/test_moe_sorting_small.py`: checks every kernel variant (`P <= 256`, uniform and skewed routing, E/topk/block = 385/7/32, 257/9/32, 129/8/16) against a torch reference of the aiter `moe_sorting` layout.

## Accuracy Tests

- Output is bit-identical to the existing kernels for every M tested (E=385/topk 7/block 32 for M = 1..36, plus E=257/topk 9 and E=129/topk 8/block 16; uniform, 12-hot-expert and top-id routing).
- New unit test: 192/192 subtests pass. The stock file also passes it.
- DeepSeek-V4-Pro TP8, DSpark b6, gsm8k (1319 questions), 2 boots per arm: before 0.944 / 0.945, after 0.948 / 0.944. The accept length is unchanged (4.38 / 4.39).

## Speed Tests and Profiling

Microbench, MI355X, one GPU, CUDA-graph timed, sort launch only (E=385, topk 7, block 32, the DSv4 shape):

| P = M*7 | before (us) | after (us) |
|---|---:|---:|
| 7-28 | 2.3-2.6 | same path |
| 35-63 | 4.0 | 3.7 |
| 70-126 | 9.5 | 4.3 |
| 133-252 | 14.8 | 5.2 |

Also E=257/topk 9: 13.7 -> 5.2 us at P=144-252. E=129/topk 8/block 16: 12.7 -> 4.5 us at P=160-256. No shape got slower.

E2E, DeepSeek-V4-Pro fp8, TP8 MI355X, image `lmsysorg/sglang-rocm:v0.5.20-rocm724-mi35x-20260927`, 8k in / 1k out. The pairs are measured on our DSv4 decode stack: sgl-project/sglang#41383 (FlyDSL fused decode, with ROCm/aiter#5882), the DSpark verify ring write, and the fused CSA `wkv_gate` GEMM. Before = that stack; after = stack + this PR. 2 boots x 3 reps, alternating order:

| cell | step time before -> after (ms) | delta mean [min, max] | steady decode tok/s |
|---|---|---|---|
| plain c8 | 12.29 -> 12.22 | -0.53% [-0.088, -0.031 ms] | 651 -> 654 |
| plain c32 | 16.41 -> 15.78 | **-3.87%** [-0.664, -0.606 ms] | 1952 -> 2031 (+4.0%) |
| DSpark b6 c2 | 15.34 -> 14.93 | **-2.67%** [-0.447, -0.367 ms] | 832 -> 854 (+2.7%) |
| DSpark b6 c4 | 18.20 -> 17.48 | **-3.95%** [-0.763, -0.667 ms] | 1351 -> 1408 (+4.2%) |

All 24 pairs are faster.
