# [MiniMax] Key sparse-decode autotune on real kernel args; skip the one-chunk merge

[Upstream PR](https://github.com/sgl-project/sglang/pull/43348) · state: open · merged: False

## Original PR description

## Motivation

Two small issues in the MiniMax-M3 sparse decode launcher (`minimax_sparse/decode/topk_sparse.py`):

1. The autotune key of `_gqa_share_sparse_decode_kernel` lists `"block_size"`, which is not a kernel argument (the kernel takes `BLOCK_SIZE_N`). Triton's `Autotuner.run` keeps only key names that are kernel arguments (`[_args[key] for key in self.keys if key in _args]`), so the entry is silently dropped. `PAGED_CONTIG` is not in the key either. Both select different compiled kernels, so a config tuned for one block size or KV layout is reused for another. Within one serving process both are fixed today, so this does not change current results; it does when they vary in one process (tests, multiple models).
2. When `NUM_TOPK_CHUNKS == 1` the merge kernel still launches, although merging one chunk is an identity: `weights = exp(lse - lse) / 1 = 1`. With one KV head per rank (MiniMax-M3 at TP4 and TP8) this is every decode step at batch size > 128.

## Modifications

- Key on `BLOCK_SIZE_N` and `PAGED_CONTIG` instead of the nonexistent `block_size`. Tensor dtypes (bf16 vs fp8 KV) were already part of the key through Triton's automatic dtype entries.
- Return the single chunk directly when `NUM_TOPK_CHUNKS == 1`.

## Accuracy Tests

New `test/registered/kernels/ops/attention/test_minimax_sparse_decode_chunks.py` compares the kernel with a torch fp32 reference at the per-rank MiniMax-M3 shape (16 q heads, 1 KV head, head_dim 128, block 128, top-16), at batch 4 (several chunks, merge runs) and batch 256 (one chunk, merge skipped). Registered for CUDA (`base-b-kernel-unit`, next to the sibling tests) and AMD (`stage-b-test-1-gpu-small-amd`). 2 passed on MI355X.

## Speed Tests and Profiling

MI355X (gfx950), ROCm 7.2.0, torch 2.9.1, Triton 3.7.0. One `flash_decode_with_gqa_share_sparse` call at the TP4 per-rank shape, 8k context, page size 128; `triton.testing.do_bench` median, minimum of 5 repetitions:

| Batch | Chunks | `main` (µs) | This PR (µs) |
|---|---|---|---|
| 32 | 8 | 53.3 | 53.0 |
| 64 | 4 | 49.6 | 49.0 |
| 128 | 2 | 62.1 | 62.0 |
| 256 | 1 | 98.5 | 95.6 |
| 512 | 1 | 154.6 | 149.4 |

About 3% per sparse layer once the batch has a single chunk (57 sparse layers in MiniMax-M3); no change below that, as expected.
