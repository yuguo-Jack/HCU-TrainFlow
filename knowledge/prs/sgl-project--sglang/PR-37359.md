## Motivation
co-author with @Richardyu114 and @FionaZZ92
<!-- Describe the purpose and goals of this pull request. -->
Prefix-hit-aware benchmarking is essential for evaluating real agent workloads, where repeated system prompts, tool schemas, and conversation context make high cache-hit rates. To accurately simulate production workload, this PR introduces a benchmark that measures inference performance under controlled prefix-cache hit rates.

`sglang.bench_serving` can generate shared-prefix requests and report cached tokens, but it previously lacked a deterministic way to benchmark a requested cache-hit rate. In particular, ordinary warmup is followed by cache flushing, so measured requests can race to populate the prefix cache unless prefixes are primed in a separate phase.

This PR adds a controlled lifecycle:

```text
generate requests -> model warmup -> flush cache -> prime prefix groups
  -> measured traffic -> cache-hit validation -> resumable artifacts
```

<img width="1600" height="1200" alt="prefix_cache_hit_benchmark" src="https://github.com/user-attachments/assets/3b3be69e-bbe9-4a9e-a380-2b6bbace9303" />

The implementation reuses the existing `generated-shared-prefix` dataset instead of introducing another dataset API. Exact prefix metadata travels with each `DatasetRow`, so the benchmark never reconstructs token prefixes from text.

<img width="2200" height="1300" alt="prefix_cache_hit_datastructure" src="https://github.com/user-attachments/assets/b5d3f9d8-3748-4f00-8180-49895171cd20" />

### Non-goals
The following item are out of scope of this PR:
- Selecting which HiCache tier serves a hit.
- Trace-driven prefix lifetime simulation.
- Multi-turn conversation semantics.
- Scheduler or cache-eviction changes.
- Guaranteeing target residency when the prefix working set exceeds cache capacity.

## Modifications

<!-- Detail the changes made in this pull request. -->
- Add optional `cache_prefix` and `cache_prefix_len` metadata to `DatasetRow`.
- Add `--gsp-prewarm-prefixes` and bounded `--gsp-prewarm-concurrency`.
- Prime one request per unique `(routing_key, cache_prefix)` after cache flush and before the measurement timer.
- Exclude priming requests from TTFT, TPOT, ITL, throughput, and request counts.
- Report expected prefix tokens and server-observed cached tokens in `prefix_cache_config` and `cache_report`.
- Add `benchmark/prefix_cache/bench_prefix_cache.py`, a standalone, resumable matrix runner.
- Support cold 0% controls, uniform/Zipf group popularity, repetitions, and deterministic seeds without model-specific scripts.
- Reject missing or inaccurate cache-hit results using a page-aware tolerance:
- Write `manifest.json`, append-only `results.jsonl`, latest-per-tag `summary.csv`, and one log per point. Restarting the command skips only valid points.
- Add a minimal README, workflow/data-structure diagrams, Bench Serving documentation, and registered CPU tests.

### Minimal usage

Start an SGLang server with cache reporting:

```bash
PYTHONPATH=python python3 -m sglang.launch_server \
  --model-path MODEL_PATH \
  --enable-cache-report
```

Run one controlled 32K-input, 512-output, 50%-hit point at concurrency 8:

```bash
python3 -m sglang.benchmark.serving \
  --backend sglang \
  --base-url http://127.0.0.1:30000 \
  --model MODEL_PATH \
  --tokenizer MODEL_PATH \
  --dataset-name generated-shared-prefix \
  --num-prompts 50 \
  --gsp-num-groups 2 \
  --gsp-prompts-per-group 25 \
  --gsp-system-prompt-len 16384 \
  --gsp-question-len 16384 \
  --gsp-output-len 512 \
  --gsp-range-ratio 1.0 \
  --gsp-group-distribution uniform \
  --max-concurrency 8 \
  --request-rate inf \
  --warmup-requests 5 \
  --flush-cache \
  --gsp-prewarm-prefixes \
  --gsp-prewarm-concurrency 1 \
  --seed 42 \
  --cache-report \
  --tag prefix-cache-in32768-out512-hit50-c8 \
  --output-file prefix-cache-single-point.jsonl
```

Run a controlled matrix:

```bash
python3 benchmark/prefix_cache/bench_prefix_cache.py \
  --base-url http://127.0.0.1:30000 \
  --model MODEL_PATH \
  --tokenizer MODEL_PATH \
  --input-lens 32768 65536 \
  --output-lens 512 1024 \
  --cache-hit-percentages 0 30 50 70 90 \
  --concurrencies 1 8 \
  --num-prompts 50 \
  --num-groups 2 \
  --warmup-requests 5 \
  --repetitions 3 \
  --result-dir prefix-cache-results \
  --quiet
```

A single `results.jsonl` entry example

### issue_comments

- Richardyu114 · comment · 2026-09-02T02:57:54Z · [source](https://github.com/sgl-project/sglang/pull/37359#issuecomment-5503648133)

Assume all prewarmed prefixes are expected to fit in HBM, `num_groups=1` and `num_groups>1` have the same first-order token workload. Each request reuses the same number of cached prefix tokens, prefills the same number of uncached suffix tokens, and decodes the same number of output tokens. Therefore, `num_groups=1` provides the cleanest baseline for measuring the direct relationship between cache-hit rate and serving performance. groups increase the physical KV working set, reduce repeated access to the same KV pages, may introduce prefix-content diversity, and can interact differently with routing, scheduling, memory locality, MoE expert selection, and speculative decoding. 

So, `num_groups=1` is the baseline for the current device-resident cache-hit-rate evaluation.  `num_groups>1` provides a more realistic resident multi-prefix workload and enables future extensions for heterogeneous request sizes and hierarchical-cache pressure.
