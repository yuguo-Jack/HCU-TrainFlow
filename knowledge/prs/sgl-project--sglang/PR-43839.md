# [ROCm][Perf] Qwen3.5: online MXFP4 for the BF16 GDN in_proj_qkvz and out_proj

[Upstream PR](https://github.com/sgl-project/sglang/pull/43839) · state: open · merged: False

## Original PR description

## Motivation

This is a ROCm performance change: an opt-in `SGLANG_ROCM_GDN_ONLINE_MXFP4` quantizes the GDN `in_proj_qkvz` and `out_proj` of Qwen3.5 / Qwen3.8 to MXFP4 after load and runs them on AITER MXFP4 GEMMs, because the Quark MXFP4 checkpoints leave both in BF16 and no BF16 kernel beats hipBLASLt on them, worth **-2.0% to -7.0% median TPOT** (+4.8% output tok/s geomean) for Qwen3.8-2.4T-A95B MXFP4 with NEXTN MTP on 8x MI355X, TP8, over 12 serving shapes.

At TP8, `in_proj_qkvz` is a 4608x8192 GEMM per rank and the largest dense weight in every decode and verify step. A new BF16 GEMM tuning table for the MTP shapes gave 99.8% of the throughput of the existing table, and no BF16 kernel we tried beats hipBLASLt on this shape, so the remaining lever is a smaller weight.

## Modifications

- `environ.py`: `SGLANG_ROCM_GDN_ONLINE_MXFP4`, a comma-separated subset of `in_proj_qkvz,out_proj`. The default is empty.
- `quark_w4a4_mxfp4.py`: `AiterMxfp4OnlineLinearMethod`. `quantize_()` quantizes a loaded BF16 weight with the existing `dynamic_mxfp4_quant`, preshuffles the weight (16x16) and the E8M0 scales, and records whether AITER has a tuned preshuffled config for (N, K). `apply()` quantizes the activation with `per_1x32_f4_quant_hip`. Up to 64 rows with a tuned config it runs the Triton `gemm_afp4wfp4_preshuffle`; everything else runs the ASM `gemm_a4w4(bpreshuffle=True)`.
- `qwen3_5.py`: the variable is read at import and ignored with a warning off gfx95x or without `SGLANG_USE_AITER=1`. `prepare_before_cuda_graph_capture` quantizes each named projection before `finalize_fused_in_proj()`. An MXFP4 `in_proj_qkvz` is no longer an `UnquantizedLinearMethod`, so the packed BF16 qkvz+ba GEMM is not built and `in_proj_ba` (N=32) runs alone in BF16. Only unquantized BF16 projections are converted.
- `test/registered/amd/test_qwen35_gdn_online_mxfp4.py`: both TP8 shapes at 1, 4, 16, 31, 32, 64, 65 and 256 rows against a dequantized FP32 reference, which covers both sides of the 32-row scale-layout split and the 64-row kernel cut.
- `environment_variables.mdx`: one row for the new variable.

With the variable unset nothing changes: no layer is touched and the packed BF16 path is built as before.

The PR depends on [Rocm/aiter5998](https://github.com/ROCm/aiter/pull/5998) (merged), which adds the tuned preshuffled config for N=4608, K=8192. The AITER pin in `docker/rocm.Dockerfile` (`e7d2453f`) predates it. On that pin `in_proj_qkvz` takes the ASM path at every size: the output is correct, but we have not measured a gain there. The numbers below use an AITER that includes [Rocm/aiter5998](https://github.com/ROCm/aiter/pull/5998).

## Accuracy Tests

The unit test passes on MI355X: relative error below 1e-2 against the dequantized reference for every shape and row count.

End-to-end, with `in_proj_qkvz` only, NEXTN MTP, on the setup under "Speed Tests and Profiling":

| Eval | BF16 (same image and config) | `in_proj_qkvz` MXFP4 |
| --- | --- | --- |
| GPQA Diamond (thinking, temperature 1.0) | 0.919, 0.929 | 0.914 |
| RULER niah_single_2 64k / 128k | 0.998 / 1.000, 0.996 / 0.998 | 0.998 / 1.000 |

The two BF16 columns are an earlier pair of runs on the same image and config (two BF16 GEMM tuning tables), not part of this A/B. GPQA here has 198 questions and sampling, so a 0.01 difference is within noise. Paired GSM8K, GPQA and NIAH for the PR setting (`in_proj_qkvz,out_proj`) against BF16 on one node are running; I will add them here.

Not tested yet: the unit test and the end-to-end runs used this change applied to v0.5.21 (the class, the method and the test in this commit are byte-identical), not a build of main. Only Qwen3.8-2.4T-A95B MXFP4 was run, and only with NEXTN MTP.

## Speed Tests and Profiling

8x MI355X, TP8, one node, both arms in one job. ROCm v0.5.21 image with #39069, #40708 and #41899, AITER including [Rocm/aiter5998](https://github.com/ROCm/aiter/pull/5998). NEXTN (3 steps, top-k 1, 4 draft tokens), ReplaySSM, `--enforce-shared-experts-fusion`, page size 16, fp8 KV cache, `--mamba-ssm-dtype bfloat16`. `bench_serve` random dataset, range ratio 0.8.
