# :construction: [WIP][llm][npu][quant] Add W4A4 MXFP4 quantization support for Qwen3.5 MoE on Ascend NPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/32602) · state: open · merged: False

## Original PR description

## Summary

Extend Ascend `--quantization mxfp4` to FusedMoE through `NPUW4A4MXFP4OnlineMoEMethod` and `NPUW4A4MXFP4MoEMethod`. Experts use single-level packed MXFP4 weights and FP4 activations. Online Dense layers keep dual-level W4A4; ignored or group-unaligned Dense layers stay BF16. Single-level and dual-level scale contracts remain separate.

## Dependencies and review scope

Updated on 2026-10-10 with ordinary merges; base remains `main`. Branch head: `425b0a9abb`. Includes official main `c55790d38b`.

Merge order: sgl-project/sgl-kernel-npu#638 (Gemma API/wheel) → #32745 → #43739 → **#32602**. This branch contains updated #43739 at `ded4671577`, including #32745 at `cf48b477db`. #32266 stays closed. #36426 remains a separate validation dependency.

Review the W4A4 increment against [the refreshed #43739 branch](https://github.com/TallMessiWu/sglang/compare/junlin_qwen3.5_moe_w4a8...junlin_qwen3.5_moe_w4a4).

## Execution contracts

- Quantize BF16/FP16 experts after loading; preserve packed offline ModelSlim weights. W4A4 weights and scales retain the single-level GMM layout.
- W4A4 dispatch stays BF16. Fused GMM1 + SwiGLU + FP4 requantization is enabled only for ascend_tp; DeepEP retains the unfused path pending hardware validation.
- Route fusion decisions through main's common gate. W4A8 keeps its clamp fallback; W4A4 explicitly rejects `swiglu_limit` because its activation paths do not implement that clamp.
- Preserve singleton Dense L0 scale dimensions before transpose. Comments now describe the actual Dense dual-level / expert single-level policy without claiming it establishes RTN accuracy.

## Current validation

Applicable pre-commit hooks passed. Isolated CPU checks passed W4A4 online/offline post-load layout, BF16 dispatch, fused-vs-unfused and clamp guards, and Dense L0 scale shapes (2D/3D/singleton). The inherited W4A8 method matches #43739 exactly and its regression checks pass. Shared MXFP8 scale checks pass.

These are CPU/static checks, not 910/950 operator, model-load, warmup, accuracy, or performance validation. Full SRT test collection was unavailable in this environment because its serving dependencies are not installed. Target hardware validation remains required.

Remains Draft. Current PR-test gates reject Draft PRs; no Ready conversion is part of this refresh.
