# model: DeepSeek V4.1 vision CP and single-owner image encoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/40219) · state: open · merged: False

## Original PR description

## Problem

The config-level vision guard made context parallelism (CP) entirely unusable for the V4.1-Flash checkpoint, including text-only traffic. Removing that guard alone would be incorrect: the CP runner called the model body directly, bypassing the multimodal merge and leaving image positions with bare text embeddings. Separately, every TP rank ran its own replicated ViT + Aligner: TP8 encoded each image eight times with CP1 and CP8 alike.

This change enables CUDA interleave prefill CP and shares image encoding across the ranks serving the same requests. CP reduces the language-model prefill cost; single-owner encoding reduces the image-encoder cost in both CP modes.

## Design choices

### Merge before sharding

A model-owned `prepare_model_inputs` hook is shared by ordinary `forward` and `_execute_extend_cp`. It merges complete image features into the full extend layout before `cp_shard_model_inputs`; the runner then executes the body and gathers outputs once for logits. Existing request-global image offsets and chunk-intersection logic remain valid, including spans crossing chunk boundaries and their start/newline/end rows.

Shard-first merging would require remapping every image overlap into rank-local feature rows and maintaining separate strategy-dependent offset logic. Moving CP orchestration into the model would instead duplicate the runner's shard/gather and output handling. The hook keeps multimodal semantics in the model and CP execution in the runner.

### Canonical IDs at the model boundary

`embed_mm_inputs` receives a clone of the hash-bearing IDs: those hashes identify image spans and cache entries, and the shared embedder clamps its input in place. The model body, logits and routing buffer receive separately canonicalized `image_token_id` values, sharded in the same layout as the embeddings. This also preserves the Engram image bypass. Canonicalizing before the merge would lose image identity; passing hashes into the body would break token semantics. Scheduler IDs are never mutated, preserving radix/cache identity and full prompt context.

### Scope the guards to supported execution

Vision + prefill CP requires CUDA interleave. PP and MoE A2A retain the existing vision restrictions because this input-preparation change does not implement their missing vision integration. NPU/zigzag remain rejected: interleave hashing/routing order and the V4.1 low-ratio attention path cannot simply be reused for zigzag ownership.

CP prefill runs eagerly. Automatic prefill graphs resolve to eager; explicitly requested prefill graphs reject because their input/replay path bypasses the new merge contract. Encoder SWA replay remains unsupported. DSpark + decoder SWA replay also rejects because the CP runner lacks the tail-aware gather/logits handling required for shortened replay outputs; ordinary DSpark remains supported. Removing all guards would expose execution paths beyond the implemented input/layout contract.

### Partition admission without starving FCFS

`PrefillAdder` separates multimodal requests from positional-embedding override requests. Overrides trigger an early embedding lookup over the batch's raw IDs, which cannot index multimodal placeholder hashes. Same-request multimodal/embedding conflicts and replacement overlap with image placeholders are rejected before that lookup.

The scheduler breaks at the first incompatible queued request. Using `continue` lets later compatible requests repeatedly pass an older incompatible request; under chunked prefill, those admissions can perpetuate the current batch class and starve FCFS work. Ending admission lets the current work drain so the waiting class can advance.

### Single-owner encoding with collective agreement

For each image, `hash % R` elects an owner within the group of R ranks executing the same request. At TP8/DP1, R=8 for both CP1 and CP8; a singleton CP1 group would leave TP duplication intact. ViT weights remain replicated. Different owners encode their misses concurrently before ordered full-span broadcasts. A fixed rank-0 encoder would eliminate redundant work but serialize all images on one GPU.

The protocol has six phases:

1. Build an ordered manifest of overlapping `(hash, span_length)` keys, validate geometry, and pin local cached tensors.
2. Exchange manifests and agree on one action per key: all-rank local hit, owner-cache broadcast, or owner-encode broadcast.
3. Allocate receives, encode all owned misses, validate/synchronize tensors, and agree on readiness before payload transfer.
4. Broadcast complete spans in manifest order, with every rank participating in each agreed transfer.
5. Commit features, slice chunks and validate masks, then fence before text embedding, whose vocabulary lookup can perform a TP all-reduce.
6. Merge embeddings and canonicalize IDs, then fence before entering the model body or CP sharding.

A local cache hit must never independently skip a collective. Only the agreed all-hit action skips payload transfer; image-containing cache-hit chunks still perform agreement. Catchable preparation errors become a common error before peers enter the next collective stage.

Full-span broadcast reuses the existing cache and chunk assembler for CP1 and CP8. Feature scatter could reduce delivery bytes, but requires shard-specific row mapping and different cache/assembly semantics; it is deferred. Text, decode and warm repeats with no image-span work add zero collectives. Cache eviction can require re-encoding; raw-input transport and its consumer acknowledgements retain their existing lifecycle.

## Performance

Measurements use 8×B200, TP8/EP8, checkpoint revision `dba1be0a`, CUDA interleave CP8 versus CP-off (CP1). These are the recorded feature-validation runs, preceding the upstream merge at the current PR head. Image matrix cells use eight requests, distinct images, cache flush per cell and four output tokens; K is images per request and C is concurrency.

### Phase 1: merge-before-shard, replicated encoder

| Check | Result |
|---|---|
| Text, CP1 → CP8, 32k | Prefill 55.9k → 104.1k tok/s (**+86%**); TTFT 917 → 335 ms (−64%). |
| Images, 16k–48k prompt tokens, C=1/4/8 | CP8 TTFT **−6…−15%**; prefill throughput +9…+18%. |
| GSM8K, full 1,319 | CP1 96.82% / 96.89%; CP8 97.04%; **100% stop**, zero truncation/errors. |
| MMMU-Pro, full 1,730, standard 10 options | CP1 **66.36%** vs CP8 **66.07% / 66.65%**: ±0.29 pp, within the 0.58 pp same-server repeat variation; zero errors. |
| Vision smoke / DSpark | 14/14, including OCR and chunk-768 span crossing; DSpark image smoke 14/14 with CP off and on. |

### Single-owner encoder: replicated → shared encoding

| Check | Result |
|---|---|
| Cold encode calls, CP1 and CP8 | **8K → K** across the TP group; identical warm repeat: zero calls. |
| K48/C1, same-session controls | CP8 **3.37 → 1.767 s (−48%)**; CP1 **3.81 → 2.33 s (−39%)** TTFT. |
| 18 matrix cells vs archived phase-1 controls | K=16/32/48 × C=1/4/8 × CP1/CP8: TTFT **−35…−46%**, prefill throughput **+56…+100%**. |
| Vision smoke | **14/14 × 3** configurations: CP1, CP8 and CP8 with chunk size 768. |
| GSM8K, full 1,319 × 4 runs | 96.74–97.04%; **100% stop**, zero truncation/errors. |
| Text regression | Saturated cells within **±1.8%**; arrival-limited latency shows run jitter with unchanged throughput. |

Notes: CP1 misses the 2.1–2.2 s target because `hash % 8` imbalances owner work; K=1 pays +7…15 ms; tiny chunk-768 K16 requests pay +4.5…6% TTFT; a fatal encode error causes the same bounded whole-server teardown as any forward exception on main, with no request-level recovery.

## Known limits / follow-ups

- **NPU zigzag:** implement strategy-aware hash/routing layouts and validate the low-ratio attention path before enabling vision CP.
- **CP prefill graphs:** carry merged embeddings and canonical IDs through stable capture/replay buffers and preserve gather/logits semantics.
- **Balanced owner assignment:** reduce the busiest owner's image count while preserving deterministic planning and cache agreement.
