# [HiCache] Resolve derived sidecars over every source transfer

[Upstream PR](https://github.com/sgl-project/sglang/pull/43110) · state: open · merged: False

## Original PR description

## Motivation

#42633 lets a buffer-mode component stage one storage pool in several `BACKUP_HOST` transfers (`_ExtraPoolFullComponent` in its tests splits its pool in two), and `BufferModePipeline._storage_transfers` merges those transfers into one key span for the storage write. Every place that resolves a derived sidecar's indices from its source pool still takes only the first transfer of that pool:

- `HostPoolGroup.resolve_host_transfers` (backup D2H): the sidecar copies only the first transfer's pages, while the storage write persists the sidecar under the whole merged span, so the tail pages are written from stale host slots and believed stored.
- `HybridCacheController._resolve_device_transfers` (load H2D): the sidecar loads only the first transfer's pages.
- `HybridCacheController._resolve_sidecar_nonkv_derived_pool_transfers` (storage write): correct today only because buffer mode merges first.
- `UnifiedRadixCache._build_sidecar_transfers`: maps the source pool to a fixed SWA/Mamba component and takes that component's first transfer, so a sidecar of a component-owned pool fails with `Unsupported sidecar indices source pool`.

The stock pools never trigger this: SWA, Mamba, FULL and the NPU C128 component all emit a single transfer per pool, so `main` is not affected today. This closes the gap in the multi-transfer contract #42633 introduced before a component relies on it.

## Modifications

- Add `merge_source_transfers` next to `PoolTransfer`: every independent transfer of a pool as one span in transfer order; a lone transfer is returned as is, so single-transfer sidecars keep aliasing their source tensors.
- Resolve derived sidecars through it in all four places above. Explicit sidecar device indices are preserved, and only source transfers own and release host allocations.
- `_build_sidecar_transfers` finds the source by pool name across all component transfers instead of a fixed component map.
- `HybridCacheController._transfer_num_bytes` sums a source pool's transfers instead of keeping the last one.

## Accuracy Tests

- `test_unified_radix_cache_unittest.py::test_buffer_only_split_pool_sidecar_storage_roundtrip`: a derived sidecar of `_ExtraPoolFullComponent`'s split pool, real CUDA D2H and file storage; every persisted sidecar page must match its source page. Fails on `main` in all 13 FULL/FULL+SWA configurations (`Unsupported sidecar indices source pool`), and with only the `group.py` change reverted (sidecar pages differ from source pages).
- With the change: `test_unified_radix_cache_unittest.py -k "buffer_only or split_pool_sidecar"` 137 passed (configuration skips only); `test_unified_hicache_regressions.py`, `test_mem_pool_host.py`, `test_buffer_mode_sidecar.py`, `test_hicache_staged_write_back_dispatch.py`, `test_storage_prefetch_lifecycle.py` 69 passed, 1 skipped. Tested on B300.

## Speed Tests and Profiling

No model forward or kernel changes. Index tensors are concatenated only when a pool has several transfers; the single-transfer path is unchanged.
