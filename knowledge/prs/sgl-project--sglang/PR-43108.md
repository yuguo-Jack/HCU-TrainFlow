# [HiCache] Defer query beliefs until the rank-synchronized hit drain

[Upstream PR](https://github.com/sgl-project/sglang/pull/43108) · state: open · merged: False

## Original PR description

## Motivation

In `buffer_only` mode, aborting a prefetch while its storage query is still running can consume rank-local pool hit verdicts before their MIN reduction. One TP rank then believes the prefix is stored and skips a backup, while another launches it. Synchronizing the query later does not undo the divergent D2H queues.

Cancellation can also make one rank skip the query entirely. Its full hash chain stays unset even after the hit count and pool verdicts are reduced. When the synchronized drain invalidates existing beliefs, the querying rank removes them while the skipped rank returns early and retains them, again producing different backup decisions.

Reproduced on main `9f5d8712514c2d9dd29c76c6080774db3fd50aa2` with real two-rank Gloo, CUDA pools, and file storage: after cancellation, ranks reported coverage `[true, false]`, launched backups `[0, 1]`, and retained pending D2H writes `[0, 1]` after the query drained. A Qwen3-0.6B TP=2 HTTP `/generate` → `/abort_request` reproduction also observed the divergent coverage. The file backend delays one rank's real query to make the race deterministic; it does not fabricate query results.

## Modifications

Consume query evidence only when draining the rank-synchronized hit queue, including terminated operations and operations whose requests have already been removed. Abort cleanup no longer mutates beliefs from unpublished query results. Before reducing a query result, reconstruct the full chain from the operation tokens, prior hash, and page size if the local query was skipped. This does not query storage or add a collective; ranks that already queried reuse their computed chain.

Add a real CUDA/file-storage regression that cancels between the query and publication, checks that a backup remains eligible, and verifies that the synchronized hit drain heals the beliefs and retires the redundant backup. Use the actual `PrefetchOperation` in the existing outcome-accounting fixture. Add a real two-process Gloo/file-backend regression in which one worker queries and the other skips after cancellation, with pre-existing beliefs and a non-empty prior hash. Add a GPU regression covering cancellation before the worker starts and the subsequent backup admission.

## Accuracy Tests

- Qwen3-0.6B TP=2 HTTP cancellation: coverage changes from `[true, false]` before the fix to `[false, false]` after the fix while one rank still holds a local query result.
- Before/after two-rank reproduction: divergent `[0, 1]` pending D2H writes become `[0, 0]`; both ranks make the same backup decision.
- Skipped-query two-rank CUDA/file-storage reproduction: before the chain fix, coverage after the synchronized drain was `[false, true]` and queued backups were `[1, 0]`; afterward both chains match, coverage is `[false, false]`, and queued backups are `[1, 1]`. The registered two-process regression also fails before the fix and passes after it.
- `test_unified_radix_cache_unittest.py -k "abort_defers_query_beliefs or cancelled_query_invalidates_existing_beliefs"`: 10 passed, 28 configuration skips.
- `test_storage_prefetch_lifecycle.py` and `test_buffer_mode_sidecar.py`: 15 passed, 14 subtests passed.
- Tested on H200 with actual CUDA transfers and file I/O. Existing third-party deprecation warnings and an environment-level pytest configuration warning were reported.

## Speed Tests and Profiling

No model forward or kernel changes. No performance claim; no benchmark run. Belief healing moves to the existing synchronized drain and adds no collective.
