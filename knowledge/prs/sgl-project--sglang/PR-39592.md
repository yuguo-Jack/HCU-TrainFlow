# [dLLM] Preserve prompt tails and literal mask tokens across prefix reuse

[Upstream PR](https://github.com/sgl-project/sglang/pull/39592) · state: open · merged: False

## Original PR description

**Incremental review:** [Files changed](https://github.com/sgl-project/sglang/pull/39592/files) against `main`.

dLLM prefix lookup can consume a partial prompt block and its synthetic masks when a cached prompt contains the same literal mask IDs. Literal mask IDs in a real prompt can also be denoised and emitted as generated tokens, causing KV accounting errors and a serving crash.

Bound cache lookup by complete real-token blocks and classify the request after matching its cache prefix. Carry an explicit committed-position mask into LowConfidence, JointThreshold and JointThresholdInDel so literal prompt IDs and previously emitted outputs stay immutable after retraction. Repeated denoising no longer subtracts the current block from the reported cached-token count. The change preserves autoregressive lookup and logprob boundaries.

The GPU/HTTP results below are historical qualification of the previous revision; they were not rerun for the October 10 refresh.

| Test | Before | After |
| --- | --- | --- |
| Real RadixCache collision, five prompt tokens with block size 4 | Matches 8 tokens and skips the tail | Matches 4; tail preserved |
| SDAR HTTP prompt containing a literal mask in a full block | Service exits with KV pool overcount on baseline and initial lookup-only patch | Cold/hot requests complete; prompt remains intact |
| Prefix boundary, FDFO KV reuse, and literal-prompt algorithm regressions | Original boundary matrix: 122 failures out of 210 | 11 tests and 228 subtests pass |
| LowConfidence, FDFO, radix enabled | — | 8 prompt cases plus synthetic-mask collision pass |
| LowConfidence, explicitly synchronous (`--no-dllm-fdfo`) | — | Same 9 cases pass; exact output IDs/text match FDFO |
| LowConfidence, FDFO, radix disabled | — | Same 9 cases pass; exact output IDs/text match cache-enabled run |
| JointThreshold, FDFO, radix enabled | — | Same 9 cases pass; cold/hot IDs/text identical |
| JointThreshold, explicitly synchronous | — | Same 9 cases pass; exact IDs/text match JointThreshold FDFO |
| HTTP cached-token accounting | Negative counts during repeated denoising | Nonnegative and equal to the first traced prefix match |

HTTP tests use `JetLM/SDAR-1.7B-Chat-b32`, BF16, TP=1, Triton, CUDA graphs disabled, block size 32, threshold 0.95, greedy sampling, 32 new tokens, and `ignore_eos=true`. Hardware: RTX PRO 4000 Blackwell 24 GB; Python 3.12, PyTorch 2.13.0+cu130, sglang-kernel 0.4.7. Each configuration runs 19 actual `/generate` requests. An observation-only wrapper records cache matches after `Req.init_next_round_input`.

### October 10 review follow-up

Merged main `c55790d38ba0c41170cec8993e7a85d5c687149c` and addressed the remaining review items:

- Batch CPU-known committed lengths into the same pinned, nonblocking transfer as positions. LowConfidence uses `torch.where` to exclude committed positions. Algorithms read the declared ForwardBatch field directly, and test doubles provide it explicitly.
- Retraction phase selection and position masks include both prompt tokens and committed outputs, independently of KV residency.
- JointThresholdInDel uses the explicit immutable mask for state initialization and excludes those positions from mask counts and transfers, while retaining its contiguous-prefix fallback when metadata is absent.
- Existing registered CPU test files now contain regressions for a literal-mask cache collision, immutable literal prompts in synchronous/FDFO decoding, retracted outputs, repeated-pass cached-token accounting and InDel behavior.

All scoped pre-commit checks passed, including CI registry validation. CPU source execution passed 25 exact repository algorithm tests, committed-token phase/prefix controls over 72 prompt/output layouts, three actual position-branch controls and the repeated-pass cache-accounting guard. Negative controls reproduced the literal-prompt InDel failure; these tests also caught and corrected its mask-count/transfer path. This source-level run omits package initialization and native dependencies. Full registered-suite and HTTP reruns require the complete SGLang environment and were not executed in this refresh; no GPU performance or memory measurement is claimed.
