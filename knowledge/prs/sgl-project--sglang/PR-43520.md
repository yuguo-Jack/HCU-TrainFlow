## Original PR description

# [Perf] Batch detokenizer outputs by tokenizer worker

## Summary

In multi-HTTP-worker mode, the detokenizer sends one IPC message per request.
When requests in the same output batch belong to the same tokenizer worker,
this repeats serialization and IPC work.

This PR adds an opt-in path that sends one sub-batch per tokenizer worker.

Closes #43096.

## Implementation

- Add `SGLANG_ENABLE_BATCHED_DETOKENIZER_OUTPUTS`, disabled by default.
- Group outputs by tokenizer-worker destination while preserving request order.
- Build all sub-batches before sending. If an output cannot be split, use the
  existing per-request path for the complete source batch.
- Propagate send failures without retrying or resending completed groups.
- Cache `msgspec` field descriptors by output type.

With the flag disabled, the existing send path is unchanged.

## Validation

The registered test suite passes 20/20 in both msgpack and pickle modes.

| Case | Expected behavior | Result |
| --- | --- | --- |
| Flag enabled, requests share a destination | One ordered sub-batch per destination | Passed |
| Flag disabled | One IPC message per request | Passed |
| Output type cannot be split | Fall back before the first grouped send | Passed |
| A send fails | Propagate the error without retry or resend | Passed |
| The same output type is split repeatedly | First field lookup misses; later lookups hit the cache | Passed |
| ZMQ round trip | Request IDs and output fields remain aligned | Passed |

Focused pre-commit checks pass for all changed files.

## Performance

End-to-end tests used one NVIDIA A30, Qwen2.5-0.5B-Instruct, four tokenizer
workers, one detokenizer worker, msgpack IPC, and 128 input/output tokens.
Values are medians of three OFF/ON trials.

| Workload | Output tokens/s OFF → ON | p50 TTFT OFF → ON, ms | p99 TTFT OFF → ON, ms | p50 ITL OFF → ON, ms |
| --- | ---: | ---: | ---: | ---: |
| Concurrency 16 | 5,731 → 5,733 | 29.77 → 30.64 | 35.97 → 34.85 | 2.52 → 2.52 |
| Concurrency 128 | 9,701 → 21,773 | 101.27 → 106.13 | 408.86 → 404.25 | 11.77 → 3.87 |
| Concurrency 256 | 6,888 → 25,943 | 295.14 → 204.34 | 2,577.22 → 509.51 | 39.12 → 6.16 |
| Offered rate 40 req/s | 4,858 → 4,865 | 12.36 → 12.42 | 22.95 → 23.35 | 2.60 → 2.60 |

All 24 trials completed: 33,792 requests, 4,325,376 output tokens, and no
request errors.

In the repeated fixed-rate test, p50 TTFT is effectively unchanged
(12.36 → 12.42 ms), so batching does not add a measurable fixed-load penalty.

The IPC benchmark uses the production split, serialize, send, receive, and
deserialize path. Values are medians of five trials.

| Batch / workers | Messages OFF → ON | Msgpack OFF → ON, µs | Pickle OFF → ON, µs |
| --- | --- | ---: | ---: |
| 1 / 1 | 1 → 1 | 16.1 → 17.9 | 23.8 → 25.6 |
| 4 / 4 | 4 → 4 | 63.5 → 63.3 | 95.9 → 104.2 |
| 16 / 4 | 16 → 4 | 252.6 → 170.3 | 390.8 → 199.1 |
| 64 / 4 | 64 → 4 | 1,006.0 → 275.8 | 1,581.0 → 282.9 |
| 256 / 4 | 256 → 4 | 4,032.2 → 697.0 | 6,193.3 → 653.0 |
| 256 / 16 | 256 → 16 | 4,053.6 → 1,101.3 | 6,537.7 → 1,163.3 |

Caching reduces the 500-iteration splitter profile from 1.313 s to 0.263 s.

## Scope

- The feature remains disabled by default.
- The end-to-end result covers one model and one GPU type.
- High-concurrency throughput and ITL improve; TTFT does not improve at every
  concurrency.
- The GitHub CI matrix is pending the required `run-ci` label.
