# fix(spec): don't inherit target quantization for an unquantized EAGLE3/MTP draft

[Upstream PR](https://github.com/sgl-project/sglang/pull/28196) · state: open · merged: False

## Original PR description


## Motivation

When the draft model quantization is not given, `ServerArgs._handle_missing_default_values` copies the target quantization onto the draft:

```python
if self.speculative_draft_model_quantization is None:
    self.speculative_draft_model_quantization = self.quantization
```

`ModelConfig._verify_quantization` then only overrides this inherited value when the draft *checkpoint itself* carries a quantization config. An unquantized EAGLE3/MTP drafter has none, so the inherited target quantization is never cleared and the draft is loaded as if it were quantized. With a quantized verifier + unquantized drafter the draft weight load fails before the server comes up:

```
ValueError: Cannot find the config file for awq
```

Relationship to #22588 (open): that PR handles the explicit `--speculative-draft-model-quantization unquant` flow and edits the same `_verify_quantization` region. It does not cover this inherited case. The two are complementary (`unquant -> None` vs `inherited-with-no-checkpoint-config -> None`) and can coexist, but they will textually conflict near the same lines, so they should be coordinated: whichever lands first, I will rebase the other onto it (happy to instead fold this clause into #22588 if the maintainers prefer a single PR for draft-quant handling).

## Modifications

In `_verify_quantization`, after the checkpoint quant config has been parsed, clear `quantization` for a draft model whose own checkpoint has no quant config:

```python
# An unquantized draft/MTP checkpoint must not inherit the target's
# quantization, or draft weight loading fails on a quantized verifier.
if self.is_draft_model and quant_cfg is None and self.quantization is not None:
    logger.info(
        f"Draft model has no quantization config in its checkpoint; "
        f"loading it unquantized instead of the inherited '{self.quantization}'."
    )
    self.quantization = None
```

The common path is unchanged: it only fires for `is_draft_model` and only when the draft checkpoint has no quant config of its own (a genuinely quantized draft keeps its quantization), and the decision is logged. It is conservative and deliberately also clears an explicit `--speculative-draft-model-quantization X` when the draft checkpoint carries no matching config; that matches vLLM, which derives the draft quant from the checkpoint (no config means unquantized), and it turns a hard load crash into a working unquantized draft (now visible in the log rather than silent).

Adds two cases to the existing `test/registered/quant/test_quant_config_parsing.py`: a draft with no checkpoint quant config drops the inherited quantization, and a non-draft model is left untouched.

## Accuracy Tests

Unit test `test/registered/quant/test_quant_config_parsing.py::TestDraftQuantInheritance`: 2 passed (and the core case fails on `main` without the fix, confirming it guards the bug).

Real EAGLE3 spec-decode E2E (verifier `Qwen/Qwen3-8B-AWQ`, drafter `Tengyunw/qwen3_8b_eagle3` unquantized, `--quantization awq --dtype float16 --speculative-algorithm EAGLE3`):

| case | before fix | after fix |
|---|---|---|
| draft quant unspecified (inherits `awq`) | server **does not start**: `ValueError: Cannot find the config file for awq` | server **UP**, generates `" Paris. The capital of Italy is Rome. The capital of Germany is Berlin."` (HTTP 200) |
| explicit `--speculative-draft-model-quantization awq` on the unquantized drafter | (same crash) | server **UP**, same output; the explicit-but-unbacked value now resolves to unquantized, matching vLLM |
| unquantized verifier (`Qwen/Qwen3-8B`, no `--quantization`) + same drafter | server **UP**, generates correctly | server **UP**, generates correctly (nothing to inherit, fix is a no-op) |
