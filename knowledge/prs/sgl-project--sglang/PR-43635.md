# feat(hicache): add indexed KVCR L3 storage with multi-pool restore

[Upstream PR](https://github.com/sgl-project/sglang/pull/43635) · state: open · merged: False

## Original PR description

## Motivation

Add KVCR as an optional ordinary HiCacheStorage L3 backend using its current indexed-region API. SGLang continues to own its GPU/host cache, radix state, scheduling, and host-to-device copies; KVCR owns the deposited DRAM cache and uses NIXL/UCX for local/peer delivery.

This is **not linker mode or direct-HBM restore**:

```text
Backup:  HBM -> SGLang HiCache host pages -> KVCR-owned DRAM
Restore: local/peer KVCR DRAM -> locked HiCache host pages -> HBM
```

Remote reads do not need a second destination-side KVCR DRAM allocation, and unpinned SGLang host pages are never offered as peer sources.

Related prior HiCache work: #36409. Lin's newer multi-pool branch already handles multiple pools and trailing-pool hints; this draft is not presented as the first implementation of either capability.

## Modifications

- Register the optional `kvcr` backend and page-first configuration, without adding KVCR as a mandatory SGLang dependency.
- Register physical pool components once and describe IO using `MemoryRef` indices. One model/layout/shard-scoped pool/page key groups its components.
- Preserve request hints through scheduler, unified radix cache, ordinary/hybrid controllers, trailing reads, and deferred prefetch tickets. Keep the LMCache override signature compatible.
- Preserve legal resume-boundary sets and intersect them across ranks; scalar maxima are insufficient for sparse trailing/checkpoint state.
- Add backend-opt-in combined KV/ALL_PAGES-sidecar reads and backups, strict per-pool result validation, and configurable read batching. Keep query/write batch sizes and failed-batch collective/ACK sequencing intact.
- Add opt-in replicated-MLA sharing: TP0 owns one KV/indexer copy while every rank restores into its own host destinations. Reject sharded auxiliary pools, CP>1, PP>1, and heterogeneous head splitting in that mode.
- Drive idle-source progress independently, retain completions for their submitting caller, and require terminal native results before returning buffers. Exit the worker on uncertain native state rather than recycling potentially in-flight memory.
- Add opt-in prefix-recency alignment, storage metrics, byte verification, and diagnostic telemetry; keep expensive diagnostics disabled by default. Log scheduler GC completion for the companion startup integration.
- Add CPU adapter/controller regressions, a manual real-NIXL host-byte gate, and a backend README with ownership, configuration, and limitations.

## Validation and Accuracy Tests

- CPU adapter/controller regressions cover unequal-sized components, physical-page validation, incomplete sidecars, large/partial read batches, backup ACKs, sparse checkpoints, shared MLA, request hints, and completion ownership.
- Earlier final-source validation: **33 adapter/controller tests passed** and **6 real-NIXL host-byte tests passed** with default UCX selection and an 8 GiB `/dev/shm`. The initial 64 MiB shared-memory fixture failed; increasing ordinary container shared memory resolved it. This host-byte gate is not GPU/model-performance evidence.
- End-to-end GLM5.3: two independently complete TP4 replicas on separate B200 hosts, CP1/PP1, ordinary HiCacheStorage, and in-process `python -m dynamo.sglang`. Head-only probes restored 8,192 tokens and matched source/restored/local-HBM outputs.
- Fresh publication validation on the retained Linux runtime: **33 adapter + 7 sidecar/boundary + 11 prefetch-ticket CPU tests passed**, plus **6 real-NIXL byte tests passed**. The final publication cleanup was formatting-only. Pinned isort, Ruff lint/format checks, and `git diff --check` passed on the scoped patch. Full upstream CI and broad-model accuracy are not claimed.

## Speed Tests

Fresh matched three-arm Agent Loadgen campaign, 15-minute workload per arm. A moved turn means the session's request landed on a different complete serving replica from its preceding turn.

| Backend | Successful requests | Moved turns | Moved TTFT p50 / p90, ms | Overall TTFT p50 / p90, ms |
| --- | ---: | ---: | ---: | ---: |
| KVCR L3 | 5,893 / 5,893 | 105 | 160.6 / 291.4 | 89.0 / 163.5 |
| Mooncake L3 | 6,009 / 6,009 | 115 | 170.4 / 305.3 | 84.0 / 150.2 |
| L2-only | 6,057 / 6,057 | 96 | 416.2 / 1,270.6 | 77.1 / 163.2 |

All 17,959 completed requests were joined to terminal runtime records with expected output lengths. The tested KVCR configuration used 128 GiB per complete replica, replicated MLA sharing, combined transfers, and 512-page reads. All arms shared the same SGLang/Dynamo base and startup-GC treatment.

These are **combined-stack, unpaired workload results**, not per-commit attribution or a statistical equivalence claim. KVCR's overall TTFT is higher than Mooncake's; some input-length groups also favor Mooncake. There were no moved >=64K requests in the L3 arms. Mooncake may place data on the destination host, so a moved turn alone does not prove an inter-host physical read. No implementation-only A/B against Lin's latest branch was performed.

## Dependencies, Limitations, and Review Order

- Requires a separately installed KVCR build exposing indexed `RegionDescriptor`/`MemoryRef` APIs. The optional larger startup budget additionally needs the KVCR companion.
- Cross-replica source discovery needs a compatible hint producer; the Dynamo companion supplies the in-process path. Hints are advisory, not source leases.
- The new storage identity is not promised to interoperate with older descriptor/segment-key adapters.
- Shared MLA is an explicit replicated-byte assumption, not generic DSV4/SWA/state-pool support. End-to-end validation here is GLM5.3, not every hybrid architecture.
- PP>1 and heterogeneous TP head splitting are rejected by this backend. Multi-node engines and other engine integrations remain outside the demonstrated scope.
- Uncertain-transfer termination is deliberate memory-safety behavior with an availability cost; no framework-page quarantine/pinning capability is added.
- Backend capability defaults preserve existing storage paths. Review `storage/kvcr/{layout,hints,kvcr_store}.py`, then controller batching/boundary changes and tests.
- Raw benchmark traces, deployment addresses, and local experiment artifacts are intentionally excluded from this patch.

Companion PRs:

- [Dynamo: in-process hints and startup GC](https://github.com/ai-dynamo/dynamo/pull/16117).
- [KVCR: optional large-registration startup budget](https://github.com/ai-dynamo/kvcr/pull/82).

The measured SGLang base was `5cbf949839b1fc73802d20670943ccbeb805d3f2`; this draft targets upstream `main`. Review the companions as a coordinated stack, while retaining the stated independent/default behavior of each change.
