# [Fix] Preserve HTTP errors for non-streaming /v1/messages

[Upstream PR](https://github.com/sgl-project/sglang/pull/43796) · state: open · merged: False

## Original PR description

## Motivation

Non-streaming `/v1/messages` requests currently turn an upstream `HTTPException(503)` into `500 api_error`. In particular, a queue-full rejection loses its overload status because the Anthropic handler catches it as a generic exception.

This fixes the non-streaming follow-up explicitly listed in #43779. It is independent of that PR and can be merged separately.

## Modifications

- Catch `HTTPException` before the generic exception handler and preserve its status code, mapping it through `ERROR_TYPE_MAP`. A queue-full rejection now returns `503 overloaded_error`.
- Reuse the existing message sanitization: 4xx messages retain useful details after sanitization, while all 5xx responses continue to return `Internal server error`.
- Log the original status code and detail server-side without duplicating the generic error-response log.
- Add regression coverage for raised exceptions, including integer and `HTTPStatus` 503, message sanitization, diagnostic logging, and unexpected exceptions. Existing returned-error tests continue to run.

The exception handler covers both internal request conversion and non-streaming execution, so HTTP exceptions raised during conversion also retain their status. Streaming behavior is unchanged.
