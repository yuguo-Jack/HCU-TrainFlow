# [diffusion] IPC all-to-all: keep exported buffers out of expandable segments

[Upstream PR](https://github.com/sgl-project/sglang/pull/43584) · state: closed · merged: True

## Original PR description

## Motivation

On 4xGB300 (aarch64, NVL fabric), `sglang serve --model-path nvidia/Cosmos3-Nano --num-gpus 4 --cfg-parallel-size 2 --ulysses-degree 2` in the default auto mode, with `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`, never becomes healthy. After the auto-residency probe, `GPUWorker._release_warmup_pool` drops the IPC all-to-all staging buffers and calls `empty_cache`, which raises:

```
gpu_worker.py, in _release_warmup_pool -> torch/cuda/memory.py, in empty_cache
RuntimeError: std::get: wrong index for variant      (some ranks)
RuntimeError: bad optional access                    (others)
```

The ranks diverge, and the next all-to-all hangs until the NCCL watchdog kills rank 0.

| Same command on GB300 | Result |
|---|---|
| expandable segments on + IPC all-to-all on (default) | crashes within 70 s |
| expandable segments off | healthy |
| `SGLANG_DIFFUSION_IPC_A2A=false` | healthy |

The IPC transport allocates its staging and flag buffers from the caching allocator and exports them with `torch.multiprocessing.reductions.reduce_tensor`. Under expandable segments those exports are expandable-segment handles (fabric handles on GB-class systems). Freeing such a segment later breaks the allocator. B200 (fd handles) is not affected.

## Modifications

- `ipc_shareable_zeros()` allocates with `expandable_segments` switched off for the allocation (`torch._C._accelerator_{get,set}AllocatorSettings`), restoring it afterwards. It is a plain `torch.zeros` when expandable segments are off.
- Every IPC-exported buffer uses it: the 2-rank transport's flag, timeout flag and staging buffers, and the N-rank transport's in/out boxes and counters. Non-exported scratch is unchanged.

## Accuracy Tests

No numerical change (same buffers, different segment type).

## Speed Tests and Profiling

GB300, same command as above with this PR: healthy after 80 s (the probe ran: `auto residency probe (1024x1024x81f, 4/35 steps)`). A T2I request then returns 200 in 2.54 s, with no errors in the log.
