## Motivation

<!-- Describe the purpose and goals of this pull request. -->

This PR fixes two bugs in the decode hicache:

1. The original code could cause memory leaks when handling two types of abort requests (kv_poll == Failed or HiCacheRestoreResult.FAILED).
2. The original code did not account for the scenario where len(rematch.device_indices) > pm.decode_prefix_len when transferring prefetched data from storage to L1, which would cause an error in the _commit_hicache_local_restore_to_req function.

We (with chen_qian [2803794751@qq.com](mailto:2803794751@qq.com)) verified the correctness of these fixes through a stress test of 4,600 requests by frequently triggering both types of aborts.

- IteratorandIterator · comment · 2026-09-10T07:18:28Z · [source](https://github.com/sgl-project/sglang/pull/37103#issuecomment-5614694581)

> Could you please share the exact experimental configuration you used when you encountered this bug? I'd like to reproduce the issue on my end to investigate further.

Sure. Our GPU configuration is 8xH20, and the model is GLM5.2-W4AFP8. However, this bug should be unrelated to the model or GPU type; it can be reproduced even with just two GPUs, with one handling prefill and the other handling decode. The reproduction method is quite simple: just enable PD disaggregation and decode hicache, and then abort some requests during inference (for example, by interrupting a request with Ctrl+C, or when the prefill node is under too much load, causing a KV transfer timeout and subsequent abort). However, make sure not to trigger a retract, as that also causes a memory leak—I have submitted a separate fix for that in PR #37100. The higher the request concurrency and KV hit rate, the more easily this issue is triggered. Eventually, you will encounter a situation where evictable_size > 0 (assuming evictable_size is N), but the actual call to the evict function fails to evict M tokens (where M < N).
