# fix(benchmark): avoid caching partial Mooncake downloads

[Upstream PR](https://github.com/sgl-project/sglang/pull/41394) · state: open · merged: False

## Original PR description

## Motivation

`download_and_cache_file()` wrote streamed responses directly to the final cache path. If a Mooncake trace download failed after partial data had been written, the partial file remained and was treated as a cached dataset on the next load.

Fixes #41244

## Modifications

- Download into a same-directory `.part` file.
- Publish the final cache path with `os.replace()` only after the response is fully written.
- Remove the temporary file when the download fails and preserve any existing final file.
- Add CPU-only regression tests for interrupted downloads, successful downloads, and existing-file preservation.
