# [Fix] Use CuTeDSL MLA for draft prefill and extend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43417) · state: open · merged: False

## Original PR description

## Motivation

Selecting `--speculative-draft-attention-backend cutedsl_mla` uses CuTeDSL MLA for draft decode, but the draft-prefill/extend factory still constructs `TRTLLMMLABackend` and identifies it as `trtllm_mla`. The existing `CuteDslMLABackend` already inherits prefill/extend support, so this fallback prevents the requested backend from serving draft extend.

## Modifications

- Construct `CuteDslMLABackend(skip_prefill=False)` for draft prefill/extend, assert that the draft model uses MLA, and preserve the `cutedsl_mla` backend identity through the wrapper.
- Register `cutedsl_mla` with the existing TRTLLM MLA model-dispatch handler. Ordinary prefill selects `MHA_CHUNKED_KV` with unabsorbed head dimensions; decode and speculative draft extend select MLA.
- Extend the existing CPU regression suite to exercise the real factory with a mocked backend constructor, wrapper identity, rejection of non-MLA models, and model dispatch.

This reuses FlashInfer's `backend="cute-dsl"` path and existing prefill plumbing. No kernel implementation or backend defaults change.

## Accuracy Tests

The backend-decision suite passes: **11 tests and 3 subtests**.

```bash
PYTHONPATH=python python -m pytest test/registered/unit/test_split_attention_backend_decisions.py -q -x -o addopts=''
```

These are CPU dispatch and factory tests. GPU end-to-end accuracy has not been tested for this isolated change.
