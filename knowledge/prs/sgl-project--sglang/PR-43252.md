# [sgl-router] Keep router input_ids from engines that render differently

[Upstream PR](https://github.com/sgl-project/sglang/pull/43252) · state: closed · merged: False

## Original PR description

## Motivation

The router renders chats with its own `--default-chat-template-kwargs`. When an engine reports different defaults, #42998 makes the router decline `/generate` (`sgl_router_openai_route_total{outcome="default_chat_template_kwargs_differ"}`). The fallback, though, still forwarded the `input_ids` the router had rendered with its own defaults, and the engine served that prompt instead of its own render.

Found in an E2E run with DeepSeek-V4.1-Flash. The engine had `--default-chat-template-kwargs '{"thinking": true, "enable_thinking": true}'`; the router had none.
- A chat that set no thinking option was rendered by the router ending in `</think>` (thinking off). The engine's own render ends in `<think>`.
- The engine's reasoning parser expected thinking, so the answer came back in `reasoning_content` and `content` was empty.
- Requests that set thinking explicitly were unaffected.

The same applies when workers disagree with each other: the router's ids are wrong for every worker whose defaults differ from the router's.

Stacked on #43000.

## Modifications

- `routes/chat/preparation.rs`: the passthrough forwards router-rendered `input_ids` only if every worker with known OpenAI settings has the router's default kwargs. The comparison `lower_openai` already makes moves into `renders_as_router`, which both paths share.
- New proxy test `chat_keeps_engine_rendering_when_default_kwargs_differ`. It fails without the fix.

## Checks

- `cargo clippy --all-targets -D warnings` and `cargo test` in `experimental/sgl-router` pass.
- Live, with V4.1-Flash on default thinking and a router without the kwargs: in all 49 cases of the chat matrix the engine received the same request as direct, and responses match except for three sampled cases (no forwarded `input_ids`). Before the fix, 42 requests forwarded router ids and `plain` returned an empty `content`.
