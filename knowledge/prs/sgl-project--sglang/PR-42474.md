# [Model Loader] Configure tensor-copy concurrency for DeepSeek loaders

[Upstream PR](https://github.com/sgl-project/sglang/pull/42474) · state: open · merged: False

## Original PR description

## Problem and scope

Related to #42361. DeepSeek V4 and `DeepseekV2WeightLoaderMixin.do_load_weights` (V2/V3/full R1 and its inherited paths) create tensor-copy executors with Python's default worker count. Checkpoint-prefetch and shard-reader parallelism control different pools.

Following @janbernloehr's feedback, this PR exposes the same `--weight-loader-copy-num-threads` interface proposed in his [broader branch](https://github.com/janbernloehr/sglang/tree/jbernloehr/weight-loader-copy-workers), limited here to V4 and the shared DeepSeek loader. LongCat/Dots3 and DSpark's separate loader are outside this patch. This implementation adapts the current argument-group/runtime-context structure; no commit from the proposed branch was cherry-picked.

## Change

- Add optional `weight_loader_copy_num_threads` to the model argument group and field order; both actual DeepSeek executors read it from the model runtime configuration.
- Unset preserves Python's ThreadPoolExecutor default. Positive values limit active copy workers per rank; queued futures and total startup memory are not bounded by this setting.
- Replace the PR's original unpublished V4-only environment variable with the shared CLI control; no released configuration is removed.
- Document the argument beside the existing weight-loader controls.

```sh
python -m sglang.launch_server --model-path MODEL_PATH --tp 8 --weight-loader-copy-num-threads 2
```

Set the same argument on all ranks. `2` is an experiment setting, not a recommended default.

## Validation

CPU regressions use real V4 and shared DeepSeek weight-loading loops, real executor threads, and small CPU parameters. They verify the concurrent-copy limit, final tensor equality, zero/negative rejection before the copy loop consumes tensors in the tested unquantized path, unset behavior, propagation of asynchronous copy errors, and CLI parsing/defaults. Post-load kernels and full model construction are excluded from the fixture.

Before wiring the shared control, the expanded regression suite reported **6 failed, 4 passed**: both loaders ignored the new setting, and invalid limits consumed the iterator. After wiring the CLI control, **11 passed, 17 warnings in 12.34s**.

```sh
CUDA_VISIBLE_DEVICES='' PYTHONPATH=python python -m pytest test/registered/unit/model_loader/test_deepseek_v4_copy_concurrency.py -q --tb=short
```

Environment: Ubuntu 24.04/WSL, Python 3.12, PyTorch 2.13.0+cu130, GPU visibility disabled. All applicable repository pre-commit checks passed; `git diff --check` passed. A full Mintlify site build has not been run.

## Remaining validation and review focus

No valid Lustre/multi-GPU startup benchmark, full-model accuracy evaluation, or R1 speedup measurement has been run locally. Issue-author observations motivate the control but are not performance results attributable to this PR.

Review focus: whether this shared DeepSeek scope and CLI are the right initial interface. On an affected system, compare unset and `2` with the same checkpoint revision, storage, image, GPU/TP topology and prefetch settings; reverse run order and record loading time, HTTP readiness, cache/page-fault state and weight/serving correctness. Other copy paths can follow separately.

AI assistance was used for implementation, tests and this description.

- Problem: On Lustre, DeepSeek V4 Pro weight loading took ~95 min even with checkpoint prefetch, because the per-tensor copy ThreadPoolExecutor used Python's default worker count (32/rank) and saturated storage. Issue #42361 reports an A/B test on an 8-GPU B300 node: capping copy workers at 2/rank dropped loading from 5717s to 199s.
- Fix: Expose `--weight-loader-copy-num-threads` to control the per-rank tensor-copy executor (`max_workers`), separate from prefetch and shard-reader concurrency. Unset preserves Python default.
- Scope: 2 loader files read the new CLI field; field_order + model.py arg wiring; docs entry; 1 CPU unit test file. No behavior change when unset.
