## Original PR description

# Pin pip CUDA JIT toolchain to the CUDA minor required by torch

SGLang's CUDA dependencies allow `humming-kernels[cu13]` to install a newer, unconstrained `nvidia-cuda-nvcc`, while torch pins the CUDA runtime to 13.0. An environment that selects the pip CUDA root for FlashInfer JIT can therefore contain nvcc/CRT/NVVM 13.4 and runtime headers 13.0. In the affected NGRAM verification path, a non-greedy top-k request triggers a CCCL compiler/header compatibility error and terminates the scheduler.

Add `cuda-toolkit[nvcc,nvvm,cccl]==13.0.3` to the CUDA package dependencies, matching torch's existing toolkit requirement. This constrains compiler, CRT, NVVM and CCCL without suppressing compatibility checks. The dependency stays in alphabetical order.

Related: https://github.com/sgl-project/sglang/issues/43412

Validation (RTX 5090 SM120, Linux, Python 3.12):
- Fresh full main dependency resolution and isolated install: torch 2.14.1+cu130, FlashInfer 0.7.0.post1, nvcc/CRT/NVVM 13.0.88, runtime 13.0.96.
- Source main snapshot `46c2585faa4fcb6fa8febf4d2d4534a7cf33da79`; relevant pyproject and eagle_utils files are identical at rechecked main `2d3893449380864c178ec74be0a6bf24d0131175`.
- NGRAM with sampling backend pytorch, tiny random Llama 4096 vocabulary, triton attention: greedy, top-k, top-p, greedy-after all HTTP 200 and health 200, with graphs disabled and default graphs enabled.
- Unpatched main dependency resolution also succeeds but selects nvcc/CRT/NVVM 13.4.92 with runtime 13.0.96; the added extra selects compiler components 13.0.88 and CCCL 13.0.85. Both full requirement resolutions are preserved.
- The older 0.5.21 stack reproduces the actual CCCL JIT failure and scheduler exit, then passes the same small-model service test after alignment.
- The proposed and original TOML parse successfully and differ semantically only by the added requirement.

A separate FlashInfer radix top-k launch-budget bug was found with an artificial 248077 vocabulary after toolkit alignment. That bug has a separate patch and must not be bundled into this dependency PR. A small-vocabulary service pass is not evidence that arbitrary vocabularies were already fixed.

Limits: this pins package versions; it does not select CUDA_HOME/PATH or fix the pip toolkit's lib64/unversioned libcudart linker layout. Tests explicitly selected the pip toolkit and created links inside the isolated environment. No claim of SM89 validation or all optional backend support. Rust extensions were disabled for editable installation; the tested NGRAM uses the C++ kernel and Python TreeCore fallback.
