## Original PR description

# Add zero-copy stacked-embedding CUDA IPC transport for the score API

## Motivation

The score API accepts per-request embedding overrides (`query_embed_overrides` /
`item_embed_overrides`, added in #20960) that replace the model's learned
embeddings at placeholder token positions. Today those override tensors are sent
from the tokenizer-manager process to the scheduler process by **value**: each
tensor is pickled (GPU→host copy), sent over the wire, and copied back
(host→GPU), and the per-item vectors are re-stacked on every request.

For callers that already hold all of a request's override vectors in a **single
GPU buffer** (e.g. a feature/embedding pool produced upstream in the same
process), that round-trip is pure overhead — the data is already on the device
the scheduler will read from.

## What this adds

An optional **zero-copy** path that forwards the already-stacked embeds to the
scheduler as a **CUDA IPC handle**, so no host round-trip and no re-stacking
happen per request. It is fully opt-in and falls back to the existing by-value
API when unused.

New parameters on `Engine.score()` / `Engine.async_score()` and
`TokenizerManager.score_request()`:

- **`stacked_query_item_embed_overrides`** — one already-stacked `[N, hidden]`
  tensor per output sequence (one per item for single-item scoring, a single
  element under multi-item scoring; `None` if a sequence has no overrides). Rows
  are ordered query-placeholders-first, then item-placeholders. Used as-is (no
  restack). Mutually exclusive with `query_/item_embed_overrides`.
- **`stacked_query_item_embed_ipc_handle`** — the CUDA IPC handle of the single
  buffer backing those tensors. When set, each override is wrapped for zero-copy
  IPC transport. Requires `tp_size == 1` (imported IPC memory can't be
  re-exported to other ranks); otherwise the tensors transport by value.

## Implementation

- `TransportProxyTensor` gains an optional `ipc_handle` and a `__reduce_ex__`
  that, on the `cuda_ipc` path, pickles **only** the handle + offset/shape/stride
  (not the storage) and rebuilds a zero-copy view on the consumer side via
  `_open_ipc_view`, reusing the shared multimodal CUDA-IPC pool-handle cache.
- `_build_token_id_inputs_stacked` computes the placeholder attach positions for
  the already-stacked embeds without touching the embed data.
- Producer contract (documented on the API): every override must be a view into
  the buffer the handle exports; writes must be complete (producer stream
  synchronized) before the call; and the region must stay allocated and
  immutable until scoring finishes.

## Fallback / compatibility

The zero-copy transport applies only when the overrides live in a single GPU
buffer on the **same device** as the scheduler and its IPC handle is supplied
(CUDA IPC is same-GPU / same-host). Behavior by case:

- **No `stacked_*` args** → unchanged; the existing by-value embed path is used.
  No change to existing callers.
- **`stacked_query_item_embed_overrides` without a handle** → the tensors
  transport by value (pickle/copy) — correct results, no speedup.
- **Handle supplied with `tp_size > 1`** → rejected with a `ValueError`
  (imported IPC memory can't be re-exported to other ranks); callers on
  multi-GPU must use the by-value API.
- **Handle supplied but IPC export fails at pickle time** →
  `TransportProxyTensor` transparently falls back to by-value transport.

So the speedup requires same-GPU placement + `tp_size == 1`; otherwise the path
degrades to (or requires) the existing by-value copy. Correctness is identical
in all cases.

## Tests

- **Unit** (`test/registered/unit/managers/test_embed_overrides.py`): adds
  `TestBuildTokenIdInputsStacked` covering the stacked input-building path
  (single-item and multi-item), asserting the pre-stacked tensor is forwarded
  as-is (not restacked/copied) and that attach positions are correct.
- **Integration** (`test/registered/prefill_only/test_stacked_ipc_transport.py`):
  a cross-process CUDA-IPC test that pickles a pool-backed `TransportProxyTensor`
  in one process and reconstructs a zero-copy view in another, verifying
  (1) `__reduce_ex__` emits handle-only (tiny pickle, storage not serialized by
  value) and the consumer reads the producer's values, and (2) writes issued
  after the handle was exported are visible once the producer synchronizes.

## End-to-end equivalence + performance

`benchmark/prefill_only/bench_score_stacked_ipc.py` (Engine-API companion to the
HTTP `bench_score.py`) scores the same synthetic inputs both ways — by-value
`query_/item_embed_overrides` vs `stacked_query_item_embed_overrides` over a
shared GPU pool + IPC handle — asserts the returned scores are identical, then
benchmarks both.

```bash
pip install "sglang[all]"
python benchmark/prefill_only/bench_score_stacked_ipc.py \
    --model-path Qwen/Qwen3-4B --num-samples 64 --items-per-query 8 --iters 20 --warmup 5
```

Validated on **Qwen/Qwen3-4B**, 1x H200. Scores are **bit-for-bit identical**
between the two paths in every config (`max abs diff 0.000e+00`). The stacked-IPC
path removes the per-request D2H+H2D copy and the per-override pickling (by-value
serializes one tensor *per placeholder*; stacked sends a single handle), so the
speedup scales with the number/volume of override embeddings per request:

| Override tensors / request | Pool size | by-value | stacked-ipc | Speedup |
|---|---|---|---|---|
| ~10   (2q+1i  x 8 items)  | 0.06 MB  | 45.7 calls/s | 46.5 calls/s | 1.02x |
| ~272  (16q+8i x 32 items) | 7.86 MB  | 10.9 calls/s | 11.7 calls/s | 1.07x |
| ~1088 (64q+32i x 32 items)| 31.46 MB |  6.7 calls/s | 10.2 calls/s | 1.51x |
| ~3136 (64q+48i x 64 items)| ~73 MB   |  2.8 calls/s |  5.9 calls/s | 2.10x |

(all rows: equivalence PASS, `max abs diff 0.000e+00`.)

At small override counts the Qwen3-4B forward pass dominates and the transport
saving is in the noise (~1.0x); as embeddings per request grow the by-value
host round-trip + per-tensor pickling become the bottleneck and stacked-IPC
reaches **2.1x** end-to-end. Exact score equivalence holds throughout.

## Usage

```python
import torch
from sglang import Engine

engine = Engine(model_path="Qwen/Qwen3-4B", tp_size=1)

# One shared GPU buffer holding this request's override vectors as views.
pool = torch.empty(NUM_ROWS, HIDDEN, dtype=torch.float32, device="cuda")
# ... fill `pool` so each item's rows are query-placeholders-then-item ...
handle = pool.untyped_storage()._share_cuda_()
torch.cuda.synchronize()  # writes must complete before the call

result = engine.score(
    query=[10, 50, 50, 20],           # token ids; 50 = placeholder
    items=[[50, 30], [50, 40]],
    label_token_ids=[2332, 1223],
    embed_override_token_id=50,
    stacked_query_item_embed_overrides=[pool[0:3], pool[3:6]],  # views into `pool`
    stacked_query_item_embed_ipc_handle=handle,
)
```
