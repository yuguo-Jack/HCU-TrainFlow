# [unified-memory] Stop allocation eviction on the joint FULL/SWA fit

[Upstream PR](https://github.com/sgl-project/sglang/pull/43169) · state: open · merged: False

## Original PR description

## Motivation

On the unified FULL/SWA pool (`--enable-unified-memory` with a hybrid sliding-window model) every cached token holds bytes on both sides, and the allocator's reclaim plan counts the same shared bytes once per side. `UnifiedRadixCache.evict_for_alloc` used to stop once each side's available view reached its own target, so the same freed bytes satisfied both targets and eviction stopped short: the allocation raised "Out of memory" with evictable cache left (on MiMo-V2-Flash geometry, an ask of 335 tokens needing 18.65 MB stopped after 288 evictions with 16.07 MB free and 2,255 tokens still evictable).

#39479 made `evict_to_free_tokens` evict the plan's per-side counts as cumulative quotas instead. That no longer stops short, but it evicts far past the fit: on a FULL/SWA pool with an 8:1 SWA:FULL entry ratio filled with one-page cached nodes, a 10-page ask now evicts 57 of the 64 pages, a 30-page ask 61, and a 3-page ask at page size 4 evicts 10 of 16, through `evict_to_free_tokens`, `reclaim_for_prealloc` and `check_decode_capacity` alike. Each such eviction throws away cached prefixes that later requests could have reused.

## Modifications

- `EvictParams` gains `alloc_demand`, the (full, swa) tokens an eviction serves. With it set, `evict_for_alloc` stops as soon as the allocator reports that demand fits, and the counts only cap each component. Callers that do not set it keep the per-side behaviour.
- `UnifiedSWATokenToKVPoolAllocator.allocation_fits` answers what `ensure_capacity` would, without compacting; both read one `_fit_state`, and `evict_to_free_tokens` passes the ask along with the plan. The plan's counts stay the caps, so no ask evicts more than it does today.

Tests (`test_unified_radix_allocation_eviction.py`, CPU): on that pool, make-room through each of the three entry points evicts exactly the pages the ask needs; before this change all nine cases over-evict (`(True, 57) != (True, 10)`, `(True, 61) != (True, 30)`, `(True, 10) != (True, 3)`). Tree tests cover the stop on the fit whatever the views read, the SWA walk, the counts as caps, and a write-back demote. `allocation_fits` is pure and agrees with `ensure_capacity`. Over 400 random trees (SWA-dead and locked nodes, compaction allowed and blocked), every make-room the per-side stop completed still completes, and the ones it left short now complete.

## Accuracy Tests

The change is to the eviction stop rule only; no kernel or model path changes. GPU unit suite (unified-memory scope): all pass except the 2 cases of `test_swa_write_back_host_full_preserves_full_and_continues`, which force the Rust TreeCore that our test image does not build.
