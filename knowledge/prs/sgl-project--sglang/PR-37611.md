# feat(moe): support FlashInfer A2A with Triton runner

[Upstream PR](https://github.com/sgl-project/sglang/pull/37611) · state: closed · merged: False

## Original PR description

## Motivation

FlashInfer A2A can provide the expert-token exchange path on NVIDIA Ampere GPUs, while the regular Triton MoE runner can execute unquantized BF16 experts. Before this change, SGLang did not register a `flashinfer` -> `triton` format conversion, so this combination could not consume FlashInfer's global expert IDs through the Triton runner.

This PR adds a correctness-first compatibility path for a static, contiguous expert partition. It does not claim a performance improvement.

## Modifications

- Register `triton` as a supported FlashInfer A2A MoE runner.
- Translate FlashInfer's global expert IDs into the current rank's local contiguous IDs, then reuse the existing Triton alignment and dispatch flow.
- Preserve the existing standard prefill path and wrap Triton output for FlashInfer's reverse combine.
- Fail fast for configurations that are not represented by this mapping yet: quantized payloads, non-contiguous or relocated experts, redundant experts, fused shared experts, `moe_dp_size > 1`, custom dispatch algorithms, and elastic EP.
- Add focused registered CPU tests and document the supported configuration and limitations.

## Accuracy Tests

- Focused registered unit test (remote SGLang environment):
  `PYTHONPATH=python python test/registered/unit/layers/moe/test_flashinfer_triton_dispatch.py`
  Result: 8 tests passed.
- Runtime smoke test on 8 x NVIDIA A100 80GB PCIe (SM80), Qwen3-30B-A3B-Instruct-2507, `tp=8`, `dp=8`, `ep=8`, `--enable-dp-attention`, FlashInfer A2A, Triton MoE runner: server started and a deterministic request returned HTTP 200. The candidate and the existing `none` sanity path produced the same output token IDs for that request.
- Official SGLang GSM8K sanity command with `--num-examples 200`:
  - candidate (`flashinfer` A2A + `triton` runner): 194/200 (0.970)
  - `none` path: 193/200 (0.965)
  This is an accuracy sanity check only; these `run_eval` throughput numbers are not used as speed evidence.
- Reproduction details: a local copy of Qwen3-30B-A3B-Instruct-2507; GPU topology has NVLink pairs (0,1), (2,3), (4,5), and (6,7), with cross-pair links crossing NUMA/SYS; latest tested commit `09eb7d86d2d52a4cdf6ae0e7f5270e526b88d1e9`.

## Speed Tests and Profiling

No speedup is claimed in this PR. A valid same-backend A100 comparison was not available in the test environment:

- the installed FlashInfer 0.6.18 CUTLASS MoE backend rejects SM80 with `Invalid backend: 80`;
- DeepEP, PPLX, Mooncake, and NIXL are not installed on the host;
- the `none` backend is not a valid A100 A2A baseline; and
- `run_eval` throughput is not a substitute for the required `bench_serving` measurement.

The required same-model, same-backend `bench_serving` comparison with at least three repeats and profiling is therefore pending. This PR should be reviewed as a compatibility/correctness change, not as a performance claim.
