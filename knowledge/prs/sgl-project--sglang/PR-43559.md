# [Fix] Release consumed lazy Mamba prefix locks before donation retry

[Upstream PR](https://github.com/sgl-project/sglang/pull/43559) · state: open · merged: False

## Original PR description

## Dependency

Depends on #43567. Keep this PR in draft and merge #43567 first: releasing the prefix lock alone can expose stale in-place checkpoint donation under slot pressure.

## Problem and change

With lazy overlap, the next decode can consume the temporary tracking slot before the previous prefill donates its checkpoint. Donation then needs a replacement slot while the consumed prefix state is still locked, exhausting the pool and asserting.

On a failed lazy donation allocation, release this request's consumed Mamba prefix reference before eviction/retry. Preserve KV locks and other requests' references; record the release to avoid a double decrement. Keep the allocation assertion and existing capacity formulas unchanged.

One regression covers full 3-slot and 4-slot per-request pools and the subsequent normal unlock. Checkpoint invalidation is handled separately in #43567.

## Validation

- This branch independently: 14 CPU tests and 12 subtests passed; pre-commit passed.
- The two PRs merge without conflicts. Their combined runtime files are identical to the previously validated combined fix (43d6c962aa).
- Combined E2E on GB300 with overlap and decode CUDA graphs: Qwen3.5-0.8B passes 24 requests with 1 running request / 4 slots and 96 with 4 / 16; Qwen3.5-4B + NEXTN passes 24 with 1 / 4. Original main asserts in these cases. Both single-request 4-slot runs exactly match their 8-slot references in output tokens and logprobs. Ordinary and NEXTN 3-slot runs also complete 24 requests each.

These GPU results cover both fixes together, not this branch alone.
