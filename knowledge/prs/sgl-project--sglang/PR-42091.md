# fix(gemma4): initialize unified LM-head state

[Upstream PR](https://github.com/sgl-project/sglang/pull/42091) · state: open · merged: False

## Original PR description

# fix(gemma4): initialize `lm_head_is_tied` for unified models

## Summary

`Gemma4UnifiedForConditionalGeneration` reuses the parent forward implementation but bypasses the parent constructor to install encoder-free multimodal components. Its local LM-head setup did not initialize `lm_head_is_tied`, which the inherited forward path reads.

This caused model warmup or CUDA-graph capture to fail with:

```text
AttributeError: 'Gemma4UnifiedForConditionalGeneration' object has no attribute 'lm_head_is_tied'
```

## Change

Store the existing tying condition before constructing the LM head:

```python
self.lm_head_is_tied = self.pp_group.world_size == 1 and text_tie
```

Then use the stored value for LM-head selection. This keeps construction and inherited forward behavior consistent while preserving the existing pipeline-parallel restriction.

## Validation

Re-run `google/gemma-4-12b-it` through model load, decode graph capture, and one generation request.

This matches upstream fix `08b1922405` / #35809 and should be carried into `amd_march` rather than submitted as a duplicate upstream fix.
