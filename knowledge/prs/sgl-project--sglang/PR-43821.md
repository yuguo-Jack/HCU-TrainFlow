# [AMD][V4.1] Trim per-cycle bookkeeping launches in DSpark decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/43821) · state: open · merged: False

## Original PR description

## Motivation

At low concurrency, DeepSeek-V4.1 DSpark decode on MI35x is bound by kernel launches rather than math. A torch-profiler trace of TP4 AgentX decode at batch 1-2 shows one draft + target-verify cycle of about 9.1 ms and about 1,300 kernels. Roughly 100 of them are small torch elementwise / copy / index / fill kernels around the HIP attention metadata, the DSpark draft layers and the verify epilogue, each costing about 2-4 us under HIP graph replay. Most are once-per-cycle glue that an adjacent launch can do, or that can be skipped.

## Modifications

Every replacement produces the same bits as the torch chain it replaces.

- **Verify / draft in-graph metadata** (`deepseek_v4_backend_hip_radix.py`, `attn_glue_hip.py`, `metadata_kernel.py`):
  - The seq_lens offset, extend clamp, row expansion, int32 cast and positions now run in one Triton launch, `expand_same_length_rows`.
  - HIP `get_swa_page_indices` + pad now use the existing causal SWA page-index kernel.
  - The `swa_out_cache_loc` translate + int32 cast is one launch (`gather_i32`).
  - The c128 page-index padding moved inside the compression-metadata kernel.
  - The low-ratio raw-index `-1` fills are folded into `sparse_buffers`.
  - An already aligned SWA page-index tensor is no longer cloned.
- **Out-of-graph replay prep:** skips the zero-width pad clone of `out_cache_loc`.
- **DSpark draft:**
  - q rope plus the copy into the head-padded q are one launch per layer (`apply_rotary_emb_copy_into`).
  - On ROCm, the commit-KV projection hands strided slices to the FlashMLA writer, which already reads the row stride.
- **Verify epilogue (ROCm only):** finalize and out-token build write the persistent buffers directly. CUDA keeps its current copy chain.
- **Engram:** the gather reads the per-layer hash-id column slice in place.

The new SWA paths run only when the pool's `translate_loc_from_full_to_swa` is the plain `DeepSeekV4TokenToKVPool` lookup. Otherwise the existing code runs.

**Code shared with CUDA.** These are all value-identical, but tested only on gfx950 here:
- `_causal_swa_page_indices_kernel` now wraps a `-1` `req_to_token` slot the way torch indexing does. Before, that slot read out of bounds.
- `build_out_tokens_triton` no longer widens `correct_len` to int64 first; its kernel already narrows it to int32.
- `engram_gather` also accepts `[T, C]` ids with a unit column stride, so the engram layer passes the column slice instead of copying it flat.

Net: about **52 fewer launches per draft + verify cycle** on the production path. Verify metadata goes from 38 to 10 launches and draft metadata from 14 to 5; the rest come from draft rope/copy, engram, the epilogue and the eager pad clones.

## Accuracy Tests

- Each new or changed kernel is checked bitwise against the torch chain it replaces. The tests were added to `test/registered/kernels/ops/attention/dsv4/test_dsv41_decode_glue_hip.py` (stage-b, 1-gpu-small-amd-mi35x, `est_time` 15 → 25). Each case guards one regression:
  - seq_lens offset / clamp / row order / dtype in `expand_same_length_rows` (int32 and int64, with and without extend, bs = 0).
  - The `-1` slot wrap in the SWA page-index kernel and `gather_i32`. Removing the wrap fails this test.
  - The `-1` fill slots in `sparse_buffers`.
  - c128 padding equal to `F.pad(..., -1)`.
  - Strided engram ids.
  - Rope-into-copy against rope-then-copy, including the no-rope dims and the source left untouched.
  - The epilogue's `out=` writes.
  - The FlashMLA cache bytes with strided vs contiguous KV, which is the evidence behind the ROCm `allow_strided_output` flip.
- `test_dsv41_decode_glue_hip`, `test_dspark_kernel_parity`, `test_ragged_verify` and `test_dspark_simulated_bonus` on gfx950: 32 passed.
- End to end, DeepSeek-V4.1-Flash TP4 with DSpark and real acceptance, on main 166b4ae7fc together with #43822 (unit tests re-run after rebasing on f006fb49ec):
  - 17×23 → 391.
  - capital of France → Paris.
  - 12+30 → 42 after sustained decode.
  - 0 NaN / error lines.
  - Real accept length 2.54, against about 2.55 on main.
