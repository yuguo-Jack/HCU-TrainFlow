# [diffusion] comfyui: consolidate executor conditioning-cache fixes

[Upstream PR](https://github.com/sgl-project/sglang/pull/43492) · state: closed · merged: True

## Original PR description

## Summary

Consolidates the ComfyUI SGLDiffusion executor's conditioning-cache correctness fixes into one PR, 4 commits:

1. **Key cached conditioning on full content.** `_cond_key` truncated conditioning to a (shape, first value, last value) tuple; two different conds with the same shape and matching endpoints could collide and the worker would serve stale conditioning. Switches to hashing everything `drop_cached_fields` removes with blake2b, so a cache hit always means the worker can restore the whole thing. Fixes #43107.
2. **Cache H3 extras per cond and key them too.** MiniMax-H3 caches extra per-cond fields beyond `image_latent`; those weren't included in the cache key or dropped on a hit, so they could go stale the same way.
3. **Split batched DiT calls into per-row requests.** ComfyUI can call the executor with a batch of concatenated conds; the executor treated the whole batch as one cond, causing cross-talk between rows.
4. **Slice batched kwargs by ComfyUI's batch contract.** Companion to (3): `transformer_options` entries that are per-chunk (`cond_or_uncond`, `uuids`, `sigmas`) need slicing the same way the main tensors do.

Fixes #43111.

## Test plan

- Added/kept regression tests in `test_comfyui_session.py` and `test_comfyui_adapters.py` covering cache-key collisions, H3 extras, and per-row batch splitting.

- niehen6174 · comment · 2026-10-10T05:26:16Z · [source](https://github.com/sgl-project/sglang/pull/43492#issuecomment-6094197362)

Thanks for consolidating these. I tested the cond-key change on H200 and have one suggestion.

**Cost of hashing every step.** ComfyUI rebuilds the cond tensors on every step (`CONDRegular.concat` calls `torch.cat`), so `_cond_key` copies each cond to the host and hashes it once per step. I timed it with MiniMax H3 at 864x480, 107 frames, 20 steps:

| task | hashed per key | one hash | per run |
|---|---|---|---|
| t2v | 0.97 MiB | ~2 ms | 41 ms |
| fl2v (keyframes) | 9.36 MiB | ~17 ms | 335 ms (~1.4% of sampling) |

**Suggestion: hash each cond once per sampler run.** ComfyUI gives every cond a uuid per `sample()` call and passes it in `transformer_options["uuids"]`. Within one run that cond's content does not change. So the key can be memoized on `(uuids, split row, tensor dtypes/shapes)` and cleared in `begin_sampler_run`. Without uuids it falls back to hashing every step.

- niehen6174 · comment · 2026-10-10T07:03:10Z · [source](https://github.com/sgl-project/sglang/pull/43492#issuecomment-6094925245)

Thanks for the per-run memo! I'd like to push one small commit (`bb9ba30c8a`) here; feel free to drop or rework it:

1. **Memo key per row.** Rows of one cond chunk share its uuid, so two rows with the same text but different reference latents got the same key, and the second row reused the first row's reference. The memo key now includes the split row. `test_batched_rows_with_same_text_keep_their_own_reference` now passes uuids, which catches this.
2. **Keep the `_execute_packed` signature.** The uuid now travels on `packed.unpack_ctx`, so executors that override `_execute_packed` (e.g. FastH3/VDN in #43504) don't hit a `TypeError`.

Your tests still pass (81 passed).
