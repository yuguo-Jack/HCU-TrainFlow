# [NPU] Stabilize HiCache and registered CI tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/43308) · state: closed · merged: True

## Original PR description

#43711 superseded the tensor-bool fix by capturing transfer buffers during host-pool initialization without evaluating their truth value. The conflict has been resolved in favor of the new main implementation, and the redundant MHA/MLA changes have been removed from this PR.

## Motivation

This PR addresses the following NPU CI issues:
1. NPU no longer supports `--enable-torch-compile`, but a dedicated compile test remained in registered CI, while DP-attention and load-balance tests also enabled the flag even though compile coverage was not their test target.

3. NPU CI left `pyarrow` unconstrained. After `pyarrow==26.0.0` entered the package index, it was installed alongside the `numpy==1.26.4` required by `triton-ascend` and failed at import time because PyArrow 26 requires NumPy 2 or newer. GPU CI currently uses the known-good `pyarrow==23.0.1` with the same NumPy version.

The MLA HiCache test also requested 30 GB of pinned host memory per TP rank. With TP=4 that is approximately 120 GB, which can fail in `aclrtMallocHostWithCfg` on the CI host.

## Modifications

2. Reduce `test_npu_hicache_mla.py` from 30 GB to 10 GB of pinned host memory per TP rank.

3. Remove `test_npu_compile_graph_tp1_bf16.py`, which existed specifically to cover the unsupported NPU `--enable-torch-compile` path.

4. Remove `--enable-torch-compile` and its compile-only max-batch-size option from the DP-attention and load-balance tests. Their test logic, targets, and assertions are otherwise unchanged.

5. Pin `pyarrow==23.0.1` in the shared NPU CI dependency installer, matching the version used by GPU CI and preventing an incompatible unbounded upgrade to PyArrow 26.
