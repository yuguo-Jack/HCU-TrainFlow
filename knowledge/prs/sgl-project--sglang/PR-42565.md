# [BugFix] Fix ragged DSA seed indices before MTP draft decode

## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Fused DSA prefill can produce top-k indices into the batch’s flattened logical KV space. The draft model captures these indices as MTP seeds and reuses them in the next draft decode, which expects physical KV slots.
This mismatch can select incorrect KV entries or cause out-of-bounds reads, particularly when long requests share cached prefixes and logical offsets exceed physical cache capacity.

The engine config that exercises this error:
```
SGLANG_DSA_FUSE_TOPK=1 \
python3 -m sglang.launch_server \
  --model-path /models/PhalaCloud/GLM-5.3-W4AFP8 \
  --quantization w4afp8 \
  --tp 8 \
  --mem-fraction-static 0.75 \
  --kv-cache-dtype fp8_e4m3 \
  --dsa-prefill-backend flashmla_sparse_q8 \
  --speculative-algorithm EAGLE \
  --speculative-num-steps 3 \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 4
```

## Modifications

<!-- Detail the changes made in this pull request. -->

- Add `prepare_mtp_seed_indices()` to map fused RAGGED seeds through the producer’s page table before capture.

## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

The gap: this PR converts seeds only on the MHA path (`forward_mha.py`). MHA is used only when `kv_len <= SGLANG_DSA_PREFILL_DENSE_ATTN_KV_LEN_THRESHOLD` (2048 by default). Longer prefills go through MLA sparse, and there the draft model exports seeds through `IndexTopKShareState.publish()` in `index_topk_share.py`. That method still copies the RAGGED (batch-global logical) indices into `dsa_seed_topk_capture` unchanged. So the long-context case this PR describes (logical offsets exceeding physical KV capacity) is still not covered. I think `prepare_mtp_seed_indices()` needs to be applied in the `seed_buf` branch of `publish()` as well.

**Update (2026-10-09):**

1. **`SGLANG_DSA_FUSE_TOPK=0` is not a valid workaround.** With it, the engine crashed about 2 min after startup on the first long prefill. The error was `RuntimeError: The size of tensor a (742) must match the size of tensor b (741)` at `dsa_backend.py` `forward_extend` (`topk_indices + topk_indices_offset`) during `_draft_extend_for_prefill`. On the unfused RAGGED path, `topk_indices` is padded to the q row count by `_pad_topk_indices`, but `topk_indices_offset` is not padded. This is a separate bug from the one this PR fixes.

2. **The latest commit (6ad90aae, `write_mtp_seed` on the sparse-MLA `publish()` path) works for us.** We backported the three files onto our sglang-runtime 1.5.0 image (applied cleanly) and ran a burst test: 10 concurrent requests sharing a ~220k-token cached prefix, 3 rounds. Results:
   - 30/30 requests OK, no engine restart, no IMA.
   - The engine logs show prefill batches with `#new-seq: 4, #cached-token: 882432`, so the batch's logical `sum(seq_lens)` (~890k) exceeds the per-rank KV pool (756,544 tokens). That is the condition that crashed the engine before this commit.
   - EAGLE accept length is unchanged (~2.8).

Minor review notes:
- `write_mtp_seed` falls back silently when the resolved backend has no `prepare_mtp_seed_indices`. If a wrapper backend is ever returned there, the old bug would come back without any signal. An assert, or a one-time warning, for the fused + EXTEND case would make that visible.
- A GPU regression test covering many long shared-prefix requests in one extend batch (`sum(seq_lens)` > pool size) would lock this in.

@BBuf thanks for reviewing, i just added a GPU regression test, which covers the handoff from draft prefill to the first draft decode end to end on real kernels. With `SGLANG_DSA_FUSE_TOPK=1` and an fp8 KV cache, it runs the real indexer and fused top-k, the seed export on both paths (dense MHA and sparse MLA, with the backend's own routing choosing between them), and the `flashmla_kv` decode. Requests share cached-prefix pages scattered across the pool, so the ragged logical offsets exceed the KV pool, which is the shape of the production crash. The test checks that every seed index stays inside the pool before any kernel reads it, that the seed exactly matches the physical slots from an independent offset-to-slot mapping, and that decode attention matches an fp32 torch reference.
