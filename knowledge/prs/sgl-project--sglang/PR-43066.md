# feat(jit): support native MUSA compilation

[Upstream PR](https://github.com/sgl-project/sglang/pull/43066) · state: open · merged: False

## Original PR description

## Overview

This PR adds native MUSA compilation to SGLang's Ninja-based JIT build path.
The MUSA branch selects `mcc`, passes `-x musa` and
`--offload-arch=mp_*`, and uses MUSA include paths and runtime libraries.
HIP retains precedence, and CUDA remains the fallback.

MUSA JIT uses C++17, aligned with the MUSA AOT build. CUDA and HIP retain
C++20. Shared-header compatibility uses compiler and standard-library feature
detection with overridable `SGL_USE_*` settings. The JIT cache fingerprints
the selected compiler path and version.

Runtime and FP8 aliases are supplied by TorchADA through
`stable_compat_include_dir()`. This path depends on
[yingzhou-bjtu/torchada#4](https://github.com/yingzhou-bjtu/torchada/pull/4),
currently a fork Draft. A TorchADA release containing that change is required
before this PR can be merged.

[sgl-project/sglang-omni#2442](https://github.com/sgl-project/sglang-omni/pull/2442)
is the downstream consumer integration: it exposes the existing joint-RoPE
provider on MUSA. JIT compilation remains in SGLang.

Part of #16565.

## Validation

Environment: MTT S5000, MUSA 5.2, `/usr/local/musa/bin/mcc`, `mcc version
5.2.0`, and `--offload-arch=mp_31`.

- `pytest -q test/registered/unit/kernels/test_jit_cache.py`: `48 passed`.
- Generated Ninja selects `/usr/local/musa/bin/mcc`, `-x musa`,
  `--offload-arch=mp_31`, `-DUSE_MUSA`, and `-std=c++17`.
- `fused_rope`: real MUSA JIT build, module load, and numerical smoke passed;
  `q_max_abs_error=0.0`, `k_max_abs_error=0.0`.
- `speculative_tree` and `ngram_embedding`: real MUSA JIT build and module
  load passed.
- `speculative_sampling`: dependency-blocked because
  `flashinfer/sampling.cuh` is absent from the validation image.

### C++ standard decision

The real `mcc` probe passed the selected public-header closure under both
C++17 and C++20 (`bits.h`, `utils.h`, `tensor.h`, `type.cuh`, and `utils.cuh`,
`5/5` for each standard). The same probe showed that the C++20 ranges path is
not usable with the MUSA clang14/libstdc++ combination. Therefore the MUSA JIT
path uses C++17 with a narrow compatibility layer, while CUDA/HIP remain on
C++20.
