# [DeepSeek-V4.1] Serve image requests under encoder SWA bounded replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/43241) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-encoder-swa-bounded-replay`, DeepSeek-V4.1 keeps only main and indexer KV for a cached prefix. When a request is admitted with a cached prefix (a radix hit, a HiCache host-tier hit, or a retracted request), `run_encoder_swa_replay` rebuilds the request's sliding-window state by forwarding the last up to 128 prefix tokens as a separate extend pass before the real extend.

That pass is built from token IDs only and sets `multimodal_inputs=[None]`. For an image request, the image placeholders in those token IDs are hash-derived pad values (they are what makes the radix and HiCache keys image-specific). Without the request's multimodal items, the model maps them to `image_token_id` and embeds that token, so a window that covers image tokens would be rebuilt from placeholder embeddings instead of image features, and every later token in the window would attend to the wrong keys. The Engram image mask, which is gated on `contains_mm_inputs()`, would also differ from the original prefill.

To avoid that, `TokenizerManager._validate_one_request` and `ScheduleBatch.prepare_for_extend` reject every image, video, audio, `input_embeds` and positional-override request while the flag is set, and the startup warmup skips its image request.
## Modifications

- Carry `req.multimodal_inputs` into the replay batch so the existing multimodal prefill path supplies image embeddings and Engram masking.
- Image requests are accepted under the flag. Video, audio, `input_embeds` and `positional_embed_overrides` stay rejected, in the tokenizer and in the scheduler check, because replay does not rebuild those embedding sources. The scheduler check moves into `check_encoder_swa_replay_request` so it can be tested directly; the cached-prompt-logprob rejection is unchanged.
- The startup warmup no longer drops its image request when the flag is set.

## Accuracy Tests

New CPU test `test/registered/unit/model_executor/test_encoder_swa_replay_multimodal.py`:

- `run_encoder_swa_replay` driven through `DeepseekV4ForCausalLM.forward` and `_prepare_mm_embeddings` (stub vision encoder and decoder layers) on a request with two images with distinct hashes. For a window with a clamped start ending inside the first image, a window starting inside the first image and ending inside the second, and a window after both, the replay's input embeddings equal the full prefill's rows for those positions, both from the embedding cache and after the cache is cleared (only overlapping images are re-encoded). The replay keeps the hash pad IDs in its batch, passes `image_token_id` to the decoder at image positions, and reports `contains_mm_inputs()` for the Engram mask. A text request in the same batch still replays without multimodal inputs. These cases fail with the `encoder_swa_replay.py` change reverted.
- Tokenizer and scheduler validation under the flag: text and image requests are accepted; video, audio, `input_embeds` and positional overrides are rejected; prompt logprobs over a cached prefix are still rejected.

GPU check: DeepSeek-V4.1-Flash, 4x RTX PRO 6000 Blackwell (SM120), TP4, with `--enable-encoder-swa-bounded-replay`, `--enable-decoder-swa-bounded-replay`, HiCache and DSpark speculative decoding, using a 256x128 test image whose left half is red and right half blue. Greedy requests (thinking off, `max_tokens=48`, logprobs) each ran on a cold cache, again with the prefix cached (the encoder replay rebuilds the last 128 prefix tokens), and on a cold cache once more. Which cache tier served the cached prefix was not recorded.

| prompt | cached tokens on the repeat | output tokens equal (cold vs cached) | max abs logprob difference, cold vs cached / cold vs cold |
|---|---|---|---|
| ~1.5K words of text, then the image, then the question | 3,584 of the prompt, 202 image tokens | 11 / 11 | 0.148 / 0.089 |
| image first, then ~1.5K words, then the question | 3,584 | 4 / 4 | 0.019 / 0.142 |
| text only | 3,328 | 2 / 2 | 0.008 / 0.032 |

Answers are identical on every path ("Left half is red, right half is blue.", "Red and blue", "391"). The text-then-image case has a larger cached-vs-cold difference than the measured cold-vs-cold difference. A multi-turn chat with the image after 3,000 words of text, follow-ups with 7,936 and 15,872 cached tokens, answered every question about the image correctly. At base commit `5cbf949839` the tokenizer rejects these requests while `--enable-encoder-swa-bounded-replay` is set.
