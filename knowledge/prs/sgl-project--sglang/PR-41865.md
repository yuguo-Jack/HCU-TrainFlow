## Motivation

This follows #39395, which follows #38681.
HiCache write-back can incur significant memory overhead during H2D due to running everything in a batch at once.
This PR splits the H2D to be done node-by-node, such that the overhead is at most a single node's worth.

<!-- Describe the purpose and goals of this pull request. -->

## Modifications

The Python implementation of TreeCore is rebased and re-verified.
Headline improvement stays the same: in my benchmark, usable tokens went from ~2.3M to ~3.3M, a ~44% increase.
This is generally consistent with #39395 tests that saw a 51% increase on a different benchmark.

In addition, this PR also adds the same feature to the rust implementation of TreeCore.
Functionality and tests are at parity with Python.
Newly added unit tests passes and the same benchmark saw the same behavior: ~3.3M usable tokens.

[by Claude Code] **Severity: functional | Confidence: High**

**Issue**

The SWA transfers in `aux_xfers` keep the `anchor_index_parts` that `build_load_back_spec` built against the whole chain's Full transfer. The last step passes only the anchor node's Full rows to `cache_controller.load`. With `--enable-unified-memory`, `HybridCacheController._resolve_device_transfers` slices `kv_device_indices[part]` with those chain offsets, so its length assert fails and the scheduler crashes. Both TreeCore backends build these parts.

**Example**

Chain A(64) -> B(64), both host-only, SWA window covers B. B's part is `slice(64, 128)`, but the last step's `kv_device_indices` has 64 rows, so it resolves to 0 rows.

**Fix**

Before the last step, remap the parts: the anchor gets `slice(0, step_tokens)`, earlier nodes get their loaded Full device values. Add a `--hicache-serialize-load-back` case to `TestUnifiedMemoryHiCacheSWA`.
