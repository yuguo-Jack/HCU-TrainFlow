#  [Proposal] Memory-semantic PD-disaggregation paradigm

[Upstream PR](https://github.com/sgl-project/sglang/pull/14775) · state: closed · merged: False

## Original PR description

## [Proposal] 
Uni-PD: A SuperPod-native, Memory-semantic PD-disaggregation paradigm.

## [Motivation] 
**Towards a SuperPod-native, memory-semantic architecture for LLM serving**:
**--Can PD disaggregation behave as if prefill and decode were colocated on a single GPU?**
<img width="1898" height="1230" alt="image" src="https://github.com/user-attachments/assets/2a5aa745-5bd7-4917-95ac-5dac508a5bf0" />

- **PD disaggregation is wasting time on KVCache transfer:** 
  - Under PD colocation, prefill and decode run sequentially. Limited compute efficiency motivates the move toward PD disaggregation.
  -  In current PD-disaggregated architectures, prefill completes first, then transfers the KVCache to the decode node. Decode must wait for the KVCache to be locally copied before computation can begin, resulting in unnecessary latency.
- **Can PD disaggregation be unified to work as if it is colocating? -- A PD zero-transfer approach.**

## [Proposing] 
**Uni-PD: A SuperPod-native, Memory-semantic PD-disaggregation paradigm**
<img width="850" height="284" alt="image" src="https://github.com/user-attachments/assets/5e830131-b639-44c6-8ee3-b3208332c2e4" />

- **SuperPod-native**: Uni-PD currently leverages the SuperPod's scale-up domain to achieve a PD-disaggregation paradigm. 
- **Memory-semantic**: In Uni-PD, a GPU worker can directly store the computed KVCache into the HBM of another GPU during kernel computations. In Uni-PD, the Prefill node stores KVCache into the Decode node's HBM during prefill computation, via a peer view of the Decode node's HBM. The decode node can start decoding without changing its GPU kernels. 
- **Zero explicit-transfer**: The kernel calculation of the Prefill node will store KVCache directly into the Decode node's HBM. This paradigm removes the need for explicit KVCache transfer between PD workers.  
- **New paradigm**: Uni-PD is our first demonstration of applying a memory-semantic paradigm to LLM serving. The core idea is to integrate memory-semantic operations (e.g., “store” / “direct-write” to remote HBM) to higher-level serving frameworks. Such a design philosophy generalizes beyond PD disaggregation and enables a broader set of applications, which will be discussed below and released as follow-up PRs. 

## Modifications

- conn.py: Updated NVSHMEMKVManager and NVSHMEMKVSender to support pwrite mode. Added notify_pwrite_chunk to handle direct write notifications.
- prefill.py: Added _maybe_use_decode_peer_views to map decode node's memory for direct writing. Updated send_kv_chunk to send dummy signals in pwrite mode.
- utils.py: Added NVSHMEM_PWRITE_MODE constant to toggle the feature via environment variable SGLANG_NVSHMEM_PWRITE_MODE.

## Benchmarking and Profiling
1. Experiment settings
   - Machines: 2 nodes GB200 with IMEX. Each node has 4 B200 GPUs. 
   - CUDA Version: 13.0
   - Comparison: Uni-PD vs Nixl 0.8.0
   - Model: DeepSeek-R1-0528
```sh
#decode node
export NVSHMEM_SYMMETRIC_SIZE=180G
SGLANG_NVSHMEM_BOOTSTRAP=decode-ip:8998 SGLANG_NVSHMEM_PWRITE_MODE=1 SGLANG_NVSHMEM_ROLE=decode SGLANG_ENABLE_NVSHMEM_KV=1     SGLANG_PD_DEBUG=0 PYTHONUNBUFFERED=1 python3 -m sglang.launch_server     --trust-remote-code     --model-path /home/model/deepseek-ai/DeepSeek-R1-0528     --disaggregation-mode decode       --disaggregation-bootstrap-port 8997       --disaggregation-transfer-backend nvshmem       --disaggregation-ib-device mlx5_bond_0,mlx5_bond_1,mlx5_bond_2,mlx5_bond_3       --port 30001   --host decode-ip       --tensor-parallel-size 4       --page-size 64     --mem-fraction-static 0.9     --chunked-prefill-size 16384     --max-running-requests 512     --context-length 65535     --enable-cache-report     --log-level info     --load-balance-method round_robin     --quantization fp8     --kv-cache-dtype fp8_e4m3     --disaggregation-prefill-tp 4

#prefill node
export NVSHMEM_SYMMETRIC_SIZE=180G
```

## [Advantages]
- Eliminating 100% of explicit KVCache transfers in the PD-disaggregated path. 
- Reducing ~80% of send_kv_chunk() time. 
- Transparent to different attention kernels. (in both prefill and decode phases)
