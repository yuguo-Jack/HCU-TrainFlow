# [AMD] DeepSeek-V4.1: fix four MegaMoE crashes at attention TP > 1

[Upstream PR](https://github.com/sgl-project/sglang/pull/43499) · state: open · merged: False

## Original PR description

DeepSeek-V4.1-Flash with MegaMoE at TP4 crashes in four places on MI355X. These runs turn the vision layers off (`vision_n_layers` 0), because V4.1's vision check rejects every all-to-all MoE backend. First, decode graph capture fails. The attention gather after the MoE uses a list all-gather, which calls torch.distributed directly. The gather now pads the rank chunks to one size, gathers them as one tensor and drops the padding rows. Second, the first padded one-request extend fails a shape check. The sliding-window replay tail kept the padding rows that batch padding adds. The tail is now taken only when there are no padding rows. Third, the GPU hits a memory fault, because padding rows got unwritten request indices. The real rows are now built from the CPU lengths, and the padding rows point to request 0, the padding slot. Fourth, every chunk above 8192 tokens fell back to the Triton MoE, which cannot read MegaMoE's weight layout. The MegaMoE gate compared the global token count with a per-rank token limit; it now compares the tokens per rank. Paths without an all-to-all MoE backend are unchanged.

Tested on the ROCm 10-06 image (SGLang 679d2851 with #42796), MI355X, TP4. With these fixes, MegaMoE captured decode graphs up to batch 256. It served all benchmark points with no traceback, including 16k chunks, which ran through MegaMoE with no fallback. The tested code also had a small opt-in decode instance that this PR leaves out, so this exact branch was not run on GPU. The new CPU tests (`test_deepseek_v4_megamoe_fixes.py`, 30 cases) pass on this branch. On main, the 19 fix cases fail and the 11 others pass. GSM8K with MegaMoE is not tested on this base. This PR fixes crashes only. MegaMoE stays slower: TPOT is 12.7% to 38.8% higher than a TP4 run without MegaMoE that uses the same two settings (shared-expert fusion off, vision layers off). That end-to-end comparison also changes the expert layout.
