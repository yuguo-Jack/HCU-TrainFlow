# [HiCache] Fix DSA direct-linker assembly with skipped top-k layers

[Upstream PR](https://github.com/sgl-project/sglang/pull/43773) · state: open · merged: False

## Original PR description

## Motivation

DSA layers that reuse another layer's top-k result keep a zero-row Index-K placeholder in `IndexKeyCache.buffer` so the list remains aligned with model layers. The Mooncake direct-linker assembler currently passes these placeholders to `DevicePoolEntry`, which raises `ZeroDivisionError` while computing `buffer.nbytes // buffer.shape[0]`. Including a zero-row placeholder would also make the pool's minimum row count zero.

We reproduced the failure with CPU unit tests before applying this fix.

## Modifications

- Exclude zero-row target and MTP draft Index-K buffers from the DSA direct-linker pool.
- Build a separate Index-K layer mapping over the remaining buffers, preserving packed target/draft ordering and byte offsets. A skipped target layer can still transfer an active draft buffer at the same depth.
- Keep KV buffers and their existing layer mapping unchanged.
- Add two regressions to the existing CPU-CI-registered `test_linker_pool_assembler.py`, covering skipped layers, page metadata, layer pointers/offsets, and sparse target buffers combined with MTP drafts.

## Accuracy Tests

No model accuracy evaluation or full server run was performed. This change is limited to cache-transfer metadata; model forward code and numerical kernels are unchanged.

CPU unit validation used Python 3.10.12 and PyTorch 2.10.0:

| Validation | Result |
| --- | --- |
| Both added regressions against the unmodified assembler at `2240049194a0` | Both failed with `ZeroDivisionError` |
| The same two regressions against the fixed assembler | Both passed |
| Additional dense DSA + MTP helper control | Passed; existing packed offsets were preserved |

The failure occurred in the production assembler:

```text
DevicePoolEntry.__init__
    buffer.nbytes // buffer.shape[0] * self._row_span
ZeroDivisionError: integer division or modulo by zero
```

The normal test-module entry point was blocked in the available environment by a missing optional dependency, `aiter.ops.triton.gemm`, imported transitively through `CustomTestCase`. For the before/after validation, an isolated runner replaced only the test infrastructure's `CustomTestCase` with `unittest.TestCase`. The repository test file and production assembler were executed unchanged; all test tensors were on CPU. This does not establish full-file or end-to-end coverage.

Static checks passed:

