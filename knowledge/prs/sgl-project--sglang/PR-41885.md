# [XPU][Diffusion] Plain-torch scale-shift for inductor

[Upstream PR](https://github.com/sgl-project/sglang/pull/41885) · state: closed · merged: True

## Original PR description

LayerNormScaleShift (norm1, norm_out) and MulAdd (mlp_residual) called the hand-written triton kernel fuse_scale_shift_kernel_blc_opt on XPU. Inductor treats a user-defined triton kernel as opaque: inside a compiled region it is neither fused with its neighbours nor retuned, so the LayerNorm output had to be materialized and cast before the modulation, and the kernel itself ran at a fraction of the card's memory bandwidth (2D masked tiles and strided broadcast reads). Writing both sites as plain torch removes that barrier. The math is the same fp32 multiply-add rounded once to the input dtype; the compiled residual add is bit-identical to the triton kernel and the norm path agrees to within a bf16 ulp, the difference being one rounding instead of two.

In eager, and equally with a torch.compile wrapper around the old bodies, the picture is unchanged: the triton kernel dominates either way and the plain-torch path costs about the same as it did. With compilation enabled the new path has room the old one never had: inductor emits one kernel per site at memory bandwidth, LayerNorm+modulation+cast fused and the residual add as a single pointwise kernel, roughly 4-5x less device time for these sites than the pass-through triton kernel. Other platforms are untouched; forward_native keeps the triton kernel.
