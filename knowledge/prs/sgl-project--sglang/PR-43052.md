# [Speculative] Add draft sampling overrides and retain corrected proposal probabilities

[Upstream PR](https://github.com/sgl-project/sglang/pull/43052) · state: open · merged: False

## Original PR description

## Motivation

Stochastic draft proposals need their own sampling controls, and verification must use the exact distribution each proposal was drawn from. EAGLE and DSpark previously ignored the request's top-k/top-p when drafting, and DSpark rebuilt q from logits during verification. Once cutoffs apply after the model's correction, verification has to keep the q that was actually sampled.

## Modifications

- Add `--speculative-draft-temperature`, `--speculative-draft-top-k` and `--speculative-draft-top-p`. Each omitted value inherits the request's setting; top-k `-1` and top-p `1` disable that cutoff. Greedy requests stay greedy, and draft temperature `0` makes proposals greedy.
- `srt/sampling/draft_sampling.py`: `DraftSamplingParams` resolves the overrides, and `build_draft_probs` returns q = top_p(top_k(softmax(logits / T))) over the model's final, corrected scores. Greedy is encoded only as `top_k == 1`, as in `SamplingParams`.
- EAGLE/EAGLE3/MTP rejection sampling uses it in prefill, eager decode, per-step and single CUDA graphs. The draft graph runner stages the request's temperature/top-k/top-p, and the overrides resolve inside the graph.
- DSpark samples from q after the Markov correction and saves that q for verification and the accept estimator. `DraftBlockResult.greedy_mask` remains the target's mask, so the accept rule and sampling-mask capture are unaffected by draft overrides.
- DFlash2 selector and sampled LiLiCorr apply the policy to each corrected conditional over the K candidates; top-k cannot add tokens. The walk kernel now takes q only (greedy rows are one-hot q), and its inverse-CDF fallback stays inside q's support.
- `srt/sampling/probability_transforms.py` shares top-k/top-p renorm dispatch between draft proposals and EAGLE/DFlash target verification.
- Plain DFlash, Domino, unsampled LiLiCorr and EAGLE tree search are unchanged.

Default behavior change: with no draft options set, rejection-sampling drafts now also apply the request's top-k/top-p, not just its temperature.

## Accuracy Tests

- CPU (macOS ARM64, Python 3.12, PyTorch 2.14.1, MPS disabled): **120 passed, 18 GPU-only skipped** across the draft-sampling, DSpark, DFlash/selector, EAGLE graph runner, spec registry and server-args suites. Other failures in `test/registered/unit/spec` (`test_eagle_seeded_coins`, `test_graph_pool_borrow`, three collection errors) fail identically on main in this environment.
- GPU tests are added or updated but **not yet run**: target/draft cutoff parity, CUDA graph replay with changing parameters, DSpark folded graph replay, and the selector/LiLiCorr Triton walk.
- pre-commit and `git diff --check` pass.

## Speed Tests and Profiling

Pending GPU validation; this PR is a draft. Expected costs to measure:
- Each rejection-sampling draft step runs top-k and top-p renorm passes over the draft vocabulary.
- DSpark folded sampling keeps an extra `4 * max_bs * gamma * vocab_size` bytes for q, included in its memory eligibility check.
- The greedy-only selector walk builds a one-hot q over the K x K candidate lattice before the walk.
