# [DFLASH] Fall back to FA4 for the draft attention on SM100/SM110

[Upstream PR](https://github.com/sgl-project/sglang/pull/43694) · state: open · merged: False

## Original PR description

## Motivation

When the target model's attention backend is not a supported DFLASH draft backend, `_resolve_dflash_draft_attention_backend` falls back to FlashInfer on every CUDA GPU. That happens for DSA models such as GLM-5.3-Flash and DeepSeek V4 (`attention_backend=dsa`). On B200 the FlashInfer fallback is much slower than FA4 for the DFLASH draft.

## Modifications

- `speculative_hook.py`: the fallback is `fa4` on SM100/SM110 (`get_platform().is_sm100_or_sm110`). Other CUDA GPUs keep `flashinfer`, and ROCm and XPU keep `triton`. An explicit `--speculative-draft-attention-backend` still wins.
- `test_dflash_draft_backend_fallback.py`: with an unsupported target backend (`dsa`), the resolver picks `fa4` on SM100, `flashinfer` on other CUDA GPUs, and `triton` on ROCm and XPU.

## Accuracy Tests

No numerical change: the draft model and verification are the same; only the draft attention kernel changes. With FA4 the DFLASH worker keeps the draft KV cache in BF16 (it already logs `DFLASH fa4 draft: overriding KV cache dtype ...`). Accepted tokens per verify step were the same within run noise (2.5 to 2.9 with either backend, 8 to 32 requests per point).

## Speed Tests and Profiling

GLM-5.3-Flash (FP8 fine-tune), TP8 on one B200 node, v0.5.20, an 8-layer DFLASH drafter (block size 8, sliding window 2,048), 16 prompts of 60K cached tokens, 1,536 output tokens at temperature 1.0 and top-p 0.95. Time per verify step:

| Draft attention backend | 1 request | 4 requests | 16 requests |
| --- | --- | --- | --- |
| `flashinfer` (current fallback for `dsa`) | 9.05 ms | 11.32 ms | 16.03 ms |
| `fa4` (`--speculative-draft-attention-backend fa4`) | 7.14 ms | 9.45 ms | 14.20 ms |

## Validation

- On a B200 node, with the `python/` tree of this branch's base (`main`) and the repository test file: the new test fails on `main` (`AssertionError: 'flashinfer' != 'fa4'`) and passes with this change. `test_oot_dflash_hooks.py` and the new test pass together (7 passed, 6 subtests).
- `ruff format` and `isort` pass for the changed files.
- The speed numbers above come from v0.5.20 with the backend set by flag; this branch was not run end to end on `main`.
