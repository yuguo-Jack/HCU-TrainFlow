# [Bugfix] Keep rope_theta when --json-model-override-args overrides rope_scaling

[Upstream PR](https://github.com/sgl-project/sglang/pull/43067) · state: open · merged: False

## Original PR description

## Motivation

Fixes #41227.

Under transformers v5 the RoPE base lives inside `rope_parameters`, and `rope_scaling` is an alias whose setter replaces that dict wholesale. `get_config()` applies `--json-model-override-args` with a plain `setattr`, so an override like

```
--json-model-override-args '{"rope_scaling": {"rope_type": "llama3", "factor": 32.0, ...}}'
```

(even one that just restates the checkpoint's own scaling) leaves `rope_parameters` without `rope_theta`. `get_rope_config()` then silently falls back to 10000 and the model keeps generating fluent text with the wrong base; the issue measured Llama-3.2-3B-Instruct GSM8K (first 200) dropping from 161 to 106. Models with a hard-coded per-model fallback (Qwen3 dense, 1e6) hide the problem; Llama (500000) and Qwen3-MoE do not.

An earlier attempt (#41239) was closed by its author before review.

## Modifications

`python/sglang/srt/utils/hf_transformers/config.py`: when the override key is `rope_scaling` or `rope_parameters` and both the override and the loaded value are dicts, merge them (override keys win, the rest survives) instead of replacing the dict. Other override keys are untouched; nested `PretrainedConfig` overrides keep the existing `update()` path.

## Accuracy Tests

No model code changes. Two cases in `test/registered/unit/utils/test_hf_transformers_loading.py`, using a local Llama `config.json` with `rope_theta: 500000` (no weights, no download):

- restating the checkpoint's llama3 scaling with a new `factor` through either `rope_scaling` or `rope_parameters` keeps `rope_theta == 500000` and applies the factor;
- an override that names `rope_theta` still wins, while the other rope keys survive.

On `main` both fail (`AssertionError: 10000 != 500000.0`, then `KeyError: 'factor'`); with the fix they pass and the whole file passes (6 tests, 4 subtests; Python 3.12, CPU).

## Speed Tests and Profiling

Not applicable: config loading only.

### Upstream

The root cause is the `rope_scaling` property setter in transformers (`configuration_utils.py`), which replaces `rope_parameters` wholesale; huggingface/transformers#49515 proposes fixing it there. SGLang still needs this merge for the transformers releases it supports today (up to 5.19.0 at the time of this PR).
