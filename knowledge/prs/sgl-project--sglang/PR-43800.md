# [Perf][Multimodal] Bound Qwen-VL video decode batches by pixel budget

[Upstream PR](https://github.com/sgl-project/sglang/pull/43800) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43710. Qwen-VL decoded every selected video frame at full resolution before calculating the final pixel budget. A high-resolution clip could therefore consume several GiB during preprocessing even when the eventual input tensor was small.

## Modifications

- Compute the existing pixel cap and target dimensions from `VideoDecoderWrapper.frame_shape` before decoding.
- Decode and bilinearly resize bounded batches, filling one output tensor. Release scratch tensors before decoding the next batch. Keep the single-batch path when the source video fits its pixel budget.
- Preserve sampling, pixel/resize overrides, dtype, device, output layout, interpolation and metadata. Add eight registered CPU regression tests.

## Accuracy Tests

All eight native CPU regression tests pass. The baseline run fails on unbounded decode batches before the fix. Tests use actual torch/torchvision and mock only the external decoder boundary, covering both wrapper backends, raw batch bounds and lifetimes, ordinary video, upscaling/no-resize, total-pixel caps, explicit dimensions, sampling and invalid-resize rejection.

Real decord preprocessing produces byte-identical uint8 pixels, tensor strides, dtype/device and every metadata field for both the 4K clip and the ordinary control. TorchCodec native libraries could not load in this environment; its wrapper path is covered with a mocked external decoder. GPU execution and model serving/accuracy were not run.

Local test command (the test environment is alongside the source workspace):

```bash
PYTHONPATH=python ../sglang-test-env/bin/python test/registered/unit/multimodal/test_qwen_vl_video_preprocess.py -v
```

Environment: Python 3.12.13, torch 2.10.0+cu128, torchvision 0.25.0+cu128, CPU only. Source baseline: `d0a098b2e08c080bd735cdee97479f9f39148a81`.

## Speed Tests and Profiling

Fresh-process CPU preprocessing of a generated four-second, 8 FPS H.264 `testsrc2` clip, sampling all 32 frames with default spatial processing and four torch threads:

| Clip / observation | Baseline | Fixed |
| --- | --- | --- |
| 3840x2160 raw decode batch | 32 frames / 759.4 MiB | 2 frames / 47.5 MiB |
| 3840x2160 peak process RSS | 6712.4 MiB | 2452.8 MiB |
| 3840x2160 preprocessing elapsed, one run | 2.186 s | 1.760 s |
| 640x360 decode calls | One batch | One batch |
| 640x360 preprocessing median, five runs | 0.120 s | 0.109 s |

RSS sampled every 2 ms; timings exclude imports and decoder construction. These are observed CPU preprocessing measurements, not GPU serving-throughput results. A single source frame can still exceed the budget, and decoder-owned buffers remain outside the returned-batch cap.
