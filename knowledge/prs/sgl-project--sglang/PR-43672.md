# [Fix] Select RoPE parameters by layer type

[Upstream PR](https://github.com/sgl-project/sglang/pull/43672) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43158.

`get_rope_config` treats Transformers v5 per-layer RoPE dictionaries as flat parameters. For example, `Gemma3TextConfig` returns a theta of 10,000 instead of the full-attention value of 1,000,000. DeepSeek-V4 compressed layers also receive the outer dictionary, so reading `original_max_position_embeddings` raises `KeyError`.

## Modifications

- Select the requested layer's RoPE parameters, defaulting to `full_attention` or `main` for nested configurations.
- Select `compress` parameters for DeepSeek-V4 compressed layers, preserving their theta and YaRN settings. Flat and legacy configurations retain the existing `compress_rope_theta` behavior.
- Add real Transformers config coverage and compare the RoPE frequency tables initialized by pure SWA, C4 and C128 layers.

## Accuracy Tests

On unmodified upstream, the new config tests fail and the layer regression produces an incorrect SWA frequency table and `KeyError` for C4/C128. With the fix, all relevant tests pass:

```text
python -m pytest test/registered/unit/utils/test_hf_transformers.py test/registered/unit/utils/test_hf_transformers_loading.py test/registered/unit/models/test_deepseek_v4_rope_policy.py -q
89 passed, 28 subtests passed
```

CPU validation with Python 3.12.13, PyTorch 2.14.1 and Transformers 5.19.0. The layer tests use the existing stubs for attention and linear modules; they exercise real RoPE frequency construction. No model-weight or GPU inference test was run.

## Speed Tests and Profiling

Not run. This changes configuration selection during initialization, with no changes to the forward path or kernels.
