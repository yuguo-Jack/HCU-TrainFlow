# [XPU][Diffusion] Use the AOT SYCL fused residual-norm-scale-shift kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/41401) · state: open · merged: False

## Original PR description

## Motivation

On XPU, `ScaleResidualLayerNormScaleShift.forward_xpu` runs a hand-written triton kernel. That kernel blocks regional `torch.compile` of a Wan2.2 DiT block: inductor re-lowers the triton kernel, and Intel triton then fails to compile the result (`triton/backends/intel/compiler.py:437 make_llir -> RuntimeError: PassManager::run failed`).

sgl-kernel-xpu now has an AOT SYCL kernel for the same op (sgl-project/sgl-kernel-xpu#497). It is registered as a custom op, which inductor treats as opaque, so compiled regions call it unchanged. In eager mode it costs the same on the GPU as the triton kernel. The reason for this PR is compile, not eager speed.

## Modifications

- `kernels/ops/diffusion/norm/scale_residual_norm_scale_shift_sycl.py`: a new backend that wraps `sgl_kernel.diffusion.fused_scale_residual_norm_scale_shift`, plus:
  - `can_use_fused_scale_residual_norm_scale_shift_sycl`, an eligibility check. sgl-kernel-xpu's wrapper raises `ValueError` on unsupported operands, so the check lives here, like the existing triton one.
  - a `register_fake` companion so Dynamo can trace the op. sgl-kernel-xpu registers only the XPU implementation.
- `layernorm.py`: `forward_xpu` prefers the SYCL kernel and falls back to triton, then to `forward_native`. The import sits in the existing `_is_xpu` block, so other platforms never import `sgl_kernel`. An sgl-kernel-xpu without the op leaves `_has_sycl_fused_norm` False, and the triton path runs as before.
- `wanvideo.py`: `WanTransformerBlock` now builds its null shift/scale in the modulation dtype (`shift_msa.dtype`, asserted fp32) instead of `hidden_states.dtype` (bf16). Both fused kernels require one dtype across gate, shift, scale, weight and bias, and `self_attn_residual_norm` has fp32 affine parameters and an fp32 gate. The bf16 zeros disqualified that call site on every call, so it fell back to triton (trace: 80 SYCL + 80 triton launches per step), which inductor also cannot lower. The other Wan block class in the file already uses fp32 zeros, and zeros are exact in either dtype.
