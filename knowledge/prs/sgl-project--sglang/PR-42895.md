## Motivation

Without an a2a MoE backend, a Kimi K3 MoE runs its shared experts on the TP group, and `_reduce_shared` all-reduces their output over it. The shared experts were built without explicit TP arguments, so under DP attention with `--enable-dense-mlp-attn-tp` they took the dense MLP's attention-TP sharding instead. Each attention-TP replica then computed the full shared output, and the TP all-reduce added `attn_dp_size` copies of it.

## Modifications

- Build the shared experts on the TP group explicitly.
- Every other configuration already resolved to that group, and an a2a backend keeps its own shared-expert layouts.
- `test_kimi_mlp_parallel_groups.py` also checks the shared experts' placement at TP 4 × attention DP 2 with `--enable-dense-mlp-attn-tp`: without an a2a backend they shard over the full TP group.

## Accuracy Tests

B200, synthetic Kimi K3 without dense layers (`first_k_dense_replace=0`), TP 4 × DP 2, deterministic inference. The reference is the same configuration without `--enable-dense-mlp-attn-tp`:
- `main` with `--enable-dense-mlp-attn-tp` differs by 0.69 in logprob, and its greedy tokens differ.
- This change with `--enable-dense-mlp-attn-tp` is bit-identical to the reference.

## Speed Tests and Profiling

Not applicable: only `--enable-dense-mlp-attn-tp` under DP attention changes, where each rank now computes its TP shard of the shared experts instead of all of them.
