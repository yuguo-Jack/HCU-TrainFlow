# [Gemma4][Attention] Enable Gemma4 FA4 on SM90 with head-dim 512 support

## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Enable opt-in FlashAttention 4 serving for Gemma4 on Hopper GPUs.
Gemma4 combines sliding-window attention with head dimension 256 and global attention with head dimension 512. The existing SM90 FA4 implementation does not support the latter, preventing Gemma4 from using this backend.

## Modifications

<!-- Detail the changes made in this pull request. -->
- Add SM90 support for equal Q/K and V head dimensions of 512, including tile selection, shared-memory layout, pipeline stages, and paged KV handling.
- Add a generalized SM90 decode split heuristic that avoids splitting short KV spans when sufficient query/head blocks are available.
- Allow Gemma4 to select --attention-backend fa4; retain Triton as the default.
- Add compact image-range metadata and an FA4 mask callback for image-token bidirectional attention. Image spans crossing prefill chunks retain the existing Triton causal fallback.
- Extend the existing test_flash_attention_4.py with SM90 regression coverage.

- SamMausberg · comment · 2026-10-03T06:58:29Z · [source](https://github.com/sgl-project/sglang/pull/42019#issuecomment-5966557361)

One thing on the [`paged_kv.py` line](https://github.com/sgl-project/sglang/blob/1508bfe5c05d22fccb2826dbd7b41bc07aa6661d/python/sglang/kernels/ops/attention/flash_attn/cute/paged_kv.py#L97): at tile_n 144, `max(1, n_block_size // num_threads)` leaves each thread one page-table entry short. A ceil-divide, as in Dao-AILab/flash-attention#2745 and #35757, covers that and still gives 1 at this PR's tile_n 64.

head_dim 80 and 96 get tile_n 144 when there is no causal or local masking. There the formula gives each thread 1 page-table entry, as the floor did before this PR. But the loader's last pass [reads a second](https://github.com/sgl-project/sglang/blob/1508bfe5c05d22fccb2826dbd7b41bc07aa6661d/python/sglang/kernels/ops/attention/flash_attn/cute/paged_kv.py#L308-L311): the one [`load_page_table`](https://github.com/sgl-project/sglang/blob/1508bfe5c05d22fccb2826dbd7b41bc07aa6661d/python/sglang/kernels/ops/attention/flash_attn/cute/paged_kv.py#L177-L182) would fill for rows 128-143.

I evaluated both forms on CPU at every SM90 tile this PR's `_tile_size_fwd_sm90` picks. That covers head_dim 16-256 in steps of 16, and 512, each non-causal, causal and local. `max(1, ...)` is short only at head_dim 80 and 96, and the ceil-divide is never short.

That part is code reading plus the CPU check. My GPU runs of this form at tile_n 144 give wrong output, but they also hit a separate bug in the loader's partial last pass (Dao-AILab/flash-attention#2957, fix in Dao-AILab/flash-attention#2958). So they don't isolate the missing entry. That bug also means the ceil-divide alone doesn't make tile_n 144 correct. On SGLang main, head_dim 80 and 96 are still wrong with it and correct with both changes. [My follow-up on #35757](https://github.com/sgl-project/sglang/pull/35757#issuecomment-5966360526) has the runs and the vendored-copy diff.
