# [Diffusion] Fix int32 offset overflow in the Ulysses packed-QKV pack kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/43140) · state: closed · merged: True

## Original PR description

## Motivation

With Ulysses SP, `_pack_qkv_destination_major_kernel` packs each rank's q/k/v rows for all heads using int32 offsets. Once a rank packs more than 2^31 elements (`rows*3*H*D`), the offsets wrap: part of the output is never written and attention reads garbage. When q/k/v are views of a fused qkv projection, the load offsets wrap too.

Boundary for MiniMax-H3 (H=56, D=128): 99,865 rows per rank. A stock 15 s Ref2VA request at 1312x736 packs 358,667 rows, so Ulysses 2 (179,334 rows/rank) renders pure noise while Ulysses 4 works. At Ulysses 2, 8 s works, 9 s breaks partway, and 10 s or longer is noise.

## Modifications

Add an `IDX64` constexpr, as in `wan_causal_cache_triton.py`: the launcher picks int64 offsets only when the output or a strided q/k/v view can pass 2^31 elements. Smaller shapes keep the int32 kernel. Add one regression test that fails before the fix.

## Accuracy Tests

- H3 Ref2VA 15 s at 1312x736, Ulysses 2 on 2xB200: stock is noise on all 362 frames (SSIM 0.17 vs the Ulysses-4 render). With the fix, SSIM is 0.95, the expected cross-degree difference. Peak memory is unchanged. (Run with an always-int64 build, which takes the same path at this shape.)
- `test_layout.py`: the new test fails on stock (illegal memory access) and passes with the fix; it covers the output, the q/k/v views, and both passing 2^31. All other tests pass.

## Speed Tests and Profiling

B200, H=56, D=128, mean +- std over 8 interleaved fresh-process runs of 100 reps each (ms).

| rows, world size | stock | fix |
|---|---|---|
| 89,667, 4 | 1.152 +- 0.004 | 1.153 +- 0.002 (+0.1%) |
| 44,834, 8 | 0.584 +- 0.000 | 0.586 +- 0.000 (+0.3%) |
| 41,750, 8 | 0.545 +- 0.000 | 0.547 +- 0.000 (+0.4%) |
| 179,334, 2 | n/a (overflows) | 2.548 +- 0.006 |

Always-int64 offsets cost +9.5 to +10.5% at the same shapes in the same run, hence the `IDX64` switch.
