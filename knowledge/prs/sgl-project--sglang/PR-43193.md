# [Docs] Add Qwen3.5 GB200 Dynamo recipe selector / [Docs] 添加 Qwen3.5 GB200 Dynamo 配方选择器

[Upstream PR](https://github.com/sgl-project/sglang/pull/43193) · state: open · merged: False

## Original PR description

The Qwen3.5 selector only generates aggregated serving commands and disables FP4 on GB200, so the new Dynamo deployment cannot be selected there. Add **Dynamo PD (GB200 NVFP4-V2)** to the existing selector, backed by the nine serving variants qualified in [InferenceX #2594](https://github.com/SemiAnalysisAI/InferenceX/pull/2594).

The selector generates copyable prefill, decode, and frontend commands with the selected variant's MTP depth, kernels, cache and scheduling limits, worker environment, request plane, and Dynamo package pair. TP16 decode exposes the four host ranks; discovery and decode-leader addresses are editable. The page explains the pinned container, checkpoint staging, fabric, etcd/NATS, and single or three-replica frontends with nginx. Worker commands now live in the selector instead of a duplicated shell case block.

These are short-context text-serving settings (`context-length=9236`) with FP8 KV cache and disabled radix cache. Long watchdogs and the final variant's `mem-fraction-static=0.94` remain visible tradeoffs. The page reports image build metadata and executed package fingerprints separately.

The rendered Mintlify selector was exercised across all nine variants and command roles, including clipboard output, TP16 ranks, address changes, and returning to aggregated serving. [Run 34389014274, attempt 1](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/34389014274), at InferenceX commit `c6331223dc1495f185373aef7ce2e1c759441367`, executed nine benchmarks and six GSM8K evals; strict exact match was 0.9666–0.9719 against a 0.94 threshold. That is existing harness qualification. The generated standalone Docker, service, and worker commands have **not** been independently executed on GB200.

Qwen3.5 页面顶部的选择器此前只能生成聚合式服务命令，并且禁止在 GB200 上选择 FP4，因此无法从界面选择新增的 Dynamo 部署。本 PR 在现有选择器中加入 **Dynamo PD (GB200 NVFP4-V2)**，覆盖 [InferenceX #2594](https://github.com/SemiAnalysisAI/InferenceX/pull/2594) 已验证的九种服务配置。

选择器按所选配置生成可复制的 prefill、decode 和 frontend 命令，包含对应的 MTP 步数、内核、缓存和调度限制、worker 环境变量、请求传输方式以及 Dynamo 包版本。TP16 decode 提供四台主机的 rank 选择，并支持修改服务发现主机和 decode leader 地址。页面说明固定镜像版本、checkpoint 准备、网络设置、etcd/NATS，以及单 frontend 或通过 nginx 代理的三个 frontend 副本。worker 命令统一由选择器生成，移除了重复的 shell case 配置块。

这些配置面向短上下文文本服务（`context-length=9236`），使用 FP8 KV cache 并关闭 radix cache。较长 watchdog 超时和最终配置 `mem-fraction-static=0.94` 的取舍仍明确展示。页面分别记录镜像构建信息与实际运行的包指纹。

已在实际渲染的 Mintlify 页面中验证全部九种配置和三个命令角色，包括复制内容、TP16 rank、地址修改，以及切回聚合式服务。[Run 34389014274, attempt 1](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/34389014274) 对应 InferenceX 提交 `c6331223dc1495f185373aef7ce2e1c759441367`，实际执行了九个基准任务和六个 GSM8K 评测任务，严格精确匹配率为 0.9666–0.9719，高于 0.94 阈值。该证据来自原有测试框架；生成的独立 Docker、服务及 worker 启动命令尚未在 GB200 上单独执行。
