# [Multimodal] Keep Pillow's decompression-bomb guard in NanoNemotron processor

[Upstream PR](https://github.com/sgl-project/sglang/pull/43713) · state: open · merged: False

## Original PR description

Fixes #43707

## Motivation

`NanoNemotronVLImageProcessor.__init__` set `Image.MAX_IMAGE_PIXELS = None`. That is process-global Pillow state, so once a NanoNemotron model was loaded, Pillow's decompression-bomb guard was off for every later image decode in the process (including the generic `Image.open(...).load()` path in `utils/common.py`), not just NanoNemotron requests.

## Modifications

- Remove the global `Image.MAX_IMAGE_PIXELS = None` assignment. It came in with the original model port (#12277) and nothing in the processor relies on it; Pillow's default limit (warning above ~89M pixels, error above ~179M) is far above the image sizes the processor tiles.
- Add `test/registered/unit/multimodal/test_nano_nemotron_vl_processor.py` (CPU suite), which constructs the processor with stubbed dependencies and checks `Image.MAX_IMAGE_PIXELS` is unchanged. It fails on `main` (`None != 89478485`) and passes with this change.
