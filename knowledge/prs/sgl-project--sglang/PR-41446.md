# [HiSparse] Avoid host synchronization in eager backup

[Upstream PR](https://github.com/sgl-project/sglang/pull/41446) · state: closed · merged: True

## Original PR description

## Motivation

When HiSparse eager backup has any token to save, constructing its index tensor directly on CUDA performs a blocking H2D copy. The host must wait for preceding work and dependencies on that stream. When these include unfinished forward work, the copy prevents CPU batch preparation from overlapping it; the size of the stall depends on the stream dependencies and workload.

## Modifications

Build the indices in pinned CPU memory and copy them to the target device with `non_blocking=True`. Existing stream ordering and backup completion events remain intact.

Validation used a temporary CUDA regression test that ran the real eager-backup path under synchronization diagnostics, checked the backed-up KV contents for every layer, and checked allocator cleanup. This test is not included in the final PR diff.
