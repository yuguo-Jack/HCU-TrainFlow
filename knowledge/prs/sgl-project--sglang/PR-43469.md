# [NPU] Support dynamic INT8 MLAProlog for GLM-5.2 attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/43469) · state: open · merged: False

## Original PR description

## Motivation

Enabling `SGLANG_NPU_USE_MLAPO=1` for GLM-5.2-w4a8c8 routes its `W8A8_DYNAMIC` attention projections through the legacy static ModelSlim path, causing an `AttributeError` when accessing `input_offset`.

This PR enables MLAProlog V3 dynamic INT8 execution for these projections.

## Modifications

- Select the MLAProlog quantization mode from the loaded QKV-A and Q-B quantization methods.
- Add mode 2 weight preparation using ModelSlim's `[K, N]` INT8 layout, splitting QKV-A weights and per-channel scales into Q-A and KV-A.
- - Dynamically quantize BF16 input activations to INT8 per token, and pass FP32 activation scales and per-channel weight scales to MLAProlog.
- Reuse the quantized latent and scale for dynamic INT8 indexers, recompute the BF16 latent for BF16 indexers, and skip this handling when `indexer=None`.
- Preserve the original projection weights and `w_kc` needed by subsequent computation.
- Add six CPU regression tests to `base-a-test-cpu`, covering dispatch, tensor contracts, weight preparation, unsupported configurations, indexer handling, and weight lifetime.

The dynamic INT8 path currently supports interleaved RoPE and requires BF16 input activations, KV cache, and `w_kc`, with BF16 final query output. NeoX RoPE and nonzero RMSNorm bias are rejected. C8 KV cache support and MoE/MLP quantization changes are outside this PR's scope.

## Accuracy Tests

- Manual smoke test: GLM-5.2-w4a8c8 runs successfully with `SGLANG_NPU_USE_MLAPO=1` in the tested configuration.
- All six CPU unit tests passed:

  ```bash
  python test/registered/unit/attention/test_npu_mlaprolog.py -v
  ```

- The dispatch regression test reproduces the original `input_offset` error against the pre-change implementation.
- Formatting, lint, and CI registration checks passed.

The CPU tests execute the production Python adaptation logic with NPU operators mocked. Full model accuracy evaluation and numerical validation against real NPU operators have not been performed.

## Speed Tests and Profiling

Not performed. No performance improvement is claimed.
