# [diffusion] keep TP/Ulysses head shards on the unsharded torch SDPA kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/43242) · state: open · merged: False

## Original PR description

## Motivation

PyTorch's flash SDPA forward picks split-KV when `batch * heads * ceil(query_len / 128)` is below 80% of the SM count (`num_splits_heuristic` in ATen's `flash_api.cpp`). Split-KV reorders the softmax sums. Tensor parallelism and Ulysses both reduce the number of heads each rank attends over. At short sequence lengths, that can push a head shard onto the split kernel while the unsharded layer stays unsplit. The result is that `--attention-backend torch_sdpa` runs differ between parallel and single-GPU execution even at the attention-operator level.

The default backends do not depend on the head count, and are unaffected:
- sm100: cuDNN SDPA. Measured on B200: head shards are bit-identical.
- sm90: sgl FA3, which runs with `num_splits=1`.

Affected setups:
- explicit `--attention-backend torch_sdpa`;
- sm120, where torch SDPA is the default;
- head dims that fall back to torch SDPA.

This came up while validating Ovis-Image (#43152), which carries a model-local version of this fix.

## Modifications

- **`SDPAImpl`** pads query rows past the split threshold when all of the following hold:
  - the request asks for `quality="exact"`;
  - the call is a non-causal, unmasked fp16/bf16 CUDA call, without dropout and with head_dim ≤ 256;
  - the local head count would split, but the unsharded layer's would not.

  Query rows attend independently, so the real rows match the unsharded kernel bit for bit. The padding is sliced off afterwards.
- **Gated on `exact`**: under the quality tiers, the default `lossless` tier already allows rounding-order changes. It keeps the faster split kernel and is unchanged by this PR.
- **`USPAttention`** accepts `global_num_heads`, the layer's head count before TP sharding, and forwards it to the impl. It defaults to `num_heads`, which already covers Ulysses-only sharding.
- **TP-sharding DiTs** pass their pre-TP head count: FLUX, FLUX.2, Qwen-Image, Anima, Wan, HunyuanVideo, Z-Image.
- **Unchanged**: `CudnnSDPAImpl` / `DynamicCudnnSDPAImpl`, explicit cuDNN priority, masked/causal calls, FA varlen and ring paths.
- **Tests**:
  - `test/unit/test_sdpa_sharded_heads.py`: head shards vs the unsharded output, plus every case that must not pad.
  - `test/single_test_file/test_usp_sdpa_sharded_heads_2_gpu.py`: real Ulysses2 `USPAttention` vs a single rank.

**End-to-end images** (exact tier, torch SDPA). FLUX.1-dev at 384² / 28 steps and Qwen-Image at 512² / 30 steps, so that 2-way head shards cross the split threshold. Mean absolute pixel difference against 1 GPU, over seeds:

| Model / topology | before (mean ± std) | with this PR (mean ± std) |
|---|---|---|

| FLUX.1-dev Ulysses2 | 3.48 ± 0.88 | 4.44 ± 0.65 |
| Qwen-Image TP2 | 2.10 ± 0.85 | 1.80 ± 0.50 |
| Qwen-Image Ulysses2 | 2.19 ± 1.27 | 1.97 ± 1.02 |

![FLUX.1-dev](https://raw.githubusercontent.com/fusheng-ji/sglang/699cd5ab302193bec227cf4f22218aa8bb2a812f/e2e-flux.jpg)

![Qwen-Image](https://raw.githubusercontent.com/fusheng-ji/sglang/699cd5ab302193bec227cf4f22218aa8bb2a812f/e2e-qwen.jpg)

**This PR does not claim an end-to-end improvement.** Every parallel image is visually equivalent to the single-GPU one, both before and after the change. The pixel differences come from many small rounding differences that the denoising loop amplifies, and they vary strongly between seeds. Over 5 seeds:
- TP2 is slightly closer to 1 GPU.
- Qwen-Image Ulysses2 is unchanged within noise.
- FLUX.1-dev Ulysses2 is slightly further away; 4 of 5 seeds got worse.

Other parallel effects, such as GEMM shapes and reductions, still separate the runs. What this PR guarantees is narrower: under the exact tier, the attention operator no longer changes with the head sharding.

Unit tests: the new unit and 2-GPU tests fail without the change and pass with it; 146 related USP/attention unit tests pass.

## Speed Tests and Profiling

Padding only triggers for exact-tier requests at short sequence lengths with sharded heads. Single attention call, B200:

| local heads / seq | padded to | before | exact tier with this PR |
|---|---|---|---|
| 12 / 1088 | 1280 | 58 µs | 61 µs |
| 6 / 1088 | 2560 | 34 µs | 65 µs |
| 6 / 1536 | 2560 | 39 µs | 118 µs |
| 12 or 6 / 4608 | not padded | unchanged | unchanged |

The `lossless` (default) and `high` tiers are unaffected.

## Not covered

- sm120 and sm90 were not run on hardware. On sm90 the default FA3 path is unaffected by construction (`num_splits=1`); sm120 uses the same PyTorch flash heuristic with its own SM count.
- The component-accuracy harness gives every rank the full token set under SP. Its Ulysses whole-model comparison against 1 GPU is therefore not like-for-like and is not reported. Ulysses is covered by the real 2-GPU test above.
