# [AMD][DSV4] perf: tuned FlyDSL fp4 indexer score  on MI355X

[Upstream PR](https://github.com/sgl-project/sglang/pull/37173) · state: closed · merged: False

## Original PR description

> Stacked on #37062 (ROCm fp4 indexer enablement); this is the FlyDSL tuned-score commit on top of it.

## Summary

On gfx950 (MI355X) the DeepSeek-V4 fp4 sparse indexer was scored with a hand-written **Triton** paged-MQA-logits kernel, which is **3–7% slower than the fp8 gluon** kernel — so `--enable-deepseek-v4-fp4-indexer` was a decode-throughput regression despite fp4's smaller index-K.

aiter already ships a **tuned FlyDSL fp4** kernel (`flydsl_pa_mqa_logits_fp4`, native mxfp4 MFMA). At the exact DSV4 indexer geometry (heads 64, head_dim 128, 128k) it is **1.32–1.63× faster than the fp8 gluon kernel at cos = 1.0** (the AMD analog of B200's DeepGEMM fp4 path). This PR wires it in for **decode / MTP target-verify**.

## Results — 1× MI355X, TP8 + DP-attention + MTP, 128k in / 1k out

**Accuracy (GSM8K 1319/1319):**

| indexer | GSM8K | Invalid |
|---|---|---|
| fp8 | 0.945 | 0.000 |
| **fp4 + FlyDSL** | **0.948** | 0.000 |

**Decode throughput (tok/s):**

| conc | fp8 | fp4 + FlyDSL | Δ |
|---|---|---|---|
| 32 | 1115 | **1644** | **+47%** |
| 64 | 1760 | **2402** | **+36%** |
| 128 | 2208 | **2516** | **+14%** |

(Before this change, the hand-Triton fp4 path was −3 to −7% vs fp8. The pool-sizing
commit in #37062 lifts the high-concurrency point further.)

## What changed

- **`fp4_indexer.py`** — a fused **quant + preshuffle store** kernel that writes index-K directly in the FlyDSL layout (`[page,1,4,64,16]` fp4 + `[page,1,4,64]` ue8m0; mapping validated bit-exact vs aiter's `create_paged_preshuffle_kv_fp4`), and a `flydsl_fp4_paged_mqa_logits` wrapper (fp4 q, cudagraph-safe `compute_varctx_schedule`).
- **`deepseek_v4_memory_pool.py`** — mirror the index-K into the FlyDSL preshuffle buffers on every store; the primary buffer still feeds the prefill Triton score unchanged.
- **`indexer.py`** — route decode / target-verify to the FlyDSL kernel; prefill keeps the Triton fp4 score.

The indexer pages at 64 tokens = FlyDSL's `kv_block_size`, so `page_table` is the block-table directly (no remap). Guarded by an assert on `page_size==64 && index_head_dim==128`.

## Known follow-ups (from self-review; deliberately deferred)

1. **Single store / drop the primary buffer**: prefill still uses the Triton kernel, so the index-K is stored twice (+~3.5% index-K memory). The clean single store needs the FlyDSL **varqlen prefill** kernel wired cudagraph-safely (prebuilt window buffers refreshed in place); the naive path GPU-faults under graph capture.
2. **Fuse q→fp4 into rope/norm** to drop the per-step `quantize_fp4_indexer_tensor`.
3. **Hoist per-layer wrapper allocs** (`out` buffer + schedule recomputed per layer though `seq_lens` is identical across layers).

None affect the decode numbers above; they are cleanliness + prefill-speed + memory.
