# [diffusion] Enable SANA-Video 2.0 breakable CUDA graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/41501) · state: open · merged: False

## Original PR description

## Motivation

Enable breakable CUDA graphs for native SANA-Video 2.0, following #35729.

## Modifications

- Connect the custom samplers to the shared BCG runner. Capture T2V and TI2V during warmup; replay matching requests and run unseen shapes eagerly.
- Keep the transformer resident and cache RoPE frequencies on device.
- Add a serving example and focused regression coverage.

## Accuracy Tests

On A800, T2V/TI2V videos matched eager exactly, including decoded frames. Changed prompts/seeds, restored inputs, and an uncaptured frame count also matched; those lifecycle probes used four steps. Focused tests and pre-commit passed.

## Speed Tests and Profiling

A800, 832×480, 81 frames, 50 steps, guidance 8, seed 42, all components resident, torch.compile disabled. Means of three requests after warmup; e2e includes video saving.

| Task | Path | Logged denoise (ms/step) | Logged decode (s) | Saved-request e2e (s) |
| --- | --- | ---: | ---: | ---: |
| T2V | eager | 692.8 | 0.12 | 35.96 |
| T2V | BCG | 576.1 | 3.71 | 35.74 |
| TI2V | eager | 694.2 | 0.12 | 36.06 |
| TI2V | BCG | 552.3 | 4.75 | 35.91 |

Logged denoise falls by 16.9% / 20.4%, while e2e improves by 0.6% / 0.4%. Stage timing is unsynchronized: queued GPU work can be charged to decode or later synchronization, so the denoise figures are not isolated GPU speedups.

Peak reserved memory increases from 20.65 to 21.32 GiB. Startup including warmup increases from 23.8 to 62.7 seconds.
