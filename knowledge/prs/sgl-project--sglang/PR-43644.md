# [Diffusion] Capture Cosmos3 GEN MLPs with breakable CUDA graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/43644) · state: open · merged: False

## Original PR description

## Motivation

Cosmos3's eager GEN MLPs incur repeated Python and CUDA launch overhead during denoising. On a single GB300, capturing these stateless regions reduces complete-image latency by 7.3–9.0% while preserving eager outputs bit for bit.

## Modifications

- Reuse the existing breakable CUDA graph runner for each GEN MLP, with a shared graph pool. Attention and the request-owned UND cache remain eager.
- Enable this path with `--enable-breakable-cuda-graph` only for a single CUDA GPU with a resident transformer and `torch.compile` disabled. Rollout remains eager.
- Capture during warmup only; serving shape misses use eager execution. Check weight storage and projection dispatch at each request so replaced weights, LoRA wrappers, and step-dependent quantization cannot replay stale graphs.

The model module hierarchy and state-dict keys are unchanged. No precision or attention-kernel changes are included.

## Accuracy Tests

- 96 generated images across the four SGLang benchmark runs match the corresponding eager output bit for bit, including alternating prompts/seeds.
- CUDA tests exercise FP16/BF16, fresh inputs, retained outputs with a shared pool, shape misses, exception cleanup, weight replacement/in-place updates, adapter/quantization fallback, residency gates, and rollout bypass.
- After consolidating MLP graph cases into the existing `python/sglang/multimodal_gen/test/unit/test_cosmos3.py`, the Cosmos3, rollout and step-mixed-precision suites pass **172 tests / 73 subtests on GB300** at `2270b82`. No new test file remains; the existing registered diffusion unit bridge collects these cases.
- Pre-commit passes on all three changed files.
- [Targeted H100 CI](https://github.com/sgl-project/sglang/actions/runs/38147168080) passes all three Cosmos3, rollout and step-mixed-precision partitions at the same head.

Model-backed validation covers Cosmos3-Nano T2I. Other Cosmos3 variants and video/transfer workloads have not been benchmarked in this PR; the existing unvalidated-model warning remains.

## Speed Tests and Profiling

One GB300, BF16 resident weights, 1024×1024 T2I, 35 steps, CFG 4, three prompts/seeds (42/43/44). Each fresh process performs 9 warmups and 15 measured requests. CPU affinity is fixed to cores 8–15 on NUMA node 0. Cross-request conditioning caching is disabled. Timing covers the native SDK returning a complete CPU image, including text encoding, denoising, VAE, and output transfer; PNG saving is excluded.

| Mode | Repeat 1 median | Repeat 2 median |
| --- | ---: | ---: |
| SGLang eager baseline | 1.493 s | 1.477 s |
| SGLang eager + MLP BCG | **1.383 s** | **1.344 s** |
| vLLM-Omni + regional torch.compile | 1.549 s | 1.546 s |
| Latency reduction vs SGLang eager | 7.3% | 9.0% |
| Latency reduction vs Omni compile | 10.7% | 13.1% |

Run order: eager → BCG → Omni → Omni → BCG → eager. Omni compilation is verified on all 36 GEN layers, with a nonzero Dynamo graph counter. SGLang uses no torch.compile. Framework environments use their supported PyTorch versions: SGLang 2.14.1+cu130 and Omni 2.13.0+cu130, so the within-SGLang comparison isolates this PR's gain.

A separate profile confirms 36 captured MLP graphs and 2,304 actual graph launches per request. Host GatedMLP forward calls fall from 2,376 to 72 (the remaining calls are the UND path). All production captures succeed with no signature misses. Profiling runs are excluded from latency measurements.

Tradeoff: SGLang's reported peak memory increases from 35,928 MB to 39,770 MB (+3,842 MB) for this workload.

Revisions: SGLang baseline `33d2ef17566685f596b82512e8264456716527f7`; Omni `194b936637f4e7356cc998c2796c67d14d52d854`; `nvidia/Cosmos3-Nano` checkpoint `e59a53c25979a090fa8706c9acc0c254a6e89b92`.
