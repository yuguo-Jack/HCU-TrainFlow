# Perf(Qwen3.8-Flash-Next): fuse PLE prefill and decode hot paths

[Upstream PR](https://github.com/sgl-project/sglang/pull/43370) · state: closed · merged: False

## Original PR description

## Summary

This PR extends the packed PLE prefill implementation introduced in #43032 with additional Qwen3.8/Qwen4Exp PLE hot-path optimizations.

It adds:

- packed varlen prefill N-gram generation;
- direct decode short-convolution with state update;
- fused prefill short-convolution activation and residual addition;
- merged non-quantized PLE key/value projection.

The fused paths preserve serving outputs in the tested BF16/FP8 configurations. Unsupported devices, dtypes, layouts, and quantized projection configurations automatically use the existing implementations.

## Dependency

This PR depends on #43032.

PR #43032 introduces packed varlen PLE prefill short-convolution and fixes mixed-length prefill activation-memory amplification and OOM.

This PR is intentionally stacked on top of #43032 and should remain in Draft state until #43032 is merged. After #43032 is merged, this branch will be rebased onto the latest `main` before final review.

## Motivation

After removing the dense padded PLE short-convolution in #43032, several PLE operations still used multiple PyTorch/Triton launches or materialized temporary tensors:

1. Ordinary prefill N-gram generation constructed token contexts and used `unfold`, advanced indexing, EOS masking, and separate hash operations.
2. Decode short-convolution used separate state preparation, `F.conv1d`, `F.silu`, residual addition, and state update operations.
3. Packed prefill short-convolution materialized its convolution result before executing separate activation and residual-add kernels.
4. Non-quantized PLE key and value projections used two independent GEMMs.

This PR fuses these operations where numerical correctness and operator-level performance gains were demonstrated.

## Changes

### Packed varlen prefill N-gram

The new prefill N-gram kernel directly consumes:

```text
input_ids
query_start_loc
per-request history
```

It produces packed N-gram IDs without constructing a padded token context.

The kernel supports:

- variable-length requests;
- empty request rows;
- chunked prefill history;
- EOS truncation;
- signed int64 overflow semantics;
- multiple N-gram heads;
- live ragged metadata during CUDA Graph replay.

The ordinary prefill N-gram path is reduced from approximately 46 GPU launches to 2 launches.

### Direct decode short-convolution

The decode kernel directly performs:

```text
state read
dilated short-convolution
BF16/FP16 materialization
SiLU activation
gated residual addition
main-state update
radix-tracking-state update
```

This replaces the previous sequence of:

```text
state preparation
F.conv1d
F.silu
residual addition
state update
```

The production state allocator guarantees the slot invariants required by the kernel:

- positive main-state slots are unique;
- positive tracking slots are unique;
- positive main and tracking slot sets are disjoint;
- non-positive slots are not written.

### Fused prefill activation and residual

The packed prefill convolution introduced by #43032 can now perform:

```text
convolution materialization
SiLU
gated residual addition
```

inside the Triton kernel.

State writeback remains a separate kernel because it must execute only after all convolution programs have finished reading the previous state.

### Merged non-quantized key/value projection

When `quant_config is None`, the replicated PLE key and value projections are merged into one projection:

```text
key_proj + value_proj
-> key_value_proj
```

Quantized and FP8 models continue using the original independent key/value projection modules and checkpoint-loading path. This avoids changing quantized parameter names, weight scales, or model-loading semantics.

The merged projection is an optimization for non-quantized models and does not contribute to the FP8 serving results below.

## Design decisions

### Full norm/gate fusion is excluded

A full PLE norm/gate Triton prototype achieved approximately `10x-30x` operator-level speedup, but did not preserve strict serving output equivalence.

The differences came from:

- grouped GEMMA RMSNorm versus Triton reduction order;
- PyTorch dot-product reduction versus `tl.sum`;
- PyTorch CUDA sigmoid versus `tl.sigmoid`.

Fixed C16 and C64 serving tests showed that disabling only this fusion restored exact output hashes. The prototype was therefore removed.

### Direct target-verify convolution is excluded

A direct target-verify convolution prototype preserved output and intermediate-state correctness, but regressed the common width-8 case:

| Verify width | Relative performance |
|---:|---:|
| 2 | 1.388x |
| 4 | 1.016x |
| 8 | 0.936x |

Because width 8 regressed by approximately 6.4%, target verify continues using the existing prepare, `F.conv1d`, and finish path.

## Operator benchmarks

Tests were run on NVIDIA H20 using real Qwen3.8/Qwen4Exp PLE dimensions.

### Packed prefill N-gram

| Workload | Original | Fused | Speedup |
|---|---:|---:|---:|
| Equal `4 × 2048` | 412.75 μs | 45.26 μs | 9.12x |
| Mixed `[8192, 1, 1, 1]` | 549.87 μs | 45.32 μs | 12.13x |

GPU launch count:

```text
46 -> 2
```

### Direct decode short-convolution

| Batch size | State dtype | Speedup |
|---:|---|---:|
| 1 | BF16 | 2.71x |
| 8 | BF16 | 3.13x |
| 32 | BF16 | 2.52x |
| 1 | FP32 | 3.61x |
| 8 | FP32 | 4.58x |
| 32 | FP32 | 3.26x |

### Prefill activation and residual fusion

Compared with packed convolution followed by separate `F.silu` and residual-add operations:

| Workload | Latency reduction |
|---|---:|
| Mixed-length | 15.89% |
| Equal-length | 15.80% |
| Radix tracking | 15.73% |
| FP32 state | 18.22% |
| Chunked prefill | 8.83% |

### Non-quantized merged key/value projection

| Token count | Speedup |
|---:|---:|
| 1 | 1.44x |
| 8 | 1.51x |
| 32 | 1.35x |
| 128 | 1.12x |
| 1024 | 1.00x |

The merged projection is intentionally disabled for quantized models.

## End-to-end validation

The final candidate was compared against #43032 using TP8 + EP8 on NVIDIA H20.

Fixed workload:

```text
8K input
1K output
MTP3
CUDA Graph enabled
```

| Concurrency | Output-throughput change | Correctness |
|---:|---:|---|
| 1 | -0.61% | Identical |
| 4 | approximately +25% | Identical |
| 16 | -2% to -3% aggregate; median E2E approximately neutral | 16/16 identical |
| 64 | +0.19% | 64/64 identical |

The concurrency-16 aggregate result was affected by one low-acceptance outlier:

```text
Baseline median E2E: approximately 10.65 s
Feature median E2E:  10.61-10.70 s
```

The C4 result demonstrates that the fused paths can produce an end-to-end benefit when PLE launch overhead is visible, but the C1, C16, and C64 results show that the benefit is not universal.

At higher MTP concurrency, QSA, MoE, TP/EP communication, target verification, and acceptance-rate variation dominate the end-to-end runtime. This PR therefore makes no claim of stable throughput improvement at every concurrency.

## Correctness

The following were compared with the original implementations:

- prefill N-gram IDs;
- EOS behavior;
- signed int64 overflow behavior;
- BF16 short-convolution output;
- FP16 short-convolution output;
- BF16 and FP32 state writeback;
- main and radix tracking state;
- empty and non-contiguous state slots;
- chunked prefill continuity;
- CUDA Graph live ragged metadata;
- MTP3 serving output hashes;
- non-quantized key/value projection output;
- quantized projection fallback.

Observed numerical behavior:

```text
BF16 output/state: exact
FP16 output/state: at most approximately 1 ULP
```

Fixed C16 and C64 MTP3 workloads produced identical output hashes for every request.

## Usage

No new command-line option is required.

Supported fused paths are selected automatically. Unsupported devices, dtypes, layouts, and quantized projection configurations continue using the original implementations.

Example:

```bash
python3 -m sglang.launch_server \
  --model-path <Qwen3.8-Flash-Next-model-path> \
  --tp 8 \
  --enable-ep-moe \
  --ep-size 8
```

## Scope

This PR optimizes isolated PLE hot paths rather than the entire Qwen3.8 inference pipeline.

The largest operator-level gains are in:

- packed prefill N-gram generation;
- direct autoregressive decode short-convolution;
- packed prefill activation and residual fusion;
- non-quantized small-batch key/value projection.

At high MTP concurrency, other parts of the model dominate runtime, so the end-to-end result can be neutral even when the individual PLE kernels are substantially faster.
