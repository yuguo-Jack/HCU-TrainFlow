# [CP] Enable opt-in interleave prefill BCG for GLM-5.3 Flash

[Upstream PR](https://github.com/sgl-project/sglang/pull/43182) · state: open · merged: False

## Original PR description

## Motivation

Stacked on #42044 (base: `codex/glm53-interleave-cp`, `75f2e07fe5`). Enable opt-in breakable CUDA graphs (BCG) for GLM-5.3 Flash interleave prefill CP to reduce host dispatch overhead at small/medium prefill sizes.

This PR extracts **only BCG** from the prefill performance experiment. It does **not** include copy-elision changes, the fused KPool unpack kernel, or an all-reduce replacement. Existing AG + RS transitions remain unchanged.

## Modifications

- Add an interleave-specific BCG input adapter with fixed-address CP-local embeddings/positions and rank-major global token IDs. Preserve global positions for KPool while supplying local positions to DSA.
- Use CP-local physical/logical token counts in the pooled-indexer eager break.
- Preserve an explicitly selected `breakable` prefill backend through the DSA and CP/TP-group-sharing configuration hooks. Default and explicitly disabled configurations remain disabled.
- Keep native MTP draft prefill eager; capture only the target model body.
- Make the CP sequence-length kernel accumulator match the input metadata dtype, supporting both eager int32 metadata and graph int64 metadata.
- Add manual regression tests for replay eligibility, stable input buffers, padded capacity, shared mRoPE behavior, CP=1 fallback, and sequence-length dtypes.

### Scope and usage

Experimental, intentionally narrow replay support: GLM-5.3 Flash, CP = TP > 1, DP/PP/EP = 1; **BS1, prefix-free text requests, exact captured token counts only**. Multi-request, prefix-cache-hit, multimodal, and non-bucket inputs retain eager CP; multimodal inputs are not banned. No automatic CP/TP routing is added.

Add these flags to the #42044 CP4 + native MTP launch command:

```bash
--cuda-graph-backend-prefill breakable \
--cuda-graph-bs-prefill 1024 4096 5120 6144 8192 16384
```

Validated launch configuration:

```bash
python -m sglang.launch_server \
  --model-path "$MODEL" \
  --tp-size 4 --ep-size 1 --moe-dense-tp-size 4 \
  --enable-prefill-cp --cp-strategy interleave --attn-cp-size 4 \
  --dsa-prefill-backend trtllm --dsa-decode-backend trtllm \
  --kv-cache-dtype fp8_e4m3 --moe-runner-backend flashinfer_trtllm \
  --reasoning-parser auto --tool-call-parser auto \
  --speculative-algorithm EAGLE --speculative-num-steps 5 \
  --speculative-eagle-topk 1 --speculative-num-draft-tokens 6 \
  --chunked-prefill-size 16384 --max-prefill-tokens 16384 \
  --max-running-requests 128 --random-seed 42 --enable-metrics \
  --cuda-graph-backend-prefill breakable \
  --cuda-graph-bs-prefill 1024 4096 5120 6144 8192 16384 \
  --host 127.0.0.1 --port 32101
```

`MODEL` is the local `zai-org/GLM-5.3-Flash` snapshot `eb9eb208eb0d988989d07a6a12d0fdeb5f52574a`. Language-only flags are not used. Capturing more buckets costs additional startup time and GPU memory.

## Accuracy Tests

- BCG adapter: 6 tests passed; CP=1 guard regression verified red before the fix and green afterward.
- Existing `test/registered/cp/test_cp_strategy_unit.py`: 24 tests passed.
- GPU CP q-sequence metadata: int32/int64 × CP2/4/8 × every rank passed.
- Real checkpoint configuration resolution: explicit BCG, default, and explicit disabled passed.
- All applicable pre-commit hooks passed.

Fresh BCG-only CP4 + native MTP validation on 4× B300:

- **GSM8K: 95/100** on a diagnostic replay-coverage variant: BS1, 20-shot, temperature 0, max 512 new tokens, cache flushed per request, leading-newline padding to exactly 8192 input tokens. This is not the unchanged registered 500-example test.
- Weighted accept length (`sum(completion_tokens) / sum(spec_verify_ct)`): **4.02116**; mean per-request accept length: **3.95440**. This run is not a new paired TP acceptance study.
- Eager fallbacks passed: non-bucket 1000-token inputs, padded 1025-token inputs, repeated prefix-cache requests, and multimodal image requests at both small and exact 1024-token shapes. Both image probes correctly identified a synthetic red image.
- Full responses, raw benchmark results, resolved server configuration, and logs are saved locally under `artifacts/glm53-cp-prefill-perf-20261008/bcg-only-pr/` (not committed).

These are focused development checks, not a claim that the full CI suite or unchanged registered 500-example accuracy test passed. The added regression scripts are manual, not CI-registered.

## Speed Tests and Profiling

Fresh BCG-only run on 2026-10-08, 4× B300, CP4/TP4, MoE TP4, native MTP enabled. `bench_serving`, random-ids, concurrency 1, exact input length, output length 1, seed 42, 80 measured requests + 5 warmups per point, cache hit 0. All 480 measured requests completed successfully with the expected lengths. The output1 client times first completion-token progress (including empty-text SSE chunks), consistently with the previous benchmark protocol.

| Input tokens | P50 TTFT (ms) | P95 TTFT (ms) |
| ---: | ---: | ---: |
| 1024 | 98.56 | 99.58 |
| 4096 | 123.67 | 126.11 |
| 5120 | 141.34 | 145.84 |
| 6144 | 155.23 | 157.78 |
| 8192 | 185.24 | 188.25 |
| 16384 | 312.72 | 315.39 |

Logs confirm `cuda graph: True` for these exact-bucket requests. Target prefill capture for these six buckets took ~26.5 seconds and reported ~6.62 GiB memory usage per rank. Timings above are unprofiled and from one sweep, not a new paired TP-versus-CP crossover study.

Previous mixed copy-elision/fusion/BCG experiment numbers are deliberately not presented as results of this BCG-only PR. No universal arbitrary-length crossover threshold is claimed; non-bucket lengths still use eager CP.
