# [Kimi] trtllm_mla: serve varlen absorbed MLA under captured prefill CUDA graphs (fixes #32655)

## Motivation

Under a captured prefill CUDA graph the DeepSeek/Kimi dispatcher returns `AttnForwardMethod.MLA` even for a genuine extend. `TRTLLMMLABackend` had no variable-length extend kernel, so it delegated the whole batch to the FlashInfer paged-MLA parent, which does:

```python
# flashinfer_mla_backend.py
k_buf = self.token_to_kv_pool.get_key_buffer(layer.layer_id).to(q.dtype)
```

`get_key_buffer()` returns the **entire KV pool for that layer**. With `--kv-cache-dtype fp8_e4m3` and a bf16 query, this converts the whole pool from FP8 to BF16 **per layer, per forward**. The cost is a full-pool memory copy, not a slow kernel. This is #32655 (Kimi-K2.6-NVFP4, 4×GB300 TP4).

This PR teaches `TRTLLMMLABackend` to serve these extends with absorbed MLA over a ragged query, reading the FP8 paged KV directly, so the conversion disappears.

## Modifications

**`trtllm_mla_backend.py`**
- Extends inside a captured prefill graph now run absorbed MLA over a ragged `q` (`trtllm_batch_decode_with_kv_cache_mla` with `cum_seq_lens_q` / `max_q_len`), reading the FP8 paged KV directly. The prefill metadata gains a block table for this; no new kernel.
- FlashInfer `auto` picks the kernel: trtllm-gen, or CuTeDSL for 64 < local heads < 128 (e.g. Kimi-K3 with attention DP). This call gets its own 150 MB workspace, allocated only when the path can run (captured prefill graph, no DCP, no skip-softmax).
- Gated to SM100 with BF16 / FP8 E4M3 KV. MHA layers, spec decoding, DCP, skip-softmax and FP4 KV keep the existing path. Dense decode is unchanged.
- `CuteDslMLABackend` and `TokenspeedMLABackend` opt out (`owns_varlen_absorbed_extend = False`).

**`arg_groups/cuda_graph_hook.py`**: only the wording of the DeepSeek-V3 `trtllm_mla` prefill-graph-disable rule is updated (docstring and warning): it no longer claims a FlashAttention fallback under a captured prefill graph, and its example override flag is `--cuda-graph-backend-prefill breakable`.

**`arg_groups/overrides.py`**: the `trtllm_mla` KV-dtype and page-size checks also apply when `trtllm_mla` is only the prefill backend.

**Tests**: gate/contract, routing and workspace tests in `test_mla_varlen_absorbed_gate.py`; numerical tests with real CUDA graph capture/replay (including the CuTeDSL path) in `test_trtllm_mla_breakable.py` via `varlen_absorbed_extend_kit.py`; plus cases in `test_server_args.py` and `test_model_overrides.py`.

### Reproduction

Both arms use the same commands (main = `ef867fa40d`, PR = `045553a440`).

**4×GB300 TP4 — conc-1 benchmark and GSM8K**
```bash
SGLANG_RADIX_FORCE_MISS=1 python3 -m sglang.launch_server \
  --model-path nvidia/Kimi-K2.6-NVFP4 --trust-remote-code --tp 4 \
  --quantization modelopt_fp4 --kv-cache-dtype fp8_e4m3 --attention-backend trtllm_mla \
  --mem-fraction-static 0.82 --host 127.0.0.1 --port 30000

python3 -m sglang.benchmark.serving --backend sglang --base-url http://127.0.0.1:30000 \
  --dataset-name random-ids --tokenize-prompt --random-input-len 1024 --random-output-len 1024 \
  --random-range-ratio 1 --num-prompts 20 --max-concurrency 1 --temperature 0 --seed 42

python3 -m sglang.test.run_eval --eval-name gsm8k --num-examples 1319 --num-threads 128 --port 30000
```

```bash

They're split because they check different things with different lifetimes:

- `_varlen_absorbed_arch_dtype_ok` (renamed per your other comment) is a
  static hardware/dtype property — SM arch + KV cache dtype — the same for
  every instance of this backend in the process.
- `_varlen_absorbed_shape_ok` is per-model-instance — it depends on
  `num_local_heads`/`page_size`, which vary with the model and parallel
  config (e.g. `num_local_heads` shrinks under wide-EP DP-attention).

More importantly, `_varlen_absorbed_shape_ok` is also read on its own as a
second-layer defensive assert inside `_run_varlen_absorbed_kernel()`:

```python
assert self._varlen_absorbed_shape_ok, (
    f"_run_varlen_absorbed_kernel called with num_local_heads="
    f"{self.num_local_heads}, page_size={self.page_size}, which "
    "varlen_absorbed_mla_shape_ok() says flashinfer's trtllm-gen MLA "
    "decode kernel does not support -- use_varlen_absorbed should have "
    "excluded this shape already"
)
If I merge the two into one flag, this assert loses precision: it's meant to catch specifically a shape-gating bug, so the message should point at shape only. A merged flag could also be False for an arch/dtype reason, and the assert message above would then mislead whoever is debugging it.

Kept them separate, but the split is now self-explanatory at the call site (static hw/dtype property vs. per-instance shape property) without needing to trace into the assert.
