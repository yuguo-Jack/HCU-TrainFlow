# test(npu): add e2e test for --enable-int8-mamba-checkpoint reuse

[Upstream PR](https://github.com/sgl-project/sglang/pull/43072) · state: open · merged: False

## Original PR description

## Motivation
PR #40140 implements --enable-int8-mamba-checkpoint , which stores radix-cached linear-attention (Mamba/GDN/KDA) states in int8 inside a separate checkpoint pool, roughly doubling the cacheable-prefix capacity at a fixed memory budget. That PR only contains the runtime change; it has no end-to-end test proving the capacity win and correct cache hits on Ascend NPU. This PR adds the companion e2e test.

## Modifications
Adds a single NPU end-to-end test:

- File: test_npu_int8_mamba_checkpoint_reuse.py (+226 lines).
- Model/config: Qwen3.5-27B , --tp-size 2 , --attention-backend ascend , --mem-fraction-static 0.8 , --mamba-radix-cache-strategy extra_buffer , --max-mamba-cache-size 256 .
- Runs the same WARM/PROBE two-phase requests across K ∈ {64, 128, 256, 512} distinct prefixes, both with and without --enable-int8-mamba-checkpoint , and computes reuse_frac = cached_tokens / prompt_tokens .
- Assertions:
  1. Within each config, reuse is non-increasing in K (capacity cap).
  2. The int8 collapse point is no earlier than bf16.
  3. The maximum reuse gain of int8 over bf16 across the sweep exceeds REUSE_GAP = 0.3 , i.e. the int8 checkpoint pool genuinely pushes the reuse collapse point outward.
- Registered via register_npu_ci(est_time=3600, suite="full-2-npu-a3", nightly=True) .
