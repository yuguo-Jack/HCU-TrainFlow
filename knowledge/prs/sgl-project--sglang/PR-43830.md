# fix: preserve tree-owned FULL KV pages when DSV4 requests finis

[Upstream PR](https://github.com/sgl-project/sglang/pull/43830) · state: open · merged: False

## Original PR description

## Summary

Fix a KV page ownership bug that can cause negative #full token and full token usage when DeepSeek V4 requests finish on Ascend with radix caching enabled.

Finished requests now use the insertion result to determine the FULL prefix owned by the radix tree.

## Root cause

The NPU DSV4 C128 cache stores complete compressed pages. With the default C128 page size of 16, the cacheable prefix is rounded down to a multiple of 2048 original tokens.

By the time a request finishes, SWA eviction may have advanced beyond that rounded endpoint. The FULL prefix is successfully inserted into the radix tree, but the subsequent prefix match can return a shorter prefix because the corresponding SWA window is unavailable.

Previously, checkpoint_into_tree() used this shorter match to update cache_protected_len. Request cleanup then returned FULL pages still owned by the tree to the allocator.

Those pages were counted as both free and evictable:

full_used = full_capacity - full_available - full_evictable

This produces negative usage and can allow pages still referenced by the radix tree to be reused.

For example, a 2304-token request with its first 2048 SWA tokens already evicted produced:

| State after request cleanup | Before | After |
|---|---:|---:|
| FULL tokens retained by the tree | 2048 | 2048 |
| Tokens released by request cleanup | 2304 | 256 |
| Reported active FULL tokens | -2048 | 0 |

## Changes

- Use InsertResult.last_device_node as the ownership boundary when checkpointing finished requests.
- Add regression coverage for request lengths of 2048, 2176, 2304, and 4352 tokens, covering both reusable and unavailable SWA windows.
- Verify FULL/SWA capacity conservation and the absence of duplicate free pages after cache eviction.

## Validation

- Passed an isolated CPU source-level replay using production radix-tree and allocator code with dependency stubs.
- The regression failed on the original implementation in both unavailable-window cases and passed with the fix across all four cases.
- Additional replay cases reproduced FULL usage of -2048, -4096, and -34816 before the fix; each returned to 0 afterward.
- Ruff lint, formatting, Python AST parsing, and git diff --check passed.

The normal test-module invocation was blocked by local dependency incompatibilities. Ascend end-to-end validation and the AIME26 rerun are still pending.

To run the regression in a compatible environment:

python3 test/registered/unit/mem_cache/test_dsv4_hicache_l2.py TestDSV4FinishedCheckpoint -v

Restart the server before end-to-end validation so the allocator starts with clean page ownership.
