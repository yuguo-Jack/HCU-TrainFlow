# [diffusion] fix: Qwen-Image BCG prompt padding misses every graph and attends the pad

[Upstream PR](https://github.com/sgl-project/sglang/pull/43632) · state: closed · merged: True

## Original PR description

## Motivation

With `--enable-breakable-cuda-graph`, Qwen-Image and Qwen-Image-2512 replayed no captured graph, and every miss produced a wrong image.

- **Every request missed.** The Qwen-Image padder buckets `freqs_cis` but not the complex RoPE cache `freqs_complex`. Its text half keeps the prompt length, so the serving signature never matches a captured one.
- **A miss attended the pad.** A miss runs the padded kwargs eagerly. The padder had also bucketed `txt_seq_lens`, and the eager forward builds its varlen text ranges from that, so the zero-padded text rows were attended as real tokens. Against the same prompts run eager: Qwen-Image-2512 17.6–37.6 dB PSNR, Qwen-Image 25.7–34.1 dB. In one prompt the composition and the person changed. This hits any BCG miss, including resolutions that were never warmed up.

## Modifications

- Pad `freqs_complex` together with `freqs_cis`.
- Leave `txt_seq_lens` unset on padded inputs, so the mask alone marks the valid text. The eager fallback builds its varlen ranges from the mask; replay is unchanged (`DynamicVarlenMaskMeta`).
- Remove the now-unused `bucket_txt_seq_lens`.

## Accuracy Tests

1x H200, 1024x1024, 20 steps, torch.compile off. Four prompts, BCG output against eager:

| | before | this PR |
|---|---|---|
| Qwen-Image-2512, warmed resolution | 17.6–37.6 dB, every request MISSED | 0 MISSED; 2/4 bit-identical, the others 43.4 / 32.8 dB |
| Qwen-Image, warmed resolution | 25.7–34.1 dB | 0 MISSED; 2/4 bit-identical, the others 54.0 / 33.9 dB |
| Qwen-Image-2512, 768x768 (not warmed, so a miss) | attends the pad | 2/4 bit-identical, the others 34 / 43 dB |

The remaining non-identical prompts are short ones (under ~48 tokens). For those, the text-stream GEMMs (txt_in, qkv, mlp_down) pick a different cuBLAS kernel at M = prompt length than at M = bucket. That is floating-point reordering, not attention over the pad. Qwen-Image-2.1 is unaffected: its prefix runs eager at the exact length.

## Speed Tests and Profiling

Not a performance change. The captured graphs now replay instead of every request falling back to eager.
