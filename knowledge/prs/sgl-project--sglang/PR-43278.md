# [CP] Support CUDA zigzag prefill for DeepSeek V4

[Upstream PR](https://github.com/sgl-project/sglang/pull/43278) · state: open · merged: False

## Original PR description

## Motivation

Enable CUDA zigzag prefill context parallelism for public DeepSeek-V4-Flash. The backend currently reads an interleave-only metadata field and assumes rank-strided query/routing layouts.

## Modifications

Select local query metadata using the existing strategy indices, then append the existing padded metadata sentinels to match physical query rows. Keep global cache-write fields and compressor group ordering global. Match routing token IDs to rank-major FFN rows.

Use the existing per-query paged attention path for zigzag when either the environment flag or automatic large-query threshold would select the interleave-dependent optimized sparse-prefill path. Cover both BF16 and q8 sparse branches. Preserve existing interleave, NPU and HIP policies; explicitly reject CUDA zigzag with V4.1, low compression ratios, Engram or bounded decoder replay.

This is an independent main-based PR. Its small rank-major input-ID change also appears in the DSA PR so neither requires the other to merge first.

## Accuracy Tests

Production revision `6d1ed324be` (current head `f5de4d38d2` only reorders test imports) passes 19 focused tests through normal package imports on H200:
- 4 tests covering actual prefill metadata construction, physical query padding/global writes, routing layout, real compressor projection/gather/writer ordering, and both sparse fallback triggers.
- 4 KV-store tests, including zigzag restoration of packed KV/rope rows before global SWA writes.
- 11 platform/configuration policy tests.

Exact current head `f5de4d38d2` on 4x GB300, public DeepSeek-V4-Flash, TP4/CP4, FP8 E4M3 KV cache, FlashInfer MXFP4 MoE and A2A `none`; 200 GSM8K examples per strategy:

| CP off | Zigzag | Interleave |
| ---: | ---: | ---: |
| 96.5% | 98.0% | 97.5% |

All runs have zero request errors, truncation and invalid answers. Native-chat smoke covers unequal long requests, chunked prefill, c4/c128 compressed-cache continuation and actual prefix hits of 256/3,072/3,072 tokens in every strategy. Zigzag cached/cold arithmetic answers agree for all three prompts; two have identical text and one changes wording. Bitwise replay and statistical accuracy equivalence are not claimed.

## Speed Tests and Profiling

No performance claim. Zigzag uses the existing paged fallback for long sparse prefill because the optimized cache builder assumes contiguous per-request query intervals. Compressor projection still gathers to global token order before c4/c128 grouping.

Qualified scope targets CUDA public V4 SWA/c4/c128 with FlashMLA. TRTLLM CP remains rejected by the existing hook; HIP zigzag and V4.1 extensions are not enabled. The shared unified-KV unit test does not constitute CUDA unified-KV qualification.
