# [diffusion][AMD] FlyDSL norm: pick the wave count per hidden size

## Motivation

<!-- Describe the purpose and goals of this pull request. -->

The FlyDSL norm kernels use a single fixed workgroup, `_BLOCK = 640`, so the tile is `BLOCK * VEC` = 5120 and the dispatch asserts `D % 5120 == 0`. That fits Wan, but excludes every other hidden size. Models such as Qwen-Image that could take advantage of this fall back to the reference path.

The kernels also bake in their own epsilon and ignore the caller's, so a norm configured with anything other than 1e-6 was silently normalized with 1e-6.

This PR picks the workgroup per hidden size instead of fixing it, and makes the dispatch check epsilon too.

On Qwen-Image, this provides 3.1% gain in e2e.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Replace the fixed `_BLOCK = 640` with `_pick_num_waves()`, which takes the largest entry of `_BLOCK_CHOICES = (640, 512, 384, 128)` whose tile (`BLOCK * VEC` = 5120 / 4096 / 3072 / 1024) divides D, and derives the wave count as `block // WARP_SIZE`. 

- Add `flydsl_norm_supports(dim, eps)` and use it in the two `forward_hip` dispatch sites in place of the `D % FLYDSL_NORM_MIN_ALIGNED_DIM` check. It also requires `eps == 1e-6`, so a norm with a different epsilon now falls back instead of being normalized with the wrong value.
