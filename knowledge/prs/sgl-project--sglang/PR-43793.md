# [AMD] Fix Flux2 kv-gather abort on non-contiguous K/V

[Upstream PR](https://github.com/sgl-project/sglang/pull/43793) · state: open · merged: False

## Original PR description

## Motivation

Flux2 packs Q, K, and V in one projection and then `chunk`s them. Those K/V tensors are views, so they are not contiguous. With `--num-gpus 2` and sequence parallel left on its default, SGLang selects `kv_gather_degree=2`. The full-sequence gather then calls `all_gather_into_tensor` on that view. PyTorch's NCCL process group (`check_gpu_single_tensor`) rejects it with `ValueError: Tensors must be contiguous` before the collective runs. The same check is in the CUDA build, so NVIDIA hits it on this path too. The prefix and suffix branches already called `.contiguous()`. The unsliced branch did not, and that is the branch Flux2 takes.

## Modifications

- `USPAttention._gather_sharded_sequence` materializes the unsliced K/V tensor with `.contiguous()` before `sequence_model_parallel_all_gather`.
- `GroupCoordinator.all_gather` does the same immediately before `all_gather_into_tensor`, so any other non-contiguous caller of that collective meets the NCCL/RCCL requirement. An already-contiguous tensor is returned unchanged.
- `test/registered/unit/layers/attention/test_sp_kv_gather_contiguous.py` builds a K tensor with `chunk`, asserts it is not contiguous, and asserts the tensor passed into the gather is contiguous and equal to the original view. CPU CI: `base-a-test-cpu`.

## Accuracy Tests

Same prompt, seed 42, 720p, 50 steps, `torch.compile` on. The 1-GPU image is `20261012-055625`. The 2-GPU kv-gather image after this fix is `20261012-071319`. Both are 1280x720. The broken run saved no image, so this is 1-GPU versus 2-GPU sequence parallel, not a before/after of the copy. The unit test checks that `.contiguous()` keeps the same values as the view.
