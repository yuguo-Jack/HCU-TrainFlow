# [Bugfix] Keep declared Kimi-K3 properties out of the additionalProperties branch

[Upstream PR](https://github.com/sgl-project/sglang/pull/43120) · state: open · merged: False

## Original PR description

## Motivation

Refs #38587 (the SGLang-side half; the nested reproduction in that issue is decided by xgrammar's JSON-schema converter and was handled upstream).

For a strict Kimi-K3 tool, `_strict_arguments_format` emits the declared properties as fixed slots and then appends the `additionalProperties` branch as a `StarFormat` whose key matcher is `[^"& \t\r\n\f\v=<>]+`, i.e. any key. So a declared name can reappear under the looser additional schema: with

```json
{"properties": {"label": {"type": "string", "pattern": "[a-z]+"}, "score": {"type": "integer"}},
 "required": ["label"], "additionalProperties": {"type": "string"}}
```

the grammar accepts `score` as a `string` argument, and with the default `additionalProperties: true` it accepts `label` a second time with any type. JSON Schema applies `additionalProperties` only to keys that `properties` does not name, so the strict guarantee for declared keys was only as strong as the additional schema.

## Modifications

- `kimik3_structural_tag.py`: the additional-argument key regex now excludes the declared property names. xgrammar's regex dialect has no lookahead, so `_dynamic_key_pattern` builds the exclusion from a trie of the names: a key is acceptable when it leaves the trie with a character no declared name continues with, or when it stops at a proper prefix of one (`data_x`, `datab`, `databases` stay valid next to a declared `data` / `database`). Keys that cannot appear in XTML (containing `"`, `&`, whitespace, `=`, `<`, `>`) are skipped. Non-strict tools keep the unrestricted matcher.
- Two regression tests in `test/registered/unit/function_call/test_kimik3_structural_tag.py`: declared keys keep their own schema under both `additionalProperties: true` and a schema-valued one (undeclared keys still follow the additional schema), and only exact declared names are excluded.

## Accuracy Tests

No model code changes. On `main` the new cases fail (`assert not True` on the `score`-as-string and repeated-`label` calls); with the fix the whole `test_kimik3_structural_tag.py` passes (38 tests) and `test_function_call_parser.py` passes. CPU only, Python 3.12.

## Speed Tests and Profiling

Not applicable: the key regex gains one alternative per trie node of the declared names, compiled once per tool set like the rest of the structural tag.
