# [sgl-router] Render chats with the defaults the workers report

[Upstream PR](https://github.com/sgl-project/sglang/pull/43311) · state: open · merged: False

## Original PR description

## Motivation

The router renders chats on the engine's behalf, so its prompt must match what the engine's own OpenAI layer would render. That depends on engine defaults: `--default-chat-template-kwargs`, plus the env vars `SGLANG_DEFAULT_THINKING`, `SGLANG_DSV4_REASONING_EFFORT` and `SGLANG_DSV41_REASONING_EFFORT`.

Today the router uses its own flag and its own process env, which operators must keep equal to every engine's by hand:
- **Kwargs mismatch:** detected (#42998 falls back with `default_chat_template_kwargs_differ`), but it loses the router path entirely. Before #43252 the fallback even forwarded wrongly rendered `input_ids`.
- **Env mismatch:** not detected at all; the router silently renders a different prompt than the engine would.

#43300 makes engines report those env vars in `/server_info` under `openai_env`. This PR has the router adopt them.

Stacked on #43000. It includes #43252, which this supersedes.

## Modifications

**Router (`experimental/sgl-router`)**
- **Adoption.** The router renders with the chat defaults its workers agree on: kwargs from `default_chat_template_kwargs`, and env from `openai_env`. This covers `/generate` lowering, forwarded `input_ids` and routing tokens alike. Adoption happens per model as workers' settings are seen, so it follows discovery and rollouts.
- **Alerting.** When the router's own flag or env differs from what the workers report, it logs once per change:

  ```
  WARN ALERT: the router's chat default differs from the workers'; rendering with the workers' value
       field="default_chat_template_kwargs" router={} engine={"enable_thinking":true,"thinking":true}
  ```

  It also sets the new gauge `sgl_router_chat_defaults_mismatch{model_id,field}`.
- **Mixed fleets.** When workers disagree with each other (mid-rollout), there is no single prompt to render. Chats then reach the engine as sent, without router `input_ids` (the #43252 guard), and lowering falls back with outcome `chat_defaults_differ`, renamed from `default_chat_template_kwargs_differ` since it now covers env too.
- **Older engines.** Workers that predate `openai_env` keep the router's own env, with a one-time warning that it is unverified.

**Processor (`rust/sglang-processor`)**
- The DeepSeek-V4/V4.1 renderers take a `RenderEnv` instead of calling `std::env::var`. `ChatFormatter::render_request` gains an `env` argument. `RenderEnv::from_process()` keeps the old behavior for `render_prompt` and `resolve_thinking`.
- `OpenAiSettings.openai_env` parses the new `/server_info` block.
- `lower_chat` sends tool chats to the engine (`tool_env`) when it reports `SGLANG_FORWARD_UNKNOWN_TOOLS` or a nonzero `SGLANG_TOOL_STRICT_LEVEL`. The processor's tool handling assumes both are off.

## Checks

- **Tests.** `cargo clippy --all-targets -D warnings` passes in `experimental/sgl-router` and across the `rust/` workspace. `cargo test` passes in `experimental/sgl-router`, and in `sglang-processor` including both parity suites at the pinned V4.1 revision.
- **New tests:**
  - router proxy test: one engine reports `thinking` via kwargs, another via `openai_env`, a third neither. The forwarded `input_ids` match for the first two and differ for the third, and the test fails without adoption;
  - mixed-fleet passthrough;
  - mismatch gauge rendering;
  - processor `RenderEnv` fallback order;
  - `tool_env`.
- **Live, DeepSeek-V4.1-Flash, 49-case chat matrix**, router started without `--default-chat-template-kwargs` and without the env vars:
  - **Kwargs:** engine with `--default-chat-template-kwargs '{"thinking": true, ...}'` (no `openai_env`). 39 chats served through `/generate` (previously all fell back), each reaching the engine with the same `GenerateReqInput` as direct. `ALERT` and the gauge fired, as did the old-engine warning.
  - **Env:** engine with #43300 and `SGLANG_DEFAULT_THINKING=1 SGLANG_DSV41_REASONING_EFFORT=low`, reporting `openai_env`.
    - With this PR: 39 chats served through `/generate`, each reaching the engine with the same `GenerateReqInput` as direct. `ALERT` fired for both env vars, and the gauge has `field="SGLANG_DEFAULT_THINKING"` and `field="SGLANG_DSV41_REASONING_EFFORT"`.
    - Without it (control, same engine): every chat that sets no thinking option (`plain`, `system`, `multiturn`, `tools_auto`) reached the engine with a different prompt (thinking off), still counted as `outcome="generate"`, with no warning.
