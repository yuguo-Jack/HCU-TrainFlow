# [Fix] GLM/Qwen3: keep a <tool_call> quoted in reasoning out of streamed tool calls

[Upstream PR](https://github.com/sgl-project/sglang/pull/42030) · state: open · merged: False

## Original PR description

## Motivation

GLM models served with `--reasoning-parser glm45 --tool-call-parser glm47` sometimes write the literal `<tool_call>`
inside their reasoning. They do this when reasoning about code or logs that contain tool markup, or when asked to
quote the marker. In **streaming** responses this corrupts the reply:

- **With tools declared**, `reasoning_content` stops at the quote. The next tool call's `function.name` is then the
  rest of the reasoning, `</think>`, the visible text and the real call's header, for example
  `followed by the function name."</think>The GLM parser looks for <tool_call>bash`. The real call's arguments are
  attached to that name.
- **Without tools**, the rest of the reasoning and `</think>` arrive in `content`.

Non-streaming responses to the same output are correct.

Cause: in `BaseReasoningFormatDetector._parse_streaming_increment_impl`, a `tool_start_token` seen while reasoning
ends the block immediately ("Streaming cannot see a think_end_token that has not arrived yet"). `detect_and_parse`
uses the tool start only when `</think>` is absent. The interruption was added for GLM-4.5 in #17714 and is in every
release since v0.5.10. `Glm47MoeDetector` then streams the captured text as a name without checking the declared
tools, whereas `parse_base_json` drops undeclared names on the non-streaming path.

Matching the marker by token id does not help. In the outputs below, the quote inside reasoning is the `<tool_call>`
special token itself (id 154843) in 119 of the 128 replies that quote it inside reasoning. Only its position relative to `</think>`
separates a quote from a call.

## Reproduction

GLM-5.3-Flash FP8, 8×B300, TP8/EP8, `--reasoning-parser glm45 --tool-call-parser glm47`, other flags default.
SGLang fe236ea6c3 (2026-09-01); the code involved is unchanged on main.

```json
{"model": "zai-org/GLM-5.3-Flash", "temperature": 0, "reasoning_effort": "high", "max_tokens": 2048,
 "messages": [{"role": "user", "content": "Without calling any tool, reply in plain text with exactly one sentence that quotes the GLM tool-call opening marker literally, in this form: The GLM parser looks for <tool_call> followed by the function name."}],
 "tools": [{"type": "function", "function": {"name": "bash", "description": "Run a shell command", "parameters": {"type": "object", "properties": {"command": {"type": "string"}}, "required": ["command"]}}}]}
```

Results on one server, same requests and seeds. "Broken" means one of: the reasoning was cut at the quote, an
undeclared tool name, a nameless `{}` tool call, or reasoning delivered as `content`.

| request (n) | main, `stream: true` | this PR, `stream: true` | main, `stream: false` |
|---|---|---|---|
| minimal request above, greedy (5) | **5/5 broken**: answer lost, nameless `{}` call | 0/5 | 0/5 |
| coding-agent prompt (system prompt + 4 tools), `reasoning_effort: high`, greedy (5) | **5/5** | 0/5 | 0/5 |
| coding-agent prompt, `reasoning_effort: low`, default sampling, 4 concurrent (20) | **19/20** | 0/20 | 0/20 |
| same, no tools (20) | **14/20**: reasoning in `content` | 0/20 | 0/20 |
| thinking off, answer quotes `<tool_call>` (25) | **25/25** nameless `{}` call | 0/25 | 0/25 |
| ordinary calls: single, parallel, thinking off (75) | 0/75 | 0/75, same tool calls | 0/75 |

With constrained tool calls (`SGLANG_TOOL_STRICT_LEVEL=2`), the model's visible `<tool_call>` is forced into a real
call, so the bad name is completed and emitted. For example
`followed by the function name.</think>The GLM parser looks for <tool_call>write`, which is the exact signature a
hosted GLM provider returned to us. Main: 3/20, 4/20 and 4/20 at 1, 4 and 16 concurrent requests. This PR: 0/20, 0/20 and 0/20. Over the full matrix at that setting (streaming and non-streaming, with and without tools, concurrency 1–16, greedy
and sampled), main has 89 broken replies out of 678, all streaming. This PR has 0 out of 692.

To show the model's text is not the cause, we replayed the exact `response_token_ids` of 337 non-streaming
replies through the parsers. The replayed one-shot parse equals the server's reply in 337/337 cases. On the same tokens:

| parsers | streaming defects | streaming reasoning == one-shot reasoning |
|---|---|---|
| main | 162 / 337 | 209 / 337 |
| this PR | 0 / 337 | 337 / 337 |

## Modifications

The PR has four commits, one per change, so each can be reviewed or dropped on its own.

1. `BaseReasoningFormatDetector(defer_tool_start=False)`, a new opt-in flag. When it is set, streaming does not end
   reasoning at a `tool_start_token`. It streams the reasoning up to the marker and holds the text from the marker on.
   - If `</think>` arrives, the held text was reasoning and is released as reasoning.
   - If the stream ends without `</think>`, `finish()` splits at the marker exactly as `detect_and_parse` does.

   `Glm45Detector` (and so `Ling3Detector`) opts in. The other detectors are unchanged.
2. `Glm47MoeDetector.parse_streaming_increment` drops a call whose name the request did not declare, through its
   `</tool_call>`. This is the same rule as `parse_base_json`, and `SGLANG_FORWARD_UNKNOWN_TOOLS` still forwards such
   calls. The skipped call leaves no `prev_tool_call_arr` entry, so `_check_for_unstreamed_tool_args` cannot emit a
   nameless `{}` for it.
3. New `Glm47MoeDetector.finish()`. If the stream ends while the detector still holds a `<tool_call>` that never got a
   name, the text is returned as content, which is what `detect_and_parse` returns, and the placeholder is dropped.
   Before this, visible text that quoted the marker (or a call cut before its name) was lost, and the end-of-stream
   flush sent a nameless `{}` call. A call whose name already streamed is untouched.

4. `Qwen3Detector` opts into `defer_tool_start` as well. It ends reasoning at `<tool_call>` for the Qwen3.5 case of a
   call with no `</think>`, and so has the same streaming defect when a model quotes the marker. On
   MiMo-V2.6-Pro-RL (`--reasoning-parser qwen3`), 10 of 10 streamed no-tool replies that quoted the marker delivered
   reasoning as `content`; non-streaming had 0 of 10. Detectors derived from it (`mimo`, `poolside_v1` and the
   internal DeepSeek-V3 one) inherit the fix.

   Scope note: change 3 goes slightly beyond the reported bug. It concerns a `<tool_call>` in the *visible* answer,
   which GLM's format treats as markup, and nothing here changes that. With default settings, though, the minimal
   reproducer above still loses its answer to a nameless `{}` call without it: 25/25 streamed replies on main, 0/25 with
   it. It only makes streaming return what non-streaming already returns. It is a separate commit and can move to its
   own PR if you prefer.

Trade-offs:
- When the model quotes `<tool_call>` inside reasoning, the reasoning after the quote reaches the client when
  `</think>` arrives rather than token by token. Before this PR, that text arrived corrupted.
- When the model makes a real call with no `</think>` (the #17714 case), the call is delivered when the stream ends.
  That is the non-streaming result.
- Requests that never put `<tool_call>` inside reasoning stream exactly as before.

Measured cost of holding: in the 128 replayed replies that quote the marker inside reasoning, the held span ran from
the quote to `</think>`: median 7 tokens, p90 76, max 140. On the server, the largest pause between stream deltas did
not grow:

| SGLang defaults, coding-agent prompt, 40 streams | p90 | max |
|---|---|---|
| this PR | 0.49 s | 1.44 s |
| main | 0.41 s | 4.11 s |

Time to the first reasoning delta and to the first answer delta is unchanged for requests without a quote: 0.22 s and
0.41 s on main and on this PR for a plain tool call. Buffering whole generations instead, as our earlier local
workaround did, postponed the first byte to the end of generation: 13.4 s instead of 0.24 s for the minimal request on the same server.

## Accuracy Tests

- `test/registered/unit/parser/test_reasoning_parser.py`:
  - GLM45 cases added to `TestStreamingChunkSizeInvariance`: a quote then `</think>` then a real call; buffered mode;
    several markers including `</tool_call>` inside reasoning; a real call with no `</think>`. Each is checked at
    every chunk width against `detect_and_parse`.
  - A per-chunk test of the quoted case.
  - The three existing GLM45 streaming tests now read the tool-interruption result after `finish()`.
  - A Qwen3 chunk-invariance case: a quote then `</think>` then a real call, and a real call with no `</think>`.
- `test/registered/unit/function_call/test_function_call_parser.py`, GLM47 streaming:
  - drops an undeclared call and keeps the next declared one at index 0;
  - drops the exact malformed stream above;
  - forwards the call when `SGLANG_FORWARD_UNKNOWN_TOOLS` is set;
  - returns unfinished `<tool_call>` text as content at the end of the stream, matching `detect_and_parse`;
  - leaves a truncated named call alone.
- Server A/B: the tables above. Same GLM-5.3-Flash Pod and flags; this patch backported to fe236ea6c3 and loaded in
  place of the two stock files.

Run in a CPU process against this branch (Python 3.12; xgrammar from the serving image):
`test_reasoning_parser.py`, `test_function_call_parser.py` and `test_unknown_tool_name.py` give 377 passed and 26

DeepSeek V4, Kimi, Qwen3-Coder and GPT-OSS that need a newer xgrammar, and none of them touch the files changed here.
All GLM45, Ling3, chunk-invariance, GLM47 and unknown-tool tests pass.
