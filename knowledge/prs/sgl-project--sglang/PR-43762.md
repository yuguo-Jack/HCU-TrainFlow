# [Test] Re-anchor the VLM flashinfer throughput floor

[Upstream PR](https://github.com/sgl-project/sglang/pull/43762) · state: closed · merged: True

## Original PR description

## Motivation

`test_vlm_serving_flashinfer` fails its offline throughput check (`output_throughput >= 5940`) on 5090 runners, with measurements of 5176–5939 tok/s.

#43564 reserves the full remaining output for running `ignore_eos` requests during prefill admission. Those requests always generate their full `max_new_tokens`, so admission no longer discounts them by `new_token_ratio`.

In this benchmark:
- **Workload:** 200 fixed-length requests, each about 410 input + 2048 output tokens.
- **KV pool:** 411,675 tokens, enough for about 167 of these requests at full length.
- **Admission:** 170 requests run at once, with no retractions. The other 30 wait in the queue and run afterwards as a small-batch tail.

This lowers offline output throughput by design.

Only offline output throughput is affected. The online phase sends 50 requests at 1 per second and stays well below the admission limit. Its medians, all within their limits:

| Metric | Limit | Measured |
|---|---|---|
| e2e | 17480 ms | 16031–16159 ms |
| TTFT | 83 ms | 66–77 ms |
| ITL | 8.4 ms | 7.61–7.72 ms |

## Modifications

Lower the floor from 5940 to 4510, using the `basic_perf` anchoring rule from #40617, worst sample / (1 + max(0.10, spread)), on 8 CI attempts on 5090 runners:

`5851.86, 5831.51, 5471.16, 5295.27, 5210.99, 5175.67, 5939.31, 5918.90`

That gives a worst of 5175.67, a spread of 14.75% and a floor of 5175.67 / 1.1475 = 4510.2. Every sample clears the new floor by at least 10%.
