# [openai] Expose opt-in per-request metrics in OpenAI-compatible responses

[Upstream PR](https://github.com/sgl-project/sglang/pull/43496) · state: open · merged: False

## Original PR description

Add an opt-in `return_request_metrics` flag to the OpenAI-compatible `/v1/chat/completions` and `/v1/completions` endpoints. When set to `true`, per-request timing metrics are returned in the response-level `sglext.request_metrics` extension:

- `queue_time_ms` — time waiting in the scheduler queue
- `time_to_first_token_ms` — created → first output token
- `generation_time_ms` — first token → request finished
- `end_to_end_latency_ms` — created → finished
- `mean_itl_ms` — mean inter-token latency over the decode phase
- `tokens_per_second` — decode throughput

Unavailable values (e.g. decode metrics for a single-token response) are omitted rather than emitted as null. Metrics are computed from the request time stats that already flow with every output, so they are independent of `--enable-metrics` and Prometheus/tracing configuration.

Defaults are unchanged: without the flag, response schema and serialization are byte-identical to before.

Closes #36678
