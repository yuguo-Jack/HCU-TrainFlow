# [Fix] Reject Chat Completions streaming errors in bench_serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/40881) · state: closed · merged: False

## Original PR description

## Motivation

An OpenAI-compatible Chat Completions endpoint can send an `error` event after starting an HTTP 200 SSE response. SGLang emits this format for streaming generation failures.

The benchmark client currently treats that event as an empty-choices chunk, skips it, and marks the request successful at EOF. An error-only stream followed by `[DONE]` is reported as `success=True, output_len=64` for a 64-token request, despite producing no text. This inflates completed-request and output-token totals and can hide failed warmup requests.

## Modifications

Reject a non-null SSE `error` before processing usage or choices, using the existing exception-to-failed-request path. Add loopback HTTP regressions for errors before content, errors after partial content (including exclusion from aggregate metrics), and a valid chunk with `error: null`.

Only the benchmark client and its existing registered CPU test file change.

## Accuracy Tests

Based on `d4dcce12d4fcdb3eb694d54d6afd31628c2eb7ce`.

- Before the fix: the two error regressions fail because the client reports success; the null-error control passes.
- After the fix: **13 tests pass**, including existing reasoning-content, usage-only chunk and non-streaming tests.
- Actual-model smoke check on one RTX 5090: **16 streaming and 16 non-streaming requests complete successfully** using Qwen3-0.6B BF16, FlashInfer, and decode CUDA graphs. This validates the normal client path; generation failures are reproduced by the CPU loopback HTTP fixtures.

```bash
PYTHONPATH=python CUDA_VISIBLE_DEVICES=99 python -m pytest -q \
  test/registered/bench_fn/test_bench_serving_reasoning_stream.py
```

The invalid GPU ordinal hides the accelerator on the test machine. The current base's test-utils import fails with an empty CUDA_VISIBLE_DEVICES value, which is outside this change.

Environment: Ubuntu 22.04, Python 3.12.14, PyTorch 2.13.0+cu130. No model-forward or sampling changes.

## Speed Tests and Profiling

No performance claim. This fixes benchmark success/token accounting; inference kernels are unchanged.
