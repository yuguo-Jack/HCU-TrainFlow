# Precompile GLM vision kernels before KV allocation to avoid first-image OOMs

[Upstream PR](https://github.com/sgl-project/sglang/pull/38214) · state: open · merged: False

## Original PR description

## Motivation

The first image request can run out of GPU memory while compiling or loading vision kernels, after the KV cache and CUDA graphs have consumed the available headroom. A small warmup image also does not necessarily compile the dynamic MLP activation used by larger images.

This PR precompiles GLM-5-Next vision attention and MLP activations after loading the model but before allocating the KV pool. The request-time forward implementation is unchanged.

Replaces #37539, which was closed when the base branch for #36507 was deleted after its merge as `97c6978369`.

## Modifications

- Add the existing model-runner precompile hook to `Glm5NextForConditionalGeneration`.
- Run the compiled `swiglu_clamped` activation at the gate_up widths of the vision block MLP and the patch merger, at 64 and 4096 tokens, so compilation covers both token counts before serving. Only the activation runs, not the modules: their `down_proj` all-reduces across tensor-parallel ranks, so a rank whose warmup failed and swallowed the error before that collective would leave its peers waiting. The activation is local and reads no weights.
- Match the serving inputs, since dynamo guards on tensor rank and inference mode: the block MLP activation is warmed with `(tokens, 1, width)`, as `GlmOcrVisionBlock.forward` reaches it, and the merger activation with `(tokens, width)`. The warmup runs under `torch.inference_mode()` for the encoder-only server and under `DynamicGradMode` otherwise, matching the scheduler's `no_grad` or `SGLANG_ENABLE_TORCH_INFERENCE_MODE` setting.
- For the Triton attention backend, launch the tower's attention specialization using small tensors with the production dtype and head geometry.
- Skip unavailable modules and non-first pipeline ranks; skip attention precompile for non-Triton backends. Log precompile failures at WARNING.

## Accuracy Tests

13 CPU tests passed, covering activation call shapes and grad modes, a single-rank warmup failure that must not enter the modules or an all-reduce, attention arguments, skip conditions and warnings. Three of them run the real `torch.compile`d activation on CPU: after the hook, serving-shaped calls at new token counts (3D for the block MLP, 2D for the merger) add no dynamo graphs under the scheduler's `no_grad`, under the scheduler with inference mode enabled, and under the encoder server's inference mode. Each attempt starts from an empty dynamo cache, so a retry cannot pass on graphs compiled by a failed attempt. Without the shape and grad-mode matching, these fail with a new compilation, including with retries enabled. The GPU specialization-reuse test (`test/registered/kernels/ops/attention/test_glm5_next_vision_precompile_gpu.py`, registered in the `base-b-kernel-unit` 1-gpu-large suite, which clears the in-memory Triton kernel cache on every attempt and requires the hook to add and load the attention specialization that the vision call then reuses) and the first-image OOM reproducer have not been rerun.

On RTX PRO 6000 Blackwell (SM120), torch 2.14.1+cu130, Triton 3.8.0, `test/registered/kernels/ops/attention/test_glm5_next_vision_precompile_gpu.py` passed with this change.
