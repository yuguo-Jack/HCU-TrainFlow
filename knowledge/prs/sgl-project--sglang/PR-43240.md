# fix(hicache): square NVFP4 host-pool geometry + page-granular block-scale transport

[Upstream PR](https://github.com/sgl-project/sglang/pull/43240) · state: open · merged: False

## Original PR description

Closes #43239.

### The bug

NVFP4 device pools store **packed** fp4 — one device row holds `row_dim / 2` **bytes** (`store_dtype=uint8`, e.g. `k_buffer[l]: (size, 2, 128)` = 256 B/token) — and keep per-block scales in **separate** tensors (`k_scale_buffer[l]: (size, 2, 16)`). The generic MHA host pool sizes host rows from device *element* counts (512 B/token), and HiCache JIT kernels take a single shared element size for both sides:

- **H2D** views the 256 B device row as half of a 512 B element: token *i* lands at device rows `2*i`; the in-range guard truncates the rest (in-engine at production scale: a 56,704-index loadback wrote ~64 KB of 14.5 MB — the function returns having restored nothing).
- **D2H** gathers 512 B spans off 256 B-stride rows, pairing two device tokens per host row.
- **Scales never move at all** on the `kernel` path, so even a byte-correct payload dequantises with stale scales.

With MTP draft KV packed behind the pool (#30393), every restored draft row is garbage: `spec_accept_length` silently pins to 1.0, throughput falls ~25% below the no-MTP baseline, target outputs stay correct, `/flush_cache` doesn't help, only a restart heals. Even without MTP, target-KV loadbacks are corrupted the same way (usually masked by re-prefill).

Reproduced deterministically at cycle 0 (3/3) on v0.5.21; `pool_host/mha.py` on current `main` has the identical geometry (`get_size_per_token` at lines 217–222, selector at 1557). Full evidence chain (in-engine poison probes, write-footprint mapping, offline byte-exact synthesis, ruled-out hypotheses with controls) is in the linked issue.

### The fix

New `MHATokenToKVPoolFP4Host` (mirrors the existing `MHATokenToKVPoolMXFP8Host` precedent), routed by `get_mha_host_pool_cls` for device pools whose `quant_method.name in ("nvfp4", "fp4_mx_block16")` and that expose scale buffers:

- Host payload rows sized in **device bytes** (`head_dim // PACK_FACTOR`, `dtype=uint8`): every inherited JIT element size becomes square on both sides, so all payload transfers — including packed-MTP handling — stay in the base class unchanged.
- Block scales ride **page-granular side buffers** moved by the same staged write-back / one-layer page kernels (`page_size=1`), like MXFP8 UE8M0 scales. Both the interleaved `[token, head, dim]` and TRT-LLM native `[page, head, token, dim]` scale layouts are page-local, so both are covered.
- MTP draft layers pack into the tail layer of payload **and** scale buffers, matching base-class packing.
- Non-page-multiple transfers cannot move page-granular scales: touched host scale pages are zeroed so a later loadback restores zeros, never stale scales.
- L3 flat-storage interfaces raise `NotImplementedError` (same boundary as MXFP8: a page's scales live outside `kv_buffer`).

Detection trap worth reviewers' attention: the runtime device pool is the plain `MHATokenToKVPool` with `store_dtype=uint8`, so `is_float4_e2m1fn_x2(store_dtype)` is **False**; the real contract is the quant-method name. (A store-dtype-keyed guard silently never fires — we lost a full validation round to exactly this.)

### Verification

Incident config: Qwen3.8-27B NVFP4, TP2, `--kv-cache-dtype nvfp4 --hicache-io-backend kernel --hicache-mem-layout page_first --page-size 64 --hicache-write-policy write_through --speculative-algorithm NEXTN` (packed draft, 16+1 layers).

| battery | before | after |
|---|---|---|
| offline byte-exact D2H→wipe→H2D round-trip, position-encoded payload+scale (9792 B/token) | n/a | **PASS (every byte)** |
| 4× dual-session evict/loadback probe accept (stock corrupts at cycle 0, 3/3) | 1.11 → pinned 1.00 | **3.00 / 3.00 / 2.99 / 3.00** |
| 10× multi-turn 137K pressure, accept mean | collapses on long runs | **2.32–2.86, healthy** |
| decode throughput | 29 t/s (collapsed) | 78.9 t/s |

Also confirmed on the same battery that `--hicache-io-backend direct` is unaffected (it bypasses JIT entirely) — this PR makes `kernel` match `direct` in correctness while keeping the kernel path's loadback speed (~1 s for a 137 K-token prefix).

### Notes / scope

- `layer_first` host layout never had the double-pitch (square contract already); this PR constrains the new pool to `page_first` like MXFP8 does.
- Asymmetric K/V head dims raise explicitly (no silent mis-size).
- If upstream would rather teach the staged/one-layer kernels asymmetric src/dst element sizes (and scale transport) instead of a dedicated pool class, this PR is a working reference for the contract either way.
