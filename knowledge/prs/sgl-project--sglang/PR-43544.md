# fix(function_call): emit every buffered call in DeepSeekV3 streaming

[Upstream PR](https://github.com/sgl-project/sglang/pull/43544) · state: open · merged: False

## Original PR description

## Motivation

With `--tool-call-parser deepseekv3`, when one stream increment carries two complete tool calls (a coalesced backlog from `_coalesce_streaming_chunks`, or a large `--stream-interval`), `parse_streaming_increment` emits only the second call, at `tool_index` 0. The first call never reaches the client.

Fixes #43523.

## Root cause

The streaming pattern anchors with greedy `(.*)` groups, so on a buffer with two calls it matches from the *last* `<｜tool▁sep｜>`: name and arguments come from the second call while the first is silently dropped. And even with correct anchoring, the old control flow returned after the first completed call, while the serving layer calls `parse_streaming_increment` once per delta with no end-of-stream flush, so a second call already sitting in the buffer would have been stranded had the last delta carried it.

## Modifications

- Match the first complete call in the buffer with lazy quantifiers (`(.*?)`) instead of the last.
- Loop until the buffer drains: every complete call already buffered is emitted in the same increment, with correct monotonic `tool_index`.

The two open PRs referenced in the issue (#42328 at 4581069, #42464 at 72cbf05) were verified by the reporter to still drop the first call; this PR fixes the root cause instead of patching the symptom. Closing the loop in the detector keeps `detect_and_parse` and streaming semantics aligned.

## Accuracy Tests

New regression test `TestDeepSeekV3Detector::test_parse_streaming_two_complete_calls_in_one_increment`: a single increment holding two complete calls must emit both with correct names, arguments, and indices. Verified red without the fix (first call missing) and green with it.

Local run (CPU-only, parser imports only): `pytest test/registered/function_call/test_function_call_parser.py::TestDeepSeekV3Detector` — both V3 tests pass. The issue's exact repro script now prints both calls streaming-side, matching `detect_and_parse`.

Note: the seven `TestDeepSeekV32Detector` failures in the same file reproduce on current main without this change (separate pre-existing issue, untouched here). No GPU available locally; parser-level coverage only, CI covers the rest.
