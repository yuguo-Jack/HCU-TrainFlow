## Motivation

Two layouts were missing from stage boundaries.

1. **A dense FFN that sums over attention TP.** Under DP attention, Kimi K3's `--enable-dense-mlp-attn-tp` shards the dense MLP over the attention TP group: it runs on this rank's DP-local rows and all-reduces its output over attention TP. An FFN stage could only declare local compute or the full TP group (rows gathered over DP).
2. **Batches not padded to a multiple of attention TP.** An FFN that runs on this rank's attention-TP slice of the rows (an a2a MoE, or a dense FFN computed locally, with attention TP above 1) reduce-scatters its input onto the slice, which needs that padding. Without attention DP, `--disable-attn-tp-gather` turns the padding off, and stage boundaries fail on the first batch whose rows do not divide. Qwen3-30B-A3B with DeepEP at TP 2 on `main`:
   - eager mode raises `input tensor must be the same size as output size times world size`;
   - CUDA graph capture hangs.

   The boundaries' attention-TP gathers also took the local DP buffer, which only MLP sync sizes for a batch.

Kimi K3's decoder handled both cases with its own communication, so these configurations kept it off stage boundaries.

## Modifications

- `declare_ffn(dense_tp_size=<attention TP size>)` resolves to the first layout:
  - input and output on the attention's rows, the output's sum owed over attention TP, and nothing moved over DP;
  - the attention's sum completes at the FFN input on this rank's rows, and the FFN's sum completes at its exit with the same attention-TP all-reduce `down_proj` ran;
  - other widths are rejected.
- A batch whose rows do not divide takes a variant of its own, `BatchVariant.UNPADDED`:
  - the FFN stays on the attention's rows, and its input completes the attention's sum with an all-reduce;
  - an a2a MoE dispatches those rows from every attention-TP rank;
  - its output arrives complete, so the exit neither sums nor gathers.

  Batches whose rows divide keep the slice. The variant is built only where such a batch can arrive (no MLP sync).
- Without MLP sync, attention-TP gathers allocate their output by the rows they gather.
- Kimi K3's dense layers already declare the TP width their MLP is built with (#42894), the attention TP size in the first layout, so Kimi K3 now builds stage boundaries for both configurations.
- `test_append_stages.py`:
  - `TestDenseFfnOverAttentionTp`: the FFN stays on the attention rows.
  - `TestUnpaddedBatches`: an unpadded batch keeps the attention rows; padded batches have no unpadded path.

## Accuracy Tests

B200, deterministic inference.

- **Dense FFN over attention TP.** Synthetic Kimi K3 at TP 4 × DP 2 (attention TP 2) with `--enable-dense-mlp-attn-tp`, three launches per tree:
  - Standard residual path: two of the three runs are bit-identical to the decoder's own path, whose three runs agree; the third matches no other run.
  - Attention-residual bank: two of three runs are bit-identical to the decoder's own path. Each tree has one launch that matches no other run.
  - Collective kernels are identical in kind and count.
- **Unpadded batches (`--disable-attn-tp-gather`).**
  - Qwen3-30B-A3B with DeepEP, at TP 2 and TP 4: fails on `main`, runs with this change. Input logprobs are identical to the padded run (flag off); output logprobs differ by up to 0.0039.
  - Kimi K3 with the bank: equivalent to the decoder's own path.
  - Kimi K3, standard path: differs by up to 0.002, since the attention's sum is now a reduce-scatter where the decoder all-reduced.

## Speed Tests and Profiling

Not applicable: both configurations crashed or ran the model's own communication before; padded batches are unchanged.

NPU uses `--enable-dense-mlp-attn-tp` and has not been run here.
