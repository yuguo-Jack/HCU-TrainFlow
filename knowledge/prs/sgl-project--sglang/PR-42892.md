## Motivation

With an a2a MoE backend and attention TP above 1, an FFN leaves its output and the residual on this rank's attention-TP slice of the rows, and the next layer's attention gathers its input from there. That holds within a rank but not across a pipeline handoff. The sending rank's last FFN is bound against the next rank's first stage rather than as the end of the stack, so it hands over the slice. The receiving rank's PP buffers hold every token's row, so its first FFN fails with a row mismatch. Qwen3-30B-A3B with DeepEP at TP 2 × PP 2 × EP 2 fails on `main` at PP rank 1's first FFN:

```
The size of tensor a (64) must match the size of tensor b (128)
```

## Modifications

- An FFN whose output crosses to another pipeline rank returns it to the attention's rows (`exit_rows=ATTENTION`), so both ranks agree on what the handoff carries:
  - The sending rank marks its last stage that way before any stage of the stack binds, so a branch that reads that stage (`prepared_from`) binds against the same declaration.
  - The receiving rank marks the neighbour stage it reads the same way.
- An FFN that computes on this rank's own rows (`_ffn_on_rank_rows`, the predicate `_resolve_ffn` already used) also writes its output into the residual at the handoff, on every batch (`StageDeclaration.writes_at_handoff`), so the handoff carries the written stream alone. Its exit completes the output there rather than leaving work for the next stage, which is on another rank.
- The receiving rank knows the stream arrives written from the producer's declaration, as it already does for MHC's written streams (`residual_in_hidden`), not from which tensors arrive. A captured decode CUDA graph's PP input buffers hold a `residual` for every non-MHC model whether or not the sender sent one. An FFN on the attention's rows still hands off its residual, and `from_pp` still requires it.
- `test_append_stages.py` (`TestPipelineHandoff`):
  - The sending rank's last FFN returns its output to the attention rows and writes it, also when its move leaves the residual.
  - The receiving rank's first stage reads the attention rows, and reads the stream as written even with a residual beside it.
  - A handoff from an FFN on the attention's rows carries its residual, which the receiver requires.
- `build_stages` in `boundary_fixtures` uses the stack's neighbour hooks to stand in for this rank's own neighbouring layers, so it turns the handoff off.

## Accuracy Tests

- Qwen3-30B-A3B, DeepEP + `deep_gemm`, TP 2 × PP 2 × EP 2 on B200: crashes on `main`; with this change it serves, and two launches give identical logprobs.
- Qwen3-30B-A3B, DeepEP, TP 2 × PP 2 × EP 2 on H200 (fa3, deterministic inference):
  - GSM8K (200): 0.935. Decode with CUDA graphs and eager decode give identical answers on all 200; `main` crashes.
  - One request at a time, answers are identical on 60/60 to one rank handing off at the same layer (layer 23 of 48), and with CUDA graphs off every layer's input matches that run bit for bit, in prefill and in decode.
  - With `--disable-attn-tp-gather`, decoding a request alone and then four at once gives coherent output with CUDA graphs. Graphs and eager decode still pick different greedy tokens on some prompts, as they do in that configuration without PP; `main` fails to serve it.
- Unchanged where no FFN leaves a slice. On H200, GSM8K with TP 2 × PP 2 (deterministic inference, fa3) matches `main` exactly: 0.930 on both arms, 200/200 identical answers. This was measured at the top of this stack.
- CPU: at the top of this stack, a 217-file battery shows no new failure against `main`.
