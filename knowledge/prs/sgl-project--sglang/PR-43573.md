# [diffusion] Accept request-level profiling on the image API

[Upstream PR](https://github.com/sgl-project/sglang/pull/43573) · state: closed · merged: True

## Original PR description

## Motivation

`/v1/videos` forwards `profile`, `num_profiled_timesteps` and `profile_all_stages` into `SamplingParams`, which starts the torch profiler for that request. `ImageGenerationsRequest` has no such fields, so pydantic drops them and an image request that asks for a trace gets none. The only way to profile an image model was the offline `sglang generate --profile`.

## Modifications

- `ImageGenerationsRequest` gains the three profiling fields (same defaults as the video request).
- `/v1/images/generations` and the multipart `/v1/images/edits` forward them to `build_sampling_params`, like the video path.

## Accuracy Tests

No numerical change.

## Speed Tests and Profiling

GB300, FLUX.1-dev TP2 served with `SGLANG_DIFFUSION_TORCH_PROFILER_DIR` set. `POST /v1/images/generations` with `"profile": true, "num_profiled_timesteps": 2` returns 200 and writes `<request-id>-2_steps-global-rank0.trace.json.gz`. Before this PR, nothing is written.
