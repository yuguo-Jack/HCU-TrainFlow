# [diffusion] comfyui: fix 14 bugs in the SGLDiffusion ComfyUI plugin

[Upstream PR](https://github.com/sgl-project/sglang/pull/43536) · state: open · merged: False

## Original PR description

## Summary

Fourteen bugs found during an audit of `python/sglang/multimodal_gen/apps/ComfyUI_SGLDiffusion/` (the ComfyUI client plugin for the SGLang diffusion server), each fixed in its own commit below. Each is confirmed against the actual pre-fix code (reproduced directly, not just read), fixed, covered by a new regression test, and reviewed.

## Issues fixed (one per commit)

1. **GGUF detection hardcoded to MiniMax-H3.** Any `.gguf` file was treated as MiniMax-H3 for ComfyUI's architecture detection, regardless of what model it actually was — a Flux/Qwen/Z-Image GGUF either failed with an H3-specific error, or silently built the H3 model around the wrong weights if an H3 BF16 file happened to be present. Fixed by inferring the real architecture from an `SGLDOptions.model_type` hint or the filename, and raising a clear error when it can't be determined.
2. **`.gguf` leaking into ComfyUI's global `diffusion_models` registry.** `SGLDUNETLoader` enabled `.gguf` by mutating `folder_paths.folder_names_and_paths` at import time — shared global state — so ComfyUI's own stock "Load Diffusion Model" node started offering GGUF files it can't load. Fixed by building this node's own file list locally instead.
3. **Server-mode nodes sending local paths a remote server can't read.** The generic video node sent a local temp-file path as `input_reference` and a client-side temp dir as `output_path`; the H3 node built `file://` URIs for keyframes/references. None of that is readable by an SGLD server on another machine. Fixed: upload local references via multipart, never send `output_path` (let the server pick its own and download the result if needed), embed H3 image conditions as base64 `data:` URIs, and raise clearly for local video/audio references against a confirmed-remote server.
4. **`enable_cache_dit` silently ignored outside MiniMax-H3.** It's a generic `SamplingParams` field, but only `MiniMaxH3Executor` read it — Flux/Qwen-Image/Z-Image users toggling it got no effect and no warning. Fixed by moving the plumbing into the shared executor base class.
5. **Bare `None` from detection failure causing a confusing `TypeError`.** `get_comfyui_model` returned `None` on two failure paths, but callers always unpack 3-4 values — users saw "cannot unpack non-iterable NoneType object" instead of the real error. Fixed to raise `ValueError` with the model path and detected type.
6. **`SGLDVideoInput` didn't implement ComfyUI's `VideoInput` contract.** `get_components()` returned a bare list instead of a `VideoComponents`, so any downstream node reading frames/audio would crash; `save_to` silently dropped `format`/`codec`/`metadata`. Fixed by preferring ComfyUI's own file-backed `VideoFromFile` and making the fallback fail loudly instead of returning/doing the wrong thing.
7. **Reported video width/height could be wrong.** The generic video node always reported the *requested* size even when the server resolved a different one (e.g. to match an image-to-video input's aspect ratio). Fixed by reading the server's resolved `size` field. (Same commit as #6, since the `VideoFromFile` fix also makes dimensions self-correcting.)
8. **Missing-runtime import guard disappearing all nodes silently.** `executors/minimax_h3.py` imported `sglang.multimodal_gen` unguarded at module scope — breaking the "stay importable without the runtime" pattern the rest of the executors follow — and `core/generator.py` imports every executor unconditionally, so this took Flux/Z-Image down too. `__init__.py`'s `except` branch then swallowed the resulting `ImportError` with zero logging, so every node just vanished from ComfyUI with no clue why. Fixed by guarding the import (mirroring `base.py`'s pattern) and logging the failure.
9. **Hardcoded 300s timeout on image requests.** No way to raise it for a large job or a first request that triggers `torch.compile` warmup. Fixed with a configurable `image_timeout` param (default unchanged).
10. **Batched image inputs silently truncated to the first image.** `get_image_path` saved only `image[0]` from a batch, dropping the rest with no warning. Fixed to raise a clear error instead.
11. **LoRA strength not settable in server mode.** The server's `/set_lora` endpoint accepts a `strength` field; the client and node never exposed it. Fixed by threading it through both.
12. **Inconsistent VRAM accounting across model types.** `SGLDModelPatcher.model_size()` returned a hardcoded guess for `flux`/`lumina2` and `0` for everything else, so ComfyUI freed VRAM inconsistently across SGLD model types even though the weights live in the worker process. Fixed by computing the real byte size from the checkpoint header at load time (falling back to the old table only when that's unavailable), and sizing GGUF loads from the actual GGUF file rather than the BF16 companion used only for architecture detection.

13. **ComfyUI "Unload models" / "Free memory" never reached the worker.** The weights live in the SGLD worker process, `loaded_size()` was always 0, and nothing called `release_memory_occupation`, so ComfyUI could not make room for the VAE or a text encoder. `SGLDModelPatcher.detach` (the end of every ComfyUI unload path, usually on a clone) now puts the worker to sleep, and `ensure_executor` / `set_lora` wake it before the next use. `loaded_size()` reports the real size while the worker is awake, and a patcher for a replaced worker cannot sleep the new one. Sleep only frees VRAM when the worker keeps the DiT resident (`dit_cpu_offload=False`, no layerwise offload); with the default CPU offload there is nothing to free.
14. **Server-mode video jobs had no progress bar and ignored Cancel.** `generate_video` now takes `progress_callback` / `check_interrupt`, wired in both video nodes to `comfy.utils.ProgressBar` and `throw_exception_if_processing_interrupted`; the interrupt is no longer wrapped in `RuntimeError`, and polling checks it about every second. Limits: the server reports progress only as 0 then 100, and Cancel stops the client waiting but the server job keeps running (there is no abort endpoint yet, see the TODO in `video_api.py`).

## How each bug was verified

- 8 of the first 12 were reproduced directly against the actual pre-fix code (not just read): GGUF-detect defaulting to H3, the global `.gguf` registry mutation, `get_comfyui_model` returning bare `None`, `SGLDVideoInput`'s broken contract, the hardcoded 300s timeout, batch truncation, missing LoRA strength, and the hardcoded VRAM table.
- The remaining ones (local `file://` paths, `enable_cache_dit` H3-only, the import-guard fragility) were confirmed by direct source inspection plus, for the import guard, a real traceback showing the original `executors/__init__.py` drags in the entire `sglang.srt` LLM-serving stack just to import Flux/Z-Image.
- An independent review pass (fresh context, no knowledge of the implementation) caught a real bug introduced while fixing #12 — GGUF model size was computed from the BF16 companion file instead of the actual GGUF — which is now fixed and covered by its own regression test.

## Tests

- `test/test_sgld_bugfixes.py` (new): 38 tests, one or more per bug above, run against stubbed `comfy`/`folder_paths` modules so they don't need a ComfyUI install or a GPU.
- `test/test_h3_request.py` (existing): updated for the behavior changes in #3/#6/#7 (base64 image URIs instead of `file://`, real temp files instead of fixed fake paths since the client now validates `file_path` locally); all pre-existing assertions preserved.
- 13 new tests for #13 and #14 (each failed before the fix); 50/50 passing locally (CPU only).

## GPU end-to-end (1x L40S)

- #13, real FLUX.1-dev worker, unloading a clone of the patcher: 24.3 GiB used awake, 1.6 GiB asleep, and the next forward woke the worker with a bit-identical output.
- #14, real Wan2.1-T2V-1.3B server and the real video node: the progress bar reached 100, and a ComfyUI interrupt 4s into a job stopped the node at 4.0s.
