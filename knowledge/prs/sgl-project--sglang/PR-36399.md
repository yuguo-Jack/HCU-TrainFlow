# [diffusion] bench: report steady-state denoise latency by default

[Upstream PR](https://github.com/sgl-project/sglang/pull/36399) · state: closed · merged: False

## Original PR description

## Motivation

The denoise benchmark measured one request. `torch.compile` incurs its compile cost on the first request, so with `--torch-compile` the reported number was first-request latency, not steady state. The distortion scales inversely with step count (H100, 1024²):

| preset | single-shot | steady state | overstatement |
| --- | --- | --- | --- |
| flux2-klein | 1.845 s | 0.275 s | 6.7x |
| zimage | 2.578 s | 0.623 s | 4.1x |
| ltx2 | 25.710 s | 7.408 s | 3.5x |

Eager pays no compile cost, so the error only inflates the compile arm — it skews compile-vs-eager comparisons, not just absolute numbers.

## Modifications

`--iterations` (default 4) runs N requests in one process and reports the fastest; request 1 loses the min by construction. Per-request timings come from stdout because the perf dump only ever holds request 1 (`cli/generate.py` writes `results[0]`), and the full series lands in `results_<label>.json`.

`SKILL.md` and `benchmark-and-profile.md`: document the default, and correct the Perf Dump Workflow — it directed readers to `compare_perf.py`, which reads the request-1 dumps, i.e. the cold numbers.

## Speed Tests

`flux2-klein`, 1×H100, 1024², `--torch-compile`, denoise seconds per request:

```
0.369  0.242  0.244  0.246   -> reported 0.242
```

Single-shot would have reported 0.369 s, 1.5x high. This run had a warm inductor cache; with a cold one the first request is several seconds and the gap is far larger.
