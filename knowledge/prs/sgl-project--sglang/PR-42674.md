# [sgl-router] Serve native gRPC ChatComplete

[Upstream PR](https://github.com/sgl-project/sglang/pull/42674) · state: open · merged: False

## Original PR description

Stacked on #42673, which moves `sglang-grpc-types` to tonic 0.14.

## Motivation

The router should offer the engine's native gRPC API (`sglang.runtime.v1.SglangService`), so a gRPC client can point at the router or at an engine without changes. This PR serves `ChatComplete`.

## Changes

- **`--grpc-port`:** serves `SglangService` with the generated server from `sglang-grpc-types`, so the router and the engine share one proto. RPCs the router doesn't serve return `UNIMPLEMENTED`.
- **`ChatComplete` routing:** a call goes through the same steps as `/v1/chat/completions`: template rendering and tokenization, `input_ids` forwarding, engine selection, PD bootstrap and DP rank. The router then calls the selected engine's native `ChatComplete` and relays its chunks. The engine's gRPC port comes from `/server_info` (`grpc_port`). HTTP requests still go over HTTP and behave as before.
- **Shared dispatch:** `forward.rs` dispatch is generic over the transport, so HTTP and gRPC share PD, DP-rank, load-guard, breaker and metrics handling. The SSE pump now carries gRPC chunks as well as bytes.
- **Headers:** request metadata and `trace_headers` act as HTTP headers for routing and forwarding.
- **Cancellation:** a cancelled call aborts the engine request.
- **Errors:** router errors become a gRPC status with an `x-router-error-code` trailer. An engine's status passes through unchanged.

## Review fixes

- **Docker builds:** both router images copy `proto/` and the `rust/Cargo.toml` it inherits from, keeping the repo layout. The release image now builds from `/work/experimental/sgl-router`. Router CI also runs when `proto/**` or `rust/Cargo.toml` change.
- **Cancellation:** an unfinished engine call is aborted by the router's rid with the `Abort` RPC, as `/abort_request` does over HTTP. A dropped call alone aborts an id of the engine's own. This relies on the `Abort` fix in #42673.
- **Backpressure:** a status that ends a stream is classified by its code, so `RESOURCE_EXHAUSTED` no longer opens the breaker.
- **Streaming status:** an engine's plain response to a streaming call (one finished chunk with `status_code`) is recorded as that status, for metrics and the breaker.
- **Router errors:** streams the router ends itself (idle timeout, stale expiry, prefill abort) keep their gRPC code and `x-router-error-code`.

## Tests

- Four new tests in `tests/proxy/grpc_chat.rs`:
  - the engine receives the same body over gRPC as over HTTP, and chunks are relayed unchanged;
  - both PD legs get the same bootstrap room;
  - a client cancel drops the engine call;
  - errors arrive as gRPC statuses;
  - a cancelled call sends `Abort` with the body's rid;
  - backpressure doesn't open the breaker, while streamed 500s do;
  - an idle timeout arrives as `DEADLINE_EXCEEDED` with `upstream_timeout`.
- Each new test fails on the previous behavior.
- Both Docker layouts (e2e, and the release cargo-chef build) were reproduced locally and build with `--locked`.
- Real engine: cancelling a non-streaming or streaming call through the router stops generation at once. Before, the request ran to its full length.
- The full suite passes and clippy is clean with `-D warnings`.
- Real engine (Qwen3-4B, `--grpc-port`), same temperature-0 chat:
  - Router HTTP, router gRPC and direct engine gRPC return identical responses, ignoring `id` and `created`.
  - Streaming gives the same 34 chunks and the same text on all three.
  - The router's `input_ids_forwarding_total{outcome="forwarded"}` counter shows the gRPC requests used its own rendering and tokenization.

Not covered yet: PD and `--dp-aware` over gRPC with real engines (PD is covered only with mock engines).
