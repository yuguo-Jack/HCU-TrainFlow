# [sgl-router] Serve the Anthropic Messages API on /v1/messages

[Upstream PR](https://github.com/sgl-project/sglang/pull/42316) · state: closed · merged: True

## Original PR description

## Motivation

Clients built on the Anthropic Messages API (the anthropic SDK, Claude Code) cannot use sgl-router today: it only serves chat completions. This adds `POST /v1/messages` and `POST /v1/messages/count_tokens` to the router.

## Modifications

A Messages request is converted to a chat request at ingress and served by the existing `chat_completions` handler, so it is routed exactly like chat (tokenization, cache-aware routing, admission, retry, PD). The reply is converted back on the outer body, streaming or not.

- **Request**: `system` as a string or text blocks; content as a string or blocks; text and image (base64 / url) blocks; `tool_use` / `tool_result` round trips; assistant thinking history sent as `reasoning_content`.
- **Parameters**: `thinking` → `chat_template_kwargs`, `output_config.effort` → `reasoning_effort` (unchanged), `output_config.format` / `output_format` → `response_format`, `stop_sequences` as a string or array, `top_k` passed through. Conversion works on `serde_json::Value`, so sglang chat extensions pass through.
- **Reply**: `thinking`, `text` and `tool_use` blocks; `stop_reason` covers `end_turn` / `max_tokens` / `tool_use` / `stop_sequence`; usage includes `cache_read_input_tokens`.
- **Streaming**: the spec event sequence (`message_start` → block start / delta / stop → `message_delta` → `message_stop`). Continuous usage is enabled so `message_start` carries `input_tokens`.
- **count_tokens**: answered by the router's own chat encoder, without an engine call; 400 when the model's tokenizer is disabled.
- **Errors**: every non-2xx answer uses the Anthropic `{"type": "error", "error": {...}}` envelope with the type for its status: router rejections, engine errors, in-stream errors and the body-limit 413.
- `src/protocol/sse.rs` is a small generic layer that rewrites a chat SSE body into another protocol's events (`SseTransducer`, `transduce_body`). It wraps the body produced by `proxy/sse.rs`, so timeouts, abort-on-disconnect and TTFT/ITL metrics are unchanged.

The companion PR for OpenAI `/v1/responses` (#42314) carries a byte-identical `protocol/sse.rs`; whichever lands second only needs a one-line rebase in `protocol/mod.rs`.

File: `experimental/sgl-router/src/protocol/anthropic/stream.rs` · line None

[P2] Tool blocks are keyed by `(kind, index)`, which breaks in two ways:

1. **Separate calls merge.** SGLang's Gemma 4 parser reuses the index for separate calls to the same tool. Two weather calls merge into one block with invalid arguments: `{"city":"Paris"}{"city":"Rome"}`.
2. **One call splits.** Any text or reasoning delta in the middle of a call closes the block. Feeding idx0 `{"x":` → text `"\n"` → idx0 `1}` gives `tool_use{name: f}` with `{"x":`, then a text block, then `tool_use{id: toolu_<random>, name: ""}` with `1}`.

Suggest: a chunk carrying `function.name` (SGLang sends it only on a call's first chunk) always starts a new tool block; argument-only chunks go to the open tool block; text that arrives mid-call is held back (or dropped if it is only whitespace).

This only sets the `thinking` / `enable_thinking` kwargs. The engine's `apply_reasoning_enabled` depends on the model:
- Hunyuan, Mistral and Inkling use `reasoning_effort`;
- always-on models reject `disabled`;
- models with no reasoning parser reject `enabled`.

Through the router, `thinking: disabled` does nothing on those models. If the router can't know the parser, please note this limitation in the README.

[P2] Consecutive same-role turns are not merged. Each turn is converted on its own, so two user messages in a row stay separate, and templates that require alternating roles fail to render.
