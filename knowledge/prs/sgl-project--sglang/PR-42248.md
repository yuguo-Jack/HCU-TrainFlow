## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Improve the embedding and prefill-only scoring paths by preserving native-dtype embedding outputs, removing avoidable metadata and padding work, and making raw-K/V attention selection agree with the existing no-cache opt-in.

This combines four changes on current OSS `main`. The implementation commits remain separate to make each change reviewable.

Updated to `main` at `46498bc8`. The net diff has the same added and removed lines in the same 18 files as the narrowed port before the base update.

## Modifications

<!-- Detail the changes made in this pull request. -->

1. **Native tensor embedding output.** Add optional `encoding_format` after `dimensions` in `Engine.encode()` and `async_encode()`, matching the source port without a keyword-only restriction. For dense outputs, `None` and case-insensitive `"float"` preserve list responses; other format strings retain detached CPU tensors at the model's output dtype. Carry the format through batch slicing, tokenization, scheduler admission, and mixed batches. Keep `_convert_embeddings` and `_convert_embedding_for_response` as separate steps, as in the source port. Use a dedicated typed IPC tensor field compatible with msgspec and preserve it through multi-tokenizer routing and response reconstruction. Also forward the retraction counts that the current tokenizer receiver requires. Do not add request-format normalization or HTTP/sparse-head rejection beyond the source port.
2. **Host-side FlashInfer MIS metadata.** Build relative positions, padding, and per-item maxima on the CPU, where delimiter indices already reside. Transfer each completed metadata tensor to the device once, preserving metadata dtypes, shapes, prefix-cache offsets, and position updates.
3. **Explicit FA raw-K/V gate.** Require `get_schedule().prefill_only_disable_kv_cache` in `fa_skip_kv_cache`, retaining the existing embedding, unchunked-prefill, disabled-radix-cache, and non-MLA conditions. Internal auto-enables such as EmbeddingGemma continue to work.
4. **Skip dense-CUDA padded-tail zeroing.** Avoid per-layer tail-zeroing operations for non-ROCm models without MoE layers. Retain zeroing for ROCm and CUDA MoE, including mixed dense/MoE layer lists. Preserve the separate idle-rank/zero-real-token output-zeroing path.

**Intentional behavior change:** embedding configurations that previously selected raw-K/V attention implicitly now use paged attention unless `--prefill-only-disable-kv-cache` is enabled. Already-opted-in configurations retain their existing path.

**Scope:** unrelated VSA imports, FastAPI telemetry, and HiCache fixes and their tests are excluded. Existing attention and multimodal tests receive only the fixture fields required by the ported code (`moe_layers=[]` and `encoding_format=None`). The GPU tensor-encoding regression comes from the source port; the additional encoding unit-test file and padded-tail test cases are removed.

The tensor format is an in-process API, not a new JSON wire encoding:

```python
# Using an already initialized dense embedding engine:
result = engine.encode("A short document", encoding_format="tensor")
embedding = result["embedding"]  # CPU torch.Tensor, preserving output dtype
```

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

No new hardware performance measurement is claimed for this upstream port.

- Tensor output avoids conversion to Python floats; default float-only batches retain the existing bulk `.tolist()` path.
- MIS metadata construction removes small eager device-side arithmetic operations.
- Dense-CUDA padded buckets avoid a tail-zeroing operation per attention layer.
- The explicit raw-K/V gate intentionally moves previously implicit users to paged attention, which may add KV-cache costs until they opt in.
