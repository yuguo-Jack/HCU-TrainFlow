The actual metrics tracking queue depths in disaggregation mode are named `sglang:num_prefill_bootstrap_queue_reqs`, `sglang:num_prefill_inflight_queue_reqs`, `sglang:num_decode_prealloc_queue_reqs`, and `sglang:num_decode_transfer_queue_reqs`.
```suggestion
| Prefill/Decode disaggregation | disaggregation mode enabled | num_*_queue_reqs, kv_transfer_*, num_bootstrap_failed_reqs_total, num_transfer_failed_reqs_total |
```

![medium](https://www.gstatic.com/codereviewagent/medium-priority.svg)

The metrics `sglang:per_stage_req_latency_seconds` and `sglang:queue_time_seconds` are registered in `SchedulerMetricsCollector` rather than `TokenizerMetricsCollector`. Consequently, they carry the scheduler/engine common labels (such as `engine_type`, `tp_rank`, `pp_rank`, `moe_ep_rank`) instead of the request metrics common labels (which only carry `model_name`). We should clarify this in their descriptions so operators know what labels to expect.

```suggestion
| `sglang:per_stage_req_latency_seconds` | Histogram | `stage` | Latency of each stage of a request's lifecycle. Note: This is a scheduler metric and carries scheduler/engine labels. |
| `sglang:queue_time_seconds` | Histogram | | Histogram of queueing time in seconds. Note: This is a scheduler metric and carries scheduler/engine labels. |
```
