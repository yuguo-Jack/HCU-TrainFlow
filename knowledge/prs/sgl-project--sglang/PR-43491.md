# [diffusion] comfyui: fix SGLDiffusionServerAPI.get_model_info hitting a 404

[Upstream PR](https://github.com/sgl-project/sglang/pull/43491) · state: closed · merged: False

## Original PR description

## Summary

- `SGLDiffusionServerAPI.get_model_info` stripped `/v1` before building the request URL, but the server only registers `/models` under the `/v1` prefix (`runtime/entrypoints/openai/common_api.py`), so every call 404'd and the ComfyUI "Load Server" node always showed `Failed to get model info: ... 404 ...`.
- The server's response also wraps the model card in an OpenAI-style `{"object": "list", "data": [...]}` envelope, so even with the URL fixed the caller got the envelope instead of the flat `task_type`/`pipeline_name`/`num_gpus` fields the docstring promises.
- Fixed by requesting `{base_url}/models` directly and unwrapping `data[0]`, with a `RuntimeError` fallback if the response shape is ever unexpected.

## Test plan

- Added `test/test_server_info_endpoint.py`, a CPU-only unit test mocking HTTP that checks the URL and the unwrapped response shape.
- `py_compile` clean; full suite needs CI (no local `sglang` install in this environment).
