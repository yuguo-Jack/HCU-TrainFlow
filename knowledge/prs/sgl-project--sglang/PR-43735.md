# [DCP] Decode context parallelism for DSA (GLM-5.2 / GLM-5.3) with MTP

[Upstream PR](https://github.com/sgl-project/sglang/pull/43735) · state: open · merged: False

## Original PR description

## Motivation

`--dcp-size > 1` does not work for the RoPE DSA models (GLM-5.2, GLM-5.3, DeepSeek-V3.2): the sparse backend returns no LSE, the index-K cache and the MTP draft pool are sized per rank while the allocator hands out widened slots, and the TRT-LLM buffers are sized for one rank's heads. Builds on the approach of #42536 (co-authored with @vincentzed) and the Flash stack #40433 / #40434.

## Modifications

- **Target KV** stays striped by position (unchanged `main` layout). The **index-K cache is replicated** and addressed by the widened allocator slot, so every rank scores the whole sequence and selects the global top-k.
- **Attention**: one Triton kernel keeps the top-k slots this rank owns, maps them to local rows and compacts them; the TRT-LLM sparse kernel runs on the DCP group's gathered query heads with `return_lse`, and the existing MLA DCP merge combines the partials. Decode, target verify and extend all take this path (no prefix-KV gather). Shared-top-k layers reuse the localized table (21 remaps per step instead of 78).
- **MTP draft (nextn)**: the pool is replicated over the widened slots (`dcp_replicated`, kernel page stays 64) and the draft attends without the DCP group (`is_nextn` / `is_draft_worker`, as the Qwen3.5 draft does), so MTP index share feeds the draft directly.
- **Accounting**: index keys and the draft pool are charged `dcp_size` times per physical token on every platform (the NPU-only guards are dropped).
- **Launch validation**: the generic DCP hook now rejects prefill CP with `--dcp-size > 1`; the DSA override rejects HiSparse, HiCache, PD disaggregation and tree drafting, and defaults the DSA backends to `trtllm` (`index_kpool > 1` was already rejected on `main`).
- **Fast follows** (rejected at launch for now): HiCache and PD disaggregation need the replicated index-K cache's widened page geometry in the host pool and the transfer page-id lists; other DSA backends need to return the LSE under DCP.
- Kept from #42536: the LSE combine keeps all-empty padding rows at zero. Not kept: the head folding for the FlashInfer 0.7.0.post1 `return_lse` bug above 32 heads, which does not reproduce on B300 with that FlashInfer (see the comment below); the gathered heads go to the kernel in one call.

Design notes with permalinks: `dsa-dcp-design.md` (shared separately).

## Accuracy Tests

`zai-org/GLM-5.3` (FP8), 8xB300, `--tp 8 --mem-fraction-static 0.88 --max-running-requests 64`, branch at `28bb3d6074`. MTP = `--speculative-algorithm EAGLE --speculative-num-steps 5 --speculative-eagle-topk 1 --speculative-num-draft-tokens 6`. GSM8K: `few_shot_gsm8k`, 8-shot, 1319 questions. AIME26: `sgl-eval run aime26 --n-repeats 4` with the GLM-5.2-FP8 preset (200k max tokens).

| Config | GSM8K acc | AIME26 pass@1 (avg of 4) | AIME26 pass@4 | AIME26 gen tok/s | MTP accept len |
|---|---|---|---|---|---|
| TP8 | 0.912 | 99.17% | 100% | 1140 | - |
| TP8 + DCP2 | 0.917 | 99.17% | 100% | 1041 | - |
| TP8 + DCP2 + MTP | 0.919 | 95.83% | 100% | 1876 | 3.51 |
| TP8 + DCP8 | 0.914 | 95.00% | 100% | 838 | - |
| TP8 + DCP8 + MTP | 0.919 | 95.00% | 100% | 1784 | 3.62 |

Spot checks (GSM8K, 300-400 questions): `--dcp-comm-backend ag_rs` DCP2 + MTP 0.907; an 8192-token-per-rank pool so the last allocator page is in use, DCP2 0.903 and DCP2 + MTP 0.907; without head folding, DCP8 0.943 and DCP8 + MTP 0.913 (the 64-head case).

AIME26 pass@1 spread is sampling noise: every run loses problem 14 to the 200k cap (including TP8), and the remaining misses are either a correct final line without `\boxed{}` (3 in DCP2 + MTP, 2 in DCP8) or single-sample arithmetic slips; no run shows degenerate output. The DCP2 + MTP run surfaced one bug, fixed in `28bb3d6074`: the DSA draft's one-shot MHA prefill keyed its prefix all-gather on the global DCP flag instead of the layer's `dcp_size`.

```python
import math, torch, flashinfer.decode
TOPK, SCALE = 2048, 1 / math.sqrt(192)
ws = torch.zeros(256 << 20, dtype=torch.uint8, device="cuda")

def run(q, kv, pt, sl):
    rows, _, heads, _ = q.shape
    lse = torch.full((rows, heads), float("nan"), dtype=torch.float32, device="cuda")
    out, _ = flashinfer.decode.trtllm_batch_decode_with_kv_cache_mla(
        query=q, kv_cache=kv.reshape(-1, 1, 64, 576), workspace_buffer=ws,
        qk_nope_head_dim=128, kv_lora_rank=512, qk_rope_head_dim=64,
        block_tables=pt.unsqueeze(1), seq_lens=sl, max_seq_len=TOPK,
        sparse_mla_top_k=TOPK, bmm1_scale=SCALE, backend="trtllm-gen",
        return_lse=True, lse=lse)
    return out.view(rows, heads, -1).float(), lse

def ref(q, kv, pt, sl):
    outs, lses = [], []
    for r in range(q.shape[0]):
        n = int(sl[r]); k = kv[pt[r, :n].long()].float(); s = (q[r, 0].float() @ k.T) * SCALE
        m = s.max(-1, keepdim=True).values; p = torch.exp(s - m); l = p.sum(-1, keepdim=True)
        outs.append((p / l) @ k[:, :512]); lses.append((m + torch.log(l)).squeeze(-1) / math.log(2))
    return torch.stack(outs), torch.stack(lses)

g = torch.Generator().manual_seed(0)
for heads in (32, 64, 128):
    for n in (1, 3, 16, 63, 64, 65, 200, 2048):
        rows = 4
        pt = torch.full((rows, TOPK), -1, dtype=torch.int32)
        for r in range(rows): pt[r, :n] = torch.randperm(4096, generator=g)[:n]
        pt, sl = pt.cuda(), torch.full((rows,), n, dtype=torch.int32, device="cuda")
        q = (torch.randn(rows, 1, heads, 576, generator=g) * 0.25).cuda().to(torch.float8_e4m3fn)
        kv = (torch.randn(4096, 576, generator=g) * 0.25).cuda().to(torch.float8_e4m3fn)
        out, lse = run(q, kv, pt, sl); rout, rlse = ref(q, kv, pt, sl)
        print(heads, n, (out - rout).abs().max().item(), (lse - rlse).abs().max().item())
```
