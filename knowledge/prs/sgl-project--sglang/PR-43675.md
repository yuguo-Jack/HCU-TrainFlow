# Fix Kimi-K3 MLA CUDA graph weight reloads

[Upstream PR](https://github.com/sgl-project/sglang/pull/43675) · state: open · merged: False

## Original PR description

## Motivation

Reloading Kimi-K3 weights after CUDA graph capture replaces the MLA `w_kc` and `w_vc` tensors in `post_load_weights()`. The captured projections still reference the previous storage, while eager execution uses the newly absorbed `kv_b_proj` weights. Consequently, replay can use stale weights after a hot update without graph recapture.

## Modifications

- Reuse the existing `bind_or_assign` helper to populate MLA buffers on the first load and copy into their existing storage on subsequent loads. The current tensor layouts are preserved.
- Add one regression to the existing K3 attention CUDA graph test file. It calls the real `KimiK3LinearForCausalLM.post_load_weights()` on a minimal MLA fixture, captures both absorbed projections, and checks two successive weight updates against eager output and the original buffer addresses.

The production change is 8 added / 2 removed lines. The regression adds 62 lines. This PR covers the MLA absorbed buffers; other K3 derived caches and fused weight buffers are outside its scope.

## Accuracy Tests

Tested against upstream `53295c697255a5e8ddb263f98ab7e047e2700ad2` on one NVIDIA H100 80GB, with BF16 tensors, PyTorch `2.13.0+cu130`, and CUDA 13.0. This is a standalone fixed-input projection reproduction: no model download, rollout sampling, trainer, or weight-checker randomization is involved.

Run the new regression:

```bash
PYTHONPATH=python python test/registered/unit/models/test_kimi_k3_bfa_overlap.py \
  TestKimiK3BfaOverlap.test_mla_weight_reload_preserves_captured_projections -v
```

The same regression fails before the production fix and passes after it:

| Reload | Projection | Before: max absolute graph/eager error | After |
| --- | --- | ---: | ---: |
| 1 | `w_kc` | 0.021484375 | 0 |
| 1 | `w_vc` | 0.34375 | 0 |
| 2 | `w_kc` | 0.04248046875 | 0 |
| 2 | `w_vc` | 0.6875 | 0 |

Both buffer addresses change before the fix and remain stable after it. All four graph/eager comparisons are bitwise equal after the fix; the test also verifies that reloaded eager outputs differ from the initial outputs.

The complete test file passes **6/6 tests** in 11.6 seconds:

```bash
PYTHONPATH=python python test/registered/unit/models/test_kimi_k3_bfa_overlap.py -v
```

All applicable pre-commit hooks pass for both changed files, including formatting and registered-test validation. The standalone test isolates BF16 MLA reload correctness; it does not establish full-model accuracy or coverage of every quantized reload path.
