# [NIXL] Support per-GPU UCX device selection

## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Allow NIXL UCX to reuse `--disaggregation-ib-device` for shared or per-GPU NIC selection. This makes GPU-to-NIC mappings configurable through the existing disaggregation option, without requiring separate backend configuration for each rank.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Resolve single-device, comma-separated, and per-GPU JSON/file mappings into NIXL UCX's `device_list`.
- Validate device names and reject conflicting CLI and backend settings.
- Preserve existing device selection when the option is unset; leave Mooncake and other NIXL backends unchanged.

Example:

```bash
--disaggregation-transfer-backend nixl \
--disaggregation-ib-device '{"0":"mlx5_0","1":"mlx5_1","2":"mlx5_2","3":"mlx5_3"}'
```
Mapping keys are process-visible GPU IDs. Device names use HCA names without port suffixes.

This change primarily targets GPU-to-CPU transfers, such as receiving KV into CPU memory with HiSparse enabled on the D side. In our same-host setup, GPU-to-GPU transfers use CUDA IPC/NVLink; NIC selection does not force them through RDMA.

**Shared NIC:** all four P/D rank pairs share one RDMA NIC.

## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->

Validated on 8 × H200 with NIXL 1.4.1:

- Cross-process GPU→GPU and GPU→pinned-CPU transfers across four GPU pairs: all 96 transfers passed full-buffer byte validation.
- GLM-5.3-Flash PD smoke test with TP4/EP4 on both sides: all eight requests completed successfully. Binding logs confirmed the expected NIC mapping for all eight ranks.
- CPU configuration checks and pre-commit passed.

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

Four concurrent GPU pairs, each transferring 64 MiB using shuffled 32 KiB pages. Median GPU→pinned-CPU transfer latency over three measured iterations after warmup:

| Device selection | Pair 0 | Pair 1 | Pair 2 | Pair 3 |
| --- | ---: | ---: | ---: | ---: |
| Default | 534.96 ms | 522.96 ms | 520.24 ms | 491.18 ms |
| Native NIXL `device_list` | 13.05 ms | 12.87 ms | 11.42 ms | 11.83 ms |
| `--disaggregation-ib-device` mapping | 12.19 ms | 12.12 ms | 12.10 ms | 12.34 ms |

The CLI mapping matches native NIXL device selection performance. On this host, explicit NIC selection substantially reduced GPU→CPU transfer latency compared with the default selection. These are standalone transfer measurements, not end-to-end model throughput.
