# [HiCache] Key MLA Mamba state per TP rank in the file backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/41907) · state: open · merged: False

## Original PR description

## Summary

Fix an existing `main` bug in the file L3 backend: MLA KV/indexer pages are replicated, but Mamba state is TP-sharded and `should_backup` makes every TP rank back up its own shard. `HiCacheFile` drops the TP rank from the key of an MLA model, so every rank writes the same `<key>.mamba` file and restores another rank's state.

Following #43594 (the same fix for NIXL), Mamba keys on MLA models use the rank-qualified suffix a non-MLA model would use (`<key>.mamba_<model>_<tp_rank>_<tp_size>[_pp][_cp]`); replicated KV/indexer keys are unchanged, and rank-ambiguous legacy Mamba files read as misses.

The file backend also has an LRU evictor that, on MLA models, only lets rank 0 own (create, track, evict) files. With per-rank Mamba keys every rank must own its own shard, so the evictor now owns keys by suffix: rank 0 still owns replicated files, and each rank owns files carrying its own Mamba suffix. Startup scans, `touch` and write admission all use the same ownership test, so a rank never adopts or evicts another rank's files.

Scope: this PR now covers the file backend only.

| Backend | Status |
| --- | --- |
| file | this PR |
| NIXL | fixed by #43594 (merged) |
| SeaweedFS | #43816 |
| HF3FS | #43817 |
| Mooncake, UMBP | already per-rank (`mha_suffix`), unchanged |

## E2E reproduction

`zai-org/GLM-5.3-Flash`, 4×GB300, TP4/EP4, FP8 KV, DSA/TRTLLM, compressed indexer enabled. Use file L3, `write_through`, `page_first_direct`/`direct`, `wait_complete`, page size 64, 65,536 device-cache tokens and a fresh shared storage directory.

1. Generate one token from a prompt with a 16,512-token shared prefix; repeat and fork that prefix.
2. Send six unrelated 16K-token prompts, wait for backup, then `POST /flush_cache` to clear L1/L2. Request the original prompt again.
3. Confirm cache hits: **device=0, host=0, storage=16,512**. Synchronize transfers and compare restored state hashes with each rank's backed-up state.

| Run | State restore result |
| --- | --- |
| Original | All four ranks restored rank 3's state; **408/544 wrong-rank payloads** |
| TP-key isolation probe | **544/544 matched their own rank**; KV/indexer transfers remained byte-exact |

GPU runs used #40134 at `49bfd862fc22` (for GLM indexer support), with a key-only diagnostic patch for the second run. This confirms the existing file-key bug, not a regression introduced by #40134. The current patch (rewritten to follow #43594's key shape) has CPU regression coverage, **not a fresh GPU E2E run or full numerical-accuracy sign-off**.
