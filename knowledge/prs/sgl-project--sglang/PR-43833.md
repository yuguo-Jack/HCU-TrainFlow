# [DeepSeek-V4.1] mHC: drop seam_open, narrow precomputed stats in take_rows

[Upstream PR](https://github.com/sgl-project/sglang/pull/43833) · state: open · merged: False

## Motivation

`forward_hc_pre_from_prev` took two seam flags. `seam_open=tail is None` closed the cross-layer seam for every layer whenever the late-layer tail was active, so tail-mode prefill lost the fused post + next combine at all 40 layer boundaries. `mega_mhc_seam_open` additionally disabled Mega mHC for both sublayers of the layer before the row narrowing, although the attention sublayer's next boundary is inside the layer and unaffected by it.

Neither flag is needed for correctness: everything a boundary precomputes for the next sublayer travels on `HcState`, and the narrowing goes through `HcState.take_rows`.

## Modifications

- `HcState.take_rows` narrows a normed next input (`HcNormed`) and the precomputed `stats` triplet together with the residual. Both are per row: `stats` is `([T, 4], [T, 4], [T, 4, 4])`, each row computed only from its own residual row. A quantized input (`HcQuantized`) is dropped, since its MXFP8 scales are swizzled per 128-row tile, and the next combine rebuilds it. `with_residual` keeps dropping both.
- `seam_open` and `mega_mhc_seam_open` are removed; the seam is always open, so tail-mode prefill keeps the fused cross-layer post.
- Mega mHC is selected inside `_post_fusion` from `next` alone; the `mega_mhc` / `mega_next` parameters of `run_attn_post` / `run_moe_post` are removed. `_can_use_mega_mhc` drops the redundant `not _is_hip` (`is_sm100` already requires CUDA).

## Accuracy Tests

- CPU unit check of the new `take_rows` / `with_residual`: the narrowed `HcNormed` rows and `stats` equal the selected rows of the originals (gather path with zero padding rows), padding rows are zero, a quantized input becomes `None`, and `with_residual` drops both.
- End-to-end accuracy with `--enable-decoder-swa-bounded-replay` (the tail mode this changes) is still to be run; this PR stays a draft until then.
