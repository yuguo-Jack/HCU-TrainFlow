# [Unified Cache] Prevent misaligned Mamba checkpoints after speculative truncation

[Upstream PR](https://github.com/sgl-project/sglang/pull/43387) · state: open · merged: False

## Original PR description

## Motivation

With Mamba `no_buffer` + speculative decoding, verify advances the live state before CPU grammar/finish truncation. Donating that state under a shorter cache key corrupts subsequent prefix reuse.

## Changes

Require the live state length to match `owned_kv_len()` before donation, accounting for grammar-retained tokens and each algorithm's non-draft count. Otherwise skip the finished request's insertion, preserving existing prefixes and normal resource cleanup. The decision survives deferred release and adds no GPU synchronization.

Extend `test/registered/radix_cache/test_mamba_cache_kl.py` with `TestMambaSpecTruncationKL`. NEXTN count/story requests end at short length limits; the test compares full-vocabulary next-token distributions for identical probe token IDs using warm cache versus a cold recompute. It also checks that speculative verify accepted drafts and that cache reuse actually occurred. Shared HTTP/distribution helpers retain the existing lazy checkpoint test.

This branch includes #43567's shared test file and should merge after #43567. The no_buffer fix itself is independent of the lazy extra-buffer fix.

## Validation

GB300, TP1, Qwen3.5-0.8B pinned at `2fc06364715b967f1860aea9cf38778875588b17`, NEXTN (3 steps, topk 1, 4 draft tokens), no_buffer, page size 1, overlap/CUDA graphs disabled. The negative control retains #43567 and removes only #43387's finished-state guard.

| Scenario | KL without guard | KL with guard | Warm cache length without / with guard |
|---|---:|---:|---:|
| Count, max_new_tokens=9 | 0.876971 | 0.000235300 | 51 / 42 |
| Story, max_new_tokens=5 | 4.107031 | 0.000941570 | 27 / 22 |

KL is `D_KL(cold || warm)` over all 248,320 vocabulary entries at the same next-token position. The threshold is 0.005: valid prompt-prefix reuse versus cold prefill has numerical differences, while the corrupted-state cases are much larger. Unsafe finished suffixes now fall back to the cached prompt; this can reduce cache hits for truncated requests.

- Registered in `extra-a`, `1-gpu-large`; the new GPU test covers NEXTN length truncation. Grammar, EOS/stop, zero-commit, deferred release, and dedicated-slot controls remain covered by CPU tests.
- GPU: each NEXTN case repeated three times with identical KL values; all six negative controls failed and all six fixed cases passed. The existing lazy in-place KL test also passed with KL=0.
- CPU: 8 tests and 11 subtests passed after integrating #43567.
- Pre-commit passed. GPU validation is limited to GB300; no throughput benchmark.
