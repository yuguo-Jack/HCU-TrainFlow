# [Observability] Propagate entry received_time through /v1/score and /v1/responses

[Upstream PR](https://github.com/sgl-project/sglang/pull/41575) · state: open · merged: False

## Original PR description

## What

Chat / completions / embeddings stamp `received_time` at the `OpenAIServingBase.handle_request` entry, so the internal request's root span (`time_to_first_token`, e2e attributes) and `e2e_request_latency_seconds` start at HTTP receipt. Two sibling OpenAI endpoints missed this:

- **`/v1/score`** — `handle_request` returns the `ScoringRequest` unchanged (`serving_score._convert_to_internal_request`), and the isinstance guard only covered `GenerateReqInput`/`EmbeddingReqInput`; no timestamp was attached. `score_request` then builds its internal `GenerateReqInput`/`EmbeddingReqInput` (after score-side tokenization) without one.
- **`/v1/responses`** — `create_responses` bypasses `handle_request` entirely; its internal `GenerateReqInput` got no `received_time` (including builtin-tool continuation turns).

So score/responses root spans and e2e latency started **after** endpoint-specific preprocessing/internal tokenization, making them systematically lower and incomparable with chat/completions/embeddings.

## Change (timestamp plumbing only)

- `ScoringRequest` gains an internal `received_time: Optional[float]`; `handle_request` stamps it alongside Generate/Embedding inputs.
- `serving_score` forwards it into `score_request(...)`, which propagates it to both internal request constructors.
- `create_responses` samples `monotonic_time()` at entry and stamps the first-turn internal `GenerateReqInput`; builtin-tool continuation turns inherit the same entry timestamp from the prior adapted request.

No new metric, no label, no behavior change beyond the timing origin.

## Verification (CPU, Linux venv with CPU torch — GPU path not exercised)

New `test/registered/unit/entrypoints/openai/test_received_time_propagation.py` (3 cases):
- **RED on unmodified main `6aacca2`**: score and responses cases fail (`unexpectedly None` on the forwarded/stamped timestamp); embedding control passes.
- **GREEN after fix**: all 3 pass.

Controls (same patched tree):

- `test_serving_embedding.py`: 14 passed.
- `test_setwise_score_mixin.py`: 50 passed.

Scope boundary: CPU/logic layer only (timestamp origin and propagation); no GPU server e2e.
