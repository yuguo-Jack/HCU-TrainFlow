# [Fix] Normalize nested thinker text config dictionaries

[Upstream PR](https://github.com/sgl-project/sglang/pull/42177) · state: open · merged: False

## Original PR description

## Motivation

Fixes #42142.

`get_hf_text_config` converts dictionary-valued top-level sub-configs into `PretrainedConfig`, but a nested `thinker_config.text_config` can still be a dictionary. The subsequent dtype propagation raises `AttributeError: 'dict' object has no attribute 'dtype'`, preventing configuration loading without any model overrides.

This is separate from #37928's optional-null guards and #27983's explicit model-override routing: neither fixes direct loading of the reported nested dictionary.

## Modifications

- Convert a dictionary-valued thinker text sub-config before the existing dtype propagation.
- Keep existing typed text objects, thinker precedence, and dtype propagation behavior unchanged.
- Extend the existing registered CPU utility tests with dictionary/typed thinker parents, inherited/explicit/absent thinker dtypes, token-attribute propagation, RoPE compatibility, priority, and repeated-call identity checks.

## Accuracy Tests

On macOS arm64, Python 3.12.11, PyTorch 2.13.0 and Transformers 5.17.0, importing the real production function reproduced the issue's `AttributeError`.
