# Support EPLB for Nemotron-H

[Upstream PR](https://github.com/sgl-project/sglang/pull/43685) · state: open · merged: False

## Original PR description

## Motivation

`--enable-eplb` fails at startup on Nemotron-H (`AssertionError: ExpertLocationMetadata is required`): the model does not implement the EPLB hooks.

## Modifications

- `NemotronHForCausalLM`: add `get_model_config_for_expert_location` and `routed_experts_weights_of_layer`; record per-layer expert counts.
- `NemotronHMoE`: pass `expert_location_dispatch_info` and `num_token_non_padded` to `topk`; add `get_moe_weights`. MTP layers set `is_nextn` and skip the remap.
- `NemotronH_Omni_Reasoning_V3`: forward both hooks to the language model.
- Tests: unit cases for the VL wrapper; nightly e2e `TestNvidiaNemotron3SuperNVFP4EPLB`.

EPLB needs a MoE runner that takes top-k ids, e.g. `--moe-runner-backend flashinfer_trtllm_routed`. `flashinfer_trtllm` routes inside the kernel, and `flashinfer_cutedsl` without a2a does not migrate its MMA-layout scales on rebalance.

## Accuracy Tests

Nemotron-3.5-Super, B200, TP2/EP2, `--enable-eplb --ep-num-redundant-experts 32 --eplb-rebalance-num-iterations 1000 --moe-runner-backend flashinfer_trtllm_routed`, `lm_eval` GSM8K 5-shot (flexible / strict):

| | baseline (no EPLB) | EPLB |
|---|---|---|
| BF16 | 0.920 / 0.836 (TP2) | 0.916 / 0.842 |
| NVFP4 | 0.923 / 0.854 (TP1) | 0.923 / 0.856 |

Balancedness 0.979 -> 0.991 after the first rebalance. `TestNvidiaNemotron3SuperNVFP4EPLB` (TP/EP 2, rebalance every 50 iters, 640 rebalances): GSM8K 0.985.

**Issue**

`--enable-eplb` turns on the expert distribution recorder, and the draft model runner also records inside `with_forward_pass`. This MTP MoE layer still runs `select_experts`, which calls `on_select_experts`, but `NemotronHMultiTokenPredictor.forward` sets no current layer. `_SelectExpertsSinglePassGatherer` then indexes `self._data[None, :]`, and `scatter_add_` fails on the extra dimension. So EPLB plus MTP should fail at draft CUDA graph capture or at the first draft step.

**Fix**

Wrap the layer loop in `NemotronHMultiTokenPredictor.forward` with `get_global_expert_distribution_recorder().disable_this_region()`, as `qwen3_next_mtp.py`, `deepseek_nextn.py`, and the other NextN models do. One launch with `EPLB_ARGS + MTP_ARGS` would confirm it.

File: `python/sglang/srt/models/nemotron_h.py` · line 916

[by Claude Code] **Severity: functional | Confidence: Medium**

**Issue**

This hook lets `--enable-eplb` start on Nemotron-H. On SM100 with no A2A, `_nemotron_h_overrides` turns runner `auto` into `flashinfer_trtllm`, which routes from logits inside the kernel. It ignores `expert_location_dispatch_info`, and the recorder gets no routing stats.

**Example**

`--ep-size 2 --enable-eplb --ep-num-redundant-experts 32` with no runner flag fails FlashInfer's `routing_logits` shape check: the logits have `n_routed_experts` columns, but the kernel expects 32 more. With no redundant experts it starts, but EPLB does nothing, and any expert move would send tokens to the wrong weights.

**Fix**

In `_nemotron_h_overrides`, pick `flashinfer_trtllm_routed` when EPLB is on and the runner is `auto`, as `handle_a2a_moe` does for A2A. Raise a clear error for `flashinfer_trtllm`, and for `flashinfer_cutedsl` without A2A.

- nvpohanh · comment · 2026-10-12T06:05:13Z · [source](https://github.com/sgl-project/sglang/pull/43685#discussion_r4245086834)

File: `python/sglang/srt/models/nemotron_h.py` · line 919

[by Claude Code] **Severity: functional | Confidence: Medium**

**Issue**

`NemotronHPuzzleForCausalLM` inherits this hook, so EPLB now starts for Puzzle models too. Puzzle layers take `n_routed_experts` from `block_configs`, and `max_n_routed_experts` exists because the count can differ per layer. This code uses the top-level `config.n_routed_experts` for every layer. `ExpertLocationMetadata` then sizes the physical map and the per-rank expert slices wrong for any MoE layer with a different count.

**Fix**

Collect `config.get_nemotron_h_config_for_layer(i).n_routed_experts` for every MoE layer. Raise a clear error if the counts differ; otherwise pass that single value as `num_logical_experts`.
