# [EPLB] Fix dynamic expert migration for E8M0 tensors

[Upstream PR](https://github.com/sgl-project/sglang/pull/34853) · state: closed · merged: False

## Original PR description

## Motivation

Dynamic EPLB migrates expert weights between ranks with NCCL point-to-point operations.

The Humming/MXFP4 MoE backend stores some expert scale tensors as `torch.float8_e8m0fnu`. PyTorch's NCCL process group cannot send or receive this dtype directly, so the first dynamic EPLB rebalance fails with:

```text
TypeError: Input tensor data type is not supported for NCCL process group:
Float8_e8m0fnu
```

The tensor payload is byte-addressable and does not require numerical conversion during migration.

## Modifications

- Add `_get_p2p_transport_tensor()` to return a zero-copy `torch.uint8` view for `torch.float8_e8m0fnu` tensors.
- Apply the transport view symmetrically to EPLB P2P send and receive buffers.
- Leave NCCL-supported tensor dtypes and tensor objects unchanged.
- Add a registered CPU unit test covering:
  - E8M0 tensors use a `uint8` transport view;
  - the transport view shares the original storage;
  - the E8M0 byte pattern is preserved;
  - writes through a receive-side view update the original tensor;
  - supported dtypes are returned unchanged.

This changes only the transport representation. It does not cast, requantize, or alter the expert tensor contents.

## Accuracy Tests

End-to-end smoke test:

- Model: DeepSeek-V4-Pro
- GPU: H20
- MoE runner backend: Humming
- MoE A2A backend: DeepEP
- Dynamic EPLB: enabled
- GSM8K samples: 20

```text
Accuracy: 0.950
Invalid: 0.000
Latency: 15.308 s
Output throughput: 136.723 token/s
```

The test completed after dynamic EPLB migration without the previous NCCL dtype failure.

## Speed Tests and Profiling

No steady-state inference path is changed. The helper creates a zero-copy dtype view only while constructing dynamic EPLB migration P2P operations:

```python
tensor.view(torch.uint8)
```

It performs no allocation or data conversion. Therefore no steady-state throughput regression is expected. The end-to-end smoke test above confirms successful inference with dynamic EPLB enabled.
