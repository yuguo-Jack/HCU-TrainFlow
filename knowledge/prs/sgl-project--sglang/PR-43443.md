# [Platform] Unify multimodal_gen platforms onto DeviceMixin

[Upstream PR](https://github.com/sgl-project/sglang/pull/43443) · state: open · merged: False

## Original PR description

## Motivation

SRT and multimodal_gen each carried their own platform abstraction. SRT moved to `DeviceMixin` (`srt/platforms/device_mixin.py`), but diffusion's `Platform` still kept its own copies of device selection, memory queries, the distributed backend, seeding, and direct `torch.get_device_module()` calls. Out-of-tree backends therefore had to implement the same device operations twice. Some backends are also removing the per-device `torch.<device>.*` module methods in favor of `torch.accelerator`, and every direct `torch.get_device_module()` call is a site that breaks when that happens. Routing device operations through one platform interface leaves one place to fix per backend.

This PR puts diffusion platforms on the shared `DeviceMixin`, so each device operation is written once and serves both runtimes.

## Modifications

**Shared base (`srt/platforms/device_mixin.py`)**
- `get_device(device_id)` returns a `torch.device` (it was annotated `str`).
- New: `current_device()`, `has_device_capability()`, and `get_available_gpu_memory(device_id=None, distributed=False, empty_cache=True, cpu_group=None)`. The last one is a policy layer over the per-device `get_available_memory()`: empty the cache, default to the current device, optionally take a MIN all-reduce over `cpu_group`, and return GiB.
- `get_device` / `set_device` / `current_device` raise `NotImplementedError` naming the class that must implement them.
- Per-device mixins gain `current_device()`. The CUDA "integrated device uses host RAM" rule moves into `CudaDeviceMixin.get_available_memory`. MPS reports Metal working-set limits.

**Diffusion platforms (`multimodal_gen/runtime/platforms/`)**
- `Platform` becomes `MMPlatform(DeviceMixin)`. `Platform` stays as an alias.
- Each built-in composes its SRT device mixin: `CudaPlatformBase(CudaDeviceMixin, MMPlatform)`, and likewise for ROCm, NPU, XPU, MUSA, MPS, and CPU.
- Deleted MM duplicates: `get_device`, `set_device`, distributed backend, `inference_mode`, `seed_everything`, the memory queries, the CPU-arch helpers, and the hardware-probing `is_xpu` / `is_npu` / `is_musa`.
- Kept MM-only: attention backend selection (now instance methods), VAE / layerwise-offload / modelopt hooks, and the NVML/MTML device queries, which avoid initialising CUDA in the launcher.
- `get_local_torch_device()` is now `self.get_device(LOCAL_RANK)`.

**Communicator hooks return classes**
- `get_communicator_class()` and `get_all_to_all_communicator_class()` replace `get_device_communicator_cls()` / `get_all_to_all_communicator_cls()`, which returned qualname strings.
- An external platform that still defines the old names is rejected at load time with a "rename it to …" `TypeError`, so it isn't silently ignored.

**Selection: `SGLANG_PLATFORM` drives both runtimes**
- `SGLANG_DIFFUSION_PLATFORM_OVERRIDE` becomes a deprecated alias (`EnvStrWithAlias`) and is removed from `multimodal_gen/envs.py`.
- SRT now accepts built-in names (`cpu`, `cuda`, `rocm`, `xpu`, `mps`, `npu`, `musa`) and returns them before plugin discovery, since the shared variable can now hold them.

**Docs:** `hardware-platforms/plugin.mdx` and both environment-variable references are updated.

### Behavior changes (diffusion)
- MUSA distributed backend: `nccl` → `mccl`, matching SRT.
- ROCm integrated APUs (gfx1151): free memory now comes from host RAM, as in SRT.
- MPS: memory is bounded by Metal's recommended working-set size, not total system RAM.
- CPU: `device_name` is `cpu` (was `CPU`), `get_device_name()` returns the arch label, and the memory query runs `gc.collect()` via `empty_cache()`.
- `is_npu` / `is_xpu` / `is_musa` report the selected platform, not hardware presence.
- `get_current_memory_usage` reports peak memory without resetting it. It has no callers.
- Setting either env var now selects the platform for SRT code in the same process. An OOT vendor should register the same entry-point name in both entry-point groups.
- OOT plugins written against the string-returning communicator hooks (#37547) need the rename.

### Out of scope / follow-ups
- SRT's `get_available_gpu_memory(device, gpu_id, ...)` in `srt/utils/common.py` (50 callers) is unchanged. Its branches carry SRT sizing policy: CPU NUMA split, MLX on MPS, HPU, and NPU zbal. Delegating it changes how SRT sizes memory, so it belongs in its own PR.
- Plugin discovery isn't merged across the two runtimes. Only the env var and the built-in names are shared, because the auto-detection orders differ.
- Migrating the remaining `torch.get_device_module(...).set_device / synchronize / current_stream` call sites in SRT to `current_platform`, and adding `current_stream()` to `DeviceMixin`.
