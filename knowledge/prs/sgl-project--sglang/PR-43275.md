# [Fix] GLM-4.7/5 tool parser: stream non-JSON array/object/boolean values as valid JSON

[Upstream PR](https://github.com/sgl-project/sglang/pull/43275) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43273.

`Glm47MoeDetector`'s streaming path passed `array` / `object` / `boolean` argument values through verbatim, assuming the model wrote valid JSON, while non-streaming runs the same values through `parse_arguments`. When the model writes a value that isn't strict JSON, non-streaming returns valid arguments but streaming emits invalid JSON:

| param type | model wrote | non-streaming | streaming (main) |
|---|---|---|---|
| array | `1, 2` | `[1, 2]` | `1, 2` ❌ |
| boolean | `True` | `true` | `True` ❌ |
| array / object | (empty) | `""` | (nothing → `{"a": }`) ❌ |

## Modifications

`glm47_moe_detector.py`:
- Array/object values still stream verbatim, but only once the value opens with `[` / `{` (leading whitespace is held and emitted with the opener). Real JSON containers, such as long todo lists, keep streaming incrementally exactly as before.
- Any other value for a non-string type (`1, 2`, `True`, any boolean, an empty value) is held and parsed when `</arg_value>` arrives, through the same `_parse_argument_pairs` call already used for `auto` / `number` / `integer`. Streaming output now matches non-streaming for these values.
- `_format_value_complete` now only receives strings, so it drops the dead non-string branch.
- Once an array/object value has opened as JSON and is streaming, its content is no longer also appended to `_current_value` (the value-close path doesn't read it). Only values still being held are buffered. This lines up with #43729, which removes the same copy for values that stream through.

Known limitation, unchanged by this PR: a Python-style dict such as `{'a': 1}` opens with `{` and still streams verbatim. Handling it would mean buffering every object value, giving up incremental streaming.

Tests: `test_glm47_schema_types.py::test_non_json_container_and_boolean_values_stream_as_json` uses the existing `check_arguments` helper (non-streaming, plus streaming at chunk sizes 1, 7 and full) for `1, 2`, `True`, and whitespace-padded real JSON containers (a guard that verbatim streaming still works). The `1, 2` and `True` cases fail on main and pass with this change.

Extra check (not committed): a grid of array/object/boolean/string/number values × chunk sizes 1, 2, 3, 5, 7 and whole, comparing streamed and non-streamed arguments. On main, 36 of 132 streamed outputs are invalid JSON. With this change, all 132 are valid JSON and equal to non-streaming.

Related: #43270 (GLM-4.7 `parse_arguments` tuple fix) touches different lines of the same files; the two branches merge cleanly in either order. `Glm4MoeDetector` (GLM-4.5) has a similar streaming pattern, plus verbatim `number` streaming, and isn't changed here (noted in #43273).
