# fix(bench): enable --header passthrough to HTTP requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/35234) · state: open · merged: False

## Original PR description

## Motivation

`sglang.bench_serving --header` passes custom HTTP headers for authenticated/proxied endpoints, but several server-bound requests used `get_auth_headers()` directly and silently dropped those custom headers:

- the readiness poll (`wait_for_endpoint`)
- the cache flush (`flush_server_cache`)
- the two `/server_info` queries inside `benchmark()`
- model discovery (`/v1/models`) and tokenizer lookup (`/model_info`) in `run_benchmark()`

Only the benchmark's async request paths respected `--header`.

## Modifications

- Folded the auth logic from `get_auth_headers()` into `get_request_headers()` so there is a single request-headers builder that always applies `parse_custom_headers()` (the `--header` flag). This removes the historical `get_auth_headers()` helper, which was the pre-`--header`-era function and had  no remaining call sites that wanted auth *without* the custom headers.
- Switched the 6 call sites above from `get_auth_headers()` to `get_request_headers()`.
- Updated `test_embedding_cache_flush_uses_the_engine_specific_endpoint` to patch `get_request_headers` instead of the removed `get_auth_headers`.
