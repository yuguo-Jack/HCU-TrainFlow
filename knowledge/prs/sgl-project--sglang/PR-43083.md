## How the commands are produced

Same pipeline and rules as #42726. Each lane is rendered at the exact commit of the run that produced its dashboard data or, for an open PR, the run named by its authorized `/use` comment (the PR head when there is none). SA-only settings are removed (benchmark harness, cluster paths and caches, telemetry, InferenceX's synthetic speculative acceptance, which is disclosed per deployment). Placeholders replace IPs, ports and NICs. Router and KV-offload variants that were not run are derived and labeled "Derived — not run". What is new here:

- **Single-node lanes from job logs.** The single-node Qwen lanes on `main` were launched by InferenceX bash launchers at their measured commits. Their commands come from the Actions job logs and a dry run of the pinned launcher, accepted only when the dry-run server command equals the logged one.
- **Same shape, measured twice at one concurrency.** A few Qwen lanes measured one shape at the same concurrency both with and without HiCache (for example B200 TP4: up to c64 without offload, c64–c76 with HiCache), or with different `--max-running-requests` caps (GB300 agg "pareto" lanes). Those become separate deployments, labeled "measured with HiCache" / "measured with no KV offload" or by the cap. Shapes without such a collision stay one deployment, as before.
- **KV offload.** HiCache variants borrow flags from the closest verified HiCache launch of the same model on the same hardware (an absolute `--hicache-size` is only reused there). Qwen3.8-Flash-Next's only HiCache launch is the GB300 one, so its B300, B200 and H200 deployments offer GPU KV only. The Mooncake variant reuses the verified DeepSeek-V4 GB300 external-linker spec on every page, and is disabled where the image's SGLang build predates `--enable-unified-cache-external-linker`.
- **Derived Dynamo on an image without `ai-dynamo`.** Derived Dynamo variants use the `ai-dynamo` bundled in the image. `lmsysorg/sglang:v0.5.16-cu130` (the Qwen3.5 B200 NVFP4 and B300 single-node lanes, all submitted with the SGLang router) ships without it, so for those 10 deployments the derived Dynamo variant installs `ai-dynamo` 1.4.2 first. 1.4.x is the release line whose `[sglang]` extra pins `sglang==0.5.16`, and 1.4.2 is the wheel the verified Qwen3.5 GB200 Dynamo launch used.
- **Not mirrored.** `qwen3.5-fp8-h100-sglang-agentic` (H100 without MTP) has never produced dashboard data, so there is no run to pin it to.
- **Images.** Several nightly tags these runs used have since been pruned from Docker Hub; the page flags them and links the SGLang commit they were built from. The Qwen3.8-Flash-Next B300, B200 and H200 lanes ran `lmsysorg/sglang:qwen38flashnext`, a moving tag; its GB300 lane pins the arm64 build of `lmsysorg/sglang:v0.5.21-cu130` by digest. #3836 pins its image by digest alone (`lmsysorg/sglang@sha256:2d53500c…`, built from SGLang `20ca564b`).

The data files are generated; please review the page text and the component changes rather than the JSON.
