# Guard the shm inference all-reduce on the host ISA

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8701) · state: closed · merged: True

## Original PR description

## Problem

The shm comm op's bf16/fp16 reduce kernels are compiled with `target("avx512bw")` and use `_mm512_*` conversions; the fp32 kernels use 256-bit AVX. Executing them on a host without the ISA faults, and because the reduce synchronizes through shm flags, the fault surfaces downstream as a **permanent hang of the peers instead of an error** — on the multi-rank CPU CI this froze an xdist worker until the phase timeout.

## Change

- Export `vector_kernel_level()` from the op: `2` = avx512bw, `1` = avx2, `0` = neither; non-x86 hosts report `2` (their kernels are JIT-built for the host ISA).
- Gate the dispatch in `inference_all_reduce`: fall back to the process-group `all_reduce` when the tensor dtype needs a level the host lacks (fp32 requires level 1, bf16/fp16 require level 2).

## Validation

- **avx2-only host**: fp32 keeps the shm path, bf16/fp16 now fall back; all dtype parametrizations of `TestDistInferenceAllReduce` pass (previously segfaulted/hung), and a standalone 4-rank repro that crashed before returns correct sums.
- **AVX512 host**: `vector_kernel_level()` reports 2 and every dtype still dispatches to the original shm kernels — the guard is a pure init-time probe with no change to the kernel code, so behavior on AVX512 machines is unchanged. `inference_all_reduce` results remain numerically equivalent to the process-group `all_reduce` across fp32/bf16/fp16 and small through large message sizes (crossing the 1MB distributed-path threshold), and the shm latency advantage over gloo is preserved (microsecond-scale small messages).

- Copilot · comment · 2026-10-05T12:18:44Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8701#discussion_r4183883621)

File: `csrc/cpu/comm/shm_interface.cpp` · line 116

Level 1 is not guaranteed safe here. `csrc/cpu/comm/x86_64/shm.h:55-58` declares both `reduce_fp32_buffers` and `parallel_memcpy` with `target("avx512bw")`, and every reduction uses the latter. The compiler may therefore emit AVX-512 anywhere in those functions even though the explicit fp32 intrinsics are currently 256-bit, so an AVX2-only host can still receive `SIGILL` and hang its peers. Either compile the fp32/copy functions with an AVX2 (or AVX) target before returning level 1, or conservatively require level 2.

- Copilot · comment · 2026-10-05T12:18:45Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8701#discussion_r4183883676)

File: `csrc/cpu/comm/shm_interface.cpp` · line None

Returning level 2 for every non-x86 host leaves the same illegal-instruction failure unguarded. The RISC-V implementations are explicitly compiled for `+v` and `+v,+zvfh` (`csrc/cpu/comm/riscv64/shm.h:58-65`), while the AArch64 fp16 intrinsics require the optional ARMv8.2 FP16 extension (`csrc/cpu/comm/arm64/shm.h:97`). JIT loading does not make those extensions universally available. Add architecture-specific runtime feature checks (or conservatively return 0 when support cannot be established) instead of unconditionally enabling every kernel.

- Copilot · comment · 2026-10-05T12:18:45Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8701#discussion_r4183883711)

File: `deepspeed/comm/torch.py` · line 301

This new dispatch branch has no deterministic automated coverage. The existing parametrized all-reduce test only exercises whichever ISA the runner happens to expose, so it cannot catch a regression where level 1 dispatches bf16/fp16 to shm or where level 0 still dispatches fp32. Add tests that control `shm_vector_kernel_level` and verify both the shm and process-group paths for each dtype/required level.
