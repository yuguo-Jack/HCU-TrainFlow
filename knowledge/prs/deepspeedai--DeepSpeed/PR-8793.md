# Average each loss of a tuple in pipeline eval_batch

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8793) · state: open · merged: False

## Original PR description

`PipelineEngine.eval_batch` fails when `loss_fn` returns more than one loss, e.g. `(loss, aux)`, which the forward pass already stores per micro-batch.

Two places broke:
- `_reduce_outputs` looped `for idx, out in outputs`, using the first loss as a list index (`TypeError`).
- With the default `bcast_loss=True`, `_bcast_pipe_scalar` only handles one tensor. On 2 stages the loss stage raised and the other stage hung in the broadcast.

Fix: sum each loss over the micro-batches by position. For the broadcast, the loss stage sends the number of losses, then all of them stacked into one tensor, as `_aggregate_total_loss` does for additional losses. A single loss takes the old path.

Tests:
- New `TestPipeEvalTupleLoss` (2 stages, `bcast_loss` True and False) passes; on master it hangs.
- New `test_pipe_reduce_outputs.py` fails on master, passes here.
- `TestPipeGradientAccumulationScaling` still passes; 1-stage gloo run returns the per-loss means. yapf and flake8 clean.
