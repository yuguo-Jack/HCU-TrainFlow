# [AutoSP] Fix tensor truthiness in get_node_shape_meta

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8760) · state: closed · merged: True

## Original PR description

Split out of #8457.

## Problem
`get_node_shape_meta` in `deepspeed/compile/fx.py` picks between `meta["val"]` and `meta["example_value"]` with `or`. When `meta["val"]` is a tensor, that `or` evaluates the tensor's truthiness. As a result:
- A tensor with more than one element raises `RuntimeError: Boolean value of Tensor with more than one value is ambiguous`.
- A zero scalar is treated as missing, so the code falls back to a stale `example_value`.

This only shows up after `pass_propagate_shapes`, which runs FakeTensorProp and fills in `meta["val"]`. Any AutoSP pass that reads shapes after that step can hit it.

## Fix
Check `is not None` explicitly.

## Tests
Added `TestNodeShapeMeta` to `tests/unit/v1/compile/test_compile_autosp.py`. It covers:
- a multi-element tensor
- a zero scalar
- falling back to `example_value`

Before the fix, 2 of these tests fail. After the fix, all 3 pass.

Hardware: 8× Intel Arc Pro B70 (XPU), torch 2.14.0.dev+xpu, transformers 5.17. The rest of the AutoSP unit tests pass. `TestAutoSPCompile` is not counted: it fails the same way on master in this environment, in the Dynamo Ulysses baseline.
