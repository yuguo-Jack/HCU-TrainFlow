# Warn when the Ulysses SP DataLoader is not sharded across the SP group

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8802) · state: open · merged: False

## Original PR description

## What's wrong

`UlyssesSPDataLoaderAdapter.refill()` gathers one batch from every SP rank and queues `sp_world_size` micro-batches, where micro-batch `i` is this rank's shard of the batch that came from rank `i`:

```python
for rank, tensor in enumerate(tensor_list):
    micro_batches[rank][k] = tensor
```

As the class docstring says, rank 0 contributes batch 0, rank 1 contributes batch 1, and so on. That only holds if the ranks read *different* samples. When the wrapped DataLoader has no sharded sampler every rank reads the same stream, so all `sp_world_size` gathered batches are identical: each batch is processed `sp_world_size` times and the remainder of the epoch is never read.

Nothing reports this. The only symptom is a silently shortened epoch with duplicated batches, which is what #7484 describes — 8 GPUs each receiving 8 copies of the same chunk. `__len__` already assumes the sharded case (`len(self.dl) * self.sp_world_size`).

## Fix

Warn at construction time when the sampler reports a single replica, naming `DistributedSampler` as the remedy, and document the requirement on the adapter and its `dl` argument.

Two cases are deliberately skipped:
- `IterableDataset`, which shards inside the dataset where there is nothing to inspect from here
- `sp_world_size == 1`, where a rank only ever replays its own batch

## Why a warning and not an error

I started with a hard `ValueError`, matching the existing `position_ids` check a few lines below, then backed it out for two reasons:

1. **It would break this repo's own tests.** `tests/unit/ulysses_alst/test_ulysses_sp_hf.py:127` and `:508` construct the adapter from a plain `DataLoader` with no sampler. Those tests assert only the first micro-batch, so they are exercising shard mechanics and the duplication never surfaces — they are legitimate as written, and rejecting an unsharded loader would fail them.
2. **A custom sampler can shard correctly without exposing `num_replicas`.** Treating a missing attribute as a hard failure would break working setups that this check cannot see into.

Worth flagging: those two existing tests *will* emit the new warning on a GPU runner, since they do pass unsharded loaders. That is arguably correct signal rather than noise, but if you would rather the adapter stayed silent I am happy to gate the check behind a flag, or escalate it to a `ValueError` and update both tests, whichever you prefer. The semantics here are a maintainer call and the issue has no maintainer response yet, so I kept the change non-breaking.

## Not a duplicate

`gh pr list --state open --search "7484 in:body"` plus keyword searches for `UlyssesSPDataLoaderAdapter` and `duplicate data sequence parallel dataloader` return no open PR. #8722 touches sampler construction but is about epoch reshuffling, not SP sharding. The sole comment on #7484 notes that a `DistributedSampler` is required — this change makes that requirement discoverable instead of implicit.

## Testing

New `tests/unit/ulysses_alst/test_ulysses_sp_dataloader_sharding.py`. The adapter's `__init__` only wraps the DataLoader in an iterator and makes no collective calls, so these run on CPU with no process group.

```
$ pytest tests/unit/ulysses_alst/test_ulysses_sp_dataloader_sharding.py -q
7 passed in 5.32s
```

Covered: unsharded map-style loader warns; `DistributedSampler` does not; `num_replicas` of 2/4/8 does not; `IterableDataset` does not; `sp_world_size=1` does not.

Reverting the source change fails the positive case, confirming the test tracks the behaviour rather than restating it:

```
AssertionError: assert 'does not appear to be sharded' in ''
1 failed, 6 passed
```

No regressions in the surrounding suite. `tests/unit/ulysses_alst/` goes from `8 failed, 30 passed, 12 skipped` on master to `8 failed, 37 passed, 12 skipped` with this change — the same 8 pre-existing failures (`deepspeed_shm_comm` JIT load needs `ninja`, unavailable here) and exactly the 7 new tests added.

**Environment:** CPU-only, 2 cores, no accelerator (`get_accelerator()` resolves to `cpu`, `torch.cuda.is_available()` is `False`). torch 2.14.1+cu130, Python 3.12.3, DeepSpeed 0.19.8 at a20acd1.

When `sp_world_size=4`, a standard `DistributedSampler(num_replicas=2, rank=sp_rank % 2)` can provide only two streams, so pairs of SP ranks gather identical inputs. This branch suppresses the warning merely because `2 > 1` (and the new parameterized test explicitly classifies that case as safe), leaving samples silently repeated; require at least enough replicas and verify that sampler ranks vary across the SP group before returning. The single-process constructor tests cannot establish that distributed invariant, so this also needs the repository-required multi-rank integration coverage.
