# [AutoSP] Rebuild query-sharded attention masks before SDPA

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8761) · state: closed · merged: True

## Original PR description

Split out of #8457. **This PR is stacked on #8760.** It contains that PR's commit, so please review only the last commit.

## Problem
AutoSP shards `input_ids`, `labels` and `position_ids` along the sequence dimension. A model can build its causal or attention mask from the sharded `position_ids`, which gives the mask the shape `[B, 1, S/sp, S]`. After the Ulysses all-to-all, SDPA sees all `S` queries, but the mask still covers only `S/sp` of them. The run then fails with a shape mismatch: `size of tensor a (s) must match ... (s//2)`.

## Fix
- Add a custom op `autosp::all_gather_sequence(input, dim)` with a fake (meta) implementation.
- In `pass_insert_attention_all_to_all`, check whether the mask's query dimension equals the local sequence length. If it does, all-gather the mask along dim -2 over the SP group. The mask can be passed as a kwarg or positionally. When several layers share one mask node, it is gathered only once.
- If the mask's key dimension is also sharded, it cannot be rebuilt correctly from the local pieces, so raise a clear error.
- Run `pass_propagate_shapes` once before the attention pass so that the mask shapes are current. This is why the PR depends on the `get_node_shape_meta` fix.
- `all_gather_sequence` has a backward pass, an `autosp::reduce_scatter_sequence` op, so masks that require gradients (for example a learnable position bias) also work.
- A mask with a full head dimension is redistributed like the query: if its query rows are sharded, it goes through all-to-all; otherwise each rank keeps only its own block of heads. A broadcast key dimension of 1 is never treated as sharded.
- Document the behavior under AutoSP Limitations.

## Tests
Added `TestAutoSPAttentionMask` (world_size=2):
- With a learnable mask bias (shared, per-head with sharded queries, or per-head with full queries), the loss and all parameter gradients match a single-device reference.
- With a query-sharded mask, passed as a kwarg and positionally, the forward loss matches a single-device full-sequence reference.
- A mask whose key dimension is sharded is rejected with a clear error.

Without the fix, all 3 tests fail. With the fix but without the `fx.py` change, all 3 also fail.

Hardware: 8× Intel Arc Pro B70 (XPU), torch 2.14.0.dev+xpu, transformers 5.17. 42 AutoSP tests pass. `TestAutoSPCompile` is excluded because of a pre-existing environment failure that also happens on master.

- Copilot · comment · 2026-10-07T04:41:18Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8761#discussion_r4203120422)

File: `deepspeed/compile/custom_ops/all_to_all.py` · line 100

This custom operator has no autograd registration, so a differentiable additive `attn_mask` (for example, a learned relative-position bias) will make backward fail once this pass inserts the gather. PyTorch custom ops require `register_autograd` when their inputs participate in gradient computation. Please add the collective's backward (including the required cross-rank gradient aggregation), or explicitly reject and document masks that require gradients.

- Copilot · comment · 2026-10-07T04:41:18Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8761#discussion_r4203120464)

File: `deepspeed/compile/passes/sp_compile.py` · line None

A singleton key dimension is broadcastable by SDPA, but when `S == sequence_parallel_size` the local key length is also 1, so this check misclassifies a valid `[B, 1, S/P, 1]` mask as key-sharded and raises instead of gathering its query rows. Exclude the broadcast dimension from the sharded-key check.

- jinyouzhi · comment · 2026-10-09T14:18:41Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8761#discussion_r4231101740)

File: `deepspeed/compile/custom_ops/all_to_all.py` · line 100

Agreed, fixed in 45059bd. `all_gather_sequence` now has a backward pass. After the gather, every rank's heads use the whole mask, so each rank only produces part of the gradient for every query row. The correct gradient of the local shard is therefore the **sum** of the matching rows over the SP group, which is a reduce-scatter. A plain slice would drop the contribution from the other ranks' heads. I added it as a separate custom op, `autosp::reduce_scatter_sequence`, so the compiled backward graph does not have to capture a process group.

Test: `test_learnable_mask_matches_full_sequence_gradients` uses a learnable distance bias and checks the loss and all parameter gradients (including the bias) against a single-device full-sequence run. If the backward is changed to slice only, the shared-bias case fails.

While working on this I also fixed a related case: a mask with a full head dimension (`[B, N, S/P, S]`) used to fail inside SDPA, because after the all-to-all each rank only has N/P query heads. Such masks are now redistributed the same way as the query (`all_to_all` with scatter=1, gather=2). If the query rows are not sharded, each rank keeps only its own block of heads. Both cases are covered by the new test.


- jinyouzhi · comment · 2026-10-09T14:18:44Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8761#discussion_r4231102178)

File: `deepspeed/compile/passes/sp_compile.py` · line None

Added the guard in 45059bd: a key dimension of size 1 is now never treated as sharded.

For context, the current flow can't actually hit this. The check compares symbolic shapes, so the local key length is the expression `(s//2)` and never the constant `1`. AutoSP also requires the sequence dimension to be a `SymInt`; this is asserted in `pass_shard_seq_dim` and `shard_tensor_node`. The guard keeps the check correct if that ever changes.
