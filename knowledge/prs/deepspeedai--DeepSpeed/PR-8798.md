# comms_logger: honor in-section enabled and bound per-op timer history

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8798) · state: open · merged: False

## Original PR description

## Summary

Fixes #8797.

The comms logger's enabled flag is currently derived from **section presence only**:

```python
# deepspeed/comm/config.py
self.comms_logger_enabled = 'comms_logger' in ds_config

# deepspeed/utils/comms_logging.py
def configure(self, comms_config):
    self.enabled = comms_config.comms_logger_enabled
```

So a user writing `"comms_logger": {"enabled": false}` (intending to disable the logger) actually **enables** it. In ZeRO-3 (~1,000 collectives/step) the per-op timers accumulate without reset and every collective walks the full history, producing the linear per-step slowdown reported in #8797 (measured 33.8 → 117.7 s/step over 10 steps; ZeRO-2 unaffected).

## Changes

1. **Honor the `enabled` field inside the section** (`deepspeed/utils/comms_logging.py`):

```python
_inner_logger = getattr(comms_config, "comms_logger", None)
self.enabled = (_inner_logger.enabled if _inner_logger is not None
                else comms_config.comms_logger_enabled)
```

2. **Bound each op's timer history** (`deepspeed/utils/timer.py`): `event_timers` is now a `deque(maxlen=1024)` instead of an unbounded list. `timed_op` reads the value via `elapsed(reset=False)` and the records are never otherwise reset; the deque keeps the defensive bound without affecting `reset()`/`mean()` usage.

Together these make `"comms_logger": {"enabled": false}` behave as documented and prevent the O(N²) accumulation even if the logger remains enabled.

## Notes

- Default behavior when no `comms_logger` section is present is unchanged.
- The per-collective `get_accelerator().synchronize()` in `comm.py` is intentionally left gated on `comms_logger.enabled` and is **not** moved or removed by this PR, to avoid forcing blocking collectives (and losing `overlap_comm`) on backends where the logger is disabled. As discussed in #8797 (compatibility note, §7), backends that rely on that sync for correctness can be addressed separately in the ZeRO-3 parameter-gather path.

Keep this generic timer's contract and bound/reset only the communication timer.

- Copilot · comment · 2026-10-10T05:36:45Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8798#discussion_r4236575911)

File: `deepspeed/utils/timer.py` · line 58

`SynchronizedWallClockTimer.Timer` is shared by engine, MoE, inference, and communication timing, so this global cap changes `elapsed(reset=False)` and `mean()` from all samples since reset to only the latest 1,024. Any timer stopped more than 1,024 times before a reset will silently under-report; meanwhile `timed_op` still re-synchronizes and sums up to 1,024 old events and records that rolling sum as one collective's latency. Preserve the generic timer contract and consume/reset each communication sample (or use a dedicated non-accumulating communication timer) instead.
